# CPU sigmoid, SiLU and SwiGLU math on AVX2

This methods reference contains no Strata timing, disassembly, selected production dispatch or local CPU bottleneck result. Its applicability anchor is commit `05a9b45c0a3a266779d4757a855b45a3bb42a62e`: `native_expert.cpp` includes a scalar row expression `(g / (1.f + exp(-g))) * u` at H=2560, FF=640, requested NT=1..4. This locates code and geometry only; it does not establish reachability, call count, layout or service share.

Keep the framework contracts separate. At vLLM commit `dd4e40142a3280ef404493e5117bde0c60c6e389`, plain `SiluAndMul.forward_native` is `F.silu(gate) * up`; CUDA/XPU call `_C.silu_and_mul`. The nearby Triton `_swiglustep_and_mul_kernel` is a different clamped operation with FP32 casts, a gate-output limit, an `up` clamp and a reduced-dtype store. In SGLang v0.5.20, CPU uses AMX when available and otherwise native `F.silu * up`; CUDA selects its JIT kernel only for supported output widths and uses the SGLang kernel otherwise; XPU uses `sgl_kernel`. These source references do not identify a selected model/MoE caller or the backend's exp, reciprocal, FMA, NaN or subnormal behavior. For a numerical comparison, pin the actual operator, dtype, clamps, rounding and accumulation boundaries. A selected, validated SGLang/vLLM contract can be relevant; libc or llama.cpp FP32 bit identity is not a universal requirement.

Method families have different costs and semantics:

- Scalar `expf`/`std::exp` follows the library's range reduction, polynomial/table work, scaling and exceptional paths. Division and scalar calls may limit vectorization; setup can dominate short rows.
- Compiler vector math can lower vectorized scalar expressions through a matching vector-function ABI. Clang `-fveclib` and GCC's vector ABI choices depend on compiler, library, linking/runtime and math assumptions. A vector `exp` does not imply vector reciprocal; division may remain. AVX2 has eight FP32 lanes. `-march=znver3` enables AVX2 and FMA, but AVX2 alone does not imply FMA.
- GCC `-mveclibabi` is a compiler/translation-unit choice unless a specific compiler version documents narrower scope; GCC documents requirements including vectorization, `-funsafe-math-optimizations` and a matching library. Function `target`/`optimize` attributes do not establish function-scoped vector ABI selection. Clang `-fveclib` is compiler-level selection; some library choices imply `-fno-math-errno`. Check effective flags and emitted calls rather than assuming equivalent semantics.
- AMD AOCL-LibM is a vendor-aligned candidate for Zen, not a proven winner here. The current AMD EULA lists AMD LibM as BSD-3-Clause; verify the exact release and bundled components. Intel VML HA/LA/EP accuracy and performance guarantees are Intel-specific; EP allows materially weaker precision/special-value guarantees and does not predict Ryzen benefit. SLEEF and bounded polynomial/rational methods offer alternatives, but published `exp` error alone does not bound composed SwiGLU output. Schraudolph's bit approximation is historical method evidence, not a drop-in libm replacement; RLIBM-32 shows constrained piecewise approximation can attain correct rounding under its stated design.

Track the full math path: range reduction and exp, division versus approximate reciprocal/refinement, gate sigmoid and SiLU products, up multiplication, FMA/contraction/reassociation, reduced-dtype store and later accumulation. FMA changes rounding. Large inputs, overflow/underflow, `±Inf`, NaN, signed zero, subnormals, errno/fenv and MXCSR DAZ/FTZ can differ by library and mode. Fast-math is a bundle of assumptions about finite values, exceptions, rounding and errno; it is not merely a vector-exp switch. Keep any future controls narrow and pin their compiler/library/FP environment.

AVX2 loads can be unaligned, so misalignment alone does not create a scalar tail. A contiguous 640-element FP32 row divides evenly into eight lanes; actual stride, padding or an aligned-only library API may need cleanup. Setup, dispatch, ABI calls, library availability, exceptional slow paths and state/table initialization can erase a vector kernel's benefit at small sizes. These are counterregimes, not measured results.
