Numerical oracle / metadata-bug distinction
-------------------------------------------
For every selected source, GGML's pinned ggml_get_type_traits(type)->to_float
decodes EVERY original packed FP32 row, with actual role type/row stride.
GU has gate[640,2560] and up[640,2560]. Expected FP16 layout is interleaved:
gate row r -> output row2r; up row r -> output row2r+1.
Down is full[2560,640], no substituted FF1280 dimension.
Expected indices/complete value counts and GGML trait block-byte equations
are independently checked against NativeFmt before comparison.
FP32 scratch rows start NaN; EVERY decoded FP32 value must become finite.
Each value is converted both with pinned ggml_fp32_to_fp16_row and an
independent binary32-bit RNE encoder. They must match EXACT bits. Nonfinite
actual-weight expected half outputs are rejected, not accepted with tolerance.
All4,915,200 output halves/source compare by uint16 bits. No hash-only,
first/last-only, tolerance or max-error gate is used.

A fixed24-case independent conversion domain gates host GGML against literal
expected binary16 bits and the independent RNE encoder:
signed zero, positive/negative normals, positive/negative even ties around1,
minimum half subnormal, ties-to-zero, ties-to-even subnormal, minimum normal,
normal/subnormal boundary tie, max finite half, overflow midpoint, infinities,
and signed float32 subnormals flushing to signed zero.
Qualify additionally tests device scalar sycl::half(float) and the actual
vec<float,8>::convert<half,automatic> form, comparing ALL48 returned half bits.
NaN-payload canonicalization is deliberately outside the literal edge domain.
All actual model-oracle values are finite; this is not a NaN semantics claim.

Separate failures distinguish:
- independent encoder vs literal edge: encoder/test metadata problem;
- host GGML vs literal/RNE: reference conversion contract problem;
- GGML trait/role/index/count inconsistency: oracle metadata/layout problem;
- device scalar/vec8 edge mismatch: baseline device-conversion contract;
- generic decoded full-output mismatch: baseline generic-vs-independent.
The first generic difference reports stage, layer/expert, gate/up/down,
original role row/column, actual bits and expected bits.
No candidate exists, so candidate-vs-generic is not asserted.
All failures suppress every timing receipt/rate; no failed cell averages.

Queue, memory and fault lifetimes
--------------------------------
One explicit Intel GPU in-order queue, Level Zero backend, fp16 and
device-USM aspects required. Every allocation belongs to that same queue/
context. All wrapper calls receive &queue. No default-queue null-stream path.
No queue factory, production caller or runtime setting is altered.

Two output slots match production DQ2. Each slot has GU6553600B and Down3276800B.
Source blobs remain immutable/device-resident across first-use, warm, all
samples and planned untimed validation. No source/output overwrite/free occurs
before same-queue completion. At j%2 reuse the in-order prior commands have
completed before the following write command executes, without host waits.

Device source/output buffers each have64-byte front and tail canaries.
Device allocations explicitly request64-byte alignment (size rounded up to64);
payload starts at+64, preserving original16-byte vector-store alignment.
Output payloads start all0xff (NaN half sentinel), and every individually
validated source has its output reset outside timing before a complete decode.
Guards of ALL allocated slots, including unused qualifier slot1, are checked.
Readback/host source lifetimes are protected by a drain guard declared after
the host buffers and before asynchronous submissions. Pair-scope drain precedes
host source destruction during exception unwinding. Each DeviceBuffer drains
before sycl::free. Readback buffers likewise drain before destruction on error.

An asynchronous error sets a sticky fault flag. wait_and_throw failure or
async fault invokes fixed failure JSON and _Exit(86), with no unwinding/free/
replay while completion is unknown. Synchronous submission/allocation errors
unwind through drain guards; if that drain cannot establish safe completion,
the same _Exit path applies. There is no fallback/candidate recovery.
The first queue exception is emitted as escaped failure JSON without allocation
inside the async handler, bounded4096 message bytes with an explicit truncation
flag. Runtime fault status is never converted into a normal timing receipt.
A blocked driver wait needs root's external process timeout; no assertion that
the driver honors an application-side bounded wait is made.

At most32 blobs/pair are held; pair storage retires before the next pair.
Explicit host+device payload buffers plus an8MiB metadata allowance are bounded
at220774528B (<512MiB). Main scratch is heap-backed; per-row host arrays total
about15KiB stack. Sample/identity receipts are bounded7pairs×7samples and at
most224 selected IDs with3 role descriptors each.
The original NativeRolePlan maps the whole54.8GB primary VIRTUALLY; this is
not an owned54.8GB payload copy. Do NOT apply a512MiB address-space/ulimit-v
cap. Explicit buffers are bounded; overall runtime/library/GGUF-header RSS
and mapped-page residency require root observation, not a source-only claim.
Root must retain an actual RSS/process budget receipt.

Timing semantics and counts
--------------------------
Each pair's first-use2-wrapper wall span and warm full batch are reported
separately and excluded. First use is not exclusive JIT time: an earlier pair
may already have loaded the same runtime-switch kernel module.
Each sample submits all2*batch wrapper calls with no per-kernel host wait,
captures host submission end, then ONE wait_and_throw boundary and host end.
No profiling queue/markers, event query or per-kernel timestamps are used.
Wrappers return void; this implementation deliberately reports no device
kernel duration or exclusive busy service. Optional profiling marker bounds
were not added. Host wall includes submit+completion, not GPU-exclusive work.

After each timed boundary, both final output-slot occupants receive full
oracle/readback/canary checks OUTSIDE timing before the next sample.
After all samples each distinct selected source is decoded/fully compared
untimed with reset outputs. This planned validation is not fault replay; an
earlier fault or mismatch aborts immediately. These checks can perturb
caches between batches; the operation is repeated device-resident actual data,
not cold VRAM, physical DRAM traffic or a selected production-route trace.

Qualifier per pair:2 wrapper calls,1 selected source,4,915,200 halves compared.
Timing per pair:
first-use2 + warm2*batch + seven samples14*batch + validation2*batch
=2+18*batch wrapper calls.
All-selected compare count=batch*4,915,200.
Timed-end-slot compare count=7*2*4,915,200=68,812,800 halves.
Source byte checks=batch*actual_blobbytes.
These counts reconcile explicitly before a successful final JSON.
Wrapper calls are counted from unchanged source API submissions, not an
independently observed hardware kernel count.

Per-sample logical packed-read bytes=batch*actual_blobbytes, logical FP16
output-write bytes=batch*9830400. Logical combined GB/s = bytes/wall_ns,
the decimal1e9 factors cancel. No H2D, readback, later GEMM reads or physical
controller traffic is included in this logical dequant numerator.
No production route frequency/time share or total-model speedup is inferred.
