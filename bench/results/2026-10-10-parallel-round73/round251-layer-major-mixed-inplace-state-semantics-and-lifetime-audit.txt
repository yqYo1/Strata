# R251 — layer-major state semantics and mixed in-place lifetime audit

Date: 2026-10-10 (Asia/Tokyo). Read-only audit of frozen production source, relevant state ownership, and the committed R249 correction. This is not a runtime qualification and does not attribute the older streamed-KV C failure to current source. No Git command, source edit, build, test, profile, inference, model-payload read, process/GPU/hardware query, or cleanup was performed.

## Finding

The per-layer state progression and mixed in-place pointer alias are source-consistent when the effective GPU prefix is aligned to the actual `run_impl` chunk schedule. Each model layer owns a distinct GDN ordinal or QSA ordinal, and each ordinal processes prompt chunks in increasing position order. The persistent residual rows carry the preceding layer's output into the next layer. In a mixed layout with `STRATA_PREFILL_LAYER_MAJOR_R_INPLACE=1`, GPU-prefix chunks alias the persistent device rows directly; host-suffix chunks continue to use `m.R` scratch and synchronized host handoffs. The R249 root correction is right: mixed in-place skips GPU-prefix D2D copies too; only reusing `F` rows of the existing scratch allocation requires `G=n`.

I found a **conditional source-level chunk-boundary defect candidate**: the outer layer-major function and inner `run_impl` can derive different first-chunk lengths when the original expert cache is fully resident and `STRATA_PREFILL_FIRST` is unset. The outer code chooses `F=256`, but it then swaps `m.cache` to a temporary one-layer cache. `run_impl` recomputes `all_cached` from that temporary cache, gets false, and chooses a full `m.T` first chunk. A partial GPU prefix is rounded against outer `F`, not the actual chunk schedule. For `m.T>256`, the resulting `G=256+k*m.T` is inside an actual `run_impl` chunk, not on its boundary. The host/GPU tests and offsets assume no such straddling. This is a concrete code inconsistency under those conditions, but its runtime occurrence depends on actual original cache residency, `m.T`, request, and env; no evidence reviewed here shows it caused a historical failure. `STRATA_PREFILL_FIRST=0` makes both sides use the full first chunk; explicitly setting the same legal short first chunk on both sides can also align them. Full-GPU `G=n` bypasses partial-prefix rounding, while a request below outer `F` becomes `G=0` and avoids a split.

## State and ordering invariants supported by source

`run_layer_major` snapshots the two PLE predecessor IDs once and restores them before each layer's `run_impl`. `run_impl` derives `prev` from `ss.ple_prev`, creates absolute QSA step positions `p0+t`, processes chunks in increasing `c0`, advances its local token window through each chunk, and commits the final two IDs before returning. PLE is active only when a stage includes model layer 1 (`LB <= 1 && 1 < LE`), so in the one-layer loop it runs once, at model layer 1. Its convolution history `ss.ple.hist` persists across that layer's chunks and is not reset per chunk. Other model-layer calls leave the PLE history alone. Fresh-session `session_zero` initializes all PLE history to zero and predecessor IDs to `[-1,-1]`; that initial-state guarantee is separate from the layer-major loop.

For GDN, `run_impl` counts GDN layers preceding `LB` and indexes the matching owned slice in `ss.gdn_state`; each GDN layer's recurrent state and convolution history then advance through chunks in increasing token order. For QSA, it similarly counts prior QSA layers and chooses the state by QSA ordinal. That state's resident K/V, indexer tail/dead/pooled rows/block position, and shared RoPE ownership remain layer-specific; QSA writes/selection for a chunk use absolute `p0`, then later chunks continue the same state. The correct local semantic comparison is consequently per-layer/per-chunk ordered inputs and state, not a comparison that expects all recurrent state to be reset at each layer invocation.

At a layer boundary, `on_chunk` stores the complete chunk result before the next layer reads it. For GPU rows it writes the persistent device row range; for host rows it performs `activation(...).wait()` into `rows`. The following layer waits at its start, reads the GPU row directly or queues a host-to-device activation copy into `m.R` before compute. The GPU and host lanes therefore have separate ownership and explicit handoff points. The source's intended row invariant is `output(layer,p0,T) == input(layer+1,p0,T)` byte-for-byte; correctness still needs a runtime digest check for every chunk.

## Mixed in-place alias map and lifetime

With `inplace=true`, `run_impl` sets `m.R` per chunk to `residual_gpu_row(c0)` when the full chunk ends at or before `G`; otherwise it sets `m.R` to `residual_scratch`. For a GPU chunk, the next-layer input pointer is that same `residual_gpu_row(c0)`, so `input != m.R` is false and the upload is skipped. The output callback receives `residual == m.R`; its destination is the identical persistent row range, so the D2D copy is skipped. This applies for mixed `G<n` as well as `G=n`. A GPU chunk is computed with its resident rows as the normal layer residual workspace; the source path intentionally permits input/output aliasing at that boundary.

For the host suffix, `m.R` remains scratch. The next-layer input is a host `rows` span, uploaded to scratch on the compute queue; the output callback waits for compute and then waits for D2H to the corresponding host span. Host ownership does not alias the persistent device prefix. Prefix/suffix writes are correct only if the chunk that triggers each callback lies wholly on one side of `G`.

Only when `inplace && G=n` does the allocator set `reused_tokens=F`, map those first rows onto the existing `restore.r` allocation, and allocate just `G-F` new GPU rows. For mixed `G<n`, `reused_tokens=0`: all `G` device rows are allocated even though their execution aliases them; the pre-existing scratch remains available for host chunks. `residual_gpu_row` uses the reused offset only in the all-GPU case. Thus there are two distinct facts: execution alias removes prefix D2D transfers; all-GPU placement alone reduces the *new* device allocation by `F*D*4`.

Lifetime ordering is explicit on normal and error exits. `run_impl` waits for its compute queue before invoking chunk callbacks. Host activation and device-residual callbacks wait for their copies. `run_layer_major` waits compute/copy queues and finishes the Stager at layer transitions and before releasing temporary cache/residual allocations. Its `Restore` destructor drains those queues and the Stager before restoring `m.R`, residual pointers, transfer context, callbacks, and cache references; the stack-owned host rows and device allocations remain alive until their users drain. PLE's `std::future` is declared after objects captured by its worker, so early returns join it before those referenced objects go away. The KV prefetch RAII drain similarly waits its stream before return. This audit found no definite dangling alias in those scopes, but it did not exercise injected failure/cancellation or backend async errors.

## Conditional split-boundary hazard

The two relevant source computations are separate:

- In `run_layer_major`, before `m.cache` is replaced, `all_cached` tests `impl_->cache->slots() >= n_layers*n_expert`. With no `STRATA_PREFILL_FIRST` override and `m.T>256`, a full original cache plus `n>512` yields outer `first=256`, `F=256`.
- The function then sets `m.cache = &layer_cache`; this cache has `n_expert` slots for one layer. Inside each call to `run_impl`, its own `all_cached` tests the temporary cache against `n_layers*n_expert`, gets false, and with no override uses `first_chunk=0`, so actual chunk boundaries are `0,m.T,2*m.T,...` (plus a final tail).
- For any partial requested prefix normalized by outer code to `G=256+k*m.T`, and `m.T>256`, `G` is not an actual chunk boundary. The first actual chunk may itself extend beyond `G`. `gpu_rows` uses the full-chunk predicate `c0+T<=G`, while `on_chunk` routes using `row+count<=G`; if a chunk straddles, that second test is false and the host destination is computed at `rows + (row-G)*D`, which has a negative offset. On a later layer the corresponding host source uses the same negative `(c0-G)` offset. This is an out-of-bounds span candidate, not just an imprecise transfer count.

The discrepancy is prevented if `STRATA_PREFILL_FIRST` explicitly makes both calculations agree (notably `0` for a full-size first chunk), if the original cache is not fully resident so both select a full-size first chunk by default, if `m.T<=256` makes the outer short first chunk ineligible, if `G=0`, or if `G=n`. These are source-derived conditions; the actual route and dimensions must be recorded. Before any mixed-prefix run, compute the exact `run_impl` chunk list with the post-swap cache state and assert every partial `G` is a cumulative chunk boundary. The run should fail admission before allocation/compute on mismatch, or the source should share one resolved chunk schedule between prefix rounding and `run_impl` before this candidate is called safe.

## Numerical and lifetime qualification plan

1. Record the frozen binary/source identity, original cache slots before any release, layer-cache slots, `n`, `m.T`, `STRATA_PREFILL_FIRST`, calculated outer `F`, and actual `run_impl` chunk list. Assert `G` is either zero, `n`, or exactly one of the cumulative chunk ends. Include the final short tail and prove no callback span has a negative host offset or crosses host/GPU storage.
2. On an otherwise identical fresh-reset 32K test, compare chunk-major with layer-major all-host; then compare one explicitly aligned partial prefix with in-place off/on; finally compare all-GPU if actual memory admission allows. Keep `kv_mode=0` for every QSA state (the source guard rejects streamed KV), preserve actual pack routes, chunk shapes, PLE selectors, and math selectors, and capture complete consumed positions without appending generated tokens.
3. Hash the residual input/output for every `(layer,chunk)` and assert exact handoff equality. For every GDN chunk hash recurrence and conv input/output state. For every QSA chunk hash Q/K/V, appended K/V code and scales, indexer tail/dead/pooled/block state, step positions, selected IDs/order, and attention output. Hash PLE initial history/window, every layer-1 chunk's history and predecessor IDs, and final `ple_prev`. Save final owned GDN/QSA/PLE state and compare corresponding arms; a matching final state by itself does not substitute for boundary checks.
4. Exercise an explicit host-to-device and device-to-host completion receipt for mixed in-place, and verify backing address/offset/length for each aliased GPU chunk and host suffix. Inject cancellation/failure only after the safe control succeeds; require queue, Stager, PLE future, KV prefetch, residual allocation and cache-restore cleanup to complete before buffers are released. Keep that as a separate fault arm.
5. If every boundary and state digest matches between aligned in-place and non-in-place placements, that supports placement/alias parity for the tested source and shape only. If the schedule assertion fails, stop before inference and classify the chunk-schedule inconsistency; do not infer it caused the older historical C receipt, whose source and streamed-KV route differ.

## Scope limits

The currently supplied production-source guard requires full single-GPU compact FP16/source conditions and resident QSA K/V (`kv_mode=0`); a streamed-KV historical run is not eligible evidence for this source. Current metadata corrects QSA geometry to two KV heads of width 256 rather than four of width 128; their FP16 KV product has the same bytes, but actual geometry must be taken from the loaded pack/session. R248/R249 capacity and historical residual traffic are not new allocation receipts. No execution here qualifies 32K, full context, in-place alias arithmetic, or restored-cache headroom. The main open source concern from this audit is the conditional mismatch between outer prefix rounding and inner chunking; everything else above is an implementation contract to verify, not a detected runtime defect.
