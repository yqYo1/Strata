# Opt-in native expert-copy preparation

This branch prepares an experimental Linux/SYCL queue factory for expert H2D transfers. It has not been compiled or executed on the GPU at this checkpoint. It is not adopted, and no speed or stall-prevention claim is made. The baseline and current quiet measurement worktrees remain unchanged.

The already completed host-accounting diagnostic on B570 pairs880 expert-ring copies in a bounded32 MiB log prefix with ordinal0, whose flags include compute and copy. The installed runtime also reports a main blitter available. [That first-use evidence](https://github.com/yqYo1/Strata/tree/4e756c556d2870e2711a5e463535e33c02478291/bench/results/2026-10-05-sycl-prefill-scaling/host-prefill-accounting-v0141-20261009/first-diagnostic) is the reason to test a copy-only engine, rather than evidence that the new factory is safe or faster.

With `STRATA_PREFILL_COPY_ENGINE=1`, the candidate enumerates queue-group properties and selects a group with COPY and without COMPUTE, using index0 only when the group exposes a queue. It uses the existing context/device and creates an asynchronous in-order immediate command list. It checks immediate identity, ordinal and immediate queue flags before importing the native list with explicit SYCL ownership transfer and in-order properties. It checks the imported context, device, order and native handle, then registers the queue with the existing device registry. Existing device/default-stream waits and queue destruction therefore retain it. Ring reuse barriers, actual DMA event retention and expert arithmetic are unchanged. No kernel or CPU host task is submitted to this queue.

Unset or0 uses the original generic factory and arguments. Invalid values fail initialization. Native copy profiling is rejected until it has its own qualification. The runtime remains configured with copy offload disabled and direct submission disabled; those settings are not removed by this experiment.

The immediate queue flag getter is `zeCommandListImmediateGetFlags`, which returns command-queue flags. `zeCommandListGetFlags` returns command-list flags with a different in-order bit; it is not used here. [The official interoperability contract](https://github.com/intel/llvm/blob/sycl/sycl/doc/extensions/supported/sycl_ext_oneapi_backend_level_zero.md) requires an in-order immediate list for L0v2 and places native ownership under SYCL when transfer is requested.

Installed package2026.1.1-325 and adapter SHA256 are recorded. The installed adapter has no GNU build ID and its exact source Git commit is unknown. The supplied offline disassembly comes from the actual installed library; native creation checks immediate identity, installs an ownership-dependent destroy callback and forwards the supplied native list into the native in-order constructor and command-list manager. Current upstream source is not asserted to be the installed implementation. This static evidence does not validate counter-event waits across engines.

Before import, an empty-list guard cleans native validation failures. After entering `make_queue`, the application never manually destroys the handle because the runtime may already have adopted it during exception unwinding. Import failure aborts initialization without fallback or retry. An error before the adapter adopts the handle may leave one empty native list until the failing process exits; no successful-run leak or safe recovery claim is made from preparation alone.

CPU source checks reconstruct the original prefill byte for byte outside the queue-selection block and reconstruct every original device-header definition after removing only the added includes/factory. The full CPU build is admitted only after the current quiet comparison has terminated healthily and its owned processes are absent. Every translation unit will be rebuilt against the same header. First GPU use must then pass logged four-fresh32K head/state/output/logprob/MTP checks, native queue/barrier/counter evidence and owned normal cleanup. Quiet32K speed comparisons and the complete262144-context lifecycle are required before adoption.
