# R148 — default-off decode work/service join: minimum source design

Date: 2026-10-12 (JST). Source-only design for immutable XeStrata snapshot `39e395a103af36323262cdc0dbaea27cba81f3e4` in `/home/yayoi/ghq/github.com/MistVVK/XeStrata/.worktree/perf-xe-prefill-row-bounded-scratch-20261011`. No implementation, build/test, model, GPU, profiler/PMU or process query, Git operation, source edit or cleanup. No decode measurement is added.

## Decision

Add one explicit default-OFF, host-only **decode work/service join** that records route ownership and actual CPU row fragments for the current native decode path. Reuse the existing synchronous `PoolMultiFn` callback and `ExpertPool` task drain. Put the request/window/pair/owner join in caller-owned bounded storage; put worker timings in per-slot storage owned by each pool participant. The only per-fragment clocks should be read when the opt-in collector pointer is non-null. Do not log expert IDs or tokens, insert queue/device work, change a route, or infer traffic from planned bytes.

Admit the first version only for one serial verifier, one GPU stage, no batch/pipeline/async adaptation/peer or remote ownership, no mutable cache policy during the measured request, and native CPU expert pooling. Mark every excluded mode `unsupported/incomplete`; do not silently treat it as zero work. The 16-output OFF/ON PASS cases remain correctness evidence, not performance or service cohorts. Keep counter-enabled runs diagnostic-only; use identical counter-OFF runs for speed.

## Exact seams and keys

### Request/window context

`Drive` in `src/program/generate.cpp` owns `ExpertDispatch`, `ExpertSource` and the pool statistics. Add a null-by-default pointer to a fixed-size request collector and a compact immutable current-window descriptor (request ordinal, window ordinal, route mode, `T`, `K`). At the serial decode loop, set this descriptor immediately before each `ver.run(T,..., drive_pool_multi, &drive,...)`, using the loop's monotonically increasing window ordinal before it advances; clear it immediately after `ver.run` returns. `drive_pool_multi` already receives `layer` in its callback signature and sets `d.d.layers = layer`; copy `(request, window, layer, T, K)` into a stack `PoolMultiDiagContext` at callback entry. Set it immutable for the complete synchronous callback. This keys workers without changing `PoolMultiFn` (`void* user, x, ids, n_tok, k, out, layer`) or widening a hot call signature.

Do not use a mutable single `Drive::current_window` across pipeline windows. `SplitDrive` wraps the same `Drive`, and pipeline servicing can overlap windows. The first version's admission must reject `pipeline_windows > 1`, split-stage execution and batch mode before enabling the pointer. A future extension would need a per-window context passed through `SplitDrive` and each `drive_pool_multi` call, with a distinct pool per stage; it is not necessary for the current single-GPU serialized question.

When `ver.run` succeeds, the caller computes effective accepted prefix `a`, then calls `ver.commit(a+1)`. Only after that commit succeeds should it finalize the window: `committed_input_rows=a+1`, `uncommitted_verifier_rows=T-(a+1)`, `offered_drafts=T-1`, `accepted_drafts=a`, and produced visible outputs as a separately observed count. Existing source has separate speculative loops, so apply the hook to both serial callsites; ordinary `T=1` gets a distinct `ordinary_T1` window row with no draft rows. On cancellation, verify/commit error, output-cap truncation, source failure, dropped/truncated collector data or close failure, mark the whole request incomplete and do not emit a complete join. Jobs that ran for a window that later commits only a prefix remain whole jobs: record committed/uncommitted route rows, but never prorate packed bytes or measured service by accepted fraction.

### Route, job, format and source at the caller

The essential owner mapping is already in `expert_pool_dispatch_multi` (`src/core/expert_source.cpp`): after optional GPU plan and `RemoteExperts::begin` finish, `kind[i]` is the final owner for route index `i=t*k+j` (`-1` CPU, `0` primary resident VRAM, `1` PCIe, `2` helper/peer). Add only bounded integer increments under `diag != nullptr` at this final point. Count entries and distinct experts separately per owner, layer, and loaded `(gu_type,d_type)`. Keep GPU-resident and CPU owners distinct; PCIe/helper rows are not CPU jobs.

At CPU `ExpertJobMulti` construction, each job's `nt` is the number of CPU-owned route entries grouped for that distinct expert. Extend the caller-owned diagnostic scratch in `ExpertDispatch` with a bounded map parallel to `jobs_multi`: for each job slot store `nt`, exact `NativeFmt` key/geometry/blob bytes, and the route-entry ordinal for every `out[t]` element. The last field is a row ordinal (`t*k+j` or equivalently token-row `t` plus slot `j`), not a token ID. It is needed to split rows into committed and uncommitted after `a` is known. Do not assume top-k IDs are unique without asserting it or supporting duplicate rows; duplicate entries must remain separate `nt` rows if production allows them.

The immutable `NativeFmt` for the callback layer is available from `expert_layout().fmt[layer]`: record loaded `gu_type`, `d_type`, both activation types, `n_embd`, `n_ff`, row bytes, offsets and whole `bytes`. Report actual format pair per layer, not a marginal GU list joined to a marginal Down list. For each actual CPU job, logical weight extent is one `f.bytes` once; count `nt` rows separately. A shape-only work convention may derive GU `2*n_embd*n_ff*nt` MAC and Down `n_embd*n_ff*nt` MAC per job; label this dense-equivalent arithmetic, not native instruction counts or FLOPs used to divide an FMA rate.

Add a compact source-origin enum through an optional `ExpertSource` diagnostic receipt at the one CPU `blob(layer, expert)` call that first creates the job. `FileExpertSource::blob` is the right owner of the branch distinction (resident complement/RAM copy, override, staged buffer, or mapped source); generic sources can return `unknown`. An opt-in `blob_with_origin` virtual helper with a default implementation that calls `blob()` and returns `unknown` avoids a second potentially stateful blob read. Do not change ordinary `blob()` behavior when disabled. A mapped/file source origin or `file_read_bytes` counter describes the mapped source/requested logical extent, not a disk transaction; an explicit RAM complement hit is likewise not a DRAM byte count. Preserve separate fields for source origin, `FileExpertSource` read counters, `NativeFmt.bytes`, actual H2D copy bytes if a chosen route performs it, and physical traffic (unknown without a valid counter).

Retain existing route counters for cross-checks (`multi_misses`, `multi_entries`, cache hits/refused, offload entries, PCIe experts), and pool `multi_bytes`. These are aggregate logical-work controls only. Ensure per-window/layer deltas are captured around the callback, not derived from process-lifetime counters. `ExpertSource::prefetch()` must not be counted as a completed blob read or physical read.

### Actual native worker fragments and caller CPU time

In `src/kernels/cpu/pool.cpp::ExpertPool::drain`, the native `mode_>=5` path already resolves task `ci`, local expert `e`, role from `mode_` (5=GU, 6=Down), row interval `[r0,r1)`, `mjobs_[e].nt`, and `nfmt_`. A flattened task can cross expert boundaries, and the existing inner loop calls a row kernel once per expert-local piece. Place the optional timer exactly around each actual call to `native_gu_rows(...)` or `native_down_rows(...)`, after all pointers/ranges are prepared, and record a fragment. For Q2-special branches, use explicit `Q2_GU/Q2_Down` labels (including GU's gate+up and SwiGLU work) rather than falsely naming them native IQ calls. Give `native_gu_rows`/`native_down_rows` an optional out-enum/diagnostic argument, or write the selected enum inside their actual dispatch decision, so branch names reflect the function that ran (e.g. GGML fallback vs IQ256/IQ512 vs IQ4NL256). Do not predict it from CPU flags in the reporter. The extra enum output is inactive when null.

The fragment key is `(request, window, layer, loaded pair, role, actual branch, NT, participant slot)` plus fragment count and logical row range. A participant slot is stable: worker IDs `0..n_-1` are the IDs already passed into `worker(i)` / `drain(i,...)`; reserve slot `n_` for the synchronous host drainer `id==-1`. At pool initialization capture the configured worker count, `host_works`, and its pinned physical-core map once. Report logical worker slot and actual core map as separate fields; never use OS thread IDs as array indices.

For each fragment collect steady wall delta and calling-thread CPU-time delta immediately around the native row call. Linux implementation can use `CLOCK_THREAD_CPUTIME_ID`; Windows needs `GetThreadTimes`. If the CPU clock is unavailable, mark CPU-time collection unsupported; never substitute process CPU time or zero. The calling thread is also the host drainer when `host_works_` is true, so its fragment times appear in slot `n_`; additionally collect one caller CPU/wall span around the entire `drive_pool_multi` callback and serial `native_quant_h` span on the caller. These measurements overlap: report callback CPU/wall, host-drain fragment CPU/wall, caller quantization and wait spans separately, and do not sum them into a new wall equation.

Keep `wait_parked` (before and after phase) and `wait_done` as existing host wall spans or separately timed fields, plus GU, caller FF-quant and Down phase wall spans. Worker CPU sums, worker wall-call sums, per-worker first-start/last-end envelope, active drain and waits answer different questions. Fragment wall sums exceed parallel phase elapsed time by design; they are not critical path. `ms_multi_gu/q/down`, `ms_run`, and `pool.multi_bytes` retain their existing semantics and remain cross-checks, not physical memory reads or CPU busy time.

## Bounded storage and race rules

Allocate request collector, route/job scratch and worker counters at request/pool construction, before workers start. Bound dimensions from existing constants: `n_layers <= 64`, `n_experts <= 512`, `MAXT`, `kMaxWindowEntries`, `kMaxSplitMulti=96`, at most `n_workers+1` participants, two native row roles plus activation-quant/callback bins, and a small declared maximum number of windows. Aggregate into integer dimensions `(window, layer, pair_id, owner, NT, role, participant)`; do not retain expert IDs, token IDs, raw pointers, token data or tensors in the receipt. Keep a mapping from request-window-row to aggregate bin only until that window's commit is known, then fold and clear it.

If the dense Cartesian table exceeds the declared byte cap, use a sparse fixed-capacity open-addressed table allocated once before the run and fail closed on capacity exhaustion. Every add uses checked integer arithmetic and sets an overflow/incomplete bit instead of wrapping. No per-callback vector growth, heap allocation, mutex, fprintf/flush, shared atomic increment or file write inside the worker loop. Each participant writes only its own cache-line-padded slot. Caller-side window/route writes happen on the serial caller. After each synchronous `run_phase` finishes `wait_done` and final `wait_parked`, the caller may read/aggregate worker cells; reset only after all worker writes for the prior phase are complete. `ExpertPool::run_split_multi_native` batches up to 96 jobs through several GU/Down phases, so either preserve a batch index or synchronously fold each completed phase before reusing the participant cells. The context pointer must stay alive and unchanged until the last phase drains and all participants are parked.

Default OFF means no clock reads, CPU-clock syscalls, source-receipt virtual call, collector allocation, aggregation, serialization or state mutation on the hot path. Initialize/parse the opt-in once, before the decode request; the disabled path should have only a predictable null/false guard at the hook seam. Keep diagnostic result output after request completion from caller-owned memory. Clock-on overhead must be compared with the otherwise identical instrumentation-off request; report attribution only if the overhead is declared acceptable, never treat the instrumented run as the quiet speed result.

## CPU-only fixture plan

Use deterministic host-only fixtures before any model run. Fixture invocation is a future implementation decision; this report authorizes no execution.

1. **Key separation and reset:** two consecutive requests and windows with identical layer IDs but intentionally different `(pair, T, owner, NT)` patterns; interleave layers 2 and 3. Assert no bin leaks across request/window/layer and final request/window counts match exact expected numeric rows.
2. **Dedup and byte denominator:** a `T=4` routing matrix with one expert repeated for several token rows plus another expert once. Assert one `ExpertJobMulti` per distinct CPU-owned expert, `nt` equals CPU-owned rows, `multi_entries` equals entries, and logical bytes are `blob_bytes` per job, not per row. Add duplicated top-k entry if production permits it; assert either exact row preservation or a fail-closed invariant.
3. **Final-owner accounting:** fake static `host_res`/GPU-plan callbacks partition one small routing matrix across resident, CPU and PCIe owners, with helper-owner case if supported. Assert each route row has exactly one final owner, CPU jobs include only CPU rows, resident hits do not add CPU packed bytes, H2D bytes are charged only to actually submitted transfers, and unknown/mutable ownership invalidates the receipt.
4. **Fragment boundaries and identity:** run multiple CPU jobs with deliberately chosen task count so at least one flattened range crosses an expert boundary and another produces a partial row tail. Use two `NT` values and two format/pair records. Assert fragments retain the exact job NT/role/branch, fragment row sums reconcile to output ranges and no neighboring task or layer is merged. Compare numerical output bitwise/within existing production tolerance with clocks off/on.
5. **Participant identity/concurrency:** host drain on and off, multiple workers, one-worker/inline fallback, and no-work phase. Assert each worker writes only its own slot, host uses reserved slot `n_`, counts reconcile after `wait_done` plus final `wait_parked`, and repeated windows do not inherit stale slots. Validate actual physical-core mapping only if affinity was successfully established; otherwise label it unavailable.
6. **Commit/cancel/overflow:** final `a` values 0, middle and `T-1`; ensure committed/uncommitted rows partition every job-row record without prorating service/bytes. Simulate normal commit and aborted/incomplete window; complete must stay false on cancellation/error. Force table and arithmetic overflow and require explicit invalid status with no plausible partial pass.
7. **Disabled parity and overhead:** run identical deterministic fixtures with collector absent and present; output and route/job semantics must match. Assert disabled path calls no injected clock/source-origin method and emits no collector output. Measure diagnostic overhead separately, then preserve quiet timer-off sample as the performance outcome.

A test-only fake source may return deterministic packed blobs and origin labels; it must not reach a model loader or GPU. Any fixture that calls real native kernels needs valid existing CPU fixture tensors and exact format geometry; do not use arbitrary bytes that could make malformed format reads appear to pass.

## Fail-closed request validity and interpretation

Set `complete=1` only if every accepted callback/window/layer has exactly one request/window key; `sum(owner route entries)=T*K`; CPU `sum(job.nt)=CPU route entries`; CPU distinct jobs and bytes reconcile to submitted pool jobs and `multi_bytes`; actual fragment range/row/task counts reconcile to completed phases; format and source origin are known or explicitly `unknown`; every worker/host slot completed; commit prefix and output counts close; no overflow/drop/cancel/fault/unsupported owner/mode occurs; and final numerical/lifecycle gates pass. A missing or unexpected row, dispatch fallback, unknown source, queue/pool stall or incomplete commit invalidates completeness, not zero-fills it.

The output can establish per-request workload exposure, logical packed source bytes, CPU scheduled service, host waits, and actual CPU branch mix. It cannot establish L1/L2/L3 hits, DRAM traffic, disk I/O, physical CPU memory-controller bytes, CPU thermal/sustained clocks, or the GPU time of resident expert work. `mapped_blob`/`file_reads`, `ram_reads`, `prefetch`, blob extents and `multi_bytes` are source/logical counters; they must not be relabeled physical reads. Current PMU admission remains blocked as reported in R95/R206/R284. Use the 36.869 GB/s stream and `(22,20)` capacity fixture only as prior operation/control data until the exact current pair/NT/branch and a matched RAM control exist.
