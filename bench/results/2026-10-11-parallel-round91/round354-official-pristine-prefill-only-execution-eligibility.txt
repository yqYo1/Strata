## Decision

**Refuse a 32K/64K official B570 prefill run with PLE enabled under the current receipt.** The normal SYCL prefill itself contains host/device polling on pinned host-USM control words, separate from the decode CPU-expert doorbell. `--no-pool` does not disable that prefill path. The short-chunk route reaches both the expert stager's `done_seq` wait and, with PLE enabled and another chunk pending, the PLE upload's `ple_done_seq` wait. Both words are allocated with `sycl::malloc_host`; device queues write them while host threads poll via `volatile` loads. That is concurrent access to host allocations for which this runtime/device tuple has no reported concurrent-access capability. The source contains no alternate serialized PLE/stager route selected by `--no-pool`, `--no-capture`, `--no-token-graph`, `--prefill-until`, or `--max-new`.

There is no stock full-prefill-and-normal-exit mode that avoids those accesses for a long prompt. A one-chunk prompt could avoid the *inter-chunk* PLE sequence poll, but long prompts still use the expert stager and its ring-reuse poll. `STRATA_PREFILL_STREAM_ALL=0` changes which experts are staged, not the stager protocol. `--no-ple` removes PLE but explicitly changes the requested model path, so it is not admissible evidence for all-component prefill.

## Flag and call-path findings

- `--no-pool` sets the decode `pool_fn` to null and removes the hit hook (`sycl/src/program/generate.cpp:5189-5194`). In this SYCL tree there is no native prefill CPU-expert share: prefill chooses its ring from nonresident-expert share, and the prompt path streams expert blobs for GPU compute (`sycl/src/program/generate.cpp:5863-5867`, `sycl/src/prefill/prefill.cpp:121-123`, `:2225-2230`). So `--no-pool` changes the final token/decode expert service, not native prefill's expert arithmetic.
- `--no-pool` alone is not a handshake bypass. The default token graph is still captured when capture is enabled (`sycl/src/program/generate.cpp:5808-5815`); its graph includes `doorbell_wait` (`sycl/src/core/session.cpp:1219-1276`), and `session_run_token` still host-polls `h_seq` and writes `h_flag` even with a null pool (`:1335-1418`). `--no-token-graph` falls back to `session_loop`, which retains the concurrent control polling (R352). This is the same unsupported path R352 rejected.
- `--no-capture --no-pool` does bypass the *decode* doorbell: the guard requires both flags, and `session_token` directly invokes `block_layer` without the pool/doorbell path (`sycl/src/program/generate.cpp:5235-5240`, `:11797-11815`; `sycl/src/core/session.cpp:1151-1207`). It still does not make the preceding batched prefill safe, because `Prefill::run` is independent of those flags.
- For an input prompt of 65,536 tokens, `n_batched` is 65,535 by default; the prompt path covers `[0, n_prompt-1)`, then the token loop starts at the last prompt position (`sycl/src/program/generate.cpp:11601-11612`, `:11717-11729`). `--max-new` must be positive, so `--max-new 1` still performs that last position and samples one token before normal completion (`:2347-2349`, `:11981-11991`). Any output token from `--no-pool` is an intentionally incomplete GPU-only-floor decode and cannot qualify full generation quality.
- The expert-stager hazard is unconditional on ordinary long native prefill that must reuse its ring: `done_seq` is host USM (`sycl/src/prefill/prefill.cpp:362`, `:385-388`); the copy queue writes the marker (`:503-507`); `buffer_free` host-polls it with a volatile load (`:509-510`) and workers wait for that predicate before reusing each ring slot (`:445-450`). The prefill comments record this same ring-wait path as the earlier Level Zero v2 hang (`:213-220`). This is needed for streamed host-resident experts; the official stock prompt requires `--native` and native GGUF blocks (`sycl/include/strata/prefill/prefill.hpp:1-10`).
- With PLE enabled, the second polling protocol is explicit: `ple_done_seq` is host-USM (`sycl/src/prefill/prefill.cpp:701-706`, allocated at `:1061-1064`); the queue writes completion after copying PLE rows (`:2315-2325`), and before reusing the other pinned input buffer the host polls that sequence (`:2341-2345`). `--ple-sync-submit` changes table-read submission, not this device-upload completion protocol (`sycl/src/program/generate.cpp:436`, `:719`, `:1717`).
- A stock debug capture exists, `STRATA_PREFILL_DUMP_R_ALL`, for every prompt-position final residual in BF16; `STRATA_PREFILL_DUMP_R` saves every 64th residual in FP32 (`sycl/src/prefill/prefill.cpp:4440-4477`). It could support an independent residual comparison if execution were admitted, but it is not a full GDN/QSA/PLE state dump or a correctness check by itself. `STRATA_DBG_NAN` reports finite counts/max magnitudes at the prompt-end residual, PLE history, and one GDN state (`:4508-4520`), not equality to a reference.

## Measurement interpretation if the runtime contract changes

The source reports batched-prefill tokens/chunks/time separately (`sycl/src/program/generate.cpp:11717-11729`). For a 65,536-token prompt that number should be described as 65,535 batched conditioning positions, followed by one last-prompt-position token traversal and one sampled output under `--max-new 1`. A successful return and a prefill rate would qualify only that prefill workload; the generated token and full-generation quality must remain explicitly unqualified when `--no-pool` is used. Do not infer numerical correctness from the rate line or residual finite scan.

Current result: **no safe, admissible stock CLI/debug mode for >=32K/64K all-expert/GDN/QSA/PLE prefill has been established on the reported B570 runtime. Refuse pending a supported host-USM concurrency contract or a source path that serializes these prefill handoffs.** This conclusion is source-based and does not propose killing a parent process or changing pristine source.
