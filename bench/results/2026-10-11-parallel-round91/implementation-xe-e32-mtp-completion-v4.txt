Production ownership helper
---------------------------
New host-only MtpCompletion is used by the real MtpDrafter. submit() marks pending
BEFORE a residual/record copy, graph launch or state-writing initialization. Several
same-queue writers remain one outstanding allocation ownership interval. Completion
is checked through real queue callbacks, never an idle/query hint. Failed waits and
exceptions retain pending; success clears pending only after the queues are confirmed.
The first fault remains sticky after a successful drain and blocks another submission,
idle/successful reuse and host-ready status. A submission generation also lets error
cleanup recognize writes earlier in the same operation even after they completed.

MtpDrafter Operation guards cover public GPU/mapped-staging operations and capture
helpers. The guard is created before public device selection; its cleanup reselects
the drafter device after an entry failure or after the entry scope restored the caller
device. Failure to select the cleanup device fail-stops before buffer destruction.
Only an explicitly successful asynchronous operation can leave pending work.
Error/exception exits abandon any active capture, reset capture bookkeeping, then check
both cs_ and side_ and ALL registered device queues before return/unwind. Unknown
quiescence fail-stops before host buffer reuse/free. Destructor selects the drafter's
own device, retires capture and performs the same all-queue drain before graph/event/
mapped-buffer destruction. This also protects persistent E4 upload vector destruction.
Normal synchronous success paths use checked MTP stream and shared-expert branch
completion. Initialization, wait failures, sticky faults and error/destructor cleanup
also check device-wide completion, including the default compute queue. A failed MTP
stream wait followed by a successful global drain may release ownership, but preserves
the original fault and still returns failure. It never becomes successful inference.

Mapped output and chain safety
------------------------------
draft() completes earlier work before host staging/record reset. Each graph submission
marks pending first. It waits checked stream/branch completion BEFORE reading h_out_
or h_prob_ and before submitting the next step. The mapped output allocations are
retained, with plain host reads only after ownership transfer; no new D2H output route
or output allocation is needed. The volatile polling loop, _mm_pause, stream_idle
probes and fences as publication claims were removed from mtp.cpp. A completed graph
that did not publish a nonnegative draft is an immediate sticky error, not a spin.
The graph math, catch-up row selection, output padding/count, probability and min_p
chain-stop behavior are unchanged. Optional top2 copy failures now propagate as faults
instead of quietly returning an unknown diagnostic value.

prepare_chain and chain_launch refuse the unqualified current backend gate before
chain graph preparation, mapped chain staging or writer enqueue. chain_outputs_ready
also refuses the gate. Existing outstanding work is safely drained at these boundaries;
a clean refusal with no new submission does not poison an otherwise healthy drafter.
For completeness, even the dormant qualified chain output readers now wait for the
ENTIRE writer chain before any host read: per-step event completion never grants CPU
access while another step writes a different region of the same output allocation.
chain_poll is therefore a checked, blocking whole-chain completion operation rather
than an unchecked event-query poll. No event_query call remains in this source.
For dormant chain submission, chain_live_ and pending begin before any source residual
copy/partial graph launch; a rejected launch/event record is drained and sticky rather
than forgotten. The live mark clears only after successful whole-allocation completion
and host output transfer. No unsupported async chain is silently approximated.

Prefill, staging, capture and copy lifetime
-----------------------------------------
E4's upload source changed from a function-local vector to pf_host_, owned by the
MtpDrafter. The entry completion boundary runs before resizing or writing it. Thus
prefill(sync=false) can retain queued device work without freeing its host record
source; a later operation/idle/destructor drains before rewrite/free. Returned async
success is still only enqueue success; the caller must retain R_rows and order/wait
on stream(). Errors retire those borrowed residual readers before returning.
The per-group mapped-input path waits after EACH graph before the next CPU record
write. Both paths check their copy/launch errors; failed submissions remain pending
until checked cleanup. Prefill validates its physical span/required pointers before
staging. Actual no-skip/full-context behavior remains owned by the v3 caller.
prepare_prefill checks completion before replacing pf_dev_. Cached immutable graph
lookups do not inspect/rewrite mapped input storage and do not wait each E4 group;
a fresh capture waits first, and later caller staging still requires completion.

finish_capture now checks end_capture and completion instead of ignoring its wait.
Failed body/capture and exceptional recording abandon the capture before queue cleanup.
Capture is recorded graph construction, not an executed state writer; no capture-only
success is claimed to prove graph execution. The existing void abandon_capture API
has no independent return status; checked queue completion and sticky state rejection
are the execution/lifetime qualification used here.

All formerly ignored synchronous copies/memsets/device waits in MTP load/bind/coupled
setup are checked. copy_checked has its own nested lifetime guard, so even a failed
compute-queue copy or exceptional completion drains before a caller's local dense/
expert/vocabulary/index vector can die. State initialization/fallback and head gather
mark pending before kernels; their completion is checked. Source layout/math is
unchanged. No precision conversion or expert-file layout was changed.

idle() reports a sticky fault even when ownership has drained. kv_restore retains its
void API but throws on bounds/transfer/completion failure and fail-stops on unknown
quiescence, instead of silently ignoring stream_sync failure. set_draft_sampling and
set_draft_history likewise retain their void APIs, complete earlier mapped readers
before host writes, and throw on a sticky fault. Those errors must be handled by the
caller or end the process; this role did not modify forbidden caller source.
