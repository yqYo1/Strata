CLI and source boundary
-----------------------
New opt-in: --full-context-probe TERMINAL_TOKEN_ID.
Requires an actual native pack, --native and --mtp, --spec >=2, exactly 262144 input
IDs, --max-context 262144, --max-new 0, fixed positive --prefill N (no auto), and
--no-prefill-borrow. Requires a positive draft window smaller than physical capacity,
and checks the actual draft KV mode is a resident ring (mode 2). Token IDs, including
the terminal probe ID, must be nonnegative int32 values within actual vocabulary.
Strict numeric checks for max-context/max-new are applied only to this diagnostic;
ordinary parsing/behavior is retained.
Rejects serve, batch/group/slot/split/remote GPU paths, vision, partial-prefill,
hardware/kernel/graph/full-GPU/stage benchmarks, output dumps, oracle/follow/corrupt
and window-hash paths, explicit async adaptation/elastic KV, PLE ablation and missing
capture/CPU pool. An argv preflight rejects the early hardware/kernel benchmark
bypass before it can execute. Verifier device tuning is skipped for this mode.
No model/vendor/device-name gating, CPU dispatch change or expert-math change.

The branch reuses normal session, MTP, CPU pool and Prefill initialization, then
returns directly from the MTP-bound Prefill branch. It invokes Prefill::run with
n=262144,pos0=0 and verifies ss.max_cells and every owned main/draft QSA capacity
are exactly262144. It never reaches normal n_prompt-1 batching, tokens[pos_start],
verifier/sampler, or kvg_ensure(n_prompt+max_new+64). Elastic KV is disabled for this
mode independently of its environment override, so there is no hidden capacity
increase or lookahead beyond the physical session.

Draft full extent and terminal safety
------------------------------------
A further source finding beyond R350: MtpDrafter::first_needed() normally skips old
prompt rows outside prompt_len-window-64. Both E-9 and ordinary MTP prefill honor it.
The diagnostic sets prompt_len=0 before load and checks first_needed()==0, so ALL
262144 draft rows are written, not merely the final window.
The production host-only helper validates the entire successor span before indexing.
Rows0..262142 use real input IDs at cell+1. Exactly row262143 uses the explicit
terminal storage probe ID. Logs state real_next_rows=262143, probe_rows=1 and no
prediction-quality claim. No token index262144 is read.

The diagnostic intentionally uses production MtpDrafter::prefill's synchronized
per-group path, selected by STRATA_MTP_PREFILL_SYNC=1 before its first invocation.
It bypasses E-9/E-4 temporary record uploads. This avoids their local host staging
vectors on early asynchronous enqueue/graph failure without editing forbidden
Prefill/MTP source. The selected path uses persistent mapped records and a checked
stream wait before the CPU changes them for the next group. It records KV only,
not a speculative prediction or attention at position262144. This is slower and is
not a benchmark of either batched draft path. This process exits after the probe,
so its diagnostic environment override cannot alter a later normal request.

Lifetime and errors
-------------------
Copies/memsets use the existing synchronous gpu API, whose Xe implementation waits
on the submitted event with Runtime::wait(event.wait_and_throw + async check); stalled
waits already fail-stop under the Runtime watchdog. Added guards drain all registered
queues before owned snapshot/checkpoint/callback/poison buffers die, including exceptions
and failed init/bind. The poison workspace has its own guard declared after it. An
unsuccessful queue drain terminates the process; it never frees uncertain in-flight
storage, resumes inference, or converts an error into a pass. The callback is cleared
on every diagnostic exit. Direct operation errors preserve actual runtime messages.
