# R152 — production reachability of active route grouping

Date: 2026-10-10 (Asia/Tokyo). Read-only trace of production prompt scheduling against the immutable active-route-group snapshot and unchanged WPROBE generate/API sources. No source edit, build/compiler, test/runtime/model/payload, GPU/profiler, Git, lock, cleanup, service, or reset operation was performed. The report determines source reachability only; it does not claim that an opt-in binary was built or that the candidate ran.

## Finding

The active route-group gate is **unreachable on every `run_layer_major` invocation**, including a 32K+ layer-major request. It is reachable in principle only from the ordinary, full-layer, noncompact `run_impl` path with no chunk/stage callback, no stage/helper/peer handoff, and a current chunk of at least 1,024 tokens, provided the loaded per-layer native format is IQ3S (`gu_type==21`) and all other gate predicates pass.

There is also a one-token boundary for the ordinary CLI. `generate.cpp` calls `prefill.run(..., n_batched, ...)`, where the normal initial prefill count is `n_prompt - 1` because the last prompt token is handled by the generation loop. Thus an input of exactly 32,768 prompt tokens passes `n=32767` to `Prefill::run` and cannot satisfy the gate's `n>=32768`. At least 32,769 prompt tokens (or an explicit `prefill_until` of at least 32,768) are required to reach the long-request predicate. A root A/B that uses a 32,768-token prompt or layer-major mode will record zero candidate selections even with the build and env opt-in enabled.

The usual CLI route can reach the candidate if run without layer-major mode, MTP callback, compact mode, multi-GPU/stage/helper route, and with the exact native-IQ3S metadata; source establishes this possible route, not that the currently selected model or runtime meets it. The current server path installs an `on_chunk` callback unconditionally, so its `run_impl` calls fail the candidate's `!on_chunk` predicate even when layer-major mode is off. No measured selection was available to this audit.

## Call-chain trace

1. The normal generate path creates `Prefill`, initializes its chunk workspace, and calls `prefill.run(o.tokens.data(), n_batched, 0, err)` (`generate.cpp:11707–11713,11756–11758,11801`). The standard `n_batched` value is `n_prompt-1`; only an explicit `prefill_until` strictly between zero and `n_prompt-1` replaces it (`:11713`). The comments at `:11703–11704` explain that the generation loop starts at the last prompt position.
2. `Prefill::run` chooses `run_layer_major` only when `STRATA_PREFILL_LAYER_MAJOR` is set to `2`, or is `1` and the request is multiple under the source's `n > m.T || (first > 0 && first < m.T && n > 2*first)` test. With the variable unset, it calls `run_impl` directly (`prefill.cpp:2353–2362`). A 32K+ request with mode `1` and a smaller configured chunk is normally multiple and therefore enters layer-major; mode `2` forces layer-major.
3. `run_layer_major` requires a full single-GPU compact FP16 route (`:2422–2425`). It iterates layers; for each layer it sets `stage_lb_=layer`, `stage_le_=layer+1`, installs `on_stage_chunk` and `on_chunk` lambdas, then calls `run_impl(tokens,n,pos0,err)` with the whole request length (`:2742–2768`). So although `n` itself can pass 32K, the route-group predicate is false independently at `!m.compact`, `!on_chunk`, `!on_stage_chunk`, and `LB==0 && LE==g.n_layers`. For later layers `hand_in_` is also non-null. No chunk length or format can make layer-major reach device grouping.
4. Ordinary `run_impl` loops over the request using `chunk_len(c0)`, with whole-call `n` unchanged and per-iteration `T=chunk_len(c0)` (`:2934–2940,2979–2988`). The gate is evaluated inside each MoE layer on that current chunk (`:4110–4118`). The default short-first-chunk policy may make `T=256` for the first chunk when all experts are cached; that chunk stays on host, but subsequent full chunks can pass `T>=1024`. A final tail shorter than 1,024 stays on host. The 32K threshold tests the run_impl request length, not the current chunk length.

## Other production entrypoints and disqualifiers

- **CLI `generate.cpp`:** `on_chunk` is only installed in the `if (!o.mtp.empty())` block (`:11762–11778`). With MTP disabled it remains empty, so an ordinary one-GPU full-layer call is not callback-blocked. If MTP is enabled, that callback alone prevents selection. The stage callback is absent in this ordinary non-multi-GPU route.
- **Server `generate.cpp`:** the serving prefill path assigns `sp.on_chunk` unconditionally to report prompt progress and handle checkpoints (`:7624–7669`). Therefore it never meets `!on_chunk`, independent of MTP selection. In multi-GPU serving the callback is moved to the last stage and each stage receives `on_stage_chunk` (`:7670–7687`), while stage bounds/next pointers also disqualify it.
- **Layer-major:** independently unreachable for the reasons above; it is not a viable route-group qualification mode. This is intentional per R146/R150's narrow ordinary noncompact route, not an implementation regression if qualification is explicitly scoped to that ordinary route.
- **Multi-GPU/split/helper:** stage configurations set partial layer ranges and/or `next_`, `hand_in_`, `helper_`; the gate excludes these (`prefill.cpp:4112–4118`). A one-stage ordinary route must still establish `no_peer`, `m.pp==nullptr`, and `pe.on==false` at selection time.
- **Compact/fused/MMQ/native type:** `compact_prefill()` is opt-in (`STRATA_PREFILL_COMPACT=1/2`) but, when selected, makes `!m.compact` false. The gate requires `!m.fused_bufs`, `!use_mmq`, `!fused_l`, `lay.native`, and `mmq_gt==21` (`prefill.cpp:993–1005,4017–4026,4112–4118`). R146 establishes the compiled SYCL MMQ/fused stubs leave `use_mmq` and `fused_l` false, but the actual ExpertLayout type must be reported from the loaded model. The code gate does not prove IQ3S metadata.

## Smallest qualification discriminator

The root should qualify the route using a one-line counter/record exactly where `device_group` is assigned, with one record per MoE layer and chunk: total `run_impl n`, current `T`, `c0`, `LB/LE`, compact/fused/MMQ flags, `lay.native`, `mmq_gt`, peer/helper/hand-in state, callback-presence bits, supported-capacity/in-order result, and final selected boolean. Aggregate selected count and report the first/last selected `(layer,c0,T)`; require a nonzero count for candidate A/B. Existing `STRATA_TRACE` reports chunk length and layer bounds (`prefill.cpp:2982–2985`) but not the callbacks, native type, or candidate boolean, so it is insufficient as a selection receipt.

For the narrow intended CPU/GPU qualification route, use ordinary CLI `prefill.run` (no `STRATA_PREFILL_LAYER_MAJOR`, no MTP callback, no compact request, no stage/peer/helper path), and ensure `n_batched>=32768`—for the standard `n_prompt-1` path this means at least 32,769 actual prompt tokens. Keep a configured chunk that yields at least one `T>=1024` chunk. Confirm selected native IQ3S layer(s), then compare candidate maps/results against the host route with identical model, input, chunking, expert source/cache and environment. A run that is intentionally layer-major, server callback-driven, exact-32,768-prompt, or has no eligible IQ3S layer is not a valid selection or candidate A/B; its zero count is expected and must not be reported as a candidate slowdown or correctness failure.
