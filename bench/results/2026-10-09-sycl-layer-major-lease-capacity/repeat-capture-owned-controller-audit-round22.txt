## Admission blockers and bounded changes

1. **No capture framing/content validation.** `request()` records `capture_before_bytes`/`capture_after_bytes` and appends begin/end offsets, then checks only that the full prompt grew the file and non-full prompts did not (`request` around lines 560–624). It never opens `repeat-rows.bin` to parse records. The production header is 12 native-endian uint64 words, 32-byte zero-padded phase, then payload (`repeat_capture.hpp:58–66`); it includes magic/version, layer, p0, T, first row/count, element count, type, width, global record ordinal and header length. The controller must parse safely with explicit file-size/offset bounds; verify magic/version/header size, monotone ordinal, allowed phase/type/layer, `elements == rows * width`, payload byte count, expected 98304–98335 rows, and no truncation/trailing bytes. Reject unknown records and assert one complete expected record set per capture-producing GEN. Derive expected phase/layer counts from the actual instrumentation rather than assuming a fixed number. Validate each request's captured subrange is exactly the records appended between its before/after offsets. Retain compact per-record metadata, offsets, and payload SHA-256 in the receipt; do not duplicate the large payload in JSON.
2. **No explicit expected controller digest.** The script records its own digest late in `source_sha256`, and pins engine sources and binary, but has no admission constant for the reviewed controller's own digest. A self-recorded digest is provenance, not a pin: changed controller text would still run. Root should compute and freeze the review-approved controller SHA before launch and assert it at the invocation boundary or in the supervisor. Include the parser implementation and report version in that hash. Likewise preserve the exact runner-helper/health-script digests checked by the run, not just the derived runtime behavior.
3. **Capture close is checked, but only as a text sentinel.** The C++ singleton closes its descriptor at process teardown and emits `repeat capture close failed` on a close error (`repeat_capture.hpp:52–55`). The controller checks this substring in the entire engine log after orderly QUIT, which is a useful guard. Keep the check and additionally require the parsed record stream to terminate cleanly and its final offset to equal the file size; this catches incomplete final header/payload even if the warning is absent. Capture errors during a prompt become `ERR` and fail the request, but a final parser is still needed to validate successful writes.
4. **Ledger semantics need a hard completion assertion.** The `capture_request_offsets` list is not itself validated against `requests`, and the saved record has no parser-derived capture summary. Before setting `completed=True`, require exactly two intended full-prompt capture intervals (full1 and full2), empty intervals for other GEN requests, no overlap/gap in the append stream, and no records outside those intervals. A mismatch or incomplete parser must leave `completed=False`, `healthy=False` or a distinct `diagnostic_complete=False`, and never permit a mathematical pass. Do not count an empty interval as proof that no stale record was consumed unless its beginning is the previous validated end.
5. **Lifecycle diagnostics remain bounded.** The script's final `full_lifecycle_passed=False` is correct. Even if both captured repeats compare equal, this run omits the clipped 2-token verification tail, RESTORE equivalence, refusal safety, and later control; do not call it full-cycle qualification or source adoption. Any synchronous capture failure or success can mask/order-shift the original race; report parity only for this instrumented build and preserve this limitation.

## Remaining control flow / edge review

- The main preflight runs before output creation and model launch, and `--cpu-preflight` exits before hardware interaction. The lock is held for the actual run and a conflicting run fails fast. A failed launch can leave its private diagnostic directory as evidence; it does not silently delete it. The five-GEN sequence uses fresh reset checks (`RESUME`/`REUSED` zero for fresh requests); the resumed control is expected at token 32831. The full requests compare `len(tokens)-1` consumed-prefix state and save count 262143, consistent with the final emitted token not yet fed back.
- `poll()` enforces a 64 MiB aggregate non-binary file limit and global timeout; `Runner.run` also has its bounded probe-output loop. The 128 MiB capture file has a separate engine-side cap. In the engine, capture is enabled only for a chunk intersecting rows 98304–98335 and layers 0–12; synchronous queue readback and bounded POSIX private-file creation are explicit (`prefill.cpp:3540–3559`, `repeat_capture.hpp:58–112`). This is intentional diagnostic instrumentation, not a clean timing configuration.
- Catch/cleanup handling records snapshots on exceptions and always closes the owned GDB/process and descriptors. However, after a non-math exception during `finally`, later fault-probe/`save()` errors may obscure the initial problem or prevent a final record; keep original exception context primary and ensure cleanup/probe exceptions are separately recorded. This is secondary to the absent parser, not a reason to broaden this capture run.
- The diagnostic corrects `scope` and compatibility notes by forcefully setting full lifecycle/adoption/performance flags false, even after normal model completion. Keep that behavior. The probe cursor begins after the kernel-before marker and the after-cursor query is bounded; “no new fault” applies only to captured cursor window and matched device filters.
