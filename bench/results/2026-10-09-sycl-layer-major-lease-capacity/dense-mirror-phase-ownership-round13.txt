## Finding

There is no source path here that lazily creates a persistent FP16/BF16/FP32 dense-weight mirror during first main-cache restore or Verifier recapture. Prompt `Gemm::native()` dequantizes rows of one dense projection into its already allocated FP16 scratch and immediately submits the GEMM; it retains no expanded weight view. Native GGUF dense loading and the optional packed-Q8 copy happen during model load. MTP `dense.bin` is copied at `MtpDrafter::load()`, and optional Q4 conversion also happens there. These paths cannot explain the first-restore free-counter change on their own. The first-restore 1,280,585,728 B decrease remains unassigned; the later 403–408 MiB observation must likewise not be attributed by resemblance to any requested allocation.

For the ordinary packed-weight path, `WeightTable` loads engine-form dense tensors into the model's device arena. They stay referenced by `WeightRef::data` and serve inference. BF16-in-F32 conversion is part of load, not a deferred view. If native GGUF overrides are enabled, `NativeDense::load()` creates device copies for supported GDN/QSA matrices and publishes each address into `WeightRef::native_data`; these same tensors feed prompt projections and decode. `core/layer.cpp` and `core/verify.cpp` use native pointers for decode; `prefill.cpp::native_proj()` passes the same pointer to the prompt GEMM. `NativeDense` owns the allocations until destruction. The graph warm path captures verifier and MTP decode work after prompt at `generate.cpp:12285-12296`; dropping shared native data under those graphs is invalid without retiring/rebuilding every consumer.

The `Gemm` prompt dequant buffer is explicit and not a hidden mirror: `GEMM_SCRATCH = 32 Mi FP16 elements = 67,108,864 bytes (64 MiB)` in `prefill.cpp:845`, carved from the prompt arena in `:1225-1228` and rebound during relayout at `:1411-1413`. On the native path `Gemm::native()` uses it as an output buffer for each dequantized matrix (or row slice when `N*K > scratch_elems_`) and immediately feeds that buffer to `f16()` (`gemm.dp.cpp:876-897`). It is therefore prompt-only scratch, already within the known prefill workspace accounting; it is not an additional persistent allocation to reclaim. The existing prompt reset/lazy-reinit lifecycle from rounds 6-8 already covers the arena as a whole, so I do not repeat it as a new proposal.

MTP has a separate dense allocation. `MtpDrafter::load()` reads `dense.bin`, allocates `dense_` for the full blob, and uploads it (`mtp.cpp:392-442`). MTP `draft_kv` is called from each prompt `on_chunk` callback (`generate.cpp:7595-7600`), and the dense projection accessors are also used by draft/decode. Thus dense tensors are shared across prompt K/V projection and decode. MTP QSA K/V state is written by prompt `draft_kv` and needed later; neither it nor the MTP dense blob is prompt-only. The existing draft expert/head lease does not release either.

## One conditional mirror candidate, not an attribution

Only if the run actually sets `STRATA_Q8_PACKED=1` and `NativeDense::load()` reports eligible Q8_0 tensors, a narrow prompt lease could release the *additional packed decode copies* while prompt work uses the original GGUF blocks. `native_dense.cpp:278-317` creates a second allocation of `bytes` for eligible Q8_0 matrices; it retains the original `native_data` because the prompt GEMM reads it, while `native_q8_0_packed_register()` maps the original pointer to the packed decode address. Requested packed bytes are exactly `P = Σ_i native_mmvq_weight_bytes(type_i, ne0_i, ne1_i)` over matrices that pass the current Q8_0/eligibility conditions (the code's `packed_bytes` sum); no actual count or total is inferred for this B570 run. This candidate does not change quantization or prompt math and does not release the original dense weights.

The safe ordering would need explicit source work: before prompt, drain decode queues; discard every graph that captured the registered packed addresses; unregister the mapping and free the packed allocations; run prompt against original `native_data`; rebuild packed buffers from that still-live immutable native GGUF copy; register the new mappings; then warm/re-capture all verifier/MTP consumers before decode. For later requests this also requires a supported all-consumer graph-retire/rebuild boundary before each prompt. Existing cache graph retirement covers cache-dependent verifier graphs, not necessarily every graph/address consumer; matching VA alone is not enough (round 11). Do not implement unless the actual env and loader report prove `P` is material and a source audit identifies a complete retirement API. Measure the before/after requested allocations and free bytes independently, then compare prompt+first-decode time and full output/state parity. If `STRATA_Q8_PACKED` is absent, this candidate is inapplicable and explains none of the observed counter delta.

I found no second dense-mirror candidate with a defensible benefit under exact semantics. In particular, MTP `--mtp-q4` creates an alternate Q4_0 copy of all Q8_0 dense projections while preserving the original Q8_0 blob (`mtp.cpp:297-324`); it changes weight representation/outputs and is opt-in quantization, not an exact prompt-only mirror lease. The Q4 head is rewritten in place, not a second dense mirror. The source does not establish that either optional mode was active in the stated full-context request.

If there is no packed copy, close this hypothesis. If there is one, collect allocator-owned sizes at model load, before prompt, after prompt, and after graph capture; a free-memory delta alone cannot name an owner.
