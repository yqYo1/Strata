## Source ownership trace

1. **Authoritative state is per-QSA host USM; the temporary stage is one prompt-wide device scratch.** `qsa_state_init()` allocates each streamed state’s pinned host pools as a contiguous identity `[page][KV head][cell][feature/group]` layout and sets up its page table/map (`sycl/src/core/layer.cpp:781-979`). For the target plain INT8 format, each page contains K codes, V codes, K scales, V scales. `qsa_state_zero()` resets the streamed resident map and indexer, but intentionally does not clear host K/V (`:985-1020`); its comment says that no cell is read before the sequence writes it. A fresh `pos0=0` run therefore depends on writing every cell it will read before attention.
2. **`m.stage` is independently owned in this run and sized for the full primary-QSA geometry.** `take_stage()` allocates `n_pages * n_head_kv * page_size` rows for the active KV representation (`sycl/src/prefill/prefill.cpp:764-790`). With `STRATA_KV_STAGE_OWN` set, it uses its own allocation list rather than the borrowed prompt region; `Prefill::init()` records that memory in `Impl::owned`, and only `Prefill::release/reset` frees it (`:800-841, 1200-1217`). The identity table is generated once from all primary-QSA pages (`:1200-1217`). Admission requires every QSA to match primary `max_cells` and page count, plain INT8/no rotation, all host/device/page-table pointers, 256 head dimensions, two KV heads, all QSA states on one GPU, and in-order `m.cs` (`:2398-2444`). These checks exclude mismatched QSA geometry and the borrowed-cache alias in this receipt.
3. **One owner exists per `run_impl()` invocation, which layer-major makes one layer at a time.** `StageOwner` is stack-local (`:2874-2895`); QSA ordinal counts preceding QSA layers. Each chunk must equal its expected contiguous `scheduled_cells`, and the updated extent advances only after the append is enqueued (`:3764-3792, 3849-3855`). Layer-major drains the previous compute/copy/Stager work before loading a new layer, waits expert DMA/Stager before compute, then calls `run_impl()` for exactly that layer (`:2683-2715, 2730-2785`). The stage contents are therefore reused across QSA layers, but owner metadata and enqueue range restart per layer; there is no carried logical owner across requests.
4. **For a fresh start, there is no prefix seed. Each chunk appends host authority and stage before attention on the same queue.** At `p0=0`, the seed count is zero and `kv_stage_from_host()` is a no-op. For resume only, the code copies `floor(p0/4)` complete pages and then exactly `tail=p0%4` valid rows and scales for each KV head (`:3771-3792`); this branch is absent in this failure. `kv_append_kernel` writes the resident ring only when the real page map maps that page, but separately writes host authority and stage using identity `row_id = ((pos/page_size)*2 + kv_head)*page_size + pos%page_size` (`sycl/src/prefill/kernels.dp.cpp:1954-2021`). The `*2` matches the admission check `n_head_kv==2`. Append and attention run on in-order `m.cs`; stage seed memcpys, host/stage writes, and QSA attention are sequenced there (`prefill.cpp:3775-3859, 4026+`). At successful `run_impl` completion, `m.cs->wait()` retires the stage writes before the callback/return; the layer-major outer guard drains compute/copy/Stager before restoring or freeing transient cache resources (`:5330-5345, 2693-2702`).
5. **The expert Stager is not the KV stage.** Layer-major Stager jobs source expert blobs and copy them through `m.copy` into the temporary `layer_cache`; it waits `m.copy` and `finish()` before calling `run_impl` (`:2730-2759`). `m.stage` is a separate `KvHostPools` object. Its lifetime lasts across the request/workspace; every fresh QSA layer/chunk overwrites the rows before use. The intervening 32K request writes only `[0,32768)`, but the repeated full request overwrites each 8K prefix chunk before that chunk’s attention. Since the full run is aligned and fresh, stale stage tail bytes cannot explain a divergence by themselves unless some consumer reads beyond the current causal/indexer-valid range.

## Assessment and ranking

**No concrete retained-stage ownership or page-alias defect is established by this source audit.** Per-layer ownership, geometry checks, fresh-position append, host+stage dual writes, in-order consumption, and successful queue drains are internally consistent for this run. Stage reuse alone is not evidence of contamination: the stage is scratch, not saved session state, and every full-run cell is rewritten before its chunk is consumed. The previously reviewed resume partial-page seed path is mathematically consistent, but it is irrelevant to this `pos0=0` receipt.

The narrowest remaining stage-related uncertainty is whether the *first differing QSA group's* host authority and stage contents are already different before attention, or whether they match while attention/indexer consumption diverges. Existing snapshots hash serialized live QSA state, not the transient `m.stage` at its consumer boundary. The failure beginning at a later QSA group does not by itself prove that group’s local owner is wrong; upstream layer/residual/indexer changes can propagate to later QSA state.

A lower-ranked asynchronous-error path also remains a source/API limitation, not a root-cause claim: normal `.wait()` calls are retirement fences when they return, but they do not necessarily deliver queued asynchronous exceptions to the handler. This receipt’s `healthy`/no-fault result is not an async-handler receipt. An unreported async execution error could leave completed-but-invalid state; no evidence in the record shows one, so do not promote this to a GPU fault or assign it to the stage.
