## Scope and evidence

The parent’s current physical-boundary receipt passed the 262,140 + 4 case through last cell 262,143, with full state (including inactive MTP/config) matching and no fault. The first 256K prompt was 830,132.7 ms, but this is not a clean timing result and has no GPU phase attribution. Normal consumed-input save count here is 262,143: the final emitted token is not fed back into the model. Do not use the wall time as evidence for any individual kernel.

The shape and call-path facts below come from `include/strata/kernels/qsa.hpp` and `src/prefill.cpp` / `src/kernels/cuda/{native_qsa_indexer,qsa_select}.dp.cpp` in that frozen tree. The QSA has 24 query heads, 2 KV heads, head dimension 256, four indexer heads of width 128, four-cell pool blocks, and a top-k of 2,048 cells. The selected width is at most 2,051 cells. `kTopkMaxCells=32768` is a capacity setting, not the model’s top-k.

Layer-major prefill processes chunks of 8,192 tokens. For the audited physical maximum, the scorer scratch is `[256, 65538]`, about 64 MiB, reused. The full-context selection path scores up to 65,536 four-cell blocks per query before exact radix top-k. A rough full-prompt sum is about 8.59 billion query/block pairs per QSA layer (`n²/8`); this is an operation-count estimate, not a timing. On SYCL, `qsa_block_scores_tc` is explicitly unavailable, so the portable block-score kernel runs. The prompt top-k variant is bounded to reach ≤2,304 blocks; full-context rows use the general one-work-group-per-query radix path. The QSA attention consumes up to 2,051 selected cells in 33 chunks of 64. The existing prompt XMX path is separate, opt-in, and not evidence that the current score or attention path uses XMX.

## Ranked mechanisms to measure

1. **Parallelize the indexer append over completed four-token blocks.** `native_qsa_indexer_append_batch` runs for each prompt chunk, but its SYCL launch is a single 256-work-item group whose append loop advances `step_idx` serially with barriers and reductions. At an 8,192-token chunk this serial dependency spans 8,192 steps, while completed four-token pool blocks are independent. A block-parallel path is the strongest source-grounded candidate if `kPfQsaIdx` is material. Preserve sequential per-token arithmetic and raw-indexer state exactly: FP16 round-trip of raw rows, reduction order, 0.25 FMA, norm/RoPE order, canonical spare/dead cell, partial tail and block positions. Use a fallback for nonaligned resume/chunk prefixes if needed. Compare every pooled index, dead/spare row, raw tail and position through the 262,143 boundary, plus selected cell IDs and logits. This is a hypothesis from the kernel’s launch/loop structure; no speedup has been measured.

2. **Multi-CTA exact radix selection for long rows, gated by `kPfQsaSel`.** Full-context rows exceed the small prompt variant’s 2,304-block reach and fall back to one CTA/query. Parallelizing histogram/count and threshold/tie compaction across CTAs could raise utilization, but adds launches and scratch. Keep the existing exact ordering key, width weighting, deterministic tie rule, and scan order; do not approximate or alter selected IDs. A vLLM Qwen3.8 report documents greedy nondeterminism near the indexer budget from persistent top-k, reinforcing that selection ordering is part of correctness, not just a quality metric: https://github.com/vllm-project/vllm/issues/54521. This is conditional on phase timing; it is not automatically worthwhile merely because the row is long.

3. **Tile-union selected-K/V gather for adjacent query rows, gated by overlap and `kPfQsaAttn`.** Reuse K/V cells gathered for a small tile of adjacent queries while applying each query’s exact selection mask. A vLLM RFC reports 87–94% compressed-block Jaccard overlap in its Qwen3.8 8K dumps and a tile-union path 1.50× faster than its corrected current-main attention kernel on an 8K GB10 replay; its whole prefill TTFT gain was about 2.9% on one box. These are NVIDIA/vLLM measurements and do not predict B570 SYCL results. The issue calls out numerical differences from summation order, multi-request tile boundaries, scratch/union width, and a small end-to-end ceiling; do not transfer the speedup claim. Strata already has `STRATA_SEL_OVERLAP` instrumentation, so first use the measured overlap and phase timers. Any experiment must retain every row’s exact selected IDs, causal tail, and per-row softmax semantics, then compare output logits/state. Source: https://github.com/vllm-project/vllm/issues/55394.

## Measurement gate and limits

First attribute `kPfQsaIdx`, `kPfQsaSel`, and `kPfQsaAttn` on the target GPU at 32K, 131K, and 262K with identical exact state/logit baselines. The existing 830-second receipt cannot rank these mechanisms. Do not reopen workspace allocation, add a 1.25-GiB 32K residual plane (the existing `R_GPU/inplace` work already occupies this design space and later headroom is about 450 MiB), or change host KV authority, stage/append, save/restore, selected-page coverage, or canonical indexer spare/tail state as part of these kernel investigations. Resumed position-zero stage seeding is a copy/host-to-device path, not the fresh-position-zero compute path; do not attribute it to QSA kernels.
