## Source invariants that matter at chunk and page boundaries

- QSA geometry is 4-cell pooled blocks (`include/strata/kernels/qsa.hpp`); selected attention uses exact selected cell IDs and the layer-major path appends the whole chunk before querying its rows (`sycl/src/prefill/prefill.cpp:3865-3900`). The indexer batch path is already parallel over completed blocks: `native_qsa_indexer_append_batch` computes inclusive completed-block bounds and launches `append_blocks` workgroups (`sycl/src/kernels/cuda/native_qsa_indexer.dp.cpp:291-355,481-562`). The old per-token path remains behind `STRATA_INDEXER_PER_TOKEN` for comparison. A claim that the current batch serializes all 8192 tokens is incorrect.
- Incomplete trailing cells live in `idx_tail`; completed blocks use raw indexer rows rounded through FP16, summed in source order, normalized, then RoPE-pooled; the spare/dead row and `idx_block_pos` are also updated (`native_qsa_indexer.dp.cpp:291-375`). Therefore a row-boundary comparison must include tail slots, dead row, pooled rows, block position, and selected IDs, not just the final output or completed pool.
- Chunk batching creates important transitions at 4-cell pooling boundaries and page boundaries. The first changed cell 98328 is 24 cells past chunk start 98304, not itself a 4-cell boundary. Compare each intermediate chunk's K/V bytes and scale bytes as well as indexer tensors; this distinguishes QSA append/quantization from selector/attention effects.
- The report registry and R13/R15 already cover possible top-k and tile-union performance ideas; those remain hypotheses. First rule out state carry, stage ownership, and exact row-boundary behavior. The resident-slot resolver (`kv_stream.dp.cpp:359-414`) is not a substitute for prompt identity staging: a finite page mapping can evict selected pages and change semantics unless every required selected cell remains addressable.

## Cross-engine evidence and limits

The strongest directly relevant external proposal is vLLM's Qwen3.8 QSA tile-union RFC. It reports that neighboring rows in an 8K selection dump share 87–94% of compressed blocks and describes gathering a union once for several query rows; the RFC reports −4.7% TTFT on GB10. It is explicitly a proposal/measurement on a different NVIDIA GPU and implementation, not a B570 result. It supports measuring selection overlap and gather duplication, not importing its speed claim or changing Strata's exact attention order. [vLLM QSA tile-union RFC #55394](https://github.com/vllm-project/vllm/issues/55394).

A separate vLLM issue reports nondeterministic `persistent_topk` sets near/above the QSA indexer budget when many values tie at the cutoff on GB10. Its author distinguishes non-deterministic order from changed selected sets and corrects an earlier interpretation. This is a useful correctness test design: record cutoff tie counts, exact selected sets/order, and only compare visible output prefixes. It does not establish that Strata's radix top-k has the same bug; Strata must retain its own deterministic tie/order contract. [vLLM persistent-top-k report #54521](https://github.com/vllm-project/vllm/issues/54521).

SGLang's QSA integration issue documents a different illegal access under concurrent Qwen3.8 prefill on H20 and cautions that a D2H synchronization point can report an error originating earlier. This is a useful diagnostic lesson: attribute asynchronous faults to the originating queued kernel and preserve the first failing kernel/driver evidence. It is an unverified community issue on H20, not a Strata defect or B570 prediction. [SGLang QSA extend issue #37633](https://github.com/sgl-project/sglang/issues/37633).

The current SGLang attention-backend documentation describes DSA backends and exact adjacent-query index-union options, but DSA is a related sparse-attention design, not Qwen3.8 QSA. [SGLang attention backends](https://github.com/sgl-project/sglang/blob/main/docs/docs/advanced_features/attention_backend.mdx). llama.cpp's Qwen3-Next implementation is useful for the hybrid recurrent-attention architecture, but its recurrent-state machinery does not provide a directly comparable paged-QSA boundary implementation. [llama.cpp qwen3next.cpp](https://github.com/ggml-org/llama.cpp/blob/master/src/models/qwen3next.cpp). I found no primary Intel llm-scaler source establishing a matching Qwen3.8 QSA/indexer implementation or a transferable boundary optimization; its general XPU/cache material should not be represented as such.
