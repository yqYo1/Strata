## Real API use and frozen-setting observation

The helper includes the actual layout.hpp, session.hpp and prefill.hpp headers. It invokes linked strata::prefill::Prefill::bytes_needed directly for T=3,256,8192,10240,12288. No allocator/counting implementation, expected-size formula, stubbed function, copied planner, fake queue property, kernel or model loop is provided.

Each fresh process accepts STRATA_PREFILL_EMB_PLE_ALIAS absent or exactly 0,1,01,true,2 and requires STRATA_PREFILL_BF16X2 exactly 0,1,2. Unsupported values return status 2 before the planner. Main must launch the six alias cohorts crossed with the three BF16X2 settings as separate processes so production static settings start fresh.

For each T the helper calls the actual API under the original requested alias string, changes the process environment to the opposite effective request (exact 1 becomes 0; every other allowed original becomes 1), calls the same API again, prints complete before/after sizes and frozen_unchanged, then restores the exact original presence/value. The first mutation immediately follows the first T3 API call. Every later T therefore also compares the original environment spelling against its opposite in the same already frozen process. Exit 0 requires all five before/after sizes equal; changed plans return 1. Environment mutation/restoration failure or a C++ exception returns 2. These outcomes have not been executed or observed.

The output header records alias string/presence/opposite, BF16X2, explicit ring, primary QSA capacity/mode/index, k and canonical geometry; each sample records T and both uint64 requested sizes. Frozen_setting_all summarizes the five actual API comparisons. It does not report an effective device alias or init success. Expected subtraction T*2560*4+256 belongs only to Main's across-fresh-process comparator and is intentionally absent from the helper. No numerical-byte/GPU parity is inferred from equal planner sizes.

## Exact plain state inputs and default expert layout

The helper creates only ModelGeometry g{}, QsaState qsa{}, and SessionState ss{} on the host stack, sets qsa.max_cells=262144 and ss.qsa_states=&qsa, and keeps these objects alive through all calls. It does not construct Prefill, call session_init, open a pack, load expert layout, initialize a model or create a queue.

ModelGeometry defaults in layout.hpp give N2560, HC4, LR320, E512, n_head24, n_head_kv2, head_dim256, idx_q_heads4 and idx_key_dim128. SessionState defaults give k10 and qsa_ord0=0; qsa_primary() returns qsa_ord0 directly (session.hpp:41-52). Thus primary state lookup resolves to the one live stack QsaState. qsa.max_cells alone supplies the capacity used by bytes_needed. ss.max_cells stays its default 0; no claim is made that this describes a fully allocated inference session. QsaState defaults have kv_mode0, all device pointers null, zero page/slot counts and no destructor with GPU resource ownership (layer.hpp:209 onward). SessionState and their member buffers contain state descriptions, not RAII allocation/Runtime initialization. take_stage returns immediately for kv_mode!=1 (prefill.cpp:501-503 in W), so no actual streamed KV staging is requested.

The process-wide expert_layout is initialized as plain ExpertLayout g_layout (src/kernels/cpu/expert_layout.cpp:17-20); ExpertLayout defaults native=false, n_layers0, n_expert=NE, empty fmt/offset/bytes vectors, max_blob=BLOB, total0 (include/strata/kernels/cpu/expert_layout.hpp:21-39). The helper never changes it. This is default canonical Q2_0 request accounting, including its real default blob/ring contribution, not the qualified mixed-IQ model's loaded native pack layout and not a loaded production arena. No native-pack full request size is inferred.

## Two implicit Runtime paths: CPU-only execution is unavailable

Direct helper code contains no Runtime, SYCL queue, GPU or allocator API call, but actual production bytes_needed is not currently Runtime-free:

1. bytes_needed calls moe_set_bytes, whose first action obtains mmq_plan. mmq_plan evaluates `mmq::built() && lay.native && (env == nullptr || std::atoi(env) != 0)` (W src/prefill/prefill.cpp:603-608; identical expression read in the current active worktree). C++ evaluates the left operand first, so even default native=false or STRATA_PREFILL_MMQ=0 does not bypass mmq::built(). src/prefill/moe_mmq.cpp:19 implements built() as kernels::iq_mmq_usable(core::Runtime::get().compute()). Runtime::get may create its context/ordered queues/watchdog and its queue-mark capability measurements (src/core/device.cpp:185 onward). The helper cannot meet a no-Runtime launch contract while calling the unchanged actual planner.
2. bytes_needed also calls ring_slots for its expert staging takes. If STRATA_PREFILL_RING is absent, ring_slots accesses Runtime::at(dev).device() and device_info(dev).total_bytes (W src/prefill/prefill.cpp:159-175), using current_device and a cached PerDevice report. This occurs before the small-T return chooses STAGE, so even T3 would not avoid the query. The helper requires exact STRATA_PREFILL_RING=16 before any API call and preserves it across all cohorts. That suppresses this second query only; it cannot suppress the independent MMQ Runtime probe above.

The helper prints a Runtime-backed-launch warning before the first actual API call. This warning does not turn an unauthorized launch into an authorized one.
