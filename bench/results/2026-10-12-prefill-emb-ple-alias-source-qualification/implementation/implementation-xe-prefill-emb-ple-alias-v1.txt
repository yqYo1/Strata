## Diff and admission contract

An Impl boolean records the admitted alias. emb_ple_alias_requested() caches exact environment value STRATA_PREFILL_EMB_PLE_ALIAS=1 on first use, as the other planner settings do. Absent, 0, or any other value keeps the previous allocation sequence. Caching prevents environment changes between bytes_needed, init and later borrowed relayout from changing their allocation plans.

init resolves the actual supplied compute stream through Runtime::stream and requires the SYCL in_order property when the alias is requested. A missing property returns false with an explicit flag error; unavailable/unrecognized stream resolution is caught and returns false with a queue-contract error. m.cs is assigned only after this gate succeeds, so a fresh rejected object's destructor never tries to drain an unrecognized stream. The gate precedes hand-off host buffers, token device buffer, copy stream, stager/events, host staging, GEMM scratch and all chunk device allocations. It also precedes run and prompt consumption. Existing compact-MoE admission, geometry, stage and size guards follow unchanged. Runtime may already exist or initialize its own context/queues when queried; the new gate is before Prefill allocations, not a claim that Runtime initialization allocates nothing.

carve retains m.emb's original T*N FP32 take. With the admitted flag, the later m.ple_emb field points to m.emb instead of performing its own T*N FP32 take. bytes_needed skips precisely that corresponding later take when the frozen flag is requested. The planner has no queue argument and is a requested-size answer; successful init is still the queue/allocation admission gate. An alias plan with no safe queue never falls back silently or reports an effective alias.

Successful carve (init or borrowed relayout) prints:
strata prefill: STRATA_PREFILL_EMB_PLE_ALIAS=1 T=<effective extent> requested_saving_bytes=<bytes> in_order=1
This names the actual carved extent, not necessarily the final partial chunk's token count. No addresses, per-task text, extra device events/waits, or launches are added. Default path emits no line.

Both original SPDX copyright notices and the LGPL identifier remain. No kernel, CUDA/HIP, dtype, conversion, projection, arithmetic, context, cache, ring or threading implementation was changed. No new CPU helper/test was added: a fabricated CPU loop reproducing broadcast/overwrite would not validate the actual GPU ordering seam.

## Other callers and ownership

Later layer-split stages read hand_in_ into R and do not write/read m.emb. A stage containing layer 1 uploads/consumes its own PLE rows on its own m.cs; stages excluding layer 1 have ple_on=false. Their unused plane can be shared without crossing stages. Each stage separately runs init's queue gate. Hand-off buffers and next-stage futures contain residual rows only. This does not authorize concurrent calls to run on the same Prefill object or mutation/destruction of its queue while it is in use.

draft_kv (candidate lines 935 onward) carves a distinct local emb from m.region (separate from both member embedding planes); its next-token embedding writes/readers never use m.emb/m.ple_emb. on_chunk executes after the existing compute drain and passes only R_rows to draft_kv or MtpDrafter::prefill (generate.cpp:6451-6456 and 10187-10193). Drafter/window state/arenas stay separately owned. No MTP state is reclaimed. Borrowed relayout first drains existing compute/copy queues and performs the same carve using the saved flag. Owned allocations track the retained embedding allocation once in m.owned, so aliasing creates no second free. Borrowed allocation removes the later take and shifts only later offsets according to the matching planner.

BF16X2 modes 0/1/2 retain their existing optional low-part buffers and operation order. The alias plane remains FP32. Geometry, fixed N=2560, stage range, compact route bounds, Alloc alignment/size_t multiplication behavior, ring planning and full-context valid_span remain unchanged. This narrow edit does not introduce general overflow hardening for unsupported enormous chunks; existing size/overflow guards and valid input requirements remain in force.

## Requested saving and T10240 boundary

Alloc::take charges ceil((T*N*4+256)/256)*256. N=2560 makes T*N*4 divisible by 256 for every legal integer T, so removed requested bytes are exactly T*N*4+256, including one guard. At T8192 this is 83,886,336 B; at T10240 it is 104,857,856 B (100 MiB payload plus 256 B); at T12288 it is 125,829,376 B. The diagnostic uses the same legal extent. These are source-request arithmetic, not measured physical VRAM saving; allocator pages and fragmentation can differ. The owned ring's pre-existing grouping/counting distinction does not change this delta.

An explicit hard-bound T=10240 is available to Prefill::init: no source chunk ceiling at 10240 was found, and the edited planner/carve accept that legal extent. This says nothing about actual GPU admission. For Main's exact-size validation, the standalone owned-buffer path (--prefill 10240 with --no-prefill-borrow, a prompt longer than that chunk, and unchanged max-context 262144) passes the explicit size through to init; no run is claimed. Caller planning can otherwise change effective settings before init: serve plan_lend halves a fixed chunk until cache slots fit (generate.cpp:5627-5631,5725-5735); automatic planning selects its explicit list, which omits 10240; standalone borrowing can round/clamp chunk to the prompt's needs (10132-10140); serve borrowed requests can relayout to min(configured chunk,token count rounded to 256) at 8705-8730. Preserve Main's explicit hard bound by reviewing the enabled diagnostic and effective settings, not just the requested CLI value. No context/cache change was tied to this alias.
