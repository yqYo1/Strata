# R187 — GDN transient low-storage numerical evidence and candidate boundary

Date: 2026-10-12. Read-only review; no model, build, test, profiler, runtime, or GPU execution.

## Conclusion

The reviewed public evidence does not qualify FP16/BF16 storage for Strata's temporary GDN tensors on Qwen3.8-Flash-Next. Implementations commonly accept low-precision Q/K/V/output tensors while keeping gate/beta float32, but their public interfaces do not establish the dtype of every private prefill temporary, and they do not report quality loss from rounding those temporaries. Existing quantitative quality reports concern recurrent-state writeback, quantized weights/operands, or residual streams, which are different rounding boundaries. Preserve the FP32 recurrent arithmetic and persistent state; the one comparatively bounded new experiment is the GDN `z` output-gate scratch store, with FP32 reload and all subsequent arithmetic unchanged. It affects output only, not the recurrent state update. This is a test candidate, not an approved optimization.

## Exact local boundary

`gdn_set_bytes(T)` and the corresponding carving allocate FP32 `qkv[T,C]`, `z[T,ZV]`, `ab[T,2HV]`, `gate[T,HV]`, `beta[T,HV]`, `hbuf[T,C]`, and `y[T,ZV]`, plus uint16 `y_h[T,ZV]`. In the GDN branch, `native_proj(attn_qkv)` writes `qkv`; `native_proj(attn_gate)` writes `z`; BF16 projection results for alpha and beta weights write `ab`; `gdn_gates` reads `ab` and writes float `gate`/`beta`; `gdn_conv` reads `qkv` and persistent convolution history, normalizes the convolution result in float, and writes `hbuf`; `gdn_recurrence` reads `hbuf`, gate, beta, z, and persistent FP32 state and writes `y` plus `y_h`; `ssm_out` consumes `y_h`. The persistent convolution history and SSM matrix share the FP32 GDN state allocation.

The recurrence update itself uses float `exp(gate)`, float beta, float FMA state update, and float reductions. The output applies float RMS normalization using `y` (sum of squares plus epsilon), multiplies the learned norm weight and `sigmoid(z)`, writes FP32 `y`, then writes rounded FP16 `y_h`. This is a material distinction: `y_h` is the existing output-projection input conversion; it does not imply that `z`, `y`, or recurrent state has already been stored in low precision.

The bounded candidate is `z`: producer `native_proj(attn_gate)` -> FP32 `m.z`; consumer `gdn_recurrence` reads `sigmoid(z)` only after recurrent update math and output RMS norm, where it gates the output. A low-storage version would round only the materialized `z` values, widen each load to FP32, and retain float sigmoid, norm, multiply, and FP32 recurrent-state updates. Because `z` is used only in output formation, it cannot feed back into the current or next recurrent state. Quality impact is still unknown; sigmoid saturation does not guarantee the cast is harmless, and end-to-end logits may change.

Do not prioritize `qkv` or `hbuf` for the first low-storage experiment: both supply q/k/v values directly to the per-token recurrence, so rounding them changes the recurrent update and then feeds into all later timesteps through the persistent state. `gate` and `beta` are likewise control inputs on every recurrence step; their FP32 domains and exponential/multiplicative use are sensitive. `ab` is consumed by gate/beta activations, so it is not isolated from those controls. Rounding `y` before output RMS normalization changes both the squared norm and normalized direction; `y_h` is already the single explicit output rounding boundary.

For `z`, scratch capacity reduction is 2 bytes per element (`uint16_t` rather than `float`), or `2*T*ZV` bytes while GDN scratch is live. At N=2560 and ZV=HV*S as in this source, this is linear in chunk length. This changes storage/rounding only; it makes no assumption that native GEMM output can be emitted in a low-precision type. Preserve native projection accumulation and materialization in float, then test the explicit store/load cast as its own condition.

## External implementation and quality evidence

- FlashInfer's primary [GDN prefill implementation](https://github.com/flashinfer-ai/flashinfer/blob/main/flashinfer/gdn_prefill.py) documents low-precision Q/K/V/output inputs for supported prefill paths and FP32 gate/beta inputs, with recurrent-state dtype separately configurable. This shows mixed dtype interfaces are used in public kernels; it does not document the stored dtype of each internal workspace tensor or provide a measured transient-store accuracy ablation.
- FLA's primary [chunk Gated Delta Rule implementation](https://github.com/fla-org/flash-linear-attention/blob/main/fla/ops/gated_delta_rule/chunk.py) returns output converted to the query dtype. The reference-level result type does not establish that its internal prefill intermediates are all stored low precision, nor does it isolate transient rounding quality. Treat it as API/implementation context only.
- R299, [public recurrent-state precision evidence](/home/yayoi/.local/state/strata-sycl/post-reboot-tuning-20261007/research-20261009/round299-lowprecision-intermediate-published-quality-evidence.txt), already records quantitative losses from repeated recurrent-state storage rounding on adjacent models: naive BF16 caused multi-point task-score declines for Qwen3.5-9B and Qwen3.5-35B-A3B; DAMP on Qwen3.6 reports FP16 close to FP32 on its tasks and RULER through 128K, while BF16 varies and FP8 E4M3 can lose substantially. These are relevant caution for qkv/hbuf/gate/beta only by analogy; none measures a temporary tensor rounded once, and none validates Qwen3.8-Flash-Next.
- The Qwen3.8 technical report [NVFP4/W4A4 study](https://arxiv.org/html/2609.04098v1) reports low-precision quantization/operand experiments and discusses recurrence sensitivity, but does not isolate FP16/BF16 prefill scratch stores. The technical report's qualitative GR residual result (logged in R289/R299) is a different tensor and lacks quantitative detail adequate to transfer a loss bound.

Thus the exact missing numerical evidence is a same-checkpoint comparison that rounds only a named transient GDN buffer, maintains FP32 projection arithmetic/recurrent state, and measures quality at intended long prefill positions. Public results located for this round do not provide such a comparison. No other model's benchmark should be cited as local parity or as a precise loss prediction.

## Validation needed before any adoption

At minimum, compare the current FP32 baseline to an isolated `z` FP16-store/FP32-load variant with identical prompt and weights at short, 32K, and the intended maximum prefill. Record per-token full-logit max/mean absolute error, top-1 agreement, KL or a stated distribution metric, greedy continuation agreement, and error by absolute-position bins (early/middle/last, including the final prefill block). Confirm persistent GDN state remains FP32 and compare its hash/values; the `z` perturbation should not alter it. Include task-level quality against an explicit acceptable loss bound. A buffer-only numerical test is useful but cannot substitute for target-model logits and long-context task checks. This round ran none of those tests.
