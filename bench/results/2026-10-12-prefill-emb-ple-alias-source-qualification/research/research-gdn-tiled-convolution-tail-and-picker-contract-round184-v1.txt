## Bound that avoids 24 row-batched projection sets

The current source charges the eight shared GDN row arrays as `G(B)=144,128*B+2,048 B` including `Alloc::take` guards. At T=12,288, the retained R179 ledger gives QSA=1,634,831,104 B; the existing GDN set is 1,771,046,912 B. To make QSA the region maximum, require `G(B)<=QSA`. This permits integer B<=11,342; the largest 64-aligned bound is **B=11,328**, with G(B)=1,632,684,032 B, 2,147,072 B below QSA. B=11,392 would exceed QSA. At logical T=12,288 this produces two ordered tiles, 11,328 rows plus a 960-row tail, rather than 24 tiles at B=512. The 960 tail is also a multiple of 64. With five row-dependent projections (qkv, gate-z, alpha, beta, output), this is ten projection calls instead of 120 at B=512, versus five on the current untiled path. Each tiled call still repeats native-weight dequant/setup; B=11,328 minimizes that repetition subject to the row-set ceiling.

At this exact T, the two tile lengths are both >64 and multiples of 64, so the current convolution's serial/large-call threshold and internal 64-row boundaries are preserved without a short convolution tail. The implementation must still support other T values: any `nrows<64` final tile of a logical T>64 call otherwise takes the wrong convolution path, and remainder 1 or 2 must correctly update convolution history.

## Convolution mode, normalization, and history

`gdn_conv()` in current `kernels.cpp:415+` makes a whole-call policy choice: if `STRATA_GDN_CONV_SERIAL` is present or the function argument T<=`CONV_TILE` (64), one work-item per channel walks rows in order, applies the four-tap causal convolution, updates the three-value history, and returns **without q/k normalization**. The large path instead uses 64-token C-3 tiles and then normalizes the q/k heads. With default `STRATA_GDN_CONVL2`, convolution and q/k norm are fused; when set to 0, normalization is a separate submission. The distinction is semantically material: a logical call of 65 or more rows gets q/k normalization, while a logical call of 64 or fewer rows does not.

The C-3 path reads the three predecessors with `t>=0 ? qkv[t*C+c] : hist[c*3+(t+3)]`. Its final history update uses the same convention for `t=T-3+k`. This is exactly what makes tails of one or two rows work: missing predecessors/history slots come from the prior three-value history, and only after the tile completes is the next persistent history written. The channel-serial path carries `v0/v1/v2` through every row and also handles these tails. A range implementation must pass qkv/h tile pointers or explicit offsets, read negative local indices from the prior history, and update history once after each tile before the next tile is submitted.

Add a call-level `ConvPlan` resolved once from original logical T and the two existing environment controls, then call a range form with `(row0, nrows, logical_T, plan)`. At minimum the plan distinguishes serial/no-normalization from large/qk-normalized and preserves fused versus separate normalization. Do not recompute `logical_T<=64` from nrows. For logical T>64, a one-row or two-row final tile must retain the large path and q/k norm; for logical T<=64 preserve the serial path. Keep the existing per-element multiply-add expression, 64-row internal partition, q/k reduction order, and history update order. The input qkv planes are already row-contiguous; each tile range is sequential on the same compute queue.

## Recurrence continuity and first-call picker

`gdn_recurrence()` mutates the session's FP32 recurrent matrix in token order. Its serial `STRATA_GDN_REC_HEADS` branch walks the passed rows in order and emits normalized y and y16 in one kernel. The nonserial D-2 and key-head kernels walk rows in order, update the same matrix, produce raw FP32 y, then a separate kernel reads y and writes y16. `GdnRecLane<16>` also walks rows in order, mutates the same FP32 state and writes raw y before that normalization kernel. Consequently, the state at the end of each tile must be the exact starting state of the next tile; never reset, copy, round, or reorder it between tiles. Tile-local `y` and `y_h` can be reused only after their output projection has consumed y_h.

Current non-lane selection is call-size-dependent at first use. If `pick<0`, key-head is enabled and the first nonserial call has T>=64, the code compares D-2 and key-head on copies of state, then stores one static `pick` for the process. It allocates `st=S*HV*S` FP32 values (3,145,728 B) and `yy=T*HV*S` FP32 values; at T=12,288, yy is 301,989,888 B (288 MiB). It runs each candidate twice, waiting after each timed launch, and frees both allocations afterward. The real session state is not tuned; each trial copies it to `st`. If allocation fails, D-2 is selected. With `STRATA_GDN_KEYHEAD=0`, the comparison is skipped and D-2 is used. If the lane path is accepted, the picker is bypassed.

Calling the existing recurrence API once per tile does not preserve the old picker policy: its first eligible call will tune using nrows (11,328 with the proposed bound), not original logical T=12,288, and the temporary yy still scales with that first tile. Later tiles reuse the selected static branch, but the algorithm choice is now based on the tile shape. The two recurrence forms are written to preserve per-column arithmetic/order, but differing launch sizes and timing may select a different form. For a controlled bounded implementation, resolve a `RecurrencePlan` once using `logical_T` and environment/device policy, then use that same plan for every `(row0,nrows)`. If retaining the D-2/key-head timing choice is required, make the tuner execute the complete planned tiled sequence from a fresh copied FP32 state for each candidate and reuse one B-row `yy` scratch sequentially on the in-order queue. This measures the actual tiled plan and removes the full-T yy allocation; it requires explicit range launchers and serializes each candidate's state carry. Alternatively use an explicit fixed D-2/key-head policy, but record that as a policy change and validate output/state parity. Do not leave an implicit full-T tuner allocation outside the bounded-region arithmetic and then claim a 136 MB peak saving.

## Is the lane recurrence an available forced route on this host?

No retained exact receipt establishes that `GdnRecLane<16>` can safely be forced active on the current B570 stack. The retained `xe-issuer-device-json-query-root-v1/record.json` records an `xpu-smi discovery` result for Arc B570, with `physical_eu_simd_width=16`; that run explicitly has `gpu_compute_executed=false` and `model_executed=false`. This is not a SYCL query of `gpu_eu_simd_width`, and it does not establish that the exact `GdnRecLane<16>` executable bundle exists. The current source gate (`kernels.cpp:757+`) requires the SYCL device aspect and reported width >=16, then attempts to obtain an executable bundle for that exact kernel ID; on exception it falls back. `STRATA_GDN_REC_LANE=0` disables it. Setting it to a nonzero value does not force it: the source still performs the capability checks and can silently take the work-group path apart from a stderr diagnostic on bundle failure.

Even successful bundle compilation would not by itself establish defined support for this kernel's `grf_size<256>` property. Retained R100/R99 material reports that the public experimental GRF-size legal-target table did not list BMG/Xe2 for the reviewed toolchain, while evidence and support for the pinned B570 compiler/IGC/driver combination remained unknown. Therefore do not use lane activation as the unverified method to suppress the picker. A future lane-specific qualification needs a retained exact-device SYCL capability record, exact kernel-ID executable-bundle admission/route receipt, and version-matched support plus realization evidence for the 256-GRF property. Until then the bounded design must work with D-2/key-head and account for or remove their tuner workspace.

## Minimal range API and falsifiers

A narrow implementation design is:

1. Choose B=11,328 for T=12,288, the largest 64-row multiple below the QSA ceiling. Resolve convolution and recurrence plans once per original GDN call, before entering the row loop.
2. Reuse the existing eight region arrays at B capacity. For each row range, invoke all five projections with `X+row0*input_width`, nrows, and tile output; keep alpha/beta in the existing two halves of the tile `ab`; call pointwise gates, then convolution range, then recurrence range. Send output projection to `m.bo+row0*N`. Keep the same session state/history pointers and do not advance the GDN layer index per tile.
3. Preserve ordered same-queue submissions through tile output projection before reusing each tile's qkv/z/ab/gate/beta/hbuf/y/y_h storage. Use an explicit dependency if any stage moves to another queue.
4. Bound autotune scratch too: compare the selected candidate over the same 11,328+960 plan using one reusable 11,328-row y scratch; do not allocate yy for all original T. The persistent 3 MiB state copy remains a separate transient. A fixed recurrence choice is simpler but must be stated.

Source-level falsifiers include any full-T consumer of a GDN plane outside the listed chain; a GEMM backend that reads beyond the specified nrows or assumes output T strides inconsistent with its pointer/leading dimension; altered q/k normalization for a short large-call tail; history not updated before the next range; recurrence state reset/reordering; or picker workspace still scaled to full T. Minimal numerical discriminators should compare untiled and tiled output/state for logical T=64, 65, B-1, B, B+1, 11,329, 11,330, 11,391, and 12,288, including tile remainders 1, 2, and 63; exercise forced conv serial, default fused large, separate norm, serial recurrence, D-2 and key-head; check per-tile history/state continuity and complete output projection rows. A same-state comparison is needed for any altered D-2/key-head policy; hashes alone do not replace output checks.

The S=128 recurrence state is persistent FP32 and represents the same logical state across all these plans. The source arithmetic may support exact per-column equality across D-2, key-head and lane implementations, but a different tile schedule, projection backend batch shape or selection plan has not been measured here. No run, fit, performance, or route qualification is claimed.
