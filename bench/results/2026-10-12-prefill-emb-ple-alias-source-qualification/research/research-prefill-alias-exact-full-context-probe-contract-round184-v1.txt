## Exact full-cell input protocol

Ordinary standalone generation cannot consume all 262,144 prompt cells while producing output. `context_bounds::admission(cells,prompt,outputs)` requires `outputs > 0` and a checked span entirely within `cells`; the ordinary CLI likewise rejects nonpositive `--max-new` and `prompt+max_new > --max-context` (`context_bounds.hpp:19`, `generate.cpp:2755-2763,3463-3467`). Serve `GEN` rejects `max_new < 1` before context admission (`generate.cpp:8066+` and `:8161+`). Consequently `prompt=262144,max_new=0` is rejected by stock generation/GEN, and `prompt=262144,max_new=1` is rejected before inference. A legal ordinary `prompt=262143,max_new=1` is one cell short: native mode batches the first 262,142 IDs, then processes the final prompt ID at position 262142, scores/emits one output, and does not consume that output. The final physical input cell 262143 remains unwritten. The endpoint row after consuming cell 262143 is not legally scoreable through this ordinary route.

The one existing source protocol that accepts all C=262144 input IDs is the standalone, opt-in development diagnostic `--full-context-probe ID`. It requires exactly C parsed IDs, `--max-context 262144`, `--max-new 0`, `--native`, `--mtp`, `--spec >=2`, fixed positive `--prefill N` (not `auto`), `--no-prefill-borrow`, a positive draft window below C, active PLE, and one GPU. It refuses serve/batch/split/remote/cache-growth/pipeline/vision/benchmark/ablation/dump/oracle-follow combinations; see the strict source gate at `generate.cpp:2460-2485`. It also refuses if the resident full session/draft capacities do not match. The diagnostic-only exception bypasses ordinary positive-output admission; it does not relax any physical bound.

This branch necessarily calls the normal `Prefill::run` object compiled into the executable with `(tokens,262144,0)` (`generate.cpp:10177-10184`, `run_full_context_probe` at `:1232+`). It runs every target Prefill chunk from absolute position zero, then waits for the target queue. Its `Prefill::on_chunk` callback calls synchronized `MtpDrafter::prefill` for each chunk and waits for the MTP stream before coverage advances (`:1306-1323`). The helper maps target rows 0..262142 to their actual next prompt IDs and maps only row 262143 to the explicit terminal storage ID (`full_context_probe.hpp:21-51`). It therefore processes the real target cell at 262143 and fills one full-span draft state, but the draft's last row is storage-only. No token at index 262144 is read; there is no sample, verifier, output, or inference after restore.

The mechanism will exercise an edited Prefill implementation if and only if the executable actually contains that edit and its alias gate is requested/effective: this diagnostic does not substitute a different Prefill implementation or bypass `Prefill::run`. The immutable W337 source has no R180 alias edit, and the exact alias switch/effectiveness is not verifiable from this source anchor.
