## Source liveness and queue proof

The only fields in the full repository for these device planes are `Impl::emb` and `Impl::ple_emb` in `src/prefill/prefill.cpp`. A source-wide search finds their only writes/reads in that file: allocation/carve, the prompt embedding block, the PLE upload, and the two PLE consumers. `emb` is not exposed through the public `Prefill` API. The PLE host gather writes `ple_rows` and `ple_emb_host`, which are separate host storage. MTP's `draft_kv` has a local `emb` carved from `m.region`; it is a different pointer and different buffer, not `m.emb`.

The critical order is more broadly supported than the R180 compact-mode-only argument:

- `Prefill::init` stores its caller's `stream` as `m.cs` (line 665). `Runtime::create_stream()` creates engine streams with `sycl::property::queue::in_order` (`src/core/device.cpp:225`); the Runtime compute and transfer queues also use that property (`:186-187`). `gpu::stream_create()` delegates to that constructor (`src/core/gpu.cpp:101-103`). Thus all engine-created candidate `cs` streams are in-order. `Prefill::init` does accept an opaque caller-supplied stream, so an alias must explicitly verify the actual stream property/owner rather than assume every caller complied.
- Each embedding producer is submitted to `m.cs`: native batched `gather_dev` forwards the stream into `iq_embed_rows` (`src/core/native_head.cpp:188`); packed batched `embedding_gather_dev` is passed `m.cs` (`prefill.cpp:1325-1336`); the per-token `embed_row` path forwards `m.cs` into its native gather/kernel or submits host-row copies to `m.cs` (`:1337-1346`, `src/core/layer.cpp:1174+`). Vision rows take this same per-token output path. `gr_broadcast` is also submitted to the same `m.cs`; its kernel reads each `e[t*N+d]` while writing `R` (`src/prefill/kernels.cpp:407-411`).
- PLE host gathering runs asynchronously on the CPU into a pinned/pageable host buffer (`prefill.cpp:1272-1284, 1350-1355`). `ple_land()` enqueues the device upload into `m.ple_emb` on `m.cs` and records the host-source reuse event on `m.cs` (`:1359-1373`). Both PLE consumers—the batched native postops and token path—are submitted with `m.cs` (`:1570-1622`). `Gemm` is initialized with the same supplied stream (`:774-775`/`:259-264` in `gemm.cpp`). The alias overwrite is therefore ordered after `gr_broadcast`, and PLE reads are ordered after that upload.
- `m.copy` is a second stream, used for expert-blob staging and `copy_async_after` (`prefill.cpp:705, 1467-1474, 1530-1537`). Full-repository searches found no access to either plane on `m.copy`; expert staging touches `stage_dev` and expert-cache slots. There is no separate `ts` member in `Prefill::Impl`. Queue separation therefore does not cross this alias's producer/consumer chain.

On engine-created SYCL streams the ordering argument holds for the normal batched and per-token embedding branches, PLE batch/token branches, and across consecutive chunks: the next chunk's embedding write is ordered after the prior chunk's PLE consumers on the same in-order queue. No explicit sync is needed at each seam for this same-queue order. On a caller-supplied out-of-order queue, host submission order alone is insufficient; the alias must be refused or an explicit dependency added.

## Hand-in, windows, stages, MTP, relayout and graphs

- With `hand_in_ != nullptr`, the layer-split stage uploads host hand-off rows straight into `R`; token embedding and `gr_broadcast` are skipped (`:1299-1302, 1307, 1337-1348`). That stage's `m.emb` has no use. If that stage runs PLE, `m.ple_emb` still receives its independent host gather/upload. The alias remains safe because the unused name adds no consumer.
- In a multi-GPU layer split, each `Prefill` stage has its own `Impl`, device/compute stream, and device-plane allocation. Stage hand-off is copied through separate host-pinned `m.hand[]` buffers; `next_->run` reads that hand-off on its own stage (`:2948-2964`, public contract `prefill.hpp:131-144`). There is no shared `m.emb`/`m.ple_emb` pointer across devices. The stage containing layer 1 is the only split stage with PLE (`ple_on` requires `LB <= 1 && 1 < LE`, `:1262-1267`); if it starts at layer 1 its `m.emb` is unused, as above. Every stage still needs its own stream-property admission and alias binding.
- Prefill chunks are serialized per `Impl`. The CPU PLE read-ahead writes only `ple_emb_host[2]`; its `ple_copied` events protect the host buffers from reuse. It does not mutate the shared device plane. On layer-split chunk pipelining, each stage's own `m.cs` is used, and the current stage synchronizes before handing rows to its next stage (`:2950-2963`).
- `on_chunk` is called only after `stream_sync(m.cs)` and receives `m.R`, not either aliased plane (`:3000-3009`; callers in `generate.cpp:1307+`, `6451+`, `10187+`). The ordinary callback's `draft_kv` reads `R_rows` and uses a distinct set of local `m.region` rows; it submits to the same main `m.cs`, then drains it. The full-context callback's `mtp.prefill` receives `R` and runs its own MTP stream. Neither reads or retains the prefill embedding pointer. This covers both MTP callback variants and the per-chunk MTP KV update.
- `relayout()` drains both `m.cs` and `m.copy` before it calls `carve()` against a new borrowed arena (`:881-899`). The alias must be assigned inside the common `carve()` path (and reflected in `bytes_needed()`), so init and every relayout bind both fields to that generation's retained allocation. Binding it only in init, or retaining the old address across relayout/reset, is a concrete stale-pointer bug. `reset()` drains/releases and replaces the `Impl` (`:537-560`); a fresh init must bind again.
- No `Prefill::run` graph capture exists in `src/prefill/prefill.cpp` or its kernel file. The model verifier's captured graphs are separate; the MTP prefill graph consumers use MTP-owned buffers/state. The MTP callback has no alias-plane pointer parameter. Therefore this alias introduces no current captured `m.emb`/`m.ple_emb` pointer. A future graph or callback that retains either pointer would falsify this audit and require a capture lifetime/recapture rule.

## Safest initial admission and falsifiers

Start with the single-GPU, full-layer Prefill instance (`stage_lb=0`, `next_==nullptr`), one non-overlapping `Prefill::run` at a time, and a Runtime-created in-order `m.cs`. Keep existing independent PLE host buffers/events. Require `m.emb == m.ple_emb`, the pointer generation matches the current carve/relayout arena, and no error in copy enqueue, stream completion, async handler or PLE event path. When the caller stream is not demonstrably Runtime-owned/in-order, retain both buffers. After this subset has direct paired parity, expand to layer-split stages/hand-in and borrowed-buffer relayout as separate admission cohorts.

Record per run/chunk: alias requested/effective/refusal reason; device/context and queue in-order property; pointer identity and carve generation; `T`, real tail length, `hand_in` state, `ple_on`; counts of batched token gather, per-token embedding, vision-row copy, broadcast, PLE gather/upload, PLE batched/token consumers and MTP callback kind/result; queue/event/copy/async fault status; chunk coverage and completed end position. Fail closed on pointer inequality when alias is enabled, a stale carve generation, out-of-order/unknown queue, failed upload/event/sync/async handler, incomplete chunks, or any existing prefill/MTP error. Confirm the byte ledger drops exactly one guarded `T*N*sizeof(float)` take and all alignment/carve bounds remain valid; this is not a run-time fit assertion.

Falsifiers include a full-source use of either field after the identified phase; any producer/consumer launch using a queue other than `m.cs`; concurrent `run()` calls on one `Prefill` instance; a reuse path that does not call the common alias-binding `carve()`; a callback or graph retaining the pointer beyond the queue-ordered PLE use; or an out-of-order caller stream. Source checks found none of the first four in the pinned implementation, and no current Prefill graph capture, but the public stream parameter makes an explicit runtime gate necessary.

## Decision

The R180 alias has a complete same-queue lifetime proof for engine-created in-order streams, including chunk reuse, hand-in stages, and MTP callbacks. The principal source-level boundary is public `init(..., void* stream, ...)`: only enable aliasing after confirming that exact queue is in-order and belongs to the expected device/context. Keep alias binding in common `carve()` to cover relayout. No current graph, MTP callback, or copy-stream consumer holds either alias pointer. With those guards, I found no source-level read/write overlap that requires retaining both FP32 planes on the pinned production path.
