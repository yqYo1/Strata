## Source-level finding

In W, `m.mixed` and `m.bo` are each contiguous `float[T*N]` planes (`prefill.cpp:786-787`), with `N=2560` for the pinned artifact. A whole-source reference search finds only these direct accesses to the FP32 `m.mixed` field after its carve: its production as an output of `gr_mix_r` (`:1643-1644`), optional async CPU-share copy (`:1909`), and MMQ activation quantization (`:2108`). The other attention/router/MoE paths consume `m.mixed_h`, `m.mixed_bf` and optional BF16 low parts, not this FP32 plane. `m.bo` receives GDN/QSA output projection or MoE combine, is consumed by a GR write, and is read by the optional post-combine NaN diagnostic (`:1667,1870,2868,2880-2887,2911-2919`). No direct FP32 `m.mixed` read was found after either output producer starts, and no current callback or graph is passed either field.

The source supports `m.bo = m.mixed` on the normal single `m.cs` order, subject to the admission conditions below. This is a source-liveness conclusion, not a runtime parity result. The proposed implementation must reject an unknown, out-of-order, wrong-device or wrong-context caller queue; the mixed/bo alias is not yet implemented in W. W's compact-MoE opt-in already rejects an out-of-order queue, but that check is conditional on compact mode and is not sufficient admission for this alias. I found no current GDN/QSA/MMQ/CPU-share algorithm branch that needs two simultaneously live FP32 `T*N` values once that queue contract is enforced.

## Read/write order by branch

**GDN and QSA attention half.** Each half first queues `gr_mix_r`, which produces FP32 `mixed` plus the separate low-precision `mixed_bf`/`mixed_h`. GDN's QKV/Z projections read `mixed_h`; alpha/beta projections read `mixed_bf`; gates, convolution and recurrence use separate scratch; the output projection writes `bo` from `y_h` (`:1643-1668`). QSA projections/indexer use `mixed_h` or `mixed_bf`; selection, KV append/attention and its output projection use separate arrays; the last projection writes `bo` from `attn_h` (`:1681-1870`). These attention routes do not read FP32 `mixed` directly. On an in-order `m.cs`, the output write into aliased `bo/mixed` follows the `gr_mix_r` write and the remaining attention work; there is no pending FP32 consumer. The subsequent GR write reads `bo`, and only after it is enqueued does the next half/layer's `gr_mix_r` produce the next `mixed` value.

**Router and MoE, non-MMQ native/fallback/fused routes.** Router logits and shared/gate/up paths consume `mixed_bf` or `mixed_h` (`:1881-1890`). The generic grouped FP16, native IQ dequant, native batch-dequant, fused resident-expert, staged/ring, and compact-MoE variants consume gathered `mixed_h` rows or quantized/fallback work buffers (`:1996-2121,2147,2200,2450-2467,2736-2753`). These routes write expert products to `Dm`/`shared` and do not add an FP32 `mixed` reader. The compact MoE request gate explicitly rejects MMQ and `STRATA_DBG_NAN`, and requires an in-order queue (`:665-682`); when compact mode is off, the same alias still needs its own unconditional in-order admission check.

**MMQ routes.** When `use_mmq` is true, `mmq::quantize(m.mixed, ..., m.Xq, ..., m.cs)` is the last direct GPU read of FP32 `mixed` (`:2108`). All subsequent MMQ modes—resident, grouped gather, direct MMQ ring, streamed, fallback/dequant of expert weights, and grouped/individual products—consume `Xq`/`Hq` and write `Dm`; `moe_combine` writes `bo` only after the expert walk and any CPU rows have completed (`:2319+`, `:2450+`, `:2736+`, `:2849-2868`). These operations are all submitted with `m.cs`. In-order queue execution therefore completes activation quantization before `moe_combine` overwrites the shared FP32 plane. Weight dequantization/gathering uses `m.copy` for expert blobs, but no mixed/bo pointer is passed to `m.copy`.

**CPU-share copy and asynchronous worker.** Where `cpu_maybe` is enabled, the host activation copy `copy_async(m.cpu_x, m.mixed, ..., m.cs)` is queued at `:1896-1909`. The following unconditional `stream_sync(m.cs)` at `:1911` completes it before the CPU worker is launched. That worker reads `m.cpu_x` and writes `m.cpu_rows`; it does not retain or read `m.mixed` (`:2097-2105`). The combine path `cpu_fut.get()` joins it, copies its finished rows into `Dm` on `m.cs`, then queues `moe_combine` (`:2849-2868`). If CPU work or later code exits early, the local `CpuJoin` waits for the worker; it does not create a CPU reader of the aliased device plane. CPU activation allocation failure happens before the copy/worker; invalid route/source and async errors do not advance into a next `gr_mix_r`.

**GR write, fusion and diagnostics.** `gr_write`, `gr_write_norm_rs`, and `gr_write_cvec_norm_rs` all read `bo` and write `R` on `m.cs` (`:2911-2919`). The `STRATA_CVEC_FUSE` and control-vector choices change whether the next norm is folded into this same GR write; they do not move the next mixed producer before the `bo` read. `STRATA_DBG_NAN` synchronizes and reads `bo` after `moe_combine` and before the GR write (`:2868-2919`); it extends `bo`'s last-read point but does not read `mixed`. QSA debug selection/dump checks use QSA arrays, and R dumps/state hashes use `R`/state rather than `mixed` (`:1767-1853,2964-3065`). `STRATA_DBG_NAN` is compatible with this alias at source level, though the compact-MoE path independently disallows it.

**Chunks, staging, borrow, relayout, MTP and errors.** Expert staging and the issuing thread use expert slots and `m.copy`, not either activation plane (`:1434-1550,2319+`). Stage-split Prefill instances hand off `R` through `m.hand[]`; each instance owns its own carved planes and queue. End-of-chunk callbacks run after `stream_sync(m.cs)` and receive `R` (`:2948-3009`); ordinary `draft_kv` uses local scratch in `m.region` and MTP-owned state, not `m.mixed`/`m.bo`. No current Prefill graph capture retains either pointer. A short tail uses the same carved buffers with `T <= T_max` and the same same-stream order.

The common `carve()` is used for init and relayout. `relayout()` first synchronizes both compute and copy streams, then rebinds all pointers through `carve()` (`:881-899`). An implementation must set both names to the same pointer inside this common carve path and must update the parallel `bytes_needed()` sequence (`:1072-1083`); aliasing only at initial init or retaining an address across relayout is unsafe. `bytes_needed()` has no stream argument, so its savings must be tied to the same deterministic eligibility policy used by init; where queue/device/context admission is unknown or refused, it must conservatively retain the separate-plane size or otherwise avoid promising that the saved bytes fit.

On `run()` success, the compute queue is drained before it returns (`:3034+`, and callbacks also drain at `:3000-3009`). On normal error returns after work submission, local staged/issuer RAII drains relevant queues and joins issuer threads; `CpuJoin` joins a started CPU worker. Exception catches explicitly synchronize compute and copy queues (`:3115+`). `release()` synchronizes both streams before freeing owned buffers, and relayout synchronizes before moving allocations (`:537-560,881-899`). The public method does not state that a caller may continue using/releasing a borrowed arena from a different queue after a failed `run()`; preserve the existing error-abort/drain boundary and require a drain before external cross-queue reuse. No in-flight cross-queue consumer of mixed/bo exists on the reviewed successful path.

## Required queue and allocation admission

`Prefill::init` stores its caller stream as `m.cs`; its public stream parameter is opaque (`:660-680`). Runtime-created compute, transfer and user streams are all created with `sycl::property::queue::in_order` (`device.cpp:186-187,202,225`), and `Gemm` is initialized with the same `stream` (`prefill.cpp:774-775`). But `Runtime::stream(void*)` can resolve a stream owned by a different device runtime (`device.cpp:245+`), so do not infer same device/context from in-order alone. Use the same strict effective gate as the current emb/PLE alias: current device/context matches the Prefill allocation, actual `m.cs` is in-order, and both aliased fields belong to this carve generation. Gate this second alias independently of compact-MoE mode. Unknown/foreign/out-of-order stream means retain distinct planes.

For `n_embd=2560`, deleting the `bo` take removes `T * 2560 * 4` payload bytes and one 256-byte `Alloc::take` guard. At the qualified `T=8192`, the source-request delta is `83,886,336 B` (80 MiB plus guard); at `T=12,288`, it is `125,829,376 B` (120 MiB plus guard). This is an exact carve/request delta only. It does not include allocator page rounding, other simultaneously live owners, cache capacity, workspaces, or VRAM headroom, and does not prove a larger chunk fits. Both `carve()` and `bytes_needed()` must remove exactly the same guarded take under the same alias eligibility rule.

## Validation boundary

There is no existing fixture that covers this complete Prefill-plane lifetime. R182's `gr_parity` and CUDA PLE block fixture are component tests only; the native full-vocabulary `--dump-logits` teacher-forcing route is a real downstream oracle, not a per-layer intermediate capture. For any implementation, retain distinct-buffer baseline versus aliased candidate on the same immutable model/input, fresh state, exact options, and actual production Prefill. The minimum branch cohort must exercise GDN and QSA attention, ordinary MoE fallback, at least one MMQ layer and its native/fused or dequant fallback where present, CPU-share copy+worker join where eligible, compact mode, control-vector GR-write fusion on/off if enabled in the product path, NaN diagnostic, layer-stage handoff and MTP callback, partial final chunk, borrow relayout, and an injected error after an async mixed reader is queued. Record each effective route and queue property; no enabled route may be silently skipped. Compare full continuation logits and outputs per R182, plus available exact state checks, and run under queue/async-error checking. These are coverage requirements, not evidence that current implementation already has such a fixture or that all branches need simultaneous execution in a single test.

**Decision:** the immutable W source has a complete same-in-order-queue lifetime chain for mixed/bo at every identified current branch: last `mixed` readers are the optional completed CPU copy and/or MMQ quantization; `bo` writers follow them; its GR read completes in queue order before the next `mixed` producer. The sole source-level rejection is an unqualified queue/device/context; a failed-run external reuse without a drain is also outside the contract. The report establishes neither a working alias implementation, correctness/parity, nor physical admission at any chunk size.
