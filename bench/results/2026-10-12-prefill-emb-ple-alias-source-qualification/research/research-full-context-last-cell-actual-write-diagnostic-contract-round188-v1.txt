## What current probe evidence covers

`run_full_context_probe` (src/program/generate.cpp) requires exactly 262144 input tokens and physical capacity, runs `Prefill::run(tokens, 262144, 0)`, validates continuous chunk coverage, installs exactly one terminal probe successor on the last residual row for MTP storage, and synchronizes main and MTP streams plus the device. It then captures K/V and running state, poisons/restores, and verifies full captured K/V bytes and GDN/PLE checkpoints. This proves the advertised full extent was processed and that captured stores restore. It does not retain a per-layer receipt that names position 262143, the physical destination chosen for that position, or whether the final append used a resident slot or host backing.

The final logical position is `pos=262143`; the physical context has 262144 cells indexed `0..262143`. The MTP terminal successor is a valid token used to form/store the draft row at the final cell. This is explicitly a storage probe, not model prediction or inference after the boundary. The probe must not request position 262144.

## KV indexing and storage distinctions

Main QSA states have `max_cells=262144`. Their logical page is `b = pos / page_size`, and in-page row is `r = pos % page_size`. The final address is therefore logical page `262143/page_size` and offset `262143%page_size`; `page_size` is the runtime `QsaShapes::page_size`, so code should calculate rather than bake the quotient.

- Mode 0 (fully resident): `page_table[b]` is the identity physical page; the production append stores at `((page * kv_heads + h) * page_size + r)` for each K/V head.
- Mode 1 (streamed main KV, e.g. `--kv-resident 32768` with a 262144-cell extent): `page_table[b]` is a dynamic map and can be `-1`. If nonnegative, the same slot-address formula writes the current VRAM page. Independently, append writes the authoritative host mirror at `(((b * kv_heads + h) * page_size + r))`. A last-cell witness must capture whether the VRAM write occurred and record the selected slot (or `-1`), while affirming the logical host row write. A 32768-cell resident budget is not 32768-cell physical capacity and is not a flat prefix of the logical context; earlier pages can be evicted/remapped.
- Mode 2 (draft ring): `kv_ring_table` initializes `page_table[b] = b % n_slots`. For the endpoint, the draft's slot is `final_page % n_slots`; it is not necessarily `final_page`. `n_slots` is determined by the MTP ring window and page size. The full-context probe requires a full-extent draft state in ring mode (`kv_mode==2`) and `first_needed()==0`; it later verifies the ring's snapshot/restore contract. Record the actual slot read from the page table at the store, not a computed assumption.
- The host mirror, when present, uses logical-page row layout even when the device page slot is remapped. Staging pools are temporary working copies for the current chunk and have a separate identity page-row layout. They are not the authoritative all-context host capture. In hybrid/Q4/Q8 paths, payload layout differs, but each append still uses logical `pos`, page table, and page offset; the witness needs only position, format, destination-presence mask, and actual slot, not a second copy of payload.
- `QsaState::idx_pooled` is the indexer's pooled block-score history, not KV backing. Its row count/ring behavior (`idx_pooled_rows`) does not define the physical K/V address for the endpoint. Do not treat a pooled/indexer row or the MTP ring slot as the logical row number.

The exact production seams are the Prefill QSA append calls in `src/prefill/prefill.cpp` (around the `p0,T` writes) and format-specific stores in `src/prefill/kernels.cpp::kv_append`, `src/kernels/xe/kv_q4.cpp::kv_append_q4`, `src/kernels/xe/kv_q8.cpp::kv_append_q8_steps`, and `src/kernels/xe/qsa.cpp::kv_append_step`. Their store code derives `pos`, page, row offset, and conditionally writes pool/host. For a real actual-write witness, place the optional diagnostic store after the terminal cell's applicable payload/scale write(s) in these kernels. Write only when `pos == 262143`; include layer id supplied by Prefill, logical pos, format, page table value, and bit flags for resident/host/stage destinations actually written. The main prompt path already has a final stream/device sync before snapshot capture, so the small witness array can be copied/read once there. For mode 1, `page < 0` is an expected resident-miss case, not failure, if host row was written. The probe must validate required destinations from the state mode and assert no record names any position above 262143.

## GDN and PLE state-write seams

Prefill processes each GDN layer on the chunk stream: `gdn_conv` reads and then commits the last three QKV values into that layer's FP32 convolution history; `gdn_recurrence` processes chunk rows in order and commits the updated FP32 recurrent matrix after its T-step loop. For the final chunk, an endpoint witness can be written only after the existing terminal QKV/history stores and recurrent matrix stores have executed. Record the global layer/GDN ordinal and endpoint `pos0+T-1`; don't claim a per-token persistent-state row exists because GDN state is recurrent and has no token-indexed rows. A single marker after recurrence is insufficient by itself to prove the convolution-history commit unless it is ordered after that commit too.

PLE is advanced at layer `l==1` by per-token `ple_block` followed by `ple_history_advance`; the history is a rolling FP32 window, not a 262144-row buffer. For the final input row, an optional diagnostic witness belongs after that row's history-advance store. At Prefill completion, `ss.ple_prev` is separately set to the final two input token IDs. These two facts should not be collapsed: history-write completion and host-side previous-token update are distinct seams.

A compact in-kernel endpoint receipt is the strongest proof because it is issued by the actual store kernel after its payload store, with no per-token synchronization. If changing every format kernel is not acceptable, a weaker but still useful alternative is one per-layer event/receipt recorded on the existing chunk stream immediately after each relevant QSA append plus GDN conv/recurrence (and PLE advance), followed by the probe's already-required terminal sync; label such a receipt as command-order completion, not independent byte verification. Do not add a sync after each token, run another token beyond capacity, or retain a profiler/full trace.

## Scope and acceptance

The minimal primary acceptance is a compact per-QSA-layer record proving that the production terminal K/V append reached its intended backing for position 262143 (main host row and any resident slot; draft ring slot), followed by the already-existing all-layer snapshot checks. If endpoint state-store coverage is also a requirement, add compact per-GDN layer receipts after both conv-history and recurrent-state commits, plus one PLE-history receipt and the existing `ple_prev` check. Each record should be bounded to a few integers/flags per layer; a single readback after existing sync is enough. Existing snapshot hashes remain integrity/restore evidence, not substitutes for endpoint receipts.
