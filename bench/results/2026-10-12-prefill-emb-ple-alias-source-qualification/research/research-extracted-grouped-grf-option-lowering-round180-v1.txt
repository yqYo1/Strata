## Decision

The current production SYCL option is expressed as a per-kernel property `sycl::ext::intel::experimental::grf_size<256>` (with subgroup size 16 on this kernel). LLVM’s supplied source lowers that request through two linked channels: per-entry SPIR-V register-allocation metadata, and per-image `sycl-grf-size=256` runtime metadata. SYCL’s Level Zero/OpenCL program manager reads the latter and appends `-ze-opt-large-register-file` to the JIT build options for a normal SYCL image. This establishes the requested mode if the image descriptor property is correctly tied to the extracted grouped image and normal runtime option construction is used; it does not establish the native kernel’s allocated GRFs or that the image was invoked.

A hand-written `ocloc -options -cl-intel-256-GRF-per-thread` is a valid Compute Runtime large-GRF option spelling in the available source, but is **not a faithful reproduction of the current SYCL build-option set**. It supplies one option string and can omit the image’s compile options, language/target flags, and environment/appended options used by the SYCL program manager. The SYCL-generated backend spelling for a non-ESIMD image is `-ze-opt-large-register-file`, not this OpenCL-facing spelling. It can still serve as a narrowly labelled “256-GRF requested” offline screen if the pinned `ocloc`/IGC accepts it; it cannot support a claim that all production JIT options were reproduced unless Main records and passes the complete effective option set and matches the backend. Do not append that flag to an assumed default option set and call it equivalent.

The source-backed image chain is:

1. `GroupedKernel` functor `get(properties_tag)` requests `grf_size<256>` and `sub_group_size<16>` in `src/kernels/xe/xmx_gemm.cpp`.
2. LLVM’s `CompileTimePropertiesPass` maps kernel attribute `sycl-grf-size="256"` to `RegisterAllocMode` metadata value 2 (large mode). The SPIR-V writer can encode that as `ExecutionModeMaximumRegistersINTEL`, and also emits the existing user-semantic form `num-thread-per-eu 4` for mode 2. Which representation appears depends on the translation path/extensions; inspect actual instructions attached to the grouped entry, not only a grep for `OpExecutionMode`.
3. `ComputeModuleRuntimeInfo` emits the separate misc property `sycl-grf-size=256` on the image; post-link splits kernels by `sycl-grf-size`, so the property is expected to characterize a homogeneous image.
4. The SYCL wrapper’s `__sycl.tgt_device_image` descriptor has the target string, compile-options string, image pointer bounds, kernel-entry range, and property-set pointer bounds. The property set is named `SYCL/misc properties`; `_pi_device_binary_property_struct` carries name, value address, type and value size. This is host-side descriptor data, not part of the raw SPIR-V payload returned by `clang-offload-extract`.
5. `program_manager.cpp` obtains the image compile options (unless replaced by `SYCL_PROGRAM_COMPILE_OPTIONS`), adds `-ze-opt-large-register-file` for `sycl-grf-size=256` on the non-ESIMD path, and then appends applicable environment flags. Its code also treats environment overrides specially. The actual effective options therefore require reading the image descriptor and accounting for the runtime environment; the property alone does not enumerate every option.

The latest final executable receipt is bound to SHA-256 `fd241348db019ec0985072e55dc27c08ac0cfd7962072847905e391e73ab83fd`, source revision `337255086026f6eef21a861c297183d05a5f7a22`. It reports 102 raw little-endian SPIR-V images (7,855,692 bytes total), with the grouped entry `_ZTSN6strata7kernels12_GLOBAL__N_113GroupedKernelILi128ELi256ELi3EEE` at result ID 2549 in retained image 4 (`/home/yayoi/.local/state/strata-sycl/post-reboot-tuning-20261007/xe-host-issuer-offload-extract-root-v1/images/image.4`). The recorded `ExecutionMode` lines for entry 2549 are mode 35 value 16 (subgroup size); they contain no maximum-register mode. That absence does not disprove the source property: the separate SPIR-V user-semantic decoration and the host image’s misc property still need inspection. Only image 4 and its converted text were retained; do not rely on retired raw images or extraction logs. The retained lossless receipt explicitly says native GRF/spill/runtime route unverified.

3. In the already retained raw SPIR-V image 4, correlate entry id 2549 by name and inspect that entry’s `OpExecutionMode` / `OpExecutionModeId` and `OpDecorate` / `OpDecorateString` instructions. 4. Reconstruct the SYCL program-manager option string from that descriptor and stated environment: image compile options plus the property-derived non-ESIMD `-ze-opt-large-register-file`, plus environment options that apply. If `SYCL_PROGRAM_COMPILE_OPTIONS` or append variables are unknown, report the final JIT option set as open. Record that this is the source-defined runtime option contract, not a runtime trace of the actual call.
