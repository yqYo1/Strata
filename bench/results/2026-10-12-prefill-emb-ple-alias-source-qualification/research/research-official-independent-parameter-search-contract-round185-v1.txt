## Execution gate comes before parameter search

R169's source finding remains controlling for the supplied B570 capability (`HOST_USM=1`, `ATOMIC_HOST_USM=0`): pristine official still has a staged-expert `done_seq` in `malloc_host` polled by a volatile host load (`prefill.cpp:388-393,513-523`) and a separate PLE upload completion word similarly polled (`:1079,2341-2362`). Prompt chunk, ring, stream threshold, CPU share, PCIe fraction, cache, MTP, and worker-count settings do not replace those handoffs with a supported synchronization contract. Positive `--pcie-frac` without `--stream-experts` is explicitly warned as fault-prone on the Xe path (`generate.cpp:2557-2569`); pin it at 0 for this target. Nor does removing all-ID kernel preload (absent from official v0.1.43 `sycl/src`) establish that the selected long-prefill kernels compile and execute correctly.

Therefore, **do not run this pristine parameter matrix on the stated target unless Main first establishes a supported, normal >=32K prefill and decode route for the exact driver/runtime/capabilities and selected kernels.** A smaller chunk or an abnormal GPU-only/no-CPU path is not such qualification. Feature/functionality updates remain a separate decision: they may be accepted on their functional merits even if measured inference performance regresses; that does not make the pristine search complete or permit describing a comparison as “against optimized official.”

## Smallest defensible search once that gate is satisfied

Use one frozen model/artifact set, device/runtime/compiler, tokenizer, KV/context policy, profile, sampling policy, generation length and allowlisted environment. Use at least 32,768 exact prompt IDs for selection; 64K can be a separate prefill block if it fits the fixed context. Keep run/process state fresh. Preserve the installer-generated configuration as its own **stock auto** arm, the historical fixed recipe as a **matched settings** arm, and the following as **independently selected official** settings. Do not call omitted CLI flags “installer defaults”: setup-generated server args include `--expert-cache auto --prefill auto --spec 4 --spec-min-p 0.5` (R177 source audit); source defaults and generated args are not identical.

**Prefill screen:** Hold decode and residency controls constant. Screen the installer stock `auto` policy and requested fixed chunks 4096, 6144, 8192 on one frozen >=32K selection prompt. These are the smallest source-grounded set: 4096 and 6144 bracket the historically effective 6144; 8192 tests the repeated historical request. This is a bounded candidate bracket, not a claim of global optimum. Keep profile/cache policy, explicit borrow policy, ring settings, PLE, CPU share, KV, and output fixed for fixed-chunk rows. Auto is a distinct admission/lending policy and must remain labeled as such. Record requested value, admission/clamp/resolution, initialized chunk/ring, each PP position/time, total batched positions, terminal prompt-token work, cache slots/MiB, and VRAM headroom. Deduplicate rows that resolve to the same effective geometry. Add exactly one `auto:16384` row only if 8192 is admitted and PP/cache/headroom evidence gives a concrete reason to test the larger admission ceiling; do not expand to 32768 by default.

**Decode screen:** Freeze the selected prefill, same model/prompt, output length, KV, cache/profile policy, MTP artifact, spec width, and min-p. Compare pool workers `auto (0)` and explicit `3`; add explicit `5` only if the runtime reports that it differs from auto or if the preserved historical matched arm needs it. The Ryzen 5 5600X has six physical cores; source auto is derived from detected topology and host participation, so inspect the effective INFO rather than assuming what `0` resolves to. If auto and five resolve identically, count them once. Record effective workers and host participation. Select on median decode tokens/s, but retain every screening value and health/output status. Keep prefill timing separate. If workers do not materially improve decode, keep auto and stop. Only if the run is decode-bound and worker rows do not explain it, add a separate, conditional spec-width comparison (e.g. 2 versus 4, or 4 versus 6 only if the exact MTP artifact supports it), holding all else fixed and checking output/quality plus drafted/accepted counters.

**Do not fold policy axes into these screens.** Cache is a shared VRAM/miss policy, not an independent prefill or decode knob: explicit requested slots can be cut, and per-layer budgeting can yield a different actual slot count (`generate.cpp:4280-4505`). Hold actual cache/profile policy fixed during chunk and worker screens; if INFO/`--stats` shows cache pressure or misses are the limiting factor, test one declared two-arm cache policy comparison (installer `auto` versus historical fixed 128 with per-layer mode) as its own cross-phase question, recording actual slots/MiB, admissions, hits/evictions and output quality. KV format/residency, context and VRAM reserve jointly alter capacity, traffic and sometimes numerical output; do not use them as hidden cache adjustments. `--pcie-frac` is fixed at 0 for this B570 route. `STRATA_PREFILL_CPU_SHARE`, ring, lend percentage, stream thresholds, affinity, host core and host-worker participation are additional interacting policy/placement choices, not first-pass independent settings. `STRATA_FETCH_THREADS` is file-backed source prefetch, not CPU expert-pool workers; the official CLI does not expose task grain. The source's available controls and their effects are documented in R177/R367.

## Held-out decision and evidence to retain

Choose settings using selection inputs only, then freeze the selected prefill and decode tuple before validation. Use a distinct, same-length held-out prompt-ID sequence (at least 32K; same model/artifacts) for an independent fresh-process validation. Run at least three separate decode processes per held-out arm—stock auto, matched historical recipe, and independently selected official—and retain every decode value, median, range, generation/correctness/fault result and exact prompt/output hashes. Keep independent prefill completions and times separately from decode; three fresh-process prefill validations are preferable if claiming a speed difference. Use counterbalanced order with a repeated baseline to expose drift. Do not reuse prompt-cache/session state as an independent prefill repetition.

Record source/binary hash, full explicit argv, exact generated stock config, selected environment allowlist, model/profile/MTP/tokenizer and prompt hashes, requested and effective settings, runtime/driver/device, context/KV, cache slots/MiB, pool worker count, PCIe share, spec/MTP counters, phase times, per-run order and correctness/fault status. Startup INFO reports effective worker/cache/KV/spec/PCIe fields (`generate.cpp:8421-8433`); chunk resolution and PP lines are needed alongside it (`:5940-6028,11631-11674`), while `--stats` provides cache and pool service evidence (`:12609-12668`). Keep the original individual results and compact receipts under the repository's artifact-retention rules. Report the selected tuple only as best among the tested candidates on this workload; if differences are inside observed spread, retain the simpler stock policy rather than widening the grid.
