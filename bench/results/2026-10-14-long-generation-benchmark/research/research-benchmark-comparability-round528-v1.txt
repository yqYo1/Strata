# Benchmark comparability and incomplete evidence audit — round 528

Date: 2026-10-14 (Asia/Tokyo). Read-only audit of benchmark sources at feature/sycl, HEAD 2f097af9a4e5aa855cc664a4ac06fa43b5cb4704. No benchmark, test, build, Git mutation, GPU/service action or cleanup was performed; the live screen was left untouched. This is the only file written.

## Findings

### Long-generation eligibility and interpretation

tools/long_generation_bench.py:45-73 requires normal stream completion, integer completion usage within 1,024–8,192, at least 512 visible answer characters, at least 32,768 actual prompt tokens, no prefix reuse, valid engine decode timing and at least 256 valid offered drafts. Although generic digest() can fall back to stream-piece count, this gate independently reads usage.completion_tokens, so missing usage cannot masquerade as a valid long response (tools/strata_bench.py:191-217). Thinking is explicitly on and included in completion usage (long_generation_bench.py:13; request at strata_bench.py:274-282). These are good safeguards against short or unmeasured samples.

The gate checks body length, not correctness of the 80 tests or story (long_generation_bench.py:18-40,54-55). The result sets quality_qualified=False and README says correctness was not checked (strata_bench.py:300-307,825-828,905-908). Keep “eligible generation sample” distinct from “task succeeded.”

### Comparability does not cover the full workload or source identity

Rows carry request SHA, workload version, settings, order, output/reasoning digests and measurements (strata_bench.py:272-282,300-307). But compare_table() gates compatibility only on workload version, thinking, temperature, minimum input and max output (strata_bench.py:912-934). It ignores request/prompt hashes, reasoning budget, model/quant/config, actual input/output gates, eligibility and sample count. Machine differences are notes, not a comparison gate. Two v3 runs with changed prompt bytes can therefore show a delta, and mismatched model/config can still show one.

The extended wrapper hashes fork benchmark files and recipes and records fork HEAD (bench/results/2026-10-14-long-generation-benchmark/check_extended.py:83-96). It invokes the actual client from U via P/bench.sh (run_server_job.py:146-155), but benchmark_source hashes files under P, not the resolved upstream U/bench.sh and U/tools/strata_bench.py; the upstream revision/cleanliness is not recorded. Thus the receipt does not cryptographically identify the code that ran.

Minimal correction: hash the resolved upstream wrapper and every executed/imported benchmark module, or verify and record immutable upstream commit plus clean worktree. Store a canonical run identity for exact messages, request template, thinking/reasoning budget, sampling, model/quant/config, context and workload version. Emit “not comparable” unless identities match and both sides have the declared eligible sample count; show differing fields and eligible/ineligible counts.

Observable checks: changing one prompt byte, thinking, reasoning budget, model/quant or client source hash must suppress the paired delta and name the difference. Matching identity with fewer than three eligible rows on either side must show raw rows/counts but no qualified comparison. Mutating the upstream client after provenance capture must fail source verification.

### MTP agreement has no no-MTP speed baseline

The code reports eligible rows, median/range decode, per-row acceptance and pooled accepted/offered ratio (strata_bench.py:291-299,875-894). Classification requires all rows eligible, at least three runs, every regular-code row >=60%, and every varied-prose row <=40% (long_generation_bench.py:76-87). The README correctly limits this to observed draft agreement, not speedup or correctness (strata_bench.py:891-894). The suite has no matched MTP-disabled generation arm, so it cannot attribute a decode difference to MTP. Generic compare_table() is an unpaired median comparison (strata_bench.py:912-928).

Minimal correction: retain the current agreement-only claim. If speed attribution is needed, add a separately named matched on/off experiment with canonical prompts, interleaved order, same model/context/thinking/decoding, actual output gates and independent task-status evidence. The off arm should use the same generation eligibility criteria, but missing draft counters are expected and must not invalidate an otherwise measured generation.

Observable checks: a qualified high/low agreement pair must never set a speedup claim; a valid MTP-off response without draft counters remains a valid speed row; changed prompt/thinking suppresses a pair; short EOS or absent usage is retained but excluded with reason.

### Agent sessions preserve rows but mix partial sessions into summaries

The scripted agent flow has six sequential requests. A returned error is appended and breaks the loop (strata_bench.py:402-414); partial sessions are retained. Yet summaries use successful turns from every session (430-444), while the separate complete flag requires six successful, stream-complete, usage-backed turns (445-460). The README run count is sessions with more than one turn, not complete sessions (811-816). The extended wrapper requires all three complete (check_extended.py:128-132), but general reports can summarize partial prefixes as full session observations. Also digest().ok means no error and at least one piece, not normal stream completion (strata_bench.py:208-217).

Minimal correction: keep all turns and partial sessions, but compute formal session summaries only from complete sessions. Report complete/partial/failed counts and optionally separate partial-turn diagnostics. Define completed turns with normal finish/DONE and usage-backed completion.

Observable checks: with one complete six-turn session and one failure on turn 5, preserve all 11 obtained rows, report one complete and one partial session, and compute formal session medians from the complete session only. A content stream lacking DONE/normal finish remains raw but is not counted complete. README run count must equal complete sessions.

### Escaping exceptions or budget termination can lose structured partial results

The HTTP helper catches many request exceptions and returns an error row (strata_bench.py:150-188); those rows can be appended and the loop continue (252-290). Agent errors similarly preserve the returned prefix (396-414). But structured result writing happens only after suite.run() returns (1043-1059). The extended runner's subprocess.run(..., timeout=...) can raise before that write (run_server_job.py:146-161). The outer receipt records an error, but cannot reconstruct in-memory request rows. Its STOP watchdog belongs to diagnostic mode, not the extended suite (run_server_job.py:99-145). A failed request caught by chat and an escaped timeout/termination therefore have different evidence retention.

Minimal correction: checkpoint each compact request row immediately, including errors/ineligibility, with phase/run/turn and terminal state. On termination retain a partial result marked incomplete and unqualified; never silently discard or rerun earlier samples. Copy/hash the checkpoint before exit evaluation.

Observable checks: inject timeout after the first long row and require that row plus an interrupted marker and complete=false; inject failure after agent turn 4 and require turns 0–4 retained; terminate after checkpoint N and verify N rows remain hash-verifiable with no qualification; a clean run must preserve equivalent rows and complete status.

### Variance is visible, but not causal evidence

stat() reports median, min, max and n (strata_bench.py:220-225); eligible rows remain individually represented and acceptance also has pooled counts (291-299). No paired delta or uncertainty interval is calculated. Three-sample threshold classification is a predeclared category, not a variance-adjusted estimate. README notes unrecorded background load and power limits (825-841,905-908). Do not infer a code effect from medians across changed identities or from range overlap alone.

Minimal correction: performance-change claims should use matched paired runs and report per-pair deltas plus a robust interval, or state that only descriptive medians/ranges are available. Keep every sample and denominator. With three pairs, call intervals exploratory.

Observable checks: identical pairs give zero deltas; a single outlier remains visible and cannot be replaced by the best run; mismatched identity yields no paired interval; an interval spanning zero is labeled inconclusive.
