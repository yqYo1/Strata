## Source findings

The corrected implementation removes the host callable that previously changed the kernel-name lexical scope. In the private helper at `iq_kernels.dp.cpp:4304–4330` and generic helper at `:4333–4360`, the `#ifdef STRATA_SYCL_PREFILL_IQ4NL_EVENT_RECEIPT` only declares a local `receipt_event` immediately before the existing `strata::q_of(stream)->submit(...)` expression; the same original `parallel_for` lambda and kernel-name type remain in that expression. After it returns, the helper passes that exact local event to `iq4nl_receipt_record`. Thus the source-level provenance is direct and unambiguous: it is the event returned by that wrapper's submit, not a queue-tail event or separately reconstructed launch. The calls stay in their original function/lexical scope.

The sink is one function-local `static thread_local Iq4nlReceiptSink*` defined in the kernel translation unit (`iq_kernels.dp.cpp:17–20`) and declared once in the private header. CMake builds `strata_kernels` as a static library, so the fixture call resolves to that same definition rather than a second header-local TLS instance. The scope is non-copyable, rejects an already-active TLS sink and non-fresh storage, then installs the pointer; its destructor clears it. Since construction rejects any pre-existing sink, clearing to null is correct for current non-nestable use. No other submitting thread inherits this TLS sink. Multi-threaded wrapper submissions would not be captured by this scope and are outside its qualified contract.

The receipt array is bounded and allocated before the measured wrapper calls. `retain` increments a `uint64_t` serial only after a successful submit has returned, sets a sticky invalid bit on serial exhaustion or full capacity, and does not overwrite slots. It catches event emplacement exceptions and leaves the stream invalid. One small implementation detail: it increments `count` before `slot.event.emplace(event)`, so a failed event copy leaves a counted slot without an event. The fixture rejects `sink.invalid` before consuming any slots, so this cannot produce a passing partial sample in the current harness. It must remain a sticky whole-batch failure in any later consumer.

`retain` stores arm, type, `n`, pointers, scope ID, serial, queue pointer, and event. The queue pointer is obtained by a second `q_of(stream)` call after submit. In this codebase `q_of` is a simple stable conversion: non-null stream is cast to `sycl::queue*`; null maps to `dpct::get_in_order_queue()` (`sycl/include/strata/sycl_queue.hpp:12–14`). For this fixture the call is `&q`, so the recorded `&q` check is sensible. It is still metadata re-derived from the stream argument, not an independent query of which queue owns the event. Direct binding at the submit site is the actual source identity evidence.

The profiling gate is tied to the fixture's actual `q`: the receipt-enabled constructor adds `enable_profiling`, and before the run it checks `q.has_property<enable_profiling>()`, `q.get_device().has(aspect::queue_profiling)`, and records `profiling_timer_resolution` (`prefill_iq4nl_parity.cpp:217–230`). The sink then checks recorded queue pointer equals `&q`, plus expected scope/serial/arm/type/size/input/output pointers, and requires `command_submit <= command_start <= command_end` (`:171–190`). These checks establish that metadata matches the expected two-call fixture plan and that queried timestamp ordering is admissible. Timestamp order and metadata alone do not establish event identity or a performance result. Source inspection establishes event identity here because the exact local submit return is what the sink receives. There is no comparison to pre/post guard events in this implementation; R179's guard-event test remains unrun and would be supplemental evidence, not a substitute for direct-submit source review. This parity fixture contains no timing aggregation or speedup assertion.

## Exception and lifetime paths

The fixture's `stage` at `prefill_iq4nl_parity.cpp:95–99` wraps each operation plus `q.wait_and_throw()`. If a submission or drain throws, or the async handler recorded an error, it emits `FAIL_STOP,...completion_unknown,no_USM_unwind` and calls `_Exit(2)`. That conservatively avoids freeing buffers on an unknown-completion path. Each generic and private receipt query occurs only after both respective stages have returned successfully, so command completion is already known before receipt validation or profiling-info queries begin.

After successful stage drains, a receipt metadata assertion, timestamp-query exception, or output/input validation exception unwinds to `main`'s catch. The per-repeat `receipts` array and `receipt_scope` are destroyed before `run`'s `Buffers` object; `Buffers` then frees device allocations. At that point the just-submitted wrapper kernels have already passed `wait_and_throw`, so event references are released before queue teardown and device buffers are not freed while those kernels can still be live. A later readback stage failure takes the fail-stop `_Exit` path and likewise avoids unsafe USM cleanup. This source handles the ordinary success, failed/unknown wait, post-completion query/validation failure, and readback failure paths conservatively.

The current code does not inject capture-copy failure, deliberate lost receipt, overflow, serial wrap, nested-scope attempt, timestamp-query exception, or readback failure. Their safe handling is therefore source reasoning only, not adversarial runtime proof. A capture-copy failure sets `invalid` after the helper returns, then the fixture's `stage` drain has already established completion; subsequent invalidation prevents timing acceptance. There is no retry, additional queue submission, or event wait in the recorder. The recorder's `noexcept` contract is satisfied by catching optional event emplacement exceptions. `q_of(stream)` itself is called inside that noexcept function and outside the `try`; for the current non-null `&q` fixture path it is just a cast, while a future null-stream scenario would rely on the default queue having already been initialized by the earlier capability/submit `q_of` calls. Avoid introducing potentially throwing queue-resolution work in this post-submit hook if the helper is generalized.

## Default-off and build isolation

All new binding, include, TLS, and record calls are under `STRATA_SYCL_PREFILL_IQ4NL_EVENT_RECEIPT`; with that macro absent, preprocessing removes the event local and record call and preserves the original direct submit path. The CMake option defaults OFF and rejects activation unless both private dequant and IQ4NL parity are enabled. It defines the macro `PRIVATE` on `strata_kernels` and `prefill_iq4nl_parity`, not on dependents or the normal application target. Therefore default builds receive no instrumentation and the macro does not leak through target usage requirements. In the dedicated ON configuration, however, the shared `strata_kernels` static library is also linked by the `strata` target, so that test configuration's application-linked kernel object contains the instrumentation branch (with an inactive TLS sink unless a scope is installed). This does not affect default-OFF builds; it is an artifact-isolation qualification if the requirement is that no application executable in the ON build contain the instrumented library.
