## Finding

The installed `qwen3.8-flash-next-iq3_s` pack metadata declares Down format type 20 in 39 of 48 native expert layers. This makes those layers format-eligible for the private helper if the loaded runtime layout matches the pack and the direct FP16 prefill branch is selected. It does not prove that the active process loaded this pack, selected those layers, routed any experts in them, or submitted either generic or private Down-dequant kernels.

The private IQ4NL helper is reachable from one production callsite in `Prefill::run_impl`. It runs only for a positive routed expert that reaches the direct native compute branch, with loaded `f.d_type == 20`, the private helper built in, and the runtime opt-in frozen true. The earlier MMQ branch returns before this callsite; the fused expert path also has its own route. Therefore a type-20 format inventory, symbols in a compiled image, chosen prefill mode, or an assumed top-k count is not a call census. Root needs a small caller-side receipt tied to actual nonempty routed experts and successful wrapper returns before attributing any optimization to this model.

The most direct source-level qualification route remains `STRATA_PREFILL_MMQ=0` before the first `mmq_plan()` initialization, plus the private build option and `STRATA_SYCL_PREFILL_IQ4NL_DEQUANT=1` at process start. This suppresses the MMQ plan, but still does not force a particular prefill mode, establish that a type-20 expert was routed, or turn source eligibility into runtime evidence. `STRATA_PREFILL_LAYER_MAJOR=2` deterministically selects the layer-major implementation only where its existing full-model, single-GPU, compact FP16, source-present and resident-K/V admission conditions hold. A census intended to describe ordinary production behavior should record the actual mode instead of changing it for convenience.

## Source route and execution modes

`Prefill::run` chooses `run_layer_major` when `STRATA_PREFILL_LAYER_MAJOR=2`, or for mode 1 when its `multiple` condition holds; otherwise it calls `run_impl` (`prefill.cpp:2353-2362`). Layer-major loops over layers and calls `run_impl` for each (`:2690-2780` in R169's pin). Ordinary prefill also enters `run_impl` directly. Thus both ordinary and eligible layer-major prefill can reach the private callsite. There is no other production call to `iq_dequant_f16_prefill_iq4nl` in this worktree: the only references outside its declaration/definition are that `prefill.cpp` caller and the synthetic parity fixture. Decode does not call this prefill-only helper. This is a static source statement, not evidence either prefill mode selected it in a running model.

Within `run_impl`, per-layer `use_mmq` derives from the lazily initialized `mmq_plan()` (`:4014`). The plan defaults on when MMQ is built and `STRATA_PREFILL_MMQ` is absent or nonzero; explicit zero disables it (`:966-993`). Fused-route selection is separate (`:4021-4022`). The routed expert list is formed from experts whose `m.cnt[e] > 0` (`:4139-4187`); only entries in `order` are walked. The expert lambda's `if (use_mmq)` branch performs MMQ work and returns before the native dequant caller (`:4748-4797`). The direct native branch then reads the runtime layer format `f` from `expert_layout()` and checks `m.iq4nl_down_dequant && f.d_type == 20` before calling the private helper; otherwise it calls the generic helper (`:4799-4810`). The output shape is passed as `f.n_embd * f.n_ff`. Record these loaded values; do not assume dimensions or infer formats from the pack directory name. The source helper validates type 20, non-null pointers, positive `n`, and divisibility by 256 before submitting the fixed-type kernel (`iq_kernels.dp.cpp:4297-4315`).

Consequences for attribution:

- An eligible type-20 layer with no positive `m.cnt[e]` has no direct expert call in that chunk.
- A routed type-20 expert can still bypass direct dequant through MMQ or the fused expert route.
- Each direct expert/chunk call dequantizes the whole Down matrix (`f.n_embd * f.n_ff`), rather than only the expert's routed rows. Routed-row count and dequantized matrix size must be reported separately.
- `top_k × n_batched` is not a valid helper-call count. Routing, chunk boundaries, bypasses and layer formats determine actual calls.
- Runtime opt-in and build-option values are fixed at initialization; setting them after `Prefill`/`mmq_plan()` initialization cannot establish the intended route.
