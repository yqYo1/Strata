## Oracle and mapping

The independent scale decoder correctly implements finite binary16 normal and subnormal values as exact binary32 values: normals use `(1024 + mantissa) * 2^(exp-25)`, subnormals `mantissa * 2^-24`, with sign restored. It rejects exponent 31. The reference byte decoder is block-local: low nibble maps to output positions 0–15 and corresponding high nibble to positions 16–31. The codebook matches the pinned IQ4_NL table. Each expected product is one float multiply then the independent integer RNE encoder; no SYCL/GGML conversion routine participates.

The RNE encoder's current call sites use shifts 13 for normal mantissa rounding and 14 through 24 for subnormal rounding, so its `shift-1` and `1 << shift` expressions are in range for all present calls. The shift-zero case in the helper would be undefined if called with zero, but none of the current branches call it with zero. The exponent classification, halfway-even test, subnormal tie handling, carry into exponent, finite overflow-to-infinity, sign preservation and FP32 subnormal-to-signed-zero behavior are consistent with binary32-to-binary16 RNE. No arithmetic or indexing error found in the present finite fixture domain. As independent validation is source-only and compilation/execution is prohibited here, the oracle's actual compiled behavior remains unverified.

The corrected model geometry is coherent: fixture declares 2560 rows x 640 columns, 20 packed 32-value blocks per row, 51,200 blocks, 6,400 flat 256-value groups and 1,638,400 active words. Since 20 is not divisible by eight blocks per flat group, some groups straddle row boundaries; `row=block/20` and `inrow=block%20` make the generated markers distinct across those transitions. Each tested block writes all low/high positions with different row/in-row permutations. The direct expected loop uses contiguous block order and therefore does not duplicate device lane/group formulas. The kernel path's `ib=tid/4`, `il=tid%4`, `qs + 8*(il&1)`, low nibble for `il<2` and high nibble for `il>=2` agrees with the scalar mapping. Synthetic negative scales are explicitly marked as robustness cases; no NaN/Inf scales are admitted.

The 84-case count is correct: three shapes (256, 512, 1,638,400) x 14 finite scale encodings x two complete resets/repeats. Active words per arm are `2 * 14 * (256 + 512 + 1,638,400) = 45,896,704`. The constructor diagnostic is an additional 20 device constructor words and is not included in those active case counts. Every output buffer word including prefix and full post-active tail is compared, because expected buffers start from the canary image and comparison scans the entire allocated output. Input bytes, including guards and inactive tail, are snapshotted and checked after each diagnostic/case readback. Allocation sizes in the static assert are 921,728 input bytes plus two 3,276,928-byte outputs, totaling 7,475,584 bytes; host arrays account for 1,843,456 input/restored bytes plus four 3,276,928-byte output vectors (14,951,168 bytes), before small local metadata.

The constructor diagnostic calls the unchanged `sycl::half(source[i])` expression on the device and records observed bits against an independent RNE expectation; it does not replace the production expression. The labels say `IEEE_RNE_reference`, `target_specific_observation`, and `portable_contract_unqualified`, which correctly avoid claiming the observed constructor contract is portable. `aspect::fp16` and `half_fp_config` are recorded as advertised capability metadata, explicitly marked so; neither is used as proof of emitted rounding or effective denormal mode. Full kernel case expected bits still form an independent RNE check, and A/B bits are counted separately.

## Lifetime, fail-stop, and admission review

The host-only check completes before queue construction and uses only an ordinary local marker pointer for invalid calls. All seven invalid cases hit the private API's initial short-circuit argument validation before `q_of(stream)`, capability check, submission or dereference; the unsigned-workgroup overflow case reaches its final disjunct after the other predicates are false. `dst` is a non-null properly aligned cast of the marker but is never dereferenced along these rejecting paths. Marker remains checked. The 14 half roundtrips cover finite values from both signs including zeros and subnormal boundaries; six literal oracle edge checks cover normal even/odd ties, subnormal zero/odd ties, overflow tie and negative zero.

The async callback is `noexcept`, bounded to 1024 counts, and retains no exception text. Each device/queue operation has a flushed `STAGE` record and a wait-and-throw plus sticky-count check inside the fail-stop wrapper. A potentially submitted exception emits `FAIL_STOP,...completion_unknown,no_USM_unwind` and `_Exit(2)`, avoiding unsafe unwind/free on unknown completion. Host/readback validation failures occur only after a successful wait/readback and can unwind safely. All queue, async state, host vectors and device buffers outlive submitted work; the last in-run drain precedes `Buffers` destruction, which precedes a separate post-USM teardown drain and queue destruction. Normal `TERMINAL` appears only after queue teardown and a second sticky async check.

The selected GPU admission ties backend/in-order status and Level Zero native properties to the queue-selected device, checking B570 IDs and exact PCI address before printing and flushing identity. `FP16_CONFIG` follows; no runtime capability inference is made beyond those emitted facts. Queue creation precedes identity checks, so a failed selection can initialize a queue/runtime, but USM allocations and kernels do not occur until after admission. This matches the described gate.

## Parser counts and interpretation

For a normal, mismatch-free full run, deterministic stdout should contain: `HOST_PASS` 1; `IDENTITY` 1; `FP16_CONFIG` 1; `CONSTRUCTOR` 20; `CONSTRUCTOR_RESULT` 1; `CASE` 84; `PASS` 1; `TERMINAL` 1; `FIRST_DIFF` 0; `FAIL` 0; `FAIL_STOP` 0. `STAGE` total is 341: constructor upload/device/readback (3), 84 cases x two repeats x upload/generic/private/readback (336), final in-run drain (1), and post-USM teardown drain (1). Per-stage normal counts are constructor_upload/device/readback 1 each, upload 168, generic 84, private 84, readback 84, final_drain 1, post_USM_teardown_drain 1. `PASS` is emitted inside `run` before buffer destruction and outer teardown, so it is not a terminal success signal on its own. Parser/admission must require the later `TERMINAL,pass,...`, zero exit, and expected complete record counts.

When generic and private are exactly equal but both differ from independent RNE expected bits, `ab=0` and equal nonzero oracle counters classify a common reference/conversion-contract disagreement; that is not evidence of a candidate regression, but remains a failed expected-bit gate until investigated. Any nonzero `ab` is a candidate parity failure; separate `oracle_generic` and `oracle_private` counters identify which side(s) also differ from the selected expected contract. Current `FIRST_DIFF` prints one combined first difference plus all three values; CASE counters contain sufficient numerical distinctions, though an owner parser should derive and label these classes rather than treating every oracle mismatch as candidate-only.

## Findings and remaining limits

No current-path out-of-bounds, bad unsigned shift, aliasing, or use-after-free issue was identified statically. The only noted dormant helper hazard is `rne_shift(..., 0)`, which would have an invalid right-shift in the halfway expression if future code added such a call; current two callers always use shifts 13 or 14–24. The private invalid path is correctly ordered before queue lookup for all listed rejections. Exact output counts and teardown ordering are internally consistent.

This audit cannot establish build validity, compiler lowering, GPU output, exact runtime parity, effective rounding/denormal control, or whether target output agrees with the RNE oracle. Per R166, the local host `sycl::half(float)` implementation truncates subnormal output values while the device source path uses native half conversion; the device constructor diagnostic is the appropriate observation and its RNE check must remain explicitly labeled as an independent expected-bit check, not a portable constructor claim. The `half_fp_config` and aspect values are capability receipts only. Actual packed model reachability or full model correctness is not established by this synthetic fixture.
