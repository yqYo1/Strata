## Finding: parity teardown frees USM after an unclassified failed drain

`sycl/src/prefill/gdn_quad_parity.cpp:54-58` catches every exception from `q.wait_and_throw()` and then unconditionally calls `sycl::free` on every tracked USM allocation. A concrete trigger is any candidate/reference submission followed by a synchronous queue-finish/backend error where completion is unknown, then stack unwinding through `Buffers::~Buffers`. The destructor will release state, inputs, and outputs while a command may still reference them; when another exception is already active it also suppresses the drain/free errors at line 58. R8's queue contract says an unclassified failed wait is not a retirement proof. Keep those allocations quarantined until completion is established (or fail-stop without freeing); do not reuse this teardown path after a failed drain. This is a test-harness lifetime defect, not evidence of a kernel defect.

Partial-allocation cleanup at lines 47-52 happens before any recurrence is submitted, reserves space for all 11 pointers before the first allocation, and tracks each successful allocation; that ordering is sound for command lifetime. However, cleanup exceptions in this constructor catch are swallowed, so an unsuccessful `sycl::free` can leak without a distinct diagnostic. There is no injected partial-allocation-failure test in the source.

## Kernel structure and admission

The static mapping in `kernels.dp.cpp:1004-1057` is internally consistent by source inspection. The launch is 128 work-items (`1×4×32`); four SG32 subgroups each cover eight columns per row role. `rg=lane/8`, `c=lane%8`, and `col=cb*32+sgid*8+c` enumerate 4 row groups × 32 columns exactly once for each head/column tile. `stage=item.get_local_linear_id()` assigns every local item one distinct Q/K row `0..127`, independently of the reduction roles. All work-items write their assigned `sq/sk` entries, then meet a work-group barrier before any recurrence reader. Both barriers are outside lane-conditional control flow. `select_from_group` indexes `c,c+8,c+16,c+24`, which selects the four row roles for the same within-subgroup column; only `rg==0` writes each output column, and each lane's `base` covers its distinct state row/column cells. This is source-level coverage, not a compiler or device proof.

The reduction is explicitly left-associated for KV and output; per-row state/update/output loops preserve the reference order by inspection. The new fixture targets cancellation-sensitive values and checks the entire state/output against the explicit frozen pipeline reference after each carried call. No source-level mapping or synchronization counterexample was found. Runtime subgroup-to-work-item realization, barrier lowering, instruction order, and exact numerical parity remain unverified.

The admission path checks in-order queue, device SG32/WG128 and local dimensions, obtains an executable bundle for the exact named kernel ID, checks `has_kernel`, then queries that kernel's compiled subgroup size and WG capacity before submit (`kernels.dp.cpp:2678-2705`). It binds that executable bundle in the command group and invokes the same named kernel (`:2707-2718`). Khronos documents `use_kernel_bundle` as binding images for handler kernel invocations, and the kernel query for `compile_sub_group_size` reports the required subgroup size; these API definitions do not prove compatibility with the unbuilt oneAPI toolchain or B570 runtime ([SYCL handler reference](https://github.khronos.org/SYCL_Reference/iface/command-group-handler.html), [SYCL kernel reference](https://github.khronos.org/SYCL_Reference/iface/kernel.html)). The public spec also leaves subgroup composition implementation-defined, so hardware execution remains a required gate ([SYCL 2020 rev. 12](https://registry.khronos.org/SYCL/specs/sycl-2020/html/sycl-2020.html)).

The read-only admission try/catch ends before submission. The status is set to `Submitted` immediately before `q.submit`; any submit, norm-launch, or `check` exception then propagates rather than returning false and inviting legacy retry. Thus the source honors the intended pre-submit-fallback/post-submit-no-retry boundary. `q_of(stream)` and the in-order property check precede the query catch, but they do not mutate candidate state; failures there propagate rather than fall back. Valid-stream/caller ownership is assumed as elsewhere in the API.

## Test coverage and remaining limits

The added target is OFF by default. CTest sets `STRATA_GDN_QUAD=0`, turns off competing selectors, enables the old pipeline, and leaves REC_HEADS unset (`sycl/CMakeLists.txt:394-400`). The new tests call the explicit candidate and explicit reference APIs, not production `gdn_recurrence_variant`; therefore they do not prove automatic environment-selector precedence, production fallback dispatch, or integration with the real prompt caller. Forced denial verifies untouched buffers and then explicitly calls the legacy reference once (`gdn_quad_parity.cpp:116-133`); this proves the seam/reference behavior, not that ordinary dispatch took that fallback.

Empty candidate behavior is directly tested before queue lookup with null device pointers, plus full-state/output sentinels on device (`kernels.dp.cpp:2670-2674`; parity `:24-40,105-114`). The harness covers the short T set, carried second/third calls, a nonzero initial state, directed 48-head values, and an ordered-cancellation fixture (`:142-148`). Full-state and active FP32/FP16 output comparisons plus outer guards are present. No observed defect in those checks.

No cancellation mechanism or cancellation test exists: the executable has no stop flag/cancel path, and its prefix loop runs to total completion (`gdn_quad_parity.cpp:137-151`). So cancellation effectiveness is unassessed. The harness also does not test NaN/Inf propagation masks, inner per-head/tile redzones, actual production dispatch, asynchronous/post-submit fault injection, or the active session/model lifecycle; these are unproven rather than failed. The prefix mode is synthetic recurrence+norm only.

## Disposition

One definite harness lifetime issue requires correction before relying on failure-path safety: never free these USM buffers after an unclassified failed queue drain. Kernel mapping, converged staging/barriers, single-writer ownership, arithmetic association, and submit/fallback boundary have no source-only counterexample found. Compile/API availability, actual kernel bundle admission, device behavior, and all numerical claims remain UNKNOWN until root's separately controlled build/runtime gates. Existing report R88/R89 coverage gaps remain relevant; no validation was run here.
