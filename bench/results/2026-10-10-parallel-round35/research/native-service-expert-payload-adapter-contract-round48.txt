# Native expert payload adapter contract — round 48

## Scope and finding

Read-only source audit for the round 46 direct-wrapper service calibration proposal, at the frozen cache-work source family `66aaec3a66ad9ed12e6d042cffe743c47e364432`. I checked the production expert layout and file-backed source, the CPU wrapper geometry, the IQ3_S pack's small metadata file, the round 42 shape report, round 46 protocol, and report-registry v35. I did not read model payloads, dump tensors, build, test, run hardware, profile, query a device, clean artifacts, or change Git state. Only this report was written.

The key correction is that GGUF offsets do **not** name a ready-to-pass contiguous per-expert blob. They name three independently located tensor payloads: gate, up, and down. Each is an expert-major contiguous tensor slice, but an individual expert's three slices can be at different byte offsets and in different shard files. Strata's CPU wrapper wants the logical concatenation `[gate rows | up rows | down rows]`; `FileExpertSource` assembles that layout into a bounded destination buffer. Thus round 46's suggestion to pass an mmap pointer to a raw GGUF expert extent is invalid. Its metadata/provenance safeguards remain useful after replacing that pointer assumption.

## Source contract

At this frozen source, the layout API is `expert_layout()` (not a separate `currentExpertLayout` API). `expert_layout_load` parses one native row per layer into `fmt[layer]`, the logical pack `offset/bytes`, three role offsets in `gguf_off[3*layer+role]`, and optional per-role shard names in v4 `gguf_file` (header comments in `include/strata/kernels/cpu/expert_layout.hpp:18-40`; parser in `src/kernels/cpu/expert_layout.cpp`). It refuses future metadata versions, asks `native_fmt(gu_type,d_type,H,FF)` to derive sizes from ggml type traits, requires the metadata blob size to equal `NativeFmt.bytes`, and requires logical per-layer expert blobs to be contiguous in the packed `experts.bin` layout. This logical pack offset is not a GGUF tensor offset.

For a selected layer/expert, the role extents are:

- gate: `fm.up_off` bytes per expert;
- up: `fm.up_off` bytes per expert;
- down: `lay.bytes[layer] - fm.down_off` bytes per expert.

`native_fmt` defines `gu_row=ggml_row_size(gu_type,n_embd)`, `d_row=ggml_row_size(d_type,n_ff)`, `up_off=gu_row*n_ff`, `down_off=2*up_off`, and `bytes=down_off+d_row*n_embd` (`src/kernels/cpu/native_expert.cpp:32-64`). Therefore the assembled destination is exactly those three extents concatenated, without metadata-specified padding between roles. The wrapper reads GU rows at offsets 0 and `up_off`, and Down rows at `down_off` (`native_expert.cpp:124-159`). Its per-expert dot geometry is `n_embd=2560`, `n_ff=640`; residual/workspace width R=10240 is a separate model-path dimension and is not a substitute for either. Keep both NT activation formats and row sizes from the selected layer's `NativeFmt`.

The GGUF offsets are absolute file offsets, including the GGUF data-section start. `check_experts_gguf` independently opens each declared source shard, finds `blk.<layer>.ffn_{gate,up,down}_exps.weight`, and checks role type, exact tensor shape, expected payload bytes, the equality `data_start + tensor.offset == native_experts.txt offset`, and file bounds (`src/core/expert_source.cpp:2559-2609`). GGUF tensor shapes are `[n_embd,n_ff,n_expert]` for gate/up and `[n_ff,n_embd,n_expert]` for down; dimension 0 is the quantized row and dimension 2 selects expert. Role (r)'s selected slice begins at `gguf_off[3*l+r] + expert*role_bytes[r]`. Never infer it as `gguf_off + expert*blob_bytes`.

There is no order, adjacency, shared-shard, or per-expert alignment contract for those three GGUF starts. The metadata sample itself demonstrates why: layer 0 (types GU18/Down20, logical blob 2,176,000 B) records gate offset 1,386,491,904, up 1,711,166,464, and down 913,711,104. Down precedes both GU tensors. The header is v3, so the three roles use the designated --native GGUF shard; v4 can name different files for gate/up/down. A version-3 row without a shard column does not authorize reaching into an adjacent numbered shard. Resolve every role's file exactly as the production parser does.

The pack's actual `native_experts.txt` was read as metadata only and hashes to `d9ac2dfa3ee63c55c9c6a6db26f72da0cec0ee41733f007e5cbbbba71617aa5d`; its header declares 48 layers, 512 experts, and 50,292,326,400 logical packed bytes. Those values and the 18/21/22/23 GU and 20/42 Down counts match the round 46 record. Bind the future run to this exact metadata hash, selected model/shard identity, shard file sizes, and source/build receipts. Do not treat this metadata hash as a hash of GGUF payload bytes.

## Existing reader and smallest integration point

The narrowest existing production reader is public `FileExpertSource`: call `expert_layout_load(pack_dir,48,512,err)`, `set_gguf(native_shard)`, `open(pack_dir,48,512,err)`, then `copy_blob(layer,expert,dst)` with a caller-owned `NativeFmt.bytes` buffer (`include/strata/core/expert_source.hpp:417-544`; implementation in `src/core/expert_source.cpp:298-376,575-678,1172-1206)). On the no-`experts.bin` native path, open checks GGUF metadata and maps each named shard read-only; this establishes virtual mappings, not a 50 GB resident read. The reader stores one role base and exact per-expert stride for each of the three roles. `copy_blob` assembles them in gate/up/down order. `mapped_blob` intentionally returns null in GGUF mode, since no contiguous blob exists in any source file. `blob()` returns a reused staging-buffer pointer; `copy_blob` is the safer calibration boundary because the caller controls scratch lifetime and no stage-buffer eviction can invalidate data during wrapper execution.

The present `native_wrapper_parity` target links only `strata_kernels_cpu`; `strata_engine` contains `src/core/expert_source.cpp` and links the engine/core layers. Thus the reader API exists, but it is not currently linked into the CPU-only harness (`sycl/CMakeLists.txt:245-282` in the wrapper worktree). Do not silently reimplement the full packer or assume the CPU library exports a GGUF reader. For future integration, first assess whether the same CPU-only target can link a narrowly extracted reader/validator without pulling in the GPU engine. If not, an opt-in harness-only adapter should share the existing layout and GGUF validation code where possible, then issue bounded role reads into one reusable `bytes` buffer; it must not duplicate parsing semantics or create a second full model representation. This round only identifies the seam and does not authorize that implementation.

`copy_blob` touches/copies the full logical blob even when a timed kernel phase uses only GU or Down. To report cache-working-set bytes by phase, count the selected role spans the wrapper actually reads: GU = gate + up = `2*up_off`; Down = `bytes-down_off`. Do not count a raw contiguous `blob_bytes` range in the GGUF, and do not attribute the adapter's three-slice assembly traffic to the row-kernel service time. If service timings exclude loading, prepare the bounded cohort outside each timed interval and make that boundary explicit. The round 46 statement that a full selected cohort is “mapped/referenced” is too ambiguous: the shard VMA may cover an entire file while the resident cohort is just selected pages; separately, a staging copy makes one bounded logical cohort in scratch. Keep the 1 GiB cap on actual sample buffers, state the page-cache/pre-touch condition, and account for the union of sampled role spans. Do not pre-read or retain the full GGUF.

## Fail-closed calibration validation

For each sampled `(layer,expert)`, before any timing, record the three resolved role paths, metadata offsets, per-role byte sizes/strides, logical `NativeFmt` fields, selected ID, and source identity. Require: layer 0–47 and expert 0–511; exact loaded metadata hash; exact `NativeFmt` match for `H=2560,FF=640`; exact format/type and tensor-shape match; offsets equal `data_start + TensorInfo.offset`; `offset + 512*role_bytes` lies within that tensor and file without overflow; selected start adds only `expert*role_bytes`; sum of the three per-expert extents equals `NativeFmt.bytes`; and every resolved shard matches its recorded name/size/receipt. A missing v2+ offset, unknown shard, unsupported type, truncated or changed file, geometry mismatch, overflow, or invalid tensor shape aborts that cell. Do not guess, clip, concatenate adjacent bytes, or fall back to a different pack.

Validate assembly without retaining payloads: for a small predeclared set, independently locate each role by GGUF tensor name and metadata, read only that selected role extent, hash it, assemble a temporary logical blob in gate/up/down order, and compare its hash/bytes with `FileExpertSource::copy_blob` output. Drop the temporary after comparison; keep only role/assembled hashes and exact extent provenance. This checks selected bytes and the reader's concatenation order without a persistent raw fixture. Before/after, recheck metadata and shard identity; any change invalidates the run. Then run the existing wrapper correctness gate on the actual assembled bytes and exact production activation-quantizer outputs before recording service timings. Correctness, source identity, and page faults/failures stay separate from timing. Actual routed IDs may only be labeled route-derived if tied to a complete R42-compatible route receipt; otherwise use predeclared metadata IDs and call the result a format-kernel calibration. R42 supplies shape counts, not payload provenance or per-job milliseconds.

No external GGUF specification lookup was needed: the production packer, GGUF tensor reader checks, and actual source assembly path establish the byte contract directly. This report makes no latency forecast and adopts no cache candidate.
