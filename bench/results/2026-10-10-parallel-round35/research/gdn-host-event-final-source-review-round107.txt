In each kernel lambda, the only values used are the original kernel inputs. The thread-local sink, clocks, optionals, and event storage are host wrapper code after submission returns, so the capture does not enter either device lambda. The norm event is the existing `gdn_out_norm_keyhead_kernel_43e92c` event; recurrence identity is the existing legacy or quad kernel. The original explicit executable bundle binding, kernel names, ranges, subgroup requirements, and arithmetic bodies remain at their existing launch sites.

`DiagnosticBinding` saves the previous thread-local pointer, rejects nesting, and restores the previous pointer on both scope exit and its explicit post-drain restoration. Each arm owns a fresh capture; its two optional events remain alive through timestamp reads and are destroyed before the next arm. On an ordinary profiling query failure the binding has already been restored. In the diagnostic path, the existing profiling property is checked before buffer construction or submission; it is never changed. `PROFILE_QUERY_FAILED` is outside `gpu_stage`, reports `completion_drained=true` and SYCL category/code/message where available, and propagates through normal `Buffers` destruction. That destructor performs the required final drain and releases the owned USM; if that drain fails it preserves fail-stop behavior. By contrast, submission or completion/async-error failures stay inside `gpu_stage` and retain no-unwind fail-stop semantics. No fallback/retry is added after submission.

The corrected source permits `end >= start`, computes device elapsed durations from the same returned event's timestamps, and keeps these separate from the host steady-clock service interval. It stops the service clock after `wait_and_throw()` and queries event timestamps only afterward. It does not sum device times into host service or treat timestamp epochs as host-clock values. A zero duration is accepted as a nondecreasing API result, not presented as proof of profiling failure.
