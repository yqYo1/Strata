## Mathematical gate

The current source join has a concrete provenance chain: v5 calls the pinned route parser on the request-owned stderr byte interval, uses the frozen parsed histogram attached to that same request, obtains residents from the exact pinned static profile, maps layer formats from the exact SHA-pinned pack metadata, then calls the pinned `reconcile_shapes`. Inputs must carry literal `passed is True`; each route's begin/end must be complete and non-offloaded; coordinates/types are bounded; each pair must satisfy integer `0 < J <= N <= 2J`; residents must be all hits and nonresidents all refused; overflow in expected totals is rejected.

For each refused pair, the helper derives `J1=2J-N`, `J2=N-J`, skips zero-job widths, and accumulates (phase, actual layer format, NT) cells with experts/jobs, tokens, and output rows. GU rows per job are 640 and Down rows per job 2560. It then builds a dictionary from actual histogram cells and requires exact key/value dictionary equality with the derived cells. Duplicate actual keys are explicitly rejected before equality. This checks per-format and per-NT allocation and row values, so a correct global total with a wrong format or NT assignment does not pass.

The caller also reconciles native histogram phase tokens with route refused entries and phase experts with distinct refused callback pairs. The pinned histogram parser verifies the frozen default settings/cell schema, selected/eligible labels and scalar variant. The route parser independently validates sorted unique coordinates, request ordinals, classifications, sparse sums, END/DONE counters, all-layer coverage, and static residency. This is a coherent layered check, conditional on the source-proved emitter invariant: each expert callback pair contributes one job, split verification limits each grouped job to NT1/NT2, and `N,J` therefore determine those two job counts. It is not a new resolver execution, a check of actual worker fragments, timing, traffic, or latency.

Metadata handling deliberately remains type-map only. The helper pins bytes and 48-layer/logical/blob geometry, admits GU/Down codes and derives per-layer format labels; v5 separately pins `native_experts.txt` and marks that no GGUF role extents or tensor payload content are validated. The report must not treat this as full model-file validation.

## Compact receipt and offline replay

The new receipt no longer embeds every parsed PAIR dictionary. For each request it retains the pair summary (begin/residency/end totals, layer-entry totals, frame bytes, and pair count), a canonical encoding description plus SHA-256 of the ordered `[layer,expert,N,J,J1,J2]` list, and one replay descriptor with stderr path, byte begin/end, interval SHA-256, parser SHA, shape-helper SHA, and resident-profile SHA. The full engine stderr path remains in the run directory and receives an overall byte count and SHA-256. The request also retains the exact DONE protocol text and the parsed frozen native histogram (including its raw line), while the top-level receipt retains profile path/hash, pinned metadata filenames/hashes, pack path through target argv, source pins, and the helper/parser hashes.

That is sufficient for deterministic offline recomputation while the raw stderr and pinned inputs remain available: extract/hash each interval, rerun the exact parser with the retained ordinal/DONE and resident profile, rerun the frozen histogram parse and format-map/reconcile helpers, then compare summary values and canonical pair-shape hash. The producer emits all BEGIN/RESIDENCY/PAIR/END records and calls `fflush(f)` before returning; its call site is before DONE emission. Thus taking the post-DONE stderr end offset does not omit buffered pair records. The compact record alone is not a substitute for the interval: if the required raw engine log or exact profile/metadata/helper sources are retired, replay ceases to be possible. Keep the engine log under artifact-retention policy for any stated replay consumer; v5 itself does not duplicate it into the receipt or claim that a log can be recreated from the digest.

One practical evidence limit: the canonical pair-shape digest supports equality verification after replay but does not expose pair-by-pair shapes to a reader without the raw interval and parser. This is the intended compactness tradeoff and is adequately documented by the replay pointers; do not describe the summary alone as a self-contained replay fixture.

## EOF change and residual source limitation

Unlike v4, v5 records PTY EIO/zero-read observation and, after QUIT, allows that transport EOF to remain recorded while awaiting a separate GDB/MI exit result until the finite deadline. The final gate still requires observed transport EOF and exit code zero/no signal; EIO before QUIT fails. This avoids v4's immediate false-negative when MI notification lags PTY closure without treating EIO itself as evidence of normal exit. The finite loop and actual MI result remain the acceptance boundary. No real PTY/OwnedGdb ordering was exercised by this audit.
