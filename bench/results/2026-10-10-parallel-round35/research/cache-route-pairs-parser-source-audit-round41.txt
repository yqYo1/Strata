## Parser findings

No acceptance bug was found in the reviewed `parse_request` wire checks for the stated fixed run. The parser requires newline-terminated bounded input, rejects CRLF and non-ASCII marker lines, caps per-request marker bytes at 4 MiB and the closed interval at 64 MiB, checks canonical decimal uint64s and fixed key order, requires BEGIN/RESIDENCY/END at the right positions, ascending unique in-range PAIR keys, checked aggregate sums, exact resident/nonresident classification from the pinned map, and matching DONE counters. It also rejects an unexpected marker anywhere in the interval. Although the parser does not separately spell out a 140-byte PAIR cap, the fixed positional grammar and at-most-20-digit uint64 fields imply a smaller maximum line length; the existing 65,536-byte line ceiling is not the only bound on a valid PAIR record.

`static_profile` is a useful independent admission check: it validates the exact STRP v1 length and geometry, full unique ranked-pair set, and inverse rank-table tail, then independently builds the 128 resident pairs and little-endian int32 FNV map. The controller pins the profile file SHA before parsing, compares the computed fingerprint to both frame endpoints, and retains producer `unchanged`; this distinguishes profile-byte identity, expected initial host slot map, and within-request map stability. FNV remains a noncryptographic map join, not weight/model identity.

The controller closes each request's stderr interval after its stdout DONE, parses that interval against exactly one DONE, then scans the complete closed engine log for misplaced/extra marker lines and validates total marker bytes. The source therefore binds frame ownership to byte intervals and checks orphan frames outside requests. Its whole-job marker budget is 16 MiB. DONE parsing inside `parse_request` checks 16 tokens and the fields used for generation length, prompt size, finish status, reused count, read count, hit/look/offload totals; the controller's preceding `validate_fresh` additionally parses prompt/decode times and MTP counts. This is adequate as a joined controller gate, though the parser function alone is not a fully validating 16-field DONE parser and should not be described as one.

The profile and static residency assumptions are strictly tied to the report's command/source pins and exact 128-slot static configuration. The source checks a current resident pair has only hits and a nonresident pair has only refused entries, with offload zero. The sparse sum and DONE look equality rejects hidden admission/offload accounting under this run. The strict equal per-layer route-entry count and top-k-10 divisibility checks are specific to the fixed complete-layer window workload, not a generic frame parser.

## CPU fixtures: independence and coverage

The fixtures build their own textual golden frame and a synthetic STRP binary rather than importing producer serialization helpers. The profile test derives the expected resident set and independently recomputes the FNV slot-map bytes; this is valuable parser/oracle separation. The golden frame exercises 48 layers, all-miss classification and aggregate reconciliation, while status/numeric/framing tests perturb the serialized input. These fixtures are CPU-only by construction, but this review did not run them.

The source tests do not yet exercise several distinct branches that the parser claims to cover: a valid frame with actual hits/resident pairs; missing or duplicated BEGIN/RESIDENCY/END individually; an out-of-order or nested marker; malformed/uppercase/short FNV; PAIR counter addition overflow and sparse-total overflow; nonzero offload; callback-pair sum/cap violations; frame record-count and whole-job budget boundaries; DONE END-field mismatch for each of the three counters; and a frame whose request interval/ordinal is wrong at the controller ownership layer. Some nearby cases fail for a different reason (for example, duplicate whole frame and selected malformed integers), so they should not be cited as tests of those omitted branches. These are coverage gaps, not observed parser defects. The fixtures also do not test `run_owned_cache_route_pairs...` interval attribution or native-histogram joins.

One internal bound deserves an explicit invariant review: per PAIR, `callback_pairs <= callbacks/48` is checked, but the parser does not sum `callback_pairs` by layer and require each layer's sum to be at most its layer-callback count. If `callbacks` means total layer callbacks as the producer contract says, a malformed frame can make many individually legal PAIR values whose layer sum is impossible. The fixed producer may never emit this, but a fail-closed parser should add `Σ_e callback_pairs(layer,e) <= callbacks/48` (or prove a stronger exact relation) and a fixture with individually in-range pair counts whose same-layer sum exceeds that limit. The current equal layer-entry and divisibility checks do not imply this callback constraint.

## CPU native-job reconciliation and aggregate NT inference

Controller histogram parsing validates native caller jobs by `(phase,type,nt)`, requires `nt` only 1 or 2, checks `tokens = experts * nt`, enforces the fixed format/dispatch selection for GU18/21/22/23 and Down20/42, and reconciles GU and Down aggregate job/token totals. The route join then requires each phase's native token total to equal refused entries and each phase's native expert-job count to equal the sum of `callback_pairs` for nonresident pairs. Under fixed static residency, one refused `(layer,expert)` callback-pair occurrence corresponds to one logical CPU expert job; cached pairs are deliberately excluded. Thus the aggregate CPU-job reconciliation has a clear source basis and does not mistake all callback pairs for CPU jobs.

Correction to Round40's broad statement: V1 lacks per-window identities and per-pair NT bins, so it cannot give window-local timing or directly report per-window job-size distributions. It can, conditionally, yield an aggregate per-pair NT1/NT2 reconstruction for static misses. For a nonresident pair, let `J=callback_pairs` be its refused expert-job count and `N=entries` its refused routed-row count. If source semantics establish that those N entries are exactly the sum of that pair's actual job.nt values, and the joined native histogram establishes every such job has `nt∈{1,2}`, then `J1=2J-N` and `J2=N-J`; require both nonnegative. Sum the derived values by layer/format and reconcile them against native histogram bins. The aggregate controller currently checks only total jobs and tokens per GU/Down, not NT1/NT2 by layer/format and not these per-pair equations. Do not assert the formula as measured fact until the route-entry/job-row correspondence is source-proved and these checks pass. In particular, top-k can contain repeated expert IDs within a token, as the parser comment acknowledges; confirm how those duplicate route entries map into job.nt before using N. A version-2 per-window trace is therefore warranted for window phase/timing and direct future observability, but is not logically mandatory merely to recover an aggregate NT1/NT2 split if the stated scalar assumptions are proven from current evidence.

The parse histogram's NT ceiling and the route pair's global `refused`/`callback_pairs` equality are independent aggregate controls; neither alone proves a per-pair NT split. Proposed safe next check is an offline, source-backed derivation/reconciliation over the retained records, not another inference or a forecast.
