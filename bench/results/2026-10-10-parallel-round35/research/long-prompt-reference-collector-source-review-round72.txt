## Correctness and admission checks that are present

- Input admission pins the owner receipt, manifest, candidate bundle receipt and both token files. It verifies exact 36,004/37,462 complete canonical integer-ID serializations and hashes, ID ranges, private file modes, and the owner receipt's corresponding prompt summaries. It uses whole files as-is and does not tokenize, truncate, pad, or splice.
- The startup grammar requires the known single INFO record and `READY 262144 stop`; the INFO grammar allows only the free-VRAM integer to vary. The runtime `/proc` executable, argv, cwd, relevant environment and process identity are checked against the exact qualified baseline. The baseline original argv is explicitly required not to contain unsupported `--pool-tasks`.
- Each prompt request requires `RESUME 0`, every exact 8,192-token progress boundary plus final `N-1`, `REUSED 0`, a 16-field `DONE` with matching prompt count, bounded generated count, finish-reason rules, finite times, and valid MTP counters. It requires alternating T/LP records, exact stored-vs-wire ID and LP identity, in-vocabulary unique top-five candidates, finite nonpositive logprobs, and consistency between the selected ID/value and the first candidate. Early `stop` is allowed with 1–64 generated tokens; `length` requires all 64. It does not assume fixed MTP counts.
- Captures must be fresh, exact-size, finite first-head floats (248,320 values), and a complete 66-part state image. State part lengths/headers are checked against the rounded final page for `upto=N-1`, all part hashes and whole-file hash are recorded, and unexpected trailing bytes are rejected.
- The execution order is train, validation, train repeat, validation repeat in one owned process. Same-prompt repeat checks require IDs, every LP line, MTP counters, finish reason and first-head hash to match, plus all 66 comparator live-state parts equal at the exact prompt endpoint. Only after all four requests, repeat gates, final transport EOF/normal exit, fault/cleanup checks, artifact budgets and source/model identities pass does the code publish the compact prompt-keyed `references` and set `reference_established=true`.
- The PTY collector preserves raw stdout and records protocol boundaries. It distinguishes EAGAIN from EOF, rejects unknown/malformed lines and unexpected queued or partial output at command boundaries, requires EOF only after QUIT, and separately requires the owned inferior's normal exit code zero. The budget checks include captures, failure SAVE and aggregate text, with a reserved failure-receipt allowance; no success status is conferred by SAVE.
- The output and receipt fields explicitly keep performance eligibility, adoption, and `full_lifecycle_passed` false. This collector establishes only numerical references for these two prompts if actually run and all gates pass; it does not qualify candidate P, the later task-6 timing arm, full-context candidate lifecycle, or the earlier failed controller results.
