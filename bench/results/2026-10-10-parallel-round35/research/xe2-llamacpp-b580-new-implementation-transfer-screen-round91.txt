## Disposition

One bounded, measurable GDN candidate survives the novelty screen: test the llama.cpp token-blocked GDN schedule as a separate exact-order SYCL variant for Strata's existing `S=128` recurrence. It groups several value columns in a subgroup and stages a small token block of Q/K/V/gate/beta in local memory, while loading the following block early. This is distinct from simply enabling grouped GEMM/XMX, caching dequantized expert weights, changing quad/dequant layout, or weakening precision/fast-math. It is a conditional experiment, not an adoption or speed forecast: Strata already software-pipelines next-token loads, so expected incremental gain is uncertain; a fair comparison must measure whether deeper block overlap and cross-column register reuse improve on that baseline.

## Upstream evidence, pinned

Discussion #29643 (Torchit1, 2026-09-29) links the author's `arc-b580` branch and B580 guide: [discussion](https://github.com/ggml-org/llama.cpp/discussions/29643), [branch guide](https://github.com/Torchit1/llama.cpp/blob/fc18b1a60b0fda3ca2e1cb54e98d063e014dbe88/docs/bonsai-arc-b580.md). I pinned the actual GDN source to full commit `fc18b1a60b0fda3ca2e1cb54e98d063e014dbe88`: [gated_delta_net.cpp](https://github.com/Torchit1/llama.cpp/blob/fc18b1a60b0fda3ca2e1cb54e98d063e014dbe88/ggml/src/ggml-sycl/gated_delta_net.cpp) (not a mutable branch URL).

At that revision, comments at lines 2066–2075 state that the non-KDA `S_v=128` blocked kernel retains the same per-token recurrence, per-column arithmetic, and reduction order as the serial SYCL path; the author attributes the original bottleneck to a global-memory stall on each token (~0.4 us/step) and insufficient thread rounds at 48 heads. `gdn_blocked_sycl<NC,NW,T,keep_rs_t>` (about lines 2077 onward) lets each subgroup own `NC` value columns and share its K/Q registers across them, stages T tokens of K/Q/V/exp(g)/beta in SLM, and issues the next block's global loads before computing the current block. The kernel fixes subgroup width at 16; workgroup shape and `NC`, `NW`, `T` are compile-time choices. Source lines 2093–2105 define bounded prefetch-register arrays and SLM accessors (`sk`, `sq`, `sv`, `sgb`). Dispatch is gated to `S_v==128` and a minimum token count (around lines 2475–2483); it is explicitly non-KDA. Do not infer support for KDA or other state widths.

The same source comments report B580-only kernel timings at 1024 tokens: 48 heads 3383 to 1688 us using `(NC=8,T=8)`; 32 heads 2762 to 1024 us using `(NC=4,...)` (lines ~2366–2376). These are the author's GDN-kernel measurements on Intel Arc B580, not Strata, not B570, and not a full model result. The guide's whole-model/prompt/decode figures concern different model/quantization/backend combinations and are not transferred here. In particular, PTQ1_0 repacking/int8-DPAS, q4_0 KV XMX attention, and oneDNN prompt GEMM results do not establish gains for Strata's GGUF expert formats or active prefill path.

## Fit against Strata and prior work

Strata's audited GDN recurrence also has `S=128`, `HK=16`, `HV=48`; its normalized Q/K, sigmoid beta, gate construction, state carry, convolution, output norm/gate, and interleaved value-head-to-Q/K mapping are model-specific and must remain unchanged. R82 documents the exact equations, `qh=value_head % 16`, session-owned FP32 state, and the default `gdn_rec_cols_pipe_kernel`; it already software-pipelines next-token loads while keeping token recurrence order. Therefore the candidate is the blocked schedule (multi-column subgroup sharing plus T-token SLM staging/deeper prefetch), not a claim that Strata lacks pipelining or needs the upstream recurrence. Map Strata's interleaved heads and all its strides explicitly; do not copy GGML's indexing blindly. Preserve all tail, state-update, repeated-call, and exact/repeat checks.

This is not the earlier chunkwise WY/FLA candidate from R82: the upstream blocked kernel still executes the serial recurrence in original order, while WY changes how a chunk is algebraically formed and has a large all-chunk workspace problem at physical 262144. It is also separate from the R81/R9 grouped GEMM, XMX, and dequant-cache candidate space. Registry v47 records existing XMX call-path audits and dequant-cache lifetime work; those address expert matrix multiplication/weight reuse, not GDN's per-token recurrent data latency. No change to quantized weight semantics is proposed: the tested operator consumes the already-produced FP32 GDN inputs/state. It adds only bounded per-workgroup staging/register pressure, but occupancy, local-memory use, numerical parity under Strata's compiler, and cost at actual prompt chunk sizes remain unmeasured.

## Minimal next discriminator

If root elects to implement a probe, keep the existing recurrence/math and compare three named variants on the same target/source/build: current pipelined Strata kernel; blocked schedule with one conservative `(NC,NW,T)`; and, only if useful, one alternate block size. First compare identical 1024-token GDN inputs to match the upstream evidence, then the actual Strata prefill chunk/tail shapes and a full 32K-plus prompt. Record kernel-only and whole-prompt timings separately, FP32 state/output parity and repeated-call behavior, register/spill/SLM/occupancy data, device memory headroom under the 10 GiB cap, and exact environment. Retain the normal precise floating-point mode and existing quantized GGUF path. Do not make a fast-math or reduced-precision variant part of this experiment; prior precision/fast-math suggestions are a different, already-rejected candidate class.
