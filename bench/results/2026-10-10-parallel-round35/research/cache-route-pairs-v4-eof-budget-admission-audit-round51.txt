## EOF reason and ordering

V4 makes a real distinction between a successful zero-byte PTY read (`zero_read`) and Linux PTY master `EIO` (`pty_eio`); non-EIO read errors are separately recorded with errno and raw offset and re-raised. It records raw/framer byte counts, the cached GDB/MI exit code or signal, whether exit was known, the last stop, and whether QUIT had been sent. It stores this observation before `protocol.finish()`, so an unterminated tail cannot erase the EOF cause/order. EAGAIN returns false without manufacturing EOF; an already-seen EOF is not read/reclassified. The final loop requires actual framer EOF and a separately observed exit, then requires exit code zero/no signal. It does not call `finish()` merely because the loop ended.

The remaining issue is a conservative false negative in the EIO-before-MI-observation race. `available_stdout()` observes PTY EIO and immediately raises when `g.exit_code` and `g.exit_signal` are still unset. The main QUIT loop does call `poll()` (which invokes `g.poll(.01)`) before checking PTY readiness, but GDB/MI is a separate selector/channel. The source gives no ordering guarantee that its `*stopped,reason="exited-normally"` record is consumed before the PTY master becomes readable with EIO. `OwnedGdb.poll` updates cached exit fields only when it reads and parses that MI record. Thus an inferior that has already exited normally can be rejected if PTY closure is observed first; later cleanup/poll may populate exit code 0, but the saved `transport_eof` correctly retains the original unknown-at-observation state and the already-raised error remains. This is a deliberate fail-closed ordering policy, not a false success. The v4 fake fixture explicitly constructs this ordering and verifies a later normal exit cannot rewrite it, but does not exercise actual OwnedGdb/PTY event ordering. A future change seeking to avoid this false negative would need a bounded post-EIO MI-drain/exit-observation policy while retaining the initial EIO observation and never relabeling it as zero-read EOF.

Conversely, EIO is not automatically accepted merely because QUIT was sent: it only passes the boundary when an exit result is already cached, no partial frame exists, and the later overall result is normal. A nonzero or signalled exit remains rejected independently. Zero-read after known normal exit is distinct and accepted as observed transport EOF. The 30-second loop times out if no transport EOF arrives.

## Final failure receipt

The v4 code closes the R49 reserve edge. `encoded_failure` serializes after all current fields exist, iterates the self-referential byte/projection fields to a stable payload, and returns the exact bytes that are then size-checked and written once. If the full failure metadata is over the 1 MiB reserve, the fallback retains actual math/pair/histogram/protocol and exit state, C/D state, compact cleanup booleans, fault count, and bounded error excerpts; it includes byte count and SHA-256 for the omitted full failure payload. It remains `healthy=false` and `text_budget_gate_passed=false`. Neither branch upgrades math status. The exact final payload size, including the newline and declared-size fields, is bounded before write. The fixture contains an exact-1-MiB case and an oversized-metadata fallback case, plus an ordinary math-pass/budget-fail preservation case; these remain unexecuted source fixtures. External helper writes can still physically exceed the aggregate cap, but overflow is reported as a failed budget result rather than repaired or passed.
