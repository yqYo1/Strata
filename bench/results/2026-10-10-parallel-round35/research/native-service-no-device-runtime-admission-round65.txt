For a new service fixture, admit only an exact executable and environment that pass the combined gates below. The safest design is a genuinely host-only executable: compile the CPU pool and shared host-role reader without `-fsycl`; link only CPU/ggml/Threads and the host reader; do not link `strata_engine`, `strata_core`, `strata_kernels`, SYCL, UR, Level Zero, OpenCL, CUDA or HIP runtime. This sharply reduces the possible surface but is not alone proof against `dlopen`, a static constructor in an unexpected dependency, or a future link change.

## Finite, fail-closed runtime procedure

1. **Freeze the test boundary.** Record source revision, executable hash, complete `DT_NEEDED` closure, build/link command and hashes of the fixture and reader inputs. Check the executable and each resolved dependency with `readelf -d` and `readelf -S`: reject `libsycl`, `libur_loader`, UR adapters, `libze_loader`, OpenCL/CUDA/HIP runtimes, `.sycl_offloading` descriptors, and SYCL registration symbols. Require no SYCL/offload compile or link flag. Scan imported/defined symbols and the host reader's link closure for device entry points. An ELF scan establishes declared linkage only; it cannot exclude `dlopen` or private/local calls.
2. **Arm the tripwire before program constructors.** For an admission run, launch the exact fixture in a fresh child process with a minimal, recorded environment. A small test-only interposition library must load before executable/shared-library constructors and record-and-abort on every forbidden API. Cover the deployed runtime's exported UR calls for adapter/platform/device enumeration, context/queue creation, memory allocation/copy, kernel/command-buffer enqueue and native-handle conversion; include direct Level Zero initialization/discovery, context/queue/list creation, allocation/copy and kernel launch exports. Cover OpenCL/CUDA/HIP only if any such runtime is in the dependency or loader closure; otherwise reject that closure. Do not let a hit fall through to the real function. Preserve an event record with symbol, library, phase and call stack; any hit rejects admission and invalidates all timings. The preload constructor must itself write an “armed” marker before normal constructors; the parent verifies the marker and a clean child exit. At exit, record that the tripwire remained active through static destruction.
3. **Observe dynamic loading and UR.** In the same child, capture the runtime loader's shared-object load log (`LD_DEBUG=libs`, Linux) and require that no SYCL/UR/adapter/Level Zero/device runtime is loaded. Set the Intel DPC++ diagnostic `SYCL_UR_TRACE=-1` for a separate or same recorded admission pass to capture all supported UR trace classes; preserve both stdout and stderr. Intel documents levels 1 (adapter/device discovery), 2 (UR calls), and -1 (all levels) in its [DPC++ debugging guide](https://intel.github.io/llvm/developer/Debugging.html#tracing-the-sycl-runtime). The trace is a useful positive detector if SYCL runs; an empty trace by itself is **not** proof: it may mean SYCL never loaded, tracing was unsupported/disabled, or an API path bypassed UR. Dynamic-load monitoring and API tripwires close those specific gaps. Record the exact DPC++ runtime version because these are developer/debug variables whose behavior may change.
4. **Run one bounded fixture only after all gates are armed.** The child opens only the preselected role extents through the shared host reader, assembles one bounded real expert, constructs deterministic finite CPU inputs, calls the synchronous `ExpertPool::run_split_multi_native`, validates outputs, then destroys reader/buffers/pool and exits. No engine/service object, SYCL object, device selector, device enumeration helper, GPU callback registration, or GPU worker is created. Run the same guards from before `exec` through process termination; if instrumentation cannot be installed before dynamic dependencies/constructors, the run cannot claim runtime attestation. Keep timing disabled until admission and correctness checks have passed; on a tripwire hit, discard timings and report only the failure.
5. **Scope the wording to observed coverage.** With zero forbidden events, report separately: “no UR/Level Zero/OpenCL/etc. device query observed under the named interposition/tracing coverage”; “no context/queue creation observed”; and “no allocation/copy/kernel submission observed.” Do not collapse these into “no GPU” or infer them from `gpu_executed=false`, CPU-only output, invisible devices, or a zero-length log. State the platform/runtime/version, loaded-object set, symbol coverage, tripwire test vector and known bypass limitations. The result is an admission attestation for this exact binary/run, not a universal guarantee about all environments.

## Why common shortcuts are insufficient

- `ONEAPI_DEVICE_SELECTOR` limits the devices the DPC++ runtime considers available. Intel's [environment-variable reference](https://intel.github.io/llvm/EnvironmentVariables.html#oneapi-device-selector) says the default leaves all platforms/devices available and that the selector filters the runtime's available-device list. Filtering is not “no query”: the runtime may initialize adapters and enumerate enough devices to apply the selector. `native_cpu:cpu` can still create a SYCL CPU device/queue. Avoid a selector in the primary admission run; it changes the tested environment and can hide discovery. Do not use it as proof, and do not change system-wide device visibility.
- `gpu_executed=false`, no GPU output, successful CPU results, or an empty stderr are application-level outcomes, not runtime API telemetry. The R61 receipt itself says `runtime_tested=false`.
- Linkage/source scans miss later `dlopen`, C function pointers and hidden/local implementation calls. Conversely, interposition can miss statically linked APIs, hidden or versioned symbols, direct internal calls, `RTLD_DEEPBIND`/separate loader namespaces, or APIs absent from its list. Verify the actual resolver/provider for every covered symbol and reject unvalidated load paths; never call a zero-hit interposer “complete” without these checks.
- `SYCL_UR_TRACE` covers DPC++-emitted Unified Runtime calls as documented, not arbitrary direct Level Zero calls or another framework's device API. It is debug instrumentation, not a device-blocking mechanism. Keep it alongside direct API hooks and loader observation, not as the only guard.
- `ONEAPI_DEVICE_SELECTOR`, masking devices, unloading drivers, stopping services, device resets, administrator privileges, and system-wide environment changes are not admission substitutes. The fixture must be fail-closed without altering machine state.

## Pool abort and callback path

The CPU pool's stall-abort branches call `strata::core::release_gpu_waits(stderr)` (`src/kernels/cpu/pool.cpp:581,604`). The inline helper in `include/strata/core/progress.hpp:39–44` loads `release_gpu_fn`, whose initial value is null, and calls only when registered. A standalone CPU fixture must not register the engine callback or link engine code; under that source condition the error path is a no-op with respect to GPU release. This is not a runtime guarantee if a future executable registers the callback or if a different failure path is added. Include one bounded timeout/fault-injection fixture only after a no-GPU admission design exists; its intended rejection is a timeout with the tripwire still clean, not a GPU call to “unstick” the pool.
