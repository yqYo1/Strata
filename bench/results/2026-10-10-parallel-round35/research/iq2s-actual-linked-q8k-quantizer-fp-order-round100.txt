Finding

quantizer it actually links: on all fixture widths (256, 512, 2560, 8192), the
normal quantization path is emitted as separate scale multiplication then magic

contain that Strata translation unit.

Exact emitted path for ordinary fixture inputs
The assembly begins with a `k <= 255` early-return check. Every fixture length is
a positive multiple of 256 and at least 256, so each enters the block path; there
is no scalar tail path for those input lengths. The reference function's C scalar
loop over 256 values is auto-vectorized in groups of four floats. After finding
the block maximum and selecting its sign, the assembly computes `iscale` with
scalar `divss`. The inner quantization loop loads four XMM vectors of four values
each and emits four `mulps` operations using the broadcast `iscale`, followed by
four separate `addps` operations using the magic constant. Subsequent instructions
perform the bit-mask/subtract nearest-integer extraction, clamp to 127, pack the
integers, and store 16 Q8 bytes. There is no FMA instruction between these
multiply and add operations and no alternate scalar quantization tail for the
fixture widths. The post-loop Q8 scale `d` is emitted as a separate scalar
`divss` computing `1/iscale`; it is not folded into the byte-generation sequence.

Thus, in this exact linked build, each ordinary finite input product is rounded
as a float by `mulps` before the magic addition is rounded by `addps`. The compiler
has not contracted `iscale*x + magic`, reassociated the division, or changed the
source operation order in this quantizer. This specifically answers the concern
that `-fp-model=precise` alone was insufficient: the conclusion comes from the
linked instructions, not from interpreting the flag as a no-FMA promise.

Nearest-integer and bounds caveat
The magic-add bit trick is not an explicit `_mm_round_ps(..., _MM_ROUND_NEAREST)`
operation; its FP addition observes the current MXCSR rounding-control mode. For
ordinary supported quantization, finite nonzero scale, and inputs in a Q8 block,
`|iscale*x|` is bounded by approximately 127 because `max` is the signed value
with largest absolute magnitude and `iscale=-127/max`. `nearest_int`'s asserted
magnitude bound (4,194,303) is therefore comfortably met. The resulting ordinary
quantizer bytes are in `[-127,127]` (upper clamped at 127); this excludes the
exceptional tiny-scale/overflow or malformed-input cases from the ordinary claim.
The linked machine order is stable, but its tie rounding result depends on the
thread's rounding mode. It neither sets MXCSR nor proves that all production
threads use round-to-nearest.

The qualification README records release and ASan/UBSan test-entry MXCSR as
`0x1f80` before `ggml_cpu_init` and `0x1fbb` after initialization. The control bits
masked by `0xffc0` are unchanged, which means these two captured test states have
the same rounding-control, FTZ and DAZ controls; low exception-status bits differ.
This is evidence for those fixture runs only. The binary capture does not run a
request and does not report any server/pool worker thread's MXCSR.

Relationship to production `native_quant_act`
In the reviewed Windex source, `native_quant_act` selects `q8k_quant_avx2` when
`cpu_avx2_ok()` is true and `STRATA_NO_Q8K_AVX2` is unset; otherwise it dispatches
to the GGML Q8_K trait's `from_float`. The trait fallback resolves to the GGML
reference quantizer covered by this capture. The normal AVX2 branch instead lives
in Strata `src/kernels/cpu/iq_avx2.cpp`: it uses explicit `_mm256_mul_ps` then
`_mm256_add_ps` with the same magic value, and its source comment describes the
product-rounding boundary and byte-parity intent. Its GCC-only inline-assembly
barrier addresses GCC's default contraction behavior. The qualification build's
compile database contains no `native_expert.cpp` or `iq_avx2.cpp` object, and this
reference-symbol capture cannot establish what IntelLLVM emits for that custom
branch or establish runtime path selection for production. Record and inspect
that path's own linked code if the actual-weight gate uses `native_quant_act`
on an AVX2-enabled host; otherwise the reference capture is sufficient for the
trait fallback only.
