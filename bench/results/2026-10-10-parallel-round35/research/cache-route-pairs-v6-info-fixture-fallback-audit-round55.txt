## Compact fallback tuple

The added `transport_small_evidence()` (`:564-579`) maps EOF/read-error state into a fixed seven-element JSON-safe tuple: reason, raw offset, exit-known-at-observation, QUIT-sent, non-EIO errno, observed exit code and observed signal. It bounds integer magnitudes and signal length, keeps EAGAIN distinct from EOF through the unchanged reader, and avoids copying raw/pending bytes or the unbounded error repr into the compact fallback. `failure_save` inserts this tuple before `encoded_failure`'s fixed-point byte count (`:651-683`). The v6 fixture checks actual stored JSON bytes equal `serialized_failure_receipt_bytes` and remain within the 1 MiB reserve in each new fallback case; it also verifies mathematical PASS is preserved while health and the text-budget gate remain false. Existing near-reserve and normal-size cases remain present.

New exact-case limitations:

- The first fallback test seeds both `transport_eof={reason: pty_eio, ...}` and `transport_read_error={errno: EBADF, ...}` and expects both in one tuple. This is useful as a schema composition test, but it is a synthetic mixed state: production `available_stdout` records and raises a non-EIO read error, while a later EOF observation is not expected after that failure path. The separate read-error-only fallback case is the realistic case for errno/offset retention; keep the mixed case described as compositional, not as a captured transport chronology.
- The new compact tuple tests cover `pty_eio` with exit unknown and a read-error-only case. They do not exercise compact fallback for `zero_read`, EOF observed with MI exit code 0, EOF observed with signal, or signal length/type and integer-range handling. Existing v5 fixture coverage of zero-read and EOF ordering exercises the full-size in-memory transport record, not the new compact tuple. A focused table of those inputs would independently establish all tuple branches, especially the MI fields newly promised by the tuple.
- `transport_small_evidence` is tested with an intentionally malformed composite fixture but not with adversarial field types. Source checks (`type(value) is int/bool/str`) constrain those values; explicit bool-as-int, negative/out-of-range integer, and long/non-string signal negatives would verify the compacting guard rather than only its ordinary values.

No source defect was established in this read-only pass. The bounded fallback path does compute the payload after inserting its added fields, writes those exact encoded bytes, and the fixture checks the written-size invariant. The remaining gaps above are coverage gaps, not a claim that current actual data takes those states.
