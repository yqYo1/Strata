Pinned source selection
Pinned GGML `ggml/src/ggml-cpu/ggml-cpu.c` has one `GGML_TYPE_IQ2_S` CPU trait entry, assigning `ggml_vec_dot_iq2_s_q8_K`, `GGML_TYPE_Q8_K`, and `nrows=1` (around lines 362–366). The generic implementation `ggml_vec_dot_iq2_s_q8_K_generic` is defined in `ggml/src/ggml-cpu/quants.c`; it is not the trait entry for this type. In `ggml/src/ggml-cpu/arch/x86/quants.c`, the same exported dot symbol has compile-time branches in this order: `#if defined(__AVX2__)`, `#elif defined(__AVX__)`, then `#else` calling the generic implementation. There is no runtime feature branch inside this function in the source. The AVX2 body uses 256-bit integer vector operations (`_mm256_maddubs_epi16`, `_mm256_madd_epi16`) and `_mm256_fmadd_ps`; the AVX branch uses 128-bit integer operations with a vector float add/multiply schedule; the final branch calls generic.

The CMake logic for this build uses a single native CPU backend variant rather than `GGML_CPU_ALL_VARIANTS`; backend dynamic loading is off. Thus source/CMake show neither a separately linked AVX2-versus-generic library selection nor a runtime multiversion dispatch for IQ2_S. The trait function pointer leads to one symbol whose body was selected at compilation. A separate GGML generic function exists, but source does not show the trait selecting it as a runtime fallback for this configuration.
