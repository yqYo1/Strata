## Verdict

The subgroup remap is algebraically plausible and precision-preserving, but the underlying mapping is **not a new algorithm for Strata**: the frozen source already contains an AMD-only `gdn_rec_quad_kernel` that maps 4 row groups × 8 columns across a 32-lane wave, shuffles the four partials, and adds them in the exact `p0+p1+p2+p3` order (`kernels.dp.cpp:1239+`). That HIP-only path is not available to the SYCL B570 dispatch. R36 did not analyze a SYCL port; its scope was correctness/ownership of existing SYCL groups. The opt-in SYCL keyhead kernel is also distinct: it reuses Q/K across three value heads but still stores `rkv[VPK][RG][CB]`/`ro` in work-group local memory with barriers. Thus the reusable candidate is a narrow SYCL port of an existing cross-backend pattern, not novel repo-wide work.

## Mapping and barrier accounting

Current default `gdn_rec_cols_pipe_kernel` uses `RG=4`, `CB=32`, `NCB=4`; launch has 192 groups of 128 items, each for one head and one 32-column tile. Its local-coordinate mapping makes each 32-lane subgroup one row group: `rg=local_id(1)`, `c=local_id(2)`. For every token it performs five explicit barriers: before Q/K shared writes; after Q/K publication; after `red[rg][c]=kv`; after all readers finish before `red` is overwritten; and after `red[rg][c]=o` before output reduction. R83's “roughly four” phrase is only an estimate; exact frozen source count is five.

A 32-lane remap can let each subgroup represent four row groups and eight columns: get `sg_lane` and `sg_id` from the SYCL subgroup, assign `rg=sg_lane/8`, `c=sg_lane%8`, and `col=sg_id*8+c`. Four subgroups then cover the existing 32 columns. Compute each same 32-row FMA partial, retain it in a register, select/shuffle the same-column partials from lanes `c,8+c,16+c,24+c`, then explicitly evaluate `(p0+p1)+p2+p3`; repeat for output partials. Each work-item still owns its 32 state rows for its value column. This can eliminate the three barriers protecting shared `red` partials/reuse, leaving the two required local-Q/K publication/reuse barriers. It does not eliminate state arithmetic, global state loads/stores, or q/k/v global reads. Staging Q/K in existing `sk/sq[128]` avoids multiplying global q/k traffic; the existing register pipeline can remain. A new implementation must re-audit subgroup-uniform participation and output/state exactly-once ownership.

Do not derive row-group identity from ND local IDs: SYCL says subgroup membership is implementation-defined and portable kernels cannot assume a particular subdivision. Deriving roles from `sub_group::get_local_id()` and `get_group_id()` plus a required subgroup size avoids that specific assumption; require size 32 (or a separately designed 16-lane mapping), check compiled-kernel support, and fall back if unsupported. The current recurrence launch has no `reqd_sub_group_size`; its portability cannot be assumed. SYCL subgroup collectives such as `select_from_group`/`group_broadcast` provide the communication primitive, and all participating lanes must call collectives convergently. References: [SYCL 2020 rev12 subgroup mapping and group algorithms](https://registry.khronos.org/SYCL/specs/sycl-2020/html/sycl-2020.html), [Intel Xe subgroup overview/architecture](https://www.intel.com/content/www/us/en/docs/oneapi/optimization-guide-gpu/2025-2/intel-xe-gpu-architecture.html). No B570 subgroup/device query was run.

## Limits and next gate

Likely benefit is three avoided work-group barriers per token, while retaining two barriers for shared Q/K. It still performs two 32-row state loops and the same four partial accumulations; shuffle instructions add work and subgroup remap may worsen memory access or registers. No speed claim. R36 confirms fixed four-partial order and no atomic reduction; R33/R35 preserve whole-state/repeat requirements; R81–R83 explored WY (separate algorithm, not repeated here). The AMD-only quad kernel is the strongest source precedent, but its ROCm wave assumptions, LDS staging and timing do not establish B570 performance.

If advanced after the root-owned CPU equation oracle, first gate is an exact source-level mapping review and a SYCL CPU/reference arithmetic fixture: compare each `kv` partial and output partial, ordered sum, delta, state cells, output, and state ownership against serial source. GPU admission remains separate and must keep all existing state/logit/ID/MTP/repeat gates and numerical tolerances unchanged. No tolerance, adoption, or performance conclusion is made here.
