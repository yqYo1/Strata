# GDN kernel reduction and determinism audit (round 36)

Read-only audit of frozen C (`6cdf81078128488e5797afb9e92824b7ebe51124`) and D (`9c2ebde89e5157c81a9c9ae135719452a0244ca3`). It complements rounds 14, 31, 33, and 35; it does not repeat request reset or queue-order analysis. No source edit, build, test, model/GPU execution, profiler/counter action, cleanup, or Git mutation. The focus is actual SYCL GDN kernel bounds and work-group participation for a full `T=8192` chunk.

## Which kernel paths source selects

C and D `sycl/src/prefill/kernels.dp.cpp` are byte-identical (SHA256 `3a5077a284048b4fde24a4146e3b02e8d84d259480f755e4b0e94cfc52e54f1c`), so the GDN source dispatch and kernel bodies match.

For a non-HIP SYCL build, the default recurrence dispatch has `STRATA_GDN_PIPELINE` on when unset and `STRATA_GDN_KEYHEAD` off when unset; the experimental tuned key-head path additionally requires `STRATA_GDN_KEYHEAD_TUNED=1`. Thus the source-default `T=8192` path is `gdn_rec_cols_pipe_kernel` followed by `gdn_out_norm_kernel`. Setting `STRATA_GDN_PIPELINE=0` selects `gdn_rec_cols_kernel`; enabling KEYHEAD or KEYHEAD_TUNED selects other variants. For convolution, absent `STRATA_GDN_CONV_SERIAL`, `T>64` selects `gdn_conv_tiled_kernel`; `STRATA_GDN_CONVL2` can instead select the fused conv+norm route. Source establishes these defaults, not the live capture process's environment; pin the capture's recorded values before calling a non-default path active. The AMD-only HIP variants are compiled behind `__HIPCC__` and do not describe these SYCL frozen binaries.

The GDN constants are `S=128`, `HK=16`, `HV=48`, `C=10240`; the recurrent matrix contains `HV*S*S = 786,432` floats, followed by `C*3 = 30,720` convolution-history floats in each 817,152-float state slice (source: `session.cpp:43-49`, prior round 33). Layer 9 is GDN ordinal 7.

## Launch geometry, participation, and address coverage

For the default tiled convolution (`kernels.dp.cpp:2473-2557`), `T=8192` gives 128 token tiles of 64. Its range is `(1,128,C/128) * (1,1,128)`: each group is one tile and one 128-channel segment; each work-item owns its channel `c`. For every tile/channel, loop rows `[t0,min(t0+64,T))` and write `h[t*C+c]`; distinct channels or tiles write distinct `(t,c)`. The initial three inputs come from `qkv` or, only when `t0=0`, the three history entries (`:475-495`). Because the tile reads original `qkv`, not prior `h`, tiles are independent. A separate history kernel assigns each channel's three history values once from the final QKV rows (`:594-607`); the range covers 10240 channels once. There are no atomics or intra-kernel reductions in this default conv path.

The default recurrence launch is `(1,1,HV*NCB) * (1,RG,CB)` where `RG=4`, `CB=32`, `NCB=4` (`:870-902,:2695-2708`): 192 heads-by-column-block groups, 128 work-items each. Each group owns one head and 32 output columns. The local IDs cover `rg=0..3`, `c=0..31`, and `col=cb*32+c` spans 0..127 across the four independent column blocks. For its state rows, a work-item starts at `base = state + ((rg*32)*48 + head)*128 + col` and advances by `rs=48*128` for 32 rows (`:895-904`). Over all `rg`, row indices are 0..127; over all heads and column blocks, each `[key-row, value-head, value-column]` state element has one owning work-item. The maximum address is element 786431, within the 786432-float recurrence matrix. The state writeback uses the same disjoint `base + r*rs` positions after the `T` loop (`:992-993`).

Each recurrence loop iteration is uniform over the work-group. `fetch(t+1)` is conditional only on the shared scalar `t<T-1`; there are no per-lane early returns. The work-group barriers before shared Q/K publication, after `red[rg][c]` writes, before output reduction, and before consuming the reduced output are outside lane-divergent branches (`:915-990`). `sk` and `sq` each have 128 entries and every work-item stores one entry per iteration (`tid=rg*32+c`); `red[4][32]` is fully written by its matching `rg,c` work-item before the barrier and read after it. The per-work-group arrays are therefore not read uninitialized in this path. The initial state is loaded from the supplied state buffer into each thread's private `s[32]`; every live row/column is subsequently written back once. No global scratch buffer or atomic reduction is used by this kernel.

`gdn_out_norm_kernel` launches `(1,HV,T)*(1,1,S)`, exactly 128 work-items per token/head group, with `reqd_sub_group_size(32)` (`:2723-2737`). This matches the four 32-lane partials in `wsum[4]`: each subgroup leader writes one slot, all work-items reach the local-space barrier, and all then read the four initialized values (`:1646-1664`). The `warp_sum` helper uses subgroup XOR offsets 16,8,4,2,1 (`:29-41`); here the launch explicitly requests the 32-lane subgroup required by that reduction. The other SYCL GDN reduction kernel `gdn_l2_kernel` similarly uses four 32-lane partials and is launched with a required subgroup size of 32, but it is not the default T=8192 conv path unless the fused conv+norm environment option is active (`:608-628`, launch around `:2515-2560`).

For the alternative non-pipelined `gdn_rec_cols_kernel`, the same grid and state ownership apply. Its shared `sq/sk[128]` and `red[4][32]` writes are similarly covered by the all-lane barriers (`:789-869`). Its arithmetic per column is ordered explicitly by four partials `red[0]+red[1]+red[2]+red[3]`; no inter-work-group floating-point sum is present. The one-block-per-head `gdn_rec_kernel` is a different fallback (`:637-758`), not the source default for this case.

## What is and is not implicated by source

I found no concrete out-of-range state/history access, duplicate state writer, uninitialized local reduction slot, divergent barrier, or floating-point atomic reduction in the default SYCL GDN kernels for `T=8192`. The reduction order is explicit and fixed within each work-group, and separate blocks own disjoint state columns. This rejects a generic “atomic float reduction order changed” explanation for these kernels. It does not prove bitwise determinism of GEMM/library projections, compiler math transformations, hardware execution, or the entire model.

The useful bounded questions are therefore narrower: confirm the frozen capture's actual `STRATA_GDN_*` environment and chosen route; if layer-9 residual input matches but post-GDN changes, compare the first internal stage across the two captures (projected QKV/gates, convolved/normalized `h`, recurrent output and state); if all sampled residual rows match but final recurrent state differs, capture state at chunk boundaries because the existing residual records cover only rows 98304–98335 while the recurrence consumes all 8192 rows. No new hook is justified before reading the pending pair. A source-level pass here does not clear the original C full-context rejection.

## External recurrence cross-check and spec

The Hugging Face Transformers Qwen3.5 reference provides both chunked and token-recurrent Gated DeltaNet paths. Its token-recurrent path carries a matrix state through each token with decay and delta update; the chunked path carries the final state from one chunk into the next. This corroborates why a 32-row output capture cannot stand in for comparing the carried full state, but does not prove Strata's arithmetic or hardware behavior. [Transformers Qwen3.5 modeling reference](https://github.com/huggingface/transformers/blob/main/src/transformers/models/qwen3_5/modeling_qwen3_5.py). The Flash Linear Attention project provides a concrete GPU Triton recurrent kernel: each program identifies a head/value block, loads initial state, applies a sequential `tl.range(0,T)` decay/update, and optionally writes final state (`fused_recurrent.py`, lines around 1261–1460). Its program decomposition is distinct from Strata's local-memory work-group kernel, but it likewise treats state ownership and the final-state write as explicit outputs. [Flash Linear Attention fused recurrent kernel](https://github.com/fla-org/flash-linear-attention/blob/main/fla/ops/gated_delta_rule/fused_recurrent.py).

Khronos SYCL 2020 defines work-group barriers as coordination for all work-items in that group: all work-items must execute the barrier or none may, and local/global memory can be made consistent within a group with the barrier. Its subgroup/group APIs provide the formal basis for the source checks above. [Khronos SYCL 2020 specification](https://registry.khronos.org/SYCL/specs/sycl-2020/html/sycl-2020.html).
