Ownership and failure cleanup

- `open()` first closes any previous plan and clears the error (source lines 59–62). All new mappings and role tables are then built under local `next`; `impl_` is published only after every role validates (72–75, 128). A metadata mismatch returns false while `next` is still local (118–122); an exception is caught (130–133). In both cases local `unique_ptr`/`map` destruction closes already-created `GgufFile`s. Thus a failed reopen leaves the object closed, as the header promises (26–27).
- `Impl` owns one `unique_ptr<GgufFile>` per distinct resolved path string and each role stores its own `Extent` plus pointer into that file mapping (38–44). Moving `next` into `impl_` does not move the `GgufFile` allocations, so role pointers remain tied to the owner for the plan lifetime. `close()` resets the owner; `extent()` pointers and source bytes are invalid after `close`, another `open`, or destruction (48–56 and header 12–14). The lifetime contract is present and consistent.
- `copy_blob()` rejects a closed plan, out-of-range layer/expert, null destination, or undersized capacity before copying (136–145). It copies each separately-strided role to a packed destination in gate/up/down order (147–154). The documented non-overlap requirement is a caller precondition; it is not dynamically detected. In-place/overlapping copy is not supported and should remain excluded from callers/tests.
- `GgufFile` owns the OS file/mapping and is RAII-cleaned both on constructor exceptions and destruction (GGUF reader lines 340–347, 376–419). The plan retains those owners rather than returning a transient pointer. External truncation/mutation while mapped can still fault or change mapped bytes on POSIX; the header correctly requires immutable source files while open. Do not describe this as protection against concurrent writers.

Geometry, offsets and overflow

`open()` checks native positive layer/expert counts, checked `3*layers`, exact format/blob/offset vector lengths, and either an empty shard vector or an exact `3*layers` shard vector (source lines 64–75). For each layer it independently recomputes GU and Down row sizes using the GGUF block geometry and checked multiplication/addition, then matches `NativeFmt.gu_row`, `d_row`, `up_off`, `down_off`, `bytes` and `layout.bytes`; it also requires the blob to fit `size_t` (79–92). This prevents `blob - down_off` underflow from a malformed layout and is stricter than the old checker’s direct subtraction. Each role stride is independently `[gu, gu, down]`; total tensor bytes use checked multiplication by `n_expert` (92–103).

For each exact tensor name, it checks the role’s type, full `[columns,rows,n_expert]` shape, `tensor_payload_bytes` equality, subtraction-form payload bounds before absolute-offset addition, and equality of `data_start + tensor.offset` to the metadata’s absolute `gguf_off` (98–117). `copy_blob` then uses an expert index already bounded by `n_expert` and a stride whose complete tensor extent was validated (139–154). Given a valid mapped file within the host pointer addressable range, expert-stride multiplication and role-copy destinations are bounded by the validated full extents and blob geometry.

One inherited platform constraint remains: `GgufFile` stores file size as `uint64_t`, but its POSIX mapping call passes that size to `mmap(size_t)` without an explicit `file_size <= SIZE_MAX` check, and `tensor_data()` uses pointer addition with the parsed offsets (GGUF reader lines 373, 398–405). The NativeRolePlan checks its destination blob against `SIZE_MAX`, not the entire mapped file against `SIZE_MAX`/`PTRDIFF_MAX`. This is safe for the reviewed 64-bit host and current 50 GB pack; a 32-bit or unusual address-space build must be refused or add a checked file-size mapping gate before using the reader. This is a shared GGUF reader limitation, not a role-stride arithmetic error introduced by the helper.

Path semantics and production equivalence

`role_path()` uses the primary path's directory plus the exact role filename, or the primary path for an absent/empty role filename (source lines 31–35). This matches the existing `expert_gguf_file()` resolution byte-for-byte in behavior (production `expert_source.cpp` lines 3600–3608): v2's empty `gguf_file` uses the primary; v3 loader expansion makes one filename apply to all three roles; v4 stores independent gate/up/down names and empty entries use the primary. The loader’s normalization is in `expert_layout.cpp` lines 429–459. The new helper rejects a partial nonempty shard vector before indexing (source lines 68–70), while the production checker currently tolerates a short vector and falls back to primary for missing entries; for parser-produced v2/v3/v4 layouts this does not change paths. It is intentionally stricter for manually malformed layouts.

This is lexical path resolution, not canonical filesystem identity. Like production, it does not collapse `.`/`..`, symlinks, or equivalent path spellings, and a shard filename can escape the primary directory if metadata supplies such a path. The new map deduplicates identical path strings, not physical file identities. Those semantics match the existing resolver; they are not a security boundary. Do not describe this source audit as adversarial path validation or as validation of split-shard family consistency: it opens individual `GgufFile`s and checks the required tensors, just like `check_experts_gguf`.

One API clarity improvement: `Extent.offset` is set to the absolute file offset from `layout.gguf_off`, and `tensor_bytes` is the complete role tensor payload, while `bytes_per_expert` is the copy stride (source lines 123–125). The header does not define those units/semantics. Document them before other callers use the descriptor for extent hashing or pointer arithmetic. The current `copy_blob()` does not depend on `Extent.offset`.

Independent negative/edge fixtures for the root-owned harness

Use only small synthetic GGUFs and metadata, never model shards. Compare helper accept/reject and resolved role paths with the production parser/checker behavior; the production checker remains unchanged and is not wired to this helper. Useful independent cases:

1. A v2 layout with all roles in the primary shard, roles physically ordered down/gate/up, and distinct per-role offsets; verify exact packed bytes and the `gu,gu,down` expert strides. A v3 case with one named sibling shard for all roles; a v4 case with gate/up/down in different siblings and one empty entry selecting primary. Assert the resolved paths against `expert_gguf_file` semantics and expected unique-path `file_count`.
2. For each role independently, wrong tensor type, wrong rank/dimensions, wrong expert count, bad payload geometry, offset mismatch, offset beyond payload, truncated last expert, and missing tensor. Include a shard failure after earlier paths have mapped; after failure require `is_open()==false`, `file_count()==0`, `extent()==nullptr`, and `copy_blob()==false`.
3. Open a good plan, then fail a reopen on a later role/shard. Confirm the prior plan is closed and no stale extent/copy succeeds. Repeat failures in a bounded loop and check OS descriptor/map ownership returns to baseline; this directly exercises RAII cleanup without treating a process exit as proof.
4. Mutate each copied layout field independently: non-native/zero counts, vector length mismatch, unsupported or negative types, nonpositive/non-block-aligned dimensions, row size/off/blob disagreement, and checked multiply/add overflow. Confirm each refuses before publishing any plan. Since real file sizes cannot feasibly hit uint64 limits, exercise arithmetic helpers through a small testable internal function or malformed synthetic metadata that fails before pointer creation; do not construct fake enormous mappings.
5. For successful copy cases, verify exact gate/up/down sentinels and guard bytes for capacity exactly blob size and one byte too short; reject null, negative/out-of-range expert/layer, after close, and after failed reopen. Keep source mappings read-only and destination non-overlap explicit.

Production boundary

The current production `check_experts_gguf()` independently validates tensor metadata and offsets at `expert_source.cpp:3622–3673`; `FileExpertSource::open_gguf()` then opens separate mappings and constructs its own role pointers (1027–1103). This new plan can validate and supply a bounded assembled blob to its own harness, but it does not yet eliminate that production check-then-reopen gap or make production use the plan’s mappings. Root must make any later integration a separate change and preserve the production caller’s error prefix, failure/close behavior, and warm/direct-I/O semantics. No production equivalence, actual pack acceptance, source-mapping identity, runtime admission, correctness, or performance claim follows from these source lines alone.
