## What Strata already precomputes or fuses

The frozen kernel source shows the following path components already exist:

- `gdn_conv_tiled_kernel` produces the causal-convolution activations; `gdn_l2_kernel` normalizes Q/K. The opt-in `gdn_conv_l2_kernel` already fuses these passes for Q/K heads while preserving the stated per-element operations. A generic “fuse convolution and Q/K norm” proposal would duplicate existing code.
- `gdn_gates_kernel` already consumes `ab`, `dt`, and per-head `ssm_a` and writes one `gate[t,head]` and `beta[t,head]` value. `beta` is sigmoid-precomputed; the decay remains in log/softplus form until the recurrence computes `sycl::native::exp(gate)`.
- `gdn_rec_kh_kernel` already has `GDN_TB=8`, two local ping-pong buffers, and stages Q/K/V/gate/beta. It computes three value heads per shared Q/K head (`VPK=3`). R92 already records this staging precedent. It still runs four 32-column blocks, so this does not itself eliminate across-block repeated Q/K/gate/beta work. Re-proposing token-block staging or the existing key-head reuse would repeat R92/current source.
- The ordinary `gdn_rec_cols_pipe_kernel` uses `CB=32`, `NCB=4`, and each CTA processes one `(head, 32-column block)`. It loads Q/K into its local SLM tile and loads that head/token's V, gate, and beta. Thus Q/K are reused inside each CTA but each of the four column-block CTAs independently performs its loads. Gate/beta are also the same head/token scalars across the four CTAs. The four blocks are independent in the launch grid; no inter-CTA shared memory is available.
- `gdn_out_norm_kernel` already fuses output L2 scale, per-channel `gamma`, sigmoid of `z`, and FP16 conversion in one pass. The recurrence output is split across four column-block CTAs and norm reduces over all 128 columns; fusing norm into recurrence would need a different all-columns workgroup/layout, redundant cross-CTA reduction, or another synchronization/materialization. That is a schedule/ownership redesign with occupancy and exact-order risk, not a small fusion.

## One bounded new factor worth source-screening

**Move the final scalar decay exponential into the existing gate-generation pass and reuse the existing gate output slot in place.** Today each recurrence work-item evaluates `g = sycl::native::exp(gate[t,head])`. In the regular pipeline that scalar is shared by 128 work-items per CTA and is independently handled by four column-block CTAs per head/token. The source shows the value is produced once per token/head by `gdn_gates_kernel`; computing the same `sycl::native::exp` immediately after the current softplus-times-`ssm_a` expression, writing that result back to the existing `gate` slot, and consuming it directly in recurrence would reduce recurrence-side exp evaluations and repeated per-column-block gate reads without an added tensor, allocation, transfer, launch, or queue lifetime. It changes only the representation of this temporary from log-decay `g` to already exponentiated decay `exp(g)`; it does not change the recurrence formula or state carry.

This is a hypothesis, not an instruction to implement. It is valid only if the actual production call chain proves the `gate` allocation has no consumer other than the GDN recurrence, every recurrence route is updated consistently, and the public API/diagnostic fixture's explicit gate inputs remain clearly distinguished from this private precomputed buffer. The reviewed frozen slice contains definitions and kernel callers but not the complete model orchestration proving those lifetime/alias conditions; an owner must close that source path before any code change. If preserving the existing gate representation requires a separate `exp_gate` array, then storage cost is 4*T*48 bytes: 1.5 MiB at T=8192, 6 MiB at T=32768, and 48 MiB at T=262144 per active layer. A full-physical T-sized array would be rejected unless it replaces already-dead scratch or remains within the exact fixed-memory budget. Do not use chunk-WY cumulative gates or parallelize the token recurrence as part of this factor.

The exact-order rationale is narrow: the producer must execute the same `sycl::native::exp` on the same stored FP32 gate value and write its FP32 result; recurrence then reads that stored result and skips only its former exp call. This should be bit-equivalent if built with identical precise-FP options and no intermediate narrowing, but it is not proven by source reasoning alone. Verify bitwise state/output equivalence, including all 48 value heads, first and tail chunks, and carried state through long prompts/physical 262144, before timing. Compare gate-prep time and recurrence time separately because exp work moves between them. Reject if total per-layer time does not improve, gate staging is bandwidth/cache-bound, the compiler already scalarizes/broadcasts exp efficiently, or API/lifetime audit finds other gate consumers.

This factor should come after the active root diagnostic is closed: it needs an event/timing baseline for gate-generation plus recurrence, not only recurrence-only timing. It has no predicted percent gain. If that clean baseline shows recurrence exp is not meaningful, or the gate producer cost offsets saved work, record no candidate and stop.

## Screened but not promoted

- **Reuse Q/K over all four column blocks via larger workgroup:** exact source confirms repeat loads, and Kim's H100 blog notes analogous repeated Q in its distinct chunk/GEMM `k2_block_idx` loop. A Strata CTA covering all 128 columns could load Q/K once, but multiplies the current CTA's work and live recurrent state (roughly four times the columns/lanes or equivalent per-lane state), reduces independent CTA count by four, and risks lower residency/spills. At the full 262144 input this is long-run state/compute behavior, not a reason to materialize another full Q/K copy (which would be 256 MiB per layer for Q+K FP32). Existing key-head/TB work already addresses some reuse. Revisit only if the new event split and per-target resource record show Q/K traffic dominates and an explicit ownership/residency design preserves exact sequential recurrence.
- **Fuse output normalization into recurrence:** current normalizer already combines its activation/projection-like operations. The cross-CTA 128-column reduction prevents a simple local fusion. A one-CTA-per-head redesign may reduce launch and y write/read traffic but reduces CTAs and may cause register/local pressure. No external report reviewed validates this for Strata shape or precise output contract.
- **Fuse gate/beta activation into AB projection epilogue:** in principle could remove a separate gate kernel and the materialized `ab` round trip; this requires the upstream projection implementation, output layout, and scratch liveness not present in the immutable reviewed slice. Do not promote without proving exact AB values and that no other path consumes `ab`. Separate launch savings may also be negligible for a long prefill. This is a larger integration candidate than the single decay-exp factor above.
- **Chunk-parallel GDN/WY/Kimi/FlashInfer/Apple:** these formulate within-chunk token interactions with matrix operations or triangular solves and change FP32 operation order. They duplicate R82/R83 and existing R92 discussion and conflict with Strata's exact ordered recurrence; reject under the current contract.
- **Q/K projection or attention-style fusion:** the current gate/QK input transform pass structure already has fused conv+QK norm option, while the final norm already fuses gamma/sigmoid(z)/FP16. No specific external implementation provides a lower-risk GDN-only fusion that preserves Strata ordering.

## Conclusion

There is one concrete, bounded source candidate that is distinct from the prior WY, reduction, GRF, bundle, liveness, and token-block staging work: in-place precomputation of the final per-token/head `exp(gate)` into the existing gate temporary, potentially avoiding repeated SFU work across the four column blocks. It is conditional on proving the private intermediate contract and must be compared as a moved-work factor, not presumed free. If production usage does not allow the representation change without extra 262144-sized memory or a new pass, reject it. The rest of the requested opportunities are already partly implemented or carry a substantial parallelism/FP/order cost; no other candidate is promoted. No local measurement or implementation was performed.
