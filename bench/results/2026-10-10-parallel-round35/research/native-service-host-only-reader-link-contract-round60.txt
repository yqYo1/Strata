# Native service host-only reader and link contract — round 60

Read-only source audit for the proposed extension of the actual CPU native-wrapper harness to assemble real packed experts through the production file reader without initializing a SYCL queue/context/device. Source snapshot: `/home/yayoi/ghq/github.com/yqYo1/Strata/.worktree/diag-sycl-cache-route-pairs-v0141-20261010`, HEAD `66aaec3a`. I did not inspect model payloads, build, test, replay, run performance, initialize/query a device, profile, clean artifacts, or change Git state. This report is the only written artifact.

## Finding

`FileExpertSource::copy_blob` is the correct production byte-assembly boundary for the CPU wrapper: it copies a complete logical `[gate | up | down]` blob into caller-owned storage and avoids the temporary pointer lifetime of `blob()`. The GGUF-backed `open` branch and `copy_blob` implementation do not themselves request a SYCL queue. A fresh default `FileExpertSource` also has null pinned/staging pointers, so its `close()`/destructor do not call `dpct::get_in_order_queue()` on that untouched state.

However, directly adding `FileExpertSource` to the current `native_expert_parity` executable is not a small CPU-only link extension. The reader class is implemented in the large `sycl/src/core/expert_source.cpp` translation unit, whose includes and other methods require SYCL/DPCT and several engine subsystems. Its virtual table retains the class's full virtual surface, including methods that allocate/free pinned SYCL storage. `strata_engine` compiles that TU and links `strata_core`, `strata_kernels`, and `strata_kernels_cpu`; linking it would import the engine/device dependency graph. The existing harness instead links only `strata_kernels` and `strata_kernels_cpu` and unconditionally creates `dpct::get_in_order_queue()` in `main` (`sycl/src/kernels/native_expert_parity.cpp`). It is therefore not a no-queue CPU harness today.

No `gpu::Allocator` is referenced in `FileExpertSource`'s declaration or the implementation search. The hidden device coupling is SYCL/DPCT queue and USM lifetime in other members, not an allocator member constructed with the object.

## Exact call and link paths

- Existing wrapper harness: `sycl/src/kernels/native_expert_parity.cpp`; CMake target at `sycl/CMakeLists.txt` around lines 382–389 links `strata_kernels strata_kernels_cpu`. `main` calls `dpct::get_in_order_queue()` before its layer loop, so a CPU-only mode must not share that initialization path; make it a separately selected execution path before the queue call, or a separate executable.
- Production class declaration: `sycl/include/strata/core/expert_source.hpp:439+`. `FileExpertSource()` is defaulted; destructor is out-of-line. Base `ExpertSource` (around lines 123–185) has virtuals for `blob`, `copy_blob`, prefetch, pin status, release, device alias, etc.; vtable use means the object does not amount to only `open` plus `copy_blob` at link time.
- Production implementation: `sycl/src/core/expert_source.cpp`: constructor-independent destructor at 420, `open` at 422, `close` at 594, `open_gguf` at 715, role copying at 793+, and `copy_blob` at 1563. `open` first calls `close`; for native layout with no `experts.bin` and a selected `gguf_`, it records counts/layout, calls `open_gguf`, then records inputs. `open_gguf` validates metadata, read-only maps the resolved shards, and stores one base pointer/stride per `(layer, role)`. `copy_blob` range-checks, chooses a resident override only if the complement has explicitly been prepared, otherwise calls `copy_from_files`; in GGUF mode that function performs three `memcpy`s in gate/up/down order.
- Queue-bearing code is also in this same TU: `close` at 598 and 614 calls `dpct::get_in_order_queue()` only when `complement_arena_` or `xstage_` exists and is pinned; other virtual/member methods call it at later lines (e.g. 1837, 1865, 1890, 2202, 2229). Runtime no-queue safety for a fresh object is therefore a state/path property; it is not a link-level guarantee.
- `sycl/CMakeLists.txt` defines `_engine` with `src/core/expert_source.cpp` at about 264 and adds `strata_engine` at 271 linked PUBLIC to `strata_core strata_kernels strata_kernels_cpu` at 273. This graph is much broader than the current wrapper harness's two CPU/kernel libraries. A `strata_engine` link is not evidence that the executable can run without loading the SYCL runtime; that must be verified by an explicit future no-device acceptance gate.
- `expert_layout()` is defined in `src/kernels/cpu/expert_layout.cpp:23`; the CPU CMake source list includes it. `expert_layout_load` is at line 372. The production `check_experts_gguf` helper is defined in `sycl/src/core/expert_source.cpp:3096`, so it cannot presently be linked alone as a host helper.
- `sycl/src/core/gguf_expert_source.cpp` is not a substitute for `FileExpertSource`: despite its introductory comment, it includes SYCL/DPCT, and its `close` frees a mirror via `dpct::get_in_order_queue`; `open` checks offset presence but does not call `check_experts_gguf` for GGUF tensor name/type/shape/size/offset agreement. Do not use this to claim the production validated reader path.

## Smallest production-compatible extension

Factor the host-only GGUF validation, role-path resolution, read-only mapping, bounds checks, and three-role copy into a dedicated host-only reader translation unit and narrow API, leaving the current `FileExpertSource` as a consumer of that shared implementation. The CPU wrapper harness can then link this helper plus the existing CPU layout/quantization/kernel libraries, without instantiating the SYCL-backed polymorphic `FileExpertSource` or linking `strata_engine`. Prefer factoring shared implementation over maintaining a second independent role assembler: otherwise the test could validate duplicate parsing logic while production drifts.

The seam should accept the already-loaded `ExpertLayout` and primary shard path, open/validate using the same parser and metadata checker as production, and expose only `open`, `copy_blob(layer, expert, dst, capacity)`, and `close`. The reader itself should contain no SYCL/DPCT headers, queue access, allocator, pinning, resident-complement, staging, prefetch worker, or device aliases. `FileExpertSource::open_gguf/copy_from_files` and the CPU harness should call this common host reader. Keep the harness's GPU path separate; its existing `main` queue call cannot be reached by the host-only execution path.

This is a source refactor, not a validated executable recipe: source audit alone cannot establish whether static runtime linkage causes runtime initialization, nor whether the proposed new target is fully linkable. The future acceptance gate must run the CPU harness on a machine with no visible GPU/device runtime path and prove: reader open/copy/close completes; no queue/context/device is created (instrument queue entry points or run in a no-device environment); the test stays within bounded selected-blob buffers; and the production-reader assembly matches independent selected-role extents/hashes before wrapper correctness checks.

## Data and validation contract that the shared helper must preserve

`native_experts.txt`'s logical packed layout is not a contiguous GGUF expert extent. For role `r`, selected expert bytes begin at `gguf_off[3*layer+r] + expert*per_role_bytes[r]`, with the role's own shard path; concatenate gate, up, then down into a destination of exactly `NativeFmt.bytes`. `check_experts_gguf` derives role sizes from `fm.up_off` and `lay.bytes[layer]-fm.down_off` and checks each GGUF tensor name `blk.L.ffn_{gate,up,down}_exps.weight`, role-specific type, shape, payload bytes, equality of absolute file start (`data_start + tensor.offset`) to metadata offset, and file bounds. Current v4 metadata can select a shard per role; v3 uses the designated primary shard. Resolve paths exactly as `expert_gguf_file` does, rather than assuming adjacent shard numbering or shared role files. The format parser and byte contract are detailed in `native-service-expert-payload-adapter-contract-round48.txt`; round 46's actual calibration/provenance protocol remains the downstream measurement contract.

For each future selected extent, retain checks for layer/expert range, metadata version/offset presence, known supported types, exact `NativeFmt` geometry, shard identity/size, overflow-safe `offset + expert*stride + stride` bounds, exact three-role sum, and unchanged source identity. The reader's map check `at <= bytes && role_bytes*n_expert <= bytes-at` is a second defense after tensor validation. Do not treat successful mmap as payload validation or read the whole source file to validate this harness.

## Evidence limit

This report identifies source-level call and link coupling and a refactor seam. It does not show that a new host-only target builds or runs, that a system with no SYCL runtime can link it, or that real-payload wrapper correctness/service calibration has passed. R46's sampling/timing protocol and R48's byte-layout requirements remain necessary before any performance result.
