## Arithmetic and state audit

The selector validates 1..48 curves, exact default geometry and budget, integer-only bounded values (excluding bool), zero initial prefix score, nondecreasing cumulative scores, and an exact-budget feasible default (`static_cache_quota.py:13-43`). Nondecreasing cumulative scores are the right input condition for nonnegative rank counts; they do not imply diminishing marginal counts. Baseline scoring is separately computed with checked uint64 addition (`:46-54`).

For each layer, the DP state is keyed by total slots spent and stores cumulative score, L1 distance from default, a rank for the selected lexicographic prefix, and backpointer fields (`:67-87`). A state with larger score dominates one with the same spent total; equal score prefers smaller accumulated L1, then lexicographically smaller prefix. Future choices depend only on layer index and spent total, while future score/distance additions are independent of the prior quota vector. Thus retaining only this best prefix per state is valid for the stated ordered objective. The recurrence enumerates every feasible current-layer quota for each prior state.

Extendability pruning is correct: after subtracting the current layer's capacity from the sum of remaining capacities, the lower bound `max(0, budget-spent-remaining)` ensures the suffix still has enough capacity; the upper bound `min(cap,budget-spent)` prevents exceeding either current capacity or total budget (`:69-75`). Every integer remainder between zero and the suffix capacity sum can be distributed among integer per-layer capacities, so the lower-bound condition is sufficient. The validated default already proves that an exact-budget allocation exists; the final infeasibility branch (`:88`) is defensive for the state builder, not a normal case under valid inputs.

Tie handling is coherent. During a transition, candidate ordering uses descending score, ascending L1, then parent-prefix rank and current quota (`:76-81`). Parent ranks preserve lexicographic ordering of the retained prefix vectors; sorting by `(parent rank, q)` then assigns ranks to the new vectors (`:82-87`). Backtracking stores the predecessor spent total and this layer's quota, then reverses the collected quotas (`:89-92`). The fixture's explicit equal-score/equal-L1 case expects lexicographically smallest `[0,2,0]` (`test_static_cache_quota.py:37-44`), and the exhaustive grid compares complete quota vectors as well as score and distance (`:7-25, 31-36`).

Overflow handling is conservative and internally consistent with the function contract. Individual prefix scores are constrained to uint64, and every DP addition uses checked `_add` rather than wrap/saturation (`static_cache_quota.py:18-21, 35-38, 76`). Because all future score increments are nonnegative, if a considered prefix sum overflows, every completion of that extendable state also overflows. Rejecting the objective even if that alternative would not win is therefore coherent with the documented policy to reject any considered feasible overflow. The default is feasible and included in the search; hence the winning score cannot be below baseline and `winner[0]-baseline` does not underflow (`:65-66, 93-96`). Fixture cases cover a maximum representable score, out-of-range input, a feasible additive overflow, and an overflow alternative despite a fitting baseline (`test_static_cache_quota.py:70-78`).

## Concrete input-boundary finding

One real but non-arithmetic interface boundary remains: `MAX_LAYER_SLOTS=256` and curve length at most 257 (`static_cache_quota.py:7-10, 31-40`), while the R59 engine/profile contract allows up to 512 ranked expert pairs per layer. A complete 513-entry cumulative curve therefore fails validation, even though the selector's maximum total budget is 128 (`:25, 32-33`). This does not change the optimum for the currently supported exact budget: no feasible quota can exceed 128, and only prefix-score entries `0..128` can be selected. A caller can safely supply the first 129 prefix scores (with validated provenance), or the selector can explicitly cap scoring to `budget` while validating source geometry separately. The current fixture's full-production test supplies 257 entries and tests concentration of all 128 slots in one layer (`test_static_cache_quota.py:49-56`), but does not exercise the full 512-rank source boundary. Treat this as an interoperability/truncation contract to document or resolve before connecting full-profile count curves, not as a defect in DP optimality or present budget-128 answers.

R57 described per-layer bounds as up to 512; with exact total budget 128, those bounds are nonbinding for an individual feasible quota. The selector's 256 cap is also nonbinding mathematically for feasible totals, but it can reject an untruncated natural input. Do not silently truncate input without making the source rank and curve-prefix provenance explicit.

## Independent oracle coverage and limits

The fixture's exhaustive implementation enumerates the Cartesian product of each layer's quota range, filters exact-budget vectors, then directly computes score, L1, and Python tuple lex ordering (`test_static_cache_quota.py:7-15`). This is structurally independent of the DP recurrence and tests literal greedy failure, a 6-choice three-layer exhaustive grid, tie cases, zero/full generic budgets, production-size 48-layer/128-slot hand oracles, malformed inputs, and overflow (`:26-78`). For a valid default, an infeasible exact budget cannot occur because that default itself is a witness; there is no separate valid-default/infeasible-budget test case to add. The 48-layer production fixtures are hand-constructed expected answers rather than exhaustive enumeration, as appropriate for their size.
