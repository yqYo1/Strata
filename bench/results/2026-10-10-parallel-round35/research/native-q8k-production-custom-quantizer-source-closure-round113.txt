## GU22 / NT1 runtime quantizer selection

This is deterministic synthetic input, shared by all selected experts of that layer; it is not a live activation sample.

Production dispatch is explicit in `native_expert.cpp:90-99`: `native_quant_act` calls `q8k_avx2(f.gu_act)`; the cached `on` condition is `cpu_avx2_ok()` and `getenv("STRATA_NO_Q8K_AVX2") == nullptr`, and the format must be `GGML_TYPE_Q8_K`. If true, it calls `q8k_quant_avx2(x,dst,f.n_embd)`; otherwise it calls the type trait's `from_float`. The fixture main also requires `cpu_avx2_ok()` and rejects `STRATA_FORCE_ISA` / `STRATA_FORCE_AVX2`, but its environment logger only records `STRATA_NO_Q8K_AVX2`; it does not require it to be unset. For the production custom arm, the owner must explicitly require the variable to be absent (presence disables it even if its value is `0`) and confirm the recorded environment. If present, byte parity might still pass through GGML fallback, but it would not qualify the custom quantizer.

`expert_layout.cpp:25-38,106-135` defines the ISA cap and AVX2 runtime gate. With force variables absent, the cap is 3; AVX2 still requires FMA, OSXSAVE, AVX, F16C, XCR0 SSE/YMM state and CPUID AVX2. The implementation TU `iq_avx2.cpp` is compiled for AVX2, FMA and F16C by the calibration CMake; dispatch must prevent calling it on unsupported hardware. `STRATA_AVXVNNI` affects the IQ dot rows (`iq_avx2_rows.inl`) via `vnni_on`, not Q8_K activation quantization. The calibration CMake fixes the IQ wrapper's `STRATA_AVXVNNI=0`; AVX-VNNI selection does not select an alternate Q8 quantizer. ## Numerical and byte contract against pinned GGML

For finite, nonzero blocks, the pinned scalar `quantize_row_q8_K_ref` (`pinned-ggml/ggml/src/ggml-quants.c:2768-2803`) scans absolute maximum with strict `>` (first max wins), uses `iscale = -127.f / max`, runs `nearest_int(iscale*x[j])`, clamps at 127, sums signed quantized bytes in groups of 16 into `bsums`, and stores `d = 1/iscale`. `nearest_int` at line 621 is the `fval + 12582912.f` bit trick (with magnitude assertion), so its rounding is sensitive to the active FP rounding mode. The pinned x86 `quantize_row_q8_K` wrapper (`ggml-cpu/arch/x86/quants.c:505-506`) explicitly calls this reference; the Q8_K trait maps `from_float` to that wrapper (`ggml-cpu/ggml-cpu.c:392-393`). Thus the fixture's per-layer Q8_K trait comparison is a reference-path comparison, not proof that production AVX2 emitted the same instructions.

The custom `q8k_quant_avx2` is at `iq_avx2.cpp:393-453`. It reduces absolute max, then rescans for the first element with that magnitude to recover the same signed max; computes the same `-127.f / mx`; uses `_mm256_mul_ps` then `_mm256_add_ps(p, magic=12582912.f)` and extracts the same mantissa/off bits as `nearest_int`; clamps at 127 and narrows to signed 8-bit values; sums each group of 16 signed bytes into `bsums`; and stores `d=1/iscale`. For the fixture's finite, normal-valued domain, source intent preserves the reference operation order. Explicit multiply and add are semantically distinct here: fused multiply-add can change rounding close to a nearest-integer boundary. The source contains a GCC-only asm barrier against GCC's default contraction; it does not by itself constrain IntelLLVM emission. The shared quantizer CMake applies `-fp-model=precise`, but the flag and source intrinsics alone do not prove the final instruction sequence.

For nonzero blocks, meaningful Q8_K content is `d`, all 256 `qs` bytes and sixteen `bsums` entries. The calibration comparator checks `f.act_bytes` against the GGML trait for each prepared layer activation. Both reference and custom skip writing `bsums` on all-zero blocks; the fixture formula cannot produce an all-zero 256-value block, so that edge is outside the admitted run. Nonfinite input behavior, NaN max selection, overflow-scale corner cases, and subnormal handling are not qualified by this finite formula.

Rounding mode is material: the bit-trick addition in both paths obeys the active MXCSR rounding control. The custom vector product must first round to FP32 before the magic add; no contraction/reassociation can be admitted. Fixture controls in `index_correctness` (`native_service_calibration.cpp:228-232,240+`) capture MXCSR at process entry and only require `(MXCSR & 0xffc0)` to remain equal to that entry value. This checks stability, not that entry mode is round-to-nearest-even or that FTZ/DAZ are in a particular state. Prior R97 records test-only MXCSR `0x1f80` before `ggml_cpu_init` and `0x1fbb` after it, with matching controls under `0xffc0`; those values do not prove this binary's execution state. Root should require and record the intended absolute rounding-control value (normally RC bits `00`, and its declared FTZ/DAZ policy) before interpreting the exact-byte check. The input formula produces finite values in `[-254/257,254/257]`, with some exact zeros and no subnormals; for each nonzero block its scale is finite and ordinary products are bounded by 127. This bounds this fixture's arithmetic only.

The actual-cohort mode quantizes prepared inputs on the main thread before it enters `index_correctness`; that branch does not start the pool. The one observed caller's MXCSR controls therefore cover only this source-only qualification path. The server's worker MXCSR remains unobserved and should not be inferred. Production comments state host-side activation quantization happens before pool start, but this fixture is not a server lifecycle proof.
