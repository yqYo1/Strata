## Safety and sample-validity findings

- **Arguments/environment before device queue lookup.** The timing branch validates exact argc and option positions, bounds decimal byte length/value, order, total/chunk/sample ranges, then calls the named-environment guard before `strata::q_of(nullptr)`. Malformed inputs and present (including zero-valued) listed tracing/validation/dump hooks therefore fail without queue lookup. The handoff appropriately calls the list finite rather than exhaustive. External profiling, unknown runtime hooks and system-level monitoring still require owner-side environment/profile checks.
- **Host endpoints stay live through async copies.** `prepare`, `floats`, `compare`, `timing_hash_pair`, and initial/final snapshot vectors are declared outside the `gpu_stage` lambda; the lambda submits copies and waits before returning. The timing helper's two digest vectors remain live through its wait and hashing. This removes the earlier vector-endpoint-unwind hazard covered in R95. Kernel input vectors in `prepare` also outlive their transfer wait.
- **Uncertain completion fails closed.** Timed recurrence wrapper and explicit `q.wait_and_throw()` are in one `gpu_stage`. Any thrown exception there calls `_Exit(2)` before endpoint/USM owners can unwind, releases no USM explicitly, and cannot retry the other algorithm. Candidate denial is rejected before a sample can be accepted; status must be Submitted and compiled subgroup 32. Pair comparison occurs only after both arms completed successfully. A bitwise mismatch after those waits takes ordinary failure cleanup, not unknown-completion recovery.
- **Final release happens before summary.** `Buffers` drains, then frees all tracked USM. Its destructor runs when `timing_run` returns; only then does `main` print `TIMING_SUMMARY`. A final-drain failure takes fail-stop, and a free/flush failure prevents normal zero exit/authoritative closure. A prior CSV `pass` line is correctly insufficient evidence without normal teardown/owner fault closure. Partial-construction failure occurs before submissions and attempts to release tracked allocations while preserving the original allocation exception.
- **Chunk/prefix carry is paired correctly.** Each pair initializes two separately allocated states from the same deterministic nonzero host state and compares full initial arrays. It does not reset between chunks. Both arms receive one prepared input chunk at the same cumulative offset, execute in declared alternating order on the same idle in-order queue, then undergo full state, active output, finite, outer-guard and unused-output-capacity comparison before advancing. The live final chunk is bounded by `min(chunk,total-offset)`. The state is independent; neither arm takes the other's intermediate state. The output normalization is invoked by each public recurrence wrapper on that chunk. Warmups also execute complete prefixes in both orders; measured samples alternate starting order. This supports paired repeated carried-prefix comparison while preserving order bias evidence.
- **Digest role is limited and correctly documented.** Full per-chunk bitwise comparisons precede FNVs. FNV and joined chunk digests are reproducibility checks and not collision-free comparisons or provenance hashes; final source/binary identity remains an owner receipt responsibility. `result.state` and output hashes are recorded per arm, and subsequent full-prefix pair digests are required to match the warmup reference. The resource fields copied from the final quad call describe its last chunk only; README/report correctly state they are not per-chunk historical values.
- **No in-scope production selector path.** The new mode directly calls `gdn_recurrence_quad_variant` and `gdn_recurrence_pipeline_reference`; it does not call `gdn_recurrence_variant`, exercise `STRATA_GDN_QUAD` selector routing, or run conv/projection/model code. This is the correct limit for a synthetic recurrence-plus-normalization service discriminator. It cannot establish automatic selector behavior, production lifecycle parity, default-prefill latency, or whole-model performance.

## Timing interpretation

For each arm and chunk, steady-clock time starts immediately before the public explicit recurrence call and ends after explicit in-order queue `wait_and_throw` succeeds. The quad interval includes its repeated exact-kernel bundle/capability/resource queries and host wrapper overhead; the legacy interval includes its explicit wrapper overhead. Both include recurrence submission/work and output norm submission/work, plus completion wait. Admission is neither separately measured nor subtracted. `DPCT_PROFILING_ENABLED` and the queue's pre-existing profiling property are unchanged, and no event timestamp is queried, so this is not an event/GPU-kernel measurement. State initialization, input generation/transfers, output guard fills, readback, comparison, hashing and output printing are outside intervals. Such gaps can alter caches, clocks, power or residency; excluded work is not free. Each reported sample sums chunk intervals for one complete carried prefix; arm execution is interleaved and reversed across counterbalanced pairs, not two uninterrupted whole-prefix runs.

There is no quiet-mode selector/default path, model or full lifecycle. Also no timing/statistical result exists yet: source only does not establish actual wall cost, cache/order bias size, queue/kernel behavior on device, stable clocks, successful resource admission, or any speed direction. The saved previous short and prefix correctness gates are separate evidence and do not qualify this new timing mode.

## One wording fix recommended

In README/handoff, describe `check()` as an included no-op DPCT wrapper call for exact source accuracy, or simply omit it from the service components. Keep the explicit `queue.wait_and_throw()` as the success/failure boundary. Do not characterize this as a safety gap: the timed fixture itself has the required explicit wait and fail-stop enclosure.
