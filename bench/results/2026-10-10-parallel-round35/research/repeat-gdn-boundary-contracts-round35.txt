## What the three residual records establish

D already records `R_input`, `R_post_attention_gdn`, and `R_post_moe` for layer 9, clipped to token rows 98304–98335 (32 rows) in the chunk beginning at 98304. The producer records input just before the two half-layer loop, and records post-GDN after attention/GDN output has been combined with the half-0 residual and any enabled control-vector write; post-MoE follows the half-1/MoE residual write. The reader binds descriptors and order, then compares semantic records. Thus a mismatch identifies the earliest *captured residual boundary* in this fixed 32-row window. It is not necessarily the first internal arithmetic mismatch.

For GDN layers, layer 9's `state` pointer is the session-owned GDN ordinal 7 slice. In the GDN block the code submits QKV and gate projections, alpha/beta projections, gate construction, causal convolution (which updates convolution history), recurrent scan (which updates recurrent state), output normalization, output projection, then later writes the residual boundary. The recurrent state has already been mutated by the time `R_post_attention_gdn` is captured. The record itself contains only `m.R` (FP32 `[rows,10240]`), not that state or any GDN intermediates. The final state diff at byte 22,880,260 is ordinal 7, float index 1, as established in round 33; it does not timestamp the first divergence.

The session allocates GDN state in device USM and fresh-request reset clears its full allocation. D's `Prefill::init` rejects a compute stream that is not in-order. Each GDN call receives `m.cs` through `strata::q_of(stream)`; these operations and residual writers use that same queue. In-order SYCL submission gives an implicit dependency between successive commands on that queue. This makes source-level ordering of the GDN pipeline explicit without a manual event per kernel. The reference contract does not prove that every external library submission uses the intended queue; audit the concrete backend handle if a captured mismatch points at a cross-queue operation.

At each capture hook, `RepeatCapture::record` drains the compute queue with `wait_and_throw`, submits the device-to-host memcpy on that same queue, then waits on its event with `wait_and_throw` before reading/writing host bytes. These calls establish that earlier commands on this queue completed before the sampled memory was copied, and that the destination remained alive through completion. They also insert a substantial synchronization point and can perturb timing-sensitive behavior. The capture does not sample/compare a pre-GDN state snapshot, does not expose event dependency edges for unrelated queues, and does not establish that a 32-row output sample determines the final state after all 8192 rows.

SYCL 2020 says `property::queue::in_order` imposes an implicit dependency on the prior command in that queue; `event::wait_and_throw` blocks for the event and dependent events and reports their asynchronous errors. [Khronos SYCL 2020 specification](https://registry.khronos.org/SYCL/specs/sycl-2020/html/sycl-2020.html). The [Level Zero `zeCommandQueueSynchronize` contract](https://oneapi-src.github.io/level-zero-spec/level-zero/latest/core/api/apis/command_queue.html) describes a host wait for a particular command queue. These are contracts for the corresponding queue/event, not global synchronization across arbitrary queues. In D the capture uses the SYCL queue API, not a direct Level Zero event; Level Zero documentation is useful only for the backend-level distinction.

## Independent recurrence cross-check

Hugging Face Transformers' Qwen3.5 modeling reference has both chunked and token-recurrent forms. The recurrent form accepts an initial recurrent state (or initializes zero), iterates tokenwise, decays state, applies the delta update, and can return the final state; the chunked form scans chunks and carries `last_recurrent_state` between them. This supports the diagnostic distinction above: chunk output rows and the final carried state are related but are separate observations, and later tokens update the same state. It does not prove Strata's kernel correctness or bitwise equivalence. [Transformers Qwen3.5 Gated DeltaNet reference](https://github.com/huggingface/transformers/blob/main/src/transformers/models/qwen3_5/modeling_qwen3_5.py).
