- **No GPU query — absent from audited source path, not runtime-instrumented.** The harness reads CPU ISA and GGML CPU state, not a device API. The record contains no device-query telemetry. gpu_executed=false does not prove that an out-of-band runtime component made no query.

## Minimal CPU service executable, separate from the R60 reader seam

The exact current target is suitable for wrapper-level coverage but does not use the production CPU pool. A bounded CPU service harness can be a separate opt-in executable linked to strata_kernels_cpu and transitive ggml/Threads dependencies, without strata_engine, strata_core, strata_kernels, or device/queue code. This is independent of R60's reader issue: real bytes require a host-only reader seam, while computation can still use the existing built CPU library.

Sources support the boundary: the SYCL CPU source list resolves pool.cpp, expert.cpp, native_expert.cpp, expert layout, and relevant IQ/Q2 units into strata_kernels_cpu (sycl/CMakeLists.txt:106+; R28/R29 source maps). ExpertPool is declared in include/strata/kernels/cpu/pool.hpp:134+; its constructor starts host std::threads (src/kernels/cpu/pool.cpp:439–470). run_split_multi_native (pool.cpp:849+) runs pool-partitioned production GU/Down wrappers and applies native_quant_h or act_quant_any to the FF intermediate. The engine caller forms input activations (src/core/expert_source.cpp:3270+) with native_quant_act or act_quant_any, groups routed IDs by expert into ExpertJobMulti, and calls run_split_multi_native at :3350–3351. native_quant_act/native_quant_h are in src/kernels/cpu/native_expert.cpp:96–101.

A no-engine service executable can reproduce that contract without copying dispatch logic: hold bounded selected blobs alive through each synchronous pool call; produce deterministic finite inputs and production-quantized per-token nact/ActQ; fill ExpertJobMulti blob, nt, act[], nact[], and out[]; call ExpertPool::run_split_multi_native on the same type/format pair; then check outputs, phase counters and faults. This exercises the real pool and wrappers, unlike the direct-row R29 harness. Do not construct engine/GPU objects.

For a service-like CPU profile, match generate.cpp:4254–4259: ExpertPool(o.pool_workers, true, !o.no_host_worker, o.pool_affinity, o.pool_tasks). Defaults mean automatic workers, pinned workers, host participation enabled, PoolAffinity::All, and automatic tasks (3 * (workers + host participant)). Record actual worker/participant/task counts, affinity mode, hybrid topology, caller CPU mask and caller placement relative to reserved host core. The pool pins its workers; a standalone caller must arrange and record host placement if matching service behavior. The 864-case matrix did not instantiate a pool, so it qualifies none of these.

pool.cpp has stall-abort calls to strata::core::release_gpu_waits (lines 581,604), but the helper is an inline callback check in include/strata/core/progress.hpp:35–46. With no engine callback registered, it performs no device action. Keep the callback unregistered and do not link/use engine code. This is source evidence, not a runtime assertion.
