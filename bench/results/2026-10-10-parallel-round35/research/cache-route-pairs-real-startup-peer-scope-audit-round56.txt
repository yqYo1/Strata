## Bounds and observed result

The v4 harness sets a 40-second run deadline, 10-second protocol timeout, and a 2 MiB text-log limit. It checks the text budget during the QUIT-drain loop and again after cleanup. The v6 controller itself uses a 64 MiB limit, a 1 MiB failure reserve, a 1,800-second deadline, and a 450-second protocol timeout; v4's smaller limits do not establish that the full controller's longer/bigger run satisfies those bounds. The v4 record says elapsed time was 0.414946 seconds and raw protocol output was 2,547 bytes (SHA-256 `88c6eea7...b6ee688`). All recorded protocol boundaries have received==consumed bytes and no queued/pending bytes; the final boundary records PTY EIO as EOF, followed by GDB exit code 0, no signal, no forced cleanup, and no survivors. PTY EIO is the transport EOF observation; the record separately confirms the later actual MI process exit.

This is a narrow startup/peer evidence supplement. It is not a substitute for the actual pinned v6 run or for any existing source, fixture, math, or GPU gate.
