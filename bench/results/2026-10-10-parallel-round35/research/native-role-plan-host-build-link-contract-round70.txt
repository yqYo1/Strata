The configured CMake runs a compiler-only `-mavx2 -mfma -mf16c` probe for AVX-VNNI intrinsics. The source property assigns `STRATA_AVXVNNI=1/0` to the root `iq_avx2.cpp` path and `q2_avx2.cpp`, but `strata_resolve()` selects `sycl/src/kernels/cpu/iq_avx2.cpp`, the forwarding wrapper. Its entry in the frozen `compile_commands.json` has no `STRATA_AVXVNNI` definition, while `q2_avx2.cpp` does (`=1` in this H build). The wrapper-included root implementation defaults an undefined macro to zero. Therefore the observed H build has Q2 AVX-VNNI enabled and IQ AVX-VNNI disabled. This is a concrete source-property/source-resolution mismatch. To reproduce the frozen H binary, set q2 to the probe result and IQ to zero. If a future CMake change intentionally applies the probe result to the wrapper, record it as a behavior/build change and qualify separately; do not silently assume it matches the frozen build. Do not infer support from the host CPU name. Keep AVX-512 flags confined to the two guarded files and preserve runtime feature checks; do not run AVX-512 code merely because it was compiled.

Keep `STRATA_IQ2S_GCC=OFF` for the minimal host target, matching the observed production configuration. If a later comparison requires it ON, copy the existing CMake custom-object arrangement rather than compiling a second ordinary `iq_avx2.cpp`: the GCC object macro-renames the IQ256 implementation symbols (`iq256_gu_rows`, variants, IQ4NL down, Q8K quantizer, and related functions), while the SYCL wrapper defines the public wrapper to route only IQ2_S NT=2/4 to the GCC aliases. Omitting that alias protocol risks duplicate definitions or bypassing the selected implementation. Record compiler identity and both values of `STRATA_AVXVNNI` / `STRATA_IQ2S_GCC` in every build receipt.

Threading, imports, and source/runtime boundary

Use `find_package(Threads REQUIRED)` and link `Threads::Threads`; `ExpertPool` creates and joins `std::thread` workers. The direct ggml calls visible in the included production sources are `ggml_cpu_init`, `ggml_get_type_traits_cpu`, `ggml_blck_size`, and `ggml_row_size`; expect those from `ggml-cpu`/`ggml-base` transitively. This is a source-level symbol contract only, not the final dynamic import list; the latter must be checked after the actual host link. Leave `strata::core::release_gpu_fn()` unregistered and do not link any engine code: the pool’s stall-abort calls reach an inline nullable callback that is a no-op when unregistered. This is source evidence only. It does not prove the loader or a dependency will never initialize SYCL/UR/Level Zero or query a device.

A host-only source/link claim requires the standalone target to omit SYCL/DPCT headers and targets, `strata_core`, `strata_kernels`, `strata_engine`, `ze_loader`, oneMKL/SYCL flags, and callbacks that register GPU waits. Keep the executable’s import/dependency audit and runtime tripwire as separate admission checks before claiming runtime no-queue/no-device-query. A source-only CMake recipe cannot prove those properties, and `gpu_executed=false` or successful CPU output alone is insufficient (R65). Pool faults can still call the release callback; for this standalone harness the callback must remain null, and timeout handling must fail closed rather than invoking an engine callback.
