Operation comparison, per 256-value IQ2_S block
Both arms retain the same outer `n/256` block loop, Q8_K inputs, scale extraction,
signed-Q8 treatment, AVX2 dot/reduction arithmetic, and final horizontal sum. The
control's inner loop advances by two 32-value groups (four groups per iteration,
eight groups total). It forms grid indices using scalar shifts/ORs from each
`qh` byte and four `iq2s_grid` scalar loads per four code bytes, repeated for the
corresponding second half. Across a complete 256 block, this means 32 grid entries
are selected. It also copies the 32-byte sign region to a local `sign_words[16]`
using `memcpy`; the captured control uses one 32-byte vector store at `[rsp]` and
reads sign words from that local buffer. That is intentional algorithm scratch in
the control and must not be mislabeled as compiler spill overhead.

The candidate substitutes `grid_indices(qs, high[qh], sp)` for assembling the
same 16-bit indices with the per-byte shifts/ORs. `high` is a 256-entry compile-time
mapping that unpacks the four 2-bit fields of qh into bytes; `grid_indices`
interleaves those high bytes with the eight low q bytes. In linked code, the
candidate still performs the same number of IQ2_S grid-table scalar loads; it has
not converted the grid lookup to a vector gather. For each four-code group, the
compiler stores the packed `sp1`/`sp2` vectors to stack at `[rsp]` and `[rsp+0x10]`,
then performs four `movzwl` reloads for each before the scalar table lookups. That
stack array materialization and scalar extraction are part of the candidate's
chosen index representation, not the control's `sign_words` scratch.

Across the fully unrolled groups, the candidate assembly also stores/reloads
additional YMM intermediates at frame offsets including `0x20`, `0x50`, `0x70`
and `0x90`; these are compiler-generated stack traffic in the candidate body.
Some offsets also hold candidate temporaries (e.g. the broadcast scale state), so
this report does not count every stack access as a spill. The distinguishing
factor is visible: repeated index-array stores and `movzwl` reloads in the
candidate, plus other vector stores/reloads, against the control's compact sign
scratch and loop-carried vector state. The candidate body is fully unrolled for
the inner eight 32-value groups, while control retains the inner loop; this can
explain code-size/register-pressure differences but alone does not imply which is
faster. Candidate and control each retain a dynamic outer block loop.

Call, lookup and target findings
There are no helper calls in either successful hot dot body; candidate/control
calls in their disassembly are confined to invalid-width exception paths. The
hot grid accesses are scalar `vmovq` loads indexed by GPR into the read-only grid
table, not AVX2 gather operations. The candidate lowers the `high` interleave and
packed index path into vector byte operations, but then scalarizes indices via
stack and GPR loads. It therefore reduces some integer bit assembly while adding
observable index materialization and scalar reload work.

The separate `ggml_vec_dot_iq2_s_q8_K` symbol is captured and its body contains
its own scalar grid-table addressing and vector dot path. The qualification's
`rows()` assembly shows the baseline indirect trait call, direct control call and
direct candidate call separately. `quantize_row_q8_K` in this linked artifact is
a jump thunk to `quantize_row_q8_K_ref`; it is called by the synthetic test setup,
not by the dot functions. There is no evidence here of candidate dispatch in the
application kernel, persistent weights, a real model workload or production
activation preparation.

Smallest justified next factor
Change only the candidate's index output representation: replace the `uint16_t
sp1[8], sp2[8]` out-parameters with packed `__m128i` results from the same
low/high-byte interleave, and extract the fixed 16-bit lanes from registers for
the existing scalar `iq2s_grid` loads. Keep the same high-byte mapping, grid table,
signed Q8 path, loop structure, accumulation order and target flags. Do not combine
this with scale-table changes, gathers, pair fusion, wider unrolling or global
compiler flags. Re-run the already defined uniform/mixed/alignment and full row
correctness gates, then inspect the exact linked body for eliminated index stack
round-trips and any newly introduced spills before authorizing a timing comparison.
