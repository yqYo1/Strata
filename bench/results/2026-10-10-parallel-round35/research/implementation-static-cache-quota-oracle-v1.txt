API/objective
score_prefix_quota(curves,quota) returns a checked additive captured-count score.
select_prefix_quotas(curves,budget,default) returns score, baseline_score, baseline_gain, quotas, total_slots, L1 distance, tie rule and objective scope. Curves directly encode F_layer(q) for q0..capacity, with F(0)=0. No file/model/controller/replay imports, loader, CLI, production admission, quota mutation or engine integration is added. One uniform MAXBLOB slot purchases one more within-layer profile prefix entry. The objective must be ONE predeclared additive captured count. No packed-byte allocation, service/time/traffic/LRU/latency/performance/adoption result is represented.

Strict bounded inputs
Accept actual list/tuple curves/defaults,1..48 layers, each1..257 prefix entries (0..256 slots), budget integer0..128, explicit default quota per layer within cap and exact default sum==budget. Scores must be actual integer uint64, nonnegative and nondecreasing. Entry0 must equal0. Bool, float, generators, malformed dimensions, negative/out-of-range score/budget/default, decreasing curve or incorrect default sum reject. Default feasibility is required rather than inventing a baseline. Production default [2]*47+[34] is supported when curves contain those entries. Generic small and zero/full-capacity budgets are supported within bounds.

Exact algorithm/ties
Dynamic programming enumerates layer-prefix choices over exact slot totals, with no diminishing-marginal/greedy assumption. State stores best score, accumulated default L1 distance, deterministic lexicographic rank, previous total and current quota. Equal total states compare maximum score first, minimum L1 second, then parent-prefix lex rank/current quota. Each stage sorts selected prefixes by (parent rank,quota) to assign exact lexicographic ranks; reconstruction follows backpointers. Thus lex comparisons are fixed-size rather than retaining full quota vectors at every transition.

Only states extendable to the final exact budget are considered. Checked addition rejects ANY uint64 overflow among feasible objective candidates, even if the default score fits. No saturation/wrap or silent removal of overflowing alternatives. Since curves are nondecreasing, an overflowing extendable partial score would also overflow some full feasible score; rejection is appropriate for a uint64 objective. Baseline sum is independently checked. Distance is bounded by2*budget<=256. Return gain is optimum minus feasible baseline and cannot be negative.

Complexity/resource bounds
O(L*K^2) transitions, O(L*K) retained states/backpointers, plus O(L*K*logK) lex-ranking work. L<=48,K<=128, caps<=256; validation examines at most12336 prefix entries. No routes/weights/data payloads are retained. This is mathematical fixed-slot count maximization, not a measured runtime or claim that Python cost improves inference.
