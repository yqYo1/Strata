## Fixture oracle versus actual CLI replay

The fixture has six `unittest` methods. It exercises local helpers using literal small data: closed-gate/source-pin rejects, interval range/hash and whole-file mutation negatives, orphan/misplaced/overlap marker negatives, literal canonical JSON/SHA with order/shape changes, and a hand-authored resident/nonresident example with literal expected coverage cells. These are useful pure-function and small-file oracle checks. They do not invoke `replay()`, load the r6 receipt/profile/metadata/raw log, parse actual histogram or route output, exercise the complete four-request chain, or execute the actual command-line entry point. The literal job example is intentionally synthetic and proves only the arithmetic encoded in that example.

Actual CLI proof must be a separate root-owned invocation using the real r6 path and exact r6 SHA, pinned v6 controller path, and reader self SHA. Its durable evidence should include the exact argv, reader/fixture and dependency hashes, stdout byte count/SHA (and compact JSON output or retained structured result), stderr byte count/SHA, exit code, duration, closed-input hashes, and no-survivor/cleanup facts appropriate to the wrapper. It must show `passed=true` with four request summaries and matching canonical shape hashes. A passed fixture receipt alone is not proof that actual replay succeeded; a source-only report or registry entry is likewise not runtime evidence. Conversely, actual CLI replay proves consistency of this captured trace under the frozen static profile and helpers, not new model math, live cache behavior, LRU policy, performance, or GPU qualification.

The replay's fixed output contains request identity and raw reference, pair count and canonical hash, observed CPU histogram cells, and static-default 128-resident coverage counts. It expressly does not reconstruct ordered access, request-time recency, LRU evictions, upload/DRAM traffic, service cost, queue time, latency, or policy benefit. Keep A/B requests separate; no merging or independent holdout claim follows from the four captured requests.
