## Disposition

R95's host memcpy endpoint lifetime issue is closed by source structure for the current parity harness: **every `queue::memcpy` and `queue::fill` in this translation unit is lexically inside a `gpu_stage` callback, and every pageable host vector used as either endpoint is declared outside that callback and remains alive across its synchronous completion wait.** If submission or wait throws, the wrapper enters `fail_stop` while those vectors and the `Buffers` owner still exist; `std::_Exit(2)` ends the process without C++ stack or static destruction. No queue-operation or host-endpoint-scope escape was found.

No remaining source-only memory-lifetime blocker was found in the requested paths. This is not runtime qualification: the host fail-stop probe, host-only mode, candidate compilation, queue failure behavior, and GPU parity remain unexecuted. Root's separate supervised run remains required before any GPU test. No issue in this review changes the numerical fixture or candidate kernel; the only fixture-flow change is an extra completion wait after the forced-denial legacy fallback, which preserves the same in-order operation sequence.

## Operation, lifetime, and exception-path audit

The helper at `gdn_quad_parity.cpp:24-33` is `[[noreturn]]`; both standard and nonstandard exceptions from its callback are caught and logged, stdout/stderr are flushed, then `std::_Exit(2)` is called. The catch does not return through the callback, so the caller's host vectors are not destroyed. C++ termination semantics state `_Exit` does not execute automatic or static destructors ([C++ working draft, termination](https://timsong-cpp.github.io/cppwp/draft.pdf), [current draft](https://eel.is/c++draft/support.start.term)). The injected probe places both a vector endpoint and a destructor marker outside the callback (`:150-154`); expected status 2 plus marker absence directly checks that this process path does not unwind those scopes. It has not been run.

- `initialize` constructs `state` before entering `gpu_stage` (`:72-73`). Both device fills, both H2D copies, and `wait_and_throw` run in one stage (`:79-82`). Success completes the copies before `state` dies. Any fill/copy/wait exception reaches `_Exit` before `state` unwinds.
- `prepare` constructs/populates `h`, `gate`, `beta`, `z`, and `gamma` outside the callback (`:84-98`); fills, all five H2D copies, and their wait are inside one stage (`:100-103`). Any later enqueue throw after an earlier accepted copy still reaches process exit while all five source vectors are alive.
- `floats` constructs receive vectors `x/y` outside `gpu_stage`; both D2H copies and wait are wrapped (`:105-106`). `compare` does the same for half-output `x/y` (`:114`). CPU comparison and `require` happen only after the wait returns normally, so throwing due to a mismatch cannot leave the receive copy in flight.
- `empty_device` keeps `before`, `after`, and `half` outside their respective stages (`:120,124,126`). The candidate T=0 call is separately wrapped (`:122`); source says it returns before queue lookup/submission. The waits complete before each snapshot comparison/check.
- `call` keeps forced-denial `before`, `after`, and `half` outside their copy stages (`:133,138,141`). The candidate recurrence submission is wrapped (`:134`). The denied fallback reference submission and wait are in one wrapped stage (`:142`). Normal candidate/reference submissions plus final queue wait are wrapped (`:144`). Existing `prepare` copies have already completed before recurrence submission. If an assertion after candidate submission throws before another wait, no host transfer endpoint is still pending; `Buffers` teardown performs a wrapped final queue drain (`:64-69`) and will `_Exit(2)` if it cannot establish completion.
- `Buffers` constructor partial allocation (`:57-62`) submits no queue work. It reserves pointer tracking first and frees successful partial allocations on construction failure; failed frees are logged and original allocation failure rethrown. This may leak an allocation until process exit, but no queue command or host vector references it. Normal destructor drains through `gpu_stage` before explicit USM frees. Unknown final-drain outcome exits before its `owned` vector or device USM owner can unwind/free. After a successful drain, free errors are logged and surfaced when no original exception is active; there is no pending command lifetime at that point.

A grep-level review of all `q.memcpy`, `q.fill`, and `q.wait_and_throw` sites found none outside these wrappers except queue creation/property/query paths. Device queue info at `main:164-165` is before `Buffers` construction and before work; failure follows ordinary main error status with no pending memory operation. Candidate dispatch catches and returns false only for read-only pre-submit support/query denial; in this strict differential executable the following assertion rejects a denied positive candidate. Submission/norm errors are inside the wrapper and cannot fall back. The explicit reference and forced-denial fallback are wrapped too. Candidate asynchronous completion is collected by a later wait on the same in-order queue (the normal reference/final-drain stage or destructor final drain); this can make attribution of an asynchronous fault less localized, but it cannot produce a PASS after an error because the wait wrapper fail-stops and state/reference arrays are distinct.

The queue used is DPCT's function-local-static in-order queue, created with an async handler (`dpct/device.hpp:684-702`). The handler delegates to `strata::rethrow_sycl_errors`, which prints and rethrows the first asynchronous exception (`device.hpp:70-73`, `strata/sycl_error.hpp:8-19`). The queue is borrowed and outlives local `Buffers` objects in ordinary mode. SYCL specifies asynchronous queue memcpy and requires event/queue completion observation before assuming work has completed ([SYCL USM lesson](https://github.khronos.org/syclacademy/Lesson_Materials/Using_USM/), [SYCL queue reference](https://github.khronos.org/SYCL_Reference/iface/queue.html)). `wait_and_throw` blocks and delivers pending async errors but can also surface synchronous/runtime errors. Installed oneAPI 2026.1 UR `ur_api.h:7320-7349` says successful `urQueueFinish` is a completion synchronization and lists device-lost/adapter-specific failure results; installed `/usr/include/level_zero/ze_api.h:3654-3685` describes host queue synchronization with device-lost/reset/error results. The wrapper's conservative all-exceptions fail-stop is appropriate for this disposable test.

`--host-only` branches before the only default queue lookup at `main:164` (`:156-161`). `early_contract()` tests host arrays and scalars; candidate T=0, reference T=0, negative T, and forced denial all return/throw before queue lookup in the source candidate API. This conclusion is source-level only; it cannot guarantee a SYCL/Level Zero plugin does no hardware-related work during loader/runtime initialization. No host mode was executed.

The program's regular final `PASS complete...` is emitted only after its test blocks and `Buffers` final drains. The following stdout/stderr flush/error check can still fail, be caught by `main`, and return 1; hence PASS text alone is not an accepted result. README line 52 correctly requires normal exit 0, final flush, recorded process/queue closure, no forced cleanup/survivors, and treats a preceding PASS as insufficient after later teardown/closure failure. Actual supervisor implementation/receipts are root-owned and were not part of this source-only worktree audit. The source also does not run its own child-process/survivor check.
