## Current allocation and residency contract

`ExpertCache::open()` allocates one uniform arena of `n_slots * blob_bytes`, checks free device memory, zeroes it, and initializes every expert as nonresident (`expert_cache.cpp:578-685`). The existing per-layer ranges are not arbitrary: `layer_slot_range` assigns `floor(slots/layers)` to each layer and gives all division remainder to the final layer (`:759-767`). With 128 slots and 48 layers this is 47 layers × 2 plus 34 in the last layer. In per-layer mode, `admit` assigns the next free slot within that layer's range and refuses when full; it does not evict (`:778-805`; header `expert_cache.hpp:84-100, 242`). Thus a replacement quota must change both the reserved ranges and their per-layer admission cursors; merely changing a selected list does not alter the engine's current quota.

The native `open_sized()` path is a distinct byte-budget mechanism: it aligns each slot to 256 bytes, sums offsets, and sets per-slot capacities (`expert_cache.cpp:691-729`). It is not equivalent to choosing `q_l` under 128 fixed max-blob slots. `generate.cpp` builds sized capacities from profile experts only for auto-cache (`:4770-4845`); an explicit 128-slot profile cache follows uniform `max_blob` sizing. The first policy comparison should therefore retain explicit 128 slots and current uniform `max_blob` arena. Mixing in `open_sized` would confound policy with a new variable-byte budget and packing rule.

The profile is an ordered list of `(layer, expert)` pairs, not a quota vector. The C++ reader checks the STRP header/model geometry, ranked length and coordinate bounds (`expert_cache.cpp:142-206`), but does not provide R57's full uniqueness/inverse validation. Keep the profile immutable and store a separate quota config bound to exact profile SHA, model geometry, all 48 integer `q_l`, slot total, and schema/version. Validate `0<=q_l<=512`, checked prefix sums, no overflow, exact sum 128, and deterministic ties in the offline selector. At engine admission, reserve exactly the first `q_l` ranks for each layer in profile order; reject malformed or mismatched config before cache fill. Do not silently clamp or fallback to a different distribution.

The warm fill walks the profile list once and attempts each expert admission; full layers are skipped while other layers may continue, yielding a per-layer prefix as long as profile order is preserved (generate.cpp profile/cache setup around `:4850-5010`). It also disables the piped special path under per-layer mode (`:4793-4798`). New quota logic must preserve source blob-size checks, source read failures, slot write/verification, and one-time fill ordering. A test-only issue to address: `verify_slot` validates slot bytes (`expert_cache.cpp:1000+`), while higher-level profile verification currently assumes `profile[0]` is resident; a candidate with `q[layer(profile[0])]==0` breaks that assumption. Select a guaranteed admitted `(layer,expert)` for the verification probe, and validate the entire resident-to-slot/inverse map, including empty-quota layers.

## Serving map, graph, and phase ownership

The cache consumer receives `cache_base`, uniform `cache_blob`, optional slot offsets, and a device residency map (`generate.cpp:5060-5080`, `:5690-5775`, `:6910-6925`). The map translates expert IDs to fixed slots; the graph path reads that device indirection. The verifier copies/retains the same pointer plan during initialization (`generate.cpp:701-710` context and verifier initialization around `:6900-6935`). Consequently the quota and residency map must be final before verifier initialization, graph warmup/capture, and any session that consumes these pointers. A live distribution change is a cache replacement: stop work using old slots, rebuild/fill arena and host/device maps, reinitialize dependent consumers and recapture graphs. The safe first candidate is a fresh process per arm, not an in-session quota swap.

Per-layer admission and adaptive swapping are separate modes. `--adapt-swaps` mutates residency after generation by updating slots/map (`generate.cpp:12190-12345`); profile-save is also an adaptive output. Keep swaps zero and profile-save/adaptive behavior out of the static arm. `--vram-elastic`/KV growth is another allocation policy; cache release via `STRATA_PREFILL_RELEASE_CACHE` changes the cache base and has explicit captured-graph refusal/rebuild paths (`:11786-11800`). Remote/peer cache also changes the source path. Hold those settings fixed at their baseline values during the static policy comparison.

A critical phase caveat for a full 256K request: prompt prefill can borrow cache-tail slots. With borrowing enabled, the engine temporarily changes `host_res` entries to nonresident, runs prompt work, reloads the lent experts and restores/reuploads residency (`generate.cpp:11715-11760, 11805-11837`; alternate path `:10009-10073`). The max-context path can enable this for long contexts when a profile exists. The static quota therefore must remain the ownership plan across prompt/decode: either preserve and measure the borrowing/restoration behavior with exact per-slot capacities, or explicitly disable borrowing while accounting for the prompt memory requirement. Verify the restored device map and the first decode phase after prefill. A max-context setting or four 32K requests does not constitute an actual full 256K prompt-to-decode lifecycle. The next lifecycle evidence must include the physical prompt tokens, phase transition, decode, correctness/state checks, faults, and map checks.

## New dependency beyond R57's count-only DP

R57 optimizes an additive fixed-trace count objective over ranked profile prefixes. That is a valid exact combinatorial answer for its declared objective, but engine feasibility adds per-layer backing/capacity constraints. Current uniform slots reserve equal-sized max-blob regions; a static quota is feasible only if the exact selected blob for every resident expert fits the destination slot under current `max_blob`, and every copy respects its slot bound. For this fixed-slot arm, retaining uniform `max_blob` makes this straightforward but potentially wasteful; a variable-size packing arm needs a separately declared byte budget and alignment/capacity feasibility oracle and cannot be inferred from the 128-slot DP. This is the additional source dependency not covered by R57: the map is not only a set of selected experts, but a one-to-one assignment into layer-owned, size-bounded storage consumed by captured kernels.

## External transferability

NVIDIA's [CUDA Graph constraints](https://docs.nvidia.com/dl-cuda-graph/latest/cuda-graph-basics/constraints.html) document that captured graphs bind parameters/pointers subject to graph-update rules; this is corroboration for careful map/base lifetime, while Strata's own device residency indirection and rebuild checks are the governing evidence for this engine. The mutable grouped expert-cache implementation in [llama.cpp](https://github.com/ggml-org/llama.cpp/blob/master/src/llama-moe-cache.cpp) demonstrates a different dynamic LRU/slot-map policy; it is not transferable as evidence for static prefix quotas or this engine's phase safety. No external source supplies a valid quota or performance claim for Strata.
