Finding: an IQ prefetch setting can silently alter an NT2 timing profile
`environment_metadata()` prints and checks a fixed environment allowlist at `native_service_calibration.cpp:79-85`, but it omits `STRATA_IQ_PREFETCH`. The production AVX2 IQ implementation reads this variable once and uses it to select a prefetch distance, defaulting to 2048 bytes (`src/kernels/cpu/iq_avx2.cpp:177-194`). The calibration CMake target includes the wrapper that compiles this AVX2 implementation (`CMakeLists.txt:33-35`); NT2 IQ gate/up rows can therefore use this implementation. Setting `STRATA_IQ_PREFETCH=0` disables prefetch, while other values alter the distance; the implementation source records prior performance differences on a Ryzen 5 5700X3D for IQ3_S. Those prior measurements are context only, not a prediction for these cells.

The variable is neither emitted in the run metadata nor rejected. Because the kernel caches its value in a function-local static on first use, the output cannot reconstruct the setting later. As a result, two otherwise identical fresh-process cell runs can silently time different implementations, and a report of the measured route lacks one performance-relevant configuration value. This is a reproducibility/attribution defect, not evidence that a correctness gate would falsely pass or that a particular run used a nondefault value. Root should require it unset in the supervised launch environment or add it to emitted metadata and pin the value across all compared profiles before treating those timings as comparable. The same value must be stated in the immutable run receipt.

Timing interpretation caveat already stated by the implementation
`prepare()` and correctness checks are outside each timer (`native_service_calibration.cpp:262-276`), and the whole measured round includes the arm’s loop/calls. The implementation reports those outer times separately from the pool’s internal phase deltas and explicitly disclaims end-to-end qualification. Train is always measured before holdout (`:260`); the README already warns that arm rotation is not proof of absent time drift and assigns profile/cell ordering and thermal observation to root. I did not count this documented limitation as a new false-pass defect. It remains relevant if comparing cohort-level rates without external counterbalancing.

Decision
Before comparing NT2 IQ cell results or combining them with other route profiles, pin `STRATA_IQ_PREFETCH` explicitly. If root does not modify this source, the owner-run receipt must at least record and verify the inherited environment value; source output by itself is insufficient to prove it was unset/default. No new code change is made in this review.
