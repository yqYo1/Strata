## What source and link evidence say about device entry paths

The isolated target includes the actual production `native_role_plan`, CPU expert layout/quantizers, `ExpertPool`, native expert kernels and GGML CPU backend. It does not link the parent SYCL project, engine, GPU allocator, or a GPU runtime. The relevant CPU operations are finite-input construction, GGUF metadata/file mapping and expert-byte copies, GGML CPU trait initialization/quantization, CPU row kernels, pool worker creation/affinity, condition-variable/atomic synchronization, clocks, and output. Source searches in the harness and linked Strata CPU files found no SYCL/DPCT, UR, Level Zero, OpenCL, CUDA, HIP, or `dlopen` call site.

There is one deliberate legacy pool error hook: `pool.cpp` calls `strata::core::release_gpu_waits(stderr)` in its stall abort paths. This helper is inline in `progress.hpp`; it loads `release_gpu_fn` and calls it only if non-null. The harness checks the callback is null before work and after each pool call; the isolated source has no registration path or linked engine code. Thus ordinary pool work has no device callback, and even the existing abort hook is a null no-op in this executable unless some future source/link change registers a callback. The watchdog still aborts on a stuck pool; it does not submit GPU work to recover.

These source facts plus the direct import list make an exhaustive Level Zero/UR function interposer unnecessary as the *first* smoke gate: there is no such runtime in the recorded direct link closure to interpose, and no linked source call path to invoke one. The remaining gap is whether startup/runtime loading or an ambient process environment introduces a new path, and whether the exact run performs unexpected device-file operations. A finite syscall/loader observation closes that gap with less machinery than R65's interposition plan for the earlier `-fsycl`-linked wrapper.

## Minimum sufficient no-device observation for the planned CPU correctness smoke

For the exact pinned binary and one bounded selected-cohort smoke, root can make a narrow, reviewable observation:

1. Reconfirm the executable SHA against the receipt immediately before launch. Launch a fresh child with a recorded minimal environment; exclude inherited `LD_PRELOAD`, `LD_AUDIT`, and uncontrolled `LD_LIBRARY_PATH`, and ensure no unrelated descriptors are inherited. Keep model/pack paths and the permitted harness feature variables explicit. Do not hide devices, alter system services, or use a device selector as evidence.
2. Trace from before `execve` through process exit with `strace -f -yy` covering file-open/close and `ioctl` syscalls (at least `open`, `openat`, `openat2`, `close`, `close_range`, and `ioctl`; include mmap if useful to distinguish ordinary GGUF/library mappings). In parallel capture the dynamic loader's `LD_DEBUG=libs` record for the exact environment. Tracing starts before dynamic-loader initialization and so observes pre-main constructors as well as harness calls and teardown. Retain the raw trace only for this admission question, with owner, byte budget and review point per artifact-retention rules.
3. Classify every opened `/dev` path and every ioctl's decoded fd/path. GGUF shards, the pack, loader files and ordinary `/proc` CPU-topology/status reads are expected host inputs; regular file mappings are not device activity. Treat an open of a GPU/accelerator node or an ioctl on such a node as a tripwire hit. Reject unexpected runtime/adapter libraries in the loaded-object log, regardless of whether an ioctl appears. Record the complete observed object set rather than only checking the direct NEEDED list.
4. Require the harness's own finite correct-exit checks and null callback checks to pass in that same traced process. If `strace` cannot start/trace completely or loader logs are absent/truncated, report the no-device observation as unavailable; do not infer it from CPU output or `gpu_work_submitted=false`.

A clean result supports only this bounded statement: “For this executable hash, environment, payload cohort and observed process lifetime, the loader log showed only the recorded host objects and the syscall trace showed no GPU/accelerator device-node open or device-fd ioctl.” Combined with the audited CPU-only source/link path, that is enough to admit this CPU correctness smoke as having no observed device probe, context/queue setup or submitted work on the observed Linux run. It is not a universal guarantee that the binary can never use a device under another environment, a proof against an untraced bypass, a full API-call interposition audit, or a performance/full-lifecycle result. Do not word it as “no GPU” without the run/environment qualifiers.

The trace must account for startup constructors and teardown, not only the harness's timed region. `LD_DEBUG=libs` records dynamic loads but does not itself observe device API calls. `strace` observes kernel-facing operations but does not name a user-space API that returns without a system call. Their combination is proportionate here because the exact link closure omits accelerator runtimes and source inspection found no direct runtime calls. If the object log unexpectedly shows SYCL/UR/Level Zero or a device library, stop and investigate that concrete new path before claiming this boundary; only then consider the specific API hooks required by that loaded runtime.
