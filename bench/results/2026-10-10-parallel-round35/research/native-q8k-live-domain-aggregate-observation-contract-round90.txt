Round 90: live Q8_K activation-domain observation contract

Question and scope
Where could a future opt-in observation collect enough aggregate evidence from real native CPU expert inference to decide whether the ordinary finite Q8_K domain assumed by R88 actually occurs, without saving activation tensors or changing quantized bytes? This is a read-only source contract for the Strata native expert path, not a measurement proposal with runtime results. It covers only Q8_K input quantization for Gate/Up and Down, separating decode from prefill and keeping the Q8_0 and Q2 activation routes out of the Q8_K population. No code was changed; no build, import, test, profiling, device/runtime/model/payload, Git, or cleanup action was performed. Candidate speed and priority, and the actual serving input distribution, remain unmeasured.

Current ownership and observation seam
`native_fmt` in `src/kernels/cpu/native_expert.cpp` takes each weight type's GGML `vec_dot_type` as `gu_act` or `d_act`. The Q8_K route in `native_quant_act` is the Gate/Up input quantizer; `native_quant_h` is the Down input quantizer. Both call Strata `q8k_quant_avx2` when the existing AVX2/runtime/environment gate allows it, otherwise the GGML trait's `from_float`. The current source gate is `cpu_avx2_ok()` plus absence of `STRATA_NO_Q8K_AVX2`; it is process-static. Formats with Q8_0 activations use their other trait quantizer, and native Q2 routes use `act_quant_any`; neither belongs in this Q8_K report.

Decode's actual input call is in `src/core/expert_source.cpp` near the CPU-native activation preparation: a layer's `x_f` rows are quantized before `ExpertPool::run_split_multi_native`. A row may be quantized when some CPU work exists in the decode window but later have no CPU-native job consuming it. Therefore a future report must count only unique token rows referenced by CPU-native jobs. It must not equate `native_quant_act` call count with consumed GU rows. The source already forms per-expert job rows and references activations by token; a diagnostic can retain only each row's compact local aggregate until the job references are known, then merge rows with CPU consumers. Do not retain input floats or Q8_K bytes.

Prefill's CPU-share branch in `src/prefill/prefill.cpp` runs on an async host task. It first makes a `need[T]` mask from tokens referenced by CPU-owned expert routes and quantizes only those `m.cpu_x` rows. This is a distinct `prefill` phase/source label from decode; counters must not combine them. Within that branch, the same token activation can feed several CPU expert jobs, so count one unique quantized row for input-value distribution and separately record its CPU-job consumer incidence.

For Down, `ExpertPool::run_split_multi_native` in `src/kernels/cpu/pool.cpp` runs the GU row phase on workers, then the caller quantizes each expert/token's `ff[t]` with `native_quant_h`, then runs the Down row phase on workers. This call is after GU completion and before Down starts; the Q8_K observer belongs at the quantizer seam, not inside the parallel row-dot worker loops. The per-expert `nt` is `jobs[e].nt`, and Down's H row is one-to-one with an expert token, so each quantized Down row has an unambiguous expert-group NT bucket. GU input rows are shared across jobs: preserve one unique-row aggregate and record NT1/NT2 consumer-incidence counts separately. A future downstream comparison may materialize consumer-weighted summaries, but must label them as weighted and must not double-count them as unique inputs.

Minimal aggregate schema
Use a diagnostic-only per-call accumulator at the actual quantizer implementation points, not a second formula that reconstructs values from output. Merge once per call into a run-scoped sink. The sink key is `(phase=decode|prefill, role=GU-input|Down-input, quantizer=Strata-AVX2|GGML-reference, activation-type, width, expert-NT-bin, FP-mode)`. Keep Q8_0, Q2 and other formats in separate route counters or omit them. Count actual unique consumed GU rows and actual Down rows separately from raw quantizer invocations.

For each observed row/block set, retain only counters and extrema:

- total blocks and scalar values; finite, NaN, and infinity input-value counts; input zero/nonzero and subnormal counts; maximum finite absolute input value;
- blocks with all-finite inputs, all-zero input, finite nonzero selected `max`, and non-finite/zero selected maximum; maximum finite block `amax`;
- `iscale` categories (finite normal, finite subnormal, zero, infinity, NaN), sign counts, and finite absolute min/max; corresponding categories for `d=1/iscale`;
- the exact pre-round `scaledprod=iscale*x` categories (finite, non-finite, zero, subnormal), finite absolute max, counts above `+127`, below `-127`, exactly at either endpoint, and nonzero inputs whose product becomes zero;
- resulting Q8_K `qs` min/max and counts for `-128`, `-127`, `0`, `+127`; and separately, written `bsums` group count, written-zero group count, min/max, and all-zero written-sum blocks;
- zero-block `bsums_skipped` count. The reference and Strata AVX2 zero-block fast paths zero `d` and `qs` and leave `bsums` untouched; never read or classify those bytes as zeros.

These are aggregate-only diagnostics; no row values, block bytes, request text, token IDs, expert IDs, or per-element log records are retained. Include call/row/block denominators so a zero exceptional count can be interpreted. A row is ordinary-domain only if every block has finite values, a finite nonzero selected max, finite `iscale`, finite products within the chosen `[-127,+127]` bound, and no output `-128`. Report each failed condition independently; do not silently discard exceptional blocks from the denominator. The `>127` counters matter because the actual floating multiply can round slightly outside the exact-arithmetic bound in R88.

FTZ/DAZ boundary evidence
At observation time, record the executing thread's x86 MXCSR FTZ and DAZ bits (or `unknown` on a path that cannot read the relevant control state), plus counts of subnormal input values, subnormal `iscale`, subnormal scaled products, and nonzero inputs producing zero scaled products. This can show that observed values or intermediates touch the subnormal/underflow boundary under a recorded mode. A zero product alone does not prove FTZ: gradual underflow may also round a tiny product to zero. Do not infer a global FTZ policy or causal mode from aggregate product counts alone. Keep the current quantizer's production FP mode; a diagnostic must not toggle FTZ/DAZ.

Thread safety and non-interference contract
Counters are diagnostic-only and opt-in. When disabled, the existing dispatch, inputs, byte writes, ordering, and allocation paths must remain unchanged. When enabled, use a small stack-local aggregate for one `q8k_quant_*` invocation, inspect classifications at values already loaded/computed by that implementation, then merge once into a run-scoped, mutex-protected sink (or equivalent per-thread shards with a safe final merge). Do not add a shared atomic update per float/block, print from worker loops, allocate a trace per block, or retain raw rows. Carry an explicit diagnostic context from the decode or prefill operation so concurrent requests and the prefill async task cannot mix phase attribution; reset/close a sink only at a completed observation boundary. If future work parallelizes quantizer calls, the same one-merge-per-call rule keeps shared counter updates bounded. Record which quantizer branch actually ran, since AVX2 and GGML fallback are distinct live routes.

To observe both implementations' `iscale` and `scaledprod` exactly, the future instrumented seam must be inside each selected quantizer implementation (Strata `q8k_quant_avx2` and the pinned GGML reference called by the trait), or use an equivalent optional observer that sees those already-computed intermediates. Observing only the Q8_K output cannot recover NaN/Inf input counts or the exact scaled-product boundary. A duplicate shadow quantization pass is not acceptable as evidence of the live path. For the AVX2 implementation, classify its already-computed vector product before the existing rounding step; for the GGML scalar reference, classify the product in its existing scalar loop. The diagnostic observes and counts, but must not replace the quantization arithmetic or write the output a second time. This instrumentation is a future implementation seam, not an implementation in this report.

NT and interpretation rules
For a per-expert `nt=1` group, the input/output relationship is one expert token; for `nt=2`, two token rows are in the same expert group. Down observation naturally bins each `h` row by that expert's `nt`. GU activations are token rows reused by all routed local experts, potentially across groups with different `nt`; count each unique row once and report its NT1/NT2 consumer incidences rather than falsely assigning a single NT to a shared row. Decode and prefill remain separate top-level strata. Report both block-weighted and row-weighted proportions only if clearly labeled; block counts differ for widths that span different numbers of 256-element Q8_K blocks. No distribution claim can be made until a future authorized real inference observation runs and closes its window.

Limits and next decision
This source review locates the minimum observation seam and fields that distinguish the R88 ordinary finite domain from non-finite, zero-block, scale-overflow, out-of-range product, `-128`, unwritten-zero-block-bsums, and FTZ/DAZ-boundary cases without keeping tensor payloads. It does not establish that serving activations satisfy the domain, how often either Q8_K branch is selected, how much instrumentation costs, or whether a diagnostic is worth enabling. No candidate speed, ranking, or actual input-distribution result is claimed. R80 service-cost accounting and R85 arithmetic-order controls are not repeated here.
