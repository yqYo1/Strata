## Rank, objective and fit-before-score audit

The declared objective is routed entry count `N`, not callbacks, logical bytes, service time or latency. `prefix_curves` requires a complete `layers*experts` rank vector and validates every rank pair's shape, integer types, bounds and uniqueness. Complete length plus no duplicates and in-bounds coordinates implies a full rank permutation. It builds each layer's within-profile order by appending IDs in their original global profile sequence; it does not sort by observed count. Sparse observed count pairs are validated and duplicate-checked; unobserved experts get zero (`:59-93`).

Production input has 48 layers × 512 experts. The pinned parser validates the entire 24,576-entry STRP profile and inverse before the adapter's fixed `<HH` unpack over bytes `[24:24+24576*4]` (`:106-108`). The adapter then uses `ids[:cap]` with `cap=128` for every layer (`:59-60, 88-92`). This is a deliberate, mathematically sufficient truncation for an exact total of 128 slots: no feasible quota can exceed 128, so ranks 129–512 cannot affect any candidate score. Crucially, it validates the full rank order first and only then truncates each layer prefix; it does not reinterpret or reorder those 128 ranks. The per-layer curve includes zero plus cumulative counts for ranks 1..128, including unseen zero-count entries, with checked uint64 prefix addition.

The selected objective/budget/default are fixed in source: A-read0 only, 128 uniform MAXBLOB slots, default `[2]*47+[34]` (module docstring and `DEFAULT`; fit selection at `:122-124`). The loop chooses the DP candidate only when `index==0`, freezes `candidate=fit['quotas']`, and subsequently only scores that frozen vector on requests 2–4 (`:110-125`). Thus B and repetitions do not participate in fit. Before recording any request result, the adapter requires its default-quota score to equal both the request parser's END `hits` and the pinned replay's default resident `covered_entries` (`:119-121`). This is a strong cross-check that rank/count mapping reproduces the already-validated observed default hits, not just a self-consistent new curve.
