## Smallest viable storage/admission API

The existing unit to change is `strata::core::ExpertCache`, despite shorthand references to “ExpertSource”: it owns slot storage, the `(layer,expert)→slot` residency map, and the per-layer admission cursor. `ExpertSource` supplies blob bytes; it does not own these slots.

Add one explicit initializer on `ExpertCache` (or equivalently a validated initializer helper called exactly once before any admission), for example:

```cpp
bool open_uniform_layer_quotas(const std::vector<int32_t>& quota,
                               int64_t expected_slots,
                               int64_t n_layers, int64_t n_expert,
                               int64_t blob_bytes, std::string& err);
```

The caller for this candidate fixes `expected_slots=128` and `blob_bytes=expert_layout().max_blob`. Keep this distinct from both current `open()` and `open_sized()` so the API makes the global 128-slot MAXBLOB budget explicit. Before allocating, reject a quota vector with wrong layer count, negative quota, quota above `n_expert`, checked-sum overflow, or sum other than exactly `expected_slots`; validate dimensions and positive blob size as `open()` does. An insufficient actual device allocation is a hard candidate failure; never silently shrink the 128 budget or redistribute quotas after seeing free memory.

Implementation outline:

1. Validate the full quota vector and sum before touching cache state.
2. Allocate exactly `expected_slots * blob_bytes` using the existing uniform `open(expected_slots,n_layers,n_expert,blob_bytes,err)` path and its current free-memory check, zeroing, residency initialization, HIP staging, segment/VMM behavior and error unwind. For the first candidate, leave segmented/VMM/hot resize off; this is the ordinary fixed uniform allocation.
3. Only after successful open, install the quota vector as the active per-layer plan and initialize every `layer_next_[l]` to its range start. Do not leave a partially installed plan if allocation fails. `close()` must clear the quota vector/ranges; the new initializer must explicitly select its mode regardless of any previous setter state.
4. `layer_slot_range(l,lo,hi)` returns prefix boundaries: `lo=sum(q[0:l])`, `hi=lo+q[l]`, with invalid layer returning `(0,0)`. The ranges must be contiguous, disjoint, and cover exactly `[0,128)`, including zero-length ranges. Keep the old equal-floor-plus-last-remainder formula unchanged whenever no explicit quota plan is active, so existing `--expert-cache-per-layer` behavior stays intact.
5. `admit(l,e)` keeps its existing coordinate check and existing-resident fast return. In quota mode it admits only if that layer's cursor is below `hi`; it increments only that layer's cursor and `admitted_`. If `q[l]==0`, return `kNotResident` for new admissions. Other layers continue filling. It must never fall through to the legacy global `next_free_` path once quota mode is active.

The actual class currently has `set_per_layer_admission(bool)` and `layer_slot_range()` (`expert_cache.hpp:167-175`), `open()` initializes `layer_next_` from the old equal-range calculation (`expert_cache.cpp:578-689`), `open_sized()` rebuilds cursors after changing slot geometry (`:691-729`), `close()` clears state (`:731+`), `layer_slot_range()` encodes equal floor/remainder (`:759-767`), and `admit()` claims slots (`:773-805`). Therefore the smallest safe change is an explicit quota-aware initialization/configuration of this same owner plus a quota-aware `layer_slot_range`/admission branch. A selected-ID list by itself is insufficient: it cannot establish owned contiguous layer ranges, zero-quota behavior, or the runtime admission ceiling.

### Why `open_sized()` is not the same budget

Do not route the 128-unit selector through `open_sized()`. That API takes a vector of per-slot byte capacities, aligns each slot to 256 bytes, and allocates the sum of those sizes (`expert_cache.cpp:691-729`). A MAXBLOB budget used by the offline quota objective is 128 identical `max_blob`-sized slots, exactly the existing uniform `open(128,...,max_blob)` backing. Sized storage can consume less than this byte total while exposing more than 128 slots, changing the optimization budget, slot count, layer-range arithmetic, prompt-loan conversion and storage capacities together. A sized representation could be a separately declared byte-budget experiment with its own selector and proof, but it is not an equivalent initializer for this uniform-128 policy.

### Quota config and profile prefix checks

Keep the on-disk `STRP` ranking unchanged. The quota is a second immutable configuration, not a rewrite or newly selected 128-entry profile. Bind the quota record to schema/version, exact model geometry, exact total slots (128), the full 48-entry quota vector, and SHA-256 of the exact profile file. Verify profile identity before any in-memory peer/profile reorder. `read_expert_profile()` checks the STRP header, geometry, ranked length and coordinate bounds, but does not provide the offline selector's full uniqueness/inverse validation; at the static-policy boundary, fail closed on duplicate `(layer,expert)` pairs or malformed ordering.

From the exact original profile order, count ranks per layer and admit only that layer's first `q[l]` pairs. Require at least `q[l]` distinct ranked IDs in each positive-quota layer. Do not globally truncate the first 128 profile rows, sort by a new score, or pass only a selected list without the quota vector. If the code is wired after the existing peer hot-rank shuffle, the rank prefix semantics change; the minimal first arm should reject/disable peer-device ranking, layer split, and helper caches. The profile file itself remains untouched.

For `q[l]=0`, the selection is an empty prefix and the complete device/host residency row for that layer must remain `kNotResident`; it is not an allocation or fill error. For positive quotas, all exactly selected profile-prefix IDs should be admitted and filled, and all other IDs remain absent. Reject incomplete fill, duplicate profile entries, or an unexpected slot count rather than treating partial quota coverage as the requested policy.

## Required generation call-path wiring

Current main-path order in `sycl/src/program/generate.cpp` is consequential:

- Profile is loaded and possibly peer-reordered around `:3339-3385`.
- Native slot-sizing branches around `:4328-4395` can turn a nominal `--expert-cache 128` MAXBLOB budget into `sized_slots` and a variable number of real-size slots. The normal allocation/retry loop around `:4470-4525` chooses `open()` or `open_sized()`.
- Current equal per-layer admission is enabled only after opening (`:4533`) and profile fill starts around `:4555`. The fill loop preserves profile order; with per-layer mode it continues on one full layer while other layers can still fill. The GGUF pipelined fill is currently disabled for per-layer mode (`piped = ... && !per_layer` around `:4570`); keep the new quota path on that simple serial fill path for the first arm.
- A current correctness assumption must change: after filling, `verify_slot` unconditionally probes `profile[0]` when `prefilled>0` (`:4717`). If `q[profile[0].layer]==0`, that slot is not resident. Select a probe from the actual admitted list / first `(l,e)` where `slot_of(l,e)>=0`, verify it, and reject only if the total required positive-quota fill is incomplete. For all-zero quotas, this candidate is not a 128-slot experiment, but the generic initializer should still reject the invalid zero total when expected slots is 128.
- `host_res` is built from `slot_of` after fill (`:5693-5725`) and uploaded by `res_put`; this must be the exact inverse of all nonnegative cache slots. The graph/hit path receives the stable device `d_res`, `cache_base`, uniform `blob`, and optional `slot_off` pointers (`:5716-5762`, verifier setup `:6914+`). These pointers and the final residency map must be installed before verifier init, hit-plan setup, or graph capture/warmup. Do not mutate quota distribution or move slot addresses in a live process.
- The ordinary CPU/native pool fallback already uses `host_res`/slot lookups for actual routing; a zero-quota layer simply follows the existing miss/CPU path. Preserve the pool configuration and hit/miss correctness gates. Do not infer a service-cost or speed effect from the static count objective.

For the smallest first implementation, make the candidate an explicit single-GPU native-pack profile mode: require explicit `--expert-cache 128`, do not run auto sizing/retry shrink, do not set `sized_slots`, preserve `max_blob` uniform backing, and use the new quota initializer instead of setting the old equal `--expert-cache-per-layer` flag. If the GPU cannot allocate 128 uniform slots while preserving reserve/headroom, mark the arm infeasible under the specified budget; don't quietly test a smaller policy. Disable adaptive swaps/profile-save, remote or peer caches, layer split, and elastic cache resizing in that arm. They have distinct owners and would require quota-aware per-owner maps and re-admission semantics.

## Prefill borrowing, restore, and cache-map ownership

Both non-serve generation and server generation have prompt-loan paths. With an explicit static profile and borrowing enabled, `pf_borrow = !no_prefill_borrow && !expert_profile.empty()` (around `:3407`). The non-serve path (`:11717-11834`) computes a tail loan, finds all `host_res` entries with slot `>= first`, saves `(flattened residency index,slot)` in `lent`, changes those map entries to `kNotResident`, uploads the map, and lends `device_slot(first)` plus a byte extent. After prompt it refills each exact saved slot from the same `(layer,expert)` source, restores `host_res[index]=slot`, syncs queued copies, and uploads the restored map. Uniform MAXBLOB slots make tail byte math (`k*max_blob`) valid; quotas may have zero-length layers but must not change this slot geometry.

The serve path has a `PfPart` per owning cache/stage around `:6400-6420`; each loan is constrained to its stage's owned layer interval, saved and restored by exact `(index,slot)` entries, and updates the same host map before resuming decode. For the first single-GPU arm only the primary `xcache` part is active, but its save/remove/refill/restore order remains required. Verify after every prompt that each nonnegative `host_res[i]` equals the cache's current `slot_of(layer,expert)`, every map slot is unique, every occupied cache slot has one owner, every temporarily lent entry has been restored, and a fresh device-map upload completed before the first decode/window read. The first decode and graph hit path must be checked after prefill, not only the prefill output.

Do not bypass or specially “lend q-zero slots”: those slots have no `host_res` owner and are naturally available in the tail buffer region. The loan is a contiguous cache tail used for prompt buffers, so it can straddle multiple layer quota ranges; its only valid exclusion list is the actual residents `host_res[i]>=first`. A later live cache policy update while the prompt path or any graph still references the old map/base is unsafe. Choose a fresh process for each baseline/candidate arm, freeze the quota before startup, and preserve the existing graph/cache address lifetime.

For the first arm, disable `STRATA_PREFILL_RELEASE_CACHE`, `--vram-elastic`, live hot resize, and `--no-prefill-borrow`; the latter changes prompt memory accounting and needs an independent reserve policy. If borrowing cannot fit the fixed 256K prompt buffers and leave the required floor, fail as infeasible rather than letting per-layer allocation hide a different cache size. If later support for release/rebuild or elastic segments is desired, its restore/reallocation path must reconstruct the quota ranges, ownership map and dependent graph pointers and repeat map verification before decode; current code's release callback updates cache bases, not quota plans.

## Minimal correctness checks before any live-policy run

A future opt-in patch should first test the cache primitive without model weights: exact prefix ranges cover `[0,128)`, range adjacency/no overlap, q0 empty ranges, q=128 concentrated in one layer, mixed quotas totaling 128, malformed vector lengths/negative/too-large/overflow/sum mismatch rejection, admissions stop independently at each layer limit, resident lookup idempotence, no global-fallback admission, close/reopen clears plan, and every resident slot maps to exactly one layer/expert. Add a generate-level synthetic profile fixture that proves original-profile per-layer prefix selection, q0 handling, and selection of the actual admitted verification probe. These are proposed tests, not run results.

Before loading a model, compare the config/profile hashes and geometry, exact rank uniqueness and capacity, quota sum 128, slot-byte uniformity, and projected total MAXBLOB bytes. Before graph setup, verify the host/device residency maps and slot ownership inverse. After prefill, verify all loans restored and re-uploaded and run the first decode against the unchanged baseline state/output gates. Keep baseline and candidate in fresh processes with identical binary (except candidate implementation), profile, prompt, pool task/workers, graph, KV, prefill chunk and machine settings.

## Remaining decision dependencies

A correct initializer only makes the chosen plan representable; it does not select a policy. Root's new whole-file train/validation input split is source-disjoint within one codebase, and the prior route pair A/B screen is near-copy. Before any live-policy patch or run, freeze the quota objective/profile/config using train only, then obtain exact prompt-specific baseline/reference and route receipts under the new prompts; validate on the separate prompt without retuning. R68 identifies that the existing controller is tied to 32K and the old four-request reference; the longer prompt requires a new reference first. Keep no generalization claim until this validation is completed.

The count DP is not a service-cost estimator: route counts `N`, `J`, `J1`, or `J2` remain separate objectives unless a measured weighting is predeclared. CPU native-hit service and GPU cache-hit service have different costs; pool/task/overlap phases and exact GPU grouped-kernel work still need calibration. The candidate can change later numerical routing, so a captured-trace replay is not live future coverage. Any performance or adoption decision still needs correctness/math, 256K prompt-to-decode lifecycle, faults/state/map restoration, and quiet paired end-to-end measurements. The 36,004/37,462 prompts do not exercise full 262,144-position capacity. No allocator, no-layer fill, pool, cache-hit, or end-to-end timing is established in this report.
