## Assessment

The core selection policy is sound for a bounded input-preparation helper: it has a fixed caller-predeclared manifest order, hashes every listed document before selection, chooses only the first complete-document prefix in `[32768,65536]`, inserts an explicit two-LF separator, and rejects an overlong complete prefix rather than truncating, padding, repeating or skipping content. It selects without validation scores, emits both rendered text and token IDs with hashes, and records source/document metadata. It rejects exact duplicate source IDs and document hashes across both splits. This is preparation infrastructure, not proof of independent statistical validation data.

Three concrete admission gaps should be resolved before root runs it on untrusted/caller-supplied files or calls an output “complete.” They are all source-level findings; I did not run the helper or fixture.

1. **A FIFO can defeat the stated time bound before the regular-file check.** `read_verified` opens the caller path using `O_RDONLY|O_NOFOLLOW` at lines 40–45 and only then checks `S_ISREG`. Opening a FIFO read-only can block before `fstat` executes; an input path naming a special device can also be opened before rejection. The current symlink fixture exercises `O_NOFOLLOW`, not FIFO/special-file behavior. Use a bounded/trusted input directory opened by directory FD and `openat` with no-follow/nonblocking flags for each component (or pre-vet paths plus an equivalent race-safe open); after opening, still require a regular owned file, single link and size/hash identity. Add a FIFO fixture that must fail promptly without waiting for a writer. The wall supervisor remains necessary for slow/network filesystems.
2. **Input byte caps are not a memory or execution-time cap.** `checked_ids` checks the list only after `encode(rendered)` has materialized the entire Python token list (`select_prompt`, lines 120–124). An 8 MiB text input can yield millions of Python integer/list elements before the `MAX_TOKENS` rejection. Runtime also parses vocabulary/merge/type assets into several Python containers and recomputes every full prefix, up to 64 times. The implementation note correctly says input caps are not RSS caps and delegates time/dependency budgets to a supervisor, but it gives no pinned supervisor limits or admission result. Root should run it as a child with explicit finite wall/CPU, address-space, file-size and descriptor limits, and record those values/exit status; for example, root can predeclare an environment-appropriate 1800-second wall limit, finite CPU limit, and a fixed RSS/AS ceiling after accounting for Python tokenizer overhead. If a future tokenizer interface can stop at `MAX_TOKENS+1`, use that; otherwise reject unbounded pre-check memory claims. On timeout or resource-limit termination, leave outputs ineligible.
3. **`record.json` can claim `completed:true` even when writing its final file fails.** `write_bundle` checks total bytes pre-mkdir, creates a private directory/files exclusively, fsyncs each file and writes `record.json` last (`:173–195`), while `prepare` sets `completed=True` before the write (`:220–223`). If the final record's `fsync` fails, its complete JSON bytes can already exist; if final `close` reports an error, the same can hold. The current injected writer failure test breaks on the first token file, so it proves only that this earlier failure leaves no record. It does not test record-write, record-fsync or close failure. A consumer must require successful child exit plus parseable record and reverified hashes for every listed output; the presence or `completed` field alone is insufficient. Add fault fixtures for failure on `record.json` write/fsync/close and assert the receipt cannot be admitted. If the file format is revised, make “prepared” an externally verified success condition instead of an assertion written before output completion. The code does not fsync the directory, and explicitly does not promise an atomic durable multi-file transaction; retain that limitation.

## Split independence and overlap semantics

Manifest source IDs and SHA-256 values are checked for equality duplicates only (`documents`, `:86–104`). Those checks catch repeated IDs and exact same-byte documents, but caller-declared `source_id`, `version` and `model_identity` do not prove separate acquisition, non-overlap, or authorship. A validation file can be an excerpt, continuation or paraphrase of a training source under a different ID/hash. The implementation note correctly says dataset provenance/content still needs owner review and that the helper's gate does not certify statistical independence. Keep this distinction in the downstream record: “distinct declared source IDs/hashes and passed structural near-overlap screen” is supported; “independent validation sample” requires separate source/task provenance review. Do not use the pair to claim population generality.

`overlap_gate` computes the set of unique contiguous 16-ID shingles for each final rendered prompt and rejects when shared unique shingles are at least 80% of the smaller set (`:130–142`). It also records the common-prefix length and positional matches. This is useful as a fixed structural near-copy filter, but the set discards multiplicity and sequence frequency: it can overreact to tiny overlap if one prompt has very few unique shingles, and it is not semantic/semantic-paraphrase detection. The exact metric and denominator must remain in the report; do not call it “80% token overlap” or a proof of independent sources.

R63's actual old A/B prompts had 32,719 common prefix token IDs and differed in only about 40 positions; they were near-duplicate workloads, not a proper independent validation pair. The new gate should reject that case due to shared 16-ID shingles, but the fake fixture does not encode that regression specifically. Add a bounded deterministic fixture with two 32,768-ID sequences sharing exactly the R63-style 32,719-token prefix and changing the remainder, and require rejection. Also test the exact unique-shingle threshold boundary (`shared*5 == denominator*4` rejects; immediately below it passes), the 16-token minimum/window endpoints, duplicate-heavy low-entropy sequences, and the reported common-prefix diagnostics. Keep these as synthetic gate-oracle tests; they do not require tokenizer assets or imply tokenization has been performed.

The current fake test verifies the 14-ID rendered/document-boundary oracle, first qualifying complete prefix and ignored tail in `select_prompt`, overage/insufficiency/bool ID, duplicate IDs/hashes, invalid UTF-8/budgets, generic overlap cases, duplicate JSON keys, symlink rejection and an earlier-file partial output failure. It deliberately does not import source modules or tokenize actual model assets, which is correct for unit-fixture independence. The label “unused tail” is true only for selection: `documents()` intentionally reads and hashes all tails before this step, and a new test should assert a malformed/hash-mismatched unused document is rejected before a selection can pass.

## Additional bounded-output details

- Per-document and total corpus caps are 2 MiB and 8 MiB; at most 64 docs per split; manifest 128 KiB; each tokenizer asset 32 MiB and aggregate 64 MiB; wrappers 4096 UTF-8 bytes; rendered prompt up to corpus cap + 16 KiB; each token list at most 65,536 after encoding; emitted bundle at most 32 MiB. These are finite serialized-input/output limits, not peak-memory or runtime ceilings.
- The source report says metadata strings are limited to 4096 UTF-8 bytes, but `documents` checks `len(entry[key]) <= 4096` in Unicode code points (`:93–95`), unlike wrapper byte length check (`:202`). The 128 KiB manifest still bounds aggregate input, so this is not unbounded; align the check to encoded UTF-8 bytes or correct the claim and add a multibyte boundary fixture.
- The output directory is mode 0700 and output files 0600, with `O_EXCL|O_NOFOLLOW`; path components above the new directory remain trusted caller input. The existing note already calls out parent-path trust. Keep the newly created output root under a caller-owned private parent and retain failed partial directories for owner review as designed; do not auto-clean.
- `record.json` includes source and asset hashes, manifest hash, tokenizer config, selection counts/IDs source metadata, output path/hash metadata and explicit non-inference/non-performance flags. Root should also preserve the parent supervisor's exact argv, source/output hashes, elapsed/wall time and exit status. Until actual exact-pack asset hashes and template compatibility are verified, fixtures are only fake tokenizer/renderer evidence. No actual model tokenization or qualification occurred.
