## Existing event lifetimes and safe query points

`ExpertTransferTimer` has three vectors (`copies`, `activations`, `device_residuals`) of records containing a `sycl::event`, byte count, and layer. With `STRATA_PREFILL_TRANSFER_TIMING` enabled, each transfer event is copied into its vector. The vectors retain all records until the timer is destroyed; `report()` queries them after queue waits. The expert-copy vector is written only by the issuer and read after joining it, as its source comment states. It has no chunk tag. Its memory use grows with the total number of events in the timed prefill; it is not a fixed ring.

`PfTimer` keeps reusable event and phase arrays. `mark()` reuses capacity, and `fold()` runs at a layer boundary after `m.cs->wait()`, queries adjacent marker ends, charges their time gap to the first mark's phase, and retains the last mark for the next segment. It does not retain explicit phase interval endpoints or kernel command events. Its marker arrays are bounded by the maximum marks between folds, unlike the transfer event vectors.

The streamed expert path enqueues memcpy on the in-order `m.copy` queue and then records a `copied[slot]` barrier event. Compute waits on that copied event before consuming the staged bytes. Compute records a `used[slot]` event after the last use; copy waits on it before slot reuse. These are correctness/lifetime edges and must remain unchanged. `copied` and `used` are fixed ring arrays allocated during prefill setup and reused; `Prefill::release()` waits on compute and copy queues before destroying them. The transfer timing vector retains independent references to memcpy events until report/timer destruction.

For the ordinary path, the final `run_impl` drain waits for `m.cs` and `m.copy`, then reports. Per-layer `m.cs->wait()`/`PfTimer::fold()` does not drain the copy queue. The issuer may still have copy work queued ahead for ring slots. The only unconditional copy-stream drain in ordinary `run_impl` is near function exit; per-step drains exist only behind diagnostic `STRATA_PF_STEP_SYNC`, and adding or enabling them would change the measured schedule. Therefore no ordinary per-layer point currently proves that every copy event in that layer is complete without waiting.

In layer-major mode there are existing queue drains around each layer's preload (`m.cs->wait(); m.copy->wait()`) and after each layer's `run_impl`; this can bound work for the layer-major-specific cache-load copies, but does not establish a general seam for ordinary streamed prefill copies. The layer-major transfer timer is shared across layers and reports only after the outer routine completes, so its existing vectors still retain all events until then.

## What the profiling specification guarantees

The normative SYCL 2020 revision 12 event-profiling text states that profiling descriptors return 64-bit nanosecond timestamps since an implementation-defined timebase and that all events sharing a backend are guaranteed to share that timebase. Thus on the recorded single-device Level Zero V2 backend, cross-queue timestamp differences/intersections are specification-supported. `command_start` and `command_end` describe action start/finish; start-query can block until running/complete, and end-query blocks until complete. There is no guaranteed timestamp accuracy. Profiling queries must be treated as fallible: they throw `errc::invalid` when the submitting queue was not created with `enable_profiling`; a backend can also report profiling unavailable/error.

The current V2 adapter source converts Level Zero device timestamps to nanoseconds and masks the raw timestamp using device valid bits. Its `adjustEndEventTimestamp` handles one counter wrap relative to start, and comments explicitly say multiple wraps are not reported correctly. The Level Zero programming guide likewise demonstrates `kernelTimestampValidBits` wrap handling. Current UR code is not a provenance proof for the installed 0.12 package, so a guarded query path and monotonicity checks remain necessary.

The source creates the prefill copy queue with profiling enabled when `STRATA_PREFILL_TRANSFER_TIMING` is present. The default Strata compute queue is created with profiling by the pinned queue helper. This makes memcpy events and compute marker events eligible for profiling in this mode, but it does not make queries infallible.

## Can current events produce a bounded exact overlap aggregate?

**Not for ordinary streamed prefill under all requested constraints.** The necessary timestamps do exist after the normal queue drain, but the transfer events are retained in the growing `copies` vector until then. Removing/recycling a transfer event earlier is not safe: the per-layer compute wait proves completion only for copies consumed by that point, and there is no host-side completion proof for all queued-ahead copies. Calling `command_end` early can block and become an added wait. Adding a copy-queue drain at each layer/chunk would add synchronization and change overlap. Capturing a timestamp requires an existing event whose lifetime has not been reused; the fixed `copied` ring events are reused and are barrier events, not the memcpy events themselves. So a strictly fixed-memory exact aggregate cannot be obtained from the currently available ordinary-path seams without relaxing one of those constraints.

The least intrusive *diagnostic-only* implementation, if parent later authorizes it, can avoid a second event list and avoid adding device work: reuse the already-retained `ExpertTransferTimer::copies` vector and the existing `PfTimer` marker events; retain only compact compute-window endpoints per phase/chunk (not event handles), then after the existing end-of-run drains query and aggregate, in place, over the existing copy vector. This does not grow the copy-event count beyond what the current transfer-timing mode already retains, but the underlying vector itself remains O(number of streamed expert copies). It therefore avoids *additional* full event-list growth, not the baseline list's growth. For a strict bound on total event storage, exact ordinary-path overlap is infeasible under the present no-extra-wait/no-extra-event constraints; this limitation must be stated, not hidden.

A separate layer-major-only aggregate could process each layer's already-drained cache-load copy events and discard those event records before proceeding, with no added drain. That measures the serial layer-load transfer window and is not a substitute for ordinary copy/compute overlap. Also, its current shared transfer vector includes callback/run_impl events, so safely narrowing that vector requires explicit ownership/tagging and must not destroy shared events still needed by the outer timer.

## Minimal aggregation algorithm and labels

If using the existing diagnostic event vector, keep per-event intervals transient (no second vector). After the already-required `m.cs` and `m.copy` waits have succeeded, query each expert-copy event's start/end inside a non-throwing diagnostic guard. Mark the entire overlap result invalid on any query failure, start/end reversal, impossible phase ordering, or counter-wrap ambiguity; omit/label invalid aggregate rather than print partial totals as valid. Do not query an incomplete event or use a failure as reason to wait per event. Do not call fatal logging/`exit()` from the query/error path. Preserve normal inference status/correctness behavior and report a separate diagnostic error flag.

For compact phase windows, snapshot the existing `PfTimer` boundary events' `command_end` endpoints before their event handles are reused by `fold()`. Each adjacent endpoint pair gives a half-open window `[t_i,t_{i+1})` labeled by the first mark's phase, matching its existing accounting. This interval includes all time between queue markers, including compute-queue waiting/idle gaps; call it a **compute-queue phase window**, never kernel busy time. There are no per-kernel start/end events in the current `PfTimer`, so kernel-active overlap cannot be claimed from this source seam.

For copy intervals `[s,e)` and phase windows `[a,b)`, use `max(0, min(e,b)-max(s,a))`. If reporting unique elapsed copy-time overlap, merge overlapping/touching copy intervals before intersecting so concurrent copy events are not double-counted. Since expert memcpy events are enqueued to one in-order copy queue, after a successful query their start/end intervals should follow queue order; still validate monotonicity. A generic robust implementation should merge by start (sort a reused in-place view/index if order is not guaranteed) and report both unique union-overlap and summed per-copy overlap under distinct names. Phase windows from consecutive compute markers are sequential; aggregate per phase label. An aggregate interval can be counted in multiple phase windows only at their shared endpoints, which contribute zero duration.

A chunk tag is not currently present in `ExpertTransferTimer::Copy`; the least extra scalar metadata is to record the current chunk index/position at issuance. Otherwise emit only per-layer or whole-request results and do not imply chunk attribution. Use checked `uint64_t` addition for bytes/counts/durations and a sticky `overflow_or_invalid` flag; never wrap silently.

## Physical 262,144-token storage bound

The exact model geometry and runtime chunk size determine the count, so no fixed byte number can be asserted from this source snapshot alone. For ordinary streamed execution, let `N=262144`, actual chunk sizes `T_j`, model layers `L`, and expert count `E`. Each streamed layer sequence contains at most one entry per expert, so the expert-copy event count is bounded by `L * E * ceil(N/T_min)` where `T_min=min(T_j)` for the actual run (and is usually lower due to resident/skipped experts). Current vector storage is therefore O(`L*E*ceil(N/T_min)`) event records; activation/device-residual records add O(`L*ceil(N/T_min)`) in the applicable paths. Vector capacity growth can exceed its size by allocator growth factor. This diagnostic already has that storage behavior today. An added timestamp interval vector would duplicate O(the same count) and is rejected. Compact phase windows are O(`phase_count * layer_count * chunk_count`) if retained for later intersection; because `PfTimer` already folds per layer and ordinary queue drains only at run end, truly bounded storage independent of total chunks requires accumulating windows/overlaps before old copy events can be discarded, which the current un-drained copy queue prevents. Report actual event count and peak vector capacity/bytes only if those are already available without new profiling or instrumented allocation queries; otherwise report formula and do not claim bounded peak bytes.

Thus the precise choice is: (a) reuse current diagnostic event list, add only compact phase boundaries, and state O(event-count) baseline storage; or (b) keep strict bounded storage and defer exact ordinary overlap until a safe natural completion seam exists that does not alter scheduling. Do not claim to satisfy strict bounded storage with option (a).
