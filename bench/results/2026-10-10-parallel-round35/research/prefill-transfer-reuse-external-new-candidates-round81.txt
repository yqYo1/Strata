## Ranked candidate

**Worth a gated prototype: chunkwise WY / delta-rule GDN prefill.** This is a new algorithmic seam, distinct from QSA attention tiling and MoE weight/dequant reuse. In this frozen SYCL source, `gdn_rec_kernel` updates each head's state in a `for (t=0; t<T; ++t)` loop, with five barriers per token in the body (lines 637 onward); ordinary dispatch selects the software-pipelined `gdn_rec_cols_pipe_kernel` by default when `STRATA_GDN_PIPELINE` is unset, then runs output normalization (around lines 2659–2747). That variant improves the recurrence's loads but retains token-serial state dependence. The head-tuned path is opt-in and limited to T>=256; its different mapping is not a chunkwise algebraic formulation. State/input/output semantics must be read from this exact implementation before porting.

FLA's implementation is a concrete external design: form chunk-local gates, build a WY representation by fused KKT + triangular solve + `w/u` recomputation, then process chunk summaries and the state handoff; chunk size is 16, 32 or 64. Its forward source explicitly describes the fused KKT/solve and the following WY / state kernels. This can replace O(T) sequential synchronization steps per head with parallel chunk-local work plus a scan/recurrence over T/C chunks. It does not eliminate the recurrence between chunks. The external API also includes q/k norm, beta sigmoid, grouped value heads, optional initial/final state and multiple gate modes; Strata's exact Qwen configuration is not interchangeable by name alone. See [FLA chunk orchestration](https://github.com/fla-org/flash-linear-attention/blob/main/fla/ops/gated_delta_rule/chunk.py) and [FLA fused KKT/solve kernel](https://github.com/fla-org/flash-linear-attention/blob/main/fla/ops/gated_delta_rule/chunk_fwd.py) (reviewed 2026-10-10; upstream `main`, not an immutable revision).

A useful independent implementation report is Prysmlabs' Qwen3.5 Gated DeltaNet Apple Silicon post. It describes a chunk size of 8, a triangular finite-series construction for chunk-local causality, then a chunk-level state recurrence. On an M4 Max and Qwen3.5 0.8B synthetic 4096-token prompt, it reports 1.54x end-to-end prefill versus its serial fallback and says GDN kernels account for 34% of its chunk GPU time. These are not Strata/B570 results and should not be used as a performance prediction. More relevant than the number is its explicit caution: reordered FP32 arithmetic can change logits enough to flip a near-tie, so its exact-serial path is retained for speculative verification. [Prysmlabs engineering post](https://www.prysmlabs.ai/blog/gated-deltanet-apple-silicon), dated 2026-07-21.

**Main risks / discriminator:** WY changes floating-point order and temporary representation. Exact output/state bit parity is not a reasonable assumption; measure output, final GDN state, logits, and repeated decode after long prefill against the serial path, with a separately stated tolerance and generated-token checks. Bound workspace at 32K and physical 262144 tokens, including partial final chunks and existing state lifetime; avoid storing all chunk-by-chunk SxS state unless its total allocation is proven acceptable. Chunk size must be tuned on target. Only proceed if phase attribution shows GDN recurrence is significant after ordinary path cost; run same prompt and environment, multiple repetitions, and report GDN kernel time plus end-to-end prefill. No speedup is established here.
