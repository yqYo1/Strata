Cause found in production source
read_expert_profile loads all n_ranked pairs into profile and checks format,
version, geometry, header count, truncated bytes and pair bounds. There is no
profile.resize to --expert-cache N here. The old generate.cpp comment describing
an explicit number as truncating the ranked list was misleading: the relevant
selection truncation occurred in the startup fill loop's want=min(profile.size,
cache.slots) and i<want limit. The full ranking remains available for learning,
refill and resident-complement consumers; multi-GPU alone partitions it by stage.

ExpertCache::admit rejects invalid IDs, an uninitialized per-layer cursor, a
filled individual layer range, or a full global cache. It returns an existing
slot for duplicate pairs. In per-layer mode, the filled-layer rejection is not
evidence that all cache slots are occupied. The old fill loop nevertheless
broke on that first rejection. Simply continuing would still examine only the
first want ranks and miss later high-ranked entries for other layers.

Implemented selection and termination
Only the startup primary-cache scan policy changes:
- Global: retain scan=want, the original hottest prefix, original admission,
  original break on admission refusal and no eviction. Valid unique profile
  input yields the same admitted pairs, slots and blob-size order as before.
- Per-layer: scan at most the whole loaded profile when want>0; continue past
  rejected pairs without requesting their blobs or copying them. Stop when
  prefilled reaches want, or when all scan ranks have been considered.
  Since ranking pairs are now unique and valid, every success is one newly
  occupied slot; each layer's first admitted pairs in rank order fill its own
  quota. Filling want slots early cannot leave a required slot unfilled when
  want is total capacity. Sparse rankings may exhaust before quotas fill and
  correctly leave unranked capacity empty.
- Zero available capacity performs no scan/copy. Each iteration advances once;
  no retry, reset, polling, eviction, fallback policy or unbounded search exists.
  The complete 48x512 ranking caps the selected case at 24576 admission checks
  and 144 successful H2D blob fills. This bound is source-derived, not measured.

Mapped-file advice remains optional; its window is clamped to scan. Bounds use
fill_ahead < scan-i before adding the offset, so huge STRATA_FILL_AHEAD values
cannot overflow the signed lookahead addition. No pointer can advise beyond the
ranking. This alters speculative file advice on the longer per-layer scan but
does not turn advice into a residency/copy success.

Invalid, duplicate and sparse profiles
Existing invalid-format/version/geometry/truncation/out-of-range refusals remain.
Added read-time refusal when n_ranked exceeds the model's pair count, before
rank/raw allocation. Added a byte-per-model-pair seen table and refusal naming
the repeated pair. Duplicate input is now explicitly invalid, rather than
inflating successful-copy counts and quota completion.

This also protects native global sized slots: sized_slots follows ranked layer
blob sizes, while admit returns an already-existing slot for a duplicate.
Accepting/refilling a duplicate and then admitting a later differently sized
layer could move that later blob into a slot sized for an earlier rank. Rejecting
duplicates preserves the size/rank relationship rather than skipping them after
slot sizing. tools/make_profile.py's production take() deduplicates pairs, and
rank_learned_profile ranks unique model indices. Neither writer/ranker/tool nor
the profile file is modified. Custom profiles containing repeated pairs that
previously loaded are a deliberate compatibility change and now fail clearly.

The added seen table is transient host memory: 24576 bytes for the selected
48x512 geometry, no new device memory. Accepted ranking length is bounded by the
model pair count; the existing raw/ranked allocations and cache memory sizing
are unchanged. Empty/sparse unique profiles remain accepted. Sparse fill logs
now use actual cache capacity as denominator instead of min(profile length,
capacity), avoiding a false fully-filled claim.

Verification and copy accounting
Track the rank and actual slot of the first successful checked blocking fill.
Verify that same pair/slot with its actual layer blob size after filling, rather
than assuming profile[0] must have been admitted. This matters for zero-quota
layers and for a first ranked pair belonging to a nonzero layer's slot range.
The verification source pointer is checked before verify_slot. No-filled-slot
cases do not dereference an invalid rank or falsely report verification.
The stderr line reports the real verified slot number (global usual slot 0), or
"no filled slot to verify". Existing full valid global runs still report slot 0.

prefilled and fill_bytes increment only after fill_slot_blocking succeeds;
quota-refused pairs perform no blob read/copy and contribute no successful count.
The duplicate reader guard makes copy/occupancy counts agree. A null blob or a
failed blocking copy/verification remains a nonzero error path; there is no
success-as-failure coercion. The source's transient fill_tmp is reused only after
the unchanged blocking copy's checked Runtime wait. No asynchronous fill was
introduced into startup.

Typed-size/all-caller review and unchanged safeguards
generate.cpp's native per-layer sized_slots uses q copies of each layer's own
blob in layer order, with 256-byte-aligned offsets; budget stays requested N
times max_blob, q is capped by experts per layer, and shrink_to rebuilds whole
layer lists. This explains requested 128 -> actual 144 without changing quota,
budget or bytes. open_sized recomputes the per-layer admission cursors after
allocating byte-sized backing storage, so returned slot indices match final
slot ranges/offsets. These sizing/admission methods are unchanged. Every selected
fill still passes expert_layout().blob_bytes(the actual pair's layer), so the
longer rank scan does not change a slot's layer/type ownership.
