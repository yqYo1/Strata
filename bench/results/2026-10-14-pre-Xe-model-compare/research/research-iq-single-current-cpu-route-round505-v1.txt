# R505 — current IQ NT1 native CPU route under STRATA_IQ_SINGLE_EXACT=1

Read-only component review for the current primary native expert CPU path, using the supplied canonical source/binary identity d3861dd5 (lifecycle build receipt) and the current source files matching its recorded pins. No build, test, Git mutation, GPU/profiler work, broad environment/log scan, or cleanup was performed. R500 was read for context; this report resolves the IQ NT1 route and does not repeat its broader decode ranking. The prohibited `prefill-gemm-only-contract-root-v1/record.json` was not read.

## Finding

`STRATA_IQ_SINGLE_EXACT=1` only changes one narrow case: gate/up native CPU jobs with exactly one token, on a CPU without AVX-512, when `STRATA_NO_IQ256` is absent, and only for GGML type IDs 18 (IQ3_XXS), 21 (IQ3_S), and 22 (IQ2_S). `native_expert.cpp` checks the opt-in and `iq256_single_gu_rows` returns false for other types. The accepted Ryzen 5 5600X has AVX2 and no AVX-512, so this is an eligible route for those types. Environment values are cached in function-local statics at first call; compare separate processes with the setting present at process start.

The single-token path does not dequantize weights to an FP32 matrix. It reads packed GGUF IQ blocks directly, paired with the already-quantized Q8_K activation row (`block_q8_K`, 256 values/block). The packed block sizes are IQ3_XXS 98 B, IQ3_S 110 B and IQ2_S 82 B per 256 weights. Per block it decodes codebook magnitudes/signs/scales, uses AVX2 integer `maddubs`/`madd` lanes, applies the FP16 block scale and Q8_K scale with FMA, and finishes with GGML's horizontal float reduction. It computes gate and up dots separately and writes `silu(gate) * up` to FP32 `ff`.

The fallback immediately below is `traits(f.gu_type)->vec_dot`, once per gate row and once per up row, with the same Q8_K activation, packed weight data, output expression and GGML CPU oracle. `iq_single_avx2.cpp` states that it preserves the original integer lanes, FMA order and horizontal reduction; its explicit implementations are adapted from GGML's AVX2 `iq3xxs_dot`, `iq3s_dot` and `iq2s_dot`. Thus “exact” names the reduction/parity contract; it is not a generic FP32-dequant path. The source test `tests/core/iq_single_exact_test.cpp` compares those three types bitwise to linked GGML `vec_dot` across four widths, seeded weights/activations, padded row strides and sub-row bounds. This review did not execute it.

When `nt >= mt_min` (default 2), the earlier dispatch selects the multi-token AVX2 implementation for supported types (subject to `STRATA_NO_IQ256`) before consulting `STRATA_IQ_SINGLE_EXACT`; this includes IQ2_XXS (16), IQ2_XS (17), IQ3_XXS (18), IQ3_S (21), IQ2_S (22), and IQ4_XS (23). At NT1, the exact helper supports only 18/21/22. IQ2_XXS, IQ2_XS, IQ4_XS and other formats fall through to GGML `vec_dot`. The helper is specifically gate/up; `native_down_rows` has independent format dispatch and is not selected by this flag.

## Shared activation quantization and compile/runtime gates

`expert_source.cpp` quantizes each input token once per layer before dispatching CPU expert jobs. For native IQ formats, it calls `native_quant_act`, which selects the activation type from GGML's `gu_type` traits and calls `from_float`; it then shares that activation buffer among the expert jobs for the token. `native_expert.cpp` currently has no special Q8_K AVX2 activation quantizer. The old `.tools/pre-xe-1eb-source-v1` had an AVX2 Q8_K branch in `native_quant_act` and `native_quant_h`; that is a separate shared per-token/per-layer component, not behavior specific to `STRATA_IQ_SINGLE_EXACT`. The NT1 route comparison should hold activation bytes fixed to isolate row-dot dispatch. Do not credit or reject the IQ flag based on the old quantizer without separate timing and byte-parity evidence.

CMake includes `native_expert.cpp`, `iq_avx2.cpp`, and `iq_single_avx2.cpp`. It assigns the latter two TU-local `-mavx2 -mfma -mf16c` on GCC/Clang (or `/arch:AVX2` on MSVC). `STRATA_CPU_ARCH`, if set, also supplies target-wide `-march/-mtune`. The exact helper implementation is compiled only under Clang with `__znver3__`; otherwise this TU defines a stub returning false. The source-level NT1 runtime gate is opt-in plus no `STRATA_NO_IQ256`, `!cpu512`, and `nt==1`; it does not itself call an AVX2 CPU probe. The stated 5600X is AVX2-safe. The permitted lifecycle receipt records source pins/size_t contract, not this stock process's per-TU compile command, so I do not assert the exact effective compiler command or that the helper was compiled into this particular binary solely from CMake defaults.

## Decision value for Main's one-factor comparison

A current-binary `STRATA_IQ_SINGLE_EXACT=1` versus `0` run is a useful isolated test only if the model actually has CPU misses in IQ3_XXS/IQ3_S/IQ2_S gate/up at NT1. It cannot test IQ2_XXS/IQ2_XS/IQ4_XS NT1, multi-token kernels, down projection, or activation quantization. If eligible calls are rare or absent, a null stock latency result says little about their per-call quality or speed. The reported MMQ1 3.4 versus MMQ0 2.8 tok/s and old separate CLI 16.6 tok/s do not identify this component; their workload/configuration and proposal/acceptance contexts differ as R500 records.

Minimal next checks, only when Main's active run is closed and Main authorizes CPU work:

1. Confirm per-layer counts for CPU-miss native jobs by `(gu_type, nt)` and whether the exact helper returns true; record timing for gate/up separately. First verify the stock binary's compile receipt/command includes the Clang `znver3` implementation and that each comparison starts a fresh process with the env set before first call.
2. For component correctness, reuse the existing bitwise GGML oracle over actual captured packed weights and activation bytes for the eligible `(type, n_embd, row stride)` shapes. Compare gate dot, up dot, post-SiLU product, and native expert down result / routed weighted output; check adjacent row canaries and non-finite values. Keep the existing synthetic test as coverage, but no need to claim full model text must match if all measured intermediates are bit-identical.
3. If broader numerical effects appear, compare representative layer routed output, post-residual tensor and next-token logits/logprobs on fixed inputs, then targeted task outputs. Record token IDs and greedy divergence as a symptom, not the only oracle. Separate the AVX2 activation-quantizer change from this flag and require byte equality before comparing it.
