## Existing queue and ownership contract

At src/prefill/prefill.cpp:665–700, stream is stored as m.cs (caller-owned compute queue). The SYCL branch currently aliases m.copy to it. CUDA/HIP instead create a private nonblocking copy stream. The compatibility adapter represents streams as sycl::queue*. Its cudaStreamCreateWithFlags calls Runtime::make_queue(true); this makes an additional in-order, profiling-enabled queue on the runtime's existing device/context, with the shared asynchronous error handler (runtime.cpp:78–88, compat.cpp:302–325). compat.cpp:queue() rejects any queue whose context differs from runtime device 0. Therefore a copy queue must be created through this shim; constructing an independent default SYCL queue would violate both context and sticky-error ownership.

Prefill::release() synchronizes cs and copy before destroying per-ring events and destroys copy only when it differs from cs (prefill.cpp:547–562). This already expresses the correct caller-owned versus internally-owned distinction for the single internal copy queue. Keep this order. Do not destroy the caller's queue. relayout() drains both queues before rewriting borrowed allocation layout (prefill.cpp:872–880); retain both drains.

Both runtime queues are in-order (runtime.cpp:68–85). SYCL 2020 specifies that in-order semantics order submissions only within that queue, with no ordering guarantee between queues. The current adapter's cudaMemcpyAsync submits queue.memcpy, cudaEventRecord submits a barrier and stores its returned sycl::event, and cudaStreamWaitEvent submits a barrier dependent on that event (compat.cpp:253–261,364–406). So the existing event pairs are the required cross-queue edges, not optional hints. SYCL event wait-list dependencies are part of queue::memcpy semantics; pointer/context rules for USM copies are in the spec's USM section. Sources: [SYCL 2020 spec, queue properties and queue::memcpy](https://registry.khronos.org/SYCL/specs/sycl-2020/html/sycl-2020.html), [Khronos SYCL queue reference](https://github.khronos.org/SYCL_Reference/iface/queue.html).

## Copy/data lifetime and exact event edges

There are two different resources with separate reuse protections:

- Device staging-ring slot. Each expert blob is copied into m.stage_dev[sl] on m.copy. Before overwriting a live slot, the issuer waits on m.used[m.used_of[sl]]; after queuing the DMA it records m.copied[sl]. Compute waits on the copied event before reading the blob. After compute/dequant/gather has enqueued its final read, it records used. The ordinary path does this in stage_one / compute and ring release_to (prefill.cpp:2376–2393,2460–2508,2541–2563). Threaded/stream-all has equivalent producer/consumer edges (1575–1593,1618–1640,2036–2057). MMQ group-gather deliberately records the used event on the last slot in the gather group and maps all group slots to it, after one copied-event wait on the group's last streamed copy (2415–2435). This last-event compression depends on ordered issuance on one in-order copy queue and on issuing the wait after the final event record is published.
- Host source/stager ring slot. For unpinned source blobs, Stager::wait() returns a pinned-or-pageable host staging buffer, the copy queue consumes it with cudaMemcpyAsync, and Stager::issued_one() records a per-buffer dma_done event on that same copy queue (Stager at prefill.cpp:212–343). A worker synchronizes that DMA event before reusing the host buffer on the next generation (280–286). This protection remains necessary even when m.copy == m.cs; same-queue ordering does not order the CPU worker's overwrite against a still-running DMA. finish() prevents more claims and waits for active host workers; StagerDone applies at layer/chunk early exits. Preserve issued_one() and its event.
- Direct pinned source blobs live in the source-owned arena; transient/unpinned blobs are first copied into the stager. End-of-run queue drains and release() keep both source and destination storage alive until copies finish. Do not move or free them earlier. Host pointers passed to SYCL handler::memcpy must remain valid through command completion; no pageable-pointer lifetime shortcut is justified here.

The copied / used event wrapper stores the latest event generation by replacing its optional event (compat.cpp:364–378). Host publish order is meaningful: producer records copied before publishing a_issued; consumer records used before give_back publishes a_consumed (prefill.cpp:1627–1640,2051–2057). Keep that order. Do not convert these barriers into host waits or remove them based on the old stall.

## Call sites and minimum safe opt-in

The actual SYCL copy_events calculation at prefill.cpp:1321–1328 currently also reads STRATA_SYCL_PREFILL_SAME_QUEUE; it sets copy_events = !same_queue || m.copy != m.cs. With current aliasing, the opt-in env can suppress the copied/used events. With an internally separated queue, the identity check forces them back on. This indirect environment override is unnecessary and easy to misread; use actual identity directly (copy_events = m.copy != m.cs) while preserving all copy/used records and waits for the separate-queue case. Same-queue mode can omit only device-slot cross-queue barriers because every copy and compute use is submitted on one in-order queue. It must never omit Stager::dma_done.

A minimal future implementation should:
1. Keep same-queue as the default. In the SYCL init branch, only for an explicit opt-in setting, call the existing cudaStreamCreateWithFlags(&m.copy, cudaStreamNonBlocking); otherwise keep m.copy = m.cs. Return init failure if opt-in queue creation fails; don't silently switch modes. This preserves the already observed B570/oneAPI 2026.1 two-queue ring stall as the default behavior.
2. Leave the CUDA/HIP branch, queue implementation and construction flags, the caller's m.cs, all runtime size_t launch-range guards/compiler flags, all host staging/DMA events, and all existing stage/compute slot barriers intact. No driver/compiler setting change is justified by this source audit.
3. Derive event need from actual queue identity, not a second same-queue env variable. With a separate queue, copied/used waits are mandatory at every listed producer/consumer path, including stream-all issuer, native streamed walk, skipped route entries, and MMQ gathered groups.
4. Keep shutdown/relayout/error drains. Normal completion already synchronizes both queues before returning (prefill.cpp:2702–2709). Error exits are scoped to an active StagerDone and IssuerJoin, but can leave submitted queue work outstanding; storage remains owned by Impl, and eventual release() drains both before destroying it. Do not add a cancellation return from a state that can leave a live separate-queue DMA without a later drain. The existing cooperative cancellation check only returns at a host-group boundary when m.copy == m.cs (2075–2078), so a separate-queue opt-in will not take that special return path.
5. Prefill itself contains no cudaStreamBeginCapture/graph construction. It queues direct copies/kernels and has host-side staging/issuer operations, so do not try to capture this schedule. Other graph-based paths are separate streams; preserve their existing MTP idle/wait boundaries. The runtime supports graph operations, but that does not imply the prefill host schedule is graph-capturable.

No specific correctness defect was found in the current same-queue implementation from these call sites. The concrete hazard in a separate-queue experiment is missing or elided cross-queue event edges, and the concrete lifecycle requirements are draining both queues before event/storage destruction. The compatibility implementation's cross-queue ext_oneapi_submit_barrier({event}) is the mechanism to retain; validate it with the selected oneAPI runtime before interpreting any speed result.

## First debug case before any speed claim

Use a single-threaded, deterministic streamed prefill with a chunk large enough to wrap the configured device staging ring and with unpinned experts, then compare default same-queue against opt-in separate queue on the exact same source/build/input. Ensure routing includes both experts gathered in one MMQ group and ring entries skipped by the route; those exercise the group-last used_of edge and skip-release edge. Start with a small prompt that wraps the ring several times, run the same prompt twice in one session, and force one early error/cancel after at least one copy has been submitted, then destroy/reset the Prefill. Record output/residual parity and asynchronous runtime errors; the main early-error criterion is that reset/release waits for queued copy work and never frees a staging buffer first. Do not begin with stream-all threaded issue plus performance timing, which mixes additional host races with the new queue mode. After this case passes, debug the stream-all issuer as its own mode; only then measure speed. The historical two-queue stall remains unresolved in root cause, so passing lifetime checks is not performance approval.

## Primary-source contract checked

The official Khronos SYCL 2020 spec says queue::memcpy returns an event for the submitted command and accepts dependency events; an in-order queue orders its own submissions only, not submissions on another queue. The same spec constrains USM allocations to the queue context. These establish why a shared context and explicit event edges are needed; they do not establish that the Intel driver will deliver useful copy/compute overlap. No Level Zero-specific assumption was needed.
