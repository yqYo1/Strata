## Exact change and diagnostics

The single modified code block is SYCL Prefill::init's queue choice. Absent flag remains `m.copy=m.cs`. Only exact `STRATA_SYCL_PREFILL_SEPARATE_COPY=1` calls `cudaStreamCreateWithFlags` through the current compat shim. A non-exact value (including 0, 2, 01, empty) keeps same queue and prints the decline reason. Exact-1 creation failure prints `mode=failed`, returns false with an error, and never reports successful same-queue fallback. Successful opt-in prints `mode=separate`, compute/copy pointer identities and `cross-queue-events=required`. Diagnostics appear only when this flag is present. A null compute pointer means the adapter's default runtime stream, not an independently allocated null queue.

No precision, tensor layout, GEMM, expert dispatch, CPU, attention, decode, model-loading, server, graph, launch flags, runtime/driver configuration, copy-event expression or host staging code is changed. CUDA/HIP branches remain byte-identical. Defaults retain the documented B570/oneAPI2026.1 same-queue workaround because realistic two-queue ring stalls remain unresolved.

## Constructor and ownership proof

`src/sycl/compat.cpp:302–314` uses unique_ptr to construct a queue from Runtime::make_queue(true), inserts it in its owned-stream registry, then assigns the output pointer. `src/sycl/runtime.cpp:78–88` constructs on the runtime's existing context/device with in_order and profiling properties and the shared asynchronous error handler. compat queue lookup validates the runtime context. A default independent sycl::queue would violate this contract; this patch never constructs one directly.

The candidate uses a local null `private_copy`. Before success, m.copy aliases caller-owned m.cs. The shim publishes an output pointer only after registration; construction or insertion failure unwinds unique_ptr and returns an error through attempt. No partially constructed private queue is exposed to Impl and no caller queue is destroyed. On success, m.copy owns the registered private queue through Impl's existing copy!=cs convention. Any later init allocation/event/stager failure remains terminal for this instance, with reset/destruction required as the public Prefill API already documents. release drains cs and copy before events and owned allocation release, and calls cudaStreamDestroy only for nonnull copy!=cs. Thus normal partial-allocation failure has the same owned-queue retirement as ordinary shutdown.

This proof is not a claim that the existing release can recover from every poisoned asynchronous queue: compat destroy waits_and_throw before registry erase, and release already ignores adapter error returns. A failed async drain remains a fatal/error case to record, not proof that storage is reusable or the registry is empty. This patch does not alter or conceal that existing error contract. Repeated init without reset is outside the documented API; it must not be used as a failure-retry mechanism.

## Required device and host lifetime edges

For actual separate queue, `m.copy != m.cs` makes copy_events true regardless of STRATA_SYCL_PREFILL_SAME_QUEUE. Same-queue/default retains the original expression exactly; a debug request can retain the extra device barriers. In-order queues order only their own submissions. compat memcpy is queued on the selected queue; EventRecord submits a barrier and captures its sycl::event; StreamWaitEvent submits a barrier dependent on that captured event. All existing callsites remain intact:

| Route | DMA admission and ready edge | Final blob-read/slot-retirement edge |
| --- | --- | --- |
| Routed ordinary path | stage_one waits on used[used_of[sl]] before overwrite; queues DMA and records copied[sl]. Consumer waits copied before compute. | Native MMQ records used after gather; FP16 fallback records used after dequant's final blob read. Blob may be reused before GEMM because GEMM reads dequant/group buffers, not original staged blob. |
| Stream-all inline issuer | issue_until uses the same overwrite wait, DMA and copied record on one in-order copy queue. | Consumer records used after actual read and give_back releases capacity only after that submission; inline issue_until then advances. |
| Stream-all threaded issuer, routed entries | Producer records copied then publishes a_issued with release; wait_issued acquire precedes reading that generation's copied event. | Consumer records used/used_of then give_back publishes a_consumed release; producer's capacity check acquire precedes reuse. |
| MMQ group gather | Each routed streamed entry calls wait_issued; flush waits only the group's last copied event. Ordered DMA submission makes that event cover all earlier group copies. | Flush records one used event on the last slot after all group source reads and maps every group slot's used_of to it. Capacity publication follows flush. Fallback scalar gather still uses the same last-event edge. |
| Native fused stream-all batches | wait_issued(k-1) precedes last copied wait; one in-order copy queue covers earlier batch copies. | Events for each streamed slot follow experts_native/experts submission, then capacity is given back. |
| Skipped route entries | No compute reads this entry's blob; any open MMQ group is flushed first. Copy queue's ordered DMAs protect copy-versus-copy overwrite order even if this skipped DMA is still running. | release_to records used/self mapping and gives capacity back. This preserves the current intended no-reader skip release, subject to the host-generation caveat below. |

Host Stager is a separate lifetime resource. Unpinned/transient source blobs are copied into its host ring; every submitted DMA is followed by issued_one(job,m.copy), which records dma_done on that **same** copy queue, then release-publishes the issued index. The worker acquire-waits for the previous generation and cudaEventSynchronizes dma_done before overwriting host buffer. This remains mandatory even on same queue because a CPU worker is outside GPU ordering. The patch neither removes these host events nor substitutes device used events for them. Direct pinned source storage remains source-owned through the copy/drain lifetime. Resident experts bypass device copy slots and retain original source/cache leases. Dequant and grouped-buffer leases and offsets remain unchanged.

## Important proof limit: threaded skipped entries

A narrow init-only patch retains every structural fence, but **a complete race-free proof of every existing threaded skip path is not established**. Current release_to (`src/prefill/prefill.cpp:2540–2549`) does not call wait_issued(k) before recording used and writing non-atomic used_of[sl]. The threaded issuer reads used_of[sl] when stage_live[sl] is already true. On a repeated chunk/session with live slots retained from a prior group-gather mapping, a skipped entry can be released before its current DMA/copy-event generation is published. No device kernel reads that skipped blob, so in-order DMA serializes its overwrite; that establishes device byte-liveness only. It does not by itself establish a C++ happens-before relation between this skip's non-atomic used_of write and the producer's read of the prior slot mapping. In the routed path, wait_issued provides that relation; in the skipped path it is absent.

R502 discusses host publish order but does not close this skipped-entry host-generation case. Do not label all threaded/skip behavior proved from this source review. The proposed init-only opt-in is exercisable in the existing inline issuer route (`STRATA_PREFILL_ISSUER=0`), with all device/host fences preserved, so this is not an always-declined proposal. Main must resolve or bound the threaded skip generation question in source before accepting threaded reuse safety; tests alone cannot prove absence of a C++ data race. Any necessary host-handshake fix would be a separately reviewed scope extension, not silently bundled here. This report flags the gap rather than changing the required narrow patch. The historical two-queue stall remains independent and unresolved.

## Finish, errors, relayout, split and graph boundaries

Normal run completion retains compute drain then copy drain (`prefill.cpp:2702–2709`), so later requests cannot use storage while copies remain outstanding. Borrowed relayout retains both drains before recarving storage. release retains drain-before-event/storage-destruction and destroys only owned copy queue. Chunk StagerDone and IssuerJoin retain their finish/join contracts. Returned early errors may leave submitted GPU work; use the existing terminal caller/reset/destruction boundary, never reuse source/borrowed slots as though an error proved DMA completion. The special cooperative cancellation boundary at line2077 is intentionally restricted to m.copy==m.cs; separate opt-in will not take that fast cancellation path. Test its actual supported error boundary rather than claiming this same-queue cancellation branch was exercised in separate mode.

Layer split's handoff sync, next_run lifetime, per-instance compute ownership and separate private copy queues remain original. No source pointers cross to a foreign-context new queue. Main must still exercise each configured split stage with actual tail/chunk/handoff shape; an ordinary unsplit test does not certify split ownership.

Prefill constructs no captured graph: its host issuer/Stager/direct submission schedule must remain outside graph capture. Existing MTP/graph idle/wait and cache/session retirement boundaries are unchanged. Do not infer prefill graph support from Runtime graph capabilities or capture the new private queue. Source DMA leases, skipped entries, event generations and grouped-last compression remain original, as do size_t guards/compiler flags.

## Combination with HC and compact FP16 MoE proposals

The queue patch hunk is confined to init's existing queue block. HC proposal changes helpers/carve/bytes_needed/Impl field; MoE proposal changes helpers/expert scratch shapes and gathers. They are semantically independent and have distinct source contexts, so all three can be combined without transplanting a whole source file. Neither proposal is applied here. Reconcile line offsets/context normally, pin derived combined hashes, and retain copy_events expression and all source lease events unchanged.

HC supported route remains GR_UNFUSED=1, no MMQ, BF16X2=0, no DBG_NAN and its exact independent flag. Its base and phase aliases rely on **compute** queue ordering; separate queue transfers expert blobs only into original staging slots, with copied/used ordering before dequant. FP16 compact's per-expert Xs/GU/Hh scratch reuse also remains compute-ordered; Down writes full original Dm offsets, and stage used after dequant still protects the original source blob. MMQ/fused adoption is not part of combining HC/FP16 fallback options. The threaded skip proof gap applies to applicable stream-all routes independently of these tensor-layout options. Four-way HC/MoE comparisons and same/separate queue comparisons must remain separate factors with matched settings.
