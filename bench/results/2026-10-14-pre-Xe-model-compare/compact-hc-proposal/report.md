## Aliases and live spans

The only base alias is `emb == mixed == bo`, each capacity allocatedT*N floats, outside the phase region. R, grs, inj, mixed_bf, mixed_h and steps stay distinct. HC `xn`, `xn16`, `lo`, `lo16`, `gated` are carved as **distinct spans** within the phase region; that entire HC set overlaps existing GDN/QSA/MoE scratch only across phases. No HC kernel receives overlapping live input/output spans. No xn/R alias, no gated/xn alias and no in-place normalization is introduced. Xs/GU/Hh, Dm, shared scratch, selections, QSA q/attn and all GDN buffer shapes/takes stay untouched.

Embedding writes image then gr_broadcast consumes it into distinct R. That finishes in the compute queue before the first HC mix writes image; PLE embedding has its own unchanged allocation. For hand-in, embedding is skipped and R is the original hand-in residual. HC pre reads persistent R, writes normalized xn and xn16 distinct within the HC set; down reads xn16 and writes lo; silu reads lo and writes lo16; up reads lo16 and writes gated; inject reads xn16 and writes persistent inj. gr_mix reads xn/gated and writes base image plus distinct mixed_bf/mixed_h. All five HC temporaries are dead at this boundary.

GDN reads mixed_h/mixed_bf for its projections; none reads base FP32 mixed, and final output projection reads its y_h and writes base image bo. QSA projections similarly read mixed_h/mixed_bf, compute all independent QSA tensors, then output projection reads attn_h and writes base image bo. With all MMQ disabled, MoE routing/shared projections and full gather read mixed_bf/mixed_h. Subsequent expert compute reads original Xs/Hh and writes Dm; combine reads Dm/shared/sg/slot/w and writes base bo. No base image reader remains when these writes begin. The FP32 mixed quantization and peer-copy routes are behind MMQ/fused eligibility and remain excluded by all-layer fallback. No expert-source or dequant ring lease is changed.

HC post gr_write reads bo[N*actualT] and inj[HC*actualT], updates R[D*actualT], with no overlap among these operands. `STRATA_GR_UNFUSED=1` makes `fuse=false` in current post dispatch, so no next xn16 is written early and carried across another phase. The next HC pre norm is freshly enqueued after residual write/control-vector application and any PLE operation. Existing SYCL postops `norm` launches actualT*HC workgroups of 256 lanes, each normalized row reading only R[row*N .. +(N-1)] and writing xn/hi in separate spans; mix uses actualT*N element operations and reads four xn/gated components before writing separate image. Their validate_spans checks continue to apply. No cross-workgroup in-place read/write race is admitted.

## Current matrix attention safety

Old scalar-only admission was necessary for old additional attention aliases and layouts. This patch deliberately does not transplant the old q/output or GDN/MoE input aliases. Current QSA carving remains `Kc, Vc, Qf, q, idx_raw, q_idx, attn, attn_h, sel_ids, sel_scores, attn_scratch` in its original order. In particular q and attn are separate takes with full allocatedT*ZV float capacity and allocator padding. HC set is dead before QSA projections start, while base bo is outside the phase region. Thus current prompt matrix attention remains admissible without changing its numerical route or forcing OLD attention.

Read/write proof from `src/kernels/sycl/prompt_attention.cpp:67–113,265–287`: launch uses queries*n_head_kv workgroups. Group `(batch, kvhead)` reads query at `(batch*n_head+kvhead*HEADS)*HD` through HEADS*HD elements (max reduction and qhi/qlo setup). Its final direct output writes `(batch*n_head+kvhead*HEADS+head)*HD+dimension`; indirect output stores through its local final buffer then copies to the same output geometry. Other workgroups can execute concurrently, but every global query address belongs to q, every output address to attn, and their allocated byte spans are disjoint. No group can overwrite a not-yet-read query. After attention, FWHT/gate_attn use original attn/Qf spans and distinct attn_h. Native output projection consumes attn_h into external bo; it does not overwrite QSA region. Scalar fallback also keeps query/merge output distinct. This argument does **not** claim old q==attn alias is safe on this matrix implementation; such an alias is outside the proposal.

## Count, carve, capacity and tails

Let `A(n,b) = align256(n*b + 256)`, matching Alloc::take's extra padding. Shared `take_hc_base` drives compact bytes_needed and actual carve. Shared `take_hc_phase` drives HC phase count and carve. Init calls carve; borrowed relayout retains its existing compute/copy fences then calls the same carve, so it inherits these shapes. Admission must be fixed during allocation/session lifetime; concurrent environment changes are unsupported as with existing process-static configuration.

For allocated T:

* H(T) = 2*A(T*D,4) + A(T*D,2) + A(T*LR,4) + A(T*LR,2).
* B(T) = A(T*N,4) + A(T*D,4) + 2*A(T*HC,4) + 2*A(T*N,2) + A(T*kStepCount,4).
* W(T) = max(existing GDN set, existing QSA set including selection/attention batch scratch, existing MoE set).
* New region = max(H(T), W(T)); all remaining arena takes, owned slots, GEMM scratch/workspace, host/KV staging and slack remain original.
* Against actual old carve at the same GR_UNFUSED=1/BF16X2=0 route, base reduction is H(T) + 2*A(T*N,4); region growth is max(0,H(T)-W(T)). Net requested arena reduction is their difference, including outer region padding.

HC payload is `(10*D+6*LR)*T = 104320*T` bytes. At T=4096 it is 407.5 MiB plus five allocator pads; at T=8192 it is 815 MiB plus pads. Two removed float N images contribute 80/160 MiB payload respectively. If W already dominates H, the combined payload reduction is 487.5/975 MiB; otherwise HC's excess enlarges region and reduces savings. These are source-derived byte formulas, **not measurements or allocator-admission claims**. Main must record the effective maximum and full arena bytes. The unpatched default bytes_needed has an existing conservative xn take and differs from actual carve's grs inclusion; this proposal preserves that default sequence. Compact base/HC sequences are shared and exact; unrelated pre-existing conservative differences (e.g. sizing with fused_layout(T,true)) remain unchanged and are declined here by no MMQ.

All active kernels still receive actualT = min(allocated chunk, remaining input), using original compact-independent row strides N/D/LR. Region helper allocates using allocatedT; actualT=1, odd tails and actualT<allocatedT therefore touch only prefixes of their separate spans. No padding or stale rows enter normalizations/GEMMs/combines. Runtime bound/span validators, QSA selection capacity, checked_count and size_t launch arithmetic remain unchanged. Source mathematics alone does not certify the BLAS implementation's private vector accesses; preserve current guards and verify tails in Main's runtime lane.
