## Decision

The primary tree retains its own prefill scheduler, per-format SYCL dispatch, CPU expert service, decode state/cache and queue/lifetime contracts. No Xe whole-engine replacement is present in this source path. Xe layer-major and bulk-upload remain donor candidates only, not adopted. The current dirty native Q2 exp compatibility change is locally bounded by an explicit runtime opt-in and a strict all-experts format/shape gate; it does not switch the ordinary default cache-hit arithmetic. Its fallback is standard `sycl::exp` when the selected compiler lacks Intel HA exp, which is a numerical change inside that opt-in route and still needs exact activation-code/scale and fixed-history model qualification. Small runtime/compat GPU success does not qualify a model, numerical parity or performance. A fresh primary model throughput baseline remains absent from the evidence reviewed here.

## Dirty Q2 exp fallback and model-format boundary

At current dirty `cmake/sycl_backend.cmake:8-25`, configuration compile-probes the selected SYCL compiler/header set for a device-callable `sycl::ext::intel::math::ha::exp` expression with `-fsycl -fno-fast-math -ffp-contract=off`; it defines `STRATA_SYCL_HAS_INTEL_HA_EXP` for `src/kernels/sycl/native_q2.cpp`. On API absence, the kernel compiles standard `sycl::exp`; the math API and accuracy contract differ. The code preserves `fdiv_rn`, FP32 operation order and non-fast-math/contraction constraints. Current dirty `src/kernels/sycl/native_q2.cpp` SHA-256 is `5a91138f3d01654d3174d6c505723687528d99c587bca2826c8cf473375d2347`; `cmake/sycl_backend.cmake` SHA-256 is `2c9c912fdc5eace61a97c656d4b66a40f6d43dd790de6990c3bd693fee58cfa9`.

This is a compile-time fallback in a single kernel, but the route is separately opt-in at runtime: `src/program/generate.cpp:298,1335,2008-2017,3389` sets `expert_cache_cpu_order` only from `--expert-cache-cpu-order`, validates `--spec 0`, SYCL, AVX2/non-AVX512, and requires every expert format entry to be GU Q2_0, Down Q2_0, `n_embd=2560`, `n_ff=640`. It then sets `Drive::hit_cpu_order`. At `src/core/expert_source.cpp:2366-2377`, only that flag chooses the Q2 CPU-order quantizer and `native_q2_expert_cpu_order`; ordinary native hits take `quantize_q8_1_rows` then `native_expert_grouped` (`:2383 onward`). Thus the fallback cannot silently affect mixed-format expert models through this CLI option: those are rejected before the route is activated. Other routes in `native_q2.cpp` are not changed by the conditional expression, and the ordinary default Q8_1 hit path remains unchanged.

The fallback still changes intermediate FP32 SwiGLU values relative to HA exp and can cross Q8 activation rounding boundaries. `tests/sycl/native_single_dispatch.cpp:75-105` checks standalone quantizer codes/scales exactly, while `:108-204,261-273` exercises integrated CPU-order hits with output tolerance; it does not compare exact SwiGLU-produced activation codes/scales against an HA control. R454 recommends a fixed input comparison of block scales, every activation code and stored sum, then Down output and fixed-history logits/state. No such run was performed here. Standard-exp correctness, token parity and any speed benefit remain **unqualified**. The default non-CPU-order route remains **unaffected by this dirty fallback** by source inspection.
