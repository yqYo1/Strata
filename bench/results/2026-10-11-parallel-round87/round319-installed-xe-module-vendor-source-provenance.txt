Status: read-only provenance investigation for the installed `7.0.0-38-generic` module files. No live kernel/module, process, sysfs, GPU, or device-status query was run. This report does not prove which module image is currently loaded and does not authorize another probe.

## Vendor package lineage

The installed package's local Debian changelog is `/usr/share/doc/linux-modules-7.0.0-38-generic/changelog.Debian.gz`. Its leading entry is `linux-hwe-7.0 (7.0.0-38.38~24.04.4) noble`; the changelog describes the module packaging/repackaging transition and records Ubuntu's nested `linux (7.0.0-38.38)` source changes. Among those changes are Xe-specific fixes (including job-timeout handling for unstarted jobs and kernel queues, GuC queue teardown/ref-lifetime work, and Xe suspend-fence handling). This is direct evidence the distro source package carries a vendor change history; it is not enough to identify the exact final source tree or prove which listed change is in this `.ko`.

The Ubuntu source-package record for noble publishes `linux-hwe-7.0` version `7.0.0-38.38~24.04.4`, with VCS `https://git.launchpad.net/~ubuntu-kernel/ubuntu/+source/linux/+git/noble`, branch `hwe-7.0`. The source record's archive checksums are orig tar MD5 `415e5d4ee110d9415c2901751e6f9c9d`, `diff.gz` MD5 `dcc710163304a01a8570ee1f0de8b66d`, and `.dsc` MD5 `32a5c0f817b6d1c1c53512bf77a7662f`. The corresponding Ubuntu package listing is [linux-hwe-7.0 in noble-updates](https://packages.ubuntu.com/source/noble-updates/kernel/linux-hwe-7.0). The source record and changelog establish vendor package lineage and version, but do not supply the exact source commit-to-binary mapping. The Launchpad Git/API content could not be inspected through the available read-only web access; the source tarball and diff were deliberately not fetched.

## Remaining finite gap and disposition

The exact gap is the mapping from the installed ELF (hash/build ID/srcversion above) to the Ubuntu source commit plus complete patch set and build recipe that produced it. The local package manifest and vendor changelog do not close that mapping. The installed-file identity also does not prove that this file is the image currently resident in the kernel; checking that would require a live module/kernel query, which was outside this investigation's scope. Therefore R317's upstream interpretation remains qualified and should not be upgraded to an installed-source attribution.

R319 closes the local installed-package/file identity portion of the provenance gap, but not exact vendor source-to-binary provenance or active-image identity. No device conclusion, fault cause, or probe admission follows from this evidence.
