# R318 — Stager final DMA and host-buffer free ordering

## Finding

The staging-buffer concern depends on the engine's allocator and release order; it is not a universal defect in both callers.

- **D caller:** final staging DMA is drained before `Stager` is destroyed. `Prefill::release()` first waits `cs` and `copy` with `wait_and_throw()`, then resets the stager. `Stager::~Stager()` calls `finish()`, joins its host workers, and frees pinned host-USM buffers. The queue wait is essential: `Stager::finish()` only stops/joins host staging work; it does not wait for the last DMA event. D's ordinary run also waits the copy queue at its end and each layer's staging paths have their own completion points, but release still provides the final teardown drain.
- **Pristine Xe:** the initially suspected teardown gap is narrower than R315 stated. `Prefill::release()` does reset the stager before its explicit stream syncs. However, when at least one Stager ring buffer is pinned, `Stager::~Stager()` frees it with `strata::gpu::free`; that wrapper calls `Runtime::free`, which drains all runtime queues before `sycl::free`. That implicit drain also protects the pageable ring entries in a mixed ring. A possible free-before-final-DMA hazard remains only when **all** Stager buffers use the pageable `std::vector` fallback: then no `gpu::free` runs, and the vectors are destroyed before the later copy-stream sync.
- **V8 is outside the risk path:** V8's `STRATA_ARENA_HOST_USM=1` streamed entries are pinned arena blobs with `job < 0`, so active H2D sources are the longer-lived expert arena, not Stager's pinned or pageable host buffers. Stager jobs are empty for that source path. This teardown observation does not explain V8's second-chunk fault.

## SYCL guarantees and context limits

The official [Khronos SYCL 2020 revision 12 specification](https://registry.khronos.org/SYCL/specs/sycl-2020/html/sycl-2020.html) states that a host USM allocation is allocated against a context, and queue operations using it must use that same context (§4.8.2). It also gives `sycl::free(ptr, queue)` as equivalent to freeing with `queue.get_context()` and explicitly says it does not enqueue a device free or act as a queue wait (§4.8.3.6). Most directly, `sycl::free` has the precondition that no in-progress or enqueued command is using the pointer; blocking/nonblocking behavior of free is unspecified, and applications must not rely on free to synchronize (§4.8.3.6, lines 12076–12096).

The same specification says `queue::wait` / `queue::wait_and_throw` block until all previously submitted commands on that queue have completed; `wait_and_throw` also passes unconsumed asynchronous errors to the queue/context handler (§4.6.5). Queue construction or the `in_order` property supplies ordering within a queue, not between independent queues. Therefore a CPU worker's `finish()` is not a substitute for draining the exact copy queue whose commands read the host buffer. Nor is `sycl::free(ptr, queue)` itself such a drain.

Xe has an additional engine-level guarantee beyond the SYCL free overload: its own `gpu::free` first drains the entire owning runtime. D's plain `sycl::free` does not; D relies on its prior explicit queue waits.

## Minimal safe shutdown order

The shutdown must first make the set of possible submitters finite, then wait for all host-side staging to stop, then drain the copy queue, and only then destroy/free the host source buffers. A practical order for an explicit close/reset path is:

1. Stop accepting new run/reset work; join the current issuer and any successor/pipeline host threads so none can enqueue another copy.
2. Call `Stager::finish()` to stop claims and wait for active host copy/read workers. Do not hold a mutex that those workers need while waiting.
3. Drain `m.copy` after no producer can submit more work. Use `wait_and_throw()` or the runtime's checked queue-drain equivalent, not `free()` as synchronization. Also drain the compute queue before freeing device destinations or dependent shared allocations.
4. Preserve any synchronous/asynchronous failure in an explicit error result. Continue freeing only after the wait has returned, since completion has then been established. If a destructor cannot return an error, log/store it through a non-throwing error path rather than dropping it; keep an explicit close/reset API able to report it. If the driver wait never completes, do not free memory that may still be in use; invoke the engine's fatal/timeout policy.
5. Destroy event wrappers and free pinned USM buffers / pageable vectors; then destroy queues and other destinations.

This order avoids a worker deadlock: queue submission must be stopped before draining; `finish()` must be allowed to signal/await workers before any resource they read is freed; the main thread does not wait for a queue while an unjoined host producer can still be blocked waiting for another staging job. A queue completion error is retained and reported, not treated as successful retirement. D's existing release already drains both queues before freeing Stager memory; Xe needs an explicit pre-reset drain only on the all-pageable branch if preserving its per-buffer `gpu::free` behavior, or, more simply, move/perform a checked copy-queue drain after producer/worker quiescence and before `stager.reset()`.
