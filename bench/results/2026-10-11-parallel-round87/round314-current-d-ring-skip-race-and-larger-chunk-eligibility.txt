# R314 — current D ring, skipped-entry synchronization, and larger-chunk eligibility

Date: 2026-10-11 (Asia/Tokyo). Read-only source/provenance audit. No GPU/process query, test, build, inference, Git operation, cleanup, or source edit was performed. Only this report was written.

## Finding

The D caller has the same **conditional same-chunk skip-entry synchronization gap** identified in Xe R311, in its threaded stream-all route. In D, the streamed-list consumer's `release_to()` skips an entry by recording its `m.used[sl]` event and writing `m.used_of[sl]`, then increments `consumed` and calls `give_back()`. That skip path does not call `wait_issued(k)`. The stream issuer can read `m.stage_live[sl]`, `m.used_of[sl]`, and the associated `m.used[...]` event while trying to publish/reuse that slot. A later `a_consumed.store(release)` cannot order an issuer access that already passed its ring-window load/acquire. If the slot is live and the accesses overlap, this leaves a potential C++ race on plain `used_of` and the event object's host metadata. As in R311, this is a conditional source finding; it does not establish a skip or a race in a particular execution.

This risk is **not eligible in the 81375 clean64K run**. Its exact recorded environment has `STRATA_PREFILL_RING=8`, and D defines `STAGE=8`. `ring_slots(T)` returns `STAGE` immediately when the explicit ring environment parses to 8. The stream-all predicate later requires `m.ring > STAGE`, `T >= stream_all_min()`, and `m.src != nullptr`; with the actual ring equal to 8, the first condition is false even though `T=8192` is above the default `stream_all_min()=1024` and the model source is available. Thus this run takes routed-only staging. `STRATA_PREFILL_COMPACT=2` has no effect on that ring decision. The record does not set `STRATA_PREFILL_STREAM_ALL` or `STRATA_PREFILL_ISSUER`; their defaults do not overcome the explicit ring-8 early return.

Maintaining the explicit `STRATA_PREFILL_RING=8` for a future effective 16K chunk still forces `m.ring=8` and keeps stream-all off. Merely increasing `T` cannot cross the `m.ring > 8` gate. If “scheduled ring 8” instead means `Prefill::set_ring_override(8)` with `STRATA_PREFILL_RING` absent, it is a different source path: `ring_slots()` does not take the explicit-env early return, and a chunk at/above the threshold can be promoted to `max(16,r)` **only if** `stream_all_ok` is true. That requires `STRATA_PREFILL_STREAM_ALL=1`, or the default policy with `g_nonres_share < 0.10`; `=0` disables it. Consequently a scheduled override of 8 is not guaranteed to remain an 8-slot stream-all ring, and 16K does not by itself establish stream-all eligibility. Record the effective `T`, `m.ring`, source pointer, stream-all env and nonresident-share decision before attributing this gap to a run.

## D caller synchronization paths

The audited source is the immutable compiled D caller `/home/yayoi/.local/state/strata-sycl/post-reboot-tuning-20261007/prefill-gemm-service-only-v1/prefill.cpp`, SHA-256 `1cf7e911a555e8611c1368a4d18d4ba81c95027bb8de77f89ad65ac64b05fc3c`. R297 records that caller's linked object (`5f16be55…`) and confirms the corresponding compiled caller identity for binary `81375b88…`; this audit does not substitute the WNEW mirror. The stream-all issuer/consumer implementation is around caller lines 3330–3595 and 4190–4205 / 5035–5090.

- `STAGE=8` and `stream_all_min()` defaults to 1,024 tokens (override: `STRATA_PREFILL_STREAM_MIN`). The effective ring comes from an explicit `STRATA_PREFILL_RING`, a layer-split override, a ring budget, or the pinned/unpinned default policy. The explicit environment value 8 is special-cased to return `STAGE` before the stream-all policy. Without that explicit environment, the later policy gates stream-all on `STRATA_PREFILL_STREAM_ALL` or `g_nonres_share < 0.10`, then returns `big = clamp(r, 16, ring_cap())` at/above the minimum. So an internal scheduled `r=8` can become 16 when stream-all is allowed.
- `stream_all` also needs a non-null model source. The current record uses an explicit ring 8, so neither actual source/cache fraction nor compact mode changes the no-stream-all result. `fused_ring()` is separate; it is disabled for portable-peer mode. Portable peer participation can set `ps_on`, which diverts selected pinned entries through the peer ring and excludes peer-owned experts from the primary list. It does not add an issuer publication wait to the primary consumer's skipped-entry path. The peer `p_issue_until` / `p_release_to` path itself issues/releases on the calling thread and has no `a_issued` issuer thread; do not conflate its ring with the primary issuer race.
- When `stream_all && STRATA_PREFILL_ISSUER` is enabled (default if absent), the per-chunk issuer thread is started. Before each issue it acquire-loads `a_consumed` in the ring-window loop, may read the live slot's `used_of` and wait event, submits the copy, marks `stage_live`, then release-stores `a_issued=idx+1`. The consumer's `wait_issued(k)` acquire-waits for publication before a **selected** streamed entry; `release_to()`'s skipped entries have no matching wait before the used-event/`used_of` mutation. The `give_back()` release-store follows those writes, but cannot retroactively synchronize the issuer's already-passed window check.
- The D source explicitly joins the issuer at chunk completion (`issuer.join()`, around line 5272); its `IssuerJoin` RAII destructor also stops/joins on early scope exit. As with Xe R311, this supplies a boundary before following-chunk work, not a same-chunk skipped-entry edge. It does not remove the conditional race above.
- With `STRATA_PREFILL_ISSUER=0`, `threaded_issue` is false. Stream-all copy submission is inline through `issue_until`, and `wait_issued` returns immediately; there is no concurrent host issuer to race with the consumer's skip metadata writes. That changes synchronization, not stream-all's full-list work or memory/queue behavior.

The skip branch catches `sycl::exception` by logging and `std::exit(1)`. The threaded issuer catches `std::exception` and unknown exceptions, writes a fatal message and calls `std::_Exit(1)` (no GPU cleanup); it does not publish `a_issued` for an entry after an exception. The enclosing `run_impl` catches ordinary `std::exception` and returns `false`, while several explicit source/data failures also return `false`. These failure paths do not supply a missing synchronization edge. The same-chunk conclusion is conditional, not a report of an observed fault.

## Relation to R311 and scope limits

R311's Xe result concerns its own exact source and confirms a possible same-chunk skip race plus a separate inter-chunk join edge. R314 establishes that the D compiled caller contains the analogous unguarded skipped-entry operation, but also establishes that the current quiet D ring-8 configuration never selects the branch. Do not transfer Xe's execution eligibility, routing skip, or failure attribution to D. A larger-chunk D investigation is relevant only if the effective ring policy actually makes `stream_all` true; with the current explicit ring-8 environment it remains routed-only even at 16K. No runtime sample here establishes that a skip occurred or that this gap caused a GPU failure.
