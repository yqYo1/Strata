# R315 — Xe second-chunk GPU dependency and lifetime audit

Date: 2026-10-11. Source-only audit of the immutable Xe source and existing R309/R311 evidence. No GPU/process/system query, build, test, inference, profiler, Git operation, cleanup, or source edit was performed. This report does not authorize or propose immediate GPU execution; current GPU work remains stopped after the V8 fault.

## Finding

For the V8 configuration that can be established from the receipt (host-USM arena, 4096-token chunks, effective stream ring 16, first layer 0, issuer default on), the first-to-second chunk boundary has explicit lifetime/order mechanisms for the main device staging ring and scratch. The chunk allocations are made once and reused; the streamed device slots persist across chunks; compute/copy queues are in-order; each ring refill is submitted on the copy queue with a dependency on the previous compute-side `used` event; each selected consumer waits for the copy-side `copied` event before reading the slot; and the next chunk's issuer starts only after the preceding chunk issuer is joined. These source contracts reveal no independent, demonstrated cross-chunk use-after-free or scratch-reuse violation in the pinned host-USM route.

This finding is bounded. It does not prove every runtime submission succeeded, that a particular event was recorded successfully, that every address/range was valid in the faulting execution, or which command produced the recorded CAT18 fault. R309 remains controlling on attribution: UR 40 surfaced while `iq_dequant_gu_f16` was submitting, not as identification of the faulting kernel. R311's conditional same-chunk skipped-entry host race remains a separate finding and is not re-attributed here.

## Cross-queue data path at the boundary

`Prefill::init` creates a dedicated `m.copy` stream. `Runtime::create_stream` constructs it in the same runtime context as the runtime compute/transfer queues and gives it `sycl::property::queue::in_order`; the runtime's primary compute queue is also in-order. The V8 input sets the arena host-USM mode. `ArenaExpertSource` creates a host-USM block for each layer, and its pinned classification covers those arena blobs. In `stream_all`, such entries use `en.job < 0`: the issuer submits H2D from the arena blob to `m.stage_dev[slot]` with `copy_async_after`. They do not route through the `Stager` host-copy buffers. The source arena is owned outside `Prefill` and remains alive through the request.

For slot `sl`, the issuer reads `stage_live[sl]` and `used_of[sl]`; if live, `copy_async_after` submits a copy command whose handler depends on the current SYCL event in `m.used[used_of[sl]]`. It stores the returned copy event in `m.copied[sl]`. On a selected streamed expert, the consumer first waits for the issuer's release/acquire publication (`a_issued`), then queues a wait on `m.copied[sl]` on `m.cs`, before calling `compute()` on the staged blob. In normal non-MMQ dequant, `compute()` queues the dequant read of that blob and records `m.used[sl]` after those reads. In the MMQ grouped path, it queues gather from the staged blob and records the release event after gather; later matrix products read the distinct group scratch. Thus the staged slot need only remain live through dequant/gather, not through the grouped products.

The handoffs are bidirectional: `used` is compute-to-copy protection against overwriting a slot still being read, while `copied` is copy-to-compute protection against reading it before transfer completion. In-order ordering inside either queue alone does not create cross-queue order; the explicit event dependency/wait is the relevant edge. The helper submits `h.depends_on(*after->ev)` for the copy, and `stream_wait_event` submits an event-dependent barrier on compute. SYCL event objects are copied into those submitted dependency lists, so later replacing the wrapper's `Event.ev` value does not retroactively change an already submitted dependency.

At the chunk boundary, local issuer counters are newly initialized for that chunk, but `stage_live`, `used_of`, `copied`, and `used` live in `Prefill::Impl` and are not reset. The previous chunk joins its issuer after finishing the layer walk; thread completion/join orders the prior host writes to the event wrappers and slot metadata before the next chunk creates its issuer. Device work need not be globally idle at that point: the next copy command still depends on the previous chunk's `used` event for the slot, and the compute consumer still waits on the new `copied` event. Queue commands submitted on `m.copy` remain ordered with other copies on that queue. The boundary is therefore not an implicit whole-device synchronization, but it does not rely on one for this ring's normal selected-entry path.

`m.copied` / `m.used` wrappers are reused, not destroyed at the boundary. A submitted SYCL command already holds its event dependency. The layer event arrays have `RING_MAX=1024`, while this run's ring is 16, so the effective slot indices remain within the arrays; R309 separately notes the sequence/ring index bounds for its receipt settings.

## Persistent and overlaid scratch

`carve(T)` allocates or binds the chunk's device buffers at initialization/relayout, not at the top of every prompt chunk. `run()` loops over chunks without freeing/recarving them. The stage ring, dequant buffers, compact/group buffers, outputs, and attention/MoE region therefore remain allocated through the first and second chunk. The code does not free `m.stage_dev`, `m.dq_gu`, `m.dq_d`, `m.grp_gu`, `m.grp_d`, `m.GU`, `m.Dm`, `m.shared`, `m.sg`, or `m.bo` between those chunks.

- On the non-MMQ path, each expert's dequant writes its group slice in `m.dq_gu` / `m.dq_d`; grouped GEMM then consumes the filled group before the next group reuses those slices. These operations use `m.cs`, an in-order queue. The stage slot is released after the dequant has read the blob, while the grouped GEMM consumes the separate dequant scratch.
- When MMQ applies and the chunk is above the stream threshold, `m.grp_gu` / `m.grp_d` are compacted group scratch. The gather and subsequent gate/up, SwiGLU, quantize, and down submissions are all issued on `m.cs`, in order. The staged source slot's `used` event follows the gather; group scratch remains live until the later products, which are already queued ahead of the next group overwrite on that same in-order queue.
- `m.Dm`, `m.GU`, `m.H`/`m.Hq` (where present), `m.shared`, `m.sg`, and `m.bo` are per-chunk/per-layer outputs or intermediates. Expert products, `moe_combine`, and the subsequent residual write are submitted on `m.cs`; layer order is serialized by that queue. The attention and MoE allocations deliberately overlay `m.region`, but the layer runs attention and writes it back to `m.R` before its MoE phase. The single compute queue's order is the lifetime boundary for that overlay.
- CPU-expert rows, if the optional pool route is selected, are copied into `m.Dm` only after `cpu_fut.get()`; the next layer performs the routing/readback synchronization before rewriting/resizing host tables or reallocating CPU buffers. This CPU route is disabled by `!stream_all` in `cpu_maybe` for the V8 4096/stream-all case, so it is not a V8 explanation.
- The PLE host rows use two buffers. `ple_next.get()` completes host generation before upload. Before the worker reuses the opposite host buffer, `event_sync(ple_copied[other])` waits for its prior upload. PLE device work and later layers share the same in-order `m.cs`. This is a separate, explicitly guarded host-buffer reuse path.

On normal `Prefill::release`, device allocations and ring event wrappers are released after `m.cs` and `m.copy` are synchronized. The layer host-USM arena is owned by the surrounding expert source, not by the chunk loop. No normal first-to-second chunk free is visible in this source route.

## Remaining limits and adjacent failure surfaces

The source does not check the Boolean result of every stream helper in the stream-all state machine. R309 already records that `copy_async_after`, event recording, and waits can fail synchronously while the caller still advances/publicizes issuer state; the receipt does not show any such failure. This remains a real instrumentation/robustness gap, but a possible failed call is not proof that a dependency was missing during V8.

R311's conditional skipped-entry concern is specific to same-chunk host access to `used_of` / `Event.ev` when the issuer may already have passed the ring-window load. It is excluded from the positive cross-chunk conclusion above and remains conditional on an actual skip/interleaving. The join at a chunk boundary does not fix a same-chunk interleaving.

One adjacent lifetime question is outside the V8 host-USM source path but should be checked before using a non-pinned source in a later test: `Prefill::release()` resets/destroys `Stager` before it synchronizes `m.copy`; `Stager::~Stager()` joins host workers and frees its pinned host buffers, but its `finish()` method does not explicitly wait for every final `dma_done` event. If such a job's last DMA is outstanding at teardown, that order could free a DMA source before the copy queue's later sync. In the V8 mode, arena blobs are pinned host-USM sources (`job < 0`), so those Stager buffers are not the active H2D sources, and this observation does not explain the recorded second-chunk fault. Keep it as a separate teardown audit item, not a fault attribution.

## Finite discriminating follow-up (only after owner separately admits GPU work)

1. First satisfy the separate post-fault device admission gate; do not use a model run to check whether a reset has recovered. Preserve the existing diagnostic state and make no reset/rebind/clear attempt.
2. For a source-path control, use a fresh process, the exact recorded V8 binary/environment/input prefix, and exactly two 4096-token chunks. Set only `STRATA_PREFILL_ISSUER=0` for this one bounded run, leaving host-USM, ring 8/effective 16, cache, model, and all other variables fixed. Record helper success/failure, source/destination intervals, slot index/generation, and submission/event IDs for `used -> H2D -> copied -> compute read`; stop at first error/fault and do not retry. This removes the concurrent host issuer while preserving copy-queue and compute-queue event handoffs, helping distinguish host issuer overlap from queue/event/device issues. It is not a safety guarantee and does not test the known race in a way that licenses an inference.
3. Only if separately admitted after a clean control, run one fresh two-chunk issuer-on arm with the same logging and inputs. Compare the single-arm results; do not run a performance comparison. A fault address is discriminating only if allocation intervals are captured while allocations are live, and still must be paired with driver fault metadata.
4. If evaluating the non-pinned teardown item, use a separate shutdown-only fixture with a deliberately active final staged DMA and instrument completion before free; do not mix that path into V8 reproduction. A fix or source mutation requires its own authorization and review.

None of these tests was run or authorized here.
