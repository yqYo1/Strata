## Finding

Current source has enough hooks to count routes cheaply, but no existing receipt joins actual `(chunk, layer, expert, ne, pair, packed bytes, residency/source, branch)` calls. The opt-in `STRATA_PREFILL_SERVICE_TIMING` `ExpertServiceLedger` records only generic-path oneMKL GU/Down returned events, shape `(role, rows=ne, N, K, ldy)`, plus expected/completed GU/Down identity pairs for the local `order`. It has no format or packed-byte field and is explicitly invalidated for MMQ, fused, and multi-GPU/peer routes. It cannot alone supply full current-route exposure.

The opt-in transfer ledger is more informative for streamed calls: `ExpertTransferTimer::copy` records layer, chunk, expert, ring slot, logical copied blob bytes, and `source=1` for direct pinned-blob copies or `source=2` for host-stager copies, plus host submission/stager/ring waits. Its aggregates preserve layer/chunk/source coverage. It sees no resident expert calls; `source=2` does not distinguish all backing-file/cache details. Existing `stats_.experts_resident`, `experts_streamed`, and `experts_dma` are request-wide counters, not layer/chunk/type keyed. `PfTimer` is an optional aggregate GPU phase timeline; `kPfDequant`, `kPfGemmGU`, and `kPfGemmD` are not labeled with layer, expert, pair type, or per-call count, and combine route branches. Non-finite debug output reports layer/type/mmq only on errors. None reports the needed exact per-chunk capacity denominator.

Source locations audited: `sycl/src/prefill/prefill.cpp` around `ExpertTransferTimer` (~2306), service admission (~2990), chunk MoE route selection and counts (~4100–4320), generic/MMQ/fused route compute (~4830–4950), streamed copy (`stage_one`, ~4720), summary reports (~5416); `sycl/include/strata/prefill_service_ledger.hpp` (`ServiceId`, record/fold/report); `include/strata/kernels/cpu/native_expert.hpp` (`NativeFmt`). The complete per-layer native `NativeFmt` is already available at the MoE loop (`lay.fmt[l]`): `gu_type`, `d_type`, `n_embd`, `n_ff`, `gu_row`, `d_row`, `up_off`, `down_off`, `bytes`. `lay.blob_bytes(l)` supplies exact logical bytes for one expert. Do not substitute role/type marginals for this loaded per-layer pair.

## Minimal bounded census to apply a capacity map

At the host route loop, after `ids_h` has populated `m.cnt` and after `on_peer`/`order`/`order_peer` and `use_mmq`/`fused_l` have been decided, add only integer counters to a default-off census. Do not add device events, markers, waits, allocator calls per expert, extra copies, or extra synchronizations. The census is per actual chunk (`p0`, actual `T`) and MoE layer. For each routed unique expert with `ne=m.cnt[e]`, update one sparse histogram bin keyed by:

`(loaded gu_type,d_type, branch, owner, residency/source, ne)`.

Each layer record also stores `layer`, `chunk_position=p0`, `T`, `K`, `n_expert`, `n_routed_entries=T*K`, invalid ID count (must be zero), distinct routed experts, exact `blob_bytes`, `gu_row`, `d_row`, `n_embd`, `n_ff`, `up_off`, `down_off`, whether formats are native, `stream_all`, `use_mmq`, `fused_l`, `fused_nat`, `fused_only`, `peer route present`, actual chunk length, and build/runtime dispatch identity already available without device queries. For the current 7-pair map, retain only exact pairs from the parent-owned census; unknown pair/type/build branches remain explicitly “no capacity-map match.”

Use these mutually clear labels:

- `branch`: `generic_iq_fp16_dequant+expert_f16_gemm`, `generic_gguf_dequant+expert_f16_gemm`, `mmq_gather+mmq_gemm`, `fused_native_iq`, `fused_q2`, `peer_mmq`, or `other/unsupported`. Derive this from the booleans and actual `lay.native` dispatch at the call site, not merely a startup flag. The generic native branch calls `iq_dequant_gu_f16(f.gu_type, ...)` and `iq_dequant_f16(f.d_type, ...)`, then exactly one per-expert GU and Down `f16_event`/GEMM call. MMQ calls `gather_native` for native packs (or `gather_strata_q2` for Strata packs), then groups its matrix products; it does not call the generic IQ-to-FP16 functions. Fused native calls `fused::experts_native`; it has no separate generic dequant or oneMKL expert call. Never multiply a generic-dequant or generic oneMKL capacity by counts from those other branches.
- `owner`: primary GPU, peer/helper GPU, CPU/off-path, or unknown. The visible current MoE loop can identify `on_peer`, `order`, and `order_peer`; preserve rather than silently merge any non-primary path.
- `residency/source`: `resident_cache` when `m.host_res[l*n_expert+e] >= 0`; otherwise `streamed_pinned_blob` when the executed `stage_one` sees `m.src->pinned(l,e)`; otherwise `streamed_host_stager` for the executed staging route. Keep the exact transfer ledger `source=1/2` join as a cross-check. Record source as `unknown` if route ownership cannot be resolved. For non-stream-all staging, use the same source decision performed at `stage_one`, not a forecast based on host residency counts.

For each sparse bin, store `calls` (= distinct expert calls), `routed_rows` (= sum of `ne`), and `logical_packed_bytes` (= calls × `lay.blob_bytes(l)`). Also store or derive the per-call packed role split from row sizes: GU+Up logical input `2*n_ff*gu_row`, Down logical input `n_embd*d_row`, total must reconcile to `f.bytes`/`lay.blob_bytes(l)` for the native format. The packed-byte quantity is the bytes presented to the dequant/gather path, not physical DRAM/L2/PCIe traffic. The existing transfer ledger separately measures H2D logical payload copies; never add it to device reads without explicitly labeling the combined logical path. GPU output materialization for generic native dequant has fixed per expert at these shapes: GU 6,553,600 B FP16 and Down 3,276,800 B FP16, independent of `ne`. This is a source-derived logical byte count, not device traffic.

Store only nonzero histogram bins and emit one compact line per `(chunk,layer)` at a safe request boundary. Do not write one line per token-route entry or expert in the hot loop. Bound memory by reusing a layer-local sparse accumulator and bound retained output to at most 32 MiB per request; if a cap, formatting failure, or allocation failure is reached, mark the entire census invalid and publish no partial capacity join. At 32K prompt length, record actual `T`/chunk count rather than assuming fixed chunk size. The maximal route-entry denominator remains `T*K`; calls are distinct selected experts and satisfy `sum(calls by owner/source/branch)=distinct routed experts`, while `sum(routed_rows)=T*K` after any explicitly recorded peer/other ownership partition. For each layer/chunk reconcile every routed ID exactly once; `sum(ne)=T*K`; local plus peer row totals equal `T*K`; and expert calls per branch/route partition sum to the distinct nonzero expert count. Transfer records must reconcile exactly against streamed expert IDs, `blob_bytes`, layer/chunk and source. Generic branch must have one GU and one Down per local expert at the same `ne`; MMQ/fused branches must have no generic pair expectation. Any missing/duplicate pair, cap overflow, transfer mismatch or unsupported branch invalidates the whole request receipt.

## Joining to service/capacity measurements

For each exact histogram bin, join the map only by the key measured in that capacity series:

- generic GPU dequant map: exact `(gu_type,d_type, packed role sizes, production geometry, backend/build)` and number of executed generic expert calls; dequant is once per expert even when `ne>1`, so routed rows are not its call denominator.
- oneMKL expert GEMM map: exact `(role, ne, N, K, ldy, backend/library/build)`; histogram `ne` counts times one GU and one Down call per generic-local expert. This does not apply to MMQ/fused/peer jobs.
- MMQ/fused map: join only to a capacity result from that exact branch, active format pair, grouping/padding geometry, and stream/peer condition. The type pair alone does not make an MMQ/fused job eligible for generic dequant/GEMM capacity.

The service ledger's event duration is device profiling `end-start` for the returned routine event, with `start-submit` queue delay; it is not exclusive kernel busy time or request latency. Its host `steady_clock` submit duration and transfer stager/ring waits are separate. `PfTimer` reports aggregate device-event phase spans. Request wall time, host CPU/stager time, SYCL device event time, and any external profiler/device-kernel time are distinct clocks/domains; no cross-clock subtraction is valid without a measured clock correlation. Do not sum overlapping event durations and call the sum critical path. Keep a clean uninstrumented matched request for end-to-end latency and treat the census run as route accounting only. Use the observed histogram to weight capacity only after the path's actual phases show it is critical; otherwise report exposure, not a predicted end-to-end gain or an optimization choice.

## Validation budget and authority

The census itself should consist of integer increments over data the route loop already has, bounded sparse aggregation, and compact serialization after inference. Its device-command count and per-expert synchronization count are exactly zero. Preallocate/reuse the layer-local counter storage. Record host-only census accumulation/serialization wall time in `steady_clock`, separately from request wall and GPU event times. At request end reconcile requested tokens/chunks/layers and every row/call/byte equation above. Include original request identity, loaded-format manifest SHA, route settings, actual current pair set, histogram checksum, and validity reason. For a default-off vs default-off comparison, absent instrumentation is represented as absent, never as zero calls.

The existing `ExpertServiceLedger` bounds at 65,536 event records and 16,384 aggregate buckets; `ExpertTransferTimer` also retains transfer events and folds at existing waits. Reuse its fail-closed validity counters and coverage checks, but do not increase event retention merely to learn route frequency. The compact route census is bounded at 32 MiB. The registry's reviewed current-pack receipt SHA supplied by the parent remains the only pack frequency authority; this runtime census then validates which of those loaded pairs and capacity branches the actual >=32K request reached. The 384-expert 22/20 fixture and M160 hypothetical averages are not substitutes for actual request counts.

No external profiler recipe is required for this census: it is a caller-side route accounting gap, not a kernel-only measurement gap. Existing oneMKL returned-event/PTI qualification remains governed by R237; this report does not repeat or alter that internal-event span recipe. No capacity result or performance claim is added here.
