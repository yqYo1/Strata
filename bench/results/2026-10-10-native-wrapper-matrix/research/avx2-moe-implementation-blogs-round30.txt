Local baseline and duplicate exclusion

Current source already decodes each IQ weight block once and reuses that decoded block across NT activation rows (`src/kernels/cpu/iq_avx2_rows.inl:31-57`); GU's row routine computes gate, up, and SwiGLU for that row (`:161-165`). The formats of interest are GGML IDs 18 IQ3_XXS, 21 IQ3_S, 22 IQ2_S, 23 IQ4_XS; IQ4_XS uses its existing 16-entry pshufb table (`src/kernels/cpu/iq_avx2.cpp:245-274,347-366`). Down 20 IQ4_NL is also pshufb-decoded once per block across NT (`iq_avx2_rows.inl:238-242`), while Down 42 is Q2_0 in a separate kernel. Existing R9 hot-expert predecode, R17 Gate/Up reuse, R21 NT spill/cache-line, and R25 Q2 GU proposals are not repeated.

One new conditional lead: test an 8-row by 8-token integer panel GEMM for routed grid-IQ GU experts at NT=8

A new upstream llama.cpp author implementation provides a concrete close analogue beyond the earlier generic tiled-kernel reference: commit 85c55223caf0a2ad0d1d88e5a73ab3fe36107867 (bartowski1182 and Georgi Gerganov), PR #27402. It decodes eight consecutive grid-IQ weight rows into an interleaved int8 scratch panel, then uses AVX2 integer dot operations for 4 output rows x 8 Q8_K activation columns. The panel code has explicit decoders for IQ2_XXS, IQ2_XS, IQ2_S, IQ3_XXS, IQ3_S, IQ1_S/M and IQ4_XS. The separate per-expert MUL_MAT_ID branch uses a minimum batch of 8 and the p4 entry for scattered activation row pointers. Primary source: https://github.com/ggml-org/llama.cpp/commit/85c55223caf0a2ad0d1d88e5a73ab3fe36107867 (implementation in `ggml/src/ggml-cpu/iqp.cpp`, interface/contract in `iqp.h`).

Transfer question: test only routed GU formats 18/21/22 first, then 23 if codebook conversion cost still looks favorable. Strata already shares decode across tokens within one output row; the different panel axis is sharing interleaved rows across vector lanes while multiplying multiple token columns. The local model uses H=2560, FF=640, block-aligned K; eight output rows fit its row count, and its IQ GU activations are Q8_K. A production adaptation must preserve gate/up/SwiGLU semantics, row output layout, the current quantized activation values, and selected dispatch. It should include panel construction in timing and use per-call scratch first, avoiding any persistent model repack/cache claim.

Prerequisites and limits: this path is only a plausible test when one routed expert has at least eight tokens at once (`NT=8`). The upstream author sets the per-expert threshold to eight because decode conversion must repay itself; NT1–7 have no upstream case for this path. It does not apply to Down20 IQ4_NL or Down42 Q2_0, and a full-panel conversion is likely a poor candidate for IQ4_XS until measured because Strata already decodes its compact 16-value LUT via `vpshufb`. Also, upstream panel GEMM changes reduction order, so do not demand bitwise equality with the existing row kernel; require the existing numerical gate/reference plus matched T/H parity for the same new kernel and inputs.

Smallest falsifier (root-owned only, after current qualification): a standalone synthetic microbench at actual H/FF, real packed blocks, production Q8_K activations and NT=8. Compare existing production GU wrapper against a panel prototype with construction cost included. First validate each predecoded integer weight/subscale against the local format decoder and outputs against the established reference; reject any tolerance failure. Benchmark per-expert GU with identical rows/inputs/CPU/flags and paired repeat samples. If fewer than eight tokens/expert occurs in actual traffic, panel setup erases the gain, or accepted per-row time does not improve repeatably, stop without production integration. Only a measured win proceeds to a fresh-request output/state gate.

Evidence in the upstream implementation: `iqp.h` documents 8 source rows decoded to scratch then integer GEMM; `iqp.cpp` defines `GGML_IQP_MIN_BATCH_ID=8`, `IQP_NB_ROWS=8`, and Q8_K panel support (raw pinned source: https://raw.githubusercontent.com/ggml-org/llama.cpp/85c55223caf0a2ad0d1d88e5a73ab3fe36107867/ggml/src/ggml-cpu/iqp.cpp). The commit identifies the batched grid-IQ GEMM, vectorized panel decoder, 8x8 Q8_K kernel, and test coverage in its change description. This is source precedent, not measured performance evidence for Strata or Zen3.

Concrete inapplicability: small register-resident lookup tables are already used where they fit; applying that approach as a new grid decoder is not justified

The quantization author discussion for IQK explains why its 4/8/16/32-value nonlinear codebooks can be looked up with AVX2 `pshufb` (https://github.com/ikawrakow/ik_llama.cpp/discussions/8). This is a distinct quant family from the large indexed grids in Strata's IQ3_XXS/IQ3_S/IQ2_S row decoders. Locally, IQ4_XS/IQ4_NL already use the small 16-entry `kvalues_iq4nl` `pshufb` table, and the grid formats already have a gathered AVX2 variant for the costly grid reads (`iq_avx2.cpp:14-16,276-345`). Therefore the generic "replace codebook lookup with pshufb" advice is already implemented for the small-LUT format and does not directly solve the >256-entry grid decode. Avoid a new LUT recommendation without distinct data showing missed grid-cache lines or improved decode mechanics.

No performance estimate or adoption recommendation is made. The only new candidate is the NT8 row-panel-by-token GEMM, with the strict format/traffic prerequisites and falsifier above.
