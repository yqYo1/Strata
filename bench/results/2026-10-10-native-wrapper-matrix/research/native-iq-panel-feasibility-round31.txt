Actual model shape and which types are present

The harness H=2560/FF=640 fixture dimensions are synthetic inputs; its random legal weights/activations and standalone wrapper arrays do not represent model tensors, routing, pool tasks or production output. The same numeric dimensions are also the active model's routed native-expert geometry: `include/strata/kernels/cpu/expert.hpp` defines H=2560 and FF=640; `expert_layout.cpp` calls `native_fmt(type, ..., H, FF)` for every layer record and refuses the pack if computed `f.bytes` differs from that record's `blob_bytes`. The installed pack `/home/yayoi/.local/share/strata-sycl/packs/qwen3.8-flash-next-iq3_s/native_experts.txt` has all 48 actual layer records and lengths; e.g. type 18/Down20 layer 0 is 2,176,000 bytes, type 21/Down20 layer 17 is 2,329,600 bytes, type 22/Down20 layer 2 is 1,971,200 bytes, and type 23/Down20 layer 47 is 2,662,400 bytes. These all match `native_fmt` at 2560/640 using the pinned block layouts (10 GGUF QK_K=256 input blocks per GU row; 20 IQ4_NL QK=32 blocks per Down row). The model index's shared expert gate/up tensors independently record 2560 x 640 dimensions. Thus the harness numeric dimensions coincide with the model geometry, while the fixture itself remains synthetic.

The active native pack contains GU IDs 18 (IQ3_XXS), 21 (IQ3_S), 22 (IQ2_S), and 23 (IQ4_XS). Its Down IDs are 20 (IQ4_NL) and 42 (Q2_0). The upstream IQ panel type list in pinned `ggml/src/ggml-cpu/iqp.cpp:494-502` includes all four GU types 18/21/22/23 but excludes both active Down types 20/42. This makes the panel a GU-only feasibility question, not a Down-kernel proposal.

Activation ABI and current call graph

Pinned ggml CPU traits (`ggml/src/ggml-cpu/ggml-cpu.c:349-389`) assign Q8_K as `vec_dot_type` for IDs 18/21/22/23, matching the panel's `block_q8_K` input. Strata's `native_fmt` records each trait's `vec_dot_type` and `from_float`, and `native_quant_act` invokes that quantizer (`src/kernels/cpu/native_expert.cpp:46-73`). `src/core/expert_source.cpp:2029,2082` stores these packed activation rows in each native job. Therefore the native GU path already has the correct upstream byte ABI and would not need a second Q8_K conversion. The panel does not accept Strata `ActQ`: `ActQ` is a separate 32-element-chunk representation used by the Q2_0 Down42 path, not the IQ GU Q8_K row pointer.

Pinned ggml already contains the upstream panel code, but `vec_dot` itself does not enter it. `ggml_cpu_iqp_supports_mul_mat_id` plus the explicit branch in `ggml_compute_forward_mul_mat_id` select `ggml_compute_forward_mul_mat_id_iqp` only for the outer GGML `MUL_MAT_ID` operation; that branch requires AVX2, a supported IQ type with Q8_K dot, F32 source activations, block-aligned K and output row count divisible by eight, and at least eight routed rows for that expert (`iqp.cpp:20-30,1053-1127`; `ggml-cpu.c:1599-1682`). The normal `vec_dot` table entries are separate fallback functions. Strata's actual native CPU pool path `run_split_multi_native` calls `native_gu_rows` directly with packed job activations (`src/kernels/cpu/pool.cpp:849 onward`, call at `src/kernels/cpu/pool.cpp:653`; wrapper dispatch in `src/kernels/cpu/native_expert.cpp:125-180`), which dispatches to Strata's own AVX2 row kernel or loops over ggml `traits(...)->vec_dot`; those direct per-row trait calls cannot reach ggml's graph-level IQP selection. Therefore the pinned library's existing IQP implementation is not already active for this Strata native wrapper path.

Panel dimensions, scratch and conversion work

Pinned ggml defines `QK_K=256`, eight panel rows, sixteen 16-value scale sub-blocks per superblock, and `block_iqp_x8` as 32 B row scales + 32 B biases + 128 B interleaved integer sub-scales + 2,048 B interleaved signed weights = 2,240 B per K=256 panel block (`iqp.cpp:27-40`). For this model's K=H=2560, one panel has ten blocks, exactly 22,400 B (already a multiple of 64); graph planning pads each worker's panel scratch to 64 and allocates one such region per worker (`iqp.cpp:1190-1191,1211-1213` and `ggml-cpu.c:2918-2921`). `ggml_compute_forward_mul_mat_id` obtains those per-thread regions with 64-byte alignment (`ggml-cpu.c:1599-1607`). A Strata adaptation would need an explicitly owned per-worker/task scratch region with the same alignment and bounded lifetime. There is no existing native pool panel buffer in the wrapper interfaces; allocate/reuse it outside inner tile loops, not per row or per dispatch.

Each panel construction visits eight rows x ten 256-value blocks (80 type decodes), produces 20,480 signed weight bytes and interleaves them into 8-row x 32-column pieces; it also writes row/sub-block scales, float factors and optional centering biases. GU needs separate gate and up weights, so an eight-row tile needs two panel constructions (160 decoder calls and 40,960 signed bytes emitted) unless the proposed design adds a second simultaneously live panel. This is construction cost to include in any falsifier, not a throughput estimate. The panel decoder's optional `GGML_IQP_VERIFY` checks that its integer/scales representation reconstructs each original dequantized weight exactly (`iqp.cpp:577-603`), but this does not prove the dot outputs match Strata's accumulation order.

Scheduling and correctness integration constraints

The upstream per-expert branch tests routed count >=8, then consumes token rows in groups of four, duplicates a short final row, and writes only real outputs (`ggml-cpu.c:1680-1682; iqp.cpp:1130-1185`). It separately partitions complete groups of eight output rows among workers. Strata's native pool instead partitions a flattened `expert_count * FF` interval among tasks and calls `native_gu_rows(..., r0, r1)` for each expert intersection. At FF=640, 8-row tiles fit exactly, but task edges can split an expert at non-8-aligned row offsets. A panel wrapper cannot widen work into neighboring rows owned by another task. It would need aligned eight-row interiors with exact scalar/current-kernel fallback for the head/tail fragments (or a reviewed task partition that owns whole panels without changing pool semantics). GU also currently computes Gate, Up and SwiGLU per row in one wrapper; the panel primitive is a matrix multiply for one weight plane. The port must preserve both projections and the rowwise activation epilogue. These requirements are additional to standard tail handling and make an unmodified call to the upstream `mul_mat_id` entrypoint unsuitable.

Do not relax any exact T/H comparisons, existing model output/state/logprob/MTP gates or current numerical admission criteria to accommodate changed FP32 reduction order. The pinned panel verifies weight decoding, not the floating dot's bit identity. If an experimental panel fails the existing model correctness gate, reject it; same-new-kernel T/H identity would not clear the old-model numerical gate.

Smallest bounded falsifier if root later authorizes a prototype

Only after current serial T/H wrapper builds and full exact comparison complete, confirm root's real routed histogram includes an adequate NT=8 sample for a grid-IQ GU layer. Then test one actual model GU type at a time (begin with 18/21/22; 23 has an existing 16-entry pshufb decoder and may not repay panel conversion) with actual packed weights, the same `native_quant_act` Q8_K bytes, production H=2560/FF=640, all row ownership fragments, both Gate and Up, and the real SwiGLU. Compare against the unchanged wrapper and full model's existing correctness gates; time the panel build and multiply together with identical worker placement/task ownership. Stop if type/route exposure is absent, fragment fallbacks erase the eligible rows, conversion storage/lifetime is not bounded, or any output gate changes. No estimated speedup is justified from the source precedent.
