## What existing phase counters can establish

The existing timer is sufficient for a first phase-ranking pass; another profiler is not needed to answer whether QSA is a material share. `STRATA_PREFILL_TIMING` is enabled by variable presence (`sycl/src/prefill/prefill.cpp:2101-2118`). It inserts marker events on the compute queue and folds each consecutive pair using `command_end(next) - command_end(previous)`, assigning the interval to the earlier marker (`:2126-2162`). The emitted structured line contains aggregate `gpu_timeline_ms`, separate host setup/chunk-wait/after-chunk values and named `phase_ms` (`:2168-2189`). The source comment explicitly defines it as timeline attribution: queue idle time while the host groups experts or waits for copies is charged to the phase that was waiting. These fields are **not pure per-kernel duration** and do not include a separate copy-queue timeline.

For each QSA call, the current marks split useful coarse phases (`:3775-3780`, `:3893-3914`, `:4073-4120`):

- `qsa proj` starts before K/V/Q and indexer projections. It also covers KV append/quantization and the post-attention gate/output projection, so it is not just matrix projection time.
- `qsa indexer` brackets `native_qsa_indexer_append_batch` (or the opt-in per-token comparison). That batch is already implemented; this is not a recommendation to parallelize it again.
- `qsa select` covers block score computation plus top-k for the chunk's selection batches. It does not split score from top-k.
- `qsa attn` covers the prompt-attention attempt/fallback dispatch and any KV-format transform in that interval. It does not split gather, dequantization, dot products or merge.
- `kv stage` brackets the streamed stage setup/seed interval. It can include compute-queue host-to-device prefix-seed copies but is not a dedicated byte/transfer-rate report.

In layer-major mode, `run_layer_major` owns a single `PfTimer` around its per-layer `run_impl` calls and reports once at the end (`:2680-2685`, `:2750-2780`). Thus a 262,140-token prompt produces aggregate phase totals across 12 QSA layers and 32 prompt chunks (384 QSA layer-chunk visits), not a per-layer or per-chunk heatmap. The phase timer gives the correct next answer—indexer versus select versus attention versus the rest—but cannot by itself show which QSA layer or context interval dominates.

`STRATA_PREFILL_TRANSFER_TIMING` is separate and records actual expert-copy events, bytes, per-layer copy totals, event active time and copy span (`:2201-2248`). It does not capture the KV stage seed. Keep that transfer report separate from the compute-queue phase totals; summing event active times or comparing copy-span to `gpu_timeline_ms` is not a wall-time decomposition.

The only retained structured `phase_reports` found are from the older `owned-dd5-phase-v2-v01402-code32k-diagnostic-r1/record.json` (SHA-256 `89ad8649fdd397d41f89ac6120ff5c3c44fd811aa153357f8968f86312a56567`). Its first 32K diagnostic reports 9.8 ms indexer, 2,664.0 ms selection, and 10,647.0 ms attention, against 323,519.1 ms aggregate timeline; it is a v0.1.40.2 non-layer-major diagnostic. This is retained evidence that the counter emits useful fields, **not** a current 256K estimate or a prediction for streamed layer-major. No retained current full-context receipt has QSA phase values.

## Diagnostic versus clean evidence

The 262K C sequence used `STRATA_TRACE` and post-prefill state dumping to validate/cache and compare state, so its wall measurement is diagnostic. `STRATA_TRACE` does not turn on `PfTimer`; only `STRATA_PREFILL_TIMING` does. Conversely, `STRATA_PREFILL_SYNC` waits at every phase mark (`:2122-2133`), and `STRATA_PF_STEP_SYNC`, repeat-capture row readbacks, `STRATA_SEL_OVERLAP`, `STRATA_IDX_FP16_CHECK`, `STRATA_QSA_DUMP`, and `STRATA_DUMP_SEL` introduce extra waits/copies/host analysis. They answer correctness or hang questions and must not be mixed into a timing arm. The repeat-capture hooks are in the debug C source, not the canonical upstream base.

The `PfTimer` report is written at the end of `run_layer_major`, before `Prefill::run` performs the optional `STRATA_PREFILL_DUMP_STATE` snapshot (`:2346-2376`, `:2760-2780`). Therefore a correctness diagnostic may keep its state capture while the `gpu_timeline_ms`/`phase_ms` still describe the prefill phase intervals; the overall request `prompt_ms` can additionally include the later snapshot. Do not treat that request wall as clean performance. Event profiling itself adds marker submission work, and the Intel optimization guide distinguishes device execution timestamps (`command_start` to `command_end`) from host submit/wait time. Strata's end-to-end marker differences intentionally include intervening queue gaps, so they are best described as phase-attributed timeline, not GPU kernel time. [Intel oneAPI GPU kernel-launch timing guide](https://www.intel.com/content/www/us/en/docs/oneapi/optimization-guide-gpu/2024-2/kernel-launch.html).

## External implementation evidence and one recommendation

The Qwen authors' architecture paper describes QSA as a sparse indexer route used in the full-attention slots, with one full-attention layer in four and micro-block scoring; it validates that QSA is a significant subsystem but gives no B570 serving-phase measurements. [Qwen3.8 architecture paper](https://arxiv.org/abs/2608.30320). vLLM's QSA tile-union RFC reports attention as about 13% of its 8K TTFT on a GB10 and shares a detailed gather-reuse implementation; those GPU and kernel measurements do not transfer to Strata/B570. The useful lesson for this round is to measure the actual phase split before selecting an optimization, not to reopen tile-union/indexer proposals already covered in rounds 13, 15 and 25. [vLLM QSA prefill RFC #55394](https://github.com/vllm-project/vllm/issues/55394).

**Recommendation (conditional, measurement only):** after root has closed the full-repeat math failure and the serial CPU-wrapper checks are complete, use one bounded, root-owned 262,140-input layer-major streamed-KV diagnostic with `STRATA_PREFILL_TIMING=1`, retaining state comparison if needed, while leaving all QSA readback/debug switches and per-mark synchronization off. Record the existing aggregate `qsa indexer`, `qsa select`, `qsa attn`, `qsa proj`, `kv stage`, and host fields in the structured receipt; keep it `diagnostic` and performance-ineligible. If the aggregate identifies a substantial phase, only then decide whether a small per-layer diagnostic is worth adding. Preserve the original C rejection and do not implement another QSA optimization from the current wall times. No hardware-transferred speed claim or optimization is recommended here.
