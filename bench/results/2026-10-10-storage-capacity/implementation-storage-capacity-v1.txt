Execution, timing and failures
All buffers, latency storage, worker receipts, thread contexts and pthread attributes are prepared before worker launch. Every pthread arrives at an atomic start gate; main waits until all workers exist/arrive, clocks before release, then stops the whole-operation clock after joining all threads. Whole wall includes atomic queue handoff, pread completion, worker bookkeeping/canary checks and joins. No payload preparation/reference/hash/formatted output is within that wall interval. Per-request clocks surround pread including EINTR retry and inflight atomics; exactly two steady_clock calls per successful job, declared in output. Canary checking is after the per-request end clock but remains in whole wall. Peak inflight describes worker pread/retry regions; it is not measured physical SSD queue depth. Host latencies can overlap and their sum is not additive wall time.

Every pread must return the entire requested size in one successful call. EINTR retries the same full request; a positive short read is rejected rather than filled/reclassified, and any non-EINTR error rejects. If another worker has failed, an interrupted retry can stop as failure, never become a partial PASS. Offset/buffer alignment and subtraction-before-bound arithmetic are checked per job. Full read count, logical byte count, worker counts/assignments, zero remaining inflight, peak<=workers, syscall_count=request_count+EINTR_retries and every nonmissing latency slot reconcile before success. Latencies are held in a bounded vector and sorted only after timer end; median/p95/p99 use nearest rank and sum has checked overflow. Failed cells emit failure JSON to stderr and nonzero; no rate, average failure or partial normal PASS is published.

Workers are noexcept at the entry point and catch all exceptions into a bounded512-byte first-error record, with errno/job/offset under an atomic flag and stop publication. Per-worker buffers/receipts and per-job latency slots have unique writers. Every other field read by main is read after joins. Atomic inflight scope decrements on all exits. RAII joins partial thread launches before file descriptors/buffers can be destroyed. If joining cannot be established, the source emits failure and _Exit rather than freeing storage still possibly used by a worker. POSIX setup/reference errors preserve the actual returned errno/code separately from cleanup. Normal success JSON is emitted only after run() returns, all threads are joined and owned descriptors/buffers have been released.

Buffer correctness and identity
Worker buffers are4096-aligned, at most1MiB plus64-byte0xa5 canary. Every successful timed read checks its canary. After timer end, EVERY worker's final surviving successful buffer is fully byte-compared to an untimed same-offset full-sized buffered pread from the same inode/device/file identity. Reference and final guards are checked. Full FNV of each final buffer plus an aggregate worker/offset/FNV digest are computed after timing. The JSON reports number/bytes of final buffers checked and each worker's final offset/hash. Only final surviving buffers are byte-validated. This is NOT full equality/hash/math validation of every payload byte of every request; all reads' requested counts/returned sizes are checked instead. Earlier worker buffers overwritten by subsequent reads are not preserved. Qualification at64 random workers has one request per worker and thus all its request buffers survive, but full cells generally do not.

Direct and buffered descriptor stats must match original dev/ino/size/mode/mtime/ctime before reference and after all checks. Output preserves original dev/ino/size and mtime/ctime seconds/nanoseconds, accepted/requested flags and stat_unchanged=true. There is no atime assertion because reads can legitimately update it. File stat stability and final-buffer equality do not prove full historical payload identity under arbitrary concurrent mutation; run under the controller's ordinary immutable-shard ownership. Path replacement between initial and reference opens fails identity admission. O_NOFOLLOW deliberately rejects a symlink rather than resolving an unreviewed target.
