R141 — GDN gate-factor real-recurrence parity oracle

Status and decision

Design only. No implementation, test, model run, runtime, GPU, compiler, profiler, or performance measurement was performed. This proposes the admission oracle for the prefill-only representation under review; it does not qualify the native exponential, establish model parity, or authorize enabling the path. The goal is to compare the current log-gate producer/consumers against a factor producer and every factor consumer while making chunk/state reset mistakes observable.

Source-grounded contract

For every `(t, head)`, legacy producer materializes FP32 `L = fl32(softplus(ab + dt) * ssm_a)` in `m.gate`; recurrence reads that materialized value and computes `G = native_exp(L)`. Candidate producer must store `F = native_exp(L)` where `L` is exactly the same rounded FP32 value legacy would have written. Every recurrence consumer must then use `G = F` (never `native_exp(F)`). Beta, convolution, state/output math and layouts stay identical. Production recurrence currently has serial, columns, pipelined columns, key-head/tuned, and backend-specific quad routes; the encoding follows whichever route is selected. `prefill.cpp` reuses per-chunk scratch, carries each layer's recurrent state and convolution state through the shared GDN block, and permits a shorter first chunk via `STRATA_PREFILL_FIRST`; ordinary max chunk length is 8192. The recurrence update in `kernels.dp.cpp` is, per row/column, `kv = sum_r s[r]*k[r]`; `delta=(v-G*kv)*beta`; `s'[r]=fma(G,s[r],k[r]*delta)`. Output uses `q`, head-column reduction/norm, `gamma`, and `sigmoid(z)`; compare FP32 `y` before projection as well as final FP16 `y16`.

Proposed smallest decisive oracle

Use two independent layers of evidence, in this order:

1. **Real prefill A/B, source-to-consumer parity.** Run the same fixed model build and token sequence in fresh, byte-identical session states, once on legacy log-gate and once on private factor mode. Capture compact per-GDN-layer/per-chunk hashes and mismatch counts at the producer boundary (`ab`, `dt`, `ssm_a`, `L`, `F`, `beta`), after convolution (`hbuf` plus conv history), and after recurrence (`y`, `y16`, complete recurrent state). Compare `L_factor` against `L_legacy` bitwise; compare `F` against the exact baseline consumer's `native_exp(L_legacy)` value bitwise for all finite in-domain inputs; compare beta, convolution outputs/history bitwise; then compare `y`, `y16`, recurrent state and final complete session state bitwise. If a target's native math makes identical source calls non-bitwise due different compiler context, record the first differing bit and gate/consumer dispatch; do not mask it with a loose end-to-end tolerance. Run one identical selector/dispatch per pair and separately repeat for every factor-capable dispatch. The equality of `L` isolates producer changes; bitwise `F` equality tests the materialization boundary; outputs/state test each consumer's use of the representation.

2. **Independent scalar semantic oracle.** For a short fixture captured from actual prefill intermediates, compute a host double reference from the serialized FP32 `L`, `beta`, Q/K/V, gamma/z and initial state, implementing the recurrence equations above with explicit high-precision `exp(double(L))`, then compare both GPU routes to it. Use fixtures spanning all heads, row groups and columns, with deterministic non-symmetric finite values and nonzero state/conv history. Include gate values around `ab+dt=-20, 0, 20` and adjacent FP32 values, plus bounded positive/negative values sampled from the actual captured prefill range. Record min/max and nonfinite counts; do not invent a model-reachable range from arbitrary stress values. Include exact `+0`, `-0`, subnormal and special values only in a separate classifier/primitive fixture, not in the real-context admission set. Require exact shape/index coverage and finite classification; semantic-oracle tolerances are `abs <= 2e-6 + 2e-6*abs(ref)` for FP32 state/output, and `<= 1 ULP` after converting reference output to FP16. This tolerance belongs only to the independent double oracle; legacy-vs-factor remains exact.

The scalar oracle must not call the production gate producer, recurrence helper, layout indexing helper, subgroup reduction helper, or native exp. Its own simple loops and explicit `(t,head,row,column)` indexing make a shared indexing/reduction bug detectable. Retain one deterministic fixture definition and hashes, not full API/session traces. If long-context mismatch first appears, retain only the first failing chunk's inputs, starting recurrent/conv states, outputs and hashes as the named numerical-failure evidence.

Chunk lifecycle set (three long cases; all chunks <= 8192)

Use an identical token sequence/context and fresh session state for the two A/B sides. Also check that the saved state at each boundary is the next chunk's exact initial state; do not reinitialize recurrent state, convolution history, or beta inputs between chunks. Poison/guard reusable scratch before each launch, then ensure every active gate/beta/output element is overwritten and no stale tail element participates.

- **Endpoint split 262143 + 1:** use 31 full 8192 chunks, one 8191 chunk, then one token (total 262144). Compare boundary state at cumulative positions 262143 and 262144 and outputs for the last two tokens. This places the final one-token call at the physical endpoint while the preceding call reuses full-sized scratch.
- **Tail split 262140 + 4:** use 31 full 8192 chunks, one 8188 chunk, then four tokens (total 262144). Compare at 262140 and 262144; this catches short-tail indexing and stale rows with a different remainder.
- **Scratch reuse/first-chunk split:** run `STRATA_PREFILL_FIRST=256` behavior followed by ordinary 8192 chunks and a short final chunk, then run the same sequence with first-chunk override off. Compare final state and common token outputs exactly. This checks differing buffer reuse/c0 advancement without confounding by reset state.

A contiguous one-call 262144-token GDN launch is neither required nor valid for the production 8192 scratch contract. The current automatic chunk policy naturally emits 8192-sized chunks plus its remainder; it does not itself select the two requested near-end splits. Exercise those splits through an existing session-continuation boundary or a test harness that invokes the same bounded chunk body with explicit `T<=8192`, preserving the actual session state between calls. Do not increase the production scratch cap to force them. Also run the ordinary automatic chunk schedule as the real-prefill baseline. A/B each case from fresh state; within each case state is carried continuously. Include the recurrent matrix state and convolution ring/history in every checkpoint, since checking only the recurrent matrix misses a reset in `gdn_conv`. Keep beta and convolution bitwise checks even though gate encoding does not intend to alter them: they detect call misalignment and a mismatched pair.

FP16, subgroup, and compiler-context controls

The recurrence and gate plane are FP32; `y16` is a separate rounded consumer output. Compare `y` and `y16` independently: matching FP16 alone can hide FP32 drift, while matching FP32 `y` does not prove the FP16 store/stride path. Exercise short T (1, 4, 31, 32, 33), odd T, and padded output (`ld_y`) on/off where eligible to test row stride and masked tails. For each actually selectable factor consumer, run same device/compiler/options in matched A/B and retain dispatch identity, subgroup geometry, route selector values, and compile flags. The source has work-group shapes involving `S=128`, row groups 4, and 32-column groups; these create different exp reader multiplicities and reduction schedules. Do not infer subgroup equivalence from one kernel: include each selected serial, columns, pipeline, key-head/tuned and quad specialization that the build can actually dispatch. Unsupported routes must refuse factor mode. No fast-math, subgroup-size, or build-option changes between members of a pair.

Native `exp` is implementation-defined in accuracy and legal input range; therefore the real-context fixture must first classify actual inputs against the target implementation's documented legal domain, and any out-of-domain/nonfinite observation blocks admission pending explicit handling. The Khronos SYCL reference describes `sycl::native` math as implementation-defined; the source audit R125 found no Intel-specific range guarantee to rely on. Exact legacy/factor comparison is therefore the qualification, not an assumed cross-vendor ULP bound. [Khronos SYCL native precision math reference](https://github.khronos.org/SYCL_Reference/iface/native-prec-math-func.html), [SYCL 2020 specification](https://registry.khronos.org/SYCL/specs/sycl-2020/pdf/sycl-2020.pdf).

Fail conditions

Any L mismatch; any finite in-domain F mismatch against the baseline's materialized-L native exp; beta/conv/history mismatch; one mismatched FP32 or FP16 output/state element; incorrect boundary state handoff; NaN/Inf or changed finite classification; stale scratch read/guard damage; missing or silently legacy-fallback factor dispatch; inability to establish identical initial model/session state; or a different token/context/projection input between A/B is FAIL/invalid pair. A result from only the old quad-vs-reference parity harness, only one recurrence dispatch, only final logits, or state that is freshly reset per chunk is insufficient.

How this differs from prior coverage

R89's quad parity harness compares legacy variants against legacy recurrence on generated inputs; it does not drive the candidate producer/direct-factor path, checks no chunk-to-chunk carry, begins with arbitrary initial recurrence state and omits the real conv/full-prefill lifecycle. R137 already specifies the typed interface and asks for context comparison; this report adds the concrete independent oracle, bitwise materialized-value checks, explicit recurrence equations/tolerances, three bounded chunk schedules, scratch poison/guards, and FP32-vs-FP16 and dispatch/compiler-context gates. R140's 512 source work-item exp-expression count remains source-only and is not validation or a performance result.
