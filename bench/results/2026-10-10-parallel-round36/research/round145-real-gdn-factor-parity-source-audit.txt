Decision

The fixture is a credible exact A/B test of the synthetic production GDN gates → convolution → recurrence → output norm component with recurrent-state and conv-history carry. Its queue ordering, per-stage drains, separate arm storage, buffer guards, and state checks are source-consistent. It intentionally does not validate model reachability, decode, physical KV lifecycle, independent mathematical correctness, or performance. One host-only test defect below must be fixed before `HOST_PASS` is accepted as evidence that both OFF-build typed factor entry points refuse independently.

Concrete must-fix in the fixture

At `gdn_gate_factor_parity.cpp:188–199`, the OFF-build factor refusal test wraps `gdn_gates_encoded(DecayFactor, ...)` and `gdn_recurrence_encoded(DecayFactor, ...)` in one `try` and one `refused` flag. The first call is expected to throw, so control skips the recurrence call; the assertion then passes. Trigger: feature-OFF host-only run. Thus the printed `HOST_PASS,...build-OFF factor refusal` does not show that the recurrence API itself rejects factor mode before queue lookup. Split the calls into independent try/assert blocks, one per API, retaining the marker/no-submission checks after each. The production implementation does appear to reject both through `validate_gate_encoding`, but the fixture currently cannot catch a regression in the recurrence refusal path.

Other review findings

- **Arm wiring and comparison:** `run()` pairs `LogGate` producer/recurrence on A and `DecayFactor` producer/recurrence on B, with the same immutable `ab`, `dt`, `a`, `qkv`, `convW`, `z`, and `gamma`. `gdn_conv` runs on each arm's own separately initialized/carrying history and output buffer; recurrence receives its own arm's h/gate/beta/state and writes its own FP32 and FP16 outputs. Both calls go through `gdn_gates_encoded`, `gdn_conv`, and `gdn_recurrence_encoded`; the production implementations bind direct-factor readers for the factor typed API. This is component-real, not full Prefill/model execution.
- **Materialized gate comparator:** after both producer/consumer arms have completed, `MaterializedLogGateExp` reads the legacy arm's materialized `gA` and writes `native::exp(gA)` into separate `expectedFactor`. It does not overwrite/mutate `gA`, `gB`, or any recurrence input. `equal(gB, expectedFactor)` therefore tests candidate factor against the legacy global-memory FP32 log-gate boundary, rather than an unrounded producer local. Beta, h, complete recurrent state, full conv history, FP32 y, and FP16 y are compared bitwise. Gate classification also checks both gates finite and candidate factor in [0,1], which is valid for this fixture's negative `a` values. No shared output buffer or state reset contaminates the A/B comparison.
- **Carry and reset:** `initialize()` gives A/B byte-identical but distinct state and history allocations; `prepare()` deliberately does not reset either, so each later chunk consumes the prior chunk's resulting recurrent and convolution state. The `--prefix` loop uses global offset-derived inputs and checks each chunk; total 262144 with tail 1 gives 31×8192 + 8191 + 1, and tail 4 gives 31×8192 + 8188 + 4 at cap 8192. The `--prefix 32768` path checks bounded carry too. The short set covers 1/3/5/31/32/33/255/256/257 and repeated buffer sizes, once from zero and once from nonzero state; `initialize()` resets the two arms together between sequences. These are synthetic GDN calls, not physical model token/context state.
- **Allocation and guards:** each device buffer reserves 32-element poison regions on both ends, uses independent allocations, initializes whole device extents, reads back before comparisons, and verifies active outputs plus prefix/suffix/inactive tails. State and history capacities are exact for the recurrence and `3*Channels` conv history; h, gate/beta, z, y and FP16 capacities match T×their source dimensions. Inputs (including the convolution weights and projections) are read back and checked byte-identical. The constructor/member lifetime is queue-bound, each operation is followed by `wait_and_throw`, fixture destruction performs a final drain before member buffers free USM, and the queue outlives the fixture. No source-level use-after-free, host-reuse-before-drain, or race in the asynchronous error vector was found.
- **Error path:** the async handler only appends under a mutex and marks an atomic failure flag. `stage()` drains and checks after each action; on uncertain completion it calls `_Exit` instead of unwinding/freeing in-flight allocations. This avoids a dangerous false clean-up after an async failure. It reports the current stage and collected diagnostics. This is source inspection, not evidence of a device failure test.
- **Host-only path:** `--host-only` branches before queue construction. Empty APIs are invoked with a null stream and marker arrays; invalid T, unsupported stride/variant and unknown encoding are rejected with null pointers before any GPU path. The implementation's validation order and T=0 early returns make these checks sensible. However, because the test catches only `invalid_argument` and does not instrument a queue counter, “no_queue_construction,no_GPU_submission” is inferred from source/API control flow, not independently measured. The split OFF test above is the actionable gap.
- **Dispatch scope:** `STRATA_GDN_REC_HEADS` presence selects typed variant 2; otherwise variant 0 reaches the current environment-selected route, with factor and log paths independently applying their corresponding wrapper precedence. Inputs alternate which arm runs first across chunks. The harness prints `variant` but not the resolved serial/columns/pipeline/key-head/tuned/quad kernel identity or selector values. Therefore a pass establishes the current process's selected route only if the exact environment and production wrapper resolution are recorded with the run; this fixture alone does not qualify every dispatch specialization. Preserve that scope in the evidence record; no source change is required to test a single intentionally pinned current route.
- **CMake:** the parity executable is behind its own OFF-by-default option, links against `strata_prefill`, and requires the Level Zero public loader. It defines the fixture's enabled macro only when the factor library option is ON, supporting both ON-path and OFF-refusal runs. No build result is inferred.

Known pending gates (not new fixture defects)

The fixture has no independent scalar/reference recurrence oracle. Its two arms can share a recurrence/indexing bug and still agree; that is a known next numerical gate, not a defect in this requested paired-differential fixture. Inputs are deterministic synthetic arrays, not projections from a named real model or a documented reachable-value capture; the gate range does not target the softplus branch around ±20. It does not run Prefill, decode continuation, physical full-context KV/cache/page lifecycle, final logits/tokens, multi-run API behavior, or performance. Terminal strings explicitly say synthetic-only, model-unqualified, full-KV-lifecycle-unqualified, adopted=false, and make no speed claim. `PREFIX_PASS` is only the synthetic GDN carried-prefix claim. No actual run output was reviewed.
