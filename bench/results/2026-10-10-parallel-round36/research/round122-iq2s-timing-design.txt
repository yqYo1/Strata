## Measurement boundary and whether the comparison is meaningful

The three arms bind and traverse the same preconstructed row sequence: split order, expert ID, output row, then Gate and Up. Each row shares the same actual IQ2_S weight bytes, the same prequantized Q8_K activation pointer, and the same preallocated scalar output address across arms. For the 192-ID streaming stratum this is 122,880 row pairs / 245,760 dot calls and 201,523,200 Gate+Up bytes per sample. For hot8 it is 5,120 row pairs / 10,240 dot calls and 8,396,800 Gate+Up bytes. Each duration is one full traversal; it must not be divided into a purported per-call latency without stating the aggregate-work normalization.

The trait arm calls the selected production IQ2_S trait through its real eight-argument GGML ABI. The direct and register arms call the isolated typed three-argument helpers. Trait selection happened before the interval: this does not include `ggml_get_type_traits_cpu` lookup, engine/native dispatch, a row scheduler, worker queue, `exp`/SwiGLU finish, Down, activation quantization, or full expert service. The clock does include the arm switch, loop traversal, the actual trait function-pointer call or helper call, and the scalar output stores. The ROOT_REVIEW correction says the switch is timed, and R116's eight-argument ABI correction is reflected. This is a meaningful same-caller dot-call comparison with real selected weights, provided its scope stays explicit; it is not a kernel-only instruction measurement and not an end-to-end production service comparison.

Expected trait bits are prepared before timing, and each timed sample is checked against them after the end timestamp. The all-ID three-arm equality admission precedes timing. This correctly keeps comparisons, hashes, input rechecks and output checks out of the interval while detecting timed-call corruption. It does not make the helper ABI equivalent to the trait ABI; any result combines the function-body difference with the calling-interface/indirect-call difference, which is appropriate to report as caller-dot cost and should not be subtracted away.

## Remaining confounds and limits

- Activations are fixed synthetic layer/token vectors, not prompt-derived model activations. The same layer activation is reused across its experts. Results characterize these selected actual weights and activations only.
- The stream set is larger than typical CPU caches, but there is no cache reset/state method. It is a fixed streaming working-set comparison, never a cold-load or DRAM-bandwidth measurement. Hot8 is a bounded repeated subset, not a model-level cache residency claim.
- Split/stratum traversal is fixed as split0 then split1, stream then hot. The seed changes expert shuffle and arm-position offset; it does not change this outer ordering. Consequently the plan does not counterbalance split/stratum drift across processes. Compare trait/direct/register only within each split × stratum × round block; do not interpret the absolute stream-vs-hot or train-vs-holdout durations as causal workload differences.
- Repeated post-sample input quantization checks, output comparisons, guard scans and FNV passes happen between timed blocks. They can influence temperature, frequency and cache state before the next block. All arms receive the same schedule and each arm occupies each position six times per cell/process, which helps with position drift, but does not eliminate it. Output serialization also occurs outside the clock and may perturb later samples.
- Sample output identifies the caller CPU, but not instantaneous frequency, temperature, interrupt load or core residency history. Root's clean-environment and observed CPU/frequency policy belongs in the run evidence. Do not run profiler, loader debug or tracing in these timing processes.
- R116 shows that register-index removes direct index shift/mask/OR work while adding a dependent 2-KiB high-table access and scalar extracts; both arms retain scalar IQ2_S grid reads. This supports no prior expectation that register must win. A result is about the exact compiled binary and host only.
- Train and holdout IDs are disjoint but derive from dependent route evidence; experts and rows are repeated within each whole-cohort pass. Rows and IDs inside one sample are not independent statistical replicates.

## Minimal fresh-process paired analysis

Use three fresh processes with frozen seeds chosen to have distinct `seed % 3` values, keeping all compiler/flags, host affinity, environment, model/packs, cohort TSV and output validation fixed. Require each process to complete its 36 warmups and 216 recorded rows, final completeness marker, flushed output, normal exit 0, and matching timed outputs. Do not mix in correctness-only, profiled, traced or failed/incomplete runs.

Within each process, pair the three arm durations by `(split, stratum, recorded round)`: all arms in that block use the same frozen ID order and exact row pointers. Preserve every raw sample and arm position. For trait-vs-direct, trait-vs-register, and direct-vs-register, report paired ratios or log-duration differences per block, then per-process summaries for each of the four split/stratum cells. Also show arm-position strata and the three process-specific summaries separately. The 18 rounds within a process are repeated observations, not independent replicas; the independent unit is the fresh process. With three process clusters, treat the comparison as a replicated screening result and avoid IID confidence intervals or significance claims based on 648 records/row counts. If applying the project's formal R46 acceptance rule, retain its predeclared pairing/bootstrap method and state its unit; do not bootstrap individual rows or pool the six arm positions as independent data.

Seeds do counterbalance arm-position rotation across fresh processes and independently permute expert order, but do not counterbalance split or stratum order. The command has no split/stratum-order option, so the design supports no claim that it has automatically controlled that drift. Keep all three arm contrasts local to the matching cell and avoid deciding from one split, one stratum, or a pooled average that hides disagreement.

## Decision

The corrected timer boundary and same-pointer traversal support a useful, bounded caller-dot comparison. Retain the real trait as baseline, keep the typed direct control as an intermediate reference, and compare the register candidate against both. The sample must be described as actual selected weights with synthetic activations, a single pinned caller, fixed stream/hot ordering, and mixed trait/helper call contracts. The three-process paired plan is enough for a disciplined initial screen, not by itself an adoption or model-performance gate. Root's release/sanitizer, source/extent identity, clean runtime-path and exactness requirements remain preconditions; no timing data were read here.
