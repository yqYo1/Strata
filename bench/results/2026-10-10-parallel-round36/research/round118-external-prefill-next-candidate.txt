Date: 2026-10-10. Read-only external-source and frozen-source audit. No source edit, Git action, build/compiler, disassembly, test, model payload, inference, device query, cleanup, or root active-output read.

## Conclusion

No new practical source-local long-prefill candidate survived. The most directly relevant new external examples—shared-prefix reuse on an Arc Pro B70 C++/SYCL engine, and vLLM/SGLang hybrid GDN prefill—either describe functionality Strata already has or depend on a different backend/model/GPU execution contract. The remaining ideas duplicate previously rejected/qualified hypotheses: GDN chunk-WY changes FP order; same-buffer `exp(gate)` reuse is R108–R110 and still lacks bitwise qualification; QSA tiling/overlap is R25 and blocked by the open QSA correctness/phase evidence; MoE row-batched Q8 kernels, transfer reuse, chunk sizing, and expert grouping are already in the report history; GDN quad is rejected by clean quiet timings. Do not start another implementation on these sources alone.

## External evidence and transfer limits

- Red-Weasel’s C++/SYCL MachX engine documents Qwen3.8 on Arc Pro B70. It reports a shared-prefix cache that cuts at its 512-row prefill grid, with four 13.6K-prefix agents reaching first token in 5.6–8.5 s versus 72–75 s; it also reports byte-identical output for that specific cache test. Its Q8_0 MoE prefill code changes show per-launch and 2K-row results (e.g. 32K one-request prefill 60.86→48.38 s for a different 35B-A3B model/path). This is the closest external hardware/software precedent, but it duplicates Strata’s existing ConversationCache and its quantization/model/engine and B70 memory configuration do not establish a B570 10 GB result. Source: https://github.com/Red-Weasel/machx-inference-engine (README sections “Faster kernels” and “Serving”, checked 2026-10-10).
- Intel LLM Scaler release notes describe vLLM/XPU changes for Qwen TTFT and prefix caching/MTP, but this is a framework stack rather than a source-local Strata kernel candidate. The branch serves Arc Pro B60/B70; there is no direct B570 + Strata measurement or implementation delta to adopt. Source: https://github.com/intel/llm-scaler (current README checked 2026-10-10).
- SGLang documents its GDN prefill backend selection and Blackwell FlashInfer condition; vLLM reports Blackwell GDN kernel results. These depend on CUDA/Blackwell and alter the chunkwise GDN implementation. They do not transfer to Strata’s Level Zero/SYCL code or establish exact ordered-recurrence equivalence. Sources: https://github.com/sgl-project/sglang/blob/main/docs/docs/advanced_features/attention_backend.mdx and https://vllm-project.github.io/2026/08/06/qwen35-25k-tps.html.
- A Qwen3.8 benchmark README reports that `UBATCH=1024` beat 512 by 8.8% for its llama.cpp setup and 2048 was no better, alongside SGLang 8K prefill-budget and PLE-placement results. Strata already has its own measured chunk/ring policies, so this is not a transferable tuning value; its workload, device and precision differ. Source: https://github.com/lukaLLM/Qwen3.8-Flash-Next-VRAM-Benchmark/blob/master/README.md.
- A recent B70 report about vLLM/XPU prefix cache plus MTP describes correctness problems, while its separate attention-backend results are specific to that vLLM build. This argues for strict cache-state/output verification rather than borrowing its mode. Source: https://www.reddit.com/r/LocalLLM/comments/1wwp0q8/mtp_prefix_caching_still_broken_on_arc_pro_b70/.

## Practical boundary and next trigger

For a one-off unique prompt (32K or full physical 262,144), prefix reuse has no hit and cannot improve that request. For repeated prompts/agents, Strata already restores shared token-prefix snapshots, so the first useful evidence is a closed report of its exact cache-hit/miss, restored-token count, host snapshot bytes/copy/restore time, queue waits and per-phase prefill time on a representative shared-prefix workload. If that evidence identifies cache restore or capacity as the remaining bottleneck, investigate a single cache-policy/lifetime change after source ownership and Level Zero completion rules are proven. Compare no-share and 32K+ identical-prefix workloads, then the full 262,144 physical-context path; include snapshot save/restore transfer and worker stalls in end-to-end TTFT, and demand exact token/state/KV equivalence. That is a trigger for a later question, not a recommendation to alter or retune the existing cache now.

For single-prompt kernel work, wait for root’s current correctness/phase results. Do not promote a generic external throughput number or claim adoption from a B70/Blackwell/CPU result. No prefill candidate is recommended in R118.
