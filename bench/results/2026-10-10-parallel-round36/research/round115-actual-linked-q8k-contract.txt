## What the exact binary establishes

The exact demangled symbol is `_ZN6strata7kernels3cpu16native_quant_actERKNS1_9NativeFmtEPKfPv` at `0x422120`. Its body checks cached `q8k_avx2` state; on the custom branch it compares `NativeFmt.gu_act` with `0xf` (Q8_K), loads `n_embd`, then tail-jumps to `_ZN6strata7kernels3cpu14q8k_quant_avx2EPKfPvl` at `0x446a00`. Otherwise it gets the GGML CPU trait and tail-calls `from_float`. The cache initializer calls `cpu_avx2_ok`, then `getenv("STRATA_NO_Q8K_AVX2")`, and stores true only if AVX2 is accepted and the variable is absent. This agrees with source. Static call reachability is now established for GU22 because the frozen selected format's activation is Q8_K; it still does not show which branch a live run selected. In particular, an environment variable present with value `0` disables the custom path because the code tests pointer nullness.

The captured `cpu_avx2_ok` wrapper at `0x41b830` calls its initializer lambda. The lambda checks cached ISA cap at least 2, CPUID max leaf >=7, leaf 1 bits FMA, OSXSAVE, AVX and F16C (`test $0x38001000`), then `xgetbv(0)` requiring XCR0 SSE and YMM state (`and 0x6`), and leaf 7 EBX AVX2 bit 5. This supports the source's AVX2/FMA/F16C + OS-save gate; the file is compiled for those instructions, and VNNI is not a second activation-quantizer branch. A successful fixture process's existing `cpu_avx2_ok()` prerequisite plus an unset `STRATA_NO_Q8K_AVX2` would establish the custom branch at runtime; these static captures alone do not establish either environment or actual process path.

In `q8k_quant_avx2`, the nonzero-block arithmetic has separate `vmulps` at `0x446d50` and `vaddps` at `0x446d56` (repeated in the loop), with no `vfmadd*` in the captured 216-line body. `vdivss` computes `-127/mx`; a second `vdivss` writes `1/iscale`. The pinned GGML reference body likewise has separate `mulps` and `addps` at `0x6a8c38-0x6a8c50`, then separate scalar divides. Thus the exact emitted IntelLLVM code did not contract the multiply with the magic addition or reassociate the key FP expressions in either captured function. This closes the R113 missing-emission question for this pinned binary, but does not prove runtime MXCSR or numerical equivalence for all possible inputs.

## Quantizer semantics and finite-domain limits

The reference trait wrapper at `0x5b1890` is a direct jump to `quantize_row_q8_K_ref` at `0x6a8910`. It is therefore the pinned scalar reference implementation, though IntelLLVM vectorized its loops in this linked build. The linked reference inner quantization loop visibly executes `mulps`, then `addps` with the magic constant, then branchless masks/saturating packing; it does not fuse the two. The custom path independently loads the same constants from the captured rodata. The constants include `12582912.f`, mantissa mask `0x007fffff`, and the optimized signed clamp bound `0x0040007f`.

The custom body does not literally emit the source's integer subtract-`0x00400000`, then min-127 sequence. It masks the magic-add result's mantissa, unsigned-mins it with `0x0040007f`, then sign-extends the low byte (`vpslld $24` / `vpsrad $24`). This is an equivalent compact encoding on the admitted ordinary domain: the integer offset `0x00400000` is a multiple of 256, so subtracting it does not change the low byte; values below the bias encode negative rounded integers in that low byte, while the unsigned cap limits positive values to +127. The source's FP max normalization bounds normal finite scaled inputs to approximately [-127,127]; with round-to-nearest, the lower endpoint remains representable and the cap reproduces `min(127, nearest_int(...))`. The following `vpackssdw`, `vpacksswb`, and `vpermd` pack and restore the byte order, and the custom code stores the 256 quantized bytes at block offset 4. It computes signed 16-value sums and writes the 16 `bsums` words at offsets 0x104..0x123; the block scale is stored at offset 0. This matches the Q8_K layout and source's meaningful `d`, `qs`, and `bsums` fields for nonzero finite blocks.

The clamp/packing observation is a static semantic derivation, not a numeric bitwise proof. It is scoped to the fixture's finite formula-generated activations: `((i*37 + layer*11 + token*101) % 509 - 254) / 257.0f`, bounded by ±254/257. For each 256-value block the index progression has nonzero entries, so the all-zero block branch is not taken. Such inputs have finite ordinary scale and products bounded near 127, far below the reference nearest-int magnitude assertion. The captures do not qualify NaN/Inf inputs, subnormal inputs, overflow-scale blocks, all-zero stale `bsums` behavior, or all possible mid-point rounding cases. The activation check compares meaningful Q8_K bytes to the linked reference at runtime, but this review does not read that runtime output.

Both magic-add paths depend on the caller's MXCSR rounding control. The linked instructions establish separate rounding points, not that their mode was round-to-nearest-even. The actual-cohort fixture's source check only compares the MXCSR control mask to its entry value; unchanged controls could still begin in a non-nearest mode. Root's next actual-weight run must record the caller MXCSR before input generation/quantization and after GGML initialization, require RC bits 13:14 = `00` for nearest-even, and state the FTZ/DAZ policy. FTZ/DAZ should be immaterial to this particular non-subnormal synthetic range, but should remain logged rather than inferred for broader activations. The no-pool actual-cohort branch quantizes on the caller thread; it provides no worker MXCSR evidence. Do not claim server-wide behavior from it.
