Findings

**No source-level must-fix defect found in the requested factor pairing or selector fallback.** This is a static conclusion only; it does not clear the implementation for adoption.

- `kernels.dp.cpp` adds the factor kernels under `STRATA_GDN_PREFILL_GATE_FACTOR && !__HIPCC__`. I normalized and compared the original and factor body pairs: serial (`gdn_rec_kernel`/`gdn_rec_factor_kernel`), columns, pipelined columns, SG32 quad pipeline, and key-head all match after replacing the old `native::exp(loggate)` load with a direct factor load (`gate[...]`, staged `cg`, or staged `sg[...]`). Other recurrence arithmetic, FMA/reduction order, barriers, local storage, row stores, output and norm inputs are unchanged. The producer is a copy with the same `v`, softplus, multiply and beta expressions; it names the FP32 `loggate` intermediate and stores `native::exp(loggate)` to the same gate slot. This matches the intended “rounded loggate then factor” source boundary. Actual device rounding/codegen and factor-vs-materialized-legacy equality remain unverified.
- The extra factor norm kernel is a renamed copy for the non-quad factor route; quad/tuned key-head use the existing out-norm launcher. No path applies `exp` to a stored factor. All five recurrence reader schedules have factor counterparts; route selection is explicit and factor-only.
- The old public `gdn_gates` / `gdn_recurrence` and legacy kernel bodies are unchanged in the source diff. `gdn_variant.hpp` is byte-identical. With the CMake feature default OFF, the new device families are preprocessor-excluded and prefill's legacy producer/consumer statements remain the compiled branch; the getter still validates the runtime selector. This supports source-level default-off preservation, not binary/kernel identity or ABI proof.
- CMake attaches the private macro to `strata_prefill`, the target containing `prefill.cpp` and resolved `kernels.cu`/`kernels.dp.cpp`. The new private header declarations are unconditional, and OFF/HIP builds retain host API definitions that reject factor use; the macro does not leak publicly from the target.
- `gdn_prefill_gate_factor_enabled` accepts absent/`0`, accepts `1` only in an enabled non-HIP build, and throws for malformed values or unavailable backend/build. Encoded entry points reject unknown encodings, T outside `[0,262144]`, negative T, unsupported variants and unsupported `ld16`; T=0 returns before queue lookup/submission. Factor mode is blocked in feature-OFF/HIP builds. Padded prefill output is refused before GDN producer/conv work whenever `ld_y` would be 6208 instead of the accepted 6144. This keeps the added path out of layouts it has not implemented.
- For SYCL dispatch, the factor wrapper preserves legacy precedence: quad is attempted only for variant 0 when no explicit serial/head/pipeline/key-head/tuned selector suppresses it; pre-submit quad refusal returns false and falls through to the factor serial/columns/key-head path, never the log-gate path. Explicit variant 2 selects the serial factor reader. Serial (`STRATA_GDN_REC_HEADS`), tuned SG16 key-head (only at T>=256), ordinary key-head, columns pipeline and columns are dispatched in the expected order. Malformed `STRATA_GDN_QUAD` is rejected for factor encoding before the gate producer API submits. Existing legacy selector caching/`atoi` semantics are copied; fresh-process selector testing remains necessary.
- The factor quad route checks the exact factor kernel ID/bundle on the active context/device, SG32 and work-group/device limits before submission. Query/admission exceptions/denials fall through; submission, norm launch and queue check are outside the catch, so there is no post-submit retry that could double-mutate recurrent state. Captured bundle lifetime extends through command-group binding; submissions use the caller's queue. The copied kernel retains the old barrier/local-memory structure. No new restrict aliasing, pointer arithmetic, subgroup primitive, local-memory extent, or SYCL API misuse was found by source inspection. This cannot establish compiler acceptance, runtime bundle lifetime, actual device subgroup behavior, or async-error handling.
- `prefill.cpp` selects one encoding before work and uses it at the shared per-layer producer and recurrence site, leaving projections, convolution, output projection and state layout unchanged. Layer-major validates mode at entry and reaches the same shared path. The feature selector is read again in that shared `run_impl`; concurrent environment mutation is not supported or claimed.

One small API-contract point for root to decide

In a feature-ON build, direct calls to `gdn_gates_encoded(DecayFactor,...)` and `gdn_recurrence_encoded(DecayFactor,...)` are permitted even when `STRATA_GDN_PREFILL_GATE_FACTOR` is absent or `0`; only the prefill caller consults the runtime selector. This is consistent with an explicitly typed private test API, but it is not a global runtime lockout. If the intended contract is “no factor submissions unless selector is exactly 1,” add an entry check to the private encoded APIs (and test that OFF/0 refuses before queue lookup); if typed explicit selection is the contract, document and test this deliberate distinction. It does not create a mismatch in the production prefill path, which passes DecayFactor only when the getter returned true.
