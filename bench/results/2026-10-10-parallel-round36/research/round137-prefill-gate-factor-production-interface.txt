R137 — production interface plan for an opt-in prefill GDN decay-factor representation

Status and source boundary

This is a source-level integration plan only. The necessary native-exp primitive has not passed, and no model/context equivalence or adoption result exists. Do not enable this path based on this report. Production call path and scratch lifetime

`Prefill::run` selects `run_layer_major` or `run_impl`; both reach the shared per-layer GDN block in `prefill.cpp` around lines 3645–3669. The current sequence is `gdn_gates(ab, dt, ssm_a, m.gate, m.beta, T)`, `gdn_conv`, then `gdn_recurrence(...m.gate...)`. `m.gate` is allocated as `T * HV` FP32 elements in the chunk scratch region (line 1314); `T` is the current prompt chunk length. The ordinary run path iterates chunks (`c0`/`chunk_len` around line 2957), so this is not an all-context buffer. Preserve this storage and its ownership; a factor representation changes only the values written in its existing gate plane. Leave beta, convolution, state, output, and output layout untouched.

Smallest safe interface boundary

Keep the existing public `gdn_gates` and `gdn_recurrence` signatures and their documented log-gate contract (`log_gate = softplus(ab + dt) * ssm_a`) unchanged. Add an internal, explicitly typed prefill-only pair, for example `GdnGateEncoding::{LogGate, DecayFactor}`, `gdn_gates_prefill<Encoding>` and `gdn_recurrence_prefill<Encoding>`. The public wrappers must continue to select `LogGate`. In `Prefill::run_impl`/the shared GDN layer block, parse one explicit opt-in selector once (proposed `STRATA_GDN_PREFILL_GATE_FACTOR`, default `0`, accepted values only `0`/`1`) and choose one typed route so the producer and every consumer receive the same compile-time encoding. Reject malformed values and refuse factor mode unless the primitive and numeric qualification have explicitly enabled it in that build. Do not add a public caller-supplied factor path that can be paired accidentally with the legacy recurrence.

Make the host choice select distinct template instantiations, not a per-element mode branch. For the producer, preserve beta arithmetic and the current log-gate intermediate/order exactly where required by the primitive qualification, then store either that log gate (`LogGate`) or the qualified `native::exp(log_gate)` (`DecayFactor`) to `m.gate`. For recurrence, specialize every kernel so `LogGate` computes the existing `native::exp(gate)` at the present location and `DecayFactor` loads the stored factor directly. Do not form `exp(factor)`. The selector is uniform host dispatch only; no conditional math branch in element loops.

Consumer coverage that must travel together

The default `gdn_recurrence` wrapper in `kernels.dp.cpp` selects among the scalar/serial kernel, columns pipeline, columns non-pipeline, tuned key-head, key-head, and backend-specific quad route. Factor support is complete only when every selected production kernel has a factor specialization: the scalar/serial recurrence's local gate load; both columns kernels' gate preparation; tuned/key-head staging; and quad kernels if they are in scope for that backend. The pipelined and key-head kernels copy gate values into local/shared staging before exponentiating (e.g. key-head stage around line 1210 then `exp(sg)` around 1240); factor mode must stage factor values and skip that exponent there. Keep selector precedence and kernel routing otherwise identical. AMD-only quad routines, CUDA/native decode routines, and verifier kernels should not silently inherit prefill factor semantics; either leave their legacy signatures/logic intact or make unsupported combinations explicitly refuse. No blanket replacement of every `exp(gate)` in the repository.

Other consumers and compatibility

The header's public gate producer and recurrence remain log-gate APIs. `gdn_recurrence_variant`, reference/parity entry points, quad/key-head variant parity APIs, and existing tests also retain log-gate interpretation, avoiding silent fixture/API changes. Decode uses the separate `core/layer.cpp` native/legacy gate producer with `gdn.dp.cpp` or `native_gdn.dp.cpp`; verifier GDN kernels in `verify_kernels.dp.cpp` consume their own log-gate values. They remain unchanged. Current source search shows production prefill invokes `gdn_gates` at the shared prefill call site; recurrence direct uses are that site plus variant/parity utilities. Any future direct caller of a typed factor consumer must be rejected or kept private so it cannot bypass producer/consumer pairing.

Required compatibility/refusal checks before an implementation can be considered integrated

1. Default-off and absent-selector path routes to the exact legacy producer and consumer wrappers and preserves current public log-gate bytes/behavior.
2. Reject selector values other than `0` and `1`; reject factor selection when build/backend/primitive qualification is unavailable.
3. Unit/parity fixtures passed to legacy APIs remain log-gates and match their current reference results. Direct factor consumer tests must use the private typed API and verify it consumes factors without exponentiating twice.
4. Exercise every selected recurrence dispatch (serial, columns, columns pipeline, key-head/tuned when eligible, quad where applicable) in both legacy mode and qualified factor mode; verify output, final recurrent state, normed FP32/FP16 outputs, guards, and failure/drain behavior. Ensure no dispatch can fall through from an unsupported factor variant into a log-gate kernel.
5. Preserve `T=0`, short/partial tile, final chunk, and chunk-reuse behavior; prove scratch sizing remains `T*HV` and no context-sized allocation appears.

Numeric and real-context admission sequence

First require the private necessary primitive's preconditioned proof: candidate producer stores the FP32 factor that matches the existing consumer's result from the materialized FP32 log-gate, for all targeted input/domain samples and all three recurrence reader schedules (scalar, SG16, SG32). Same source spelling for native exp is not proof: evaluating exp from an unmaterialized producer local may differ from exp of the FP32 value after the baseline global store/load. Preserve explicit nonfinite/domain classification; do not call unobserved inputs model-reachable. Any mismatch blocks integration.

If and only if that primitive passes, add a minimal real-context A/B harness around the shared `Prefill::run` path, comparing one unchanged model/token sequence and fresh equivalent session state between baseline and factor mode. Cover both `run_impl` and layer-major routing where production supports them; multiple chunks and an odd/short final chunk; every supported recurrence dispatch. Compare per-chunk GDN recurrence state, beta, output `y`/`y16`, and final complete state, including convolution history and QSA K/V state, plus final logits/tokens and normal completion. Existing `STRATA_PREFILL_DUMP_STATE` captures the complete recurrent/conv, PLE, indexer and QSA checkpoint state after a run; use it only as the named A/B consumer and retain captures only while that comparison remains current. Add compact per-layer/per-chunk hashes and mismatch counts to the report. Use repeated 8192-token checkpoints and the full physical 262144-token lifecycle with near-end and endpoint checks; completion and equality are required before any default-on decision. Run performance comparisons only after correctness, with identical selector/dispatch/model/input and per-sample results. This plan itself makes no performance or numeric equivalence claim.

The current public GDN recurrence wrapper also contains environment selectors such as `STRATA_GDN_QUAD`, `STRATA_GDN_REC_HEADS`, `STRATA_GDN_PIPELINE`, `STRATA_GDN_KEYHEAD`, and `STRATA_GDN_KEYHEAD_TUNED`; the new representation selector must not rewrite their precedence. Bind encoding at the wrapper level so the existing choice selects the matching log-gate or factor kernel family. `STRATA_PREFILL_LAYER_MAJOR` selects a different scheduling mode, not a different gate contract; the representation switch belongs at the shared prefill GDN block so both routes agree.
