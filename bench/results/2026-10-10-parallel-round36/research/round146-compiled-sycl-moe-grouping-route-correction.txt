# R146 — correction: compiled SYCL MoE route is FP16/GEMM, not MMQ/fused

Date: 2026-10-10 (Asia/Tokyo). Read-only audit of the fixed WPROBE609a270d source and build definitions. No build-tree inspection, compile, test, runtime/model, GPU/profiler, Git operation or cleanup was performed. R142 and R144 are left unchanged as historical reports; this report corrects their compiled-path premise.

## Correction and disposition

The R142/R144 proposal to call the existing `fused::group` implementation from a compiled non-fused MMQ branch is invalid for the SYCL target. `sycl/CMakeLists.txt` source-resolves `gemm.cu`, `kernels.cu`, and `prefill.cpp`, then explicitly adds `moe_fused_stub.cpp` to `strata_prefill` (`:71–90,276–281`). It does not add `moe_fused.dp.cpp` or `moe_mmq.dp.cpp`. The fused stub answers `built/available/enabled/requested=false`, `native_supported=false`; its `group()` aborts if reached (`sycl/src/prefill/moe_fused_stub.cpp:20–35`). In `prefill.cpp`, the `#ifndef STRATA_PREFILL_MMQ` MMQ stub returns `built=false`, `fits=false` and no-op methods (`:67–85`). `mmq_plan()` requires `mmq::built()` for its `on` predicate (`:961–985`), so `STRATA_PREFILL_MMQ=1` at runtime cannot activate MMQ in this build. `STRATA_NATIVE_EXPERTS` is a separate ggml-cpu/native-expert build option; the top-level CMake rejects `STRATA_PREFILL_MMQ` unless HIP is enabled (`CMakeLists.txt:71–86,1131–1135`).

Consequently, for a regular SYCL run whose `ExpertLayout` selects native IQ3S, `use_mmq` is false on every layer and `fused_nat/fused_l` are false. The live path enters the `else` host-group branch at `prefill.cpp:4077`; there is no actual non-fused MMQ route to optimize, and no existing GPU `fused::group` code is available to link. Reports R142/R144 must not be read as an implementation recommendation for a compiled MMQ route.

There is one distinct, possible implementation seam: a new standalone SYCL integer route-group kernel could replace host grouping for the active native-IQ/FP16 fallback. This is a fresh unmeasured candidate, not reuse of a linked kernel. It may be worth a source-only design/implementation review because the existing host path still copies full route IDs to host, forms counts/offsets/order and `slot/src`, then copies route maps back; the compiled FP16/GEMM consumers use those maps. No runtime evidence establishes that route mapping is a material B570 bottleneck or that the candidate is faster. If a standalone kernel is not accepted as a new scope, the correct conclusion is simply to withdraw the transfer candidate until measurements identify another active seam.

## Actual linked route for native IQ3S

`strata_resolve` maps each requested `.cu` to a migrated `.dp.cpp` only when that file is listed (`sycl/CMakeLists.txt:71–90`). Its `_prefill` list names `src/prefill/gemm.cu`, `src/prefill/kernels.cu`, `src/prefill/prefill.cpp` (`:276`), resolving to `gemm.dp.cpp`, `kernels.dp.cpp`, and `prefill.cpp`. Fused functions come from the explicit stub instead. The `_kernels` list does include `iq_kernels.cu`, resolved to `sycl/src/kernels/cuda/iq_kernels.dp.cpp` (`sycl/CMakeLists.txt:249–264`), which supplies the native IQ dequant functions used below. The present `moe_mmq.dp.cpp` and `moe_fused.dp.cpp` files are not members of these targets; seeing them in the tree is not proof they are linked.

For native IQ3S expert layers, `ExpertLayout` provides per-layer native format metadata. In `Prefill::run_impl`, `use_mmq = mmq_plan().any && mmq_plan().layer[l]` (`prefill.cpp:3992–4001`); with MMQ stubs, this is false. The host-group branch at `:4077–4201` currently copies `ids[T*K]` D2H (ordinary vector or the `STRATA_GROUP_COPY` mapped-host path), waits, validates IDs, constructs `cnt/off`, and constructs expert-ID-ordered `order`; it builds `slot/src` and uploads/copies them to device. The expert transfer loop below that branch still uses `order[j]` to choose resident, pinned-RAM, Stager/file or ring-sourced expert blobs (`:4560+`); route grouping does not select blob storage or change expert weight reads.

The path gathers activation rows with `src_dev` for the non-compact fallback (`prefill.cpp:4236–4237`), and the per-expert compute branch sees `lay.native` and calls `iq_dequant_gu_f16` plus `iq_dequant_f16` (`:4778–4785`). These are supplied by the linked `iq_kernels.dp.cpp` (`iq_dequant_f16` around `:4292–4317`, `iq_dequant_gu_f16` around `:4390–4417`). It then invokes `m.gemm.f16` for gate/up, `swiglu_interleaved`, and `m.gemm.f16` for down (`prefill.cpp:4791–4802`). On the SYCL build, `gemm.dp.cpp:750–785` falls through to `dpct::blas::gemm` with FP16 inputs and FP32 accumulation (`:776–783`); its opt-in PF-GEMM and WMMA hooks in that function are guarded by `STRATA_USE_HIP` (`:754–764`). This is the concrete linked route to assess for IQ3S, subject to runtime confirmation of the actual `ExpertLayout` and selected model. It is not MMQ or the fused int8 expert kernel.

Layer-major is a different full-single-GPU compact FP16 route; it requires `m.compact` and rejects split/peer/helper cases (`prefill.cpp:2381–2402`). It is outside the first standalone-group candidate. The CPU verifier/oracle and decode paths do not call this `Prefill::run_impl` grouping seam; do not change verifier or decode routes.

## One qualified standalone candidate

**Candidate:** in the ordinary one-GPU, non-compact SYCL prompt path, replace only route-group mapping inside `Prefill::run_impl`'s non-MMQ host branch with a newly compiled, small standalone SYCL count/scan/place routine. Keep the existing host behavior for validation/fallback, peer/helper/split paths, compact/layer-major, small chunks and any unsupported or failed allocation. Initially target native-IQ3S layers that fall through to dequantized FP16 GEMM; admit other formats only after separate path/correctness review.

The smallest source seam is adjacent to `prefill.cpp:4077–4201`: route IDs and router coefficients already reside on device; a kernel can count expert IDs, prefix-scan expert offsets, and write device `slot_dev/src_dev`. Copy only `E` counts to host and preserve current host ID-ascending `order`, prefix offsets, active-expert and source scheduling, per-expert `ne`, and all later expert-stream/GEMM logic. `src_dev` must satisfy `src[slot[i]] == i/K` for route pair `i`; `slot` must map each route into its expert's contiguous interval. Preserve the existing host error for invalid IDs by reporting an invalid count or verifying copied count sum equals `T*K` before using maps (the current host explicitly rejects out-of-range IDs at `:4118–4122`). `T*K`, `E`, count/offset integer limits, scratch bytes and allocation must be checked before selecting the new path.

The integer group kernels in `moe_fused.dp.cpp` cannot be called from this target: source-resolution excludes that translation unit, the linked fused stub's group aborts, and its workspace API reports zero. A standalone routine must have its own SYCL implementation and be added explicitly to the SYCL target (or kept local in an already linked SYCL translation unit). Importing only the count/scan/place algorithm still requires a new compile, device-code, in-order queue, scratch lifetime, and full SYCL validation; it is not an already validated kernel. The host must wait for the small count transfer before using `cnt/order/off`; `slot/src` placement must complete before gather/GEMM and remain alive through `moe_combine`. Reuse only checked, preallocated scratch that is dead until the following GEMM, or account for a new allocation explicitly. Do not increase 262K lifecycle memory by allocating any full-context route tables: route buffers and scratch are per current chunk and reused.

### Copy bound and uncertainty

On the ordinary non-mapped host-buffer branch, the route payload replaced is `4*T*K` bytes of IDs D2H plus `8*T*K` bytes of `slot/src` H2D; the candidate instead returns `4*E` bytes of counts D2H. Thus the maximum explicit copy-byte delta is `12*T*K - 4*E` per invocation when positive. This is a source-derived upper-bound formula, not a bus counter or timing result. Under `STRATA_GROUP_COPY` the existing arrays use mapped pinned host memory and GPU `copy_i32` kernels, so physical fabric traffic differs; record that arm separately and do not claim the same PCIe-byte saving without counters. The new group kernel still reads all IDs and writes all route maps on GPU, so it removes round trips and host O(TK) loops, not route-array work or expert-weight traffic. No quantitative speed effect is established.

### Correctness obligation

Atomic placement changes row order within each expert relative to the current host fill loop. For route pair `i` with expert `e=ids[i]`, require `off[e] <= slot[i] < off[e]+cnt[e]`, `src[slot[i]] == floor(i/K)`, every route appears once, and `off[e+1]-off[e] == cnt[e]`, `off[0]=0`, `off[E]=T*K`. `gather_rows16` then supplies the same FP16 activation row for each expert-route pair. Native IQ dequantization and the oneMKL GEMM shapes/weights remain unchanged; `swiglu_interleaved` is rowwise; `moe_combine_kernel` uses `slot` and accumulates the ten routes in fixed `k=0..9` FMA order (`kernels.dp.cpp:1893–1917`). These support the inference that a consistent within-expert permutation should preserve each route's values and the combine association, but oneMKL/GEMM bitwise invariance is not established by this source inspection. Require correctness-only per-route de-permuted product comparison, combined output/logits and full state/logits over the 262,144-token lifecycle before timing admission. If any route product or model-visible value differs, do not call it harmless row-order change.

## Minimal discriminator if root chooses to pursue it

First prove target selection using source-derived counters at each layer/chunk: native format type, `mmq::built`, `mmq_plan.any`, `use_mmq`, `fused::built/enabled/native_supported`, and chosen expert branch. This confirms an ordinary IQ3S request reaches the measured host-group → IQ dequant → FP16 GEMM path; do not infer that from a source file alone. Then compare baseline and opt-in standalone grouping with identical >=32K input/model, chunk/cache/ring/source configuration and warm state. Record per layer/chunk host route-group time, old route ID/map transfer bytes and count-copy bytes, group kernel time, wait, active expert and row-count histogram, source-kind/streamed-weight bytes, IQ dequant, gate/up GEMM, SwiGLU, down GEMM and end-to-end prefill. Test small/last chunks and scratch-cap fallback, then the physical 262,144-token lifecycle. The decision depends on correctness, evidence that the new branch executed, and end-to-end improvement beyond run variation; this audit does not claim a hotspot or speedup.
