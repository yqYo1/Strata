# R284 — default task-0 decode worker-service instrumentation contract

Date: 2026-10-10 (Asia/Tokyo). Read-only source and evidence contract. No implementation, build, test, model, GPU, profiler, PMU, Git operation, source edit, environment dump, service action, or cleanup was performed. This report is the only new artifact.

## Finding

The minimum useful join is a default-off diagnostic that measures, on each pool participant, wall and that thread's CPU time around each actual native GU/Down row-kernel call fragment, and joins those spans to the actual layer, role, `NativeFmt` type, `ExpertJobMulti.nt`, output-row range, and request/window. Add one caller-side exposure count per expert job and `nt` before submission, then reconcile the worker fragments against those exact counts after the phase. The caller count is necessary because row tasks are flattened ranges and can cross expert boundaries; a claimed task ID alone is neither a job nor an NT cohort.

Keep three quantities distinct: kernel-call CPU time (scheduled service of the calling worker), kernel-call wall durations (which can include preemption), and the phase critical envelope (earliest worker kernel start to latest worker kernel end). Their sums are useful for worker service/work distribution but must not be described as phase latency. Time in `claim`, row-range setup, waits, caller quantization, and callback planning belongs in separately labeled bins. No counter may change row grouping, the automatic task count, NT, kernel math, work selection, or ordering.

This extends the service-time idea in R215 with the correction in R282: use actual per-layer/per-window job counts and do not join marginal GU22/Down20 totals as if they were paired layers. The prior 68.5–75.3 ms/output values were already per emitted output; do not divide them again. They remain descriptive for the task-0 32,769-position diagnostic, not a current production service rate.

## Minimal instrumentation contract

1. **Enablement and identity.** Introduce one explicit, default-off diagnostic switch, frozen when the pool/request is initialized. Assign a monotonic request ordinal and per-request verify-window ordinal at the request/verify boundary, plus existing prompt length, emitted token count, and `d.layers`. Carry only a compact immutable key through the existing phase publication; do not add a callback or inspect task 0 as a different scheduling mode. Record the configured task value (`0`) and actual `n_tasks` per phase.
2. **Caller exposure, once per layer-window.** Just before `run_split_multi_native`, inspect the already-constructed `ExpertJobMulti` array once. For each actual `nt`, count distinct CPU expert jobs, sum `nt` CPU expert-token rows, and record GU and Down `NativeFmt` types from this layer's `NativeFmt`. Preserve the pair `(gu_type,d_type)` at that layer. Include zero/absent NT bins only as absent; do not infer NT3/NT4 service from fixture capacity. This is a bounded `MAXT` histogram, not per-token logging.
3. **Worker kernel fragments.** In `pool.cpp` `drain`, after resolving `e`, `[r0,r1)`, and `mjobs_[e].nt`, place a wall-clock and current-thread CPU-clock pair immediately around each call to `native_gu_rows` or `native_down_rows`. The cell key is `(request, window, layer, phase/role, format type, nt, worker-or-host slot, actual branch if captured)`. Add one record for each contiguous expert-local fragment; a task spanning experts emits separate fragments with each expert's own NT. For Q2 branches, use a distinct Q2 category and time the two GU row calls separately or as an explicitly named GU pair; never label them IQ4NL. Capture `[r0,r1)`, expert/job ID, task ID, `nt`, logical rows, call count, CPU ns, wall ns, and first-start/last-end. For GU, state whether rows count logical FF output rows or the two gate/up matrix products; retain both range and convention.
4. **Actual branch identity.** Type + NT is mandatory. If the report is to name a specific selected implementation, write a small branch enum at the actual dispatch branch in `native_expert.cpp` (GGML, IQ512, IQ256, IQ4NL256, KQ256, Q2, fallback). Avoid a second approximation from CPU feature flags: hybrid affinity or runtime overrides can make a machine-wide guess wrong. Branch IDs are optional for answering per-format/NT service and should be omitted until they can be recorded without a shared hot-path counter.
5. **Non-kernel bins.** Around each worker's `drain` invocation, capture total drain-loop CPU and wall time into a worker-owned phase slot. This includes claim/setup/bookkeeping and native fragments but stops when `drain` returns; it excludes time parked between phases. Measure the three wait sites in `run_phase` separately with steady wall time: pre-publication `wait_parked`, `wait_done`, and post-phase `wait_parked`. Keep host drainer as its own slot. Keep serial `native_quant_h`/`act_quant_any` time on the caller as quantization, and do not fold it into worker GU or Down service.
6. **Bounded storage and reporting.** Allocate fixed cells before worker start, with dimensions bounded by `pool_slots=(n_workers+1)`, two row phases, `MAXT`, a compile-time set of dispatch branches, and the model's bounded layer count. A compact 32-byte cell for per-worker `(count:u32, rows:u32, cpu_ns:u64, wall_ns:u64)` has a conservative upper bound `layers × 2 × (n_workers+1) × MAXT × branch_count × 32`; for 64 layers, 8 workers plus host, MAXT=8, 7 branch IDs this is 2,064,384 bytes. Store first-start/last-end once per worker/phase in a separate small bounded record, plus wait/job histograms. Allocate once; no per-job vectors or logs. Make overflow, unsupported clock, and incomplete cells explicit invalid statuses, never zero-time success. If one fixed table is larger than the agreed cap, aggregate after each synchronous phase into a fixed report buffer while preserving layer/window keys; do not silently drop or merge keys.
7. **Hot-path discipline.** Worker writes only its own padded record. No lock, shared `fetch_add`, allocation, `fprintf`, flush, or shared-head writes during `drain`; no new clock calls in the default-off path. Existing completion acquire/final re-park boundaries are the only reader synchronization. Use the existing per-layer serial call order so a cell can be finalized once workers have completed the phase. Preserve all mode/NT/math and job arrays byte-for-byte on the disabled path.
8. **Clock meaning and overhead.** Linux `CLOCK_THREAD_CPUTIME_ID` is per-calling-thread CPU time; Windows `GetThreadTimes` reports thread kernel and user execution time. Pair it with a monotonic/steady wall clock. CPU time captures scheduled service, including time stalled while executing, but says nothing about retired instructions or memory-controller bytes; wall includes preemption. Linux reference: [clock_gettime(3)](https://www.man7.org/linux/man-pages/man3/clock_gettime.3.html). Windows reference: [GetThreadTimes](https://learn.microsoft.com/en-us/windows/win32/api/processthreadsapi/nf-processthreadsapi-getthreadtimes). Calibrate the clock helper on the host and compare timer-off, counters-only, and clocks-on cohorts on identical inputs. Predeclare an overhead ceiling and invalidate a clocks-on performance claim if the diagnostic changes request/phase behavior or crosses the ceiling; report only the component attribution.

The required summary is per layer-window and exact `(gu_type,down_type,nt)` pair: submitted distinct jobs and expert-token rows; worker/host kernel-call CPU sum; per-worker wall-call sum; first-start/last-end phase envelope; active drain CPU/wall; wait-before/wait-done/repark wall; caller quantization CPU/wall; rows/fragments/calls; exact validation and timing validity flags. Keep sums and envelope in separate columns: sum of parallel-call wall durations is not elapsed phase wall. Reconcile total job and token counts to `jobs_multi`; reconcile the sum of fragment rows to phase output rows. Report CPU times as thread CPU time, not process CPU or busy percentage.

## Acceptance gates and claim validity

- First validate counters-only with a deterministic host pool fixture containing multiple experts, multiple NTs, a task boundary inside an expert and a task spanning experts, host drain on/off, empty phase, and each branch that is present. Require unchanged outputs, no lost/duplicated jobs, exact job/row reconciliation, and disabled-path parity. This report authorizes no implementation or run.
- For attribution, pair clean diagnostic-off and diagnostic-on requests with the same default task-0 settings and weights. Retain prompt, emitted-output, verify-window, layer, NT, format-pair, per-worker, waits, and checksums. The joined per-layer GU/Down pair and same-request identity are required; separate task-6 route data is not a substitute. Keep the performance result from diagnostic-off only.
- Report the input actually consumed, not only `--max-context`. A 32,769-position input supports only that measured context; setting capacity to 262,144 does not qualify a 262,144-position run. A claim above 32K requires a new closed run whose prompt/model state actually reaches the claimed position and whose decode continues there; a physical 256K claim requires actual 262,144 positions in the model input/state. Preserve the ordinary default task-0 routing, same NT and layer-format capture, cache/restore state, and complete output/correctness/lifecycle gates. Do not extrapolate service from capacity tests, task-6 histograms, average emitted tokens, logical packed bytes, or synthetic activation fixtures.
- Per-layer NT bins may be sparse. The earlier closed task-6 histogram reached NT2 only; NT3 and NT4 are absent there. The actual-weight service fixture's NT1–NT4 values are capacity controls, not online production rates. Report absent bins as absent. Mean MTP acceptance and marginal GU/Down counts cannot be multiplied into a layer-pair count.
- With no admitted same-interval PMU/uncore counters, CPU time and wall can distinguish scheduled worker service from waits, but cannot prove instruction throughput, cache behavior, or physical DRAM saturation. R282 records PMU unavailable (`perf_event_paranoid=4`, no effective CAP_PERFMON); do not substitute stream bandwidth or byte arithmetic.

## Decision

Proceed, if source work is later authorized, with the caller-side NT histogram and the per-fragment worker CPU/wall pair as the minimal useful service join. Keep active drain and waits as separate diagnostic categories to explain their difference from kernel service. Emit `request/window/layer/(GU type,Down type)/NT` identities in the same receipt, preserve actual task-0 configuration, and use bounded preallocated cells. Branch enums are a later refinement if per-NT service identifies a cohort worth explaining. This instrumentation can determine where scheduled service and elapsed waits accrue; it cannot on its own prove a hardware bottleneck or optimization opportunity.
