## Boundary invariants in D

With `STRATA_PREFILL_LAYER_MAJOR=0`, `Prefill::run` selects `run_impl` (lines 2435–2447). `chunk_len(c0)` is `min(m.T,n-c0)` when first-chunk is disabled; the loop advances by exactly that returned length, sets absolute `p0=pos0+c0`, then walks layers in order for the chunk (3031–3037, 3076–3086, 3643–3649). The 12K test must prove the initialized and selected `m.T` stayed 12,288: the caller may shrink a fixed request on admission, and `--prefill 12288` alone does not prove the selected size. The controller's intended progress protocol is exactly `[12288,24576,32767]` for `n_batched=32767`; record its actual `selected_chunks`/headroom evidence and protocol result.

The state-carry invariants are specific:

- PLE n-gram rows start from the two carried `ss.ple_prev` tokens, then consume `tokens[c0..c0+T)` in order. `prev` is advanced once over the chunk and saved at the end; the next async gather uses the same prefix and token sequence (3023–3050, 3249–3257, 5392). Each row is gathered before layer 1 consumes it. Chunk size may change GEMM M for batched PLE projections; the PLE input history and per-position row order must not change.
- Each non-QSA layer's GDN uses its existing layer state and convolution tail, projects T rows, applies convolution for T rows, then recurrence for those T rows before the output projection (3795–3811). Chunks must be serial in position order; no state reset is valid at c0.
- QSA step records use absolute positions `p0+t` (3260); K/V RoPE and append use `p0,T` (3824–3830, 3861–3889). Indexer append uses the same absolute `p0` and appends the entire chunk before scoring its queries (3898–3917). Selection is in bounded query batches, with the last query determining the active block range; an incomplete block is represented by `dead` until completion (3919–3936 and comments 3898–3900). Preserve this exact prefix/tail interpretation at boundaries; the batch append order and `dead`/pooled transition are correctness invariants, not floating tolerances.
- `pos0` and c0 are distinct concepts: chunk starts are relative to this prompt slice, while rope, KV and indexer operate on absolute positions. In the fixed fresh case both start at zero; future resumed cases must not conflate them.

For an input length of 32,768, the conditioned positions are `[0,32767)`: chunks cover `[0,12288)`, `[12288,24576)`, and `[24576,32767)` (lengths 12,288, 12,288, 8,191). Position 32,767 is deliberately processed by the token loop as the first prediction point, not by batched prefill (`generate.cpp` 11672–11682). At maximum prompt length 262,144, the conditioned prefix has 262,143 rows: 21 full chunks (258,048 rows) and a 4,095-row tail, then the final prompt token is handled by the token loop. This does not prove 256K occupancy or tail correctness; keep full-context lifecycle gates separate.

## Numerical tolerance versus acceptance

The D source explicitly labels QSA tensor-core block scores as 3x-TF32, “FP32-level, not bitwise” (3925), and the full-chunk QSA prompt-attention kernel as FP32-level but not bitwise (4064–4068). Chunk M also changes for native/BF16 projections, and the batched PLE key/value GEMMs use `nb` derived from the chunk/PLE scratch region (3658–3685); different GEMM M can select a different implementation or reduction schedule even with unchanged weights and mathematical rows. The shape dependence makes a small local numeric delta plausible. It does not supply a numeric tolerance for end-to-end state or outputs. The source has no general “12K numerical tolerance” contract.

The current controller is deliberately stricter than a local FP32-level kernel comparison: `same_output` requires exact IDs, logprob protocol strings, MTP counts, and finish reason; the first-head floats compare by SHA; all 66 live state parts compare by byte hashes (padding-only differences are excluded by the state comparator); and actual chunk endpoints must match exactly. Therefore do not turn a tensor-core comment into permission to waive state/output checks. If a kernel-local follow-up is needed, report per-position max-absolute and RMS error against the same row/position in an independently identified baseline, plus QSA selection-ID agreement and score margins around any changed top-k. Such metrics characterize a local reduction delta; they cannot substitute for the current exact output/state acceptance. In particular, a changed selected cell is a discrete semantic divergence even if its score delta is small. Large head/state changes or token ID changes are not explained by the phrase “FP32-level.”

## Failure localization if the gate reports a mismatch

The current capture is end-of-prefill only. Its serialized 66-part state lets a receipt classify the first differing channel, but not the exact chunk/layer at which it first diverged. The serializer writes `ple_prev`, GDN state, PLE state, and indexer `tails`, `dead`, `block_pos` first (parts 0–5); then, per QSA state ordinal, K, V, K-scale, V-scale, and pooled index keys (five parts per state; dump order in lines 2464–2477). Use the first differing *live* part as the channel locator, not only the aggregate count:

| Earliest live part(s) | First channel to inspect | Boundary discriminator |
| --- | --- | --- |
| 0 / 2 | carried PLE token history / PLE convolution history | Compare carried two-token prefix and PLE rows entering layer 1; then compare history after each boundary. |
| 1 | concatenated GDN state/conv state | Identify first changed GDN layer and whether convolution tail or recurrent rows first differ; the end-state aggregate alone cannot identify that layer. |
| 3–5 | QSA indexer tail, dead block, or block positions | Compare step positions, append count, tail-to-pooled promotion, and selected IDs at the first changed prefix. |
| 6 onward | QSA ordinal's K/V, scales, or pooled keys | Map ordinal to its QSA layer; compare pre-append K/V at identical absolute position, then indexer selections and attention output. |
| no live state difference, head hash differs | prefill head/residual path before stored state | Compare per-chunk final residual rows and then first changed layer/operation; the controller's state-only pass can miss an activation-only delta. |

To establish *earliest* divergence, take matched prefix checkpoints at 12,288, 24,576, and 32,767 conditioned tokens for both 8K and 12K with the same fixture and initial state; find the first prefix whose live state differs. Then bisect the layer/channel inside that prefix, preserving exact input rows and state entering the slice. D currently exposes `STRATA_PREFILL_DUMP_STATE` only after the whole `run_impl`, not at each chunk or layer (2451–2480); `STRATA_TRACE` reports chunk/layer range, not numerical state (3079–3082). Thus the present final capture alone cannot identify an earlier boundary or layer. Any added capture must be treated as a diagnostic rerun with a separate receipt, not as evidence already present in the current gate.

The route-census and service-ledger streams are explicitly OFF in this test and their additions do not alter math. Preserve that matched configuration for the gate. If a later failure needs route diagnosis, use a separately pinned diagnostic run and compare exact routed expert IDs/weights at the first changed layer; do not attribute a downstream state shift to GEMM until route/indexer decisions are checked.

## Concrete type and extent checks

For the requested sizes there is no power-of-two or 256-row precondition in the reviewed allocation path. `m.T` is the supplied chunk and `m.T_max` records it; scratch sizing/carving multiplies size_t extents and `Alloc::take` accounts byte extents in uint64_t, while `prompt_attn_batch` and QSA selection use `min` for short tails (1053–1057, 316–340, 912–931, 1117–1119, 1290–1345). The visible narrowing candidates are `embedding_gather_dev(...,(int)T,...)` (3154) and `native_ple_postops_batch(...,(int)nb,...)` (3684). At the 12,288 chunk (and 4,095 final chunk) they fit signed 32-bit exactly; the absolute prompt positions through 262,143 also fit signed 32-bit QSA step fields. These do not justify unbounded user-supplied chunks: the source has no nearby `INT_MAX` guard at either cast, and generic `T * width` sizing expressions assume a size that will not overflow `size_t`/the uint64 byte count. Those generic extremes are not implicated by fixed 12K or 256K prompt length because allocation T remains 12K.

A concrete unrelated buffer guard is present for fused MoE: fused layout is only safe at the chunk size used to size it, and D errors if a slow/non-fused expert path would write a full T*K rows into smaller fused buffers (4145–4156). The R285 environment keeps the fused route off; if a receipt shows it on, that invalidates the intended matched configuration and is a setup failure, not a numerical tolerance case. No reviewed D guard identifies 12,288 itself as unsupported for the selected ordinary path. Conversely, this static review cannot prove the runtime backend's GEMM or allocation behavior; the run's selected-size, allocation, and full mathematical receipts remain required.
