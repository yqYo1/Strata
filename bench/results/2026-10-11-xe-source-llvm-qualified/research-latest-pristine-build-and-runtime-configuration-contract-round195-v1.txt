    cmake --build /path/to/build/upstream-sycl --target strata

The CMake default is SPIR64/SPIR-V with runtime JIT. `STRATA_SYCL_AOT` is the existing AOT switch: nonempty values select `spir64_gen` and pass `-device <value>` to the AOT backend. For Xe2 BMG, the file adds `STRATA_XMX_SG16` for a `bmg...` target. The source comments cite `bmg-g31` for Arc Pro B70; do not infer an exact B570 AOT target or tool support from that example. Default SPIR-V is therefore the source-supported baseline, not a claim that runtime JIT is safe.

Every translation unit and link uses `-fsycl`; both compile and link force `-fsycl-device-code-split=per_kernel`. The default JIT link also sets stateless addressing and correctly rounded divide/sqrt. These are existing correctness/configuration choices, not switches to exclude a kernel from the runtime's enumeration. `STRATA_SYCL_PARITY=OFF` can trim parity-only build work if present, but does not affect executable startup. There is no license/free/contrib switch in this CMake project. It unconditionally appends `-qmkl=sequential` for `strata_prefill`; whether this custom clang driver accepts that Intel driver option is unresolved by this source-only audit. The installed oneMKL alone does not prove that it does. Record the configure/build command and actual compiler diagnostics if this route is attempted later.

    cmake -S /path/to/pristine/XeStrata -B /path/to/build/xe-free -G Ninja \
      -DCMAKE_BUILD_TYPE=Release \
      -DCMAKE_C_COMPILER=/home/yayoi/ghq/github.com/MistVVK/XeStrata/.worktree/fix-xestrata-e32-host-handoff-20261011/.tools/intel-llvm-v711/install/bin/clang \

      -DCMAKE_EXPORT_COMPILE_COMMANDS=ON -DSTRATA_GGML_DIR=/path/to/the/3cf03257.../llama.cpp \
      -DSTRATA_LICENSE=free -DSTRATA_ENABLE_XE=ON \
      -DSTRATA_CUDA_ARCHS= -DSTRATA_HIP_ARCHS= -DSTRATA_ONEMKL=OFF
    cmake --build /path/to/build/xe-free --target strata

      -DCMAKE_BUILD_TYPE=Release \
      -DCMAKE_C_COMPILER=/home/yayoi/ghq/github.com/MistVVK/XeStrata/.worktree/fix-xestrata-e32-host-handoff-20261011/.tools/intel-llvm-v711/install/bin/clang \
      -DCMAKE_CXX_COMPILER=/home/yayoi/ghq/github.com/MistVVK/XeStrata/.worktree/fix-xestrata-e32-host-handoff-20261011/.tools/intel-llvm-v711/install/bin/clang++ \
      -DCMAKE_EXPORT_COMPILE_COMMANDS=ON -DSTRATA_GGML_DIR=/path/to/the/3cf03257.../llama.cpp \
      -DSTRATA_LICENSE=contrib -DSTRATA_ENABLE_XE=ON \
      -DSTRATA_CUDA_ARCHS= -DSTRATA_HIP_ARCHS= -DSTRATA_ONEMKL=ON \
      -DMKL_ROOT=/opt/intel/oneapi/mkl/latest
    cmake --build /path/to/build/xe-contrib --target strata

Replace the abbreviated GGML argument with the full path above. Empty CUDA/HIP architecture settings prevent auto-detection and avoid irrelevant NVIDIA/AMD toolchains. Free and contrib do not have equivalent dense kernels: free uses XeStrata's own Xe kernels; contrib selects oneMKL through oneMath. Treat these as separate backend configurations, not a controlled comparison of an otherwise identical implementation. The existing R348 recipe used tests ON; test targets are unnecessary for the minimal `strata` executable build and were not run here.

Runtime failure and available controls
--------------------------------------
In pristine Xe, startup launches a background routine which enumerates `sycl::get_kernel_ids()` and requests an executable bundle for each ID, catching individual exceptions as skips. `wait_preload()` synchronizes later probes; it is not a disable switch. No `STRATA_PRELOAD_KERNELS` environment handling exists in this source. The sweep is part of the `strata` runtime path, so choosing only target `strata`, disabling tests, selecting free/contrib, or disabling native experts cannot bypass it.

The upstream port has no matching preload routine in its SYCL `src/` or `include/` tree, so the Xe-specific startup behavior should not be attributed to upstream without evidence. It still has device kernels that may be compiled on demand; this audit makes no runtime success claim for either tree.

`-fsycl-device-code-split=per_kernel` is already active in upstream, but the runtime loop still enumerates every kernel ID. It limits image grouping; it does not filter the loop. AOT could move compilation into the build and may change runtime module behavior, but the existing source does not make it a supported workaround for this sweep, and AOT itself must be qualified against the installed compiler/backend/device. No Xe root-CMake AOT option was found. Therefore do not present AOT, per-kernel splitting, or a `strata`-only build as a fix for PackedA startup failure.
