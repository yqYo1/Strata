## What the source markers mean

`PfTimer::mark` (`prefill.cpp:1174-1214`) records a timing event on every call. It reuses event objects after each fold, but it does not coalesce repeated phase markers: each call records an event and increments the call count. `fold` asks elapsed time for every adjacent pair and attributes the interval to the earlier marker's phase; it runs only after a compute-stream sync. Thus repeated same-phase marks still generate queue records and measured intervals. The interval can include gaps while the host prepares/submits later work, waits, and compute-stream idle time. It is neither an exclusive kernel duration nor a copy-stream duration. In the 32K receipt, the large mark-call wall is material evidence that this observer itself is expensive; subtracting it from a phase bucket would be unjustified.

The expert order and grouped work are separate from timer coalescing. Routing produces expert counts and an order; compact/native group paths may gather or dequantize a group and then run products, while individual paths mark around each expert (`prefill.cpp:2240-2290, 2390-2570`). Sorting or grouping changes which work falls between phase marks, but does not suppress timer `event_record` calls. The current coarse markers cannot split host grouping, dequant command submission, device execution, and waits into exclusive costs.

## Inline issue and ring lifetime

Fullstream issuance is active only for `m.ring > STAGE`, `T >= STREAM_ALL_MIN` (2,048), and a non-null source (`prefill.cpp:1380-1390`). The chunk creates an ordered `seq` of nonresident experts, in layer and expert-ID order, and starts the stager for unpinned/transient blobs (`1391-1426`). `STRATA_PREFILL_ISSUER` defaults on. With it set to zero, `threaded_issue` is false and the launch thread calls `issue_until(ring)` before layer work and thereafter through `give_back`; with it enabled, a producer thread submits the same sequence, waits on atomic issue/consume credits, and publishes `a_issued` only after queue submission (`1452-1554`).

Each issue uses `k % ring` as its slot. The copy queue submission waits on that slot's last `used` event when necessary, copies the blob, and assigns `m.copied[slot]`; the consumer waits for the copied event on `m.cs`, launches the GPU reader, and records `m.used[slot]` after that reader. Skipped entries also queue a used event before giving the slot back. Reuse is therefore guarded by stream dependencies and sequence credit, not by host timing markers (`1452-1499, 1546-1554, 2500-2558, 2780-2826`). The issuer join guard stops and joins the producer before draining compute and copy queues on unwind. Normal completion joins the thread before stager drain; chunk transfer/census publication follows (`2905-2925`).

The non-timing events used for `copied` and `used` are mutable ring-slot synchronization state, and are overwritten/re-recorded as slots wrap. They must not be read later as stable per-copy timing records. `gpu.cpp:331-382` confirms elapsed-time queries reject events created without timing; `event_record` on a timing event submits a profiling tag, while normal copy/compute operations remain asynchronous. A diagnostic must own distinct timing events and keep them alive until the existing chunk drains have completed.

## Lowest-load useful discriminator

First retain the existing opt-in `STRATA_PREFILL_TRANSFER_COUNTS` route/byte census and the already sampled inline-vs-threaded setting as the zero-new-event baseline. That census counts transfer bytes/routes and does not measure completion or device service; it can show whether the sampled chunk had the expected nonresident traffic, but it cannot resolve the phase-time ambiguity on its own.

For a timing discriminator, the narrow next source change is a fixed, opt-in sample set per chunk, not another per-command timer. Select by deterministic stream sequence ordinal and layer: the first eligible transfer and the first ring-wrap reuse (ordinal `ring`, slot zero) for the copy queue; select the matching first and wrap GPU-consumed expert/group for the compute queue. Emit two timing tags around each selected copy submission and around each selected compute group after its copy wait. This is four samples / eight timing events per chunk, independent of token/expert count. Record the selected layer, expert, ordinal, slot, group mode, and bytes next to the sample. The two copy samples include queue-dependency delay if the preceding slot use is still outstanding; label that as copy-queue interval, not DMA-engine time. The compute sample brackets the queued dequant/product group after its `m.copied` wait; it includes the stream's queued work and host submission gaps, not an isolated kernel time. Do not add event synchronizations in the issuing or consuming loop.

Keep the timing events in a dedicated fixed array owned by the chunk, separate from `m.copied`, `m.used`, `PfTimer::ev`, and any event reused across ring slots. Only after the issuer has joined and `chunk_stager_done.complete()` has drained both streams, read elapsed values and destroy the sample events. No sample event may be recycled before that point. If a path has no nonresident entry, no ring wrap, no GPU group, or no timing support, mark that sample absent with a reason rather than shifting the ordinal or inventing a substitute. Use the same exact prompt shape, ring size, compact-mode setting, and source as the closed comparison; record quiet baseline and instrumented sample status separately. This is still an intrusive diagnostic, so compare only within that diagnostic configuration and do not call it a production timing.

This small sample can discriminate whether the selected copy-queue interval, selected compute-group interval, or host-side grouping remains long enough to justify a broader trace. It cannot estimate all expert work, infer total H2D bandwidth, isolate individual kernels, or prove a critical path. If broader kernel attribution is then needed, the pinned v711 `unitrace` source audit in round 166 documents a health-only interposer path and its caveats: callbacks can add timestamp events to launches without signal events, allocate event pools in 1,024-event blocks, change scheduling, and can assert/fail rather than degrade. That report only admitted a tiny health workload, not a Strata graph; no unitrace result is inferred here. A workload-specific pass needs separate admission after active GPU work closes and a bounded trace/output policy.

## Implementation and acceptance boundary

The minimum change should be confined to opt-in sample selection, a fixed event array, serialization of sample metadata, and post-drain elapsed reads. Failure to create/record/read an event should fail the diagnostic explicitly without converting the request's original result to PASS. Test both `STRATA_PREFILL_ISSUER=0` and `=1`, with a ring-wrap case and a no-wrap case, and verify selected ordinals/slot lifetimes and output equality before interpreting intervals. The selection must not add waits, change `seq`, regroup experts, alter slot-credit order, or move existing copy/compute submissions. Build/test/GPU validation were not run for this source-only report.

No conclusion here ranks host grouping against dequant device service or copy service. The closed phase buckets are coarse and the marker path costs tens of seconds at 32K. The proposed bounded sampling is only a discriminator for the next measurement decision.
