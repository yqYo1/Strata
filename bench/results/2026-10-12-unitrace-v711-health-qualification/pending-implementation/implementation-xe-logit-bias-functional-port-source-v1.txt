Behavior and request admission
INFO reports logit_bias=1; native GEN/GENI accept one logit_bias=id:value,... option.
HTTP accepts object token IDs to finite [-100,100] biases, or pair lists where false means a ban.
Reject bool IDs, nonintegral/negative/out-of-vocabulary IDs, duplicate normalized IDs, malformed values, NaN/infinity, out-of-range values and all-vocabulary bans.
Native parser checks strtoul overflow, embedded NUL, duplicate IDs/options, full value termination, finite double range and exact -100 before FP32 conversion.
HTTP uses .17g round-trip decimal transport; a finite near -100 penalty cannot become a hard exclusion in transport or FP32 conversion.
Only exactly -100 is mapped to negative infinity. Finite FP32 -100 from a near-boundary input remains finite.
Bias is applied before penalties, top-k/top-p/min-p/temperature/pick at all three Xe target sampling sites: greedy, ordinary top-k and large-vocabulary stage 1.
Explicit bans bypass penalty arithmetic so zero/negative repeat penalties or +infinity raw logits cannot resurrect a banned token.
Input logits are read, never mutated. The null-bias branch calls the original penalty arithmetic directly.
The default SamplerParams pointer is null. Unbiased requests do not allocate a bias buffer or add a bias transfer/wait.
Each valid request constructs an empty req_bias unless explicitly supplied; empty bias clears previous request pointers after prior readers drain.
Same dense bias reuses the completed allocation without copy; a changed bias uploads into the persistent allocation.
Configured/shared sampling defaults and non-None request overrides are validated with the same merge as Service.run. An explicit empty object/list clears configured bias; None retains defaults.
Chat Completions and Responses validate before SSE headers. Direct StrataEngine generate/generate_batched also validate capability/batch before sending.
Nonempty bias is intentionally unsupported in continuous batching, rejected by server and native parser before request state mutation. INFO capability plus batch rejection matches upstream scope.
Default old engine requests without bias remain allowed; unsupported nonempty bias produces a clear engine-capability error.
The native parser checks request bias before embeddings/token admission/prefill/session mutation. Transfer/allocation failure during request setup prints ERR and exits; there is no retry on a possibly partial upload.

Allocation, queue ordering, graph and teardown ownership

Final target stage only: set_logit_bias forwards through next_, uses OnDevice(device_), and refuses active/capturing changes.

Pipelined parity verifiers each own their own buffer/event; earlier non-head stages allocate none. Device bytes remain allocated until verifier teardown, including after clear.
Host completed dense state and pending upload source are member-owned vectors. GEN also temporarily owns its parsed dense vector; these host bytes are additional, not asserted physical GPU fit.
Before replacing/clearing storage, gpu::stream_sync(cs_) completes prior sampling readers on the actual final-stage stream.

Runtime::create_stream in src/core/device.cpp constructs in_order queues; compute and transfer queues are also in_order. The event barrier follows the copy on the SAME queue.
gpu::q resolves the actual stream owner independent of current device; event_sync uses owning Runtime::wait, which waits_and_throw and checks async errors.
Host staging is swapped/cleared only after successful completion. Failed drain/upload/event wait poisons state; run/pl_launch/pl_finish refuse reuse.
