## Current sequence and ownership facts

For `stream_all` (`m.ring > STAGE`, `T >= STREAM_ALL_MIN`, source present), the chunk builds `seq` in layer then expert order, excluding host-resident experts. Each entry is direct-pinned when `job < 0`; `job >= 0` means it goes through `Stager`, either because the source is transient or because `ExpertSource::pinned` is false. Transient entries have no source blob pointer; the stager calls `copy_blob`. Non-transient unpinned entries have a source pointer which the stager copies. The stage buffer selected by `Stager` may itself be pageable when host allocation fails or `STRATA_TEST_PAGEABLE=1`; this is a separate property from the source entry being direct-pinned. Source: `prefill.cpp` around 1386–1475 and `Stager::init/work` around 271–343.

Inline mode first calls `issue_until(ring)`. Later the consumer's `give_back(upto)` calls `issue_until(upto + ring)` synchronously on the launch/consumer host thread. It can block in `Stager::wait(job)` before submitting that copy. A direct-pinned entry skips this wait. Both paths call `copy_async_after(dst, host, bytes, copy_queue, after, copied_event)`, where `after` is the previous reader's `used` event when the ring slot has been used. On the stager-backed path, `issued_one(job, copy_queue)` records the stager buffer's DMA completion event and publishes that buffer for reuse. The sequence frontier `issued` advances only after these steps.

Threaded mode runs one issuer thread, with `core::OnDevice` set for the stage device. Before each entry it can spin/yield until `idx < a_consumed + ring`; that is a distinct bounded-window wait, not a staging wait. It then follows the same direct-pinned or stager-backed path and release-stores `a_issued = idx + 1` only after copy submission and stager buffer retirement marking. The consumer calls `wait_issued(a_issued, a_stop, issuer_failure, k)` before consuming entry `k`, then later release-stores `a_consumed` in `give_back`. The existing release/acquire frontier pair is the ownership handoff; do not replace it, publish a ledger snapshot before issuer join, or add per-entry ledger atomics.

The consumer owns `chunk_census`; the issuer may update `chunk_transfers` for its own entry's layer, and only after join does the consumer read/move these values. A ledger must follow the same split: per-thread producer-local aggregate in threaded mode, launch-thread local aggregate in inline mode, then merge/report after a successful join. Pre-size fixed storage before thread start if any per-layer slots are required. Do not resize a shared vector or write one shared aggregate from both threads.

## Exceptional exits and lifetime boundary

The issuer catches every exception, captures it in `issuer_failure`, sets `a_stop`, and cancels the stager. Consumer frontier waits or `give_back` rethrow the captured failure. The chunk-end path joins a joinable issuer and rethrows before merging issuer statistics. Early returns/exceptions run `IssuerJoin` first in destruction order: it requests stop, joins the thread, then checked-drains compute and copy queues. `StagerDone` follows: it cancels, checked-drains both queues, finishes workers, and rethrows the stager failure only on explicit `complete()`; its destructor performs cleanup without rethrowing that stored failure. The catch around `run_impl` also drains both queues. Stager buffers and chunk-local ledger storage must remain alive until these joins/drains have run.

On the normal successful path the explicit issuer join/rethrow and `chunk_stager_done.complete()` happen before `transfer_chunks.push_back`. The later terminal compute drain precedes the existing final transfer summary. A host ledger should be emitted at this same successful chunk boundary, after join and stager completion; avoid publishing apparently complete timing records for failed chunks. If failure records become a requirement, define that separately as an error receipt with explicit incomplete counts and drain status, not as a success ledger row. Checked cleanup can itself fail; do not claim failure cleanup completed if `cleanup_require` throws before later teardown steps.

`m.stage_live`/`m.used_of` and event ownership are existing ring protocol details. The added observer must not record timing events, call queue/device synchronization, wait on `copied` or `used`, change event creation, advance `issued`/`consumed`, or change stager cancellation/drain ordering. Its observations are host wall only and must be labeled as such.

## Suggested fixed protocol

One line per successful chunk, one existing-format H2D line per layer, and one bounded issuer aggregate line per chunk is enough. Reuse the H2D line for byte/call comparison; do not add one record per expert. New ledger mode should be opt-in, cached once, and off by default. With it off, allocate no ledger state, read no extra clocks, do no atomic updates or extra scans, and emit no records; one guarded observer branch at the existing issue site is acceptable. Do not make H2D census opt-in a prerequisite for issuer timing.

Suggested line grammar (decimal ASCII, fixed keys and order; no strings from expert/source identifiers):

`strata prefill issuer ledger v1: device=<u32> stage_begin=<i64> stage_end=<i64> chunk_offset=<i64> pos=<i64> tokens=<i64> stream_all=1 issuer=<inline|thread> ring=<u32> sequence_entries=<u64> direct_calls=<u64> direct_bytes=<u64> staged_calls=<u64> staged_bytes=<u64> staged_dst_pinned_calls=<u64> staged_dst_pageable_calls=<u64> stager_wait_count=<u64> stager_wait_ns=<u64> submit_count=<u64> submit_ns=<u64> issuer_window_wait_count=<u64> issuer_window_wait_ns=<u64> whole_issue_ns=<u64> clock_samples=<u64> clock_invalid=<0|1> counter_overflow=<0|1> completion=checked`

Use fixed aggregate counters only. `staged_dst_*` splits staged source entries by the actual destination buffer `Stager::pinned[j % kRing]`, sampled from the job index before `wait`; it does not add route discovery. This split matters because a stager-backed source does not prove that its staging destination is pinned. For bytes, add the layer blob extent only after `copy_async_after` returns success, matching the existing transfer counter's definition of successful wrapper submission. Keep `sequence_entries` separate so the aggregate can show attempted/accepted mismatch on internal diagnostics; successful output should satisfy accepted calls = sequence entries for a stream-all chunk, accounting for zero-byte extents explicitly if the format permits them. In the current model blob extents are expected nonzero, but avoid relying on that in the parser.

`stager_wait_*` measures only time spent in `Stager::wait`; `submit_*` brackets only the `copy_async_after` wrapper call. The whole issue interval retains a useful inclusive measure and includes staging wait, submission, event mark/host bookkeeping, and loop work. The threaded window wait is measured separately around the existing consumer-frontier loop. For inline, window wait fields are zero. Existing `stats_.ms_experts_host` / `iss_ms` also include host elapsed around the full per-entry path and must not be described as a newly exclusive component.

Bounds/validity: all counts and byte sums use checked `uint64_t` addition and set overflow; on overflow mark the ledger invalid and do not wrap. Accumulate durations as integer nanoseconds from `steady_clock`; require nonnegative elapsed values, reject an end before start, and check duration addition before accumulation. Keep sample counts and invalid status even when duration accumulation fails. If invalid/overflow is set, still report bounded counts if safe but consumers must not compare invalid duration sums. No per-entry list, expert ID, address, event ID, source path, dynamic histogram, or unbounded string is permitted. If distributions are needed later, use a small fixed set of predeclared latency buckets with checked counters and report only bucket counts; sums/counts are the first version. This preserves bounded record size independent of prompt length.

Do not record GPU timing events. The existing phase observer's `wait copy` or dequant intervals are compute-queue adjacent event gaps; they cannot independently resolve launch-thread gaps, copy service, or queue idle. This ledger can establish host thread placement, explicit stager wait, submission-call duration, and threaded ring-window wait. It cannot establish device DMA service time or when a copy became ready. A transfer-count success record confirms wrapper acceptance plus existing checked drains at the report boundary, not PCIe-exclusive bytes/service.

## Comparison with the existing transfer census

The existing `STRATA_PREFILL_TRANSFER_COUNTS` output has per-layer successful submission calls/bytes, mode, issuer, layer blob extent, and checked completion; its total uses overflow-checked sums. It is the right cross-check for the new observer because it already avoids per-expert timestamps. For a successful stream-all chunk, compare issuer ledger `direct_calls + staged_calls` and `direct_bytes + staged_bytes` with the sum of the matching per-layer `full_nonresident_stream` H2D lines. Also compare `sequence_entries` against the expected streamed nonresident sequence length, obtained from the existing route census (`active_nonresident` per layer) only where that census's meanings are verified for the same run. The source's per-layer transfer census is stronger for actual submitted byte extents; route census is a routing expectation, not proof of submission. Keep `completion=checked` and identical chunk, layer stage, format, and issuer keys in the join.

The transfer census is omitted on failed calls, and its success-only rows are emitted after joins/drains. The new success ledger should follow that same admission rule. Never compare ledger totals from a failed/incomplete chunk to the existing success-only total as if they were complete. Ensure only one instrumentation mode is toggled at a time when comparing observer perturbation; enabling H2D counts adds pre-existing route scan/counter work and is not a neutral baseline for timing overhead.

## CPU-only fixture cases that would prove the contract

A host fixture can test aggregation/protocol semantics without SYCL, GPU, clocks from the device, or production model imports by injecting a fake monotonic clock and fake issue/stager calls into a small ledger helper:

1. **Inline, all direct-pinned:** N entries, varied per-layer extents. Verify direct calls/bytes, zero stager/window waits, submit/whole timings, fixed output bound, and no per-entry output.
2. **Inline, mixed stager-backed:** include transient and non-transient unpinned classes, and both pinned and pageable stager destinations. Verify source route and destination-memory split, one stager wait per staged entry, per-layer byte agreement, and `whole_issue >= stager_wait + submit` only as a broad accounting check (do not assert exact equality because wrapper/local work is included).
3. **Threaded bounded ring:** block fake consumer frontier so the issuer waits, then release it. Verify window wait is counted separately from `Stager::wait`, publication occurs only after successful fake submit/`issued_one`, and no consumer read of the producer aggregate occurs before join.
4. **Failures at boundaries:** fake stager wait failure, copy wrapper rejection, and `issued_one` failure. Verify no successful line is admitted; accepted-byte count reflects only wrapper successes, overflow/validity behavior is deterministic, and the owner performs join/drain before storage destruction. This validates the accounting helper and lifecycle seam only; it does not prove actual SYCL queue fault behavior.
5. **Limits/disabled mode:** zero entries, largest legal fixed counter values, count/byte/duration overflow, regressing fake clock, and observer off. Verify bounded output and explicit invalid flags; off mode performs no ledger allocations or clock callback.

These fixtures should assert contract properties, not duplicate production logic line-for-line. A source-only host fixture cannot validate actual queue submission semantics, staging buffer DMA lifetime, or hardware overlap.

## Observer perturbation and decision

The parameter-only pipeline comparison should hold prompt/model, output, chunk size, ring, `STRATA_PREFILL_ISSUER`, `STRATA_PREFILL_NATIVE_DEQUANT_BATCH=0`, and all other knobs fixed. Record source/worktree identity, the actual parameter values, and the existing H2D census separately. Compare the same configuration with the new observer off/on, first inline then threaded. Report observer line count/bytes, CPU host wall and throughput as distinct measurements; do not subtract observer overhead linearly or infer GPU service. Existing per-entry `Clock::now` and `ms_since` calls already run for `stats_.ms_experts_host`; the observer should reuse that interval start where possible, and add clock pairs only for subcomponents (stager wait, wrapper submit, threaded window wait). The parameter-only change in batch mode or G16 memory accounting invalidates the comparison rather than serving as a control.

Conclusion: source supports a bounded host ledger around existing issuer calls, with exclusive thread-local ownership and report admission only after successful join/drain. It can resolve whether host-side stager waits, threaded ring-window backpressure, or wrapper-call wall time account for host issue gaps. It cannot fill the GPU launch/copy service gap by itself.
