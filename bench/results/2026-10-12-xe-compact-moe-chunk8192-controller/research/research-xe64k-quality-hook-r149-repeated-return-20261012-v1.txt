## Fixed-target state and position contract

Add a default-off explicit quality option in the generator parser, preferably a strict fixed-token file plus declared target count. It must validate the entire file, exact count, integer syntax and every ID in `[0,n_vocab)` before model work. Reject incompatible path-changing or output-stopping options (including prefill-until, suffix/lookup drafts, sampler penalties, and EOS stopping); the quality path must neither sample nor stop on a forced EOS token. Keep the option absent from ordinary generation with no file open, logits readback, extra scoring, or behavior change.

The quality mode must require native pack and the existing native `--spec >= 2` setup, but override the main verifier width to `T=1` on every quality iteration, irrespective of requested spec width. Keep `--mtp` absent for initial isolation. Do not use ordinary speculative proposals/acceptance as the state-advance decision; `a` must not select how many target inputs are committed. For each row, score its target against the raw `read_logits(1)` row, choose the next fixed ID as the next verifier input, and call `ver.commit(1)` exactly once for the input that just ran. In particular, force T=1 before building/dispatching each window and ignore `outv[0]` except as an optional greedy-comparison field. A verifier run consumes one input and predicts one next token; the output target itself is not yet consumed.

For P prompt IDs and N target IDs c0..c(N-1), the complete score must have exactly N rows at predictor positions P-1 through P+N-2. Row 0 processes prompt[P-1] and scores c0. Row i>0 processes c(i-1) at position P+i-1 and scores ci. Therefore exactly N-1 continuation IDs are fed back after the first score; do not feed c(N-1) after its own probability is recorded. This avoids duplicate final-token input and a spurious extra state advance. Require `P + N - 1 <= max_context`, so the final predictor position is at most `max_context-1`; additionally honor any stricter allocation/window bound. N must be positive. Emit one row per supplied ID and validate at close: count=N, target IDs equal the input list element-for-element, positions are contiguous and unique, first position=P-1, final position=P+N-2, and commits/input positions each advance once. When a forced target equals EOS, continue until all N rows are recorded.

Do not simply enable stock `--spec-follow`: it substitutes outputs in a window that may have T>1, then derives an accepted prefix and commits `a+1`; this is a different state transition and does not prove clean one-token teacher forcing. Setting T=1 explicitly and unconditional `commit(1)` is the isolation contract.

## Bounded outputs and paired metrics

The minimum compact receipt has one record per target position containing arm/source/config IDs, absolute predictor position, target ID, target log-probability and NLL, argmax ID/log-probability, target rank, top-1/top-2 margin, and optional top-K IDs/log-probabilities. Compute `logp(target)=z[target]-(m+log(sum(exp(z[v]-m))))`, with `m=max(z)`, using stable accumulation. Record exact row coverage and nonfinite failures. Pair arms on the same fixed target and position; report per-position NLL/log-probability delta, mean/median NLL, target exact-match rate, top-1 agreement, margin deltas, and top-K overlap/coverage. Top-K summaries do not yield full KL or full-vocabulary distance; label those metrics unavailable unless full distributions were retained.

If full KL is required, each arm's float32 full row is `4*V` bytes; two arms for N targets require exactly `2*N*V*4` bytes before framing/metadata. Determine V and N from the validated run input, check overflow and a caller-declared sidecar byte budget before starting, and fail before inference if the bound cannot be met. Preserve a single per-arm binary row stream plus hashes under a named owner and paired-KL consumer; compute forward/reverse KL from aligned full rows. Retain only until the paired summary and hashes are verified, then record path/hash/reason in the deletion manifest when the owner closes. Never label truncated top-K mass as KL. Keep this scoring/readback/file path out of quiet performance measurement.
