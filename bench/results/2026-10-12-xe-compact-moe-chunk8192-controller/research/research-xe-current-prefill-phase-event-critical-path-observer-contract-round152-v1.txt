# Current Prefill phase/event observer contract (round 152)

Date: 2026-10-12 (Asia/Tokyo). Read-only source audit of clean Xe commit `39e395a103af36323262cdc0dbaea27cba81f3e4`. No runtime, GPU/model/process/profiler query, active artifact/controller read, import, build, test, Git/source edit, or cleanup was performed. This report describes the current instrumentation boundary and a proposed observer; it reports no timing result, bottleneck, counter availability, or hardware-counter support.

## Finding

The current `STRATA_PREFILL_TIMING` path is a useful coarse observer of ordered intervals on Prefill's compute queue. It is not a per-kernel timer, copy-engine timer, CPU service ledger, or end-to-end critical-path measurement. Each interval is attributed to the phase of its first marker; it can include GPU idle time while the host stages/groups data or the compute queue waits on a separate copy queue. A separate H2D event/span ledger is absent from this pinned source. Summing current compute timeline with independent copy activity would double-count overlap and would still not establish which dependency gates request completion.

The source has improved validity behavior compared with older phase-timer audits: a failed/missing/non-timing/reversed event query is rejected, not silently omitted or allowed to wrap into a huge phase value. This makes a timer-query failure a failed Prefill invocation. It does not make individual intervals exclusive kernel durations or validate phase coverage against an expected event count.

## Current queue, marker, and event behavior

`PfTimer` is enabled by environment-variable presence: any `STRATA_PREFILL_TIMING` value, including `0`, activates it. It allocates `Event` wrappers with `timing=true`, calls `event_record` on the passed compute stream at `pt.mark`, and stores a parallel phase ID. `event_record` uses `sycl::ext::oneapi::experimental::submit_profiling_tag(queue)` for a timing event; the ordinary marker policy (`Runtime::marks_by_barrier`, informed by `STRATA_EVENT_MARK`) applies only to non-timing events. The timing marks therefore add ordered profiling-tag commands to the in-order queue. `Runtime`'s compute, transfer, and created stream queues are constructed with `in_order`; this source does not add an `enable_profiling` property to those constructors, nor does `PfTimer` inspect a queue property before using the profiling-tag extension.

At fold, `event_elapsed_ms` obtains `command_end` timestamps for adjacent tag events and returns their end-to-end separation in milliseconds. It does not query a kernel's `command_start`/`command_end`. `PfTimer` charges each difference to the earlier event's phase, then retains the last event as the next fold's left edge. The main layer fold follows a checked `stream_sync(m.cs)`; the final fold follows another checked compute-stream sync. No per-marker `STRATA_PREFILL_SYNC` mode or `STRATA_PREFILL_TRANSFER_TIMING` branch exists in this 39e source; instructions from older reports about those paths do not describe this implementation.

Current error path: `event_elapsed_ms` rejects missing events, wrappers without timing enabled, reversed timestamps (`b < a`), and SYCL query exceptions. `PfTimer::fold` passes failure through `publication::require`, so the exception reaches `Prefill::run`'s catch path, which checks/drains both compute and copy streams and returns failure; no normal phase report is emitted. This supersedes R205's old-source description of a caught query that could silently skip a bucket and of unchecked unsigned underflow. The report still lacks explicit expected-marker reconciliation and raw timestamp fields, so a successful line only supports the coarse source-defined timeline.

The event wrapper is a `std::optional<sycl::event>` plus a timing flag; `event_destroy` deletes this wrapper, not a raw Level Zero handle. On normal folds, the source synchronizes before querying and reusing the markers. `Prefill::release` synchronizes compute and copy queues before destroying member events and freeing the buffers. Some false-return branches can unwind a chunk before the final run sync; the R151 event-lifetime review found no basis to call dropping a SYCL event reference equivalent to destroying an in-use Level Zero pool, but its DPC++ implementation pin was for an earlier source/runtime identity. A future observer should keep each raw completion handle until its queue is known complete and should retain the current dual-queue drain rule for any scratch or host buffer reclamation.

`mark_host_ms` records host time inside `PfTimer::mark` (including event creation/record calls and local bookkeeping); `fold_host_ms` records the host-side timestamp queries and fold bookkeeping. Neither includes the full scheduling perturbation of inserting profiling-tag commands, time spent at existing queue syncs, or a timer calibration. The timer is diagnostic instrumentation and does not produce a quiet timing sample.

## Exact current phase boundaries

The phase set is `embed+steps`, `hc read`, `gdn`, `qsa proj`, `qsa indexer`, `qsa select`, `qsa attn`, `router+shared`, `host grouping`, `gather`, `wait copy`, `dequant`, `gemm gate/up`, `gemm down`, `combine`, `ple`, `kv stage`, `gdn conv+gates`, `gdn recurrence`, and `gdn out proj`. All refer to compute-queue intervals between marker commands. They aggregate across chunks/layers; there is no current layer-by-chunk breakdown.

| Current marks / caller work | What the bucket can represent | Specific attribution boundary |
|---|---|---|
| `kPfStart` at chunk entry, and again near chunk end | First interval includes token/embedding upload or gather, broadcast, QSA step table setup, PLE gather kickoff, and early stream planning/issue until the next phase marker. Later `kPfStart` intervals can include chunk-tail host/callback work and next-chunk preparation before a subsequent marker. | The final chunk's last `kPfStart` has no following marker; the final fold adds no interval after it. `gpu_timeline_ms` therefore covers only the adjacent-marker spans, not the final post-marker host callback/wall tail. |
| `kPfPle` at layer 1 | PLE device processing: batched native/BF16 key/value projections and post-ops, or the per-token PLE block/history path. | `ple_land` runs before the mark: it waits for the gather future, submits the PLE embedding upload on `m.cs`, records/synchronizes the double-buffer event, and starts the next host gather. The queue bucket does not separately measure that host gather/upload setup. |
| `kPfHc` per attention/feed-forward half | Normalization, HC down/up/inject projections, activations and mixing until the next marker. | It includes enqueued dense/GEMM commands and intervening queue gaps; no exclusive HC-kernel times are emitted. |

All these spans run on `m.cs`; none is an exclusive time slice across all device queues. Since `m.copy` can progress concurrently, a compute bucket can contain a dependency wait while H2D work runs, and an independent copy interval would overlap rather than add to this timeline.

## H2D and existing host counters

The prompt expert copy queue is `m.copy`, separate from `m.cs`. In stream-all mode, `seq` is assembled from every nonresident expert and the inline or threaded issuer submits its copies using `copy_async_after` to `m.copy`; the copy event stored in `m.copied[slot]` is the `sycl::event` returned for that `handler::memcpy` command. In routed mode, `stage_one` uses `copy_async` on `m.copy` followed by `event_record(m.copied[slot], m.copy)`. These `m.copied` wrappers are created with default `timing=false`; `event_elapsed_ms` will reject them as duration endpoints. Their `stream_wait_event` role establishes dependencies, not a service measurement. The PLE upload is instead enqueued on `m.cs`.

When `STRATA_PREFILL_TRANSFER_COUNTS` is present, `PfExpertTransfers` records successful expert-copy submissions, request extents and calls, later labeled explicitly as not PCIe-exclusive bytes or DMA service. There is no current copy-queue start/end timing toggle in this worktree. The 32K R151 census confirms why route census and traffic must stay distinct: all nonresident sequence entries can be issued in each full-stream chunk, including zero-route experts; route-zero skips dequant/products, not already-issued H2D.

Host-side counters answer separate questions. `host_setup_ms` covers early chunk setup up to the layer loop. `stats_.ms_experts_host` and the threaded issuer's `iss_ms` time host source staging/copy-issue spans; they do not include GPU copy duration or the full idle time waiting for ring permission. `stats_.ms_ple` uses host `Clock` around gather-future wait, embedding upload submission and PLE path setup, not the GPU duration of its queued kernels. `host_sync_ms` is accumulated only when a chunk callback is installed, around the compute-stream wait before callback work. `host_chunk_ms` then covers post-sync stage/chunk callbacks (including draft/MTP/progress/checkpoint work) and is also conditional on a callback. These fields overlap other host/GPU activity and cannot be summed into a device service total.

`Prefill::run` starts `t_start` after argument/context checks and the empty-input return. Its reported `wall` ends after the final compute-queue sync and before timing-report formatting; `stats_.ms_total` includes setup, chunk loops, host staging and installed callbacks within that call. It does not include `Prefill::init`, model/server setup, all request admission/cache work, or the final prompt token that native generation routes to its verifier after `prefill.run` returns. In serving, the flushed `PP` line is printed by the chunk callback after MTP/draft work at `done=p0+T`; it precedes the end of `Prefill::run` and subsequent verifier handling. It is a progress boundary, not a clean profiler pause/resume boundary or proof that decode has not started elsewhere.

## Proposed observer contract

1. For a coarse phase-location diagnostic without source changes, use only `STRATA_PREFILL_TIMING=1` on an explicitly diagnostic run; record actual source/binary/model/config, route/issuer/native-dequant mode, chunk geometry, the complete raw output, query failures, wall, host fields, all phase fields and marker/event/fold counts. Presence semantics mean the value `0` is still enabled. Do not use this run as a quiet throughput result, infer per-kernel times, call a label a copy-service measurement, or add phase and host counters.
2. For H2D and host overlap, add a separately gated observer that records bounded chunk/layer/copy identity, mode (stream-all/routed), byte extent, issuer thread, host staging wait and submit begin/end, copy-queue command completion, compute wait and the dependency/event ID. For a real copy-service interval, expose profiling timestamps from the actual copy command's returned event; a `submit_profiling_tag` before/after a batch measures a queue span that can include dependency/issue gaps, not copy-engine active time. Keep this stream's interval distinct from the compute timer.
3. To isolate native per-expert dequant, GU and Down calls or dense GEMMs, add diagnostic event completion handles at the underlying SYCL/oneMKL/kernel submission sites (the current wrappers generally return no command event), plus host API submit durations. Query actual command `command_start`/`command_end` only when supported for that specific event and queue, fail closed on missing/invalid timestamps, and include the call/shape/format/group/route identity. Do not substitute the coarse marker-to-marker duration. An event around an entire group is a group span, not one expert's kernel service.
4. Keep host `steady_clock` fields (source `copy_blob`/stager wait, issuer gating, route grouping, `native_flush`, API submit, PLE gather/future wait, callback, stream waits) separate from device queue timestamps. Link them by recorded queue/event dependencies and one request-level wall interval. Establish a critical path only from that dependency graph and endpoint wall; concurrent compute, H2D and PLE work must not be added as if serial. No occupancy, bandwidth, utilization, or counter claim follows from these timestamps.
5. Bound diagnostic retention and overhead. First compare current coarse timer against an uninstrumented run only to describe observer overhead, not to correct or transfer phase shares. Avoid per-expert timestamp events in a quiet perf arm; they can alter high-copy/high-kernel counts and queue behavior. Keep the diagnostic source gate off by default and preserve queue-drain/lifetime guarantees: retain event objects until their command work is complete, drain both `m.cs` and `m.copy` before event/buffer retirement, and fail-stop if a drain cannot establish completion.

This design is a source contract only. It does not assert that a particular profiler can collect device counters on this GPU/driver or that the proposed diagnostic tags would be low-overhead or critical-path complete.
