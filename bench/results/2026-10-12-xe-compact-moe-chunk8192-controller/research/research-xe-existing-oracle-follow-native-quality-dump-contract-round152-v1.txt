## Source path and exact alignment

For prompt length `P` and fixed reference `c[0..N-1]`, the native-pack path batches `n_batched=P-1` prompt IDs through Prefill by default (`generate.cpp` near 10201), leaving prompt ID `P-1` for the verifier. Native mode exits the ordinary token loop before it consumes that ID; `spec_pos` is its position. The standalone verifier is entered when `--spec T` is set, and native admission requires `T >= 2` (near 2936). `--mtp` is optional. With MTP omitted, `use_mtp=false`, so no MTP drafter is bound or used; `S_mtp` remains the configured verifier/spec width.

If the same reference ID file is supplied to both `--spec-oracle FILE` and `--spec-follow FILE`, the first native verifier window is forced to `T=1` (`first_window=native_pack`). It runs only the final prompt ID at `P-1`; its output row predicts `c0`. `--spec-follow` replaces that row's output ID with `c0` after `ver.run`. The next window starts with `c0`. For each later window, the oracle proposal at `window[i]` uses the matching reference ID (`oracle[produced.size()-1+i]` for `i>=1`); follow substitutes the matching IDs into verifier outputs. When the arrays are identical and no EOS stop applies, each proposal matches the prior target output, so the verifier accepts the available reference prefix and commits it in one operation per window.

With `--max-new=N` and both files containing exactly N identical IDs, each verifier invocation emits up to its window width or remaining output budget, whichever is smaller. Windows therefore cover N predictor rows at positions `P-1` through `P+N-2`. The input committed after the last row is `c[N-2]`; `c[N-1]` is output/scored as the last target and is never consumed as a verifier input. The oracle file's last ID is also never needed as a proposal: oracle supplies next-row inputs only through `c[N-2]`; follow supplies the final output `c[N-1]`. For N=1, only the prompt-terminal first window runs and no reference continuation ID is consumed as input.

This is fixed-reference scoring with MTP disabled. It does not measure production MTP4 behavior, MTP quality, or speculative speed. Keep this quality cohort separate from any production MTP4 arm. The verifier still uses `--spec` as its maximum window/capacity parameter; no claim that `--spec=0` or `--spec=1` is admitted for native packs.

## Dump and commit/read lifetime

Native dump dimensions set `dump_first=P-1` and `dump_positions=N` when `--max-new=N` (near 4895). The header is two int32 values `{n_vocab, row_count}`; with the default stride 1 it declares exactly N rows. Each row is `n_vocab` float32 values. The verifier path writes only rows corresponding to emitted outputs, using the row selection derived from `p+i-dump_first` (near 10808–10820). Thus, in the no-stop full-coverage case, expected file size is `8 + 4*N*n_vocab` bytes and the row order is predictor positions `P-1 ... P+N-2`; the header itself carries no positions or IDs. For attribution, validate header, exact byte length, finite values, reference IDs, and row count externally. The dump rows are full distributions, unlike serve `logprobs=20`.

`ver.run` completes the verifier window and produces `head_logits_`; output substitution and `ver.commit(a+1)` follow. The generator then calls `ver.read_logits(emitted, ...)` after commit and before the next `ver.run`. The commit code updates recurrent/KV/session state and tracks its completion; it does not overwrite `head_logits_`. `read_logits` copies that separate logits buffer, and the next run is the operation that reuses it. Therefore this post-commit read has a valid source-level buffer lifetime. Readback is part of the quality invocation and must not be included in timing measurements.

## Admission, flags, and limitations

A narrow run configuration is: standalone native pack with its normal preset and fresh state; ordinary fixed Prefill path; `--spec T` for legal T>=2; `--spec-oracle FILE --spec-follow FILE` using the same immutable file; `--max-new N` equal to that file's N IDs; `--dump-logits PATH`; greedy/default sampling; MTP omitted; no suffix-draft, lookup-chain, corruption, adaptive swaps, or `--stop-eos`. Leave `--prefill-until` unset so `n_batched=P-1`; retain configured `--max-context=262144`. Existing prompt/generation admission requires `P+N <= max_context` in this source, which is one cell stricter than the last-predictor mathematical condition `P+N-1 <= max_context`. This is an admission bound, not proof of allocator fit or physical last-cell execution.

There is a real fail-closed limitation: the CLI reads oracle/follow files inside the speculative path, after prompt model work, and does not require equal paths/content, exact lengths, or validate every oracle/follow ID against `[0,n_vocab)`. `follow` shortens effective `max_new` to `min(--max-new, follow.size())`; a short file silently yields fewer outputs/rows, while an overlong file is truncated by the budget. `--spec-oracle` proposals are used only where supplied; absent entries become ID 0. The same-file, exact-N, all-in-range conditions are caller preconditions, not source-enforced guarantees. Validate them before launch in the run wrapper, and treat any incomplete/invalid artifact as a failed run. A future narrow source change would be justified only if these conditions must be enforced by the binary; no source hook is needed to make the valid case function.

`stop_eos` defaults false, but if enabled the output loop can end early at an EOS. Additionally, accepted-prefix accounting consults the EOS ID list even when stop-eos is false; an EOS can shorten a window's emitted prefix, requiring later rows to be recomputed. For predictable one-pass N-row output, exclude EOS IDs from the fixed continuation and leave `--stop-eos` off; alternatively, explicitly validate that full N rows still appear. Do not mistake the default EOS token IDs alone for enabled early stopping.

## Future fixtures and A/A diagnostic

Before any model run, a wrapper/fixture should reject N<=0, token IDs outside the model vocabulary, unequal oracle/follow contents or hashes, declared N mismatch, `--max-new != N`, truncation/overrun, and context overflow. Exercise N=1 and N>1 alignment; a deliberately short/long file; invalid negative and `>=n_vocab` IDs; EOS with stop disabled and enabled; max-context boundary; exact output count; and the invariant that the final reference token is emitted/scored but not consumed. Check no source-side option silently activates MTP, suffix/chain, corruption, or adaptation. Keep fixtures CPU-only and model-free where possible; they validate the wrapper/parser contract, not GPU numerical equivalence.

For a later A/A on the same fixed prompt/reference, run identical native settings twice, each with the same oracle/follow file and MTP off. Require both dumps to have the exact `{n_vocab,N}` header and expected byte length, and compare all float rows (byte-identical where execution is deterministic; otherwise report max/mean absolute and relative differences), top-1 IDs, and logits finiteness. Verify generated output equals the N reference IDs; retain invocation/config/source/model/pack hashes and the reference token-file hash. Keep A/A and quality measurements separate from throughput runs. A/A can reveal nondeterminism or harness errors; it is not an independent quality threshold or evidence for production MTP4.

## Judgment

The shortcut is valid as a conditional, standalone native full-logit quality harness under the exact equal-file, valid-ID, exact-N, greedy, no-stop, fresh-prefix constraints above. It preserves the native long batched Prefill, the `P-1` prefix boundary, and configured 262144 context. Its source does not guard the crucial file equality/coverage/range conditions, so the caller must validate these before paying for model work and must verify the dump after the run. This audit provides no runtime, quality, capacity, or speed result.
