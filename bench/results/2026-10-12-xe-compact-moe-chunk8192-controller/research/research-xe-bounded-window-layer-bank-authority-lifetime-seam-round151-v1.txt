## Finding

A dedicated, packed-native active-layer bank is feasible using the current prefill consumers, but **not by borrowing or repurposing the decode/profile cache and not by treating the existing `ExpertCache::admit` as an eviction/rebind API**. The narrow seam is an internal per-call expert view: a separate GPU slot arena plus a separate mutable `(n_layers × n_expert)` host map, selected for the bounded-window prefill object's lifetime. Refill that arena only after the prior layer's final device reader is done. The existing model-level `host_res`, its device mirrors, profile cache and tail slots stay authoritative for decode and scratch borrowing.

The packed bank can use the exact layer bytes already consumed by current native prefill. This avoids introducing a different preload/GEMM kernel or an FP16 conversion path. For non-MMQ native experts, the normal code still dequantizes some or all packed weights per chunk; keeping the blob resident removes its repeated copy, not that computation. Full FP16 persistent weights are not a drop-in bank for the current `host_res`/blob consumer.

## Exact map and slot contracts

- `Prefill::init` stores borrowed `ExpertSource*`, `const ExpertCache*`, and `const int32_t* host_res` directly in `Prefill::Impl` (`src/prefill/prefill.cpp:659-664`). The public header describes the map as static `(n_layers × n_expert)` slot IDs or `-1` (`include/strata/prefill/prefill.hpp:80-84`). Within the MoE body, the only `m.cache` operations are six `device_slot(map[layer,expert])` lookups; resident tests read `m.host_res[layer*n_expert+expert]` (`prefill.cpp:1992-2000,2131,2157,2300-2317,2510,2557,2778,2823`). Thus a private bank/map pair can be wired at `init` on a separate `Prefill` object without writing the caller's decode/profile map. Its private map can clear all rows to `-1`, set only the currently scheduled original layer's row to bank slots, then clear it before the bank is refilled for a new layer. The public prefill interface has no mid-run map setter; avoid changing `Impl` pointers under concurrent use. Keep the map vector alive until all host worker/issuer threads have joined and both queues are drained.
- `ExpertCache` offers a bounded, actual-device-checked allocation, stable `device_slot`, heterogeneous `open_sized`, and async `fill_slot` (`include/strata/core/expert_cache.hpp:91-99,140-176`; `src/core/expert_cache.cpp:380-405,466-496`). `fill_slot(..., bytes)` copies the specified short blob when it fits its slot. A fixed `n_expert`-slot arena using `max_blob` slot size can therefore receive each current layer's exact `blob_bytes(layer)` without padding being read by the native consumer. Heterogeneous per-slot sizes are useful for a single layer; layouts differ between layers, so re-opening/rebuilding a differently sized `open_sized` cache at every layer is not necessary. A uniform max-sized arena is simpler but its fit is unmeasured.
- `ExpertCache::admit` explicitly never evicts (`expert_cache.hpp:143-146`); once all E slots are admitted for one layer, it cannot transparently transfer that ownership to the next actual layer. Do not call `admit(actual_layer,e)` for every layer against one E-slot cache and expect rebind to work. A private bank namespace can admit `(bank_layer=0,e)` once into each fixed slot, while the separate Prefill map row `(actual_layer,e)` maps to that slot; `Prefill` uses only `device_slot`, not the cache's `slot_of`, in these lookups. Alternatively a new explicit fixed-slot map/provider should make this separation clear. On each rebind, invalidate the former actual-layer row before overwriting slots. No write to decode `host_res` or cache residency is required.
- The owned bank must be an additional GPU allocation. Generate lends the existing cache tail as chunk scratch (`src/program/generate.cpp:5538-5570,5721-5770`); those bytes become `stage_dev` and related workspace, not persistent expert storage. `Prefill::bytes_needed`/lend sizing cannot be used as a proxy for bank capacity. Bank plus normal chunk workspace must pass separate real allocation/preflight checks before session mutation. Capacity remains unmeasured.

## Source, copy, ring and last-reader ownership

Current `stream_all` builds a sequence of every nonresident expert in each chunk's active layer range, then `issue_until` or its issuer enqueues every sequence copy (`prefill.cpp:1385-1429,1452-1474,1505-1535`). Route-zero experts are skipped for products but, in this mode, their transfer may already have been issued; route skips do not prove H2D savings. The routed/non-stream-all path forms its stager jobs from the current chunk's active `order` (`:2298-2310,2579-2590`) and can copy fewer experts. Thus a full-E bank refilled each bounded window most directly removes repeated **stream-all** transfers; in route-specific mode it may increase traffic by preloading experts absent from that window. Do not claim the bank improves both modes without route-union/copy evidence or a separately justified route-planning step.

Each expert source blob must retain its exact `ExpertLayout::blob_bytes(layer)` and format metadata. For stable pinned source blobs, the copy queue may DMA directly. A transient source's `blob()` pointer is explicitly not stable beyond the chunk's queue; `Stager::Job::from` calls its `copy_blob` into the stager's pinned/pageable host ring (`prefill.cpp:248-255,300-337`). For bank fills, reuse that source-copy pattern rather than caching transient pointers. After each async host-to-bank copy, `issued_one` marks its host ring buffer reusable only after the DMA event (`:379-382`). The existing `stage_dev` ring is a separate destination ring whose copies wait on `used[used_of[slot]]`, recorded after the ring slot's last consumer (`:1458-1471,2311-2354`). Do not recycle either of these staging-ring lifetimes as the active bank lifetime.

The bank's contents have a longer lifetime than one ring entry. One ordered protocol is: fill its E packed slots on `m.copy`; record a bank-ready event and have `m.cs` wait before the first layer chunk; after the final chunk's expert products for that layer, record one bank-last-reader event on `m.cs`; make `m.copy` wait on that event before refilling for the next layer. Current compute and copy queues are distinct (`m.cs`, `m.copy`, `Impl` fields `:408-410`), so host submission order alone is not a fence. The last-reader event must follow every packed-source reader, including the fused resident `iq_gemm_grouped_f16` kernels, not just an expert copy or an individual source dequant. Queue order makes one final-layer event sufficient only if all chunk work was submitted on that same ordered compute queue and no auxiliary queue reads bank pointers.

On a fill, conversion, kernel, cancellation or callback error, stop/join any active issuer, cancel/finish the stager, drain both compute and copy queues, and only then clear the temporary map, reuse/free bank slots, or destroy the dedicated cache. Existing guards show the necessary components: `StagerDone` drains compute and copy and finishes workers (`:1431-1451`); `IssuerJoin` stops and joins its producer and drains both queues (`:1491-1503`). A new window/layer path must cover pre-bank-fill and between-layer failures too; existing chunk-local guards do not by themselves prove that broader lifetime. Restore/remove the temporary expert view only after these drains, so no worker holds stale map or slot pointers. Failure of a partially advanced recurrent session still means discard/restore that session; it does not make the layer boundary a coherent checkpoint.

## Packed native support versus a fully FP16 bank

`ExpertLayout` defines the native blob as raw GGUF slices with per-layer `gu_type`, `d_type`, `up_off`, `down_off`, and byte length; the source comment says the arena, VRAM tier and prompt path all use this table (`include/strata/kernels/cpu/expert_layout.hpp:4-9,21-43`). Metadata only (not weights) in the pinned worktree's committed fixtures shows formats vary: Q2_0 has GU/down type 42 and 1,382,400-byte blobs; the IQ3_S sample includes GU type 18 or 22 with down type 20 or 42 and layer-specific blob sizes (`tests/data/native_experts/q2_0.txt`, `iq3_s.txt`). The native cache should preserve those bytes and offsets verbatim.

Current consumers support this without a new preloaded kernel assumption:

- MMQ layers use `mmq::gather_native` on packed blob offsets and then the planned MMQ products (`prefill.cpp:2691-2717`). MMQ eligibility and each layer's GU/down type pair are selected by the existing plan; a bank should not broaden that plan.
- For non-MMQ native layers, current `compute` uses `iq_dequant_gu_f16(gu_type, gate, up,...)` and `iq_dequant_f16(d_type, down,...)`, then the unchanged grouped FP16 GEMM/fallback (`prefill.cpp:2472-2484,2174-2216`). Grouped native dequant is explicitly optional and off unless `STRATA_PREFILL_NATIVE_DEQUANT_BATCH` is set (`:2218-2223`); do not require it for the bank.
- For cache-resident experts satisfying the current XMX/type/layout checks and at most `kIqGemmTileRows`, `iq_gemm_grouped_f16` reads the packed GGUF blocks directly and decodes them in local memory to the same FP16 values, avoiding a persistent FP16 tensor; larger/non-fusable experts use the normal explicit FP16 scratch route (`prefill.cpp:1980-2005`, `include/strata/kernels/iq_kernels.hpp:68-83`). This is an existing current path, not a proposed preload path. Its checks remain authoritative; residency alone cannot force it.

A persistent FP16 bank would have to change the resident-map consumer's blob contract and retain the exact converted gate/up interleave and down layouts across chunks. Today's resident branch gives the slot to native `blob_dev`, inspects the layer format/offsets, and dequantizes or fuses from the packed codes. No existing `host_res` type distinguishes FP16 slot contents from packed blobs. Therefore FP16-bank-as-drop-in is unsupported by this source; building it would be a separate typed-provider/consumer design and would change allocation and numerical conversion boundaries.

## Narrow implementation seam and exact remaining proof

Construct a separate one-shot Prefill/expert view with a private E-slot packed bank and private map; factor the existing per-chunk layer body so the bounded-window driver supplies `(actual single-layer range, private map, packed bank)`. The same map is set before each layer's first chunk and held stable over the full window; its slots are never returned to the prompt scratch ring. Keep the existing `ExpertSource` and native consumer path, the actual QSA/GDN session state, and normal per-layer routing/dequant logic. Do not alter the decode/profile map, profile refill, cache slot ownership, or use public `set_stage` to bypass its stage-chain invariant. The R142 restrictions still apply: one GPU/full layer range, no multi-GPU, next/helper handoff, or serving/checkpoint route until transactional behavior exists.

The remaining acceptance evidence is a bank-specific source/format matrix and phase receipts: compare copies per layer/window in both stream-all and route-specific modes; verify every source copied to exact `blob_bytes`, every active map slot references the intended bytes, bank-ready and last-reader events dominate all queue users, failure at each enqueue/wait/format branch drains and clears the map before reuse, and decode/profile slot/map hashes remain unchanged. Compare current outputs and all GDN/QSA/PLE/MTP state against the existing chunk-major path. Measure E-slot native bank plus workspace against actual VRAM and ensure the window host plane is separately counted. No performance or fit claim is established here.
