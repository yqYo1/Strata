## Hook ownership and evidence semantics

The caller's host route census is built after the existing device-to-host route-ID read/wait and the original range check (`ids_h[i]` must be in `[0,n_expert)`), then counts `m.cnt[e]`. The census checks each count is in `[0,T]` and that `sum(ne)=T*K`; the original source explicitly returns an error for an invalid raw ID before the census hook. The census does not independently reread IDs or record a separate `invalid_id_count`; that would add no new device read, but remains a useful explicit CPU contract assertion. Counts/bins originate from the same checked `ids_h` population used for `order` and the expert calls, not from a second route-ID authority.

The planner records an already-decided resident/pinned/RAM/transient/GGUF source before issuer startup; it does not claim a copy happened. `copied()` is called only after the existing successful transfer submission, with the actual transfer's layer, expert and blob byte extent, and the source selected by the actual route. For non-stream-all, staging decisions are made over routed `order`; for `stream_all`, all nonresident experts are planned and copied, including legal unrouted copies. The receipt separates all transfer totals from routed-transfer totals, and only selected routed experts enter route bins. The transfer extent is compared with the layer's actual `blob_bytes` and with the planned source.

The issuer lane writes only its fixed `(layer,expert)` `Copy` cell and request-sticky `copy_fault_`; it never reads or mutates main-thread `valid_`/`reason_`. Bounds are pinned before thread launch. `active_chunk_` is set before launch, stays stable while the issuer runs, and changes only after the existing join. The only threaded issuer writes distinct sequence entries; the inline and `stage_one` paths record from the caller thread and are mutually exclusive with the threaded issuer for a chunk. Main-thread folding happens after join, and the next chunk resets scratch only after the prior issuer join. `stager_source()` reads the preplanned cell after startup; the plan table is immutable during issuance. This ownership is sound for the actual single-issuer/sequential caller. It does not support arbitrary concurrent external calls, correctly outside the stated contract.

`executed()` counts one selected expert call and records residency from the actual `slot < 0` route. In the native generic path, GU and Down product hooks run after each original `expert_product` call returns, including the unsupported event-path fallback to the existing GEMM call. End-of-chunk reconciliation requires exactly one call and one GU/Down per selected generic expert, none for MMQ, and one actual copy iff the selected call was nonresident. MMQ's `calls` mean selected per-expert gather/participation; MMQ's products are grouped launches and are not represented as per-expert generic products. Fused dispatch and peer route invalidate the entire receipt rather than borrowing generic/MMQ accounting. This distinction prevents interpreting MMQ/fused calls as generic IQ-dequant/GEMM exposure.

`logical_packed_bytes` is selected expert calls multiplied by the native blob extent; it is bytes presented to the route, not physical DRAM, L2, PCIe or controller traffic. Transfer bytes are separately logical host-to-device payload. The header records format pair/rows/offsets/branch and bins by `(ne,source)`, but it has no device profiling durations, cache/controller counters, per-kernel identity, or runtime hardware/library/compiler/build identity sufficient by itself to join to capacity measurements.

## Fail-closed behavior and remaining limits

Ordinary invalid IDs in the preexisting route loop return false; the census destructor then emits one invalid receipt on unwind. Invalid metadata, identity, count, source, pairing, coverage, arithmetic, allocation, formatting or output-cap paths mark the request invalid. Layer JSON is buffered and is written only if the entire receipt remains valid; an invalid controlled run therefore emits no layer rows and one invalid receipt. A missing allocation leaves `valid_` false, and finish does not dereference the absent storage. The 32 MiB output limit reserves room for the final receipt. If the layer-text `fwrite` fails partway, the final receipt is invalid (or absent if stderr itself fails); a consumer must require the final valid receipt plus exact output size/hash/counts, never join partial rows.

Explicit caller fatal receipts precede no-unwind exits in the issuer exception and instrumented compute/fatal paths. Some existing nested fatal helpers, including the transfer-ledger copy fatal path, can terminate before the census destructor and have no local final census record. That remains fail-closed only if the controller classifies absent/partial receipt, abnormal exit, or missing normal completion as invalid; the archived v1 contract already makes this a required consumer rule. The current root CPU/TU receipts do not exercise these process-fatal paths or prove full cleanup/unwind. No evidence supports claiming every fatal produces a complete invalid JSON receipt.

Default-off reasoning is consistent with the caller diff and header: absent/exact `0` returns in the constructor before census allocation, clocks or output; host hooks are guarded by `on`; the only newly gated peer-mode check is host-side. No new queue/event/device command or wait is added by the census. This is static path inspection, not machine-code identity, command-count measurement, or default-off output/numerical/performance parity. The actual TU compile proves the changed caller and header work together with the recorded include overlay; it does not prove a linked binary uses this exact object/header pair at runtime.
