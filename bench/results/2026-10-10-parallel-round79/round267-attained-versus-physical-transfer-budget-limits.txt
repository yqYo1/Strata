## Inputs and exact byte model

The corrected four-stream residual width is `D = 4 * N = 4 * 2,560 = 10,240` FP32 values per position, so one residual position is `D * 4 = 40,960` bytes. The existing layer-major path has 48 layers and 47 layer boundaries. For `n` positions, the host-residual payload per direction is therefore:

`Bdirection(n) = n * 40,960 * 47`.

At 32,768 positions this gives 63,082,332,160 bytes (58.75 GiB) in each direction, 126,164,664,320 bytes total H2D plus D2H. The full-context host-plane extent is a different quantity: `n * 40,960`, or 1,342,177,280 bytes (1.25 GiB) at 32K. At 262,144 positions the per-direction payload is 504,658,657,280 bytes, the two directions total 1,009,317,314,560 bytes, and the host-plane extent is 10,737,418,240 bytes (10 GiB).

The measured one-way transfer rates in the component matrix are pageable H2D 4.605214 GB/s and D2H 5.273931 GB/s; direct Host-USM H2D 6.446834 GB/s and D2H 5.642946 GB/s. These are attained 256 MiB transfer results on the recorded Ryzen 5 5600X / Arc B570 setup, not guaranteed live layer-major residual rates. Their payload conventions are one-way payload. The physical-bandwidth receipt gives an ideal encoded external Gen4x4 rate of `16 GT/s * 4 lanes * 128/130 / 8 = 7.876923 GB/s` per direction before protocol overhead. That is an ideal upper-envelope arithmetic input, not a measured transfer rate or a guarantee that an arbitrary host pointer is eligible for it.

The metadata-only current pack census contains 24,576 expert blobs across 48 layers and 50,292,326,400 packed bytes. This is a current-pack census, not proof of a particular request's route, selected experts, residency, transfers, or one-pass reload count. To expose the same comparison as R262, I model one complete unique packed-weight pass in addition to the residual handoffs. Its H2D time is 7.801090 s at the measured Host-USM rate, or 6.384768 s at the ideal encoded Gen4x4 rate. This full-pack pass is a scenario denominator, not an observed request.

The pageable row reproduces the corrected conditional R262 budget. It says that if the layer-major residual plane uses pageable transfer behavior at these measured rates and a full packed pass serializes with it at the measured Host-USM rate, those two transfer components alone exceed the 32.768 s prompt budget. It does not establish that the runtime uses pageable residual transfers, that these phases are serialized on the production critical path, or that the whole 32K request misses its target. The direct Host-USM and ideal-link rows are alternative rate assumptions, not claims about registration, allocation compatibility, driver pinning, or achievable live overlap. All rows exclude GEMM, routing, attention, other copies, setup, synchronization not embodied in the measured rate, and other request work.

If and only if the residual plane lives in ordinary host memory and the implementation must make a separate application-level staging copy between that plane and a distinct pinned/USM transfer buffer for every direction, add one host copy of the full directional payload. The matrix's synthetic three-worker host ring reports 13.743331 GB/s for payload once, giving a conditional additional `126.16466432 GB / 13.743331 GB/s = 9.180 s` at 32K. For example, that would raise the serialized pageable residual-plus-pack scenario to 42.640 s if this host copy is also serial. The ring test is not live residual-staging evidence; its worker count, burst pattern and verification behavior may not match production. Do not add this term when the residual plane itself is directly allocated/registered in the transfer-compatible memory or when the chosen measured pageable API rate already includes the driver's internal staging. Do not silently assume that plane allocation is Host-USM eligible.

## What order changes and what physical capacity proves

For a fixed placement and fixed set of 47 layer-major handoffs, changing submission order does not change the logical residual payload above. It can change overlap only when the dependencies permit it and the operations share the critical path; it does not change the byte denominator. A layer-group schedule is a different schedule/placement choice: with `g` groups over 48 layers, it would cross host backing at `g - 1` group boundaries, giving `Bdirection = n * 40,960 * (g - 1)` rather than 47 boundaries. That genuinely reduces host residual bytes if the implementation actually keeps activations on device within groups, but it requires the group weights and state/fences to be valid. A full-context host residual plane remains the backing capacity requirement. This is not “order alone,” and the estimate is not an implementation or performance result. In-place residual aliasing can remove modeled GPU D2D copies for the GPU prefix; it does not remove the host H2D/D2H handoffs.

There is one transfer-rate-independent capacity contradiction in the specified full-plane placement: the 262,144-position residual extent is 10 GiB (10,737,418,240 bytes), while the whole B570 device capacity in the correction is 10,666,115,072 bytes. The residual plane alone exceeds the device's entire stated capacity by 71,303,168 bytes (68 MiB), before QSA KV, model weights, session state, scratch, or runtime allocations. Thus a design requiring the *entire* 262K residual plane on this GPU cannot fit even under ideal transfer rates. This is a real physical-capacity arithmetic result, independent of pageable/USM/PCIe rates. It does not show that a 262K prompt is impossible: host backing is 10 GiB, and a host-backed or smaller-GPU-prefix placement is a different architecture. It also does not prove any candidate's actual peak allocations or full-context correctness. At 32K, the 1.25 GiB residual plane by itself is below total GPU capacity, but that comparison alone does not admit a GPU placement alongside simultaneous allocations.

Accordingly, the statement “order changes cannot reduce bytes” is true only for the same set of transfers under fixed placement. It is false when a qualified layer-group schedule removes intermediate host crossings. The 32K pageable estimate is conditional on transfer behavior and serial exposure. The 262K all-GPU residual-plane oversize is the genuine, rate-independent capacity contradiction. None is evidence that the current production route uses all-RAM residual handoffs or that residual traffic is the measured critical path.
