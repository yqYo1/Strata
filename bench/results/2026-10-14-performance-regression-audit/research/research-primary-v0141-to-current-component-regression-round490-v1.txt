## Source resolver proves an engine-family switch

At `1eb89482`, root `CMakeLists.txt` enters `sycl/CMakeLists.txt` and returns. The SYCL `strata_resolve()` prefers `sycl/src/<path>` copies, then root source; its registered `_kernels` include migrated CUDA-derived `sycl/src/kernels/cuda/*.dp.cpp`, with port-only `qsa_prompt_attn_xmx.dp.cpp`. It links MKL SYCL BLAS for the old migrated `prefill/gemm.dp.cpp`, builds migrated `prefill/kernels.dp.cpp`, and includes migrated native MoE fused IQ support.

At current 4fa, root CMake includes `cmake/sycl_backend.cmake`; that directly compiles the current root-native `src/kernels/sycl/*`, `src/prefill/sycl/{gemm,postops,blob,moe_mmq,moe_fused}.cpp`, and root `src/prefill/prefill.cpp`. It does not resolve or build the `sycl/src` overlay. The two entrypoints select different implementations behind some shared function names. Therefore the valid question is whether each former active component has an equivalent or better current call path under the measured flags, not whether old history is an ancestor of 4fa.

## Likely regression hypotheses, ranked by source evidence

1. **Active QSA prompt path lost its measured layout selector.** The actual old run used layout 1 and the current resolver has no equivalent option. QSA attention repeats across the prompt; this is the clearest user-selected per-layer implementation disappearance. Speed attribution still requires phase/model A/B.
2. **Old compact=2 workspace selection no longer exists under the same meaning.** The current workspace is sized around current MMQ/fused layout and shares buffers differently. It may alter maximum feasible chunking or allocation/relayout behavior; user-configured actual chunk is 8192 on the old run, so this alone is not proof of 3–4× PP regression.
3. **Old and current prompt expert/attention kernel families differ even where interfaces match.** The current source has capable native MMQ/fused and joint_matrix attention paths; format, chunk, dispatch, fallback and workspace sizes must be compared. The 0.1.41 integrated run combines these with all upstream and safety updates, so its +5.204% cannot be assigned to a kernel.
4. **Compile/JIT and queue timing may affect first use or measured phase boundaries.** The historical quiet run excludes profiling and first-use rows separately; global build flags differ. These are worth matching in warm runs but cannot explain sustained prefill solely from source flags.
5. **CPU/prefill scheduling could differ despite `pool-workers=5`.** Compare number of CPU-served expert jobs and their rows/phase before drawing conclusions. Old decode does not establish a reliable advantage; decode medians are effectively tied.

The old and current runs both have actual 32K fresh inputs, 262K context, int8 KV and 32K resident KV in the historical comparison, so this is not dismissible as a short-prompt or FP16-KV setting mismatch. However, tool methodology differs: old uses six later reads across two processes; current owner procedure uses quiet GEN64. The actual `1eb` integrated-versus-control gain is only +5.204% PP; it does not itself account for a large current-vs-old gap. Need compare current-vs-old individual samples with matching selected request method before quantifying the magnitude.

Specifically retain queue drain before release, graph retirement before pointer/cache invalidation, canonical spare/full-capacity checks, typed-access tails, and delayed speculative visibility. Do not restore global `SG32` or remove `size_t` query flags; annotate/test subgroup assumptions per candidate kernel.
7. Keep separately: (a) clean warm throughput with no profiling and the current owner’s fixed 64-output method; (b) correctness/fault/lifecycle checks. Record all individual timings, source/binary SHA, actual input end, outputs, process order, flags, model/KV/cache/chunk, JIT/AOT state, and event/normal-exit result. Apply the same method to both trees when allowed by Main; don't cite the old harness result as exact parity with the current GEN method.

## Conclusion

The previous R489 caveat that no measured pre-Xe result tied a source loss to regression is superseded by the pinned, byte-preserved `historical-v0141/tuned32k` evidence. Before Xe work, the separate 0.1.41 SYCL source lineage delivered actual 32K PP around 449.7 tok/s with matching cross-version outputs. Its measured source path is demonstrably not the current 4fa path. The most actionable missing selectable components are compact=2 workspace semantics and QSA prefill layout=1; old QSA XMX is a different kernel implementation while current retains a matrix attention path. The historical integration gains only +5.204% over its already-qualified control and decode is statistically unresolved, so neither it nor the source differences alone explain current performance. Restore as current-source, per-component candidates, retaining all safety and long-context contracts; confirm attribution with matched current method before concluding the regression magnitude/cause.
