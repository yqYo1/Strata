## Native-pack route and row alignment

In the assigned generator, native packs are identified from the loaded expert layout (`generate.cpp:2512`). The input guard currently requires `--native`, `--spec T` with T at least 2, and a positive `--prefill` chunk (`2678–2685`). The long prompt is batched as `n_batched = n_prompt - 1` by default and passed to `prefill.run` (`11672–11682, 11770`). Then `pos_start=n_batched` and `tok=tokens[pos_start]` (`11809–11813`). For prompt length P, Prefill processes IDs 0 through P-2; the verifier's first T=1 window consumes the final prompt token at position P-1 and produces logits for c0. The native path explicitly leaves the ordinary per-token loop and sets `spec_pos` there (`11828–11830)); verifier initialization follows (`12127–12140)). `first_window=native_pack` and `T=1` are explicit (`12322–12324, 12375–12383)). Thus the actual compiled native_pack route already has the needed first full-vocabulary row in `Verifier::run`, after the long Prefill state and final prompt token, without changing Prefill.

A minimal quality-only mode can reuse this seam and `Verifier::window_logprobs` (`verify.cpp:2443–2493)), which copies the completed window's `T*n_vocab` head logits and computes stable log-sum-exp, target log-probability, argmax/log-probability, and optional top-K. For exact simple coverage, make the ability mode run one verifier token per round (T=1), capture and score the single target `follow[j]` at absolute predictor/input position `P-1+j`, then replace the model output with that same fixed ID before it becomes the next input. Existing `--spec-follow` already substitutes output IDs after `ver.run` (`12463–12469)); the `T=1` native first window guarantees c0 is included. Add scoring before substitution/commit. On the next round the fixed token is `x`, so the same SessionState is advanced once and the next row scores c1. Repeating this N times scores c0…cN-1; the final target need not itself be consumed to score its probability. Do not use multi-token windows for the first implementation: existing speculative acceptance uses drafted window inputs, and scoring rows after an unforced/wrong draft would condition later rows on the wrong prefix.

The existing `--spec-follow` is close but incomplete: it substitutes continuation IDs and reports argmax disagreements; it does not call `window_logprobs`. Its current code can also run with T>1, where speculative window inputs may differ from the fixed target prefix. The ability mode should bypass draft selection and acceptance semantics, force T=1 throughout, and append each supplied target once. It must ignore EOS/visible-output truncation until all N score rows exist (or reject EOS-containing continuations under an explicitly declared policy). Keep MTP unbound/off, and disable suffix/lookup draft sources. The native-pack CLI guard means ordinary `--spec=0` currently cannot reach this route. To provide a true “MTP/spec off” ability mode, a source change must allow the ability-only native path through that guard, while initializing a verifier with its minimum supported window capacity 2 (`Verifier::init` rejects max_t < 2 at `verify.cpp:432–435`) but only calling `run(1,...)`. It must skip the normal speculative loop/drafter rather than pretending `--spec=0` works today. Alternative temporary use of `--spec 2` may satisfy current validation but still enables the speculative route and therefore does not meet the requested off-mode cleanly.

## Admission and complete coverage

Let P be prompt ID count and N the fixed continuation ID count. Reject before model work unless N>0, every ID lies in [0,n_vocab), and N fits the declared generation budget. The predictor positions are P-1 through P+N-2. With physical context capacity C=262144, require `P+N-1 <= C`; final predictor position is then at most 262143. A request needing a predictor at 262144 is invalid, even if it labels itself “262144 tokens.” Keep P-1 batched (require default n_batched=P-1 and reject a `--prefill-until` split), and report selected Prefill chunk/path. At completion assert exactly N rows, target IDs exactly equal follow[0..N-1], predictor positions are contiguous P-1..P+N-2, and no stop condition ended the run early. Include P, N, C, max_new, chunk, and first/final predictor positions in the compact result.

This is an admission rule for scoring, not a measured 262,144-cell pass. R296/R321 require the separate physical-capacity lifecycle test to prove actual last-cell access and restore/repeat behavior. A full-length score additionally needs the exact binary's other admission/allocator predicates pinned; the inequality above is the mathematical bound for predictor positions and must not be mistaken for proof that the current binary admits the request.

## Restore, cache, and execution mode

Use a fresh standalone request with no session restore, prompt-cache hit, parked conversation, or partial prefix resume. Such a restored state can skip the candidate batched Prefill or omit its terminal row, breaking attribution. Do not enable server checkpoint paths for this measurement. Start from the same fresh SessionState and token IDs in control and candidate.

The existing Prefill cache lease is a separate storage-lifecycle concern. It borrows expert-cache slots before `prefill.run`, refills those slots afterwards (`11683–11724, 11774–11806)); preserve that sequence exactly. If `STRATA_PREFILL_RELEASE_CACHE` is used, its callback updates `drive.d.cache_base` and `thits.cache_base` after reallocation (`11755–11768)); verifier `VerifyHits` is built later from those pointers (`12127–12136)). The ability hook should not hold/reuse stale verifier cache pointers across that restore. Do not change cache behavior between paired arms. Score readback and log-softmax are quality-run overhead and invalidate timing; run performance measurements separately.

## Prior and external implementation pattern

R320's plain-loop seam is not the right native-pack hook because native_pack breaks before `run_head`; the verifier first window is the native path's corresponding head-producing point. `STRATA_DUMP_FIRST_LOGITS` at `generate.cpp:12484–12489` writes that first row only and does not force continuation. LOGPOS alone likewise does not establish the long Prefill plus full fixed-answer contract (R294/R297).

The official vLLM source exposes prompt log-probabilities per position and explicitly represents the first prompt token as having no preceding-token probability; it also has tests asserting prompt log-probabilities cover all later prompt positions. This is a useful alignment convention for the proposed P-1/c0 first row, not evidence about Strata's implementation: [vLLM logprob containers](https://github.com/vllm-project/vllm/blob/main/vllm/logprobs.py), [vLLM prompt-logprob tests](https://github.com/vllm-project/vllm/blob/main/vllm/tests/v1/sample/test_logprobs.py). A vLLM issue discussing fixed prompt/completion scoring is only a design lead, not an implementation guarantee: [vLLM issue #5234](https://github.com/vllm-project/vllm/issues/5234). The main external lesson is to define the one-token shift explicitly and test coverage; do not treat an API's prompt-logprob label as proof it includes the completion's first token after a separate batched path.

## Conclusion and status

The smallest source-level seam is in the native verifier loop: after each T=1 `ver.run`, score the supplied target with `window_logprobs`; then force that ID as the one output/next input and commit once. This preserves the long batched Prefill and uses the same live model state. A dedicated ability mode needs an admission exception for native_pack when conventional speculation is off, an internal verifier capacity of at least 2, and a forced single-row run loop. This is a source design only. It has not been compiled or executed; complete coverage, context admission, cache restore handling, and model-quality implications remain unverified.
