Confirmed source concern (Main finding): first query-selection loop can access a block in different work-items at different query-relative selection positions. Ordinary page_table read can overlap atomic -1 -> -2 CAS. Ordinary identical-value resident slot stamp/ref writes can overlap one another. SYCL has no identical-value race exemption. Fix uses existing relaxed/device/global atomic_ref<int32_t> load for page_table and stores for slot_stamp and slot_ref. CAS and algorithm, loops, kernel ordering and every barrier remain unchanged. This finding does not establish the cause of any GPU hang.

Barrier/ownership audit:
1. Initial barrier separates tid0 ordinary sh initialization from local atomic increments. Every work-item reads epoch before that barrier, so final tid0 ctl publication cannot overlap those reads. sh counters are read ordinarily only after all increments finish at the selection-ending group barrier.
2. All page_table accesses in selection are now atomic. Multiple resident stamp/ref updates are atomic. Relaxed operations suffice because these accesses select a marker or set an identical epoch/ref flag; no other data is published through an individual atomic operation. Existing work-group barriers provide visibility at the phase boundaries, including global memory. Atomic references here are temporary, and later ordinary accesses occur after the phase boundary.
3. Each sweep iteration maps tid to (hand+tid)%n_slots; legal n_slots >= RT makes indices distinct. block_scan barriers separate candidate reads from write selection, cut publication barriers serialize sh[2], and the end-of-iteration barrier orders slot_stamp/slot_ref writes before the next sweep's reads. No mixed atomic/plain operations remain concurrent here.
4. Miss block uniqueness follows from CAS success once per -1 page. Sweep stamp protects taken slots from re-selection after wrap and selected resident slots from eviction; miss slots are unique. Last sweep barrier orders sweep accesses before placement. Old resident blocks are distinct and cannot be miss blocks (initial map inverse invariant; miss blocks started at -1); placement page_table and slot writes are therefore disjoint. No blanket atomic conversion needed. Zero-miss calls skip both sweep and placement.
5. Resolve and pool copy kernels are submitted to production Runtime in-order stream/compute queues (src/core/device.cpp). This patch does not repair unsupported simultaneous resolves/appends to the same map on independent queues. Existing map integrity, ascending valid IDs, slot capacity, integer ranges/epoch lifetime and queue ownership remain preconditions.
