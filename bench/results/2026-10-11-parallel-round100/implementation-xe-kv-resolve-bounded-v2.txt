Completion, ownership, and exceptional exits
CLI argc must equal1; extra arguments return2 before Runtime initialization. The queried Runtime must report GPU; compute must be in-order, use the same device/context, and be owned by Runtime::owner_of_stream. Before allocations, both host/device USM aspects are checked; every allocation checks exact pointer type in Runtime context and Runtime::owner. Host-USM initialization occurs before any probe command uses that pool. Every upload waits before its source can change, every readback waits before its destination can be read, and every resolve is followed by checked Runtime-wide finish before any host-USM oracle access. No simultaneous CPU/device access is assumed.

Reset/resolve use explicit &compute stream; this avoids their implicit null-stream finish path. All probe Runtime::wait/finish calls and enqueue calls sit inside immediate checked() catch boundaries. An uncertain submission/wait/finish exception invokes production publication::cleanup_require(false, operation, error-text), which flushes its diagnostic and _Exit74; no retry, cleanup drain, stack/global buffer destruction, or USM free follows. The same conservative contract handles a release exception. Runtime initialization is also wrapped. Runtime-internal exception mechanics/watchdog remain production behavior, not invented completion capability. For other exceptions (allocation, type/owner validation, byte/map/count mismatch), owning containers remain alive across the handler: one checked whole-Runtime drain, then USM release; a throwing drain immediately takes74 without retry.

At successful end of each format, one terminal whole-Runtime drain succeeds before any USM free. Every USM pointer is freed, then the format returns and ordinary vectors are destroyed. Only then can the next format begin. After both returned format frames and flushed receipts, main uses explicit _Exit0 to avoid Runtime's additional implicit global-destructor waits after the finite trace. Safe noncompletion error returns from a format use _Exit1 at main after that frame drained/released; pre-format exceptions similarly drain once before _Exit1. _Exit is not a fence or recovery claim: the successful drains, not process teardown, establish ownership before release.
