Actual integration path and controls
The source includes the real public gpu/runtime headers and production
publication::cleanup_require. It calls Runtime::get, uses &Runtime.compute as
the explicit Stream for every record/copy, and checks the queue's in_order
property. Runtime::get retains production engine device admission/selection,
context construction, marker-policy measurement and watchdog. No Runtime stub,
Event replacement, extracted helper, mirrored timestamp subtraction, fake
completion, new kernel, graph, additional stream, preload or polling is present.
The committed device.cpp carries the engine's existing ProbeKernel image for
device admission; the probe adds/launches no unrelated kernel. Runtime startup
can enumerate/query devices, obtain bundles and perform its own marker/barrier
policy measurement. It is not represented as a zero-initialization-cost harness.

The two timing Events are opaque actual production Events. Timing records always
use submit_profiling_tag; normal production queues need not enable the old DPCT
queue profiling property. Recorded non-timing Events retain Runtime's selected
barrier/tag policy, and are still refused by event_elapsed_ms's timing guard.
No environment marker-policy override is introduced to make this probe pass.

Controls before the fixed samples:
1. Two unrecorded timing Events form a refused pair: false, exact production
   "event_elapsed_ms: an event was not recorded", bitwise unchanged float sentinel.
   Neither Event owns a queued recording, so this negative query needs no invented
   completion fence. The pair is checked without submitting it.
2. Two non-timing Events are recorded on the same compute queue, followed by a
   successful checked stream_sync before querying. The query must return false,
   exact "event_elapsed_ms: an event was not created for timing", unchanged sentinel.

Each of exactly eight planned samples (no CLI parameters) does:
  - change all 4194304 source uint32_t words deterministically by sample index;
    poison every destination word with the complement of its current source;
  - start host steady_clock immediately before the first timing record;
  - record start, copy 16 MiB H2D, copy 16 MiB D2H, record end, all on that same
    actual in-order compute queue;
  - checked production stream_sync; stop host wall immediately after return;
  - compare every roundtrip word with the actual staged input;
  - query normal completed start/end interval using production event_elapsed_ms;
  - deliberately query the completed pair in reverse with a fixed float sentinel;
  - query completed end/end and require actual zero.
All host rewrites and Event reuse occur only after preceding checked completion.
Event durations are queried after the current checked stream completion, never
used as a wait or a proof of device completion themselves.

Raw endpoints come solely from the real reversed query's last_error:
  event_elapsed_ms: end < start (start=<later raw>, end=<earlier raw>)
The bounded strict parser extracts decimal uint64 fields, without subtracting,
scaling, correcting or replacing them. Output raw_start_ns/raw_end_ns restores
the normal earlier/later labels; the original reversed error is also printed
verbatim. It requires earlier>0 and later>earlier, false API result, and bitwise
unchanged sentinel. At least one positive distinct reversed case is necessary;
this implementation conservatively requires every one of its eight samples to
establish that case. Equal/zero-resolution endpoints reject the arm, with the
real API/result/error retained. A same-event zero never independently earns PASS.

Coverage, plausibility and budgets
Markers enclose both transfers by same-queue in-order sequencing. Successful
checked completion and a fully changed/poisoned data roundtrip establish that
the submitted transfer work completed within that ordering. Their interval is
a queue timeline including applicable scheduling/host gaps, not exclusive kernel
or DMA service. No phase/service additivity or PCIe/device roofline is claimed.
Correct data/order is not independent proof that the implementation's profiling
tag timestamps cover every nanosecond of those transfers correctly; that remains
a contract/domain/adapter uncertainty, explicitly retained.

Host wall is a separate monotonic-clock observation: first marker submit through
successful compute stream_sync return, including host API/submission/wait cost.
Pattern creation, data verification and postcompletion query/logging are outside
that bracket. Success-path completion wrapper performs no output flush before
the wall endpoint. Clock epochs are never correlated. The only duration sanity
gate is finite positive event/host durations and:
  event_ms <= host_wall_ms * 1.25 + 10 ms
This deliberately loose ceiling rejects gross implausibility without an invented
accuracy/clock-drift band. No lower bandwidth-derived bound, calibrated timer
domain, division-derived speed, wrapped-counter repair, clamp, best-of sampling,
retry, reset, backend fallback or host-clock replacement of a failed event exists.
An ordered but subtly wrong duration can still pass this ceiling; report that
limit instead of calling these timings independently validated performance.

Fixed allocations: one 16 MiB device USM buffer, two 16 MiB host USM buffers,
five Event wrappers; real Runtime/driver overhead is additional. These are actual
SYCL allocations in the production Runtime device/context. Probe-owned allocation
checks guard every partial construction. Direct SYCL free after terminal drain
avoids inserting an additional Runtime::free wait during release; this is not an
exercise of production allocator bookkeeping/DeviceArena or a mock allocation.
Each sample moves 32 MiB, whole arm 256 MiB. Full comparisons total 33554432
uint32_t words; pattern/poison writes are also finite. No runtime sample/size knob,
model/context/cache/math change or unbounded submission loop exists. Runtime's
preexisting watchdog has a 120-second hang limit. Finite probe work is not a
guaranteed wall deadline for driver/initialization failures; Main owns supervision.

Completion/failure ownership
Owned exists before any probe allocation/Event construction and holds all partial
state. A submission API false/exception, data mismatch or query-contract failure
throws to this scope; no next sample or other work submission follows. Its sole
cleanup terminal drain is actual gpu::device_sync (all queues owned by the current
Runtime), checked through existing publication::cleanup_require before ANY
probe Event or host/device USM is released.
Every sample/control stream_sync is independently checked. If a completion call
returns false or throws standard/unknown exception, the wrapper flushes output
and uses actual cleanup_require(false) to print operation/error and _Exit(74)
at that point, before scope unwind or another wait. Failed wait is never retried
or treated as completion. The destructor is noexcept and takes this same policy.
Successful drain precedes Event destruction and real USM free. A release exception
gets a separate flushed "release failed after checked completion" diagnostic and
_Exit(74), stopping any further release; it is not falsely described as a failed
wait. No successful-path queue ordering or production wait/watch policy changes.

Runtime initialization happens before any probe host storage is allocated. An
initialization failure rejects the arm and retains the production constructor's
own behavior; the diagnostic cannot repair/protect internals already unwound by
that unchanged implementation. Normal Runtime static destruction still performs
its own checked finish. Its existing fatal/watch path can exit 1, or startup may
fail before Owned exists. Require actual normal exit 0 as well as printed PASS;
a PASS line before a later production destructor fault is not an accepted arm.
No actual asynchronous failure, unknown-completion event, hang or constructor/
release fault was injected or qualified here. _Exit is fail-stop process teardown,
not a GPU fence, reset or claim of recovery.
