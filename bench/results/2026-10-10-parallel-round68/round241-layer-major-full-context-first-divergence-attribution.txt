## Semantic path that must be held fixed

For the historical full input, normal generation consumes 262,144 physical positions as 262,140 batched positions plus four token-path positions (the reported split-control), ending at physical cell 262,143. The ordinary N-token CLI convention instead batches N−1 and processes the final prompt token on the token path. Layer-major applies only to the positions actually passed into `Prefill::run`; a 262,144-token prompt by itself does not prove that all 262,144 positions ran through the layer-major prefill body. R160/R199 specify the correct strict-cap route: test-only zero-output admission, preserve the normal final-token/head path, consume the input at position 262,143, drain, snapshot, and stop before sampling/appending. Never substitute a 262,144-token prefill call that skips the final position path or a synthetic 262K GDN fixture for the full model lifecycle.

On a fresh request, `session_zero` zeros every GDN recurrence/conv state, every owned QSA cache/indexer state, PLE convolution history, and sets `ple_prev` to `[-1,-1]`. In `run_layer_major`, the starting PLE pair is saved and restored before each layer's `run_impl`; within that layer's chunk loop, its own GDN state slice (indexed by GDN ordinal) and QSA state (indexed by QSA ordinal) persist from chunk to chunk. `run_impl` rolls PLE history across chunks and commits the final pair. QSA step records use absolute `p0+t`; QSA K/V, indexer tail/dead/pool/block position, selected IDs, and attention state are separate per QSA layer. At each model-layer boundary, layer L's residual output for `(p0,T)` is copied to the persistent host/GPU row plane and is the next layer's input for the same `(p0,T)`. R40 states the byte invariant `post_moe(L,p0,T) == R_input(L+1,p0,T)`; it was source-audited, not measured for all rows in the failed receipt.

The fresh C repeat path did not use conversation restore as the initial condition. Do not assign it to checkpoint restore without evidence. For any separate restored-continuation control, the exact current `conversation_snapshot_restore` path restores QSA KV, GDN state, PLE history, indexer tail/dead/block position, and derives `ple_prev` from the final two saved IDs; it must be separately verified byte-for-byte before continuation. Fresh-start and RESTORE arms are distinct semantic inputs, not interchangeable repeats.

Weight reuse and submission ordering are different hypotheses. Layer-major loads each expert's packed weight once per layer and reuses it across chunks; pure submission reordering keeps the same work/bytes and changes only issue timing/overlap. The hardware-architecture decision note makes this distinction and labels its 50.29GB/190.24GB figures conditional scenarios. R240 also corrects that the 384-expert IQ2_S/IQ4_NL capacity fixture is not production graph metadata; record the actual graph expert count, each layer's loaded native type and actual `ne`, and actual source/cache path. The ordinary SYCL path stages packed blobs on CPU, then dequantizes on device and calls oneMKL GEMMs; CPU quantized-decode measurements are not this path. If operation shapes or kernels differ between arms, that is an arithmetic-path confound, not a pure order comparison.

Already-rejected/redundant directions: the current QSA indexer append-batch is already parallel over completed blocks; do not re-test “serial append” as the new cause. A source reset audit makes simple stale QSA indexer state less likely but cannot rule out wrong input, incomplete state, alias, or race. The D fixed-window instrumentation cannot explain the earlier C repeat. No report demonstrates full-context repeat parity or root-cause onset.

## Finite attribution sequence

Run only under the main owner's serialization and existing retention/ownership controls. First pin one source/build/model/input and verify the binary used for every arm. The historical C failure cannot be called a result on commit 495 without a current-source replay; preserve the old receipt/status separately.

1. **Admit identical full input and reset.** Hash the exact 262,144 token IDs and record `pos0`, prefix/tail split, actual `n_batched`, all `(c0,T)` boundaries, output count, and final consumed position. Start each arm with a new equivalent session or a proven `session_zero`; require zero resume/reuse counts and record GDN/PLE/QSA reset hashes. For the first reproduction pair, run two identical layer-major fresh sessions with no intervening 32K request. This distinguishes a repeat defect from the old interposition sequence. If both pass, one additional pair with the exact old 32K interposition can test whether interposition is necessary; do not use it as the initial control. Capture the final prompt token's token-path/head completion so the physical endpoint is exactly 262,144 positions and zero generated IDs are appended.

2. **Use one order-only control.** On the same immutable binary, model, fresh state, route-affecting environment, `m.T`, first-chunk setting, and token IDs, compare ordinary chunk-major (`STRATA_PREFILL_LAYER_MAJOR=0`) with forced layer-major (`=2`), each at the full 262,144-position strict-cap lifecycle. Keep chunk lengths identical (including 8,191 or the chosen matching tail), compact FP16, resident-KV/no-PLE-preload eligibility, and all math/route selectors fixed. Log actual experts, types, per-expert `ne`, GEMM args, kernel selection, cache lease/restore mode, and whether each packed blob came from resident RAM or a transient read. Hash/verify the actual packed bytes restored for any cache lease. If shapes, weights, or kernels differ, stop calling this an order-only comparison and branch to the corresponding arithmetic-path check.

3. **Record only ordered boundary digests first.** At every `(layer,chunk)` boundary hash the full input residual, post-MoE/output residual, and the persistent host/GPU row interval. Enforce `post_moe(L,p0,T) == R_input(L+1,p0,T)`; record allocation identity, offset, length, queue/event dependency and successful completion before hashing. At each GDN layer/chunk hash the input row, projection/gate inputs and outputs, recurrence input state and output state, convolution history, and output projection. At each QSA layer/chunk hash Q/K/V pre-quantization, K/V code plus scales/zero metadata, `idx_tail`, `idx_dead`, active pooled rows and `idx_block_pos`, step words, active score bits, selected cell IDs/order, selected K/V bytes, attention output and residual. Hash the PLE window/prev pair and token IDs at chunk seams. Include the saved final GDN, PLE, all QSA KV/scales/indexer, output/logits, and exact position-validity state. Emit digests/first differing offsets, not full tensor dumps. If a producer queue/lifetime cannot be ordered safely, omit that edge and mark its attribution unavailable; do not read a reused buffer asynchronously.

4. **Stop at the first mismatch and classify it by the immediate dependency.** If layer L input residual differs, compare layer L−1 output and its host/GPU spill/reload bytes; mismatch only after spill/reload is an order/ownership handoff candidate. If residual and packed weights/routes are equal but GDN state entering chunk c differs, trace the preceding chunk's GDN output and reset/restore history; if the state and operation arguments are equal but projection or recurrence output differs, reduce to the first kernel's exact same-input output and call descriptor (arithmetic route, nondeterminism, or race). For QSA, equal Q/K/V plus different KV bytes/scales indicates append/quantization; equal indexer input/state plus changed active scores/selected IDs indicates score/top-k; equal IDs and selected K/V plus changed attention output indicates attention arithmetic/scratch; changed preceding residual or indexer history makes downstream QSA differences consequential. Only after localizing should one bounded raw window around the first changed stripe/cell be retained.

5. **Test restore only if the fresh result points there.** Save an exact checkpoint at an agreed prefix in a separate arm, verify the checkpoint IDs and every GDN/PLE/QSA K/V/indexer component against the live source before closing it, restore into an equivalent clean session, and continue the same suffix to physical position 262,143. Compare against a continuous fresh run. This arm still accounts for all 262,144 input positions and must report the restore outcome; do not equate restoring a partial conversation with fresh `session_zero`.

## Decision rule

A deterministic same-mode repeat is the prerequisite. If repeat mismatches while every aligned operation input, route, weight byte and history hash matches, classify the first output-only difference as a kernel arithmetic/nondeterminism/race candidate. If a layer/chunk input or carried state already differs, follow the exact preceding residual, recurrence, PLE or QSA handoff and label it an order/state/restore/input-path defect only after that edge is isolated. If chunk-major and layer-major have identical per-operation inputs/shapes but differ reproducibly, the outer processing order or its storage/lifetime schedule is implicated; if inputs or actual GEMM types/shapes differ, arithmetic-path differences remain viable. No one changed final state, matching generated IDs, or faster/healthier completion is a causal pass.
