## Source verdict

I found no concrete unsafe compact-buffer access or count/carve mismatch in the patch for its declared scope, subject to execution validation. Its key safety argument holds in the reviewed current path:

- Admission (`patch` near current `prefill.cpp:623`) requires the exact opt-in, `mmq_plan().any == false`, fallback active, no `STRATA_DBG_NAN`, and, for native layout, nonempty formats all at N=2560/FF=640. The current MMQ plan marks `any` when any layer takes MMQ (`prefill.cpp:603–620`), so mixed MMQ/fallback layouts cannot enter compact. No MMQ/fused scratch contract is silently shrunk.
- `fp16_moe_rows(T)` is the shared sizing rule. The candidate changes both count-only and carve takes for Xs/Hh, and `moe_bufs()` GU elements; the corresponding takes remain in the same order and types (`prefill.cpp:645–667`, `:834–861`). Region sizing uses `moe_set_bytes()` as one of the three maxima, so init and relayout inherit the same compact plan. The helper is process-static through the admission and therefore cannot switch between count and carve absent unsupported concurrent environment mutation.
- For a chunk with actual `T <= m.T`, router top-10 selects without replacement: both current router implementations overwrite each selected probability with negative infinity before the next rank (`router.cpp:45–71`; `native_router.cpp:83–105`). Thus one expert receives at most one row per token and `cnt[e] <= T`; the proposed pre-increment check is a fail-closed guard (`prefill.cpp` candidate near `:2105`). The histogram offsets partition exactly the `T*K` routed rows. Each `src_h[p] = i/K` is in `[0,T)`. With no peer path (`peer_init` requires MMQ; current compact admission excludes MMQ), offsets are ordinary expert-order offsets. The compute guard checks `0 < ne <= T <= m.T` and `0 <= o0 <= T*K-ne` before using the range.
- Compact gather reads precisely `ne` source indices starting at `src_dev+o0` and writes Xs at row zero. GU and Hh use the same zero-based scratch rows; Down writes to the original global `Dm + o0*N`, preserving the scatter expected by `moe_combine`. The original full `T*K` Dm and route arrays remain allocated. The earlier whole-chunk gather is skipped only in compact mode (`prefill.cpp` patch near `:2188`).
- Resident and staged/streamed experts both call the same `compute` lambda. Dequantization precedes optional gather and GEMMs; the staged blob's `used` event is still recorded after the dequant read. Compact gather consumes `mixed_h`/`src_dev`, not the expert blob, so it adds no source-blob lease. DQ buffers are reused in the same in-order compute queue; each subsequent dequant/GEMM is sequenced after prior work. `queue_for()` enforces in-order queues (`launch.hpp:47–57`), and oneMKL `Gemm::f16` submits on that queue and retains event ordering (`gemm.cpp:17–29, 101–107`). No extra host wait is needed per expert.
- The successful `run_impl` and release fences remain outside the patch. On early error, the function returns failure and existing caller/owner shutdown drains queues before freeing workspace; the patch does not catch an async exception and continue reuse. The bound error itself occurs after this expert's dequant may have been submitted, so callers must keep the existing fatal-error/drain contract. No source shows an error path that reuses the compact workspace after this return.
- `STRATA_DBG_NAN` is declined based on presence, matching the existing diagnostic's presence check; this avoids its full `T*K` GU scan overrunning compact GU. The patch does not preserve per-expert GU/H diagnostics when enabled, so no compact diagnostic claim should be made from that mode.

No specific bad patch line or condition was found in these reviewed invariants. The source review does not establish compilation, allocator admission, numerical quality, runtime correctness, or speed.

## Minimum runtime cases before adoption

Run serially in the configured root/SYCL build and capture the effective compact admission and actual chunk, since the environment variable alone does not prove the fallback/layout gates passed. At minimum:

1. Same supported native format inventory, `STRATA_PREFILL_MMQ=0`, fallback only, matched 4096 chunk: option off vs on; include a real chunk with resident experts and another with staged/streamed experts. Check per-layer outputs/logits or distribution deltas, finite values, and that expert rows land in the same Dm offsets. Exact model output identity is not a blanket adoption requirement.
2. Exercise a short final chunk (`actualT < allocatedT`, including T=1) with option on. Confirm count/offsets and no stale rows influence combine. Exercise `relayout` from a larger borrowed allocation to a smaller chunk and back if that API is used by the selected entrypoint; sizing/carving must stay within the same region.
3. Check `STRATA_DBG_NAN` presence and compact request together: it must decline compact and retain the original full layout. Also check a plan with MMQ active (including a mixed supported/unsupported format plan) and an unsupported native geometry; both must retain stock scratch. These are gate checks, not compact-path performance cases.
4. Trigger the existing cancellation/error or allocation-failure boundary only if a ready offline seam exists; verify the caller treats failure as terminal and drains the compute/copy queues before workspace reuse/free. Do not invent a fault injection or GPU run during the active benchmark. The existing source contracts should remain unchanged.
5. After those pass at 4096, record actual admitted capacity and allocation plan. Request 8192 only if both baseline and candidate allocate it; then test the same tail and lifecycle cases. The source-derived byte reduction is payload arithmetic only, not proof of 405 MiB actual region savings at 4096.

Use the practical numerical gate from R496: structural/finite checks plus representative intermediate or distribution deltas and a bounded task-quality comparison. Do not require bitwise FP32 or identical generated strings. Keep performance evaluation separate and only after correctness/capacity validation, with the active primary benchmark serialized by Main.

## Decision

The proposal is internally plausible and no source-level bug was identified in the requested compact Xs/GU/Hh reuse, actual-vs-allocated tail, fallback/resident/streamed branches, relayout counting, offset bounds, queue ordering, source/DQ lease, debug layout, or error ownership. It is not ready for adoption without the minimum execution cases above. R495's corrected old route makes the proposal a reasonable capacity/layout restoration candidate, but supplies no evidence of current-root speedup.
