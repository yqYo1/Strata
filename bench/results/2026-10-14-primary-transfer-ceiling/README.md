# Primary transfer ceiling proposal, 2026-10-14

Implementation-only candidate for feature/sycl HEAD 5bf07429. No build, test, runtime, GPU, profiler, service, model payload read, Git mutation, or measurement was performed. Main owns application and serial validation after the live model run ends. This is a synthetic transfer helper, not an inference change or an adoption decision. Sole upstream is Niko1221/Strata.

The helper links only the current production `strata_sycl_runtime`, calls its CUDA-named compatibility allocations/copies/events, and checks its explicit stream has in-order/profiling properties and the cached Runtime's device/context. It never constructs `NativeExpertSource`, registers/maps model memory, or loads expert data. Host-USM means `cudaMallocHost` -> production `MemoryKind::Host`; physical OS pin state is not asserted. Ordinary host means `malloc`, with no fallback.

`extract_extents.py` reads at most 1 MiB of `native_experts.txt` only, validates ordered layers, cumulative blob offsets and total against the header, and emits every actual extent and metadata SHA-256. It opens no index/GGUF/expert payload. Its exclusive-create TSV output carries expert/layer counts and every layer extent. The helper chooses actual min/lower-median/max extents; if equal it deduplicates. The current metadata inspected textually has 48 layers, 512 experts, total 50,292,326,400 bytes, min 1,510,400, lower median 1,971,200, max 2,662,400 bytes. The two middle layer sizes differ; mathematical median 2,073,600 is not an actual copy shape and is never substituted.

Large lane: exact 256 MiB, four back-to-back same-stream bursts with five event brackets, all four event rates plus best and median per repetition. Uses the same one-slot reuse as the existing current bulk selector. Four distinct 256 MiB slots would exceed the lane bound; bulk reuse is disclosed. Each allocation has 128 extra guard bytes, explicitly reported, so the exact 256 MiB payload can coexist with before/after guards. Small lane: each allocation is at most 256 MiB including guards; as many distinct slots as fit up to metadata n_expert, batches 1/8/32, rotated starts by repetition, no padding of copied payload. A full 512-slot layer does not fit this bound. Each slot has 64-byte guards and preserves the underlying allocator alignment; no new host-alignment guarantee is assumed. This is not a production slot-alignment study.

Every sample contains shape, arm, repetition/order, byte/copy counts, individual copy-call times, whole enqueue span, final host completion wall, compat event interval, effective rates, setup/verification/lifecycle API counts, slot count, allocation bound and full payload/corpus/guard status. Bulk host completion and counts refer to the same four-burst group, are repeated on its four records, and must not be summed. Copy-call samples measure each API call with the steady clock; enqueue span includes event submission and loop/timer bookkeeping. Host completion starts before the initial event record and ends after final event synchronization. Event intervals use compat's difference between ordered barrier `command_end` timestamps and include relevant barrier overhead. No interval has overhead subtracted. Elapsed queries occur after completion timing ends. This is no overlap measurement.

Both lanes initialize and fault host pages, initialize device memory, warm one copy, then poison timed destinations outside timing. H2D verifies the full device corpus by a separate full readback; D2H verifies full host destinations and also device immutability. Both check all guards and inactive slots, not sampled bytes. Full pattern generation, scans/readback, logging, allocation and cleanup are outside measured regions. Per-arm data is reconstructed with deterministic per-slot/per-byte/per-repetition patterns. Verification vectors are ordinary host and disclosed by setup/verification byte counters; they are not timed-arm fallback buffers. Host memory includes up to four ordinary-host verification/pattern vectors plus the arm host allocation, with a single device allocation. Each vector is bounded by lane allocation; peak host storage is roughly 1.25 GiB, not one 256 MiB total-process bound.

Normal cleanup explicitly checks stream completion, each event destruction, both compatibility frees and stream destruction. Cleanup errors are emitted, retained and cause failure. Allocation/copy/verification failure emits a failure record after a flushed `arm_begin` context, then process fail-stop without freeing possibly active storage. A watchdog with a required finite deadline also fail-stops without freeing active buffers. A failed arm never emits a pass sample. Failure paths do not perform retries/fallbacks. OS process teardown is the recovery boundary, not successful API cleanup. Main must retain the exit status and stderr together with stdout.

Main review, before execution: the initial proposal's outer `_Exit` catch did
not prevent ordinary-host vector destruction while unwinding out of `arm`.
A failed copy/wait could therefore free a source/readback buffer before GPU
completion. Main added a guard declared after all GPU-copy vectors, immediate
fail-stop on CUDA-compat API errors, and a host-only lifetime fixture. The guard
exits before those buffers unwind unless checked stream cleanup has completed.
This fixture is prepared, not executed during the live model benchmark.
Main also moved the API-count snapshot to the actual end of host completion
timing; later elapsed-time queries are no longer counted as timed APIs.

A second review found that the H2D poison upload used `expected_device` as
an asynchronous source and then changed that vector immediately. Main added
a checked wait before changing it. This is outside timing, and the H2D arm
now reports six stream synchronizations rather than five. No GPU run used
the unsafe proposal.
