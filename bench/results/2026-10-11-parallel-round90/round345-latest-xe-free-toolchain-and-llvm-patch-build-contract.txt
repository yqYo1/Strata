Decision
Follow the e32 AGENTS.md policy: do not build/test SYCL code with contrib-icpx. On this B570 host the documented immediate reproducible compiler route is a from-source intel/llvm v7.1.1 DPC++ build using tools/intel_llvm_build.py, then a STRATA_LICENSE=free engine configure using its installed clang/clang++ and libsycl. The repo's CMake checks for intel/llvm DPC++ and __LIBSYCL_MAJOR_VERSION >= 9; ordinary nix clang and icpx do not satisfy the free path. Local environment report supplied by the caller says only icpx 2026.1 and ordinary nix clang 21.1.8 are available; DPC++ free 7.1.1 is absent.
Intel's release description says prebuilt Linux/Windows binaries are provided and states the release includes clang 22.1.0 and SYCL runtime 9.0.0. But the public v7.1.1 release assets expansion currently lists only the auto-generated source zip and source tar.gz, with no Linux toolchain binary asset name, download URL, or checksum. Therefore there is no verifiable free compiler archive URL/hash from this release page to give or bootstrap reproducibly. Do not invent an asset URL or treat the source tarball hash as the binary hash. Even if an independently verified archive is later found, the repo policy specifically says the free qualification uses intel/llvm built from source; a prebuilt would not satisfy that prescribed qualification without an explicit policy change.

Intel v7.1.1 primary-source findings
- Official release page identifies v7.1.1 at commit 504366f, clang 22.1.0 and SYCL runtime 9.0.0; states Linux/Windows prebuilt binaries are provided, with Linux configure options including Release, zstd, CI defaults, disable JIT, no assertions, security sanitizer flags, HIP and CUDA. It also says the binaries are not formally SYCL CTS-conformant and its Intel GPU E2E configurations name B580 (not B570). This makes the advertised release useful evidence for compiler/runtime version, not direct B570 qualification.
- Public expanded assets endpoint, https://github.com/intel/llvm/releases/expanded_assets/v7.1.1, contains only source code zip and tar.gz entries dated 2026-09-15. Those are source archives, not a prebuilt compiler, and no SHA-256 is published in that asset list.
- For Intel GPU runtime, Intel's Get Started guide requires a Level Zero implementation on the host for the Level Zero backend. The repo's own source bootstrap deliberately forces fetch of the release-pinned Level Zero headers/loader (SYCL_UR_FORCE_FETCH_LEVEL_ZERO=ON) because the installed loader can be too old or accepted unchecked without pkg-config; the actual B570 device runtime/driver still must be separately available. No runtime version or B570 capability was queried here.
- The upstream release Linux binary configuration enables CUDA and HIP adapters. The artifact and dependency inventory is not exposed as an asset here, so its exact external shared-library dependencies and reproducible checksum cannot be established from this release URL.

Repo contract and exact B570 free path
- AGENTS.md's newer Free and non-free builds rule states: build and test SYCL code with intel/llvm only in free and contrib-llvm modes; free build is build/free with intel/llvm built from source as docs/DEVTOOLS.md describes; contrib-icpx is not built or tested.
- CMakeLists.txt around lines 230-260 explicitly rejects IntelLLVM/icpx unless STRATA_LICENSE=contrib-icpx, and rejects older/ordinary compilers unless the SYCL header check and libsycl major >=9 check pass. For Intel Xe with empty CUDA/HIP architecture lists the default device target is spir64. STRATA_LICENSE=free disables oneMKL (non-free), while XeStrata's own SYCL kernels handle Intel GPU dense operations.
- docs/DEVTOOLS.md explains the source bootstrap. Prerequisites are git, cmake, ninja, g++, lld, Python, hwloc headers and static zstd development files (Ubuntu/Debian: git cmake ninja-build g++ lld python3 libhwloc-dev libzstd-dev). The script pins tag v7.1.1, configures Release, forces the pinned Level Zero fetch, zstd, 10 GB LLVM link RAM/job, assertions OFF, lld, and compiles using all CPU threads by default. It installs at .tools/intel-llvm/install (bin/clang, bin/clang++, lib/libsycl.so), records the tag/commit, applied patch ids, backends and XMX probe output in install/XESTRATA.json, then deletes build/ unless --keep-build is set. The script automatically compiles and runs tools/xmx_probe; invoking it therefore performs an actual GPU/runtime query, which was intentionally not done in this audit.
- Future B570 engine command shape, after allowed bootstrap and on a clean source tree: configure with -DCMAKE_C_COMPILER=/tmp/.tools/intel-llvm/install/bin/clang -DCMAKE_CXX_COMPILER=/tmp/.tools/intel-llvm/install/bin/clang++ -DSTRATA_LICENSE=free -DSTRATA_ENABLE_XE=ON -DSTRATA_CUDA_ARCHS= -DSTRATA_HIP_ARCHS= -DSTRATA_ONEMKL=OFF -DSTRATA_BUILD_TESTS=ON. Use a fresh build/free directory. Run executables in a shell without oneAPI setvars and with .tools/intel-llvm/install/lib on LD_LIBRARY_PATH, as docs/BUILD.md requires, to prevent loading mismatched oneAPI adapters/libumf. Keep all tests/qualification behind the owner's later explicit test/GPU boundary; this report did not run them.
- The setup script checks Intel LLVM version based on runtime __LIBSYCL_MAJOR_VERSION >=9, but runtime feature probing remains required before claiming B570 XMX path or device qualification.

Patch applicability to B570 / Level Zero
The checked-in third_party/main/intel-llvm/patches directory has 17 files. Patches 01, 03-10 are CUDA adapter/compiler/NVIDIA-image fixes; 02, 12-17 are HIP fixes; 11-build-job-pools.patch modifies the common LLVM HandleLLVMOptions CMake module to avoid duplicate Ninja link_job_pool definitions. No patch changes Intel's Level Zero adapter, ZE memory rules, SPIR-V codegen, or B570/Xe XMX tables. No Xe-specific or Level Zero-specific Xe12 patch is needed for a B570-only free build. The bootstrap script currently applies all checked-in patches unconditionally, even when no CUDA/HIP target is configured; allow that script to provide its recorded patch set rather than manually cherry-picking. For a B570 free target, only patch 11 is materially common to host-toolchain build stability; the GPU-specific CUDA/HIP patches are inactive target fixes. The repo docs say the build-job-pools fix itself does not require rebuilding an already completed toolchain, but the source bootstrap applies it before configuration.
