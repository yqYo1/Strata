## Interface and ordering risks

`ReplicaEngine` is a wrapper at the existing `Service` engine boundary, not a second API implementation. Its closure includes `serve/replicas.py` and `serve/cpu_affinity.py`; the latter is a required lazy import unless CPU partitioning is removed/disabled. Server changes also include setup's `--replicas` option/config persistence, replica-specific args/env/log/profile names, per-child CPU assignments, concurrent startup/partial-failure cleanup, aggregated metrics/context/slot view, per-thread routing, and restart/healing. `ReplicaEngine` must satisfy the engine attributes read by `Service` and status/metrics while routing request generation to one current child. Notably, `silence_s`/`gpu_busy` propagate to every child and `last`/progress are request-thread-specific. Keep the local slot-pool and API request path; do not try to make each replica a separate web server. The fake tests do not prove real multi-GPU capacity or performance.

READY changes belong at `StrataEngine.start()/restart()` and the HTTP exception path, not in the engine protocol. The local tree already has the timeout mechanism; the main identified missing guard is restart's access to a slot condition that lazy startup may never initialize. Adapt this small guard to local state and keep existing restart-waiter semantics.

Context overflow is a request error-message/classification adjustment at `Service.prepare()`/API translation. It should not truncate prompt IDs, change token counting, or affect inference flags. Tests use an artificial context size of 131072 and byte token IDs, so they establish only server boundary/error semantics.

Keepawake must balance every acquire/release through the `Service.run()` generator lifetime. Since the run iterator yields a queue ping before acquiring the single-turn FIFO, wrapping only active engine generation would omit queued work; wrapping the public generator covers queue, execution and early close. This should remain independent of backend/decode phase instrumentation.

The effort-end change is an argv compatibility gate. Existing behavior checks for a feature marker before passing an engine option, which protects older engines; only the binary selected by the SYCL launcher/config environment is currently missed. Resolve the real binary first, then retain the existing tokenizer role-token check and fallback. Add the fake-path test before wiring the resulting args into both normal and replica child starts.

The setup archive path is also independent of inference. The baseline helper can be reused; wire its call only around ZIP-format/CRC `BadZipFile`, and preserve valid archives on filesystem errors. The recovery fixture checks cached corruption, a bad download, CRC during extraction, cleanup failure and exception identity.

`serve/test_queue_keepalive.py` is an additional upstream regression file for the same Service FIFO: it tests SSE keep-alive while queued, queued cancellation, and generator close using `MockEngine`/loopback HTTP. Its command is `python -m unittest serve.test_queue_keepalive -v`; no model/GPU/process. The upstream `serve/server.py` queue acquire logic and the local scheduling/FIFO implementation overlap, so include it if integrating that behavior.

Correction to R343: upstream has `tools/cancel_park_test.py`, not `tools/test_cancel_park.py` or an importable `tools.test_cancel_park` unittest module. Keep either as a separately named real SYCL engine/protocol gate if the inference park/restore change is selected; neither belongs in the server-only CPU command.
