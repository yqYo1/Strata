Runtime and library resolution
- Both modes use the source-built free intel/llvm SYCL runtime, UR loader, Level Zero adapter and libumf. docs/BUILD.md:185–188 explicitly warns to run without oneAPI setvars.sh: oneAPI UR adapters/libumf can precede the matching custom runtime and cause GPU tests to segfault with mismatched libsycl.
- Run the free engine with the custom install lib first in LD_LIBRARY_PATH. For contrib-llvm, keep that same custom compiler lib first, then add MKL_ROOT/lib (typically /opt/intel/oneapi/mkl/latest/lib), followed only by needed system paths. Do not let oneAPI compiler/UR library dirs from setvars precede the custom runtime. Confirm libsycl.so.9, libur_loader, libur_adapter_level_zero and libumf resolve from the custom install; oneMKL libraries should resolve from MKL_ROOT. Intel's DPC++ FAQ says Linux runtime lib directory must be on LD_LIBRARY_PATH: https://github.com/intel/llvm/blob/sycl/doc/FAQ.md. Intel's oneMKL Linux guide lists its SYCL dynamic libraries in the MKL lib directory: https://www.intel.com/content/www/us/en/docs/onemkl/developer-guide-linux/2024-0/dynamic-libraries-in-the-lib-directory.html.
- Controller forces a pinned Level Zero loader/header source for toolchain configuration, but it does not supply the Intel GPU kernel driver. Level Zero driver/compute-runtime remains a host runtime prerequisite. Official LLVM guide: https://github.com/intel/llvm/blob/sycl-rel-7_1/sycl/doc/GetStartedGuide.md.
- Packaged runtime files differ from local contrib development: docs/BUILD.md:415–437 says intel/llvm runtime and UR files are bundled; oneMKL is not. A local contrib run must expose MKL separately while preserving the custom free runtime first. Configure/link success alone is not runtime validation.
