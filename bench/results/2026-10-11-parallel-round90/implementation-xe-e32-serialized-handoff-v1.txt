The current Xe protocol has no matching legal host/device atomic operations. Therefore gpu::host_handoff_concurrent(Stream = nullptr) is a universal false protocol gate. It does not infer safety from GPU name, vendor, usm_host_allocations, host-USM visibility, Level Zero sharedSystem capabilities, or even a positive atomic-host capability alone. Unknown and capable devices both take serialized mode until an actual atomic allocation/protocol contract is implemented. This deliberate universal fallback was allowed by the task; no device-dependent concurrent optimization is being claimed.

Changes and source-derived ordering
1. Session loop: checked sync before changing per-token host staging. For every layer, launch pre, check event_record, check event_sync, inspect h_seq once only after completion, then read routing payload and run existing hit launch/CPU pool. Check initial and per-layer parts-copy enqueue, launch existing post and next pre in their original same-queue order. The next pre completion also finishes the previous parts copy before y_miss reuse. No live sequence polling remains in session_loop, for either overlap setting. overlap=false retains an additional post wait; overlap=true does not permit a live host/device control exchange. Local error/unwind guard drains the stream before locally allocated scratch can free; unsuccessful drain terminates rather than return with unconfirmed async users.
2. TokenGraph: generate's residency/graph setup eligibility and capture selection consult the false gate. Normal generation therefore selects already-captured SessionGraphs. Direct session_capture_token and session_run_token calls reject before capture or enqueue. The legacy token graph cannot be repaired by waiting on a complete graph because it contains host-dependent internal waits.
3. Publication kernels: device sequence increment is a plain single-writer read/increment/store while the host owns none of that allocation. doorbell_publish retains its work-group barrier and writes the sequence once. System fences and volatile ring stores were removed: checked graph/queue completion transfers ownership to the host. No arithmetic, expert quantization or routing precision was changed. doorbell_wait rejects valid controls before enqueue and preserves null-control no-op semantics. No device spin is submitted by this function.
4. Verifier: init always forces segmented mode; STRATA_VERIFY_SEGMENTED=0 cannot bypass the protocol gate. No functional visibility probe is used. doorbell_visible returns false without allocation or kernel submission. wait_flag_ge and wait_flag_ge_or reject before submission; their device spin kernels were removed. The normal segmented recording path does not call those waits.
5. Segmented run: check both queues before staging controls, then keep an error/unwind drain guard. The expected segment vector shape is checked before first launch. After checked compute-stream completion, read seq once; a missing ring is an immediate error, not another polling loop. Late PLE host staging was disabled for segmented execution in both record_window and run, so PLE rows are gathered before graph launch.
6. DMA: fetch_dma checks every expert copy enqueue and host callback enqueue and propagates the issuing thread's gpu::last_error into dma_error_. A rejected enqueue does not raise success. Callback captures flag pointer and expected value directly, eliminating the mutable FlagSet argument slots. After synchronous pool return, segmented execution checks copy-stream completion and stored enqueue errors before host flag inspection or next segment submission. flagB reads use the same host atomic builtins as the monotonic host-host raise operation. Final copy drain and profile read are checked. Destructor drains compute and copies before graph/callback state destruction; uncertain completion terminates before cleanup. These fail-stop paths preserve memory lifetime, but are not GPU recovery guarantees.
7. Entry points: init_slots and capture_all reject batch/pipeline modes under segmented policy; stage_batch, prestage and pl_launch independently reject the false protocol gate before staging/launch, protecting callers that skip preparation. Diagnostic callbacks no longer read live control words on the serialized path. Header API comments record the current ownership contract and environment override limit.
8. Resident verifier graph: retained. recording_res_ makes the router ring no host doorbell and omits host flag waits; plan construction and zero CPU-share handling stay on-device. run skips host pool/ring processing and waits for full completion before consuming outputs. Direct GPU-only/session_replay helpers have no CPU handoff and no live control polling; they still require their existing caller completion/staging obligations. No GPU-only replay result is claimed to validate CPU routing.

Remaining caveats and qualification boundaries
- All source conclusions above are unverified at runtime. No compiler, lint, test or GPU result is claimed. Source review cannot prove queue-completion visibility on a particular runtime/driver, asynchronous fault status, numerical parity, service quality or performance.
- Concurrent mode is disabled universally. To reintroduce it, implement matching host/device atomics over one properly aligned control object, query the selected queue/device and exact host-USM allocation capability/order/scope contract, fail closed on absent/unknown capability, and separately qualify the compiler/runtime/driver tuple. Changing this helper to true alone is unsafe; legacy TokenGraph/session_run_token and nonsegmented verifier host code still contain their old volatile protocol and are currently unreachable. Kernel wait implementations intentionally reject unconditionally.
- CPU hit/expert arithmetic, native routing, AVX-512 dispatch and CPU layouts were unchanged. generate edits only gate token-graph setup/selection. CPU pool errors still use its existing driver failure channel; PoolFn/HitFn void interfaces are not redesigned here.
- Batch and pipelined verifier modes are refused rather than silently produce an incomplete fallback. Higher-level callers may need to choose serial windows; MAIN must check selected CLI/serve/MTP settings and refusal behavior.
- Existing external callers of stage_token/session_replay and other GPU-only measurement replay helpers remain responsible for completion before reusing their host staging. They do not poll control words or run CPU handoff. This patch does not redesign general staging API ownership.
- The global watchdog's existing raw Verifier lifetime registry was not redesigned. New diagnostics avoid control-word reads; this does not prove unrelated diagnostic pointer lifetime under concurrent object destruction.
- Serialized completion removes mid-graph CPU/shared-expert overlap and token-graph speedups. rings_mid_graph stays zero for this loop; ms_to_ring now includes completion wait. Old overlap timing interpretations and GPU-floor timings are not comparable without noting the change.
- A false async drain can represent an operation fault even if work actually finished; conservative terminate is intentionally stronger than claiming safe cleanup. It is not an attribution to historical CAT18/UR40/B570 faults.
- MAIN's prefill publication countermeasure remains a separate overlay. This report excludes its hashes because MAIN is actively editing those files.
