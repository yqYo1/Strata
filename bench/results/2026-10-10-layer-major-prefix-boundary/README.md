# Layer-major residual prefix follows the execution cache

With a fully populated original expert cache, no explicit STRATA_PREFILL_FIRST, a32768position request and8192token chunks, the old outer prefix calculation used a256token first chunk. It then replaced the cache with a512slot one-layer cache. The inner execution consequently used8192token chunks. A requested8192position GPU prefix became256positions and the first host-copy span started256rows before the allocated host residual plane. This is a conditional source defect; no reviewed receipt shows these conditions caused a historical GPU hang or numerical rejection.

The outer calculation now uses the same temporary layer cache as execution. In that counterexample the effective GPU prefix is8192positions and is a real chunk boundary. A runtime check also rejects any residual prefix that splits a chunk before its input/output copies.

Root extracted the original and fixed prefix calculations and unchanged execution chunk calculation verbatim into a CPU harness with stub cache/geometry objects. An independent row-span bounds oracle evaluates the actual produced chunks and host/device extents without creating an invalid pointer. Each fresh process fixes FIRST to unset,0,256,1,8192 or-1; it checks8064configurations spanning14lengths including262143/262144, six chunk limits, six original cache capacities and16prefix requests. Some requests repeat within this matrix; these are case evaluations, not unique configurations or performance samples. Both optimized and UBSan builds pass all twelve fresh processes:96768evaluations total. In each unset-FIRST process the original produces416invalid spans, all rejected by the new guard; the fixed calculation produces zero. Explicit-FIRST processes have no original mismatch. The named counterexample confirms oldG256 versus fixedG8192. The actual modified SYCL translation unit compiles with the existing precise/SG32/sequential-oneMKL recipe. All owned processes close normally without survivors.

Receipt field named_unset_original_first_host_offset is the arithmetic -oldG in every process; it describes the actual invalid first host span only in the unset-FIRST counterexample. In explicit-FIRST cases that chunk is on GPU and no such negative host span is taken. Original receipt remains unchanged.

Only the existing opt-in SYCL layer-major path changes. This is not a GPU inference, copy-lifetime, numerical equivalence or full262144physical-position qualification. No throughput change is measured. The ordinary route, CUDA and HIP source are unchanged; the GPU was not executed during these tests.
