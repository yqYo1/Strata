Scope and design
----------------
The resident packed-pointer Stager arm performs memcpy, not CPU dequant.
This standalone C++20 program measures ONLY a synthetic ordinary aligned-RAM
source-to-host-ring memcpy control. No production source was changed.
There is no shard read, ExpertSource::copy_blob, GGUF assembly, DMA, USM,
pinning/mlock, device access, dequantization, numerical model math or inference.

Explicit worker count1/3/4/6; no hardware-derived default. Ring16. Corpus192
synthetic immutable packed blobs, each1971200B. These are selected-fixture
control dimensions, not asserted production graph topology or universal blob
size. Seed defaults1, or explicit uint64 decimal. Corpus generation is
deterministic SplitMix64(seed XOR (blobindex<<32) XOR wordindex) expanded
little-endian per8-byte word. FNV1a64 full-payload expected hashes are recorded
for all192 blobs. Root can reproduce source data independently.

A sample has12 batches, each16 distinct ring slots and16 corpus blobs.
The fixed corpus order is0..191. One full warmup precedes seven measured
samples. Qualification mode has one full warmup plus one qualification sample
and suppresses capacity rates; timing_claim:false. All individual batch and
job copy durations, per-job full hashes, worker assignment counts and
correctness durations are retained even for warmup. No aggregate median
hides individual samples; root derives medians/ranges from recorded samples.

Threads are created and pass a startup ready barrier outside copy timings.
An atomic index claims each of16 batch slots exactly once. A mutex/CV
generation prevents stale workers claiming a later generation. Per-job tags
contain exact generation and source job index. Each worker writes only its
claimed slot and result record and its own assignment counter.

Main waits for EVERY worker to depart a batch before touching its results or
destination bytes. The completion mutex establishes the happens-before edge
for source/result reads. Main verifies EACH job's entire1971200-byte payload
with memcmp against its immutable source, checks both64-byte tail canaries,
computes full destination FNV and checks the expected hash. Only after all16
jobs pass does main acknowledge the generation. The next batch explicitly
refuses an unacknowledged generation before resetting the atomic index or
writing any ring slot. Every overwritten job has therefore been fully checked
before reuse. This is a host acknowledgment surrogate, NOT a DMA event or
actual live Stager scheduling.

Worker errors cannot escape the worker entry point. Failure wakes the startup
or batch waiter. Main rejects failures, stops/joins all started threads before
arena destruction and emits nonzero/failure JSON. Constructor partial thread
creation unwinds through the same stop/join path. A genuinely broken mutex
cannot be recovered safely and aborts rather than reporting success.
Batch and startup waits have a shared process_start+60s deadline. All normal
work loops are finite; no unbounded job queue/replay or detached thread exists.
Owned arena outlives all workers. Stop is safe when called again by destructor.

Timing semantics
----------------
Each batch's main steady-clock interval begins before locking and publishing
its generation, and ends after all workers report completion while main holds
the completion lock. The sum of12 such intervals is reported per sample.
It includes lock/issue/notify, worker wakeup, atomic claims, memcpy, worker
clock calls, completion notification/barrier and main wait. It excludes final
lock release, all preparation, full verification/hash/canary/ack, source-final
checks, thread startup/join and JSON formatting.
Each worker captures two steady-clock timestamps immediately around memcpy.
Per-job spans and their SUM are reported separately. The sum is concurrent
worker wall spans, NOT exclusive CPU service and NOT sample wall time.
No subtraction of worker-summed spans from main wall is called overhead.
The reported worker_clock_calls_per_job2 and batch_clock_calls2 refer to
explicit captures; deadline/CV/verification clocks add other calls outside or
inside the labeled synchronization implementation.

Verification/ack duration is separate and untimed for the capacity numerator.
All checks precede slot reuse; no copy/check race is introduced to obtain the
rate. The full hashes/memcmp perturb source/destination cache state between
batches and samples. The control is therefore12 barrier-separated16-slot
bursts, NOT one uninterrupted192-job streaming window, actual consumer pacing,
or live production throughput. A host immediate acknowledgment is not a
substitute for DMA overlap or DMA completion. There is no claim of actual
cache residency, physical DRAM traffic or memory-controller peak.

Logical payload/source bytes per sample378470400.
Logical destination payload bytes per sample378470400.
Logical source-read+destination-write bytes per sample756940800.
The two timed_batch_*GBps fields use sum-of-copy-batch-wall seconds:
payload rate counts one payload; read+write rate counts twice that payload.
Both use decimal1e9. They are logical rates, NOT controller transaction bytes.
Successful normal run verifies1536 jobs (warmup+7 samples), every byte/job.
Successful qualification verifies384 jobs (warmup+1 sample).
Each sample checks384 tail canaries. Final source validation adds192 full
source hashes and192 source canary checks after joined workers.

CLI, allocation and bounds
--------------------------
PROBE WORKERS [SEED] [--qualify]
WORKERS must be exactly1,3,4,6. No worker default.
SEED is strict unsigned decimal uint64, default1. Unknown/duplicate options,
overflow, sign/leading-zero forms and missing/excess arguments fail before
allocation. There are no configurable corpus/ring/blob/sample sizes.
No CPU affinity API or topology query is called. The process inherits root's
chosen affinity, and JSON says so. Root should record and apply explicit
known topology controls externally; this implementation does not assume them.

One64-byte aligned arena contains192 sources and16 ring slots, each payload
plus64-byte tail canary. Arena410022912B (<512MiB). Blob size is divisible64,
so every source/destination slot and the aligned_alloc allocation size meet
64-byte alignment. Immutable sources, destinations and guards cannot overlap.
Job/result/sample arrays and vectors are bounded; eight normal sample records
hold192 job times/hashes plus12 batch durations each. No allocation occurs
inside timed copy batches. Source preparation and first-touch happen outside
timing. Memory is ordinary allocator memory, explicitly NOT pinned.

Owned work budget60s measured from before parsing/preparation; checks run
during preparation, before every batch, and during final validation. Exceeding
it invalidates the whole run; no partial averages. A timeout initiates safe
join before arena release. OS scheduling or an external stall can delay join,
so root must impose a hard external wall limit as well. The internal60s gate
is not proof the requested matrix fits a particular host's runtime.
JSON prints only after all validation/reconciliation and final source hashes.
Exception JSON retains stage and escaped reason on stderr with nonzero exit.
Root requires exit0 and valid complete success:true JSON, never partial stdout
or counts from a failed process.

arm. Batch16 retirement differs from the live issuer/DMA ring.
