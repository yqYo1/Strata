Admission/default safety
New STRATA_PREFILL_SERVICE_TIMING is enabled by environment-variable presence (value 0 enables it). It does not enable PfTimer or its phase markers. It admits the actual existing compute queue by enable_profiling property plus queue_profiling device aspect. Gemm stream queue equality is checked; the event-aware wrapper verifies the descriptor queue equals its bound stream. No compute queue is replaced or modified. The existing copy queue's conditional profiling creation now also accepts the new switch; with both diagnostic variables absent its original property remains unchanged. STRATA_PREFILL_TRANSFER_TIMING alone enables the hardened copy ledger, not GEMM recording.

Original Gemm::f16 signature/body is untouched. A SYCL-guarded f16_event declaration adds a distinct diagnostic-only entry point. The DPCT gemm optional output channel accepts only real_half/real_half/real_float plus float scaling and routes it to the existing oneMKL call. When null, gemm_impl executes its original call and discards the event. Event-aware f16 uses identical trans/nontrans, N/T/K, K/K/ldy, alpha=1/beta=0, dtype and compute-mode arguments. Non-oneMKL/non-USM routes and unsupported/invalid shape return false before submission, and the caller invokes the original path exactly once while invalidating coverage. No duplicate GEMM, replay, barrier or wait is submitted by this instrumentation.

With SERVICE and TRANSFER absent: service/copy lanes perform no recording, profiling, admission queries or added clocks. The expert lambda calls original f16 once per role with its original arguments, retaining surrounding dequant/SwiGLU/ring-release order. Copy capture returns the original queue->memcpy immediately; stager_wait invokes its original callback immediately. New issuer ring timestamps are conditional on diagnostic presence. Disabled ledgers have no events/maps allocated and their destructors return immediately. This is source reasoning for unchanged model maths/submission schedule, not proof of binary byte identity or runtime equivalence. Root must build and compare frozen controls.

Owned bounded lanes, coverage and failure behavior
The generic production ServiceLedger header has deterministic host-only Ops injection for testing; it owns no queue command or wait. Compute owns expert_gemm, activation_copy and device_residual_copy lanes. The issuer alone owns expert_copy while running; inline issue/stage paths are mutually exclusive with that issuer. Main pre-admits queues before starting the issuer, then folds copies only after existing join/synchronization boundaries. No shared vector mutation or recording mutex is introduced.

Records retain request-local lane sequence, actual chunk position, layer, expert, role, rows/ne, N/K/ldy, ring, source kind, returned event, logical bytes and independent host submit duration. Copy source kinds distinguish direct pinned blob (1) and host stager (2); activation/device kinds are 3/4. Roles are GU=0, Down=1, expert copy=2, activation=3, device residual=4. Layer-major preload uses chunk=-1 plus actual expert/layer. Existing stager waits are bracketed behind the opt-in at streamed, stage-one and layer-major copy sites. The issuer's existing a_consumed/ring-release polling span is captured separately as host_ring_publication_wait_ms. Queue dependency barriers are not mislabeled host waits. Activation/residual copies have layer and kind, but do not currently carry a token-position identity; their explicit coverage chunk=-1 denotes that limitation.

Expected GU/Down pairs are registered from actual routed order and m.cnt before expert compute, keyed by chunk/layer/expert. Completed batches must contain exactly one GU and one Down with the expected same row count; duplicate/missing/extra/wrong-row pairs invalidate. Final expected-pair registrations, completed pair count and pending expectations reconcile. Pair identities are compacted after completed folds; reported expert ID sum/xor are a digest, not a replacement for independent per-expert tracing.

Each lane retains at most 32768 pending events, at most 32768 pending expected pairs and at most 4096 shape plus 4096 chunk/layer/role aggregate buckets. At most four detailed query/reversal diagnostics per lane are printed, plus counters and one bounded aggregate report. Caps are fixed in source and emitted in receipts. Cap overflow permanently invalidates the lane, drops further event records while retaining the last returned event for safe completion checks, and suppresses its aggregates. It does not truncate and claim completeness, grow with 256K input, or abort a successful model workload merely for telemetry cap overflow. Compute events fold at existing chunk callback waits and final wait. Copy/activation completed events can retire after joined producer + existing compute wait; pending copy events remain until the existing final copy wait. Layer-major preload folds after its existing copy wait. A request without intermediate chunk callbacks may exceed caps and produce invalid telemetry, intentionally.

After existing synchronization, completion is inspected and asynchronous errors drained without waits; submit/start/end are queried independently and counted. Every event enforces submit<=start<=end before unsigned subtraction. Equal timestamps are legal. Query exceptions retain bounded error text. First reversed raw timestamps remain in the final receipt, even when later valid events overwrite the last raw endpoints. No current-submit/previous-end difference is computed/rejected, since ordinary pipelined submissions can precede previous completion. No retained-event gap is labeled idle/starvation. Checked unsigned additions protect logical bytes, summed event durations, queue-delay durations and rows/counts. Host fields have finite/nonnegative admission and finite summed checks.

Final receipt reconciles attempts/submitted, retained+dropped/submitted, folded/retained, zero pending, exactly three queries per folded record, query success and expected pairs. Invalid receipts suppress that lane's returned-event aggregates; any invalid transfer lane suppresses aggregates from all three transfer lanes. Scope text explicitly says returned routine/copy event, not exclusive kernel busy. Runtime query failures are not silently omitted. Unknown/incomplete completion, async delivery failure, submission/storage failure and diagnostic exception unwinding use flushed invalid receipt plus std::_Exit, avoiding replay and automatic storage destruction. Relevant existing compute/copy wait error returns and expert-compute exceptions enter the same diagnostic fatal path. The ledger destructor checks the latest returned event, including dropped records, and drains the admitted queue. This is diagnostic local safety, not a comprehensive redesign of every existing engine fault/cleanup path.

Unanswered coverage and limits
A oneMKL returned event represents routine completion, but its start/end has not been proven to cover every internal library kernel. Independent complete-kernel/dependency tracing remains necessary before calling this total GEMM service or deciding resource utilization. Shared experts, dense projections, dequant, SwiGLU, barriers, CPU workers and other commands are deliberately outside expert_gemm coverage; MMQ/fused/multi-GPU paths invalidate rather than silently qualify. No cross-queue overlap or hardware-controller bandwidth is derived. Logical copy bytes are submitted payload, not DRAM/controller traffic. Host/device clocks remain separate and no cross-clock subtraction occurs. Shape aggregates and chunk/layer/role coverage preserve actual submitted geometry and bounded expert identity digests; they are not a full raw per-call timeline. Production long-input cap adequacy and all actual event fields remain untested.
