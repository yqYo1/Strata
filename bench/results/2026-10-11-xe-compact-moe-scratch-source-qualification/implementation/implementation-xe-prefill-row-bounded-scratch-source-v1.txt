## Exact opt-in and unsupported combinations

STRATA_PREFILL_COMPACT_MOE_SCRATCH is default OFF. The environment is sampled once per process with strtol(base 10); a nonzero parsed value opts in. Unset, empty, zero, or a string with no numeric prefix remains OFF. This does not change STRATA_PREFILL_MMQ itself. Enable with STRATA_PREFILL_MMQ=0 STRATA_PREFILL_COMPACT_MOE_SCRATCH=1 for the intended fallback experiment.

Eligibility is mp.any=false AND mp.fallback=true AND STRATA_DBG_NAN absent. Pure MMQ and any mixed MMQ/fallback plan are unsupported. STRATA_DBG_NAN presence (including a value of 0, matching the existing presence-based diagnostic) is unsupported. An unsupported explicit opt-in returns a descriptive init error before buffers/events/copy stream allocation; bytes_needed conservatively retains the ordinary layout for these rejected combinations. MMQ GU is never shrunk. Diagnostic behavior is not changed or silently limited to the final compact group. Without the opt-in, the existing full-route diagnostic remains as before.

The compact init also rejects nonpositive chunks, route capacities exceeding int32, checked T*K*N FP32 size_t allocation limits, expert counts outside int32, and a compute queue without the in_order property. Runtime accepts only its own queues (src/core/device.cpp Runtime::stream); compute/transfer/additional runtime queues are constructed in-order at device.cpp:186-225. No vendor, model identifier, or device-ID decision is introduced. The shared source remains used by free and contrib-llvm modes. Both modes are unverified. No HIP/CUDA-specific work was added.

## Schedule and precision

Preserve existing order, off[e], src_dev, slot_dev, CPU routing tail, cpu_fut join/copy, combine and token/rank accumulation. The compact route validates all expert counts and total T*K coverage before prefix construction. GPU rows are explicitly checked in [0,T*K]. Logical native fallback dequant groups retain their existing q indices and --prefill-experts grouping (G16 by default, current setter up to 64); native_flush batching/window/ring/event handling is unchanged.

Only after a complete logical group's weights have been expanded, compact_moe_groups validates the whole window, then partitions it into maximal contiguous positive-count subgroups. Every count must satisfy 0<cnt<=T; global bounds must match each count and lie inside rows_gpu; each local bound starts at 0 and ends at the checked sum nr<=T. Extension uses cnt<=cap-sum to avoid overflow. Bad counts/bounds produce runtime_error handled by the existing run catch/drain path; no clamping, truncation, or dummy zero-count GEMM is used. The host partition has no fixed G16/G32 limit, and its persistent descriptor is sized to n_expert+1, so an arbitrary future logical group up to the actual expert order remains row-cap safe.

For subgroup [a,b) of logical [j0,j1), q0=a-j0 and r0=xb_host[a]. Gather mixed_h via src_dev+r0 into Xs[nr,N]. The existing gather copies FP16 bits without a new conversion. GU uses the existing FP16 product with FP32 output at compact row zero. The unchanged swiglu_interleaved writes saturated FP16 Hh; Down remains FP32 and writes Dm+r0*N. Weight bases are dq_gu+q0*GU_ELEMS and dq_d+q0*D_ELEMS, with expert strides unchanged. All bases are positive in-allocation offsets; no base-minus-offset trick exists. Dm remains full T*K*N FP32 and combine still reads original rank order. This is a grouped row-cap schedule, not a blanket G1 schedule; one-expert subgroups occur only when a row cap/window actually requires them.

The same partition/gather/local-bound scheme covers resident fused IQ windows (original logical group <=kIqGemmGroup=32). The existing per-expert IQ tile-row limit is checked as well as cumulative nr<=T; host weight lists stay in expert order. Unsplit resident and native groups retain grouping. Both optional-native-batch and ordinary fallback compute branches share fallback_products; OFF performs the same full-route products as the baseline.

Full-stream zero-count entries remain outside order. release_to/skipped_entry still wait for issued copies, flush pending native readers where required, record the original used event, advance consumed, and give back their original slots. No stream/copy issuer ownership, blob lifetime, or slot release edge was shortened. No serve workspace retirement/cache enlargement was implemented. Configured 262144 streamed-KV/session capacity, page tables and staging pools are not changed; runtime verification of the full-context configuration remains pending.

## Descriptor and matrix lifetime

compact_xb_dev is a persistent device-resident allocation/carved span of n_expert+1 int32 entries outside the shared GDN/QSA/MoE arena. Its capacity appears in BOTH carve/relayout and bytes_needed. Owned mode keeps it in Impl::owned until release drains queues and frees allocations. Borrowed mode keeps it within the borrowed layout; relayout first drains compute and copy queues, then recarves consistently. No stack host descriptor is asynchronously uploaded and reused.

The original xb_host/xb_dev layer descriptors retain their existing lifetime. A new compact_moe_bounds kernel translates xb_dev+a into compact_xb_dev on m.cs; xb_dev is immutable through that layer's grouped products. Exact ordered sequence for each subgroup is device bounds translation -> compact gather -> GU -> unchanged SwiGLU -> Down -> next subgroup translation/gather. IQ/XMX device kernels read compact_xb_dev asynchronously on that same in-order m.cs; the next translation follows their last Down reader. Persistent Xs/GU/Hh allocations likewise survive all commands; subsequent writes follow all previous consumers. No per-subgroup host synchronization is added.

Gemm::f16_groups consumes the subgroup vector's HOST bounds synchronously while looping oneMath products (gemm.cpp:343-363). Only its asynchronous matrices, not this host bounds vector, need survive return. blas obtains Runtime::stream(m.cs) and product submits oneMath gemm on that same queue (gemm.cpp:153-170); compact matrices/weights remain allocated and reuse is ordered there. IQ copies its host weight pointer list into IqGemmPtrs before launch (iq_kernels.cpp:1780+), while the pointed-to cache weights retain the unchanged cache lifetime. These are source contracts; all backend/runtime lifetime qualification is pending.

## Requested-byte formulas, not physical VRAM

Let A(payload)=round_up_to_256(payload+256), the actual Alloc::take request. Existing three planes are A(2*T*K*N)+A(4*T*K*1280)+A(2*T*K*640). Eligible compact planes are A(2*T*N)+A(4*T*1280)+A(2*T*640). FP32 Dm remains A(4*T*K*N). Raw interior payload reduction for aligned receipt T is T*(K-1)*(2*N+4*1280+2*640), i.e. 810 MiB at T8192. The actual shared arena still uses max(GDN,QSA,MoE), so the arena savings are capped by unchanged GDN/QSA, as corrected in R137/R139.
