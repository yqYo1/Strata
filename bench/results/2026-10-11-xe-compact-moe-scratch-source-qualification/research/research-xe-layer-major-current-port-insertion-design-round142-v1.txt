## Recommended minimal design

Add an explicit schedule enum to `Prefill` and a `set_schedule(PrefillSchedule)` configuration method used before `init`; keep `run(tokens,n,pos0,err)` stable and dispatch to `run_chunk_major` or `run_layer_major`. An opt-in `--prefill-schedule layer-major` parsed beside other prefill options in `src/program/generate.cpp` is preferable to silently activating based on `kv_mode`. During the first integration, require the schedule to be explicitly selected, one GPU, one full layer range, no `next_`, no helper/pipeline, no image embedding rows, no borrowed cache slots that overlap the layer expert bank, and `kv_mode==1 && kv_int8 && !kv_q4 && !kv_hybrid` for every main QSA state. Keep resident and other KV modes on current chunk-major. Report a precise refusal before changing session state.

Factor the current per-chunk body (embedding/hand-in, GDN/QSA/MoE and chunk end) into an internal `run_chunk(tokens_chunk, T, p0, input_residual, output_residual, callback_policy)` or equivalent. Initially leave the existing loop and behavior in `run_chunk_major` unchanged and verify byte-for-byte behavior through source review; call the same helper from the new route. Pass an optional host `input_residual` for layers after layer 0, copying that chunk to `m.R`; if null, use ordinary token embedding. After each nonfinal layer chunk, synchronously copy `m.R` to the output plane at row `p0-pos0`. The loop order is:

1. Allocate one pageable host FP32 residual plane for `n * D` values (`D=hc*n_embd`), not one per layer boundary. Save starting PLE previous-token scalars. Keep device activation and attention/MoE scratch bounded by existing `m.T` buffers.
2. For `layer=0..n_layers-1`, select `[layer,layer+1)` and process `c0=0..n` in the existing chunk size/order. Layer 0 embeds tokens; other layers upload the matching rows from the residual plane. Run the normal layer body, which advances that layer's GDN or QSA state exactly once for each chunk.
3. Store each nonfinal layer's residual output to the one host plane. Only final-layer chunks run public `on_chunk` and progress/checkpoint notification. Restore schedule/stage/input state in an RAII scope on every return.

Do not repurpose public `set_stage` for this loop: its stage-chain invariant (`prefill.hpp:132-138`, validated in `prefill.cpp:653-660`) says a nonterminal layer range must have a `next_`. Add a private loop layer-range parameter or a separate internal single-layer entry that bypasses only that chain validation while still forbidding `next_` and helper handoff in layer-major mode. Keep the per-run session state (`ss`) shared; do not reinitialize GDN/QSA between layer passes. Reusing the ordinary layer code retains native projections and QSA/GDN kernels.

### Single-layer expert ownership

Repeated-weight-pass removal requires every expert blob for the active layer to stay resident over all token chunks. Current static `host_res` and `ExpertCache` mapping (`Prefill::Impl` at `prefill.cpp:397-438`; route hit tests around `:1370-1385`, `:1900-1955`, slot reads `:2070-2085`) belongs to decode/profile residency and cannot be mutated in place. Current `generate.cpp:5538-5570, 5718-5778` lends only tail cache slots to the chunk scratch; no cache suspension/restore lease is present there.

For a first simple implementation, provision a separate one-layer expert bank, with `n_expert` slots sized to the largest per-layer native expert blob (or an exact per-layer size layout if the bank can be allocated once without per-layer reallocation). Before entering the schedule, preflight and allocate the whole bank plus current `Prefill::bytes_needed` workspace; if it cannot allocate, refuse before session mutation. For each layer, copy each expert into its bank slot from the existing `ExpertSource` with correct native byte length, wait for the last copy, then use a local `host_res` table whose active-layer entries map to those slots and all other entries are `-1`. Restore `m.cache` and `m.host_res` via RAII. Never evict or overwrite the decode/profile cache. A follow-up can implement a proper decode-cache lease/borrow only after the cache snapshot/refill and verifier graph lifecycle is designed and measured.

This bank is an additional GPU owner, not “free” because residual rows are host-side. `bytes_needed()` today accounts for normal chunk device workspace only (`prefill.hpp:105-106`; `generate.cpp:5555-5565`). Add a distinct layer-major plan/bytes query and include the bank plus workspace in lend/reserve admission. The current ordinary tail-slot scratch loan cannot overlap it. Do not claim fit from cache slot count or arithmetic alone.

## Preserve current QSA streamed INT8 machinery

Use the already-current session state rather than a new backing store. `src/core/layer.cpp:650-816` creates `kv_mode`, slots, map and host K/V codes/scales; `:872-891` resolves selected ids; `:1072-1086` appends K/V with host mirroring. In `src/prefill/prefill.cpp:711-720`, init makes the stage identity table; `:1643-1677` stages the prefix and appends K/V to host plus stage/resident slots; attention pools are selected at `:1807-1822`. The layer operation in `src/core/layer.cpp:1100-1120` runs selected-page resolve before attention. Retain these kernel calls and the staging reuse fence. In the new loop the selected `QsaState` is determined by the sole active QSA layer, not assumed to equal `qsa_primary()`; preserve the correct state ordinal even when GDN layers lie between QSA layers. Do not introduce the legacy stage path as a second cache authority or copy all historical pages into VRAM. For INT8, keep both scale runs and any format/rotation flag coupled with code pages.

Causality remains chunk-causal: prior K/V is resolved from the host authority, current chunk K/V is appended before selected-page resolution/attention, and `steps` continue to cap each query at its own position. A stage page/map entry is valid only while its attention reader is complete. Insert no new async prefetch in the initial version; use the existing ordered calls and fences. This makes the first design easier to reason about, even if it does not overlap stage copies.

## Callback, PLE, MTP and serve semantics

The existing `on_chunk` contract is final residual per prompt chunk (`prefill.hpp:114-123`), and server fills next-token ids then calls `draft_kv` or `mtp.prefill` (`generate.cpp:6451-6457`). In layer-major, intermediate layer results must go only to the host residual plane. Invoke `on_chunk` exactly once for each chunk after the final layer, in increasing position order; preserve the last prompt token omission already chosen by `n_batched` (`generate.cpp:10201-10202`). Keep MTP's independent state and existing fallback: `draft_kv` may return not-applicable for its own KV mode or scratch, then the server runs `mtp.prefill`; main streamed-KV mode must not change that decision. No MTP draft append occurs on intermediate layer passes.

PLE input rows depend on token history, but PLE state mutates at layer 1. Factor chunk body so the PLE work still runs once per token during only the layer-1 pass. Snapshot the entry `ple_prev` and preserve it while layer 0 is processed; let layer 1 advance it chunk by chunk; later layers must not reset or advance PLE history. Initial mode should refuse `STRATA_PREFILL_PRELOAD_PLE` if it bypasses this ordinary path. GDN and QSA state similarly must persist across chunks and not be reset at each layer iteration.

The key serve issue is checkpoint coherence. With chunk-major, all layers reach the same `done` position before `on_chunk`; in layer-major, after one layer reaches end-of-prompt, later layers have not advanced. Therefore do not call `on_stage_chunk`, periodic checkpoint capture, conversation-cache checkpoint insertion or cancellation recovery callback at an intermediate layer/chunk. In a first implementation, gate layer-major out of multi-GPU and all serving/cache routes; allow only an explicitly opt-in one-shot full-prefill path whose caller discards the session on any partial failure. To integrate service later, checkpoint the complete pre-run state (including streamed host K/V and all QSA/GDN/PLE fields) and restore it on failure/cancel, and publish a completed conversation checkpoint only after all layers finish. This transaction can be expensive; it must have a phase memory budget. Do not treat partial layer progress as a resumable checkpoint.

Current snapshot code is the right state boundary: `src/core/conversation_snapshot.cpp:79-114,127-225` chooses authoritative host pools for streamed layers and validates/resets map data; `generate.cpp:7787-7989,8344-8354` handles disk and live restore; checkpoint helpers are around `:7305-7345`. Keep snapshot bytes in current host code/scale format, not transient slots. The save/restore implementation need not change if round-trip gates prove it already covers this selected mode; do not assume parity without tests. If restore is invoked during layer-major, refuse until the pre-run transaction is restored and normal chunk-major execution resumes.

## Reuse from legacy versus do not port

Reuse the legacy *algorithmic shape*: outer layer, inner chunks; one host residual plane; retain a layer's experts across chunks; intermediate chunk callback copies to the plane; only final layer publishes callbacks; RAII restores temporary runner state. The exact legacy functions/types cannot be copied as-is: its full-single-GPU compact-FP16 guard and residual/cache lease machinery are tied to different formats and ownership (`legacy prefill.cpp:2501-2511,2714-2775`). Current Xe needs `ExpertSource` native blob lengths, `ExpertCache::open_sized/fill_slot` (`include/strata/core/expert_cache.hpp:91-98,169-184`), current stream IDs and session snapshots. Reusing the legacy eager all-prefix KV staging as the durable store would be a mistake; current Xe's `QsaState::host` and `KvStreamMap` own full history.

## Bounded correctness gates and rollout order

1. **Route and chunk-body seam:** introduce explicit schedule, no behavior change for default chunk-major. Static/source tests should confirm fixed `LB/LE` validation, every intermediate callback is private, final callback is exactly once per chunk, and any early return restores state/config pointers.
2. **Small single-layer reference:** compare resident and streamed-int8 runs at short contexts with chunk sizes that end before, on, and after a KV page boundary; compare final logits/residuals and full QSA codes/scales, map-reset behavior, indexer tails/dead/pooled/block_pos, GDN state/conv state, PLE history/prev and token positions. Use identical chunk sizes and disable MTP initially; do not weaken existing tolerance.
3. **Layer-major versus chunk-major state:** exercise at least one GDN layer before/between/after QSA layers, plus PLE layer 1. Compare per-layer session checkpoint components at end and sampled intermediate residual plane rows. Exercise empty prompt/no-op, nonzero pos0, final partial chunk, error from source load/copy, and cancellation at each layer and chunk. For first API, errors/cancel poison/discard the session; no decode follows.
4. **MTP and ordinary serving callbacks:** enable MTP only after final-layer callback counts, `next_tokens` alignment, its resident/ring fallback, draft KV end position and final logits are matched against chunk-major. Then test one-GPU service with checkpointing disabled. Keep `on_chunk` progress/PP emitted monotonically and once per final chunk.
5. **Snapshot/restore and transactional service:** save, restart/restore, continue decode, and branch/rewind from a checkpoint; compare QSA authoritative host code/scale pools and all recurrent state. Add pre-run rollback before enabling cancellation, periodic checkpoints, parked conversation cache, or disk SAVE/RESTORE with layer-major.
6. **Full 262144 occupancy and failure gates:** only after small parity, run fixed max_context=262144 with `--kv int8`, `kv_mode=1`, multiple configured resident-slot counts and chunk boundaries. Record per-phase host RSS/pinned bytes, VRAM free/total and owner extents from before prefill through max live overlap (layer bank + Prefill scratch + QSA slots/indexer/RoPE + GDN/PLE + cache/graphs + snapshots); verify no OOM fallback or allocator overcommit, no stale/missing page, no partial-state decode. Re-run restore and cancellation fault paths at the same capacity. A pass establishes only that tested configuration's correctness and occupancy; not speed or universal fit.

## Plan ranking and initial refusal matrix

**Plan A (recommended, least protocol risk):** add dedicated, preflighted full-layer native expert bank and one residual plane; reuse exact current layer chunk body and current QSA stream kernels; single GPU, one-shot, explicit opt-in; no serving cache/checkpoint/MTP initially. This most directly removes repeated expert reads across chunks within a layer, with a transparent and potentially large VRAM requirement. It has high allocation-risk but the smallest correctness surface.

**Plan B (later, lower peak VRAM):** resident/profile experts plus a bounded layer-local expert tile, preserving remaining experts on current source/stager. It reduces the bank peak but makes `m.host_res` routing, native grouped-MoE source ordering and per-layer/chunk expert staging complex; an expert can still be streamed repeatedly across chunks, so the intended pass reduction is not guaranteed. Only pursue after Plan A state parity; use measured routing/supply traces to bound slot need.

Initially refuse: multi-GPU/split layers and peer helper; image/vision `embd_rows`; MTP batched draft path (route may be enabled later with callback parity); service and live/periodic checkpoints, parked conversations, SAVE/RESTORE and cancellation resume; resident FP16, Q4, hybrid K8V4, draft ring, or other non-`kv_mode=1` main QSA states; partial prefill that expects intermediate checkpoints; and any configuration whose preflight cannot reserve both the one-layer expert bank and chunk workspace before mutating `SessionState`. Keep current chunk-major as the fallback for every refusal. This separation makes the first implementation a correctness experiment, not a production policy.
