## Finding

The legacy route is structurally close to supporting streamed main-layer KV because it already invokes the ordinary chunk-major `run_impl` once per layer while retaining layer-major expert weights. The hard rejection at `sycl/src/prefill/prefill.cpp:2506-2511` (`kv_mode != 0`) is definitive today. The surrounding schedule at `2483-2505, 2749-2750, 2785-2850` keeps one full-context residual plane, loads each layer's experts once, sets `stage_lb_/stage_le_` to that layer, and runs all token chunks for that layer in order. The output callback writes each chunk into the same residual plane for the next layer. Thus each QSA layer can independently append positions 0..N in chronological order; prior layers' KV and indexer state remain complete, and future layers remain untouched until their pass. This ordering is compatible in principle with a per-layer host-backed KV authority. Removing the guard alone is not a safe change: the chunk route must establish and use its streamed staging/map contract for these repeated per-layer passes, and session/MTP/state parity must be demonstrated.

The sequence is not the proposed “one full context through one layer at once” QSA kernel. It remains chunked within each layer. Existing causal chunk semantics must remain: for chunk `[p0,p0+T)`, keys from `[0,p0)` are made available from backing storage, current K/V for this chunk are appended before attention consumes the chunk, and the attention mask/selected ids must ensure each query at `p0+t` sees no key beyond that position. The next chunk may evict resident slots only after attention readers finish. Host K/V, not transient device staging slots, must be the authority after each chunk.

## Current Xe reference contract

Current Xe QSA state sets `kv_mode`, slot/page counts and allocates a host pool for streamed states in `src/core/layer.cpp:650-685, 780-816`; `qsa_kv_resolve` routes selected ids through the per-state map at `872-891`. For INT8, the authoritative host pool comprises K/V codes and group scales. Layer append kernels mirror new rows there (`src/core/layer.cpp:1072-1086`; prefill batched append at `src/prefill/prefill.cpp:1643-1677`), rather than treating resident slots as durable state. `src/kernels/xe/kv_stream.cpp:212-243` resolves requested blocks and completes transfer before attention; `:269+` provides host-to-staging page copies. Prefill initializes an identity page table for the staging pool (`src/prefill/prefill.cpp:711-720`), stages the previous prefix before QSA attention, appends the chunk to host plus resident/staging pools, then attends (`:1643-1677` and subsequent attention dispatch). The asynchronous staging pool is single-owner: current prefetch logic (`:3260-...` in legacy source) waits for its prior reader before reuse. An implementation must retain that lifetime fence or an equivalent pin/reference protocol; a page cannot be overwritten while attention reads it.

The legacy `run_impl` already contains a staged path: it recognizes streamed QSA layers, transfers the prefix to its KV staging pool, mirrors appends to host, and chooses staging pools for attention. But `run_layer_major` rejects the mode before reaching that path, and stream-stage allocation/selection must be rechecked for a one-layer `LB/LE` range across repeated `run_impl` calls. Specifically establish that stage buffers are allocated once from the correct QSA layout and that the map is resolved against this layer's persistent backing, not accidentally the primary state's map or a shared identity-only stage. For attention to use INT8, every staging pool must carry the same code and scale runs and format/rotation as that state.

## Recurrent, PLE, MTP and session obligations

GDN recurrence is session state, not residual scratch. Layer-major revisits each GDN layer over prompt chunks in increasing position order, so its recurrent and convolution state can match chunk-major if no state is reset between chunks and each layer runs exactly once. QSA indexer tails, dead block, block position and pooled rows likewise advance once in token order per layer; the per-layer loop must not duplicate their append when staging or retrying.

PLE is tied to layer 1 and token chronology. Legacy layer-major rejects `STRATA_PREFILL_PRELOAD_PLE=1` (`2512-2515`); ordinary PLE work remains in `run_impl` for the layer-1 pass. The initial PLE history is restored before each layer pass (`2826`), then layer 1 advances it across chunks; later layers must not advance it again. Preserve final `ple_prev` and PLE history exactly once. Do not apply the layer-major callback to PLE once per repeated stage in a way that double-advances history.

The `on_chunk` callback is per chunk of the final layer only: intermediate layer callbacks copy residual chunks to the shared host/device plane; final layer callbacks invoke the saved callback (`2831-2849`). Current server callback uses each final residual chunk to fill next-token IDs and call `draft_kv` (or `mtp.prefill`) (`src/program/generate.cpp:6451-6457`; probe path `10187-10192`). The MTP draft state has its own KV geometry/mode and append path; `draft_kv` currently rejects modes other than resident 0 or draft ring 2 (`src/prefill/prefill.cpp:1447-1455` legacy; Xe equivalent around 900+). Main-layer streamed INT8 eligibility must not accidentally imply MTP streamed support. Keep one callback per final-layer chunk, preserve full prompt order and last-token omission, and either retain the existing valid MTP mode or explicitly fall back to per-chunk `mtp.prefill`.

Current Xe session snapshots make host K/V authoritative for nonresident states: `src/core/conversation_snapshot.cpp:79-114` selects `st.host.*`, requires the host pool and validates the stream map; save/restore are at `:127-225` and reset/reconstruct streaming metadata. The service's disk and conversation restore routes call snapshot validate/restore in `src/program/generate.cpp:7787-7989, 8344-8354`, and checkpoint state carries QSA/GDN/PLE data. A legacy insertion must ensure its `conversation_kv_save`/checkpoint paths select streamed host K/V and restore enough page-map metadata (or deterministically reset the map and resolve pages lazily) before decode. Capturing only current VRAM slots would lose evicted pages. No evidence in this audit establishes that every legacy save/restore route already handles stream mode from layer-major; this needs explicit source parity review and round-trip comparison.

## Minimum conceptual changes, ranked

1. **QSA stream preconditions and per-layer stream lifecycle (blocking).** Replace the all-resident guard only after proving that the selected `run_impl` staging, append, map-resolution and attention paths run under single-layer `LB/LE` calls. Create/reuse stage storage at the right extent and format; bind correct state and resolve pages before every attention read; serialize host backing writes against attention, stage reuse, cancellation and chunk transition. Keep the existing resident mode unchanged.
2. **State/session parity (blocking).** Ensure streaming host arrays are the persistent source for checkpoint, conversation save/restore, rewind and decode continuation. Confirm map reset/resolve after restore; do not serialize slot contents as full history. Compare streamed and resident checkpoint components including K/V, indexer tails/dead/pooled/block positions, GDN recurrence/conv state, PLE history/prev and token IDs.
3. **MTP and callback parity (high).** Preserve final-layer-only `on_chunk` and per-chunk ordered next-token inputs. Decide and validate fallback when MTP is not in an accepted mode. Do not invoke draft append on intermediate layer passes.
4. **Causal/chunk boundary and failure atomicity (high).** Validate prefix stage → current K/V append → selected-page resolve/pin → attention ordering with non-page-aligned chunk boundaries, page crossings, repeated chunks, chunk size smaller/larger than slots, cancellation and allocation/copy errors. Make failed/partial prefill non-decodable or rollback to the last checkpoint.
5. **Phase memory admission (required before any claim).** Keep R140's one host FP32 residual plane (10 GiB at 262143 rows) distinct from cumulative transfer traffic. Streamed INT8 backing is a separate full-context pinned host allocation (6.188 GiB at 262144 cells in the corrected geometry); VRAM then holds resident slots, stage buffers, indexer/RoPE, expert cache, dense/session workspaces and runtime allocations. Layer-major temporarily owns the current layer expert cache plus existing cache-lease and session states. Gather simultaneous phase receipts; no device/host fit or performance claim follows from the conceptual compatibility.

## Scope limits and conclusion

The current XeStrata WX source is chunk-major and has no `run_layer_major`; it serves here only as a contract reference. The legacy code's pass order makes streamed INT8 main-QSA KV plausible without retaining all FP16 K/V on device, but compatibility is conditional on correct staging/map handling and session lifecycle. The guard is a real explicit prohibition, not proof that deleting it suffices. The immediate useful source work after this research is a narrowly scoped design/patch proposal for the legacy streamed single-layer stage, followed by resident-vs-streamed state/callback/restore equivalence and phase-aligned memory qualification. This report itself contains no qualification result.
