## Result and proposed carve condition

The two contiguous QSA projection allocations `m.Kc` and `m.Vc` form a viable scratch span after the last K/V append consumer. The base is `m.Kc`, and the span is the combined payload of both FP32 projections. Every current prompt K/V format consumes these projections into session-owned KV storage before attention: ordinary FP16, ordinary INT8, rotated Q4, hybrid K8V4, resident cache, and streamed host/staging/resident copies. The attention kernels read the session pools and selection state, not Kc/Vc. A same-compute-queue order proof therefore makes the span reusable by decode-attention scratch without changing K/V values, query selection, attention output, or precision.

The carve must be conditional on `combined_KV_projection_bytes >= attn_batch * qsa_decode_attn_scratch_floats(cap, shapes) * sizeof(float)`, with checked multiplication and the exact active shape/cap/batch. If false, keep the existing separately carved `m.attn_scratch`. At the supplied T=8192 source arithmetic, the corrected guard-aware threshold is T=6388; do not extrapolate that threshold to a changed shape, cap, batch, or allocator. For T below the threshold the separate-scratch fallback is required. At or above threshold, the precise runtime condition—not a hard-coded token cutoff—decides eligibility.

A maintainable implementation should centralize this predicate and use it identically in `qsa_set_bytes` and `Prefill::carve`, which are also reflected by `Prefill::bytes_needed` (`prefill.cpp:573-581,741-781,1028-1048`). On eligible layouts, keep the original Kc and Vc pointers/extents and set `m.attn_scratch = m.Kc` instead of taking a new scratch extent at the tail. The Kc and Vc takes must remain adjacent and their combined extent must be sufficient. On ineligible layouts, preserve the current independent scratch take. This keeps the QSA view's high-water count honest and avoids changing GDN/MoE phase overlap or region ownership. Existing 256-byte allocation guard/alignment accounting must be applied to each resulting take sequence; this is not a raw payload-only carve.

## Lifetimes and queue dependencies

The QSA view starts with Kc and Vc, followed by Qf, q, indexer/query/attention outputs, selection IDs/scores, and currently a final attention scratch take (`prefill.cpp:774-781`). In the layer path, K/V projections write Kc/Vc; K normalization and rope consume/mutate Kc; then mode-specific optional transforms and append operations consume the projections (`:1636-1678`). The subsequent Q/query transforms, indexer updates, selection scoring and top-k use Q/indexer buffers and persistent indexer state, not Kc/Vc (`:1679-1721`). Prompt attention consumes `q`, IDs, steps, and session KV pools; decode fallback consumes the same plus scratch and writes the separate `m.attn` (`:1807-1821`). Rotation of the attention result and the output gate/projection consume `m.attn` after attention (`:1822-1825`), never the K/V projections.

All projection, append, selection, prompt-attention and decode-attention operations in `Prefill::run` receive `m.cs`. `Runtime` compute queues are in-order; the copy queue is used for staging/expert transfers, and event waits connect its writes to compute consumers (`device.cpp:185-187`, `prefill.cpp:1645-1651`, surrounding staging code). K/V appends may still be running when their host wrapper returns, but later scratch writes are queued after them on the same in-order compute queue. The selector can therefore execute between append and attention without keeping Kc/Vc alive. Decode fallback loops over query batches and reuses one scratch buffer; successive calls are ordered on that queue, and each call's merge is enqueued after its split-K producer (`qsa_decode_attn.cpp:298-315,319-332`).

The append's destination and ownership are session state: `st.page_table`, persistent K/V arrays or compressed pools, host mirror, and optional staging pool. In streamed mode the routine first stages old pages from host, then appends the new cells to host/stage and resident slots (`prefill.cpp:1643-1678`). `take_stage` allocates storage separately from the QSA shared region (`:497-521,840`), so aliasing Kc/Vc does not alias or shorten the staged pool. The source projection is dead after append even when the durable session data have multiple owners.

## Feature and dispatch matrix

| QSA KV / path | Last Kc/Vc consumer before scratch | Source lifetime conclusion |
|---|---|---|
| Default FP16 pools | `kv_append` converts/copies Kc/Vc into `st.k_pool`/`st.v_pool` | Safe after append on `m.cs` |
| Ordinary INT8 | `kv_append` writes quantized K/V and scales into persistent `st.k_q`/`st.v_q` pools | Safe after append; scratch does not touch those pools |
| Rotated Q4 K/V | Optional in-place FWHT of Kc/Vc, then `kv_append_q4` encodes into persistent Q4 pools | Safe after Q4 append; transformed projection values need not be preserved |
| Hybrid K8V4 | K append consumes Kc; V is optionally rotated then Q4 append consumes Vc | Safe after both append submissions; retain ordering between the two writes and scratch |
| `kv_mode == 0` resident cache | Appends target the session pools/page table | Safe; no separate staging ownership |
| `kv_mode == 1` streamed | `kv_stage_from_host`, then append writes host mirror, staging pool and any resident blocks | Safe only after all compute-queue append submissions; host/stage destinations remain session-owned |
| `kv_mode == 2` ring/window state | Appends target ring/page-table-backed pools; scratch is transient | Same lifetime; ring/page-table semantics unchanged |
| New prompt-attention batch kernel succeeds | Reads Q, selected IDs/steps and pools; writes `m.attn`; it does not access `m.attn_scratch` | Alias is dormant and harmless |
| Prompt kernel returns false or `STRATA_PROMPT_ATTN_OLD` forces fallback | Decode attention uses `m.attn_scratch` in batches of `m.attn_batch` queries | Alias is active after append; capacity predicate is mandatory |
| Q4/hybrid prompt kernel unsupported or disabled | Prompt helper returns false before launching; caller uses decode fallback | Same scratch rule; Q4 modes do not extend Kc/Vc lifetime |

The prompt helper's `false` cases are capability/shape checks before dispatch; it launches an attention implementation only on the true path (`qsa_prompt_attn.cpp:1038-1095` and following dispatch). On that true path no decode scratch is passed. The decode path's four KV modes are selected from pool pointers, and validate the needed pool components before launching (`qsa_decode_attn.cpp:298-345`). QSA selection's `cap` is computed from `qsa_selection_width(kTopkMaxCells, shapes)` and geometry; `max_blocks` comes from session `max_cells`, while `sel_batch` and `attn_batch` are currently 256 and 32 (`prefill.cpp:425-428,757-761,1041-1047`). Shapes and these tunables must remain inputs to the predicate: changing selected width or decode batch changes scratch demand, and changing geometry changes the bytes per query. `max_blocks`/selector mode affects selection buffers but not decode scratch's cap formula.

## MTP callback, prompt/session lifecycle, and other consumers

`Prefill::run` synchronizes `m.cs` before invoking `on_chunk` (`prefill.cpp:2882-2891`). The normal prompt MTP callback calls `draft_kv` from that callback (`generate.cpp:6451-6456`; another caller is at `:10187-10193`). Thus the main QSA append, attention, and output projection are complete before the callback can repurpose `m.region`. `draft_kv` then takes the region as its own temporary carve, including its own Kc/Vc, and writes the drafter's separate session state; this happens after the main scratch lifetime and does not require restoring the previous scratch contents (`prefill.cpp:872-944`). If a future callback is moved inside the QSA phase or invoked before compute sync, this proof no longer applies.

The selector and debug selector paths use `m.sel_scores`, `m.sel_ids`, `m.q_idx`, and persistent `st.idx_*` (`prefill.cpp:1685-1805`). They do not retain Kc/Vc. `STRATA_QSA_DUMP` copies IDs, not K/V projections. PLE owns separate buffers. Persistent session KV and indexer state, page tables, host copies, stage pools, and attention output all remain distinct. The proposed alias only affects transient scratch bytes inside the shared region; it must not alter any `QsaState`, cache, page table, snapshot/restore representation, or host pool.

## Required invariants, failure cases, and validation gates

- Compute byte sizes with overflow-checked arithmetic from the actual `T`, `cap`, `attn_batch`, and `QsaShapes`. Include allocator guard/alignment policy in allocation-size/count validation. Verify the exact Kc/Vc combined address interval is contiguous and the scratch interval does not exceed it.
- Keep Kc/Vc projection outputs and all transforms/append arguments unchanged. Do not alias Qf, q, selector buffers, `m.attn`, `m.attn_h`, or persistent KV; those remain live during decode attention or have distinct consumers.
- Submit every K/V transform and append before any possible scratch write, on `m.cs`. If an append or attention path moves to another stream, add explicit event dependencies and prove source reads have completed before reuse.
- For insufficient span, retain independently allocated scratch and preserve the original qsa_set_bytes/carve sequence. This covers small T and any geometry/cap/batch that increases scratch demand. Do not force a smaller `attn_batch` as an unmeasured workaround.
- MTP `on_chunk` remains after compute synchronization. Preserve current failure propagation and stage/event draining; do not let a failed append proceed to decode attention or callback.

Before accepting an implementation, compare aliased and unaliased results for each KV mode (FP16, INT8, Q4 rotated, hybrid K8V4), both resident and streamed/ring cache where supported, and both prompt-attention success and forced decode fallback. Exercise fallback below the exact capacity threshold and alias at/above it; include short and maximum chunk shapes, multiple query batches, page-boundary appends, nonzero prompt positions, streamed host staging, and MTP callback enabled. Check Q/K/V cache bytes/scales, selected IDs, attention output, residuals, final session state and subsequent decode logits against baseline using established tolerances; include guard/sanitizer or explicit canary checks for the shared interval and verify `bytes_needed`, `init`, and `relayout` agree. Full-context occupancy must be tested separately for acceptance. No source-only argument here establishes device parity, allocator fit, or speed.
