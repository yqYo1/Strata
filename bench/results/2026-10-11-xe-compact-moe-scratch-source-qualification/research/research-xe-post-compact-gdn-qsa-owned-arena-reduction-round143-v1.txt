## Current allocation ownership

`Prefill::carve` at `src/prefill/prefill.cpp:741-805` creates the one `m.region` as `max(gdn_set_bytes, qsa_set_bytes, moe_set_bytes)` at `:763-768`. The same address is independently carved three times, once for each mutually exclusive attention/MoE phase: GDN at `:769-773`, QSA at `:774-781`, MoE at `:782-795`. `bytes_needed` and relayout use the same `carve`/count sequence (`:1038-1048`, plus the `Prefill::bytes_needed` path and init/relayout callers around `:643-...` and `:850-...`); any alias must change both the count-only set and actual carve identically. Compact MoE reduces only its own set; it does not alter GDN or QSA sets. It also adds a separate n_expert+1 bounds descriptor outside this shared maximum, so that descriptor is not part of the 1.0877-GB MoE set.

GDN set (`:567-572`) is 7 allocations: FP32 qkv `T*C`, z `T*ZV`, alpha/beta `T*2*HV`, gate `T*HV`, beta `T*HV`, convolution output hbuf `T*C`, FP32 y `T*ZV`, and FP16 y_h `T*ZV`. Here `C=10240`, `ZV=6144`, `HV=48` (`:63-64`). Layer producer order is `native_proj(qkv)` then z/alpha/beta projections, `gdn_gates`, `gdn_conv(qkv -> hbuf)`, `gdn_recurrence(..., y, y_h)`, `native_proj(y_h -> bo)` (`:1601-1623`). No other `m.y` consumer exists in the prefill source; search shows its sole production as the recurrence argument and no reads beyond that call. `y_h`, in contrast, is immediately consumed by the output projection and remains live through that call.

Kernel source `src/prefill/kernels.cpp:779-955` establishes why y cannot simply be deleted: every selected recurrence implementation writes FP32 y, and the following FP16 output-normalization kernel reads y and writes y16/y_h (`:940-955`). In the serial route it writes both y and y16 in the recurrence loop (`:804-809`); alternate D-2/key-head/lane variants produce y before the separate output norm (`:831-939`). `STRATA_GDN_REC_HEADS`, `STRATA_GDN_KEYHEAD`, `STRATA_GDN_REC_LANE`, pipeline settings and device auto-pick do not make y dead earlier. But qkv is read by `gdn_conv` before recurrence and has no later consumer (`prefill.cpp:1612,1618-1622`). All these operations are queued on the same in-order compute queue. Since qkv's `T*C` allocation is larger than y's `T*ZV`, the exact y byte span fits at the beginning of qkv once convolution has completed. Reassign `m.y` to `m.qkv` in the GDN carve and remove the separate y take; retain the existing kernel and arithmetic. This is a storage-lifetime alias, not a precision or output change. It saves `T*6144*4` requested bytes from the GDN set: 201,326,592 B at T=8192. GDN becomes 979,372,032 B using Main's candidate set request (aligned allocations are multiples of 256 at that T).

QSA set (`:573-581`) owns per-token Kc/Vc FP32 `2*T*512`, Qf FP32 `T*12288`, q FP32 `T*ZV`, idx_raw `T*128`, q_idx `T*512`, attention output FP32 `T*ZV`, attention output half `T*ZV`, selected ids `T*cap`, plus fixed scores `sel_batch*max_blocks` and attention scratch `attn_batch*qsa_decode_attn_scratch_floats(cap,s)`. The selected geometry (`include/strata/kernels/qsa.hpp:114-120,130-139`) gives `idx_top_k=2048`, `idx_block=4`, `page_size=4`, so `cap=2051`; at max_context 262144, `max_blocks=262144/4+2=65538` (`prefill.cpp:760-761`). `sel_scores` is therefore a significant fixed allocation, not a small per-layer detail.

QSA lifetimes: Kc/Vc/Qf and indexer projections are produced at `:1635-1640`; Kc is normalized/RoPE'd and K/V append writes codes/scales to state/staging at `:1641-1677`; Qf is split to q at `:1679-1682`. Indexer buffers feed selection; Qf must stay live past attention because `gate_attn(m.attn,m.Qf,...,m.attn_h)` consumes Qf at `:1824`, and q feeds attention at `:1814-1820`. The FP32 attention output and half output overlap in the gate, so they cannot be aliased. The K/V projection buffers have no consumer after their append (all `m.Kc/m.Vc` references in this file are those projection and append sites); the existing attention scratch is not used until the fallback attention loop (`:1816-1820`). Thus Kc and Vc together can hold attention scratch after append, if their combined extent is large enough and the compute queue preserves append-before-scratch order.

For the T=8192, max_context=262144 recipe, the current QSA count is derived as follows, using the exact source layout and its aligned `Alloc::take` sequence:

- Per-token Kc/Vc/Qf/q/idx_raw/q_idx/attn/attn_h: 117,248 B; across T: 960,495,616 B.
- selected ids: `8192*2051*4 = 67,207,168 B`.
- score matrix: `256*65538*4 = 67,110,912 B`.
- attention scratch: `32 * (ceil(2051/64)*24*(256+2)+64) * 4 = 26,163,200 B` (`qsa_decode_attn.cpp:23,329-332`).
- total QSA set: 1,120,976,896 B.

Kc+Vc is `2*8192*512*4 = 33,554,432 B`, enough to host that 26,163,200-B scratch after both append reads finish. Re-carve Kc/Vc as one contiguous `2*T*512` float span; alias `attn_scratch` to its base only when this span is at least the attention-scratch size. Then remove the separate attention-scratch take from the QSA count and actual carve under the same condition. On the usual in-order compute stream, prior K/V projection/append work completes before later attention scratch use; the queue ordering must be explicitly preserved if any append leg is ever moved to another queue. The same QSA count/alias rule must hold in `bytes_needed`, `init`, and borrowed `relayout`. With T=6144, Kc+Vc is only 25,165,824 B, smaller than 26,163,200 B, so this alias is ineligible; retain the old scratch allocation there. Threshold is `T >= ceil(scratch_bytes / (2*512*sizeof(float)))`, 6384 rows for these shapes.

The scratch alias saves at most 26,163,200 B at T=8192. It is safe only if Kc/Vc have no hidden diagnostic/alternate consumer after append, no command on another queue still reads them, and both pointers are laid out contiguously with correct alignment. The QSA prompt-attention fast kernel does not use scratch, but fallback/`STRATA_PROMPT_ATTN_OLD` does; preserving fallback capacity is required. Do not alias Qf, q, attn, attn_h, or sel_scores based on apparent ordering: Qf and q overlap through gate/attention, q and attention output participate in the same operation, attn feeds gate, attn_h feeds output projection, and scores overlap active query/indexer material. An in-place attention kernel change would need its own kernel proof and parity gate.

## Post-compact max and exact effect

For the report's fixed 8192-token, max_context=262144 source arithmetic, the current max is GDN `1,180,698,624 B` (QSA `1,120,976,896`, compact MoE `1,087,671,808`). Removing the dead separate y allocation, while reusing qkv, changes GDN to `979,372,032`; QSA becomes the maximum and the shared region becomes `1,120,976,896 B`. This alone lowers the shared-region maximum by 59,721,728 B; it does not save all 201 MB from the total region because QSA takes over.

Adding the conditional Kc+Vc/attention-scratch lifetime alias lowers QSA to `1,094,813,696 B`. The maximum is still QSA, ahead of compact MoE by 7,141,888 B. Relative to the reported pre-alias shared max of `1,180,698,624 B`, the combined exact-alias design lowers the shared-region request by 85,884,928 B. The descriptor remains separately requested at 2,560 B, so total requested-buffer arithmetic includes it independently. These deltas are computed maxima from the provided source receipt; allocator alignment outside the already aligned individual requests, runtime temporary/autotune allocations, other owners and actual device headroom are not included.

## Other region consumers and feature branches

`m.region` is also used as variable-size sub-batch scratch for batched PLE (`prefill.cpp:1231-1233,1528-1540`) and for `draft_kv` (`:888-944`), both of which size their sub-batch B/SB from `region_bytes`. They do not carve an additional fixed larger set; they must be rerun after shrinking to prove the selected batch still fits and fallback behavior remains valid. PLE's mutating work stays on the PLE path, distinct from GDN/QSA storage alias. MTP may return false/not-applicable on less scratch and caller falls back to its own prefill; verify it does so with empty error. A success route may change batch size, so callback/final state must still match; do not treat changed batching as harmless without validation.

Optional `STRATA_GDN_REC_*` recurrence branches all still require FP32 y and the alias preserves their identical pointer capacity. QSA fallback attention and the old-attention switch still require full attention scratch, so they constrain the conditional alias threshold. `STRATA_DBG_NAN` reads GDN state and MoE buffers but not m.y; however the compact-MoE source explicitly rejects DBG_NAN. Preserve that rejection and exercise debug without compact separately. `STRATA_QSA_DUMP` records selected ids and does not read Kc/Vc. QSA INT8/rotated/hybrid formats affect append/staging data but not these temporary FP32 buffer extents. PLE preload, MTP batching, small T, BF16x2, MMQ/fallback combinations and relayout require source-count consistency; do not update only one carve path.

`GDN state`, `conv` state, `QsaState` KV arrays/indexer state, decode caches, and pinned host backing do not live in this shared region and cannot be counted as saved by these aliases. They remain allocated with their existing lifetime. `m.region` alone also does not describe temporary `yy` and state copies used by GDN kernel selection/autotune (`kernels.cpp:904-938`), which can briefly increase first-use physical peak even though the persistent shared arena gets smaller.

## Safe next change and bounded gates

The lowest-risk source change is GDN-only: remove the separate FP32 y span from both `gdn_set_bytes` and carve, assign `m.y=m.qkv`, retain kernel signature and all precision paths. First prove the compute queue orders qkv projection/conv before the aliased recurrence writes and verify all recurrence env branches plus final GDN projection and checkpoint state. This alone has a clear ~59.7 MB shared-max saving under T8192 because QSA takes over.

A second, still precision-preserving but more structural change is conditional QSA scratch/Kc+Vc overlap for T >=6384 with max QSA scratch geometry. It needs a contiguous projection span, byte-identical count/carve predicates, queue-order proof for K/V appends, fallback/old-attention coverage, and a T-boundary matrix around 6384. It raises confidence risk, so it should be a separate change after GDN alias.

Qualification gates for either: compare old/new final residuals/logits, per-layer GDN recurrence/conv state, QSA K/V codes/scales/indexer state and checkpoint/restore; run GDN serial/D-2/keyhead/lane selection paths; run QSA fast and fallback/old-attention; exercise PLE and MTP scratch consumers; verify T=6144 retains unaliased attention scratch while T=8192 aliases; compare `bytes_needed`, init, borrowed relayout and actual requested extents for default/compact and debug/MMQ rejected combinations; then collect a phase-aligned full-context occupancy receipt including first-use GDN autotune. No speed prediction or full262144 fit claim follows from this arithmetic.
