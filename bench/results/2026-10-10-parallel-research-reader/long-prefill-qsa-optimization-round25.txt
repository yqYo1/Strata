## Candidate 1 — tiled QSA score kernel that reuses a key tile across queries

**Mechanism.** In the active long-prefill fallback, `block_scores_kernel` assigns one work-group to one query and a run of eight key blocks (`qsa_select.dp.cpp:32-72, 1576-1645`). Each work-group loads the 128-float pooled key block for its query/block pair; neighboring query groups repeat those key loads. At full context the prompt path sends up to 256 queries per score call and reaches about 65,538 block slots (`prefill.cpp:687, 1293-1301, 3914-3927`), although only active blocks are written. A portable 2D tile over a small query group and key-block group could stage each pooled key tile once and reuse it across several query rows, retaining the existing per-query score output layout and subsequent top-k. A query tile already exists in the dormant/target-specific score implementation family (`qsa_block_scores_tc` and its `TC_QT=16`, `TC_NB=32` design); the current SYCL path does not take that path, so this is a new portable SIMT data-reuse experiment, not a claim that the tensor-core scorer is active.

**Correctness/lifetime constraint.** Preserve each score's current FP32 operation and reduction order exactly: four 128-wide heads, per-head subgroup XOR reduction, ReLU per head, sequential head sum, and the `+1e9` causal-tail bias (`qsa_select.dp.cpp:49-71`). Keep one independent score row per query and leave radix selection untouched. A tiled kernel that changes reduction ordering or score bits can change a near-threshold selection even if output logits usually match. Stage only immutable `idx_pooled`/`idx_dead` tiles; all rows in the tile consume the same published indexer state after append completion. Avoid mutating reusable tile memory until all work-items consuming it have passed the group barrier.

**When to try / smallest falsifier.** First use clean root-owned `kPfQsaSel` timing to confirm block scoring is material at 131K/262K; no current receipt attributes the long wall time to this kernel. On one QSA layer, compare current and tiled score tensors bitwise for short, middle, and full-context query windows including block tails and close-score/tie rows, then compare exact selected-ID arrays and full outputs/state. A single changed score or selected ID rejects the math-preserving claim. Only if exact parity holds, compare score-phase wall time and memory traffic on B570; account for local-memory use/occupancy and added barriers. The CUDA/AMD tile implementation is architectural precedent, not proof of portable SYCL speed. [Strata score source](https://github.com/yqYo1/Strata/blob/main/sycl/src/kernels/cuda/qsa_select.dp.cpp) (target implementation details are in the frozen worktree noted above).

## Candidate 2 — overlap a completed select batch's attention with the next select batch

**Mechanism.** Current prefill selects all query batches (`sel_batch=256`) before it runs the separate attention batches (`attn_batch` default 32), then gates/projects attention (`prefill.cpp:3914-3955, 4098-4119`). This creates a phase barrier in the host submission order even though each query's attention depends only on its own selected IDs, Q row, step row, and the already-appended KV stage. A bounded pipeline could do: scorer + top-k for selection batch A; submit attention sub-batches for A; while those consume A's IDs, score/select the next query batch B on the existing selection queue. The same 64-MiB maximum score scratch can be reused once A's top-k has completed because attention does not read scores. Keep output/query ranges disjoint; serialize attention sub-batches that reuse `attn_scratch`; make the final attention/GPU transform wait precede FWHT/gating/projection. This is a queue/dependency scheduling hypothesis, not a proposed cross-row arithmetic fusion.

**Correctness/lifetime constraint.** Explicitly order all reads of `q`, `q_idx`, steps, pooled indexer, and stage KV after their writers; order each attention batch after the event that completed its top-k; retain its `sel_ids` range until attention finishes; do not reuse `attn_scratch` before the previous attention batch completes; and wait for all output rows before the following full-buffer transform/gate. If the pipeline uses a second SYCL queue, create explicit event edges instead of relying on queue submission order. Intel's SYCL Graph guide demonstrates `depends_on(event)` dependencies and warns that graph/library compatibility is not automatic; this proposal should first use ordinary queues/events and remain outside captured command graphs until graph dependencies are separately qualified. [oneAPI SYCL Graph usage guide](https://intel.github.io/llvm/syclgraph/SYCLGraphUsageGuide.html).

**When to try / smallest falsifier.** Only consider it if clean phase/event timing shows both scorer/top-k and selected attention occupy enough time and target-device scheduling can overlap them. Start with two adjacent 256-query selection batches on a single QSA layer: compare IDs, attention rows, residuals and final output bitwise against the serial schedule, with explicit event tracing and allocation lifetime assertions. Measure overlap and total layer time separately; reject if the device serializes the queues, either phase slows enough to erase overlap, or memory pressure/lifetime complexity increases without wall-time reduction. Then perform the fixed-window and full-context/repeat tests under root ownership. Never use this instrumented pipeline to clear the prior uninstrumented failure by itself.

## Cross-engine evidence and transfer limits

- **StreamIndex** demonstrates chunked score plus partition/merge top-k for DeepSeek V4 compressed sparse attention, with a tiled driver and an attention backend downstream. Its report gives an H200-specific memory-bounded regime extension, but says the chunked path adds 10–15% wall time where full materialization fits. It is a useful existence proof that score/index selection can be tiled with explicit top-k merge, and a warning to test overhead below the memory limit; its 64 indexer heads, score definition, Triton/CUDA implementation and model are not Strata QSA. It does not justify another radix-top-k proposal in this report. [StreamIndex implementation](https://github.com/RightNow-AI/StreamIndex), [paper and measurements](https://arxiv.org/abs/2605.02568).
- vLLM reports a long-prefill allocator regression when QSA logits width grows with `max_seq_len` and each chunk receives a larger allocation; the issue describes retained cached allocations and growth up to a 166,400-token failure on GB10. This is a distinct code/hardware failure, not a Strata bug. Strata already carves a fixed `sel_scores[sel_batch,max_blocks]` region and reuses it, so preserve that capacity-based allocation if the score pipeline is reorganized; do not allocate a new exact-length logits tensor for every chunk. [vLLM long-prefill logits allocation issue #56457](https://github.com/vllm-project/vllm/issues/56457).
- No direct Intel llm-scaler Qwen3.8 QSA tiled kernel or B570 QSA benchmark surfaced in the checked public sources. Do not describe general Intel XPU or DeepSeek sparse kernels as directly transferable measurements.
