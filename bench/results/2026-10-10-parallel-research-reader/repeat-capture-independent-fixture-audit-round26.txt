## Full-fixture independence and coverage

`producer_reference_records()` separately enumerates all 13 captured layer ordinals, QSA layers 3/7/11, phase order, per-row score frames, interleaved step/ID frames, dimensions, and 345-record / 66,747,936-byte totals. `generate_full()` uses this transcription and hard-coded producer wire constants/field ordering, not the reader’s phase table, magic constant, or field tuple. The source-pin case hashes the specified `prefill.cpp` and then checks all reference descriptors against `expected_full_records()`; consequently, a reader geometry change alone cannot silently redefine the fixture. The end-to-end full-pair case parses 690 frames and compares the two requests, while separate mutations test count, duplicate, order, phase, layer, row, and score-width rejection. The earlier R24 coupling finding is therefore resolved at the source-structure level.

Limit: the pin authenticates only the stated `prefill.cpp` blob, while the fixture’s framing constants and binary field tuple are handwritten in the test. This is a source oracle, not a parser of producer source or a check of the separate wire-header declaration. The prior independent producer-to-reader source review supplies the static cross-check; if the producer header/schema changes while `prefill.cpp` does not, this test’s hash gate alone will not notice. Keep that distinction in the report and re-review the producer schema when it changes. Repeated-zero selected IDs are valid fixture data for this parser contract, but do not validate real top-k content or numerical behavior.

## Ledger, descriptors, bounds, and identity

`read_ledger()` calls the shared no-follow component walker with a 64-KiB file limit, reads at most 65,537 bytes, rejects the extra byte, compares final descriptor identity against the initial `fstat`, and checks read length against the pinned size before JSON decoding. It closes its descriptor in `finally`. The tests include exact-64-KiB input, over-budget/malformed inputs, symlink/hardlink/FIFO/directory/permissions cases, deterministic growth and same-size mutation during read. I found no path by which ledger input can exceed the stated read budget or substitute a different inode after open.

`validate_ledger()` now rejects non-exact integers (including booleans), negative offsets, offsets above file size/capture cap, invalid sizes, gaps/overlaps, order/name errors, wrong empty/nonempty requests, and trailing uncovered bytes. Since the reader itself pins capture size under `MAX_BYTES`, the enforced `end <= size <= MAX_BYTES` is consistent. `owned_full` still requires each complete frame to belong to exactly one of the two full intervals and validates both full-request coverages. No new size/offset issue found.

One optional canonicalization hardening remains: standard `json.loads` silently keeps the last value for duplicate object keys. Shape/name/range validation still applies to that resulting dictionary, so this does not bypass the byte cap or descriptor identity, but a ledger such as a row containing two `"begin"` keys is textually ambiguous. If ledgers may be edited by an untrusted producer, use an `object_pairs_hook` that rejects duplicate keys and add a fixture. For the described private, root-owned ledger workflow, this is low priority.

## Path/API and test-meaningfulness limits

The tested empty string and root paths now fail deliberately; directory and filesystem-policy errors fail closed. A narrow API edge remains: `private_path()` accepts the result of `os.fspath()` but passes it into `pathlib.Path`; a bytes path is a valid `os.fspath` result, yet `Path(bytes)` raises `TypeError`. `read_capture()` catches only `CaptureError` and `OSError` around that conversion, so `read_capture(b"/some/path")` can escape as an uncaught `TypeError` instead of returning its partial manifest. The CLI constructs string-backed `Path` arguments, so this does not affect its ordinary path flow. Either reject bytes explicitly as `CaptureError` or normalize them with `os.fsdecode`; test the chosen contract. This is a low-severity API/error-reporting edge, not a file-reading escape.

The test suite’s full-pair fixture is now meaningful against an independent, pinned static geometry transcription, and its malformed cases exercise both reader functions and end-to-end owned framing. It still validates a generated fixture rather than a real 256K producer capture; the optional normal/partial files are only small framing cases. The tests remain unexecuted in this audit. Root should retain the CPU test receipt and source hashes when it runs them, and keep producer freshness, controller byte-ledger matching, close-error handling, the original C rejection, and full-lifecycle gates independent. A passing parser test cannot clear the numerical rejection or admit GPU/model work by itself.
