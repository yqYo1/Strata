## Concrete issues and limits

1. **Ledger integer bounds are not restricted to the actual capture budget.** `validate_ledger()` checks contiguity and `end <= size`, but callers can supply Python integers much larger than the native producer's uint64 offsets. The later file-bound checks still reject actual records, so this is not a payload allocation/read bypass; it does mean malformed ledgers are not rejected at the ledger boundary as a bounded producer ledger. Consider enforcing `0 <= begin <= end <= min(size, MAX_BYTES)` explicitly. Existing tests cover gaps, booleans, ordering, missing rows, and trailing bytes but not huge Python integers or negative offsets in each slot.
2. **CLI ledger ingestion is less hardened than capture ingestion.** `main()` follows `args.ledger` with `stat()` and `read_text()` (symlink allowed), and the size check/read are separate, so the file can be replaced/grown between them. The ledger has a 64-KiB intended cap but the read itself is not bounded. This is outside the binary parser's payload path, but conflicts with describing the CLI as bounded against an untrusted ledger. Open with no-follow, validate a regular file/size on the descriptor, and read at most 64 KiB plus one byte, or clearly constrain the ledger to trusted controller-produced input. Add symlink and oversized/race-oriented ledger cases if it is an admission boundary.
3. **Path edge failures can escape the documented error type.** `open_private('/')` reaches `parts[-1]` with an empty component list and raises `IndexError`; `read_capture()` translates only `CaptureError` and `OSError`, so CLI/API callers can get a traceback rather than a partial manifest/CaptureError. Empty or root paths should be rejected deliberately. Add a path-edge test. This is low severity and does not affect a valid capture pathname.
4. **The open-component policy is sound for the final object, with a narrow claim.** Directory descriptors pin each traversed component and every component rejects a symlink; only the final parent must be owned/private, as specified in the code docstring. It does not verify ownership/mode of every higher ancestor. That is not by itself a demonstrated race: traversal uses already-open directory descriptors and final-parent ownership is checked. Keep the report's precise claim (“no symlink in every opened component; final parent private”), rather than implying all ancestors are private.
5. **Test coverage is broad but not adversarially exhaustive.** There are useful malformed headers, lengths, padding, truncation, extra bytes, ordinal, layer/type/phase, ledger, coverage and filesystem fixtures, plus NaN/Inf/step/ID and pair comparisons. There is no deterministic mutation-during-read test; the production identity check is only tested with a stale manifest at compare time. This is a worthwhile follow-up only if root's trust boundary includes concurrent hostile writers. For the actual root workflow, orderly producer shutdown, O_EXCL freshness, and closed-file parsing remain required provenance; a reader cannot establish producer freshness itself.

The tests do test `validate_ledger()` and `validate_full_segment()` directly as well as end-to-end malformed owned streams; they do not prove a real capture's source-derived hook geometry. The full synthetic pair uses 133,495,872 bytes, correctly below the 134,217,728-byte cap by 721,856 bytes. The previously retired 133-MB fake capture remains retired with its recorded manifest; do not recreate or retain a duplicate just for this audit.
