# R169 — private IQ4_NL Down eligibility in compact layer-major prefill

Date: 2026-10-10 (Asia/Tokyo). Read-only source audit of the pinned IQ4_NL implementation worktree at the supplied HEAD `2ab09413117044d7499ac6acc6c12db404024f9d`, using R156/R160/R163 context. No implementation, build/compiler/disassembly, tests, import, GPU/device queries, profiler, model/payload access, lock, cleanup, service, or reset was performed. No runtime branch receipt was available. This establishes source eligibility, not execution, output parity, or performance.

## Decision

The new type-20 helper can execute in a layer-major call, because `run_layer_major` calls the existing `run_impl` body for each layer and each run_impl call retains the native expert dequant branch. But selecting layer-major alone does not establish that the helper runs. The helper is reached only from the per-expert direct FP16 compute arm when all of these are true: the loaded expert layout is native; the current layer's actual `f.d_type` is 20; the private build and frozen runtime opt-ins are enabled; and the expert is processed by the direct compute lambda rather than MMQ or the fused-native arm. The current MMQ plan defaults on when MMQ is built and `STRATA_PREFILL_MMQ` is absent or nonzero. Since the helper sits after `if (use_mmq) ... return` in that lambda, a normal selected layer may never call it. The source by itself does not prove that the selected model has type-20 Down layers or that any such expert was routed in a real run.

For a clean qualification path, force layer-major with `STRATA_PREFILL_LAYER_MAJOR=2`, opt in to the private helper, and set `STRATA_PREFILL_MMQ=0` before process start. This makes `mmq_plan().any` false, hence `use_mmq` and `fused_only` false and `fused_nat`/`fused_l` false; eligible native layers then flow through the direct compute branch. Still require a runtime receipt at the call site that records actual per-layer format, shape, call count, and selected arm. Do not use the file's model-level format inventory as a substitute for that receipt.

## Source path and bypasses

`Prefill::run` selects layer-major when `STRATA_PREFILL_LAYER_MAJOR=2`, or when it is `1` and `multiple` is true (`prefill.cpp:2353-2362`). For `=1`, `multiple` means `n > impl_->T` or a qualifying `STRATA_PREFILL_FIRST` split; for one-chunk requests, `=1` can fall through to ordinary run_impl. `=2` is the deterministic selector for this qualification. For `n > 0`, `run_layer_major` enforces full-model, single-GPU, compact FP16, source-present conditions; it rejects staged/split/helper/peer configurations and nonresident K/V and rejects PLE preload (`2402-2422`). It loads each layer's packed expert blobs into a temporary one-layer cache and calls `run_impl(tokens, n, pos0, err)` once for that layer (`2690-2780`); run_impl divides the full `n` into its configured chunks (`2976-2984`). Thus a 32K+ layer-major request traverses each model layer over all batched positions, with the first-chunk schedule and chunking still in effect.

Within run_impl's MoE arm, `use_mmq` is `mmq_plan().any && mmq_plan().layer[l]`; `mmq_plan()` defaults its `on` value to `mmq::built()` when `STRATA_PREFILL_MMQ` is unset, and enables MMQ on each layer whose GU and Down shapes fit (`prefill.cpp:966-993`, 4011-4022). `fused_nat`/`fused_l` can also choose native fused experts for stream-all workloads when MMQ/fused-only admission and native format support permit (`4018-4022`, 4037-4060). Both paths bypass the direct dequant call. In the expert compute lambda, the `use_mmq` branch returns before the direct arm (`4748-4797`). Only after that branch does `lay.native` select the native pack; the source then tests `m.iq4nl_down_dequant && f.d_type == 20` and calls the private helper, else the generic helper (`4799-4810`). Therefore disabling MMQ before plan initialization is the smallest source-level route to the helper; if left enabled, type-20 presence is insufficient.

`f` comes from `strata::kernels::cpu::expert_layout().fmt[l]` and supplies the actual loaded `gu_type`, `d_type`, `n_embd`, `n_ff`, `down_off` fields; `lay.native` and the `fmt` vector are selected from the installed expert source/layout, not inferred from an environment variable (`prefill.cpp:4013-4017`, 4799-4807; `iq_kernels.dp.cpp` native layout construction around 4446-4462). For a type-20 layer with the model geometry previously reviewed, the flat Down tensor has `n = f.n_embd * f.n_ff = 2560*640 = 1,638,400` values. That is 6,400 256-value groups, with 20 IQ4_NL blocks per 640-value output row; retain the corrected R163 orientation (2,560 output rows × 640 input columns). Per routed expert and chunk, the private helper dequantizes the complete matrix, not only rows assigned to that expert's routed tokens. Whether an expert is routed is determined by the current chunk's `order` built from route counts. A format/type receipt without a positive routed order/call count does not demonstrate helper use.

The private selection also needs the build option ON and runtime setting exactly `1`; init rejects enabling the env when the helper was not built and freezes the setting before run (`prefill.cpp:1058-1072`, CMake private paired target definitions near 283-288). With default OFF or runtime unset/0, the call uses the generic public helper. This does not change decode paths.

## 32K token accounting

The CLI sets `n_batched` to `n_prompt - 1` unless a positive `--prefill-until` is strictly less than `n_prompt - 1` (`generate.cpp:11703-11714`). The final prompt token is handled later by the token loop, so a prompt of exactly 32,768 tokens only contributes 32,767 batched positions. To qualify at least 32,768 prefill positions through the ordinary CLI flow, use at least 32,769 prompt tokens and a positive output budget; the CLI also requires prompt plus output to fit `--max-context` (`generate.cpp:2352-2355`). Avoid a smaller `--prefill-until`; omit it or set it at/above `n_prompt - 1`. Record the actual `n_batched` passed to `prefill.run`, not the nominal prompt length. This qualifies batched prefill occupancy but does not claim 32,768 tokens in one chunk: `m.T` may split it into chunks, and every chunk contributes to the full n count.

For an unambiguous mode selection, start a fresh process with `STRATA_PREFILL_LAYER_MAJOR=2`, the compile-time option ON, runtime `STRATA_SYCL_PREFILL_IQ4NL_DEQUANT=1`, and `STRATA_PREFILL_MMQ=0`. Retain a small diagnostic receipt from the production caller with: requested prompt length, `n_batched`, `--prefill-until`, actual mode, configured `m.T`, per-layer `lay.native`, `f.gu_type`, `f.d_type`, `f.n_embd`, `f.n_ff`, and counts for direct-private calls, generic direct calls, MMQ/fused routes, and selected expert count. For every claimed layer, show at least one private call and `n == f.n_embd*f.n_ff`; report type-20 layers with zero routed experts as eligible by layout but unexercised. Keep receipts compact and avoid retaining raw packed blobs or model payload.

## Established and unresolved

Established from source: layer-major invokes run_impl over each layer and all positions; the private caller is in that shared direct path; MMQ and fused native paths can bypass it; MMQ is default-on when built unless explicitly disabled; the private flag and type check are necessary; the model format/shape must be read from the loaded per-layer layout; and CLI prefill batches one fewer than prompt length by default.

Unresolved without runtime: whether the selected model's actual loaded layout is native and contains any type-20 Down layers; which such layers have experts selected in the actual 32K+ run; whether the flags/build are active in the root's selected binary; which arm is taken per layer; and the number of helper calls. A diagnostic receipt is required before claiming eligibility or interpreting any speed result. The no-MMQ setting intentionally routes through FP16 dequant/GEMM and therefore qualifies this helper, not the default MMQ prompt path; report the route explicitly.
