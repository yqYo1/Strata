## Actual route and CPU grouping boundary

`Verifier::run(T,...)` invokes the multi-row pool callback once per MoE layer with `T` rows and route width `K`; `expert_pool_dispatch_multi` checks `1 <= T <= cpu::MAXT` (currently 8) and `T*K <= 128`. For native packs it obtains the loaded layer format from `expert_layout().fmt[layer]`. It classifies each unique routed expert into `kind`: `0` means resident primary-GPU cache; `1` means the selected PCIe stream route; `2` means peer/helper GPU ownership; negative means CPU. The static residency table is consulted first, peer ownership next, and remote helper ownership may change a negative kind to `2`. All rows for a selected expert receive the same final kind in the supported split path.

After any remote ownership claims are applied, the callback walks `(token row t, top-k slot j)`. Every nonnegative kind is returned to the GPU/peer path and its output row is zeroed by host or GPU according to the existing copy path. Every negative kind becomes one CPU `ExpertJobMulti` per distinct expert: each subsequent row for that expert increments that job's `nt` and adds its activation/output pointers. The pool then calls `run_split_multi_native(fmt, jobs, njobs)` for native packs. The job's `nt` is the number of this window's rows for that expert owned by CPU, not `T`, not total calls in the layer, and not worker parallelism. NT1–8 can occur because `MAXT=8`; the current 22/20 capacity fixture only admits NT1–4.

The host already accumulates request-wide `multi_misses` (CPU distinct expert jobs), `multi_entries` (CPU-served route entries), `cache_hits`, `offload_entries`, `peer_entries`, and decode pool-phase timing counters. `ExpertPool::native_histogram_add` can report selected/eligible GU and Down dispatch by phase/type/NT with experts, tokens and output rows. These are useful cross-checks, but none joins pair + layer + ownership + packed bytes + job NT; GU/Down type marginals cannot be combined into the seven exact current pairs. The histogram is exposure/selected-dispatch evidence, not a time or traffic measurement. `CacheRoutePairs` V1 has layer/expert identity but no format or row token. None of these current summaries reports whether the contributing verifier rows were committed or later discarded.

## Minimal host-only fields and hook placement

Reuse or version the caller-owned `CacheRoutePairs` accumulator rather than adding a second decoder/prefill ledger. Keep the V1 evidence intact if consumers require its current wire format; a `CACHE_ROUTE_PAIRS_V2` frame is the cleanest extension. Admission should remain default-off (`STRATA_CACHE_ROUTE_PAIRS` unset/`0` by default), parse only explicit supported values, and enable only the exact documented host-side modes. Do not share its output label or receipt with the R254 prefill service ledger.

At request begin, record a request ordinal, source/build identity supplied by existing request setup, route mode (`ordinary_T1` or `verify_window`), loaded layout/format-manifest identity, geometry, actual per-layer pair map, residency snapshot, and settings relevant to ownership. Use the current existing residency snapshot check and caller-thread ownership check. Start one fixed-size window accumulator before each `ver.run`; do not allocate in dispatch. At each existing row classification increment a small owner/pair/token-index row bin. At CPU job construction retain a local fixed-size token bitmask for each just-built job (max 80 for `T<=8,K=10`) and, after `jb.nt` is finalized but before the pool call, aggregate one job into its `(loaded pair, NT, token-mask)` bin. Derive role sizes and bytes from the loaded `NativeFmt`, not from a hardcoded type table. Do not retain expert IDs in the emitted summary.

When `ver.run` returns, `generate.cpp` already computes `a` as the consecutive draft match and then clips it through `visible_output_prefix`; it commits `a+1` input rows. After this final effective `a` and immediately before/after `ver.commit(a+1,...)`, finalize the current route window with `T`, `K`, offered drafts `T-1`, accepted drafts `a`, committed input rows `a+1`, uncommitted input rows `T-(a+1)`, and actual emitted output-token count separately. The final boundary is host-known here; there is no need to copy verifier rows from device. Accumulated token masks partition each route bin at `t < a+1` versus `t >= a+1`. Label the latter “uncommitted verifier input rows”; they may result from a mismatch, output limit, EOS, or another visible-prefix stop, so do not call them all semantically rejected drafts. For mixed CPU jobs, count one whole job/call and its full packed input bytes, plus how many of that job's rows were committed and uncommitted. Do not prorate packed bytes or service time between those rows: the grouped job ran once for all `nt` rows.

If recording ordinary T=1 decode, use the same callback with `T=1`, no draft fields (`offered=accepted=0`), `commit_keep=1`, and zero uncommitted verifier input rows. Distinguish that mode from MTP verification. Current V1 admission specifically requires MTP and split spec-4, so removing that one restriction requires a separately qualified admission path. Keep pipeline, batched requests, dynamic/adaptive residency, cache admission during request, PCIe split, peer/helper GPU, multi-stage verifier and remote ownership `supported=0` until each classification and reconciliation is explicitly implemented. A frame for unsupported configuration must not be joined to CPU capacity.

## Compact output schema

Use bounded numeric records, not one line per routed row/expert. A single request summary carries:

- `META`: schema version, request ordinal, completion/error/unsupported reason, route mode, `layers=48`, `experts=512`, `T`/window histogram, `K`, actual top-k row count, window count, build/layout/format-manifest identity, relevant route settings, host-res unchanged status/fingerprint, enabled state, overflow flag, checksum.
- `WINDOW`: ordinal, `T`, `K`, offered drafts, effective accepted drafts `a`, committed input-row count `a+1`, uncommitted input-row count, emitted output-token count, verifier completion/commit status.
- `PAIR`: actual `gu_type,d_type`, layer count/identities represented, exact `n_embd,n_ff,gu_row,d_row,up_off,down_off,blob_bytes`, then owner-specific `route_rows_committed`, `route_rows_uncommitted`, `distinct_expert_calls`, and `logical_packed_bytes`.
- `JOB`: pair, owner=`cpu_native`, actual native CPU branch/build/ISA settings, `NT=1..8`, `jobs`, `routed_rows`, `committed_rows`, `uncommitted_rows`, `mixed_jobs`, `logical_packed_bytes`, and per-role GU+Up / Down logical packed byte totals. An optional fixed 256-mask histogram per pair/NT can be used internally to finalize accept-prefix counts; output the derived totals, not raw masks or IDs.
- `OWNER`: per pair and row-index bucket, resident-cache GPU, streamed-primary GPU, peer/helper GPU, CPU, and unsupported/unresolved counts. Keep distinct expert calls and logical bytes separate from route-row counts. In the presently supported single-GPU static-cache path, peer/helper and PCIe counts must be zero; if nonzero, the request is incomplete rather than silently folded into GPU hits or CPU misses.
- `RECONCILE`: per-window/layer and request totals, CPU job/entry counters cross-check, native histogram cross-check, accepted/uncommitted row partition, limits, and final `complete` bit.

For a native format the exact logical role identities are `GU+Up = 2*n_ff*gu_row`, `Down = n_embd*d_row`, `total = GU+Up+Down = blob_bytes`. Per CPU job, packed logical bytes count one expert blob once even when `nt>1`, as does source `ExpertPool::multi_bytes`; routed rows count `nt` separately. These are logical input extents, not measured L1/L2/DRAM/PCIe transactions.

## Fail-closed validation equations and admission

For every complete verifier window and every layer, require valid distinct IDs, exactly one final owner for each route row, and:

`sum_owner route_rows = T*K`.

Across all `T*K` rows, require the `(layer, expert)` loaded format to match the active native pair set and the selected owner to match the final `kind` after GPU plan and remote ownership resolution. Require per-pair kept plus uncommitted row counts to equal its route-row count. Per window, `committed_input_rows + uncommitted_input_rows = T`, offered drafts=`T-1`, effective accepted drafts=`a`, and committed input rows=`a+1`; emitted output tokens are an independent count.

For each layer's CPU jobs, require each expert occurs once, `1<=nt<=T<=8`, `sum(job.nt)=CPU route rows`, `job count=distinct CPU-owned experts`, and the pair/NT histogram agrees with `ExpertDispatch::multi_misses`, `multi_entries`, `ExpertPool::multi_bytes`, and the pool's native dispatch histogram. Each job's token mask has exactly `nt` set bits and refers only to route rows of that expert; committed plus uncommitted mask bits equal `nt`. For each pair, sum of owners' distinct calls equals the layer's distinct routed experts. `logical_packed_bytes=distinct calls*blob_bytes` by owner and pair; CPU per-role bytes sum exactly to CPU logical blob bytes. All additions/products must be overflow-checked. Require the request's actual layout manifest and host-res table remain unchanged under supported static-residency mode.

Only report `complete=1` when every window/layer callback is present exactly once, all row/job/byte/call equations pass, `T*K<=128`, `T<=8`, K and geometry match the frozen source, the request and every commit finish normally, no dispatch/source failure or cancellation occurred, output cap was not hit, no unsupported owner/branch occurred, the caller-thread ownership and residency invariants hold, and output storage stayed within its fixed budget (suggested <=1 MiB). Any missing callback, invalid ID, counter overflow, unknown type pair, duplicate/missing job, incomplete commit, source failure, changed cache residency, unsupported mode, serialization truncation, or mismatch makes the entire request `complete=0`; do not publish a partial capacity join as valid. Keep a failed but representative diagnostic only under the repo's artifact retention policy.

## Connecting counts to the decode budget and capacity

The 14.286 ms value is a whole emitted-token target budget, not a CPU service budget. On the same build and request, preserve clean uninstrumented request wall time and report it against actually emitted output tokens, `wall_ms / emitted_tokens`; separately report speculative window rows/cost exposure. Never divide by attempted verifier rows or equate offered drafts with committed output. A census request is for routing accounting; do not claim its instrumented latency as clean performance. Keep CPU host phase times (the existing `ms_plan`, `ms_actq`, `ms_jobs`, `ms_run`, and pool GU/quant/Down counters) separate from request wall time and accelerator event/phase clocks.

Join CPU service only by exact active `(gu_type,d_type)`, actual per-expert NT, H/FF and loaded packed layout/build/dispatch. Existing measured CPU capacity is only `(22,20)` at NT1–4. Other six pairs and NT5–8 receive route/exposure counts but no assigned time or capacity rate until independently qualified. Because the published service rate is per expert-token, `SUM(jobs[NT] * NT * measured_service_us_per_expert_token(pair,NT))` is the explicitly conditional serial service sum for matching qualified cells. It is not end-to-end latency because CPU jobs overlap GPU work and accepted/uncommitted rows share grouped jobs. Report full actual CPU-job cost separately from accepted-row attribution. GPU cache-hit calls, PCIe/peer calls, and any GPU-MMQ/fused branch do not consume CPU native capacity. Current supported census excludes offload/peer modes, so no GPU-work estimate is available from that frame; cache-resident row counts alone are not GPU time.

This hook does not establish physical GPU cache hit rates across unsupported mutable policies, source-file or RAM-cache misses, hardware memory traffic, GPU event critical paths, reuse distance, or kernel time by pair. It provides a bounded host route denominator and exact CPU grouped-job NT distribution for later matched capacity joins. Keep all timing/profile and device-event work out of this host-only census.
