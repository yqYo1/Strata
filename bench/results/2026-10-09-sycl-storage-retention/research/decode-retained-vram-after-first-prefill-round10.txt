What changes after the first output

The source traces around A and B quantify a real intervening capacity change. After A's temporary layer cache and temporary buffers have been freed, device free is 1,637,191,680 bytes. Before B's layer-cache allocation it is 1,062,842,368 bytes. That is a decrease of 574,349,312 bytes (about 548 MiB) between two trace points. B then lacks 300,306,432 bytes (about 287 MiB) relative to the layer-cache request.

The 548 MiB difference cannot be assigned to one allocator from this receipt. It occurs after prompt completion and decoder work, but the run has no allocation-by-allocation profiler. Source does establish that, by the first decode, the default `STRATA_WARM_GRAPHS` path calls `ver.warm()` and `mtp.warm()` after prompt processing and retains their executable graphs in the long-lived verifier and drafter (`sycl/src/program/generate.cpp:12285-12296`; verifier graph arrays in `sycl/include/strata/core/verify.hpp`; MTP graph arrays in `sycl/include/strata/core/mtp.hpp`). This is a plausible contributor, not proof that those graphs account for 548 MiB. Persistent decode graphs, MTP model weights, session/KV state and expert cache must remain available to decode. Do not describe the difference as a leak or attribute it to the streamed-KV candidate without an allocation breakdown.

There is also a separate, source-proven persistent prompt reservation. Serve owns one `Prefill sp` and initializes its owned workspace before requests; ordinary request completion does not call `sp.reset()` (`generate.cpp:6374, 6677-6784, 10119-10124`). In this candidate, the diagnostic layout reports 1,861,857,536 bytes accounted for the 8192-token compact-HC workspace, including a 1,166,147,584-byte shared phase region. These are source/accounting figures, not a measured reclaimable-VRAM delta. The prompt allocation is retained so later prompt reads can reuse it.

The MTP distinction matters. Round 6 found that `draft_kv` uses `Prefill::Impl::region`; round 7 corrected round 6's claim that it is a decode-time consumer. Active SYCL callsites invoke `draft_kv` only from the prompt `on_chunk` callbacks (`generate.cpp:7595-7604, 11700-11707`). It fills the drafter's persistent K/V state, but its batched scratch is used only during prompt chunks, and its queue is waited before callback return (`prefill.cpp:1444-1521, 1649-1655`). Keep MTP KV/state and decode weights/graphs. The temporary prompt region does not need to survive the completed prompt for decode. Round 8 already defines the safe full-object boundary: after all prompt segments/checkpoints and successful cache refill, reset the prompt `Prefill`, then lazily initialize it before a future `sp.chunk()`/`sp.run()`. This is an existing proposal, not new round-10 work.

Existing release hooks and their exact semantics

1. Main decode expert cache: the already-shipped `STRATA_PREFILL_RELEASE_CACHE=1` hook is attached only for single-GPU serve when enabled (`generate.cpp:7662-7670`). `run_layer_major` snapshots or obtains the restore bytes, waits queues, calls `Verifier::discard_cache_graphs`, shrinks the cache, and after `layer_cache.close()` grows/restores the exact payload at its prior address and calls `Verifier::rebuild_cache_graphs` (`prefill.cpp:2467-2609, 2613-2616, 2799-2807`; `verify.cpp:3832-3870`). Default release fraction is 1.0. This frees the decode cache only while prompt work runs; it is restored before `run_layer_major` returns, so it does not reduce steady decode residency.
2. MTP decode weights: `STRATA_PREFILL_RELEASE_DRAFT=1` is read during `MtpDrafter::load` (`mtp.cpp:370-375`). When enabled and supported, layer-major's suspend callback drains queues, verifies the immutable host copy if `STRATA_PREFILL_DRAFT_VERIFY=1`, drops MTP graphs, and releases the physical expert/head mappings (`mtp.cpp:212-245`). Restore remaps the same virtual addresses, copies and optionally verifies the weights before returning to decode (`:247-279`). The MTP K/V state remains. `draft()` rebuilds any missing round/step graphs through `capture_round`/`capture_step` (`:1650-1668`). The release is per prompt and restored before the layer-major call returns; it is not a post-prompt free-memory policy.
3. Prompt workspace: `Prefill::reset()` already drains pending stages and waits compute, copy, and optional KV-copy queues, stops the stager, frees `Impl::owned`, then installs a fresh `Impl` (`prefill.cpp:800-840`). Current serve uses it for failed init/chunk fallback but not a normal prompt boundary. Round 8 provides the exact lazy init/reset wiring across cache hits, prompt segments, checkpoints, and yields. This can release the persistent prompt reservation after the prompt, without preserving `draft_kv` scratch through decode. The next prompt must lazily reinitialize using current session/cache state and retained callbacks.

Prior v01402 release trials were consulted. Their main-cache full/half release and RAM/snapshot restore receipts use the same release hooks; the corresponding diagnostic sequences checked all main-state parts, first-head values, IDs/logprobs, and MTP payload. The separate layer-GPU-release receipts checked MTP payload before/after. Those were 32K v0.1.40-era runs; their correctness checks are valuable lifecycle evidence but do not qualify this v0.1.41 262K streamed-KV configuration. Their clean timings varied widely and do not establish a speed benefit. These mechanisms must not be presented as new proposals.
