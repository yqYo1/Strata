# Layer-major with streamed int8 KV: code and capacity audit (2026-10-09)

Scope: read-only inspection of `/home/yayoi/ghq/github.com/yqYo1/Strata/.worktree/sync-upstream-v0.1.41-20261009` at HEAD `23268953`, plus primary upstream/design references. No source edits, build, test, model, GPU, profiler, service, or git operation was performed. Target under discussion: Qwen3.8-Flash-Next, max context 262144, int8 KV with 32768 resident cells, B570 10 GiB. The numbers below are geometry-derived capacities, not measured performance or a guarantee that a 10 GiB device has sufficient free memory.

## Conclusion

A narrow, plausible extension is to keep the existing host-authoritative paged KV and resident 32768-cell pool unchanged, while retaining the existing full-capacity `m.stage` for only the QSA layer currently being processed by layer-major. Seed that stage from host only once at the start of the layer (only `[0,pos0)` on a resumed prompt), append each 8K chunk to both host KV and that stage as today, then reuse it across the remaining chunks of the same QSA layer. At the next QSA layer, wait for all current-layer readers, repopulate the same stage from that layer's own host prefix, and continue. This preserves token order, chunk size, and arithmetic order; it changes stage lifetime/copy frequency only. It does not remove the `kv_mode!=0` guard by itself: that guard also protects other assumptions such as PLE/cache residency, so the new branch needs explicit eligibility checks and the normal chunk-major fallback.

This proposal is not yet safe to implement without tracing stage identity/generation and queue event ownership through the outer layer loop. `m.stage` is currently a shared scratch stage, whereas host KV plus each QSA's resident-page map, pooled indexer, and dead/tail state are persistent session state. The idea relies on only one QSA layer reading the stage at a time; it must never replace the canonical page map or silently drop selected pages. It is worth prototyping only after checking device memory headroom and measuring the full 256K run on the target B570. No speed claim follows from reducing redundant copies.

## Current schedule and protected behavior

`Prefill::run` selects layer-major only for multi-chunk work when `STRATA_PREFILL_LAYER_MAJOR=1`, or when forced with `=2`, and drains before final state capture (`sycl/src/prefill/prefill.cpp:2332-2376`). `run_layer_major` currently rejects QSA `kv_mode!=0` with an explicit all-pages-resident requirement, as well as unsupported source/PLE cases (`:2399-2412`). Do not simply delete this guard.

The existing path already leases/restores the main expert cache and verifier graph, suspends/restores MTP weights, creates a temporary one-layer expert cache, and by default keeps the long residual rows in host memory (`:2418-2648`). It loads one layer's experts and runs all prompt tokens for that layer before moving on (`:2683-2768`). Thus layer-major scheduling, cache release, and MTP suspension are existing mechanisms, not proposed new work. The chunk size stays `m.T=8192`; output is written back through the layer-major row callback, so only one full residual/hyperconnection plane is needed, not an input and output plane (`:2647-2648,2683-2745`).

Current KV stream state has two different roles. Each QSA owns host backing, resident pages and a page map; `kv_stream.dp.cpp:335-414` describes/implements append and demand resolution. Host append remains authoritative, and the device resident pool is a bounded cache. Prompt QSA currently uses an identity-page-table staging pool to access arbitrary selected cells (`prefill.cpp:1198-1215,3690-3704,3919-3957`). `take_stage` allocates/reuses one shared staging plane with capacity based on the full `max_cells`, including int8 K,V and scale arrays (`:762-785`). In ordinary chunk-major execution, per-chunk prefix copy/prefetch state is local to `run_impl` (`:3147-3205`); append writes host and stage (`:3717-3748`), and the indexer appends query rows and selects exact top-k (`:3756-3795`). Layer-major calls `run_impl` one layer at a time, so the existing “prefetch next QSA” optimization does not naturally bridge its chunks; inspect/disable that overlap only inside the opt-in new branch unless ownership is deliberately redesigned.

Do not substitute decode's `kv_stream_resolve` for prompt staging without a separate capacity proof. It resolves the union of demanded pages into a finite resident slot pool (`layer.cpp:1035-1039,1311`; `kv_stream.dp.cpp:359-414`). A prompt chunk can demand more unique pages than 32768 cells can hold. Overflow or page-table `-1` behavior would risk omitting selected context, changing attention results. The current full identity stage can represent all selected cells, so retaining its semantics is the conservative route.

## Geometry and capacities

The pinned model config describes 48 layers, hidden width 2560, 24 QSA query heads, 2 KV heads, head dimension 256, max positions 262144, indexer width 128/block 4, and linear-attention dimensions 16 key heads, 48 value heads, per-head dimension 128, convolution kernel 4, and MoE intermediate width 640. `include/strata/kernels/qsa.hpp:94-116` confirms the local QSA dimensions/page size. The model's repeating attention pattern yields 12 QSA and 36 GDN layers. Treat the config as model geometry, not runtime allocation measurement.

For int8 KV, each cell stores K and V codes for 2 heads × 256 features plus per-group scales (group size 64): `2 × 2 × 256 = 1024` code bytes and 32 scale bytes, or **1056 bytes/cell**. This agrees with the page allocation and append code (`layer.cpp:737-779,904-949`; `kv_stream.dp.cpp:335-343`). With page size four:

- One QSA layer, full 262144-cell host backing: **276,824,064 B = 264 MiB**.
- Twelve host-authoritative QSA backings: **3,321,888,768 B = 3.09375 GiB**, plus small alignment/metadata.
- One QSA layer, 32768-cell resident cache: **34,603,008 B = 33 MiB**.
- Twelve resident caches: **396 MiB** total (about 0.387 GiB), plus page maps (3 MiB total).
- One full-context staging plane for the active QSA layer: **264 MiB**, reused serially; not twelve stages. `take_stage` already sizes for one full-context plane. Do not allocate another per-layer stage.

All twelve QSA pooled indexer arrays remain live in the session: `(262144/4 + 2) × 128 × 4` bytes each, about **32 MiB per layer**, **384 MiB total**, plus dead/tail/block-position state. They encode prior context required by sparse selection; freeing them between layers would require explicit host checkpoint and exact restore, which is outside the minimal proposal. RoPE cos/sin at 262144 positions and 64 rotary dimensions is about **64 MiB shared** (`session.cpp:70-73`; QSA use in `layer.cpp:775,954-966`). These are not stage KV.

The layer-major residual has four hyperconnection streams: `D=2560×4=10240` floats/token (`prefill.cpp:112`). At 262144 rows the single host plane is **10,737,418,240 B = 10 GiB**. This is required by the current all-token layer-major schedule and is larger than the KV backing; host-RAM feasibility must include it and other host allocations. At 8192 rows, that plane's chunk slice is 320 MiB. Existing per-chunk scratch is reused and remains independent of context length. For scale, known PLE gather staging uses two 8192×2560 float host buffers (160 MiB total) and one device buffer (80 MiB), plus row IDs (`prefill.cpp:1174-1197,1380,2916-2929`). PLE preload remains forbidden by the current guard. The temporary expert-cache size is `n_expert × MAXBLOB()` (`:2612-2616`); its exact target value depends on loaded model metadata and is not inferred here.

The resulting simultaneous lifetime is: **all 12 host KV states live; all 12 bounded resident caches and QSA indexers live; exactly one full-context QSA staging plane live; one 10-GiB host residual plane live; per-chunk scratch reused; one temporary expert layer cache live.** GDN recurrence/conv and PLE history stay in their existing session states. For the stated geometry, GDN recurrent state is 128×48×128 floats = 3 MiB per GDN layer (about 108 MiB across 36) before convolution history. No state should be freed just because the scheduler has advanced to another layer.

## Minimal additional specification

1. Add an opt-in streamed-KV layer-major eligibility path; keep existing fallback for any unsupported QSA mode, multi-GPU/source format, PLE preload, missing stage, or insufficient capacity. Keep `max_cells`, the 8192-token chunk, routing, and math ordering unchanged.
2. Give the single stage explicit owner `{session generation, QSA ordinal}` and `valid_cells`. Before a QSA layer's first chunk, wait until previous stage readers/copies are complete, establish identity mapping for that layer, and copy exactly the prior host prefix `[0,pos0)` once when resuming. For a fresh prompt (`pos0=0`) do not copy an empty prefix. In every chunk, append the current QSA's K/V to host authority and the owned stage before attention; advance `valid_cells` only after append completion. Before next QSA ownership, drain all consumers and invalidate the old owner. Do not treat the resident page map as the staging identity map.
3. Make queue/event ownership explicit. Existing `kv_ready`/`kv_released`/`kv_pending` are tied to chunk-local `run_impl` flow (`prefill.cpp:3147-3205`). A persistent stage owner cannot outlive its copy event accidentally or let a later layer overwrite memory before earlier QSA attention completes. The outer layer loop already drains compute/copy/stager queues before each layer (`:2683-2685`), but verify that drain includes every async append and stage copy used by the new path. Disable the overlapping next-QSA prefetch for this mode unless its event and owner state are redesigned together.
4. Preserve QSA indexer, dead/tail and pooled-row append exactly; sparse top-k and identity-pool semantics must match chunk-major reference. Keep host K/V as source of truth for checkpoint, snapshot, and decode. Existing final state capture includes K/V, GDN/conv, PLE, and indexer state (`:2346-2376`). Preserve cache-lease and MTP restore behavior after the final layer so decode-plan graph/state sees the normal session allocations.
5. Add counters/trace for owner, valid prefix, bytes copied, page validity, and queue waits. Do not silently claim a performance benefit; compare end-to-end wall time and copy bytes on the target card after correctness.

## Boundaries and validation

With capacity 262144, valid cell indices are 0 through 262143; an extent/count of 262144 is the full state length. Test both a 262144-cell prompt (last append at 262143) and a 262143-cell prompt followed by a generated token at position 262143. Save/restore at count 262144 must preserve all QSA pages, pooled indexer/tail, GDN recurrence/conv, and PLE history. A subsequent append at position 262144 exceeds this configured capacity and must remain rejected. Exercise state dump comparison already available at `prefill.cpp:2346-2376` against chunk-major baseline, including page-boundary tails and resumed `pos0>0`.

Validation sequence after implementation (not run here): one QSA layer, short context with int8 stream and a chunk boundary; one layer at 32K and just over 32K to verify resident eviction/page resolution; full 256K all-layer prefill with 8K chunks and state dump; resumed prefix; save/restore at 262143 and 262144 counts; then decode-plan graph capture and a next token where capacity permits. Compare logits and all serialized state against the unchanged chunk-major path, inspect memory peak and stage owner/copy counters, then measure end-to-end prefill on B570. A standalone timing of the stage copy is insufficient.

## Related work: what transfers and what does not

- Strata's existing staged expert loading and per-layer cache lease already solve weight residency; they do not make streamed QSA KV/indexer state layer-local. Existing `prefill-code-audit-addendum.txt` documents the staged expert ring; do not re-propose it.
- SGLang HiCache uses a GPU/host storage hierarchy for reusable KV blocks and overlaps tier transfers. This is useful precedent for explicit ownership and event sequencing, but it is a prefix-cache/offload design, not this single-active-QSA full prompt staging plane: https://docs.sglang.ai/advanced_features/hicache_design.html
- vLLM KV offloading likewise tiers KV blocks to CPU for cache reuse; it does not establish correctness for Strata's sparse indexer and per-chunk QSA attention: https://docs.vllm.ai/en/latest/features/kv_offloading.html
- vLLM Ascend's layerwise/sparse KV cache offload is an NPU-specific capacity strategy; useful for buffer-lifetime concepts, not a B570 performance reference: https://docs.vllm.ai/projects/ascend/en/v0.26.0rc1/user_guide/feature_guide/layerwise_and_sparse_kv_cache_offloading.html
- AirLLM streams model weights layer by layer and does not address this model's paged KV/indexer/attention contract: https://github.com/hmzainjamil/airllm
- S-MoE layer-major prefill and the Anemll Flash-MoE sidecar notes are architecture-specific demonstrations, not evidence for this QSA stream path or target hardware: https://docs.s-moe.com/v1/internals/layer-major-prefill and https://github.com/Anemll/anemll-flash-llama.cpp/blob/master/docs/flashmoe-layer-major-dedup-single-sidecar.md
