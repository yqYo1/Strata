## Conclusion and corrected history

For the target single-GPU `--no-prefill-borrow` serve path, the existing prompt `Prefill` object can be reset after the request's entire prompt-read phase has finished, then initialized lazily immediately before a later request actually uses the batched `sp.run` path. No `Prefill` scratch is used by decode: round 7 corrected round 6's mistaken claim that `draft_kv` is a decode consumer. The MTP K/V state that `draft_kv` fills is persistent session state and must remain; its temporary inputs are only needed during prompt callbacks.

The safest narrow insertion point is after the outer prompt-segment loop has completed and `refill(err)` has succeeded (`generate.cpp:10283-10330`), just after prompt timing has been recorded and before `REUSED`/the first verify window (`:10331-10340`). This is after all `sp.run` parts and checkpoint captures for this request, but before decode. Keep reset conditional on a `prompt_paths_ready` flag so the no-read/cache-hit case is a no-op. In `read_part`, call an `ensure_prompt_paths()` before reading `sp.chunk()` or calling `sp.run` (`:10119-10125`). This ensures an uninitialized `Impl` is never queried for its chunk length and avoids allocation for requests whose fresh text is handled entirely by decode windows.

`Prefill::reset()` is already the supported reusable teardown: public docs say it frees buffers/streams/events, starts empty so `init()` can run again, and preserves stage range and callbacks (`include/strata/prefill/prefill.hpp:69-74`). It waits/drains in `release()` and replaces `Impl` (`prefill.cpp:797-840`). This is not a proposal to clear only `m.region` or to keep a decode scratch arena: current SYCL code has no decode consumer. It is also not permission to discard session/cache/verifier state.

## Actual serve setup and call sequence

The serve-local `Prefill sp` is constructed near `generate.cpp:6374`. The initializer lambda `init_prompt_paths` is defined once at `:6677`; for one GPU it initializes `sp` with the current model geometry, live `SessionState`, `ExpertSource`, expert cache/residency table, chunk size and caller queue (`:6695-6696`). Startup currently calls it eagerly in the fallback loop at `:6761-6784`. The serve callbacks are attached after initialization and before the request loop: MTP suspend/restore and `sp.on_chunk` at about `:7585-7604`; the callback selects `draft_kv` or falls back to `mtp.prefill`. `sp.should_stop` is attached later at `:8280`. All of these are public `Prefill` members, retained across `reset()` by the header contract.

The prompt reader decides each segment independently. `windows_ok(a,b)` routes sufficiently short text through `read_windows`, unless checkpoint reread or image rows force the batched path (`generate.cpp:9797-9810`). Such a `read_windows` segment does not call `sp.run`; only `read_part` does (`:10119-10124`, called at `:10291-10293`). Therefore lazy allocation belongs at the start of `read_part`, after determining that a segment is batched. The batched loop may split a segment at `sp.chunk()` boundaries and run batch decode between chunks (`:10121-10208`); do not reset from inside this loop.

After all segments, the outer loop refills any lent expert slots, logs “prompt done”, captures prompt timing and prints `REUSED`; only then does it start the verify-window/decode loop (`:10329-10343`). That is the complete-prompt boundary. An optional state dump configured by `STRATA_PREFILL_DUMP_STATE` is written inside `Prefill::run` before it returns (`prefill.cpp:2332-2376`). Turn/root/message checkpoints are saved inside the segment loop after the corresponding `sp.run`/window read (`generate.cpp:10317-10330`). Reset after the loop preserves both. The later `STRATA_STATE_HASH` reads session-owned main and MTP state after decode (`:11307-11435`); it does not read Prefill buffers.

## Concrete minimum call contract

A target-only wiring can keep `init_prompt_paths` and its current step-down fallback but expose a readiness wrapper:

1. At startup, perform the existing non-mutating sizing/loan planning and chunk-fit policy. For `--no-prefill-borrow`, `pf_borrow` is false (`generate.cpp:3383`) and no `PfPart` loan is planned (`:6428+`); this target passes `borrow=nullptr`/zero bytes into `sp.init`. Do not recreate cache loans or change the 128-slot reserve policy.
2. Before any `sp.run`, `ensure_prompt_paths()` checks `prompt_paths_ready`. If false, call the existing init lambda. Re-run its chunk-step fallback on “do not fit”: reset every partially initialized Prefill path, set the next permitted chunk, clear the sticky error and retry exactly as current startup does (`:6761-6784`). Mark ready only after all active paths and any required helper setup succeed. Since this task is single GPU, this is just `sp`; keeping the existing all-stage helper is useful for other configurations but must not be half-initialized.
3. In `read_part`, call ensure before computing `C=max(sp.chunk(),1)` and before `sp.run`. Do not initialize on a `read_windows`-only request. If a request has both paths, initialize only when its first batched segment is reached; keep the same arena across all subsequent batched pieces and windows for that prompt.
4. After the segment loop finishes, after successful `refill(err)` and all checkpoint callbacks have returned, record `prompt_ms`, then `sp.reset()` if ready and set readiness false. This occurs for normal completion and the graceful cancel/yield path after its `sp.run` has returned and the outer loop has copied/parked state and refilled slots. Do not reset when `sp.run` returns a fatal error and the server is leaving; do not suppress wait errors or free memory after a failed drain. For the generic borrowed case, refilling/returning loans must happen before reset; the target itself has no loan.
5. Leave `sp.on_chunk`, `sp.should_stop`, `sp.on_decode_suspend/restore`, and other wrapper callbacks attached across reset; they remain the same callable objects. The request-scoped `cur` token vector is updated before reading (`:9535`); the MTP callback captures the serve-scope `cur` by reference and uses the current positions. Ensure the captured objects outlive every subsequent `sp.run`; if callbacks are reconstructed instead, reinstall the exact current callback before marking ready.
6. After reset, leave `SessionState`, MTP QSA K/V, QSA page tables/indexers/tail/dead state, GDN and convolution state, PLE history, RoPE, expert cache/residency map, MTP weights, and verifier/decode graphs untouched. `Prefill::release()` waits prefill-owned compute/copy/KV-copy and tears down stager/events/queues; it is not a server/model teardown (`prefill.cpp:806-840`).

The serve loop receives `SAVE`/`RESTORE` only between requests (`generate.cpp:9086-9300`). After a completed request, the scratch is already reset; save uses the live token/checkpoint view plus session/KV/MTP state, while restore writes the supplied image back into those persistent session objects. The next `GEN` decides whether to reuse a live prefix, checkpoint, parked conversation, slot source, or restored session (`:9535-9710`) before it reaches the reader. If a prompt read is required, lazy initialization sees the active `ss` and current expert residency. A full cache hit or restore followed by no fresh batched segment leaves Prefill uninitialized and decode proceeds using the already-restored persistent state.

## Edge cases and guards

- **Cache hit / tokenwise short read:** No `sp.run` means no Prefill init. Keep `read_windows` as-is. If only a later segment crosses `req_short_read` or has image rows, lazy-init at the first `read_part` call. Do not call `sp.chunk()` before init.
- **8192 chunking / `--batch`:** `read_part`'s `C` comes from initialized `sp.chunk()`. Preserve the existing 8192 chunk geometry and its per-request split behavior. Requests with batch decode interleaved between chunks retain the same Prefill allocation until the full request's prompt segment loop ends; no reset at each successful `sp.run`.
- **BYIELD:** A successful yield copies the processed prefix to a batch slot, marks it partial, and returns `false` with `yielded_at` (`:10165-10203`). The outer code treats it as cancellation, refills, and emits the parked slot after prompt completion. Reset only after this outer handling. The resumed request restores/copies the parked `SessionState`, resumes at `slot_tokens`, then lazy-inits before the next batched segment; never keep old `Prefill` pointers into the parked session.
- **STOP/cancel:** `should_stop` is checked by Prefill and window reads. The graceful path sets `cancelled`, refills and reports the number actually read (`:10300-10330`, `:11400+`). Reset after that path's successful retirement, not at the callback's cancellation point. The partially read live session is deliberately not marked reusable (`:11303-11308`); existing checkpoints remain valid because they were captured before reset. On fatal queue/device error, do not attempt a “recovery” reset and then continue; the error path terminates the request/server.
- **SAVE/RESTORE:** Commands are handled before a GEN request, between requests. `SAVE` requires a complete `live_ok` session, and `RESTORE` validates/transfers into session/MTP K/V (`:9150-9297`). Those routines don't depend on Prefill scratch. A `STRATA_PREFILL_DUMP_STATE` write is inside `sp.run`, so it completes before the outer reset. Do not move reset into `on_chunk`, before checkpoint creation, or before a diagnostic dump.
- **Chunk-init fallback:** Current startup may reset all prompt paths after a failed `init`, try `6144,4096,3072,2048,1536,1024,512`, and clear the error (`:6700-6784`). Reuse the same retry semantics for a lazy allocation. Do not mark ready after one stage has initialized but another failed. With target `--prefill 8192`, preserve the selected 8192 chunk when it fits; no test here establishes whether the target's later allocations always fit.
- **Expert-cache ownership:** The target `--no-prefill-borrow` means owned buffers, not a cache loan. Keep the same expert-cache object and `host_res` table alive; pass their current addresses/values on every new `init`. Existing adaptive/refill operations mutate residency contents, not the lifetime of the Prefill pointer. If generalized to a borrowing configuration, first refill the returned slots and restore `host_res` mappings, then reset; cache-slot contents are not owned scratch.
- **Layer-major/cache release:** Existing `run_layer_major` cache lease, MTP decode-weight suspend/restore and graph refresh callbacks are synchronous parts of `Prefill::run` and restore on its completed path (layer-major round-3 report; `prefill.cpp:2418-2609,2747-2810`). Reset belongs after `run` returns, after cache/weights/graphs have been restored. It must not replace or alter these existing leases.
- **Callbacks and external references:** `reset()` preserves callback members and `set_stage` state, but recreates `Impl`. `set_peer`/stage helper own implementation-side buffers and must be reapplied after each lazy init when enabled; `set_cpu_pool` is a wrapper member. Target single GPU/no peer avoids this extra setup. Do not assume all `Prefill` metadata lives in the `Impl` or that reinitializing means only calling `init` in multi-stage mode.

## What remains separate, and what not to claim

The round-7 finding remains: `draft_kv` is prompt-only; retain MTP K/V, not its scratch. `init_prompt_paths` currently runs once at serve startup (`:6761`) and `sp.run` is reused across requests (`:10119-10124`), so reset alone is incomplete unless `read_part` can lazily re-init. The public API already supplies the reset/re-init capability; no new `release_decode_scratch` API or separate MTP arena is indicated by current callsites.

Layer-major streamed KV and expert-major routing are separate algorithmic proposals. Their respective 264 MiB stage and 25 GiB route-contribution estimates are not part of the 2116 MiB Prefill allocation. Do not resurrect blanket expert-cache resizing, do not remove QSA streamed-KV guards, and do not attribute a faster decode to this change without target measurements. Releasing prefill-owned USM may make memory available to the runtime/cache, but the source audit cannot prove all 2116 MiB becomes visible free VRAM or that decode rate changes.
