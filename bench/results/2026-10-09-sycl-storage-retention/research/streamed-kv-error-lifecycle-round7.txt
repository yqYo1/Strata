Findings

1. Error and cancellation cleanup has a real exception-safety hole in the new streamed path. `KvDrain::~KvDrain` calls `stream->wait()` and then `retained_compute->wait()` without catching exceptions (`prefill.cpp:2915-2924`). In streamed mode the second pointer is `m.cs`; an enqueue/runtime error can be surfaced by these waits while unwinding an earlier `return false` or SYCL exception. Destructors are implicitly `noexcept`, so such a wait exception terminates the process and prevents `run_layer_major`'s outer `std::exception` handler and `Restore` cleanup from running. The outer `Restore::~Restore` likewise performs `m.cs->wait()`, `m.copy->wait()`, `m.stager->finish()` and, for retained mode, `m.kv_copy->wait()` without a catch before restoring callback/cache/residual pointers (`2688-2702`). The ordinary path already had a `KvDrain` wait, but the retained compute wait and retained-mode queue drain expand this hazard on the new path. Cancellation (`should_stop`, `prefill.cpp:327x`) normally reaches ordinary `false` returns and drains successfully; backend/async failure during that drain is the problematic case. Suggested qualification: inject/induce a compute-queue failure at a QSA append/attention and a copy-queue failure during layer transfer, then verify the API returns an error, queues retire, callback/context pointers restore, and process remains alive. If queue `wait()` may throw, make cleanup drains catch and preserve the primary error, while ensuring pointer/state restoration runs even after a drain failure.

2. The ordinary success-path wait correction is coherent by inspection: retained compute drain is initialized for streamed mode, then nulled only after the existing successful `m.cs->wait()` at `5330-5334`. Earlier `false` returns retain the fallback. Layer-major's destructor waits the compute queue before local stage ownership and temporary layer cache disappear. This is structurally sound when queue waits succeed.

3. Resume-prefix seeding handles the requested positive boundaries correctly by arithmetic inspection (`3762-3793`). It copies `floor(p0/4)` full pages, then for a nonzero tail copies exactly `tail` code rows and the corresponding `tail * (head_dim/64)` uint16 scales per K/V head. Thus p0=1,2,3 seed valid cells in page 0; p0=32767 copies 8191 pages and three valid cells in page 8191; p0=262143 copies 65535 pages and three cells in final page 65535. The append starts at p0 and extends the scheduled extent to p0+T, preserving earlier tail cells. p0=262144 is accepted only for n=0; `run_layer_major` returns to `run_impl` before streamed admission when n<=0 (`2385-2387`), while positive n is rejected by capacity subtraction (`2422-2424`). The no-op boundary therefore needs an explicit test to confirm it leaves all KV/indexer state untouched. For positive resume cases, verify host authority, resident page mapping, indexer state, and staged QSA attention agree; code inspection alone cannot establish page-map/runtime behavior.

4. Stale next-QSA prefetch is addressed in order: `run_layer_major` waits any existing `m.kv_copy` before changing the scoped mode (`2708-2711`), and `run_impl` sets `kv_prefetch = kv_prefetch_on && !retained_stage` (`2870-2877`). Therefore streamed one-layer invocations do not schedule another QSA into the shared stage plane. The mode is restored on normal completion before decode restoration callbacks (`2790-2795`) and in the scope guard on return/cancellation (`2693-2702`). The old queue is drained before mode switch; no stale prefetch window was apparent.

5. Scope admission matches the storage assumptions in the edited code: every allocated QSA must match primary geometry, use plain streamed INT8, have host/device pools and page table, and fit 262144 cells; full-model QSA ownership and an in-order compute queue are required (`2413-2443`). A one-layer `StageOwner` validates ordinal and contiguous extent before each staged chunk (`2884-2895`, `3762-3768`). Session carve order (`qsa_ord0 == 0`, full QSA count) agrees with ordinal counting. Default opt-in-free behavior remains: streamed states fail admission with the existing resident-only error; all-resident states continue into the same layer-major body, with `layer_major_streamed_kv=false`, unchanged QSA prefetch behavior and no identity-stage seeding. This is a static path comparison, not a measured equivalence claim.

6. Borrowed cache, graph, MTP and callbacks: the temporary expert cache is declared before the `Restore` guard, so the guard drains queues and restores `m.cache`, residency, transfer context, residual pointers, callbacks and `stage_lb_/stage_le_` before the cache object is destroyed. Cache/decode leases are established before this guard and unwind afterward, allowing callbacks to rebuild decode resources after the temporary cache closes on success. `ple_prev` is restored before each layer invocation, and callback state is retained/restored. Remaining qualification should cover cancellation after cache suspension and after an intermediate layer, plus failures in `on_stage_chunk` / final `on_chunk`; existing lease destructors deliberately terminate if cache/decode backing cannot be restored, so test those paths to ensure no stale graph points at released storage.
