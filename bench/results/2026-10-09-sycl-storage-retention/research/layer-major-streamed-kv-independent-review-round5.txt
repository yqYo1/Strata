## Review result

The code's partial-page seed offsets, separation between streamed identity stage and resident page mapping, per-layer QSA ordinal handling, and queue ordering are internally consistent for the explicitly admitted geometry. I found one concrete performance/synchronization issue beyond the already reported zero-QSA default bug: the new `KvDrain` adds an unconditional extra compute-queue wait on every one-layer `run_impl`, including successful completion where `run_impl` has already waited that same queue. Root should fix or explicitly measure this before treating the patch as an optimization. I did not find another clear out-of-bounds or page-table correctness defect in the reviewed paths. Source inspection does not prove runtime correctness, allocation fit, or speed.

## Concrete issue: redundant compute wait on every layer

`run_impl` already waits the compute queue in its normal completion path at `sycl/src/prefill/prefill.cpp:5212`; it then separately waits `m.copy` at `:5231`. The patch's new `KvDrain` sets `retained_compute = m.cs` for every retained-stage layer invocation and its destructor unconditionally calls `retained_compute->wait()` (`:2915-2924`). Layer-major calls `run_impl` once per model layer (`:2683-2685`, `:2785`), so this is an additional compute queue wait after the normal end wait for each of the model's 48 per-layer invocations, not only for QSA layers. The original `KvDrain` already waited its selected prefetch/default queue; the `retained_compute` wait is new.

The wait is needed if an early return/error/cancellation occurs before the end wait, but not after the successful `run_impl` fence. Track whether the compute queue has already been drained and only perform this fallback wait on incomplete/error paths, or have root measure this extra wait explicitly against the quiet baseline. Do not remove error-path drainage. Also note that `run_layer_major::Restore` already waits `m.cs`, `m.copy` and Stager when its scope exits (`:2693-2704`), and existing per-layer boundaries wait queues at `:2685`, `:2707`; this is additional to those fences. No throughput or latency result was measured here.

## Layout and dataflow checks

The partial-prefix seed uses `pages = p0 / page_size` and `tail = p0 % page_size` (`prefill.cpp:3771-3792`). `kv_stage_from_host` copies complete blocks of each of the four INT8 arrays using `runs_of`, whose block lengths are `n_head_kv * page_size * head_dim` for codes and `n_head_kv * page_size * (head_dim / 64) * 2` bytes for scales (`sycl/src/kernels/cuda/kv_stream.dp.cpp:39-60,456-470`). The partial copy offsets compute the row as `(page * n_head_kv + head) * page_size`, then byte-offset codes by `row * head_dim` and scale elements by `row * head_dim/64`. This matches the kernel address arithmetic `[page][kv_head][cell][feature]` / `[page][kv_head][cell][scale group]` in `sycl/src/prefill/kernels.dp.cpp:1967-2022`, including uint16 scale byte counts. At `head_dim=256`, `n_head_kv=2`, the reported `1056 * p0` seed bytes equal those four arrays' valid prefix payload. Full pages plus a nonempty tail cover `[0,p0)` without copying invalid cells. `p0=0` enqueues no seed; first append writes the prefix before attention reads it.

Resident and staging page layouts are kept distinct. `kv_append_kernel` addresses the resident arrays through `table[pos/page_size]`, but writes the host authority and optional staging arrays through identity `row_id` (`kernels.dp.cpp:1967-2022`). The new path calls normal `kv_append` with `st.page_table` and `&m.stage` (`prefill.cpp:3842-3844`); prefill's identity table is separately allocated/initialized from primary `n_pages` (`:1200-1217`). Attention selects `pools_of(m.stage,m.ident_table)` for mode-1 state (existing path around `:4028-4054`), so it does not accidentally treat resident ring/stream page mappings as identity. `kv_stream_resolve` later uses the real resident map/page table and authoritative host arrays (`sycl/src/core/layer.cpp:1035-1039`). The copied prefix is rebuilt for every QSA layer because the stage is shared scratch, while each QSA's host arrays remain authoritative.

The streamed append is submitted on `m.cs`; the guard requires that queue to have the in-order property (`prefill.cpp:2436-2444`). Seed `memcpy`s, append kernel, and following QSA selection/attention are enqueued on that same queue (`:3775-3859`, `:4053-4065`), so the identity-stage prefix/appends are ordered before attention without new event waits. Queue property and pointer admission checks appear before the layer-major cache/MTP suspension and before this routine changes per-layer callbacks/state (`:2406-2455`, then setup). This ordering check is important because the code relies on it.

`StageOwner` is local to a `run_impl` call (`:2877-2895`). The invocation must cover exactly one layer, computes QSA ordinal by counting preceding QSA layers, checks the expected ordinal and contiguous enqueue extent before seeding/appending (`:3765-3769`), and advances the scheduled extent only after enqueue (`:3850-3855`). `run_impl` also initializes QSA/GDN ordinals from `LB` (`:3218-3219`) before using the layer's state at `:3743`, consistent with this count. This model has 12 QSA and 36 GDN layers; the outer loop still visits every model layer, while GDN and PLE state paths remain the existing per-layer logic.

## Ownership, queue cleanup and source-specific failure semantics

The existing layer-load sequence waits copy/compute/Stager before preparing the next expert layer, issues that layer's copies, then waits `m.copy` and Stager at `:2683-2707`. `Restore` drains the compute/copy queues and Stager on ordinary return or unwinding (`:2693-2704`). The new `KvDrain` is constructed before the retained-stage operation and has an added retained compute queue fallback for return/error/cancellation (`:2915-2924`). The layer-major path has no next stage/helper/peer/hand-in admission (`:2398-2402`), reducing concurrent writers. For ordinary `run_impl` failure, `Prefill::run` calls `drain_pipeline`, which is not itself the queue fence; the new local KvDrain must remain responsible for the retained compute queue. `Restore` then provides an outer safety drain before scratch/cache cleanup.

A nuance for runtime error handling: queue `wait()` calls inside destructors may throw depending on SYCL asynchronous error delivery. The existing `KvDrain`/`Restore` destructors already wait queues; the patch adds `m.kv_copy->wait()` in `Restore` only when retained mode is still active (`:2694-2697`). There is no recoverable error test in this static review. Existing migrated helper paths can terminate on SYCL failures; don't claim that queue drainage makes every failure recoverable or that cache/session state can be reused after a device fault.

The new mode drains any existing ordinary `kv_copy` queue before setting the mode (`:2708-2710`), disables next-QSA prefix prefetch while retained mode is active (`:2870-2876`), and outer cleanup drains `kv_copy` on retained-mode error. Since no new prefetch is launched during the mode, the successful path's later explicit reset of the bool before callback restoration (`:2793-2796`) is safe if the entry drain succeeded. This needs an error-path test with `STRATA_KV_PREFETCH=1` first used in an ordinary run, then layer-major retained mode, as well as cancellation/error after seed and after append.

`conversation_kv_restore` restores the canonical host K/V and resets the streamed resident map (`sycl/src/core/conversation_snapshot.cpp:217-235`). The next layer-major run reseeds its temporary identity stage from that restored host prefix; the stage is scratch and is correctly absent from the saved conversation. SAVE/RESTORE or in-memory prefix resume therefore should not require serializing StageOwner/stage contents. This is a static dataflow conclusion, not a tested SAVE/RESTORE result. The actual serve SAVE/RESTORE caller is in `sycl/src/program/generate.cpp` around `:9086+`; resumed prefill and standard CLI prompt call sites must be exercised because a restored prefix can end in a partial page.

## Boundary and state-preservation implications

Admission uses short-circuit checks to bound positive `max_cells` to 262144 before `max_cells + 3`, checks `pos0` and then compares `n > max_cells - pos0` rather than overflowing `pos0+n` (`prefill.cpp:2419-2426`). `run_impl` also checks each `p0,T` against `st.max_cells` using subtraction (`:3765-3769`). For the target's four-cell pages, `n_pages == (max_cells+3)/4`; the explicit head geometry check fixes the scale layout assumptions. At `max_cells=262144`, `262143` is a one-cell final tail and `262144` is all full pages. `262145` is rejected at admission. A prefill stage test ending at each of these positions is still needed; in `generate.cpp` ordinary prompt prefill can stop at `n_prompt-1` before the last prompt token is consumed by the token path, so distinguish the Prefill direct boundary from end-to-end prompt/decode boundary.

The patch does not mutate QSA indexer arrays, resident maps, GDN recurrence/conv state, or PLE history beyond existing computations. `Restore` snapshots only layer-major callback/cache/residual settings plus the prior mode bit (`:2687-2707`), not SessionState; no new SessionState mutation is made outside normal append. Cache release/restore and verifier graph callbacks remain existing paths (`:2800-2810`), and the MTP suspend/restore callbacks remain attached by generate (`:11691-11706`); the opt-in checks are before these side effects. The already-known primary-QSA dereference/default hazard in this diff is excluded from this report because root has identified it and plans to fix it. Do not mark the current hash accepted until that correction is re-reviewed.
