## SYCL completion points

`Prefill::init` creates `m.copy` as an owned **in-order** SYCL queue (`sycl/src/prefill/prefill.cpp:1109-1112`; factory implementation `sycl/include/dpct/device.hpp:623-635`). `ExpertTransferTimer::copy` returns the event from `q->memcpy` (`prefill.cpp:2198-2219`). Expert H2D copies use this queue, and the per-slot `m.copied` barriers record dependency on it (`:3327-3352`, threaded issuer `:3397-3422`, routed-only `:4609-4644`). Thus the existing `m.copy->wait()` at normal `run_impl` completion (`:5231-5242`) is a genuine retirement point for all preceding source reads on that in-order queue. The copy is into `m.stage_dev` (stream path) or the layer's device cache; compute consumes the destination, so source-arena retirement need only follow completion of the H2D copy.

The current baseline described in the request (`STRATA_PREFILL_RING8`) has `m.ring == STAGE == 8`; `stream_all` is exactly `m.ring > STAGE && T >= stream_all_min() && m.src != nullptr` (`:3210`), so this disables the stream-all walk regardless of chunk size. `ring_slots()` explicitly maps `STRATA_PREFILL_RING=STAGE` to routed-only staging (`:208-240`). In this routed-only path, the routed layer builds Stager jobs and `stage_one` issues copies while traversing that layer (`:4576-4597`, `:4598-4644`); there is no unconditional `m.copy->wait()` between layers. Existing event/barrier use protects ring destinations and compute dependencies; it does not retire the arena source range. The next general fence is the chunk's `m.copy->wait()` at `:5231`.

The stream-all path also has only chunk-end retirement; its issuer is joined at `:3377-3381`, but `StagerDone` calls only `finish()` (`:3315-3318`). `Stager::issued_one` records a copy event for host staging-buffer reuse and `buffer_free` queries its true completion (`:518-536`); this is not a fence for an arbitrary arena range and does not establish that all source copies are complete. The direct-copy events in `ExpertTransferTimer` are retained only when timing is enabled; the queue wait is the unconditional normal completion point.

The exceptional path matters. `run()` calls `run_impl`, then `drain_pipeline`, which joins/settles the successor pipeline but does not wait `m.copy` (`:2332-2345`). In `run_impl`, `KvDrain` drains `m.kv_copy` or the global in-order queue, not `m.copy` (`:2849-2853`). `IssuerJoin` and `StagerDone` settle host threads/jobs only. Many early returns and exceptions can occur before the normal copy-queue wait; a caller that returns an error cannot release a source lease based on `run()` returning. `Prefill::release()` does wait the copy queue at `:806-818` before resetting the stager and destroying events/queues (`:820-838`); `reset()` calls release first (`:800-804`), and the destructor calls release (`:797-798`). A lease therefore must stay owned/quarantined until successful `copy->wait_and_throw()` on this cleanup path. The current release implementation propagates queue wait exceptions; do not release the import in a destructor if queue wait failed.

## Where bounded lifetime is and is not sufficient

For the active routed-only/chunk-major path, a single fixed stable source interval can be prepared before a `run_impl` call, used only for copies within that interval, and released after the existing chunk-end `m.copy->wait()`. This establishes a sound bounded **one-interval-per-run_impl** lifetime without an added wait. A fixed layer span is a possible scope if the interval is page-aligned/rounded according to the import API and all matching copies are routed through it. Other spans must remain on the current Stager path. This does not justify preparing/releasing as the issuer advances from one layer to another: routed-only staging has no per-layer copy-queue completion. Nor does it justify a separate interval for every expert. For the streamed-KV model-wide path, repeated per-layer leases in ordinary chunk-major execution therefore remain unsupported under the no-new-wait constraint; importing the entire arena instead is not a bounded substitute.

There is a separate, existing layer-major path with a stronger candidate boundary. It queues the current layer's expert copies, then calls `m.copy->wait(); m.stager->finish()` at `:2703-2708` before computing that layer. Its scope guard `Restore` also waits `m.cs` and `m.copy` and finishes the stager on every exit (`:2652-2667`), so an in-flight layer lease could be retired during ordinary success or unwinding/error. A per-layer bounded lease could therefore cover the full current layer's stable expert span and retire at `:2707`, with the guard as cleanup. However, this path explicitly refuses noncompact/multistage/source-ineligible configurations (`:2398-2402`) and requires `kv_mode == 0` (`:2404-2405`); it does not currently provide a layer-major completion scheme for the streamed-KV (`kv_mode == 1`) target. Do not transfer this candidate to streamed-KV unless that guard/path changes and its queue semantics are reviewed.

## Arena, source and import support

The SYCL `PinnedArena` constructor reserves ordinary mmap/VirtualAlloc memory and documents that SYCL cannot register that existing host range as host USM (`sycl/src/core/pinned.dp.cpp:353-369`). Destruction's former `cudaHostUnregister` operations are literal no-ops (`:377-400`). Correspondingly `ArenaExpertSource`'s current address alias only becomes populated when `registered_bytes > 0` (`sycl/src/core/expert_source.cpp:3544-3565`); this port's no-op path does not establish a device-accessible imported alias. A proposed UR import is a different API and has not been integrated here. No `prepare_for_device_copy`, `release_from_device_copy`, or native copy-only factory use was found in the required SYCL paths.

`ArenaExpertSource::open` reserves and fills the arena synchronously, and the source is assigned at `generate.cpp:4066-4069`, `:4133-4159`. Deferred registration exists only in the Windows branch (`expert_source.cpp:3447-3456`); Linux hardcodes `deferred = false` (`:3451-3452`). The deferred thread (if enabled on Windows) starts at `:3483-3495` and is joined before open completes at `:3503`. This SYCL `PinnedArena` does not provide actual host registration anyway. File/route prefetch and `--stream-experts` worker paths are separate and may materialize/copy data; they do not establish import readiness for the arena pointer.

In serve, the persistent `Prefill sp` is constructed after `arena_src` (`generate.cpp:6374` vs source at `:4066`), so normal reverse destruction releases Prefill before the arena object. One-shot `Prefill prefill` is also constructed after the source at `:11636`. Explicitly ensure any lease is retired before source `close()`/destruction (`expert_source.cpp:3316`, `:3579-3593`). SAVE/RESTORE is a between-request command (`generate.cpp:9086 onward`); restore uses synchronous snapshot transfer and resumes the loop, while no prefill import is active after a successful `run_impl` queue wait. It does not repair the failed-prefill case: if the serve loop proceeds after a failed `run()` without resetting/releasing Prefill, an active lease must remain quarantined. Locate this failure handling at the caller before adopting an implementation.

## Host task/event mechanisms and runtime status

`sycl/include/strata/event_completion.hpp:11-45` is CPU-side bookkeeping that retains a `sycl::event` and queries command completion; the active Stager uses it at `prefill.cpp:371`, `:518-536`. It neither synchronizes a whole queue nor proves completion for other source ranges. `sycl/include/strata/host_completion.hpp:7-25` provides an in-order host-task acknowledgement helper, but it is not used by this prefill path. Introducing it to release an import would add an async queue command/lifetime path not present in the baseline; this audit does not establish that calling UR release from that host task is supported. No native copy-only factory exists in the active files; `m.copy` is the normal in-order profiling/nonprofiling queue factory. Do not restore per-copy `wait()` calls or invent such a factory as part of this audit.

The installed L0 v2 `0.12.0` binary and 2026.1 matching-source/provenance and import-support behavior remain unverified, as in round 3. The declared API or a success path alone is insufficient evidence. Keep runtime-supported import and unsupported/fallback semantics on hold until the exact binary's source provenance and import/release implementation are established. Existing PinnedArena no-op, range-overlap UB and v1 silent-success findings from prior reports remain applicable; they do not prove v2 behavior.

## Corrected decision

The CUDA round-3 claim that `src/prefill/prefill.cpp:3991` supplied an adequate retirement point is withdrawn for SYCL. On the actual SYCL path, the analogous valid normal-return fence is `sycl/src/prefill/prefill.cpp:5231` (`m.copy->wait()`); it supports a single bounded interval held for the whole `run_impl` chunk, not multiple sequential layer-range leases within that chunk. Per-layer turnover is possible only in the separate layer-major route at `:2707`, whose current `kv_mode == 0` guard excludes streamed KV. Error cleanup is safe only if lease ownership persists until `Prefill::release()`'s successful `m.copy->wait_and_throw()` (`:816-818`) or layer-major `Restore` scope guard (`:2659-2660`). Therefore a useful all-layer bounded import design for the active streamed-KV routed-only path is **not established** without a new completion mechanism or a redesigned path, both outside this request's constraints. Single-interval-per-chunk may be a narrow experiment, but exact runtime support/provenance and caller failure behavior must first be confirmed.
