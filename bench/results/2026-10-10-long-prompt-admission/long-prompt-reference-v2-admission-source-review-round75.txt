## Blocking valid-run denial: compile_commands is not the Strata TU source list

`source_closure()` reads only `<build>/compile_commands.json`, passes that JSON to `admission.compile_paths()`, and then requires the resulting project set to contain `src/kernels/cpu/native_expert.cpp`. The pinned file in the frozen build directory has SHA-256 `836656f71cd8dfbf13844ea8f808d2ebc9993f66c65b7548755fb63dee21b8d6`; the file inspected here has 26 entries, all external GGML translation units. It contains no Strata project TU. Therefore `compile_paths()` returns `project=[]` and raises `ValueError('actual production native source path')` before source-closure admission can succeed, before the output directory is made, and before any GPU/model work. This is a deterministic fail-closed refusal of the valid reviewed build, not a hypothetical malformed-input issue.

The exact pinned `build.ninja` has SHA-256 `44d5c41881ea9ea4e5f1c9c38f5be1883c39acd6840071f6914ad7a45c769274` and contains the Strata object edges. The SYCL CMake source resolver also establishes the correct native source: CMake explicitly adds `src/kernels/cpu/native_expert.cpp` from the project root, and `sycl/src/kernels/cpu/native_expert.cpp` is absent. The v2 literal fixture fabricates a compile-command list containing that root TU, so it exercises the path check but not the actual pinned `compile_commands.json` or the actual `strata` target graph. This is why the pure fixture does not catch the admission blocker.

A correction must derive the project translation units from the actual `strata` target edges in the pinned Ninja graph (or a separately pinned, independently extracted target manifest) and use `compile_commands.json` for the GGML entries it actually contains. Do not scrape every edge in `build.ninja` as the target closure: that generated file also declares auxiliary/test targets. A graph parser/query must follow only the executable's transitive object/archive/link dependencies. The existing source resolution must retain the path mapping and the absent-SYCL-override assertion.

## False-accept gap: `.inl` dependencies are outside the conservative suffix set

`CODE_SUFFIXES` in the helper omits `.inl` (and also `.ipp`/`.tpp`). Yet compiled CPU code includes tracked `.inl` files: root `src/kernels/cpu/iq_avx2.cpp` includes `iq_avx2_rows.inl`, and root `src/kernels/cpu/q2_avx2.cpp` includes `q2_avx2_rows.inl`. The actual SYCL IQ-AVX2 source is a wrapper that includes the root `iq_avx2.cpp`; its nested quoted include resolves the `.inl` beside that root file. These paths are real compiled dependencies, not hypothetical suffixes.

`conservative_inputs()` adds tracked paths only when they match its suffix list or are named `CMakeLists.txt`. `validate_closure()` checks the content hashes for that resulting set and merely requires that the reported changed-file paths do not intersect it. It does not reject unclassified code changes. Consequently, a build-to-current change to a tracked `src/kernels/cpu/iq_avx2_rows.inl` or `q2_avx2_rows.inl` is classified as noncompiled and can pass this closure gate even though it changes a compiled TU's contents. The same omission applies to applicable `.ipp`/`.tpp` include files. This is a possible false acceptance; I did not run Git to claim any of these files changed between the reviewed commits.

The robust fix is to compare the complete dependency-file closure for each object in the `strata` target, including all project and GGML headers regardless of suffix, plus generated include/source inputs. If using a conservative tracked-file superset instead, include all active include suffixes (at least `.inl`, `.ipp`, `.tpp`) and fail closed on any changed code/header/CMake-like path not explicitly classified. Pin the graph/dependency manifest and compare every relevant build-commit blob with current content. Merely adding `.inl` without validating target graph and generated dependencies would not resolve the first blocker or prove the full closure.
