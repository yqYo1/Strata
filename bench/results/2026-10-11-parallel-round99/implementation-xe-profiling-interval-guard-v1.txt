Current event/helper behavior and change
gpu::event_record uses submit_profiling_tag for timing events; non-timing events
may use the measured barrier policy. event_elapsed_ms reads both events'
command_end timestamps, as before. Timing-mark placement, queue factory and
Runtime selection are untouched. The current Runtime constructs in-order
queues; this review does not transplant the old DPCT enable_profiling assertion
or invent a new timestamp-domain admission contract for profiling tags.

The old helper subtracted unsigned b-a and then cast the result to int64_t.
It now checks b<a before subtracting. On reversal it returns false and stores
the exact decimal raw endpoints in thread-local last_error:
  event_elapsed_ms: end < start (start=<raw a>, end=<raw b>)
The failed interval does not write the caller's ms output. There is no clamp,
repair, wrap correction, host-clock substitution, offset, retry or sample reuse.
On ordered endpoints, convert the unsigned difference directly to double/float
milliseconds, removing the unnecessary signed reinterpretation. Equal endpoints
remain valid zero. No arbitrary duration ceiling or plausibility tolerance is
introduced. Existing unrecorded/not-created-for-timing/query-exception failures
remain false results with their existing last_error information.

This is necessary timestamp-order validation, not proof of equal clock domains,
counter width, profiling-tag semantics, timer resolution, actual device interval,
phase coverage or independent elapsed-time correctness. An ordered but implausible
interval is not certified by this check. Float conversion and existing accumulation
precision are unchanged; no model arithmetic changed.

PfTimer fail-closed propagation
PfTimer::fold no longer conditionally drops a failed sample. It uses the existing
publication::require contract for each event_elapsed_ms result, with operation
"prefill phase timer interval", then adds only a successful sample.
An unrecorded event, timing/query failure or reversed pair raises the existing
runtime_error path. Prefill::run catches it and returns false with err containing
the operation and underlying error (including raw endpoints for a reversal):
  prefill: prefill phase timer interval: event_elapsed_ms: end < start (...)
The current run's final phase timeline/percentages are not emitted. Earlier
successful intervals may exist only in the local accumulator, which is discarded
on that failed run; they do not become an apparently complete current phase report.
The caller/observer must retain the failed request/run status. Serving need not
terminate its process merely because a completed request's measurement failed;
no request success or authoritative current timeline is returned by Prefill::run.

Presence semantics remain: TIMING absent disables PfTimer, while
STRATA_PREFILL_TIMING=0 still enables it. Disabled mark/fold paths return at the
same guards and do not create markers or query elapsed intervals. This patch adds
no wait per mark, per interval, or normal kernel launch and changes no phase labels,
mark placement, successful accumulation, inference scheduling, tensors, kernel
selection, cache, context or MTP logic. Independent event consumers may still use
profiling during automatic CPU-share measurement/startup probes; TIMING absence
does not imply the entire program never uses an event timer.

Completion and ownership reasoning
Both PfTimer folds already follow successful checked compute-stream completion:
the MoE routing boundary uses publication::cleanup_require(stream_sync), and
the final fold follows stream_sync success. A timestamp check is not used as a
completion fence. No failed wait is relabeled as completion.

At an inner fold failure, existing IssuerJoin cancels/joins the producer, then
drains compute/copy queues; StagerDone cancels, drains and finishes the stager
before the run-local PfTimer/event cleanup. The existing function catch drains
both member queues again before returning false. At the final fold, chunk guards
have completed, the next-stage future has been joined, and the compute markers
have completed before any elapsed query or event destruction. The existing
publication cleanup contract flushes a diagnostic and _Exit(74) if completion
cannot be confirmed, before buffer release. Those guards/policies were not edited.
These are source ordering conclusions, not a new asynchronous-fault injection
or driver completion guarantee.

All event_elapsed_ms consumers reviewed
1. PfTimer::fold: hardened as above, current primary target.
2. session_replay_stages_per_layer/session_replay_stages, stage_sweep and
   stage_prefixes: previously ignored false and returned success with initialized
   zero durations. Added small bool/error propagation in session.cpp. Each query
   occurs after its existing successful checked stream_sync. A failure now returns
   false with the actual last_error, instead of authorizing a zero-duration sample.
   Sweep saves the error before destroying its two completed events. The other
   methods retain their existing RAII cleanup. generate's --gpu-stages consumers
   already check these bool returns and abort with the error, so no caller/API
   signature or default generation path changed. Previously printed successful
   sections in a multi-section diagnostic do not make its later failing run valid.
   Existing prefix-difference arithmetic is untouched; this does not validate
   negative/uncertain differences between separately measured prefix totals.
3. Prefill's automatic CPU-sharing feedback: the existing conditional query skips
   its adaptive update on false. New rejected reversed timestamps therefore do not
   enter that update. Keep this existing policy/selection fallback unchanged;
   it is not an emitted authoritative phase timeline or a successful sample claim.
4. generate probe_pcie_h2d_gbps: existing ok chain rejects a failed interval and
   returns its failure sentinel; no change needed for this new bool failure.
5. Legacy layer stage_timing_report: still skips failed queries, and its complete-
   wait result/expected-versus-unrecorded slots need a separate diagnostic receipt
   design. It is not hardened or qualified by this patch. Treat it as unsuitable
   for authoritative phase attribution until its sample/failure ledger is fixed.
6. Legacy --hw-bench bench_copy_gbps: still picks surviving successful intervals
   if another query fails. It needs whole-arm failure accounting before using it
   as independent validated transfer/performance evidence. Its existing submission/
   completion/failure cleanup also deserves its own audit. No benchmark/default
   runtime-selection policy or broader lifecycle redesign was added here.

Items 5 and 6 are explicit remaining measurement limitations, not claims that
all timer consumers now fail closed or that any existing output is validated.
The additional session change is confined to callers which unconditionally
expect every elapsed interval and already expose bool/err propagation. Optional
