## Source-level coverage of the full physical extent

The opt-in parser requires exact 262,144 input IDs and max-context, max-new zero, native/MTP, spec at least two, a fixed positive prefill chunk, no borrowing, and a positive draft window below capacity; it refuses serve/batch/split/remote/pipeline and CLI dump/benchmark/ablation modes. It forces `STRATA_MTP_PREFILL_SYNC=1` before the first MTP prefill call (`generate.cpp:2457-2479)). Later checks require a native pack and vocabulary-valid IDs including the explicit terminal probe ID (`generate.cpp:2861-2864,3922-3927)). The probe itself requires exact main and draft capacities, a whole-session layer carve, an MTP resident ring, and `first_needed()==0` (`generate.cpp:1237-1249)); MTP prompt length is set to zero in this mode (`generate.cpp:3887-3893`). These source guards prevent the ordinary lookback optimization from silently leaving the early draft cells uncomputed.

The target call is `prefill.run(o.tokens.data(), 262144, 0, err)`. The actual `Prefill::run` iterates chunks while `c0<n`, runs the layer work for each chunk, increments `stats.tokens` only after the chunk's layer work/stager completion, then synchronizes the target compute stream before invoking `on_chunk` (`prefill.cpp:1202-1208,1455,1591-1632,2338-2352,2408-2418)). The QSA append/indexer calls use `T,p0` for each chunk. Thus the source executes target prefill rows covering [0,262144), rather than merely allocating a full-sized state. There is no independent per-layer append counter, so a future receipt's token/chunk count is not a direct device-side count of successful writes for every layer.

For the MTP callback, the helper requires a gapless next chunk, validates the full successor range before indexing, and maps cells 0..262142 to input ID cell+1 while mapping cell 262143 to the explicit terminal ID (`full_context_probe.hpp:21-49)). It calls synchronous `mtp.prefill(...,true)` and additionally synchronizes the MTP stream before advancing coverage (`generate.cpp:1307-1323)). The MTP prefill validates `cell0+n<=st_.max_cells`, uses `first_needed()==0`, stages each group and checks completion before reusing mapped records (`mtp.cpp:1057-1067,1139-1161)). The final row's position is 262143 and its exclusive step is 262144, which is representable; there is no cell 262144 read or appended. Coverage requires exactly 262143 real successors plus one terminal probe and a matching full prefill token/chunk count (`generate.cpp:1324-1341); it does not ascribe prediction semantics to the terminal row.

This is meaningful source evidence that both target prefill and draft K/V prefill are issued across the full logical extent. A real GPU receipt is still needed to show the run actually completed.

## Capture, poison, and restore extent

The capture view uses the full ID vector, no images/checkpoints, and normal PLE state. Before capture, the probe estimates the snapshot plus two checkpoint-sized budgets and a 1 MiB reserve, rejects overflow/unknown/insufficient memory, and repeats admission just before allocating the snapshot (`generate.cpp:1251-1296,1345-1351)). Snapshot sizing uses production layout/payload sizing; `ConversationBuffer::allocation_peak` accounts for segmented payload and directory growth (`conversation_state.cpp:221-245,248-270`; `conversation_buffer.hpp:48-63)). At 262144, the probe checks each saved image has exactly that extent and that its pages match the state's full page count (`generate.cpp:1357-1369)). The snapshot layout rounds to page size; this explicit equality rejects an extent/page combination that did not cover the exact physical context (`conversation_snapshot.cpp:24-30,33-76)).

Poison writes every captured authoritative K/V/index byte in bounded 64 KiB transfers. For streamed main states the authoritative target is the full host copy; for the MTP ring it also overwrites every physical resident slot with the correctly bounded page-bytes times slot-count extent, not the full logical extent (`generate.cpp:1168-1219)). The production negative verifier requires the exact byte-mismatch result for each state. Production snapshot restore writes all authoritative payloads, resets streamed main residency or refills the draft ring from its host copy, and restores the running checkpoint (`conversation_snapshot.cpp:207-225,367-377)). The post-restore verifier compares every authoritative payload byte and, for the draft ring, each resident page in the current ring window (`conversation_snapshot.cpp:259-299)); the probe also requires identical before/after fingerprints (`generate.cpp:1381-1402)). Ring refill's page-to-slot mapping is `page % n_slots` (`kv_stream.cpp:245-266)), matching the diagnostic verifier's slot mapping.

Running-state checkpoint fields include GDN state, PLE history, indexer tails/dead rows/block positions, while main K/V snapshot includes pooled indexer rows (`conversation_state.cpp:131-165,180-218)). The probe complements each saved running vector, restores through the production checkpoint routine, and then compares each restored vector and the last two PLE IDs (`generate.cpp:1371-1375,1404-1409)). The probe does not poison/capture a full-span residual tensor: residuals are temporary per-chunk buffers, consumed by MTP prefill before coverage advances. Its byte-exact round-trip claim is for authoritative K/V/index state and the named running-state vectors, not every transient residual byte. No later inference is performed to turn restored state into a numerical-equivalence check.

## Admission, error lifetime, and concrete limits

The RAM gate is conservative for the intended host process: required bytes include the production snapshot allocation estimate, two checkpoint budgets, a 1 MiB reserve, and a remaining-free-RAM floor of at least 2.5 GiB; availability is checked before prefill and again before capture. Allocation failures are caught by the outer diagnostic branch and end the process without inference. The probe does not allocate a second full K/V tensor on VRAM: snapshot buffers are host-side, copies reuse existing pools, and restore repopulates the already allocated ring. Main session, MTP ring and prefill buffers are allocated by normal startup before entering the probe. There is no probe-specific VRAM peak forecast or reported free-VRAM-before/after measurement; without a GPU run, actual allocation headroom remains unknown.

One conditional admission gap is explicit in the source: `conversation_available_memory()` reads Linux `/proc/meminfo`, and its API documents host MemAvailable rather than container/job reservation (`conversation_memory.cpp:32-38`; `conversation_memory.hpp:12-22`). If the probe is run inside a cgroup/job with a tighter memory limit, host MemAvailable may overstate usable process memory and the large capture can still trigger OOM. Before running in such a constrained environment, either make the telemetry cgroup-aware or refuse when the effective job limit is lower than the required allocation. This is not a blocker for an unconstrained host-memory run.

A second environment-dependent artifact risk is not covered by the CLI guard: `Prefill::run` honors debug environment variables such as `STRATA_PREFILL_DUMP_R_ALL` (writes all chunk residuals) and `STRATA_QSA_DUMP` (writes selected-cell traces), plus diagnostic allocation/check paths such as `STRATA_IDX_FP16_CHECK` (`prefill.cpp:1672-1717,1719-1734,2385-2405)). The CLI rejects its dump options but the probe parser does not refuse these environment variables. Since the current environment was not queried, I cannot say whether they are set. For the authorized physical run, Main should explicitly unset and record them, or a future source guard should reject them in probe mode; otherwise the run could write large artifacts or alter peak resource use without appearing in the CLI arguments.

Drain ordering is source-consistent: callback-local drain is destroyed before its successor vector; poison drain before its workspace; run-level drain before snapshot/checkpoint buffers; main-scope guard also covers prefill initialization/MTP bind exits. An unconfirmed device sync terminates rather than releasing possibly referenced storage (`generate.cpp:1159-1165,1181-1219,1255-1264,1307-1323)). Failure/partial restore returns nonzero and the diagnostic branch exits before verifier/sampler or later inference (`generate.cpp:10108-10109,10161-10169)). The poison test itself mutates live state; failure is deliberately terminal and does not attempt best-effort recovery after a failed restore.

## Evidence not established by these checks

A successful source path, helper tests and free build do not prove numerical correctness at position 262143, every target layer's emitted payload, correct attention/RoPE behavior at the final position, a physically resident full main state, or successful full-state restore on the target driver. The before/after FNV-1a values are corruption summaries, not cryptographic identity; exact bytewise comparisons do verify restore against the bytes just captured, but that captured image is not an independent numerical oracle. Input/model/tokenizer/shard/source/compiler/runtime/device/driver hashes and IDs need an external SHA-256-bound receipt. The final draft row is a storage-only probe, not a generated token or model-quality sample.
