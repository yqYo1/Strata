Oracle and tolerance:
  Each actual 16-bit input is decoded by independent IEEE exponent/significand arithmetic into double,
  without the production BF16/FP16 converters or SYCL half. Reference computes the unpadded dense
  X[T,K] * W[N,K]^T independently. It never copies production tile logic, DP4a blocks/scales/integer
  dot products, or output padding decisions. Input patterns contain signed zeros and varied signed
  normals (nonzero magnitudes within FP16's normal range), so production BF16-through-FP16 conversion
  is exact for these BF16 values; subnormal and saturation behavior is deliberately outside this fixture.
  NaN/Inf oracle and GPU output are failures. Every output has a fixed a-priori FP32 bound:
    1e-6 + gamma * sum(abs(products) + abs(beta1_initial)),
    u=2^-24, gamma=4*(2*K+8)*u/(1-(2*K+8)*u).
  Production DP4a requantizes inputs to int8, so that path cannot honestly use FP32-roundoff-only
  tolerance against the exact dense oracle. If the hardware-derived own path could use DP4a for a
  nonaccumulating eligible shape, add a conservative nearest-rounding envelope using full-row maxima:
    ex=max(abs(Xrow))*(1/254+8*u), ew=max(abs(Wrow))*(1/254+8*u),
    Q=ex*sum(abs(Wrow))+ew*sum(abs(Xrow))+K*ex*ew;
    limit=1e-6+gamma*(absolute_products+Q)+Q.
  Full-row maxima bound each block without simulating blocks. The accumulating DP4a dispatch uses
  gemm_rows, so beta=1 retains the FP32-only bound. Thresholds are never tuned to observed errors.
  Changed-input references are required to differ outside the sum of both tolerance envelopes in at
  least one output, making the repeated data observably capable of rejecting stale output.
  Per-call stdout records max absolute error, relative error with 1e-6 denominator floor, RMSE,
  maximum error/limit, full checked count, beta, dimensions, repetition and mismatch count.
