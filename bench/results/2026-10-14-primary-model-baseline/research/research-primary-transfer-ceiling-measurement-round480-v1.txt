# R480 — primary SYCL transfer ceiling measurement design

Date: 2026-10-14 (Asia/Tokyo). Read-only measurement design for the primary Strata SYCL implementation at `0f4ce392` on Arc B570 10 GiB / Ryzen 5 5600X / 128 GiB RAM. Requested current question: attainable host/device transfer ceiling, distinguishing large copies from the actual small expert-copy shape, and separating submission cost from transfer completion. No build, test, GPU/runtime execution, profiler, process/service query, model payload read, Git operation or source mutation was performed. This report is the only write. I did not read the prohibited `B/prefill-gemm-only-contract-root-v1/record.json`.

## Conclusion

A fresh probe should be a small standalone executable linked to the exact Strata SYCL runtime and CUDA-compat layer, run later in a separately scheduled quiet window. It should report two different facts: (1) isolated large-copy rates for Host-USM and ordinary pageable host buffers in each direction, and (2) the cost and end-to-end completion of the real per-expert copy shape, using the exact layer byte extents from loaded pack metadata. Report both host enqueue-to-completion time and device-event interval. Do not compress them into one “PCIe bandwidth” number.

The existing `probe_pcie_h2d_gbps()` is intentionally an optimistic H2D selector: one 256 MiB Host-USM allocation, one warm-up, four consecutive same-default-stream copies, and the fastest of four event intervals. In this SYCL port, compat `cudaEventRecord` submits a barrier and `cudaEventElapsedTime` subtracts `command_end` timestamps. The interval is therefore between ordered stream barriers, after final event completion; it does not include all caller-visible setup/host wait time. Taking the maximum suppresses burst disturbance and is useful as a best attained anchor, but it does not describe small-copy latency, D2H, pageable staging, per-call host overhead, source diversity, or production overlap. It cannot stand in for a current model run’s transfer rate.

## Proposed bounded experiment

Use one helper executable initialized through the production `Runtime`, `cudaMalloc`/`cudaMallocHost`, `cudaMemcpyAsync`, stream and event compatibility calls, and `cudaFree` APIs. Record source revision and binary hash, compiler/runtime/driver/device identity, exact selected context/device, allocation kind, byte count, command count, queue/stream identity, and whether queue profiling is enabled. Runtime source currently creates profiling queues (`src/sycl/runtime.cpp:70-85`); compat event elapsed time waits for the end event and reads its SYCL profiling `command_end` (`src/sycl/compat.cpp:364-427`).

Bound the data to a 256 MiB host and device allocation for the large lane, plus a fixed-size corpus of expert slots for the small lane. Allocate both pinned and pageable host variants; test H2D and D2H independently. Fault in pageable pages and initialize the source before timing. Warm the context and copy engine, then synchronize before each measured group. Do not include allocation, first touch, pattern generation, correctness scan, logging or cleanup in a transfer interval. Keep ordinary pageable memory genuinely ordinary host allocation; do not silently substitute host-USM on allocation failure. Record a failed allocation as unavailable.

For each direction/allocation class, retain every individual sample, not only the fastest. Alternate pinned/pageable and H2D/D2H order to reduce thermal/clock drift. Include a cold-after-quiet start and a warmed group, and record active link state only if a passive, non-invasive platform source exposes it during the run; a prior idle sysfs speed/width reading is not a ceiling. Include the existing four-burst/256 MiB/fastest statistic as a comparable output, while also reporting median and full sample range. A single 1 GiB burst or a single maximum is not sufficient evidence of repeatable current ceiling.

For the small lane, obtain exact per-layer `blob_bytes(layer)` values from the pack/layout metadata after normal model metadata initialization, without reading expert payloads. Report the set/range and use representative lower, median, upper and maximum layer extents; if the current layer sizes are uniform, preserve that one exact size. Exercise a rotating corpus (at least one full layer's expert slots when feasible) so each command uses a distinct host source and device destination extent, rather than repeatedly reading one tiny buffer that may remain in cache. Copy only the exact blob length; do not pad to a max-slot allocation. Use exact production expert counts only if the selected pack's metadata supplies them. This avoids inventing an expert-size proxy and does not require model-weight contents.

Measure three distinct views for the small lane:

1. **Single-copy completion:** one copy, then wait on its completion event. Capture host wall from just before enqueue through event synchronization, device event interval, and enqueue-call wall separately. This shows fixed submission/retirement cost at the real size.
2. **Same-stream batch completion:** enqueue 1, 8, 32, then a bounded full-layer count of exact-size copies without per-copy waits; record API-call total and per-call distribution, event-to-event device interval for the batch, and host wall through final completion. Report payload bytes divided by each applicable interval only as batch effective rate. This approximates a queued layer upload while retaining per-copy calls.
3. **Production call shape:** if production uses a staging source (Stager or pageable fallback), include a separate host preparation/copy-into-pinned-slot cost, then H2D, with bytes and host time for each stage. Never label this combined time a raw link rate. The existing 8-slot ring and same-queue dependency policy can inform the bounded batch only where the benchmark can preserve its actual number of outstanding source slots and event reuse rules; do not claim overlap unless separate queues and measured concurrent execution are explicitly tested.

Keep warm-up and all data verification outside timed windows. For H2D, initialize a deterministic byte pattern in each host slot, perform the timed copies, wait, then verify the destination bytes in a separate D2H/readback pass. For D2H, initialize device buffers before timing, copy to host, wait, and verify the host bytes afterwards. Put distinct sentinels/canaries before and after each active extent; verify every copy extent, all corpus slots, and all guards. Report a failed/partial transfer as failure, not as a low bandwidth sample. Retain a compact per-sample CSV/JSON with bytes, host enqueue duration, host completion wall, device interval, API count, allocation class, direction, slot count, correctness and canary status.

Run under a finite deadline and small bounded log budget. Avoid tracing/profiling layers that intercept each API call for the speed samples; the compatibility timing events are sufficient for the device-command intervals, and a separate diagnostic run can inspect API behavior if required. Do not run alongside model inference, build, test, cleanup or another GPU workload. Since the parent reports an active model/GPU job, schedule this only after that job is finished and its GPU slot is released; no action against it is part of this design.

## Interpretation limits and distortions

- A 256 MiB copy is large enough to amortize fixed dispatch cost; it measures a bulk-transfer regime, not the service time of thousands of expert-sized copies. The small lane must preserve the actual per-expert extents and count.
- A single stream with all copies enqueued before a final wait measures queued batch throughput and queue service under that submission pattern. It hides per-copy synchronization and can let host submission run ahead. The one-copy lane exposes the fixed completion path. Report both.
- Device event intervals omit host work before submission and can understate caller latency. Host enqueue-to-completion includes runtime/API cost and wait, but can be distorted by timer overhead, scheduling and a slow submitter. Capture enqueue-only, event interval, and completion wall separately.
- Back-to-back barriers/events can add scheduling and profiling overhead, especially for tiny copies. Use the same event strategy across arms, amortize timing over batches, and keep small-copy singletons as latency results rather than claiming precise bus utilization. An empty barrier/control batch can quantify queue/event overhead, but subtract it only as an explicitly labeled diagnostic, never as a corrected measured transfer time.
- Reusing one source/destination repeatedly gives cache-friendly behavior and can overstate production. Rotate through distinct expert slots; still state that generated data and a synthetic corpus do not reproduce actual file-backed source latency, source NUMA placement, CPU staging, cache pressure or model overlap.
- Pageable SYCL `queue::memcpy` can involve runtime/driver staging. A pageable result is an API-path result; it does not reveal whether staging is internal, nor should an extra host memcpy be added to that rate.
- Host-USM eligibility and concurrency are device/runtime contracts, not implied by a fast isolated copy. Host-USM measurements do not authorize overlapping host/device accesses to the same allocation. Distinguish allocation kinds, and do not mix arbitrary registered mappings with `malloc_host` results.
- A queued batch on one same-order queue has dependencies by construction. It cannot show copy/compute overlap or independent queue-engine capability. Separate queues alone also do not prove overlap. If overlap is later a question, measure a separate copy-plus-kernel experiment with explicit event edges and report both standalone and combined wall intervals.
- The source probe's four-burst maximum deliberately avoids persistent disturbances, but can select an unusually favorable burst. Preserve all four values and show the selector result alongside the distribution; do not call the maximum a sustained guarantee.
- Timing around only `cudaMemcpyAsync` enqueue would mostly measure host call overhead, not completion. Conversely, synchronizing after every copy answers serial latency, not queued production throughput. Both views matter.

## Implication for current 4K/8K prompt tuning

The requested configuration context is native model, cache 128, int8 KV resident 32,768, context 262,144, prefill 4,096, no-borrow, ring 8, same-queue enabled, exact MMQ, tile 8, compact enabled and pack disabled. A new large H2D result can bound only how quickly a sufficiently large contiguous payload moves in an isolated transfer. The small-copy results can establish whether per-expert submission/retirement is material at this pack's real layer sizes and whether batch queueing amortizes it. This can help decide whether a 4K/8K layer-major or staging schedule is plausibly transfer-limited versus CPU/API-limited.

It does not establish that these prompt settings actually send that payload over PCIe, which directions or counts are on the critical path, whether copies overlap GEMM/attention, or whether another schedule wins. Preserve current ring-8/same-queue controls during a later matched model run; any 4K/8K conclusion requires model-run bytes, per-stage host and event timings, actual queue dependencies, correctness, and matched prompt wall samples. Do not multiply an isolated ceiling by estimated expert bytes and call the result predicted prefill time.

## Primary sources

- Current source `src/program/generate.cpp:1024-1092`: the four 256 MiB H2D bursts, warm-up, event brackets, max selector, and its intended interpretation.
- Current source `src/sycl/compat.cpp:231-268, 306-427`: Host-USM mapping for `cudaMallocHost`, arbitrary host-register rejection, queue memcpy, barriers for event record, and event elapsed using SYCL event `command_end` values.
- Current source `src/sycl/runtime.cpp:70-85`: runtime queue profiling property.
- Khronos, [SYCL 2020 Specification revision 12](https://registry.khronos.org/SYCL/specs/sycl-2020/html/sycl-2020.html): queue `memcpy` returns a completion event; USM pointer/context/accessibility constraints and queue profiling. This supports using the actual runtime event for copy completion, not assuming host enqueue means transfer completion.
- Intel, [Level Zero Core Programming Guide](https://oneapi-src.github.io/level-zero-spec/level-zero/latest/core/PROG.html): command lists and events express ordering; submitted independent work or different queues do not by themselves guarantee simultaneous execution.
- Intel, [Level Zero Command List API](https://oneapi-src.github.io/level-zero-spec/level-zero/latest/core/api/apis/command_list-2.html): copy-offload hint is only a hint and may be ignored, so it cannot substitute for device measurement.
