# R482 — bounded primary layer-major reuse splice contract

Sole upstream is Niko1221/Strata; Xe is an optional architecture reference. CUDA/HIP is outside scope. No build, test, runtime/model, GPU, profiler, payload read, or Git mutation was performed. Only this requested report was written. The active unchanged primary `bench.sh` run was not inspected or disturbed. I did not open the prohibited B record.

## Decision

A bounded layer-major *reuse* splice is source-level feasible only as a separately gated, opportunistic execution path with a complete fallback to current chunk-major `Prefill::run`. It must not lower `max_context`, shorten a prompt, or change KV precision to fit. For this PC, a full-GPU residual bridge is not a plausible general design: at primary geometry `hc=4`, `n_embd=2560`, each retained FP32 residual row is 10,240 floats = 40 KiB/token. A layer-major pass needs the prior layer's rows for all prompt positions while the next layer is computed. That bridge alone is 2,684,354,560 bytes (2.5 GiB) at 65,536 and 10,737,418,240 bytes (10 GiB) at 262,144. This is before the active layer's all-expert cache, normal prompt workspace, KV/session, verifier/MTP, graph/provider peaks, and explicit reserve. A host-residual suffix plus bounded GPU prefix can make 64K an admission candidate, but the current primary-source audit does not establish that its measured free RAM/VRAM can admit any particular prefix. At 262,144 the conservative route is current chunk-major; retain that full-context route and report layer-major inapplicable on failed admission.

This is not the old proposal to import the Xe layer-major engine. The smallest useful port would reuse existing primary layer kernels and expert dispatch, changing only the outer schedule for one fully-supported single-GPU, fresh-prompt shape: iterate layers outside chunks; preserve per-layer routed expert blobs for reuse; copy the next-layer residual between a bounded device prefix and host suffix; and keep current chunk kernel/dispatch as the fallback. Do not implement a novel FP16 residual or infer its accuracy. Keep all residual rows FP32. Before throughput work, the implementation needs full model-output and state parity gates and deterministic admission/failure tests.

## Current primary call shape and state dependencies

`Prefill::run` in `src/prefill/prefill.cpp` is chunk-major: for each chunk it prepares embeddings/PLE/QSA steps, loops all layers, then synchronizes callbacks and advances the chunk (`:1360-1387`, `:1443-1487`, `:1664+`, `:2635-2685`). Per-layer attention, hyper-connection and MoE scratch share the same region because they are sequential on the compute queue (`:569-574`); current chunk workspace is carved by `bytes_needed`/`carve` and optionally borrowed (`:785-890`, `:1163+`). The supported path is `run_impl`; there is no current primary layer-major selector at this HEAD.

A layer-major loop can preserve recurrence only if it processes that layer's chunks in increasing absolute position and leaves session state resident until all chunks of that layer finish:

- GDN `state` and convolution tail are selected by `gdn_index` (`:1744-1765`). Today each prompt chunk initializes its local GDN/QSA ordinal from `stage_lb_` and processes all layers, naturally visiting a given layer in order. The new outer schedule must advance the GDN state once per chunk per GDN layer, never reinitialize it between chunks, and commit final `ss.gdn_state` only after the full prompt succeeds.
- QSA uses each layer's `QsaState`; appends K/V at `p0`, maintains indexed cells/tail/dead/pooled index state, and reads prior cells for selection (`:1767-1857`). Across chunks the next layer pass must use exact positions and maintain the current int8 KV32K resident plus host/ring staging semantics. Current step records encode absolute `p0+t`; staged K/V pages are sourced before attention (`:1786-1814`). Do not assume attention is chunk-independent or that appending the whole prompt at once is equivalent.
- `prev`/`ss.ple_prev` and PLE history advance over tokens in chunk order (`:1359-1364`, `:1443-1480`, final commit near `:2679`). PLE rows are currently double-buffered and prefetched alongside a chunk, uploaded just before layer 1 (`:1443-1478`). A layer-major path must preserve token-order PLE predecessor state, avoid reusing host/device PLE buffers before their copy event, and run per-chunk callbacks in the order the MTP drafter expects.
- Every layer transforms the hyper-connection residual; attention updates are mixed before MoE and the next layer reads that result. Therefore layer-major needs a complete `[prompt_positions, hc*n_embd]` FP32 residual plane between layers, not just each chunk's `T*D` `m.R`. A bounded GPU prefix and host suffix need explicit copy completion and disjoint offsets; host storage for full context is 2.5 GiB at 64K and 10 GiB at 262K. This does not include a second residual plane if implementation cannot safely overwrite rows in place.
- Dense/non-MoE operations remain part of each existing layer: embedding/broadcast, GDN or QSA, hyper-connection/norm, shared dense path, expert path, residual combine and final norm/head. Reusing only MoE weights without preserving the entire layer's dependencies changes outputs. Reuse must not skip `on_chunk` MTP prefill: callback contract supplies chunk residual rows synchronously before they are overwritten (`include/strata/prefill/prefill.hpp:96-108`, `prefill.cpp:2668-2677`).

The per-layer expert bulk slot is a transient layer lease: after a layer's last chunk has consumed its resident/streamed expert data, drain all compute reads and any outstanding copy before replacing that slot for the next layer. It cannot alias the long-lived verifier hit-cache or standard ExpertCache entry unless ownership/publication is explicitly integrated. The archived Xe reference's `layer_major.hpp` plans an all-experts cache as `n_expert * align256(max_blob)` and a residual split by `gpu_tokens`, with explicit fresh free-memory/reserve admission; it is a useful shape contract, not proof its sizing/leases fit primary. Xe commit `28a7b9ae7ca5eba28eecd65f6453a7479c04fce8` includes a separate guarded path, source `git show ...:src/prefill/prefill.cpp` at `:707-738,1422-1467`; its gate rejects borrowed/multi-GPU/staged/checkpoint/draft and some session modes. Do not copy those restrictions blindly as feature truth; use them as evidence that these lifetimes require exclusion or porting.

## Lifetimes the splice must explicitly own

- **Dense/model and service allocations:** serve constructs one `Prefill sp` and keeps it through decode/requests; no-borrow 4K workspace stays allocated, while Verifier arena/graphs and MTP binding are also live before READY. The internal conversation restore writes into existing session buffers; it does not recreate or rebind verifier/MTP pointers. See R472 and `src/program/generate.cpp:4260-4700,5450-5496`; `src/core/verify.cpp:323-364,1051-1171`. Layer-major temporary capacity must be admitted alongside these already-live allocations. Reallocation/cache relocation while Verifier or MTP holds pointers is unsafe without rebuild/rebind. Do not bulk-cache model dense weights beyond the source's existing `WeightRef` mapping/lifetime.
- **Bulk layer weight:** one layer slot is reusable only after the final chunk's kernels have finished reading it. With async host uploads, record a layer-complete event after all consumers; wait for that event before slot overwrite/free. Admission failure or partial blob read must unwind to the chunk-major path before publishing altered session state, or return an error while preserving valid rollback semantics.
- **Stager and ring:** primary currently has routed staging slots, `copied` and `used` event arrays, `stage_live`, and MMQ grouped-slot last-use mapping (`prefill.cpp:461-478`, `:1488-1572`, per-layer issue/consume around `:2336-2534`). On same SYCL queue, queue order can replace some copy events only where source/destination lifetime remains ordered; the `Stager` still needs its DMA completion before pinned host slot reuse. Layer-major reuse cannot free these objects until all queued reads and copy completions drain. Preserve bounded ring fallback and its event rules; do not let an unused-slot event be mistaken for a recorded completion.
- **STOP/cancel and pending commit:** `should_stop` is polled at chunk boundaries (`:1381-1383`), while current state may already have advanced for earlier chunks. A layer-major schedule would have advanced multiple session layer states before it can report full-prompt completion. It must either stage mutable session state/checkpoint and publish atomically after all layers, or support rollback for every GDN recurrence, QSA KV/index append, PLE history/predecessor, and MTP draft append. Do not expose half-prompt state after STOP/error. In service, STOP/cancel and request pending commit paths must be tested at each transaction boundary; conversation RESTORE (`generate.cpp:5450-5496,5544+`) must still restore into existing buffers correctly. The serving Verifier's decode `pending`/commit state is separate from prompt layer state; do not free or resize verifier/cache objects at prefill completion. R472 confirms final verifier commit is drained before DONE (`:5997-6001`), and prompt callback synchronizes before MTP work.
- **Dense/MTP callbacks and RESTORE:** synchronous `on_chunk` currently receives each final residual chunk after stream sync; a layer-major pass cannot call it at the old point unless it retained that chunk's final-layer rows. Either retain only callback rows in an explicitly bounded queue/consume them immediately when final layer arrives, preserving exact callback order, or reject MTP/callback use until implemented. Current reference gate excludes draft/checkpoint callbacks. No such exclusion may silently fall through while advertising layer-major. Conversation cache restore and next request must be tested after a successful accelerated prompt and a canceled prompt.

## Candidate limited design and admission

Suggested first implementation boundary: only fresh, full-context single-GPU prefill with `pos0=0`, no image embedding, no layer split/peer, no adaptive phase cache, and no checkpoint callback; accept the layer-major mode only where the exact PLE/MTP/service behavior is either fully supported or return to chunk-major before state mutation. Use current FP32 primary layer bodies and exact current MoE per-format dispatch. Retain one layer's expert blobs in an owned slot through all prompt chunks; preserve source/cache leases and queue events. A hybrid host-residual design is a possible capacity mechanism: preallocate pinned (or separately validated pageable) host storage for non-prefix rows, one active FP32 layer cache slot, existing per-chunk GPU scratch, plus any callback rows; use explicit contiguous range transfers and wait at every boundary. But pinned full-context 10 GiB at 262K is not an acceptable default, and pageable host allocation must not be represented as DMA-pinned. Make admission per request based on checked arithmetic, actual alloc kind, fresh VRAM + explicit reserve and a host-memory budget; require a valid plan before changing session state. On any unsupported mode or capacity failure, take existing `run_impl` at the same requested context/KV/prefill settings.

A full 262,144 context remains valid by using chunk-major fallback (prefill chunk 4096, KV int8 resident 32768, existing ring/cache policy). Never truncate the request to the admitted GPU prefix. A 64K attempt is optional and only after host+GPU admission includes the live 4K workspace, ExpertCache, QSA/KV, MTP+Verifier allocations, bulk-slot bytes and reserve. Current source provides no reliable exact per-session free headroom for this report, so no numeric GPU prefix is recommended. `round482` leaves the default schedule unchanged pending implementation and matched measurement.

## Smallest meaningful qualification gates

1. **Planner/overflow/lifetime unit fixture:** exact 64K/262144 residual byte arithmetic; prefix/suffix offsets including chunks crossing split; zero/partial/full GPU prefix; overflow rejection; capacity failure has no state mutation; slot reuse blocked until last-reader/copy completion; recorded vs never-recorded event; stop/error cleanup drains in-flight queue and host staging before releasing owners.
2. **Numerical/state equivalence:** same model, prompt, compiler and kernels; compare current chunk-major vs layer-major logits/final residuals with documented FP32/quantization tolerances; exact GDN state+conv, every QSA KV/index state and positions, PLE history/prev, and deterministic next-token/decode logits. Do not assume bitwise equality if existing reduction order differs; do not relax tolerance to hide mismatch. Include mixed IQ2_S/IQ3_XXS/IQ3_S/IQ4_XS GU and IQ4_NL/Q2_0 Down dispatch.
3. **Lifetime/API cases:** 64K ordinary prompt; full 262144 requested-context run proves automatic chunk-major fallback still completes; STOP at first/middle/final chunk leaves next request usable; failure during blob load and during layer output does not publish partial session; fresh prompt then internal RESTORE then prompt; generation after accelerated prefill verifies verifier/MTP; MTP callback boundary/order; PLE enabled; QSA ring/staged cells and resident-to-staged boundary. Include explicit unsupported-mode admission result, not silent acceleration.
4. **Performance gate:** matched primary model/settings/warm policy and unchanged primary kernels; record per-layer bytes actually read, cache hits/misses, H2D submitted and completed bytes, event waits, residual host/device transfer bytes and wall, per-request memory high-water, all individual 64K samples and fallback 262K status. Compare prefill end-to-end and output/state parity; decode latency and memory remain separate. Do not infer 1000 tok/s from the layer-major shape or Xe speed. The active `bench.sh` run owns the current GPU window; no performance claim from this audit.

## What is new against prior R400/R459/R460/R470/R472/R474/R480

- R452/R456 already said layer-major is unadopted and proposed measuring cache misses/transfer exposure first; R480 specifies a transfer-ceiling probe. This report resolves the *data dependency cost*: full-context layer-major has a 40 KiB/token FP32 residual bridge, yielding 2.5 GiB at 64K and 10 GiB at 262K, while R480's expert-copy ceiling cannot price that extra host/device residual traffic.
- R472's service-lifetime audit establishes persistent prompt workspace, Verifier and MTP pointers and RESTORE semantics. New splice contract: their allocations must be charged during prefill admission, and verifier/MTP rebind is not a safe cache-resize shortcut.
- R474 covers chunk completion/STOP markers and source staging failure mechanism. New correctness issue: layer-major crosses chunks within one stateful layer; GDN/QSA/PLE state advancement must be ordered by position but cannot expose partial multi-layer prompt state to STOP/error. Existing chunk callback returns one chunk's final residual and MTP work; a layer-major implementation must buffer/stream these final-layer rows explicitly.
- R459 and R470 distinguish issue from completed bytes/critical-path overlap. New lease boundary: per-layer bulk weight slot reuse requires last reader completion across *all chunks*, while Stager's pinned host buffers remain owned until DMA completion even when compute/copy share one ordered queue.
- R460's low-VRAM candidates include old layer residency discussion; this report narrows to preserving the existing primary kernels and conditional layer scheduling. No host pinning, external throughput, or full Xe-engine result is adopted.
