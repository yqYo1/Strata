# R475: bounded host abort observation contract

Date: 2026-10-14 (Asia/Tokyo)
Scope: read-only research for a future, separately authorized owner-run diagnostic. No diagnostic, build, test, profiler, GPU, process, Git, fetch, configuration, service, or cleanup action was performed for this report.

## Finding

The smallest safe observation for the next short owner-run reproduction is a fixed, bounded host-failure marker plus a separate read-only supervisor sampling the already-owned process's per-thread `/proc` counters. Do not try to unwind the damaged thread from a SIGABRT handler, stop the live GPU-owning process in GDB, or create a large core. This gives reliable failure classification and progress/thread-activity evidence, but not arbitrary user-space stacks.

If JIT attribution is needed, make a separate, single-reproduction run with Level Zero/Unified Runtime API tracing limited to the first relevant module/kernel setup and submit. Treat trace overhead as a confounder and cap trace events/bytes. API tracing can show when host API calls such as module creation and command submission begin/end; it does not recover other threads' CPU call stacks or prove what code is executing between API calls.

## Evidence boundary

The R474/R473 records and the canonical accepted v7 receipt identify a 148.028-second diagnostic that exited 1 after a watchdog message, `GPU finished 0ms`, and `*** stack smashing detected ***`; the 4605-byte v7 `owned/engine.stderr` is the only remaining raw v7 artifact consulted in the previous round. The receipt says persistent SYCL cache was disabled, parameter validation was enabled, and the compact XMX tile-8 setup used one same queue and ring size 8. It does not establish a GPU fault or locate the host overwrite. No secret B record/config was read. Existing accepted controls include a 61,055-second normal run and a separate 105.36-second bitwise/canary pass; they are not the same failing model operation and do not invalidate this host-side failure.

## Existing `__cxa_throw` interposer

`bench/results/2026-10-14-primary-model-baseline/exception_backtrace.cpp` exports a C-linkage `__cxa_throw` wrapper, resolves the next symbol once in a constructor with `dlsym(RTLD_NEXT, "__cxa_throw")`, uses a thread-local recursion guard, logs matching type names, calls `backtrace`/`backtrace_symbols_fd`, then forwards the same three argument values to the saved implementation. The Itanium C++ ABI specifies `__cxa_throw(void *, std::type_info *, void (*)(void *))` and that it does not return. The source's `void *` type-info parameter has the same pointer calling representation, but matching the ABI declaration exactly is clearer and safer for maintenance. Preserve `[[noreturn]]` and forward object, RTTI and destructor unchanged.

The wrapper sees dynamically resolved C++ exception throws that pass through this symbol. It is not a general signal/failure observer: stack protector failure goes through `__stack_chk_fail` (and toolchains may use a local variant), while `abort()` and SIGABRT are separate paths. The absence of its `strata diagnostic SYCL throw` line therefore does not rule out a stack-canary abort. For an interposer to run, the executable must be dynamically linked and resolve the relevant symbol through the preload object's lookup scope; `LD_PRELOAD` must reach the actual engine process, and secure-execution mode, static linking, hidden/local binding, symbol versioning, or another wrapper may change or bypass lookup. `RTLD_NEXT` means the next definition after this object, including another preload wrapper, not necessarily a fixed libc implementation. Check the exact target's dynamic symbol/relocation binding before inferring coverage.

The present throw observer's failure path is not a safe model for a corrupted-stack path: type-name access, `strstr`, `strlen`, `backtrace`, and symbolization can touch loader/unwinder state, allocate, lock, or fail. Its thread-local guard prevents only same-thread recursion and is reset only if the logging calls return. A thrown exception is not itself proof that the process will abort; forwarding preserves the runtime's catch/unwind behavior.

## Minimal failure marker

For a future implementation, add optional, disabled-by-default wrappers for `__stack_chk_fail` and (if useful for broad abort classification) `abort`, using the exact no-argument, non-returning C ABI. Resolve and cache the next function before the failure path. At entry, emit only a fixed short marker and an integer thread ID using a bounded direct `write(2)`/`syscall(SYS_write)` path, then immediately chain to the next function. Do not allocate, call stdio, symbolize, inspect type names, take locks, call `dlsym`, or call `backtrace` there. A fixed marker is a low-overhead classification aid; do not claim its presence makes any hook reliable after arbitrary memory corruption. `abort` observation is generic and may be missed if libc takes a hidden/internal path; it cannot identify the trigger by itself. Validate which symbols the actual compiler/runtime calls in a non-GPU fixture first, and keep the observer opt-in.

A SIGABRT `sigaction` handler can safely write a preformatted fixed marker, but should not unwind or symbolize. Linux/POSIX signal-safety documentation limits handlers to async-signal-safe operations; `backtrace` is not listed as such, and the glibc manual labels it AS-Unsafe (`init heap dlopen plugin lock`). The handler should return to normal termination semantics; it must not swallow SIGABRT. Since the process is already failing, even a fixed write is best effort, not a guarantee.

## Bounded supervisor and JIT alternative

The owner can supervise the child PID it launched without attaching to or stopping it. Record PID start time to avoid PID reuse; at 200 ms intervals for at most 180 seconds (900 samples), enumerate `/proc/<pid>/task/<tid>` and retain only TID, state, user/system CPU ticks, wait channel and, when readable, `/proc/<pid>/task/<tid>/syscall`. Cap each row to 256 bytes and the total file to 256 KiB; stop on child exit or deadline. This is low-volume and read-only. It can identify the CPU-hot or syscall-waiting TID and coarse progress. `/proc` snapshots are not atomic, permission-sensitive, and cannot provide userspace frames; a missing `syscall` row is not failure evidence.

For a separate reproduction that needs setup attribution, enable the installed Level Zero tracing layer or PTI/UR tracing only around one bounded first-submit window, writing to an owner-created capped file. The Level Zero loader and Intel PTI docs describe `ZE_ENABLE_TRACING_LAYER=1`; PTI documents Level Zero/SYCL runtime API tracing. Prefer timestamp/thread-ID/API-duration records and stop after target module creation/kernel submission, or at a fixed deadline/event cap. Do not enable a broad device timeline/profiler. Tracing adds host overhead and may perturb the timing; compare outcome with the untraced reproduction. Existing `UR_ENABLE_LAYERS=UR_LAYER_PARAMETER_VALIDATION` is validation, not call-stack or JIT timing capture.

## Explicit exclusions and limits

Do not attach GDB or issue all-thread backtraces while this process owns a spinning GPU queue: ptrace stop can freeze host progress while device work and buffers remain live, potentially worsening the state. Do not capture a default full core for a process with approximately 50 GiB resident: size is mapping- and policy-dependent and may include large private/anonymous mappings. `RLIMIT_CORE=0` avoids the dump but gives no stack; a size cap can produce a truncated, misleading artifact. The bounded marker + `/proc` plan intentionally accepts that it will not recover user-space frames. If frames become necessary, design a new isolated, short reproduction and a memory-dump policy from its actual mappings before running it; that is a separate decision, not a reason to stop the current owner-run GPU process.
