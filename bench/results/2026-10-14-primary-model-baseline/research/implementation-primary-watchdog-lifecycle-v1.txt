Implementation contracts
The snapshot mutex covers only publication/copy and the terminal host flag
signal. It never covers formatting, a driver call, stream query, pool call,
GPU wait, or layer step. Original last_t_/last_pos0_/tokens, graph selection,
inference arithmetic, sampling and commit fields remain request-thread fields.
Each snapshot contains generation, phase and one coherent T/pos0 pair. A new
window publishes its complete participating next_ chain as preparing before
capture; nested sequential stages reuse that publication. Each stage becomes
running only after its mapped flags have been reset/staged, immediately before
launch. GPU+copy completion changes phase to finishing (no spin rescue), and
successful run completion changes it to completed. RAII marks still preparing,
running or finishing stages failed on every return/exception path. Completed
historical stage records are not overwritten by a later child failure.

Layer stages execute sequentially through next_->run after the prior stage's
streams synchronize. Future preparing stages have no submitted spin work and
must not receive UINT32_MAX before their later flag reset. The registry visits
every eligible running stage, rather than choosing one global pointer or all
initialized idle objects. This covers all currently active chain stages while
preserving correct staging for future stages. Prefill leaves verifiers inactive
or historical and triggers no rescue. A failed/capture-only window is not falsely
reported as completed. Finishing/sampling failures are reported failed by RAII.

Registration at the end of successful init avoids callbacks seeing partially
initialized pointers. Capacity16 exhaustion returns a concrete err/false and
normal destruction frees allocated resources. Duplicate registration is accepted.
Callbacks acquire a counted lease under the registry mutex before using a
pointer. Destruction first closes/removes its entry and waits for every acquired
lease, then performs the original stream/graph/buffer teardown. The closed slot
cannot be reused before lease quiescence. Static callback functions remain
installed: an empty registry is safe, including previously loaded function
pointers. Exception-safe lease destruction decrements references and notifies.
Callback functions must not delete their own leased object; no production call
site does that. Object lifetime of next_ outside callbacks still assumes the
existing serialized engine/request teardown; this is not a general concurrent
run/destructor API.

Eligibility is checked and the released_ latch/host flags are signaled in one
snapshot critical section (if_running), so a stale diagnostic read cannot
select a newly completed/idle window. Bounded stream drain runs after unlocking
while the callback lease retains the object. Synchronous verifier timeout paths
keep release_gpu_waits(5000), now sharing signal/drain helpers. The existing five
second per-verifier bound, seq_cst fence and sfence remain. Multiple stage bounds
can accumulate just as in the former all-live loop; this is not a new whole-
device deadline. Rescue logs now say verify/copy streams, never whole GPU drain.
No active entry prints a message explicitly stating prefill/device drain was
not assessed. The watchdog still calls abort after its report/rescue.

The serve observer is declared after the already-created verifiers and pool,
so return/QUIT/EOF and stack unwinding stop+wake+join it before their destruction.
A callback that already started finishes before stop returns. Terminal abort
intentionally has no normal teardown. Pool timeout release uses the same leased
registry even independently of the serve observer. Existing pool waits execute
in request flow, not after normal serialized teardown; the pool's separate raw
diagnostic registry is not generalized here because the scoped serve observer
joins before pool teardown. This patch does not introduce concurrent pool
construction/destruction support.

Mapped flag race assessment
h_flag_/A/B are host-written words consumed by GPU waits. Original watchdog
volatile writes conflicted with host main-thread writes and B's atomic host
callback operations; volatile was not C++ host synchronization. All their host
reads/reset writes/monotonic raises now use the same atomic_ref helper. Host
callbacks and the watchdog use monotonic CAS raises, so a late B/A/M raise cannot
lower UINT32_MAX. Reset remains before that stage's running eligibility. This
changes host synchronization and preserves the existing device fences/order.
Mapped h_seq_ is device-written, and staging resets it. SYCL diagnostics retain
reached_'s completed-event host mirror. CUDA/HIP diagnostics no longer sample
h_seq_ concurrently: they label a zero host mirror as unavailable. Their polling
in the actual inference path is unchanged. C++ atomic_ref alone does not establish
device synchronization or qualify system-scope GPU visibility: Main must validate
mapped flag visibility, supported alignment and lock-free generated operations.
No GPU rescue kernel, wait, ordering fence or completion boundary was removed.
The ignored copy-stream completion result now returns an explicit verify copies
error; it cannot publish a completed window on copy completion failure.

CPU tests proposed, not run
Concurrent snapshot publication/read checks generation/T/position consistency;
completed and failed snapshots are inspected. A lease callback blocks on a
promise while another thread removes the object; removal cannot finish, and
capacity cannot be reused until the callback returns. Capacity exhaustion is
asserted. Idle/prefill and preparing stages release nothing; two running stages
both execute the exact if_running gate; completed/failed stages release nothing.
Observer stop is checked both during its periodic wait and with a callback held
by a promise, proving join cannot return before callback completion. Monotonic
host flag rescue is checked against a late lower raise. Assertions remain active
in NDEBUG builds. These tests use production helpers, not mirror registries or
fake Verifier GPU logic. They do not cover graph capture, GPU/device visibility,
actual split-device operation, or full server protocol.
