Submission/refusal semantics
GU group is attempted once. On false, only its old GU wrappers run, one per expert, incrementing old GU census after normal return. Down group is attempted independently; false invokes only the old flat Down wrappers and increments old Down census after normal return. On admission the corresponding old wrapper count is zero for those experts. Both calls use the existing m.cs stream. A grouped exception propagates; it is never converted to false or rerun. A Down refusal after GU admission invokes only Down fallback. If Down throws after GU has submitted, no markers/give_back occur and no GU rerun occurs. New code does not catch exceptions or free uncertain GPU resources.
All releases follow both readers, including all fallback calls. True means normal submission, not completion; checked used-event recording on m.cs establishes an ordered last-reader marker. A marker failure prevents producer publication. Normal final flush is explicit before stager_done.complete and combine. Existing issuer/stager cancellation, join/drain guards and outer exception cleanup remain in place; candidate does not weaken their uncertain-resource policy or add a host drain.
