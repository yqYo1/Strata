CONCRETE WORKLOAD
Seven real layout pairs, in this fixed order:
GU/Down 18/20,18/42,21/20,21/42,22/20,22/42,23/20.
Every projection has ff640 x emb2560 = 1,638,400 weights. GU produces 3,276,800
fp16 elements in the unchanged interleaved row layout; Down produces 1,638,400
flat fp16 elements. GU stride is 3,276,824 fp16 elements, Down stride 1,638,424.
GU/Down capacities cover all16 slots including their24-element padding. Source
projections have real block extents from iq_row_bytes plus16-byte alignment and
64-byte source gaps. Full64-byte external guards and all gaps/padding are checked.
The two arms use identical device addresses, native bytes, destination strides,
active slots and written bytes. No packed-cache/H2D timing or host decoder.

The deterministic fixture generates native integer fields per expert/projection/
block and rewrites each supported format's actual fp16 d field to a signed finite
small normal scale in [0x1400,0x17ff] or the corresponding negative range. It
checks full reference output fp16 finiteness without decoding native weights on
the CPU. FNV-1a identities are aids; exact comparison scans every allocation
byte and counts all differences. The authoritative comparison remains old versus
optional production APIs. This fixture is not a model tensor capture.

The unchanged individual arm enqueues GU then Down for each active expert.
The group arm enqueues one optional GU API call for all active experts then one
optional Down API call. This intrinsic ordering difference is explicit; each
repetition reads and writes the same amounts. It is component service work only,
with no GEMM, downstream consumers, token routes or model execution.

Runtime::get().compute() is the only benchmark stream. Admission requires a GPU,
device USM, Runtime/context/device ownership, in-order queue and256-work-item
local shape supported in both APIs. Tags additionally require enable_profiling.
Device choice never uses a vendor/name/device ID. No queue or host-USM protocol is
created. The optional API has no automatic production caller switch. The broader
engine retains its individual API path; this standalone benchmark fails rather
than changing its comparison after capability refusal. No retry/fallback follows
admission, exception or output mismatch. Returning normally is not completion.

TIMING DEFINITIONS AND LIMITS
Host-only selectors use steady_clock around actual enqueue loops and separately
enqueue through checked Runtime::finish(compute). host_submit_ms ends immediately
after normal enqueue returns; it is NOT completion. host_submit_checked_drain_ms
ends after checked compute queue completion/async error handling. Normalize both
by n*4 expert GU+Down pairs, recording4 repetitions, call counts and output bytes.
This includes real production wrapper checks/submission, fixture loop dispatch
and small logical-return bookkeeping, host-driver blocking and enqueue/device
overlap. It does not isolate pure driver CPU cost or exclusive GPU kernel time.

Separate tags selectors call actual production gpu::event_create(timing=true),
event_record and event_elapsed_ms, backed by src/core/gpu.cpp. Its prior receipt
qualified16 complete samples,8 each in free and contrib-llvm, including completed
and reversed/control cases. The current helper source hash matches that receipt.
The benchmark does not expose Event internals, directly fetch raw profiling data,
use new queues, or replace the helper. A positive finite tag interval is required.

Start-tag submission precedes the host enqueue clock; end-tag submission follows
enqueue. host_submit excludes both mark submissions. submit+checked-drain starts
at enqueue and includes the pending start tag and end-mark submission/wait;
host_mark_enclosure separately includes both mark submissions. Begin/end mark
submission durations are recorded separately. event_elapsed uses the difference
of completed production tag command_end timestamps: complete sequential stream

tag fields have the sentinel -1. No tracing/profiler instrumentation is supplied.
