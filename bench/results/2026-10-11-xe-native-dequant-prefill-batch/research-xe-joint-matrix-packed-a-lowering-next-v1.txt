# Xe joint_matrix local PackedA lowering: evidence and next steps

Date: 2026-10-11
Scope: read-only investigation. No GPU, build, test, service, or model run was performed. No source or Git state was changed. The only run evidence inspected was the three previously designated `model.stderr` excerpts; this report does not claim the full log was reviewed.

## Finding

The failure is a device module compilation failure. The recorded backend error says the symbol

`__builtin_spriv_OpJointMatrixLoadINTEL_PackedA_RowMajor_SG16_16x16_i16_8_local_v8i8_pi32_i32`

is undefined, followed by `UR_RESULT_ERROR_PROGRAM_BUILD_FAILURE` and `ZE_RESULT_ERROR_MODULE_BUILD_FAILURE`. In the inspected excerpts it occurs while compiling three modules; kernel names include `xe::Kernel<2,bfloat16,...>`, `xe::Kernel<2,half,...>`, and `PromptAttnMma<...>`. This happens before kernel execution, so it is not evidence of a bad numerical result or a dispatch-time hardware fault. The symbol name points to an Intel joint-matrix PackedA row-major load variant with local address space. It is consistent with a missing/unmatched compiler builtin lowering or backend implementation for that specialization. The available excerpt does not identify which component introduced the mismatch, nor prove which oneDNN/Strata source kernel generated that exact symbol.

## Practical next actions

1. For a controlled diagnostic, reproduce with the exact installed compiler/runtime/driver tuple recorded alongside the failing command, compiler version output, device identity, and SPIR-V/module hash. Reduce to one local-memory `joint_matrix_load` with the same element type, shape, layout, subgroup size and stride; compare with a global-memory load and non-packed shapes. This separates compiler emission from IGC lowering and avoids attributing the error to a source path by name alone.
2. As an unvalidated lowering experiment, run the reproducer with `IGC_JointMatrixLoadStoreOpt=0`, then compare compile success and generated output. Treat it only as a diagnostic; no evidence here says it is a workaround or preserves performance/correctness for the model.
3. The dependable avoidance strategy, if startup must proceed before a driver fix is known, is a build-time dispatch that does not register or emit the affected local-load joint_matrix specializations and uses an existing non-joint-matrix fallback. A runtime branch alone may not help if startup background-compiles every registered specialization. Verify the fallback's model correctness and behavior separately before relying on it.
4. Do not mix an independently downloaded compiler with arbitrary IGC/NEO binaries based solely on the 7.1.1 release note. First establish the actual compiler and driver tuple; then test a vendor-supported matched package or a driver/compiler update against the reduced reproducer.
