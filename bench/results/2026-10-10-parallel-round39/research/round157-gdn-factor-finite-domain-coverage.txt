# R157 — GDN factor finite-domain coverage gap screen

Date: 2026-10-10 (Asia/Tokyo). Read-only source/specification review only. No source edit, build/compiler/disassembly, test/runtime/device/GPU/model/payload/profiler or cleanup was performed. The result is a bounded coverage recommendation, not a test result, native-math qualification, model-reachability claim, speed estimate, tolerance change, or adoption decision. The feature remains model-unqualified and physical-KV-unqualified.

## Decision

There is a concrete gap between the useful primitive screen and the real producer/consumer fixture: the latter does not cover the finite boundaries already represented in the primitive's artificial value set. Add only a small, explicitly labeled finite-boundary extension to the real fixture, keeping its existing exact A/B comparisons. This is numerical coverage only; it does not resolve whether a target's `sycl::native::exp` has a documented valid interval or matching results across kernels. Do not label the added points model-reachable or documented-valid without separate evidence.

## Frozen source and comparison

The source reviewed is the supplied factor worktree at `00d9c24e` (source identity from the handoff). Relevant SHA-256 pins: `sycl/src/prefill/kernels.dp.cpp` `ee745dbc335748709023dd349829d0300b797adefae0e951f975bae4e5408e3f`; real fixture `sycl/src/prefill/gdn_gate_factor_parity.cpp` `46ccf7ac95bc86cc183a42f969b253fc6ec4d012d46bf1325509d9f7ab3b25c3`; primitive `sycl/tools/gdn-gate-factor-probe/gdn_gate_factor_probe.cpp` `801b9c6ee397c04f7ce3478d63f17d09aedbee1b39f61dfbf3fe26541a6f9632`.

The production gate producer forms `v=ab+dt`, then `L=(v>20 ? v : log1p(native::exp(v)))*ssm_a` and stores FP32 `L` (`kernels.dp.cpp`, `gdn_gates_kernel`). Legacy recurrence consumers load that stored value and call `native::exp(L)`; the factor path stores a producer-computed factor and reads it directly. Thus there are two distinct finite-domain questions: producer softplus behavior as `v` approaches zero/underflow and the `v=20` branch, and consumer behavior when the materialized FP32 `L` approaches exp underflow/subnormal boundaries.

The real fixture's deterministic source values constrain `ab`'s first plane to `[-3.0, 3.0]` in 0.1 steps; `dt` is in `[-0.06, 0.06]`; `ssm_a` is in `[-0.124, -0.04]`. Therefore its `v` stays roughly within `[-3.06,3.06]`, far from `v=20` and the inner-exp underflow region. Its materialized `L` is only a modest negative value (roughly from zero to about `-0.4`), so its expected factor remains near one. Its exact comparisons are valuable for the actual synthetic GDN pipeline and carried state, but do not exercise extreme finite gates.

The existing primitive screen provides the missing *candidate points* but is not an equivalent real-fixture check. It uses `a=-1` for most heads and `a=-1e-6` for a few, and input values including `-80`, `-104`, `19.999998`, `20`, `20.000002`, `80`, `87.33655`, `103.27893`, and `104`. This probes producer-side branch/underflow behavior and creates some extreme `L` values; it compares baseline and candidate producers plus scalar/SG16/SG32 readers. However, its consumer path is a separate primitive screen, without the real fixture's convolution, recurrent state, output, or exact expected factor generated from a materialized legacy FP32 gate buffer. The primitive labels finite cases as synthetic with unverified native-exp domain, correctly avoiding a reachability/domain claim.

## Smallest useful extension

Keep the present ordinary real-fixture arrays and all existing state/output/hash assertions. Add a small separate deterministic boundary batch (for example, a handful of heads/tokens with a distinct `FINITE_BOUNDARY_SYNTHETIC` marker), routing the same values through both real typed encodings and its existing `MaterializedLogGateExp` comparator. Preserve per-case raw FP32 input/output bits and finite/subnormal/zero classification. Do not replace or perturb the ordinary fixture inputs or merge these results into its production-context claim.

Cover these bounded cases:

1. **Softplus input near zero and the linear-branch boundary:** `v` at `-min-normal`, adjacent subnormals/zero, `nextafter(0,±inf)`, and `nextafter(20, -inf)`, `20`, `nextafter(20,+inf)`. These complement the primitive's current wider `-8` and near-20 values. Use finite, negative `ssm_a` values already accepted by the fixture so resulting `L` is finite and nonpositive. Compare `L` producer bits and factor-vs-materialized-legacy `native::exp(L)` bits; do not infer mathematical correctness from A/B equality.
2. **Consumer `L` around IEEE exp landmarks:** directly target the FP32 global log-gate boundary at `-87.33655` (normal-minimum neighborhood), `-103.27893` (minimum-subnormal neighborhood), and `-103.97208` (round-to-zero neighborhood), with only a few adjacent representable values on either side, plus `-FLT_MIN`, `-min-subnormal`, `-0`, and `+0`. Feed these as explicitly marked consumer inputs through both consumer encodings while retaining a paired producer call for ordinary fixtures. The current primitive's `v=-104` creates approximately `-0`, not a materialized log gate near `-104`; its `v=+104` takes the linear branch and also makes `L≈-104`, so it does hit one far-negative consumer region but misses the local boundary neighborhoods and does not classify their outputs by bit pattern. Keep consumer-only injected values separate from producer-reachable fixture cases.
3. **Large finite softplus scaling:** include at most two finite `ssm_a`/`v` pairs that make the rounded `L` approach the normal/subnormal boundary while keeping `v` below 20, plus a pair on the `v>20` linear branch. Construct the case from chosen finite target `L` via a finite negative `ssm_a`, then record the actual resulting rounded `v`, `L` and factor bits. This is synthetic stress, not a claim that these `ssm_a` values can arise in a named model. Avoid `±infinity` and NaN in this finite-domain extension; the primitive already has a separate optional artificial-nonfinite mode.

For every pair, preserve the current gate/consumer exact-bit comparison and existing state/output exact comparison, but report these edge batches only as `synthetic finite boundary coverage`. A mismatch is actionable parity evidence; a match only means the tested source paths produced equal bits for those inputs on that exact target/build. No native-exp range classification follows from equality. A target/version-specific native-math contract is still required before any `documented-valid-domain` label. Keep the real-context fixtures' ordinary input provenance, result status, and model-unqualified wording unchanged.

## Interpretation and limits

R141 already requires an independent scalar semantic oracle for a later qualification; this report does not repeat that design. R145 already found the fixture's synthetic values do not target softplus around ±20 and that the fixture does not run model projections/full prefill; the present delta is only the finite-boundary subset and the distinction between producer `v` and materialized consumer `L`. Do not enlarge numerical tolerances, infer that edge values are model-reachable, infer cross-kernel native-exp bit identity from source topology, or make an adoption/performance decision from a primitive or synthetic fixture pass.

Khronos specifies `sycl::native` math accuracy and valid range as implementation-defined; this applies to `native::exp` and means IEEE landmarks are test points, not guaranteed in-domain inputs. See [SYCL native precision math reference](https://github.khronos.org/SYCL_Reference/iface/native-prec-math-func.html) and [SYCL 2020 specification](https://registry.khronos.org/SYCL/specs/sycl-2020/pdf/sycl-2020.pdf). The prior R125 source audit records the same contract and notes that the exact Intel compiler/device-specific range and denormal behavior remain unresolved.
