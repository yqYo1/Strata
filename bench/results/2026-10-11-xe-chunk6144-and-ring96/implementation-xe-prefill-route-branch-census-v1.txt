Purpose and implementation
Presence of STRATA_PREFILL_TRANSFER_COUNTS, including the string 0, continues to enable the existing H2D ledger and now enables this separate census. All existing H2D and timer format strings remain unchanged. No new setting is introduced. No compute, transfer, ring, group, thread, native/canonical, hardware capability, chunk-size or scheduler parameter is changed.
PfRouteCensus stores host facts and wrapper-return counters. Per-layer chunk_census is separate from chunk_transfers and declared before the issuer join guard. Only the main consumer writes census fields. The threaded issuer continues to own its existing transfer-field writes; no issuer reads census fields. Inline copy counters retain existing behavior. Both arrays are moved into the completed chunk record only after issuer.join(), issuer failure rethrow, stager failure checking and chunk_stager_done.complete(). Census lines are emitted in the existing final transfer-count block, after terminal compute drains and optional diagnostics have succeeded. Early return or exception before that block emits no census completion rows. Existing H2D total remains after census emission and supplies the stage-run completion marker for a strict parser. No extra joins or synchronization are introduced.
Empty vector objects exist on the stack as metadata; when counts are disabled there is no additional vector allocation, routing scan, Clock call, GPU call, event, synchronization, tensor/payload allocation, or arithmetic used by model compute. Enabled mode allocates only the per-layer host metadata array retained with existing chunk records. It scans the already-populated m.cnt once per routed layer/chunk and performs checked host arithmetic. The group wrapper return is assigned to a local bool to count accepted/declined results; the existing branch and its arguments are preserved.

Fields and exact units
Device/stage/offset/pos/tokens/layer keys come from the same source variables as existing H2D rows. chunk_offset is relative to this invocation's input pointer; pos is absolute p0. Recursive downstream stage invocations may have different chunk_offset identities. mode and issuer are exact stream_all/threaded_issue source policy flags, not deductions from traffic.
mmq_enabled is the exact mmq_plan().any && layer flag for routed layers, matching production use_mmq. Initial metadata uses the same plan and a bounds check for every stage layer, including a layer with no MoE branch. It is a plan fact, not evidence that kernels executed, matrix hardware exists, or any specific driver implementation was selected.
plan_fallback is the global mmq_plan().fallback allocation/plan fact. It may be true while this layer has mmq_enabled=1 because a different layer needs fallback. It does not count fallback execution, group declines, hardware rejection, or dense GEMM backend selection.
routing_observed is set only after actual host route grouping fills m.cnt. A row with routing_observed=0 has zero route and call counters and no observed gather/direct policy. It must not be interpreted as proof that every expert had zero rows; plan flags remain source-plan facts.
routed_rows is the sum of actual nonnegative m.cnt[e], not a replacement with T*K. expected_rows is separately checked unsigned T*K. The measured sum must equal expected_rows or run fails without census completion output. Negative counts and multiplication/sum overflow throw. Existing route-ID validation remains in place. Active counts are from that same m.cnt before CPU assignment; therefore active_nonresident includes nonresident experts later assigned to CPU when that existing branch is enabled.
active_experts counts experts with m.cnt[e]>0. active_nonresident counts those with rows>0 for which the exact production resident predicate (m.host_res && m.cache && host_res[layer*n_expert+e]>=0) is false. zero_nonresident counts experts for which this predicate is false and rows==0. Their sum is the nonresident expert population for this layer/chunk when routing_observed=1. No extra source lookup or resident-state mutation is performed.
mmq_direct and group_gather are copied from the exact existing branch booleans after routing. mmq_direct uses use_mmq and m.mring; group_gather uses group_env, stream_all, use_mmq and !mmq_direct. The field describes the selected source policy, not a guarantee that a wrapper was needed for a zero-active layer.
gather_group_accepted_calls counts gather_native_group returning true; gather_group_declined_calls counts its returning false. The counter is incremented immediately after normal return. A declined group is followed by the same preexisting individual-wrapper fallback loop; accepted does not certify numerical correctness.
gather_individual_calls counts normal returns at both exact gather_native production call sites (declined-group fallback loop and ordinary non-group gather branch). It does not count copies in a direct ring path. It does not multiply a wrapper by three or infer underlying API calls.
native_dequant_gu_calls counts normal returns at iq_dequant_gu_f16 in the native expert fallback branch. native_dequant_down_calls counts normal returns at iq_dequant_f16 immediately after it. Canonical blob_dequant_f16 is unchanged and excluded. Fused resident expert compute and CPU expert compute are unchanged and excluded from these wrapper counters. A zero dequant count alone is not proof that MMQ ran.
All counter increments use PfRouteCensus::add with uint64 overflow checks. Expected-row multiplication checks its operands and bound. No census summary arithmetic is performed at emission; every emitted count was checked when recorded.
