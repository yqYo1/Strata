## Prioritized findings

**R1 — build gate: omitted peer stub; closure is not complete.** Independently checked all 197 listed files: original blob, SHA256, bytes, mode and faithful-anchor bytes agree; all 49 external vendor hashes agree. However `validation/pr6-restore/sycl/CMakeLists.txt:156-161` requests `src/core/peer_experts.cpp`. Neither restored resolver candidate exists. Resolver lines 66-71 therefore reach FATAL_ERROR; this is source-proved, not an observed configure failure. `historical-closure.json` silently omits this request from `_engine` (12 listed versus 13 actual). Original `d0c5dda` has SYCL stub blob `63656fd6866d15670a940a9e25e7750f3b071ebc`. Including three explicit port-only sources, actual engine closure requires 84 translation units, versus reported 83. Restore that original stub, update closure/evidence counts, and have Main configure the gated wrapper. This adds the original unsupported-peer behavior; it need not change inference math.

**R2 — before GPU: completion counters lack a valid concurrent-access contract, with unbounded failure progress.** P:258,285-287 allocate `done_seq` using **host USM**, not device/shared USM or C++ atomics. P:415 submits ordinary `queue::fill<uint64_t>` after the blob memcpy on the in-order copy queue; P:420 reads the same location through a volatile host load. There is no atomic API, memory order or memory scope for this shared counter. `issued` is a host `std::atomic<int>` release/acquire publication of `want`; that orders host metadata, not concurrent GPU writes into `done_seq`. The analogous PLE path uses host USM at P:1028 and fill/volatile polling at P:2358-2379. A queue may implement fill as a kernel or transfer; neither spelling establishes atomic publication. In-order queues order their device commands; they do not turn this fill into a C++ atomic operation. Host USM accessibility itself is legal; concurrent unsynchronized counter access is the unresolved defect, not the mere use of pinned memory.

Normal ring wrap requires this handshake; asynchronous signal failure can also leave workers spinning forever. P:346,349,400,426 and PLE:2378 have no cancellation/error/deadline branch. `finish()` releases the issued gate but cannot repair an accepted signal that never updates the counter. Fix B addresses **submission rejection**, not this case. Replace the handshake with checked completion events/status and bounded failure retirement, or an explicitly supported host/device atomic protocol with matching operations, system scope and capability checks. A host atomic load alone does not fix the writer. Preserve buffer reuse only after DMA completion. Ring-2 wrap, cross-generation reuse, signal rejection, accepted-command failure and cancellation need Main-owned finite fixtures. See [Khronos USM host-access rules](https://github.khronos.org/SYCL_Reference/iface/usm_basic_concept.html) and [atomic requirements](https://github.khronos.org/SYCL_Reference/iface/atomic_ref.html).

The current-project `own-native16-separate-queue-timeout-v2.ja.md:3-9` records a separate-copy/compute fixture timeout, with cause unresolved and no fresh GPU fault. That is a different source/runtime path, **not proof PR6 caused a fault or will reproduce that hang**. It nevertheless supplies no qualification for resurrecting PR6's separate queue/event route. Keep the known risky route source-only until addressed; layer-major's already serialized layer upload is a candidate for a simpler checked single-queue contract, reviewed separately by Main.

**R3 — before GPU: asynchronous errors can be consumed as apparent success.** D:69-79 catches SYCL exceptions, prints and returns. D:616-627,670-692 installs it on both the default and `create_queue(true)` queues. P:942-945 and M:371 use those queues. New `wait_and_throw` calls in A/B/C/F invoke this handler; they do not necessarily throw to the lease's catch or DPCT_CHECK_ERROR. Ordinary waits remain at P:2058,2080,4075,4128,4147 and M:1068. Thus failed computation/upload can still produce a successful return/residency publication. This is an error-reporting/correctness defect; a terminal failed command can still have completed its accesses, so handler swallowing alone does **not** prove a DMA use-after-free. Add owned sticky error/fail-stop propagation checked before publishing state and before accepting any result. Inject provider async errors independently from synchronous exceptions. External runtime environment settings cannot repair this C++ handler. See [Khronos async-handler contract](https://github.khronos.org/SYCL_Reference/iface/async_handler.html).

**R4 — before GPU failure qualification: Prefill destroys a borrowed default queue.** P:529-530 initializes both queue pointers to the DPCT default. P:651-652,660-676 unconditionally destroys `impl_->copy`, including constructor/destructor without init, geometry refusal, or token-allocation failure before private queue creation at P:942. D:635-642 erases its owning shared_ptr but leaves `_q_in_order` unchanged; D:569 and897 then dereference that dangling pointer. Other model owners can still use it. D's queue ownership implementation proves the hazard; no device failure is needed to trigger it. Initialize the owned copy pointer to null or track ownership explicitly; only destroy a successfully created private queue. Main should cover no-init destruction and every pre/post-queue init failure while verifying the default remains usable. Healthy completed-init math is unaffected.

**R5 — host admission gate: 'init must complete' check is incomplete.** P:886-887,947,955-967 publishes every field examined at P:1889-1891 before allocations/carving finish at P:1053-1066. A later scratch/carve allocation failure returns false but a subsequent public `run` can pass the new guard and submit kernels with incomplete workspace. Standard generator checks init's return (generator:7416-7420), so this is not evidence its valid recipe normally follows that path. Add an explicit ready flag published only after successful init, cleared before initialization/reset/failure; reject run after injected late failure. Also validate chunk geometry before its initial allocations; the new run span check does not protect init from invalid chunk requests. No normal math/order change is needed.

**R6 — invalid-input GPU bounds: native vocabulary upper bound remains unchecked.** Fix E accepts any int32-representable token at P:1896-1899. In the native embedding branch `wemb == nullptr`, so P:2272 checks negativity but has no vocabulary upper bound. `NativeEmbed::gather_dev` at native_head.cpp:278-279 forwards to iq_kernels.dp.cpp:2387, which forms `table + tokens[t]*row_bytes` without bounds. The per-token native fallback at layer.cpp:1188-1191 likewise checks only negativity. Generator's tokens-file parser accepts through INT32_MAX (763-777,1352-1361); the explicit vocabulary rejection at generator:6457 belongs to a serve path. Trigger: native table with a supplied token >= its vocabulary. Reject using the actual embedding table's vocabulary before any submission, including draft next_tokens and direct embedding entrypoints; test zero, last valid and one-past-last IDs on the host. This inherited defect does not affect valid tokenizer output; use independently validated token fixtures for future diagnostics.

**R7 — startup allocation failure: doorbell null return still reaches memset.** Generator:2487-2492 calls doorbell_init on the normal startup path. Its layer.cpp:1164-1172 allocator checks only DPCT_CHECK_ERROR, aliases the returned host pointer and then calls memset. A nonthrowing null USM allocation therefore crashes before the caller can handle a zero return. Add a nonnull check and partial-allocation cleanup, then Main injects each field allocation failure. D fixed its named sites but does not close this reachable startup case; healthy math/order stays unchanged.

## Seven-fix audit

- **A / aceb6b0f:** P:1312-1321,1336-1354,1408-1423 gives each batch immutable token/bounds storage, declared before its guard. `draft_uploads.hpp:18-50` handles partial batches and nonzero first offsets; at physical262144 its counts/products fit int32. Guard arms before either upload, drains on early return/exception and fail-stops with storage live if drain throws/fails. Same kernels/batch order and final wait count. No additional A-specific defect found, subject to R3; no native validation claimed.
- **B / 47fb8e05:** P:410-427 now publishes want only after fill submission succeeds, then issued release. Wrapped workers acquire issued before reading that slot's want; subsequent publication of the same slot requires that worker's ready, so names alone do not prove a concurrent host want race. Layer-major Restore drains compute/copy before finish and before residual/cache locals die (P:1992-2048). Its explicit `_Exit` preserves owners when a drain throws. This fixes the rejected-fill deadlock under completed prior signals; R2/R3 remain. The chunk-major StagerDone guard only calls finish (P:2530-2533), so do not generalize the layer-major failure-drain proof to every historical route.
- **C / 9e770e33:** M:923-955 declares record lease after rec, arms before upload, and retains it through capture/submission failures and final drain (1015-1030). It also retires borrowed R_rows on this branch. pf_dev is outside captured graphs; fixed tok/step/pos/Rin buffers are graph inputs (M:957-998,795-801). No normal record values/group order change found. Reallocation/rebind/graph failures remain execution gates.
- **D / edf7cd79:** Nonnull checks at Alloc P:219-225, staging P:295-305, P:907-922,989-1022,1038-1049, M:67-70,915-919, expert_cache.cpp:510-529 correctly restore fail/fallback behavior for targeted null returns. - **E / 1ecced66:** Subtraction-based `range_guard.hpp:12-16` correctly admits continuation ending at262144 and rejects overflow/excess despite reserved allocation cells.
