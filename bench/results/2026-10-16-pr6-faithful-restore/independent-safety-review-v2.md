## Prioritized remaining findings

**D1 — high, source-proved inherited wait/progress defect: a pending queue is reported as finished.** At `sycl/src/core/session.cpp:1370-1384` and V:1541-1558, the value returned by `ext_oneapi_empty()` is discarded inside `DPCT_CHECK_ERROR`. Original `sycl/include/dpct/dpct.hpp:92-102` evaluates its expression, then returns `dpct::success` (0) whenever it does not throw. Consequently `q != 1` is true for *both* an empty queue and an ordinary nonempty queue. Trigger: the mapped sequence has not reached `want` when the approximately 2 ms polling interval expires, and the query returns normally. The code reports “graph finished” and returns false even if the graph is pending. The new async handler does not repair this boolean/error-code confusion, and a failed receipt from this branch must not be treated as proof that the graph actually finished. This is not proof of a particular downstream free or driver fault. Minimal repair: preserve and interpret the query boolean separately from exceptions; consume async errors explicitly; on abandonment retire/release the actual graph's work or fail-stop before returning to owners. Main should cover pending, genuinely complete-without-ring, provider exception, and slow-but-valid progress. Intel defines this API as a boolean completion query in the [queue-empty extension](https://raw.githubusercontent.com/intel/llvm/sycl/sycl/doc/extensions/supported/sycl_ext_oneapi_queue_empty.asciidoc).

**D2 — high for malformed public input, source-proved inherited arithmetic/admission gap.** M:904-907 validates IDs and count, but not `cell0`, the residual pointer or the destination context span. For valid `n=1`, valid token IDs and `cell0=INT64_MAX`, M:959-964 forms `cell + 1`, which overflows signed int64. `draft(T=1, p=INT64_MAX, a=0, ...)` similarly reaches M:1127-1131. V:1443-1452 checks IDs/count, then forms `pos0 + T` before rejecting negative/overflowing positions; `T=1,pos0=INT64_MAX` is already signed overflow. Negative positions can pass the existing upper-bound-only check. R6 closes the original out-of-vocabulary trigger; it is not a complete input/bounds gate for these public APIs. Minimal repair: subtraction-based host span admission against physical262144 and the actual session/state limits, plus required pointer checks, before capture, copies, narrowing or additions; account for draft lookahead separately. These are public invalid-input defects, not proof a valid tokenizer/normal CLI workload reaches them. Main may initially exclude these entrypoints with explicit valid-position/one-attempt constraints, but must not call them arbitrary-input-safe.

**D3 — high for enabled concurrent doorbell paths, source-proved missing synchronization contract; hardware outcome unproved.** R7 fixes allocation, not signaling. `sycl/include/strata/sycl_doorbell.hpp:14-21` uses device system-scope relaxed atomic operations, while `session.cpp:1353-1397` and V:1515-1601 concurrently use ordinary volatile host loads/stores; host fences do not change those accesses into matching atomic acquire/release operations. The device ring/wait code at `sycl/src/kernels/cuda/elementwise.dp.cpp:370-389` does not supply that missing host contract. Nor does the allocator establish `usm_atomic_host_allocations` or a matching payload-publication proof. This is a concrete missing language/capability contract, not a claim that host USM itself is illegal, nor a measured hang. Keep native paths using this handshake held until Main replaces it with checked completion boundaries or specifies and qualifies compatible atomic accesses, scope, capabilities and payload ordering on both sides. A model-free event-copy check can avoid this protocol. The [SYCL host-USM rules](https://github.khronos.org/SYCL_Reference/iface/usm_basic_concept.html) distinguish accessibility from synchronized concurrent access.

**D4 — medium, source-proved inherited failed-reload state defect.** `NativeEmbed::load` mutates `row_` and `bytes_` at N:185-186 before payload admission, and returns false at N:188-192 without clearing an earlier `dev_`, `type_`, `n_embd_` or `n_vocab_`. Trigger: successfully load an IQ table, then attempt a same-shape supported BF16 table with a truncated payload, then use the existing object after the second load returns false. `vocabulary()` still reports the previous nonzero vocabulary; both admitted gather at N:284-288 and `gather_one` at N:312-315 combine the old allocation/type with the new BF16 row stride. A valid high token can therefore address beyond the old allocation. No concurrent mutation is needed. Normal generator startup loads once and checks failure; this is not proof that it performs this retry. Minimal repair: enforce a one-attempt load before any member mutation, or build all table metadata/storage transactionally and publish only a consistent successful replacement; invalidate on failure if rollback is not supported. The original R6 initial-load one-past-ID trigger is repaired, but the public repeated-load case is not.

**D5 — medium, source-proved deadline/report mismatch.** P:2615-2617 wraps the destructor's issuer join in a 60-second watchdog, but the normal explicit join at P:4036-4037 has no such local watchdog. If the issuer blocks in an unwrapped provider operation such as P:2658, this join is governed only by the enclosing `run` deadline of 7200 seconds at P:1932. It is finite under the stated OS scheduling assumptions; it is not the claimed 60-second bound for every issuer join. Minimal repair: apply the same bounded join contract at the explicit join, or narrow the documented deadline claim and supervise it accordingly. This finding does not establish a DMA source lease failure.

No additional definite *new* event-publication, default-queue destruction or normal-input math defect was established in the correction diff. The inherited findings above and the unexecuted gates below prevent a whole-route safety judgment.

## Event, queue and lifetime analysis

**Stager:** P:338-374 increments active before claiming and checks stopping before and after retirement. For wrap job `j`, it acquire-observes `issued > j-kRing` before copying the prior event; P:414-418 writes the actual DMA event before release-publishing issued. The issuer first acquire-observes job-ready at P:407-409; that ready store occurs only after the worker has retired the prior event and finished its CPU copy. This supplies the handoff before the next event overwrite. The generation check in P:377-403 prevents an old-generation claim from consuming a new generation's metadata; finish first cancels claims, releases issue gates, then waits active workers and retires events (P:425-431). A late failed old claim accesses no job storage. StagerDone is declared before IssuerJoin, so unwinding joins the issuer before finishing the stager; layer-major has its own inner Restore ahead of local cache/residual destruction. No counter-based release remains.

This proof assumes serialized start/finish by the owner and completed previous finish before start, as the inspected call sites implement; it does not authorize concurrent public calls on one Prefill. Source read failures now fail-stop rather than publish fabricated zero data. Default-constructed event slots are complete by the [SYCL event contract](https://github.khronos.org/SYCL_Reference/iface/event.html). Provider event copy/status/wait behavior must still be tested rather than inferred from this handoff.

**PLE:** `ple_gather`, its referenced locals and error string precede `ple_next` (P:2250-2267), so destruction joins the future before referenced storage dies. P:2397 consumes the current future before uploading its buffer. P:2410 stores the actual copy event, and P:2416 retires the *other* buffer's previous upload before starting that refill. There is one refill future; `ple_read_ms` is read after joining. Request cleanup retires accepted queue work before reusable Impl storage can be released; layer-major's inner Restore protects its local residual/cache owners. A failed/cancelled session is not transactionally rolled back: discard it or RESTORE. A failure return is not a reusable partially advanced state.

**Retirement/deadlines:** `sycl_retirement.hpp:8-25` accepts only complete status, then calls `wait_and_throw`; queue retirement places a terminal barrier and calls `throw_asynchronous`. Status exception, noncompletion, blocked provider call, failed barrier submission and uncertain transfer recording route to exit86, not to ordinary unwinding/free/publication. The watchdog mutex, condition variable and done flag precede the thread; the destructor sets done under lock, releases it, notifies and joins before member destruction (`retirement.hpp:21-39`). The watcher only observes those still-live members and exits the process on timeout. Nested watchers are independent, so the earliest live deadline wins. Thread creation failure, OS scheduling and external process supervision remain limits; this is no proof of driver health. D5 identifies a real bound discrepancy. Calls to this helper during graph recording are not qualified: Main must prove retirement is outside capture, or abort capture and prove its queue state before attempting an ordinary barrier. No recorded graph event may substitute for a terminal event of accepted work.

**Same queue:** P:969-977 explicitly requires an in-order queue in the allocation context/device and sets `copy=cs`. Examined ring dependencies are snapshots of already submitted events; slot-used publication precedes the release of `a_consumed`, and issuer acquire-observes that handback before reuse. I found no necessary new dependency cycle from this alias alone. It serializes uploads with consumers and allows extra queued work between an upload and its marker; that can increase latency. It does not prove multithreaded provider submission or event-query progress on the installed stack. Ring2, partial tails, more than two wraps, skipped experts, inline/threaded issuing and cancellation require actual finite qualification.
