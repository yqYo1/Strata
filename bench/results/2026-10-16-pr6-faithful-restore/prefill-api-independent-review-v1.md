## Ranked findings

### H1 — high: C++20 requirement is absent from the sibling executable

`CMakeLists.txt:118-128` creates the harness in the parent directory and copies only `strata_prefill`'s COMPILE_OPTIONS and LINK_OPTIONS. The `CMAKE_CXX_STANDARD=20`, REQUIRED and EXTENSIONS settings are local to `sycl/CMakeLists.txt:15-17`; no PUBLIC/INTERFACE cxx_std_20 requirement propagates through the libraries. CMake generates a standard flag from the target property, rather than making that generated flag part of COMPILE_OPTIONS. The parent target therefore has no enforced C++20 mode unless the invocation supplies it externally. The delivery recipe does not supply it.

The new TU needs `std::endian` (:49), `std::rotr` (:94-95), `string::starts_with` and associative `contains` (:176-185). With a pre-C++20 compiler default, the advertised target cannot compile. Declare the new target's CXX_STANDARD=20, CXX_STANDARD_REQUIRED=ON and CXX_EXTENSIONS=OFF, or an equivalent sufficient feature requirement. Actual configure/compile commands remain unobserved. CMake's [target standard property](https://cmake.org/cmake/help/latest/prop_tgt/CXX_STANDARD.html) documents initialization at target creation; its [variable scope rules](https://cmake.org/cmake/help/latest/manual/cmake-language.7.html#variables) explain the child directory scope.

### H2 — high: native PLE key can be smaller than the fixed kernel reads

`wire_ple` (:254-264) checks the native key pointers and supported type, without admitting its ne0/ne1/elements against the fixed PLE shape. `check_all` checks layer/GDN/QSA tensors but omits PLE tensors. `NativeDense::load` verifies each GGUF projection against the corresponding pack WeightRef, then allocates for those supplied dimensions; agreement between two inputs is not agreement with PLE's fixed operator.

Concrete trigger: keep all ordinary model and expert geometry valid, but give the quantized native PLE key matching index/GGUF shape `[2560,256]` with supported Q8_0 type8 and a correctly bounded payload. NativeDense accepts and allocates that smaller matrix. The harness accepts its native pointers/type. With the harness's postops=true, `prefill.cpp:2768` calls `Gemm::native(..., nb, HD=10240, N=2560)`. `gemm.dp.cpp:488-506` dequantizes that fixed 10240x2560 matrix without allocation metadata; its read exceeds the uploaded small key. This is a concrete missing caller extent check, not speculation about a provider implementation.

Require ne0=2560, ne1=10240, elements=2560*10240 in both native and unquantized key arms before inference, preserving existing representation/type checks. The BF16 arm already enforces total bytes but still admits a same-size transposed shape. NativeDense's existing match to the GGUF will then connect the admitted native shape to its actual allocation. No kernel or math rewrite is needed.

### H3 — medium: the PLE table need not cover the artifact's hash domain

`PleTable::open` validates declared rows/bytes/type; it does not require PLE_TABLE_ROWS=320001536. `wire_ple` assigns fixed `ple_artifact_consts()` and `ready()` only checks an open table and nonnull fields. A separate one-row IQ4_NL PLE-only GGUF can pass open/wire checks while real model shards/pack remain valid. `ngram_rows` uses the fixed sixteen domains; `read_row` (:350-352) replaces missing rows with zeros without reporting failure. The harness can therefore finish with finite values for the wrong table, still correctly labeled UNCOMPARED but without rejecting the incompatible fixed geometry.

Require `r.ple->rows() == kernels::PLE_TABLE_ROWS` before inference. This is a fixed model representation gate, not a demand for new model authentication, new synthetic inputs or a whole-repository parser audit.

### H4 — medium: no concrete small-input gate exists in this delivery

The parser (:141-142) rejects every count<32768. The delivery explicitly acknowledges that the required tiny/odd-tail/continuation gate must be separate; the validation tree contains this one native harness plus six ordinary host helpers. Thus this harness cannot be Main's first small-input full-model gate. This is an acknowledged missing validation capability, not proof that its long-input path bypasses a runtime check.

The next source step can be narrow: explicitly admit validation-only short real token files in this harness, or author a separately reviewed native small-input harness, while retaining the benchmark minimum for long speed samples. Keep chunk8192 and context at least8192: Prefill::init rejects chunk>session.max_cells, so merely lowering count while making context=count would still fail. A 1-token, then small odd-count fresh-position-zero gate can exercise the same fixed 48-layer model and layer-major mode2 after provider qualification. The source admission change must also handle the single-token predecessor explicitly: current :466 indexes `ids[ids.size()-2]`, safe only under the existing long minimum; the expected two-token window for count1 is [-1,last]. Its effective first-chunk receipt (:477) must use min(chunk,count), matching run_impl, for inputs shorter than8192. Lowering the parser minimum alone is therefore insufficient even with context8192. A reduced-geometry toy model is unsupported by this engine; “tiny” means input/work extent here, not invented smaller weights. Continuation needs a separate API call/state-comparison gate because this harness only runs once at position0. None of these changes or runs were made. Never interpret the current minimum as permission to jump directly to32768.

### H5 — low: QSA pinned host staging is lost before explicit cleanup completes

`qsa_state_init` allocates host_step and host_pos for each of twelve states (`layer.cpp:683-707`). QsaState is a pointer-only struct without a freeing destructor. `session_release` only unregisters owned RoPE (`session.cpp:135-140`), while Runtime close (:235-236) immediately deletes the descriptors. It never frees those host allocations, including a partly initialized state's nonnull fields. A complete fixed session loses24 pointers, 12*((kStepCount4+1)+n_head24)*4 = **1392 requested bytes**, plus allocator overhead, until process exit. This is bounded in this one-shot child and is not a GPU use-after-free finding. Free those nonnull fields after existing retirement and before deleting their descriptors if claiming complete explicit owner cleanup; no historical source edit is required.

### H6 — low: optional capture ignores close failure

The opt-in capture checks fwrite and fflush (:470-473), then lets a unique_ptr deleter discard fclose's return. A close-only failure can therefore precede an otherwise successful capture receipt. Explicitly check its single close if retaining the delivery's “capture write failure remains failure” contract. Successful fflush already checks buffered writes; this issue does not require fsync, a new persistence protocol or a new hold on runs without capture. No close failure was observed.
