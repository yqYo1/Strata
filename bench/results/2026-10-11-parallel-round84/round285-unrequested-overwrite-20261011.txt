## Source invariants at chunk boundaries

In this D source, `Prefill::run` routes to layer-major only under the explicit layer-major setting; otherwise `run_impl` is the chunk-major loop (around lines 2436–2444). `run_impl` computes `T=min(m.T,n-c0)` unless the separately configured first chunk applies, advances `c0` by the actual `chunk_len`, and sets absolute `p0=pos0+c0` (around 3030–3040 and 3077–3086). For the controller’s `n=32767`, `first=0`, fixed `m.T=12288`, the only valid partition is 12,288 + 12,288 + 8,191, ending at positions 12,288, 24,576, 32,767. Position, chunk length, and order must remain continuous across all 30 layers.

Stateful components make boundary continuity testable. PLE gathers each row from the prior two token IDs, advances that two-token history across every row, and stores `ss.ple_prev` after the complete walk (around 3026–3034, 3239–3245, 5390 onward). Each GDN layer projects the chunk, runs `gdn_conv` against that layer’s current convolution state, then `gdn_recurrence` against its recurrent state for the same `T` rows (around 3760–3783). Each QSA position gets a step record from absolute `p0+t` (around 3260); K/V writes use those positions, while indexer appends cover all `T` rows before selection/attention for those queries (around 3848–3914). A partition bug should first show as a wrong position, missing/duplicated row, changed recurrent/indexer/KV state or top-k decision at the first affected boundary; it is not excused by approximate GEMM arithmetic.

Chunk-specific allocation is sized from supplied `chunk` (`m.T_max=chunk`; host token/transfer buffers use `size_t chunk`; around 1051–1125). Scratch takes `T`-scaled extents, attention uses `min(requested,T)`, and loops cap their final sub-batch with `min` (around 923–931 and 3890–3930). The reviewed D path contains no requirement that `T` be a power of two or a 256-token multiple. `12,288=48×256` is an arithmetic convenience, not a safety or correctness proof. The actual admission record and allocation success still govern this run.

The QSA step stores positions/counts as int32; the SYCL helper rejects `pos<0` or `pos>=INT_MAX` (`src/kernels/sycl/kv.cpp`, `qsa_step_fill`, around 253–262). A 262,144-token context’s largest cell position, 262,143, is below that explicit limit. Per-chunk 12,288 row counts and `T`-scaled byte extents are also far below 32-bit limits when widened to the source’s `int64_t`/`size_t` extents. The selection kernel’s `kTopkMaxCells=32768` is a bound on its selection work/scratch (`include/strata/kernels/qsa.hpp` around 279–282), not a statement that the model context is capped at 32,768: the source separately tracks QSA state capacity and active blocks. This source review found no 12,288-specific integer overflow or power-of-two restriction. It is not a proof of every downstream allocator/kernel for a full-context run; check their capacity/error paths and runtime context admission separately.

The caller batches prompt positions `[0,n_prompt-1)` and processes the last prompt token in the token loop (`generate.cpp` around 11672–11809). 2. If the first changed layer is GDN, compare its incoming hidden rows and projected QKV/gate inputs, then convolution state/output, recurrent output/state, and output projection in that order. Correct positions and identical inputs with the first deviation only in a T-row projection point toward a GEMM shape/kernel path; a deviation at the first row after a boundary in convolution/recurrent state points toward carry/order/state advancement.
3. If it is QSA, compare the indexed positions and K/V append positions/counts, indexer block/tail state, per-query selected IDs, then attention output. Identical inputs with changed scores/values can be numerical; changed selected IDs are a discrete top-k transition and can amplify small score differences. A missing/duplicate position, wrong `n_kv`/`n_bid`, or incorrect prefix/tail cell is a semantic failure, regardless of the downstream head.
4. If routing changes, use the already-off-by-default census only in a deliberate diagnostic rerun; compare per-layer/per-token selected expert IDs and counts to identify the first route decision. Same routes with changed expert projection values favors numerical accumulation; a route change is a discrete divergence, not a GEMM tolerance result. ## GEMM tolerance versus acceptance

Changing T changes the row count of projections and can change GEMM dispatch, tiling, reduction grouping, or fused-kernel choice. The source itself calls the QSA score tensor-core path “FP32-level, not bitwise” (around 3898–3903). A targeted internal GEMM comparison may therefore report absolute max error, relative RMS, finite-value status, shape, backend/kernel, and identical input hashes against an independently computed same-shape reference; tolerance must be justified from that measured implementation/reference pair. Do not borrow an unexplained global tolerance from the final logits or from the old rejection.

That diagnostic tolerance does not loosen the candidate’s acceptance contract. The controller defines the math gate as all 66 live state parts equal, first-head hash equal, greedy IDs/logprobs/MTP counters and finish reason equal, plus exact chunk protocol. If the accepted gate requires exact hashes/equality, any mismatch remains a rejection unless the parent explicitly revises the gate based on a separately approved, measured numerical criterion. A small internal GEMM delta can explain a first local deviation; it cannot on its own establish semantic correctness, full state parity, or output correctness. Conversely, exact outputs with a failed state comparison do not pass the full-state requirement.
