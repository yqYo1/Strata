## Quality hooks actually present in the compiled source

Because the compiled source input is the `sycl/src` generator above, its quality hooks are the hooks found there (and are also present in matching WNEW `sycl/src` content):

- `STRATA_DUMP_FIRST_LOGITS` is read in the serve generation loop around lines 11190–11195, immediately after the first `ver.run`; the comments identify this as the first verifier window run over the state left by prompt processing. It writes one vocabulary-sized row from `ver.copy_logits(0, ...)`. The standalone generation path has its own first-window dump around 12484–12489. This hook can capture the next-token distribution after a batched prompt has left its state and the final prompt token is processed. It does not force a reference completion, and one row does not score the full completion.
- `STRATA_LOGPOS` is read only in the serial `read_windows` prompt-reader path around 9944–9982. That loop creates `win[t]=cur[q+t]` and `nxt[t]=cur[q+t+1]`, runs the verifier on `win`, then calls `ver.window_logprobs(nxt, T, q, ...)`. `window_logprobs` records target log-probability, argmax/agreement, extra-token mass and optional top-K details from those verifier-window logits (`sycl/src/core/verify.cpp` around 2443–2493). Setting the hook disables the pipelined window variant so the serial loop can inspect each window.
- These hooks do not turn a long segment handled by `Prefill::run` into verifier-window scoring. A long fresh prompt still follows the configured batched Prefill path; `STRATA_LOGPOS` observes only tokens actually sent through `read_windows`. The first-logits dump is useful for the first prediction following the batched prompt, but it neither forces the expected first completion ID nor gives paired token scores for the remaining fixed completion.

Therefore R291 was right that a teacher-forced hook exists in the source family, but its generator hash was misattributed and its description must not be read as complete scoring of a candidate batched-prefill continuation. R294's path limitation applies: LOGPOS alone is insufficient for a paired NLL comparison of a long batched Prefill plus a fixed completion. A valid harness must capture the first distribution after the actual candidate Prefill/final prompt token, score completion token 0 against that row, force token 0 into the state, then score the remaining fixed tokens on the same candidate continuation and assert exact target-position coverage. Keep quality traces separate from timing.
