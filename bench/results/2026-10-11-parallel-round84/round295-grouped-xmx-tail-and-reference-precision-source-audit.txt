Tail, empty-expert, and collective control-flow findings
`xmx_gemm_grouped` chooses a 128-row x 256-column workgroup tile, computes launch capacity from caller-provided `max_rows`, and launches `G * tiles_m * nN` workgroups. In `GroupedKernel`, each workgroup derives one expert and row/column tile. All work-items in that workgroup read the same two bounds values and evaluate the same `tm * WM >= rows` branch. Thus empty experts and capacity-only row tiles return uniformly before any matrix operation; there is no divergent early return within a subgroup. A live tile calls `tile_any` uniformly. `tile` has no explicit barriers; its matrix objects and operations are subgroup-scope collectives.

For actual row/column tails, `tile_any` selects the checked path when either workgroup tile crosses `rows` or `N`. The accumulator is initialized to zero because this grouped path uses the default `ACC=false`; it does not read old Y. A row-tail A load uses `joint_matrix_load_checked` with height `rows` and width `K`. The checked store bounds the accumulator write to `rows x N`. K is iterated in 32-element chunks and then 16-element matrix steps; the public shape admission requires `K >= 32` and `K % 32 == 0`, so no K-tail mask is required for admitted input. The qualifier's production shapes K=2560 (GU) and K=640 (Down) meet that condition.

B is row-major `[N,K]`, loaded as a column-major matrix tile to represent `W^T`: `W + bn[j]*K + k`, with stride K. On a column tail, `bn[j] = min(n0+j*TN, N-TN)` repeats the last wholly in-range 16-row B window for matrix columns whose outputs will be masked by the checked C store. This avoids a B load beyond W; because `N` is admitted as a multiple of 16 and at least 16, `N-TN` is a legal row start. Grouped weights use `W + ex*w_stride`; the qualifier's `N*K+32` half-element stride adds 64 bytes and satisfies the implementation's 64-byte stride alignment check.

The qualifier cases (1, 127, 128, 129, 257, sparse counts 0/1/129/257/0, and all-empty) are pertinent to tile boundaries and sparse expert assignment. Its empty case uses max_rows=1, so it still exercises a launch whose expert workgroups uniformly return. The shape cases are still synthetic: they do not prove arbitrary caller bounds, device-memory extent, or malformed strides safe. The qualifier checks exact output guards and inputs/bounds/weight guards for its own cases; all-empty output must remain at the prefill sentinel.

Source-level validation gap / bug assessment
No tail-mask or collective-uniformity defect is evident for valid caller inputs in the audited path. The exposed API contract says `max_rows` bounds each expert but does not state all required memory preconditions. The implementation only checks `xmx_gemm_ok(X,W,Y,N,K,N)` and `(w_stride*2)%64==0`; it does not check `w_stride >= N*K`, bound monotonicity/nonnegativity, that final bounds fit X/Y allocations, or that each expert count is at most max_rows. Those are safety-critical caller invariants: a too-small aligned stride or bad bounds can address outside storage or under-size the launch. The finite qualifier supplies valid inputs and therefore does not close this API-contract/validation gap. This is a hardening/specification gap, not evidence that the production route violates it. The multiplication in `w_stride*2` also has no overflow guard for hostile extreme values; normal model dimensions are far below that range.

Numerical-reference audit
The qualifier independently decodes fixture FP16 bit patterns to FP64 and forms each dot product with FP64 multiply/add, comparing actual output to the exact-input dot-product reference. Its recipe argues fixture products are exactly representable and its full sum fits FP64 precision; for the deliberately restricted normal half operands and bounded K this is plausible, but it remains the qualifier's fixture-specific mathematical claim. The proposed `gamma32` allowance uses `2*K` ordinary FP32 rounding steps plus a small FP64/reference-output term and `sum(abs(x*w))`. It is a conventional conservative bound if the implemented dot product behaves like sequential FP32-rounded products/accumulations (or an implementation covered by that model). The source does not establish this model for XMX/DPAS reduction order or internal precision.

Intel's official experimental `sycl_ext_oneapi_matrix` spec defines the operation mathematically as D=C+A*B and says matrix operations are subgroup collective functions requiring converged control flow. It does not state a forward-error bound or prescribe sequential FP32 rounding for XMX accumulation. The SYCL `joint_matrix` API is explicitly experimental. Accordingly, `gamma32` is a predeclared qualification hypothesis, not a spec-derived guarantee. A pass would demonstrate this fixture/device/library stays within the bound; it would not establish error behavior for all finite FP16 values, exceptional/subnormal/overflow cases, other devices, or model quality. Do not enlarge the tolerance based on observed outputs. If it fails, record the mismatch and separately establish the target's accumulation semantics before deciding whether the bound or kernel is wrong.
