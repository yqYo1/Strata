## New concrete mismatch: OFF accepts a damaged observer marker

`issuer_ledger.validate()` only treats a line as an issuer row when the exact current marker is a substring (`issuer_ledger.py:57-60`). With `enabled=False`, it then accepts any capture containing no exact marker (`issuer_ledger.py:61-63`). Thus a malformed or version-corrupted issuer record such as `[prefill-issuer-host-v0] ...` is silently ignored and OFF is accepted as “absent,” even though the expected OFF invariant is complete absence of observer output. Enabled mode catches the analogous loss because it requires the full row count; OFF has no independent row count, so it does not.

Smallest Main-owned CPU fixture: call `issuer_validate('[prefill-issuer-host-v0] unexpected=1', enabled=False, transfers=..., census=..., n=64, chunk=8192)` with already validated fixture joins and require rejection. A narrow parser fix is to reject lines beginning with the observer-family prefix (for example `[prefill-issuer-host-`) unless they carry the exact supported marker and valid row grammar, including in OFF mode. This is a fail-closed parser refinement, not evidence of a production emission or a runtime failure.
