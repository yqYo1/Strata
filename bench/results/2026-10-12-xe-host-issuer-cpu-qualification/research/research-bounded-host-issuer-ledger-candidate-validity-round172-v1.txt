## Source findings

The candidate does instrument the four nonresident issuer copy sites: inline and threaded fullstream `copy_async_after`, and both local `stage_one` branches using `copy_async`. `entry()` is reached after the successful copy path and existing completion bookkeeping; the staged wait and copy wrapper are timed separately. The `submit_op` label distinguishes `copy_async_after` from `copy_async`, so the two wall intervals are not falsely represented as the same wrapper. `wait_slot()` queue-wait submission, `issued_one`, and event-record work are outside the local raw-copy span; the output does not label that span as total issue time. Direct entries correctly receive no stager wait sample. (Header lines 44–58, 70–84; prefill lines 1466–1479, 1529–1543, 2351–2369, and 2637–2655.)

The threaded producer is the sole writer while it runs. `issuer_timing.emit()` occurs after `issuer.join()`, producer-failure rethrow, stager-failure check, and `chunk_stager_done.complete()`, so the consumer does not snapshot the producer-owned vector before join or before queue drain (prefill lines 1520–1550 and 2925–2939). The aggregation is bounded by layer count and three fixed kinds, with fixed-size output and no expert identities. Empty buckets remain ineligible because `entries != 0` is required.

The callback seam in `measure()` allows CPU callers to verify that the supplied operation is invoked once and that its exceptions propagate, and the constructor can force enabled/disabled mode. It does not provide a clock seam, bucket seeding/inspection, or an output sink. `Clock::now()` and private metrics are hardwired (header lines 13–18, 24–31, 39–51, 73–84); deterministic regression and near-overflow cases cannot be constructed through the public API. A useful source-level CPU fixture can check disabled call-once behavior and ordinary aggregation via emitted output capture, but it cannot directly force regressing timestamps or counter overflow. No fixture was run.

## Concrete defects / limitations for Main

1. **Default mode still does repeated environment work and per-entry dispatch.** `IssuerTiming::requested()` calls `getenv` and exact-string comparison each time the object is constructed (header lines 35–40; prefill line 1393), and that construction is once per chunk. Further, every issuer copy path calls `measure()` and computes `timing_kind` while disabled; `measure()` performs a runtime enabled branch and invokes the closure (header lines 44–45; prefill lines 1462–1472, 1525–1535, 2346–2360, 2632–2646). It avoids allocation and extra clock reads when off, but it is not a no-default-cost observer. The implementation report acknowledges the branch/lambda and classification; this audit confirms the concrete scope and adds the repeated per-chunk environment lookup. If the intended contract means zero observer overhead when unset, this candidate does not meet it. If that contract permits bounded dispatch overhead, record it as a limitation and measure observer off/on before using timing data.

2. **Overflow cause is hidden in the wire record.** Checked `add()` sets `accounting_valid_ = false` without wrapping (header lines 19–22), and that only forces `coverage_complete=0` (lines 63–69). The emitted record includes neither `accounting_valid` nor `counter_overflow` (lines 73–84). Counter overflow and other coverage mismatches therefore serialize identically, while `clock_valid` can remain 1. Concrete counterexample: two `entry()` calls for a bucket with byte counts `UINT64_MAX` and `1` leave the serialized `expert_bytes` at `UINT64_MAX`, set `coverage_complete=0`, but provide no indication that the reason was overflow. Consumers must reject eligibility, which is safe, but cannot audit the failure mechanism from the record. Add an explicit overflow/accounting-valid field if this ledger is expected to diagnose overflow as requested.

3. **No deterministic validation of clock regression/overflow from the current seam.** The defensive branches exist (`end < begin`, negative duration, checked sums), but there is no injectable clock and no accessible seedable metric; real steady-clock execution cannot practically drive metric counts or nanosecond sums to overflow in a CPU fixture. This leaves the requested invalid-clock and overflow semantics source-reviewed only unless a narrow injectable clock/accounting seam is added. The issue is independently visible from the missing serialized overflow flag above.
