## Result

The active fallback is not inherently a oneMath grouped GEMM. `Gemm::f16_groups` is a dispatch shim: in a build with `STRATA_ONEMATH`, it attempts separate oneMath FP16 GEMMs per nonempty expert only when `gemm_path(FP16)` reports `DP4a`; if any per-expert call rejects, it returns false and the caller queues `xmx_gemm_grouped` for the entire group. In a free build (`STRATA_ONEMATH=0`) it always returns false, so the fallback directly selects XeStrata's grouped kernel. The supplied current `build/free/compile_commands.json` records the free-mode compile, `-O3 -DNDEBUG`, `-fno-fast-math`, `-ffp-contract=off`, `-fsycl`, and source-built clang++ under the v7.1.1 install. It points at an LLVM build in a different worktree; the supplied compiler provenance (v7.1.1 + 17 patches) is user-provided, not independently validated here.

With free mode, the device-kernel choice remains runtime-dependent:

* Intel XMX path: `xmx_gemm_grouped` selects `GroupedKernel<128,256,3>` when `xmx_available(f16)` is true and portable MMA is not forced. `xmx_available` requires a device-reported FP16 matrix combination (8x16x16, FP32 accumulator, subgroup 16) and a successful `large_grf_ok` executable-bundle check. The path can still fail at launch; the existing code has no catch-and-fallback around that grouped XMX launch.
* Portable `joint_matrix` path: selected when `mma_usable(q,false)` and either `STRATA_MMA=1` or Intel XMX is unavailable. Admission checks the device-reported FP16+FP32 matrix combination/subgroup and the chosen grouped shape's local-memory/work-group bounds. `STRATA_NO_XMX=1` disables this route too unless `STRATA_MMA=1` forces it.
* DP4a grouped path: fallback when neither selected matrix route applies. Its subgroup and tile choices are device-reported in `dp4a_gemm_grouped`; it does not use oneMath in free mode.

The source's *advertised* `gemm_path(FP16)` can say `joint_matrix`, `XMX` or `DP4a`, but the grouped dispatcher uses a related, not identical, condition: the `STRATA_MMA` force flag can send grouped products to the portable implementation even when the ordinary path string is XMX. Thus the startup path string alone is not a complete receipt for `xmx_gemm_grouped` selection.

This resolves the broad route uncertainty for the supplied free build, but the exact B570 branch is not established by this static audit: no device query was allowed, and no live selected kernel/image receipt exists here. `STRATA_PREFILL_FUSED=0` removes the resident packed-IQ path from this arm. Compact grouping only partitions the fallback rows; it does not change the FP16 dequant + dense product arithmetic. No new algorithm candidate is eligible from this evidence. Do not reopen the R173 staged packed-IQ fusion proposal or treat the R174 llama.cpp gather claim as compiler-only evidence.
