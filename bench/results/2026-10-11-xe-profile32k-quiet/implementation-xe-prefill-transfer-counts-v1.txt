Optional enablement and exact output scope
New variable: STRATA_PREFILL_TRANSFER_COUNTS. Presence enables accounting once
per Prefill::run, including value0 or empty. It is independent of
STRATA_PREFILL_TIMING. To count without heavy PfTimer queries, Main can leave
STRATA_PREFILL_TIMING ABSENT and set STRATA_PREFILL_TRANSFER_COUNTS=1. Do not set
TIMING=0 to turn phase timing off; its existing presence semantics stay unchanged.
No extra clocks or GPU instrumentation are introduced. With transfer variable
absent, all six hotpath counter branches short-circuit before any extent/counter
update, allocation of layer rows, aggregation or output. Empty local diagnostic
vector objects and one run-level getenv remain; there is no claim of byte-identical
stack layout or measured zero host overhead. The routed copy argument is factored
into the same size_t bytes value so the counted extent is exactly the API argument.

One completed diagnostic row is retained for every executed chunk and every layer
in this Prefill stage [LB,LE), including zero-count layers. It records:
  device; stage range; local chunk_offset c0; session pos p0; actual chunk tokens;
  absolute layer; mode=routed or full_nonresident_stream; issuer=inline/thread;
  format=native_gguf or canonical_q2_0; native gu/down type IDs (otherwise -1);
  layer layout blob_bytes; submitted_calls; submitted_bytes.
Format IDs/blob_bytes are immutable layout metadata, while calls/bytes are actual
success-path counters. They are not derived from routed expert count, capacity,
arena size, resident slots or a theoretical all-expert pass. Per-chunk totals can
be reconciled by summing that chunk's layer rows. A completed-run total line gives
routed/full-stream calls/bytes and the combined calls/bytes, with
scope=this_prefill_stage_run and completion=checked. Existing phase text is untouched.
The prefixes are "strata prefill expert H2D:" and "strata prefill expert H2D total:".
Main must preserve final request/process status and not treat a missing/truncated
ledger as zero traffic or a successful run.

Each hook is immediately AFTER its existing production publication::require
accepts the actual copy API result, before later marker/publication actions. It
adds one call and the exact same size_t bytes argument, only when nonzero. Zero
extents do not count as H2D work: production copy_async returns without memcpy
for zero, and copy_async_after omits h.memcpy for zero. Legal pack extents are
positive; this exclusion also avoids labeling an empty dependency submit as H2D.
Failed submission is not counted, and a later failed marker/worker/drain prevents
publication of the entire current run's diagnostic, even if earlier requests were
successfully submitted. Counters are uint64_t; both call/byte updates and final
mode/combined sums check overflow and fail rather than wrap/invent totals.

The full-stream modes count every actually issued nonresident sequence entry,
including entries routing later skips. That is intentional actual traffic; it
does not claim these are all routed/used experts. Routed mode counts only actual
stage_one H2D requests after residency/CPU-selection skips. Direct pinned and
stager-backed uploads are BOTH included: existing experts_dma increments only
the direct path and cannot substitute for this logical H2D call/byte ledger.
MMQ-direct ring and ordinary STAGE targets share stage_one, so both routed target
layouts are covered without changing slot pointers, extents, release order or math.

Format coverage and exact exclusions
The same machinery uses ExpertLayout::blob_bytes(layer): per-layer native raw
GGUF blob sizes when layout.native, otherwise the canonical Q2_0 BLOB. Thus the
ledger includes supported native format pairs and canonical Q2_0 when they use
these six calls; it is explicitly labeled rather than claimed native-only.
Native packing/typed sizes/offset checks remain in the production layout loader;
no alternative arena estimate or extracted selector/copy body is introduced.
Pinned, unpinned and transient/file-backed sources all converge here. The worker
stager's host memcpy/read/copy_blob traffic is not an H2D request and is not counted.

Excluded: resident cached reads/fused resident products; resident-to-MMQ-ring
D2D copy at2124; native MMQ gather/dequant device reads/copies; CPU expert results
activation H2D at2273; routing/token/row/bounds/PLE/embedding/QSA/KV/residual copies;
D2H diagnostics/activations and all host memcpy/file IO. Startup/cache profile
fill, post-prefill cache refill/restore, decode/MTP/expert-source/kernel-read alias
traffic, a different layer-major implementation and transfers outside this
Prefill::run are not part of the completed total. This is a complete source-level
ledger for the six blob-staging calls in this implementation, not all engine/model
traffic. A zero row means no successful nonzero expert-blob upload request for
that layer/chunk; it does not mean no weights read from RAM/device/cache.

Thread ownership, publication and failure safety
A chunk_transfers vector is optionally sized to LE-LB BEFORE any issuer thread
or its RAII join guard is constructed. Exactly one path writes it:
  full stream + threaded_issue: only the existing issuer worker;
  full stream + inline: only issue_until on the consumer thread;
  routed: only stage_one on the consumer thread.
The inline issue_until path is not invoked when threaded_issue is true: its
initial call is in the existing else-if, and give_back selects atomic publication
instead of inline issue. Routed staging is mutually exclusive with stream_all.
The main thread performs NO live read/aggregation of worker counters, not even
at each layer boundary. No worker increments a shared run-total or vector size,
and no new atomics, mutexes, publications or polling are required.

At the existing chunk end, issuer.join happens first, then issuer_failure.rethrow
and existing stats merge, then stager failure checking, then
chunk_stager_done.complete. Only AFTER those succeed is the vector moved into
the completed-chunk ledger. Thread join establishes the host happens-before;
checked existing stager compute/copy drains establish buffer completion ownership.
Full-stream chunk_stager_done owns that drain/finish/rethrow path. Routed mode
already calls stager_done.complete for each layer, draining compute/copy and
finishing/rethrowing the stager before progressing. Its chunk guard is inactive
because every routed layer's stager is already closed; no drain is invented.

On exception/early return, IssuerJoin remains later in declaration order than
chunk_transfers, so it cancels/joins/drains before the counter vector retires.
Worker counter overflow propagates through the original issuer Failure/cancel
contract, not through a new unsynchronized error flag. Existing StagerDone and
run catch checked drains remain unchanged. Diagnostic allocation failures follow
the same original guarded unwind. Unknown/failed completion keeps the original
fail-stop policy; counters never establish completion or authorize buffer release.

No rows/totals are printed at chunk/layer boundaries. After all chunks, the
existing next-stage future has been obtained, final compute sync succeeded, any
enabled final PfTimer fold/report succeeded, and optional GDN-hash checked copies
succeeded. Only at the final path immediately before returntrue does accounting
preflight all totals and print the layer/chunk rows plus completed total. Failed
submission, worker, stager, callback, final sync, timer query or later GDN-hash
diagnostic exits before this new ledger. Earlier collected successful chunks are
discarded with a failed local run; no partial run is labeled complete. Output
write errors/truncation are not a new IO durability protocol: Main must require
the complete final line/rows and actual run status from its capture/observer.

Layer-split stages have separate Prefill::run objects and local ledgers. The
explicit device/stage/position scope prevents treating one local total as a full
model/request total. A child stage can finish locally before another stage later
fails; Main must qualify the overall request before aggregating stage-local
receipts. Existing stdio serialization governs individual fprintf lines; no new
global ordering/request-ID protocol is introduced. Repeated runs with identical
metadata still need the Main-owned observer's request/log boundaries.

Costs and interpretation limits
No additional GPU Event/wait/sync/copy, phase-marker move, scheduler decision,
payload buffer layout, typed extent, model math, cache/context/MTP/bounds or host
handoff admission is changed. Diagnostic counters/allocation/retention/output do
have optional host cost, so a count-enabled arm is an instrumented diagnostic,
not an automatically comparable quiet performance baseline. It works with phase
timing disabled but inherits any unrelated existing Runtime/startup/CPU-sharing
timers selected by normal production policy; it does not globally eliminate them.

Host ledger storage is O(ceil(n/chunk)*(LE-LB)): two uint64_t counters (16 bytes)
per layer/chunk plus vector/chunk descriptors and allocator overhead. The supplied
32767-position/4096-chunk/full48-layer geometry would have8 chunks384 rows and
6144 raw counter bytes, not a prediction of H2D calls/bytes. Very small chunks at
full262144 context can create a much larger host ledger/output; no hidden fixed
VRAM payload, arbitrary chunk reduction or context cap is added to rescue it.
Optional host allocation failure rejects the local run through existing drains.
Extreme small-chunk/high-layer diagnostic memory/output remains unqualified.

Submitted bytes count the logical extent of accepted application H2D requests.
They do not measure physical PCIe packet bytes, DMA engines/service, memory bus
traffic, driver staging/segmentation, protocol overhead, source fault/host copy
traffic, bandwidth, overlap or the request critical-path bottleneck. Neither a
native arena census nor this counter can establish a PCIe roofline/performance
winner without a separately admitted transfer/timing experiment and request
completion receipts. No new magnitude, GPU fault behavior, numerical equality,
model-quality or speed claim is established here.
