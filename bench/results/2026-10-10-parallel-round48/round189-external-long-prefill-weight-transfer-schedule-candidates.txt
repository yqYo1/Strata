# R189 — external long-prefill weight-transfer schedule candidates

Date: 2026-10-10 (Asia/Tokyo). Read-only review of the committed report registry, pinned Strata source, and public primary implementations/papers. No source edit, build, compiler/disassembly, test, model/runtime/payload, GPU/device query, profiler, service, Git, cleanup, or root-owned run was performed. External results below are not B570 predictions.

## Decision

One conditional schedule candidate survived: double-buffer only the *layer-major full-layer expert cache*, starting H2D staging for layer L+1 into an independent second `ExpertCache` while `run_impl` computes all chunks of layer L. After L's compute/callbacks drain, wait for the next-layer copy and swap the active cache. This changes when the same model bytes move; it does not reduce the bytes or number of expert blobs transferred. It is distinct from the ordinary streamed STAGE ring, which already overlaps expert copies with expert compute, and from the R162 rejected proposal to add a second queue for dequant/GEMM overlap. Layer-major's explicit full-layer load barrier is the uncovered seam.

This is a headroom-gated measurement candidate, not an implementation recommendation. It costs one additional complete layer cache (`layer_cache.bytes()` as reported by the existing cache object, plus allocator overhead) while temporary layer-major residual/KV/workspace buffers are live. On a 10 GiB B570 that may be disqualifying. If root's actual memory receipt cannot admit a second layer cache with safe operating headroom, stop without prototyping. No bandwidth assumption, minimum gain, or external speedup is transferred.

## Candidate mechanics and limits

Keep the current active cache immutable while current-layer chunks and their callbacks consume it. Allocate a second same-sized cache; pre-resolve the next layer's source jobs on the issuer thread as current code does, then use the existing worker stager and copy queue to populate the inactive cache while `run_impl` executes the current layer on `m.cs`. Only after current-layer compute, residual/state handoff, and required queue/error drains finish may the code switch `m.cache`/`m.host_res` to the filled cache and begin layer L+1. The independent cache avoids a write/read alias. The route, expert order, packed formats, dequant, oneMKL GEMMs, double DQ buffers, callback boundaries, residual layout and output arithmetic remain unchanged.

The full next layer is loaded regardless of routes, as in the current layer-major implementation; do not claim saved weight bytes. The possible benefit is hiding some or all of a layer's currently exposed staging+H2D interval behind the preceding layer's compute. If per-layer load time is already hidden by prior work, or prefill compute is too short relative to a full-layer load, the extra buffer will not help. Host staging can also contend with active compute/system memory traffic. For 32K and full 262,144 positions, verify the exact mode really selected layer-major, exact `m.T`/chunk count and actual per-layer `layer_cache.bytes()`; do not infer reachability from an environment setting alone.

The publication/reuse contract is demanding: next-cache transfer events must complete before that cache becomes the active layer source; current-cache reads must complete before its slot is recycled for L+2; failure/cancellation must stop the stager, drain all submitted copies, and keep both caches alive until their events complete; callback/state order across layers cannot advance early. Restore the original decode cache/MTP state only after both temporary caches and residual allocations are retired. Preserve standard non-layer-major and decode schedules.

## External implementation evidence

- MoE-CORE v1, submitted 2026-10-01, explicitly says it stages complete expert layers in alternating buffers during prefill. This is a primary design precedent for independent layer buffers and transfer/compute overlap. The paper evaluates Huawei Ascend systems and also reports decode/cache methods; its numbers and hardware do not establish a Strata result. [MoE-CORE paper and version history](https://arxiv.org/abs/2610.01950).
- DuoServe-MoE describes a two-stream CUDA prefill path that fetches the next expert while the current expert computes, with a second expert slot. This validates the general independent-buffer lifetime pattern, but Strata's regular streamed path already does that; it is not evidence for B570 or the layer-major cross-layer extension. [DuoServe-MoE paper](https://arxiv.org/abs/2509.07379).
- The Layered Prefill authors' repository describes changing the schedule axis so a prompt traverses layers once and avoids repeated chunk-driven expert reloads. Strata's layer-major code already reuses one loaded layer across all its chunks, so adopting this broader scheduling change would duplicate existing functionality rather than add a candidate. [Layered Prefill implementation](https://github.com/scale-snu/layered-prefill).
