# R191 — layer-major next-layer prefetch wait and stager contract

Date: 2026-10-10 (Asia/Tokyo). Read-only source and report review. This narrows R189's conditional full-layer double-cache idea to the actual `run_layer_major` → `run_impl` → stager/callback/restore ownership seams. No source edit, build, compiler, test, device query, inference, profiler, service, Git action, cleanup, or prototype was performed.

## Decision

Starting layer L+1 copies on the existing `m.copy` queue before calling `run_impl` for layer L would not normally be stopped by a `run_impl` entry wait or each ordinary chunk callback: those use `m.cs`. It would, however, be forced complete before `run_impl` returns, because its unconditional terminal `m.copy->wait()` drains that same queue (`prefill.cpp:5239-5269`). Optional `STRATA_PF_STEP_SYNC=1` also waits both queues after named steps inside a chunk (`:3490-3502`), so that diagnostic mode would expose the speculative copy at its first step.

The existing `m.stager` cannot safely be treated as an independent next-layer producer. `Stager::start()` assumes prior jobs are finished and replaces the current generation/job storage when nonempty (`:495-510`); `finish()` stops outstanding claims and waits for active host workers (`:531-538`). In the layer-major per-layer-cache run, all current-layer experts are marked resident, so the ordinary per-layer staging job set is empty. In the non-`stream_all` route, the local `StagerDone` still calls `finish()` as `run_impl` exits (`:4616-4619`); it can stop the L+1 prefetch producer. In `stream_all`, its empty job start is a no-op and `StagerDone` is null, but the terminal shared `m.copy->wait()` still removes all overlap before the layer call returns. If the current-layer route ever has nonresident entries, its own nonempty `start()` can overwrite the prefetched generation. Therefore the current queue/stager combination does not permit a useful, robust L+1 transfer to survive through the L computation boundary.

R189's separate full-layer cache remains only a capacity-gated measurement candidate. This audit does not establish actual memory headroom, transfer/compute overlap, execution mode, performance, or unconditional implementation value. Production asynchronous pre-consumer/unwind safety remains unimplemented; retry, cancellation, and error unwind cannot be assumed safe.

## Exact active path and barriers

`Prefill::run` selects layer-major only when `STRATA_PREFILL_LAYER_MAJOR` is set to 2, or set to 1 and the call has multiple chunks (`prefill.cpp:2353-2366`). `run_layer_major` admits only the full single-GPU compact FP16 path (`:2420-2430`), creates one temporary `ExpertCache` for `g.n_expert` entries, and sets its layer-local residency map to slot `e` for every expert before calling `run_impl` (`:2633-2637`, `:2735-2741`). It loops layers serially. Before each layer load it performs `m.cs->wait(); m.copy->wait(); m.stager->finish()` (`:2704-2708`); this is a pre-load boundary, not a barrier at `run_impl` entry. It resolves transient-source jobs on the issuer thread, starts the single stager, submits each expert copy through the single copy queue, then waits for that queue and finishes the stager before computation begins (`:2710-2734`). Thus today's L load is deliberately serial with L compute.

The non-layer-major expert-stream route has a ring: copies go through `m.copy`; copied events are made on that queue; `m.cs` inserts a wait barrier on the copied event before consuming a streamed slot; and the used event prevents refilling a slot while compute still reads it (`:3340-3377`, `:4619-4669`, `:4851-4856`, `:4885-4895`). The layer-major cache-hit case differs: `run_impl` maps the current layer's cache entries through `m.host_res` and `m.cache` (`:4191-4198`, `:4847-4855` and `:4897-4902`), and its resident experts bypass ring staging. This distinction matters: the existing ring's per-slot events do not provide a cross-layer publication/retirement protocol for a second full-layer cache.

For each layer, `run_layer_major` installs callbacks and then calls `run_impl` synchronously (`:2743-2766`). `on_chunk` stores the current layer's residual into the host or GPU handoff backing and waits for a device copy event when needed (`:2747-2760`); `run_impl` waits `m.cs` before invoking those callbacks when a callback is installed (`:5183-5206`). The layer-to-layer residual callback is therefore an actual handoff boundary and must finish before layer L+1 changes inputs or callbacks. The last-layer stage callback delegates to the saved callback only at the final prompt position (`:2743-2745`); final chunk callback/state ordering must also remain intact.

At normal `run_impl` completion, it unconditionally waits the compute queue and then the expert copy queue (`:5239-5269`), even when layer-major's current experts were all resident. Consequently a speculative copy issued earlier to that same `m.copy` queue will be complete before `run_impl` returns; because all work on a SYCL in-order queue is ordered, no later L computation command on `m.copy` is involved, but the host wait itself serializes the proposed overlap at every layer boundary. If the current `run_impl` returns early, its layer-major owner guard also waits both `m.cs` and `m.copy` before restoring pointers (`:2673-2691`). The separate layer-major restore at normal return waits those queues again and finishes the stager before closing the layer cache/device rows and restoring decode cache/MTP state (`:2768-2789`). A queue wait is a completion fence only when it returns successfully; the existing guard does not provide a safe unknown-completion recovery path.

## Shared stager ownership and failure paths

`Stager::start` returns immediately for an empty job vector; otherwise it resets the failure bit, replaces `jobs`, reinitializes ready flags, clears stopping, advances the generation and wakes workers (`prefill.cpp:495-510`). The source comment explicitly says the previous layer's jobs are finished before this call. A worker can be copying a transient expert or host pointer into a pinned/pageable staging slot; it does not mark ready until that host copy completes (`:449-483`). It waits until the prior DMA for its ring slot is acknowledged before overwriting that slot (`:455-461`); `issued_one` records each DMA event and `buffer_free` tests its completion (`:520-529`). `finish` prevents further claims and waits for active CPU workers; it is not a queue drain (`:531-538`). These jobs, ready flags, generation, ring buffers and DMA completions are one mutable ownership domain, not a safe multi-layer job table.

`run_impl` creates `StagerDone` for non-`stream_all` mode and calls `m.stager->start(js)` only when `!stream_all` (`:4592-4619`). With all current-layer experts resident in the layer-major cache, `js` is empty, so `start` does not replace L+1's generation, but `StagerDone` still finishes the shared stager at function exit. In `stream_all`, `StagerDone` is null; the current layer's stream plan skips resident cache entries (`:3286-3335`), and a zero-job `start` cannot overwrite pending jobs. That case is still serialized by the terminal `m.copy->wait()`. If nonresident current-layer entries were admitted, a nonempty current job start could replace the speculative jobs. Do not rely on the route remaining full-cache without making the two producer lifetimes explicit.

On normal success, current `run_layer_major` waits for the copy queue before `finish`, checks the stager `failed` flag, establishes the layer residency map, and then computes (`:2723-2741`). On cancellation between layers it returns before a new load (`:2704-2706`). On failure/cancel while `run_impl` is active, the local `Restore` destructor waits compute and copy, calls `finish`, restores callbacks/cache/residual pointers, and then local buffers unwind (`:2673-2691`). Its waits are plain `wait()`, not `wait_and_throw()`, and the implicitly-noexcept destructor cannot safely turn every thrown drain into a normal returned error. R40/R42/R44 already document why failed waits cannot be treated as proof of retirement and why the production error/unwind owner is still missing. A future speculative job adds another live source and destination to that cleanup. It must be stopped and joined, all submitted copies observed, and both cache allocations kept alive until completion is known; cancellation cannot publish a partly copied cache. If a wait fails with unknown completion, do not swap, free, restore, or retry against possibly live storage.

The current `m.copy` queue is made in-order with profiling (`:1128-1135`). SYCL's queue ordering is per queue, and the blocking queue `wait()` waits for previously submitted work while `wait_and_throw()` additionally dispatches unconsumed async errors. A `queue::memcpy` returns an event; its source and destination must stay valid for the copy's lifetime. These are API-level rules and do not establish this device's overlap or a real failed-driver wait behavior. Primary reference: [Khronos SYCL 2020 revision 12, queue/event/copy semantics](https://registry.khronos.org/SYCL/specs/sycl-2020/html/sycl-2020.html). R42 discusses the local queue-handler/error boundary in more detail.

## Minimum changes before any prototype

A safe prototype would need all of the following before a device comparison:

1. A second `ExpertCache` with the same `g.n_expert`/`MAXBLOB()` layer capacity and an explicit admission receipt that it fits beside the selected run's live residual/KV/workspace state. R189 already owns that capacity gate; this report does not repeat its external precedents or propose another headroom rule.
2. A second in-order copy queue and a second independently owned stager/ring, including its own job generation, host staging buffers, DMA completion receipts, stop/join path, and error status. A second queue alone is insufficient: `run_impl`'s terminal wait on `m.copy` and its `StagerDone` currently bind the schedule and lifetime. If a new queue is used, its asynchronous handler/error drain and copy source lifetime must be integrated explicitly.
3. A caller-owned cross-layer state machine that begins filling only the inactive cache; makes no cache/map visible to `run_impl` until every intended expert copy has completed successfully; waits for L compute and all callbacks/handoffs to finish; then switches active cache/residency for L+1. Reuse the former active cache for L+2 only after L's consumer work is retired. Preserve `m.cache`/`m.host_res` mapping semantics, chunk order, `on_chunk` and `on_stage_chunk` behavior, residual/state publication, and decode restoration.
4. A non-destructor-only completion/error/cancellation path that joins the speculative host producer, fences compute and both copy queues, records async errors, and preserves all owners if any fence leaves completion unknown. The in-order queue wait and callback sequencing must not silently convert an error into success. No generic retry on the speculative path.
5. Proof that the ordinary streamed ring and decode/non-layer-major paths are unchanged and remain independently selected; no reuse of the second-layer cache through those paths without their own mapping/lifetime contract.

These are prerequisites for a prototype, not a request to implement one. No implementation recommendation follows until the normal >=32,768-position and physical 262,144-position model gates in R189 are met and a paired measurement demonstrates exposed current-layer transfer time, safe extra-cache capacity, exact output/state behavior, and repeatable total-prefill improvement. There is no new arbitrary gain threshold and no performance result in this audit.
