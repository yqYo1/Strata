## Source contract for V values

`KV_Q8_GROUP` is 64; Q8 V codes are laid out as `[page][kv_head][page_size][head_dim]`, and scales as `[page][kv_head][page_size][head_dim/64]` (`include/strata/kernels/kv_q8.hpp:5-12,22`). The kernel fixes `HD=256`, `SG` is a compile-time 16 or 32, and each work-group has `8*SG` work-items (`qsa_decode_attn.dp.cpp:19-22,129-130,616-623`). Dispatch can choose `SG=32` for variant 1; variants 2/default and 4 use `SG=16` (`:626-633`). The V pass is the per-dimension loop at `:314-355`; in Q8 mode, each dimension reads its own code and reads `v_scale[row * 4 + dim/64]`, converts that stored half to float, then computes `(float)code * sc` (`:328-335`). The scale is per selected cell and KV head as well as per 64-dimension group.

Let `t` be the local work-item ID used at `:161`, and `dim=t; dim<256; dim+=8*SG` at `:316`. The source's intended lane arithmetic is `lane=t%SG`, `warp=t/SG`. Under the existing contiguous subgroup mapping expected by these kernels, the V ownership is:

| Template | Subgroup `warp` | Subgroup lane | V dimensions owned by lane | Scale groups touched by this subgroup, per dimension-loop pass |
|---|---:|---:|---|---|
| SG32 | 0..7 | 0..31 | `32*warp + lane` (one dimension) | `floor(warp/2)`; each subgroup spans 32 dims wholly inside one 64-dim group |
| SG16 | 0..7 | 0..15 | pass 0: `16*warp + lane`; pass 1: `128 + 16*warp + lane` | pass 0: `floor(warp/4)`; pass 1: `2 + floor(warp/4)`; each pass is 16 dims wholly inside one 64-dim group |

Thus SG32 makes one possible broadcast per selected cell and each subgroup has one scale group. SG16 executes two V-dimension iterations per work-item; each iteration belongs to a different scale group, so it needs a separate broadcast per iteration. Specifically SG16 passes 0/1 touch scale groups 0/2 for warps 0–3, and 1/3 for warps 4–7. Neither layout permits one broadcast to cover all scales used by the whole work-group, and the SG16 pair of scales must not be conflated.

For each selected-cell loop iteration `c`, `n_here` is set once per work-group (`:158-164`), then all lanes visit the same `c < n_here` iterations (`:320`). If a selected row is nonresident, `srow[c] < 0` is also the same work-group-local shared value for every lane, and the early `continue` is uniform (`:149-152,172-181,320-322`). Therefore both short final chunks (`n_here < 64`) and `page_table[cell/page_size] < 0` masked cells skip the broadcast for the entire work-group/subgroups together. The `n_here <= 0` return is before the V loop and is group-uniform (`:163-167`). These cases create no lane-divergent collective at the proposed V scale site.

This analysis covers the kernel's defined short-width/tail and nonresident-page masks. It does not make malformed selected IDs safe: the current source indexes `page_table[cell/page_size]` without a range check (`:172-180`), so selected-ID validity remains an upstream invariant and a separate correctness gate.

## SYCL collective and lane-mapping constraint

SYCL group functions are synchronization points and must be called by all work-items in a group under the same conditions. The Khronos SYCL 2020 specification's group-functions wording and reference require converged control flow; `group_broadcast` returns the source work-item's value to the group. In the default overload, source is the smallest group linear ID; explicit source ID must be identical and in range for all group members. Sources: [SYCL 2020 specification, subgroup execution model and group algorithms](https://registry.khronos.org/SYCL/specs/sycl-2020/html/sycl-2020.html), [Khronos SYCL Reference: group functions](https://github.khronos.org/SYCL_Reference/iface/group-functions.html).

Applied at `:329-335`, a correct broadcast must be inside the `KV_MODE==1` V branch and after the uniform row-validity `continue`. Every lane in each `sycl::sub_group` must execute exactly one broadcast for each executed dimension iteration, with the same source local ID (use subgroup local linear ID 0 or the default overload). The selected source lane loads the same half bits that the original lanes load; it performs the existing half-to-float conversion once, and all lanes receive that float. Every lane still reads its own `v_q[row*HD+dim]` code and performs the same code-times-scale multiply. The existing accumulation `fma(sp[h][c], v, acc[h])`, iteration order, reductions, softmax and masking remain untouched (`:320-355`).

Do not put the collective in a lane-only `if`, a per-dimension-group branch that differs across lanes, or any branch around the `srow`/tail checks that is not uniform. A leader-only load/conversion is safe as ordinary control flow if it reconverges before the collective and all subgroup lanes call the collective; initialize the broadcast argument on nonleaders to a defined value to avoid undefined input evaluation. Prefer to keep exact half bits and conversion intrinsic as currently written (`:329-334`); do not reconstruct scales or alter multiply/accumulator order.

There is a second contract beyond convergence: the scale-ownership table assumes subgroup membership follows the `t%SG` contiguous lane grouping. SYCL 2020 says the work-items composing a subgroup are selected in an implementation-defined way and portable code must not assume a specific work-group-to-subgroup partition (`spec: 3.9.4`, cited above). `[[sycl::reqd_sub_group_size(SG)]]` requests the subgroup size (`:619`), but this static audit did not establish that it guarantees this source's `t%SG` ownership on the pinned compiler/device. Current reduction helpers also use subgroup XOR while the V work is indexed by `t`, so this source family already depends on a suitable lane mapping; that existing dependency is not proof of B570 layout. The table is the exact source arithmetic conditional on the same contiguous mapping convention, not evidence of target execution or a portable SYCL guarantee.

## Smallest safe source branch and qualification boundary

A candidate branch belongs only at the Q8 V scale expression at `:328-335`, leaving `load8_q8`/K scoring unchanged. Use the actual subgroup object and its own local-linear ID rather than deriving the collective's source lane from `t%SG`. In a compiler/device path whose mapping has been qualified to keep all subgroup lanes within one `dim/64` scale group, the smallest candidate is: each subgroup's lane 0 performs the existing indexed half-bit load and half-to-float conversion; all subgroup lanes call one broadcast; each lane multiplies the broadcast float by its distinct Q8 code. SG16 repeats this independently on both `dim` iterations. This branch is eligible only for `KV_MODE==1`; modes 0, 2 and 3 must retain their current paths.

If the compiler/device mapping is not established, a safe but potentially unprofitable source guard is possible: all lanes first call a subgroup broadcast to obtain lane 0's `dim/64`, then all call a subgroup `all_of` predicate that each lane's `dim/64` equals that value. Since both collectives are unconditional at this site, they converge. The resulting predicate is identical for the whole subgroup; only if it is true may lane 0 load/convert and all lanes call the scale broadcast. Otherwise every lane executes the original per-lane scale load/conversion. This preserves correctness for a subgroup crossing scale groups, at the cost of two extra collectives and a uniform branch; static compile-time source mapping qualification is preferable if compiler documentation or an inspected compiler artifact establishes it. No such target-specific evidence is present here.

A still smaller and stronger gate is to defer writing the branch until the pinned compiler/device path can show (via its documented mapping contract or compiler-generated evidence, then a kernel probe owned by root) that subgroup lane IDs and the source's local `t` values align as assumed for both SG16 and SG32. Merely observing that `t%SG` is used as `lane`, or seeing `reqd_sub_group_size`, is not that proof. The source has no per-lane branch at the V expression today, and this report proposes no implementation.
