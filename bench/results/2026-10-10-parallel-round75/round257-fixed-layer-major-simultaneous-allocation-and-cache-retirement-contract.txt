## Allocation order and lifetimes

1. **Model and decode setup remain live.** Dense/device weights, base runtime state, the main `ExpertCache`, and (when configured) MTP draft weights are allocated before the layer-major call. Cache `open`/`open_sized` sizes storage before use and zeros the payload. The main cache's exact current-pack payload is `C0 = cache.bytes()`; its current mapped backing is `C0m = cache.mapped_bytes()`. Neither value is supplied for this source/input. In the common non-segmented case they are equal when fully open. MTP device expert/head backing is `Wmtp = expert_storage.full_bytes() + head_storage.full_bytes()`; no current run value is supplied.

2. **Session init and Prefill init persist through the call.** `session_init` owns the GDN recurrence/convolution state, QSA state and shared QSA buffers, MoE/block scratch and PLE history. The Prefill object owns its token, activation, route, quant/dequant, stage-ring and shared region buffers, plus host stage/stager buffers. The one carved QSA/MoE/PLE/GDN region is sized to the maximum of those alternatives, not their sum; other separately carved buffers remain additive. The existing `m.R` is a per-chunk `T*D*4` allocation and remains allocated even when the layer-major path temporarily points `m.R` at a residual row. Use R248 for source-derived QSA/GDN/Ple values and `bytes_needed_owned` formulas; no exact current allocation receipt was observed here.

3. **Optional main-cache lease runs first.** `STRATA_PREFILL_RELEASE_CACHE` must be nonzero to suspend the original cache. The code drains its queue and all device queues, captures cache payload to the host (`snapshot`) or builds spans into a complete already-resident `ArenaExpertSource` (`ram`), retires captured graph references, then shrinks backing. Default `snapshot` temporarily adds `max(0, cache.bytes()-kept)` host bytes. `ram` does not add a complete copy but requires the resident RAM arena and adds span metadata. For non-segmented storage, only fraction 1.0/full release is legal; segmented storage rounds the retained amount upward to whole segments. The fraction applies to currently mapped bytes, while saved payload uses `bytes()-kept`; therefore distinguish `C0`, `C0m`, and rounded `kept` in a receipt.

4. **Optional MTP lease follows.** If configured, the MTP hook verifies full immutable RAM sources and payload, drains queues, drops graphs, then unmaps expert/head device backing. This frees `Wmtp` on the device while preserving its host source. It is independent of main-cache release; either hook may be absent. The MTP hook's source contains no partial release: it shrinks both stores to zero and restores full backing later.

5. **Temporary layer cache allocates before residual and compute.** `layer_cache.open_sized(vector(g.n_expert, MAXBLOB()), 1, g.n_expert)` reserves one contiguous allocation with one 256-byte-aligned slot per expert. Define `b = align_up(MAXBLOB(),256)` and `CL = 512*b` for the stated geometry. This is the current layer-major cache's exact source formula. The current pack's `MAXBLOB()` is unknown, so no numeric `CL` is asserted. With default release flags, compute-phase occupancy includes both `C0m` and `CL`, plus `Wmtp` if MTP release is not active. Cache `open_sized` is not layer-by-layer allocation: all 512 slots are allocated and zeroed together.

6. **Residual backing then allocates.** The host vector holds `(n-gpu_tokens)*D*4`; the GPU backing requests `(gpu_tokens-reused_tokens)*D*4`. `reused_tokens` is nonzero only with in-place enabled and all residual rows placed on GPU; it then reuses the already-live `m.R` scratch for the first chunk. For mixed/host suffixes, in-place does not retire the original `m.R` scratch. Default `gpu_tokens=0` is all-host residual and adds no residual-plane device allocation, but retains `m.R` and all existing Prefill/session device scratch. The stated 256K all-GPU residual alone is 71,303,168 B greater than whole-device capacity, before other allocations. Host snapshot bytes can overlap the host residual vector.

7. **`run_impl` reuses initialized scratch but can create path-specific temporaries.** The general per-chunk activation/MoE/QSA workspace is allocated by `Prefill::init`/`carve`, not freshly allocated per layer-major call. `run_impl` also lazily creates stream-KV events/page-table objects only for `kv_mode=1`, which `run_layer_major` rejects; those are not part of this eligible path. Some specialized paths contain local device allocations (for example PLE/page and diagnostic branches), and graph/runtime/backend allocations can occur or grow on first use. Their current-pack/run high-water contribution is not quantified by this source worksheet and belongs in the measured residual term `Urun`. Do not count the shared carve region once per layer or assume source ownership proves eager allocation of every conditional branch.

8. **Teardown releases temporary buffers before restoring leases.** On successful completion the code waits for compute/copy/stager work, closes the temporary layer cache and releases its GPU residual allocation, then restores the original Prefill pointers. The main cache is restored by its scope lease and MTP weights by its decode lease on scope exit. Main cache restoration grows/maps original backing, copies saved snapshot or current RAM spans, verifies if requested, and refreshes retired graph state. MTP restoration maps full allocations, copies from immutable RAM and recaptures/validates. Therefore restoration peak is a separate phase after `CL` and layer-major residual GPU backing are gone; snapshot host storage and full host residual may still overlap until function exit. If restoration fails, the lease terminates rather than returning with consumers able to use unbacked cache memory.

## Simultaneous budget worksheet

Use `B` for persistent device weights/base allocations excluding the main cache and MTP backing; `S(n)` for session state; `P(T)` for persistent Prefill allocations; `G` for device residual bytes after legal in-place reuse; `Urun` for any path-specific lazy and backend/graph high-water not already counted. Let `Ckeep` be original cache backing after the requested release (zero for ordinary full release; segment-rounded for elastic cache), and `Wkeep` MTP device backing after optional release.

| Phase | Live-device expression | New host peak contributors |
|---|---|---|
| Before layer-major leases | `B + S(n) + P(T) + C0m + Wmtp` | existing model/arena, PLE/cache working set |
| After optional leases, before temp cache | `B + S(n) + P(T) + Ckeep + Wkeep` | `restore_bytes` snapshot or RAM arena spans; existing host state |
| Temp cache allocated | prior row `+ CL` | same |
| Residual allocated / compute | prior row `+ G + Urun` | `(n-gpu_tokens)*D*4`; plus snapshot `restore_bytes` when snapshot restore; `Uhost` |
| Temp cache/residual freed, cache restoration | `B + S(n) + P(T) + C0m + Wkeep` then `+ Wmtp` as MTP restores | snapshot and residual can still overlap |
| Fully returned | `B + S(n) + P(T) + C0m + Wmtp` | host state returns to caller's normal ownership |

This is a lifetime equation, not a claim all terms are numerically known. The guaranteed default compute overlap (without either release hook) is `B + S(n) + P(T) + C0m + Wmtp + CL + G + Urun`. With both full-release hooks enabled, compute falls by the actually released `C0m + Wmtp`, but restore later reintroduces them after the temporary layer cache and residual GPU allocation are gone. If cache release uses snapshot mode, add the released cache payload to host peak; `ram` restore avoids that duplicate payload only with a complete resident arena. Cache release cannot make model weights or session state disappear.

## Correct retirement and restoration conditions

A cache is safe to shrink only after dependent queues are idle and backend graph/command-list references to the physical backing have been retired. The source enforces queue drains before shrink and requires both graph-retirement and refresh callbacks for an active main-cache lease; restoration checks the cache's slot count (and segmented base address), copies payload back, then refreshes captures. Reusing the same virtual address alone is not proof that backend allocations remain valid. MTP uses the same principle: drain queues, drop graphs before unmapping, restore payload to the same virtual addresses, then validate/recapture. Do not manually free or replace a cache/session allocation while a `Prefill`, decode or captured graph can still reference it. A stale cache object must be closed/reset through its owner and all consumer graphs retired before any backing change; the safe state rebuild boundary is after request work and queues drain, followed by source-supported restore/refresh or full owner reinitialization. Session QSA/GDN/PLE state has request semantics and must not be reset merely to reclaim cache bytes.
