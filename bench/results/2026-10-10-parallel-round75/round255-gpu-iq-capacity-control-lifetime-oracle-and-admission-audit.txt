## Submission, allocation, and failure lifetime

The queue is constructed for the explicitly selected device with `sycl::property::queue::in_order`. Every USM allocation, copy, `parallel_for`, dequant wrapper, drain, and free uses that same queue/context; no default-queue/null-stream path is introduced. Each packed device slot receives its host source and canaries before an explicit drain. The source vectors are fully built and reserved before asynchronous copies begin, and remain alive throughout the pair's queue work. The pair-scope `Drain` is declared after the host vectors and buffer-owner containers, so on exception unwind it drains before those host sources and containers are destroyed. `DeviceBuffer` destructors independently drain before `sycl::free`; its edge/readback use also has local drain guards. A synchronous launch/allocation/copy exception therefore unwinds through a drain before reuse/free. An async exception sets the sticky flag and is fatal; if completion cannot be established, `_Exit(86)` avoids unwinding or freeing storage the device might still reference. This is a sensible fail-closed design for this standalone process.

The DQ2 ring is correctly represented by two GU and two Down output buffers. Warm/sample/validation loops enqueue both wrapper calls for a source in program order; slot `j%2` is reused only by later commands on the in-order queue. Every timed batch has one terminal `wait_and_throw`; no per-expert wait is placed in the sample loop. The two final slot occupants are fully read/compared after each sample, outside the clock; each distinct selected source is then separately reset, launched, drained, and fully checked outside timing. Because selected batch sizes are even (16 or 32), those final two sources own slots 0 and 1. No packed source, slot output, or readback lifetime is shortened before the queue completes.

The unqualified runtime edges are driver behavior under an asynchronous fault or blocked wait, actual queue submission/copy-offload behavior under the root's qualified flags, allocation success under full system load, and any process termination/cleanup behavior around a real device failure. The harness cannot force a driver wait to honor an internal deadline; the handoff correctly assigns timeout/ownership control to the root. Its async handler reports a bounded first exception and then fail-stops; a reader of raw stderr should expect diagnostic JSON lines followed by fatal failure JSON rather than treating either as a successful receipt.

## Guard, storage extent, and explicit-byte bound

`DeviceBuffer` requests `n+2*64` bytes rounded up to 64-byte alignment, uses the base as the canary region and `base+64` as payload, and reads the whole payload plus both guards back. The front/tail guards are 64-byte aligned, leaving each dequant payload start 64-byte aligned (and hence preserving the production store's 16-byte alignment). Host packed vectors have the same 64-byte canaries. GU and Down lengths match the fixed production shape (`GU=2*FF*H` half elements, `D=H*FF` half elements); the host array/ref/readback bound includes the simultaneously live full expected half vector and both actual role readbacks. The source checks all selected device packed bytes against the host original and its hash, and checks both output slots' guards, including the unused qualifier slot.

The static explicit payload expression is 220,774,528 bytes: 32 host plus 32 device maximum packed blobs including guards, four device output slots, a simultaneous expected vector/two role readbacks, one maximum packed readback, and an 8-MiB allowance. This is below 512 MiB and rounds each device allocation by at most 63 bytes; the stated slack covers that small alignment addition. It is a bound on source-declared payload buffers, not total RSS/USS, mapped primary-file residency, SYCL/Level Zero/driver allocations, GGML internals, or process-wide virtual address space. The NativeRolePlan mapping of the 54.8-GB primary is virtual and must not be represented as an owned 54.8-GB copy, but page residency and total process RSS still require a root receipt. The 8-MiB allowance is a source budget, not a measured bound for all runtime/allocator/library allocations.

No source/storage underflow was found in the selection/launch sizes: `DeviceBuffer` admits blob sizes through `MAXBLOB=2,662,400`, the exact GU output bytes `GU*2=6,553,600`, Down output bytes `D*2=3,276,800`, and small edge buffers. Those match the production shape and output pointer types (`uint16_t*`). Source `fmt.bytes` is checked against `MAXBLOB`, and role row-byte/offset equations and range bounds are checked before decode. True allocation fit remains dependent on runtime free memory.

## Independent oracle and exact output indexing

The pinned GGML type traits decode each actual packed role row to FP32 using its own role type, row stride, and source offset. The independent RNE encoder converts each FP32 value to binary16 bits; the pinned GGML FP32-to-FP16 row helper must produce the same bits, and both are separately checked against literal edge cases. Each row is prefilled with NaNs and every expected FP32 value is checked finite, so an incomplete GGML row decode fails instead of accidentally leaving zero-valued output. Actual expected half infinities/NaNs fail closed. This oracle does not depend on the generic GPU decoder to generate expected values.

GU indexing is consistent with the production wrapper: gate role row `r`, column `c` maps to flattened expected index `(2*r)*H+c`; up maps to `(2*r+1)*H+c`. The compare routine reverses this mapping for first-difference role/row reporting. Down maps `r,c` to `GU+r*FF+c`, and comparison derives row/column with width `FF`. The three role extents are checked against `ggml_type_traits` block size/type bytes and against the native format's `gu_row`, `d_row`, `up_off`, and `down_off`. The complete written count must equal `GU+D = 4,915,200` half values per selected blob. The 24 literal cases cover signed zero, normals, tie cases, half subnormal/normal boundary, subnormal underflow, overflow, infinities, and signed float32 subnormals; the separate device diagnostic compares all 48 scalar-constructor/vec8-automatic bits. R252 correctly distinguishes that device edge path from the live generic `store_run<half,4/8>` constructor path: a source/CPU oracle alone cannot prove backend conversion semantics. In this control, the scalar form matches the production constructor spelling and the vector form is a separately reported extra contract.

The three-way interpretation is sound: host GGML-vs-literal/RNE checks the independent encoder/reference contract; generic GPU-vs-independent checks the current generic baseline; no candidate exists and candidate parity is not asserted. A generic/oracle mismatch invalidates timing as a baseline contract failure, rather than being counted as a candidate regression or pass. NaN payload behavior is intentionally outside the literal test domain; actual model-weight outputs are required finite.

The selected production-source census is the seven loaded pairs `(18,20)`, `(18,42)`, `(21,20)`, `(21,42)`, `(22,20)`, `(22,42)`, `(23,20)`, with layer counts 14, 3, 9, 1, 15, 5, 1. This is a format census and isolated dequant input selector, not evidence that a request routes those types or calls the ordinary generic path for them. MMQ/fused branches and actual expert frequencies remain outside this control.

Per actual blob, one GU wrapper plus one Down wrapper launch writes 3,276,800 + 1,638,400 = 4,915,200 half values (9,830,400 output bytes). Qualification selects one actual blob per pair: 14 dequant wrapper calls, 34,406,400 output half comparisons across all seven pairs, plus 24 host conversion literals, 48 device conversion bits and full source/guard checks. It reports no timing sample. Timing with batch `B=16` or `32` performs `2 + 18*B` dequant-wrapper calls per pair: two first-use calls, `2B` warm calls, `14B` calls in seven samples, and `2B` untimed all-source validation calls. Each sample makes `2B` wrapper calls and verifies both final-slot occupants outside time. Every distinct selected source is fully compared after timing. These counts reconcile with the source's `launches`, `compared`, and `end_compared` checks; wrapper counts are software submissions, not device profiler observations.

Logical timing bytes are selected packed bytes plus 9,830,400 output bytes per expert divided by host batch-completion wall time; this is not physical memory traffic or exclusive GPU service. The queue lacks profiling markers and the wrappers return void, so no device-exclusive kernel time is claimed. Host copy/H2D, source parsing, routing, GEMM, and model execution are excluded. ## Receipt and remaining admission gates

The archived boundary for the related prefix task is not this probe. The R255 implementation handoff is source only; per task, root will compile/test a private staged copy. Before any timing result is usable, root must preserve exact hashes for the copied source, source tree, CMake recipe, host object/library closure and final binary; the compiler policy string in harness JSON is not a cryptographic attestation of reused object flags. It must also admit one matching qualifier process with the same device/backend, compiler/runtime flags, object hashes and source identities. Source stat/FNV checks are useful accidental-change checks but not cryptographic proof against a concurrent/malicious rewrite; the current primary's full 54.8-GB SHA is intentionally not recomputed by this program.

A successful qualification would still establish only these selected actual blobs and isolated generic dequant behavior on that specific device/runtime. It would not prove the production call takes that generic path, compare full output for every model expert, establish free/peak VRAM/RAM including mapped pages/runtime and model session allocations, or qualify any 32K/full-context numerical lifecycle. A complete root-owned memory/process receipt and actual route-service census remain necessary for those claims. No concrete control-code gate defect was found in the immutable source inspected.
