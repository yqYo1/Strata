## What starts before the route is known

`Prefill::init` creates one long-lived `Stager`, its pinned/pageable host buffers, per-buffer DMA-completion events and worker threads. It scans the whole source for any transient entry to choose thread/ring sizing. For each full-stream chunk, the prompt path then builds a `seq` of every nonresident expert across the stage's layers. For every transient entry or unpinned nontransient entry it appends a `Stager::Job`; transient jobs retain `(ExpertSource*,layer,expert)` and a null pointer, while ordinary unpinned jobs retain the pointer returned by `blob()`. It calls `Stager::start` on this complete job array before the layer routers have produced `cnt[]` (prefill.cpp around 711-730 and 1403-1429).

`start` moves the job vector into the Stager, initializes a generation-tagged atomic claim head and per-job `ready` flags, resets `issued`, increments the generation and wakes workers. Each worker claims jobs in parallel. For job `j`, it waits until the previous host buffer's DMA was issued if `j >= kRing`, synchronizes that buffer's prior `dma_done` event, then either calls `copy_blob` for transient sources or `memcpy`s the saved stable source pointer. It marks `ready[j]` even on a failed source copy, with `failed`/captured exception carrying the error. The launching thread's `wait(j)` waits for readiness and propagates failure; after the copy queue accepts the H2D from that host buffer, `issued_one(j,copy)` records `dma_done[j % kRing]` on that queue and publishes `issued=j+1`, allowing a worker to reuse the staging buffer after that DMA. `cancel` sets the cancellation flag, advances/notifies `issued` to wake waiters; `finish` closes the current claim generation and waits until already-active workers leave. These are distinct boundaries: `finish` does not retire an in-flight device read by itself.

Consequently, R153's proposed “do not call `wait` for a zero-route job” is insufficient to avoid host work under the current chunk-wide `start`: a worker may already have copied that job, or may still do so when the consumer decides it is unused. `issued` backpressure bounds how far the worker pool can run ahead of copy submissions, but the initial inline ring and threaded issuer advance make that prefix real work. Filtering only the H2D issue would avoid the new H2D request but not guarantee suppression of the CPU `memcpy`, transient `copy_blob` file assembly/read, or its ready/job bookkeeping. Thus the claim “zero-route avoids host staging” requires removing zero-route jobs before workers can claim them.

## Smallest source-correct filtered pipeline

Keep the existing all-expert, increasing-ID streamed sequence and ring/event discipline initially, but move construction/start of the stager job batch to the point where this layer's routing IDs have been copied to host, synchronized and counted. Build jobs only for active (`cnt[e] > 0`) nonresident entries that need staging (`transient || !pinned`). Keep a per-expert or per-active-order `job_of` map; pinned active entries remain direct-copy entries and resident experts never enter the transfer sequence. Start workers on that immutable per-layer subset before the MoE consumer begins; while consuming active experts in the existing `order`, wait only on its mapped job and call `issued_one` after the H2D submission. Zero-count nonresident entries remain release-only sequence positions with no stager job, source `blob`/`copy_blob`, wait, or H2D. Existing `native_batch`/grouped-MMQ flush-before-release rules still govern when a *real* staged device blob's ring slot becomes reusable.

Before replacing `jobs`, `job_of`, route counts, or per-layer sequence metadata for the next layer, finish the prior Stager generation after all required jobs have been consumed; on any early error, cancel, join/finish workers, drain the compute and copy queues, and only then retire staging buffers or source ownership. The enclosing current `StagerDone` does cancel plus checked `cs`/copy drains before `finish` on chunk completion/unwind; an inner per-layer generation needs an equivalent explicit boundary. If a `copy_blob` or event operation fails, treat the Stager instance as terminal as its `start` contract says; do not reset its vectors or continue the next layer. Keep the `ExpertSource` alive through all workers and queued copies.

This moves source reads/host copies later than the current all-layer lookahead and cannot know future layers' active routes early. It can still launch active-current-layer host preparation as soon as the route counts are available, overlap that work with remaining input gathering/quantization and active expert GPU computation, and preserve the worker ring's lookahead within that active set. Retaining cross-layer host prefetch before routing would require either predicting routes (not exact) or preparing data for possible zero-route entries (which forfeits the requested suppression). This is a scheduling tradeoff, not a speed judgment. Do not call `blob` merely to decide the route: for transient sources, the source explicitly says the returned assembled pointer is short-lived and callers retaining it need `copy_blob`.

## Concrete `blob`, `pinned`, and `transient` lifetime cases

`ExpertSource::blob` has a deliberately weak base contract: a pointer need stay valid only until the next `blob()` call unless a caching source documents otherwise. Its `pinned` answer is the explicit predicate that the blob lies in device-copy-registered memory for direct async H2D. Its `transient` answer means the blob is assembled in short-lived storage, and the interface specifically calls out the prompt path's chunk-wide stager as a consumer that must copy it through `copy_blob` instead. `copy_blob` must support concurrent calls when `transient()` is true.

- Default non-mmap generate path: `generate.cpp` owns local `ArenaExpertSource arena_src` and sets `srcp = &arena_src`. `ArenaExpertSource::open` owns a `PinnedArena`, loads canonical/native packed blobs (or assembles native GGUF roles during load) into it, and keeps it alive until `close`/destruction. With the ordinary registered-mapping constructor, all pieces are registered for copy and `registered_bytes` is set for the arena; if that registration constructor fails in the supported private case it retries as layer-separated host USM. `STRATA_ARENA_HOST_USM=1` directly requests one host-USM allocation per layer plus pad. In either host-USM path, `registered_bytes=capacity`, `ArenaExpertSource::pinned()` returns true for all real expert extents, and `blob()` points into stable arena-owned memory; `transient()` is inherited false. Therefore unpinned stager jobs are not expected for this whole-model arena case. Actual ownership is `ArenaExpertSource` -> owned `PinnedArena` -> registered mapping or per-layer host-USM blocks, not a `NativeExpertStore`.
- `STRATA_ARENA_MMAP=1` maps an existing `experts.bin` read-only in `ArenaExpertSource::open`, with `pinned_bytes_=0` and no device alias. Its inherited `transient=false` and stable `blob()` pointer mean it takes the unpinned nontransient Stager `memcpy` path. It is an mmap-backed source, not page-locked memory.
- `--mmap-experts` uses `FileExpertSource`. A plain `experts.bin` mmap yields stable nontransient blob pointers but is not pinned, so jobs use Stager `memcpy`. Native GGUF roles, or the unbuffered file path, make `staged()` true. For nonresident/non-overridden entries `transient()` is true; `blob()` assembles a temporary cached blob, while `copy_blob()` directly assembles/copies the three role slices or reads the requested file data into Stager's buffer. Thus transient jobs must retain `(source,layer,expert)` and call `copy_blob` in the worker; saving a `blob()` pointer there would violate the lifetime contract. A pinned cache-complement entry may be nontransient/pinned and can use direct H2D. Pageable resident complement/override entries are nontransient stable pointers and need Stager `memcpy` if not pinned.

`ArenaExpertSource` is the model expert-arena owner for the normal current path; `FileExpertSource` owns maps and optional complement/staging caches for the mmap path. `Prefill::Impl` borrows `ExpertSource*`; the owner must outlive Prefill workers and queue submissions. A new per-layer pipeline must not weaken that relationship or free a `PinnedArena`, mapped role files, source staging buffers, or Stager host buffers before source reads and device transfers finish.

## SYCL lifetime rule from primary documentation

The actual queue dependencies remain explicit in this source: `copy_async_after` uses `handler::depends_on` for a slot's previous `used` event before `handler::memcpy`, returns its event as `copied`, and `stream_wait_event` on the compute queue gates consumption. Stager's `dma_done` separately gates reuse of each host staging buffer after the copy queue has consumed it. Khronos SYCL docs describe `handler::depends_on` as a prerequisite for the command group and `handler::memcpy` as the copy command ([command-group handler](https://github.khronos.org/SYCL_Reference/iface/command-group-handler.html)); queue `memcpy` overloads can take dependency events ([queue reference](https://github.khronos.org/SYCL_Reference/iface/queue.html)). The USM allocation reference says `sycl::free` does not wait for in-progress or enqueued commands and freeing memory still used by commands is undefined ([USM allocations](https://github.khronos.org/SYCL_Reference/iface/usm_allocations.html)); SYCL 2020 revision 12 likewise requires no enqueued/in-progress users before free ([specification](https://registry.khronos.org/SYCL/specs/sycl-2020/html/sycl-2020.html)). Thus host worker join and queue drains are separate required lifetime edges: join prevents more host writes/reads; drains retire accepted device commands before freeing the referenced allocation. These references document semantics, not a specific backend's timing or copy behavior.

## Boundary summary for implementers

The actual API names in this worktree are `Stager::init/start/work/claim/wait/issued_one/cancel/finish`; there is no separate `prepare` or `take` method/file. Preparation is worker execution after `start`; `claim` is its job take. The unmodified full-stream call starts a chunk-wide set too early to suppress zero-route host preparation. The minimum source-correct change is a post-routing per-layer active-job set, immutable while the current generation is live, with worker finish/cancel plus source lifetime and checked queue drains before storage reuse/free. Preserve exact source bytes and existing active expert order/float path. No measurement or speed claim follows from this source contract.
