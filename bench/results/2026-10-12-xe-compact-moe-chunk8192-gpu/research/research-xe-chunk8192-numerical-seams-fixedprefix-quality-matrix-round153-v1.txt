## What can vary numerically with chunk size

A larger T is not only a changed loop count. The same source-level sequence can take different batch shapes and grouping boundaries. These are plausible numerical seams to inspect; the source audit does not predict that any one of them causes a measurable delta.

- **Embedding and hyper-connection / shared projections:** `Prefill::run` gathers a chunk's embeddings in one batch when eligible, then runs HC and other BF16/native projections with `T` rows. `Gemm::bf16`/`f16` can use oneMath (when compiled and accepted), then XMX or row kernels; the FP16-only-engine BF16 route slices/converts rows as needed. Library/kernel choice and internal reduction order can depend on M/T. BF16X2 is off by default and the source comments say default BF16 changes prompt-path numbers relative to FP32 decode; pin its mode explicitly and compare only like-for-like. Prompt token IDs and row-wise mathematical formulas alone do not guarantee bitwise equality.
- **GDN:** QKV, gate, alpha/beta projections and convolution/recurrence execute over T rows while updating persistent GDN/convolution state. At chunk boundaries, the next T-row recurrence begins from the carried state. A missed, duplicate, reset or reordered row would change the later state even if its shape-level kernel error were small. The existing `STRATA_STATE_HASH_GDN` debug output is a truncated 16-bit hash of final GDN state after Prefill, not a numerical error measure or a checkpoint trace.
- **QSA indexer, selection and attention:** `qsa_step_fill` encodes absolute positions; batched indexer append processes T rows before the chunk's query selection. `STRATA_INDEXER_PER_TOKEN` selects the older per-token append path. Block-score/top-k runs in `sel_batch=256` tiles; the active block limit derives from the last query in each tile. Tensor-core score selection uses the documented 3x-TF32 path when eligible, otherwise fallback, with `STRATA_SELECT_OLD` changing selection. Prompt attention uses its batched implementation when supported, otherwise decode-style batches of 32; `STRATA_PROMPT_ATTN_OLD` forces the latter. Larger T changes which queries share the final partial selection/attention tile and can expose small score-order changes near selection ties, changing selected IDs and later attention output. `STRATA_QSA_DUMP` can record selected cell IDs for the trailing positions, but causes readbacks/synchronization and should be a separate diagnostic, not the clean logits measurement.
- **PLE:** PLE n-gram rows are gathered for the chunk with rolling predecessor tokens, double buffered on the host, then uploaded before layer 1. The batch post-op path depends on `STRATA_PLE_BATCH`, native PLE implementation, and available shared scratch; its internal subbatch size `SB` is computed from scratch and T. Otherwise PLE runs token by token and advances history for each token. Fix the branch, preload setting, and PLE data across arms; compare PLE history/state at matched positions if a diagnostic exposes it. No full PLE state-dump option was found in the standalone path.
- **MoE routing and reductions:** The router projection and shared-expert gate run with T rows; router scores feed top-k route IDs, then host grouping sorts expert IDs, constructs row bounds and packs source rows. Small router numerical shifts can change a route at a near tie. Expert row counts and the per-expert M dimension then change grouped FP16/oneMath or native MMQ products and accumulation/combine order. The non-MMQ path also has resident fused IQ GEMM eligibility based on expert row counts; MMQ quantizes activations in route-row shape and groups experts into `MMQ_GROUP` products. Compact MoE scratch changes row packing and descriptor/index paths, so keep compact state fixed across a T-only pair and verify that it was effectively enabled or disabled as intended. Pin MMQ plan and all of `STRATA_PREFILL_COMPACT_MOE_SCRATCH`, `STRATA_PREFILL_FUSED`, `STRATA_PREFILL_NATIVE_DEQUANT_BATCH`, `STRATA_PREFILL_GROUP_GATHER`, expert group and CPU share. For a GPU-only pair, set/verify CPU expert share off; the CPU and GPU expert implementations are documented to round differently. Pin `STRATA_PREFILL_RING` too: default ring slots can differ at T>=8192, although ring size is a transfer schedule/storage choice rather than an intended numerical factor.

## INT8 QSA host-prefix handoff

For main KV INT8 with resident capacity 32,768 under the requested 262,144 context, keep format, resident count, page map, and source/driver/runtime identical. In the streamed QSA path, each chunk stages old host-backed KV cells `[0,p0)` into the working staging pools before attention, appends the current chunk's newly projected K/V to both the host copy and the applicable staged/resident store, then uses those pools for selection/attention. The Q8 writer computes each group scale, rounds that scale to stored FP16, quantizes values against that stored scale with round-to-nearest-even, and writes INT8 codes plus FP16 scales. Therefore compare the host-backed codes and scales, not reconstructed FP32 K/V alone, if doing state-level diagnosis; also validate page-map/extent and no duplicate/missing positions.

Both 6144 and 8192 are multiples of the current QSA page size (4), so their full-chunk boundaries are page-aligned. The 65,535-row Prefill still ends with a partial tail at position 65,534, followed by the final prompt token at 65,535 in verifier. Same positions/page map and persistent host prefix are important invariants; page alignment does not prove equal Q/K/V arithmetic, selection, or state. No standalone option in the pinned CLI was found that exports the full QSA host KV tensors/scales or full QSA/PLE state for numerical diff. `STRATA_STATE_HASH` and detailed KV hashes found in source are serving-side diagnostics; the standalone `STRATA_QSA_DUMP` contains selected cell IDs, not KV values. Do not imply a full internal-state diff is available from `--dump-logits`.
