## Source path and exact score alignment

For prompt length `P`, the default native generator batches `n_batched=P-1` IDs through `Prefill::run`, then places the final prompt ID at `spec_pos=P-1` as the first verifier input (`generate.cpp` around 10458 and 10633–10695). The native path initializes `first_window=native_pack`, forces that window's `T=1`, and runs the final prompt token once. The logits from this row predict completion target `c0`; the row's predictor/input position is `P-1`.

The narrow harness belongs immediately after each `ver.run(T, ...)` succeeds and before output substitution, acceptance handling, commit, or any next verifier call. `Verifier::read_logits(1, host, err)` copies the full float32 vocabulary row (`verify.cpp` around 1754); `window_logprobs(&target, 1, p, ...)` can instead produce the existing stable log-probability/top-k record from the verifier row. `run()` synchronizes its compute and copy streams before returning, and `read_logits` is called before another run overwrites `head_logits_`. Prefer the existing score helper where its output contract meets the artifact needs; otherwise use stable `logsumexp` over the captured full row. Score `c_i` at predictor position `P-1+i`; after scoring it, force that same ID to be the next one-token verifier input. Call `ver.commit(1)` exactly once for the input just run. Thus the input sequence is final prompt ID at `P-1`, then `c0` at `P`, through `c_(N-2)` at `P+N-2`; the harness scores `N` targets at predictor positions `P-1 ... P+N-2`. It must not consume `c_(N-1)` after scoring it.

The existing `--spec-follow` is insufficient as-is: it substitutes outputs after `ver.run`, but normal draft sizing, acceptance `a`, and commits can remain multi-token. Once a proposed verifier input diverges from the reference continuation, later rows no longer describe the fixed reference prefix. Add an explicit opt-in fixed-follow path that selects `T=1` on every main-verifier invocation, bypasses draft/proposal and acceptance decisions, scores before substitution, then commits one input. It must not invoke the sampler, truncate on EOS, or emit a partial-success result. Validate all IDs and budgets before model work. Require the normal native pack and fixed `--prefill` route; reject `--prefill-until`, restore/resume/cache-prefix shortcuts, or any other mode that bypasses fresh batched Prefill. Keep `n_batched=P-1` and the final prompt token on the first verifier row.

Today the native-pack CLI guard requires `--spec >= 2`; the ordinary native verifier path can also use MTP only when `--mtp` is enabled. A clean main-model quality arm should keep `--mtp` off and use a new explicit ability mode with verifier capacity initialized to at least its existing minimum (2), while every actual run remains `T=1`. Do not claim that `--spec=0` works in the current source. If implementation instead reuses `--spec >=2`, it must force `T=1` after sizing and bypass draft/lookup selection, with tests proving no candidate proposal can alter the forced prefix. A separate intended-MTP follow-up must keep T=1 and teacher-force the MTP state using the actual main residuals plus each next reference ID; if that state-sync contract is not implemented, report that arm unsupported and fail closed. Such a quality arm does not measure MTP speculative performance.

## Paired 64K quality protocol and bounded evidence

Use the exact same 65,536 prompt token IDs in every arm and record their byte encoding, count, and SHA-256 in the closed receipt; this audit did not read an active run's token artifact and cannot supply or invent that hash. Keep `max_context=262144`, main KV format and resident count, model/pack, native head path, MTP setting per arm, `STRATA_PREFILL_COMPACT_MOE_SCRATCH`, MMQ plan, ring and all kernel/runtime settings fixed except the matrix factor being tested. Compare T6144 ON against T8192 ON to isolate chunk size; if needed compare T6144 OFF against T6144 ON separately to isolate compact mode. Require actual effective T and compact state, not only requested flags. For P=65,536, `n_batched=65,535`: T6144 makes ten 6,144-row chunks and a 4,095-row tail; T8192 makes seven 8,192-row chunks and an 8,191-row tail. The final prompt token then runs at position 65,535 in the verifier. Keep all corresponding token/state lifecycle settings identical.

A compact result can record one row per target with absolute predictor position, target ID, target log-probability/NLL, top-1 ID/logprob, margin, and target rank; optionally include top-K. Aggregate per arm/root: target count/coverage, mean and median NLL, target top-1 agreement, top-K coverage, and per-position paired deltas. Include fixed continuation ID bytes/hash and an explicit no-EOS-truncation policy. Do not claim full KL or all-vocabulary distance from top-K. If KL is required, capture complete rows for both arms with an explicit bounded sidecar budget of `2*N*V*4` bytes for two float32 vocab rows per target set, compute the metric, and assign an owner, consumer, and review/retention date; otherwise discard the full rows after compact evidence is verified. For each arm assert exactly N output scores, exact target IDs, and the contiguous position set `P-1..P+N-2`; flag any missing, duplicated, out-of-order, or consumed-twice prompt/continuation position. No numeric acceptance threshold is authorized in the reviewed material: publish measurements and leave quality acceptance unresolved unless the owner supplies an existing threshold.

Context admission for a full score requires `P+N-1 <= 262144`, so the final predictor remains at or below 262143. This mathematical index bound does not prove allocator fit or a full-context lifecycle pass. For 64K, retain the fixed 262144 configured context, KV format/resident cells, and relevant receipt details from R148; do not infer capacity from prompt length or the owned-request byte table. Keep timing in separate invocations because full-row readback and host scoring perturb execution.

## Required harness checks and limits

Before model work reject empty continuation, token IDs outside `[0,n_vocab)`, inconsistent declared count, insufficient `max_new`, or `P+N-1 > max_context`. In source-level fixtures (without model/GPU) verify: N=1 scores only the final prompt token row and never consumes c0 after score; N>1 maps c0..cN-1 to positions P-1..P+N-2; exactly one commit per run; forced EOS ID does not truncate; invalid IDs and position overflow reject before execution; missing, duplicate, or reordered rows fail coverage; output sequence length is exactly N; and paired arm metadata requires same token hashes and configuration except designated matrix factor. A/A harness parity should reproduce identical rows and exact full coverage. These are contract fixtures, not evidence of numerical model parity; no tests were run here.

Prior evidence says N=64 and N=2,049 OFF/ON strict-16-ID/LP5 parity passed, and R148 lists historical 745 MiB OFF/1,286 MiB ON startup-free figures. Those results do not establish this 64K full-distribution quality result or a T8192 capacity limit. The active six-root T6144 diagnostic and its artifacts remain the owner's run; this audit did not inspect them. Keep raw tensor/session captures only for a named current comparison consumer, and retain a deletion manifest if later cleanup is performed under the repository retention policy.
