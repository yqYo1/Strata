R167 — CPU-native AVX2 decode deltas for the Ryzen 5 5600X profile
Date: 2026-10-12
Scope: read-only source comparison. No tests/imports/builds/runtime/process inspection, Git mutation, cleanup, or active-artifact inspection. Local comparison target: safe XeStrata 39e395a103af36323262cdc0dbaea27cba81f3e4.

Decision
There are two real AVX2 setting differences worth keeping visible, but neither should be adopted as an unqualified speed default. XeStrata xe0.1.42 and local 39e automatically force the AVX2 native-i-quant single-token multi-row kernel for nearly every native format. Official Strata v0.1.43 restores the general default threshold of two and adds a narrower opt-in for IQ3_S. This is a decode arithmetic/rounding choice as well as a dispatch choice. Xe42 also enables Q2 bit-plane rows by default; local 39e and upstream v0.1.43 keep those opt-in. Q2 bit-plane is relevant only to the canonical Q2_0 AVX2 expert path, not to native IQ expert rows. Neither upstream's AVX-512-only canonical CPU expert kernel nor unrelated CUDA/HIP/SYCL work is a 5600X AVX2 decode candidate.

Relevant hardware boundary
AMD lists the Ryzen 5 5600X as 6 cores / 12 threads, 32 MB L3 and DDR4 up to 3200 MT/s ([AMD product specification](https://www.amd.com/en/products/processors/desktops/ryzen/5000-series/amd-ryzen-5-5600x.html)). The useful source distinction is its AVX2 execution path versus AVX-512-only code paths. Keep claims specific to the 5600X profile: the Intel i7-14700 P/E-core measurements embedded in upstream code are evidence for that Intel machine only, not for Zen 3.

1. Native IQ multi-row dispatch: official .43 is a material default change; local39e still follows Xe42
In Xe42 and local39e, `native_gu_mt_min()` reads `STRATA_IQ_MT_MIN`; if unset, the AVX2-without-AVX512 path sets threshold 1 for every native gate/up type except IQ2_XXS. In `native_gu_rows`, that means supported custom multi-token row kernels can process one-token groups as well as verify groups. The downstream IQ4_NL multi-token kernel independently uses threshold 2 unless `STRATA_IQ_MT_MIN` is set.
Official v0.1.43 changes the automatic rule: the general threshold remains 2, with `STRATA_IQ3S_MT1=1` opt-in enabling threshold 1 for IQ3_S only, and only when AVX2 is available, AVX-512 and the custom IQ256 kernel are enabled, and `STRATA_IQ_MT_MIN` is unset. The explicit `STRATA_IQ_MT_MIN` still wins. Thus the default for 5600X transitions from custom multi-row at one token (most native IQ formats) to ggml-cpu's per-token dot at one token; groups of 2+ still use the custom rows. This does not remove AVX2 kernels from the build.
Why the exact boundary matters: the official source explains these custom and ggml paths can use different float reduction order, so choosing the 1-token path can change last bits and draft/group dependence. Setting the custom kernel at threshold one can make a token's expert rows independent of whether a verifier grouped them, but speed depends on format, core and token count. Upstream reports 2.0-2.4x over ggml-cpu at three tokens and no improvement at one in native expert parity; its AVX2 Intel per-format one-token measurements show mixed results (IQ2_S, IQ3_S, IQ4_XS faster on the i7-14700 P-core; IQ2_XXS slower). Do not project those deltas onto 5600X.
Minimal candidate if the goal is to match official .43 semantics: port only the threshold rule in `src/kernels/cpu/native_expert.cpp`, retaining the existing `STRATA_IQ_MT_MIN` override and adding the narrow IQ3_S override. Do not transplant the upstream CPU pool or native-expert files wholesale. If the goal is to preserve local output and measure speed, first record current behavior (unset env = AVX2 threshold 1 except IQ2_XXS); then compare explicit threshold 2 and 1 with the same model, verification/MTP, prompt, pool workers and warm state. Capture token equality as well as timings.

2. Q2_0 bit-plane rows: Xe42 default is not current/upstream default
The actual Xe42/local `q2_avx2.cpp` hash is identical. Local code reads `STRATA_Q2_BITPLANE` once and enables the bit-plane image only when the env value is nonzero; unset means the legacy AVX2 Q2 row dot. Xe42 uses the same code body but flips the condition: unset enables the bit-plane kernel and `STRATA_Q2_BITPLANE=0` disables it. Official parent .43 explicitly keeps bit-plane opt-in, so current local behavior already matches that numerical default.
The bit-plane path precomputes a permuted activation image and combines code planes in integer lanes. It changes float accumulation order (and therefore can alter final bits). It applies to canonical Q2_0 experts on the custom AVX2 kernel; it is not the native IQ3/IQ4 path described above. Xe's source cites the measured i7-14700 P-core Q2_0 down-row delta 0.057→0.032 ms at one token and 0.126→0.061 ms at four. Those timings have that exact Intel environment and a kernel scope; they are not full decode or 5600X results. Do not switch local default to on without an A/B on the target and correctness parity. For same-answer comparisons keep unset/off; add an explicit `STRATA_Q2_BITPLANE=1` comparison arm only if this canonical Q2 kernel is exercised.

3. Already present or not a meaningful candidate
- `iq_avx2.cpp` per-format gather policy: official .43 selects gathered IQ3_S grids only when the per-core probe says gather is fast, while other formats retain scalar table indexing unless overridden. Local39e has `iq256_variant_for(type)` and the same IQ3_S-only default; no new port is called for. Xe42 is older here. This gate is core-sensitive by design, so do not force it machine-wide on the 5600X.
- AVX2 Q8_K activation quantization, AVX2-native IQ formats, and GGUF native expert dispatch exist locally. No candidate here should replace the activation contract or globally switch all formats to a different quantizer.
- The CPU pool's default remains one worker per physical core besides the reserved host core, with the host also participating in drain; `--pool-workers` overrides the worker count and `--pool-tasks` overrides the default 3 row tasks per participating thread. On the homogeneous 6-core 5600X, hybrid P/E affinity policy is irrelevant. Source differences between the full pool implementations are extensive platform/architecture adaptations and do not establish a 5600X decode improvement. Keep current pool dispatch; do not port `pool.cpp` wholesale. The one plausible pool knob is an explicitly measured `--pool-workers` choice, not a source merge.
- Canonical S2/Q2 CPU kernel and native IQ CPU kernels are distinct. Upstream's canonical CPU support gate requires AVX-512 VNNI/VBMI; it is not the 5600X CPU-only path. The AVX2-native GGUF expert kernels are relevant when the service routes CPU-resident native IQ experts.

Comparison requirements: cold prompt versus warm decode
A cold 16K prompt is chiefly a prompt-read/attention/cache-state measurement and cannot establish the effect of AVX2 one-token expert dispatch. Measure decode on an already warm model/session separately from a cold 16K prompt; do not merge prefill or initialization time into the native expert conclusion. Record whether expert data is resident in the arena or read through a cold/warm file cache, because the two sources change the CPU work and memory traffic. Keep model/quant, prompt and continuation, MTP/spec settings, expert residency/cache, `--pool-workers`, sampling, thread placement, and environment flags fixed. Compare per-request completion timing and accepted/offered draft counts, and preserve exact output/token IDs for each default-changing arm. Report cold-16K prefill independently with its own fresh/reused cache state. Do not claim that a multi-row kernel makes warm decode faster from row-level Intel results alone.

Recommended disposition
1. No broad CPU kernel or pool merge from upstream .43 into local39e: the source already contains AVX2 native IQ, per-format gather dispatch and Xe-specific safe engine work.
2. For the official behavior comparison, make `native_gu_mt_min` the first isolated code delta and make its default explicit in the report; test threshold 1 versus 2 on the target 5600X across warm decode and MTP group sizes. Keep default selection as a deliberate numerical policy.
3. Leave Q2 bit-plane opt-in/off by default in the safe baseline. Only assess it if the benchmark actually runs canonical Q2_0 CPU expert rows; it is irrelevant to native IQ decode.
4. Keep pool worker count as an explicit benchmark dimension, with its chosen value reported; no source evidence establishes a better 5600X worker/task default.
