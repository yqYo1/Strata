## Proposed behavior

`STRATA_PREFILL_FP16_GATHER_BATCH=1` is exact-string, default OFF and process-static. Other values decline. Admission requires configured SYCL, effective existing compact FP16, all-FP16 fallback/no MMQ, no peer, no next pipeline stage, complete layer range and positive contiguous expert-ID-order partition of exactly actual `T*K` rows. Existing compact admission additionally handles native geometry and `STRATA_DBG_NAN`. A rejected batch request leaves existing compact per-expert gathering in place. Noncompact/MMQ layouts retain their current path. No MMQ/fused opt-in, new queue, precision, allocation or host-staging policy is introduced.

The whole immutable consumer order is checked once before batching. Each first compute in a group scans forward only until the next expert cannot fit allocated `m.T` Xs rows. The scan verifies positive counts, actual `ne<=T`, exact contiguous offsets and source-table bounds. A group gathers `[groupStart, groupStart+groupRows)` once into Xs row zero. Subsequent GU calls read Xs at `expertOff-groupStart`; GU and Hh continue writing row zero per expert, Down continues writing `Dm+expertOff*N`. The input offset is separate from the output scratch offset. An unexpected metadata change fails the run rather than continuing with an invalid pointer; normal unsupported layouts decline before consumption.

No allocation accounting/carving/count-only/relayout code changes. Existing size_t contracts remain unchanged. Capacity is actual allocated `m.T`, not the smaller actual tail `T`, and no unallocated budget is assumed. Full Dm and routing `T*K` remain intact. The existing compact expert-bound guard is retained.

`STRATA_PREFILL_FP16_GATHER_BATCH_DIAG=1` separately enables at most four aggregate lines per run: actual exact requested/effective state, decline category, layer, actual/allocated rows, active expert count, compact gather calls and total gathered rows. These are host enqueue counts, not completed device timing. Diagnostics do not read device tensors or log experts, raw tensors or profiler events. Noncompact paths report zero compact gathers (not zero total gathers). No diagnostic line is emitted by the separate fused branch. The four-line cap means long-run tails require a separate tail-focused invocation to observe counts.

## Bounds and lifetime argument

Host counts become authoritative after the existing route-ID synchronization. The no-peer layout creates ordinary expert-ID-order prefix offsets; order contains only positive-count experts ascending. `src_h[p]=i/K` proves every gathered source ID is in `[0,actualT)`, even when IDs repeat across experts. The table and `mixed_h` are immutable while the layer consumes experts.

Actual SYCL `gather_rows16` in `src/prefill/sycl/postops.cpp:232` validates destination `groupRows*N*2`, source minimum row span `N*2`, and the selected index-table `groupRows*4`. It indexes source by the supplied row IDs, not by output row number. Thus output rows may exceed actual source token count and repeat inputs safely. Source `mixed_h` remains allocated for `m.T` input rows; source IDs are below actual `T<=m.T`. The minimum-span validator does not itself prove the maximum dynamic index: the host construction and bounds above provide that proof. GU span validation checks `ne*N*2` from the offset input pointer, which is inside the gathered Xs group and allocation.

`queue_for(m.cs)` requires an in-order SYCL queue; oneMKL GU is submitted to that queue. Every group's final GU input read precedes the next group's gather overwrite, even though dequantization of the next expert may already be enqueued. GU/Hh reuse, Down write destinations and DQ reuse order are unchanged. All source-blob dequant reads, copied waits, used events, `used_of`, staging-slot releases, threaded producer lease handoffs and `give_back` locations stay byte-for-byte at their original sites. Gathering uses activations and route metadata, not expert-slot payload. Host lookahead inspects only immutable counts/offsets/order and neither stages future experts nor acquires/relinquishes slots. Existing terminal error/drain ownership must still apply if a guard fails after submitted dequant work.

For full actual `T==allocated m.T=C`, all expert counts lie in `(0,C]`, their contiguous total is `K*C`, and greedy consecutive packing uses at most `2*K-1` groups. For adjacent groups, the first item of the second did not fit the first, so their sums exceed C. If 2K groups existed, K disjoint adjacent pairs would exceed K*C, contradicting the total. This bound depends on the complete contiguous partition and capacity assumptions; it is not a general timing bound. Balanced counts may give roughly ten gathers rather than up to 512 active-expert gathers, but no typical launch count or speed was measured. For actual T1 with allocated m.T64, all ten routed rows fit one group safely. The same row bytes are gathered overall; only launch boundaries and input pointer offsets change.
