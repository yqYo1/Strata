## Conclusion

The best small implementation boundary is the existing `strata generate` entrypoint in `src/program/generate.cpp`, with a narrowly gated input-only diagnostic mode. That executable already owns model/weight loading, session sizing and `session_init`, QSA/GDN/PLE allocation, expert source/cache setup, `Prefill::init`/`run`, optional MTP binding, the final-token forward path, and the configured SYCL runtime. Reusing its setup avoids a duplicate several-thousand-line model initializer and guarantees the configured CMake source resolver is exercised. In this checkout `cmake/sycl_backend.cmake` builds the executable from `src/program/generate.cpp` and the active prefill from `src/prefill/prefill.cpp` plus `src/prefill/sycl/{gemm,postops,blob,moe_mmq,moe_fused}.cpp`; the CUDA-root generator alone is not evidence of a separately resolved Arc implementation.

A special `--input-only` mode should accept `--max-new 0` only when the flag is present, require a nonempty prompt fitting `--max-context`, and skip sampling/output after all prompt IDs have passed through the ordinary engine. For the strict full-boundary arm, require exactly 262,144 input IDs and `--max-context 262144`. Retain the engine's existing prompt split: batched `Prefill::run` processes the first 262,143 conditioning IDs and the ordinary token path evaluates the *last input ID* at position 262,143, including target head/logit work, then the diagnostic returns before sampling/producing a token. The input fixture is 262,144 IDs and visible/generated output is zero. This is an implementation partition of one 262,144-token input, not a 262,143-token input plus generated output. It naturally preserves the established PLE predecessor window, final QSA/GDN/session state, expert refill, and optional MTP work through existing callbacks. It should reject native speculative modes that redirect the final prompt position into a verifier path unless that mode's complete input-only semantics are implemented; no special state or metadata shortcut is needed.

Why this boundary is necessary: current CLI parsing rejects `max_new <= 0` and requires `tokens.size() <= max_context - max_new` (`generate.cpp` near lines 1697–1703); it also rechecks prompt plus generation later. For normal generation, `n_batched` is `n_prompt - 1` and the final prompt token is consumed by the token loop (around 6239–6246, then `run_head` in the token loop). Therefore a bare `max-new=0` change is insufficient: without the diagnostic early exit, the ordinary loop would sample output. The serve protocol independently requires `max_new >= 1` and reserves eight cells (`n + max_new + 8 <= max_context`, around 5312 and 5409), so it cannot represent exact 262,144-input/zero-output at a 262,144-cell context. Do not call the prior 262140+4 observation proof of this condition and do not call the separate 262143-input/1-output run a substitute.

## Suggested validation matrix

1. **Strict full-input proof:** diagnostic mode, exactly 262,144 IDs, context 262,144, zero generated/output IDs. Keep `--prefill-chunk` and the stock resolver/config explicit; record the actual accepted chunk, all 262,143 batched positions, final token forward at absolute position 262,143, successful head completion, and clean return with output count zero. Use the existing residual/logit diagnostics only as needed; a compact completion receipt should include input count, last input position/token ID, prefill token/chunk stats, output count, return status, configured backend/source identity, and error/fault status. Do not fake `n_prompt`, session capacity, page count, `pos`, or position tables.
2. **Near-boundary generated output:** separate normal generation arm with 262,143 input IDs, `--max-context 262144`, and `--max-new 1`. The standalone CLI's prompt+generation checks permit this exact fit. Record actual output count/token, final input/output positions, head/logit and normal completion. It is deliberately a separate question from the zero-output full-input proof.
3. **Actual conversation restore:** use `--serve`, `--prompt-cache > 0`, `--conversation-cache-mib` admitted by the live snapshot estimator and physical-RAM floor, and at least two slots. The public protocol needs eight spare context cells, so at context 262,144 the largest request with one output is 262,135 input IDs. Use a fixed long prompt within that bound; issue request A, a different request B to move A out of live state, then A again so `ConversationCache::best/take` must restore the parked A entry. Capture `parked` and `restored` logs and the snapshot identity/bytes. `STRATA_SNAPSHOT_VERIFY` currently verifies the restored draft/MTP KV and prints its fingerprint, not every main-session component. Run an equivalent fresh/read-all request in a separate clean process/config as the behavioral reference and compare the full visible output and first target logits where the current diagnostic route can record them. A full-context request cannot also be restored via the public protocol at `max_context=262144` because of its +8 admission rule. If an exact 262,144-token parked snapshot is separately required, run this as a distinct internal diagnostic with enough extra context/headroom and explicitly mark it separate from the strict context=262144/zero-output receipt.
4. **Near-boundary restore/generated output:** optional but useful independent arm: context 262,144, input 262,135, output 1 with the A/B/A park-restore pattern, after admission. It checks the last supported public-protocol range without conflating it with the strict boundary proof.

The current normal serve route has no textual `SAVE`/`RESTORE` verbs. Parking and restore are automatic conversation-cache behavior. `STRATA_CKPT_REREAD` covers prompt checkpoints: it resets state and rereads a checkpoint prefix instead of restoring that checkpoint; it is not a full parked-snapshot reread comparison. Snapshot restore does validate the whole image before writes and refuses to continue after transfer failure.

## Existing engine-compatible fixtures and state coverage

`Prefill` is a direct engine API (`include/strata/prefill/prefill.hpp`): `bytes_needed`, `init`, `run`, `stats`, `reset`, `relayout`, `on_chunk`, and `should_stop`. `run(tokens,n,pos0,...)` processes absolute positions and updates GDN/QSA/PLE state through the same active prefill implementation. However, a standalone test that initializes only `Prefill` would still need the same model parsing/weight resolver, `ModelGeometry`, `WeightTable`, full `SessionState`, PLE/native weights, expert source/cache, stream/runtime, and optional MTP construction. There is no short ready-made whole-model initializer API found. The CLI diagnostic reuses the existing owner and is the smallest trustworthy actual-model validation entry.

Existing tests are component fixtures, not substitutes for the full prompt: `tests/sycl/prefill_state.cpp` checks state behavior, `prefill_storage.cpp` checks storage, `prefill_mmq.cpp` checks MMQ, `prefill_fused.cpp` checks fused MoE, `tests/core/prompt_checkpoint_test.cpp` checks full-context checkpoint cell addressing, and `src/core/conversation_snapshot_test.cpp` checks save/restore and K/V read-back on a synthetic fixture. None proves the current root model consumed all 262,144 input IDs on the configured SYCL build.

The physical state remains allocated at the requested context. `session_bytes(g,max_cells,...)` prices QSA state and buffers at `max_cells` plus per-GDN state, PLE history, block state and MoE/session scratch; `session_init` uses that same capacity. QSA includes paged K/V, the page table and indexer `tail`, `dead`, `pooled` with its spare row, and block-position scratch. Prefill uses `QsaState::n_pages`, page tables and its own cap/attention scratch. Do not shrink these for the test. The indexer currently documents `topk_512`'s per-step selection limit at 32,768 selected-KV cells, not a 32,768 total-context cap; long-context paging/index selection and its configured limits remain exercised by the actual engine route. Full boundary requires normal allocator admission, complete page sizing and the existing tail/spare row behavior.

Conversation snapshots cover substantially more than KV. `conversation_checkpoint_save/restore` carries GDN recurrent state including conv history, PLE history, QSA indexer tails/dead/block-pos and reconstructs PLE's two-token window from saved IDs. `conversation_snapshot_save/restore` adds every owned QSA layer's K/V, scales and pooled index rows, plus the draft/MTP KV, geometry/layer-range identity, live IDs/images and checkpoint chain. Restore validates capacity, formats, authoritative host pools, layout and layer carve before writing; streaming mode resets residency so later reads refill from authoritative pools. Main GDN/PLE/indexer running-state byte hashes are not exposed by the current public diagnostic; `STRATA_SNAPSHOT_VERIFY` is specifically draft KV verification. For full per-component byte round-trip evidence, the narrowest extension would be an opt-in snapshot diagnostic at the existing save/restore boundary, recording hashes of checkpoint state and every QSA/draft payload before/after restore, and only reading them after stream synchronization. Keep the normal restored-vs-fresh output/logit comparison as an independent semantic check.

## Capacity and implementation costs to resolve before GPU use

The existing code already calculates admission rather than relying on a guessed static cap. For live context memory, record the actual `session_bytes` result, `qsa_state_bytes`/page counts, MTP state bytes, prefill `Prefill::bytes_needed` for admitted chunk and `relayout`/borrow size if applicable, expert cache/resident slots, allocator free watermark and configured reserve. At primary geometry, the 262,144-position K/V/indexer and MTP backing are multi-GiB class: R485 records 3.09 GiB pinned host backing for the existing `--kv int8 --kv-resident 32768` configuration. This is an older recorded observation, not a current measurement or admission guarantee. Do not promise capacity from it; current `conversation_snapshot_bytes` is the authoritative snapshot estimator and parking additionally requires `estimate + physical free-memory floor` admission. Exact snapshot bytes depend on KV format, paging, index geometry and snapshot segmentation; query the estimator at runtime before choosing `--conversation-cache-mib`.

No source-only reason establishes that the current host RAM, pinned-memory budget, device reserve or snapshot cache budget admits a full-context restore. Conversation cache defaults off (`--conversation-cache-mib 0`); cache is also disabled if `--prompt-cache 0` or slots=0, and layer split is explicitly unsupported for parking. Verify the request's own conversation snapshot byte estimate and free-memory admission before attempting; a skipped park is not a restore pass. The serve +8 constraint means a strict full-context snapshot restore needs a separately configured context with at least the protocol headroom and exact full input still consumes 262,144 positions.

The input-only CLI change itself is small and co-located: add a bool option/help entry, gate the positive-max-new validation only for the exact diagnostic mode, permit the corresponding full prompt fit, and after final prompt input `run_head`/normal synchronization return before sampling and token emission. Keep `n_prompt` equal to the actual token vector length; avoid constructing a copied or synthetic 262144-cell prompt and avoid a CPU/session bypass. Add the precise no-spec constraint if needed. Preserve ordinary generation checks unchanged. If the desired proof specifically requires every one of the 262,144 positions to run through `Prefill::run` rather than the current established 262143-batched + final-token path, that is a larger semantic/API change: `on_chunk`'s MTP callback expects a following input token for every residual row, so the final row needs an explicit no-successor contract. Do not simply set `n_batched=n_prompt` and let the callback index `tokens[p0+t+1]` at the final cell. The existing canonical split avoids that new edge case while still evaluating all 262144 input positions and preserving normal model state.

For cancellation/error/reset coverage, `Prefill::should_stop` is checked before chunks and cancellation returns false with `cancelled`; `Prefill::reset` synchronizes its compute/copy streams before freeing/reinitializing workspaces. The CLI token path has separate stop/fault handling and prompt buffers are reset before ordinary decoding on the SYCL path. Add first/middle/final chunk cancellation and injected expert/prefill failure only to an opt-in diagnostic path if source changes are later authorized; do not turn a build/test-only fixture into an actual-model pass. Restore transfer failure is fatal by design and must be recorded as failure, never followed by decode from partial state.
