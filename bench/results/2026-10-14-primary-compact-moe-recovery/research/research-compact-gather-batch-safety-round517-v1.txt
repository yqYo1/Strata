## Conclusion

The proposed operation is source-safe under the following narrow contract: exact existing compact FP16 eligibility; one compute queue; group rows are a prefix interval of the already-built CSR table; each group contains whole nonempty experts and no more than the allocated `m.T` rows; one activation gather is enqueued immediately before processing the first expert of that group; expert GU/SwiGLU/Down operations then use local scratch offsets while Down keeps its original global `m.off[e]` destination. This preserves per-expert row order and GEMM shapes, and it does not need to change math, dequantization, staging, copy queues, slot leases, or attention/HC storage.

The source review does not prove an implementation or runtime result. In particular, a batched gather must be integrated into both the ordinary and streamed expert walk without bypassing their different staging/wait behavior. No speed claim follows from the reduction in gather launches.

## Source contract

At `src/prefill/prefill.cpp:627–641`, compact mode is admitted only when `STRATA_PREFILL_MOE_COMPACT_FP16` equals exactly `"1"`, MMQ has no active layer and retains its FP16 fallback, `STRATA_DBG_NAN` is absent, and native layouts (when present) have the expected `N=2560`, `n_ff=640`. Existing `STRATA_PREFILL_MOE_COMPACT_FP16` is the only selector established here. This review does not propose a new selector. Compact sizing at `:642–657` gives Xs `Talloc*N` half elements, GU `Talloc*1280` floats, and Hh `Talloc*640` half elements; Dm and route slot/source tables retain `Talloc*K` rows with `K=10`.

The host path copies `Tactual*K` routing IDs to host and synchronizes before counting, then validates every expert ID, builds `m.cnt`, prefix offsets `m.off`, and fills `src_host[p] = i/K` in route encounter order (`:2103–2195`). Thus each expert occupies `[m.off[e], m.off[e]+m.cnt[e])` in `src_dev`; offsets are nondecreasing even across zero-count experts. Exactly `Tactual*K` routes are represented. The existing check rejects a count above actual T (`:2122`), while the FP16 compute bounds check rejects nonpositive/too-large `ne` or invalid CSR spans (`:2547–2554`). Source rows are produced as token indices in `[0,Tactual)`, not arbitrary device data.

The selected gather definition is `src/prefill/sycl/postops.cpp:232–243`. For `n` rows and `width=N`, it reads `rows[i/width]` and copies the corresponding input row, writing zero for a negative row. It checks aligned, nonnull, disjoint spans and span byte overflow through `validate_spans`, but it does not upper-bound-check row values. That is safe for this path only because the synchronized host-built table gives each row index in `[0,Tactual)`. For a grouped call over CSR rows beginning at `s`, passing `m.src_dev+s` with `n=sum(group counts)` copies the same rows as concatenating the current per-expert gathers; it must not pass an expert ID, a slot index, or a group-relative token index in place of this source pointer.

Current FP16 compute (`:2534–2561`) dequantizes weights on `m.cs`, gathers one expert's activation rows into Xs row 0, computes GU into GU row 0, runs interleaved SwiGLU into Hh row 0, then computes Down into `m.Dm + o0*N`. The grouped form must preserve those operations per expert: source rows are gathered once into the group-local Xs range; expert `e` uses `local = m.off[e]-group_start` for Xs, GU, and Hh; Down continues writing `m.Dm + m.off[e]*N`. Dm remains a global CSR-ordered table, and `moe_combine` later uses the original `slot_dev` rows to select those global outputs (`:2630`). Do not write Down at local offset or compact Dm: that would break the unchanged slot map.

`Gemm::f16` in `src/prefill/sycl/gemm.cpp:14–30,89–105` validates the full matrix spans and submits row-major oneMKL `X[T,K] * W[N,K]^T -> Y[T,N]` with caller-provided rows/leading dimensions. Compact source/destination row offsets are element offsets, not byte offsets. `N=2560`, GU width 1280, and Hh width 640 make every per-row byte stride a multiple of 256 (respectively 5120, 5120, and 1280 bytes); the scratch offsets therefore preserve allocator alignment. The bump allocator at `src/prefill/prefill.cpp:183–201` rounds each allocation to 256 bytes, and scratch arrays are distinct takes. `validate_spans` requires 4-byte alignment and disjoint writable/output spans (`include/strata/sycl/launch.hpp:14–39`). The grouped gather reads `mixed_h` and `src_dev` and writes Xs, which are distinct allocations; GU and Hh remain separate allocations. Do not alias Xs with `mixed_h`, or GU with Hh.

The actual chunk may be shorter than the carved allocation: `run()` uses `Tactual=min(m.T,n-c0)` while `m.T` is the allocated/relayout chunk capacity; `relayout` rejects nonpositive or over-`Tmax` sizes and synchronizes compute and copy queues before recarving (`:899–919`). Group capacity may use the carved `m.T`, but every count and source extent must be checked against actual `Tactual`. A short tail may fit all `Tactual*K` routes in the allocated Xs/GU/Hh scratch when `Tactual*K <= Talloc`; this is a valid single-group case. Avoid unchecked `T*K`, prefix additions, signed-to-size conversions, and `int32_t` offsets. The existing route table and `m.off` are int32; retain a checked total no larger than `INT32_MAX` before generating/casting offsets. Require `Tactual>0`, `Tactual<=Talloc`, each `0<=ne<=Tactual`, and each group span `0<=start<=end<=Tactual*K` and `end-start<=Talloc` before pointer arithmetic. Zero-count experts are skipped and never handed to GEMM.

## Queue, staging, and lifetime review

The active prefill compute queue is required to be in-order (`queue_for`, `include/strata/sycl/launch.hpp:47–60`); the runtime creates it with `sycl::property::queue::in_order` (`src/sycl/runtime.cpp:64–85`). For a non-null stream, GEMM `finish()` does not host-wait; oneMKL returns after enqueue and the event is not retained. Ordering is therefore the safety mechanism: on `m.cs`, gather(group) must precede all of that group's dequant/GU/SwiGLU/Down work, and the next group's gather must follow the preceding group's last Down command. This ensures Xs/GU/Hh are not overwritten while queued work still reads them, without adding synchronization. Do not move grouped gather to a different queue or add a host wait to make reuse safe.

The ordinary `!stream_all` loop stages ahead, waits for the expert's copy event when needed, then calls `compute` (`:2563–2580`). Group gathering can be queued once before the first expert's GEMM; the subsequent expert wait/dequant sequence remains in place. In `stream_all`, the route loop calls `wait_issued`, normally waits on the copied slot, calls `compute`, and advances/releases the slot (`:2585–2627`). Keep these per-expert staging and lease transitions intact. Group activation gather only reads `src_dev`/`mixed_h`, so it need not wait for expert blobs, but it must be queued after the route-table copies already issued on `m.cs`. It must not delay or duplicate a `used` record, release a slot before its expert weight dequant has read the blob, or alter `give_back` timing. The existing streamed native grouped-weight gather is a different MMQ-only path (`:2447–2475`); do not conflate it with this FP16 activation gather.

The source permits `stream_all` when `m.ring>STAGE`, `Tactual>=stream_all_min()`, and an expert source is present (`:1519`), even though compact mode disables MMQ. Therefore the candidate must work in both streamed and non-streamed walks. It must not assume `ring=8` means streamed; the source defines that as the staging-only depth. In the no-MMQ compact case, `pre_mmq` is false, so peer grouping is not entered; the path remains primary-card FP16. Threaded issuer activity exists only with `stream_all && issuer_on` and hands off routed expert copies; grouped activation gathering must not change its ownership/release protocol (`:1641–1686`, `:2600–2627`).

`mixed_h` is generated from the layer residual immediately before attention/MoE (`:1774–1776`) and is read by GDN/QSA projections and later routed/shared paths. It is separately allocated outside the attention/MoE overlay region (`:818`). Group gather reads it but does not modify it. `src_dev` is filled for the current layer after route synchronization and remains the source table until the current expert work is queued; later use of the same table is ordered by the existing layer flow. The attention and MoE scratch sets intentionally overlay one `region` because their phases run sequentially (`:570–578`, `:835–861`); Xs/GU/Hh are distinct from each other inside the MoE carving, and this proposal does not authorize changing that overlay. The subsequent HC write consumes Dm/bo/injection and updates R after MoE combine; no new alias with HC or GDN state is needed.

## Group-count bound

For a greedy next-fit partition of the positive expert counts, using capacity `C=Talloc` and starting a new group only when the next whole expert will not fit, every adjacent group pair has combined load greater than C: the last expert of group i plus the first expert of i+1 exceeded C at that boundary. For `g` groups, each disjoint pair `(1,2),(3,4),...` therefore contains more than C rows. Since all routed rows total `K*Tactual`, `floor(g/2)*C < K*Tactual`; hence `g <= 2*ceil(K*Tactual/C)-1`, also bounded by the number of nonempty experts. Since `Tactual<=C`, this is at most `2*K-1` (K=10, at most 19). This upper bound does not require a full chunk; partial tails give a tighter bound, and if `K*Tactual<=C`, one group suffices. The loose `2K-1` endpoint is only potentially tight in the full-capacity case; it is a bound, not a likely observed count or a performance claim. This proof depends on whole-expert next-fit groups, positive counts in the ordered list, and no group larger than C. It does not apply to arbitrary fixed expert-ID windows or a grouping policy that leaves avoidable capacity unused.

## Main validation matrix and stop conditions

A useful direct test should compare the actual compact implementation's gathered rows, GU/Hh scratch placement, and global Dm placement against the existing per-expert reference with identical generated weights/routes. Cover: one expert carrying all routes (`ne=Tactual`); asymmetric adjacent counts that force a group boundary; zero experts at the beginning, middle, and end; all active counts fitting one group; exact capacity `sum(group)=Talloc`; a would-overflow next expert; one-token and short tail chunks, including `Tactual*K<=Talloc`; allocation full chunk where `Tactual=Talloc`; source rows at token 0 and `Tactual-1`; maximum allowed route offset; and relayout from `Tmax` to a smaller actual chunk then back. Also verify invalid negative/out-of-range source rows, `ne>Tactual`, negative/overflowing offsets and spans, `Tactual>Talloc`, and undersized borrowed allocation fail before any enqueue. Exercise ordinary staging and real `stream_all`/threaded issuer configurations separately, preserving actual staging, in-order queue, and slot event logic. Include a same-queue delayed-consumer/reuse case so the test proves no overwrite before queued Down completes. These are proposed checks, not current results.

For model validation, compare flag-off current per-expert versus flag-on grouped path in fresh matched processes with the same native weights, tokens, initial session, chunking, residency, and settings. Confirm exact effective compact admission, per-layer route row totals, no NaN/Inf, residual/logit deltas and token outcomes; include a short partial final chunk and actual nonresident streamed experts if the intended setup uses them. Then run the required actual 262144 input tokens with 0 output tokens; `262143+1` is not a substitute. Record source/binary/config identities, actual per-chunk T, correctness/fault status, and the measured full-context boundary. Only after correctness and lifetime checks close should Main measure performance; keep clean stock measurements separate and do not infer speed from fewer gather calls or a theoretical launch count.
