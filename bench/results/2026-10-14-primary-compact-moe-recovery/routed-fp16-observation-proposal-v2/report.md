## Proposed behavior and admission

`STRATA_PREFILL_ROUTED_FP16_OBSERVE=1` is the only enabling value. Unset, `0`, `01`, `true`, empty or other values produce no observation output, histogram allocation, extra copy, queue operation or clock query. Small stack structs and disabled branch checks remain; default OFF is not a promise of identical generated machine code. Existing arithmetic, precision, queue configuration and storage remain unchanged.

Admission additionally requires the configured SYCL engine, exact explicit `STRATA_PREFILL_MMQ=0`, and actual cached MMQ plan `any=false, fallback=true`. It requires N=2560, GU=1280 via native n_ff=640, Down=640, 512 experts, routing K=10, 1–512 model layers, native complete format/byte tables and positive byte/row sizes. Every native layer must match this geometry and `blob_bytes == NativeFmt.bytes`. It requires actual `m.src != nullptr`; source-less resident execution declines as `requires_native_expert_source`, and no native-source or cache-hit claims are made for that path. It requires configured and maximum allocated chunk sizes in 1–8192, n in 1–262144 and nonnegative pos0. Peer, pipeline, hand-off and partial layer stages decline explicitly. These are diagnostic scope bounds, not new inference admission restrictions: decline changes observation only and the stock run continues normally.

The initial guard excludes MMQ/fused routed execution because both actual fused branches require `use_mmq`. Histogram and calls are instrumented only in the actual host-grouped routed branch and its two fallback `f16` calls; dense/shared expert, attention, MTP, MMQ and fused calls never increment routed GEMM counters. Other features and flags are untouched. The summary reports actual `m.compact_moe_fp16`, not the requested compact flag; either actual value 0 or 1 is admitted.

At the existing post-sync authoritative count table, validate all 512 `m.cnt` values before histogram indexing: 0 <= ne <= actual T <= capacity, and sum(ne)=T*10. A legacy noncompact route table with ne>T declines observation without pretending that its histogram is complete and without changing the stock result. Valid tables contribute one exact `[ne,count]` histogram over the entire invocation, including ne=0. Positive-ne row weight is derived as `ne*count`; no duplicate row-weight histogram is allocated. Layer-chunk counts, zero/active expert counts, max ne, actual chunk min/max/last, chunk count and tail chunk count are recorded. Chunk T is fixed by this run's `m.T` except the final tail, and all those actual values are reported.

GU and Down calls/row sums increment at their real submission callsites. Successful observation at completion additionally validates sum(histogram counts)=512*layer_chunks, zero+active=sum(histogram counts), histogram[0]=zero, sum(nonzero histogram counts)=active, GU/Down call counts=active, and weighted exact histogram row sum=GU rows=Down rows, with at least one observed routed layer-chunk. Any mismatch declines with `histogram_or_call_accounting_mismatch` and emits no partial histogram. Cache-served expert calls are `resident_expert_calls`: with peer excluded, actual slot=-1 here means the existing host_res/cache route. Histogram calls describe `(ne,1280,2560)` GU and `(ne,2560,640)` Down. `2*rows*N*K` produces mathematical shape FLOPs only, not hardware instructions, executed tensor operations, utilization or service time.

Native format rows have fields `[layer,layer_chunks,gu_type,d_type,gu_matrix_bytes,down_matrix_bytes,blob_bytes,up_offset,down_offset]`. Types are native ggml type IDs. GU matrix bytes are `2*n_ff*gu_row`, Down bytes `n_embd*d_row`; full blob payload uses actual `ExpertLayout.blob_bytes(layer)` and may differ because of layout/padding. This is a compact format-count representation by layer, not one record per expert call. The FP16 materialized weight tensors still use the stock dequantization path.

## Blob submission accounting and lifetime

Accounting is placed at the existing inline issuer, threaded issuer, and small-chunk `stage_one` submission branch. It uses the existing chosen direct source versus stager-buffer source and the same existing submission byte count; it does not inspect tensor contents or copy pointers/IDs into logs. One FP16 blob copy attempt is one attempted host submission/copy group. `blob_h2d_requested_submission_payload_bytes` is the sum of requested byte arguments before the existing legacy copy API call; `blob_h2d_attempted_host_copy_calls` counts those attempted calls. Because legacy copy API return values are unchecked at these callsites, these counters do not establish successful DMA submission, successful DMA completion, physical PCIe traffic, throughput, driver transactions or overlap. Existing checked final queue completion/error paths remain separate evidence; a stock successful return does not strengthen this byte-counter meaning. The patch adds no mandatory inference error handling.

Counts distinguish attempted direct pinned calls, attempted stager-buffer calls, attempts reusing live device stage slots and actual resident expert compute calls. A reused live stage slot is reuse of the existing stage slot, not a cache hit or a claim about host-buffer reuse. Stream-all includes existing copies of experts the route later skips; the payload therefore need not equal active_experts*blob_bytes. `stats_experts_dma_delta` retains its stock meaning (direct pinned submissions in these paths), which differs from all attempted blob copy calls and inherits legacy unchecked-copy limitations. `stats_experts_streamed_delta`, resident delta and host staging milliseconds are invocation differences from the existing stock counters.

The producer thread never reads mutable observation state or writes shared observation counters. It reads an immutable enable snapshot, increments only `issuer_payload` on its own thread, and Main's consumer merges that payload only after the existing `issuer.join()`. The snapshot and payload are declared before IssuerJoin, so the existing early-return RAII join runs before their destruction; they also outlive the thread on normal completion. If the consumer later declines observation, the immutable snapshot remains safe, and no producer totals are published as complete observation. Inline and small-chunk counters run on the consumer thread. No additional lock, atomic, wait, synchronization or query is introduced. Reads of `stage_live` reuse the same producer/consumer ownership and release ordering as the existing copy submission's stock read; they do not add a new cross-thread observation dependency.

## Output and limits

One prefixed compact JSON line is emitted per successfully returning Prefill::run, after all existing completion/error checks and existing optional debug work. Effective decline produces only effective=false plus its scope reason, with no partial histogram. Failed or cancelled runs return on existing paths and emit **no success summary**. Absence of a summary must be recorded by Main as missing/incomplete observation alongside the unchanged failed/cancelled receipt; `run_return=success` is a code return status, never a numerical-correctness pass. No destructor logs partial data.

Histogram has at most 8193 uint64 counts = 65,544 bytes (64 KiB plus 8 bytes), plus at most 512 uint64 layer counters = 4096 bytes. Storage is bounded per invocation and released on return; it holds no routes, tensors, events or per-call records. JSON is bounded by admitted histogram/layer counts and has a hard 1 MiB output check. With n<=262144 and <=512 layer-chunks per input chunk, accumulated shape FLOPs remain within uint64. Admission-time histogram/layer allocation `std::bad_alloc` declines rather than changing inference admission. Final JSON `std::string` construction can still allocate and throw `std::bad_alloc`; this proposal does not catch or hide that exception. Thus a completed inference computation can lack an observation summary or reach existing outer exception handling because of output construction. No complete-observation or inference-pass receipt should be inferred from absent output. The 1 MiB limit bounds the constructed output size, not a guarantee of allocation success. Output construction is only after completion and only if requested.

If STRATA_PREFILL_TIMING is enabled, the observation embeds the already existing phase-ms array in existing `kPfNames` order: embed+steps, hc read, gdn, qsa proj, qsa indexer, qsa select, qsa attn, router+shared, host grouping, gather, wait copy, dequant, gemm gate/up, gemm down, combine, ple, kv stage, gdn conv+gates, gdn recurrence, gdn out proj. The phase order is governed by the pinned source; Main should retain that exact source with the receipt. No additional event is created or retained by this patch. Existing PfTimer gaps are **nonexclusive queue timeline intervals** and can include host/queue gaps and overlapping work. They do not isolate all routed BLAS GPU work: phase buckets can include dense work, and the returned oneMKL event can represent only a last/internal command. This proposal supplies no event service timing. Wall and staging milliseconds from this diagnostic are not clean speed samples. Keep stock quiet samples separate.

There is no measured histogram, tuned GEMM dispatch, bottleneck attribution, hardware ceiling or speedup here. Exact shape frequencies from Main's actual target run are the next consumer. They enable a bounded same-runtime orientation probe over frequent and tail values. Establish useful FP16/transfer hardware limits and measured phase/critical-path contributions before tuning. Historical PP gap remains unattributed; a short synthetic diagnostic is not target throughput or the separate physical 262144-input/0-output capacity gate.
