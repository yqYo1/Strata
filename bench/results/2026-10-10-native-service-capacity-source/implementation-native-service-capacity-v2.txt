Independent numerical admission
NT1 keeps its exact GGML FF/SwiGLU byte comparison and exact staged Down20 comparison; an exact independent full-chain Down20 check is added. NT1 Down42 retains its previous non-bitwise reference diagnostic scope. NT2-4 requires SIX explicit owner-chosen finite CLI tolerances before any file/payload preparation:
--gu-maxabs V --gu-nrms V
--down-maxabs V --down-nrms V
--chain-maxabs V --chain-nrms V
No defaults, auto-estimation, observation-driven adjustment or threshold fitting are present. Every stage requires BOTH its maxabs and normalized RMS limits to pass for EVERY expert/token vector in both source cohorts, even in hot mode. Missing any of the six gates rejects NT2-4 before source load. Optional gate pairs for NT1 are logged but NT1's exact controls remain the admission criteria.

GU_SwiGLU reference computes independent single-token GGML Gate and Up dot products from the already independently checked GGML-equivalent quantized layer activation, then evaluates SwiGLU. It compares all640 FF values, not independently exposed production Gate/Up outputs (the production API returns FF). Down_actual_FF reference quantizes actual production FF using GGML and computes all2560 Down output rows: this isolates Down arithmetic. full_chain_independent_FF separately quantizes independent GGML FF and computes independent GGML Down rows, comparing against the actual complete native output. Thus using actual FF in the staged Down reference cannot mask GU/quantization error in the full-chain gate. All actual/reference FF and outputs are finite, fully initialized and guarded; both reference quantizer buffers have checked meaningful size and untouched tail guards. GGML Gate/Up scalar dot outputs are finite before SwiGLU.

Each REFERENCE_TOKEN row preserves case index, layer, expert, NT, token, stage, maxabs, normalized RMS, maxabs relative to reference maxabs, reference RMS, error RMS, reference maxabs and checked row count. Normalized RMS is sqrt(sum((actual-ref)^2)/n)/max(sqrt(sum(ref^2)/n),1e-12). Relative maxabs is maxabs/max(max(abs(ref)),1e-12). This predeclared fixed floor avoids division by zero; it is emitted with gates and does not clamp errors. Both diagnostic ratios and sums must remain finite. Each stage maxabs/NRMS gate is an AND, not a permissive OR. REFERENCE still gives per-case worst maxabs plus the new full-chain column; REFERENCE_WORST supplies worst normalized/relative diagnostics. REFERENCE_COUNTS reconciles384*NT token cases,384*NT*(640+2*2560) checked vector rows, and384*NT*3 stage records. NT4 therefore expects1536 token cases,8,847,360 compared row values and4608 stage records. These are finite fixture counts, not token-request/model qualification.

Tolerance considerations for root review
No candidate numeric limits are selected here: the assigned task requires the owner to select gates before execution. Maxabs is dimensional and must reflect the existing owner numerical contract for these synthetic activation scales and actual payloads. NRMS is scale-normalized across each full token vector; a separate maxabs condition catches isolated absolute outliers. FF/SwiGLU contains a nonlinear combination, staged Down has a different magnitude/reduction length, and full-chain errors may include discrete quantizer-code changes caused by tiny FF perturbations. Therefore GU, staged Down and full-chain limits need separate predeclared justification; a Down-only tolerance cannot qualify GU/chain. Exact zero gates are admissible and intentionally strict. Do not set broad limits solely to pass observed deltas, auto-tune after a failed cell, or relabel numerical fixture admission as model adoption. Existing model-level evidence, output sensitivity and any independent numerical contract should determine the values; this source makes lack of an approved gate explicit by rejecting NT2-4.
