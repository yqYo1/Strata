## CLI distinction and chunk admission

The parser accepts `--prefill auto:16384` by setting `prefill_auto=true` and the ceiling to 16,384. But later, before allocation planning, `generate.cpp` explicitly disables auto and sets the chunk to 2,048 whenever `no_prefill_borrow` is true or the expert profile is empty (`~2218`). Therefore `--prefill auto:16384 --no-prefill-borrow` does not request a 16K owned workspace; it is reduced to 2,048. The auto planner's purpose is to choose a cache loan, so do not recommend that combination.

A fixed `--prefill 16384 --no-prefill-borrow` follows a different branch: it leaves `prefill_auto=false`, preserves the fixed chunk, skips the loan, and passes `borrow=nullptr` to `Prefill::init` (`~11699-11725`). `Alloc::take` then creates owned device buffers. `bytes_needed_owned(g, ss, 16384)` is the source-provided exact preflight for that ownership mode; the default `160 + T*680/1024 MiB` reservation in `generate.cpp` is a sizing reserve, not a measured allocation or fit guarantee. No 16K owned allocation was attempted here. The existing R273 8,192-token measurement (1,861,857,536 accounted bytes; 1,166,147,584 shared-region bytes) is not enough to infer a 16K peak or fit.

## Smallest viable lease ordering, still unimplemented

For a serialized request with the fixed 16K, no-borrow path, source supports this narrow ordering as a candidate:

1. Keep MTP dense projections, K/V/state, main session QSA/GDN/PLE state, cache and head available. Ensure immutable expert/head RAM payloads exist, as required by `can_release_decode_weights()`.
2. Once the native head exists, bind MTP before `Prefill::init` (the existing `bind(wt, &native_head, nullptr, err)` call can move to this boundary). Suspend only MTP decode experts/head. Do not install Prefill's internal `on_decode_suspend` / `on_decode_restore` callbacks: their current restore point is inside layer-major execution and would recreate the same overlap. Keep the prompt `on_chunk` callback so MTP K/V is filled.
3. Initialize and run the fixed 16K owned prefill. On successful return, drain/refill any independently borrowed cache state first (none for the specified no-borrow run), then call `prefill.reset()` at the caller boundary. This frees the workspace without resetting SessionState or MTP state.
4. Restore and verify MTP expert/head storage at the same virtual addresses. Only then initialize/rebind the verifier's final residual pointer and capture decode graphs. Standard drafts can recapture lazily; call `warm()` when the existing warm path is required, and call `prepare_chain()` after restore for forced chain mode.
5. Use an external RAII lease/fail-closed error path: if init/run/cancellation fails after suspend, reset partial Prefill allocations before attempting restoration, and do not decode unless restore/verification and required graph preparation succeed. Never restore from within Prefill while its run stack or callbacks can still use the workspace.

The source establishes that this ordering can free owned Prefill workspace before MTP restoration while preserving the named prompt and session state. It does not establish the size of the overlapping peak, that the 16K allocation will succeed, or request concurrency safety. The C++ server keeps a long-lived MTP drafter and handles requests after `READY` (`generate.cpp ~8444`); each request's prefill/rebind/warm path is later in the request body (`~11680`, `~12141`, `~12331`). Since suspension discards shared MTP graphs and mutates shared weights, a server implementation needs an explicit serialization/lease boundary covering all users of that drafter, plus exact error/cancel recovery. Treat the first candidate as single-request/serialized only until that is proven. Do not infer safety merely from `Prefill` being a local object.

The current auto-without-borrow fallback is a separate correctness trap: `auto:16384` cannot be used to test the owned 16K lease while `--no-prefill-borrow` is set. Use the fixed-size path for any later experiment, then record actual allocated bytes and high-water/free memory. Keep the full-262144-context, zero-output, final-prompt-token boundary and exact QSA/GDN/PLE/MTP state and output gates mandatory; the accepted 32K route census remains only route accounting and does not qualify that context.
