## Bounded output-cap case against the real header

Include the immutable v2 header directly in a standalone CPU driver and call its public `RouteCensus` methods. Do not copy the class into a test implementation or edit the header. The least admitted request length that can force the output cap with many records is 32,768 tokens; use 32 synthetic chunks of `T=1,024`, `K=10`, `p0=0,1,024,...,31,744`, and 64 layers (`LB=0, LE=64`) with `NE=512`. This makes 2,048 potential layer records while obeying the header's request, chunk, layer and expert bounds.

Use native MMQ metadata for pair 22/20 on every layer: `H=2560`, `FF=640`, `gu_row=820`, `down_row=360`, `up_off=524800`, `down_off=1049600`, and `bytes=1,971,200`; set `branch=mmq`, `mmq_built=true`, `native=true`, `stream_all=false`, and `fused_only=false`. This is a CPU ledger fixture only; it makes no claim about a GPU MMQ execution. For each chunk/layer, assign the 512 experts to these 314 distinct `(ne,source)` bins:

- For each `ne=1..62`, create one expert for each source enum 1 through 5: 310 bins, with count sum `5*(1+...+62)=9,765`.
- For `ne=63`, create one expert for each source 1 through 4: 4 bins, count sum 252. The 314-bin subtotal is 10,017.
- Assign 197 remaining experts to `(ne=1, source=resident)` and one remaining expert to `(ne=26, source=resident)`; their count sum is 223. The total is 10,240=`T*K`, and all 512 counts are positive and at most `T`.

For source 1, record a resident call. For source 2 through 5, call `plan_source(layer,expert,source)` and `copied(layer,expert,1,971,200,source)` before `executed(...,false)`. Then call `executed(...,true)` for residents. This gives 261 resident and 251 copied expert calls per layer; no generic `product` hooks are used because this fixture declares MMQ. The same exact counts are reused for each layer/chunk. These inputs satisfy the header's per-layer partition and copy reconciliation without source payloads or a GPU.

Each emitted layer row has at least 314 bin objects. Even the shortest bin object is 96 bytes before its separating comma; therefore the bins alone exceed 30,457 bytes per layer row. If the request were allowed to finish, 2,048 rows would exceed 62 MB, above the header's body limit `output_cap - 8,192 = 33,546,240` bytes. The real header must therefore reach `output_cap_or_format_failure` before the last record. The driver should run in a dedicated owner-controlled subprocess with, for example, a 120-second wall cap, 60-second CPU cap and 64 MiB RSS cap. Expected live allocations are 32 MiB output plus at most 2 MiB scratch and a 16 KiB histogram stack array, with a small executable/driver; the 64 MiB limit is a test bound, not a measured RSS result. Capture only the short final stderr receipt: buffered layer text is not written on invalidation.

The output-cap assertions should be:

- Exactly one `prefill_route_census_receipt`, `valid=false`, first reason `output_cap_or_format_failure`, `capacity_join=false`, and `device_commands_added=0`.
- Zero `prefill_route_layer` lines, `output_bytes=0`, `calls=rows=transfer_calls=transfer_bytes=routed_transfer_calls=0`, and `histogram_fnv1a64="0000000000000000"`. The header zeros these summary fields and hash when invalid.
- Do not assert that the receipt's numeric `layers` field is zero. In `end_chunk`, `layers_` is incremented after the appends without checking whether the final append invalidated the object; the failing row can be counted internally even though no buffered layer line is published. `chunks` can likewise include the chunk in which the cap fired. Do not assert timing fields, which are nondeterministic.
- If the case instead ends as a valid receipt or `request_final_coverage`, treat the cap fixture as failed: the purpose is to prove cap rejection against this exact header. The existing small positive fixture remains the control for exact output-byte and valid-body FNV computation; no duplicate broad correctness matrix is needed here.

## Deterministic allocation failures

The constructor has exactly two census-owned nothrow allocation attempts, in order: scalar `new(std::nothrow) Scratch` and array `new(std::nothrow) char[output_cap]`. The private `Scratch` size need not be exposed: assert the first observed scalar request is positive and no larger than 2 MiB (the header's static assertion), and the second observed array request is exactly 33,554,432 bytes. The constructor attempts the output allocation even if scratch allocation failed, so both ordinals should be observed in either test.

In a dedicated test binary that includes the actual header, replace only the global nothrow scalar and array overloads with a small ordinal fault interposer. Arm it immediately before constructing a valid `on=true` census, disarm it immediately after construction, and do no harness allocation while armed. In the non-failing branch delegate successful nothrow requests to the matching ordinary `::operator new` or `::operator new[]` inside `try/catch`; that preserves the standard allocation/deallocation families used by the census unique pointers. Do not return `malloc` memory and then depend on an unrelated `delete` implementation. Keep the interposer state test-owned and single-threaded; fail only allocation ordinal 1 or ordinal 2, not arbitrary allocations in the process.

For ordinal 1, Scratch is null and output allocation succeeds. For ordinal 2, Scratch succeeds and output is null. In both runs, use `n=32768,pos0=0,LB=0,LE=1,NE=10` and call `finish(true)` once after constructor return. Expected result: one invalid receipt, reason `allocation_failure`, zero layer lines, `chunks=layers=calls=rows=transfer_calls=transfer_bytes=routed_transfer_calls=0`, `output_bytes=0`, and zero FNV. The first case must show second allocation still attempted; the second must show only the requested output allocation failing. The test also asserts no crash/dereference during `finish` or destruction and that the successful Scratch is released in the second case. A normal-allocation control can record the same two request sizes and complete a valid small fixture.

## Fatal, unwind, and ownership checks

The public `fatal_receipt(reason)` helper can be exercised without the caller or GPU in a child process: call it with a fixed literal such as `cpu_fatal_probe`, then `_Exit(7)`. Assert status 7 and exactly the helper's one minimal JSON line (`valid=false`, that reason, `capacity_join=false`), with no layer rows. This verifies the immutable minimal fatal receipt and that no live census lane is inspected; it does not prove every production fatal call site emits the helper or that a later process consumer accepts it correctly. Existing nested fatal helpers may exit without a final route receipt. The controller must treat no receipt, partial receipt, abnormal status, or missing normal request completion as invalid; missing output must never be interpreted as a zero-cost or zero-call valid census.

For normal C++ unwinding, construct the census first, then declare the worker and its join guard so reverse destruction joins the worker before destroying the census. Begin a chunk, make one source plan, and let a CPU worker write one distinct `Copy` entry using `copied()`. Leave the chunk unfinished and unwind the scope (test both early return and a thrown/caught exception if both control forms are used). Assert the join guard completed before the destructor's receipt is read. With no earlier census fault, the expected final output is one invalid receipt with first reason `request_early_return_or_exception`, zero layer lines, zero output bytes/calls/rows/transfers, and zero FNV. This is the minimal fixture that tests the existing caller's owner order; the census destructor itself does not join producers. A separate injected sticky copy fault can retain its first reason if explicitly invalidated before unwind, so use a clean fault-free writer for the exact reason assertion.

The root-owned caller declares `RouteCensus` outside the per-chunk issuer/stager guards; its join guards are destroyed first during ordinary stack unwinding. This ordering is the safety precondition, not a property guaranteed by `RouteCensus`. A fatal `_Exit` cannot run destructors; only the literal helper or a missing-receipt failure gate protects those paths. Keep these consumer outcomes distinct: a complete explicit invalid receipt, an unwind-generated invalid receipt after owner joins, and no receipt after an unchanged nested fatal are all invalid, but only the first two should have census JSON.

## Default-off evidence limits

Against the header, absent environment and exact `STRATA_PREFILL_ROUTE_CENSUS=0` return from the constructor before the two nothrow allocations. All `HostSpan` instances and their `steady_clock::now()` calls are after early `!on` checks; the disabled destructor and `finish()` return without logging. In the caller, census hooks are guarded by `route_census.on`. The source includes no SYCL types, queue, event or wait. These static facts support “no census-owned allocation/clock/output/device command on the off path” for this source. The constructor still reads the environment; its enabled-only peer-mode argument remains short-circuited for absent/zero.

A narrowly armed allocation counter around default-off construction can assert zero census nothrow requests; it does not prove no direct `malloc`, runtime allocation, or all allocations in linked production code. A `clock_gettime` wrapper can be used only if validated to intercept the chosen standard-library `steady_clock` implementation; it may miss vDSO/inlined/library paths. Source inspection is the reliable no-new-`HostSpan` argument here. Neither test proves production machine-code identity, no incidental allocation by all runtime libraries, queue-command identity, default-off model parity, or performance. Those remain separate link/runtime comparisons owned by root; this CPU report must not claim them.
