# Per-layer initial profile fill: break versus continue (R222)

Date: 2026-10-12. Read-only source comparison of pristine Xe v0.1.42, pristine official v0.1.43 and the Strata/SYCL integration tree at the requested integration snapshot. Prior reports R303-R306 and the supplied report registry v154 were checked to avoid treating old receipt evidence as current. No code, build, test, import/AST, GPU/model/process/Git operation or cleanup was performed. No TPS or correctness result is claimed.

## Finding

Yes: the pristine Xe v0.1.42 normal profile-fill loop can stop at the first saturated layer and leave slots in other layers unused. Official v0.1.43 and the integration loop both continue past that layer's quota refusal, allowing later profile entries from other layers to fill their own ranges. This is exactly the scenario named by the official source comment `#369 (dag08)`: one full layer previously ended the whole fill and left most layers empty.

The break is specific to the main, single-cache profile-fill loop in pristine Xe: if `profile` and `srcp` exist, it sets `want = min(profile.size(), xcache.slots())`, calls `admit` in profile order, and immediately `break`s on any `kNotResident` (`Xe src/program/generate.cpp:4435-4457`). It does not ask whether the refusal means only that this particular layer is full. With per-layer admission, `ExpertCache::admit` returns `kNotResident` when the current layer's range is exhausted (`Xe src/core/expert_cache.cpp:432-461`). Therefore once a layer has received its quota, the first later profile pair for that layer ends the Xe fill loop—even if other layers still have free slots and later ranked pairs could fill them. Under a global/non-per-layer cache, `kNotResident` means the global range is full; the same `break` is correct there.

Official v0.1.43 computes `want = profile.size()` when per-layer admission is active and continues on `kNotResident` for that mode; only the non-per-layer path breaks (`sycl/src/program/generate.cpp:4597-4604,4727-4745`). Its pipelined GGUF-fill branch is explicitly disabled when `per_layer` is true (`:4612`), so the relevant per-layer path is the later serial fill loop with the continue. The integration tree uses the same normal-loop rule (`src/program/generate.cpp:3184-3204`): `want` is the full profile length in per-layer mode, and quota refusal continues. Its separate fill branch for GGUF pipelining likewise excludes per-layer mode. Thus this repair is not conditional on `--prefill`; it is conditional on per-layer cache admission within the profile-fill path.

The old R306 receipt records 29 of 144 slots prefilled in its 2026-10-11 host-USM run, consistent with the old break behavior and a concentrated profile prefix. It is corroborating historical evidence only: it is not the current v0.1.42 startup, and it does not establish what the present profile's first saturated layer or fill count will be. The current pristine-Xe run's original failure status is not changed by this source analysis.

## Exact conditions and capacity versus fill counts

The profile fill runs only when the profile is nonempty and the selected source pointer is non-null. `per_layer` is read from `xcache.per_layer_admission()` after the option/configuration has set that cache mode. A successful cache allocation is also required to reach the fill loop. The official `--short-read` / `--spec` verifier-window choices and Xe `--prefill 8`/8K chunk choice do not choose the break/continue branch; the fill is startup cache initialization before request routing. Cache policy, source kind, profile availability, and per-layer admission do.

For 48 layers and quota 3, the Xe log's physical capacity 144 means 144 allocated VRAM slots, not 144 slots populated by profile reads. The mode has an independent per-layer capacity. A successful `admit(layer, expert)` claims a new slot and increments `admitted_`; a repeat pair returns its old slot without a new admission. `resident()` reports distinct admitted experts when per-layer admission is on; `slots()` remains physical capacity (`include/strata/core/expert_cache.hpp:99` in Xe; corresponding accessor in official/integration). `fills_` increments for each successful copy operation, including a fill of a previously admitted duplicate pair; the local startup `prefilled` counter likewise increments after each successful fill attempt. Hence the meanings are:

- `slots()` / `INFO expert_slots`: allocated capacity.
- `resident()` / `admitted_`: distinct pairs assigned a slot (does not prove all bytes were correctly transferred).
- `fills()` and local `prefilled`: successful fill calls/attempts, not necessarily distinct pairs if the profile contains duplicates.

The profile readers in all three compared trees validate header/geometry, pair bounds and truncation, but the inspected versions do not reject duplicate (layer, expert) pairs. Therefore one must not assume `prefilled == resident` solely from source structure. With a unique profile and successful copies, they should agree for this one-time fill. The actual `INFO` capacity or a “pre-filled N of M slots” message alone does not reveal the complete per-layer residency map; count/slot map or equivalent runtime summary is needed to establish it.

There is also a sizing distinction before filling. Pristine Xe and official v0.1.43 use a uniform per-layer quota `q=floor(cap/sum(aligned layer blob sizes))` and make `L*q` physical slots (capped by expert count); the prior Xe receipt's 128-largest-blob budget yielded 3 per layer = 144 physical slots. In the current Strata/SYCL integration, native per-layer `per_layer_slot_sizes` and `per_layer_slots_that_fit` are used under `STRATA_ENABLE_SYCL` (`src/program/generate.cpp:3017-3031`, `expert_slot_sizes.hpp:15-48`); automatic sizing can include a remainder in the last layer. For manual `--expert-cache N`, this code keeps N as `o.expert_cache` and lays out that many per-layer slots, with `ExpertCache::layer_slot_range` placing the remainder in the final layer. Thus identical numeric `--expert-cache` requests need not mean the same physical slot count across these source branches. Main should compare reported/effective capacity, not assume that “128” means 144 in every binary/configuration. This sizing difference is separate from the break-versus-continue defect.

## Decode and stream-all prefill effect

For decode, `expert_source.cpp` checks `slot_of(layer,expert)` for every routed expert; a pair without a cache slot is a miss, while a newly admitted pair can be filled if that layer still has capacity (`Xe src/core/expert_source.cpp:2047-2074`). Since the cache has no eviction, the initial profile prefix shapes warm-cache coverage; after an early break, unused per-layer slots can still be claimed by future decode routes. That does not retroactively prefill them: those first uses need source lookup and a cache fill. Therefore the break changes the initial set and may change cold misses/first-use work; it is not equivalent to permanently reducing capacity, and the source does not quantify tokens/s or hit-rate impact for a current profile.

For prompt prefill, the `stream_all` selector is independently `ring > STAGE && T >= STREAM_ALL_MIN && source != nullptr` (`Xe src/prefill/prefill.cpp:1323-1335`). The static cache residency table determines which routed experts are resident cache inputs and which are nonresident experts to stream through the ring (`:1922+,2056-2078,2092-2102`). The fill-loop fix does not change chunk size, ring size, threshold, issuer, stream ordering, or the `stream_all` boolean. If it makes additional layer quotas resident, it changes which experts are staged for that prompt and which read from VRAM; exact routed set, staged bytes and elapsed time require runtime measurement. Thus stream-all remains the same algorithmic route while its resident/nonresident partition can differ. It is inaccurate to claim that this change disables or bypasses stream-all, or to predict a prefill speedup from capacity alone.

## Applicable fix and useful host-only fixture

Official v0.1.43's inline `#369 (dag08)` change is the directly applicable fix: in per-layer mode, continue the profile scan when a layer quota is full; retain `break` for global admission. The integration tree already has this condition in its fill loop. The pristine Xe v0.1.42 loop lacks both the per-layer `want=profile.size()` and conditional continue. Do not generalize the per-layer continue to a non-per-layer cache, where the first refusal signals global exhaustion.

A minimal CPU-only fixture can exercise the policy without model data or a GPU: use four synthetic layers, quota one each, and profile sequence `L0:A, L0:B, L2:A, L1:A, L3:A`. A faithful `admit` returns slot 0 for L0:A, then `kNotResident` for L0:B because layer 0 is full. The old global-break policy must report one successful admission and leave layers 1-3 empty; the fixed policy skips only that refusal and admits the later three layers, reaching four unique admitted entries. Assert the slot map, `slots=4`, `resident=1 vs 4`, `fill calls=1 vs 4`, and every layer range. Add a duplicate pair in a separate fixture to show `fills/prefilled` can exceed `resident` if the caller refills a claimed slot. These tests should target a factored host-only per-layer scan/admission helper or a fake admission interface; constructing `ExpertCache` itself allocates device memory and is not CPU-only. They validate control logic/accounting, not copy correctness, profile quality, hit rate, prefill latency or TPS.
