Safety/provenance findings

The implementation design is substantially fail-closed: explicit child environment allowlist; child cmdline/environment checks; source/package hash pins; external owner hash immediately before import; forbidden credential receipt rejected before read; source guards at preflight, READY, DONE and final; model stat identity checks; same-boot health hash/phase checks; owned pidfd closure; flock serialization; fixed 11 fresh roots; failed prefix blocks retries; only normal QUIT/reap is success; and first body failure is preserved as `primary_model_failure`. Source says incomplete/failed roots block later roots and are not converted into PASS. Actual enforcement has not been exercised here.

Runtime controls are bounded on paper: each root/model run has a 1800 s total admitted controller/engine budget, startup <=300 s, utility wall limits 30 s, QUIT send <=5 s and close <=30 s; engine RSS 88 GiB, utility RSS 4 GiB, logs capped at 64 MiB/file, 96 MiB/root and 64 MiB aggregate. CPU limits (3600/3601 s) are looser than the absolute 1800 s wall cap, so wall is the effective bound. Main still needs its documented outer controller overhead budget. GPU execution itself has no independent interruptible kernel deadline documented: the engine/root wall deadline is the practical bound and must be tested for enforcement, not treated as a separate GPU watchdog.

Debug, clean and guard environments are deliberately distinct. Debug enables ZE/parameter validation and logging/tracing. Timed and held-out clean arms set validation to zero, logging off, and remove `STRATA_TRACE` entirely because presence enables tracing. Guard-on/off pairs differ only in `STRATA_NAN_GUARD`; source confirms that option is read in `src/core/verify.cpp` (`Verifier::nan_guard_on`, around line 2260). Safety controls otherwise remain fixed. Fresh health must match the exact arm environment. Debug route checks trace four 8192-token chunks; clean route checks cannot use traces because tracing is disabled.

Evidence limits and interpretation

The 11-root design uses fresh 32768-token prompts and 16-token greedy decoding: startup guard, debug off/on, three timed off/on pairs, and independent held-out off/on. Each ON arm binds the OFF receipt and identical input hash; pair equality checks exact generated tokens and LP5 fingerprint. It retains per-run host and engine timing samples. This is appropriate for a narrowly scoped guard/performance comparison if all admission gates pass.

Important limitation: clean timed/held-out protocol validation requires no trace, so it cannot empirically establish the runtime read route. The controller's `actual_route` output is source-coded; progress and PP lines do not independently prove the route. Debug traces do observe the route. Therefore describe the clean route as source-bound/inferred from fixed source and environment, or add a separately reviewed non-instrumenting route receipt before claiming clean-arm route observation.

The quality/correctness evidence is limited to 16 generated tokens and LP5 fingerprint equality. It does not establish full-logit parity, full-output quality, perplexity, 262K context behavior, restore/session behavior, or an optimal route. Do not broaden claims beyond the measurements.
