## Findings

The Xe tree is not missing the upstream server wholesale: it contains the mature request queue, restart waiters, saved sessions, slot save/restore, and fatal native-restore invalidation. Its fatal-recovery test is present and exercises a native `FATAL` that leaves the child alive: [serve/test_fatal_recovery.py]. Keep that recovery path. The highest-value functional gap exposed by this delta is a specific engine/server protocol pair: upstream v0.1.43 recognizes a `DONE ... nonfinite` / `BDONE ... nonfinite` finish, prevents poisoned-window tokens from being emitted in `generate.cpp`, drops that request's cached state, and lets the service retry a request once only when no token has been sent. Xe `src/program/generate.cpp` has no `nonfinite_hit` detector or `DONE/BDONE nonfinite` producer, and Xe `serve/server.py` has no `EngineNonFinite` handler/retry. Its `LP nan` diagnostic is not an equivalent guard. This is a correctness/fault-recovery gap, not a performance feature, but it is not safe to fix by copying only server code: the engine must implement and test the matching terminal status and cache invalidation across solo, batch-slot, prompt, and decode paths. The v0143 server behavior is at `serve/server.py:318-320, 1184, 1348-1349, 1454-1455, 1498, 1716-1717, 3891-3945, 5090`; engine comments/paths at `src/program/generate.cpp:6203-6209, 7988-7998, 9442-9445, 9600-9603, 10622, 10675, 11061, 11668-11678, 11942-11948`. Xe source has none of the detector/finish markers (search of its generate.cpp shows diagnostics only).

The lowest-risk cohesive first landing is the **server-owned optional exit page-cache release**: add upstream `serve/cache_drop.py` and `serve/test_cache_drop.py`, plus the small `server.py` shutdown hook (upstream around line 6450) after engine close. It is default-off, POSIX-only, checks the engine process exited, advises only model files named by this engine (`--native`, `--pack`, `--mmproj`, `--model`), and never raises; it has no engine protocol dependency and no serving-time effect. It is an optional host-memory/page-cache preference, not a correctness requirement. Keep this as a separable change; do not tie it to engine cache invalidation or R190 NaN recovery.

`serve/replicas.py` and `serve/test_replicas.py` are absent locally. Upstream config/CLI offers opt-in data-parallel replicas with card grouping and round-robin load distribution (`serve/server.py` around `start_replicas`, `--replicas`, and replica startup); classify this as optional multi-GPU capacity/throughput, outside the single-GPU functional baseline. `serve/test_ready_timeout.py` is also upstream-only; Xe already has readiness timeout behavior but lacks that regression test, so port/adapt the test against Xe startup semantics rather than replacing its implementation. `serve/test_restart_waiters.py` exists in both trees.

There are relevant API differences beyond those newer opt-ins. Upstream imports `serve.logit_bias`, normalizes OpenAI `logit_bias` against tokenizer vocabulary, and includes the bias in the cache projection key (`server.py` around lines 62, 1023, 5340); Xe has no such import or validation, and its engine has no matching bias request protocol. Do not expose this API by porting only the request parser: it needs an engine sampling-parameter contract and tests for vocabulary bounds, projection/cache separation, and actual logits. Upstream also has opt-in `reasoning_effort` / `effort_position=end` support and its `tools/test_effort_end_args.py`; Xe already has parts of effort handling, but the upstream test is not present and must be adapted to its wrapper executable resolution as recorded in R349. These are service/API parity items, not prerequisites for existing requests.

## Setup delta

Both trees have `get_llama_cpp()`, but the Xe version at `setup.py:1181` has no `BadZipFile` cleanup path or `drop_archive()` call. It downloads to `third_party/main/llama.cpp-<hash>.zip`, extracts all members, and unlinks the archive only on success. Upstream `setup.py:1715` catches `zipfile.BadZipFile`, removes the archive and `.done` marker while preserving the original exception, and excludes unused `/tools/ui/` members to avoid deep paths on Windows; its regression is `tools/test_setup_llama_archive.py`. The Xe archive is laid out under `third_party/main/` and its installed source additionally requires `tools/mtmd/CMakeLists.txt`, so transplanting the upstream function/test verbatim is wrong. The concrete Xe fix is adapt the damaged-ZIP discard/retry behavior to this path and its stricter installed-source validation, then port/adapt the test. This is a setup recovery bug, not a serving/API blocker. The test is standard-library-only and uses a local tiny ZIP, so it is suitable for the instructed offline setup-test lane.

## Safe dependency boundary and validation

1. For host-side optional page-cache behavior, port just `serve/cache_drop.py`, its isolated unit test, and shutdown invocation. Validate with `python -m unittest serve.test_cache_drop` and existing server lifecycle tests. No engine rebuild is involved.
2. For nonfinite recovery, treat it as a separate engine/server protocol feature. First map all SYCL execution routes that publish logits (`solo`, `batch` solo/admission/slot, prompt and decode including any verify/speculative path); make the engine scan before sampling/emission, ensure only the affected cache state is discarded, and emit the exact documented finish statuses. Then add server parsing/one-retry-before-first-token and terminal-error-after-retry/after-output semantics. Add/adapt tests equivalent to upstream `serve/test_server.py` DONE parsing, `serve/test_parallel.py::test_nonfinite_in_batch_mode`, and service/API coverage around retry/no-duplicate-output. The upstream logic is a protocol reference, not evidence that the SYCL implementation is safe.
3. For setup archive recovery, adapt the implementation and `tools/test_setup_llama_archive.py` fixture to Xe's `third_party/main` and mtmd contract; run only the named Python setup test after implementation.
4. Keep `replicas`, `logit_bias`, `effort-end`, and `keepawake` as separately reviewable API/performance deltas; rely on R165/R349 for their broader dependency audit rather than importing the newer server wholesale. In particular the pristine official Xe-unsafe long-model route (volatile host-USM `done_seq` plus PLE completion polling; R169/R185) remains a hard execution gate: do not use upstream serving support to imply that route is safe or authorize a benchmark.
