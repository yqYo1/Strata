Field interpretation

Intel Compute Runtime’s Zebin definitions identify these as separate metadata fields, and its decoder maps `grf_count` to `numGrfRequired`, `eu_thread_count` to `numThreadsRequired`, and `private_size`/`spill_size` to private-scratch/spill-fill-scratch descriptor values. Therefore the artifact reports a compiler-selected GRF requirement of 256 and an EU-thread-count descriptor value of 4 for this kernel. These are static compiler metadata, not measurements of live register pressure, actual running threads, occupancy, or spill traffic. `simd_size=16` describes the kernel’s SIMD width metadata; `has_dpas=true` reports the DPAS feature flag. Neither proves runtime execution of the kernel or a performance result.

Spill and private-storage status is unknown from this record. An omitted `spill_size` is not an explicit zero-byte spill size; omitted `private_size` and `per_thread_memory_buffers` likewise do not establish absence of private/scratch use. Runtime decoder defaults, if any, are not evidence that the artifact explicitly emitted those values. Intel’s optimization guidance treats nonzero spill memory as evidence of spills and nonzero private memory as evidence of a private variable not promoted to registers; the converse can only be used when the corresponding compiler metadata is actually present and authoritative for this artifact.

Minimal offline follow-up that can bound the question

Use the already-hashed `image_bmg.bin` as the input to the matching installed `ocloc` disassembler, explicitly target `bmg-g21`, and save output in a fresh diagnostic directory. Extract the `.text` section for the exact mangled kernel and retain the disassembler identity/version, command, section identity, and output hash. Inspect the native ISA for compiler-generated scratch spill/fill accesses using the matching Intel ISA definitions, and distinguish these from ordinary program memory operations. If the disassembly unambiguously identifies spill/fill operations, report the positive evidence and its scope. If the disassembly cannot distinguish spills from other scratch or memory traffic, it only bounds the observation and the status remains unknown; absence of recognizable instructions alone is not proof of zero spills.

If the existing native image cannot provide an attributable answer, an offline repeat of the exact recorded AOT compile can enable Intel Graphics Compiler shader dumps (`IGC_ShaderDumpEnable=1`, `IGC_DumpToCustomDir=<fresh-dir>`) while keeping the source input, target, compiler binary, and compile options fixed. Preserve the emitted final `.asm`, `.isa`, `.visaasm`, `.options`, and any `.ze_info` for this exact entry; compare hashes/options with the recorded compile before treating it as equivalent evidence. Prefer explicit emitted `spill_size`/private-size metadata or final native ISA spill/fill sequences. Do not infer zero from missing fields or from an intermediate representation that does not include final register allocation. This procedure remains offline and cannot close runtime/JIT or model-invocation questions.
