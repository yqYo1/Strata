## Admission

Source admits the stated route for a GPU fixture, subject to the existing runtime/device checks: with an expert miss (ar_on()==false), STRATA_VERIFY_STEPPED=1 captures command-graph segments and runs the host pool only after the preceding segment's queue wait; the CPU reads the ring/payload only after cs_->wait(), and writes plan/flags before submitting the next segment. STRATA_VERIFY_PIPE=0 disables the helper-thread path. This removes the concurrent host/device polling and store overlap at the layer handoff. The prompt-to-decode transition also drains the final async commit before returning from the read loop.

This is source admission, not a claim that a particular GPU/driver run succeeds. The pristine source makes the all-resident case distinct: ar_on() means all_resident_ && !ar_off_ (verify.hpp:339), not device_plan_. Thus the requested STRATA_VERIFY_DEVICE_PLAN=1 does not by itself divert a miss-bearing window into the all-resident path. If every expert is resident, stepped_ar is used instead: host prepares optional PLE rows and raises the single flag before graph launch (verify.cpp:2041-2057); no host polling loop is used.

## Access and ownership sequence

- read_windows(a,b) copies each up-to-S prompt-token window and its teacher-forced next-token IDs into ordinary vectors, disables head sampling, calls ver.run, commits every prompt row, then calls ver.wait_commit before returning (generate.cpp:9964-10009). With short-read 65536 the 32768-token text segment satisfies windows_ok unless it includes image embeddings or STRATA_CKPT_REREAD is set (9839-9848); the exact segment routing is handled elsewhere and is not re-audited here.
- Verify host buffers (tokens, positions, commit inputs, output, ring/payload, flags) are allocated by the SYCL host-USM helper; in stepped mode ordinary payload buffers are used unless STRATA_VERIFY_HOST_UNCACHED is set (verify.cpp:218-237, 530-550). Before every window, the host fills token/position arrays and clears ring/payload tags and flags (verify.cpp:1935-1954).
- For a miss-bearing window, capture selects segmented capture when stepped is enabled and eager mode is absent (verify.cpp:1737-1744). serve waits for the submitted segment, then reads h_seq_ and ring payload, executes CPU experts, publishes plan/flag-A as needed, waits for copy work, and raises flag-B/M before the next segment is enqueued (verify.cpp:2041-2149). The disabled pipe option removes the helper thread / concurrent pool-run-and-flag-A-spin block (2090-2117). The default segment loop submits each remaining segment in order (2140-2150).
- A 32768-token prompt at spec/window size 8 is 4096 windows if one uninterrupted segment is routed through this window loop (last window is still committed in full); each window's commit(T) may be asynchronous, but read_windows waits for the final commit before returning (generate.cpp:10003-10009; verify.cpp:2617-2736). The host commit fields are written before commit graph submission; the final event/queue wait orders completion ahead of decode setup.
- SPECULATIVE DECODING begins with the last prompt token as input to produce the first output (generate.cpp:12010-12031 and 12252-12275). With no MTP and --suffix-draft 0, the loop sets T=1 and suffix drafting is disabled (generate.cpp:12317-12330). Therefore the first 16 outputs are 16 serial one-token verify windows; --spec 8 is not an eight-token draft in this configuration. The greedy verifier path reads the mapped output only after the verification queue has completed; no sampled-token host readback is needed (verify.cpp:2365 onward; sampling defaults greedy at initialization, 558-559). State commits follow each generated window (generate.cpp:12425 onward).
