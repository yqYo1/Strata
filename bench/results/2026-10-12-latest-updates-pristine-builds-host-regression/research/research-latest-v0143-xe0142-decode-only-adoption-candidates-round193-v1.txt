# R193 — Decode-only candidate eligibility in official v0.1.43 and Xe 0.1.42

Date: 2026-10-12 (Asia/Tokyo). Read-only source/reports comparison. No build, test, compiler, AST/import, runtime/GPU/device/process query, model run, Git mutation, or cleanup. This report considers decode changes only; prefill speed is not used to select decode work.

## Finding

The newest diffs yield one decode behavior worth a controlled, opt-in candidate study: Xe's `STRATA_ROUTE_RESIDENT` rank adjustment for a verified cache-miss cohort. It intentionally changes routing and output, so it is not a safe default adoption. No retained exact B570 decode result shows that this cohort is a critical-path bottleneck or quantifies the resulting quality/performance tradeoff.

Do not transplant the newer Xe early `Verifier::service` return to B570 as-is. Its purpose is to avoid a device switch on a no-doorbell poll, but it still reads the volatile host-USM doorbell; the current B570 capability record lacks host-USM `CONCURRENT`, and W337's fail-closed host-handoff/segmented behavior must remain authoritative. Official v0.1.43 fused wait/copy and conv+projection work is CUDA/HIP-specific and cannot be carried into the SYCL B570 kernels as a source-only policy. Latest Xe's MTP context-edge bound is already subsumed by W337's stronger output/context predicate (R191). No distinct safe sampler/KV/attention implementation candidate remained after these exclusions.

## Candidate: resident-aware MoE routing (`STRATA_ROUTE_RESIDENT`)

Xe 0.1.42 adds an opt-in pass after the ordinary router and before planning/doorbell in `src/core/verify.cpp`. It is limited by source to 512 experts and top-10 routing with a resident-expert map; default rank range is 6–9, with a configurable positive logit margin. It can replace lower-ranked nonresident choices with resident choices and records separate statistics for windows `T<=8` (decode) and `T>8` (prompt). The route prior/resident adjustments alter selected experts; weights remain router weights according to source comments. W337 has no corresponding `STRATA_ROUTE_RESIDENT` kernel/policy.

Potential mechanism: for requests with actual nonresident/CPU/PCIe misses among ranks 6–9, replacing a route with a resident expert could reduce a slow expert fetch or CPU service event. It will do nothing useful when the selected expert set is already resident, there are no eligible ranks, or host/device/cache policy makes the relevant traffic noncritical. It also changes model computation and output distributions, even with a numerically small margin. Therefore this is a quality/performance tradeoff, not semantics-preserving scheduling.

Eligibility for W337 is unresolved: current B570 production source uses its own router, expert source tiers and cache policy. R307 states that existing clean decode receipts lack a joint actual decode format/NT/owner histogram; a task-6 diagnostic is not a clean default request. R335's 1.31x Xe-vs-D 64-token sample (8.855 to 11.607 tok/s) had differing outputs after five IDs, MTP work, cache fill and 1.7% vs 4.6% decode cache-hit ratios, as well as different builds/runtime paths. It is not evidence that route-resident adjustment caused a speed gain. R203/R204 say aggregate host phase timings overlap GPU work and do not identify the critical path.

Decision: retain as the single candidate for a guarded B570 experiment only after a clean decode request demonstrates eligible rank/miss exposure and phase attribution. A test should keep prompt, context/KV mode, cache occupancy/slots, expert source tier, CPU-share/host-handoff mode, MTP policy, fixed decode inputs and binary otherwise constant; measure paired physical decode wall and actual route/cache/miss deltas separately. Require a paired target-quality comparison with explicit acceptance criteria before considering any default. Do not infer benefit from a prompt/prefill result.

## Changes rejected as independent B570 speed ports

**Xe verifier no-doorbell poll return.** In `src/core/verify.cpp`, Xe checks `h_seq_` and timeout/deadline before `OnDevice`; if there is no pending doorbell and recent flush/deadline bounds hold, it returns immediately. This can reduce host poll/device-switch overhead in a genuinely active pipelined verifier. W337's `Verifier::service` constructs `OnDevice` before its `h_seq_` poll. However, W337 guards its paths with `host_handoff_concurrent(cs_)`, and B570 R351 records host-USM access without `CONCURRENT`. A shortcut which merely moves or repeats the volatile read does not establish a safe host/device handoff. R342 separately documents that disabling overlap alone still polls and that captured TokenGraph handshakes are not repaired by a completion event. The optimization is not eligible for the B570 path unless the source first proves a safe serialized/no-doorbell service state that needs no concurrent mapped polling; no such performance evidence is retained. Do not import it based on Xe's behavior.

**MTP max-step cap near context end.** Xe 0.1.42 bounds draft steps by remaining K/V cells. W337 already applies `context_bounds::mtp_window`/`verifier_window` with both context and remaining-output constraints, including next-window bonus reservation. R191 directly corrects the earlier symbol-level false gap and establishes W337's stronger behavior. This is no new optimization and must not be presented as an adoption candidate.

**Official v0.1.43 fused verify work.** Upstream diff adds CUDA/HIP paths including fused GDN conv+AB projection and wait/copy operations, with source comments describing gfx12-specific measurements. These implementation units and graph launches are CUDA/HIP, not B570 SYCL. The release diff does not supply a portable SYCL implementation, nor local Xe2 instructions/measurements. Reimplementation would need SYCL kernel/API work, graph and doorbell lifetime proof, exact numerical parity, and B570 timing; it is outside a narrow independently importable optimization. Official nonfinite detection/recovery is a correctness/recovery feature, not decode speed evidence.

**Sampler and KV/attention changes.** Xe 0.1.42 adds request-scoped target logit bias support and sampler ownership/dispatch conditions, not a faster default decode algorithm. R172 identifies nonfinite/no-candidate hard-ban fallback risks and a possible repeated bias read cost; W337 does not implement this interface, so there is no safe performance-only sampler patch. The Xe diff did not add a distinct QSA decode-attention or KV arithmetic kernel change suitable for port; the MTP bound is already covered as above. Avoid creating a sampler/KV rewrite without production timing tied to those phases.

**CPU expert decode dispatch.** R335 already reviewed Xe's broader AVX2 one-token native-expert dispatch and the existing narrow `STRATA_IQ3S_MT1` control. The latest Xe 0.1.42 CPU expert delta mainly refactors the oracle flag/feature checks, not a new decoded arithmetic fast path. R307 lacks an exact clean 64K NT1/type/owner denominator, and fixture service numbers use synthetic/prequantized activations. Do not use prefill CPU-share results or unrelated CPU fixture medians to select a decode kernel.

## Evidence needed before revisiting

First obtain one clean, full-lifecycle B570 decode receipt that binds the exact executable, pack/model, prompt/context and consumed positions, generated count, MTP windows/acceptance, cache capacity/fill/hits/refusals, KV mode/residency, expert source tier, route owners and per-request timings. Preserve fresh-first and restored decode as separate cohorts. Existing phase counters are host elapsed buckets and overlap; they need request join plus the route/miss evidence, not arithmetic summation. If resident-rank misses have real exposure and plausible critical-path contribution, then test the route-resident policy as an explicit quality-changing arm; otherwise stop. No decode bottleneck, 64K optimization, numerical acceptance, or adoption claim is made by this source review.
