## Prefill KV spill, reload, and ownership

In streamed mode, each QSA layer owns a host-USM authoritative KV copy (`layer.cpp:785-818`). The pinned host allocation is mapped to a device pointer before the pools are exposed to kernels. The host allocation is part of the persistent QSA state, not a prompt-local buffer. For the main QSA layers, `kv_mode==1` selects streaming; prompt state initialization creates an identity page table for the staging pool (`prefill.cpp:745-755`).

For each prompt chunk and QSA layer, `prefill.cpp:1688-1722` stages all prior complete pages from the host copy into the layer staging pool using `ceil(p0/page_size)`, then appends this chunk's K/V to its host copy and staging pool. The append for the tail chunk writes cells `[32768,37460]` into the host copy and staging pool; attention then reads from the staged pools (`prefill.cpp:1852-1865`). At chunk end, the ordinary compute stream remains ordered through projections, append, selection, and attention. For decode, `qsa_kv_resolve` calls the resolver only when `kv_mode==1` (`layer.cpp:888-893`). On the Xe path, `kv_stream_resolve` submits a resolve kernel and then the host-to-slot gather-copy kernel on the same runtime queue (`kv_stream.cpp:212-243`); the attention consumer is subsequently enqueued on that stream. ## Buffer lifetime and completion dependencies

The host KV pools are persistent QSA state allocations; the staging pools are part of Prefill's carved device region and survive all chunks of this `Prefill` object. `kv_stage_from_host` enqueues its copies on the supplied stream and only explicitly finishes for a null stream (`kv_stream.cpp:269-276`); in the audited call it receives `m.cs`, so stream submission order supplies the dependency before subsequent appends/attention. The full run drains `m.cs` before returning success (`prefill.cpp:3034-3038`). Error unwinding drains both compute and expert-copy streams before the buffers are released (`prefill.cpp:3132-3140`); `release()` likewise syncs both (`prefill.cpp:541-544`). Cleanup treats failed synchronization as unconfirmed completion and exits before freeing referenced host buffers (`publication.hpp:23-30`).

The separate expert H2D path is not the KV spill path. For expert blobs, compute waits on the per-slot `copied` event before consuming a staged slot; stager workers wait for the earlier DMA completion before reusing host staging buffers (`prefill.cpp:1464-1474`, `Stager::work` around lines 316-329). The issuer joins and drains before stager buffers retire (`prefill.cpp:1504-1509`). This is consistent with the controller's source-side ARENA_HOST_USM1 setting, but this source audit does not establish actual host-USM overlap qualification or run completion.
