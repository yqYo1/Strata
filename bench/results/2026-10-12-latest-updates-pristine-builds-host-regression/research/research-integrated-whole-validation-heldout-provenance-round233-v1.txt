This validation split is separate from the prepared train split at the source-file/hash level, but both are files from the same Strata repository/source commit. The preparation record explicitly says this gives no independent-authorship or population claim. Its diagnostic overlap with train was 88 common-prefix IDs and 92 shared 16-ID shingles, below its 80% rejection threshold; that is only a near-copy alarm, not evidence of statistical independence. The held-out content is also not from an unrelated repository. It must not be described as independent generalization data.

The canonical 32K campaign remains the first 32,719 IDs plus the 49-ID tail from a historical 65,536 fixture. R231 documents its shared historical lineage and warns that changing only the tail would be weak independence. The candidate's different source and token hashes show it is not that exact token sequence; they do not prove novel authorship, task independence, or quality generalization. For the proposed guard-off/on comparison it can be an input-disjoint paired sample, with that narrower wording.

Controller-v3 admission and Main handoff

Current integrated source-v3 `common.py` permits held-out geometry 32,768–65,536 and requires `whole_document_preserved=true`; `run_root.py` carries the full measured held-out sequence without crop/splice/pad; `protocol.py` validates the actual supplied prompt length. The current 37,462-token file therefore fits the source-level geometry. The source-v3 pending qualification still has `main_reviewed=false`, `held_out=false`, and no reviewed input pin.

Source-v3 additionally requires a separate pinned `preparation_receipt`. Its verifier expects a passed, complete, inactive, Main-reviewed and provenance-reviewed receipt, `whole_document_preserved=true`, `altered_to_fit=false`, `model_executed=false`, and exact equality of input path/hash and token count. The v2 preparer candidate record does not satisfy this schema (`completed=false`; it has no Main/provenance review fields). The outer CPU receipt is useful closed-command provenance, but is not that preparation receipt either. Main must create and review a separate immutable receipt binding the exact candidate path/hash, count 37,462, complete four-document/task provenance, tokenizer/source pins, and the existing closed CPU run receipt; then pin both the input and receipt in the v3 qualification. Recheck both hashes and all five pack assets before the first held-out root. Do not edit or retrofit the old candidate record and do not set Main review flags until task and provenance review is complete.
