## Critical reconciliation: W337 does not implement native `--session-save-reclaim`

The W337 Python server does detect the literal flag in `StrataEngine.__init__` (`serve/server.py:626`) and enables the Python SAVE retry wrapper on that value. That is not evidence of a native implementation. A direct source search of W337 `src/` and `include/` finds **no** `--session-save-reclaim` option, `session_save_reclaim(...)` call, reclaim header, or implementation. Its native option parser at `src/program/generate.cpp:2335–2456` handles the existing session/cache arguments and rejects every unknown argument with `unknown argument: ...` / exit code 2. Therefore a config containing `--session-save-reclaim` reaches the engine as an unknown option; the server can treat it as opted in, but the engine cannot start. Even if only the Python retry helper were wired around the current engine, it would only repeat the same SAVE after psutil reports enough host RAM; it does not evict any native cache.

W337 **does** implement the existing typed refusal protocol and its baseline native SAVE admission. In `src/program/generate.cpp:7792–7799`, the native handler emits one-line `SERR <kind> <published> <reason>`; SAVE computes a conservative preflight before capture and calls `refuse(why, SessionError::memory)` when admission fails (`:7850–7884`). The refusal text has the shape the Python parser expects: `not enough RAM to save the session (<need> MiB plus a floor of <floor> MiB needed, <available> MiB available)`. The Python `SessionRefused` parser also distinguishes malformed/out-of-step output, typed errors, and `FATAL`; W337's fatal RESTORE/device-state handling must remain intact. This proves the **typed memory refusal** contract exists, not the reclaim contract.

Official v0.1.43 has the complete native opt-in. `src/program/generate.cpp:628, 778, 2010` declares, documents and parses `--session-save-reclaim`; the SAVE path at `:9854–9877` invokes `session_save_reclaim` before `session_save_checkpoints` copies/selects save data, then rechecks the admission budget and emits the same typed memory refusal only if it still cannot fit. `include/strata/core/session_save_reclaim.hpp` implements bounded-by-content reclamation: drops reusable retained buffers, evicts unpinned parked conversations, then removes unpinned non-selected checkpoints; after each operation it re-probes. It preserves the selected deepest checkpoint and explicit pins, does not discard live device state, and uses no cache-reclaim path for RESTORE. `src/core/session_save_reclaim_test.cpp` and the conversation file tests cover the pure native helper. Xe `da3d426` has the same flag parse, native call and helper path (source inspected through `git show`); it is the closest protocol reference. Its SAVE refusal uses the v0.1.42 memory source, while official has since extended that source as described below.

**Required port is native + server + tests as one integration.** Port the native flag parse/state and reclaim helper/call before preflight selection; use a memory sampler that obeys official cgroup/explicit-cap semantics; retain the updated status/diagnostic line format and tests. Then keep the Python retry wrapper as a bounded, opt-in fallback only after the native attempt has reclaimed what it can. Verify the flag is accepted by native CLI, real native `SERR` remains parseable, native reclaim happens before SAVE capture, and RESTORE/fatal behavior is unchanged. A Python test with fake engine alone cannot qualify this.

### Memory-accounting correction to R192

R192's “no cgroup accounting in either checkout” statement was too broad. It was accurate for the Python `warn_budget_over_ram` advisory, not for native session memory.

- W337 `src/core/conversation_memory.cpp` reads only `/proc/meminfo: MemAvailable`; its `conversation_available_memory()` has no cgroup or explicit memory-cap input. The W337 expert-source cgroup helpers are for the separate mmap/file-cache capacity/reclaim logic and are not used by SAVE admission (`generate.cpp:7871` calls `conversation_available_memory()`).
- Official v0.1.43 `src/core/conversation_memory.cpp` samples MemAvailable and the visible cgroup v1/v2 ancestor limits, credits only clean inactive file cache, applies optional `--memory-limit-mib` / `STRATA_MEMORY_LIMIT_MIB`, and fails closed when an explicitly configured cap cannot be measured. `include/strata/core/conversation_memory.hpp` documents the source and limits. Native SAVE diagnostics use `ram_note(mem)`, which says `source meminfo`, `source cgroup`, or `source flag`; the regex-relevant required/floor prefix is preserved. This is a real host-memory contract gap for containerized runs, separate from the missing reclaim flag/helper.
- The Python retry helper's `available_mib()` is based on psutil host `virtual_memory().available`; it is advisory for retry timing and cannot stand in for the native cgroup/cap-aware admission check. Keep retry bounded and fail-closed when telemetry is unknown; do not make the Python value authoritative for native admission.
