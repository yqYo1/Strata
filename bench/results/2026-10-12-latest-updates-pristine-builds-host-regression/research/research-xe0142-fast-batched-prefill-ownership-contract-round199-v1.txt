R199 — Xe 0.1.42 fast batched prefill ownership contract
Date: 2026-10-12
Scope: source-only review of pristine XeStrata `da3d426079019daa6e01388d03b0d94ae67070b7`, specifically a long `--serve` text prompt routed through `--short-read 0 --prefill 8192 --spec 4`, with pool enabled, MTP absent, and CPU gate disabled. No tests, compiler, build, model/GPU/runtime/process query, Git mutation, or cleanup was performed. This is not a measured performance result or a hardware safety qualification.

Finding
-------
These options put every positive-length fresh text segment through batched `read_part`/`Prefill::run`, using 8192-token chunks when the request and memory plan allow. In that prefill implementation, expert staging and PLE buffer reuse are ordered by queue events; `src/prefill/prefill.cpp` contains no volatile host/device polling. This ownership mechanism is distinct from the old sequence-word polling described in the official v0.1.42 prefill report.

The exact proposed environment names `STRATA_VERIFY_STEPPED` and `STRATA_VERIFY_PIPE` are not present anywhere in this pristine Xe tree. They do not select a verifier mode here. For Xe, the supported switch is `STRATA_VERIFY_SEGMENTED=1`; the supported pipeline control is `--pipeline-windows 0` (also the default). With segmented verifier execution selected, the source waits for the compute queue before the host reads its sequence word and submits the next graph segment only after host planning/publication. That is the existing source-level fallback for the verifier's host/device control words. MTP absence avoids MTP's separate mapped-output polling path, but does not by itself avoid the verifier's ordinary control-word polling. The configuration as stated therefore does **not** establish the intended verifier ownership protocol; use the source-supported segmented option if reviewing an end-to-end request.

No unpatched Xe command can be called source-proven safe end to end on the historical B570 setup. First, the all-kernel executable-bundle preload is unconditional and independent of the prompt/verifier settings; historical evidence records a PackedA module-build failure in that operation. Second, the prefill event edges are not fail-closed at every call site: several event record/sync/wait return values are ignored. The code demonstrates an intended queue-ownership design, not validated success under event/API failure or on this device. No startup, correctness, speed, or device-safety claim is made.

Prompt route and configuration boundaries
-----------------------------------------
- `--short-read` parses an explicit nonnegative limit and remembers that it was given. For explicit zero, `ShortReadCost::windows` returns true only for `tokens <= 0`; every positive-length fresh text part is therefore batched. The serve loop chooses `read_part` rather than `read_windows`. Image-bearing segments are also routed batched. Set `--prompt-cache 0` and `--conversation-cache-mib 0` for a fresh-input control; otherwise a matching prompt checkpoint can bypass the path.
- `--prefill 8192` is a fixed chunk size (it is not the `auto` policy) and requires `--native`. The first full chunk of at least 2048 tokens chooses `stream_all` when a source is present; `ring_slots(T)` then clamps the ring to at least 16, which exceeds `STAGE=8`. The final short chunk can fall below 2048 and use the smaller non-`stream_all` path. A fixed serve chunk may be reduced if the lend planner finds a smaller one that fits; if no lending plan fits, source allocates its own buffers. Thus record the effective chunk and borrowing decision from the actual run; these flags alone do not guarantee 8192 fits B570 VRAM.
- A native pack requires the matching native shard and `--ple-gguf` (native PLE is required by source). `--serve` requires `--spec T` and a fillable expert cache; the graph-hit path additionally requires its expert profile. Model/context limits, available VRAM/RAM, pack format, cache/profile completeness, PLE shard validity and actual prompt length remain admission conditions. For the request context, preserve the documented request constraint `prompt_tokens + max_new + 8 <= max_context`.
- No `--no-pool` keeps the normal CPU expert pool available. For a full 8192-token `stream_all` prefill chunk, the prefill CPU-share eligibility test includes `!stream_all`, so the CPU pool is not assigned those full chunks. A final chunk below `STREAM_ALL_MIN`, or other non-stream-all conditions, can be eligible. `STRATA_PREFILL_CPU_GATE` only enables the experimental alternating layer gate when its first character is `1`; setting it to `0` (or leaving it unset) disables that gate but does not disable the default automatic CPU share. Use `STRATA_PREFILL_CPU_SHARE=0` only if the intent is to exclude CPU sharing from the prompt path while leaving the decode/verifier pool enabled.
- MTP absence means `--mtp` is omitted. It does not necessarily mean one-token decode: `suffix_draft` defaults to 3. For a one-token decode control, also pass `--suffix-draft 0`; `--spec 4` is only the verifier window capacity absent other draft sources. `--pipeline-windows 0` keeps the serial serve loop explicit.

Queue ownership in batched Prefill
----------------------------------
1. `Prefill::init` creates the copy stream, per-ring `copied` and `used` events, and (when applicable) the PLE and Stager events. A setup failure for these events is checked. In streamed staging, the issuer submits a host-to-device copy after the slot's last `used` event and records the `copied` completion. The compute queue waits for `copied` before consuming the stage slot; after the last reader, the compute queue records `used` to release the slot back to the copy issuer. `copy_async_after` encodes the wait/copy/completion-record sequence in the copy-queue submission.
2. The Stager workers copy source blobs into pinned host buffers. Before reusing a ring buffer, a worker waits on that buffer's prior `dma_done` event; the issuer records `dma_done` after queuing the buffer's DMA. Host-side `ready`, `issued`, `active`, and generation variables use C++ atomics/condition variables. Those are host-thread coordination variables, not device-written control words. A worker's `event_sync(dma_done[b])` and the issuer's `event_record(dma_done[...])` do not check their results.
3. PLE gather runs on a host future. The compute queue uploads its result and records `ple_copied[buf]`; before reusing the alternate host buffer, the code synchronizes the prior upload event. This is a queue-event ownership edge, not the old volatile `ple_done_seq` host polling. In this path, the return values from the copy, event record, and event sync at those call sites are not used to fail the request.
4. The prefill source has no `volatile` loads/stores in `src/prefill/prefill.cpp`. Some CPU-pool coordination is joined through `future::get`; the regular stream-all ring issuer additionally uses host atomics and yields. Neither proves that every GPU event operation succeeded. Treat these edges as the intended data lifetime and dependency ordering, with an unchecked-error qualification.

Verifier, decode and startup are separate
-----------------------------------------
- Xe `src/core/verify.cpp` chooses `segmented_` from `STRATA_VERIFY_SEGMENTED` if present; otherwise it calls `doorbell_visible(cs_)`. `STRATA_VERIFY_STEPPED` and `STRATA_VERIFY_PIPE` do not occur in the source. Explicit `STRATA_VERIFY_SEGMENTED=1` forces the queue-segmented branch. In `Verifier::run`, each segment is `stream_sync(cs_)`'d before the host checks `h_seq_`, calls the CPU pool, and publishes the next flags/launch; when segmented mode is active the graph's in-device wait kernels are omitted and the whole-window volatile poll branch is not used. Volatile sequence/flag loads and stores remain, but are sequenced at the queue boundary. Do not override with `STRATA_VERIFY_SEGMENTED=0` on a device lacking concurrent host/device access support.
- The source's default `doorbell_visible()` is a runtime visibility probe, so its result on a specific B570 is not established by this read. Its explicit mode override permits a deterministic source path for a later controlled run, but it is not itself hardware validation. Also keep `--pipeline-windows 0`: the separate pipeline mode has its own eligibility restrictions and verifier lifecycle.
- With MTP absent, MTP draft/prefill functions are not bound. In `src/core/mtp.cpp`, the MTP output/probability polling loops still use volatile mapped host memory when MTP is active; omitting `--mtp` avoids that subsystem. Normal verifier behavior remains relevant for every generated token, so segmented mode is still needed for the verifier handoff on the conservative path. If suffix drafting remains enabled, verifier T can exceed one without MTP.
- `Runtime::preload_kernels()` is invoked during startup and unconditionally enumerates `sycl::get_kernel_ids()` and asks for executable bundles. The short-read, prefill, pool, CPU-gate, and verifier environment options are all later path choices and do not filter that sweep. Prior retained B570 evidence has an unresolved PackedA builtin/module-build failure during all-ID preload; source overlap makes this a concrete startup eligibility blocker, not a proven da3d426 failure with a known current provider tuple. There is no pristine da3d preload-disable option, so a successful startup cannot be inferred from the request flags.

Source-level configuration for a bounded future evaluation
----------------------------------------------------------
Subject to owner-supplied valid pack/shards, matching PLE, cache/profile and a fit-capable context, the closest existing no-patch source configuration to the requested ownership boundary is:

    STRATA_VERIFY_SEGMENTED=1 STRATA_PREFILL_CPU_GATE=0 \
      ./strata --serve --native /path/to/model-shard-1.gguf \
        --ple-gguf /path/to/model-ple.gguf --spec 4 --short-read 0 \
        --prefill 8192 --pipeline-windows 0 --suffix-draft 0 \
        --prompt-cache 0 --conversation-cache-mib 0

Leave `--mtp` absent and do not pass `--no-pool`. Supply whatever required expert-cache/profile options the selected pack's route requires. Set `--max-context` to a numeric value at least the final tokenized prompt length plus the requested output cap plus eight. This proposal disables prompt cache reuse, forces the batched fresh-text route, keeps the serve loop serial, forces segmented verifier handoffs and disables the experimental CPU gate. It still does not disable/qualify startup preload, establish 8192-token buffer fit, check ignored prefill event failures, or prove runtime behavior. Do not label it tested safe or fast.

The exact environment in the task (`STRATA_VERIFY_STEPPED=1 STRATA_VERIFY_PIPE=0`) is not a supported Xe setting. If that exact configuration is used unchanged, `Verifier` chooses its default based on the visibility probe, which is an unresolved B570 runtime fact; the segmented ownership guarantee cannot be claimed from those misspelled/foreign environment names.

Existing safety comparison and evidence boundary
------------------------------------------------
The older official v0.1.42 risk was host threads polling device-written volatile `done_seq` for expert Stager reuse and `ple_done_seq` for PLE buffer reuse. Xe da3d's inspected Prefill uses event-based staging/PLE edges instead, so that specific polling mechanism is absent in these prefill routines. This comparison does not erase all volatile host/device handoffs in the program: standard verifier paths contain them, MTP contains its own, and the compile/preload stage precedes both.
