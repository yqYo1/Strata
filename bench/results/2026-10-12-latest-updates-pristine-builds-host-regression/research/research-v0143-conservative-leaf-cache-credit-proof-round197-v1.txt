# R197 — conservative process-leaf cache credit: source and fixture plan

Read-only audit of the requested candidate source and fixture. No code or test changes were made; no compile, AST/import, test, build, runtime, GPU, process query, Git mutation, cleanup, or scratch/temp file was used. This is a smallest-change proposal, not implementation or runtime qualification.

## Finding

The proposed policy is a defensible conservative repair for the *visible cgroup-limit terms*: credit clean inactive-file cache only at a fully resolved process cgroup that has no child cgroup directories; attach that credit only to finite limits at that same leaf; give every visible ancestor and the visible mount/namespace root zero credit; use zero credit when the leaf path or its child-free status is uncertain. Do not subtract the leaf's own `memory.min` or `memory.low`: Linux applies protection relative to the reclaim target and ignores the target memcg's own protection during targeted reclaim. With no descendants, the leaf's own min/low therefore does not make its cache unavailable when reclaim is targeted at that leaf's `memory.high`/`memory.max`.

This policy is safer and simpler than trying to infer effective min/low for an arbitrary descendant tree. It is not a complete guarantee against a hidden ancestor limit: cgroup namespaces can hide ancestors, and reclaim targeted at such an ancestor can still honor protection on the leaf. The candidate's existing visible-hierarchy limitation remains material. Exact leaf credit should be described as a bounded estimate for the visible leaf-target limit term, not as globally guaranteed SAVE headroom.

## Smallest code shape proposed (not implemented)

1. Preserve current usage/limit collection for every visible level. Add a tri-state leaf qualifier (confirmed child-free; has child; unknown) and an explicit `process_leaf_index`/`exact_leaf` result from path resolution. Do not infer exactness from `dirs.back()` alone.
2. Credit only when the v2 `0::` path was parsed as an absolute normalized cgroup path, every component was found below the supplied mount root, and the final directory is the process leaf. A path of `/` is the visible root and never receives cache credit. Do not turn a partial walk, absent `self_cgroup`, malformed path, `..`, or symlink traversal into an exact leaf.
3. Fully enumerate the candidate leaf directory. If any child cgroup directory exists, set credit to zero. If enumeration, entry classification, or path/file status returns an error, or a symlink is encountered anywhere in the root-to-leaf chain or as a possible child, classify the leaf as unknown and give it zero credit. Never treat an iteration error as “empty.” This is intentionally simple: it avoids reading/configuring child protections and makes no claim about effective protection under overcommit or recursive-protection settings.
4. Use `reclaimable_cache(leaf, leaf_current, v2)` only for finite `memory.max`/`memory.high` entries belonging to that exact leaf. Keep all ancestor and visible-root `Limit.credit` values at zero. Do not read or subtract the leaf's own min/low value. Keep the existing dirty/writeback deduction, `min(inactive_file, current)` clamp, and malformed-stat no-credit behavior.
5. Keep `root_credit = 0` unconditionally. The explicit operator-cap branch uses the visible root's raw `memory.current` when available, or the existing host-used fallback; it does not reuse leaf credit. The explicit cap is not itself a kernel reclaim target. Root/subtree usage may include siblings and protected descendants, so root `inactive_file` is not justified as available capacity for this cap. If future product semantics define an explicit cap scoped exactly to a process leaf, that is a separate contract and would need its own accounting field and evidence.
6. For v1, either leave cache credit disabled under this narrow policy, or apply the same exact-leaf/no-child requirement using the v1 memory-controller path and `total_inactive_file`. Do not apply v1 leaf credit to ancestors. The requested v2 target/min/low proof is not itself evidence about v1 reclaim behavior; no v1 memory.min/low files exist.

A race remains between resolving/enumerating the cgroup and sampling its counters: another actor could create a child or move tasks after the “no children” observation. Existing cgroup samples are not reservations. This source/fixture proposal proves only the static fixture contract and the result of a best-effort snapshot. A hard guarantee under concurrent cgroup management would require external synchronization or disabling cache credit.

## Path, namespace, symlink, and error review

The kernel cgroup v2 documentation says a cgroup namespace virtualizes both `/proc/$PID/cgroup` and cgroup mounts. In the namespace, the process's cgroup path may be `0::/`; this denotes the namespace root, not proof that it is the global hierarchy root or a child-free exact leaf. The namespace root is the cgroup where that namespace was created, and visible paths are relative to it. Therefore:

- `/` must get no leaf credit. A child under `/` is still visible and must not be ignored; hidden *parents* above it are not discoverable by walking the mounted subtree.
- A non-root path such as `/a/b` can qualify only if every component exists under this mount and `/a/b` itself is completely enumerated with no child directories. Reject `..` rather than trying to resolve it; the kernel documentation shows relative paths beginning with `/../` in cross-namespace views, which this simple scanner cannot safely map.
- The configured mount root is an assumption boundary. Reject symlinks in the root and every relative path component for purposes of credit; do not follow a cgroup-looking symlink and label the destination an exact leaf. Treat a symlink among leaf entries as unknown/child-present. `std::filesystem::is_directory()` follows symlinks, so the proposed check must use `symlink_status()` (and inspect its error code) before accepting directories. For a strict trust boundary, the configured `cgroup_root` itself must be trusted as the intended mount; if that cannot be established, no leaf credit.
- Use `directory_iterator` with `error_code` overloads and check both constructor and increment errors. Any unreadable directory, permission error, status error, or incomplete iteration means unknown and zero credit. Do not rely on `is_empty()` without checking its error result. A child entry whose type cannot be established is also unknown; treating every symlink as unknown avoids following it to an apparent directory.
- The `memory.stat` and cgroup control files used for a qualified leaf should themselves be ordinary interface files, not symlink targets. If file metadata cannot be checked or reads fail, keep zero credit. The raw current/limit behavior can remain as currently specified, subject to existing fail-closed rules for unusable control files.

The cgroup v2 docs define `memory.current` as usage of the cgroup and descendants. The kernel source labels its memory-stat aggregate as subtree page state. This is why a parent/root's inactive-file count cannot be assigned wholesale to its limit when descendant protection composition is unknown. A child-free leaf removes that uncertainty for the visible leaf subtree, but cannot reveal protected ancestors hidden above a namespace or mount root.

## Small fixture plan

Make the smallest changes in `memory_guard_test.cpp` around its current cache-credit fixture (roughly lines 264–337) and Linux path-error fixture (roughly lines 340–361). These are proposals only; none were run here.

- **Retain leaf credit:** use `0::/system.slice/strata.service`; create all path components, no child directories below the service leaf, finite leaf high/max, valid leaf `memory.stat`; make ancestor/root limit room sufficiently roomy. Assert the selected cgroup reading credits only the leaf's clean inactive-file bytes and preserves dirty/writeback deduction. Put a much larger valid `inactive_file` into the visible root and intermediate ancestor stats; assert they contribute zero to their limit terms.
- **Exclude a child subtree:** add an empty child directory under the service leaf (and, in a second variant, a child containing `memory.min`/`memory.low` and large inactive-file stats). Assert leaf credit is zero regardless of the child's configured values. This verifies the deliberately conservative no-descendant rule without attempting to compute effective protections.
- **Reject partial path:** report `0::/a/b`, make `/a` a readable finite limit with large inactive cache but leave `/a/b` absent. Assert `/a` may still contribute its raw limit/current with zero credit; it must not be promoted to the process leaf. If the path resolution itself errors rather than merely stopping at a missing component, preserve existing scan failure behavior (explicit cap unknown; no-cap fallback remains the documented compatibility path).
- **Root/namespace root:** report `0::/`, give the mount root valid current/stat data and a finite explicit cap in the fixture. Assert root credit and returned flag credit are zero. Also create a child directory under root to ensure no code accidentally treats the namespace root as child-free process leaf.
- **Symlink handling:** use symlinks for (a) one component between mount root and leaf, (b) the candidate leaf itself, and (c) a possible child entry pointing at a directory. Each must yield zero leaf credit; with an explicit cap, use raw visible root usage or unknown according to the existing control-file readability contract, never symlink-derived credit. Keep existing broken-loop/ancestor tests.
- **Enumeration errors:** assert an iterator permission/status/increment error produces unknown leaf and zero credit. A chmod-000 fixture is not deterministic when the test runs with privilege that bypasses DAC. The smallest deterministic unit test needs a narrow injectable directory-enumeration helper/result (or a test seam that supplies `permission_denied`); otherwise make the permission-mode test conditional on observing the actual error and document that it is not guaranteed to run privileged. Do not interpret a permission-restricted child as absent.
- **Operator cap isolation:** change the existing flag-cap test that currently expects the mount-root `inactive_file` credit. Assert `root_credit == 0`, the cap is computed from raw root current, and source/limit/current still identify the operator cap when it wins. Also add a valid large leaf stat and show it is not deducted from root usage. Keep the separate cgroup-leaf-limit case to prove leaf credit still works.
- **Target's own min/low:** optionally place nonzero `memory.min`/`memory.low` files on a child-free exact leaf and assert the fixture still retains leaf credit. This protects against a future regression that subtracts the target's own configured protection. It is a parser/arithmetic contract only; the kernel source/doc is the primary support for targeted behavior.

Tests can demonstrate deterministic parser/accounting outcomes on fixture trees. They cannot qualify the real kernel's reclaim outcome, cgroup-mount namespace relationship, concurrent cgroup mutation race, allocation success, or absence of OOM.

## Primary Linux references

- [Linux cgroup v2 memory interface](https://docs.kernel.org/admin-guide/cgroup-v2.html#memory-interface-files): `memory.current` includes descendants; min is hard protection within its effective boundary; low is best effort; high triggers throttle/reclaim pressure; max is the hard memory limit.
- [Linux cgroup v2 reclaim protection](https://docs.kernel.org/admin-guide/cgroup-v2.html#reclaim-protection): protection depends on the reclaim target; a target's own protection is ignored, while descendant protection applies when reclaim targets an ancestor, with intermediate-ancestor caps.
- [Linux cgroup v2 namespace documentation](https://docs.kernel.org/admin-guide/cgroup-v2.html#cgroup-namespaces): a cgroup namespace virtualizes `/proc/$PID/cgroup` and cgroup mounts; its root is the process's cgroup at namespace creation; `/` can be that virtual root.
- [Linux kernel `include/linux/memcontrol.h`](https://raw.githubusercontent.com/torvalds/linux/master/include/linux/memcontrol.h): `mem_cgroup_protection()` and `mem_cgroup_unprotected()` implement the targeted-reclaim own-target exception (current upstream source, around lines 514–595).
- [Linux kernel `mm/memcontrol.c`](https://raw.githubusercontent.com/torvalds/linux/master/mm/memcontrol.c): memory-stat state is aggregated over the subtree (around lines 632–639, 1633–1656); `memory.high`/`memory.max` update paths initiate reclaim targeted at their memcg (around lines 4580 and 4635).

This source-level plan does not establish runtime OOM behavior or SAVE qualification.
