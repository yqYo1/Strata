## Remaining required single-GPU Linux API behavior

One additional user-visible API gap remains in the inspected WN snapshot: non-empty OpenAI `logit_bias` is not implemented or explicitly rejected. WN `serve/server.py` has no `logit_bias` handling; its sampling conversion at about lines 4698–4702 forwards a fixed allowlist of temperature/top-p/top-k/min-p/seed/penalty fields that excludes `logit_bias`. WN `src/program/generate.cpp` has no `logit_bias` request parser/protocol, and WN has no `serve/logit_bias.py`. Thus a client can submit the OpenAI field without getting the requested bias or a clear unsupported-field error. This is an API semantic gap; no engine support is implied.

Official v0.1.43 makes the boundary explicit in `serve/logit_bias.py` and calls its validator in the OpenAI request path (`serve/server.py` around lines 5340–5351): it normalizes IDs and values, checks vocabulary bounds, checks an engine capability bit and refuses unsupported engines with an error. The native request path consumes `logit_bias=id:value,...`, rejects malformed/all-vocabulary bans and continuous batching, and calls the verifier's bias setter. The helper's unsupported-engine text explicitly points clients to a supporting CUDA/HIP build, so porting full token-bias execution into the Xe engine is not the minimal integration required here.

Smallest safe functional change for the B570 single-engine target: reject a non-empty `logit_bias` before generation with a clear HTTP 400 “unsupported by this engine” response, instead of silently omitting it. Reuse a normalizer/validator if useful, but do not claim support or add a cache key unless the Xe engine has a separately reviewed sampling contract. The focused request coverage should include OpenAI Chat Completions and Responses, malformed values, and empty/omitted bias remaining unchanged. If product requirements explicitly demand working token bias on Xe, that is a larger native sampler change and needs its own correctness work; this source review does not recommend or qualify it.

R190 already flagged `logit_bias` as pending engine/API qualification, and R194 explicitly left that qualification outside its reconciliation. This R198 pass confirms the gap is still present in the current WN working-tree server/native sources.

## Explicitly not required for this target

- **`prevent_sleep` / keep-awake:** official `serve/keepawake.py` documents a Windows-only `SetThreadExecutionState` setting; on other platforms it logs that the setting is ignored. It is an optional Windows behavior, so its absence in WN does not block a single-GPU Linux B570 server.
- **Replicas:** official `serve/replicas.py` implements opt-in data-parallel routing over two or more GPU groups, and official `setup.py` configures multiple groups. This target has one B570 and one engine; replicas are outside its product scope. WN's lack of `serve/replicas.py` does not block it.
- **No missing legacy completion endpoint:** both servers advertise OpenAI Chat Completions, Anthropic Messages, and OpenAI Responses. The v0.1.43 endpoint dispatch examined in U and WN is aligned for those routes; no separate legacy `/v1/completions` addition was identified in this audit.
