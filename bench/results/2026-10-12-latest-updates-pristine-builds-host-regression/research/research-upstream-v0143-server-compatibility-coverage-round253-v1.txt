## Two concrete compatibility contracts not covered by those tests

1. **The optional benchmark command is only verified for a POSIX shell.** `setup.py:2490–2509` builds a `sys.executable`/script/config command and renders every token with `shlex.quote`. `test_setup_http_bench_offer.py:41–48` asserts the simple spaced config path is wrapped in single quotes. That checks shell-safe display on POSIX, but setup is also launched through `START-HERE.bat` on Windows, where `cmd.exe` does not treat single quotes as quoting characters. A Windows path such as `C:\Program Files\...` can therefore be displayed in a command that is not copy-pastable into the documented Windows terminal. This is inferred from the renderer and shell convention; no Windows execution was observed. The missing compatibility contract is that the optional command be correctly rendered for the shell actually used on Windows, including paths with spaces. The smallest focused test should assert the Windows rendering without invoking the benchmark or server.

2. **The archive importer tests the expected fixture layout, but not layout validation before replacing an installation.** `setup.py:1182–1211` extracts selected ZIP members into `_unpack`, then chooses `next(tmp.iterdir())`, removes an existing `third_party/main/llama.cpp`, and replaces it with that first directory. The tests construct a valid ZIP with exactly one top-level `llama.cpp-<commit>` directory and the expected `ggml`, `gguf-py`, and `tools/mtmd` members. They cover archive corruption and I/O failures well, but no valid-CRC archive with a wrong/multiple root or missing required member. Thus the important compatibility contract that a successful extraction has the expected unambiguous upstream archive root and required source files **before** replacing an existing tree is not demonstrated by the run. This is a source/test-scope observation, not evidence that the pinned archive is malformed. A minimal fixture can exercise those structural cases and assert the existing source remains intact on rejection.
