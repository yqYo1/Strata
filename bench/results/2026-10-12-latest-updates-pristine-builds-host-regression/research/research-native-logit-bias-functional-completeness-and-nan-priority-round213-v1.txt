## Decision

The current API surface is **transport/validation compatibility, not functional logit bias on WN**. WN already imports upstream's `serve/logit_bias.py` and server helper: normalized values enter the request's sampling/projection key, while `validate_request` fails closed unless the engine's `INFO` says `logit_bias=1` and the engine is not batched. WN's current native `src/program/generate.cpp` has no such INFO field, protocol parser, or sampler setter. Therefore the nonempty-bias HTTP 400 is expected and useful protection against silently ignored input, but does not satisfy the persistent requirement to import the upstream feature behavior on the current SYCL engine. Empty/omitted values remain ordinary no-bias requests; a capability rejection is not an implementation.

The upstream v0.1.43 docs explicitly scope this to supporting CUDA/HIP engines. The upstream tree has the parser/Verifier/Sampler implementation, but its `sycl/src` does not have the corresponding feature; transplanting only server code or INFO would falsely advertise support. The narrow functional delta is to add a SYCL-native target-sampler implementation and request-owned verifier plumbing in WN, plus the protocol/advertisement and HTTP-to-engine connection already represented by the candidate. Preserve WN's unrelated nonfinite recovery, session/cache state, server accounting and MTP/event safeguards while merging.

## Narrow native dependency closure

The candidate's needed native edges are coherent and phase-specific:

1. `include/strata/core/logit_bias.hpp` provides strict parsing and dense request state. `src/program/generate.cpp` must parse the common GEN/GENI sampling suffix against the loaded output-head vocabulary, reject duplicate/malformed/out-of-range/nonfinite/all-vocabulary-ban input and `--batch` before prompt/session mutation, reset request-local state on every request, set both `ver` and `ver_b` when pipelined, and advertise INFO only after this support is present. Omitted/empty API input must clear old request state; a native `logit_bias=` empty field may remain invalid because HTTP empty maps serialize as omission.
2. `SamplerParams` and `src/kernels/xe/sampler.cpp` must carry and score the optional dense table in all three target routes: greedy argmax, ordinary sampling, and split large-vocabulary stage-1 selection. Apply before existing penalties/filters, preserve null-pointer legacy arithmetic, exact hard-ban `-inf` semantics, read-only raw logits, and the score/logprob contract.
3. The final output-head `Verifier` owns the dense device allocation and host staging. Earlier stages forward logical request state only, never another device's pointer. `set_sampling` must bind the final stage's own pointer, and both serial `run` and pipelined `pl_finish` must re-sample biased greedy windows outside the captured neutral graph. Allocation/upload/compute queue completion and destruction order must keep staging and device storage alive through their owning Runtime/queue; never replace WN completion/error barriers with polling.
4. `MtpDrafter::set_draft_sampling` must explicitly null the bias pointer in draft params. Draft rows are unbiased proposals; the target verifier makes the biased sample/acceptance decision. Capture/replay must not retain a request pointer. Keep the separately configured target-side bias in the correct final verifier for every parity.
5. Server validation/transport in WN already handles request and merged defaults, API normalization, capability/batch rejection, and a deterministic request key. Keep upstream semantics including explicit empty clear vs `None` inheritance, correct loaded-tokenizer vocabulary validation, and enough decimal precision to keep `-99.9999999` distinct from exact `-100`. Native parser must independently validate the loaded `n_vocab`; API validation alone is not an engine trust boundary.

At vocabulary 248,320, the optional table is 4*n_vocab = 993,280 bytes (0.9473 MiB) per final-head verifier, potentially two allocations for the pipelined verifier. This is a memory addition, not evidence of 262,144-context fit. Capability/INFO cannot be enabled before actual native sampler, owner, protocol and failure handling are integrated.

## Raw nonfinite priority conflict in the candidate

WN's `STRATA_NAN_GUARD` is on unless explicitly set to `0` (`src/core/verify.cpp:2260-2266`). The captured head graph writes per-row raw-logit nonfinite flags. WN then samples in `Verifier::run` (`:1641-1651`) or `pl_finish` (`:2664-2674`), copies output IDs, and calls `note_nonfinite` (`:1652`, `:2676`) to populate `nf_row_` from the completed flag. The request loop calls `nonfinite_hit` afterward (`src/program/generate.cpp:9878` and prompt/window paths around `:8790`, `:9651`), then applies existing nonfinite recovery and suppresses that window's output. `note_nonfinite` deliberately identifies **raw-head logits**; a hard-ban `-inf` or a later penalty/temperature transform must not be misclassified as a raw-logit failure.

The v3 package's no-effective-candidate guard is currently placed immediately after sampling queue synchronization and before output copy/`note_nonfinite` at candidate `src/core/verify.cpp:1685-1691` and `:2667-2673`. Thus the pending hunk order can return `ERR logit_bias` for a no-candidate result before WN records a raw nonfinite window and routes it through the default-on `DONE nonfinite` recovery. This is a real merge conflict with the package's own contract, which says raw nonfinite status has priority. The correct WN seam is after the existing owning queue is complete, with raw-head status made available first and the bias-ID refusal gated on **no raw nonfinite hit**. Preserve the caller's existing nonfinite-hit branch and no-publication behavior; a deliberately banned candidate remains a logit-bias refusal only when the raw head was finite. Avoid adding an unowned stream sync/poll or returning success in a way that bypasses the existing `nonfinite_hit` caller. For pipeline parity, `pl_finish` must perform the same ordering while preserving its completed-event guard.

## Fixture-plan audit

The candidate's CPU parser/state and whole-window ID-guard fixture, HTTP normalizer/server tests, and GPU sampler-parity source are useful but do not currently prove the WN-specific merge-order invariant. The source-only plan should add an explicit priority case at the boundary used by WN: (a) raw nonfinite flag + sampler sentinel/all-ban outcome routes to raw nonfinite recovery and emits no ID; (b) finite raw logits + no admissible post-bias/post-penalty target route fails as `logit_bias`; (c) finite raw logits with a bias ban plus another permitted token remains a valid sample. Exercise the policy for both serial `run` and pipelined `pl_finish`, and ensure a biased greedy request following a warmed neutral graph uses request values without capture leakage. If a CPU-only fixture cannot connect the device raw-NF status to the production refusal branch, record that as an unproven integration edge and cover it in WN's test harness once executable qualification is authorized.

Existing fixture plan already names A→empty→B request clearing, GENI/common-parser coverage, MTP target-vs-draft behavior, graph neutrality, and terminal failure before token forwarding; these remain planned evidence, not results. Retain tests for both ordinary and split large-vocabulary sampler routes, plus a separate old-sampler process if that mode is first-use frozen. None of these source fixtures establishes hardware correctness, output parity, actual streaming behavior, memory fit, or production qualification.
