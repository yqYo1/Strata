Lifecycle decision, deliberately explicit:
The old HTTP benchmark's auto-start path lacks the root-owned process/session/logging controller needed to meet the requested ownership, finite capture, graceful child/engine closure and post-kill reap contract. Rather than adding an unsafe partial controller, this port makes real auto-start UNSUPPORTED and requires --url attachment to an already-loaded dedicated server. Missing --url returns 2 before any subprocess launch. start_server/wait_ready/stop_server/log_excerpt and config auto-selection are removed, along with --port/--gpu/--ready-timeout auto-start options. It never Popen/terminates/kills/restarts an inference server and uses no killpg. The owner starts/stops/reaps the server outside this tool. A loaded Strata health response is required; reported in-flight work refuses admission. URL credentials/query/path are rejected; API key uses explicit key/env or optional config.
Because this client owns no engine child and creates no temporary raw logfile, parent logfile close, private temporary log namespace, successful full-log retirement and killed-child reap are not falsely claimed as implemented. It neither reads/deletes server logs nor retires an unresolved-failure diagnostic. Its existing read-only subprocess.run metadata helper still reads the client Git commit with a finite timeout; no model process management is hidden there. A future auto-start feature must supply a separately qualified owned controller; do not restore the deleted Popen flow or describe attachment as lifecycle ownership.

HTTP/report bounds and honest status:
One TextBudget shared across discovery/config, measurement and concurrent HTTP clients admits at most 64 MiB of charged text. Outgoing JSON bodies count, as do incoming JSON/SSE bytes. It reserves bytes under a lock BEFORE each bounded read1/read, so readers cannot overshoot the shared byte allowance; unused reserved bytes are refunded. Long lines are capped at 1 MiB and malformed JSON data frames fail a request rather than being silently counted. Inputs/output JSON object overhead and process RSS are not claimed to be 64 MiB; Main's outer owner must bound actual runs. The word-list fixture refuses calibration above 131072 words, avoiding unbounded prompt expansion from a bad calibration.
Generation uses the existing 3600-second request timeout as a monotonic deadline, checked between bounded underlying reads, plus at most 30-second socket waiting. Metadata reads retain their finite timeout/deadline. This is not a whole-benchmark wall controller, and outer Main ownership remains necessary for real qualification. CLI rounds are 1..16 and clients 0..32. Those bounds are limits, not authorization to exercise parallel/long model routes.
SSE EOF without [DONE], explicit errors, invalid data frames and budget/deadline errors cannot be successful samples. Warm-up/calibration errors also remain failures. Concurrent rounds with errors are excluded from throughput aggregation and their request errors enter the overall failure list. Any recorded request failure returns1 and writes status FAILED even if earlier samples succeeded. Successful normal completion is labeled COMPLETED, explicitly not correctness PASS. Budget/IO/validation aborts retain a fresh compact failure.json and bounded partial-results.json when available; no previous diagnostic is deleted. Saved README/results/optional caller-supplied excerpt total is bounded 64 MiB. The normal attachment path supplies no excerpt and emits no raw server log.
