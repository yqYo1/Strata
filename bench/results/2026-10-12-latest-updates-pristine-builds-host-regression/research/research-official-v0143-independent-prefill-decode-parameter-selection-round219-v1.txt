# Official v0.1.43 independent prefill/decode parameter selection (R219)

Date: 2026-10-12. Source-only review of pristine official v0.1.43 at `/home/yayoi/ghq/github.com/Niko1221/Strata/.worktree/bench-upstream-v0143-pristine-20261012`. No model/GPU/runtime/build/test/compiler/import/AST/process/Git/cleanup operation; no source changed. Read registry v154 and the relevant R207/R210/R215/R217 reports first. This report chooses candidates; it contains no new performance or correctness result.

## Decision

There is no generally safe, high-throughput batched prefill setting for a discrete Arc whose `usm_atomic_host_allocations` aspect is absent. The promising big-chunk path still has reachable raw host-USM polling in Stager and, with multi-chunk PLE, PLE-buffer reuse. The safe stepped verifier path is a synchronization control, not a production-speed recommendation: 32K tokens at T=8 means up to 4096 serial verifier windows. Keep the settings below as independent benchmark arms and record results before choosing a default. Do not use a result from one path to claim a result for the other.

The exact remaining blocker is source-level: no option suppresses `Stager::issued_one()` for a nonresident, unpinned expert, and no queue/event completion replaces its `done_seq` polling; no option removes the PLE marker poll when a second chunk follows. Turning off stream-all, issuer, or batched PLE arithmetic does not fix either. A conditional one-chunk batch can avoid those polls only if all routed misses are pinned/resident. That workload-dependent condition is not a dependable general 32K/64K route without runtime evidence.

## Other knobs and confounds

- `--prefill CHUNK` is real only with `--native`; `auto` is a memory/cache planner and may select/change chunk. For controlled candidate tests, record the effective chunk from startup/runtime output, not merely argv. On Alchemist ≥12 GiB the code forces own prompt buffers and caps automatic chunks at 2048 because of the documented oneMKL >4 GiB operand issue. On Battlemage the default borrowing rule changes above a 32K context. Do not compare across this policy boundary without recording effective borrow and slots.
- `STRATA_PREFILL_FIRST` defaults to a 256-token first chunk only if all experts are cached; setting it to zero removes that short-first-chunk split. It does not itself remove Stager polls and can alter numerical rounding/chunk work. `STRATA_PREFILL_RING` / `STRATA_PREFILL_STREAM_MIN` change which expert stream path/buffer scale runs; neither is a host-poll safety switch. `STRATA_PREFILL_STREAM_ALL=0` disables all-experts walk but not routed-only Stager. `STRATA_PREFILL_ISSUER=0` only removes the stream-all issuer thread. `STRATA_PLE_BATCH=0` chooses the PLE arithmetic A/B, not the PLE upload lifetime/poll.
- `--kv-resident`, `--kv`, `--expert-cache`, `--no-prefill-borrow`, cache profile, resident RAM tier and PCIe controls can change memory fit or how many experts miss. Treat each as a separate capacity/residency experiment; freeze them when comparing prefill algorithms or CPU pool workers. In particular, reserving VRAM for KV or own prompt buffers can reduce the expert cache and slow cold decode after prompt.
- `--spec 8` with no MTP and `--suffix-draft 0` does not give an eight-token draft; decode remains one-token windows in the previously audited route. Keep it fixed. R210 establishes separate argv syntax: `--short-read 65536 --spec 8 --suffix-draft 0`, not concatenated forms.

## Evidence and source anchors

Pristine source anchors: `sycl/src/prefill/prefill.cpp:119-120, 204-227` (`stream_all_min`, ring selection and stream-all gating); `:364-390, 449-470, 510-523` (page-locked `done_seq`, Stager worker, volatile completion read); `:1078-1081, 2179-2200, 2326-2362` (PLE allocation, arithmetic toggle, chunk and upload marker/poll); `:2464-2465, 2580-2681, 3809-3865` (route choice, issuer, expert stream branch); `sycl/src/program/generate.cpp:565-579, 669, 1718-1805, 1853` (chunk/borrow/short-read options); `:2172-2202` (context/Alchemist borrowing policy); `:9838-9844, 9958-10009` (serve short-read admission, read-window and commit); `:11630-11700` (standalone batched prompt route); `sycl/src/core/verify.cpp:1737-1744, 2035-2150` (stepped segmented graph and queue-boundary serving). For exact marker reasoning and the conditional route, see R207. For window counts, valid argv, and decode-only worker axis, see R210. For prompt/commit/decode lifetime, see R215. R217 records that native fused IQ prefill is stubbed in the official SYCL target; standard prefill remains available.

The pristine comments/docs provide historical measured points, not a transferable optimum: `prefill.cpp` comments say a 40K B70 prompt read 1,159 tok/s with stream-all versus 1,106 routed-only; `docs/INTEL.md` reports 40K Coder 1,117 tok/s and 256K Coder 757 tok/s with an RTX 5070, and a distinct B70 section reports 4,095-token Alchemist IQ3_S prompt 784–1,002 tok/s depending on chunk/buffer policy. These are different devices, model routes, context, residency and code paths; they do not validate the present atomic-host-free route or establish an expected rate for the target card. Intel's [SYCL GPU atomic guidance](https://www.intel.com/content/www/us/en/docs/oneapi/optimization-guide-gpu/2024-0/atomic-operations.html) says host-allocated USM atomics and concurrent host/device accesses to shared USM are unsupported on discrete GPU; the recommendation is device USM for atomics. Its [data-transfer guide](https://www.intel.com/content/www/us/en/docs/oneapi/optimization-guide-gpu/2024-1/optimize-sycl-data-transfers.html) discusses transfer optimization, not a permission to poll host USM concurrently. Intel's [application optimization guide](https://www.intel.com/content/www/us/en/docs/oneapi/programming-guide/2024-0/optimize-your-sycl-applications.html) supports profiling the actual host/device bottleneck; it does not identify a winning Strata knob.

## Validation ledger recommendation

For each arm record board/driver/runtime and atomic-host aspect; pristine source/build identity; exact model/weight hashes and cache source; prompt token count and hash; effective context, chunk, first chunk, ring, borrowing, resident experts and KV settings; environment/argv; process-cold status; actual window/chunk/PLE/Stager route; prompt time/throughput; first-token latency; decode wall time/tokens; cache hit/miss counts; output equality; synchronization errors, faults, and memory high-water. Use ≥5 independent interleaved cold starts for each candidate at both lengths and keep every sample. A timeout or error is a failure sample, not an omitted run. No timing should be interpreted until the synchronization predicate is proven for the selected route.
