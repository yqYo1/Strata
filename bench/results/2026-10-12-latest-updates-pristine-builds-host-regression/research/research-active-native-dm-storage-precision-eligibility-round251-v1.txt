# R251 — active native Dm storage precision eligibility

Date: 2026-10-12
Status: static source audit only. No runtime, import, test, build, device/process query, profile, Git, cleanup, or source change. The current Sol packet was not inspected. Source conclusions below do not establish that a particular launch actually took the route.

## Result

For the specified WN0691 native IQ3_S batched 8192 configuration, a narrow Dm16 **store after FP32 output has been computed** is source-eligible in the compact fallback. It is not limited to a compact-only/non-MMQ proposal: the compact `fallback_products` branch accepts the fallback grouped GEMM/XMX writers, whose output pointer is FP32 Dm. The existing combine reads FP32 Dm. IQ3_S itself is MMQ-eligible for both products at the stated geometry; with MMQ explicitly disabled (`STRATA_PREFILL_MMQ=0`), the same type/geometry chooses fallback instead. This is a source eligibility finding, not proof of actual launch flags, selected writer, saved arena bytes, fit, quality, or speed.

## MMQ versus fallback by type and pack geometry

The native IQ MMQ support predicate is the explicit type switch in `src/kernels/xe/iq_mmq.cpp:623–627`: accepted IDs are 16, 17, 18, 20, 21, 22, 23, 29, and 42. The adjacent decoder specialization identifies ID 21 as IQ3_S (`iq_mmq.cpp:121+`). `mmq_plan()` (prefill.cpp:612–623) selects MMQ for each layer only if both GU and down types are supported and `up_off == mmq::matrix_bytes(gu_type, 640, N)`; the enabled plan requires `mmq::built()`, native layout, and MMQ not explicitly disabled.

For IQ3_S/type 21, row bytes are derived with QK=256 at `iq_mmq.cpp:630–640`. The requested geometry has N=2560, hidden width 640, and doubled gate/up width 1280; all are multiples of 256. Therefore type 21 GU and down are each in the supported-type set and their row shapes are block-compatible. The packed GU/up offset equality is a separate layout check and is computed from the actual native pack. If both actual per-layer types are 21 and that offset test passes, MMQ is eligible when compiled/enabled. If either type is unsupported or the offset check fails, that layer is fallback. With `STRATA_PREFILL_MMQ=0`, all layers are fallback regardless of the supported types; `MmqPlan` begins `fallback=true`, and compact mode can be admitted if the other guards pass.

This answers source eligibility, not the actual per-layer type map for the active file. The no-live-packet restriction means the actual pack metadata is not claimed here. The report must use the run's retained per-layer `gu_type`/`down_type` receipt to say “all layers are IQ3_S”; a model label alone is insufficient.

## Exact Dm writer/reader route under the requested fallback

For `use_mmq == false`, the main MoE route enters the fallback branch at prefill.cpp:2120 onward. With native-dequant batching off and fused kernels off, it reaches `fallback_products` at 2185. Under `m.compact_moe`, it partitions expert rows into groups (2186–2200), gathers FP16 activations, then calls `Gemm::f16_groups(..., dst, ...)` with `dst = m.Dm + group.row0*N` (2196–2209). If that backend declines, it calls `xmx_gemm_grouped(..., dst, ...)` with the same FP32 Dm destination. These are both real output writers eligible for a post-product Dm16 store; the exact choice between oneMKL grouped f16 and XMX fallback is backend/runtime dependent. The source signatures and Dm type remain float, so a candidate must preserve each writer's FP32 accumulation and convert only its completed result before combine.

`moe_combine(m.Dm, ...)` is the reader at prefill.cpp:2868, after the optional CPU-tail copy (2848–2859). `src/prefill/kernels.cpp:1000+` defines the combine with `const float* Dm`; the Dm contribution is widened/not applicable today because it is already float, then weighted route contributions are accumulated into FP32 output. A Dm16 candidate needs a matching reader that converts each stored value to float and preserves route rank order and FP32 accumulation. The CPU tail is excluded by host issuer0; if any CPU rows are admitted, its FP32 copy at 2858 is another writer that must be converted or the candidate gated off. MMQ Dm writers at 2468/2754 are excluded by `use_mmq == false`, and fused writers are excluded by the requested fused-off setting.

The R239/R301 8K raw Dm size reduction cannot be called an arena saving here. In this integrated source, the shared region is the maximum of overlaid GDN/QSA/MoE terms; no actual max-after-conversion, fit, or selected chunk result is inferred by this audit.

What source does **not** log in those records is `compact_moe` admission or an explicit Dm writer/backend identity (oneMKL grouped versus XMX fallback). The source predicates then establish compact admission and the eligible fallback. If the review requires proof of the selected grouped backend, current route census does not provide it; one bounded per-layer/per-chunk writer counter or existing backend status would be required. No such runtime result was observed in this read-only audit.

Do not use that routing evidence to claim Dm16 correctness. Separate, bounded numerical evidence must compare pre-store FP32 writer outputs with post-roundtrip values, final combined FP32 outputs, and the predeclared task/logit checks; capacity evidence must report the actual shared-region maximum and fit. This report does not provide or imply any of those results.
