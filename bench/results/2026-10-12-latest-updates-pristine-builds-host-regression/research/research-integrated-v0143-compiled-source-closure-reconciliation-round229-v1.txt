R229 read-only compiled-source closure reconciliation

Scope

Read-only comparison of the original free Xe build receipt, the integrated neutral-controller source pins, Main's current-source boundary receipt, the finalization-host-v8 test receipt, and the actual device-fixture receipts. No import, AST, build, test, Git command, process query, GPU action, cleanup, or source mutation was performed for this report. Do not read the prohibited prefill-gemm-only contract receipt. Original result statuses remain unchanged.

Finding

The selected integration revision `0691bcdf5af63a85b3b25650f367d3276db64035` can be reconciled to the original v4 free build at the source-byte/compile-closure level. The source-only build subset audit compares 460 pinned paths and identifies exactly one byte difference: `serve/test_session_save_retry.py`. The old build receipt's source pin is `8da3a32386d10d8643484fbde3b5b59c399aeff736e7486273466325975a770a`; the selected revision's pin is `15917adc5b5e391640af016ad7c7bbdb3e756a0ac6c97a5d8be1887ede6e55de`. Every other path in that comparison has the exact original pinned digest.

The exception is narrowly noncompiled. The original receipt records a full CMake/Ninja configure/build of the C++ `strata` binary and listed C++ test/parity targets. Its captured compile/link recipe has C++ translation units, C++ headers and link inputs, and no Python test file. Its explicit build targets also contain no Python test runner. `serve/test_session_save_retry.py` is not an input to C++ compilation or linking. The exact same CMakeLists and packaging/build scripts are pinned on both sides. This is a path-specific exclusion supported by the recorded recipe and byte map, not a conclusion from the `.py` suffix alone.

This supports a new Main-reviewed `compiled-source-closure-equivalent` receipt for the existing ELF if Main accepts byte-identical compiled closure as sufficient. It does not justify labeling the original build as a build of commit 0691, rewriting its original status, or claiming the Python test was run. If Main's admission rule requires a binary freshly emitted at the selected commit, perform a fresh exact build and bind its new receipt; the source-only equivalence does not replace that requirement.

What the old build actually proves

`xe-v0143-nonfinite-free-qualification-root-v4/record.json` is a passing build/CPU-test receipt with `gpu_executed=false`, `model_executed=false`, `nonfinite_gpu_parity_qualified=false`, and `performance_eligible=false`. Its checked out `HEAD` was `337255086026f6eef21a861c297183d05a5f7a22`, but the build tree was intentionally dirty relative to that base. The recorded `git diff --name-only HEAD` and untracked lists include the integrated C++ work; therefore HEAD equality alone would not describe what was compiled. The receipt also pins 460 source-file hashes and records the actual build commands and recipes. The source audit correctly compares those source bytes against the new committed source instead of treating the historical base commit as the build source revision.

The recorded configure used CMake/Ninja, Release, `STRATA_ENABLE_XE=ON`, free license, native experts, tests and Werror, with the pinned llama.cpp worktree and Intel LLVM 7.1.1 compiler path. Compiler receipt reports DPC++ 7.1.0 prerelease based on clang 22.1.0. The captured successful build command used four jobs and explicitly built `strata`, C++ unit tests, and parity/device targets. The full `ninja -t commands` output is retained in the original record (136,899 bytes); the original configure `CMakeCache.txt`, `compile_commands.json`, and `BUILD.json` hashes are recorded there. The C++ source path list and direct recipes are the relevant evidence for excluding the Python test.

Guard semantics and detector coverage

The selected C++ source implements a post-head-logit detector. `src/kernels/xe/verify_kernels.cpp` scans FP32 logits for exponent-all-ones bit patterns (infinity or NaN), writing flags by row and vocabulary block. `include/strata/core/nonfinite.hpp` reduces completed host-USM flags into an active-row bit mask. In `src/core/verify.cpp`, `STRATA_NAN_GUARD` defaults on; only the exact string `0` turns it off. After queue/event completion, the last stage reads flags, records the first bad row and token position, and exposes the mask through `include/strata/core/verify.hpp`. The guard does not repair or substitute logits. On a hit, `generate.cpp` suppresses that window's output, terminates the request/slot as `nonfinite`, clears cached state, taints other live slots as required, and forces the next request to start from prompt token zero.

The recorded 324-device-case fixture covers the actual detector and mask helper on FP32 synthetic logits: vocab widths 17 and 4099; rows 1, 2 and 8; direct launches and captured graph replay; positive/negative infinity and positive/negative quiet-NaN bit patterns at first/middle/last columns; active-row overwrite after poisoned data; mixed/all-bad rows; stale inactive tails; flag canaries; and invalid-argument rejection before runtime initialization. It is not 324 model cases. It does not test model-generated logits, the full model's BF16/other precision computation paths, every kernel that can numerically cause nonfinite values, long-context quality, or end-to-end server recovery. The free and contrib roots both preserve the `graph_supported=1`, 324-case completion line.
