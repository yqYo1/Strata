R240 — integrated versus official NaN/Inf guard phase contract

Scope and disposition

Read-only source audit of the integrated Xe worktree supplied by Main at revision `0691bcdf5af63a85b3b25650f367d3276db64035` and pristine official v0.1.43 at `7695859aa13afb248bdb4d36f9b2e95707db079d`. Reviewed prior R201, R212 and R229 reports to avoid repeating their general scan-cost and phase-timer material. No build, test, runtime/GPU/model/process query, profiler, Git, cleanup, or source change was performed. The secret-tainted prefill GEMM receipt was not opened. This report uses only source and the measurements Main supplied.

The main distinction is route and backend. The integrated guard is a post-head-logit production guard in `Verifier`; it runs in verifier windows used for prompt reading **when the prompt is routed through `read_windows`**, and again on decode windows. It does not run inside batched `Prefill::run`. Therefore a displayed “prefill” duration includes guard work only when that duration is made up of verifier prompt windows; a batched prompt prefill is unaffected by `STRATA_NAN_GUARD` until its first verifier window. There is no phase-specific environment selector today.

Official v0.1.43 has the same guard in the generic root verifier/CUDA source. However, the pristine B570 SYCL implementation is the separate `sycl/` source tree. Its `sycl/src/core/verify.cpp` has no `STRATA_NAN_GUARD`, `nan_guard_on`, `note_nonfinite`, or production `logits_nonfinite_rows` call. It has `STRATA_DBG_NAN` host-readback diagnostics. Thus the integrated Xe guard is a safety feature added to the SYCL path, not a behavior that can be assumed from the upstream generic CUDA implementation. Do not use the CUDA source's guard to claim that the official SYCL baseline had the same protection or cost.

Integrated Xe production path

`Verifier::nan_guard_on()` caches a process-wide choice on first use. It defaults on; only the exact string `STRATA_NAN_GUARD=0` disables it (`src/core/verify.cpp:2260-2265`). The recorded window graph adds `logits_nonfinite_rows(head_logits_, T, n_vocab, m_nf_, cs)` immediately after the greedy pick (`:1252-1260`). The detector bit-tests FP32 logits' exponent bits, so it catches either infinity or NaN even when fast-math is enabled. It launches `T * 16` work-groups, partitions each row across 16 blocks, scans `T * n_vocab` logits and writes 16 32-bit flags per active row (`src/kernels/xe/verify_kernels.cpp:1137-1157`; `include/strata/kernels/verify_kernels.hpp:21, 132-136`). For `n_vocab=248,320`, this means 993,280 bytes read per row: at most 7,946,240 bytes (7.58 MiB) per 8-row window and 64 bytes of flags. This scales with active vocabulary rows, not model layer count.

The verifier already completes both its compute and expert-copy queues before reading outputs/flags (`verify.cpp:1612-1620`). `note_nonfinite()` reads only the completed host-mapped `T*16` flags and reduces them into a row mask (`:2287-2305`, `include/strata/core/nonfinite.hpp:10-20`); it does not copy the full logits to host or spin on host USM. In non-pipelined `run`, the call follows window completion and output extraction (`:1651-1652`). In batch-slot service it follows the completed host handoff (`:2115`); in pipelined finish it follows a nonblocking event readiness check (`:2643-2677`). The detector is a graph node, so the queued scan extends device work and the existing queue completion covers it. It adds no separate blocking synchronization or logit D2H copy on these paths. R201 describes the bounded nonblocking readiness query that accompanies pipelined flag reads.

`generate.cpp` consumes a hit at prompt `read_windows` callsites and at decode: it refuses the affected window's tokens and terminates with `nonfinite` (`:6431-6440, 8742, 8790-8793, 9878-9886`). This is a head-output guard, not a scan of all intermediate activations or recurrent states. A batched prefill's many layer/chunk intermediates do not pass through the `Verifier` detector; after Prefill, its next verifier window's head logits are checked.

Official v0.1.43 source surfaces

1. **Generic root CUDA verifier:** official root `src/core/verify.cpp` records the same post-pick detector in the window graph (`:1794-1796`). Its default-on `nan_guard_on` reads `STRATA_NAN_GUARD` with `atoi(value) != 0`; `note_nonfinite` reads the completed mapped flags with a row/block early-exit scan (`:3106-3155`). Its CUDA kernel uses the same `kNonfiniteBlocks=16`, grid `(16 blocks, rows)`, and 256 threads per block (`src/kernels/cuda/verify_kernels.cu:871-876`). This is the generic CUDA implementation, not the B570 SYCL implementation. There is a small parser-semantic difference: upstream `atoi("00")==0` disables, while the integrated Xe version disables only exact `"0"`.
2. **Pristine official SYCL verifier:** no production `STRATA_NAN_GUARD` or `logits_nonfinite_rows` call occurs in `sycl/src/core/verify.cpp`, and the corresponding search of `sycl/src` finds no such detector definition. Its `Verifier::run` instead has `STRATA_DBG_NAN` (`sycl/src/core/verify.cpp:2428-2445`): after output sampling/sync it copies `T*n_vocab` floats to host and walks them until a bad row is found. This is a diagnostic report-only path; it does not set a nonfinite row, suppress tokens, or terminate the request. With finite logits `reported` remains false, so the full copy and scan repeat each verifier window. `STRATA_DBG_NAN` must not be described as the upstream SYCL production safety guard.
3. **Prefill debug scans in both SYCL trees:** `STRATA_DBG_NAN` performs a compute-queue wait after each MoE combine, copies arrays to host and runs scalar `std::isfinite` loops (`integrated src/prefill/prefill.cpp:2868-2890`; official `sycl/src/prefill/prefill.cpp:4238-4278`). It checks the GPU-written MoE outputs (GU/H where present, Dm and bo; fused layouts omit inapplicable GU/H). The function scans those arrays on every MoE layer/chunk while enabled; a static `reported != stats_.chunks` condition suppresses repeated diagnostic messages within a chunk, not the scans. At the end of `Prefill::run`, the diagnostic waits again and copies/scans the last residual row, PLE history if present, and 64*1024 GDN-state floats (`integrated :3016-3032`; official `:4533-4558`). This is a synchronous diagnostic with data-dependent geometry, not the lightweight production detector, and it does not cover every intermediate activation or all QSA/recurrent state.
4. **HIP-specific GEMM debug:** official `sycl/src/prefill/gemm.dp.cpp:938-958` has `STRATA_DBG_NAN` in `Gemm::f16_inplace` only inside `#if defined(__HIPCC__)`; it launches `widen_rows_f16`, synchronizes and reads a HIP symbol counter. This branch is not the SYCL/Level Zero execution path. The integrated Xe source tree has no matching `src/prefill/gemm.dp.cpp` callsite.
5. **Other optional logit readback:** the integrated non-stream-token `generate.cpp` output path reads and scans the selected output logits (`:10546-10560`). `--check-logits` specifically forces that full host readback for stream-token mode. This is a separate output path and is not the verifier guard or Prefill diagnostics.

No available phase selector

`STRATA_NAN_GUARD` is process-global and cached statically. Its result is baked into the captured window graph at `record_window`; changing the environment between prompt and decode is unsupported and, for an already-recorded graph, cannot switch the node. There is no `STRATA_NAN_GUARD_PREFILL`, `..._PROMPT`, or `..._DECODE` branch in the integrated source. More importantly, “prefill” does not name one consumer: `read_windows` uses `Verifier` and gets the production detector; batched `Prefill::run` does not.

For safe cost attribution, keep production guard default-on and use the existing global OFF/ON in fresh processes, with the same exact route and phase-separated timings. Count and record how many prompt verifier windows and decode windows actually ran. Do not use `STRATA_DBG_NAN` for timings: it adds full host readbacks and per-MoE-layer synchronization. If future work truly requires independent phase controls, the minimum implementation is an explicit guard-domain/boolean passed from the prompt-window and decode callsites into graph capture, with that bit included in the graph cache key; default both domains on and preserve nonfinite recovery for either enabled domain. It cannot enable an intermediate-activation prefill guard by itself; that would need a distinct detector placed at named Prefill outputs with separate flags/recovery semantics.

Main-supplied measurements and evidence still needed

Main reports a single debug 32K comparison with identical 16 generated tokens and LP5 fingerprint (`f8aca...`): guard OFF, prefill 100,181.4 ms / decode 2,209.9 ms; ON, prefill 93,299 ms / decode 1,716.9 ms. These two observations are not a performance estimate: the detector's source path is conditional on verifier windows, and one sample per arm cannot separate run-to-run variation or establish a throughput effect. They also do not justify disabling the default safety guard. The interpretation of the prefill delta depends on the actual 32K route: with `read_windows`, prompt verifier scans are within the prompt/pre-fill interval; with batched prefill, there is no guard kernel in that interval. Record the actual route and window count with each arm. The clean three-pair campaign and the 37,462-token whole-validation heldout remain incomplete per Main's status; no result is inferred for them here.

Minimum evidence for a cost conclusion is fresh-process, interleaved OFF/ON pairs on the same source/binary/model, prompt token hash, cache/KV/context/sampler and route; at least three pairs plus the heldout Main specified. Retain every sample, exact effective `STRATA_NAN_GUARD` value at process start, active guard route/window counts, separate prompt and decode wall times, exact output/LP5 checks, and normal closure/fault status. Keep `STRATA_DBG_NAN` absent. If both arms use `read_windows`, attribute the difference only to the global verifier detector plus ordinary noise unless a detector-specific device service measurement is added; if both use batched prefill, the prefill interval is a control with no production detector in Prefill. Main's existing paired-by-phase timings are the right shape, but the one-pair count is too small to decide measured cost.
