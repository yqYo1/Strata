Decision and correction to the prior wording
--------------------------------------------
In current Xe source, an executable-bundle exception for an individual kernel ID does **not normally abort the preload loop or directly block model loading**. `Runtime::preload_kernels()` catches each `std::exception`, increments `skipped`, and continues to the next ID. It neither logs the exception text nor records a failure state that `wait_preload()` checks. The main thread starts this worker and continues initialization; its later joins only wait for completion. Therefore a PackedA module-build error can coexist with model initialization and `READY`.

R194's historical receipt is consistent with that behavior: the process recorded module-build failures, reached `READY`, had no `GEN`, and was later sent SIGTERM by the controller. Its subsequent exit `-11` and longjmp warnings are a separate host termination symptom; the receipt does not establish that the JIT errors caused that signal-time outcome. There was no retained `ZE_RESULT_ERROR_DEVICE_LOST` or launched model-kernel failure in the evidence summarized there. The compilation error is not evidence of a GPU reset or inevitable startup refusal.

Clarify R199's phrase “concrete startup eligibility blocker”: the retained PackedA failure blocks a claim that the all-ID preload completed cleanly and leaves selected-kernel support unresolved; it is **not** a source-established fatal blocker to reaching `READY`. An exception is silently counted as a skipped ID, and the source cannot tell expected “not for this GPU” IDs from a failed build. The historical run proves that at least one particular binary/configuration continued past those recorded errors to `READY`. It does not establish a current da3d runtime tuple, clean preload, a successful selected PackedA specialization, or correctness of any prompt path.

Preload control flow and model-loading order
--------------------------------------------
`src/core/device.cpp::Runtime::preload_kernels()` launches a background thread. The thread enumerates `sycl::get_kernel_ids()`, checks a stop flag, and for each ID calls `sycl::get_kernel_bundle<bundle_state::executable>(context_, {device_}, {id})`. It does not submit a kernel to a queue or execute the resulting kernel. Each caught `std::exception` is discarded after incrementing `skipped`; only when `STRATA_TRACE` is set does normal completion print the aggregate “kernels built ahead / not for this GPU” counts. No failed ID, exception message, or failure category is retained in that summary. A non-`std::exception` escaping the worker is not handled by this catch and is outside the ordinary per-ID continuation guarantee.

`src/program/generate.cpp` performs early CLI and pack checks before starting preload. For a native pack it loads the CPU-side expert layout and checks each layer with `native_expert_supported`; `--native` shard/PLE discovery and several argument checks also precede preload. It then calls `Runtime::get().preload_kernels()` around line 2847, before `Gemm::prepare()`, native embedding/dense tensor loading, session and cache initialization, and the final `READY` print around line 7221. Main therefore proceeds with model initialization while preload runs. `wait_preload()` is called by later calibration helpers (`read_memory_rate_before` and `measure_pcie_split`); it only joins the thread and does not inspect skipped count or convert a caught exception into an error.

The standard single-device serve startup, absent an explicit PCIe policy that bypasses calibration, calls `setup_pcie_split()`. Its `measure_pcie_split()` first joins preload, then submits a separate small GPU timing path (`native_expert_grouped` for one/eight groups and `fetch_blobs` transfers). This is not the all-ID bundle sweep and is not a PackedA joint-matrix launch. It is still actual GPU calibration work, so a full startup is more than a CLI dry run. Passing an explicit `--pcie-frac` or `--pcie-mode direct|dma` can bypass this calibration branch, but changes the startup configuration; neither option disables all-ID preload.

Existing bounded checks before any model request
-----------------------------------------------
- `strata --version` / `-V` returns before GPU setup. `--help` prints the option list during argument parsing before device/runtime initialization. These check the executable/CLI surface only; neither confirms device selection, pack validity, memory, model load or kernel support.
- `strata --hw-bench [--native GGUF | --pack DIR]` is detected before normal option parsing and returns before the main-path preload call. It reads RAM/SSD and tests pinned/pageable host-to-device and device-to-host copies (four 256 MiB bursts per direction, with queue events). Runtime device discovery also asks for an executable bundle for the tiny `ProbeKernel` in `unusable()`; the probe is compiled but is not submitted. This mode does not load the model, enumerate all kernel IDs, request the PackedA specialization, or launch a model kernel. It can establish basic runtime/device/USM/copy/event and selected storage facts, not native model admission or startup preload behavior.
- `strata --kernel-bench --pack DIR` is not a dry initialization check. It initializes oneMath/GEMM and runs a synthetic 4096-row dense BF16 product plus supported prompt MMQ expert products. It does not invoke the global preload loop and is not a long-prefill or verifier test. It submits kernels; do not use it to claim the PackedA all-ID boundary was tested or ruled safe.
- No existing `--validate-only` or “load model, stop before preload” path is present. A normal native serve initialization performs the all-ID executable-bundle requests. Pack metadata and type checks happen before them, but model tensors are loaded after the call to `preload_kernels()`. The first-source-only checks cannot be reported as successful model initialization.

What a supervised startup-only launch can establish
----------------------------------------------------
A Main-owned, bounded `--serve` process that sends no `GEN` can establish whether that exact built executable/runtime/provider tuple reaches model/session initialization and emits `READY`, and whether its all-ID preload logs module-build diagnostics. `STRATA_TRACE=1` adds only aggregate preload counts; preserve any independent runtime/driver build diagnostics because the source suppresses per-ID exception text. If ordinary setup continues after a bundle failure and `READY` arrives, that demonstrates failure isolation for that launch, not a clean preload. If the worker completes and the source reaches the explicit later `wait_preload()` without termination, it demonstrates the loop/join completed, but the aggregate skipped count does not identify why IDs were skipped.

Do not send a request in this bounded startup arm. No `GEN` means no prompt, decode, verifier, or long-input performance claim; it also avoids dispatching selected model kernels after the preload sweep. Still record that executable-bundle compilation was requested for every registered ID and that normal startup may run the non-PackedA PCIe calibration described above. Use an owner-controlled process deadline, preserve a finite error window and exact binary/runtime/driver/provider/source identity, wait for normal `QUIT` and exit, and distinguish runtime module-build errors from host shutdown signals. A forced timeout/kill must be recorded as incomplete, not as a clean startup result. A subsequent selected-path correctness run is separate and must not be inferred from `READY`.

The explicit direct prerequisite path that avoids both model preload and any model kernel is `--hw-bench`, plus the CPU-only `--help`/`--version` and pack-file metadata checks. This answers basic setup questions without executing a PackedA model kernel. It cannot answer whether the current PackedA compiler/provider tuple can build the full registered bundle inventory; even `--hw-bench`'s tiny ProbeKernel bundle only tests a different specialization.
