Target: pristine XeStrata `da3d426079019daa6e01388d03b0d94ae67070b7` at `/home/yayoi/ghq/github.com/MistVVK/XeStrata/.worktree/bench-xestrata-xe0142-pristine-20261012`.

The B570's reported `atomic_host_usm=0`, native IQ3_S, 262,144 context, int8 KV, no MTP, suffix-draft 0, single queue, and LLVM 7.1.1 are target conditions supplied for review, not independently verified here. ## Decision

**Source-admitted, conditionally:** this pristine tree has a real large batched-prefill route whose normal host/device transfers use completed queue/event boundaries. Its Stager reuse marker is an event (`dma_done`) and PLE buffer reuse waits on a recorded event (`ple_copied`); neither uses the official v0.1.43 raw device-written host-USM sequence polling that caused R207 to retract broad admission. CPU MoE grouping explicitly synchronizes the compute stream before reading routed IDs and queues subsequent table uploads after the host has built them.

For a serve request, use actual batched prompt processing (`--short-read 0`) and request a 32,768-token prefill chunk (`--prefill 32768`, or `--prefill auto:32768`). The serve setup can reduce a requested chunk to fit its cache-lending budget, so confirm the resolved chunk through normal run output before claiming the requested size was used. `--max-context 262144` and int8 KV are compatible target settings in scope, but this review cannot establish that they fit on a particular B570.

The verifier has an event-completed segmented route in the SYCL code. Set `STRATA_VERIFY_SEGMENTED=1` to select it explicitly and avoid running the `doorbell_visible()` concurrent-visibility probe; the SYCL capture path itself records event-completed segments. `STRATA_SYCL_VERIFY_OVERLAP=0` is an implemented conservative option to suppress overlapping shared/hit work graphs, if the intended configuration requires serialized CPU/GPU service. MTP/drafting stays disabled as requested. Do not enable batch or pipelined verifier modes that require a GPU kernel to wait on host writes.

The conclusion is conditional on using the SYCL/Xe backend represented by these sources and the stated single-queue configuration. The source has a concrete safe path; the audit does not establish that its current immutable checkout was built with these sources or that B570 executes it successfully.

## Whole-path handoff trace

- **Routed IDs, CPU grouping, and table write-back:** `src/prefill/prefill.cpp:2061-2072` queues the routed-ID transfer and calls `cudaStreamSynchronize(m.cs)` before the host reads `ids_h`. Host grouping then fills the slot/source tables; lines 2122-2135 enqueue their uploads only after those host writes. This is an exclusive host phase after queue completion.
- **Stager host-buffer reuse:** `src/prefill/prefill.cpp:255-283` creates a `dma_done` event for each host staging buffer. The Stager worker waits for `event_sync(dma_done[b])` before overwriting a buffer at lines 321-337. `issued_one()` records the event after queuing the corresponding H2D copy (`373-376`). Host-side `ready[]`, `issued`, and `head` are C++ atomics between CPU threads, not a device/host USM polling protocol (`257-263`, `338-376`). This is materially different from R207's `malloc_host` `done_seq` polled through a volatile load.
- **Stager reachability:** for the non-stream-all routed path, `src/prefill/prefill.cpp:2078-2092` creates Stager jobs for transient or unpinned nonresident routed experts. `stage_one()` uses `m.stager->wait()` and then records the copy event (`2097-2131`). For the streamed path, `issue_until()` obtains staged blobs and calls `issued_one()` after queuing copies (`1353-1378`). Therefore neither disabling nor avoiding Stager is needed for synchronization admission; this Xe version has event-managed Stager reuse. Its large-chunk stream route is selected from ring size and chunk size (`1323-1327`), not by a `STRATA_PREFILL_STREAM_ALL` switch.
- **PLE buffer reuse:** `src/prefill/prefill.cpp:1295-1313` enqueues the current PLE host-to-device upload, records `ple_copied[ple_buf]`, and before reuse waits for `ple_copied[ple_buf ^ 1]`. A subsequent PLE gather starts only after this wait. This is an event boundary for multi-chunk prompts; there is no `ple_done_seq` host poll in this source.
- **Single-queue ordering:** `src/prefill/prefill.cpp:1317-1327` documents that one in-order queue orders device ring copies and reads. Stager host buffers still use their explicit DMA events. If `STRATA_SYCL_PREFILL_SAME_QUEUE=1` causes the copy and compute streams to be identical, `copy_events` is conditionally suppressed only for the same stream; in-order queue ordering is the stated replacement. The target explicitly prescribes a single queue.
- **Verifier completion before host service:** `src/core/verify.cpp:1225-1229` launches a captured graph segment with a completion event. Under `STRATA_ENABLE_SYCL`, before host expert work the run path synchronizes `layer_done_` (`1248-1257`), then after service synchronizes the copy stream and launches the next graph segment with the same completion event (`1329-1345`). The SYCL `pre/post` code separates shared/hit work into work graphs when overlap is enabled (`src/core/verify.cpp:777-783`, `900-924`, `1513-1529`); `STRATA_SYCL_VERIFY_OVERLAP=0` selects the non-overlap path.
- **No device spin-wait fallback:** `src/kernels/sycl/sequence.cpp:37-44` makes `wait_flag_ge` and `wait_flag_ge_or` throw with “mapped flag polling is unsupported.” The SYCL implementation of `doorbell_wait` likewise throws in `src/kernels/sycl/elementwise.cpp:127-129`. It therefore cannot silently fall through to the CUDA-style GPU polling kernels. `STRATA_VERIFY_DEVICE_PLAN` is forcibly disabled in SYCL (`src/core/verify.cpp:402-409`), avoiding the device-plan flag-wait route.
- **Visibility probe:** `src/core/verify.cpp:492-497` reads `STRATA_VERIFY_SEGMENTED`; if unset, it calls `doorbell_visible(cs_)`. In the Xe kernel that probe exercises a host/device concurrent volatile doorbell (`src/kernels/xe/verify_kernels.cpp:721-745`). Explicit `STRATA_VERIFY_SEGMENTED=1` skips that probe. For the SYCL build, capture is split into event-completed segments independently (`src/core/verify.cpp:1000-1049`), and each graph handoff uses `layer_done_` as above. Under a non-SYCL Xe build, `segmented_` is the mechanism that places a stream synchronization before reading the device-written sequence (`src/core/verify.cpp:1604-1616`); that branch is outside the requested SYCL/Level Zero configuration and should not be presumed safe solely from the label `atomic_host_usm=0`.

## Real controls and non-controls

- `--prefill 32768` and `--prefill auto:32768` are parsed in `src/program/generate.cpp:2238-2248`; `--prefill auto` is capped at 8,192 by default unless `STRATA_PREFILL_AUTO_MAX` or `auto:N` raises it (`1242-1247`). The later cache-lending planner may lower a requested chunk (`generate.cpp:5608-5638` and serve setup around `5730-5747`).
- `--short-read 0` is a real serve option: `generate.cpp:2323-2325` records it as explicitly given; `windows_ok()` uses the resulting route decision and `--short-read` selects verifier windows versus batched prompt processing (`1179-1181`, `8586-8595`, `9052-9063`). A segment containing image embeddings remains in batched prefill.
- `STRATA_VERIFY_SEGMENTED=1` is read in verifier initialization (`verify.cpp:492-497`). On the SYCL build, event segments are structural regardless; this explicit value avoids the visibility probe and records the intended safe mode.
- `STRATA_SYCL_VERIFY_OVERLAP=0` is read in `verify.cpp:393-400` and selects no shared/hit graph overlap. It changes scheduling overlap, not the completion-event protocol.
- `STRATA_PREFILL_ISSUER=0` is a real inline-issuer switch (`prefill.cpp:1383-1399`); threaded issuer coordination uses CPU `std::atomic` variables. Leaving it unset/default is source-admitted too. It does not disable or bypass the event-backed Stager.
- `STRATA_PLE_BATCH=0` is a real PLE arithmetic selection (`prefill.cpp:1198-1205`), not a synchronization control. Event-based PLE reuse remains in force either way.
- `STRATA_PREFILL_STREAM_ALL=0` and `STRATA_PREFILL_FIRST=0` are not present as controls in this checkout. Do not carry those R207/official-v0.1.43 settings into a Xe command and infer that they disable a route. The Xe streamed route is chosen automatically at `prefill.cpp:1323-1327`.

## R207 comparison and standard

R207 correctly withdrew an overly broad v0.1.43 admission because that official tree's Stager `done_seq` and PLE `ple_done_seq` are device-written host-USM words read by host volatile polling. This pristine Xe v0.1.42 tree has different handoffs: host staging reuse is event-backed, PLE upload reuse is event-backed, and verifier GPU waits are explicitly unsupported by its SYCL sequence implementation. Thus R207's specific raw-marker blocker does not transfer to these Xe paths. The shared CPU-grouping observation from R207 does transfer, and here the queue synchronization remains present.

The Khronos [SYCL 2020 specification, revision 12](https://registry.khronos.org/SYCL/specs/sycl-2020/html/sycl-2020.html) defines `aspect::usm_atomic_host_allocations` in terms of supporting atomic access to host USM concurrently from host and device, and separately requires synchronization between host and device accesses to host allocations (sections 4.6.4.5 and 4.8.2). Queue/event completion is the relevant synchronization model for this admitted route; the absent aspect is not a reason to reject these mutually exclusive, event-ordered accesses. This does not validate the separate concurrent volatile doorbell probe or spin-wait protocol.
