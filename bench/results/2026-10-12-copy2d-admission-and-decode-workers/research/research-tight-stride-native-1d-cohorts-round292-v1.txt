Round 292 — tight-stride native 1D expert-copy cohorts

Scope and result

Read-only source and closed-receipt audit of the current combined source and the WCO (windowed copy-cohort) source branch. No code, build, test, GPU, or model work was performed. The 2D WCO implementation is not needed for a direct 1D memcpy when a source run and destination run are both contiguous at the same stride. In the existing fixed-stride ring, that is true only when each blob width equals MMQ_SLOT(). It is false for IQ3_S in the R273 artifact. A narrow, source-dependent 1D candidate remains for the single largest-blob layer (layer 47); its actual contiguous-run count and performance have not been measured.

The authorized closed record is `/home/yayoi/.local/state/strata-sycl/post-reboot-tuning-20261007/main-prefill-native-batch-diagnostic-model-root-v1/xe-timed1-on/record.json`. It has 192 layer/chunk H2D rows: 48 layers × 4 chunks, each reporting 509 submitted calls. The closed run total is 97,728 calls and 199,990,579,200 bytes. These are observations from that run, not a prediction for a new implementation.

The ten layers with GU type 21 (IQ3_S) have `blob_bytes=2,329,600`; each reports 509 calls per chunk. The receipt reports `2,662,400` bytes for layer 47, GU type 23, the maximum among all 192 layer/chunk rows. Thus the model's observed MAXBLOB/MMQ_SLOT is 2,662,400 bytes. The IQ3_S width is 332,800 bytes smaller than that pitch. It is divisible by 256 (9,100 × 256); that preserves an alignment boundary but does not remove the inter-slot gap. Layer 47 is the only layer at the maximum width. If all its entries could be grouped in runs of 16, its 509 per-chunk copies would have a theoretical floor of ceil(509/16)=32 submissions, or at most 1,908 fewer submissions over the four chunks (1.95% of the observed total). This upper bound assumes every source entry is eligible and adjacent; the actual reduction could be smaller or zero.

Source evidence

The combined source is `/home/yayoi/ghq/github.com/yqYo1/Strata/.worktree/sync-latest-updates-20261012`.

- `src/prefill/prefill.cpp:597` defines `MMQ_SLOT()` as MAXBLOB rounded up to 256 bytes. Lines 856–873 allocate an owned ring as one `ring * MMQ_SLOT()` allocation and set `stage_dev[i] = ring_base + i * MMQ_SLOT()`; the borrowed path allocates MAXBLOB bytes per slot. The comment at 861 describes the owned slots as 256-byte aligned.
- Lines 1387–1433 build the streaming sequence layer-by-layer and expert-ID-increasing, omitting resident experts. Lines 1462–1473 copy each entry's actual layer blob width to its fixed-pitch slot; the threaded branch does the same at 1523–1538. WCO's layer/expert/source adjacency test at its `src/prefill/prefill.cpp:1474–1487` confirms that batching is conditional on actual consecutive expert IDs and source pointers, not just a matching size.
- The host layout computes each native blob from its actual GU and Down row sizes (`src/kernels/cpu/native_expert.cpp:59–63`). `src/kernels/cpu/expert_layout.cpp:282–295` records per-layer blob sizes and refuses a layer table whose offsets are not contiguous. The QType mapping identifies ID 21 as IQ3_S (`include/strata/artifact/gguf_reader.hpp:187`).
- Other consumers make the fixed layout material: stage-slot uses and reuse events are indexed by `stage_dev[sl]` and `used_of[sl]` in prefill; native batched dequant uses the actual `f.up_off`/`f.down_off` offsets and validates actual payload extent (`prefill.cpp:2247–2266`); the MMQ direct ring has its own MMQ_SLOT addressing and passes MMQ_SLOT as `Product.expert_bytes` (`prefill.cpp:2324, 2445–2467, 2741–2755`). A 1D transfer of `height * 2,329,600` bytes into the current IQ3_S destination slots would run into the next destination slot before its `MMQ_SLOT` boundary. It is therefore incorrect with the current address layout. Flattening is not a valid replacement for 2D on IQ3_S.

The WCO implementation is in `/home/yayoi/ghq/github.com/yqYo1/Strata/.worktree/perf-prefill-native-copy-cohorts-20261012`. It already caps a cohort at 16, prevents ring wrap, requires owned staging/no MMQ direct ring, direct pinned entries, same layer and adjacent source pointers, and validates source extent and host-USM membership (`src/prefill/prefill.cpp:1464–1487`). It captures each slot's last-reader event and completion association, submits one operation, assigns its returned event to every copied marker, marks each slot live, then returns the number of entries issued (`1471–1512`). This preserves per-slot reuse and the caller's credit accounting as long as a 1D implementation keeps that behavior and returns the same cohort height; native-batch consumer group release remains outside this issue operation.

`src/core/gpu.cpp:257–270` has `copy_async_after`, which submits `handler.memcpy` but accepts only one prior event. WCO's `copy_cohort_async` instead accumulates all non-null last-reader events and calls `queue.ext_oneapi_memcpy2d` (`src/core/gpu.cpp:274–302`). A standard-SYCL 1D cohort wrapper can use one `queue.submit` with `handler.depends_on(vector<event>)` and `handler.memcpy(dst, src, height * width)`, then attach its returned event to every `done[row]`. This avoids the 2D extension and does not need a private runtime API; it is a new multi-dependency wrapper path, not the existing single-event `copy_async_after` helper unchanged.

For layer 47, `width == MMQ_SLOT()` and both the source and owned destination are tight by expert. It can use that 1D submission only for each run that also passes the existing WCO source-adjacency, host-USM, allocation-extent, no-wrap, event-dependency, and credit checks. The existing `copy_range` membership/extent check is still required: the sequence being consecutive is not proof that its backing source range is valid. Layers with width below MMQ_SLOT, including all observed IQ3_S layers, must remain on the current per-slot copies or the separately validated 2D path.

A per-layer tight pitch for IQ3_S could make a future 1D transfer geometrically possible, because its width is 256-byte aligned and is less than MAXBLOB. That changes slot addresses. Under asynchronous execution, changing the stride between layers can make the new layer's slot range overlap a different old layer slot; waiting only on that same-index slot's `used` event would not cover such cross-slot overlap. Any such design would need a deliberate ring relayout/barrier and re-audit of all stage/MMQ consumers. It is outside the no-layout-change 1D candidate and is not justified by this audit.

Eligibility and evidence needed before implementation

1. Keep the fixed pitch. Enable the standard 1D path only when `width == MMQ_SLOT()`; for this receipt that is layer 47, not IQ3_S. Retain every WCO gate and check actual source/destination extents, pointer geometry, host/device allocation kinds, slot range, and credit before enqueue.
2. Make one public-SYCL submission depend on every non-null `used` event for the slots, enqueue one contiguous `height * width` memcpy, then associate its completion event with every slot's `copied` event before publishing issued credit. Do not weaken `stage_live`, stager ownership, stop/drain, or native-batch release semantics.
3. Add bounded tests for equality (max-width 1D eligible), less-than-pitch rejection (IQ3_S rejected), source gaps/resident omissions, pinned/transient and invalid source ranges, ring tail/no-wrap, 16-row cap, all prior-reader dependencies, event assignment for every slot, and issuer failure/drain. The fake or CPU fixtures must prove geometry and publication; a later device check must verify ordering and copied bytes.
4. Before a performance run, obtain the exact cohort/fallback counters for layer 47 from the current source and a fresh matched receipt. The R273 receipts give 509 copies per layer/chunk but not the number of adjacent eligible source runs, and no timing or speedup is inferred here.
