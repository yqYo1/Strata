GEN128 parsing and output scope

validate_long directly parses the actual full protocol. It requires RESUME0, exact four8192-route PP records through32767, REUSED0,128 alternating T/LP5 pairs and one actual16-field DONE at the end. Actual DONE generated count128, prompt/read_n32768, finishlength, zero reuse/draft/EOS truncation, finite positive engine times and nonnegative tier accounting are required. IDs are bounded below248320, sampled/logprob values finite, top5 IDs unique, tags/field lengths/count/order bounded. Emitted EOS248044/248046 are rejected; these constants are source-bound to the actual candidate generate.cpp default before owner import. Cancel/nonfinite/ERR/batch/truncated/extra output is rejected. No DONE is synthesized, rewritten to16 or delegated to the old GEN16 validator.

The full128 T/LP5 stream and the actual first32 output lines (16 real pairs) are independently hashed. The prefix must equal f8aca127a7f45238d7567368ee8ad5c26c4a3488fc0cc6b83a4d19d50a6cbd6f and the immutable original closed native-batch GEN16 proof. The prefix digest was read from the committed MODEL_RESULTS, not a live worker root. Every later long sample must also match the first successful long sample's full128 fingerprint on identical input/binary; divergence is retained as failure, preventing timing comparisons on changed continuation targets. Each sample retains raw protocol, individual engine/host samples and full/prefix fingerprints. Clean route is source-bound/inferred, not falsely called observed tracing.

Optional --paired-gu unchanged/off/on is explicitly separate from the worker sweep. unchanged is default and preserves the exact original environment. off/on require the current candidate source/binary actually implement the flag plus a separate Main-qualified pairedGU CPU parity receipt bound to exact source/binary. A no-op or unsupported flag is refused before owner import. For adjacent opposite arms with identical worker/input/binary, the runner checks all environment fields except the explicit GU flag and records full128 equality. The existing fixed build/runtime proof paths remain unchanged; a future different binary needs a NEW Main-reviewed derivative/artifact chain, not rewriting or reusing an original receipt as its qualification.
