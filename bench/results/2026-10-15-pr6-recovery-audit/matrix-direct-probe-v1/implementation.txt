CLI/default correctness mode
----------------------------
No args or --validate runs host contracts, then device admission/correctness.
--help and --host-only return before runtime_for/device discovery. CLI parsing,
dimension/product/overflow checks and the known benchmark shape budget precede
runtime initialization. --host-only additionally exercises the actual product
empty-batch and invalid count/cap/head-dimension paths with an invalid stream
sentinel that those early gates must never dereference. It does not launch a
kernel or query a device. Its report's runtime_created=false refers to this
program never constructing a Runtime, not absence of executable image loading.

Geometry limits are fixed 24 query heads, two KV heads, dim256, page4, logical
262144 cells / 65536 page-table entries. Each fixture checks pointer-size-safe
products/additions, selected logical IDs and physical map bounds. A conservative
512 MiB combined host/device/reference byte bound rejects oversized fixtures
before allocation. This is a fixture size limit, not a replacement for the
product's device/local-memory admission gate or a free-VRAM measurement.

Default validation has 44 pairs / 88 actual matrix calls:
  * Formats0FP16,1INT8,2Q4_0,3K8V4: nq3 and width0/31/32/33/63/64/65/2051.
    cap=max(1,width), so width0 is a real admitted zero-selection kernel case.
  * All four formats: nq1,width65,all logical pages nonresident.
  * All four formats: nq3,width65,dense,all scales zero (format0 uses zero KV).
  * Extra dense format0,width65 and dense-hot format1,width2051, both nq3.
  * Extra format1 invalid device widths -1 and cap+1 with valid physical inputs.

Sparse cases use five physical pages, with table[0]=3,[1]=1,[17]=4,
[65534]=0,[65535]=2 and all others -1. Negative ID mask entries and missing
logical pages are present; the final ID of every nonempty normal selection is
262143. Its valid nonidentity page mapping addresses a real row in the small
physical pool. All-nonresident cases map every page to -1. This is real selected
logical address arithmetic plus component attention computation, NOT a full
262144-cell ingestion/state/RESTORE proof. Width0 has no active selected ID;
invalid-width/all-nonresident cases likewise do not prove a physical high-cell
read. Dense cases map every selected low page via a permutation and map logical
page65535 to one additional physical page, retaining the high logical ID.

For Direct0 and Direct1, exact same host/device Q, pools, table, IDs, steps,
capacity, geometry and output allocation are reused. Only output is reset to
its initial sentinel before each correctness call. Input payloads and prefix/
suffix guards are read back and checked byte-for-byte after each arm. Output
prefix/suffix guards are checked, and every admitted output element is compared.
No output subset sampling or fallback reference is used.

Every actual qsa_prompt_attn_batch bool is recorded. false is followed by a
checked drain and proof that the entire output, including payload, is unchanged.
It is classified UNMEASURED_DECLINED, never filled by qsa_decode_attn_batch or
counted as a matrix correctness pass. All four formats use the unchanged product
admission. Modes2/3 may decline on this device; there is no new local-memory
gate, forced admission or Direct-specific capacity relaxation. The existing
STRATA_PROMPT_ATTN_Q4 option is not altered; its disabled-by-environment boolean
is recorded so an option-driven mode2 decline remains interpretable.

Independent numerical reference and pair contract
-------------------------------------------------
The oracle is independent scalar double-precision dot, max/exp/softmax and V
weighted sum. It decodes the stored FP16 bits with host _Float16, INT8 codes
with one FP16 scale per64 dimensions, and packed Q4_0 nibble/FP16 block scales
per32 dimensions. It uses the documented page/head/cell address formula and
current selected IDs; it does not call matrix/split-attention helper math.
Missing/negative selections contribute no weight; all missing/invalid/empty
rows yield zero. Query data and KV codes are deterministic finite synthetic
values; normal INT8 also has some exact zero scale groups.

Each arm requires finite output and absolute error <=1e-5*(1+abs(double_ref))
for EVERY output element. This is the existing STRATA_TEST_PROMPT_MATRIX
reference tolerance in decode_attention.cpp, adopted before any run. Max
absolute error/nonfinite counts and oracle-comparison admission are recorded.
The FP16/Q4 coordinate inputs are already in the attention entrypoint's basis;
this is not a test of upstream RoPE/Hadamard transforms or model tensor state.

With STRATA_SYCL_PROMPT_NATIVE_KV_MIN=0 fixed before runtime construction,
Direct0 and Direct1 instantiate launch<Mode,false,false> versus
launch<Mode,true,false>. Source Q scaling, QK/PV hi-lo joint-matrix operations,
online-softmax sequence, accumulation and final division are identical. Direct
only changes final output storage: normalized accumulator elements go directly
to global output instead of local final[] + barrier/copy. No new reduction or
summation order is introduced. Existing matrix test already requires their
bitwise equality. Accordingly this fixture requires whole-output/guard bitwise
equality when BOTH arms admit, and reports that result separately from the
double oracle. Compiler-template differences can still falsify that expectation;
such a failure remains a failure requiring review, not an automatic tolerance
relaxation. This does not require matrix versus split fallback to be bitwise.

Native mode0 FP16 KV optimization is explicitly disabled by setting exactly
STRATA_SYCL_PROMPT_NATIVE_KV_MIN=0, so this compares only Direct storage. The
program has one host issuer, no user host worker threads; setenv toggles only
STRATA_SYCL_PROMPT_DIRECT=0/1 before queued calls. Product dispatch reads getenv
on every call. No process-wide external model environment is changed; these
mutations occur only inside the separately launched probe process. Main must
serialize it with model/build/test work as requested.

Separate benchmark mode
------------------------
--benchmark performs NO correctness/oracle/guard readbacks or host-test suite.
It defaults to format1 INT8, fully resident selected rows in a small nonidentity
dense-hot physical pool, width2051, nq32 then nq256. Q/table/IDs/steps/pools are
identical between arms, and all data allocation/upload/hash work is outside the
timed samples. Shared selected cells deliberately make this a hot synthetic
component workload, not a model-memory traffic or whole-prefill measurement.
There is no nq4096 workload in v1.

Both existing variants are prewarmed with four calls each and a whole-queue
drain. Each warm arm records actual admitted-call count/bool. If either declines,
the case is UNMEASURED_DECLINED and has no timed samples. There is no fallback.

Default40 samples use Direct0,1,1,0 repeated (ABBA):20 samples/arm. Each sample
enqueues four entrypoint calls, with no per-call waits, readbacks or fixture
validation, then performs ONE whole runtime queue drain. Product entrypoint
validation/admission remains part of the unchanged interface and is not bypassed.
Every sample records requested/admitted call count; a changed decline makes
that sample unmeasured and stops rather than reporting a fallback timing.
CLI bounds are samples40..400 divisible by4, repeats1..32, queries32or256.
All individual samples are emitted before medians; no averages replace them.

Two DIFFERENT measurements are recorded per sample:
  submit_plus_whole_drain_wall_ns: steady_clock from before first marker issue
  until after the final whole checked drain; includes marker issue/work,
  host product/admission/submission work and queue completion waiting.

  marker_device_envelope_ns: final marker command_start minus initial marker
  command_end, read only after checked completion. It contains attention work
  AND GPU idle/submission gaps between markers. It excludes marker service;
  it is not exclusive kernel time, not an event for a returned BLAS operation,
  and is not interchangeable with wall time. No claim is made that either is
  a sum of actual kernel intervals or a source-component critical path.

--benchmark rejects enabled known tracing/UR/ZE validation environment switches
before runtime initialization. It never dumps general environment contents.
This finite list cannot detect every injected collector/runtime layer. Main
must use its recorded clean explicit launch whitelist and no profiler/trace/
validation wrapper. Diagnostic correctness and quiet timing are separate runs.
Runtime's existing profiling-capable in-order compute queue is retained, as
needed to obtain the marker timestamps; no product kernel is instrumented.

Ownership, errors and records
------------------------------
Host Input is created before device buffers; Lease is declared after those
owners and before any upload/submission. Kernel readers use only immutable
device owners; host upload vectors remain live. Checked Runtime::wait drains
compute+transfer and checks sticky async errors before Lease permits owners to
unwind. Runtime Allocation itself also uses the existing checked cleanup rule.
Readback/upload helpers fail-stop immediately on a submission/wait exception,
before their temporary source/destination vectors can be destroyed. A failed
drain delegates to the same sycl_backend::cleanup_fail_stop used by Runtime,
which terminates the process with owners live. No unchecked wait/free proof,
uncaught async error continuation or timeout-as-completion assumption is added.

CLI/geometry/correctness errors emit FAIL and return1 after scoped retirement;
sticky completion failures stop the native process through the existing fatal
cleanup policy. No arbitrary external queue/owner is introduced. Main still
owns the finite process deadline: a blocking driver wait cannot be cancelled
safely by freeing these buffers. Do not run unsupervised after application.

Output consists of one short device/driver/local-memory line and compact JSON
records: policy, input descriptors/FNV64 fingerprints, actual admission, each
arm's full-output result, pair status, every benchmark sample and medians.
FNV64 identifies generated operands for this bounded comparison; it is not a
cryptographic/collision-resistant source receipt. Pin binary/source SHA256 and
compiler/runtime/environment separately in Main's run receipt. CLOSED/exit0
means requested operations completed; any UNMEASURED_DECLINED record still
means no matrix result for that arm/case. It is not turned into a pass by exit0.
