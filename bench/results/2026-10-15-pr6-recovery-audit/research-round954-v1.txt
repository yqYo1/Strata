# R954 — decision support: BF16 QSA prefix softmax ownership

**Decision:** two register layouts can distribute the current 32-score max and sum across the eight SIMD16 subgroups already in the 128-thread workgroup, with no added host work, global scratch, or workgroup barrier. First try two head rows per subgroup in two sequential row waves using `reduce_over_group`; compare against two simultaneous eight-lane row segments per subgroup using register partials and XOR reductions. Neither choice has measured performance. Directly reducing all 32 values from the current matrix fragments is not a zero-communication option: each row’s two 16-score fragments belong to different subgroups.

## Contract and current point

The pinned SGLang `qsa/sparse_attn.py` source at [`877be2974aa151a984e52822c028276c2b1e9303`](https://github.com/sgl-project/sglang/blob/877be2974aa151a984e52822c028276c2b1e9303/python/sglang/srt/layers/attention/qsa/sparse_attn.py) has no-prefix extend in `_sparse_gqa_prefill` (lines 79–110) and prefix extend in `_sparse_gqa_chunk_prefill` (lines 217–253). Both scale Q by `scale * log2(e)`, round it to Q’s dtype, mask invalid selected tokens, and maintain FP32 max, normalizer, and V accumulator across online blocks. P is converted to V’s dtype for the PV dot; output is allocated like Q. In the configured BF16 path this means BF16 Q/K/V/P/output with FP32 softmax state and matrix accumulation. Prefix packing uses the requested output dtype, normally Q dtype (lines 320–358). The source’s dispatcher varies `BLOCK_N` with query count; for long batches it can use 16. Strata’s 32-cell tile is a different block boundary, not a reason to alter the numerical contract.

SGLang masks missing keys to `-inf`, but has no explicit all-missing-row guard or nonfinite diagnostic in these kernels. Strata’s stronger conditions remain required: invalid or unmapped rows contribute P=0; an all-missing row returns zero; nonfinite Q/score/scale flags are preserved; a live row with a diagnostic condition keeps the current canonical-NaN output behavior. In particular, do not evaluate `exp2(-inf - -inf)` for an empty row. These guards are Strata requirements, not properties inferred from SGLang.

The current kernel has 8 subgroups of 16. QK score production uses subgroups 0–3 for four `8x16` score fragments: two 8-head groups times two 16-cell halves. `joint_matrix_apply` writes them to FP32 `scores[head][33]`. After the existing score barrier, only `tid < 16` performs softmax, so one work-item serially scans 32 scores per head, emits BF16 P, then updates FP32 max/normalizer. The `score_pitch=33` padding and VNNI-packed local operands remain fixed for this decision.

Current supplied evidence is only context: the matched six-process component result for tilepack was 333.381292 ms row-major versus 311.120328 ms tilepack; static attention instructions were 4977 versus 3901, SLM loads 576 versus 306, and static DPAS 16 versus 24. The softmax ownership was unchanged, so none of these numbers isolates it or establishes a softmax bottleneck. The 39262-token model comparison for this new layout is still pending.

## Candidate A — two row waves, standard subgroup reductions

Let each subgroup `s` process rows `s` and `s+8` in two fixed iterations. For one row, lane `l` loads cells `l` and `l+16`, turns masked/nonfinite scores into `-inf` for max, and reduces their local pair with `sycl::maximum<float>`. A `reduce_over_group(sg, ..., maximum<float>)` gives the tile max. Combine it with that row’s prior max, then compute FP32 alpha. Each lane evaluates the two masked `exp2(score-new_max)` values and locally adds them; `reduce_over_group(..., sycl::plus<float>)` produces the FP32 tile sum. Each lane writes its two BF16 P values to the existing probability tile. Lane zero updates the row’s max, alpha, and `fma(old_normalizer, alpha, tile_sum)`.

All eight subgroups participate, including for the four padded head rows. Every lane calls both reductions in both row iterations; row validity is data, never a divergent branch around a group operation. This shortens each row’s 32-score serial scan to two lane-local scores plus subgroup reductions and reuses the existing score/P arrays and barriers. The counterevidence is that each subgroup still handles two rows serially and executes two max and two sum reductions per tile; its critical path may therefore retain a row-wave cost. Reduction lowering and the extra shared-score reads are compiler/runtime dependent.

## Candidate B — two simultaneous eight-lane segments, register partials

Assign row `2*s` to subgroup lanes 0–7 and row `2*s+1` to lanes 8–15. Each lane handles four cells for its row (`lane_in_half + 8*j`, `j=0..3`), keeping finite/mask-filtered max, score-bad bits, and later the four FP32 exponentials/sum in registers. Reduce each value with `permute_group_by_xor` masks 1, 2, and 4. These masks do not toggle lane bit 3, so the two eight-lane rows remain isolated. Apply the row’s prior max after the three max exchanges; after computing four probabilities per lane, use the same three exchanges for the FP32 sum. Lanes 0 and 8 write each row’s FP32 state, while every lane writes its four BF16 P cells. A two-bit per-lane diagnostic flag combined by bitwise OR can preserve separate row score flags without cross-row contamination.

This runs both rows in each subgroup at once, without an additional workgroup barrier or scratch allocation; the subgroup exchanges are the row reductions. It costs four score reads and four exponentials per lane at once, explicit exchange stages, and more simultaneously live registers. It is a coherent alternative if Candidate A’s two row waves remain costly, but source alone cannot predict which wins. The SYCL `permute_group_by_xor` contract requires the same mask in all subgroup lanes and returns the lane selected by XOR; masks 1/2/4 are in range for both 8-lane halves of SIMD16.

## Fragment-owned alternative and API constraints

Intel’s coordinate-aware `joint_matrix_apply` example explicitly permits accumulating per-row local partials (`sum_local_rows[row] += val`). That is useful evidence for fragment-local partial work, but it does not make a full 32-cell reduction free here. Each 8x16 score fragment covers only one half of the row; the second half is in another subgroup. Each fragment can form local max/sum partials, but joining the two halves and rebasing all probabilities on the final max needs inter-subgroup exchange. With the present stage order that means shared partial state and a synchronization handoff, or a different score tiling/query shape. The oneAPI extension documents BMG BF16 accumulator combinations including 8x16x16, not an 8x32 output tile in the listed table; runtime `matrix_combinations` remains authoritative. Treat direct full-row fragment reduction as conditional research, not a ready no-barrier candidate. Do not rely on undocumented lane-to-fragment register mapping.

`reduce_over_group`, `permute_group_by_xor`, and Intel matrix operations are group functions. All subgroup lanes must reach them convergently, with identical operation/parameters; do not put a collective inside the per-element `joint_matrix_apply` callback. Keep the existing `reqd_sub_group_size(16)` and the current workgroup capability guard. The pinned oneAPI matrix spec also records BMG pointer alignment and load/store stride constraints (4-byte base alignment, byte stride a multiple of 8); do not change the current `scores` representation to a joint-matrix load/store without checking those constraints. Runtime device-query success is still required; the spec is not proof that a given driver/device advertises this path.

Both candidates preserve the online recurrence: tile maximum includes the prior maximum; alpha is zero when the prior normalizer is zero; FP32 `p` is summed before rounding only the P matrix operand to BF16; FP32 FMA updates the normalizer; BF16 V and output remain unchanged. A reduction tree changes FP32 addition order and may change normalizer/output rounding. That is acceptable reduction-tree rounding under the actual SGLang contract, provided task-level numerical gates pass. It is a contract change to sum BF16-rounded P, narrow max/normalizer/accumulator, alter Q/P/V rounding points, omit `alpha`, use a different mask, or lose the empty-row/diagnostic rules. Do not make llama.cpp or an extra-precision FP32 oracle bit equality the adoption gate.

## Recommendation, gates, and provenance

Implement no code from this report. For Main’s next serialized experiment, compare Candidate A first to minimize mapping and compiler uncertainty, then B in the same binary and fixture if it is still useful. Keep tilepack, score pitch 33, selected IDs, tile boundaries, diagnostic flags, and all unrelated work fixed. Use an independent BF16-contract oracle and cover full/partial 32-cell tiles, multiple online tiles, invalid IDs/pages, all-missing rows, finite ties, NaN/Inf Q or scores, bad scales, output guards, input immutability, and fault/lifetime checks. Preserve exact status for every case. Measure only Main-owned component and later model runs; do not infer a softmax gain from these proposals. Full-context and RESTORE gates remain separate.
