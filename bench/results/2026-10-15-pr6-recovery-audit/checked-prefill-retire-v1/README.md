# Checked Prefill scratch retirement proposal v1

Status: proposal only. Product sources, binary and current profiling run remain untouched. No build, tests, GPU, Git, network or cleanup performed. The Python generator only writes this directory; an initial `python` invocation was unavailable, then `python3` generated the files. Main owns review, application and every execution below. Static contracts/mocks cannot qualify lifecycle safety, full context correctness or performance.

Read inputs: project skill, retention policy, current research-index, R599 and R594. Current root source resolves Prefill through `src/prefill/prefill.cpp` including `layer_major.inc`; GEMM/MMQ implementations are the SYCL files, not historic `sycl/src`. Prior MTP expert detach/restore is unchanged.

`source.diff` is the proposed patch; `source/` contains complete modified-file copies. `source-manifest.json` pins base and candidate SHA256. Main must compare bases again after profiling closes. The generator remains as provenance, not a test or runtime recipe.

Exact `STRATA_PREFILL_RETIRE_SCRATCH=1` opts in. Unset, `0`, and other strings preserve prior dispatch. Initial candidate admits SYCL single-device, no split/peer/remote, static cache (`--adapt-swaps 0` or adaptation disabled). It adds no context bound. Existing full physical 262144 host-KV backing stays intact. It supports owned scratch and existing borrowed tails; borrowed cache memory is never freed. Cache enlargement/admission and speed are separate work.

Serve retires after the entire segmented prompt loop, checkpoint operations, final refill and a checked residency publication, before the first decode window. Individual successful segment returns do not retire. On failed/cancelled run return, the opt-in arm checks global completion before cache refill can overwrite loaned scratch. Cancellation then exits the loop, performs existing final refill, then uses explicitly labelled cancelled-prompt teardown; cancelled status and existing DONE behavior remain unchanged. Failed prompt/setup/checkpoint/refill returns enter checked owner teardown rather than unchecked cleanup. A failed completion/free exits immediately without stack unwinding, destructor retry or caller queue destruction. This is a process failure, never a successful request or cancellation result.

A fresh empty Impl replaces the released one, while callbacks, stage policy, embd_rows and accumulated statistics stay on Prefill. The next `lend()` lazily initializes before its own-buffer early return or any relayout. Initialization uses the saved configured maximum chunk and original maximum loan pointer/size; the existing lend logic then carves the exact current request loan. Keeping maximum geometry permits later larger segments in that same prompt without intermediate retirement. RESTORE/checkpoint application occurs earlier; read_windows-only requests never invoke lend and can keep scratch retired. The first server request still inherits existing startup initialization; this proposal does not move startup admission/planning. Standalone already resets Prefill by default; only the opt-in arm substitutes checked retirement.

## Owner proof and irreversible operations

- `Impl::owned` holds only original cudaMalloc pointers: GEMM external scratch/workspace; carved device buffers including R, token IDs, shared GDN/QSA/MoE region, staging ring and optional identity/staged-KV scratch. Borrow bump allocations are absent. `SessionState` pointers are non-owning; session block, recurrence/conv, KV/page tables, PLE history and host backing remain untouched.
- Each `run_impl` chunk synchronizes before on_chunk, calls callbacks synchronously, joins its issuer and stage/PLE futures on exit, and checks compute/copy completion at successful epilogue. Layer-major's temporary cache/residual owners close before its return. MTP draft_kv/fallback prompt work and selected-head readers finish inside callbacks. Only driver-completed whole prompts use the successful retirement phase. No callback or external consumer may retain R after callback return.
- Verifier arena/R, all VerifyHits/cache pointers, graph handles, commit work, MTP window_R binding, MTP KV/normal/coupled graphs/dense/head/expert owners and conversation checkpoints are unchanged. No call to cache.close, session_zero, verifier retirement or MTP bind is added. Existing MTP release scope finishes before this boundary.
- Stager has persistent host threads: stop claims, finish active jobs, signal quit and join every thread before the global drain. Run-local issuer/futures are already gone. The queue may alias caller cs; no stream destruction occurs in this candidate.
- Global cudaDeviceSynchronize checks compatibility streams and runtime queues before any irreversible release. Memory query must succeed before frees. Per-resource checked release also waits all relevant queues; failed later waits stop immediately with remaining owners retained. Successful resource handles become null immediately.
- Existing cudaFree return checking is inadequate: compat release moves/erases its registry owner before Allocation's noexcept cleanup. New strataFreeChecked keeps the registry Allocation in place through explicit `release_checked`; only known successful sycl::free clears data and erases the empty Allocation. An exception leaves registry ownership intact and causes immediate process fail-stop. No retry follows an unknown free outcome. Defaults retain the original release functions.
- SYCL Gemm is external and frees no buffer in its destructor; SYCL mmq Context destructor is default. Stager destruction after explicit cleanup sees joined/cleared threads and null owned event/pinned handles. After a fresh Impl swap, no stale pointer/owned vector survives. Replacement allocation happens before frees; any exception fail-stops.

`device_freed_bytes` sums successful registry allocation sizes, including token/identity allocations omitted by some historical scratch estimates. `host_freed_bytes` is separate. Before/after free/total queries identify the precise retirement phase; their difference is not claimed to equal allocated bytes because driver accounting can differ. R599's 1,662,831,872 B (~1.55 GiB) remains historical accounting, not a measured free delta or an asserted result of this patch. Borrowing releases only actual separate owned allocations, never the lent arena.
