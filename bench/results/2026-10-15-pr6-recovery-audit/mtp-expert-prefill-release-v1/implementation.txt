Detach and decode graph lifetime
1. Checked device selection, pointer/state/accounting validation.
2. Checked cs_ stream drain. Failure exits immediately with all owners alive.
3. Checked destroy and null each normal round_exec_/step_exec_ and coupled
   round_exec_c_/step_exec_c_. A partial destroy failure exits immediately;
   surviving graph handles and expert owner remain live until process exit.
4. Checked cudaFree(experts_). Only success nulls experts_, subtracts exact
   expert_bytes_ from vram_ and enters Detached. A free failure exits without
   claiming successful detachment or attempting a second free/unwind.
5. Keep window_R_ unchanged, including nullptr in standalone prompt. The owner
   remains Verifier and its normal subsequent bind establishes a valid pointer.
   Keep prefill_exec_/prefill_dev_exec_ (KV-only), dense/KV/workspace/head storage.
6. draft/draft_first/capture_round/capture_step and record_forward(full) reject
   absent/detached experts before any expert graph lookup or first residual copy.
   This applies to normal and coupled decode. No stale expert graph survives.

Source identity, host owner and restore
- Default-off retains the old loader. Opt-in original load hashes exactly the
  owned source slabs actually uploaded, avoiding a second 675 MiB source scan.
  The new helper implements streaming SHA256; source bytes/hash are logged.
- Validate positive expert count, multiplication, size_t/SHA bit length/VRAM
  addition overflow, and exact 64-bit file length g.n_expert * cpu::BLOB.
  Every fread must fill its requested span; EOF/read-error and trailing bytes are
  checked. Restore must match original byte length AND original loaded SHA256.
  Files replaced under the same path or changed during streaming are accepted
  only if the exact assembled bytes still match the original SHA256.
- Open rt_dir_/experts.bin once per operation; RAII owns that FILE handle through
  all reads, hash validation and publication. OS page cache may serve the source;
  the implementation does not retain another full 675 MiB host weight copy.
- Owned pageable slab is at most 64 MiB. Admission reserves slab + 1 MiB overhead
  and preserves 8 GiB physical RAM floor; unknown telemetry rejects. No borrowed
  ExpertSource pointer or mmap view is submitted to H2D.
- Allocate an unpublished owned device buffer. Restore submits H2D on cs_ and
  checks cs_ completion before reusing/freeing every slab. Initial load precedes
  cs_ creation, so its opt-in helper uses checked copy plus device completion.
  Failed enqueue still performs a checked drain before slab/device cleanup.
- A failed drain exits while FILE, slab, pending allocation and all MTP owners
  are still alive. A read/hash/allocation failure after healthy retirement frees
  only the unpublished allocation with checked cudaFree; experts_ remains null,
  Detached remains true and vram_ remains reduced. An ambiguous cleanup exits.
- Publish experts_ and re-add exact expert_bytes_ only after all uploads and the
  final hash pass. Then restore clears Detached. Source RAM state is not read
  from VRAM or copied back: weights are immutable original bytes.
- The target count is 512 * 1,382,400 = 707,788,800 bytes = 675 MiB. This is the
  source allocation size, not a measured driver headroom improvement.

Scope/error/cancel and repetition
- Direct double detach/double restore are errors with no state change.
  Scope open twice is an error; scope close is idempotent once inactive.
- An open scope has an owner only after successful detach. Failed restoration
  retains that owner and Detached state; retry may be attempted by an exclusive
  direct caller. Do not mix direct transitions into an active scope.
- Normal prompt failure/cancel returns through run_layer_major's checked lifetime
  guard and local destruction, then restores experts without overwriting the
  original prompt error. A C++ exception follows the same restore then rethrow.
- A restore failure is fatal in the call wrapper: serve must not swallow it as
  cancellation and proceed to another request/decode. The active scope still
  owns the MTP object when _Exit occurs. An unclosed scope destructor also exits
  rather than silently assuming restoration succeeded.
- Multiple long serve segments may each detach/restore independently. Each run
  recomputes its GPU residual plan after detachment. No entire-request resource
  lease or retry after ambiguous GPU completion is invented.
- MTP destructor adds an opt-in checked cs_ drain before original teardown. The
  feature does not redesign unrelated preexisting load/teardown APIs.

Lazy graph regeneration and timing
- Restored experts can have a different address. All four decoder graph sets
  were nulled, so existing capture_round/capture_step build them on demand using
  the restored experts and current borrowed window_R_. Coupled graphs are lazy
  independently of normal graphs.
- After a detach, finish_expert_capture checks EndCapture/instantiate/source-graph
  destroy/upload/drain. Failed upload drains then destroys/nulls the exec; no
  failed graph is kept for the old `if (exec)` fast path. Ambiguous drain/destroy
  exits with owners live. Default-off uses the original capture function.
- Public cumulative counters ms_expert_detach, ms_expert_restore,
  ms_expert_recapture and log lines allow measurement of retirement, reload
  (open/read/hash/alloc/H2D/completion), and each later normal/coupled round/step
  capture. Recapture logs include kind/coupled/ok/individual and cumulative ms.
  Costs are not hidden in the post-run prompt statistics; wall-clock prompt and
  first decode naturally include them. No speed advantage is claimed.
