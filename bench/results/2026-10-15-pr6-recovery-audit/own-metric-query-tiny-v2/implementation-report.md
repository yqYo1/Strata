## Fail-stop and ownership boundaries

Audit lines have fixed schema, PID, monotonically increasing sequence and call ID, site/API, entry metadata and result numeric/hex/symbolic fields. The result names cover the exact pinned `ze_result_t` enum; unknown codes retain their number and the explicit UNRECOGNIZED name and cannot pass the reader. A missing reached function pointer has an entry plus an `unavailable` record; no synthetic ze_result value is assigned. Each line is written directly once to existing native stderr, at most 4096 bytes, with no retry/buffer flush dependency. A short write, unavailable function, metadata exception or missing closure cannot qualify. Concurrent audit records are serialized, while the provider call retains the original thread/call ordering rather than holding a logger lock across the call. The reader matches in-flight calls explicitly.

Any metric API non-success causes `_Exit(125)` immediately after its exact result is recorded. The only exception is an explicitly logged ZE_RESULT_NOT_READY on the metric completion-event poll, which preserves original polling and requires a later successful event/read/reset for its sample. There is no environment mutation, loader interposition library, exception propagation to the application, recovery/freeing sequence or silent fallback. Error recording itself can block/fail, so the finite external supervisor remains necessary and a partial log holds.

A small process-lifetime tracker marks a query busy before begin, binds actual submissions to kernel instance IDs and clears it only after successful data extraction and reset. Returning a busy query to the free pool, overlapping submission, finalizing with a pending/begun query or destroying a busy query stops before that uncertain owner is returned/freed. On a failed original kernel append, the existing callback reaches PutQuery before releasing its event; its new busy guard stops that path. No metrics error unwinds/destructs device owners. The tracker and audit state are intentionally not destroyed at process teardown; the OS reclaims their small host allocation.

The patch preserves the original successful metric API arguments, pool/query indices, call return values, reset/destruction order, CSV format and typed arithmetic. It adds host logging/validation overhead and can reject valid general configurations outside the selected tiny scope. It does not make ownership guarantees for arbitrary graphs, application failures, implicit multi-device scaling or unexecuted command lists. It does not instrument every core Level Zero event-cache/driver operation, provider internal API, kernel JIT or asynchronous driver action. Existing assertions/warnings and native/fault gates remain active; event-cache status coverage must not be described as all Level Zero API coverage. The original `Finalize` deactivates/destroys its own activation contexts before member query-pool destruction; query pools use original application command-list contexts. This order is retained and must actually return success in Main's run. Opaque handles or source inspection alone cannot establish driver cleanup. Failure, timeout, unexpected map or missing normal closure leaves HOLD even if some CSV rows were already produced.
