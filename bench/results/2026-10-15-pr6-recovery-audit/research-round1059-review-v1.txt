Review findings
---------------
R1058’s main distinction is source-supported and material: the Intel XPU kernel uses 16-token KKT blocks and spills selected raw off-diagonal blocks through the activation-typed A tensor, reloading them as FP32 for merge. With BF16 keys, diagonal A, selected raw scratch, solved off-diagonal A, W/U and v_new have BF16 materialization points. Its carry kernel streams K in 64-wide pieces, keeps local update/correction FP32, saves `h` snapshots in `k.dtype`, casts the gated delta to `k.dtype`, and writes the updated state through the caller’s `initial_state` element type once per 64-token chunk. The separate `track_state` snapshot is asserted FP32; that assertion says nothing about `initial_state`’s dtype.

The common CUDA path in the pinned SGLang `chunk_fwd.py` holds four diagonal and six off-diagonal 16×16 FP32 blocks through the solve and merge, then stores final A in `k.dtype`. Its merge dot precision is selected by `is_tf32_supported`: TF32 when true, IEEE otherwise. That differs from XPU’s explicit IEEE merge and BF16 scratch/reload. These are source-level expression/storage boundaries; they do not prove the emitted device instructions or exact rounding of each Triton dot. R1058 appropriately avoids a B570 speed claim.

**R1058-C1 — source hash label error.** R1058 labels `70abf4fd…` as the XPU `chunk_fwd.py` hash. Eligibility and the inspected file show that hash belongs to Strata `src/kernels/sycl/fused_gdn.cpp`; the XPU source hash is `3ed3455447d142b1a61bd657e93e0fd979c4f2c1de7898f58268eb73b281ea14`. Correct the source attribution in the index. The file itself is still identified by the eligibility manifest, so this citation error does not invalidate the algorithm review.

**R1058-C2 — pool dtype is conditional, not inferred from `track_state` or a model flag.** In the XPU kernel, the persistent store converts to the pointed-to `initial_state` dtype. `track_state.dtype == float32` applies only to the separate checkpoint buffer. Qwen’s model config path passes `mamba2_state_dtype(config)` to its cache parameters; the helper defaults SSM state to FP32 and lets `SGLANG_MAMBA_SSM_DTYPE` override it, and the pool allocator uses that temporal dtype. The pinned author config’s FP32 setting therefore supports the expected default, not a universal run-time proof. Main’s comparison must record the actual pool tensor/argument dtype and effective environment at the call. The existing XPU-registered `test_chunk_gated_delta_rule.py` uses an FP32 pool, but it is a test case, not proof of the configured production pool.

**R1058-C3 — keep the candidate’s numerical label precise.** Main’s v1/v2 manifests describe BF16 tensor scratch, FP32 gates/beta/persistent carry, a full-64 FP32 triangular solve rounded once into BF16 A, current `head % 16` order, and final FP16 output for Strata’s consumer. That is an independent mathematical implementation and an intentional candidate contract. It is not the XPU BC16 scratch contract; it also does not reproduce the CUDA source’s four-block solve schedule. The exact-dyadic orthogonal-key T=1/T=3 smoke is only a smoke, not evidence for general rounding behavior. Compare a BF16 pre-consumer output to SGLang’s BF16 chunk output, then assess the separately required FP16 conversion at Strata’s consumer boundary.

**R1058-C4 — preserve the current input order for this recurrence experiment.** The `s=3*k+j` to `l=16*j+k` mapping and state transpose are valid for the specified converter convention, as R1053 records, but the GGUF metadata does not prove that this artifact came from that converter. Same-input recurrence work does not need that history: keep the candidate’s existing `head % 16` order and compare identical loaded-order operands. Introduce a cross-framework permutation only in the separate tagged layout/loader test.

**R1058-C5 — provenance is per-file; it does not block independent math.** SGLang’s common `chunk_fwd.py`, `wy_fast.py`, `chunk_o.py`, and common `chunk_delta_h.py` carry explicit FLA adaptation/copyright notices. The XPU-specific files in the eligibility pin lack those notices; this is not proof of independent ancestry, and the dispatcher imports shared FLA-derived SGLang helpers. The linked FLA files and root LICENSE currently declare MIT, but those links are mutable and the SGLang eligibility set has no immutable FLA ancestor revision. Do not present current FLA `main` as the exact source ancestor or use SGLang’s Apache root license to erase an FLA-derived notice. No such pin is a prerequisite for Main’s independently authored candidate or for using the pinned SGLang math as a numerical reference. Any future FLA code reuse requires an immutable source/license pin and preservation of applicable notices.

The pinned SGLang Qwen4Exp chunk path is selected by `chunk.py` under `is_intel`; its gating producer allocates FP32 g and beta. The author config and Qwen linear layer support sigmoid output gating and RMS epsilon 1e-6, with norm-before-gate; the exact loaded GGUF config remains unproved. `chunk_o` accumulates in FP32 and stores in v dtype, which is BF16 for the BF16 model path, before the configured norm/gate. Keep these actual callers/configs in the fixture. Do not infer the complete operator contract from the XPU kernels alone.

Existing executable reference criteria
--------------------------------------
The primary test `test/registered/attention/test_chunk_gated_delta_rule.py` registers for XPU, compares chunk output/state to tokenwise `fused_recurrent_gated_delta_rule`, and covers BF16 Q/K/V, FP32 pool, short T=1/7/16/32, production T=64/128/256, long T=512/1024/1536/2048, and varied batch/head/dimensions at ATOL 2e-2, RTOL 1e-2. It omits 48 value heads, FP32 production g/beta, norm/gate, and A/W/U/v_new boundaries. Use as a template, not an automatic adoption threshold; this review ran no test.

After Main resolves v2 compilation and its bounded smoke, the next useful correctness evidence is deterministic non-orthogonal BF16 Q/K/V with FP32 g/beta and nonzero FP32 state at the actual 16-key/48-value/128-state shape, spanning 15/16/17 and 63/64/65 and 127/128/129. Compare the identical current-order inputs through baseline, candidate and the pinned SGLang XPU path; retain output and final-state comparisons, and expose A/W/U/v_new/h snapshots where the path makes them available to localize rounding differences. Record actual `initial_state.dtype`, `ssm_states.dtype`, gate order/epsilon, per-chunk carry and the separate BF16-to-FP16 consumer conversion. Keep 8192-token speed/quality and physical 262144/RESTORE gates pending. Main owns this execution; no new source-research scope is schedulable before it identifies a specific unresolved boundary.
