## Input identity correction and required gate

V1 incorrectly inferred same actual long-generation input from matching workload source/version/run number. `Suite` creates a timestamp-seconds nonce (`tools/strata_bench.py:385`); `warm_up` uses nonce-tagged calibration requests (`:494-504,510-514`). Those calibration token counts determine `tokens_per_word` and `overhead`, which in turn determine the filler word count in each long-generation body (`:439-449`). Different process nonces can therefore change calibration prompts/results and produce different measured long-generation request bodies even when source, workload version and run number match. The long-generation message itself has no direct nonce tag; the calibration dependency still breaks the inference of equality.

Consequently the command above is only a candidate measurement recipe today, not an exact paired-input comparison. Before claiming held-out paired speed, Main must first review/apply/qualify the proposed fixed-workload-ID and request-identity tools, then run a fresh recipe/root that passes their checks. The public `bench-fixed-workload-v1` README describes an optional stable ID and actual request-body journaling, but is explicitly source-only / not tested / not run. The public `bench-request-identity-v2` README says its comparator is also not applied or tested. It requires matching the actual ordered request-body SHA-256 values for all non-agent-feedback requests and rejects missing, extra, reordered, or changed input. For this long-generation-only pilot there are no agent turns, so every measured request body can and must match exactly across arms. Use the future fixed ID identically in both launches, but treat only the comparator's actual journal match as proof; a fixed ID/source pin alone is insufficient. `qualify_bench_input_tools_v1.py` is a proposed future serial host qualification path, not evidence that either proposal has passed. Do not run or apply it here.
