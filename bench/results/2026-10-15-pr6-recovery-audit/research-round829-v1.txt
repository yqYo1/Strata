# R829 — Lossless GPU compression of floating activation and state streams

Purpose: knowledge collection. This distinct scope studies lossless GPU codecs; R828 covers lossy FP8/MX, while index entries R595 and R661 cover CPU predecode and lossy-storage quality. None establishes activation-stream compressibility.

## Falcon: float-specific delta and bit planes

Falcon, arXiv 2511.04140v2 (11 Nov 2025), targets floating-point time series. The evaluation is mainly double precision, with a separate single-precision experiment; FP16/BF16 is not evaluated. The paper text names CC BY-NC-ND 4.0. Its artifact repository has no immutable revision or software license established in this review, so both paper and repository are design references only; no code was copied. [Paper v2](https://arxiv.org/html/2511.04140v2) [Artifact repository](https://github.com/Spatio-Temporal-Lab/Falcon)

For each chunk, Falcon finds maximum decimal place and significand. Within its stated bounds (decimal place ≤22 and transformed significand ≤15), it scales values by a power of ten and converts to integers with a recoverability proof. It delta-codes adjacent integers and ZigZag maps differences. If the bounds are exceeded, it first reinterprets the original float bits as integers, then differences them. It transposes the integers to bit planes, drops shared leading zeros and selects sparse or dense byte storage per plane. The codec therefore relies on nearby values having similar decimal structure and small differences; it does not rely on arbitrary repeated bytes.

A chunk holds 1,025 values so the 1,024 differences align to 64-bit packing: 8,200 source bytes for doubles. Each chunk stores decimal metadata, an absolute first value, bit width, row-mode flags and payload; a chunk-size array supplies offsets. Delta state resets at each boundary, so chunks decode independently, but one value requires decoding its predecessors in that chunk. Random access is effectively chunk-granular. Fixed metadata is at least two bytes plus an eight-byte anchor, one-byte width, flags and payload; exact per-dataset overhead is not tabulated.

The paper describes one compression kernel per batch. A GPU thread builds a chunk in per-thread local storage; a decoupled look-back offset operation lets each thread write directly to final global output, avoiding a large output reservation and merge pass. Input and output GPU buffers are allocated per stream, and a chunk-size array is emitted. Decode reads sizes, computes offsets, decodes chunks and writes reconstructed output. The paper does not quantify thread-local scratch, register use, possible spills, scan workspace or peak live bytes.

On RTX 5080, Core i7-14700KF, 32 GB DDR4, Ubuntu 24.04.2, CUDA 12.9 and driver 575.51.03, Falcon reports mean compressed/raw ratio 0.299, compression 10.82 GB/s and decompression 12.32 GB/s across 12 time-series datasets. These are not activation results. Ratios vary: NYX is 0.484 and taxi-position 0.765; some synthetic data favor ALP's frame-of-reference coding, while trailing-zero-rich taxi-position favors byte codecs. Throughput decreases with larger significands. The headline rate uses original bytes divided by total processing time and the paper describes an overlapped host/device pipeline, but does not separate kernel, PCIe and file-I/O time.

The bit-exact boundary is unresolved. The proof covers stated finite conversion cases and the fallback reads float bits, but the paper excludes special values in its layout discussion. It does not establish preservation of NaN payloads, signaling state, signed zero or every subnormal encoding. Outliers can also widen a whole chunk's bit planes. Tensor use would require explicit FP16/BF16 support and bitwise tests over every representation that may occur.

## GPULZ: multi-byte LZSS blocks

GPULZ is Zhang et al., ICS '23, arXiv 2304.07342v2 (2 May 2023). The paper is CC BY 4.0 on arXiv. Its source repository has a 2023 copyright notice but no software license declaration was identified. The main-branch CUDA file was inspected for pass and allocation behavior but was not pinned to a commit; no code was copied. [Paper v2](https://arxiv.org/html/2304.07342v2) [CUDA source on main](https://github.com/hpdps-group/ICS23-GPULZ/blob/main/gpulz.cu)

GPULZ is LZSS for 1–4-byte symbols. A block searches a bounded backward window for repeats; a flag bit distinguishes literals from matches, which store length and offset. Integer-word literals preserve input bytes exactly. Unlike Falcon, GPULZ does not exploit approximate numeric similarity: random mantissas and changing activation values can leave few matches, so flags and literals may expand output. It needs exact repeated sequences within the window. Larger windows can improve ratio while increasing search work. The paper tests 2,048–16,384-byte blocks, 1–4-byte symbols and 32–255-symbol windows; its default is 2,048 bytes, two-byte symbols and window 128.

Encode uses a global multi-pass pipeline. Kernel I loads a block into CUDA shared memory, finds matches and emits length/offset intermediates and size counts. Kernel II performs two CUB device-wide exclusive scans for compressed-data and flag offsets. Kernel III gathers the intermediates and writes final flag and payload arrays. Fusing match and local-prefix work reduces some shared/global movement, but both scans and final repack remain.

The inspected source allocates full raw input and reconstructed output, temporary and final compressed buffers each sized to padded raw input, temporary and final flag buffers, per-block sizes/offsets and two scan workspaces. It clears these and keeps them live through decode: peak allocation is at least about 4N for N raw bytes, plus flags, padding and scan scratch. This is a property of the open reference, not an LZSS lower bound. Its decoder assigns one GPU thread per block. That thread reads flags/tokens serially, copies literals or expands matches from prior output, and writes the reconstructed block; blocks are parallel but tokens within a block are not. Random access is therefore block-granular.

The source's CUDA events surround Kernel I, both scans and Kernel III, then the decode kernel. Host-to-device copy is before these events; device-to-host copy is after them. The paper defines throughput as original bytes over compression/decompression time, so its GPU rates are not PCIe-inclusive. Tests use A100 40 GB (CUDA 11.4.120) and GTX A4000 16 GB (CUDA 11.7.99). On the Hurricane quantized field, 2,048-byte blocks, four-byte symbols and window 32 give paper compression ratio 3.58 (raw/compressed, or r≈0.28) and compression 29.00 GB/s on A100, 18.07 GB/s on A4000. Mean decompression is 29.1 GB/s and 16.4 GB/s respectively. These are structured scientific/database workloads, not neural activation tensors. Larger blocks use more shared memory and reduce L1; some sizes cannot run within the device shared-memory limit. [Study and results](https://arxiv.org/html/2304.07342v2)

## Break-even for a 6 GB/s link

Let N be raw bytes and r the effective compressed/raw ratio, including headers, offsets, alignment and padding. A raw one-way transfer takes Traw = N/6. If encode, transfer and decode are serial, Tcodec ≈ N/Re + rN/6 + N/Rd + Tfixed. Ignoring fixed overhead, compression pays only if r < 1 − 6/Re − 6/Rd.

Using Falcon's RTX 5080 dataset means only as illustrative inputs gives r < 1 − 6/10.82 − 6/12.32 = −0.042. No nonnegative payload ratio can break even on this serial path; the codec work alone exceeds raw-link time. The rates come from different data and are not a per-kernel forecast.

With full steady-state overlap across enough independent chunks, T/N approaches max(1/Re, r/6, 1/Rd), plus finite-batch start/drain. If both codec stages actually sustain above 6 GB/s and r<1, the link can remain the bottleneck and compression can win. This requires enough buffers/events and no consumer dependency that forces a decode before transfer or computation finishes. Metadata and staging count against r and scratch.

For capacity, the long-lived saving is (1-r)N only after raw storage is freed. During encode, raw, compressed output and scratch can coexist; during decode, compressed input and restored output coexist. If that transient peak does not fit, output is near N, the full value is immediately required, or each operator causes decode/re-encode, capacity and time gains may disappear.

## SYCL and BMG boundary

Transferable ideas are bounded independent chunks, per-chunk metadata, coalesced final writes, adaptive plane storage and overlapping independent batches. SYCL 2020 has work-groups, local accessors and group synchronization; Intel documents the shared-local-memory model. GPULZ shared arrays are a design analogy for SYCL local memory. CUB scans need a SYCL scan or another offset scheme. Falcon's CUDA decoupled look-back needs a separate portability and memory-order review; a hierarchical scan may add a global pass. These are hypotheses to measure on BMG, not claims of support or speed. [SYCL 2020 rev. 12](https://registry.khronos.org/SYCL/specs/sycl-2020/html/sycl-2020.html) [Intel SLM guide](https://www.intel.com/content/www/us/en/docs/oneapi/optimization-guide-gpu/2024-0/shared-local-memory.html)

NVIDIA nvCOMP 6.0.0 exposes proprietary Bitcomp through CUDA-oriented APIs. The API supports lossless FP16/FP32/FP64-as-integer input, queries temporary GPU storage, and caps compressor chunks at 16 MiB; its documentation recommends smaller chunks such as 64 KiB for decompression throughput. It is a constraint reference, not a BMG option: no Bitcomp source or nvCOMP implementation is available for an Intel BMG SYCL queue. A BMG codec would need independent SYCL implementation and measurements. [nvCOMP 6.0.0 release notes](https://docs.nvidia.com/cuda/nvcomp/release_notes.html) [nvCOMP C API](https://docs.nvidia.com/cuda/nvcomp/c_api.html)

## Evidence limits

Neither study tests Strata, model activations/state, FP16/BF16, Intel BMG or a 6 GB/s link. Falcon is sensitive to data correlation and has an unresolved full IEEE bit-preservation boundary. GPULZ is byte-exact in its integer path but can expand incompressible blocks and has high reference scratch allocation. Timing boundaries also differ. A local decision needs representative activation bytes, bitwise round-trip tests, peak allocation, chunk decode latency and an end-to-end path including transfers and dependent consumers. This report describes mechanisms; it does not qualify either implementation or predict compressibility.
