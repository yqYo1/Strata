# GPU 内スコア配置改善のエンジン統合

対象は `STRATA_SYCL_PREFILL_QSA_MATH` の明示的な長大入力経路。既定・短入力・decode の選択は変えない。既存 BF16 prefix 経路を同じバイナリに保持し、32/33 の score 行幅だけをテンプレート引数にする。独立した確率分散・行幅変更・組合せの測定がすべて閉じてから候補を選ぶ。個別改善率は加算しない。

Q/K/V/P/出力の BF16、Q の事前スケーリング、FP32 QK/PV 累積・max/normalizer、32要素の逐次加算順を維持する。全体出力が llama.cpp と一致することは採用条件ではない。独立診断・境界検証と同系モデルの SGLang/vLLM 契約を基準にする。

既存コメントの「No production caller」は以前の統合で古くなっている。実際の呼び出しは `src/prefill/prefill.cpp:2602`、既存39K cohort はこの経路の実測。レビュー原本は保存し別紙で訂正した。

行列拡張の base pointer は4-byte整列が必要。BF16 local_accessor の要素型だけから4-byte整列を推測せず、`alignas(4)` の構造体内の実配列を local_accessor で割り当てる。配列外へのポインタ演算や uint32_t からの型別名参照は用いない。基準/候補の両方に同じ整列保証を適用し、各経路を実際のビルド製品で検証する。

順序は小さなURトレース→11構造/数値ケース（物理262144を含む）→all48モデルの合成129 token 診断→公式bench.shによる実32K超入力の診断と各3独立測定。これは full-model 256K、保存/RESTORE、一般品質の完了を意味しない。速度改善後に64K入力・GPU残差配置を別々に検討する。
