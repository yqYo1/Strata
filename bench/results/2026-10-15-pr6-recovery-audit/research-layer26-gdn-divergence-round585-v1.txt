## Conclusion

Layer 26 is GDN under `is_qsa_layer` (`layer % qsa_interval == qsa_interval - 1`; QSA layers are 3, 7, … for interval 4). R585’s exact selected-row comparison moves the first observed cross-arm difference from final logits into layer 26’s stored residual: layers 0–25 match at all 19 selected rows; layer 26 differs at rows 24575, 24576, 32767, 32768, 34600 and 34601, with first byte differing at row 24575 and max absolute difference 1.6435981e-5 (layer-26 selected-scope maximum 1.8215738e-5). Later layers amplify the same six selected-row differences. This is a useful localization to the layer-26 boundary, not proof that GDN is the cause: the audit samples 19 rows, not every row that can affect the recurrent GDN state, and does not expose each GDN phase.

I found no concrete uninitialized local read, shared-memory race, state-span overrun, queue-order defect, or alias/lifetime violation in the inspected portable SYCL GDN prefill path. The local reductions and shared tiles have explicit barriers and all consumed entries are written in the active geometry. The review therefore does not reclassify the automatic-24576 FAIL or claim a GDN fix. The paired diagnostic itself adds synchronization/copies and may suppress a timing-sensitive race; Main’s recorded caveat remains material. The auto diagnostic logits also differ from the old non-diagnostic auto FAIL, so those captures must not replace or relax that original gate.

## GDN route, shapes, and ownership

`src/prefill/prefill.cpp` runs layer operations in the order: hyper-connection residual work; BF16/FP16 projections; GDN projections `attn_qkv.weight`→`m.qkv`, `attn_gate.weight`→`m.z`, alpha/beta projections→`m.ab`; then `gdn_gates`, `gdn_conv`, `gdn_recurrence`, and `ssm_out.weight` projection from `m.y_h` to `m.bo`. `gdn_recurrence` calls the portable fused recurrence in `src/kernels/sycl/fused_gdn.cpp`; it does not select the separate native decode GDN route. For the model geometry, C=10,240, ZV=6,144, state S=128, h_k=16, h_v=48, conv taps=4. `m.hbuf` stores `[T,C]` FP32 projected/conv data; `m.gate` and `m.beta` each `[T,48]` FP32; `m.z` and `m.y` are `[T,6144]` FP32; `m.y_h` is `[T,6144]` 16-bit output consumed by `ssm_out`.

The persistent per-GDN-layer session state is contiguous `[S,h_v,S]` FP32 recurrence state followed by `[C,d_conv-1]` FP32 convolution history. At this geometry that is 786,432 recurrence floats (3,145,728 B) plus 30,720 history floats (122,880 B), 3,268,608 B per GDN layer. Session creation allocates it; `session_zero` clears all owned GDN state before a fresh sequence. The prefill layer ordinal `gdn_index - ss.gdn_ord0` indexes the owned GDN slice; the convolution pointer begins immediately after recurrence storage. This allocation is persistent across chunks, intentionally.

The transient GDN scratch is carved from a shared per-chunk `m.region`. `gdn_set_bytes(T)` and the matching `Alloc a.take` sequence agree: qkv, z, ab, gate, beta, hbuf, y, y_h. QSA and MoE use separately carved views over that same region, whose capacity is the maximum of the three exact byte calculations. The GDN phase runs before that layer’s MoE phase on the same in-order compute queue; the later MoE view does not overlap a live GDN operation. `m.bo` is separately allocated outside the shared region. Current code/source inspection found no GDN-to-QSA/MoE alias overlap at valid geometry. This is source reasoning, not a run-time allocator proof for the historic failed binary.

## Barriers, reductions, state updates, and concrete doubts checked

* The batched convolution builds each row from the old three-row history for the first three token positions and from prior rows of `x` thereafter. Every lane writes a unique output channel. The first tap uses a normal multiply, later taps use `sycl::fma`; this is a fixed but not necessarily bit-identical arithmetic sequence to a distinct kernel. The `part[4]` local array is written once by each subgroup leader before the barrier and each Q-head group reads all four values. `gdn_conv` waits for convolution completion, then queues a separate history update on the same queue. History inputs are captured before writes, and the update advances by T rows, including the `T<3` case.
* In recurrence, one workgroup owns one value head; four 128-lane tiles partition its 512 work-items. The first 128 work-items fill all 128 `sk` and `sq` entries before a local barrier. Every one of 512 work-items fills its `red[tid]` entry before consumers read the four 128-wide segments. For normalization, the four subgroups in `rg==0` reduce the 128 output columns and write `part[0..3]`; the barrier precedes reads. `part[4..15]` are also written by the other recurrence groups but are not consumed. Thus the local `part(16)` array has no uninitialized consumed value in this geometry. The per-head workgroup writes a disjoint `[state row, head, column]` region; no atomics are used.
* Each token’s state update loops recurrence rows in fixed order, then the kernel loops tokens in increasing order. Query/key pairing is `head % hk`; projected K/Q tiles are shared read-only within the workgroup. The state is updated in place once per head/column, and the final `state[base+r*rs]` write is one owner per element. `gdn_recurrence` passes `keep=nullptr`, so the ordinary prefill path processes all T rows and commits final state.
* Geometry checks constrain S/head counts and checked products; the prefill wrapper validates `T>0` and `T<=INT32_MAX`. The convolution wrapper additionally bounds T against `INT32_MAX/(C/128)`. Kernel indexing uses `size_t` for token-stride products. No negative or unbounded indexing path was found for the stated real geometry.
* The portable recurrence’s local operations and queue dependencies are structurally ordered. It calls `finish(stream,event)`; the convolution call also finishes before the separate history update. This means the normal path already contains waits at phase boundaries. It does not prove absence of compiler/device arithmetic differences or an error elsewhere in projection/GEMM and upstream row values. The R585 diagnostic’s additional device-to-host raw auditing may add a further serialization point, so its observed agreement does not eliminate races.

Numerical/order sensitivity remains possible without UB: GDN state is recurrent across all rows and chunks; its projections use the existing GEMM path; exponentials, reductions, FMA choices, and the state’s input history can magnify a small earlier difference. The current receipts do not show that any GEMM variant changed, that unsampled `m.mixed_h` rows match, or that GDN is the first operation to differ. In particular, layer-26 stored-residual equality for 19 rows through layer 25 is not evidence that the entire 24,575-row prefix feeding the layer-26 recurrence was equal.

## Minimum next phase capture (at most three checkpoints)

Use the existing diagnostic binary/configuration and the six selected rows only for this narrow follow-up, retaining the original FAIL receipt untouched. Bind each capture to `(arm, layer=26, global row, chunk start/T, dtype, tensor name, byte count, SHA-256)`; compare raw bytes, not rounded summaries. The paired audit already adds D2H/copy synchronization, so write down the resulting serialization explicitly and do not treat a PASS as race-free proof.

1. **GDN projection input:** `m.mixed_h` at layer-26 entry, six rows × 2,560 × 2 B = **30,720 B per arm**. This checks whether the selected incoming activation already differs before GDN projections. It does not check unsampled recurrent history.
2. **Recurrence inputs:** capture `m.qkv` (six × 10,240 × 4 B = 245,760 B), `m.z` (six × 6,144 × 4 B = 147,456 B), `m.gate` and `m.beta` (each six × 48 × 4 B = 1,152 B), and `m.hbuf` (six × 10,240 × 4 B = 245,760 B): **641,280 B per arm**. This isolates projection/gate/convolution outputs before recurrence; one bounded device-to-host checkpoint after each producer phase can serialize those buffers and may mask asynchronous faults.
3. **Recurrence output plus carried state:** capture selected-row `m.y_h` (six × 6,144 × 2 B = **73,728 B per arm**) and the layer-26 recurrence+conv state at matched chunk boundary before/after the relevant recurrence (**3,268,608 B per snapshot per arm**). Exact state serialization costs 6,537,216 B per arm for before+after snapshots and requires extra boundary waits; capturing state immediately after row 24576 would require a bounded in-kernel state checkpoint because it is inside a multi-row chunk. Prefer before/after at actual chunk boundaries first. If state bytes differ before recurrence, the cause precedes the recurrence; if inputs match but post-state/output differ, narrow within recurrence/serialization next. Do not dump every layer or all token rows.

These three checkpoints are sufficient to distinguish selected-row upstream input/projection/conv differences from a recurrence-output/state difference, while keeping the capture bounded. If Main needs to prove equality of all rows feeding the recurrent state, this six-row scope is insufficient; a separate narrowly bounded per-chunk fingerprint over every GDN input row is required and its hash/copy cost must be reported. No extra checkpoint or full trace is recommended until these receipts are reviewed.
