# R1048 — Qwen4Exp GDN head/data boundary

Classification: **decision support**, source-only; not implementation adoption. Read pinned eligibility v1 and shared research-index. No benchmark/runtime inference, execution, tests, Git/process activity, or product edits. Main's serial-four-request benchmark and subgroup-softmax comparison remain untouched.

## Finding

Before a chunk64 port, treat the head-order difference as an unresolved checkpoint/layout boundary. The selected source-defined SGLang Qwen4Exp → Qwen3_5 → Triton-prefill path has 16 K/Q heads, 48 V heads, and maps V head `s` to K/Q head `floor(s/3)`. Strata's current kernel reads K/Q head `l % 16`. Both are internally coherent if the 48 V channels (and their related tensors) use different permutations. The supplied source establishes the two formulas and downstream split layouts, but does **not** establish how the external GGUF-producing conversion arranged this checkpoint's projection rows. Therefore these expressions alone do not prove a Strata bug.

For a future isolated boundary, use explicit index adapters rather than silently changing the recurrence: for local V slot `l`, the SGLang slot with the same key is `s = 3*(l % 16) + floor(l/16)`; inversely, `l = 16*(s % 3) + floor(s/3)`. Example: local slots 0,16,32 (all key 0) map to SGLang slots 0,1,2; local slots 1,17,33 map to 3,4,5. K/Q stay identity. If keeping local channel order, a SGLang-form recurrence must gather V/Z/beta/gate and head-indexed recurrent state through `s→l`, then scatter output and final state back; convolution history and its per-channel weights, gate parameters (`A_log`, `dt_bias`/equivalent), and output-projection input columns must follow the same V-slot permutation if the *weights/checkpoint* are being transformed. Do not permute only V or only state.

## Source reconciliation

- SGLang `Qwen4ExpLinearDecoderLayer` inherits `Qwen3_5LinearDecoderLayer`; its forward calls `linear_attn` between the HC read and finish. At TP1, Qwen3_5 sets `key_dim=16*128`, `value_dim=48*128`; `in_proj_qkvz` is `[all Q | all K | all V | all Z]`, `in_proj_ba` is `[all B | all A]`. `fix_query_key_value_ordering` directly splits those contiguous regions and reshapes V/Z into heads. Its fused split helper likewise copies V/Z and B/A in increasing head order, grouping three adjacent V slots under each K head; the prefill projection-view helper is a strided view of the same regions. No model-level head permutation is visible in these paths. `TritonGDNKernel.extend` calls chunk GDN with `head_first=False`, `use_qk_l2norm_in_kernel=True`; chunk size is 64. This identifies a source algorithm, not runtime selection.
- In SGLang FLA `chunk_delta_h`, K offset is `(i_h // (H // Hg))`, i.e. `floor(s/3)`. `chunk_gated_delta_rule` calls Q/K L2 norm, chunk-local cumulative log-gate, intra-chunk WY (`A,w,u`), recurrent chunk carry/update, then chunk output. The 64-token final partial chunk is boundary-masked; state carries across chunks and is written in place when requested. Triton initializes live state tiles/update accumulators as FP32, then stores using pool dtype. Select FP32 incoming/outgoing `[48,128,128]` state and FP32 conv history at this candidate boundary. SGLang also supports other state dtype/backend combinations; this report does not claim Strata or a target ran this path.
- The local projection is `qkv` stride 10,240 = Q 2,048 + K 2,048 + V 6,144 (16/16/48 × 128), with Z in a separate 6,144-wide tensor; B/A are 48 each. Local recurrence reads `head%16`, direct V slot `head`, and stores per-slot state. Local `strata_pack.py` copies each dense tensor's GGUF raw bytes into the packed dense file with the source name/metadata; its visible custom relayout is the separate Q2_0 expert gate/up arena, not GDN. `pack_layer.py` only interleaves expert gate/up rows. Thus these local packing steps do not show a GDN head permutation. The external GGUF conversion revision/recipe and whether it permuted V/Z/B/A/conv/norm/output rows together are absent; tensor shape/name and byte-copy behavior cannot answer that.
- vLLM Qwen3Next corroborates grouped QKVZ splitting: it reshapes by K head, splits `V_PER_K=3` slices per group, then flattens V/Z and B/A to 48 slots. Its selected FLA helper also uses `i_h//(H//Hg)`. This is corroboration only; SGLang is the accepted contract. Use eligibility's corrected vLLM revision `b31e9326a7d9394aab8c767f8ebe225c65594b60` (R929's old prefix is invalid).

## Precision and operation boundary for a candidate

Use SGLang's BF16-model path as the prospective hidden-tensor contract: Q/K/V/Z and A/B projection tensors retain model BF16 storage; Q/K L2 normalization occurs before recurrence and returns the input dtype; the gate helper computes `g = -exp(A_log.float()) * softplus(a.float()+dt_bias.float())` and `beta=sigmoid(b.float())`, with FP32 outputs. Chunk-local gate cumsum, WY `A`/triangular solve and state/update use FP32 local arithmetic where declared, while `A,w,u` intermediates store in input dtype. The recurrent kernel rounds its computed `b_v` to K's dtype before its K·V state update; state tiles accumulate in FP32 and round only at the persistent state store (FP32 under this selected boundary). `chunk_gated_delta_rule` returns output cast to Q dtype; caller applies gated RMSNorm to the recurrence output using Z (`norm_before_gate=True`) and then output projection. Keep the Qwen3.5 normalization epsilon/weights and this ordering. This is a mixed storage/accumulation contract, not “all FP32” and not “cast saved residuals only.”

Local `gdn_gates` writes FP32 softplus×loaded-`ssm_a` and sigmoid(beta); equivalence requires `ssm_a == -exp(A_log)` and matching B/A order, which loader/checkpoint provenance does not prove. Local convolution/recurrence use FP32 buffers/state and emit a low-precision output copy. For hidden-state reduction, keep persistent state/history FP32 and first try BF16 projection/conv/Q/K/V/Z and chunk-intermediate storage to match SGLang. FP16 is a separate candidate: same byte width, different exponent range, mantissa and rounding. Do not force local-FP32 bit parity by changing these boundaries.

Chunking requirements: process each sequence in increasing chunks of 64, carry exact FP32 state from one chunk to the next, preserve log-gate/cumulative-decay convention, mask the final partial chunk, and never treat independent input chunks as zero-state. Preserve causal-convolution history advance exactly once in token order across the same chunk/tail. Outer callbacks must publish state/history before continuation. Physical 262,144-context, bounds/lifetime/fault and restore remain separate gates.

## Minimal discriminating validation recipe (future isolated fixture; not run here)

1. Before comparing arithmetic, use per-head tagged Q/K/V/Z/A/B, conv weights/history, and nonzero FP32 recurrent state. Assert the two index formulas and a bijective gather/scatter on all 48 slots. Compare the projection and post-convolution tensors under identity and the stated permutation. A head-specific mismatch that disappears after a consistent all-related-tensor permutation indicates layout; a one-tensor permutation should fail this control.
2. Feed identical captured BF16 Q/K/V/Z and FP32 gate/beta plus the same FP32 state/history to (a) the current local serial path and (b) source-contract chunk64/WY reference. Compare per-head output, outgoing state after each chunk, and outgoing conv history; record max/relative errors and nonfinite/bounds results. A mapping error produces structured head/channel disagreement; acceptable WY reassociation should be assessed with predeclared error/drift bounds against this same validated SGLang contract, not rejected solely for differing from serial FP32 bits. Include T=1, 63, 64, 65, multi-chunk and final-tail cases, then a long sequence with nonzero carried state. Do not infer model quality or target-runtime performance from this component oracle.
