## Capture and oracle independence

The proposal's WeightTable hook copies each converted `host_src` span into `EngineSnapshot::bytes` immediately before its H2D submission, then waits for completion and records row metadata/fingerprints. This is a copy of the actual host bytes submitted by startup loading; it does not derive its expected payload from a later device read. The fixture also separately D2H-reads each startup `WeightRef` and compares it with the capture. For source conversion, `source_reference` reopens the pack's `dense.bin`/`embd.bin`/`experts.bin`/`extra.bin`, reads the declared source span, independently performs the packed-plane scale conversion or F16/BF16 promotion, and compares those bytes with the capture. Thus payload expected bytes are independently rematerialized from pack contents; the capture is not simply treated as the conversion oracle.

That is not an independent end-to-end GGUF/pack oracle. `source_reference` takes `file_id`, `src_off`, `src_bytes`, `kind`, `elements`, quantized plane sizes and conversion flags from `row.original`, which is the `WeightRef` emitted by the same WeightTable load being checked. No second GGUF/index parser validates the tensor identity, source offsets, dimensions, kinds or plane descriptors. A bad loader descriptor can therefore direct both the loader conversion and reference conversion to the same wrong bytes or conversion rule and pass. Describe this as independent payload reread/conversion using loader-supplied descriptors, not independent validation of GGUF metadata. Metadata equality after bank activation/restoration likewise checks preservation against the captured original metadata, not correctness against a separate metadata source.

## What the fixtures establish, and gaps

`component_fixture.cpp` exercises real `WeightTable`, `NativeDense`, and `CanonicalDenseBank` objects when Main compiles/runs it. It rejects zero capture budget, mismatched/interior arena owner, altered capture bytes, and an injected native pointer overlap; then checks device startup payloads, adopts the exact root owner, checks the pinned target census (arena 1,538,035,200 B; bank 32,284,672 B; persistent pool 82,821,120 B), traverses 48 layer activations, verifies active/inactive row visibility and metadata, checks active row payloads (persistent payload once), restores native and canonical owners, compares every restored canonical row's bytes/metadata, and requires Full state with a non-null owner. This is meaningful component lifecycle coverage, but it is not a complete model inventory oracle or a Prefill/Verifier/model pass.

HC coverage checks persistent classification of rows through the traversal and lookahead norm presence; the host fixture explicitly checks the 96 HC norm names. PLE coverage is weaker: component coverage asserts selected `PleWeights` fields are non-null at layer 1, and the host fixture classifies selected PLE names as persistent. It does not prove every PLE field points to the intended canonical row or that each PLE pointer's bytes match its corresponding captured row. The loop's payload checks cover canonical rows exposed by the bank view, but pointer binding itself is not audited field-by-field. Recommend explicit PLE name-to-pointer/size/content assertions before treating PLE ownership as proven.

Fault injection is deliberately narrow. The fixture macro intercepts only inline `CanonicalDenseBank` `cudaMalloc` calls; WeightTable and NativeDense allocations stay real. The recipe names separate prepare/restore allocation-status arms and requires Main to inspect exact fail-stop operation and owner preservation. The fixture directly asserts ordinary `false` plus unchanged owner/state only for confirmed OOM-null. Uncertain/contradictory arms are expected to abort; the fixture does not itself assert the emitted operation text or prove every abort retained all owner publications. It does not inject cancellation, native reservation failure after canonical reservation, staging allocation/free, H2D submission/completion, drain, graph retirement/recapture, or general cleanup uncertainty. The recipe acknowledges these Main-owned gaps; they remain required qualification, not passed tests.

Host-only policy checks cover allocation result/pointer classification, HC naming, PLE persistence classification, stride arithmetic and malformed layer names. They do not exercise allocation or lifecycle. Neither fixture proves default-OFF wiring in the actual configured generator, native-only behavior, cancellation behavior, request/reader exclusion, full API integration, physical 262144-context correctness, or successful-quality behavior. Those are correctly left to the serial Main recipe and must not be inferred from fixture source. No fixture has yet produced runtime evidence.

## Gate conclusion

The source provides a useful actual-loader/component fixture design and a byte oracle that is independent for pack payload bytes, with a correlated descriptor path. It does not yet meet the stronger contract “independent GGUF/pack conversion” without a separate metadata/index oracle. Add field-level PLE binding checks and independently validate the loader descriptors. Run the named host/component/fault arms only under Main's ownership, including the unresolved reservation/cancel/staging/upload/graph cases. Until those checks are executed and pass, label this source review as design evidence only; no inference adoption, restoration correctness, or safety result follows from it.
