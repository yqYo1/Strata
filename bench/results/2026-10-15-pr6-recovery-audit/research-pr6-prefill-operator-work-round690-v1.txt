## Operator work that is common

The shape constants in the historical and current prefill sources agree: `N=2560`, `HC=4`, `D=10240`, routed `K=10`, and `NE=512`. Both routes execute 48 layers, of which 12 are QSA and 36 GDN, with one router/shared-expert step and the same top-10 routed expert dimensions: GU is `1280 × 2560` (two 640-wide halves), SwiGLU produces width 640, and Down is `2560 × 640`. The selected current compact-MoE route is forced by `MMQ=0` and compact-FP16=1; it gathers each expert's rows to FP16 scratch, runs GU, interleaved SwiGLU, then Down. Historical `COMPACT=2` also takes the compact FP16 expert path. Both schedule those routed expert products per chunk; neither implements expert-major one-time dequantization/GEMM across the whole prompt. Current source confirms this at `src/prefill/prefill.cpp` around lines 2960–2977; historical source at the named commit around 3760–3790.

The native pack is identified in the PR report as IQ3_S and current receipt as the same named pack/model family. Both source paths use the per-layer native format metadata for GU/Down dequantization (`iq_dequant_gu_f16`, `iq_dequant_f16`) before FP16 products. The retained PR run receipts do **not** list per-layer GU and Down type codes or dimensions from the loaded native-format table; dimensions above come from source/model geometry, while exact per-layer quant-type equality across measured and current binaries cannot be independently checked from these receipts. Do not fill in type codes by assuming every expert matrix is a single IQ3_S code.

For the compact expert GEMMs, historical `sycl/src/prefill/gemm.dp.cpp` calls DPCT BLAS with half inputs and `dpct::compute_type::f32`; current `src/prefill/sycl/gemm.cpp` calls oneMKL row-major GEMM with `sycl::half` inputs and FP32 output. This establishes half-input/FP32-result arithmetic in both source routes and an apparent FP32 accumulation contract in the historical call. It does not establish identical oneMKL algorithm, rounding or instruction schedule. Router projection is BF16 input to FP32 output in both paths; the shared PLE/GDN/QSA projections also retain the existing native/BF16 projection dispatch rather than being changed to all-FP16 by compact scratch.

## Concrete arithmetic and dispatch deltas

1. **GDN recurrence kernel.** The PR benchmark environment explicitly enabled `STRATA_GDN_KEYHEAD_TUNED=1`. At `f263d87:sycl/src/prefill/kernels.dp.cpp`, this selects `gdn_recurrence_keyhead_variant` when `T>=256` and pipeline is enabled; with PR chunks of 8192, this applies to all 36 GDN layers for each of four chunks. That kernel has a distinct key-head work mapping (subgroup 16, 256 GRFs) and its source comment claims same-bit arithmetic relative to its preceding key-head kernel. The current configured root calls the current `gdn_recurrence` implementation through `src/kernels/sycl/fused_gdn.cpp`; there is no current `STRATA_GDN_KEYHEAD_TUNED` equivalent on that selected route. This is a real per-GDN-chunk kernel/work-mapping delta. It could contribute materially, but these receipts have no per-GDN component timings and provide no causal share of the >2× historical-to-current rate difference.

2. **QSA top-k selector.** PR #6 set `STRATA_PREFILL_TOPK_TUNED=1`, invoking `qsa_block_topk_prompt_variant` with fallback to `qsa_block_topk`. Current unset means the standard `qsa_block_topk` path. This is a concrete optional fast-path omission for the 12 QSA layers. The variant is intended as a selector implementation; the source and receipts do not say how often its fallback ran in PR, and no current top-k profile isolates its wall contribution. It changes selection kernel scheduling, not the requested top-k count.

3. **QSA attention fallback layout/batch.** PR set attention batch 128 and layout 4. Current batch default is 32 and layout unset (0). Both implementations first attempt the prompt matrix attention path and use the variant/fallback batch path only if that attempt declines; therefore receipts do not prove layout 4 actually ran in PR, or that current batch 32 is the executed attention path. If fallback ran, the batch and fallback layout differ. Since the PR's environment records layout 4 while current root's `prefill_fallback_attn_layout()` only accepts layout 1, layout 4 cannot be ported by merely replaying the old environment. Need dispatch evidence before treating this as a measured cause.

4. **KV work, selection width and residency.** The historical receipt is K8/V8 (INT8 K/V) with all KV resident and mode 0. Current invocation is INT8 with a 32,768-cell resident prefix and 262,144 context; for positions beyond that prefix it uses mode-1 staged KV. That adds per-QSA-chunk host/stage history movement and stage-pool reads/writes absent in historical mode 0. This is a concrete work difference across the later prompt positions, despite both formats using one-byte K/V payloads. QSA selection width itself is not eight times larger: source sets `idx_top_k=2048`, `idx_block=4`, so selected width is `min(n_kv, 2051)` for both. For almost all positions in either long prompt, it is capped at 2051; the longer context adds indexer/KV history work and storage range, not a 262K-wide selected attention set. This corrects a possible but unsupported claim that full context directly multiplies selected cells by 4×.

5. **Attention/GDN storage precision.** The receipts identify FP32 residual rows and both paths compute shared layer residuals in FP32. Compact scratch only changes buffer reuse and gathered expert activation storage; it does not mean whole-model activations or recurrence state were stored in FP16. Current remains FP32 residual storage. K/V is 1-byte INT8 in current, while PR calls its format K8/V8; both are 1-byte storage, though exact quantization/layout equivalence between historical K8/V8 and current `int8` should not be inferred solely from labels. No retained receipt reports per-layer expert quant type, QSA indexer type, QSA selected-ID trace, or executed QSA attention fallback, so precision equality there is unavailable evidence.

## Work and denominator implications

At the same 32K token count, the common model still performs 48 × 4 = 192 layer/chunk traversals, with 12 QSA and 36 GDN operator invocations per chunk. Historical T=8192 has four chunk passes; current T=8192 also uses four chunks for a 32K request. Thus no arithmetic-work reduction from “layer-major” itself explains the rate change: the outer order is shared and full-layer model math remains. The known R668 differences (context and mode-1 KV; residual rows) remain real, and this audit adds kernel dispatch deltas (especially GDN key-head tuning and tuned QSA top-k). There is no retained per-operator timeline paired with the PR result and current clean result, nor a matched current 32K/no-MTP/mode-0 run. It is not possible to attribute a >2× gap to one operator or to quantify whether those kernel deltas explain it.

Timing scope also differs. Historical receipts are standalone CLI `cli_wall_ms` for the 32,768-token prompt (50,736.4 ms at 645.85 tok/s), with no MTP model, phase markers, transfer timers or PLE preload. Current clean samples report server `prompt_ms` (333,447 and 327,554 ms for actual 78,453 prompts), and the cohort launch uses MTP4 and staged INT8 KV. Server prompt timing includes the request's prompt callback path; it is not the historical standalone CLI timer. Neither timer is an inner-kernel sum. The first current log sample at 3.2 tok/s is present in the receipt but is a warmup/initial request, not one of the 78,453-token clean samples. Comparing those raw tok/s figures as an isolated operator regression would mix work and denominator.

## Missing producer evidence for a decisive arithmetic comparison

- A manifest binding historical executable hash `eae0...` to the exact compiler, resolver-selected source hashes, compile flags and all static libraries. The named PR commit is the nearest retained source provenance, not verified binary provenance.
- Per-layer native GU/Down type IDs, dimension/stride descriptors and dequant implementation versions from both measured binaries.
- QSA dispatch counters or an event trace showing whether prompt matrix attention succeeded or fallback layout 4/0 executed; current actual per-query width/selected IDs; and proof of same selected cells across the changed selector.
- Per-operator phase durations from comparable uninstrumented runs, particularly GDN recurrence, QSA selection/attention and mode-1 KV staging.
- A matched current-root producer with the PR arithmetic/dispatch settings where supported, identical model/input, 32K actual input, same context/KV mode/residency, MTP off, and a documented common timer. This is necessary to separate operator implementation from context/KV and server callback work.
