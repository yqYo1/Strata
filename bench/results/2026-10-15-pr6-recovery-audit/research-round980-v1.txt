# Current row-major subgroup QSA source audit

Classification: decision support. Scope: source and numerical-contract audit only. No Git commands, builds, tests, profiler/process inspection, GPU work, runtime/config changes, or product edits were performed. The only created file is this report.

## Result

I found no definite source-level defect in the generated normalization block for the pinned current score33 row-major QSA implementation. The generated block keeps the current Q/K/V/P representation and online state, has converged per-subgroup collectives, maps all 16 heads and 32 cells without overlapping writes, and retains the work-group barriers needed before scores are consumed and before probabilities are reused by PV. It changes FP32 probability-sum association; this is the one intended numerical change, and it fits the already accepted SGLang QSA contract. This is not a compile, runtime, lifetime, fault, performance, model-quality, or full-context qualification.

## Source-level findings

### Exact candidate versus baseline

`build_qsa_rowmajor_subgroup_v1.py` locates only the existing serial normalization block (lines 37–38), replaces it with `norm` (39–68), renames the private implementation template and exports a private candidate entry (69–79). It selects `rowmajor_subgroup_impl<Cells + 1>` and explicitly excludes the packed-template instantiation. Thus the candidate is the current optimized `ScoreStride = Cells + 1 = 33`, `TilePacked = false` row-major implementation, not the earlier packed proposal. The current optimized wrapper is `prefix_batch_impl<Cells + 1>` at source lines 308–314.

The code outside that block is retained from the pinned source: score production is still the row-major QK path (`kv + d * Cells + cell`, QK apply to `scores[(head+r)*ScoreStride+cell+c]`, source lines 214–230); PV still reads row-major P at `probability + head * Cells + c` and V in row-major layout (275–279). There is no operand repack, additional scratch, new local allocation, host calculation, queue operation, or changed matrix call in the generated diff described by the generator. The baseline serial path at 233–253 accumulates 32 FP32 probabilities in cell order, stores each as BF16, then updates the existing FP32 normalizer with `fma`; the candidate preserves BF16 P storage and the same normalizer update.

### Collective convergence, mapping, and addresses

The candidate iterates `h = subgroup` then `h += 8` until 16. With the existing `[[sycl::reqd_sub_group_size(16)]]` kernel and local size 128 (source lines 145–155), the work-group has eight SIMD16 subgroups; `subgroup` is uniform within its subgroup, so each subgroup takes two iterations and every lane takes the same branches and calls the same collectives in the same order. `valid0/valid1` vary by lane only as reduction inputs, not as control flow. Each iteration calls `reduce_over_group` with the same subgroup, operation type, and value type for all its lanes (invalid flag, max, then sum), followed by `group_broadcast(..., 0)` in all lanes. SYCL requires group functions to be encountered in converged control flow and `group_broadcast`'s requested local id to be common to all participants; the current expressions meet those requirements.

For each head, lane `l` reads cells `l` and `l+16` (`c0 = lane`, `c1 = lane + 16`). Score loads are `scores[h*33+c]`; probability stores are `probability[h*32+c]`. For h=0..15 and c=0..31, these form a disjoint complete partition of the allocated 16x33 score storage's active 16x32 cells and the 16x32 probability allocation. The score row padding (column 32) is neither read nor written by the new normalization. Each h is owned by exactly one subgroup (`h % 8`), and each cell is owned by exactly one lane within it.

### Persistent state, invalid data, and barriers

Only lane 0 reads `maximum[h]` to seed `prior`, then all lanes receive it through broadcast. Only lane 0 reads `normalizer[h]`, computes `alpha`, ORs the reduced `score_bad` into `bad_head[h]`, and writes `maximum`, `alpha`, and `normalizer`. Each head maps to one subgroup, so no two subgroups update the same persistent row. The initial Q diagnostic and state initialization occur before the existing work-group barrier at source line 187. Row-index setup is followed by the barrier at 202; QK score writes are followed by the barrier at 232 before the new code reads scores; probability and alpha writes are followed by the existing barrier at 263 before PV consumes them; the loop's final barrier at 281 remains before final state use. The candidate does not rely on a subgroup collective as a work-group/local-memory fence.

For an active row, non-finite scores set `score_bad` and are excluded from both max and probability, matching the old scalar conditions at lines 237–245. Missing cells and tile-tail cells have `rows[c] < 0`, contribute `-inf` to max and zero probability, and do not set a bad-score flag. With no valid cell, `tile_max` remains `-inf`, `old_norm` is zero, `alpha` is zero, and the normalizer remains zero; no `exp2(-inf - -inf)` is evaluated for invalid cells because the conditional selects zero. `bad_head` is ORed only by its owner lane. Existing final output logic still gates invalid-Q/score/scale diagnostics with `any_live`, produces zero for empty/missing-only rows, and normalizes output only when `normalizer[h] > 0` (lines 283–295). Invalid-width handling, page-table/prefix validation, scale diagnostic generation, and packing are outside the replacement block and unchanged.

### Kernel identity

The private template changes from `prefix_batch_impl` to `rowmajor_subgroup_impl`, and the private exported symbol changes from `qsa_bf16_prefix_optimized_batch` to `qsa_bf16_prefix_rowmajor_subgroup_batch`. This establishes source-level distinction from the baseline optimized kernel and avoids reusing the same template/lambda enclosing identity by name. The build recipe compiles the candidate as a separate private source and the test macro directs the test entry to that export. No compiler output/IR was inspected, so actual compiler-generated kernel IDs and the linked binary's symbol uniqueness remain unverified; the source review JSON itself records `compiler_executed=false` and `GPU_executed=false`.

## Numerical contract

The normalization formula remains online softmax: per tile, `m = max(old_m, tile_max)`, `p_i = exp2(score_i-m)` for finite active cells and zero otherwise, `alpha = exp2(old_m-m)` only when the previous normalizer is positive, then `normalizer = fma(old_norm, alpha, sum(p))`. The candidate's only intentional arithmetic difference is the FP32 `sum(p)` association: each lane first forms `p0+p1`, then `reduce_over_group` combines 16 lane values. It still sums unrounded FP32 probabilities and only then stores each individual P as BF16. Max/normalizer/alpha and PV accumulation stay FP32; Q/K/V/P/output storage and matrix operands remain unchanged.

This is consistent with the local accepted QSA contract and the pinned upstream reference, not an assertion of bit identity with SGLang. At immutable SGLang commit `877be2974aa151a984e52822c028276c2b1e9303`, the official `python/sglang/srt/layers/attention/qsa/sparse_attn.py` contains both `_sparse_gqa_prefill` and `_sparse_gqa_chunk_prefill`; each uses FP32 `max_value`, `normalizer`, and `accumulator`, computes `probabilities = exp2(scores-next_max)`, converts P to the V dtype for the matrix product, and updates normalization with a reduction (`tl.sum(probabilities, 1)`). The prefix interface dispatches the chunk-prefill kernel. This supports the storage/state boundaries and a parallel FP32 probability reduction; it does not promise the same reduction tree, matrix rounding, or output bits as this SYCL implementation. Direct URL: https://github.com/sgl-project/sglang/blob/877be2974aa151a984e52822c028276c2b1e9303/python/sglang/srt/layers/attention/qsa/sparse_attn.py . Khronos SYCL Reference documents that group calls require convergence and that `reduce_over_group` combines all lane values; its reduction order is a generalized reduction, not the old serial cell order: https://github.khronos.org/SYCL_Reference/iface/group-functions.html and https://github.khronos.org/SYCL_Reference/iface/group-algorithms-library.html .

The currently wired independent host fixture does not require output-bit equality with the optimized baseline or llama.cpp. `tests/sycl/qsa_bf16_prefix.cpp` computes an independent BF16-operand/FP32-online reference, permits one BF16 ULP plus `2e-6` per output (lines 155–199), and separately requires bitwise deterministic repeat output for the same implementation/input (201). This is the correct distinction for the changed sum order. Its FP64 dot/PV reference is a diagnostic oracle under that tolerance, not a stricter precision-adoption policy. No cross-arm equality criterion should be added.
