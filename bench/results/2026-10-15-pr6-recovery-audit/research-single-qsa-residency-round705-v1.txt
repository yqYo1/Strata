# R705 — one active QSA residency for 262144-row layer-major prefill

2026-10-15 JST. Read-only implementation plan for the personal `feature/sycl` fork on Arc B570 10 GiB. Product source, branches, services, builds, tests and GPU were untouched. This file is the only new artifact. The restricted post-reboot `record.json` was not opened. No external claim is needed: the relevant mechanism is fully specified by the configured source and existing capacity metadata.

## Decision

A one-active-QSA residency policy is plausible for the proposed long layer-major route, but it is not current production behavior. The smallest safe seam is inside the already layer-major prefill pass, immediately around each QSA layer's `run_impl` call in `src/prefill/layer_major.inc`, with a new owner abstraction in QSA/session state that swaps only the KV device pool and selected page map for that ordinal. Keep the existing per-layer `run_impl` chunk traversal, QSA indexer buffers, host KV authority, RoPE table, GDN states, PLE history, callbacks, and residual schedule. This avoids introducing another attention/indexer implementation.

The existing mode-1 stream is a useful source of truth and fallback, but cannot itself satisfy the hypothesis: it allocates an `n_slots` device K/V ring for every QSA layer, and `layer_major.inc` accepts all 12 states while preserving their allocations. `NativeDense` v2 is orthogonal: it banks expert/native dense weights while canonical all-layer rows remain resident. The 1.3413 GiB combined active weight bank and the one-active-QSA KV figure are separate owners and must both appear in admission.

## Existing behavior and exact seam

`session_bytes` counts every QSA state in one device arena; the first state owns shared RoPE and the other 11 borrow it (`src/core/session.cpp:54-72,101-117`). `qsa_state_bytes` includes K/V slots, page table, mode-1 map, full-context indexer `tail/dead/pooled/block_pos`, and RoPE only for the primary (`src/core/layer.cpp:496-534,555-614`). At max context, there are 65,536 four-token pages and 65,538 pooled rows; the spare pooled row is required at the physical boundary. Do not resize or alias these indexer rows to a KV resident-slot count.

Mode 1 retains a complete authoritative pinned host K/V copy per QSA layer (`layer.cpp:633-663`) while its device pools contain only `p.slots`. During every prompt chunk, the current `run_impl` stages prior pages `[0, ceil(p0/4))` from that layer's host copy into a distinct identity-addressed stage pool, appends the current cells to host and device/stage destinations, then uses the staged pool for causal attention (`src/prefill/prefill.cpp:2197-2200,2207-2221,2335-2355`; `src/kernels/sycl/kv_stream.cpp:301-320`). The SYCL copy validates full-span source/destination ranges and finishes its queue before returning. The distinct host copy remains complete; the mode-1 slot map is a decode residency cache, not prompt history.

`layer_major.inc:91-109` currently checks every QSA state for common mode/format and available host/stage pools. Its outer loop loads one model layer, sets `[stage_lb_,stage_le_)=[layer,layer+1)`, calls `run_impl(tokens,n,pos0)`, waits, and then advances (`:292-395`). This is the correct integration point: at the QSA-layer boundary, acquire the active QSA's full-context device KV/indexer working owner (or promote its existing KV owner), run all chunks in ascending order through `run_impl`, ensure the host copy is authoritative through the final append, then release only the temporary full-resident K/V owner before advancing. On GDN layers, no QSA owner transition occurs. Layer 1 PLE runs once under the existing range logic; the final model callback remains final-layer-only (`prefill.cpp:1578-1602,3136-3172`; `layer_major.inc:343-400`).

To avoid per-chunk full-history DMA, active QSA attention should use its now-full device page table/pools directly after append. This is a targeted change to the existing `staged` choice at `prefill.cpp:2197` and the active layer's pool selection; keep the current stage path for all other modes/callers. On completion, the full K/V data is already represented by `st.host`, since the streaming append mirrors writes there. Releasing the active full bank therefore needs no D2H KV export. Later decode may continue with the existing compact mode-1 slots and resolver (`layer.cpp:732-737`, `verify.cpp:827-832`), which repopulates selected pages from the authoritative host copy. The current stream mode remains the post-prefill/decode representation.

The important complication is indexer state. The selection path reads full `idx_pooled` and `idx_dead` every chunk (`prefill.cpp:2233,2260-2263`) and verifier decode also reads `idx_pooled`, appends into `idx_tail/dead/pooled/block_pos`, then selects (`verify.cpp:785-828`). Unlike K/V, indexer arrays have no host-authoritative mirror. Safest first version: keep all 12 indexer arrays resident and allocate/replace only the active layer's KV page payload/map. The R705 hypothesis's phrase “other QSA layers in RAM” is thus accurate only for their K/V backing, not their indexer or shared RoPE. If the target budget specifically requires indexer eviction too, add a separate checked per-layer snapshot/restore owner for all indexer buffers and transfer it only at layer transitions; that expands the seam and requires decode state reload before graph use. Do not call the full QSA object RAM-resident while those buffers remain on device.

## Capacity and owners

Prior `prefill-capacity-current.ja.md` and `prefill-capacity-metadata-v2.json` already calculate 4K, K8V8, 262144-context, combined-bank layout. The structured case reports `one_active_QSA_full_context_bytes=377,753,104` B (about 0.351 GiB), `all_hidden_with_one_active_QSA_fits=true`, and `one_active_QSA_remaining_bytes=1,421,781,232` B (about 1.324 GiB) for the 1.3413 GiB combined bank, 4K workspace, GDN/PLE state, 512 MiB runtime assumption, 16 MiB small-owner allowance, and 5 GiB saved hidden. This is source/metadata admission arithmetic, not a 262144 allocation or model run. The separate-max expert/dense layout leaves only 145,976,432 B (about 139 MiB), so the combined reusable bank is material to the claim.

That one-active-QSA term is not simply one-twelfth of the all-QSA total. It includes one full-context K8V8 KV state plus indexer/page/map and shared RoPE according to the metadata recipe. The all-QSA device state is about 3.534 GiB. A proposed active-only allocator must reconcile its payload allocation sizes and 256-byte/16-byte padding with the existing `qsa_state_bytes` and allocator fixture; no double count of shared 64 MiB RoPE is allowed. K8V4 remains a capacity-only scenario: `qsa_state_init` rejects hybrid streamed mode (`layer.cpp:580-590`) and current SYCL layer-major does not establish a working K8V4 route.

The scenario budget has strict exclusions: short/decode layout, output head, full MTP draft owners, runtime actual peak, and device allocation fragmentation. The current NativeDense bank does not free canonical all-layer payloads; its v2 owner/reader transaction is still a separate lifecycle proposal. `layer_major.inc:118-155` also budgets new expert upload cache, residual storage, and a 512 MiB free-VRAM reserve without reclaiming any existing QSA state. Thus “fits” requires reclaiming or not initially allocating inactive QSA device K/V payloads; allocating a second full bank beside all current QSA owners cannot inherit the metadata result.

For long 262144 rows the saved FP16/BF16 hidden remains 5 GiB (20,480 B/token), and 4K `run_impl`'s existing carve is 1.1424 GiB under the cited capacity report. The current planner's partial-hidden FP16 staging requirement is irrelevant only if all 262144 rows truly fit; otherwise chunk-rounded host tail plus one full FP16 staging chunk must be budgeted as reported in the same document. FP16 and BF16 are equal storage bytes; neither is numerically qualified here.

## Transfers and preservation

With current mode 1, each QSA layer/chunk stages all earlier pages again. For 4K chunks and 256K input, the prior-page payload copy work is quadratic in chunk count per QSA layer; the active-full-bank route can remove that repeated host-to-device history restore for the active layer. A one-time full upload at layer entry is a poor alternative if it recopies cells already produced in earlier chunks. The active bank should instead be used from the first chunk and populated as normal K/V appends occur. If startup enters after some prompt prefix (RESTORE/resume), one full prefix upload is needed for that active QSA and must be charged separately; this candidate's first gate should require `pos0=0`.

At the end of that layer, no full-bank-to-host copy is needed for K/V because the current streamed append writes the authoritative host copy on every append; verify this for each active format and every append implementation. The 12 K/V host copies are already pinned per QSA state. A stable mode-1 page map should not be used as the active full-page table: use a dedicated identity table over all 65,536 pages (or prove the existing active page table is identity-initialized and no resolver mutates it during prefill). Preserve the saved decode slot map separately or reconstruct/reset it only after all readers have retired and before the next decode graph uses it. Restoring decode requires selected-page fills via `qsa_kv_resolve`; it should not require uploading all KV to device.

For an active QSA's K8V8 pages, the capacity metadata's per-layer full state includes roughly 0.35 GiB. At 4K chunking, naive per-layer prefix restaging transfers roughly `sum(0,4K,...,252K)` token-equivalents, about 8.3 million token-equivalents per QSA layer, before format bytes and current-chunk appends. A full-bank-once design populated incrementally transfers zero historical prefix bytes from host during a fresh prompt; that is the bounded-cost target. Measure exact bytes and time in Main's serial GPU gate, including append and final release, rather than attributing the whole prefill speedup to KV.

## Pointer, callback, and terminal constraints

Do not free/rebind any `QsaState` storage while Verifier or SessionGraphs can read its pointers. Session capture bakes pointers to per-layer state (`src/core/session.cpp:191-354`); Verifier retains its target state/window graphs and commit path (`verify.cpp:785-832,1258-1270`). The smallest first prototype should leave the original mode-1 state arrays allocated and redirect only prefill's `QsaState` view to a separate active KV owner. That will prove semantics, not recover the full theoretical capacity, because old device pools remain allocated. Capacity recovery needs a preceding owner-layout change (allocate inactive KV as host-only / omit it from the session arena) and a coordinated decode owner that recreates the compact pool/map before Verifier recapture/use. Avoid mutating shared graph pointers in place.

`on_chunk` is synchronous after the compute stream drain. The layer-major route invokes it only after final model layer rows, preserving MTP draft-side prompt pairs exactly once (`generate.cpp:5040-5045,6514-6520`; `prefill.cpp:3164-3172`). Do not publish intermediate layer rows as checkpoints or send them to MTP. Preserve all GDN recurrence, each QSA indexer state, shared RoPE owner, `ss.ple_prev`, PLE history, token position and cancellation ordering. A failed device/copy wait must retain all owners and prevent later layer, decode, checkpoint, or callback consumption.

The full physical-context gate remains 262144 input cells, with the last legal input at position 262143 and no next target position. On the native MTP4 path, existing `generate.cpp` sends that terminal input through the first verifier `run(T=1)` and `commit(1)` window; successful commit plus `wait_commit()` is required before a zero-output return (R700). This residency plan must not interpret the final prompt prefill callback or MTP draft prompt preparation as proof the target verifier consumed row 262143. Test both the all-prefill state and terminal verifier commit, with emitted token count zero.

## Gated implementation sequence

1. Add an allocator/source-only ledger for all 12 QSA `QsaState` fields: full and streamed KV byte counts, shared RoPE once, identity/decode page tables, map arrays, indexer arrays including 65,538 pooled rows, pinned host copies, prefill stage, and verifier/graph consumers. Assert totals against metadata and current `qsa_state_bytes` for C=262144, K8V8, page size four. Include allocation padding and the active model layer identity. No GPU claim from this step.
2. Define an explicit `PrefillQsaLease` for one ordinal. It receives `QsaState`, active full KV payload, identity page map, host KV, and the existing indexer pointers; it returns a prefill-only view. Use `run_impl` with that view and a `kv_mode` indicating direct identity/full residency, while leaving session-owned decode state unchanged. Keep current mode-1 behavior as fallback. Prove enter/restore on all returns and exceptions, checked stream drain, unchanged host authority and indexer bytes, no double-free, and no graph-visible pointer mutation.
3. Add host contract coverage for pages 0/1/65535, positions 262140..262143, rejection of 262144, identity addressing, host-mirror append format parity, no repeated prefix stage in active mode, and lease failure/cancellation ordering. Add an integration mock that captures the original SessionGraphs/Verifier pointer values and asserts they remain unchanged across the prefill-only lease.
4. Only after semantic fixture pass, Main decides whether allocator restructuring is necessary for the intended capacity recovery. The real allocation must omit 11 inactive GPU KV banks while retaining their host copies and all needed indexer state, shared RoPE, plus one full active bank. It must account 5 GiB hidden, active layer weights, workspace, GDN/PLE, 512 MiB runtime allowance, expert upload cache, and allocator fragmentation together. Reject admission before mutating session state if measured free memory or host pinned-memory budget is insufficient.
5. Main serial GPU gates: tiny parity against current chunk-major for each QSA format supported by configured SYCL; streamed fresh 4K prompts with per-layer host KV/indexer hashes and byte-transfer counters; cancellation/fault at every layer boundary; short RESTORE/resume rejected or separately qualified; decode one token after prefill with selected-page resolver and Verifier/SessionGraphs; finally full 262144-cell consume with terminal position commit and zero output. Repeat clean long-prefill measurements only after correctness and capacity receipts pass. Compare total path (activation residency, upload, prefill, release, decode restoration) against current route.
