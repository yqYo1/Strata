- `/usr/bin/ocloc` is present, version `26.31.39395.14`; `ocloc compile --help` recognizes `bmg-g21` and `bmg` as target devices, and `ocloc disasm --help` disassembles Intel Zebin images to readable assembly/sections. `ocloc query OCL_DRIVER_VERSION` reports `26.31.39395.14`. These are host-side tool queries only; they did not compile anything or access the GPU.
- The system `/home/yayoi/.nix-profile/bin/clang++` is upstream LLVM Clang 21.1.8, not the pinned DPC++ compiler. It is not a valid substitute for this SYCL source/compiler combination.
- The existing retained reference executable/build metadata is not a compiled prompt-attention image receipt: it is a generic/JIT application binary and no compiled B570 `.bin`/Zebin for this kernel was identified in the bounded existing build records. `ocloc disasm` cannot infer the final machine code from C++ source or an ordinary host executable.
- Intel compiler documentation says `-save-offload-code=<dir>` saves offload intermediates; for this toolchain family it is an extraction step, not a promise of final JIT machine code. For final static device code, use `spir64_gen` AOT for BMG-G21/B570 and disassemble the generated Zebin with `ocloc disasm`. AOT is a resource inspection build; its binary/compilation route differs from the existing JIT route, so do not treat its timing or resource allocation as a directly measured property of JIT execution without verifying the actual runtime image.

No administrative access is inherently needed for an isolated compile, extraction, and disassembly when the compiler and IGC/OCLOC components are already installed. Running the program, collecting live driver JIT output, enabling privileged device instrumentation, and querying device counters are unnecessary for offline AOT inspection. The absence of a GPU during compilation is supported by the offline-compiler model; support for this particular B570 revision must still be checked against the installed OCLOC/compiler versions. Do not install/change toolchains as part of this plan.
