## CPU sourceを「全て明確」または「全てclean」と言わない理由

`df4f8742`のGit diffは単なる追加markerだけでなく、CPU dispatch/layout/pool/AVX implementationの変更を含み、SPDX表示が複数live source/headerに存在する。一方、それ以前のown CPU engine (`73d0dc22`等を含む履歴)、upstreamをexplicitly出典とする`378770ae`以後の書換え、own tuningが同じ現在ファイルに重なっている。レポートやdiffは有力なancestryだが、symbol marker不存在や現在の短いcommit messagesだけで差分を全部識別できない。次の実撤去判断は`df4f8742`のbaseに対する元差分と、各後続commitの適用hunkをown historyだけで再構成し、engine上必要なpreexisting implementation/independent later modificationsを保ったsource hunk単位レビューが必要。著作権表示を消して残す方法はsource removalではない。これはさらに継続する必要がある候補として扱い、ここではコードを変更しない。

## Direct1はDirect-output経路、fallback Qlayoutとは別

R716の「current Direct1 diagnostic = alternate fallback query layout」という解釈は誤り。今回のown source/configを照合すると、実測artifact `native-dense-bank-direct1-v1.json` は `STRATA_SYCL_PROMPT_DIRECT=1` を指定。現行`src/kernels/sycl/prompt_attention.cpp`のdirect selection (約300行) はDirect-outputを選ぶ。originは`cd4d4d97` “perf(sycl): write prompt attention outputs directly” (Oct 4, yqYoi) の`prompt_attention.cpp`実装と記録に繋がる。Direct1はこのprompt-attention output-mode armを表す。

`84374f68` “recover opt-in fallback query layout for prefill” は別のOct 15 own change。これは`src/kernels/sycl/decode_attention.cpp`のsplit/fallback attentionに`qsa_decode_attn_batch_layout` / `TransposeQ` variantを足し、`src/prefill/prefill.cpp`からfallback selectionを追加する。これはDirect-output switchではなく、QSA split decode fallbackのquery layout selector。R561も`STRATA_PREFILL_ATTN_LAYOUT`をfallback-onlyとしてprompt `joint_matrix` pathと区別している。従ってDirect0/Direct1 artifactを84374f68由来Qlayoutの性能結果と扱うのは誤り。これら二つは別のentrypoint, flag, kernel routing, ancestryでレビューする。

## source scopeの確認点と限界

* `cmake/sycl_backend.cmake`の`strata_kernels`固定source listにはdecode/prompt attention両方が含まれる。SYCL backendをbuildする時に両方のtranslation unitがcompileされても、runtime call siteは別 (`qsa_decode_attn_batch[_layout]`対`qsa_prompt_attn_batch`) である。build source presenceだけで一つの測定が両方を実行したとしない。
* CPU native expertsは`strata_kernels_cpu`に入り、ggml-cpuをactivation quantization / generic type-trait dotの依存として使う。`native_expert.cpp` commentsもこの役割を述べる。これはggml upstream dependencyの存在と、df4f8742由来 hunkの存在を区別する必要がある。
* `src/sycl`のorigin判定は3 runtime sourceとprincipal loader/compat implementationの履歴に限定。その他のSYCL kernels全体をこの追加監査だけでcleanと宣言しない。R716で確認したDirect1 scope以外のfull-source exhaustiveness auditは未実施。
* 共有索引、R715 removal-hook report、R716 provenance reportを先に確認。R716はpre-Xe prompt/decode kernel ancestryを示すがDirect1 routingについての記述はこの報告で訂正する。layer-majorのpre-Xe ancestryはR716の範囲なので繰り返さない。
