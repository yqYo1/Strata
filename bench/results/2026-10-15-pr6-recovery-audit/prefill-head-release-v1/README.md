# Long-prefill output-head release proposal v1

SOURCE ONLY / NOT APPLIED / NOT BUILT / NOT TESTED. Runtime remains unchanged. Only this new directory was written. No compiler, tests, py_compile, GPU, process inspection/control, environment inspection/mutation, Git, cleanup or private B reads. Main owns application and serial validation after its active prefilling run closes. The project-only skill, AGENTS.md, retention policy, R672 and long-prefill execution-order report govern this bounded candidate. No speed, VRAM delta, quality, full-context or adoption claim is made.

`source.diff` is against exact current root files. `pins.json` records each base and proposed output SHA256; `artifact-sha256.json` pins proposal files and relevant inputs. There are no complete copies of large translation units. `author.py` is the text-authoring recipe, not a product/test runner. The small `prefill_head_scope.hpp` duplicates only the new compact host helper to make the fake fixture independently reviewable; its exact proposed bytes/hash are recorded. Main must reconstruct/verify the patch and rebuild NativeHead, MtpDrafter, Verifier and every layout-consuming TU together. This root-based proposal is independent of indexed-head and NLL proposals; do not blindly stack overlapping patches.

Only exact `STRATA_PREFILL_RELEASE_HEADS=1` activates the boundary. It requires SYCL, exact layer-major=1, native MTP4, one full-device stage and ordinary head sampling. Split/peer/remote/coupled, selected-prefill logits, teacher-forced NLL and STRATA_LOGPOS routes reject before retirement/free. A short segment `n <= chunk` goes through the original path; short-input dispatch thresholds are untouched. Both real batched prompt call sites invoke the same helper: warm SERVE supplies its existing Verifier, standalone supplies null because its verifier is created after prompt ingestion. No standalone-only substitution is made.

R672 correctly identifies the two weight owners and KV-only MTP prompt path. Its warm-serve discussion proposed destroying verifier arenas as well as graphs; this candidate narrows retirement to graph handles and queues, keeping those arenas and session owners in place. Target K/V, GDN, PLE, verifier arena/mapped staging/sampling state and completed commit graph survive. MTP retains dense/arena/KV, draft logits, dvocab/order/count, optional sampling buffers and both KV-only prompt graph families. NativeEmbed is neither released nor counted as a proven large device owner.

The common helper preflights all owners and reserves a bounded RAM snapshot before publication. It drains the ordinary target main stream, waits the verifier's pending commit, drains verifier compute/copy queues (including callbacks), destroys every target window/segment/work graph with checked statuses, and drains/destroys all MTP normal/coupled round/step graph families. Only after all readers retire can either packed head allocation be freed. Detached guards reject target projection, verifier full windows/capture/commit/logits, and MTP full forward/draft/capture/bind/head-size queries; no reader can infer full-vocab fallback merely because dhead_ temporarily becomes null. MTP KV-only graphs remain legal.

NativeHead snapshots exactly its already-uploaded packed bytes into owned pageable RAM using a checked synchronous D2H copy, then frees only weights_. Metadata/type/dimensions/quantization, scratch and math stay unchanged. The snapshot is bounded at 1 GiB; unsupported larger heads reject before retirement. Restore allocates exactly the old byte count and uses checked H2D from that same snapshot. The snapshot is released only after both heads have been restored and readers are about to resume. No unbounded files, GGUF reopening, format conversion or stale source-path trust is involved. This deliberately adds one full packed-target D2H and one H2D per qualifying prompt segment; whether the extra GPU headroom repays this traffic/capture cost is unmeasured.

MTP's duplicate head is not saved to RAM. Preflight captures/checks the existing device IDs in bounded host vectors, validates every ID and subset count <= n_vocab (the existing max_t*n_vocab logits capacity), and retains the same device map allocation through prompt execution. IDs are compared before and after the prompt, with duplicates and order unchanged. There are two additional subset-map D2H readbacks per release cycle, before and after the prompt. Restore gathers the same packed rows from the restored NativeHead using the unchanged device dvocab_, checks enqueue/completion, then restores accounting. The no-subset full-head decision is retained as well. After first use, bind permits only the same WeightTable/head/format and immutable map; window_R_ can change for standalone's later verifier bind only while no full graph reader exists. No sampler/token remapping policy changes.

For the specified Q6 geometry, NativeHead=521472000 B and duplicate draft head=223227900 B, total theoretical packed payload=744699900 B. The native snapshot consumes 521472000 host bytes, plus two subset int32 vectors (106299*8=850392 B for the specified subset; a full-map upper bound for this vocabulary is 248320*8=1986560 B). Each map vector has an explicit 4 MiB budget, independent of context. These are source arithmetic, not measured allocation/physical VRAM savings. Existing startup head/draft reservation remains intact, so decode restoration admission is not silently removed. This proposal does not automatically enlarge the GPU residual bank, change chunk size or claim fewer RAM residual round trips; later controlled placement/chunk work must actually consume admitted headroom.

On normal return, false/error/cancel return or prompt exception, the common helper restores the original native head, reconstructs the duplicate, resumes guards and lazily recaptures full decode graphs. Existing MTP expert-release mode can nest inside this boundary: its temporary prompt allocations retire and experts restore before output-head restore. Unknown DMA completion, graph destruction, free, allocation/restore or resume failure uses existing non-unwinding fail-stop with owners live; it never returns a detached persistent server. A scope cannot escape detached. A lease declared immediately after local NativeHead drains main/MTP readers before NativeHead destruction, including the absent-subset borrowed-head case; the verifier's nested lifetime ends first. Future callers must honor the documented serialized boundary and borrowed-owner lease.

The state/helper fixture is source only. It uses the exact reusable production orchestration, state-transition validator and ID validator, with fake owners. Always-on checks cover success, normal false/cancel, prompt exception with original error, rejected preflight without detach, nested reentry, repeated scopes, duplicate/illegal transitions, immutable duplicate/nonmonotonic IDs, negative/out-of-range IDs and capacity. It does not instantiate CUDA/SYCL classes or prove DMA/graph retirement. Main may later compile `host_scope_fixture.cpp` with a host C++17 compiler, then execute it under the serial policy; no execution has occurred.
