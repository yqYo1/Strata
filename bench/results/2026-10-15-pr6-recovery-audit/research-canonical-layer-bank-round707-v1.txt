# Canonical layer-bank extension on the NativeDense transaction (R707)

2026-10-15 JST. Read-only source and prior-evidence audit. No product source, branch, build, test, GPU or service action was performed. This report is the only new artifact. Source review was against the live `feature/sycl` tree containing NativeDenseBank v2, including `src/program/generate.cpp`, `src/core/native_dense.cpp`, `src/core/weights.cpp`, `src/prefill/prefill.cpp`, `src/prefill/layer_major.inc`, and the named prior receipts/reviews. The existing transaction is default-off and startup opt-in; this report does not qualify its runtime, memory reclamation or performance.

## Finding

A small canonical extension can reuse the existing outer request transaction and layer-major activation callback, but NativeDense's current `layer_view()` is only a native-projection overlay. Its `activate_layer()` restores each native row's saved `WeightRef` metadata while changing `native_data`; it does not provide canonical device payload. The shared canonical `WeightTable` arena remains live throughout `Residency::Bank`. Consequently the current `LayerView::get()` fallback works today because canonical pointers are still resident. Once canonical rows are released, that fallback becomes invalid and the prefill path must resolve a complete active canonical-plus-native layer from an independent private map.

The smallest safe extension is a `CanonicalLayerBank` owner joined to `NativeDense` inside the existing `run_prompt_with_native_dense_phase` transaction. It should use the already retired graph/readers boundary, retain the original `WeightTable` metadata and source identity on the CPU, populate one maximum-sized combined canonical/native bank per active layer, expose one immutable composite `LayerView::Overlay`, and restore full canonical plus native owners before recapture/resume. Keep the present single outer transaction and its checked `session_graphs_retire_dense`, Verifier retire/resume, MTP callback drain, PLE withdrawal/rebind, restore guard and `phase.recapture`; do not nest another owner transaction or independently resume any reader.

## Payload and peak ledger

`prefill-capacity-metadata-v2.json` records canonical per-layer payload totals after native-served tensor skips, 300 NativeDense matrices, and packed experts. Its 1,538,035,200-B canonical arena and 2,116,951,040-B native owners are disjoint. Layer 47 is the largest **combined dense** layer: 32,366,592 B canonical plus 44,646,400 B native = 77,012,992 B. With 1,363,148,800 B packed experts its combined active payload is 1,440,161,792 B (1.3413 GiB). This matches the requested one-combined-active-layer weight hypothesis; it is not current allocation behavior.

Other useful source/receipt totals:

- Current NativeDense-only policy: native snapshot RAM is 2,116,951,040 B; bank payload is 50,918,400 B (maximum native-only layer 28); currently retained canonical arena is 1,538,035,200 B. The existing `2,066,032,640 B` theoretical native recovery does not include canonical bytes.
- Canonical per-layer maximum is layer 1 GDN at 95,483,776 B. Layer 47 is 32,366,592 B. The 48 per-layer canonical sum is 1,524,887,040 B; the remaining 13,148,160 B of the canonical arena belongs to rows outside `blk.<layer>` and must remain independently owned or be assigned to their actual consumer.
- All 96 HC attention/FFN norms cost 3,932,160 B (40,960 B each). Retaining this one small GPU pool allows the fused residual writes to read the next layer's HC norm while only the current full layer is in the main bank. Existing capacity figures include these norms inside canonical layer bytes, so subtract them from the main bank maximum before adding the pool. As a safe bound, retain the pool and bank at most `1,440,161,792 - 81,920 + 3,932,160 = 1,444,012,032 B` for dense/native/experts plus persistent HC norms. That is 3,850,240 B above the single combined-layer target, before allocator alignment/metadata. If actual layer-47 HC norm rows are preserved in place, do not also count their bytes in the bank; the simple bound assumes all HC norms leave the bank.
- NativeDense's 6,912-B Q8_1 scratch is already persistent and is excluded from `weight_bytes()`. Expert cache is already allocated for one active layer by layer-major execution; don't add its 1,363,148,800 B twice. Per-layer prompt GEMM scratch/workspace, QSA/KV staging, session/GDN/QSA/PLE state, saved residual, output head, MTP-owned draft tensors, runtime reserve and allocation padding are separate owners. For the 4K capacity plan, existing source values are 1.1424 GiB prefill workspace, about 0.1099 GiB GDN/PLE state, 512 MiB runtime + small-owner allowance, and 5 GiB total saved hidden at 262144 tokens; 8K workspace is 2.1528 GiB. Do not sum the R677 active weight/cache/workspace composite with these workspace values again: the R677 composite already includes the shared 32-MiB scratch and 32-MiB GEMM workspace. The cited runtime and small-owner reserve is a planning assumption, not a measured maximum.

Transition peaks require separate admission from steady-state bytes. With existing objects still full, *capture/storage in RAM* does not consume VRAM. On entry, NativeDense first allocates its 50,918,400-B bank before releasing 2,116,951,040 B of native matrices. A canonical owner must likewise allocate its destination before withdrawing/releasing the full canonical arena; if it allocates the full 95,483,776-B maximum while the source arena remains live, transient VRAM is at least the current full target-weight owners plus 146,402,176 B, plus other existing allocations. This first destination is below the canonical arena size, so canonical entry has no positive payload peak over the existing full state if allocation succeeds. Once both banks are active, steady dense/native VRAM falls from 3,654,986,240 B to at most 77,012,992 B layer payload plus the HC pool accounting above. On full restore, however, the current NativeDense implementation allocates all 2,116,951,040 B originals while retaining its bank (50,918,400 B), and only then frees the bank. A symmetric canonical restore would allocate the 1,538,035,200-B canonical arena while retaining its canonical destination; combined temporary allocation reaches the original 3,654,986,240 B full weights plus both banks (up to 146,402,176 B), in addition to the retained HC pool if it is separately allocated. Restore therefore needs full-owner headroom, not just the one-layer steady-state budget. OOM must retain both valid banks and prohibit decode; never free an unrelated owner to force restore.

The one-active layer 47 upload comprises 32,366,592 B canonical + 44,646,400 B native (77,012,992 B), while experts are handled by the existing expert stage/cache. A layer-1 `PleRun` native-key overlay is a row from the native active-layer map; PLE value/norm/conv weights and history are separate session owners and must be kept, not charged as missing canonical layer payload. Existing NativeDense prompt flow withdraws/rebinds the native PLE key publication explicitly around the full transaction.

## Source and lifetime contract

Canonical source bytes should come from the canonical pack's `index.txt` plus the indexed `dense.bin`, `embd.bin`, `experts.bin`, or `extra.bin`, using the exact conversion and alignment rules in `WeightTable::load`. This avoids a device-to-host snapshot. Two viable minimal source lifetimes are: (a) copy the loader's already converted host `stage_out` bytes into per-layer immutable RAM snapshots during the original startup load, charging approximately 1.538 GB extra RAM, then upload that exact engine form; or (b) retain/validate the original pack identity and reopen/read/convert only the active layer on each activation, with source files guaranteed stable for the full prompt and checked short-read/hash behavior. Option (a) gives the simplest transition and deterministic upload source, but must be included with NativeDense's existing 2.117-GB snapshot in physical RAM admission. Option (b) avoids the 1.538-GB shadow but adds file reread/convert work and needs a pack immutability contract. Do not copy canonical device bytes D2H after runtime initialization as a snapshot strategy.

`WeightTable::load` today reads/copies/converts from indexed source rows into one device arena. `skip` compacts the arena but skipped rows have null `data`; there is no layer load/free API. Recalling `load()` per layer is unsafe because it clears/repopulates the shared map and uploads every retained row. Add a purpose-built loader/materializer which preserves each original `WeightRef`'s shape, kind, quantization fields, source coordinates and resident semantics, then rebinds only `data` for the private active view. The full shared table may temporarily hold withdrawn refs as NativeDense does, but no normal reader may see them. Save/validate table identity independently of owner pointers; a copied metadata table must not become a second, accidental owner.

Use one combined scratch bank sized to the largest `canonical layer bytes + native layer bytes` rather than fixed independent max canonical and native banks. At each transition, retire the current prefill queue and synchronous MTP callback; construct and upload all canonical+native rows for the next layer into a complete next view before publishing it. A source read, host allocation, or bank allocation failure before publication leaves the old bank/view valid and is recoverable through the existing outer full-restore guard. Once the destination reuses the same physical bank, the old layer view must already have no queued/callback readers. On any uncertain copy/drain/free status, retain all source/destination owners and fail-stop as current NativeDense does. After the entire pass, clear the view, restore every full canonical/native owner, restore separate PLE publication, recapture SessionGraphs, then resume Verifier; only after that may normal inference/RESTORE continue.

## Exact tensor consumers and exceptions

The current layer-major `run_impl` direct dispatch constructs `LayerView(*m.wt, l, overlay)` in the active layer and separately constructs `LayerView(*m.wt, nl)` for fused residual normalization. The layer callback is invoked only at final-layer chunk completion and synchronously drains its own MTP work. The new resolver must supply every active layer tensor from either canonical data or native data without changing canonical/native precedence. The minimum routing changes are:

1. Build the complete active overlay (or a composite resolver) with canonical active-layer rows plus NativeDense native rows. Existing native overlay alone is insufficient after canonical release. Carry original canonical metadata and native type/Q8 scratch exactly as the current refs do.
2. Keep all HC attention/FFN norms in the persistent 3.93-MB pool, so half-0's current `hc_ffn_norm` and half-1's possible next-layer `hc_attn_norm` resolve without overlapping two full layer banks. R686 documents conditional fusion/fallback boundaries; no other next-layer full weights are read through `LayerView` in this active dispatch.
3. Keep layer-1 PLE value, key fallback if non-native, norm-key/query/conv and conv1d weights in `SessionState::ple.w`, along with PLE history/scratch. The optional native PLE key is separately published from `WeightTable` and already withdrawn/rebound by the outer phase; ensure the layer overlay's `blk.1.ple_key.weight` matches that exact native owner while layer 1 is active. Do not make PLE's independent owner look like a second full canonical layer payload.
4. Preserve `NativeEmbed` mapped host lookup for target embeddings. For native packs `token_embd.weight` is skipped from canonical `WeightTable`; MTP's `record_forward` has a fallback to `wt_->find("token_embd.weight")` when no NativeEmbed is registered. The configured native path must prove NativeEmbed remains available during retained MTP prompt callbacks; otherwise keep that table row resident or defer callback/MTP prompt reads under a separately validated policy. MTP draft dense projections are its own allocation and are not target canonical payload.
5. Keep non-layer canonical owners (embedding metadata/lookup, final norm, output/head route and any special rows) according to their actual consumers. The non-layer 13,148,160-B remainder in the metadata pool should be itemized by name/owner before any arena free; `NativeHead` is independently owned and must not be confused with that canonical remainder.

Readers to retain/restore are already mapped by R689/R694/R703/R704: prompt main stream; all SessionGraphs families/arrays; Verifier exec/segments/work; synchronous MTP callback and MTP-owned graphs/weights; separate PLE key pointer. Session KV/GDN/QSA state, indexer buffers, PLE history, residuals, workspace, and expert-cache data are not canonical weight readers and must remain live. Embedding/NativeEmbed ownership is special and independent. A live queue or captured graph must never retain a pointer into the reused active bank.

## Minimal implementation sequence

1. Extend the current opt-in startup admission with a canonical source manifest: all eligible layer refs, source hash/size, exact engine-form bytes, non-layer row inventory, per-layer byte totals, HC norm pool size, snapshot RAM requirement (if option a), restore peak, and fresh free-VRAM/RAM checks. Report single-owner bytes, transient overlap and persistent special owners separately. Validate the observed per-layer sums against `WeightTable::pool_bytes` and current capacity metadata.
2. Add a canonical owner beside NativeDense, with one max-combined-layer device allocation and either immutable converted RAM snapshots created during `WeightTable::load` or verified pack-backed layer reads. Store canonical full-owner restoration data and original `WeightRef` metadata. Keep separate ownership for the persistent HC norm pool and non-layer rows that still have readers.
3. Add a private combined layer resolver to `LayerView`/Prefill, making both active `l` and fused `l+1` HC reads explicit. Replace the hook's native-only overlay publication with a complete canonical+native active view. Ensure PLE's native key binding is consistent with layer 1 and NativeEmbed/MTP embedding remains valid.
4. Reuse the one current `NativeDensePhase` transaction for enter, every layer activation, restore and graph recapture. Prepare both owners before either is withdrawn. For entry OOM, keep Full state and return through unchanged prompt path only if both owners remain Full. Once either owner is Bank, every error/cancel/throw must restore both owners or fail-stop. Restore allocates/publishes both full owner sets before resuming any reader; partial restore cannot resume.
5. Add host/source fixtures for every layer and tensor identity, all canonical conversions, shape/form parity, composite lookup precedence, fused HC lookahead at all 48 boundaries, layer 1 PLE, output/non-layer rows, NativeEmbed/MTP path, RAM budget, enter/activate/restore OOM, short read/source identity mismatch, partial upload, cancellation/callback exception and fail-stop. Then perform Main's serial full generator transaction, graph recapture, RESTORE/decode continuation, numerical and physical-context gates. This research does not supply those results.

## Decision boundary

This extension is an actionable minimum to reach the **single combined active-layer weight** hypothesis. The current 1.44-GB active weight number is not a promise of total runtime headroom; expert cache, prefill workspace, persistent small owners, session state, saved hidden, runtime allocation and restore overlap still govern admission. In particular, retaining the HC norm pool makes the actual combined dense/native persistent payload about 3.85 MB above the nominal largest combined layer unless special-cased in place. The method must not claim the 1.44-GB row itself includes those execution and lifecycle costs.

R684 establishes the canonical/native aggregate and source feasibility; R686 gives exact fused norm residency; R689/R694 identify generator/LayerView seams and graph/MTP boundaries; R703/R704 cover the applied NativeDense transaction and its known host/full-generator proof gap; `prefill-capacity-current.ja.md` supplies the context/workspace plan; R705 is orthogonal QSA-state residency. No speed, allocator reclaim, exact source read count, successful restore, numerical parity, 262144-context or adoption claim follows from this source audit.
