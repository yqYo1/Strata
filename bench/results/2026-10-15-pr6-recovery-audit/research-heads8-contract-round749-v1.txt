## Contract trace

- **Geometry and bounds:** HRows8 gives WG64 and two head tiles per
  `(query, kvhead)`. Each group computes `headbase` as 0 or 8 and keeps the
  logical row stride at `HEADS=12`. Query loads offset from the current KV
  head by `headbase*HD`; `qi < HEADS*HD` zero-fills the second tile's rows 4–7.
  Direct output uses `kvhead*12 + headbase + row` and suppresses heads 12–15.
  Thus both KV heads cover logical query heads 0–11 without padding stores.
- **QK and PV collectives:** In WG64 there are four 16-lane subgroups.
  QK's `subgroup < HRows/4` condition selects subgroups 0–1, with each
  subgroup executing both cell panels. The condition is subgroup-uniform;
  selected subgroups encounter all matrix collectives in the same order.
  PV has no subgroup-divergent collective branch and uses all four subgroups.
  The changed HRows16 loop bound is selected at compile time, so baseline
  HRows16 retains its original four QK subgroups, expressions and output
  mapping. The candidate does not introduce a per-lane branch around a
  `joint_matrix` group-function.
- **Address space, alignment, and strides:** The HRows8 route requires
  KMapping0, so it uses the existing contiguous local `half` KV accessor and
  existing local-accessor matrix pointers. Query and PV row strides remain
  256 and 32 half elements; KV uses the existing 256-element row stride.
  Reducing row count changes allocation extents, not pointer element type,
  leading dimensions, or matrix tile footprint. The HRows8 path does not use
  the separate pitch40 wrapper or any global pointer as a matrix operand.
  Header/source review supports preservation of the existing address-space
  and alignment contract; compile-time/device validation remains outstanding.
- **SLM/barrier lifetimes:** All seven barriers in the selected-cell loop
  remain outside the QK subgroup condition and are reached in the same order
  by every work-item. `rows`, `scores`, K/V staging, scales, probabilities,
  and online-softmax state are written before their consumer phase and are not
  reused before the corresponding barrier. HRows8 shortens only row-indexed
  arrays; the 32-cell KV tile and shared row/scale arrays retain their
  extents. This is a source lifetime review, not an allocation or occupancy
  claim.
- **Flag and mode dispatch:** Exact `STRATA_SYCL_PROMPT_HEADS8=1` is checked
  only in `dispatch<1>`. It rejects Direct disabled and exact KMapping1/2
  before launch, then launches `<1,true,false,0,8>`. Other mode instantiations
  bypass this branch. Non-exact HEADS8 values keep existing dispatch. This
  inspection found no mixed-mode route into HRows8; tests of rejection and
  all dispatch combinations are unrun.
- **Launch range:** `nq` is validated as 0–65535 before dispatch (zero returns
  early); `n_head_kv` is 2 and `n_head` is 24. Multiplying by HTiles and WG
  remains within size_t for the validated query bound. The newly doubled
  grid factor does not exceed the existing per-dimension bound from `nq`.
  `cap` and page-size checks are unchanged, and cell indices are divided only
  after the existing `cell < 0` guard.

The config range is intentionally narrow: the candidate's explicit reject
checks cover Direct-off and KMapping1/2 as recorded in its README; there is no
claim that this constitutes validation of malformed environment strings or
runtime dispatch behavior. No additional concrete defect was found in scope.
