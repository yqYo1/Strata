# Round 1017 — first long-prefill compile cost: AOT, process reuse, persistent cache

Classification: decision support. Read-only research for the Arc B570 / Level Zero V2 path; no compiler, build, test, GPU, profiler, process, driver, cache, environment, or Git operation was run. I read the task-provided build/profile receipts and the compiler index entry plus the R611 report/Main review selectively; this report does not repeat their compiler-stack survey. This is a proposal, not evidence that an offline compiler, BMG target, or cache mode works with the installed DPC++ v7.1.0 pre-release build.

## Decision in brief

The first long request is a plausible place to remove runtime device compilation, but current receipts do not establish that compilation explains the window-dependent CPU delta. Keep the current SPIR-V/JIT executable and safe Level Zero configuration as control. Measure (1) same-process in-memory reuse, then (2) persistent SYCL cache across fresh processes; consider device AOT only if the exact installed compiler/linker toolchain proves that it can emit an image for this B570 and the image is selected at runtime. These strategies alter when/how device code is produced, not source arithmetic, but each still needs output, fault, and full-prefill validation. Do not change numerical flags or safe driver settings to make AOT work.

Installed compiler `bin` listing has clang-offload tools and `sycl-ls`, but no `ocloc`. This only describes that listing; it does not prove no compatible OCLOC exists elsewhere. The exact compiler root is the user-supplied `.tools/intel-llvm-v711/install` path; its pathname does not override the recorded compiler version. Do not inspect private configs or credentials.

At 78K input, the supplied paired profile receipts report unclassified thread CPU 12.2548 s (window2) vs 20.8493 s (window8), while `gemm_submit` CPU is essentially flat at 3.3889 vs 3.3916 s despite 141,230 vs 76,286 calls. These tags cannot identify the residual as JIT. More window-8 accumulation work, validation/grouping, runtime/driver work, compilation, and wait/poll CPU remain competing explanations. ## Comparison

| Approach | What may be reused / moved | First-long-request expectation | Limits and target-specific gates |
|---|---|---|---|
| Device-specific AOT | Embed device image at build time; avoids SPIR-V-to-device compilation when accepted. Add generic SPIR-V for fallback portability. | Lowest compile component if all used kernels are covered/selected. Does not remove validation, allocation, submission, driver setup, wait, or shape work. | Highest toolchain burden. Exact old compiler's BMG support is unproven; current CMake target is empty. Image can be architecture-specific/larger. Runtime-generated or unsupported kernels can still JIT/fail. No recorded `ocloc` in the install bin; that does not prove absence elsewhere. Never substitute PVC/Xe-HPC/CUDA flags. |
| Process-local reuse | SYCL in-memory cache, documented default on (`SYCL_CACHE_IN_MEM=1`); repeated identical images/specializations may reuse compiled code. | First long request still pays first use; later same-process requests may improve. | Does not survive process exit; new shapes/specializations may compile. The 74-token warmup does not prove long-shape kernels were built. Least invasive probe. |
| Persistent SYCL cache | `SYCL_CACHE_PERSISTENT=1` may save/reuse JIT binaries across processes; `SYCL_CACHE_DIR` selects root. | First process with empty cache is cold; later fresh process may hit. | Current arm sets it to 0. Keys/hits are not guaranteed across binary/toolchain/driver/device changes; IO/locking may offset savings. Prove writes and hits; not a safety qualification for this stack. |

SYCL caches are distinct from IGC/driver caches. Keep driver settings unchanged. A fresh `XDG_CACHE_HOME` isolates the default SYCL cache only if `SYCL_CACHE_DIR` is unset. For persistent-cache testing, set an owned `SYCL_CACHE_DIR` before launch and reuse it only for the warm process. Never change variables after runtime init; XDG alone does not clear every cache.

## Falsifiable Main probes (at most two)

1. **Host-only capability and attribution gate.** On an idle build slot, save exact version/hash, compile/link recipe, environment and tool paths. Ask only this compiler/toolchain's help/version whether it accepts `-fsycl-targets=spir64_gen` plus `-Xsycl-target-backend=spir64_gen "-device bmg"`, and whether matching OCLOC can emit/list a BMG image. Failure refuses AOT on this stack; do not substitute a different GPU flag. If it passes, package a disposable minimal SYCL sample and inspect its bundle—still not a Strata result. Separately, run diagnostics (not timing) with `SYCL_CACHE_TRACE=0x07` and thread CPU stacks; timestamp validation/grouping, exposed program build, allocation, submission, and waits, correlating queue/device event duration. Compilation is supported only if cold misses/compile stacks coincide with CPU and diminish on exact-image reuse while validation/submission stay stable. Residual CPU without misses/compiler stacks falsifies “all unclassified CPU is JIT.”

2. **Serialized GPU cohort after active mode10 closes.** Pin source/binary/model/input/window and safe vars (`UR_L0_V2_FORCE_DISABLE_COPY_OFFLOAD=1`, `EnableDirectSubmission=0`, forced adapter/queue/driver). Use 74-token warmup plus `tools/strata_bench.py --think --prefill-only --prefill-tokens 65536 --workload-id prefill_v1_20261015 --runs 4`, distinct tags; verify four long requests actually hit one still-running engine PID (if the harness restarts it, use four tagged client requests to one owned server instead). Label `first_long_same_process` / `later_long_same_process`; record prompt tokens, zero prompt reuse, TTFT/wall/tok/s, host CPU categories, GPU event time, faults and output/quality fingerprint. Control: persistent cache 0, fresh root/process. Persistent arm: set `SYCL_CACHE_PERSISTENT=1` and owned `SYCL_CACHE_DIR` before process 1; run it empty, then fresh process 2 on same cache; preserve/hash manifest and record trace hits separately from timing. Keep samples and spread. If Probe 1 passes, add AOT as distinct binary/arm with BMG image + SPIR-V fallback and unchanged `-O3`, `-DNDEBUG`, C++20, source FP flags, libraries and numeric choices. Do not bundle compiler or split changes.

The existing 74-token warmup is a separately labeled request, not a long prefill warmup. First long after it is still “first long.” Later long means another full distinct request in the same live process, with zero prompt cache reuse. To measure persistent-cache behavior across process launches, the “later fresh long” is the first long request in process 2, on process 1's cache. Keep both labels: `first_long_fresh_cache_process`, `later_long_same_process`, `first_long_fresh_process_persistent_cache_hit`. Do not average these populations together. A new server per run resets process-local cache; it does not reset persistent cache unless using a distinct empty path.

## Host CPU accounting and alternatives to JIT

“Unclassified” is a profile bucket, not a compiler attribution. Queue waits can burn CPU through polling/completion progress; host validation, grouping/index construction, oneMKL descriptor/dispatch work, command-list submission and allocation can also land there. The nearly unchanged `gemm_submit` CPU total alongside a changed call count specifically weakens a simple “more gemm calls caused more submit CPU” story, but does not determine what filled the residual. Attribute thread CPU by stack and phases; separately report process wall time, thread CPU, device event time, host submission intervals, wait intervals, and device idle gaps. Avoid treating `SYCL_CACHE_TRACE`, logging, validation capture, or profilers as performance data. Do not infer compilation solely from faster second call: clocks, model paging, OS/driver caches, allocator warmup and GPU residency are alternatives; use cache-hit evidence plus exact same request shape and outputs.

Code split is a separate axis: AOT may trade runtime compile for build/link time and image size. `-fno-sycl-rdc` processes device code per TU; it may reduce device-link work but constrain cross-TU optimization or create more runtime images/cache entries. Keep RDC fixed initially. Consider split only if profile shows link/image granularity matters; then record build/link time, image count/size, cache misses and long-prefill correctness/performance separately. Preserve FP flags.

## Adoption / refusal gates

Adopt a cache or AOT path only if (a) exact image selection or exact cache hits are evidenced, (b) there is a repeated first-long benefit larger than run-to-run spread and a meaningful reduction in the attributed compile phase, (c) prompt-cache reuse is zero and request/model hashes match, (d) output/task numerical checks, fault checks, physical-context and full existing validation gates pass, and (e) later requests do not regress. Refuse or defer if cache traces show no hit, benefit is only in unclassified time, AOT needs unverified B570 flags/toolchain mixing, image fallback silently JITs, cache writes fault, correctness shifts, or the runtime/driver stack changes. Current data supports neither adoption nor causal assignment; it supports the two-stage probes above.
