# NativeDense bank と configured generator の接続点（R694）

2026-10-15 JST。読み取り専用の source audit。`feature/sycl` の HEAD `465379dccbf12ff7137c085c0b10fb64dbe99f44` を確認した。変更したのはこの新規レポートのみ。build/test/GPU/process/cleanup/環境変更/branch/commit は行っていない。R689の一般的なgraph危険の反復ではなく、実際の `generate.cpp`、現行head-release境界、NativeDense layer-bank proposal を、退役順・残す状態・Prefill viewの引渡しに限定して照合した。

## 適用される実装と容量契約

現在の本体 API は `NativeDense::load(shards, table, err, include_ple_key)` のみ（`include/strata/core/native_dense.hpp:22-23`; `src/core/native_dense.cpp:71-189`）。loadは全pending allocation/upload後に `WeightRef.native_data/native_type/native_q8_1` を `wt` に公開する（cpp:179-188）。NativeDense destructorは自分のscratchとnative matricesをfreeするだけで、tableの公開ポインタは撤回しない（cpp:66-69）。従って、通常のowner破棄順ではなく、新しいlease/state APIを導入しなければ安全な退役・復帰にならない。

R691でsource review済みの提案は**未適用・未compile・未実行**。その提案だけに `load(..., include_ple_key, capture_layer_bank, layer_bank_ram_limit=3GiB)`、`ReaderRetirement`、`enter_layer_bank`、`activate_layer`、`restore_full`、`layer_view()` がある（`prefill-native-dense-layer-bank-v1/proposed/include/strata/core/native_dense.hpp:24-79`）。提案loadの追加引数は宣言/シンボルを変え、現 `generate.cpp:2258` 等すべてのcaller再compileが要る。`ReaderRetirement{true}` は呼び出し側の表明であり、graph/callback破棄をAPI自身が検証する機能ではない。

提案のcaptureは元GGUF packed bytesをload時にsnapshotし、native ownerを再構築可能にする。payload上限は3GiB、300行の実payload合計2,116,951,040 B。全canonical arena 1,538,035,200 Bは保持し、native-only最大layerのbankを置く。proposal review記載のnative VRAM回収は2,066,032,640 B（全native payloadから最大1層bankを差し引く値）。この回収値はcanonical arenaを含まず、262144 context実行や物理VRAM回収実績でもない。参照: R691本文と `prefill-native-dense-layer-bank-v1/source-review.md`。

## Generatorの実際の呼出し境界

serveの実体は `run_prompt_with_mtp_experts` (`src/program/generate.cpp:181-245`) から `prompt.run` を呼ぶ形。実際のbatched prompt callerは `:6005-6009`、standalone callerは `:6575-6579`。前者は `read_windows` に分岐するwindow区間があり、NativeDense bank admission対象に含める根拠がない。後者/前者とも現状はNativeDense leaseを持たない。layer-major dispatchは `Prefill::run` が `STRATA_PREFILL_LAYER_MAJOR=1 && n>T` のときだけ `run_layer_major` へ進む（`src/prefill/layer_major.inc:12-16`）。そこでsingle full-stage等の既存guardが `:36-40` 以下にあるが、target native ownerまたはsession graph retireを確認していない。

実運用の `SessionGraphs gr` は `generate.cpp:3091-3103` でserveのcache sizing前にcaptureされる。capture graphは `session_capture` 内で `block_layer_pre/post`（必要ならroute/shared、split preA/preB/prePも）を呼び、その際の `tables` はtarget NativeDenseが公開済みの `wt`（`src/core/session.cpp:191-193,246-289,333-350`）。decodeは同ファイル `:371-402,436-440,485` などでexecをlaunchする。`generate.cpp:3095-3096` の「cache-slot pointers無し」はexpert-cache slotに関する説明で、target native projection/scratchを含まないとの保証ではない。これらを解放前に退役しないと、永続execが旧native addressesを保持する。

現 `session_graphs_free(gr)` は終了時 `generate.cpp:7421`（別graph-only経路にも`:4109`）にあり、`session.cpp:580-629` が全exec配列を破棄しhandle/flagsをresetする。ただしdestroy statusは確認しない。layer-bank移行には、使用streamのdrain後に全配列をchecked destroyし、成功後のみ `gr.captured=false` 等にするrequest-level retire APIが必要。復帰は `restore_full` 後、同じ `wt/ss/parts` の `session_capture(wt,...)` を呼び直して成功するまでdecodeを閉じる順。現行 `session_capture` は `gr.captured` 時即return (`session.cpp:194`) なので、破棄・resetなしでは再captureしない。capture途中失敗がpartial arraysを残すため、退役/失敗cleanupの完全性も必要。

## 具体的な退役・維持・復帰順序

1. caller (`generate.cpp:6005-6009` と `:6575-6579`) がprompt全体の間、normal decode、session graph replay、verifier launchを排他する。capabilityはlong full layer-major (`n > prompt.chunk()`)、single device/native compact path、非window・非split/peer、Full NativeDense state、token graph無し、verifier idleで、対象callbackも非実行を確認する。SYCL `no_token_graph=true` は `:480` だが、別modeも同じleaseに入れないよう明示checkする。
2. promptに入る直前、主stream (`main_stream`/`main_cs`) と `SessionGraphs` をlaunchする各execution streamをdrainし、Verifierのcompute `cs_` とcopy `copy_` をdrain。MTP callbackが既に返ったこともrequest exclusionで保証する。失敗/例外を無視してowner freeへ進まない。特に `session_graphs_free` 現行はdestroyがuncheckedなので、bank退役に直接流用せず、checked版を用意する。
3. drained後にsession layer exec一式をdestroy。Verifierにはhead専用でないNativeDense-retire APIを新設し、inactive/completedかつcallback未実行を検査後 `wait_commit`, `cs_`, `copy_` drainし、target-weightを含み得る `exec_`, `segments_[T]`, `work_[T]` を全Tでdestroy/resetする。`commit_exec_`/commit workはsession state commit専用でtarget weightsを含まないことを確認して維持可能（現行head retirement comment `src/core/verify.cpp:253-255`）。session KV、GDN/QSA/PLE recurrent state、residual/session buffers、doorbell、cache residency maps/hit graphsは、target dense address参照がないものを保持する。state bufferを壊す必要はない。
4. Verifierをinactive/blockedにし、callbacksを閉じたまま提案 `native_dense.enter_layer_bank({true},err)` を実行。提案ではbank allocationが失敗すれば元owners/tableはFullのまま (`proposed/src/core/native_dense.cpp:302-326`); 成功後はnative-only rowをwithdrawし、canonical data含むそのtable refsは非resident/nullになる。layer 1 PLE native keyの別publication (`generate.cpp:2429-2437`) も同じtransactionでwithdrawする必要がある。Canonical arenaとPLE value/norm/stateは維持。
5. layer passごとにPrefillが直前pass完了と全callback終了を確認し、提案 `activate_layer(layer, stream, {true}, err)`。このAPIは同stream同期、旧viewをclear、該当layer packed snapshotsをupload・同期してからcomplete overlayをswapする (`proposed/src/core/native_dense.cpp:329-359`)。次layerのactivate前に前layer view利用がすべて終了することを同じqueue boundaryで保証する。`Prefill::run_layer_major` はcancelチェックでfalseを返し (`layer_major.inc:293,306`)、chunk callback falseもあり (`:343-355`)、exceptionもcatchしてfalse化する (`:411-417`); RAII `Restore` は `:219-231` でPrefillのfield/callbackを戻すだけで、dense owners/graph/PLE publicationは戻さない。外側leaseはqueue drain保証 (`:232-244`) を得た後、必ずview clear→`restore_full(stream,{true},err)` を行う。
6. `restore_full` falseは通常allocation OOM時にBank/viewを保持し、withdrawn tableも公開しないまま返る (`proposed/src/core/native_dense.cpp:361-400`、特に `:373-379`)。このときbank owner、snapshots、必要なactive view storageは生存し、decode再開禁止。callerはrestoreをretryするかprocess fail-stop。copy/drain/free等結果が不確かなケースはproposalがfail-stopする設計。cancel/throwの通常復帰は、callback unwind、Prefill側checked drain、view clear、Full復元とPLE再bind、完全owner/table validationの後に限る。失敗した復元/退役で通常returnしてはならない。`activate_layer` のunknown layer/host allocation falseは既存viewとbankを維持 (`:334-346`); upload/syncのruntime不確実性はfail-stop。callbackの並行実行は不可。`on_chunk` はlayer-majorのfinal-layer passで同期的に呼ばれる (`layer_major.inc:343-355`)。MTP `prefill` は自身のqueueでgraphをlaunchしfinal syncしてからreturn (`src/core/mtp.cpp:1138-1271`)。callback in-flight中はactivate/restore/次のresidual reuseをしない。
7. Full restoreとPLE再bindが成功し、target pointer coverageを検証後に、`session_capture(wt,...)` をrecapture。全session graphsのcapture成功とVerifier resume可能性を確認してからnormal decode、prompt failure/cancel応答、conversation RESTOREを続ける。Verifierのwindow graphsは必要時にlazy recaptureするが、target full table復元前はlaunch禁止。

## 現行head-release scopeとの差

現行 `STRATA_PREFILL_RELEASE_HEADS` は `run_prompt_with_mtp_experts` 内で長いlayer-major routeをguardし (`generate.cpp:185-197`)、head/MTP prepare、main stream同期、Verifier head retire、MTP head-reader retire、detach、prompt、stream同期、restore、resumeの順 (`:199-245`)。Verifier条件はidle/inactive-or-completed full single-device native MTP4 (`verify.cpp:218-229`)、そのhead retirementはcommit wait、`cs_`/`copy_` sync後に verifier exec/segments/workを消す (`:231-255`)。それでも `generate.cpp` の `gr.execs/posts/routes/shared/preA/preB/preP` には触れない。またhead refsだけを判定し、NativeDense projection/scratch ownersもPLE key別fieldも扱わない。従ってこのhead scopeの `retire_prefill_head` をNativeDenseのretirement証明に流用できない。

MTPのhead-release APIはdraft head readerを退役するためのもの（`src/core/mtp.cpp:482-541`）。MTPのprompt-KV graphsは別owner/別weightを読む。R689の実コード追跡では `record_forward` がtarget `wt` から読むのはembedding sourceで、NativeEmbedまたはcanonical embedding経路、projectionはMTP自身のowners。ゆえに、callbackが同期完了しその条件を維持するならMTP prefill graph/weightsは保持できる。head pathの retirementを必要以上にNativeDense対応と解釈せず、`on_chunk` callback実行中の競合だけをleaseで禁止する。

## Saved canonical table + native overlay を渡す小API案

既存 `LayerView` は `WeightTable const&` とlayer番号だけを持ち、`get()` は必ず単一tableの`find()`に進む (`include/strata/core/layout.hpp:72-82`)。既存 `Prefill::Impl` はinit時の `const WeightTable* wt` を持つ (`src/prefill/prefill.cpp:428,769-792`)、layer-major executionは各層で `LayerView(*m.wt,l)` 等を作る (`:2068` 周辺) 。現状APIにoverlayを渡す経路はない。

最小の型案は `LayerView(const WeightTable& canonical, int64_t layer, const NativeOverlay* overlay=nullptr)` と `get(suffix)` のoverlay-first lookup。overlayは提案 `NativeDense::layer_view()` のnative-only `map<string,WeightRef>`（各値はsaved original WeightRefのcanonical metadata/dataを保ち、native_dataのみbankを指す）を借用する。非overlay nameはcanonical tableからlookup。Prefillのlayer-major per-layer dispatchに `const NativeOverlay*` を一時引数で渡し、layer終了前にだけ借りる。Base canonical rowsを書き換えたり、overlayを独立のcanonical tableと誤認したりしない。提案の `layer_view()` 自体は**native overlay mapだけ**で、saved canonical full WeightTable APIではない。proposal `activate_layer` はwithdrawn canonical tableを再構築せず `s.original` をmapに置く (`proposed/src/core/native_dense.cpp:334-357`)。したがってこのcomposite lookupが必要。

注意: 現 `core::block_layer` / pre/post helpersの多くは `const WeightTable&` を受け、内部で自身の `LayerView` を作る (`src/core/session.cpp:283-289`; `src/core/layer.cpp` の各layer functions)。上の案を本当に小さく適用するには、layer-major direct call chainが使うentryを `LayerView`/resolverへ渡すoverloadに寄せる必要がある。`WeightTable`を丸ごとcopyしたり、withdrawされたtarget table refsをその場しのぎで変更する案はこの提案APIには存在せず、採用済み実装と書いてはならない。特にPLE native keyは別 `ss.ple.w.*` pointerなので、overlayのlayer1行と同期して明示bind/revokeが別途必要。
