The technical claims hold with the stated scope. In the pinned NEO source, `DumpZEBin` defaults false; the Level Zero module path dumps a decoded Zebin blob, and the archive decoder has a separate dump site. `dumpFileIncrement` tests base/suffixed names then writes, so concurrent writers can race; default output is the current working directory and `ForceLoggingDirectory` redirects it. The Level Zero specification defines `localMemSize` as local memory used per thread group. NEO maps it to a descriptor total from the kernel object's dynamic local-argument state: later local arguments are aligned by their required alignment, sizes are accumulated, and the dynamic end is rounded to 1 KiB. Compiler-resolved mode adds inline SLM; runtime-adjusted mode uses a nonzero dynamic total or inline SLM when no dynamic args were supplied. These are pinned-NEO implementation semantics, not proof the installed `1.17.39395+14` driver has the same source/build. The installed driver binary hash in eligibility (`dfa844e5afd8e8f74bf5ce9da3ea2837706d9116bc8efeaed90efba5acaf7b1c`) does not identify its source revision. Preserve the report's deployed-driver caveat and do not infer BMG command encoding, bank traffic, residency, or occupancy from `.ze_info` or source payload.

## Later evidence and operational digest

Main's separate capture receipt (`own-qsa-native-zebin-serial-smoke-v1.json`, SHA-256 `8405d680425692de4bcbd26345dcd3bac42cf8cb6046a9484afa2f97dff0deb5`) and offline decode (`qsa-native-disasm-v1.json`, SHA-256 `07fe7d596b6da947e58a1f6b0ba57f1812b9766b512ca2e664e036b2788e112f`) are later evidence, not corrections to R1056. The exact captured module is 306,232 bytes, SHA-256 `049221cb25a6c6e9c36f9e96a7cdee08d4309e857c21aa14e468beec9d8ab896`; the decoded target symbol is `prefix_batch_impl<33,false,false>`. Its assembly contains 16 static `dpas.8x8` instruction lines, and `.ze_info` reports `grf_count: 128`, `slm_size: 32`, and nine dynamic local-argument descriptors. This establishes native DPAS presence and those static fields in this captured module. Instruction count is not dynamic execution/utilization; it does not alone prove which QK/PV regions execute DPAS, or speed. Static `slm_size` and local-argument descriptors do not give the live localMemSize after arguments, encoded dispatch allocation, concurrent residency, or hardware saturation. The smoke artifact is not the 120-call model-prefill measurement, so keep its kernel/service association bounded to the captured fixture/module and the separately pinned source/service evidence.
