One narrow parser hardening gap remains: `parse_qsa_profile()` and `parse_profile()` build dictionaries with `dict(re.findall(...))`, so duplicate keys are silently last-value-wins, and neither parser enforces an exact key set. The current executable formatter is fixed and source-pinned, so I found no route for malformed duplicate keys in this actual run; this is not evidence of a false PASS. A future fixture/fuzzer should reject duplicate and unknown keys explicitly. The fine parser also checks each aggregate field against expected totals but does not independently recompute every aggregate vector/counter from the 48 parsed rows; the pinned formatter does construct that row by summing those rows. This is another parser defense-in-depth opportunity, not an observed bad aggregate.

## Caller, event lifetime, and failure handling

The admitted route owns the fine observer only when `STRATA_PREFILL_LAYER_MAJOR_QSA_PROFILE=1`, and requires the coarse profile flag. It allocates fixed 48-row/seven-section storage and reserves 2 MiB for coarse plus fine owners. Fine owner and borrow declaration order places the checked draft-upload lease and `Restore` later; reverse destruction retires the lease, restores borrowed fields, restores the fine observer slot, then destroys its events while the fine/coarse owners remain alive. On success, the lease is retired before fine `finish`, `close`, and `emit`. This matches the existing coarse lifetime pattern recorded in R727.

All seven intervals begin and end around one whole QSA layer/chunk section. `chunk_retired()` is called only after the existing successful callback stream synchronization in `run_impl`; event query and elapsed-time retrieval therefore follow that drain, and pairs are reset for reuse only after both checks and elapsed retrieval succeed. On failure, the observer becomes unusable; it does not add a wait or drain, and its pending handles remain owned until normal owner retirement. Partial creation and event/query/destroy failures cannot emit `complete=1`: `close()` calls checked destroy, `fail()` clears `complete`, and the parser requires zero errors and complete output. If the outer checked retirement fails, existing fail-stop abort occurs while owners are live. This relies on the pinned own SYCL compatibility `EventDestroy` implementation; the task excludes CUDA/HIP validation.

The actual dispatch counter is called exactly once at the `qsa_prompt_attn_batch` decision and records the returned `matrix_used` result, plus actual `staged`, `T`, and `m.cap`. It is outside the optional dispatch observer. Dispatch bounds cap, positive queries, max chunk width 8192, expected chunks, and cumulative query overflow. `finish()` requires all seven sample counts equal expected geometry, actual dispatch and query sums match geometry, no pending event pair exists, all GDN rows are zero, and QSA cap is positive/consistent. `staged_chunks` is bounded by expected; the model parser further requires every QSA chunk staged for this exact selected configuration.

For this request the engine-prefill length is 78,452 after its reserved final token, so `ceil(78452/8192)=10`; QSA interval four gives 12 rows × 10 chunks, 36 GDN rows with no fine samples, 120 total fine samples per section, and 941,424 aggregate query-rows (`12 × 78,452`). The parser checks these numbers and cap 2051 per QSA row. At 262,144/C8192, the observer's corresponding fixed-output upper geometry is 384 QSA chunks / 3,145,728 aggregate query-rows; the model gate does not claim this physical-context result. Output remains exactly header + 48 rows + aggregate, bounded well below the parser's 64 KiB diagnostic allowance at the documented 1024-byte row budget plus header.

## Model-gate dependencies and residual scope

The fine parser depends on the native stderr captured by the owned runner and on the binary/source pins checked before and after launch. It checks the coarse and fine output separately, enforces the shared wrapper denominator, verifies native/server exit and experiment environment, verifies exact request/journal and selected FP32 capture, and rejects native cleanup/retirement error text. A failed fine observer prevents receipt completion, even if inference itself returns normally. This is the right gate relationship for diagnostic failure.

The parser infers the 12 QSA layers by the current fixed 4-layer pattern (`l % 4 == 3`), while the product observer initializes expected rows with `core::is_qsa_layer(g,l)`. Those agree for the pinned 48-layer geometry (`qsa_interval=4`). The model gate's model identity/metadata and exact request gates make that a bounded, pinned assumption; if the gate is generalized to other geometries, it should derive QSA rows from recorded/model geometry instead of keeping the literal modulo-four rule. I found no current geometry disagreement.

Queue values are barrier-to-barrier intervals, nonexclusive and include host gaps; host spans include marker submissions and helper waits. They are not kernel service, exclusive critical-path shares, or link traffic. The diagnostic cannot support clean speed, task quality, full 262,144-context correctness, or RESTORE.
