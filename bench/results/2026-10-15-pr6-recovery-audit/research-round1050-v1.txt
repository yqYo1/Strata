# R1050 — exact K global-to-SLM staging decision support

Classification: decision support; source-only. The required source hash matches `fa505d02e2b24f7cb6948033921fa697c8aeb58e6f4df6d873f13e5a7918e36b`. Eligibility says the serialized serial model cohort closed at 725.7 median and the same-path attention service binding is 120 calls / 37.077867 s in a 78K prefill, not evidence of physical saturation. The actual subgroup-softmax cohort remains Main-owned and active; its partial results do not qualify subgroup speed or authorize touching it.

## Current mapping and fixed contract

In `prefix_batch_impl<33,false,false>` with `Cells=32`, `Dim=256`, `Workgroup=128`, `SG=16`, K staging flattens the destination matrix: `i=tid+128*n`, `cell=i%32`, `d=i/32`, then loads `packed.k[rows[cell]*256+d]` and writes `kv[d*32+cell]`. There are 8,192 BF16 values, 64 iterations per work-item. At a fixed `d`, each SIMD16 subgroup's 16 lanes read one 16-bit value from each of 16 selected rows; it writes 16 adjacent values in SLM. Since packed K is row-major by selected row, the global lane pattern is strided by 256 BF16 elements (512 bytes) when rows are adjacent, while the SLM write is contiguous. The later K matrix load consumes row-major `[d,cell]` with leading dimension 32, in increasing `d` blocks of 16. V is the complementary mapping: `cell=i/256`, `d=i%256`, global row-major reads and `kv[cell*256+d]` stores; do not change it as part of a K-only trial.

Keep the exact selected-ID sequence and row validation (negative ID, `live_cells`, logical-page bounds, page-table mapping, physical-page bounds); tail/missing rows remain `-1` and stage zero. Keep BF16 bits via integer copy/bit-cast, without a value conversion. Keep the 32-cell tile, score pitch 33, matrix subgroup collective/order and QK/PV loops, FP32 score/online max/normalizer/alpha/accumulator operations and rounding, and all barrier ownership. The post-row barrier publishes row IDs; the post-K barrier must still precede QK. Every work-item must encounter workgroup barriers; each joint-matrix operation must remain converged across its whole SIMD16 subgroup. `joint_matrix_load` still sees the same valid 4-byte-aligned base and leading dimension 32. Only remap K's load/store ownership. These invariants make the staging a pure BF16 bit permutation; arithmetic and online-state order need not change.

## Plausible same-path remaps and counterevidence

**First minimal candidate: four-wide row vectors with blocked thread ownership.** For `tid` in `[0,128)`, use `cell=tid/4`, `q=tid%4`; for `block=0..15`, load the four consecutive values `packed.k[row*256 + 16*block + 4*q + t]`, `t=0..3`, and store each to `kv[(16*block+4*q+t)*32+cell]`. This is a bijection over the same 32x256 tile: one row per cell, no shared writes, same row test and zero for missing rows. Adjacent groups of four lanes cover four adjacent 4-BF16 runs from four rows; a subgroup covers 4 rows x 16 K dimensions per block. Compared with current 16-row x one-dimension subgroup accesses, this can reduce scattered sectors and expose contiguous row loads if the compiler emits vector/block accesses. It also changes SLM writes from contiguous to strided; for a fixed `t`, the four `q` lanes of a cell store 64 bytes apart. On Intel bank mappings that can alias banks and serialize; exact B570 bank behavior is not inferable from source. Scalar stores, register pressure, address arithmetic, and loss of current contiguous SLM stores can erase global-load gains. Adjacent/nearby selected rows may also let current scattered loads reuse cache lines.

Use scalar `uint16_t` loads first, or a documented vector API after proving base/row alignment and vector bounds. `row*256` preserves alignment only if the allocation base does; don't type-pun the `uint16_t*` or assert alignment without proof. A 4x4 register transpose/shuffle could restore contiguous cell stores, at the cost of subgroup permutes; it must stay subgroup-local and keep unique destinations.

**Blocked/register staging.** Load contiguous row runs to registers, transpose a small cell-by-dimension tile, then store to SLM. This may retain global utilization and contiguous local stores, but adds shuffles/registers. Direct scatter is simpler but may conflict in SLM banks. Keep `kv[d*32+cell]`; pitch/padding changes the matrix consumer and local footprint.

**Collective load is conditional.** Intel's experimental `sycl_ext_oneapi_group_load_store` distributes a common contiguous range; all members must use the same iterator, with supported group and truthful alignment/full-group properties. It cannot directly load 16 different row bases. A subgroup-per-row variant has a common base but changes ownership and still needs a transpose to `[d,cell]`; feature macro/API and generated code must match the deployed DPC++. Do not assume portable async global-to-local copy or useful prefetch: prefetch neither fixes coalescing nor publishes SLM data/replaces the barrier. Intel ESIMD block-load/prefetch is a separate path, unsupported by this audit.

## What can and cannot be inferred

Intel's GPU memory guide explains that scattered small objects can waste cache-line traffic, while reuse can stay cached. Each selected row contributes 512 bytes and is reused as d advances, so current accesses may reuse lines despite scattered subgroup addresses; random IDs and clustered IDs differ. Reordering helps only if generated accesses issue fewer global transactions without harming cache reuse or increasing SLM bank conflicts. Actual bank mapping, stores, cache hits, transactions, occupancy, spills and bottleneck are unknown. The 37.078-second binding and 725.7-tok/s median prove neither K staging is limiting nor a speedup.

R1043/R1044 already covers C16/C64, 64-work-item, general overlap, subgroup-softmax and prior packed paths. Those are not reopened here: C64 regressed (64.05% at 32K, 50.26% at 128K), C16 was mixed and not adopted, and no old private packed candidate should be retried. This report adds only the exact producer-side K transpose alternatives; no code or measurement is proposed as an adoption claim.

## Bounded discriminating experiment for Main

After the active subgroup cohort closes, compare one K mapping at a time against `<33,false,false>` with identical build/runtime, inputs, clustered and sparse/random IDs, tails/malformed pages, warm state and serialized paired order. Keep strict correctness/fault and physical-262144 gates; compare staged K bits and output/reference before timing. Measure the same QSA component dependency path (row checks, K stage, barrier, matrix use, completion), and report samples. Main may inspect generated code/resources and cache/memory evidence during its serialized run. Reject wins that shift cost to SLM stalls/spills or another stage.

Only a component winner clearing every gate proceeds to paired serial whole-model samples on the same selector/build and fixed long-prefill workload. Record source/binary, samples, correctness/faults and decision. Subgroup partials do not qualify whole-model speed; retain the 262144-query failure. No hardware saturation or speed is predicted here.
