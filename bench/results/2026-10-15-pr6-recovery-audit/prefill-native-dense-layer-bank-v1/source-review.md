`load(..., include_ple_key=false, capture_layer_bank=false, layer_bank_ram_limit=3GiB)` preserves existing callers and default GPU layout/upload path. Explicit startup opt-in copies original GGUF packed bytes into owned RAM while the original validated GGUF mapping is present. The initial GPU upload uses those same snapshot bytes; no D2H recovery or subsequent disk reread occurs. Existing architecture/shard/shape/block/span/type checks still run. Snapshots record name, numeric layer, shard, tensor payload offset, GGUF data start/file size, full original WeightRef metadata and original bytes. Their data remains immutable and alive for this NativeDense object's lifetime. The saved current full-owner pointer is updated only after a completed full restore; tensor metadata/payload/provenance are unchanged. Opt-in startup uploads, pending-owner cleanup and Full-state destruction also fail-stop on runtime uncertainty; default legacy error behavior stays unchanged. The 3GiB default capture budget bounds packed payload; vector/string/map metadata is additional. A capture-budget or host-allocation failure before load publication retains the old table unchanged.

The states are Full and Bank. Every transition requires explicit caller attestation that ALL relevant readers have retired. That attestation is an integration contract, not proof supplied by the component: caller must destroy affected token/decode/MTP/verifier graphs, drain every owning stream/callback, exclude table mutation and forbid normal readers until full restore and graph recapture. No process environment changes occur. All component copies use an explicit caller-owned ordered stream, with checked completion before publication; nullptr streams are rejected.

`enter_layer_bank` first validates every original table row and corresponding allocation owner, then allocates one max-layer bank while all originals remain alive. Bank allocation failure leaves all original owners and published rows intact. At the release boundary it withdraws affected normal-table rows (data/native_data/native_q8_1=null, resident=false; all type/shape/provenance remains unchanged), then checked-frees original native owners. Withdrawn rows are deliberately invalid for normal inference, including canonical fallback. The full canonical allocation stays physically resident. Unaffected canonical rows, including all HC norms, remain available. No fallback to skipped canonical rows is invented. Normal reader exclusion is mandatory: this component does not retrofit a global WeightTable access gate.

`activate_layer` builds a complete private map of matching original WeightRefs before touching the old view. It validates bank extents and restores original canonical metadata/pointers in that private view; only native payload addresses point into the bank. Each native matrix begins at a 256B-aligned bank offset. After caller retirement plus checked stream completion, it withdraws the old view, uploads this layer's exact packed bytes, checks completion, then publishes the complete const map. Unknown layer/host allocation failure leaves the prior view and bank contents intact. There is no second bank or overlap upload. A view is borrowed only until the next activate/restore; keeping copies/pointers past that point is forbidden. Integration must compose this overlay with the retained canonical table when constructing the prefill view; the returned map is intentionally only the native projection overlay, not a complete LayerView.

`restore_full` validates the withdrawn table, drains the owned stream, allocates all original-sized owners before changing the bank/view, uploads every snapshot, checks completion and revalidates table identity. Only then it republishes every original WeightRef with the matching new native owner, clears the view, checked-frees the bank and returns Full. Ordinary OOM frees only unsubmitted new allocations with checked operations and returns false with the old bank/view intact. Uncertain allocation errors, copy/drain/free errors, owner mismatch after release, and destroying a Bank-state object fail-stop using abort before destructors can destroy potential DMA owners or snapshots. Fail-stop is mandatory for uncertainty; it is not a claim that recovery succeeded. A caller receiving false while in Bank must retry restore or fail-stop; it must never resume decode. All graph addresses must be recaptured after restore, even if some allocations happen to reuse addresses. RESTORE state rollback is outside this component.

Capacity from the already committed target-model metadata (not a new GPU measurement): 300 original matrices require exactly **2,116,951,040 B new owned RAM payload**. The maximum native-only layer is **layer28, 50,918,400 B**; every target matrix size is already a multiple of 256, so alignment adds zero payload padding for this model. Native-only device recovery is **2,066,032,640 B**. Layer47's 44,646,400 B is not this native-only maximum: it belongs to the largest combined expert+dense layer used by the earlier capacity plan. The canonical arena **1,538,035,200 B stays resident**. Existing native Q8_1 scratch stays resident unchanged: max input6144 /32 *36 = **6,912 B**. No head, expert cache, session, KV, canonical norm, dequant or GEMM scratch owner is released here. Allocator/runtime bookkeeping is not included in payload sums. Entry and full restore briefly require full native payload plus the max-layer bank: **2,167,869,440 B**, plus the unchanged scratch; callers must reserve restore headroom. Snapshot RAM persists after restore for later prompts and is not a request-scoped allocation.

Main's norm correction is preserved: half0 uses this layer's FFN norm, half1 next layer's attention norm; only one 40,960B lookahead norm would be needed if the canonical owner were later banked. This component keeps the entire canonical owner resident, so it adds no norm pool or lookahead allocation. Canonical banking would be a separate component and cannot count this recovery twice.
