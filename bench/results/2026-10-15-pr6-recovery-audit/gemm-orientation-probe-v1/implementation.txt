Input, descriptor and storage contract
Synthetic deterministic IEEE FP16 X/W use integer splitmix64-derived values and explicit _Float16 conversion, with separate fixed X/W seeds. These are synthetic hot operands, not real weights, seven native source-format rotation, dequantization, streamed slot lifetimes or a weighted model workload. No histogram weighting or aggregate speed/adoption decision is emitted. Each cell logs input FNV1a64 hashes (including sentinel guard bytes), geometry and role; Main should also record binary/source hashes, exact runtime/toolchain/driver and effective environment.
Arms share one binary, one oneMKL library, the same runtime compute in-order queue/device/properties and exact X/W/Y addresses. One guarded FP32 output buffer is reused sequentially; diagnostic initial C is re-uploaded identically before each call. Arm0 is row_major(nontrans,trans,T,N,K,X,K,W,K,Y,ld); arm1 is column_major(trans,nontrans,N,T,K,W,K,X,K,Y,ld). Inputs are FP16, alpha1, beta/output FP32. A nonnull current Gemm::f16 wrapper is validated against the direct row-major call on the same queue/pointers/ld. No GEMM workspace or extra matrix transpose is introduced.
Outputs have16-float guards at both ends and17 padding columns per row, all sentinel12345.25. Inputs have16-half guards at both ends; entire X/W bytes are read back after validation and required unchanged. Explicit runtime wait drains checked compute and transfer queues while storage is still alive; Allocation also follows existing runtime lifetime behavior. The benchmark uses no returned-BLAS-event timing or per-call waits.

Validation (written, not executed)
Every16 shape/role cell runs beta0 and0.25, arms0/1 and current wrapper arm2, with reset identical C. All three full outputs are checked finite through pair comparisons; all guards/padding are checked independently. Every logical output is compared row/column and row/wrapper with declared pair bound
  abs(a-b) <= 2e-4 + 5e-5*max(abs(a),abs(b)).
An independent CPU double dot/value reference decodes exact FP16 inputs and includes beta*C. For ne<=12, every output is checked. For larger ne, Cartesian rows/columns include0,1,middle,last-1,last (deduplicated); last column borders padding and every padding element is sentinel-checked. The reference tolerance is declared before any run:
  limit = 2e-5 + gamma_K*sum(abs(x_k*w_k)) + 4*u*(abs(ref)+abs(beta*C)),
  u=2^-24, gamma_K=(K*u)/(1-K*u).
This is a conservative FP32 accumulation bound on the actual FP16 operands, not a tolerance for a different input precision or a guarantee of oneMKL's internal algorithm. Pair tolerance is tighter and independently declared. Failure aborts with row/column, actual error and limit; no tolerance adaptation exists. Per-arm CPU point count/max_abs/error_over_limit and full-output pair error metrics are flushed. Progress is flushed before every shape and diagnostic call. No GPU parity, padding safety or wrapper acceptance has been established until Main executes it.

Benchmark (written, not executed)
Separate --benchmark process; fixed synthetic inputs, beta0, same addresses and in-order queue. Per shape/role, first_call_in_cell is recorded separately for each arm, including host_submit_ns, drain_ns and batch_wall_ns. Only the first actual BLAS call in a fresh process might represent process initialization/JIT; later first_call_in_cell values must not be described as cold process/JIT results. Both arms then receive8 alternating ABBA warmup calls total (4/arm), followed by checked completion.
Each cell produces20 samples (10/arm) in repeated0/1/1/0 order. Repeats per sample are16 for ne1/12 and4 for all larger anchors. No call-level wait, readback, CPU oracle, event query, profiling marker or trace is added inside the timed block. Timestamp start, submit completion, then Runtime::wait completion yield host_submit_ns, drain_ns and batch_wall_ns. wall_ns_per_call is batch_wall/repeats. Runtime::wait includes compute and idle transfer queue drains and sticky async error checks. Drain is not exclusive device time: launch/scheduling/submission overlap and internal BLAS commands are included. No claim of full GEMM service from a returned oneMKL event is made. Output sample lines are flushed after completion, outside their timing windows.
Setup/upload/hash computation happen outside timing; post-cell output readback checks finite values and padding/end guards outside all sample windows, with no CPU oracle. All320 individual warm samples and32 first_call_in_cell results/order are printed; no lossy averages replace them.
