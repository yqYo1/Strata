## Decision

The production code already implements FP16 storage at every non-final layer-major residual boundary, restoring once into FP32 before the next layer. Explicit all-GPU placement for a known row count is representable: set `STRATA_PREFILL_LAYER_MAJOR_R_GPU` to the exact batched row count, which is the only request that retains a partial final chunk. For the present natural history, that would be 78,452 rows. The planner and production allocation path still decide whether that request fits under the live free-VRAM/headroom budget; source capability and the previous FP32 prefix allocation do not prove admission. The next all-GPU run must require the emitted plan to say `residual_gpu_rows=78452`, `residual_host=0`, `residual_staging=0`, and must fail the gate if it backs off, rejects, or reports anything else.

No current checked-in runnable produces a dense teacher-forced NLL comparison for the current 78,453-token prompt. `prefill-teacherforced-nll-v1` is an unapplied, unbuilt source proposal. The existing selected-prefill-logit route can measure full-vocabulary logits and target NLL at selected input positions without requiring identical generated tokens, but its checked-in model runner is hard-pinned to the old 34,603-token fixture and 19 positions. It is a usable sparse gate for that fixture only, not the current input or full-row quality gate. Quality remains unqualified.

## Current production boundary and placement

`include/strata/prefill/layer_major_plan.hpp` admits only `fp32` and `fp16`. For explicit `R_GPU`, the planner rounds down to complete chunks unless the requested count equals `n`, in which case it retains the partial final chunk. An FP16 partial host tail reserves a one-chunk staging buffer. `auto` selects a whole-chunk prefix from the remaining GPU budget and reserves staging when needed; it is not a reliable all-GPU request unless the resulting receipt proves all rows fit.

`src/prefill/layer_major.inc` writes FP16 using `to_f16` into either the device residual bank or a shared FP16 staging buffer followed by D2H for host-tail rows. It drains before the stored bytes are consumed/audited. In `src/prefill/prefill.cpp`, a device-resident FP16 chunk is restored with `from_f16` directly into the live FP32 residual; host-tail FP16 first copies H2D into the same staging buffer, then restores. Model operators and live residual arithmetic remain FP32. The final layer forwards FP32. With all rows device-resident, the host residual write/read and FP16 staging path disappear; this does not prove the rest of the whole prefill has no host work or that throughput improves.

At current `C=8192`, input 78,453 means 78,452 batched residual rows. The existing FP32 `R_GPU=32768` receipt represents a 1,342,177,280-byte (1.25 GiB) device prefix. An FP16 all-row bank would request `78,452 × 10,240 × 2 = 1,606,696,960` bytes (about 1.497 GiB), with no tail/staging if admitted. It is about 264.5 MB more GPU residual allocation than the present FP32 prefix, while removing the FP32 host tail; these requested byte counts are not observed free-memory savings or admission evidence. No 256K placement/readiness follows from a 78K run: `prefill-capacity-current.ja.md` records a 5 GiB FP16 bank for 262,144 rows before other owners and placement constraints, and explicitly distinguishes capacity arithmetic from actual full-context admission.

Current task context for pairing is C8192, 78,453 input tokens / 78,452 batched rows, `R_GPU=32768`, FP32, native and canonical dense bank 1, head release 0, Direct 1, prompt mapping 0, no-token-graph. The closed arm1 selector diagnostic is separate: 346.6 tok/s; selected 768 rows exact and healthy, three clean component selections with one radix and two cyclic positives. It is not residual quality evidence. Arm2 is running and has not been inspected here.

## What can run now, and what it measures

1. `python3 bench/results/2026-10-15-pr6-recovery-audit/check_selected_prefill_logits.py long` is the exact existing checked-in command for the 34,603-token natural-history sparse diagnostic. It launches independent FP32 and FP16 native processes against identical input token IDs, captures 19 registered full-vocabulary positions, verifies coverage and finite logits, and computes selected target-NLL deltas and distribution comparisons. Identical input history is needed; identical generated output IDs are not. The command was **not run in R741**. Its fixed input and fixed positions mean it does not evaluate the present 78,453-token input. Its 19 correlated positions are diagnostics, not dense mean token loss or independent task examples.
2. The product interface `STRATA_PREFILL_LOGITS` plus `STRATA_PREFILL_LOGITS_POSITIONS` supports up to 64 selected full-vocabulary rows at the initial batched-prefill head. A separate pair of ordinary generator processes with the same token file/template and pinned recipe can therefore sample the current history and score target NLL/KL at selected positions without comparing generated tokens. No checked-in runner here accepts the present 78,453 input plus custom registered positions and writes the complete paired recipe, so this route needs a current-input runner/receipt before it is executable as the next gate. It is sparse evidence only.
3. `STRATA_PREFILL_NLL` is **not implemented in the current tree**. `bench/results/2026-10-15-pr6-recovery-audit/prefill-teacherforced-nll-v1/` contains a source diff, writer/comparator and fixtures only. Its intended command is to apply the exact pinned proposal to its exact base, build the configured SYCL target and fixtures, then launch one fresh standalone process per arm with `STRATA_PREFILL_NLL=<exclusive-output>` and the same complete natural-long input/recipe. It is **UNRUN and unavailable as a current-product command**. Before interpreting results, bind each receipt externally to model, input/template, source/binary, environment, C8192, context/KV/MTP, dtype and actual GPU-prefix/tail. The proposal emits one stable FP32 target NLL for each of all `n_input-1` targets, checks exact token/gold identity and complete row coverage, and caps raw output below 4 MiB. It documents an input-length representation limit through 262,144; that limit is not physical 256K admission, RESTORE, or quality qualification.
4. `STRATA_LOGPOS` / `Verifier::window_logprobs()` is a teacher-forced log-probability hook for verifier windows in generation/serve. It does not evaluate all targets from the initial chunked batched prefill history, and the NLL proposal explicitly rejects that route. Do not substitute it for the initial-prefill NLL gate. No current task/retrieval harness in the inspected artifacts provides paired, fixed-scoring outcomes for this current input. A later fixed held-out retrieval/QA/coding/reasoning set can compare rubric or answer scores despite differing generated tokens, but it is task-level evidence separate from token NLL and must record per-item outcomes rather than require byte-identical generations.

## Concrete next gate

The next quality gate should keep exact 78,453 input token IDs/template, current C8192/model/checkpoint/MTP/KV/source/binary/runtime and all other settings fixed. Use at least two independent FP32 storage-control processes to establish baseline spread, then the FP16 process. First choose a matched mixed-placement FP16 prefix/tail so the experiment isolates storage precision against the existing FP32 `R_GPU=32768` placement; the FP16 planner's actual rounded prefix and staging must be read from the run receipt and recorded. Then, as a separate placement experiment, request `R_GPU=78452` for FP16 to assess the all-GPU bank and removed host-tail transfer path. Do not compare its latency to the mixed-placement control as a dtype-only effect.

For quality, use the all-row NLL diagnostic once integrated and reviewed: require exactly 78,452 finite records with target at position `p` equal to input token `p+1`, then compare paired per-position delta distribution and aggregate mean against the observed FP32 repeat spread. Preserve early/middle/late, 8192-row chunk-edge and actual placement-boundary summaries. Add a small preregistered selected-logit sample for KL/top-two margin/top-1 flips and sparse residual checkpoints only if they can be captured without changing ownership/scheduling. Follow with a fixed scored task/retrieval set; token-sequence equality is descriptive and not an acceptance criterion. No numeric acceptance margin is established by existing evidence; agree one against FP32 repeatability before examining candidate outcomes.

Before all-GPU execution, preflight the current production planner/runtime admission using the actual request's emitted plan and headroom. Keep `STRATA_PREFILL_PHASE_AUDIT` off because the phase-audit path requires FP32. The FP16 boundary audit can verify sampled pack/store/restore mechanics, but it does not compare FP16 with paired FP32 quality; for any placement-boundary sample use rows on both sides of the actual boundary. Preserve individual run outcomes and fault/owner-retirement receipts. Do not run the quality or placement arm concurrently with other GPU work.
