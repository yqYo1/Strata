## Reader and state audit

The retirement helper waits `main_cs`, then the MTP drafter queue. The real MTP prompt callback (`draft_kv`, with `prefill` fallback) is invoked synchronously from the layer-major final-chunk callback; both paths return only after their own completion boundary, and the explicit MTP stream drain is retained before transitions. MTP's projection weights and prompt graphs are owned separately; the audited callback's target-table use is embedding lookup only. That is consistent with retaining MTP graphs/owners while dense projection owners are banked.

Session graph retirement destroys and resets the full, route, shared, post, and split-prefix arrays (`preA`, `preB`, all five `preP` arrays), then clears capture flags and graph metadata. The candidate uses checked graph-destroy results and stops if stream completion or destruction is uncertain. Entry refuses split capture. Recapture is requested only when the graphs were captured on entry, uses the original `captured_post` recipe, and completes before verifier resume/decode. The retained commit graph is session-state work; Verifier commit is waited first. Verifier retirement checks idle/inactive-or-completed full single-device state, waits pending commit, drains compute/copy, and retires `exec_`, every `segments_` and `work_` entry. Resume verifies the complete native publication and leaves verifier weight windows to recapture lazily. `head_recapture_checked_` remains set, so teardown retains checked destruction behavior after a dense-only cycle.

The separate native PLE key publication is withdrawn before dense owner release and rebound from the restored table before session graph recapture. During layer-major execution the active PLE key is supplied through a local copied `PleRun`; `ready()` is evaluated after adding the active-layer key. Normal table rows are not modified to expose the temporary bank. The activation callback runs after checked local drains, and the overlay is cleared only after pass completion drain. Enter-bank OOM occurs after readers were retired but before publication/free; the scope guard recaptures/resumes the original full state. Restore allocation OOM retains Bank and stops through the outer restore guard, so decode cannot resume. Uncertain callback, destroy, upload, or restore paths fail-stop.

## Specific residual proof gap

There is no actual-generator fake-transaction fixture in v2. Existing component and resolver fixtures do not execute `generate.cpp`'s combined state machine, so they cannot prove that every real SessionGraphs array and Verifier graph family was empty before the first native free, nor that all were rebuilt/reopened before the first later decode. Current diagnostics also do not record per-array graph counts/handles or a pre-free/post-recapture receipt. The candidate recipe correctly requires actual captured and uncaptured graphs, Verifier pending-commit and presence arms, native-only PLE, callback failure/cancel/throw, enter OOM, restore OOM, and recaptured decode/RESTORE checks; those outcomes remain unrun. The theoretical approximately 2.07 GB payload delta is not runtime reclamation evidence.

A useful first isolated fixture should seed each graph array independently (including all `preP` slots), Verifier segments/work plus a pending commit, and native-only PLE; expose a narrow observer at the last pre-free point and after restore/recapture to assert every expected owner/array is retired or rebuilt. It should include injected destroy/sync failures as separate processes and prove fail-stop before ordinary return. Keep it under Main's serial test/build/GPU ownership rules.

## Head-release combination seam

The current explicit exclusion is safe and preserves the separately implemented head-release route. A combined path should use one outer transaction: prepare the head owner, perform a single verifier retirement that covers both head and dense readers, drain/retire MTP head readers as needed, retire SessionGraphs once, withdraw both owner publications, run the prompt, restore both owner sets, recapture SessionGraphs, then resume Verifier once. Nesting the current helpers directly is unsafe because the existing head helper independently retires/resumes Verifier and the new dense eligibility correctly rejects an already head-detached verifier. This is a future API seam only; v2 does not attempt it.
