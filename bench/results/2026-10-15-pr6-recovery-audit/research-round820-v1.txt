# R820 — Typed chunk boundaries versus recomputation in low-precision recurrence scans

**Purpose:** knowledge collection. **Question:** for long affine or linear recurrences, when is it preferable to persist selected chunk states in FP16/BF16 while keeping local math FP32, versus rematerializing chunk intermediates from retained inputs and boundary state? This compares two implemented CUDA/Triton patterns from Mamba SSD and Flash Linear Attention (FLA), records their actual contracts, then separates transferable ideas from backend-specific assumptions. It makes no Strata adoption, speed, or model-quality claim.

## Novelty and overlap check

R759 surveys GPU prefix/partition scans such as decoupled look-back and hierarchical scan; its concern is inter-work-group ordering and work-map construction, not recurrent state. R782 maps 16-bit activations and recurrent-state dtype contracts across serving frameworks, but does not trace a chunk scan's materialization and recomputation graph. R592/R693 detail the fork's GDN state layout and work mapping; they do not compare typed chunk-state output with rematerialization. R786 is not an affine-scan survey: its object is graph destination fan-in, atomics, and floating reduction order. The incremental evidence here is source-level tracing of Mamba's FP32 state-passing accumulator plus selectable low-precision inter-chunk outputs, against FLA's chunk-bounded saved-activation policy that reruns WY/state intermediates in backward. This is not a new general GPU scan or mixed-precision survey.

## Method 1: persistent low-precision inter-chunk states, FP32 carry

Mamba SSD divides the sequence into chunks, computes each chunk's contribution (`_chunk_state_fwd(..., states_in_fp32=True)`), then passes the carry between chunks before `_chunk_scan_fwd` consumes the incoming state for each chunk. The `state_dtype` argument is explicitly “the dtype of the materialized inter-chunk SSM states”; the forward call supplies `state_dtype` as the state-passing output type, falling back to `C.dtype` when it is unset. The layout passed to the state-passing stage is flattened from `[batch, chunks, heads, headdim, dstate]` to `[batch, chunks, heads, headdim*dstate]`, then reshaped for the chunk consumer. The sequence can remain in its input activation type while the stored boundary tensor has a separately selected type. [Mamba `ssd_combined.py`, pinned at `e9594ce1c732d97440f0332fdc43170a2294dbfa`](https://github.com/state-spaces/mamba/blob/e9594ce1c732d97440f0332fdc43170a2294dbfa/mamba_ssm/ops/triton/ssd_combined.py)

The state-passing kernel makes the precision boundary unusually clear. It loads the initial state, each chunk contribution, and each decay scalar into FP32; updates its live carry as `scale * states + new_states`; and writes every non-final chunk result through the output tensor's selected dtype. The separately allocated final state is always FP32. Since the kernel retains the FP32 `states` value through its chunk loop instead of reloading its just-written output, narrowing an intermediate chunk result does not narrow this kernel's continuing carry. The low-precision rounding affects the materialized chunk input consumed downstream. This is a typed intermediate contract with local FP32 state, not a globally low-precision recurrent state. The allocation/call contract is part of the same pinned Mamba source tree; the kernel's explicit casts and stores are in [`ssd_state_passing.py`](https://github.com/state-spaces/mamba/blob/e9594ce1c732d97440f0332fdc43170a2294dbfa/mamba_ssm/ops/triton/ssd_state_passing.py).

The strongest case is a consumer that rereads one state matrix per chunk and accepts the narrow format directly. Each stored boundary halves logical bytes versus FP32 while the carry and final state stay float. More chunks add rounded boundaries; larger chunks alter work balance, scratch, tail waste, and dependency depth. This source contract establishes neither numerical acceptance nor speed.

## Method 2: keep chunk boundaries, recompute transient intermediates

FLA's Gated Delta Rule chunk path uses chunks of 16, 32, or 64 tokens. In forward it forms the WY representation `w,u`, computes one `h` state per chunk, and produces the output. In its custom autograd function, the saved tensor list includes inputs, gate/beta data, initial state, and chunk indices; it does not save `w`, `u`, `h`, or `v_new`. Backward calls `recompute_w_u_fwd` and invokes the chunk hidden-state kernel again to rebuild `h` and `v_new` before its gradient consumers. It therefore trades recomputation for not retaining these forward intermediates across the forward/backward gap; it does not avoid materializing them during the backward pass. [FLA `chunk.py`, pinned at `f470469e3192112814df229a4221454a195666a6`](https://github.com/fla-org/flash-linear-attention/blob/f470469e3192112814df229a4221454a195666a6/fla/ops/gated_delta_rule/chunk.py)

The associated hidden-state kernel initializes its recurrent matrix accumulator as FP32, promotes an initial state into FP32, applies the chunk's token updates to that local value, then stores one `h` per chunk in `k.dtype` at `[B, NT, HV, K, V]` (or `[B, NT, HV, V, K]` when `state_v_first` is selected). The optional final state is allocated as FP32. `K` is capped at 256, `HV` must be divisible by `H`, and the public path rejects chunk sizes outside 16/32/64. These are material constraints, not universal recurrence defaults. [FLA `chunk_delta_h.py`, same pinned commit](https://github.com/fla-org/flash-linear-attention/blob/f470469e3192112814df229a4221454a195666a6/fla/ops/common/chunk_delta_h.py)

`recompute_w_u_fwd` uses `BT=A.shape[-1]` and launches a grid over chunks and value heads; it allocates `w` with `k.new_empty(B,T,HV,K)` and `u` with `empty_like(v)`, so these temporaries follow the key and value input dtypes. Its kernel carries several tile accumulators in FP32 but casts selected transformed values to input element type before later dot products/stores. Thus “recompute” does not mean all-FP32 transient storage, and “chunked” does not mean only boundary bytes exist. It means the pass retains chunk organization and rematerializes the same typed WY intermediates when backward needs them. [FLA `wy_fast.py`, same pinned commit](https://github.com/fla-org/flash-linear-attention/blob/f470469e3192112814df229a4221454a195666a6/fla/ops/gated_delta_rule/wy_fast.py)

This training memory benefit is not a ready-made inference optimization. FLA rebuilds `w/u/h/v_new` for backward instead of retaining them across the autograd boundary. In one-pass inference, another input pass can add work without reclaiming later-use activations. An inference design could save selected FP32 chunk-entry states and recompute local prefixes for a second consumer, but FLA's `h` follows `k.dtype`; it does not implement that checkpoint policy.

## Comparison and useful decision boundary

| Contract | Persist typed boundaries | Recompute at chunk boundaries |
|---|---|---|
| Retained between dependent phases | Materialized per-chunk state in selected dtype; final state FP32 | FLA saves source inputs/boundaries for backward, then regenerates `w/u/h/v_new`; no saved copies of those intermediates |
| Local arithmetic | Mamba's state carry is FP32 through its chunk loop; chunk builder is requested in FP32 | FLA's local matrix accumulator is FP32, with typed inputs/selected intermediates and typed per-chunk `h` |
| Main cost moved | Less boundary traffic and capacity, but narrow values are consumed downstream | More arithmetic and input rereads in exchange for less long-lived saved-activation memory |
| Favor when | The low-precision boundary is consumed directly and repeated state traffic matters | Intermediates are otherwise live across a long training gap, and recomputation is cheaper than retaining them |
| Counterexample | State matrix is small, state traffic is not limiting, or boundary rounding changes outputs beyond tolerance | Inference has one consumer, or rematerialization repeats expensive projections/gates without enough memory benefit |

The two ideas can be combined: retain compact chunk metadata or selected boundary states, and recompute local intermediates only where consumers are separated in time. For the simple scalar/vector recurrence `s[t] = a[t] s[t-1] + b[t]`, each segment has an affine summary `(A,B)` and summaries compose associatively as `(A2*A1, A2*B1+B2)`. A scan can compute chunk summaries in parallel, prefix those summaries, then evaluate each chunk from its incoming state. A gated matrix recurrence such as Gated Delta Rule also has an affine view if state is flattened, but materializing each unrestricted matrix transform would erase its structured rank/update advantages; preserve the model-specific update, state layout, and gate ordering rather than porting the scalar monoid literally. This also fits non-LLM AR/IIR recurrences and segmented stateful signal pipelines when each segment has a compact composition rule.

## Xe2 B570 transfer limits

The decisions about what to store and what to recompute are algorithmic and do not require CUDA. A B570 implementation can express chunk passes with ordered SYCL kernels, subgroup/work-group collectives, global buffers, and FP32 local carry. The Mamba kernel's loop over chunks is a simple candidate for a standard SYCL kernel; it does not require an XMX instruction. FLA/Mamba Triton tensor layouts, `tl.dot`, warp-count tuning, and CUDA/Triton launch plumbing are not drop-in SYCL. Their benchmark configurations, warp assumptions, CUDA graph context, and autotuning choices are not B570 evidence.

If the recurrence's local matrix update benefits from matrix hardware, Intel's SYCL `joint_matrix` extension supports XMX-class devices but is experimental, subgroup-scoped, and requires querying the executing device's legal type/shape combinations. BMG-family combinations in the specification establish a route to investigate; they do not prove that a specific driver/compiler advertises the needed FP16/BF16 tuple or that a state scan should be reformulated as GEMM. Scalar affine state passing is likely a better first port than forcing each step through matrix hardware. [Intel `sycl_ext_oneapi_matrix` specification, retrieved 2026-10-16](https://github.com/intel/llvm/blob/sycl/sycl/doc/extensions/experimental/sycl_ext_matrix/sycl_ext_oneapi_matrix.asciidoc)

The source shapes also matter. Mamba's SSD state tensor is `[B, chunks, heads, headdim, dstate]`; FLA stores GDN matrix states in K/V order with optional V-first layout and uses only 16/32/64-token chunks in this route. Strata's existing GDN geometry and chunk schedule are different. A reusable design needs exact stride/span validation, preserved FP32 recurrent state and scalar gate/reductions, explicit short/tail paths, and shared state across chunks. Do not infer a B570 crossover from CUDA timing or a source-level `float32` accumulator.

## Evidence limits and discriminating experiment

No external performance measurement is used here. These are source-observed implementations and dtype/layout contracts, not measured results for B570, Strata, or model quality. The repositories and source pins are: Mamba `e9594ce1c732d97440f0332fdc43170a2294dbfa`, Apache-2.0; FLA `f470469e3192112814df229a4221454a195666a6`, MIT. No implementation text was copied. [Mamba license](https://github.com/state-spaces/mamba/blob/e9594ce1c732d97440f0332fdc43170a2294dbfa/LICENSE), [FLA license](https://github.com/fla-org/flash-linear-attention/blob/f470469e3192112814df229a4221454a195666a6/LICENSE).

For a future B570 component study, generate a stable FP32 affine-reference stream and keep identical coefficient/input tensors across arms. Compare (a) FP32 chunk-boundary storage; (b) FP16 and BF16 boundary storage with FP32 carry; (c) FP32 selected checkpoints plus local recomputation for the actual second consumer; and (d) a combined sparse-boundary policy. Sweep sequence length, state width, chunk size and tail, with coefficients covering decay near 0/1 and sign-changing updates. Record boundary count/bytes, recomputed FLOPs and input bytes, number of launches, each dependent path's latency, scratch/peak allocation, FP32 final-state error, per-chunk state/output error, and task-level checks. Preserve an FP32 reference and compare FP16/BF16 separately: range, rounding cadence, state recurrence and consumer tolerance decide format. Test chunk resets, physical context, restore/continuation, and tail behavior independently. This is a proposed experiment, not an adoption gate or a prediction of which arm wins.
