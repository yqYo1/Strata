# R794 — Statistical evidence design for paired inference comparisons

## Scope and relevance

This read-only review asks how sampling, pairing, stratification, multiple outcomes, random seeds, and rare failures affect comparison evidence. It sets no threshold, accepts no precision change, and makes no Strata claim. R791 already distinguishes tensor diagnostics, teacher-forced outcomes, and generated behavior; its 16-prompt localization exercise has no statistical sample-size rationale. This report considers how a later comparison could quantify uncertainty and define its coverage.

First define the target. With a fixed finite prompt list and deterministic decoding, the aggregate exactly describes those items; a confidence interval cannot make them representative of future prompts. An interval needs a sampling model: prompts from a defined population, random decoding runs conditional on prompts, or both. For hand-picked prompts, a bootstrap relies on exchangeability and cannot establish coverage of an unspecified deployment distribution. Report the finite-set score too, and name the population each interval represents.

## Which observations carry uncertainty?

For autoregressive comparisons, the outer sampling unit is usually a prompt or independent prompt family. Tokens share prompt content and generated history. Treating within-sequence tokens as independent is pseudo-replication: it substitutes token count for independent prompts, usually narrows standard errors, and can hide long-prompt tails. For a token-weighted estimand, retain tokens within each sampled prompt and recompute the weighted aggregate in every prompt-level resample.

For shared prompts, compute each prompt's paired contrast and resample prompt IDs with both arms together. Pairing removes prompt-difficulty variation when outcomes are positively correlated; an unpaired analysis discards that covariance and is often less precise. Unpaired analysis fits separate prompt samples or invalid matches. A paired t interval is efficient for well-behaved differences; bootstrap or randomization tests make fewer distributional assumptions and handle nonlinear aggregates, but cannot fix biased or tiny samples. Dror et al. discuss paired tests for NLP; Koehn demonstrates paired bootstrap for a corpus metric. Neither proves validity for long autoregressive generations.

| Design choice | What it estimates | Main advantage | Main failure mode |
|---|---|---|---|
| Paired prompt bootstrap | Prompt-population distribution of arm differences, conditional on the observed run protocol | Preserves shared prompt difficulty and supports nonlinear scores | Small or unrepresentative prompt sets give poor population coverage; resampling tokens breaks clusters |
| Unpaired arm analysis | Difference between two separately sampled arm means | Fits independent prompt samples or genuinely unmatched observations | Throws away valid within-prompt pairing and may inflate uncertainty; overlapping separate CIs are not a test of the paired difference |
| Nested prompt × seed analysis | Prompt uncertainty plus within-prompt decoding variability, if both are in the target | Separates hard prompts from stochastic output variation | One seed per prompt cannot identify these variance components; few seeds estimate them poorly |
| Token-IID standard error | A token mean as if every token were an independent draw | Simple calculation and often narrow interval | Sequence dependence and prompt clustering make the effective sample size much smaller than the token count |

For sampled decoding, repeated seeds answer a different question from more prompts. One output per prompt mixes prompt and decoding variability; it cannot separate them. Repeating prompts under independent seeds estimates within-prompt sampling variation, while distinct prompts estimate generalization across prompts. A nested bootstrap can resample prompts and then seeds within prompts. Seeds are irrelevant to deterministic decoding; for stochastic service behavior, report both variance components.

A shared seed is a block label, not proof of useful coupling. Sampling the same random stream against different token distributions can diverge early and then produce different contexts. Measure the paired covariance instead of assuming seed matching reduces variance; if seed replay is not exact, record that and treat runs as stochastic replicates. HELM reported variation across three in-context-example selections and warned that 1,000 instances and three seeds could leave claims uncertain. Those seeds concern adaptation, not decoding, and do not prescribe a seed count.

## Strata, metrics, and stopping

Task and context strata can expose concentrated changes hidden by an average. Define strata before comparing arms, such as task family × context band, sample within each, and report counts and paired intervals. Fix aggregate weights in advance: equal weights answer a macro-average question; deployment-frequency weights estimate a target mixture. Balanced sampling can cover a sparse long-context group, but reweight to estimate deployment mix. Report the weighted total and stratum tails. Selecting the worst slice after inspecting many creates selection bias and multiplicity; confirm it on new prompts or adjust for selection.

State the inferential family for multiple metrics. If the claim is that at least one changed, or an endpoint is selected after inspection, unadjusted tests raise false-signal risk. Holm controls family-wise error for a declared family; simultaneous bootstrap intervals can preserve metric dependence. If every co-primary outcome must meet its criterion, state that conjunction and avoid cherry-picking. Keep exploratory dashboard metrics descriptive. HELM's scenario-by-metric matrix shows the cost of a universal score and leaves aggregation to stakeholder priorities.

Rare failures need event-level denominators. Define the independent trial (prompt or shared-source prompt family) and failure in advance. With zero events, the estimated rate is zero but risk is not: the approximate one-sided 95% “rule of three” upper bound is 3/n for n independent trials. Hanley and Lippman-Hand explain this zero-event trap. For a failure limited to one context or task stratum, overall n says little about that conditional rate; sample and report that stratum. Keep event severity and counts visible beside averages.

Use a fixed sample count and one planned analysis when possible. Repeatedly checking an ordinary 95% interval and stopping at a favorable look breaks nominal coverage. If interim looks are needed, prespecify alpha spending or use a time-uniform confidence sequence; Howard et al. derive the latter under explicit process assumptions. This does not license adaptive prompt selection or changing metrics. For a pilot, inspect blinded variance, then freeze the plan before revealing arm differences.

## Bounded prospective sampling protocol

For one future paired comparison, freeze revisions, prompt formatting, tokenization, context limits, scoring, and a finite prompt frame. Define four cells before scoring: two task families × two context bands. Draw 64 distinct prompt clusters per cell (256 total) with a recorded random seed; keep prompts from shared documents/templates together. Fix population weights in advance and publish per-cell results plus a weighted aggregate. Balanced sampling covers subgroups; it does not assert equal deployment frequency.

Run three generation seeds per prompt on both arms, paired by prompt and seed ID, with identical non-precision settings. Store each prompt outcome and predeclared event indicators. Resample prompt clusters within cells, keeping paired arm/seed results together; resample seeds within prompts only when decoding randomness is in scope. Report prompt-level and nested prompt/seed analyses as appropriate. Apply the declared metric family once after the fixed sample. Stop at 256 prompts; if intervals are too wide for the owner's separately chosen meaningful-change margin, report unresolved and design a new study. This bounded protocol is not a threshold or proof of adequate power; review the cap and seed budget against variance before use.

## Sources and limits

1. Rotem Dror et al. (2018), [“The Hitchhiker’s Guide to Testing Statistical Significance in Natural Language Processing”](https://aclanthology.org/P18-1128/), ACL. General NLP test-selection guidance; not an autoregressive inference study. ACL lists post-2016 material under CC BY 4.0; no text or code was reused.
2. Philipp Koehn (2004), [“Statistical Significance Tests for Machine Translation Evaluation”](https://aclanthology.org/W04-3250/), EMNLP. Empirical support for paired bootstrap over shared sentences on BLEU, with older MT tasks and assumptions that do not settle LLM sampling design. ACL lists pre-2016 materials under CC BY-NC-SA 3.0; no reuse is proposed.
3. Percy Liang et al. (2023), [“Holistic Evaluation of Language Models”](https://arxiv.org/abs/2211.09110), TMLR. Useful evidence on scenario coverage, metric matrices, limited random-seed budget, and paired bootstrap in human evaluation. The paper's seeds are in-context-example selections, not decoding seeds; arXiv lists the paper under CC BY 4.0.
4. Sture Holm (1979), [“A Simple Sequentially Rejective Multiple Test Procedure”](https://doi.org/10.2307/4615733), *Scandinavian Journal of Statistics* 6(2):65–70. Establishes family-wise step-down testing; applying it to model metrics requires defining the claim family first. Rights remain with the journal/archive; no implementation or text was reused.
5. Steven R. Howard et al. (2020), [“Time-uniform Chernoff bounds via nonnegative supermartingales”](https://doi.org/10.1214/18-PS321), *Probability Surveys* 17:257–317. Supports time-uniform inference under its stated stochastic-process conditions; it does not validate adaptive benchmark selection. No code was reused.
6. James A. Hanley and Abby Lippman-Hand (1983), [“If Nothing Goes Wrong, Is Everything All Right? Interpreting Zero Numerators”](https://doi.org/10.1001/jama.1983.03330370053031), *JAMA* 249(13):1743–1745. General rare-event reasoning, not a model evaluation paper. Copyright remains with the publisher; no text was reused.

These are statistical-method references, not device or version evidence; none measures Intel SYCL, a GPU, Strata, or this model. The operational protocol is a synthesis for a possible future study. It does not establish adequate power without an estimand, variance estimate, and practical margin chosen by the study owner.
