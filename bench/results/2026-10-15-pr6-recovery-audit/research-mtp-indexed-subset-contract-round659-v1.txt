# R659 — MTP indexed-subset state contract for a no-copy Q6_K draft head

Date: 2026-10-15 JST. Read-only source audit of current root and public A artifacts. No implementation or proposal branch/file was read or changed. No build, test, GPU, process, `py_compile`, Git, cleanup, private B, live ON log, or environment inspection was performed. Only this report was written.

## Finding

Current MTP uses `dhead_ != nullptr` as both “a draft vocabulary subset is active” and “the subset head is a gathered copy.” Those happen to be equivalent in today's implementation, but cease to be equivalent if a Q6_K-only mode keeps subset IDs and computes indexed rows directly from `NativeHead::weights()`.

There are five behavior sites guarded by this sentinel, plus destructor cleanup:

| Site | Current source behavior | Required contract for no-copy subset |
|---|---|---|
| `bind_bytes` (`mtp.cpp:512-527`) | When `dhead_==nullptr`, checks `draft_vocab.bin` and reserves subset-head row bytes plus ID bytes. | Preflight must use the selected head strategy, not infer it from a pointer. For indexed mode reserve logits and IDs but zero replicated-row bytes; retain coupled upper bound as applicable. This function is called before `bind` during auto cache sizing (`generate.cpp:3039-3041`), so strategy/type/subset state must already be queryable there. |
| `setup_coupled` vocabulary size (`:530`) | Chooses `n_dvocab_` only when `dhead_` exists; otherwise allocates coupled scratch for full `n_vocab_`. | Use an explicit `subset_active_` / subset descriptor; otherwise a no-copy subset gets wrong scratch size and coupled eligibility. |
| `setup_coupled` inverse map (`:548-559`) | Builds `dinv_` from `dvocab_` only if `dhead_` exists. | Build it whenever subset is active. It maps target token ID to subset-logit index for coupled penalties. |
| `bind` (`:637-655`) | `dhead_==nullptr` initiates subset file load, ID and gathered-row allocation, upload/gather. | Separate “subset initialized” from “replicated head allocated.” New mode must keep/restore `dvocab_` without requiring `dhead_`; repeated bind must be idempotent or reject/rebind transactionally. |
| Full `record_forward` head (`:810-825`) | `sub = (dhead_ != nullptr)` selects both weight pointer and vocabulary width; later chooses subset `dvocab_`/`dinv_` sampling arguments and maps ordinary output IDs through `dvocab_`. | Split these decisions: subset semantics (`nv`, coupled map arguments, post-sample token remap) from matrix storage (copied `dhead_` versus borrowed full `head_->weights()`). No-copy indexed Q6_K still has subset output width and global-token remapping. |
| Destructor (`:122-149`) | Independently frees `dhead_` and `dvocab_` if non-null, plus `dinv_` and logits. | Keep independent ownership/freeing; null `dhead_` cannot mean the subset ID owner is absent. Retire graphs and the MTP stream before freeing any captured pointer. |

No other `dhead_` references exist in the searched current code outside these source files. In particular, `capture_round` and `capture_step` do not branch on the sentinel themselves; each captures `record_forward`'s selected head path into graph execs.

## Hard MMVQ and output-shape condition

The existing `native_mmvq(type, weights, x_q8_1, y, n_in, n_out, ncols, stream)` contract consumes a contiguous row-major matrix and emits all `n_out` rows. It has no row-index-table argument. Passing the full `NativeHead::weights()` with `n_out=n_dvocab_` would read the first contiguous rows, not `dvocab_[i]` rows, and passing full `n_vocab_` would change subset logits/sampling semantics. Therefore current root cannot implement “full-head weights + `dvocab` row index” by only changing the MTP weight pointer. A Q6_K-specific indexed-row kernel/API is required, with each output row `i` reading source row `dvocab[i]`, while preserving subset order and the existing Q8_1 activation / output-column layout. Q6_K is type 14 in `native_mmvq.hpp`; the opt-in must reject any other `NativeHead::type()` and invalid dimensions rather than silently switch semantics. The full target `NativeHead::weights()` remains unchanged and live.

Subset IDs are semantic state, not merely a storage optimization. In ordinary greedy sampling, the head produces subset logits; `sample_tokens` returns subset row IDs and `map_ids` converts those IDs to target vocabulary IDs. In coupled sampling, `coupled_draft_sample` consumes the same subset logits with `dvocab_` and `dinv_`. Preserve `n_dvocab_`, every ID's order and contents, logits width, and target-token mapping. Validate every ID is in `[0,n_vocab_)` before any indexed read or `map_ids`; current loader checks only that the file has at least one int and a byte size divisible by four. Preserve duplicate entries exactly if they are accepted, since order/tie behavior is observable. The subset file's validity/failure policy must be explicit: today's malformed/missing file silently means full-head fallback, so an explicitly requested indexed-subset mode should fail closed rather than accidentally run a different draft distribution.

## Bind/preflight/accounting and rebind obligations

- Startup measurement supplied by Main (not independently read in this audit): 106,299 draft-head subset rows and 212.9 MiB of gathered `dhead_`. That is the measured copied-head allocation in the closed startup log; it is not proof that `cudaMemGetInfo` free bytes rise by exactly 212.9 MiB if removed. Keep requested/owned bytes separate from driver-visible delta.
- `bind_bytes()` currently estimates `max_t*n_vocab*4` logits when `head_logits_` is absent, then subset rows times `NativeHead::row_bytes()` plus raw IDs. In no-copy mode, omitting the copied rows from the preflight is required to size `ExpertCache` around the real plan; retaining the old formula is conservative over-reservation, not the true requested allocation. Add the strategy/type to the preflight contract or store a validated immutable mode before the preflight call. Keep the optional coupled reservation (`n_vocab*4` inverse table plus ring/scratch/params upper bound) aligned with actual setup.
- `vram_` increments the copied head and ID bytes after gather, but does not increment `head_logits_` at bind. `bind_bytes()` includes logits. Thus `vram_bytes()` is not the total binding-byte authority. A no-copy mode must count ID storage, omit copied-head bytes, and avoid duplicate increments across repeated bind; do not repair/compare against the current counter as if it were exact free VRAM.
- `bind()` currently assigns borrowed `wt_`, `head_`, and `window_R_`; it allocates logits if absent, reads `draft_vocab.bin` to a temporary host vector, allocates `dvocab_` and `dhead_`, copies IDs, gathers rows from `head->weights()`, then optionally sets up coupled sampling. The copyless path must publish subset-active state only after validated IDs and required allocations/uploads complete. Use temporary owners/checked status so a failed second allocation cannot leave a half-published “subset” or leak an overwritten `dvocab_` on a later bind. Treat changes to subset contents, output dimension, head type, or head pointer as a full rebind: retire all normal/coupled decode graphs and recreate `head_logits_` dimensions plus coupled scratch/`dinv_` as needed. Existing graphs are keyed by T/coupled mode, not by subset strategy or head identity.
- `setup_coupled()` currently copies `dvocab_` device-to-host, builds `dinv_` of length `n_vocab_` initialized to `-1`, and uploads it; these copies and allocations are not all individually checked. A new mode must preserve the same mapping and do not publish `coupled_ok_`/decode-ready on failed setup. The `dvocab_` owner must outlive both this initialization and every coupled graph execution.

## NativeHead lifetime and graph capture

`NativeHead` owns the original full matrix (`weights_`) and Q8_1 scratch; `weights()` returns a non-owning device pointer, and `row_bytes()` is `bytes_/n_out_`. The ordinary verifier uses that same head object and full weights for its own full-vocabulary MMVQ (`verify.cpp:980`). `MtpDrafter::head_` is also borrowed. Standalone generation binds `&native_head`; serve binds `&native_head` or the last `GpuStage::head`. These owner objects remain in the enclosing generation/stage lifetime while decode runs. A Q6_K no-copy MTP path must not take ownership, free, relocate, or mutate the target matrix, and requires the target `NativeHead` to stay loaded and at the same device address until all MTP calls/graphs using it have retired. `MtpDrafter` must not outlive active readers of that pointer.

Both normal and coupled round/step graph captures can record the full-head and subset-ID addresses. The existing expert-release transition already synchronizes `cs_` and destroys all four decode graph families before expert free; any indexed-head strategy switch, rebind, or storage transition must apply the same checked graph retirement boundary. Captures must be created only after subset IDs, strategy, `head_`, logits, `dinv_`, and the selected matrix-access path are stable. Prompt `prefill_exec_`/`prefill_dev_exec_` use `record_forward(...,-1,...)` and return after K/V append before the draft head, so they do not consume the new indexed-head resources; keep their state and buffers intact.

## Minimal state split and failure-prone conditions

The smallest coherent source change is an explicit subset descriptor/state independent of `dhead_` (for example `subset_active_`, `n_dvocab_`, and a valid owned `dvocab_`), plus a separate head-storage strategy (copied subset rows versus indexed full-head rows). Replace each predicate in the table above according to its actual meaning. In particular:

1. `sub` must describe vocabulary semantics, while the MMVQ source selection describes storage. For indexed Q6_K it is `sub=true`, `nv=n_dvocab_`, matrix base `head_->weights()`, and row indices `dvocab_`.
2. Ordinary results still map subset row IDs to target IDs; coupled sampling still receives subset `dvocab_` and the inverse map. Otherwise tokens or penalties silently use subset positions as vocabulary IDs.
3. Preflight bytes must distinguish logits, ID table, copied head rows, and coupled buffers. The 212.9 MiB copied row count is the only Main-provided source figure; no runtime delta is asserted here.
4. Restrict the new strategy to type 14 Q6_K and supported aligned `n_in`/row stride. The native MMVQ docs require Q6_K input width in 256-element blocks; the generated indexed kernel must preserve row byte offsets and bounds for all 106,299 selected IDs.
5. Keep all captured pointers stable through graph executions. A source strategy or subset rebind without destruction of ordinary and coupled graph families is a stale-pointer/wrong-output bug.
6. Handle no-subset, malformed-subset, full-vocab, and opt-in-but-non-Q6_K cases explicitly. A null `dhead_` can mean either no subset or an active indexed subset; no remaining code may conflate these states.

R657's head-owner recommendation remains conceptually valid, but this round narrows it: avoiding the 212.9 MiB duplicate rows is not just freeing `dhead_`; it changes the meaning of the null pointer sentinel across preflight, bind, coupled state, sampling, and captured graph inputs. No code or additional proposal is made here.
