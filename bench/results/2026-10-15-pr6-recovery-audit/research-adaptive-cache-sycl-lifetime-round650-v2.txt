# Adaptive expert-cache SYCL lifetime audit — Round 650 v2 correction

2026-10-15 JST. This v2 corrects the ordinary-SYCL route interpretation in the preserved v1 report; v1 is not overwritten. Source-only audit of the current root SYCL/native single-GPU serve path, especially ordinary MTP4. No tests, build, GPU, process control, Git, cleanup, product/proposal edit, private environment scan, or forbidden record access was performed. This report alone is new.

## Corrected finding

In the ordinary SYCL verifier, the target GPU expert route is host-planned. Verifier::init reads STRATA_VERIFY_DEVICE_PLAN but forcibly sets device_plan_=false under STRATA_ENABLE_SYCL (src/core/verify.cpp:420-427). The only Verifier path that calls resident_plan with hits_.d_res is guarded by device_plan_ at :796-800. Current expert_source.cpp:2050-2130 instead reads d.host_res on the host, writes the GPU slot address into the host plan P.ptr for resident routes, marks absent routes as misses, and publishes the plan through P.publish. Therefore the unchecked d_res device-table refresh in apply_pending/res_upload is not the active ordinary-SYCL MTP4 cache route. The v1 claims that this failure makes ordinary-SYCL decode use an old device map and access the overwritten slot were wrong; they do not apply to the configured serve path.

Likewise, the explicit no-wait setting is not by itself a stale-slot read in this host-plan route. During a swap, adapt immediately marks the victim out as kNotResident; incoming in was already nonresident and stays absent until pending completion is applied. With pending transfers, a host plan routes both as misses and CPU fallback reads their source blobs. The victim's old bytes are copied D2H and synchronously staged before slot overwrite when resident-complement exchange is needed (generate.cpp:195-230); otherwise the ordinary FileExpertSource path can supply the source blob. The partially filled slot is not advertised in host_res. After a successful event, the next apply_pending publishes in's slot. This is safe against the particular old-slot GPU read described in v1, subject to intact source/exchange storage and successful copy handling.

One concrete ordinary-SYCL blocker remains: serve adapt ignores the return from cudaEventRecord(adapt_ev, adapt_stream) (generate.cpp:5127). The pending vector and host_res publication assume this event represents all refills. In the SYCL compatibility layer, event recording may fail, while event query/synchronize on an event with no stored SYCL event treats it as already complete (compat.cpp:112-116,364-398). A prior completed event can also remain in event state. Then serve apply_pending can publish the incoming expert's slot to host_res before its H2D refill is known complete; expert_source's host plan may hand that slot pointer to the GPU kernel while it still contains the victim or partial incoming bytes. The event-record result must fail-stop before publishing/launching the next route. This applies at the per-window apply point and the request-boundary wait.

The ignored d_res upload remains poor error handling but is not a current ordinary-SYCL expert route blocker: res_upload at serve generate.cpp:5047-5053 and apply_pending :5075-5079 updates a device map that SYCL's forced host plan does not read. Revisit it if device_plan semantics change or another SYCL consumer is introduced. The standalone loop has analogous unchecked calls at :6856-6864 and :6925, but standalone is not evidence of the current official serve benchmark route.

## Official serve order and host route

The relevant work is the serve loop:

- Serve creates the adaptive stream/event and defines res_upload/apply_pending at generate.cpp:5034-5079. For ordinary single-GPU serve, apply_pending checks the event status, runs src.commit_exchanges(), then writes pending incoming slots into host_res and calls res_upload. Under SYCL, the default forces wait unless STRATA_SYCL_ADAPT_SYNC is exactly "0"; the call site also passes !adapt_nowait().
- At each request boundary, serve waits on apply_pending(true) at :5864-5866 before prompt setup. Thus the previous request's unfinished swap is meant to complete before the next prompt uses its host_res map.
- Before each decode verifier window, serve calls apply_pending(!adapt_nowait()) at :6043-6046. The target route is then derived from host_res in expert_source.cpp:2050-2121; resident expert pointers are placed in host P.ptr, while absent experts become CPU/PCIe misses. The plan is published at :2128-2132.
- Only after ver.run has returned does serve start adapt_thr at generate.cpp:6070-6073. It commits session state and calls mtp.draft, then joins the adaptation thread at :6111-6114. Verifier run drains its graph and copy streams before returning (verify.cpp:1393-1404); MTP draft uses its separate stream/cache and synchronizes it (mtp.cpp:1140-1190). No ordinary verifier cache-slot reader overlaps the refill interval.
- The adaptation considers decayed host-side usage every four rounds, replaces within each layer, and queues H2D into the victim's slot. The H2D copy result is checked and false propagates to an ERR/failing request. The victim is immediately removed from host_res; incoming is only inserted into host_res by apply_pending after event completion (generate.cpp:5082-5128). Hence during an allowed no-wait window both entries are routed as host misses, rather than using a partially refilled slot.

This does not qualify other modes (multi-GPU peer/stage paths, CUDA/HIP device-plan paths, or process/cache teardown after arbitrary driver failure). The current official benchmark's serve path, not the standalone generate loop, is the basis for this conclusion.

## Remaining exchange bookkeeping and source data

When resident-complement exchange applies, resident_stage_swaps first queues D2H of the victim blob into an exchange buffer, synchronizes that stream, then stages the override before the H2D slot refill (generate.cpp:203-230). Thus the host fallback for the evicted expert is available before its host_res entry is cleared. On successful event completion, src.commit_exchanges moves saved victim bytes into the incoming expert's former complement location and exchanges the complement map (expert_source.cpp:1780-1807). Its return count is ignored at serve generate.cpp:5075 and standalone :6859. A short count appears to leave the evicted expert available from the backing file/mmap fallback rather than advertise a wrong cache slot, so this is a source-tier/performance accounting concern; preserve file-read counters and do not claim every swap was RAM-resident. It is not evidence of the v1 stale GPU-slot scenario.

Adaptive replacement retains the per-layer byte geometry. For native per-layer SYCL caches, generation builds a slot-size vector using each layer's blob_bytes and the current total capacity, then opens one aligned arena (generate.cpp:3122-3135; expert_cache.cpp:256-285). Victims and candidates are paired within the same layer and H2D copies use that layer's blob_bytes (generate.cpp:5087-5107,5110-5125). It does not move an expert across layers or resize the arena. R632's initial capacity plan remains 128 = 281,651,200 B with final layer quota 34; 192 = 392,908,800 B with quota 4; 256 = 533,734,400 B with quota 21, and all preceding 47 layers have quotas 2/4/5 respectively. Enabling adaptation changes occupants, not total bytes or these quotas.

R584 found the checked profile file is shape-compatible but not bound to model weights or route corpus. R607's CPU census and append-only upper bound used adapt-swaps 0; the later profile overlap review was conditional because that historical census did not capture the profile content hash at the time. These artifacts cannot estimate what default adaptation will swap on a new prompt or whether it improves decode wall-time. Adaptive routing also changes CPU-versus-SYCL ownership (SYCL hit uses Q8_1, CPU retains IQ arithmetic), so MTP4 acceptance and output work can move. Keep profile fit, output/quality, and speed as distinct evidence.

## PCIe miss-fetch remains a separate mechanism

The adaptive H2D operation fills a cache slot for a newly admitted resident expert. The PCIe-fraction path in expert_source.cpp:2064-2095 and :2110-2132 is a different route for a cache miss: it may send a pinned host blob to a staging/direct/kernel copy mechanism. Its enqueue/fetch error checks do not cover adaptive event recording; fixing PCIe fetch does not close the adaptive publication blocker, and this report does not claim a defect in the PCIe path.

## Corrected decision

Do not treat unchecked d_res publication as a current ordinary-SYCL decode blocker, and do not reject ordinary host-plan no-wait solely on the old-slot concern. Keep the actual serve event-record failure as a blocker: check cudaEventRecord and fail before pending residency can be published if it fails. The same event must represent all successfully queued refill copies. Keep host_res publication after successful completion, and keep source fallback available for entries removed while a transfer is pending. For a static-versus-adaptive comparison, use separate served processes with explicit settings, same cache/profile/context/KV/MTP4 settings, and actual swap/hit/CPU route, output/quality, fault and owner-closure receipts. Do not combine capacity changes and adaptation changes into one result. No fix or measurement was made here.
