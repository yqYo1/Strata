# R685 v2 correction: long-prefill workspace alias contract

This report supersedes the byte arithmetic and width assumptions in R685 v1; v1 remains unchanged as the original reviewed artifact. The corrected geometry came from `src/prefill/prefill.cpp:98`: `N=2560`, `HC=4`, `D=N*HC=10240`. No source change, build, test, GPU work, process/environment scan, Git mutation, or cleanup was performed. The current benchmark job was not interrupted.

## Corrected capacity arithmetic

The C8192 capacity scenario in `prefill-capacity-plan.ja.md` has a modeled deficit of 161,033,920 B after its stated 512 MiB driver reserve. The four named arrays `emb`, `mixed`, `bo`, and `ple_emb` are each `float[T*N]`, not `float[T*D]` (`src/prefill/prefill.cpp:851,856-857,924`). At T=8192 and N=2560, one array has 20,971,520 FP32 elements and requests **83,886,080 B = 80 MiB**. This is the previously confused number: 83,886,080 is bytes for one N-wide array, while the prior v1 used D=10240 and overstated each by 4x.

Ignoring the independent `Alloc` padding for the moment, the byte effects are:

| N-wide FP32 arrays sharing one slot | Removed full array slots | Payload released | Result against 161,033,920 B deficit |
| ---: | ---: | ---: | --- |
| 2-to-1 (one pair) | 1 | 83,886,080 B | 77,147,840 B still short |
| 3-to-1 | 2 | 167,772,160 B | 6,738,240 B nominal remainder |
| 4-to-1 | 3 | 251,658,240 B | 90,624,320 B nominal remainder |

These are payload-only savings. `Alloc::take` rounds each item as `((n*sizeof(T)+511)&~255)` (`prefill.cpp:196-209`), so an 80 MiB aligned payload currently costs an additional 256 B per allocation. A single shared allocation also needs one guard/padding unit: exact additional savings are 256 B for each removed allocation. Do not omit this per-take detail when updating `bytes_needed` and carved layout.

The 32 MiB `GEMM_WS` candidate is separate. Under the actual SYCL resolver, `cmake/sycl_backend.cmake:111` selects `src/prefill/sycl/gemm.cpp`; `init_external` ignores the workspace length, stores the pointer, and GEMM methods do not use `workspace_` (`:41-58,81-100`). The non-SYCL CMake path selects `gemm.cu` (`CMakeLists.txt:427`) and still gives the workspace to cuBLAS. Conditional removal of the SYCL-only allocation would release 33,554,432 B; alone it leaves **127,479,488 B** of the stated deficit. Paired with 2-to-1 aliasing it still leaves **43,593,408 B** short; with 3-to-1 aliasing it leaves a nominal **40,292,672 B**. All results remain capacity arithmetic, not measured allocation success.

## Rechecked phase lifetimes

`run_impl` processes each chunk through layers and each layer through attention half then FFN half. Relevant compute and copy operations on `m.cs` are issued to the SYCL in-order queue (`include/strata/sycl/launch.hpp:55-62`; SYCL GEMM binds that queue in `src/prefill/sycl/gemm.cpp:47-54`). A safe reuse must follow these source order edges; it cannot rely on equal sizes alone.

| Logical buffer | First write | Final source read/use before reuse | Earliest safe next write to a shared slot | Alias result |
| --- | --- | --- | --- | --- |
| `emb` | Chunk embedding gather or row upload into `m.emb` (`prefill.cpp:1716-1744`) | `gr_broadcast(m.emb, m.R, ...)` at `:1746` | The first `m.mixed` write from `gr_mix[_r]` after broadcast, or the later PLE upload | Can reuse the same slot as `mixed`, `bo`, and/or `ple_emb` if `R` remains separate and queue order is maintained. |
| `mixed` (FP32) | Each HC-half `gr_mix[_r]` (`:2056-2058`) | On the FFN half, routed expert activation quantization reads FP32 `mixed` (`:2366-2367` fused or `:2512-2514` MMQ). The compact FP16 path instead gathers `mixed_h` (`:2880-2886`), so the F32 buffer has no later expert read there. | Attention projection output may first write `bo` after the attention input projections have used `mixed_h`/`mixed_bf` (`:2075-2087` or QSA `:2103-2107,2299-2301`). For FFN, `moe_combine` writes `bo` only after the quantization read and expert work (`:2967-2969`). | `mixed` and `bo` can plausibly share one N-wide slot. `mixed_bf`, `mixed_h`, and optional `mixed_bf_lo` remain disjoint; their projection reads can overlap the phase in which F32 mixed is generated/used. |
| `bo` | Attention output GEMM (`:2085` or `:2301`) and later FFN combine (`:2969`) | `gr_write_norm_rs`/`gr_write` reads it into persistent residual `R` (`:3011-3015`); phase audit captures before the residual write | The next HC-half `mixed` write, the later PLE landing, or the next layer's outputs, all ordered after the `gr_write` consumer | Same shared slot is plausible. Never alias it with `R`: residual write reads `bo` while updating `R`. |
| `ple_emb` | `ple_land` copies host-gathered rows to device immediately before layer 1 (`:1755-1768`) | Layer-1 PLE batched GEMMs/postops read it (`:1990-2025`) or the token path calls `ple_block` (`:2028-2035`) | Layer-1 HC `gr_mix` and subsequent outputs on `m.cs`, after PLE's last read | Same shared slot is plausible if landing stays after previous-slot readers and before PLE readers. The async host gather is into `ple_emb_host[2]`, not this device slot. Its pinned source reuse remains guarded by `ple_copied` (`:1638-1649,1770-1779`). |

One feasible four-to-one timeline is: embeddings write/read through broadcast; attention-half mixed inputs are produced in the distinct BF16 outputs, then attention `bo` is written/read through residual write; FFN-half mixed is written and consumed by activation quantization; FFN `bo` is combined and read into residual; at layer 1, PLE lands/read occurs after layer 0's final `bo` read and before layer-1's next mixed/output writes. At later layers the same attention/FFN sequence repeats. This is a source-order proof candidate, not runtime or numerical validation. In particular, `Gemm` input/output must never overlap for one operation: the candidate F32 slot is not the GEMM input (`mixed_h`/`mixed_bf`/`y_h`/`attn_h` are the GEMM inputs), and reuse is only across completed in-order operations. Keep input/output aliasing out of the design.

`mixed_bf`, `mixed_h`, and `mixed_bf_lo` are same-phase projection inputs and must remain separate from each other and the shared N-wide F32 slot. `R` is `float[T*D]` and represents persistent residual state. `region` is the larger max-of-GDN/QSA/MoE scratch set (`prefill.cpp:866-905`) and is not this alias group. `on_chunk` can invoke `draft_kv`: it uses `R_rows` and carves its MTP temporary K/V/embedding tensors from `m.region`, then synchronizes `m.cs` before returning (`:965-1148`; callback after stream sync at `:3079-3088`). It does not consume the four candidate pointers. This final-layer callback does mean a candidate slot cannot be reinterpreted as `R` or `region`, and a callback must not retain candidate pointers.

Peer execution is a different queue edge but is explicitly ordered in the current source: `PeerPrefill` waits on `P.ev_in` before copying `m.mixed` on `P.s`, then the main queue waits on `P.ev_done` before `moe_combine` writes `bo` (`prefill.cpp:2536-2550,2967-2969`). Therefore the source does not show a peer read racing the FFN `bo` reuse. Nonetheless, any alias implementation must preserve both events and test peer mode; if event/order behavior is changed, reject the alias layout on that route. Expert staging's separate `m.copy` stream accesses `stage_dev`, not these four arrays. Layer split/handoff streams move `R` and use stage-local prefill arrays; they likewise must not be allowed to retarget this slot to `R`.

## Sizing and dispatch constraint

`Prefill::bytes_needed(g, ss, chunk)` and `Prefill::init(..., chunk, ..., borrow)` size/carve storage before the call's `n` is known (`prefill.cpp:1247-1260,727-840`). `Alloc` either creates individually owned `cudaMalloc` blocks or suballocates one parent-borrowed span. Serve calls `bytes_needed` to size the expert-cache loan (`generate.cpp:4324-4333,4460-4488`), and later `relayout(want, borrowed_span, ...)` re-carves a request-sized layout between requests after draining streams (`prefill.cpp:938-960`; `generate.cpp:5907-5920`). Therefore a policy saying “allocate the smaller layout only if this request is long layer-major, otherwise fall back to the original layout” cannot be selected inside `run_layer_major` after `n` arrives: by then bytes are already owned or the cache-tail loan has already been sized. Adding a second persistent original-layout arena would erase the VRAM saving.

The practical narrow choice is a pre-init layout mode, recorded consistently for `bytes_needed`, `init`, and every borrowed `relayout`. That mode must be correct for **both** `n<=T` short `run_impl` calls and `n>T` long layer-major calls, because prompt length is unknown at initial startup. It changes only the prompt scratch layout; it must not alter short-prefill's decode weight/cache route or long dispatch threshold. The current phase order appears common to chunk-major `run_impl`; `run_layer_major` itself adds the stronger single-GPU/same-queue restrictions (`layer_major.inc:36-43`). A route-specific mode can be selected from startup-known topology/configuration, but the current `bytes_needed` signature lacks a topology/layout argument and `m.pp` can be attached after init. For that narrower case, either extend the sizing/init API with the same explicit mode and propagate it to every borrower, or do not advertise the reduced `bytes_needed` result. Environment must be set before process/runtime initialization and stay immutable. Do not key allocation layout to `n` or to `compact_moe_fp16()` alone: the latter changes MoE scratch rows, not the four buffer extents or their order (`prefill.cpp:645-660`).

Owned and borrowed savings are not identical operationally. In an owned init (`borrow==nullptr`), each current `o.take` calls `cudaMalloc` (`Alloc::take` at `:196-209`); aliasing means carve fewer N-wide allocations, directly releasing 80 MiB payload per removed slot. In the borrowed serve case, pointers are offsets within cache slots; no `cudaMalloc` is removed, but a matching reduced `bytes_needed` can return fewer tail slots to prompt use and return more slots to the expert cache outside the request. `relayout` can choose a smaller request-sized borrowed span because `want` is computed per request, but `bytes_needed` and `relayout` must agree on the alias mode and alignment. If short fallback requires a nonalias layout, reserving the maximum of two simultaneously resident arenas is not a solution. Either prove/use the same alias layout for short and long `run_impl`, or retain the original single layout without claiming long-only capacity reduction.

## Corrected hidden transfer arithmetic

Hidden residual row width is D=10,240 floats: **40,960 B per FP32 row**, **20,480 B per FP16 row**. The current FP16 boundary path converts on the producer before host-backed store and restores once on the next layer (`layer_major.inc:359-369`; `prefill.cpp:1672-1689`). Per host-backed boundary, producer store plus consumer reload is 327,680 B/row in FP32 and 163,840 B/row in FP16, saving 163,840 B/row at added conversion cost. Across 262,144 rows and 47 boundaries, assuming every boundary row is host-backed:

| Storage | Round-trip traffic | Difference |
| --- | ---: | ---: |
| FP32 | 1,009,317,314,560 B = 940 GiB | — |
| FP16 | 504,658,657,280 B = 470 GiB | 504,658,657,280 B = 470 GiB less |

This matches R679's independent full-hidden arithmetic (`research-layer-major-offload-primary-round679-v1.txt`: 5 GiB per full FP16 hidden store multiplied by 94 store/reload operations = 470 GiB). It is an upper-bound logical byte count for host-backed spans, not proof of PCIe traffic or saturation; GPU-resident prefix rows use D2D. FP16 long-boundary quality remains unqualified. A future late conversion or recompute strategy may trade arithmetic for fewer bytes, but source inspected here establishes only the current FP16 conversion path, not a new correct recomputation schedule.

## Proposed negative/positive fixture (not run)

Before using a shared slot, add a small fixture with the corrected N=2560 and T chosen to fit cheaply, plus distinct canary patterns in each logical phase. Enqueue embed write/broadcast, attention projections and `bo`/residual consumption, FFN activation quantization, combine/`bo`/residual consumption, PLE host gather/upload/PLE use at layer 1, and a next-chunk embed overwrite. Compare consumer checksums and final `R` to an unaliased reference. Include a final partial chunk, optional `on_chunk` MTP mock reading `R` and separately using `region`, and delayed peer-copy completion that asserts `P.ev_done` precedes `bo` overwrite. Negative mutations should move PLE landing before embed's last read or omit the peer event wait; the fixture must expose the overwrite or reject that layout. Run the same alias layout for short chunk-major and long layer-major inputs; test a nonalias mode as control. This is a proposed fixture contract, not test evidence.
