## Independent later own-fork measurement and comparison limits

Do not collapse this result into the later, closer-context `historical-v0141/tuned32k` record. It is a separate strong measurement with different source, work, and settings. That record, indexed from original report commit `16b1b04...`, used the migrated pre-Xe fork source at `1eb89482a4afd20277ae0405780ed4f8eb98eb20`, actual fresh 32,768-token prompts, context 262,144, 32,768 resident INT8 KV cells, chunk 8,192, 128 expert slots, five workers, PCIe fraction zero, MTP4 and 64 output tokens. Its two-process/four-request design yielded six later reads: control median 427.442 (range 427.242–427.677) versus integrated 449.674 (449.491–450.083) PP tokens/s; pooled later reads 427.452 versus 449.698 (+5.204%). IDs, logprobs and MTP counts match; normal exits and no new GPU faults are recorded. This supports a repeated advantage for the integrated 1eb source/configuration over its qualified 0.1.40 control, without isolating a kernel. It is not the same method as the PR #6 CLI comparison and does not explain the difference between 449.7 and 645.8.

Current `feature/sycl` source and current stock records report roughly 118.5 PP on actual 32,049-input / 24-output requests in a different configured path. That value is much slower than either historical result, but it has different source, client/workload, context/chunk/MTP and setup. It establishes that current observed throughput is lower; it does not identify a causal source change or make the historical paired measurements disappear. The current closed thinking suite's actual inputs around 33.2K and TG samples are another workload/configuration and are not a matched remeasurement of PR #6.

The meaningful source-level regressions are bounded: historical positive results name source paths and active selectors absent from the current configured source. They establish missing selectable behavior and a prior configuration's performance; they do not establish that each missing component alone caused the full end-to-end gap. Existing R490 review is the strongest committed per-component reconciliation: `bench/results/2026-10-14-performance-regression-audit/research/research-primary-v0141-to-current-component-regression-round490-v1.txt`. It identifies (a) old compact=2 workspace semantics missing from current source, (b) measured QSA prefill layout=1 selector missing, (c) a changed old QSA attention implementation where the current tree still has its own matrix path, and (d) replaced native prefill kernel/source families whose per-format current dispatch must be compared. The paired PR #6 study specifically combines compact scratch and layer-major traversal; do not attribute all 29.8% to either one. The 1eb study used compact=2 and layout=1 among other changes, but its +5.2% over its own control likewise does not identify the responsible component.

R490 also finds `STRATA_KV_PREFETCH` absent from active current source, but it was disabled in the accepted old speed run, so it cannot explain that speed. The source review says the QSA matrix/XMX family is not wholly missing from current code, and old decode data does not demonstrate a decode speedup. Those controls matter to avoid declaring all earlier inference behavior lost. Oct4 root-native positives remain separately in current source, so avoid framing this as wholesale erasure of prior work.

## Configured source route and preservation status

The old measured 1eb build was not just today's root source at a different version. Its root CMake entered `sycl/CMakeLists.txt`, then `strata_resolve()` preferred migrated `sycl/src/<path>` implementations over root copies. `sycl/CMakeLists.txt` built the old overlay, including migrated prefill, QSA attention, core/session/verifier and CUDA-derived SYCL-port kernels. The exact route and selected-file hashes are recorded in `source-routes.json` and R490/R492/R493. At the current primary route, root CMake includes `cmake/sycl_backend.cmake`; it directly compiles root `src/prefill/prefill.cpp`, `src/prefill/sycl/*`, `src/kernels/sycl/*`, root core and root program code. It does not select the historical `sycl/src` overlay. Current workspace itself has no `sycl/` source tree. Current greps find no old `STRATA_PREFILL_COMPACT`, `STRATA_PREFILL_LAYER_MAJOR`, or `STRATA_PREFILL_ATTN_LAYOUT` dispatch in the configured root prefill. `docs/UPSTREAM_INTEGRATION.md` and the source-route audit explicitly distinguish preserved ancestry from source integration.

The PR #6 implementation is present in commit history and its report/data are preserved, but its old overlay is not an active configured build target. A history-preserving merge or retained original commit is not code integration. Do not re-enable the complete legacy overlay or point current CMake at it to reproduce one result: current source has different resolver, core, queue/lifetime protections, `size_t` ranges, and current-format dispatch.
