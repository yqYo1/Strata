# Decision support: live Mode1 K8V8 rows before BF16 pack integration

Checked 2026-10-16; source-only investigation. This resolves the live-source precondition, not a speed or adoption decision. Main reports the initialized-pool `own-qsa-bf16-packed-{smoke,component}-v1.json` receipts PASS, including its 262144-cell component fixture; that proves the component under its supplied initialized-input contract, not that a model session satisfies it.

## Finding

The precondition is **not satisfied by a live Mode1 K8V8 session in general**, and the existing long layer-major path does not consume Mode1's resident slot pool for prompt attention. `qsa_bf16_packed_batch` packs every row in `bounds.physical_pages` and reads all four K/V scales and all 256 K/V codes per row before attention. Its header explicitly requires every physical input element, including unused rows, to be initialized (`include/strata/kernels/qsa_bf16_packed.hpp:12-22`; implementation `src/kernels/sycl/qsa_bf16_packed.cpp:58-97`). Session initialization carves device K/V pointers from a `cudaMalloc` arena and creates the pinned Mode1 host K/V allocation, but does not clear either pool (`src/core/session.cpp:75-128`; `src/core/layer.cpp:555-663`). The required sequence reset, `session_zero`, does clear the *device slot pool* across `n_slots * 2 heads * page_size` rows, then resets the Mode1 map; it intentionally does not clear the full host copy (`src/core/session.cpp:139-153`; `src/core/layer.cpp:693-720`).

That is not a lasting guarantee for Mode1 physical slots. Mode1's host pool is authoritative and identity-laid out over all logical pages; its page table maps logical page to a resident slot or `-1` (`include/strata/kernels/kv_stream.hpp:1-18, 30-65`). K8 append always writes the host copy, writes a device slot only if its page is mapped, and writes an optional prefill staging pool (`src/kernels/sycl/kv.cpp:54-188`). During decode, `kv_stream_resolve` maps selected pages into slots and copies each **whole page** from host to device; there is no live-cell mask for the final partial page (`src/kernels/sycl/kv_stream.cpp:121-268`). Since host rows/scales after the last append were never initialized, that copy can put indeterminate unused cells into a slot that `session_zero` had previously zeroed. The pack then reads them. On a fresh session, this can happen on the first resolution of a partial final page; on reuse, slot contents can also be stale. The “nothing reads” argument in `qsa_state_zero` covers unselected cells in the existing attention reader, not a pack that deliberately traverses every row.

Mode1 also separates the prompt's logical prefix from those resident slots. `Prefill::init` allocates `m.stage` for the full logical K8V8 range and an identity `m.ident_table` (`src/prefill/prefill.cpp:546-580, 901-910, 1034-1039`). For each layer-major chunk at position `p0`, the path copies `ceil(p0/4)` complete blocks from authoritative host K/V into that identity staging pool, then appends the current chunk to host, any mapped slots, and staging. Prompt attention receives `m.stage` plus `m.ident_table` when `kv_mode == 1` (`src/prefill/prefill.cpp:2387-2427, 2583-2605`). This path does not call `qsa_kv_resolve`; `m.stage`, not `st.k_q/st.v_q`, contains the complete prefix read by that chunk. The stage copy includes unused cells in its final page, and its allocator is reused across chunks/layers, so the stage tail is not itself initialized merely because the previous chunk used it.

The accepted layer-major geometry has page size 4, two KV heads and 256 dimensions. `n_pages = ceil(max_cells/4)` and the physical pool is `n_slots` pages (`src/prefill/layer_major.inc:86-99,132-151`; `include/strata/core/layer.hpp:203-235`). At the 262144 logical limit there are 65536 logical pages; this arithmetic is not a claim that a session run or RESTORE passed at that limit. The typed QSA branch currently rejects Mode1 and requires Mode0 resident INT8 with no host pool (`src/prefill/layer_major.inc:153-189`). Thus the passed full-pool component fixture does not establish the required Mode1 long-prefill source contract or a production caller.

## Reuse, reset, append, RESTORE, and lifetime

`session_zero` is the point at which an empty sequence gets a deterministic device slot pool. The normal generator allocates the session arena with `cudaMalloc`, calls `session_init`, then calls `session_zero` before prompt work (`src/program/generate.cpp:3077-3104`). In serve, an empty request calls it again; a parked-conversation restore instead copies the authoritative K/V extent and resets the Mode1 map so stale resident slots cannot be mistaken for restored pages (`src/program/generate.cpp:5903-5945,5962-5972`; `src/core/conversation_snapshot.cpp:200-223`). Snapshot K/V extents round up to full pages, but this is not a blanket initialization of the unused host suffix: `conversation_snapshot.cpp:40-56,194-218` copies the saved rounded extent only. Checkpoint restore separately restores indexer/recurrent state (`src/core/conversation_state.cpp:172-192`); the cache snapshot supplies K/V.

The device arena size comes from `session_bytes`, while each Mode1 host copy is a separate `cudaHostAlloc` for all logical pages; host RAM admission is therefore a separate failure point (`src/core/session.cpp:54-73`; `src/core/layer.cpp:537-552,633-663`). The host pools remain attached to each `QsaState` across token appends and requests. In the inspected source, `session_release` only releases owned RoPE tables (`src/core/session.cpp:131-137`); it does not free the Mode1 KV host allocation. No repeated state teardown/recreation should be assumed to release this pinned memory. The normal serve state is long-lived, but any future concurrent/per-request state owner needs explicit pinned-memory lifetime accounting.

There is no packed persistent cache today: the candidate refreshes caller-owned scratch on every call and retains neither K/V nor validity metadata (`qsa_bf16_packed.hpp:12-22`). A future persistent mirror would need its own validity generation. Mode0 can use a stable identity mapping, but `session_zero`, append overwrite, and snapshot RESTORE must reset or refresh it. Mode1 makes a slot-keyed mirror more fragile: eviction changes `page_table[logical]` and `slot_block[slot]`; a miss then replaces that slot with another host page (`kv_stream.cpp:181-235`). Append can update a mapped page in place. RESTORE resets the map but does not clear or repopulate the physical slot bytes (`conversation_snapshot.cpp:209-218`). A mirror keyed by slot therefore needs invalidation on remap and restore, plus live-tail handling; one keyed by logical page still needs invalidation on sequence reset/restore and refresh for every overwritten logical row.

The temporary stage and any packed scratch must remain owned until the in-order compute queue retires. `run_layer_major` requires `m.copy == m.cs`, takes a checked outer lease, and drains at entry/layer boundaries/exit before temporary owners go away (`src/prefill/layer_major.inc:75-85,329-374,430-433`). The SYCL adapter requires an in-order queue; for an explicit queue its `finish` does not wait, so pack and attention must be submitted to the same `m.cs`, and scratch must remain alive through the outer checked drain (`include/strata/sycl/launch.hpp:44-63`; packed implementation `qsa_bf16_packed.cpp:56-58,95-98`). No CPU row grouping or host synchronization is needed for a GPU kernel to consume existing `steps`, `ids`, `page_table` and live extent; ownership and queue order still need explicit integration.

## Alternatives and scope-qualified recommendation

| Design | What it reads/writes | Applicability and counterevidence |
|---|---|---|
| Whole physical pool pack | Convert every `n_slots * 2 * 4` row, then use the existing page table. | Keep scoped to Mode0 only when an earlier sequence reset has initialized the pool, or to a caller that separately proves every physical K8V8 row and scale initialized. It is simple, but Mode1 has unmapped slots, whole-page fills with unwritten host tails, and a dynamic slot map. In layer-major Mode1 it packs the wrong source pool. |
| Active logical-prefix pack with page mapping | In long prefill, pack the authoritative/staged logical prefix `[0, live)`, where `live = p0 + T`, into compact BF16 pages; supply a logical-page table that maps each live page to its packed page. For this contiguous prefix, identity mapping for live pages is sufficient; mark later pages absent. Mask/zero the final page's cells `>= live` rather than loading them. Keep the original `ids` and `steps` unchanged so every selected live cell remains eligible. | Best source-level fit for long layer-major Mode1: `m.stage` already holds the prefix plus newly appended chunk and is the same source the current prompt attention uses. It avoids reading host suffixes/unused stage rows and does not make CPU selection decisions. It costs a second conversion over the full prefix each chunk (quadratic total prefix work over many chunks) and a larger transient output; no speed result exists. A selected-page union could reduce work but would require GPU compaction/mapping and exact coverage proof, so is a separate design. |
| Incremental packed-cache refresh | Update BF16 rows when a K8 row is appended; refresh restored prefixes or cache invalidation after reset/reuse. | Potentially avoids repacking prior rows, but a pack derived from K8 must round `int8_code * stored_fp16_scale` to BF16, not pack raw pre-quantized K/V. Mode1 requires slot remap/eviction invalidation or logical-page generations; `session_zero` and snapshot RESTORE also invalidate. The long-prefill stage is reused across layers/chunks, and restored host prefixes require a complete initial conversion. This adds state and lifecycle obligations before speed is established. |
| On-the-fly K8-to-BF16 in attention | For each selected cell, load its codes/scales through the current page table and convert into local BF16 operands; keep existing selected IDs/steps and FP32 online reductions. | Avoids any full-pool/prefix scratch and its full-initialization precondition; it is a clean allocation-failure fallback candidate. It repeats scale/code loads and conversion for each attention consumer and could change service time. It needs a distinct kernel path and correctness evidence; no performance claim follows from avoiding scratch. |

Recommendation: do not route Mode1 layer-major prefill through the current complete-physical API. If a future integration needs a separate BF16 packed representation for this path, prototype a same-queue active-prefix pack sourced from `m.stage`, with checked `live` and active page count, final-page masking, and the unchanged GPU-produced selection arrays. If its workspace cannot be admitted, keep the existing K8 attention path as the baseline fallback (with its existing arithmetic), or reject the optional BF16 route before enqueue; do not present that fallback as equivalent BF16 arithmetic. A failed allocation must be resolved before queue submission, not by freeing or reusing memory still referenced by queued work. Treat incremental refresh as a later option that first specifies invalidation on `session_zero`, append, RESTORE and Mode1 slot remap. The full physical API remains a valid narrower candidate for Mode0 under its explicit post-reset initialization contract. This recommendation is about source correctness and ownership only, not an inference-speed choice.

Capacity is a first-class gate. `qsa_bf16_packed_batch` receives scratch from its caller and performs no allocation (`qsa_bf16_packed.hpp:19-26`); the layer-major `cudaMemGetInfo` admission currently accounts for the extra expert cache plus 512 MiB headroom, not a new packed-pool workspace (`src/prefill/layer_major.inc:206-229`). A full-context BF16 K+V prefix/physical workspace at this geometry is 262144 × 2 KV heads × 256 × 2 bytes × 2 tensors = 512 MiB, plus row diagnostics and alignment. A Mode1 20480-cell slot workspace would be 40 MiB, but does not solve the layer-major source mismatch. Add exact scratch, page-map and diagnostic bytes to preflight/`bytes_needed`, and check actual free VRAM before work. On failure, preserve the current K8 path or fail the optional candidate cleanly. Pinned Mode1 host allocation is separate and can fail `qsa_state_init` before inference (`src/core/layer.cpp:633-650`); no successful GPU allocation proves pinned-RAM availability.

At 262144, the prefix has no partial final page; earlier chunk positions and any shorter restored prefix can. Keep 262144 capacity, rounded extent, `int64` checked byte counts and page-table bounds separate. No memory or output claim at the boundary is made here. The relevant current component receipt and any future model-level physical-boundary/RESTORE evidence must remain separate under the artifact-retention policy.

## SGLang design comparison and provenance

R928/R931 already traced the broader SGLang QSA path; this report only retrieves the prefix-pack point. At official `sgl-project/sglang` commit `877be2974aa151a984e52822c028276c2b1e9303` (inspected 2026-10-16; repository root `LICENSE` is Apache-2.0), `_pack_qsa_prefill_kv` maps each valid logical token through `req_to_token`, loads K/V under a `valid` predicate, and stores only valid packed rows (`python/sglang/srt/layers/attention/qsa/sparse_attn.py:263-358`). The backend calls it only when an extend has an existing prefix, sizes output from `total_k`, and then passes that contiguous output to its chunk-prefill consumer (`python/sglang/srt/layers/attention/qwen_sparse_attn_backend.py:1426-1473`). This is a useful source design for bounds-driven valid-row packing; it does not show that Strata needs a K/V pack, since Strata already consumes a page table directly and its Mode1 layer-major route already stages a logical prefix. It is a source comparison, not evidence this branch ran in a local SGLang process and not code to copy. Keep Strata implementation independently authored under its repository `LICENSE`.
