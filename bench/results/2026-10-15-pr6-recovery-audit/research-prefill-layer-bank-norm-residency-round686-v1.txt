# Prefill layer-bank fused norm residency and layer-view contract (R686)

Read-only source audit. No source edits, build, tests, GPU execution, or changes to existing reports. The report resolves the R684 fused-next-layer-normalization exception into exact device payload sizes and a minimum prefill view/owner boundary. Counts below are source/metadata proofs; any performance, allocator reclaim, or lifecycle behavior is unexecuted and remains a hypothesis.

## Exact geometry and per-layer small-vector census

`src/prefill/prefill.cpp` defines `N=2560`, `HC=4`, and `D=N*HC=10240` at the translation unit's prefill constants. `src/core/layout.cpp` checks layer tensor shape/form against `ModelGeometry`; `prefill-capacity-metadata-v2.json` records observed canonical tensor shapes and byte counts for all 48 layers. In particular `hc_attn_norm.weight` and `hc_ffn_norm.weight` are each F32[10240], 40,960 B. The model's current GDN SSM norm has 128 elements, and QSA attention norms have 256 elements while QSA indexer norms have 128 elements, as evidenced by layer 0 and 47 entries in the metadata receipt.

The exact norm/scale/bias and scalar shared-gate vectors per layer are:

| layer family | entries used in its layer | canonical bytes |
| --- | --- | ---: |
| every layer: HC attention + HC FFN norm | 2 × F32[HC×N] | 81,920 |
| GDN: SSM norm, `ssm_a`, `ssm_dt.bias` | F32[128] + F32[48] + F32[48] | 896 |
| QSA: attention q/k norms + indexer q/k norms | 2 × F32[256] + 2 × F32[128] | 3,072 |
| every layer: shared-expert gate scalar/vector | BF16[2560], stored as `Bf16InF32` | 5,120 |

Thus the listed resident small vectors total 87,936 B on GDN and 90,112 B on QSA. These totals intentionally do not include projection matrices (`ssm_alpha/beta.weight`, which are 2560×48 matrices in canonical form, and QSA projection weights), nor PLE per-layer norms on layer 1. Those are normal active-layer payloads; they are not fused-next exceptions. `ssm_a` and `ssm_dt.bias` are the GDN scale/bias terms; they are needed by the active GDN layer and have no next-layer lookahead use in the inspected prefill dispatch.

The fused read is narrower than “keep the next layer's complete norms.” In `src/prefill/prefill.cpp` around the residual-write block at lines 2990–3010, `nl=l` for half 0 and `nl=l+1` for half 1. `gr_write_norm_rs` reads `hc_ffn_norm.weight` for half 0 and `hc_attn_norm.weight` for half 1, using `LayerView(*m.wt,nl)`. When fusion is disabled by the existing conditions (last stage/layer, PLE boundary, control vector, or `STRATA_GR_UNFUSED`), it uses `gr_write` and does not read this lookahead norm there. Therefore the unconditional simple contract is: keep the active layer's own two HC norms available, and provide exactly one next-layer HC norm (40,960 B) for each fused half that is enabled. For the usual interior layer both halves fuse, so the extra live next-layer payload is **81,920 B**. At the final layer `nl` is not admitted and there is no next-layer allowance.

The maximum two-layer HC-norm residency needed by this fused schedule is therefore 163,840 B (four F32[10240] vectors: current pair plus next pair), even though the fusion actually consumes one future vector in each half. If only the recurrently consumed HC norms are made persistent, the exact pool is `48 × 2 × 40,960 = 3,932,160 B` (3.75 MiB). This is the cleanest simple lifetime contract: all 96 HC norm arrays have a dedicated small owner, while each active layer bank carries a stable reference to its current pair and its next pair. It makes fusion independent of the layer-bank payload eviction schedule. GDN/QSA vectors in the table remain in that layer's active canonical view; keeping all of them resident is not required for the fused exception.

## Alias and format accounting

These norms/scales/biases are canonical-only in the capacity receipt: they appear under each layer's `canonical` entries, and do not occur in the `native` matrix list. `NativeDense` owns quantized projection payloads and does not provide an alias for these F32 vectors. The R684 sum of 1,538,035,200 B canonical plus 2,116,951,040 B native is disjoint for the measured target pack, but this small-vector audit must not add the same canonical norm bytes again as “native.” The BF16 shared-expert gate is canonical engine form with 2 bytes/element (5,120 B), not an F32 10,240-B tensor. HC/GDN/QSA norm data are F32 and the kernel sites cast `WeightRef::data` to `const float*` (for example `layer.cpp` QSA norm path around 857–858); materializing a second persistent copy would add bytes only if the implementation truly duplicates rather than redirects the active view.

For attribution, distinguish three cases in any future receipt: source pack bytes read, canonical device payload bytes, and native device payload bytes. A per-layer canonical metadata copy or view is not a second payload. Persistent HC norms should be either pinned in their original canonical allocation and referenced by the prefill view, or copied once into a separately owned 3,932,160-B allocation while their original canonical payload is released. Never count both as one recovered payload. A CPU metadata map can retain `WeightRef` shape/kind/source coordinates; its copied `data` pointer must be explicitly rebound to the persistent owner, never left pointing at the released arena.

## Minimum prefill layer-view owner contract

`Prefill::Impl::wt` is currently `const core::WeightTable*` (`src/prefill/prefill.cpp:423-424,722-727`), and both layer execution (`~1983`) and fused lookahead (`~3006`) resolve through `LayerView`. The smallest usable seam is a prefill-only immutable `LayerView` resolver, selected before each layer's `run_impl` pass, that returns stable `WeightRef` metadata for the active layer and the permitted lookahead HC norm references. Preserve the existing short/chunk-major route as it is: the resolver is used only when long layer-major execution owns a layer pass, and the existing shared full `WeightTable` remains the decode/MTP/verifier table.

Minimum ownership rules:

1. Keep CPU metadata and source identity for all layer rows independently of device-payload lifetime. The active view resolves all canonical and native projection payloads for layer `l`, plus existing session/PLE special owners under their current paths. It must represent the distinct canonical and native payloads without aliasing one as the other.
2. Put all HC norms in one persistent owner (3,932,160 B device payload for this model), or explicitly allocate the 81,920-B worst-case lookahead overlap in addition to active-layer storage. The former is simpler and avoids layer parity/conditional-fusion residency rules.
3. Do not mutate the shared decode `WeightTable` or free/reuse its backing allocation while its `WeightRef::data`, graph nodes, verifier, MTP, or callbacks can be reached. The prefill resolver is a separate map/view, not a temporary rewrite of shared pointers. For actual capacity recovery, transition only after checked queue and reader retirement; before decode, rebuild/restore the full canonical and native owners, then publish valid shared pointers and only then recapture graph consumers. If preserving shared pointers cannot be guaranteed during the release window, keep the original allocation alive and claim zero recovered bytes.
4. A view owns or retains its payload owner for the full queued-work interval. On failed load/publication, keep old and destination banks alive through checked drain, publish no partial view, and return to a complete valid owner state or stop before exposing a dangling reference. A pointer table that is copied but refers into a bank that is later reused is not an immutable view.

This keeps the current chunk-major short path and avoids dangling shared decode pointers by construction: only the dedicated long-prefill resolver consumes the bank, while the shared table is switched back only after full decode owners exist. It does not itself solve R684's graph-destruction/recapture, MTP prompt callback, verifier timing, session RESTORE, cancellation, or source identity validation obligations; those remain separate gates.

## Concrete implementation gate

Source proves that the fusion exception costs only one next HC norm per enabled half, 81,920 B at an interior layer; a persistent HC norm pool costs 3,932,160 B. Source also proves current layer resolution uses the shared `WeightTable` and no existing per-layer payload loader/view is exposed. It does **not** prove allocations can be released safely, that 3.93 MB changes admission, or that this ownership design improves throughput.

Before treating the view as implementable/adoptable, require a component fixture that walks all 48 layer-family transitions under both fusion enabled and disabled, verifies each resolved name/shape/kind/source identity and byte count against full-resident references, and asserts the view carries current layer payload plus both HC norm pairs where required. Include transitions into/out of layer 1 PLE and final layer. The fixture must show shared decode table pointer values stay unchanged during prefill-view selection; after an explicit full-owner restore, validate shared pointers are live before graph recapture/decode. Inject short read, allocation failure, cancellation and callback failure; prove no partial publication or freed pointer can be observed. Then use the broader R684 lifecycle oracle (graph retire/recapture, MTP retained/deferred, RESTORE-and-continue, physical 262144 context) before any full model run. Only after these gates should allocator receipts and repeated clean long-input measurements decide capacity/performance benefit.
