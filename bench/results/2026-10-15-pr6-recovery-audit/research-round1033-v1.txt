# R1033 — QSA score-only 16-bit inputs: current API and precision audit

**Class:** decision support. **Question:** can current Strata SYCL GEMM use 16-bit QSA score inputs and retain FP32 per-head values through ReLU/head-sum, dead-key replacement and top-k? Source-only; Main owns the FP32 build and tests.

## Decision digest (7 lines)

- R589's stride blocker is gone: flatten Q; existing FP32-C `f16()`/`bf16()` APIs fit.
- Keep each head dot FP32 through per-head ReLU and ordered head sum; `*_out16()` rounds each head before this epilogue and is not equivalent.
- Append a converted dead-key row and gather it to each query's own `n_bid`, or compute a separate dead dot/query. Preserve partial-tail `+1e9f`, future masking and top-k semantics.
- The oneMKL wrapper has no explicit CPU fallback, but source does not prove provider, accumulation lowering or GPU/XMX execution.
- vLLM MiniMax M3 is a low-precision indexer precedent (BF16/FP8 stored operands, FP32 MMA/score), not Qwen3.8-Flash-Next quality evidence.
- First close Main's FP32 baseline, then measure one isolated 16-bit-input/FP32-output arm on the same inputs, with IDs, task quality, live bytes and full prefill.
- Keep production FP32 pending receipts; output epsilon does not excuse changed IDs.

## Layout and API fit

The scorer uses contiguous `q_idx[nq,4,128]` FP32, `idx_pooled[max_blocks,128]` FP32 and one 128-float FP32 `idx_dead`. Per query, complete blocks use pooled rows; `n_bid=n/4` uses dead. Four independent 128-element dots are ReLUed per head and summed in FP32 head order; only a partial dead/tail score gets `+1e9f`. Existing top-k consumes query-major scores; future blocks remain invisible.

Use `X[4*nq,128] * W[N,128]^T -> C[4*nq,N]`. Flattening heads is contiguous, so no 512-element input stride is needed. FP32 epilogue reads rows `4*q+h`, preserves head order, and writes the final query/block score. Dead differs per query: append dead as an additional W row then gather that column into each query's own `n_bid`, or compute one dead dot/query. Never replace the shared pool row globally. At physical 262144 tokens/block size four, `n_bid` reaches 65536; qualify last physical query/block. If pool capacity is 65,538, padded/appended GEMM rows are not selector IDs.

| API | Source contract and fit |
|---|---|
| `Gemm::f16()` / `bf16()` | 16-bit row-major X/W, FP32 Y, K strides for X/W, explicit output `ld`, beta supported, positive dims and `ld>=N`. Fits packed Q/K and FP32 C; no N multiple restriction in wrapper. |
| Own `*_out16()` | FP32 matrix accumulator/beta epilogue, then 16-bit Y; N,K multiples of 16; registered spans, in-order stream, native BMG matrix support; no fallback. Not equivalent because per-head Y rounds before ReLU/sum. |
| Isolated vLLM `beta0()` | FP16/BF16 input and FP32 MMA accumulator, but 16-bit Y and beta=0. BMG G21/G31 Level Zero Runtime queue; N%64, K%32, `ldy%8`, 64-byte bases and full rectangles. Returns event; adapter borrows Runtime/queue/owners. Wrapper waits. Not equivalent for the same early-rounding reason. |

At `nq=256`, N=65,539 (65,538 pool plus dead), per-head FP32 C is 256 MiB; padding N to 65,552 is ~256.05 MiB. Converted pooled+dead keys require 16,777,984 bytes; Q pack 262,144 bytes. Existing final score storage (64 MiB) cannot hold four-head C. Logical sizes only; separate dead dot avoids the appended row. Count scratch, arena peak and cache reserve.

`multiply()` validates spans, resolves `queue_for(stream)`, calls oneMKL row-major GEMM (`lda=ldb=K`, `ldc=ld`, alpha=1), then `finish(stream,event)`. It stores but does not pass `workspace_`. This wrapper is synchronous; owners live through completion and same-Gemm calls need serialized ownership. There is no explicit CPU/software fallback branch here, but queue/API names alone do not prove selected provider, FP32 accumulation lowering or XMX. Record actual device/backend, provider/version and device-execution evidence. Own native16 checks matrix support; vLLM requires BMG/Level Zero and live event owners.

No model-specific published accuracy result was found isolating FP16/BF16 q/k dot-input rounding for this scorer. Other models' BF16/FP8 support does not establish matching formula, cache representation, selection sensitivity or quality. Keep precision boundaries distinct: (1) converting FP32 q/k to FP16/BF16 changes input operands; (2) oneMKL exposes FP32 C, but actual accumulation lowering needs evidence (native16 source explicitly declares FP32 matrix accumulation); (3) FP32 C preserves per-head results, while `*_out16()` rounds before ReLU/sum. FP32 accumulation is not equivalent to FP32-input scoring.

## Options and minimum Main gates

1. **Existing oneMKL FP32-C GEMM:** pack Q/K to FP16 or BF16, flatten heads, then FP32 dead gather and epilogue. Least API work; conversion, C and epilogue may erase gains; dispatch/lowering are unproven.
2. **Strata 16-bit-input / FP32-output scorer:** fuse dot and FP32 ReLU/head-sum/dead/tail, avoiding full C. New kernel/schedule and codegen/resource evidence required; current `*_out16` is not this contract.
3. **Keep FP32 production; measure 16-bit GEMM privately.** Preserves current behavior but offers no adopted speed benefit absent a passing receipt.

After the FP32 baseline closes:

- **Path/cost:** pin binary/toolchain, actual queue/device/provider and GPU execution; verify ownership/synchronization. Count packs, C, epilogue, score buffer, arena peak/cache reserve. Separate host pack/submit/wait from device interval.
- **Math/routing:** same-quantized-input reference for FP32 per-head outputs isolates GEMM/epilogue; separately compare quantized-input scores and exact IDs with current FP32 scorer. Cover nq=1, partial and 256; N=1/nonmultiple/max; varying `n_bid`, partial/nonpartial tails, last physical block, ties/near-top-k, negative/zero dots, future columns, nonfinite policy, guards and lifetime. Preserve historical statuses.
- **Quality/speed:** paired same-model/config/input runs changing only score-input precision; record per-layer/query ID flips and teacher-forced logprob/NLL or task deltas against baseline repeatability. Time conversion+GEMM+dead/tail+top-k and repeated integrated prefill; separate warmup, device, host wait and full result. Adoption also requires long-prefill, RESTORE, task-quality and physical-context gates.
