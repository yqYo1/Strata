# R664 — Indexed Q6_K draft-head kernel and fixture audit

Read-only source audit of `sycl-mtp-indexed-head-v1`, compared with R660's MMVQ contract and corrected R658 v2. This artifact is still an unbuilt proposal; no source was applied, and no test/build/GPU/process/Git/cleanup or private/live-run inspection was done. Only this report was written.

## Finding

The Q6_K kernel design preserves the important arithmetic invariant for valid IDs: `Indexed=false` leaves the old row expression and no map read; `Indexed=true` changes only the source weight row and writes into the compact output row. It reuses `Q6KTraits`, the same accumulation/reduction path, and the existing dispatcher. The wrapper's byte extents and registry checks are mostly well bounded, and the API is enqueue-only on a validated explicit in-order stream.

There is one concrete MTP fallback bug in the archived `files/src/core/mtp.cpp`: after the optional `read_file(draft_vocab.bin, raw)` indexed branch, lines 799–801 mark `indexed_head_weights_` and `indexed_bind_complete_` for any eligible Q6_K head, even if the file was absent and no `dvocab_`/`n_dvocab_` was set. With no subset, legacy behavior should use the full head. Instead `indexed_head_` becomes true, `has_draft_subset()` returns true, and `record_forward` calls the indexed entry with `subset_rows == 0` and a null map; the new shape check throws and MTP fails. This contradicts the README's claimed no-subset legacy fallback and is a stop-ship correctness defect. Mark bind complete/borrowed head only when indexed subset loading actually succeeded.

## Kernel/API contract

For Q6_K, a row is `210 * (n_in / 256)` bytes. At the MTP input width 2,560, each row is 2,100 B; with the proposal README's 106,299-row subset the gathered head would be 223,227,900 B. For a 248,320-row full vocabulary, the borrowed full matrix span is 521,472,000 B. The map is 106,299 × 4 = 425,196 B; the T=1 Q8_1 activation is `(2560/32) × 36 = 2,880 B`; compact output is 106,299 × 4 = 425,196 B. These are logical spans, not measured VRAM deltas.

`IndexedHeadShape` checks positive dimensions, `int` bounds, `n_in % 256`, `ncols` 1..8, and overflow against `ptrdiff_t` before products. The wrapper checks full weights, map, activation, and output spans; `validate_spans` enforces 4-byte base alignment and output disjointness from inputs. A Q6_K block itself is 2-byte aligned; at the 256-wide boundary its 210-byte row stride can make alternate row addresses only 2-byte aligned, which is compatible with `Q6KBlock` (`alignof==2`). The base pointer still has the established 4-byte API alignment. The Q8_1 extent formula matches its 36-byte blocks and contiguous columns. The caller must pass the full weight-row count, not the subset count, for registry and bounds checks.

The new compat helper consults the actual `cudaMalloc` allocation registry under its mutex, accepts in-allocation interior spans, rejects host-kind or unregistered/short spans, and checks each complete logical span. The proposed MTP path obtains the full head and map through `cudaMalloc`; its Q8 scratch and output also use registered device allocation. Thus those production owners satisfy the registry scheme. It is intentionally stricter than arbitrary SYCL USM: a pointer not entered in this compat registry is rejected. The helper does not inspect device map contents; bind validates every host ID before allocating/uploading, while the kernel's defensive negative/too-large ID branch skips weight reads and leaves an all-zero output row.

Negative IDs are not admitted by the production host helper. The defensive device behavior is distinct and suitable for corruption containment; it is not permission to accept invalid `draft_vocab.bin`. Positive IDs at or above the full row count are likewise rejected on the host before publication. Duplicates and input order are retained, matching `gather_rows`; coupled inverse-map construction keeps the first occurrence as before.

`launch` retains Q6's required subgroup size 32, existing rows/warps dispatch, block iteration, FP32 accumulation order, cross-warp partial merge, XOR offsets, and compact column layout. For the real MTP `T=1`, columns are contiguous and sampler/map semantics remain compact subset indices followed by token-ID remapping. `multi_exact` does not change the T=1 dispatch, but the fixture properly runs exact=true and exact=false as separate process arguments for multi-column parity. The program sets the explicit mode once before stream/runtime use. The fixture must actually be launched twice by its owner; its source is not an orchestration harness.

Full weights, device IDs, Q8 activation, output, stream and graph-captured readers have coherent intended lifetimes: bind owns the immutable ID vector/device map, `NativeHead` owns the borrowed matrix, queue order puts quantization before MMVQ and sampling after it, and the added generate scope lease calls checked stream drain and graph-exec retirement before the later-declared native head is destroyed. The indexed kernel itself allocates, waits, copies, and inspects no device contents. This ownership remains source-only and needs the actual graph and destruction gates before qualification.

## Fixture coverage

The CPU contract fixture uses always-on-in-source `assert` only. It checks shape products for 2,560/full=200,000/subset=106,299/8 columns, type/shape gates, duplicate/nonmonotonic IDs, negative and too-large IDs, and an overflow case. If the eventual fixture build defines `NDEBUG`, these checks vanish; compile it with assertions enabled or replace them with an always-on check. It does not execute the bind path or kernel.

The GPU fixture compares the complete output allocation byte-for-byte (`reference == actual`), including guards, after legacy gather + generic MMVQ versus indexed Q6_K. It uses the same quantized Q8_1 activation and checks input/map/weight immutability, finite values, and defensive zero output for invalid device IDs. Across `cols=1..8` it has selected counts 1, 3, 5 plus 17, 33, 37 and 51, nonmonotonic/duplicate IDs, and a full row count of 37 (not divisible by four). That gives output-tail and compact-column coverage. Each exact-mode invocation includes `cols=1`, so N=2,560/T=1 is represented in both exact modes.

Coverage gaps relative to R660 remain: the GPU fixture does not include the one-Q6-block `n_in=256` boundary; it tests the actual MTP input width but only a small full matrix/subset, not the production 248,320-row head and 106,299 selected rows; and it captures then launches the indexed graph only once, not multiple replays. The CPU helper covers invalid host IDs, and the GPU fixture covers invalid device IDs, but neither is an actual `MtpDrafter::bind`/full-forward integration. Do not claim production-shape or graph-replay qualification from the fixture source.

## Compile and review gates

No definitive syntax error was found in the stored sources by inspection, but they have not been compiled. In particular the `Indexed` template path, SYCL graph-captured kernel, new compat registry declaration/definition link, and the `STRATA_ENABLE_SYCL` conditional MTP/generate layout all require the intended SYCL target build. Confirm the source resolver compiles the modified existing `src/sycl/compat.cpp` and that the MTP owner/layout TU is rebuilt together; do not mix the new class layout with stale objects. Verify false specialization IR contains no map read/branch, and true specialization retains Q6 arithmetic exactly. Then fix the absent-subset fallback before any build/measurement. Follow with CPU fixture under assertions, both exact-mode GPU fixtures, added n_in=256 and graph replay cases, registry/OOB negatives, and actual MTP selected-logit/token-map plus retirement/fresh-fault gates.

R660 and R658 v2 already contain the broader generic MMVQ arithmetic and prefill-allocation contracts; this report records only indexed proposal-specific findings and the concrete fallback/fixture deltas above.
