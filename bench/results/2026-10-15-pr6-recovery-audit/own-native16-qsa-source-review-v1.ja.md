# R818 typed QSA source review

Main reviewed the complete source assembly/patch anchors, new API and kernels, independent component fixture, reuse of R787 core, fixture lifetime changes, source/provenance manifests and README. Source-only proposal is archived on feature/sycl; not applied or executed. The patch contains two required blank context lines with one space; ordinary nested-patch whitespace diagnostics are not product trailing whitespace. Other staged artifacts pass diff --check.

QSA projection produces BF16 directly through existing out16 abstraction; fused scaled FP32 RMS/NeoX RoPE reads BF16 and narrows once. KV append uses BF16 directly into resident Q8 codes/FP16 scales. QSA indexer is an explicit remaining FP32 boundary. BF16 attention uses the reviewed one-part FP16 local fragments and FP32 local softmax/accumulators, then direct BF16 output; gate produces FP16 for the existing output GEMM. No full FP32 QSA tensor restore is inserted.

Domain checks use actual registered Device allocation extents in the queue context/device; physical pools are bounded by owner n_slots, page table by n_pages. Logical size cannot stand in for physical allocation size. All reductions execute uniformly; missing/invalid pages skip after reductions. Nonfinite KV groups avoid NaN/Inf-to-integer conversion. Page mapping must remain injective for writes and immutable while kernels execute. Owners and in-order queue establish scratch lifetimes.

Request preflight rejects streaming/host mirrors, rotated/Q4/hybrid pools, wrong mapping, unavailable per-session text RoPE table or unsupported device before layer work. Requires native16 long mode, resident INT8 K/V, STRATA_ROPE_TABLE=1, Mapping0 and no presence-based OLD switch. Short/decode routes remain old. Arena reservation is unchanged; reduced logical contents are not freed VRAM.

Follow-up risks/gates: strict gradual-underflow behavior of scaled RMS and BF16 conversion, fused norm/RoPE rounding, FP16 single-part Q/P effects, actual capability/resources, end-to-end selector causality, matched table-based FP32 control, physical262144 and RESTORE. No model-quality tolerance has been accepted. Main will first finish R810/R816 GEMM qualification, combine the independent backend/QSA proposals, then own all compilation and GPU tests serially.
