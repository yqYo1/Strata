# IQ3_XXS subgroup materializer v1

PROPOSAL ONLY. Product source, tests, builds, GPU work, Git and running processes were not changed. Every execution gate is NOT_RUN. Main owns application, execution and adoption. This is a new type-18 FP16 materialization candidate, derived from R619 and the pinned parallel-IQ v1 scalar formulas; no external engine was imported.

`source.diff` is incremental to **parallel-iq-dequant-v1/proposed/src/kernels/sycl/iq.cpp**, not the current product tree. Apply that earlier proposal first in Main's isolated reviewed build, retaining its `iq_parallel_decode.hpp`. Full replacement iq.cpp and the new header are under `proposed/`. No other format, F32 path, GEMM, decode route or public signature changes.

Set `STRATA_SYCL_IQ3XXS_SUBGROUP=sg16` or `sg32` before exec. These are the only accepted strings. Missing/empty/other values disable this candidate. With both candidate selectors disabled, legacy scalar is default. `STRATA_SYCL_PARALLEL_IQ_DEQUANT=1` remains the independent per-element comparator. For type 18, an admitted subgroup selection takes precedence; an unsupported requested subgroup falls through to legacy scalar even if per-element was also requested. Other formats retain the previous proposal's selection. Invalid subgroup selector plus per-element=1 retains the per-element comparator; fixture invalid-selector arms deliberately set per-element=0.

Each subgroup owns one contiguous 98-byte/256-value block. Four subgroups form a workgroup; padded subgroups return uniformly before collectives. SG16 has 16 iterations and SG32 has 8; j=iteration*S+lane. Lane zero loads block d once, then aux and db once for each of eight 32-value groups. R619's statement that scale is block constant is corrected: only d is constant. Four-lane leaders load grid words; eight-lane leaders expand parity; every participating lane calls both selects. All broadcasts use uniform source zero. There are no workgroup barriers or cross-subgroup exchanges.

`d` uses the identical `fp16_to_fp32(read_u16(block))` helper. Each db expression and final db*magnitude*sign retains the existing left-to-right FP32 order and existing f16_from_f32 conversion, including NaNs and signed zero. Main must retain -ffp-contract=off and no fast-math/reassociation. Public entrypoint shape, overflow, alignment and full-span validation precedes dispatch. Admission checks subgroup sizes and launch limits before submission. Unsupported widths decline to the old launch. Supported kernels have mandatory reqd_sub_group_size; a compiler/runtime failure is a failed gate, never silently accepted or retried after a possibly submitted command. The existing in-order queue and finish implement a single replacement product launch.

`gpu_fixture.cpp` reuses the complete old public-entrypoint corpus and CPU oracle, adding 27 full-array cases around 1/2/3/4/5/7/8/9/17 blocks, generic accepted 2-byte offsets, odd GU rows and padded workgroups. Quick has 69 and full has 75 cases, plus six unchanged F32 cases and 20 negative cases. Existing edge blocks vary every group's scale/aux. It also runs a separate required-width device collective probe with guards and actual lane/subgroup-size records. This probe is not proof of the product kernel's lowering; review product IR too. No CPU model claims to validate GPU shuffles. The comparator compares entire source/output/guard arrays strictly between OFF and every candidate, including NaN sign bits. CPU oracle NaN sign latitude remains only the inherited CPU/device accounting.

See main-validation-plan.md for execution and retention. Source/body hashes and inputs are recorded in source-pins.json; artifact-sha256.json identifies this proposal. No runtime samples or raw captures exist.
