## Finding

**The current streamed-KV contract does not inherently prevent layer-major ascending-chunk execution.** It has the source-level ingredients needed to preserve attention history: every streamed QSA layer owns a complete authoritative K/V host copy in identity logical-page order; prompt execution restores all pages before the current chunk into a separate full-logical-range staging pool, appends current K/V into the authoritative host copy and staging pool, and performs that chunk's causal attention before moving to the next chunk. At 262,144 maximum cells with 32,768 configured main-resident cells, the QSA state has 65,536 logical pages and 8,192 resident slots (page size four). The host copy remains 262,144-cell-capable; the resident slot pool is only a decode/cache residency policy.

The older PR#6 route is still not directly reusable: it explicitly rejects all `kv_mode != 0` (`d0c5dda...:sycl/src/prefill/prefill.cpp:1928-1932`), and current root prefill differs. The current route's staging pool itself is sized for the full logical page count and is sourced from the prefill allocation/borrowed expert slots (`src/prefill/prefill.cpp:503-530,777-785`). A layer-major port can reuse the *current root chunk implementation* one layer at a time; it must not replace the complete host backing with a 32,768-cell ring or run a later chunk without restaging its earlier logical pages.

This is a source feasibility result only. It does not establish that a layer-major port exists, fits the target allocation budget, passes GPU correctness, preserves callbacks/MTP in a particular caller, or improves speed.

## Ownership and address contract

`kv_plan` computes `pages = ceil(max_cells/page_size)` and starts with `slots=pages`; streamed main mode selects `slots=ceil(max(configured_resident_cells, qsa_kv_resident_min())/page_size)` (`src/core/layer.cpp:501-518`). The minimum is 20,480 cells (`:534`), so 32,768 requested cells select 8,192 slots at page size four. At maximum 262,144 cells, pages are 65,536. `qsa_state_init` allocates the device K/V pools for `slots`, a page table for all logical pages, and the CLOCK map only in mode 1 (`:537-552,555-609`). For each streamed QSA layer it separately pins `pages * kv_block_bytes(...)` host bytes, maps them for device access, and carves the authoritative host K/V arrays in identity order (`:633-663`). Those allocations are per layer; `session_init` creates one `QsaState` for every owned QSA ordinal (`src/core/session.cpp:101-118`).

The main mode-1 residency map is global *to a QSA layer*, not global to the whole prompt: `page_table[block] -> slot or -1`, `slot_block`, `slot_stamp`, `slot_ref`, miss lists, and control counters are all inside that layer state. Initialization and `session_zero` reset the map to all blocks absent; the host K/V bytes are deliberately not cleared because no unwritten cell is reachable (`layer.cpp:678-689,693-720`). There is no eviction of the authoritative host copy. Decode selection calls `qsa_kv_resolve` after top-k; the resolver protects selected pages for one epoch, chooses unselected CLOCK victims, remaps the device page table, and copies misses from the host copy (`layer.cpp:732-737`; `include/strata/kernels/kv_stream.hpp:3-20,50-75`; `src/kernels/cuda/kv_stream.cu:82-157,160-169`). The map epoch/hand/counters persist across calls. Do not reset this map between prefill chunks or layers except at the existing sequence-reset boundary; each QSA layer has its own map.

Prompt execution has a separate map and pool. `Prefill::init` creates `m.ident_table` with `ident[b]=b` for every logical page (`prefill.cpp:777-785`), and `take_stage` allocates staging storage with `q0.n_pages`, not `q0.n_slots` (`:503-530`). At each QSA layer/chunk, when `st.kv_mode == 1`, `run_impl` copies host pages `[0, ceil(p0/page_size))` into that separate pool via `kv_stage_from_host`; then it appends current cells at logical `p0` to the real streamed state and supplies the stage pool to the append routine, so current-chunk pages are also available at identity addresses for prompt attention (`:2024-2053`). Attention reads `pools_of(m.stage,m.ident_table)` in staged mode (`:2182-2196`). The K/V append implementations write the host copy always and write the resident slot only when the main page table says the page is resident; staged append additionally writes the prompt pool. `include/strata/kernels/kv_stream.hpp:15-17` states this writer contract. This is the decisive reason the 32,768-cell main residency limit does not truncate prompt history.

`kv_stage_from_host` performs copies into the beginning of the staging arrays and assumes identity addressing; it has no eviction or page map (`kv_stream.hpp:80-88`; CUDA reference implementation `kv_stream.cu:244-252`; current configured SYCL resolver should be reviewed at its own source before implementation). It must not be called with a staging capacity smaller than the maximum restored logical page range. Chunk ordering must remain monotonic within each layer: prior host pages are valid because that same layer already processed earlier chunks. The stage pool is overwritten/restaged on every chunk, so it does not need cross-chunk retention, but it does need enough capacity for all `ceil(max_context/page_size)` pages and correct current-chunk append ordering.

## Can each QSA layer be traversed separately?

Yes, subject to preserving the full root `run_impl` chunk path and its state. For each layer `l`, invoke its existing one-layer range over chunks in increasing `p0`; retain that layer's QSA `idx_tail`, `idx_dead`, `idx_pooled`, `idx_block_pos`, KV host copy, KV residency map, page table, and RoPE position mapping across chunks. The query at a position must be selected and attended before any later chunk is consumed. Then move to layer `l+1` only after all chunks of layer `l` complete. The saved residual output for every chunk becomes that same-position input to layer `l+1`. A schedule that processes chunk 0 for all layers then chunk 1 for all layers changes the dependency: chunk 0 at layer `l+1` needs layer `l+1`'s KV/index state for its own prior positions, which would not yet exist. The layer-major schedule is the valid topological order.

The current root `run_impl` uses layer slices (`LB`,`LE`) and local QSA/GDN state ordinals; it resets local ordinals by counting layers below `LB` (`prefill.cpp:1713-1714`). It applies PLE only when the range includes layer 1 (`:1578-1588`) and the PLE history advances tokenwise/chunkwise at that layer (`:1947-1960` in current file). Thus PLE should run once on the layer-1 pass; do not restore/reset its convolution history or repeat its embedding residual updates on each later layer. By contrast, PR#6 saves/restores `ple_prev` scalar token bookkeeping before each layer because its old loop/callback contract did that (`d0c5dda...:1941,2035-2039`); that exact workaround must not be transplanted without checking current root PLE fields and callbacks. Current PLE history is session-owned and sequence-persistent (`src/core/session.cpp:48-52,124-126,139-163`).

GDN recurrence and convolution history are likewise layer-local and persistent. `session_bytes` accounts a distinct `gdn_state_floats` carve per GDN layer; `set_gdn_layer` points buffers into that layer's recurrent plus conv state (`session.cpp:38-44,64-65,165-175`). Keep each layer's state across the ascending chunks and do not reset on layer entry. There are 36 GDN and 12 QSA layers in this geometry; do not allocate or count 48 GDN states.

## Full-capacity boundaries and canonical spare row

For `max_cells=262144`, page size / indexer block is four: logical pages = 65,536; cell positions are `0..262143`; no cell at 262144 may be appended. `qsa_state_init` gives the streamed host and page arrays 65,536 logical pages. Its indexer has `pooled_rows = max_cells / idx_block + 2 = 65,538` (`layer.cpp:503-505,610-614`). The native batch indexer accepts exactly `p0+n <= max_cells` and appends only completed four-cell blocks (`native_qsa_indexer.cu:255-289`). It writes the block's spare row at `b+1`; for the last complete block `b=65535`, that is row 65,536, so the extra allocated rows keep the canonical spare address in range at full capacity. `append_first` writes `pooled[0]` and `dead`; it does not imply that row 1 is initially written (`:143-169`). Keep the extra row allocation and the batch append's exact full-bound check; do not shorten to `max_cells/4`, clamp a valid last cell away, or treat 262144 as a valid position.

The selection state is causal and order-sensitive: prompt steps carry `pos`, `n_kv=pos+1`, `n_bid=n_kv/4`, and selection width (`qsa_step_fill`); indexer appends chunk rows in position order before scoring/top-k and attention (`prefill.cpp:1707-1711,2060-2096`). A layer-major implementation must use the absolute token position `pos0+c0+t` consistently for step fill, RoPE, host K/V page address, QSA indexer append, and residual row mapping. Test capacity with a real final-cell append at 262143 and an explicit rejection of the next append; the old 256K allocation-only sample in R559 is not this proof.

## Shared/global state and order hazards

- **Session/global sequence state:** `session_zero` resets residual, all per-layer GDN states, each QSA state/map/indexer, PLE history, and PLE token window (`session.cpp:139-163`). A layer-major traversal must call this only once at sequence start, not per layer/chunk. `g_kv_resident`/format switches are process-global planning choices captured when session state is sized/initialized (`layer.cpp:491-518,532-535`); no per-layer traversal should toggle them mid-session.
- **QSA state:** each layer's host K/V, page table/map, indexer tail/dead/pooled/spare, and absolute-position state advances once per chunk. Never share these arrays between QSA layers or clear them to make stage restoration convenient. The dynamic map is not used by the staged prompt attention's identity table; it still needs to remain internally correct for later decode and any non-staged reader.
- **Residuals:** chunk `c`'s post-layer residual must be retained until layer `l+1` consumes chunk `c`. Existing root scheduler's scratch region is reused across layers/chunks; a layer-major route requires full prompt residual storage (host and/or device) or an equivalent bounded tiled schedule with a proven dependency. Retain the R559 callback rule: intermediate-layer outputs cannot be published as final checkpoints; only the final layer/final chunk is a whole-model boundary.
- **PLE:** PLE embedding rows depend on prompt tokens and previous-token window; history advances only at layer 1. Pre-gathered/current `m.ple_emb` buffers are per chunk. The PLE token window must advance exactly once and its history must survive through subsequent chunks; do not rerun layer 1 or reset it at each layer.
- **Expert/cache/stager queues:** PR#6's per-layer expert cache is separate from KV state. Expert staged host pointers must remain leased through copy-queue completion (`stager->issued_one`, queue wait, finish); residency must only publish after successful upload. Current R541 and R542 contract reviews remain applicable to async source and captured pointer lifetimes.
- **MTP/draft callback:** layer-major emits only final whole-model chunk output to the caller's existing `on_chunk` callback, or it would give the drafter/verifier an intermediate-layer residual. Keep `on_stage_chunk` checkpoint readiness false until the final layer and final position. Current serving keeps MTP object/graphs alive across requests; PR#6's unchecked local `Restore` waits are not sufficient lease retirement after sticky queue errors (R559; R541/R542/R547/R548). Do not free or rebind MTP workspaces/graphs as part of this prefill traversal. The current `draft_kv`/fallback prompt callback must see each final residual/token pair exactly once, in ascending chunk order; the draft K/V state is separate persistent state and is not eligible for reuse as target QSA KV.
- **Cancellation/failure:** on any compute, copy, stager, callback, allocation, or queue-drain error, do not report checkpoint-ready or allow the next layer/decoder to consume partially advanced state. Drain/retire every submitted reader before reusing host/stage/residual/expert memory; if completion cannot be proved, retain owners and fail the request. Restore callback pointers, range, borrowed residual pointer, cache, stage pointers and statistics contexts only after checked successful completion. R559 identifies the old destructor's unchecked waits as a retirement hole; adapt its idea, not that destructor.
