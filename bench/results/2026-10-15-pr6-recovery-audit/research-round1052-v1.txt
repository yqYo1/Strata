# R1052 — Qwen4Exp loaded GDN layout and output-gate contract

Classification: **decision support**, source audit only. Read R1048, R1049 review, shared index, eligibility pins, and compact loaded-GGUF metadata first. No model tensor/GGUF payload read, execution, tests, Git/process inspection, product/source edits, or XeStrata material.

## Decision

The actual loaded shard metadata is `qwen4exp`, `state_size=128`, `group_count=16`, `time_step_rank=48`, `inner_size=6144`, `conv_kernel=4` (metadata JSON, 2026-10-15 audit; file stat and header digest are recorded there). With the corresponding 128-wide heads, this is 16 K heads and 48 V heads. The exact pinned llama.cpp converter transform maps contiguous grouped source V slots to the tiled order used by Strata’s `head % 16` key lookup. Thus, **if** this GGUF was made with this converter convention, Strata’s current V slot `l` is already the tiled slot; do not apply R1048’s grouped-to-tiled adapter a second time. The GGUF header proves geometry, not which converter produced its tensor order.

The public base-model author config at Qwen’s Hugging Face revision `de4b8e4d43b917e7706784d8bb445c9af86a3540` declares `text_config.output_gate_type="sigmoid"`; the ISTA-DASLab GGUF card identifies `Qwen/Qwen3.8-Flash-Next` as its base model. This is the strongest available target-specific activation evidence, but neither the config nor converter revision is embedded in the loaded GGUF metadata. Therefore sigmoid is the expected source contract for this model, subject to artifact provenance; the GGUF alone cannot prove the setting. SGLang’s Qwen4Exp GDN inherits its Qwen3.5 loader, which passes loaded `output_gate_type` to RMSNormGated. If absent, that operator defaults to swish/SiLU. The separate Qwen4Exp **full-attention** gate is explicitly sigmoid in its own attention path and must not be used as evidence for the GDN norm gate.

## Exact layout transform (pinned source conventions)

Pins: llama.cpp `3cf03257f219afbe7334045ff7c6a06ac68c627d`; SGLang `877be2974aa151a984e52822c028276c2b1e9303`. Eligibility v1 pins converter, loader, Strata `fused_gdn.cpp`, and license hashes. Sources are design/format evidence only.

In source/HF grouped order let `s=3*k+j`, where `k∈[0,16)` is the K head and `j∈[0,3)` is the V head within that K group. The converter `_reorder_v_heads` reshapes `[16,3,D]`, swaps those axes, and flattens (`conversion/qwen.py:453-476`). Thus source slot `s` is written to tiled GGUF slot

```
l = 16*j + k = 16*(s % 3) + floor(s/3)
```

Inverse (GGUF tiled slot to grouped/SGLang slot):

```
s = 3*(l % 16) + floor(l/16)
k = l % 16
j = floor(l/16)
```

Sanity: `s=0,1,2` (three V heads under key 0) become `l=0,16,32`; `s=3,4,5` become `l=1,17,33`. Q and K rows stay unchanged; only V rows in fused `in_proj_qkv.weight` are reordered (`qwen.py:578-586`). The converter also reorders Z projection rows (`588-590`), B/A projection rows (`592-595`), A_log/dt_bias/dt_proj head rows (`596-603`), the V-only channel section of conv1d while retaining Q/K channels (`605-612`), and output-projection input columns (`614-616`). The NVFP4 companion transform applies the same row/column mapping to packed values and scales (`478-563`). A/B correspond to SGLang `in_proj_ba`; A is the decay/time-step gate, B is beta.

Do not reorder the per-head norm scale: it has only `head_v_dim=128` entries, shared along each head feature axis, not a 48-head axis. The Qwen4Exp loader builds this norm with `head_v_dim` (`qwen3_5.py:504-515`); llama.cpp’s Qwen4Exp tensor shape is `{head_v_dim}` (`src/models/qwen4exp.cpp:235-238`). Converter’s V permutations do not mention a norm tensor. This remains identity even when other V-indexed tensors move.

SGLang Qwen4Exp says checkpoint input uses Qwen3.5 head-first layout and maps separate `in_proj_qkv`, `in_proj_z`, `in_proj_b`, `in_proj_a` into fused modules (`qwen4_exp.py:2278-2291`). Qwen3.5 splits `[Q | K | V | Z]`, reshaping V/Z in ascending head order and B/A likewise (`qwen3_5.py:674-692`). This source grouping is compatible with a later GGUF tiled transform. The GGUF card documents base model and GSQ/RCO assembly, but not converter revision or row-transform recipe; the original conversion record and loaded HF config are unavailable.

## Recurrent-state adapter and candidate alternatives

Strata state indexing in `src/kernels/sycl/fused_gdn.cpp:106-110,133-165` is `H_local[r,l,v]`, with linear offset `((r*48+l)*128+v)`; `r` is the K/state dimension and `v` the V feature. SGLang chunk GDN uses per-head state `[head,V,K]` (R1049 correction to R1048, pinned FLA chunk state source). For matching heads the exact layout relation is therefore:

```
H_sglang[s,v,r] = H_local[r, l, v]
l = 16*(s % 3) + floor(s/3)       # grouped source slot -> tiled slot
```

Equivalently, reading a Strata tiled slot `l` as the SGLang head requires `s=3*(l%16)+floor(l/16)` and matrix transpose `S[s,v,r]=L[r,l,v]`. The 128×128 dimensions being square do not eliminate the transpose. This state conversion is for comparisons/adapters; it does not imply converter weights reorder runtime recurrent state.

Two viable implementations remain, pending identifying actual GGUF order: (A) keep GGUF tiled rows and Strata `l%16`, adapting state with the equation above for SGLang comparison; (B) convert/checkpoint rows back to grouped order and use SGLang `floor(s/3)` association, consistently across V, Z, A/B, decay parameters, conv V channels and output columns. A partial permutation is invalid. Against A, strong evidence against includes an exact conversion receipt showing this file retained source grouped rows, or a same-input tagged projection test where converter-predicted tiled channels fail and grouped channels match. Against B, the pinned converter implementation and GGUF card’s standard llama.cpp-compatible artifact context favor A, but are not proof of exact build provenance.

## Activation and numeric gate

Qwen author config `https://huggingface.co/Qwen/Qwen3.8-Flash-Next/resolve/de4b8e4d43b917e7706784d8bb445c9af86a3540/config.json` gives 16/48 heads, 128 dimensions, conv 4, BF16, sigmoid and RMS epsilon `1e-6`. The ISTA-DASLab card at `https://huggingface.co/ISTA-DASLab/Qwen3.8-Flash-Next-GSQ-RCO-GGUF` identifies that base and describes standard GGUF assembly, but not use of pinned `3cf03257…` converter code. Sigmoid is source-expected; local metadata omits it.

Qwen4Exp uses `Qwen3_5LinearDecoderLayer` (`qwen4_exp.py:1781-1802`); the linear layer reads `config.output_gate_type` and passes it to `RMSNormGated` (`qwen3_5.py:389-391,504-515`). RMSNormGated defaults to `swish` (`layernorm_gated.py:244,365-367,497-505`); Qwen3Next config defaults `output_gate_type=None` (`configs/qwen3_next.py:72-74,183-208`), so absent an override it becomes swish/SiLU. The author config explicitly selects sigmoid. The separate Qwen4Exp full-attention gate also uses sigmoid (`qwen4_exp.py:1934-1943`) but is not the GDN norm gate. Local Strata GDN uses sigmoid (`fused_gdn.cpp:260-287`), matching public config, not proving this artifact’s provenance.

Numerical adoption still requires matching SGLang’s actual target path and dtype boundaries as R1048/R1049 document; do not treat llama.cpp conversion format as a universal numerical standard. Exact SGLang backend/runtime selection is not inferred from Python model definitions. Preserve physical context 262144, state/history lifetime, bounds/fault and restore gates independently.

## Smallest falsifiable fixture

Use synthetic tagged tensors only (no GGUF model read): for each source `s`, assign unique per-head markers to V/Z, A/B, A_log/dt_bias, conv V channels, and output-column blocks; tag Q/K separately. Verify converter equations above against actual generated indices for all 48 slots; assert Q/K identity and norm identity. Feed the same synthetic projection values through source-grouped SGLang splits and a converter-transformed local view. Require equality after applying one consistent permutation to every V-indexed object; deliberately permute only V as a negative control. Use a non-symmetric tagged `[K=128,V=128]` state so the head gather and K/V transpose each independently fail if omitted. Then add a same-input layer fixture using author-config `output_gate_type=sigmoid` and a separate `None` control; compare pre-norm output, normed/gated output and final projection to isolate activation selection. Include exact artifact config/conversion receipt before claiming loaded-GGUF identity; otherwise report the two layout possibilities and sigmoid as source-expected only.
