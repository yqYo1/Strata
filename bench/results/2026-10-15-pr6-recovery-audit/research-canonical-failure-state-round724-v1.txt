## Conclusion

I found no concrete use-after-free, double-free, or ordinary-return path that resumes decode with incomplete ownership in the reviewed v3 state machine. Confirmed allocation OOM before retirement has a rollback path. Once graph retirement or owner withdrawal is partial/uncertain, the proposal uses fail-stop with source owners still held or with complete restored owners; it does not resume decode. The main remaining evidence gap is fault-injected execution of the actual integrated candidate, especially around graph retirement and the combined restore sequence; existing host/component fixtures are unexecuted and do not establish runtime or graph semantics.

## Entry, leases, and reservation rollback

The request checks route support, intact Full states, verifier preconditions and required graph/session objects before taking `occupied`. `Exclusion` clears that flag on every ordinary return and exception unwind after acquisition. Short/default-disabled requests return through the existing path before acquiring it. Canonical mode also requires NativeEmbed and a canonical Full owner. The native-only route remains distinct: it does not prepare a second canonical bank, and `NativeDense::enter_layer_bank` retains its original prepare-before-withdraw behavior.

With canonical mode enabled, the transaction prepares canonical destinations first, then reserves the native per-layer bank, while original full owners and publications remain intact. If canonical bank or pool allocation returns confirmed OOM, canonical prepare leaves `Full`; if pool allocation fails after bank allocation, the bank is checked-freed before returning. If native reservation then returns confirmed OOM/null, `Reservations` cancels the native reservation and canonical `Prepared` allocation in that order. These are ordinary returns because no graph reader or original publication has been retired. Unexpected allocation status, successful-null, contradictory owner, or uncertain free is fail-stop. The v3 guard is conditional on the canonical pointer; in native-only mode the existing enter method handles allocation and rollback itself.

The canonical prepare catch distinguishes pre-publication host exceptions (returns false with `Full` owners intact) from an exception after it marks state `Prepared` (fail-stop). Queue upload/synchronization errors use checked fail-stop. The raw local allocation pointers are released before propagating a map-build exception. This preserves ownership on the reviewed paths; injected failures are still needed to validate all allocator/runtime combinations.

## Retirement, enter, and activation

The transaction drains the main/MTP callbacks, retires the verifier's ordinary dense graphs and, when canonical mode is enabled, retires its norm-bearing commit graph, then retires session graphs. `retired` becomes true only after those operations return. Any exception in that retirement block fails closed and aborts rather than letting the reservation guard free candidate storage while graph completion is uncertain. Verifier graph-destroy failures also fail-stop at the point of partial destruction. The program does not treat a boolean retirement failure after the preflight/prepared boundary as a recoverable no-op; it aborts because graph state may already be partial.

After retirement, native PLE publication is withdrawn, native enter withdraws its selected table refs and frees original native owners, and canonical enter publishes persistent views, nulls the borrowed arena owner, marks `Bank`, then checked-frees the original arena. A failure during native/canonical enter is fail-stop, not a return that resumes with half-withdrawn owners. PLE rebind errors also fail-stop. The PLE binder checks all required pointers before mutating its fields; native key fields are restored separately from the canonical projection fields.

Per-layer activation first drains the prior callback readers, activates the native view, then activates the canonical view over that native overlay. Canonical `activate` constructs/validates its next overlay before retiring its old view; it synchronizes before clearing the old view, submits H2D copies, synchronizes completion, and only then publishes the new view. Invalid state/host allocation/overlay collision returns false; CUDA submit/completion uncertainty fail-stops. A false callback result or C++ exception unwinds through the transaction restore guard; the callback is cleared before full restore. Thus a successful native activation followed by a canonical host-side false does not ordinary-return to decode: the wrapper restores both owner sets or stops. Runtime-injected partial-copy behavior remains untested.

## Restore order, OOM, PLE, and destructors

Restore drains main and MTP work and clears the callback. Native full restore happens first. It synchronizes readers, allocates all original owners before publishing any, and on confirmed OOM releases the partial allocation set and returns false with native Bank state/table withdrawal intact. The wrapper turns that failure into fail-stop. Canonical restore follows: it synchronizes, allocates the exact original arena, uploads it, validates the withdrawn table, republishes full refs, and enters `RestoredPending`. Confirmed OOM leaves canonical Bank/persistent owners intact; because native may already be fully restored, the wrapper fail-stops rather than exposing a mixed state to decode. This ordering does not lose the native owner set: it is restored Full while canonical bank/pool remain live. The fatal message's “both owner sets retained” means both formats' backing owners remain available, not that the native layer-bank allocation itself is retained after native full restore.

The wrapper cancels a merely `Prepared` canonical owner, cancels any still-prepared native bank, binds full canonical PLE projections, restores a native PLE key if one was present, then calls `finish_restore` only when PLE fields no longer point into the persistent pool. `finish_restore` checked-frees bank/pool and marks Full; an uncertain free aborts. Session graph recapture and verifier resume occur after owner and PLE publication are restored. Any PLE bind, finish, recapture, or verifier-resume failure is fatal; the code does not clear `retired` and continue. In particular, canonical restore OOM after native restore is fatal, not an ordinary return.

The declaration order is deliberate: `Restore` is destroyed before `Reservations`, which runs before `Exclusion`. On exception after retirement, restore must complete (or fail-stop) before prepared allocations or `occupied` are released. On pre-retirement failure, `Reservations` releases only prepared banks, then `Exclusion` clears. `CanonicalDenseBank`'s destructor aborts unless state is Full and bank/pool are null; `NativeDense` likewise aborts if destroyed in Bank. These destructor guards prevent silent owner loss on an escaped transition, but are not a substitute for process-level fault injection.

The ordinary-return cases are limited to confirmed OOM or preflight/host validation before publication withdrawal; uncertain graph/copy/free/runtime status and every restore/publication failure stop.
