# R683: applied prefill head release source safety review

Scope: read-only review of the applied `prefill-head-release-v1/source.diff` against the current source and the unbuilt `prefill_head_roundtrip_fixture_v1.cpp`. No test, build, GPU run, environment scan, or runtime fault injection was performed. This is source inspection, not a claim that device completion behavior has been exercised.

## Call path and ownership order

The default-off and short-prompt path calls the existing prompt/expert wrapper directly. The new path is selected only by exact `STRATA_PREFILL_RELEASE_HEADS=1`, a positive prompt chunk, and `n > chunk`. It then rejects configurations outside layer-major, supported native MTP4, noncoupled, single-GPU operation and rejects logits/NLL diagnostics before detaching anything. The serve call passes its verifier; standalone passes `nullptr`. Both pass the same `NativeHead`, MTP owner and main stream.

On an eligible request, preflight first asks the verifier and MTP to validate the current target owner. MTP drains its stream and snapshots/validates the device vocabulary map into bounded host vectors; NativeHead allocates its exact-size packed-byte snapshot. If NativeHead preparation fails, the MTP prepared flag is cancelled and no allocation is detached. The boundary then synchronizes the ordinary main stream, waits for verifier commit completion, synchronizes verifier compute and copy streams, destroys verifier head-reading graphs, drains MTP's stream and destroys its full-round/step graph families. Only after those retirements does it snapshot and free the target head, then free MTP's duplicate draft head. The prompt executes with its KV-only MTP prompt graphs and cache/state alive. On normal return, false return, or a thrown prompt exception, the boundary synchronizes main and MTP prompt work, restores the target allocation from exact packed bytes, regathers the MTP subset from the restored target using the preserved map, and then re-enables NativeHead, MTP and lazy verifier graph recapture. Prompt false/error status is preserved after mandatory restoration. Restore/retire operations are `noexcept` and use fail-stop paths for uncertain completion or allocation/copy failure, avoiding unwind through live owners.

## Findings

No direct dangling-pointer, known-order UAF, or default-off regression was established by the reviewed source. The principal safety properties are explicit: all full-head reader graph families are retired before free; verifier commit/copy callback work is drained before graph destruction; main and MTP prompt queues are drained before restore/reuse; MTP vocabulary IDs remain allocated and are checked for validity and immutability; and the target object remains at a stable address throughout release. Retired graphs are recaptured lazily after restoration. The per-invocation `HeadReaderLease` is declared after `NativeHead`, so it runs first at teardown and retires MTP readers before the borrowed target owner is destroyed. Its default-off action is a no-op.

The retained packed bytes are copied byte-for-byte without interpretation. `NativeHead::prepare_prefill_weights` verifies the allocation size against `native_mmvq_weight_bytes(type_, n_in_, n_out_)`, caps the snapshot at 1 GiB, and does not alter `type_` or dimensions. Thus source inspection finds no forced conversion or assumption that Q6 is Q5. The proposed fixture asserts the current Q6_K output head as type 14, dimensions 2560×248320, 2100 bytes per row and 521472000 packed bytes, then compares exact restored bytes and projection logit bits. That fixture is narrowly a target-head component test; it does not exercise MTP map/gather, verifier graph retirement, callbacks, prompt unwind, or combined serve/standalone lifecycle.

The only rollback caveat is deliberate fail-stop behavior: after the owner transition begins, any unprovable stream/graph completion or target/draft restore failure terminates with owners retained rather than returning an error and risking reuse. This is appropriate for the stated unknown-DMA rule, but means ordinary recoverable rollback is not implemented for those device failures. The `with_prefill_head_release` helper itself assumes backend transition methods honor the `noexcept` contract; its compile-time check enforces that signature. The prompt's local temporary cleanup and completion semantics are relied on by the comment and subsequent main-stream synchronization, and should remain covered by Main's isolated source/build validation.

## Review boundary

These conclusions are limited to inspected call ordering and source state. The new fixture was not built or run, and no full lifecycle test exercised both a serve verifier and MTP across an injected prompt exception/cancellation. The fixture's heap-owned `Owners` plus `_Exit` on failure correctly avoids C++ unwinding of potentially live device owners, but success validates only NativeHead's Q6 packed snapshot/restore and projection behavior. Before enabling the opt-in for measurements, Main's fresh SYCL build and prepared fixture run remain the needed device evidence; a later integrated test should cover verifier/MTP owners and both false-return and throw restoration paths.
