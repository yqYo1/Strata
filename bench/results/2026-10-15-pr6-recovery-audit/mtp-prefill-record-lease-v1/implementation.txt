Confirmed ownership gap
  Current src/core/mtp.cpp:724-800 MtpDrafter::prefill, E-4 branch selected by
  !per_group_sync && n > 0, allocates rec at line 760, fills it once, then
  cudaMemcpyAsync(pf_dev_, rec.data(), ...) at line 773 submits its contents.
  src/sycl/compat.cpp:253-260 directly submits queue(st).memcpy and does not
  retain a host owner or wait for the event. rec is immutable while alive, but
  its lifetime ends on every function return and ordinary exception unwind.

  After H2D, each of these edges can destroy rec without a successful checked
  same-stream retirement edge:
    - The H2D API reports failure, possibly after submission.
    - capture_prefill_dev(T, err) returns false.
    - Any group D2D copy or cudaGraphLaunch reports failure.
    - The existing final cudaStreamSynchronize(cs_) reports failure.
    - A C++ exception from capture/submission/error-string construction unwinds.
  An already cached graph has no implicit wait. A first graph capture may call
  finish_capture's existing cudaStreamSynchronize, whose status is currently
  ignored; that call is neither universal nor sufficient to replace the final
  checked retirement edge. This proposal does not alter capture behavior.

Proposed implementation
  Reuse include/strata/prefill/draft_uploads.hpp::DraftUploadGuard unchanged.
  The record vector is constructed and filled first. The drain status and
  record_lease are declared after rec. Arm immediately before the first H2D
  enqueue, including the possibility that an enqueue reports failure after
  submitting work. The lease stays armed across all groups and graph captures.

  All early returns and ordinary C++ exception unwinds after arm invoke the
  existing guard destructor before rec destruction. Drain calls the actual
  cudaStreamSynchronize(cs_) and accepts only cudaSuccess. A thrown drain is
  caught by the existing guard; status begins at cudaErrorUnknown so that a
  thrown call cannot be logged as a successful drain. On a non-success drain
  or exception, the fatal callback prints the status and calls std::abort
  while rec, drain status, OnDevice, member device storage and enclosing caller
  owners are still alive. The guard also has its existing unconditional abort
  fallback if a fatal callback returns. Abort does not unwind these owners.

  src/sycl/compat.cpp:64-77 attempt() checks sticky runtime state before its
  body. A sticky error can prevent the drain body from waiting at all. Such a
  non-success therefore causes fail-stop; it is never treated as retirement.
  This is a conservative source-lifetime contract, not recovery, rollback,
  a guarantee of a completed GPU drain, or a model-state restoration mechanism.

  The existing final sync remains in its original position and checks its
  original result. Only after success does record_lease.retire() run. A failed
  final sync leaves the lease armed, so the destructor makes one checked drain
  attempt and then fail-stops if retirement still cannot be proved.

  Lease/bounds logic is enabled only for STRATA_ENABLE_SYCL. CUDA/HIP inference
  implementation and validation are outside this task. The per_group_sync=1
  loop is byte-for-byte unchanged. No graph node, math, stream/queue selection,
  row order, H2D/D2D size for valid input, graph launch, normal synchronization,
  timer, or current err string is changed. Healthy E-4 retains one explicit
  final sync and the same existing cold-capture syncs; the retired destructor
  adds none. Error paths may perform one additional checked drain as required.
  The new fail-stop stderr diagnostic supplements existing error messages.

Related bounds and 256K
  E-4 previously computes signed n * (5 + NHp), then multiplies by sizeof(int32_t)
  for allocation and upload. The candidate rejects invalid NHp before 5+NHp,
  then rejects n above either INT64_MAX/per_row or SIZE_MAX/sizeof(int32_t)/per_row
  before multiplication. The existing "mtp prefill: the input records do not fit"
  string is reused. The resulting records count is computed once and used for
  device allocation, pf_cap_, and host vector construction. Positive per_row
  makes all constituent n, 4*n, and n*NHp record offsets fit the same count.

  Actual callers are the synchronous on_chunk callbacks at generate.cpp:4861
  and :6296, plus the verifier-window reader at :5640. Each owns next_tokens in
  a vector for the call and supplies actual positive chunk/window rows, with
  p0/q from the prompt. Prefill::run invokes on_chunk with its actual T at
  prefill.cpp:3030 after its existing stream wait; the layer-major final-layer
  forwarding preserves the logical count/position (layer_major.inc:272-280).
  The CLI's current context guard is below 2^31 (generate.cpp:1697), and prompt
  and generation must fit. The new layer-major path additionally limits the
  request/session to 262144 and chunk capacity to 8192. These existing callers
  make record-position int32 conversions valid in the supported request range;
  this focused patch does not add a new blanket 256K or per-group path limit.

  ModelGeometry's normal QSA NHp is 24 (layout.hpp:41), so per_row=29.
  Even one hypothetical n=262144 E-4 call has 7,602,176 int32 elements and
  30,408,704 bytes: accepted by both new checks on the configured 64-bit host.
  The supported chunked full-context calls remain accepted as well. This is
  arithmetic/source analysis, not a 256K model, allocation-fit or RESTORE result.
  std::vector may still throw on host capacity exhaustion before any enqueue;
  no lease is needed before the source is exposed, and existing allocation
  exception behavior is retained.
