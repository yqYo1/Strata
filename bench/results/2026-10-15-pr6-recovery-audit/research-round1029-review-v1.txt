## Material corrections and limits

**R1029-C1 — eager pooled reads are safe for the evidenced engine caller; keep the generic API distinction.** `qsa_select.cpp:42-53` loads `pooled[b]` before checking whether a query row exists, its step record is valid, or `b<=nb`. Therefore tile 8 changes the read set relative to `qsa_block_scores` for valid rows with a shorter prefix; at `active=-1`, it reads every declared pooled row. R1026 was right that `validate_spans` proves address extent but does not prove contents initialized. The new owner receipt and pinned `layer.cpp` now close that uncertainty for the intended engine path: primary QSA state allocates `max_cells/idx_block+2` pooled rows (`layer.cpp:501-505, 610-614`), `qsa_state_zero` clears all `idx_pooled_rows*idx_dim` bytes before use (`:717-719`), and the layer-major caller scores on the same in-order compute queue as append (`prefill.cpp:2515-2559`; owner receipt). At capacity 262,144 the receipt records `active=65,537` and 65,538 allocated rows. Thus no current-engine out-of-bounds, uninitialized-read, or concurrent-producer defect is demonstrated.

The public header still says the dedicated scorer has the “same contract” as the old scorer but does not spell out the added full-active-prefix initialization and immutability obligation. The owner receipt states that the prefill API treats the declared pooled span as immutable; that policy is not explicit in the pinned header. Classify this as a generic direct-entry contract/documentation gap, not an engine-path bug. If all direct callers must provide initialized, immutable pooled rows over `[0, active)`, put that obligation in the API docs and test it; if partial initialization or concurrent production is intended to remain legal, avoid reading rows no query in the tile consumes. The current actual-entry suite uses initialized fixture data and does not settle that generic contract.

**R1029-C2 — update the obsolete 262,144 test gap.** `qsa-score-prefill-qualification-v1.json` and its full/tail receipts qualify the public scorer+selector entry at 262,144 with 256 rows and a 255-row final partial tile, for tile 0 and tile 8 where recorded. R1026 predates this Main-owned qualification. Preserve its remaining missing-boundary recommendations as tests to consider, not defects.

**R1029-C3 — keep actual entry separate from engine dispatch.** The suite directly calls the public scorer/selector through the built Strata Runtime and validates both tile settings; it does not run the `prefill.cpp` layer-major dispatch, short-prefill path, `STRATA_SELECT_OLD`, or a real-model tile-8 arm. Main's handoff says the real-model tile-0 arm is currently running. I did not inspect processes or infer its result. Neither the direct-entry pass nor the static caller predicate qualifies tile-8 model speed, quality, default selection, RESTORE, or production adoption.

**Shared helper limit.** R1026 properly confines alias/span/queue claims to call-site parity: both scorer APIs use the same `validate_spans`, `queue_for`, and `finish` sequence. The helper definitions are outside the five-file frozen snapshot; this review does not independently widen those guarantees. The graph warning for active bounds remains applicable.
