## Finding

**Origin classification: unknown.** The available own-tree evidence shows that `CpuGuReuseObserver` was authored and proposed as a new request-cold CPU recurrence simulator in this repository, and supplies no positive evidence that its implementation was copied from XeStrata. However, it does not document a specific source-free origin or establish a pinned set of external sources from which the implementation was independently composed. Under the current policy, absence of an attribution header or a recorded XeStrata reference is not enough to certify it as independent. There is likewise no positive source evidence in the reviewed artifacts that makes it a clearly XeStrata-derived implementation. Keep the existing header classified as unknown; this finding alone does not trigger either deletion or an independent-origin certification.

## Evidence and limits

`git log --follow -- include/strata/core/cpu_gu_reuse_observer.hpp` shows one first-add commit, `bab7bf063bc110558133ec87a1e51fa5720fadb4`, dated 2026-10-15. Its subject is `perf(cpu): qualify bounded GU reuse observer and int8 direct profiling`. The commit adds the header, tests, and proposal records. It is an own-fork commit, which proves where the current file entered this repository but not where every implementation idea came from.

The committed proposal artifacts `cpu-gu-reuse-observer-v1` and `cpu-gu-reuse-observer-v2` are marked proposal-only and pin the own source files, prior own research reports, mock fixtures, and proposal inputs. Their READMEs describe an issuer-side simulation of ordinary byte-budget LRUs, a request-cold lifetime, fixed counters and expert identity capture at the existing CPU job creation point. The v2 construction record says it transforms v1, keeps v1 intact, and regenerates the final source diff against the same unapplied baseline. The included mock is described as a separate vector-LRU oracle. R595/R598 discuss the predecode/cache question and alternative designs; the R598 report cites T-MAC as an idea-level alternative and says it does not implement Strata's IQ formats. None of these own artifacts identifies a XeStrata source file, revision, or copied implementation as the observer's origin.

Those records are concrete evidence of the observer's local design path, but they are not an independent provenance attestation. A conventional LRU, issuer-side accounting, bounded counter arrays, and a mock oracle are generic constructs; their presence cannot distinguish independent implementation from adaptation. The proposal pins establish inputs and reproducibility, not a complete external-source inventory. I therefore cannot turn the lack of a recorded external implementation into a clean-origin finding.

The header currently has no SPDX or other origin statement. This is recorded only as a file fact and is not used as evidence for either classification. No external-code similarity check was performed because the instruction prohibited inspecting XeStrata implementation source.
