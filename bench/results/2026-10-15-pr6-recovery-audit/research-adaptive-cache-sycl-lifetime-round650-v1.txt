# Adaptive expert-cache lifetime audit — Round 650

2026-10-15 JST. Read-only audit of the current root SYCL/native single-GPU ordinary MTP4 cache path, cache sizing, current profile evidence, and named R584/R607/R624/R632 reports. No tests, build, GPU, process control, Git, cleanup, product/proposal edit, private environment scan, or forbidden record access was performed. This report alone is new.

## Finding

The normal adaptive swap sequence is intended to avoid stale-slot reads: each verifier window drains its graph and copy stream before returning; the adaptive thread starts only after ver.run, changes the host residency view while no verifier is running, queues the refill on a separate stream, and the following window normally waits for the refill event before publishing the new host/device residency map and launching the next verifier graph. The pending swap therefore does not overlap an ordinary verifier read of the slot. The MTP drafter has its own model/cache and synchronizes its own stream before returning; the adaptive refill is not its expert source. The asynchronous verifier commit updates session state on the verifier stream and does not read expert-cache slots.

However, the source has two unchecked operations at the publication boundary that make --adapt-swaps 96 unsafe to qualify as a correctness-preserving default without first fixing or otherwise closing those error paths: cudaEventRecord(adapt_ev, adapt_stream) is ignored, and the device residency refresh cudaMemcpy(d_res, host_res.data(), ...) is ignored. If event recording fails, the subsequent event query/synchronize can succeed against an older event (or an event with no recorded command); the code then publishes the new host map although the refill may not be complete. If the device-table copy fails, it still proceeds to ver.run with the previous device map while the selected slot may now contain a different expert. That can send the GPU graph to stale/wrong slot contents. Current SYCL compatibility makes the empty-event case concrete: cudaEventQuery treats an absent underlying event as ready (src/sycl/compat.cpp:112-116,381-392), while cudaEventRecord reports failure through its return value (364-379). Both failures must prevent decode from proceeding.

The refill cudaMemcpyAsync return values and cudaStreamSynchronize in the resident exchange staging helper are checked; cudaEventSynchronize/Query statuses are checked; caller failures generally terminate the generation request. Those checks do not cover the unchecked event-record or residency-copy results. In complement mode, src.commit_exchanges() also returns a success count that the caller ignores. Its checked prerequisites and normal path imply the copy-back is complete before this call, and a failed metadata exchange appears to fall back to file reads rather than corrupting GPU slot contents, but its result is not reconciled against staged swaps. That is a separate state/accounting robustness gap.

## Current ordering and graph references

- src/core/verify.cpp:1393-1404 synchronizes verifier stream cs_ and its expert-copy stream before the window proceeds to sampling/return. SYCL uses event-completed segments; the final stream sync is still explicit. Therefore the just-finished verifier's expert-cache reads are complete before the adaptive thread is started.
- src/program/generate.cpp:7031-7033 starts adapt() only after ver.run returns, then calls ver.commit, completes mtp.draft, and joins the adaptive thread at 7050+. Commit is asynchronous in the single-GPU ordinary path, but Verifier::commit queues session-state work on the verifier stream (src/core/verify.cpp:1630-1665); it does not use d_res or cache slots. MTP draft graphs run and synchronize on MtpDrafter::cs_ (src/core/mtp.cpp:1140-1190), with distinct drafter experts. No concurrent reader of the target cache was found in this interval.
- The next verifier window calls apply_pending before ver.run (generate.cpp:6997-7003). With default controls, adapt_nowait() is false and this requests an event wait. STRATA_SYCL_ADAPT_SYNC also forces waiting unless exactly "0"; therefore a no-wait publication requires the explicit combination STRATA_ADAPT_NOWAIT=1 and STRATA_SYCL_ADAPT_SYNC=0. That combination is unsafe for cache slot reuse: apply_pending(false) returns while the refill is incomplete, leaving device d_res at the old mapping while the slot may be partially overwritten. Keep both controls pinned to the synchronous path for any adaptive screen.
- After successful event completion, apply_pending commits the resident-RAM exchange, writes the new host map, then copies the full table to d_res (generate.cpp:6850-6864). The verified kernel graph captures the device table pointer, not a frozen copy of the table contents; updating its data between drained windows is compatible with graph reuse, provided the copy succeeds and completes before launch.

This audit found no ordinary MTP4 graph still reading the evicted slot across the normal synchronous transition. That conclusion depends on the ver.run drain, adapt_thr.join, successful refill event, and completed successful d_res publication. It does not extend to no-wait mode, failed APIs that are currently ignored, cancellation/failure at arbitrary async boundaries, multi-GPU peer paths, or an in-process cache resize/reopen.

## Slot byte and profile relationship

The CLI default is adapt_every=4, adapt_decay=0.7, adapt_swaps=96 (src/program/generate.cpp:451-454,476); --adapt-swaps 0 suppresses usage allocation and adaptation (6834-6845). The algorithm computes decayed routed usage per (layer, expert), compares missing candidates with that layer's least-used resident experts, requires candidate usage at least 2 and a 1.5-count margin, then globally caps swaps per adaptation round (6883-6906). It is a dynamic replacement policy, not a larger static profile or a cache-capacity increase.

For native per-layer SYCL caches, startup constructs each slot from its owner layer's blob_bytes, 256-byte aligned (generate.cpp:3122-3135); open_sized lays out a single arena from those byte sizes (src/core/expert_cache.cpp:256-285). Profile fill walks ranked (layer, expert) entries and admits only within per-layer ranges. Adaptive victims and candidates are chosen within one layer, so the replacement blob uses that layer's byte size (generate.cpp:6911-6918); it does not cross-fill a larger blob into a smaller layer's slot. R632 exact arena arithmetic remains applicable to the initial per-layer map: 128 = 281,651,200 B (47 layers quota 2, final layer 34), 192 = 392,908,800 B (47×4, final 4), 256 = 533,734,400 B (47×5, final 21). Enabling adaptation does not change these allocations or quotas; it changes which experts occupy slots over time. The 128→192/256 choice also repartitions the final layer and changes the startup resident set, so capacity and adaptation are separate axes.

The loaded expert-profile.bin is only shape-checked against the model. R584 found no binding to model weights or the route corpus. R647/648 review's exact CPU-route overlap result was conditional because the historical census producer did not hash the profile content at capture time. R607's CPU-only histogram was collected with --adapt-swaps 0; its append-only replacement ceiling does not model adaptive policy. Enabling adaptation may move beyond the startup ranking after several rounds, but neither old report establishes whether the policy fits these prompts, earns enough useful replacements, or improves wall time. It also changes GPU/CPU owner assignment; current SYCL cache experts use native Q8_1 arithmetic while CPU experts use IQ arithmetic, so logits/tokens and subsequent MTP acceptance/work may change. Route/profile fit is not a correctness or quality gate.

## PCIe fetch is a separate route

The adaptive refill is cache-slot replacement: D2H saves an evicted resident into an exchange buffer when needed, H2D copies the incoming host expert into that same layer's cache slot, then the next verifier route should see an updated d_res. The current PCIe-fraction/miss-fetch path is separately selected by drive.d.pcie_num (generate.cpp:6824-6829) and executed in expert miss handling. Its enqueue/fetch failure repair does not cover adaptive refill or residency publication. A fix or validation for the PCIe miss path therefore cannot be treated as closing the two unchecked adaptive calls above; conversely these adaptive findings do not establish a defect in the current PCIe-fetch correction.

## Minimum blocker closure before default-policy comparison

Before changing a controlled --adapt-swaps 0 capacity/profile arm to the default policy, ensure every adaptive event-record and d_res copy status is checked and causes fail-stop before the next verifier launch; reconcile the staged resident-RAM exchange completion count or explicitly prove its failure fallback. Keep the existing drain-before-refill and refill-event-before-publication order. The production candidate comparison should be a separate process/arm with adaptation explicitly pinned, same total cache/profile/context/KV/MTP4/residual/chunk settings, immutable env, and actual route, swap, output/quality, fresh-fault and completed-owner receipts. Do not reinterpret the 0-swap profile-fit result as an adaptive result, or compare a capacity change and adaptive policy change as one effect. No code fix or run was made here.
