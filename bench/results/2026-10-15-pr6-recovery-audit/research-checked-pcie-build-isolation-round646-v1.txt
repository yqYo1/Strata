Decision

The build recipe has the right core ABI strategy: it recompiles both TUs that directly include `verify.hpp` with the proposal include directory first, replaces the generate object in the frozen native link command, adds the replacement verify object, and checks actual compiler depfiles plus a link map. The current root source/compile database corroborate that scope. The critical remaining pre-run blocker is lifecycle robustness: both scripts create their one-shot private root before entering their `try/finally` failure-recording region. A preflight failure after `mkdir()` can leave the root without a terminal receipt; the next invocation then refuses the existing root, and the recovery path is not documented. Move deterministic preflight before root creation or make every post-creation failure persist a closed failure receipt before allowing a retry. Do not delete a stranded root as routine cleanup.

Second, the prior `libstrata_engine.a` contains an old `verify.cpp.o`. The script does not remove/rebuild that archive; it relies on the candidate link map proving that the old member was not extracted. That is a reasonable isolation gate, but it is not yet empirically demonstrated because the candidate link has not run. The eventual review must inspect the actual map and prove both the new verify/generate objects are selected and the archived `verify.cpp.o` member is absent. The native link receipt alone is not proof of that outcome.

At `build_checked_pcie_fetch_v1.py:79-91`, the script uses the actual receipt's `link-native` argv, checks exactly one original generate object, replaces it with candidate generate and verify objects, and redirects output/map to the private root. It is conservative but text-based; it does not explicitly parse the map's archive-member inclusion table or assert the exact old member's archive-qualified spelling. A successful build gate should preserve the actual map and manually/structurally inspect the archive-member inclusion record, not infer selection solely from exit code or argv.

The base link receipt's `linked_inputs` includes all listed archives, linked objects, and MKL libraries; the replacement mapping removes only the original generate object and adds the two new objects. The link map is therefore important for detecting archive extraction beyond the direct argv substitution. Failure-recording gap

Both scripts check `not root.exists()` and call `root.mkdir()` before entering the `try` block that writes the terminal receipt. In the host script, compiler/hash setup, `Owner` construction and initial persistence precede the `try` (`:42-61`); in the build script, compile database parsing, two-TU selection/version checks, command rewriting and link-argv validation follow `mkdir()` and precede the `try` (`:46-106`). A malformed/missing compile entry, changed version macro, archive link command shape or owner initialization can leave an empty/partial root, without the A-side receipt and without an explicit failed terminal record. A rerun then fails the fresh-root check. This is the only source-level workflow blocker found; no build result or existing candidate root was created in this audit.
