## Integrated call and lifetime findings

The checked route admits 48 layers, QSA interval 4, 12 QSA states, 36 GDN states, chunk size at most 8192, and full input up to 262144 (`src/prefill/layer_major.inc:49-60`). The observer is default-off and allocated only for `STRATA_PREFILL_LAYER_MAJOR_PROFILE=1`; its fixed rows and twelve event objects are RAM-admitted before construction (`:205-218`). It does not change route selection or loosen the route's unsupported-observer guard (`:67-76`).

The observer’s extra queue operations are event record markers only. Its event intervals are retired after existing checked drains: upload after `drain()` (`layer_major.inc:337-354`), store after callback `drain()` (`:404-435`), and input/GDN/QSA/MoE after `run_impl`'s existing callback stream synchronization (`prefill.cpp:3210-3223`, particularly 3212-3220). `retired()` clears the begun/ended flags only after successful queries and elapsed-time retrieval (`layermajor_coarse_profile.hpp:65-83`), so reusing the same event pair on the next chunk follows retirement. Compatibility event record submits an in-order barrier; elapsed-time retrieval waits for the ending event, but here it is called only after the relevant checked drain (`src/sycl/compat.cpp:364-379,408-424`). I found no added pending-event wait, extra stream drain, or reuse-before-retirement path in the integrated caller.

On ordinary failure returns and C++ exceptions, declaration order keeps the profile object alive beyond the checked lease and `Restore`: profile and borrow precede `Restore`, which precedes the armed `DraftUploadGuard` lease (`layer_major.inc:207-218,225-268`). Reverse destruction therefore retires/checks the lease first, restores borrowed fields/callbacks next, restores the profile slot, and only then destroys the profile/event objects. If the lease cannot prove retirement its failure callback aborts while owners remain live (`:261-265`). On success, explicit `lease.retire()` precedes event destruction and emission (`:465-474`). Event destroy is delete-only in this compat implementation (`compat.cpp:360-362`). The success header explicitly says teardown is unmeasured; no restoration-tail duration is represented (`layermajor_coarse_profile.hpp:87-90`). I found no source-visible lifetime escape or unsafe event destruction in these paths.
