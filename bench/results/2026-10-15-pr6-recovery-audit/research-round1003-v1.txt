The SYCL recurrence receives `T` tokens, `hk=16`, `hv=48`, key/value width 128, packed Q/K/V width 10,240 and FP32 state. It assigns one 512-work-item group per value head, loads 32 FP32 state scalars per work-item, loops tokens serially, forms `proj = Sᵀk`, `delta = beta*(v-decay*proj)`, applies `S = decay*S + k*deltaᵀ`, then produces q-read, RMS-like normalization, gamma and sigmoid-z gating. ## Algorithm family: why WY is useful

For one head, writing state as `S ∈ R^(K×V)`, scalar decay `a_t=exp(g_t)`, and post-sigmoid beta `b_t`, the recurrence can be expressed as

`S_t = a_t S_(t-1) + k_t b_t (v_t - a_t k_tᵀ S_(t-1))ᵀ`.

The read is `o_t = q_tᵀ S_t` (with the target's documented scale/normalization and gate applied at the prescribed location). A literal recurrence exposes T token steps. Chunking uses the fact that the correction among rows within a chunk is lower triangular: construct a gated, beta-scaled key Gram matrix, solve a unit-lower-triangular system, and turn the chunk into WY auxiliaries `W,U`. Then chunk outputs are a parallel intra-chunk term plus the incoming state contribution; the boundary state is compactly updated from `W,U,K,V` and cumulative gate. This replaces T serial state iterations with fixed-size chunk kernels plus a sequence of chunk boundary updates. It does not remove the boundary dependency if one request is run serially across chunks.

FLA's inspected forward path is a pipeline, not one kernel: chunk-local gate cumsum; scaled `K Kᵀ` with gate-difference and beta; triangular solve; `recompute_w_u`; chunk state update; intra-chunk output. The recent FLA `chunk_fwd.py` contains a fused `KKT + solve_tril` option for `BT=64` on non-Intel, but selects the mathematically equivalent separate KKT/solve path under `IS_INTEL`. Its source comment says the fused kernel keeps ten `[BC,BC]` FP32 accumulators live across K and spills on Intel GPUs, with the split path 2.3–3.0x faster on the authors' tested Intel cases despite a second HBM round trip. Treat this as a useful counterexample to “one fewer launch / less HBM must win,” not a B57010GB result or a transferable speed prediction. The source's Triton-specific `IS_INTEL` branch is also not evidence for a SYCL implementation.

Variants and alternatives:

1. **WY plus triangular solve (FLA/vLLM):** parallelizes independent chunk/head work; chunk KKT storage is O(T*BT) per head and direct solve work scales cubically in BT. FLA permits BT=16/32/64. Smaller BT lowers solve footprint but adds launches/boundaries; larger BT amortizes setup but increases quadratic scratch and working set.
2. **Fused KKT+solve:** saves a launch and scratch round trip only while the live matrix fits registers. FLA's current source says its fused BT=64 path keeps ten FP32 `[BC,BC]` accumulators live and spills on tested Intel GPUs; its split path measured 2.3–3.0x faster there. This is not B570 evidence. A small fused diagonal block with split cross-block work is a hypothesis.
3. **Chunked recurrence/superchunk:** serially compute exact state within segments, parallelize preprocessing/head work, and materialize boundaries. It preserves familiar update order but outputs in later chunks still need correct incoming state. Two-level compact-transform scans trade serial depth for matrix scratch and combine work.
4. **Associative scan:** token recurrence is affine in matrix state, so maps compose associatively, but arbitrary K×K maps can require O(K²) storage and O(K³) merge work. WY exploits rank-one delta structure to avoid that general transform; scan is plausible only when transforms are compact or K small.
5. **Parallel intra-chunk outputs, sequential chunk boundaries:** likely a lower-risk algorithm boundary for one long request. Expose work across 48 value heads and within a WY chunk before adding distributed/context-parallel state synchronization.

Papers give algorithmic motivation, not target-specific measurements. The DeltaNet sequence-parallel paper establishes chunkwise parallelization of the delta rule ([NeurIPS 2024 paper](https://papers.neurips.cc/paper_files/paper/2024/file/d13a3eae72366e61dfdc7eea82eeb685-Paper-Conference.pdf)). FLA cites its Triton-based hardware-efficient linear attention work; its repository implementation is MIT. Detailed author-style walkthroughs can help derive the triangular equations, but the implementations and paper are the authoritative references.

## Xe2 mapping hypotheses and contraindications

Target is one Arc B570 10GB GPU, PCIe characterized by the assignment as about 6 GB/s, and 12 CPU threads. These do not establish effective bandwidth, SLM/register capacity, occupancy, PCIe traffic, or execution resources; no kernel or benchmark was run.

Intel SYCL*TLA's Xe architecture note describes 16-lane subgroup SIMD collectives, subgroup-distributed register ownership, DPAS matrix atoms, and block-2D global-memory operations with alignment/shape restrictions. These are mapping concepts, not GDN-specific kernels or B570 limit evidence. Query this device/compiler before assuming supported subgroup or matrix shapes.

Finite mappings to study if measurements justify a candidate:

- **Split tiled path:** parallel KKT per (chunk, value head), triangular solve, WY generation, parallel outputs, and per-chunk state update. Store only required triangle/scratch. Measure launches, scratch traffic, repeated state reads, and dependent boundary-state work.
- **Small fused block:** keep a small diagonal block in registers/SLM, leave cross-block KKT separate. Tune block/subgroup/workgroup together and inspect spills. FLA's Intel comment is a clear counterexample to minimizing launches at all costs.
- **Group value heads:** 16 key heads serve 48 value heads (3:1 reuse). Sharing Q/K can save loads, but triples live value/state work and may reduce occupancy. Compare separate and grouped heads with emitted spill/register data.
- **Chunk-state scan:** GPU-resident transforms may reduce serial depth, but full affine transforms cost O(K²) storage and O(K³) composition; for K=128 this can exceed WY's structured work. Prefer only if the measured sequence has enough chunks and compact transforms; quantify added synchronization/state transfers. Do not assume desktop PCIe is limiting unless copies are measured.

For precision, FLA's BF16 input examples do not prove its compute/state contract. Compare actual gate prefix, beta, reductions, state orientation/dtype, normalization and every cast. Keep FP32 recurrent state/reductions where the model contract requires them; test BF16/FP16 only with model-specific range and quality evidence. BF16 range and FP16 mantissa tradeoffs do not imply a winner.

A candidate must preserve canonical session state and physical 262144 behavior: correct final state and chunk offsets/tails, accepted-prefix commit on cancellation, RESTORE of recurrent state plus convolution history, and continuation. WY scratch is transient, never canonical state. Bounds/lifetime/fault gates remain separate from numerical parity.
