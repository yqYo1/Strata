## Path and causal state

The opt-in is reached only through `Prefill::run` for long prompts with `STRATA_PREFILL_LAYER_MAJOR=1`; the window switch is read in `run_layer_major` (`layer_major.inc:3-29,32-55`). Window mode requires native16 BF16, `m.T==8192`, scratch aliasing, full single-GPU compact-FP16 expert layout, `STRATA_PREFILL_MMQ=0`, same queue, and the fixed Qwen geometry (`layer_major.inc:45-50,95-115`). Other layer-major preconditions reject unsupported topology before the pass. If prefix checkpoints are required, `window_on` is false and the ordinary 8K route remains selected; current serve sets that flag when periodic checkpoints are configured (`generate.cpp:4707-4709`).

For each layer, the helper sets the layer range to one layer and calls `run_impl` across the original `tokens[0:n]` with the caller's `pos0` (`layer_major.inc:557-561,681`). `run_impl` uses request-relative `c0` to read tokens and absolute `p0=pos0+c0` for QSA step records, RoPE, KV append/indexer positions, and output callbacks (`prefill.cpp:1874-1893,1968-2005,2047-2050,2452-2513`). Its `prev` starts from session `ple_prev`, advances through the full token array, and layer-major restores the same initial PLE predecessor before every layer while installing final predecessors only after the last layer (`prefill.cpp:1761,2047`; `layer_major.inc:220-222,560,700`). These are the right coordinates for a nonzero-position continuation; route rows separately remain local to the two-piece window.

The pair predicate is explicit: at a chunk boundary, it asks the residual plan for both chunk spans and selects the window only if both are device spans (`prefill.cpp:1872-1889`). With the fixed 8K chunk and residual plan's whole-chunk device prefix, their bank offsets are contiguous (`layer_major_plan.hpp:90-135`). `window_piece` limits the ordinary layer loop to half 0, so each piece still executes the existing attention-half body once; QSA appends/indexer and GDN recurrence are not moved into the MoE helper (`prefill.cpp:2313-2316,2354-2386,2440-2516`). At layer 1, PLE rows are gathered from the original request tokens and uploaded before the existing PLE body; BF16 residuals are restored to FP32 for PLE and packed back afterward (`prefill.cpp:1853-1866,2013-2045,2247-2311`). The second piece follows the first on the same queue, so PLE history and recurrent state see causal order. A short final piece is legal: the first piece's predicate checks the actual tail span, helper rows may be 8192 plus a tail, and the helper loops in 8192-row subchunks (`prefill.cpp:1884-1887`; `moe_window.inc:5-8,84-101`).

The helper recomputes only HC FFN/MoE from saved post-attention residual rows (`moe_window.inc:82-100`). It computes per-piece normalized/mixed data, shared branch, gate, then reads router IDs back and builds the immutable host mapping. The route header validates all IDs and duplicates, forms stable original token-slot to expert-slot indices, and stores source token rows. The engine uploads both maps once per window and each expert job gathers from the complete mixed window into a bounded job scratch; job output lands at its expert-global Down offset, which `combine` addresses through the uploaded slot map (`moe_window.inc:102-149`; `moe_window_routes.hpp:61-96`; `native16.cpp:141-158`). The source list is correctly rebased to `source + job.global_row`; it does not reuse the old chunk-relative `m.src_dev + o0` assumption. It checks full mixed/source/output extents and each weight/cache span before the corresponding GPU use (`moe_window.inc:17-48,125-146`).

## Callback order, fallback, and lifetimes

`run_moe_window` performs both pieces' HC writes to the bank and checks `cudaStreamSynchronize(m.cs)` before returning (`moe_window.inc:149-157`). Only after that drain does `run_impl` loop over the two rows: the final stage checkpoint callback is considered first, then `complete_piece` advances the ascending chunk cursor; on the last layer it restores one bank slice to FP32 `m.R`, drains, and calls the original `on_chunk` with `pos0+row` (`prefill.cpp:3513-3525`; `layer_major.inc:562-575,577-585`). This preserves the public per-chunk callback interface and its normal `on_stage_chunk`-then-`on_chunk` order. CLI MTP consumes the callback's absolute positions and next prompt tokens; `draft_kv` drains the main queue before returning (`generate.cpp:6773-6779`; `prefill.cpp:1248-1277`). The server MTP callback also accepts each chunk in order, but periodic state checkpoints make `requires_prefix_checkpoints=true`, disabling window mode (`generate.cpp:4708,5301-5338`). Root/turn checkpoints are made by the server after a whole `sp.run` segment returns, so those do not interleave a pair (`generate.cpp:6253-6300`).

RAM placement fallback is a real branch, not merely a claim: if either 8K span is in the host tail, neither piece takes the window branch; each uses ordinary 8K attention+FFN and the existing `on_chunk16` store/callback path (`prefill.cpp:1884-1888,3528-3605`; `layer_major.inc:642-679`). Device spans use the bank; host spans use owned RAM and H2D on the next layer (`layer_major_plan.hpp:123-135`; `prefill.cpp:1901-1942`). No row is split across stores. If window mode is disabled by the checkpoint gate, execution is also ordinary 8K. An unsupported native/topology setting is an explicit error, not a RAM fallback. The helper's `region_bytes` lower bound is checked after attention state has run (`moe_window.inc:20-23`); with the current fixed geometry the ordinary 8K MoE region includes at least the 838,860,800-byte `Dm` view plus other mandatory views (`prefill.cpp:741-757,988-1030`), so the 998,443,520-byte check is below the current allocated minimum. Still, move this requirement into layer-major preflight if later buffer accounting can shrink.

The ownership boundaries are substantially correct. All upload vectors live in `MoeWindowContext`, declared before `Restore` and the armed `DraftUploadGuard`; the route `shared_ptr` survives both H2D submissions and all expert reads until the checked final write drain, then is reset (`prefill.cpp:439-445`; `layer_major.inc:361-412`; `moe_window.inc:111-115,153-161`). `m.region`, residual bank, cache, residency map, and temporary host slabs also outlive the lease. Since layer-major enforces `m.copy==m.cs`, the lease drains every queue used by this integration. Readback, final write, attention-store, and callback bridge failures return through the lease. If retirement itself cannot be proven, its fatal callback aborts while owners remain live (`layer_major.inc:398-412`). The route vectors are not released on partial upload, cancellation, thrown exception, or failed write drain.

Concrete counterexample / caller obligation: stop may become true after the first piece's attention/state work but before the next piece's top-of-loop check, or between expert jobs (`prefill.cpp:1875, run_moe_window:120-121`). In the former case QSA KV/indexer, GDN recurrence and possibly PLE history have advanced for one piece, the bank contains post-attention rows, but no MoE write or MTP callback for that partial pair occurs. In the latter case some Down jobs may have run before the window combine/write. This is not a host-lifetime defect: the checked lease drains, retaining route owners. It is non-transactional session mutation, explicitly acknowledged by the `Restore` comment (`layer_major.inc:367-369`). The current server sets `live_ok=false` before reading and leaves it false on cancellation, then either starts from zero or a saved checkpoint next time (`generate.cpp:5963,6293-6295,6476-6482`); standalone CLI exits on failure. Keep that invalidation invariant, and add a caller-level regression for cancel-after-first-piece before any broader caller can reuse a failed session. Do not describe the layer-major `Restore` as state rollback.

## First GPU qualification checks

Keep current performance and adoption status unchanged until serialized Main diagnostics. First, trace an 8192+1 prompt at nonzero `pos0` with both pieces device-resident and one case whose second span is host-resident. Confirm per-layer `attention store -> second attention -> MoE window -> HC writes drain -> callbacks at pos0 and pos0+8192`, and verify host fallback has no `run_moe_window` event. Include an odd number of chunks so the unpaired last chunk proves ordinary routing.

Then compare a small completed run against the existing 8K path using identical input/session initialization: per-piece PLE boundary, GDN recurrent state after each piece, QSA append/indexer/KV extents and selected IDs, router IDs/weights, and final residuals. Use biased routes with `ne==W`, a >8192-row expert split, zero and tail routes, and window sizes 8193/16384; check that no route slot/source crosses the window. Finally check MTP K/V after each callback and one full physical-context 262144 continuation/RESTORE. Inject cancellation before piece two, during an expert job list, and after the final write but before callback; verify owners remain valid through retirement and the caller invalidates/reloads state. Fault-path checks should retain the existing fail-stop behavior when drain is uncertain. These checks are needed because syntax-only compilation does not instantiate device code or establish queue lifetime, data values, physical allocation bounds, or full-context state equivalence.
