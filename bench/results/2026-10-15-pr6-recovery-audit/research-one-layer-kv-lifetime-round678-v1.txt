# One-active-QSA KV lifetime contract for layer-major prefill (R678)

Read-only ownership/source contract. Capacity numbers are from the completed `prefill-capacity-plan.ja.md` and `prefill-capacity-metadata-v2.json`; their statuses remain planning arithmetic, not physical admission, quality, or speed. No source implementation, tests/build/compiler, GPU/process, environment mutation, private-B inspection, Git mutation, or cleanup was performed.

## Existing owners and data path

The current `SessionState` owns 12 QSA states, each initialized with a full-logical page table, its own K/V slots, indexer state and map; one state owns the shared RoPE tables and the others borrow them (`src/core/session.cpp:61-67,101-116`, `src/core/layer.cpp:555-624`). In KV mode 1, each state additionally gets a full-context pinned host K/V copy as its authoritative backing (`src/core/layer.cpp:633-662`; `include/strata/core/layer.hpp:227-243`). `qsa_state_zero` clears the GPU slot and resets its map but intentionally does not clear the host copy, because no cell is read until rewritten (`src/core/layer.cpp:693-720`).

The prefill owner separately carves one full-logical-range `m.stage` KV allocation and an identity table when the session is mode 1 (`src/prefill/prefill.cpp:508-510,521-553,815-824,920-926`). It is explicitly a temporary pool for one layer, not a session owner. For each prompt chunk, mode-1 prefill copies all prior complete blocks of that layer from `st.host` into this identity-layout stage (`src/prefill/prefill.cpp:2110-2118`). The append kernel then writes each new cell to three destinations: the layer's resident slot if its page maps to one, that layer's authoritative host backing, and the stage pool (`src/prefill/prefill.cpp:2127-2138`; SYCL `src/kernels/sycl/kv.cpp:114-124,140-152`). Attention uses the stage pool with the identity table (`src/prefill/prefill.cpp:2268-2277`). Thus the current long-prefill path has (a) 12 states' resident slot pools, (b) 12 host backings, and (c) one temporary full-context stage; stage is refreshed from host each chunk, and new cells are mirrored to host and slots.

## Can the existing stage be the active-layer pool?

Yes as a data-path design, subject to source changes and explicit lifecycle rules. It already has full logical capacity and the identity page table needed for sparse selected IDs; QSA prompt selection/attention consume indexer state and a `QsaAttnPools` plus page table, while append accepts a page table and separate pool pointers. A layer-major active-state view can therefore point K/V writes and gather reads to `m.stage`/`m.ident_table`, while retaining that layer's `idx_tail`, `idx_dead`, `idx_pooled`, counts, position, and shared RoPE. For a mode-1 host-backed session, append in this mode must omit per-token writes to `st.host` and the layer's ring slots. On entering a QSA layer, restore the previously committed range from that layer's host backing to the shared stage once; append all chunks of that layer in place; at layer completion drain the queue and commit the complete encoded range from stage to that layer's host backing once. The next QSA layer reuses the same stage. The extant `kv_stage_from_host` performs only host-to-device copies (`src/kernels/sycl/kv_stream.cpp:301-315`); a reverse full-range commit primitive and failure-checked layer boundary are not currently present in that API.

This avoids reloading the prefix from host at every prompt chunk and avoids host writes per appended token; it does not by itself remove the existing 12 per-layer resident slot allocations. To realize the capacity-plan's one-active-QSA saving, the long-prefill reservation must also stop holding those redundant per-state K/V slots (or explicitly count them as live). It can retain all 12 indexer/page-table/count/status allocations and one shared RoPE table. The plan's `one_active_QSA_full_context_bytes` row is the arithmetic for one active full-context QSA store plus its associated QSA state, not proof the current arena can reclaim or reuse the 12 slot ranges. Existing mode-1 startup reserves each state's slots and page table in the session arena (`src/core/layer.cpp:537-552,577-608`); a lifecycle/allocator design is needed to reclaim or defer slots and later rebuild/decode-reserve them. `qsa_state_init` currently determines those pointers at initialization, so an isolated `QsaState` view is less invasive than mutating the session's owned state.

The lower-risk comparison preserves current per-layer host backing and resident slots unchanged, keeps `m.stage` as an additional temporary pool, and continues the existing mirror behavior. It has no new restoration/commit protocol and preserves current decode state, at the cost of the repeated prefix H2D and duplicate resident-slot writes/allocations described above. Capacity arithmetic must distinguish this from the one-active-store design.

## Position, indexer, partial blocks and completion

All 262,144 logical positions need to remain representable: 65,536 pages of four cells, identity table entry `page -> page`, and no ring/modulo addressing in the active full-range pool. `qsa_state_init` gives each state `n_pages=ceil(C/4)` and a full identity table only in mode 0; mode 1 starts with `kv_stream_reset` (`src/core/layer.cpp:595-608,678-687`). A temporary active view needs an identity table/pool pair for all pages regardless of the underlying state mode, and must not pass the old slot table with the new full pool. Preserve the current chunk `p0`, token position, and the four-cell page layout. New append batches can end on any chunk boundary; only complete byte ranges may be committed as the QSA format's encoded rows, with exact tail-page handling. K8V8 row components are contiguous in the existing pool descriptors; page-level bulk copy must retain K/V code and scale alignment and avoid copying guard bytes as data.

Indexer state is independent of K/V location and is updated by each chunk's `native_qsa_indexer_append_batch` before selection (`src/prefill/prefill.cpp:2146-2165`). It must remain layer-specific and resident through the complete layer pass; do not reset/rebuild it between chunks or accidentally share it across the twelve QSA layers. Sparse selected IDs are then resolved by the identity page table through prompt attention (`src/prefill/prefill.cpp:2267-2277`). The active stage must contain every prior cell plus the current chunk before that attention runs.

Layer commit is a state transition: only after all chunks for that layer have completed, all queued KV writes are complete, and the full-range host copy succeeds may the layer's generation/valid-position be marked committed. If cancellation, allocation/copy fault, or early return occurs before commit, the current layer's host range is stale/partial and decode or continuation must fail closed until the prompt/session state is reset or the layer is fully reconstructed. `run_layer_major` already uses checked per-pass callback order and drains chunk/layer work, but cancellation is tested at chunk boundaries in `run_impl` (`src/prefill/prefill.cpp:1652-1655`) and no QSA layer-commit marker exists today. On restore/reuse, validate that every QSA layer has the same expected committed prefix before enabling decode. At the 262,144 boundary, confirm last-page and final partial-chunk handling without relaxing the physical context check.

## Decode graphs and pointer identity

Session graph capture chooses each layer's QSA state and passes it into `block_layer_pre` (`src/core/session.cpp:246-250,283-289`); QSA operations are capturable and consume the state pool/page pointers (`src/core/layer.cpp:904-906,953-967`). A captured graph contains the concrete buffer addresses used at capture. Reassigning `SessionState.qsa_states[i].k_*`, `v_*`, or `page_table` to the shared stage and later restoring the C++ fields does not retarget an already captured graph. To preserve existing decode graphs, keep those owning state pointer fields and their allocations stable and use a temporary prefill-only QSA state view/pool arguments. When restoring to the existing mode-1 decode design, committed host backing is the authority; the existing `qsa_kv_resolve` loads selected blocks into the existing slots before attention (`src/core/layer.cpp:732-736,953-967`). Full 256K device restore is not required for that streamed decode route. If a future full-resident decode route is selected, copy each host layer into its original stable full pool and retain identity mapping; otherwise explicitly retire every graph family referencing the previous pool addresses, rebind state, recapture, and enable decode only after recapture succeeds. Any API exposing borrowed `QsaState`/pool pointers also needs the same lease boundary; arbitrary caller-owned copies are outside internal ownership unless their caller has returned/quiesced them.

## Format scope and gate

The configured layer-major path currently accepts modes 0 or 1 but rejects `kv_hybrid` at its admission check (`src/prefill/layer_major.inc:91-109`). K8V4 is therefore outside this present lifetime contract; don't infer its support from generic allocation math. The concrete candidate to investigate is K8V8/INT8 in the current supported mode. The capacity plan's FP16 residual remains a separate, quality-unqualified saving and is not required for the one-active-QSA pointer/lifetime design. No throughput claim follows from reducing resident copies; compare total dependency path costs, including one restore and one commit per QSA layer, host pinning/RAM, decode restore or block-resolve, and removal of repeated chunk-prefix transfers, before adopting.
