# Explicit prompt consumption: native MTP4 producer proposal

Unapplied source proposal against current production (not the NativeDense bank v2 proposal). No build, host test, GPU/model/API run, process query, Git/branch change, environment mutation or cleanup was performed. Only this new directory was written; V2 and prior reports/index remain unchanged. Main owns serial review/qualification/integration. Inputs: AGENTS.md, ARTIFACT_RETENTION.md, R698, R700 and main-review-round696-698.ja.md. This is not an upstream check.

`--consume-prompt` is a new explicit default-off standalone CLI diagnostic. It accepts at least two prompt IDs within a positive configured context up to the existing 262144 physical limit; the complete prompt is consumed with zero completion IDs. Small exact contexts such as512 and exact262144 use the same producer. The strict gate requires SYCL, the --native preset and actual native expert layout, --spec4 with loaded --mtp, --suffix-draft0 (explicit, avoiding the default suffix policy's spec4→6 expansion), positive --prefill, full resident target KV, PLE, no token graph, fresh standalone single GPU, no split/peer/remote/window/vision routes, no competing selected-logit/NLL/state-dump/control-vector/measurement diagnostics. `--mtp-max-t` may be0 or4. Other ordinary engine performance settings remain available.

Only this explicit mode bypasses positive generation-budget and prompt-plus-output reservation checks. It accepts --max-new0 and ignores nonnegative --max-new values (including default16); it never changes o.max_new or ordinary/API semantics. Negative max-new remains rejected. Without this flag, --max-new0 remains invalid and full prompt+new1 retains the existing rejection. Context capacity is never raised to262145. Existing validation continues to reject input IDs/model incompatibilities.

Target prefill processes exactly positions[0,N−1). A composed callback validates each expected contiguous chunk shape *before* invoking the existing MTP callback, then records successful final-layer residual and MTP callback completion separately. Its callback count, actual initialized chunk capacity, last chunk range and complete contiguous span are in the receipt. MTP callback coverage means successful input pairs `(target residual R_i, prompt ID i+1)`; the MTP has its own KV/window and can skip obsolete cells. It is not evidence that all MTP KV remains retained or that target state was updated by MTP.

The ordinary native-MTP token loop still breaks before layers and hands prompt ID[N−1] at positionN−1 to the first verifier window. Before calling ver.run, the producer snapshots first_window and validates first/T1/exact position/exact prompt ID/zero outputs/complete prefill. After ver.run succeeds, existing acceptance logic clears first_window; the saved immutable consume_this_window governs the diagnostic branch. It commits exactly1 and waits for commit completion, including asynchronous commit. The mode never starts the adaptation thread or creates its unnecessary adaptation event/stream; a defensive join remains before the terminal branch. It stops before produced.push_back, MTP draft, p advancement or another window. Verifier prediction computation remains intact but its prediction is discarded.

After checked main/MTP drains, twelve QSA indexer block-origin words are copied (48B total) and checked against the last completed four-token block. At exact512 the expected word is508; at exact262144 it is262140. These are actual device indexer observations, not per-layer logical token counts or QSA attention-status checks. In a non-multiple-of4 input they refer to the latest completed block, not the unpooled tail. GDN36 is recorded as host owner geometry plus successful verifier run/commit, with an explicit absence of per-layer position measurement. PLE receipt checks host token predecessors against the last two input IDs; it does not certify all PLE history tensor values. No whole-state numerical correctness is implied.

Target NativeHead loaded/not-detached, MTP's attached head/expert-owner flags, and native table publication count/scratch presence are observed separately after terminal commit. These observations do not measure physical memory recovery or prove byte-exact owner reconstruction; the existing head/expert release helper's successful restoration remains its own contract. Bank v2 is not part of this patch. Its future merge and full native lifecycle validation belong to Main.

Success flows through the existing verifier scope destruction, existing summary path and existing manual SessionGraphs/doorbell/device frees. No early return0 skips cleanup. The new bounded JSON receipt is emitted only after that manual cleanup point; destructor/process-owner exit and fresh GPU fault absence must be verified externally. The normal 262144-ID prompt print is replaced by a compact count only in this diagnostic. Existing manual cleanup status handling is not upgraded or represented as individually checked. Diagnostic run/commit/wait or observer completion uncertainty fail-stops with owners retained and cannot produce a success receipt.

Artifacts: proposed mirrors, production→proposal source.diff, exact base/proposed hashes, actual helper host_fixture.cpp, bounded independent verify_receipt.py, and Main recipe. It does not execute the generator or simulate GPU arithmetic. The receipt checker validates field consistency and input file SHA256; it is not a supervisor or GPU pass.
