## Findings and corrections

R1052’s 16-key/48-value mapping is correct for the pinned llama.cpp converter convention. With grouped source slot `s = 3*k + j` (`k=0..15`, `j=0..2`) the converter reshapes `[16,3,D]`, swaps the first two axes and flattens, so the tiled GGUF slot is `l = 16*j + k`. The inverse is `s = 3*(l % 16) + floor(l/16)`. This is a source convention; the loaded IQ3_S GGUF metadata establishes `group_count=16`, `time_step_rank=48`, `inner_size=6144`, `state_size=128`, and `conv_kernel=4`, but it does not establish which converter produced its tensors.

For that converter convention the complete logical permutation is: only V rows in `in_proj_qkv` (Q and K row blocks remain fixed); all `in_proj_z` rows; the 48 output rows of each `in_proj_a` and `in_proj_b`; the 48-element `A_log` and `dt_bias` vectors (`A_log` is converted to `-exp(A_log)` and `dt_bias` is renamed to `dt_proj.bias`); V channels only in `conv1d` (the first 4,096 Q/K channels stay fixed); and `out_proj` input columns. The shared 128-element norm scale stays unchanged. The generic converter’s 2D `.dt_proj` branch permutes its **last** axis; Qwen3.5 GDN defines only `A_log` and `dt_bias` vectors, so do not infer a target matrix without its shape. Packed scales follow affected logical axes; the NVFP4 branch does not prove IQ3_S conversion history.

The state correction in R1049 remains required. Strata addresses `L[r,l,v]` with row-major `[K,HV,V]`; SGLang’s recurrent pool is `[H,V,K]`, so `S[s,v,r] = L[r,l,v]` in addition to the conditional head gather above. A square 128-by-128 state still needs the K/V transpose. This comparison adapter does not mean the converter rewrites runtime state.

Activation evidence is now stronger but remains conditional on artifact identity. The immutable Qwen author config at revision `de4b8e4d43b917e7706784d8bb445c9af86a3540` declares BF16, `mamba_ssm_dtype=float32`, 16/48 heads of width 128, `output_gate_type="sigmoid"`, and RMS epsilon `1e-6` ([official config](https://huggingface.co/Qwen/Qwen3.8-Flash-Next/blob/de4b8e4d43b917e7706784d8bb445c9af86a3540/config.json)). Pinned SGLang Qwen4Exp linear layers inherit Qwen3.5 GDN and pass a non-None `config.output_gate_type` to its RMSNormGated; that operator defaults to swish when no type is supplied. The full-attention sigmoid multiply is a different gate. The loaded GGUF header contains no gate type or HF config, and the author’s conversion receipt is unavailable, so record sigmoid as source-expected, not proven for this exact shard. Local Strata GDN currently computes sigmoid.

The R1052 numeric paragraph is too brief to serve as the precision contract. At the source-selected SGLang chunk path, Q/K/V and `A`, `w`, `u`, per-chunk `h` scratch, and output `o` use the activation dtype (the author config says BF16); chunk arithmetic and the live recurrent accumulator are FP32; `g`, `beta` and the default cumulative gate are FP32; final carry is written to the configured state dtype (author config says FP32); and `o` is cast back to Q dtype. SGLang convolution history defaults to BF16, while environment settings can override convolution and temporal state dtypes. Current Strata recurrence consumes FP32 operands, accumulates and retains FP32 state, emits an FP32 output plus an FP16 copy, and feeds that FP16 copy to `ssm_out`; its convolution history is FP32. Keep these storage and rounding points explicit. They are not an exact match, and FP32/ggml precision alone is not the adoption criterion.

## Actionable same-input route

A recurrence/chunk candidate can be validated without proving the old converter revision. First make a bounded deterministic post-convolution fixture in the current target shapes: normalized `q/k [1,T,16,128]`, `v/z [1,T,48,128]`, `g/beta [1,T,48]`, `gamma [128]`, and a nonzero FP32 initial state. Define unique values in grouped SGLang head order `s=3*k+j`, with BF16 Q/K/V bytes, FP32 gates/beta and state, and sigmoid output gating. Build the Strata view with the pinned convention: leave the 16 Q/K heads unchanged; permute V, Z, g, beta, and state heads by `l=16*j+k`; transpose state `S[s,v,r]=L[r,l,v]`; leave gamma unchanged. Tag every head so a wrong gather/transpose is visible. Feed each view to the pinned SGLang Qwen4Exp `TritonGDNKernel.extend`/chunk-64 path and the Strata baseline/candidate (cast BF16 fixture values exactly to float for Strata’s current pointer API). Call the SGLang norm/gate with the immutable target config. Compare per-token pre-norm output, post-norm output at each side’s declared output cast, and final recurrent state after gathering/transposing; do not mistake its BF16 per-chunk `h` scratch for the FP32 carry. Cover `T={63,64,65,127,128,129}` with nonzero state, then the candidate’s chosen chunk boundary at `C-1,C,C+1,2C+1`. Record exact backend, config/environment, input and fixture hashes. Set component tolerances against this SGLang execution path and its storage/rounding points; do not require exact full-model tokens or elevate a more precise FP32 oracle to adoption policy.

Then capture one small live `hbuf, gate, beta, z, gamma, state_before` at the existing Strata `gdn_recurrence` call for a selected target layer and replay those identical operands through baseline and candidate. This checks the current loaded distribution without reading the GGUF tensor payload or recovering its converter history; this local replay does not by itself prove cross-framework head identity. If a candidate changes weight/head packing, separately use the deterministic tagged-weight fixture to test every axis above and keep the actual loaded-order question open until a matching conversion receipt or discriminating live-loader fixture resolves it. Keep 262144-context, state/history lifetime, fault and RESTORE gates separate from this local mathematical comparison.

No code was copied or proposed for adoption. SGLang’s FLA-derived chunk is used only as a comparison contract; check nested provenance/license before reuse. This adds converter axes, author-config activation and a same-input route to R1049’s state/precision corrections. No runtime, performance, model-quality, artifact-layout or physical-context result is claimed.
