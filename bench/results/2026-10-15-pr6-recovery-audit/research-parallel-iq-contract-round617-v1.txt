## Source contract comparison

`parallel_iq_element` in `parallel-iq-dequant-v1/proposed/include/strata/sycl/iq_parallel_decode.hpp:21-79` matches the scalar formulas and packed fields in `include/strata/artifact/iq_codebooks.hpp:1106-1169`, `include/strata/artifact/dequant.hpp:113-139,273-294`, and `include/strata/artifact/dequant.hpp:69-79` (Q2_0). In particular:

- 18 uses the four-byte aux word at 66+4g; top-nibble scale, 7-bit sign inputs and parity, grid byte, and `d * (0.5 + scale) * 0.5` match the scalar loop. Each output's sign bit matches `word/2`, `word%2`, and lane extraction.
- 22 reconstructs the 10-bit grid from the byte and two high bits, selects the group/cell scale nibble and sign byte, and preserves `d * (0.5 + scale) * 0.25`, then grid value, then sign multiplication.
- 21 reconstructs its 9-bit grid, odd group scale and two-nibble sign byte. Operand order `db * grid-byte * +/-1` is preserved.
- 23 uses the same packed six-bit scale assembly, subtracts 32 after integer assembly, and does `d * (ls-32)` before multiplying by the IQ4_NL table value.
- 20 uses the same low-nibble element `j` / high-nibble element `j+16` mapping and `d * table[code]` order.
- 42 uses four LSB-first 2-bit codes per byte and `(code-1) * d`, with subtraction while integral before float conversion.

All packed reads are byte accesses. Maximum read offsets are 97, 81, 109, 135, 17 and 17 respectively, the last byte of each declared block. For the dispatched j ranges, group/cell/word/lane and variable shifts remain bounded; table indexes remain within 256/512/1024/16 entries. `iq_even_parity_signs` is reused directly. FP16 scale conversion is the same function for types 20/42 and the same `f32_from_f16` function for types 18/21/22/23. The final conversion calls the existing `f16_from_f32`, preserving its explicit RNE, signed-zero, subnormal, overflow and NaN behavior.

The proposed launch mapping at `proposed/src/kernels/sycl/iq.cpp:25-46` gives each output half one writer. Generic mapping `block=i/B, j=i%B` is correct for complete blocks. GU mapping maps each consecutive output row to gate/up alternately and source row `row/2`; it computes packed row bytes as `width/B*S`, equal to validated `rowbytes` for the six types. `count*2` is safe after the existing `count <= SIZE_MAX/4` guard, and output span validation covers those `2*count` half elements. Existing `width % 256` plus format divisibility checks ensure GU columns divide into complete blocks. Current span validation requires 2-byte source alignment and catches address overflow/overlap before dispatch; the proposed path adds no stronger alignment requirement. Odd row counts work with this mapping.

The opt-in read is exact-string `1`, initialized once at file scope (`proposed/src/kernels/sycl/iq.cpp:18-23`). Both new attempts follow the existing entry-point shape/alignment/span checks (`:71-83` and `:169-183`). F32 still uses the original path. Unsupported but valid half types return false from the six-case switch and run the old kernel. Invalid types/shapes still fail before dispatch. OFF has the prior kernel launch and finish; ON replaces it with one launch and the same finish. No default-on path is present.

## Fixture contract and actual coverage

The host fixture compares every generated output both as FP16 bits and, for non-NaN values, FP32 bits against `decode_block` + `f16_from_f32` (`cpu_fixture.cpp:10-40`). Its generator exercises every possible FP16 scale bit pattern per format and explicit zeros, signed zeros, subnormals, normals, max finite, infinities and NaNs; it traverses every grid index, all field values by construction, and source byte offsets 0..3. GU layout maps candidate element outputs against independently decoded complete gate/up rows for odd/even row counts 1/2/3 and widths 256/512/2560 (`:42-68`). This is useful independent original-vs-candidate coverage, but it is structured sampling rather than the Cartesian product of all packed fields and scales.

The GPU fixture calls the actual public entry points in separate immutable OFF and ON processes. Quick cases include all six candidate types in generic mode at source offsets 0 and 2 and in 3-row GU mode at width 512, plus decline-path cases for the other listed supported formats, F32 checks, invalid shape/pointer/span checks, guard/input checks and CPU scalar oracle output (`gpu_fixture.cpp:75-145,147-205`). Full mode adds GU 640x2560 for types 18/22/21/23 and generic 2560x640 for 20/42. The offline comparator requires equal OFF/ON complete arrays including NaN bits, identical input/oracle files, guards, and F32 outputs (`compare_captures.py:45-102`). It does not itself establish native process ownership, runtime fault status, source identity or actual route; the proposal correctly leaves these to Main's receipts.

## Remaining coverage gaps (not source defects)

1. Neither fixture constructs adversarial FP32 values immediately below/at/above half-way rounding boundaries for every final conversion coefficient. The exhaustive 65,536 scale sweep is strong but pairs scale bits with `seq=scale*37`, so packed codes are correlated with scale rather than exhaustively crossed. Add a small targeted corpus that selects code/scale pairs producing FP32 halfway residues if numerical review requires direct boundary evidence.
2. The GPU quick cases use offset 0/2 only; CPU helper coverage at offsets 1/3 proves byte loads in host code, but does not exercise public product validation/runtime at those offsets. This is appropriate if the runtime contract intentionally requires 2-byte source alignment; make that boundary explicit in claims.
3. Current CPU NaN check compares half encodings including NaN signs, but allows any FP32 NaN payload/sign difference before the half conversion (`cpu_fixture.cpp:29-34`). Since conversion canonicalizes NaN, output half coverage still checks payload/sign policy. If exact FP32 NaN source-operation behavior is part of the contract, the fixture needs an explicit NaN-sign/payload policy rather than excluding all FP32 NaNs.
4. The GPU F32 check verifies the old F32 path against the scalar decoder with ordinary finite scales; it does not exercise its NaN/Inf behavior. Since proposal does not change F32 dispatch, this is a limited regression check, not a candidate-specific blocker.

## Disposition

Source-level contract review: pass with the four fixture limits above recorded. No confirmed defect requires a patch. Proposal status remains NOT_RUN; no numerical or performance qualification follows from this audit. Main's stated freeze-release and serial validation gates remain controlling.
