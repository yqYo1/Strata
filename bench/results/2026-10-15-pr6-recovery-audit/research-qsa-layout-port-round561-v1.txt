## What `STRATA_PREFILL_ATTN_LAYOUT=1` actually selected

The old prefill parses values 1–4 at `sycl/src/prefill/prefill.cpp` around lines 931–937 and consults this selector only in the fallback branch around 3946–3955: first try the full-chunk `qsa_prompt_attn_batch`; if unavailable/forced old path, split T by `m.attn_batch`; for each slice call `qsa_decode_attn_batch_variant(..., variant, ...)`. Historical R490 confirms measured config `STRATA_PREFILL_ATTN_LAYOUT=1`; this flag was not the prompt XMX/tensor-matrix kernel layout.

Layout 1 dispatch is `launch_chunk_variant<KV_MODE, 32, true, false>` in donor attention lines 627–634. It means subgroup width 32, `TRANSPOSE_Q=true`, `QUERY_FAST=false`: query remains the outer grid dimension; it does not coalesce adjacent queries and does not change selected-cell order. For each `(query, KV head, 64-cell chunk)` group, 256 work-items stage the 12 x 256 FP32 Q values in the same 12,288-byte `sq` array. Store index is `sq[h][(d % 8)*32 + d/8]`; score lanes load `sq[h][lane], sq[h][32+lane], …, sq[h][224+lane]` (upper 16 lanes use corresponding +16 addresses). This is a 32-by-8 transpose of Q's dimension tiling. Each lane still owns its eight consecutive K dimensions; it now fetches Q dims separated by 8. This changes Q local-memory access pattern only.

The remaining group-local `sp[12][64]` scores/weights (3,072 bytes) and `srow[64]` row indices (512 bytes) stay as before; declared local arrays total 15,872 bytes. Old path computes 64-cell partial max, sum and weighted-value accumulator, then a separate `attn_merge_kernel`. Layout variants all use the same merge. Old wrapper launches a chunk kernel and merge kernel for each fallback slice. Source-level launch count is therefore 2 launches per fallback slice (T divided into `attn_batch`), independent of layout; there is no extra layout-copy kernel. No timing or device acceptance is inferred here.
