# Prefill head release/reload graph contract (R673)

Source-only audit. No build, test, compiler, GPU, runtime/process, environment, Git mutation, cleanup, source edit, or memory/latency measurement was performed. This records required ownership contracts; it does not establish a VRAM benefit or warm-serve speedup. The head reload/recapture costs remain to be measured.

## Finding

A warm-serve implementation cannot free the native target head's device storage while retaining the current Verifier objects and their captured decode graphs. The verifier borrows a `NativeHead*`, and lazily captured window graphs embed the target weight address. MTP also borrows the head object, gathers a duplicate subset into `dhead_`, and lazily captures full draft graphs. Prompt MTP graphs are a distinct K/V-only family and do not record the output projection. There is no head-only detach/rebind API today; MTP bind couples the head to logits/subset setup, while Verifier init couples the head pointer to its lifetime.

The safe boundary must be request-exclusive and graph-aware. It must retain the serving session and prompt state, not tear down the engine merely to free head storage. Whether reclaiming both packed head payloads improves long-prefill service after accounting for reread, upload, and recapture is an open measurement question.

## Exact graph and callback references

- **Target head / Verifier.** `Verifier::init` saves the borrowed pointer at `src/core/verify.cpp:239-249` (`head_ = head`). `record_window` builds the last-stage output projection at `:961-995`; the native branch calls `native_mmvq(..., head_->weights(), ...)` at `:977-985`. Thus each captured full-stage window graph can contain the target weight device address. `capture(T)` memoizes one executable per T in `exec_[T]` for the non-SYCL path (`:1074-1134`); SYCL stores segmented `segments_[T]` and overlapping shared/hit `work_[T]` executables (`:1039-1073`). `run()` lazily captures the requested T and the commit graph (`:1204-1233`). Retire every populated T family, not just the most recent window. A split verifier on an earlier stage returns before the head (`:952-959`); the last stage owns the target-head graph. The public `NativeHead*` remains caller-owned.
- **MTP duplicate and full-draft graphs.** `MtpDrafter::bind` stores borrowed `head_` (`src/core/mtp.cpp:622-630`), allocates `head_logits_`, and, when a draft vocabulary file exists, gathers target rows into owned `dhead_` with `dvocab_` (`:636-654`). Full forward runs the head at `:803-824`: it reads either the copied subset or `head_->weights()` and always calls `head_->type()`. `capture_round` and `capture_step` create full decode graph families (`:913-975`, then continuation at `:976+`), with ordinary/coupled variants in `round_exec_`, `step_exec_`, `round_exec_c_`, and `step_exec_c_`. Captured graphs reference their buffers and head payload; a subset copy avoids a graph's direct weight dependency but does not make the borrowed object pointer disposable because host capture/re-capture still calls `head_->type()`.
- **MTP prompt graphs.** `record_forward(..., full=false)` returns immediately after the K/V append (`src/core/mtp.cpp:660-671`, `:735-740`), before output projection (`:803-824`). `capture_prefill` and `capture_prefill_dev` record exactly this K/V-only work into separate `prefill_exec_[T]` / `prefill_dev_exec_[T]` families (`:895-910`). The batched prompt path launches them and synchronizes MTP's stream before returning (`:1091-1137`). These graphs, MTP K/V state, MTP dense weights, the borrowed `window_R_`, and target session state do not need to be discarded for a head-only transition.
- **Async verifier commit.** `capture_commit` records session GDN/QSA indexer and PLE state updates, not head weights (`src/core/verify.cpp:1138-1201`). `commit()` may enqueue it asynchronously and set `commit_pending_` (`:1630-1665`); `wait_commit()` is the explicit event wait (`:1667-1675`). Commit is not a head reader, but it is a verifier/session writer and must be drained before any session reuse/checkpoint or verifier destruction. Header contract at `include/strata/core/verify.hpp:124-133` explicitly requires that wait before another stream or host accesses the session.
- **Host callbacks and other readers.** `Verifier::~Verifier` first removes itself from the live callback registry and waits for acquired callbacks, then synchronizes its verify stream; it destroys graph executables/events/arena and staging (`src/core/verify.cpp:215-237`). Within a live verify window, the host pool publishes plans, copy stream synchronization protects DMA staging, and SYCL launches successive segments (`:1333-1403`); do not release during a window or its callbacks. In serve, the prompt's `sp.on_chunk` calls `draft_kv`/`mtp.prefill` after each prompt chunk (`src/program/generate.cpp:4961-4978`), so the transition must wait for the whole prompt callback chain to return. Optional selected-prefill-logits callback directly uses `native_head.run` or the canonical head and synchronizes before proceeding (`:6443-6493`); it must finish before head release or be explicitly disabled for that prompt.

## Minimum safe retire / restore contract

1. **Exclusive gate:** stop admission of new serve requests that can touch this engine; wait until all prompt `on_chunk` work and any output/logit callback has returned. No concurrent generate, RESTORE, prompt-cache continuation, checkpoint, or verifier/drafter call may race this transition. Preserve session/KV, GDN/conv, PLE, prompt-cache/RESTORE data and prefill/MTP K/V state in place.
2. **Finish existing work:** require no active verifier window and no acquired verifier callback. Drain every verifier's verify and copy streams, then `wait_commit()` for the final asynchronous commit before touching the session. Synchronize MTP's stream after all prompt/full-draft work. Any failed drain is fail-stop: retain owners and stop serving; never free storage after a failed/ambiguous wait.
3. **Retire graph readers before freeing storage:** destroy all verifier window graph families for every cached T (including SYCL segment/work graphs), and retire the final-stage verifier or otherwise provide a checked API that invalidates every head-bearing executable and clears/rebinds its pointer. MTP must retire every ordinary and coupled full-draft round/step graph before freeing `dhead_`/target weights. Keep MTP prompt graphs and K/V/session arenas. Clear stale graph handles and forbid decode/draft calls while detached. Retain the `NativeHead` object address/type metadata while MTP still holds its borrowed pointer, or replace the pointer atomically at the gated boundary; its current no-`unload` API and destructor-only ownership are not sufficient for a checked transition.
4. **Release only head-owned payloads:** target `NativeHead` owns packed weights and Q8 scratch (`src/core/native_head.cpp:14-17, 19-64`). MTP owns duplicate `dhead_`, `dvocab_`, and full-vocabulary `head_logits_` (`src/core/mtp.cpp:146-148`, allocations at `:631-654`). Decide explicitly whether logits/map are worth releasing; do not count them as target weights. Keep all session arenas and KV/recurrent state untouched. NativeEmbed is not part of this head transition.
5. **Restore fail-closed:** while the same exclusive gate is held, reload target `output.weight` from retained `native_head_shards` (the owning `NativeHead` currently has no reload/unload method; `load` reads shard data and uploads at `:19-64`). Restore MTP's duplicate subset/logits via an explicit split-phase bind/restore; validate all allocations/copies and the target head is loaded. Reinitialize/rebind the final verifier with the live head pointer. Rebuild the needed Verifier window graph families and MTP full-draft graph families lazily or eagerly, checking each capture/instantiate/upload/sync before reopening requests. Any load, copy, capture, instantiate, or drain failure must leave the engine fenced from decode; do not retain an executable that refers to the old allocation.
6. **Serve state continuity:** carry the same `SessionState`, prompt cache/checkpoints, token position, and MTP K/V progression through the boundary; do not clear or regenerate them as a shortcut. Test long/chunked prompts, selected-logit mode, RESTORE/cache continuations, repeated requests and 262144 context before adoption. Measure actual free VRAM delta and end-to-end prompt rate including target reload and graph recapture, then check short-input decode remains on its current path.

## Ownership distinctions and limits

`generate` owns the standalone `NativeHead` object (`src/program/generate.cpp:2997-3004`) and passes its address into Verifier/MTP. In warm serve, `native_head` remains in the request-serving engine scope; MTP is bound once and Verifier initialized once before requests (`:4773-4801`), so the caller can coordinate a gated lifecycle, but neither callee currently offers a safe head-only detach protocol. In a layer split, the head is stage-owned (`:2805-2809`, `:4773-4784`) and only the final stage's Verifier/MTP need head rebinding; earlier stages' session and hand-off buffers remain live. An arbitrary external API caller that supplied `NativeHead*` owns that object's lifetime; the callee cannot unload or delete it.

This contract establishes required safety and test work only. It does not assert that warm serve should release the head, that the target head can be absent from initial cache sizing, or that reload and recapture are affordable. Compare those costs against the measured memory benefit before choosing the warm-serve path; standalone prefill remains a separate candidate.
