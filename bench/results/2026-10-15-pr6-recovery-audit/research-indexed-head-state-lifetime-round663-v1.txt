# R663 — A indexed-head proposal state and lifetime audit

Date: 2026-10-15 JST. Static read-only audit of public A proposal `sycl-mtp-indexed-head-v1` against current root and R659/R660. Read the proposal README, source diff, reconstruction/pins, and root call sites. Did not apply or reconstruct the diff, run tests/build/GPU/process/Git/cleanup, inspect B/private/live-ON/environment, or modify root source. Wrote only this report.

## Finding

The proposal substantially closes R659's null-`dhead_` state split. `has_draft_subset()` covers the current sentinel uses in preflight, coupled setup, bind, output width, and decode head dispatch; indexed decode retains `dvocab_`, subset width/order, coupled inverse mapping, and the ordinary `map_ids` path. The Q6_K kernel indexes full rows while writing compact subset output. The proposal is coherent enough for Main's source/build/runtime gates, but the owner-retirement API is not a complete lifetime guarantee for every caller, and the preflight/eligibility contract has two mismatches requiring resolution before adoption.

## Bind and preflight

- The SYCL three-argument `bind_bytes` can omit copied-row bytes only when requested, type 14, aligned input, and computed row stride match. It still reserves ID bytes and logits. The legacy two-argument API passes unknown type and remains conservative. This is a sound default-off preflight distinction for the supported path.
- Preflight recognizes a candidate subset from file length, not validated IDs. `bind` later validates the complete host map before upload, so malformed IDs fail closed there; however `bind_bytes` can under-reserve copied rows for a malformed-but-length-valid subset before `bind` rejects it. Because startup then errors, this is not a successful wrong-distribution path, but it violates the precise “bytes match actual bind plan” contract. Validate the subset during preflight or make candidate eligibility contingent on the same validated immutable descriptor used by bind.
- Opt-in but non-Q6_K/unsupported geometry and opt-in with no subset silently use legacy behavior. This matches the proposal's documented fallback and preserves mathematical behavior, but it does not fail closed when an operator explicitly requested indexed mode. R659 called for explicit indexed-subset requests to reject absent/malformed subsets instead of silently changing the draft distribution. Main should decide whether the env means “prefer indexed where eligible” (documented fallback is valid) or “require indexed” (currently unmet); do not describe the latter as already guaranteed.
- For valid indexed input, host ID validation occurs before map allocation/upload; duplicate and nonmonotonic entries are retained. Upload failure is fail-stop after device allocation ownership may be uncertain. `indexed_head_` is set only after upload succeeds. Incomplete indexed bind is rejected on reuse, avoiding a partially published subset state.

## Coupled, output remap, and rebind

The substitutions preserve `nv=n_dvocab_`, coupled `dvocab_`/`dinv_` inputs, and normal post-sampling mapping. Coupled inverse construction uses the host ID vector in indexed mode and preserves first-occurrence semantics. Indexed coupled ring initialization, inverse upload, and setup synchronization check failures. Allocation failure can return false with already acquired allocations retained by the Mtp object for its destructor; no captured indexed head reader exists at that point.

After indexed bind completes, only the same WeightTable, NativeHead pointer/weights/type/output width, and window pointer can be rebound; this returns without rereading IDs or mutating captured map state. Other indexed rebinds and use after explicit retirement reject. The guard is deliberately conservative. Legacy binds retain old behavior. Full-forward dispatch still derives subset semantics from `has_draft_subset()` while selecting the indexed kernel only for `indexed_head_`; the pre-existing sampling/remap sites therefore continue to use compact row IDs correctly.

## Borrowed owner and graph retirement

In `generate.cpp`, `MtpDrafter mtp` is declared at line 2819, before `NativeHead native_head` at line 2997. The added lease is declared immediately after `native_head`; C++ reverse destruction therefore calls `retire_indexed_head_readers()` before destroying the local `NativeHead`. The lease's early-return case is safe because retirement is a no-op unless indexed mode was published. Layer-split serve binds to `last_st->head`; those stage owners were created before `mtp` and remain alive beyond it, so the local lease does not shorten their lifetime. Ordinary/coupled round and step exec families are drained and destroyed before the borrowed head owner ends. Prefill execs use KV-only `record_forward` and return before the head operation, so omitting them from the indexed retirement loop is consistent with the reviewed path.

The remaining lifecycle gap is at the public API boundary: `retire_indexed_head_readers()` is the only explicit borrowed-owner fence, but arbitrary `MtpDrafter` callers can still destroy/reload a `NativeHead` without calling it. Its header comment states the obligation; no type-level owner or destructor link enforces it. The proposal README also says other callers must call it. This is an integration obligation, not a defect in the audited `generate.cpp` ordering. Verify every production bind caller is covered before adoption; if the API is intended to guarantee safety independently, it currently does not.

## Kernel and validation observations

The indexed wrapper checks full-weight, ID, activation, and compact output spans, validates all spans against the SYCL compatibility allocation registry, checks dimensions/overflow, and enqueues on the validated stream. Its `Indexed=true` branch changes source-row address and preserves shared Q6_K arithmetic. Invalid device IDs skip row computation, yielding zero through the launch's zero-initialized accumulator; production IDs are separately rejected on host. Fixtures are proposed but unrun, so parity remains unproven. No performance, physical VRAM delta, model quality, or selected-native-type claim is established here.

## Gate summary

No broad source-contract blocker was found in bind state, coupled mapping, output remap, or the actual generate/stage owner ordering. Before adoption, resolve the malformed-file preflight under-reservation and state clearly whether opt-in requires indexed mode or permits documented legacy fallback. Confirm all non-generate callers obey the borrowed-owner retirement contract. R660's bitwise parity and the proposal's explicit runtime/build/IR gates remain outstanding; source inspection is not a result for them.
