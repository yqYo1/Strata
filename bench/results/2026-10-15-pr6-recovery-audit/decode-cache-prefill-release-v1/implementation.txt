What is implemented

Exact opt-in: STRATA_PREFILL_RELEASE_DECODE_CACHE=1. All other values are OFF.
Default OFF follows the existing Prefill::run with no new profile scan,
allocation, queue wait or memory query. Added booleans/branches guard decode
callbacks and Prefill against a live prompt lease; no default-path device work
is added by those guards.

Initial supported scope is deliberately narrow:
  - STRATA_PREFILL_LAYER_MAJOR=1, native single GPU, no token graph;
  - explicit positive --expert-cache, nonempty --expert-profile;
  - explicit fixed --prefill, --no-prefill-borrow, native hit graphs;
  - --spec >=2, because this first candidate uses the existing static residency
    table created for speculative verification, rather than adding another map
    setup path for non-speculative decode;
  - no peers/remotes/layer-split/adaptive replacement/vision;
  - no live RouterLookahead (set STRATA_LOOKAHEAD=0 when the source would enable it);
  - complete native GPU hit setup and a fully populated fixed profile cache;
  - a prompt segment longer than Prefill::chunk(). Short segments retain the
    existing path and never release the decode cache.

The existing layer-major constraints remain in force, including explicit
STRATA_PREFILL_MMQ=0, compact FP16 expert compute and a shared compute/copy
queue (the existing STRATA_SYCL_PREFILL_SAME_QUEUE=1 configuration). This
candidate does not relax geometry, KV, residual precision or host-headroom
admission. It does not change model operator math.

The original explicit-cache startup resolver can choose sized slots from its
byte budget. The transaction pins the actual resolved current slots/offsets/
arena bytes and reproduces them exactly; it does not rerun a free-memory or
profile-sizing planner during restore. No auto cache is accepted. Actual
resolved slots must all have original profile entries. Per-layer admission is
supported only when every allocated slot is populated and can be replayed in
the same profile order; otherwise the transaction is rejected before mutation.

Ownership and ordering

1. Validate the complete existing map against ExpertCache::slot_of(), resolve
   each populated slot in original profile order, and save exact per-slot
   sizes, map, arena bytes, admission mode, internal allocation blob size and
   dispatch blob size. The internal raw blob maximum is saved separately from
   padded slot offsets, so a sized restore does not silently enlarge later
   default fill lengths. Allocate two
   bounded host-USM slabs, each one largest actual expert blob: one immutable
   upload source and one strict byte-check readback destination. There is no
   second full-cache host copy. File/mmap-backed and resident sources remain
   alive; this is not a claim that all source weights are physically in RAM.

2. A fail-stop lease is armed before detach/driver mutation. Prefill checks
   own-buffer status, full single-stage long layer-major eligibility, host
   stager active/claimable state and queue completion; then nulls its cache/map
   fields. Its detached run gate refuses a fall-through into ordinary chunk
   execution. Layer-major installs its own temporary cache before run_impl
   consults resident slots.

3. Serve only: Verifier checks a healthy inactive/completed window boundary,
   pending commit completion and verify/copy queue completion; checked-destroys
   every T's segments/work/exec handles. It clears completed host/device plan
   pointer copies and its VerifyHits values. arena_, final_R, streams, events,
   mapped buffers and cache-independent commit_exec_ remain alive. Its next
   run is refused while detached. NativeHitGraphs is checked-drained and every
   owned executable plus its mapped plan is checked-destroyed. Another shared
   NativeHitGraphs owner is refused. Main's serialized issuer and joined
   session/window calls are the host-pool completion boundary; ExpertPool's
   run APIs already return after their completion/park barrier. Lookahead and
   adaptive threads are excluded rather than assumed idle.

4. Mark Dispatch not ready; sever its cache/base/offset values and TokenHits
   cache base; clear old native host/device pointer metadata, publish stable
   host/device all-miss maps and checked-wait. Only then close the same cache
   object through close_checked. The close reports free failures and never
   erases a failed pointer. Failure immediately exits through the outer lease,
   before ordinary destructors can retry an uncertain owner.

5. Run only the long layer-major segment. Its own lease must complete before
   its temporary cache/residual owners go out of scope. Healthy false returns
   (including cancellation) still proceed through complete decode-cache
   restoration, preserving the original prompt status/error. A driver failure
   or an exception before complete restoration fail-stops with owners live.
   This restores cache availability, not partially computed session state;
   existing request cancellation/session-reset semantics still apply.

6. Reopen the SAME ExpertCache object with saved actual slot layout and byte
   count, without allocation-time device initialization. Inside the outer
   checked lease, explicitly zero the arena and wait, restoring deterministic
   startup padding. Re-admit in saved profile order and require each original
   slot index. Copy original source bytes into the bounded upload slab, enqueue
   one slot fill, checked-wait before slab reuse, enqueue D2H into the retained
   readback slab, checked-wait, then compare every byte of every restored blob.
   This strict candidate checks all populated slots; upload and verification
   time are part of restore cost, not excluded overhead.

7. Require every saved slot, blob byte count and full residency map before
   publication. Keep the existing host_res vector storage; copy the full saved
   map back, upload d_res and wait. Refresh Dispatch cache/base/blob/off,
   TokenHits and Verifier VerifyHits.n_slots/base/off/blob. Re-capture every
   previously captured Verifier T window; untouched T values remain lazy.
   Re-capture native hit graphs with failure retention enabled and checked-wait.
   Rebind Prefill, retire both slabs, query restored free VRAM, then mark
   decode ready. Decode callbacks and Verifier::run reject earlier entry.

Native graph recapture adds a strict capture lease so the local graph owner
cannot free its host-USM plan during error unwinding. Verifier recapture has a
strict failure exit before its ordinary failed-capture cleanup. The original
default capture behavior remains selected when this option is OFF.

Diagnostics added

Two finite stderr lines per released segment:
  detached: actual arena_bytes, slots, entry-through-detach wall_ms,
            free_before and free_after in bytes;
  restored: same arena_bytes, actual blob upload_bytes and verify_bytes,
            slots, refill_ms (allocation/zero/upload/verification),
            recapture_ms, restore_ms, restored free bytes,
            original prompt_ok and decode_ready=1.

Detach wall includes opt-in plan validation and slab allocation. Restore wall
includes map publication, recapture, rebind and slab retirement. Existing
Prefill stats still describe Prefill; existing outer prompt wall measurements
include the new wrapper costs. Free bytes are observations at distinct owner
states. An increased free query is not an allocation/performance success.
