# QSA indexer device-batch candidate review (R682)

Read-only source review of `qsa-indexer-device-batch-v1` against the R680 dependency contract. No candidate code was applied, built, compiled, or run; no process, GPU, or environment inspection was performed. Main retains all integration and execution control. The candidate remains source-only and unqualified.

## Review result

I found no source-level race or certain arithmetic/state-transition defect in the proposed two-phase completed-block kernel plus finalizer. The implementation structure addresses the main R680 hazards: the zero-position seed uses the original append kernel before block groups; each group writes only its completed pooled row; tail, moving spare, and `block_pos` have a separate finalizer after the groups; and selection remains ordered after append on the same validated queue. The copied half conversion, sum order, FMA, RMS tree, RoPE/M-RoPE expressions, and absolute-position mapping match the existing append body by inspection (`source.diff`, `qsa_indexer_device_batch.cpp:79-155` in the candidate source). This is a review conclusion, not parity evidence.

The artifact pins all four existing-file base hashes to the current root files (`source-manifest.json`); in particular the unchanged native source currently hashes to `d87abcf8...38685`. The proposal is separately linked to the actual `strata_kernels` source and manual fixture in its CMake diff. It is default-off, preserves the existing single-cell body, and the process flag parser accepts only absent/`0`/`1`. There is no claim here that the proposed source is applied or compiled.

## Candidate-specific gaps and risks

1. **No candidate batch tests the seed-only path.** The small suite starts `p0=0` with chunk length one, which takes the explicit `n==1` original-append fallback (`README.md`, candidate `sequence()` and `candidate()`); its later chunks begin at `p0=1`. The large suite does exercise a multi-cell seed plus completed blocks. Thus the candidate's `seed_zero` followed by finalizer with no completed block (for example `[0,2)` or `[0,3)`) is not covered, although source inspection looks consistent. Add small `p0=0` candidate batches of lengths 2 and 3, and an exact `[0,4)` case, with full state comparison after each.

2. **Invalid-span coverage is narrower than the README wording.** `invalid()` tests raw misalignment, raw-to-pooled/raw-to-tail aliasing, and block-position-to-dead aliasing, plus null pointers. It does not exercise misaligned gamma/state spans or the other state-state overlap combinations, despite the README describing pointer/alias/alignment rejection broadly. The production validator is reused and appears to validate the required disjoint spans, but candidate-specific prelaunch/no-mutation evidence for these cases is absent. Add a few representative state-span misalignment and state-state alias cases, checking every state byte remains unchanged.

3. **The fixture's “restore” check is deliberately synthetic.** It copies an `Image` into new allocations and republishes the moving spare from `dead` (`candidate fixture:193-198`); this cannot detect integration errors in session snapshot serialization, actual RESTORE validation, or callbacks. README and result flags accurately leave real RESTORE unqualified. Keep the separate actual RESTORE gate in Main's plan.

4. **No execution or fault closure exists yet.** The README accurately says the host planner, GPU fixture, registered-table/M-RoPE modes, long batches, and physical last-row case are proposed manual tests only. Copied arithmetic and fixture intent do not qualify SYCL compiler acceptance, device ordering, exact state/selected-ID parity, queue retirement, full-context model behavior, or speed. Main must run its listed independent-oracle gates before considering adoption.

## Contract trace

- Seed and block ordering: candidate explicitly submits original position-zero append before completed groups; the in-order queue provides a kernel boundary. The separate finalizer handles latest tail slots, terminal spare, and final block position. There is no per-group write to shared tail/dead/spare/block_pos (`source.diff`, new helper bodies).
- Partial starts and chunk splits: planner computes completed rows from `[p0,end)`, and group inputs use old tail only for components preceding `p0`; the finalizer leaves earlier tail slots untouched. The planned split test includes partial boundaries and a seeded nonzero prefix, but must actually run.
- Causal selection: the fixture runs existing score/top-k consumers on both independently allocated oracle/candidate states, supplies per-query steps, and checks score/ID parity, sorted IDs below each query's `n_kv`, identity range, future score sentinels, and ID canaries (`qsa_indexer_device_batch.cpp:104-152`). This is meaningfully independent because the oracle uses the unchanged single-cell append body, unlike the old loop-backed batch API. It remains unexecuted.
- Rope and M-RoPE: the completed-block expression mirrors the existing body, while the fixture matrix selects analytic/full/short registered tables and plain/M-RoPE in separate invocations. The short-table case is intended to test table plus analytic fallback; it remains unexecuted.
- Maximum physical row: planner allows `capacity/4+1` pooled rows, and the physical suite allocates the full extent, builds a contiguous 262140-cell single-cell prefix, then batches cells 262140–262143 and checks spare row 65536 and the next-row canary. This is a real fixture allocation design, not a reduced-capacity relabel, but is not a 262144-token model-context qualification.
- Environment/production dispatch: parser uses the exact immutable option and candidate API can be called directly. The C++ host fixture tests parser helper values; it does not itself prove separate-process production dispatch behavior. Main's suggested strict-flag processes and unchanged default-path tests remain necessary.

## Main follow-up

Before applying, retain the source-only identity and verify current base hashes again at the integration boundary. Add the seed-only and representative state-span cases above, then run the host planner and the manual SYCL matrix under Main's measurement/fault controls. Require exact complete-state and selected-ID comparisons against single-cell appends before model comparisons. Keep full RESTORE, callback/MTP, physical model-context, cancellation/fault, matched timing, and adoption as separate later gates; this candidate provides no speed or quality result.
