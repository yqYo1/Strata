## Corrections

**R1046-C1 — `MemoryCopyFromContext` emitted labels are described incorrectly.** The callback passes the source context/pointer and `nullptr` as the destination context. The classifier therefore returns only the source allocation bucket. `AppendMemoryCommandContext` adds that value to the `MemoryCopyFromContext` enum base; that enum's first four names are `H2H`, `H2D`, `H2M`, `H2S`. Thus H/D/M/S source buckets are emitted as `FromContext(H2H/H2D/H2M/H2S)`, respectively. For example, a device-type source is named `H2D`, not `D2H`. These names do not encode a source/destination pair, and the destination pointer/type was not queried. See pinned source [classifier](https://github.com/intel/pti-gpu/blob/6c0d6b0b80c6dbac4b5902d9d5ade1c75b9e9033/tools/unitrace/src/levelzero/ze_collector.h#L4670-L4729), [enum/name table](https://github.com/intel/pti-gpu/blob/6c0d6b0b80c6dbac4b5902d9d5ade1c75b9e9033/tools/unitrace/src/levelzero/ze_collector.h#L249-L427), [context append helper](https://github.com/intel/pti-gpu/blob/6c0d6b0b80c6dbac4b5902d9d5ade1c75b9e9033/tools/unitrace/src/levelzero/ze_collector.h#L3625-L3645), and [callback](https://github.com/intel/pti-gpu/blob/6c0d6b0b80c6dbac4b5902d9d5ade1c75b9e9033/tools/unitrace/src/levelzero/ze_collector.h#L4884-L4892).

**R1046-C2 — several source anchors do not point to the cited code at the pinned revision.** Replace the affected anchors with the actual ranges: allocation classifier `L4670-L4729`; standard copy callback `L4743-L4751`; region callback `L4849-L4864`; context callback/helper `L4884-L4892` and `L3625-L3645`; timing aggregation `L948-L973`; timestamp conversion and collection `L2555-L2608`; and command-name size rendering `L1094-L1127`. This is a citation correction only; the other source-backed findings were checked against the raw file at the exact commit.

## Supported findings and limits

For standard copy and copy-region commands, source and destination are queried separately and successful allocation types map HOST/HOST_IMPORTED to H, DEVICE to D, UNKNOWN to M, and SHARED to S. A successful query for memory unrelated to the supplied context may return UNKNOWN under Level Zero; the collector asserts query success, so a failed query is not a fallback to M. The source confirms these are allocation-type labels, not residency or route measurements. The region callback initializes size to zero and only multiplies by depth, so its displayed size cannot represent region payload.

Device timing aggregates start-to-end device timestamp intervals, with call count, total/percent, average, minimum, and maximum. It excludes append-to-submit and submit-to-start delays, reported separately by the submission table. No byte-rate column exists. Verbose command names can include requested size; standard copy passes the API's requested `psize`, but that is logical command payload, not measured wire traffic. These intervals and sums are not dependency critical-path time, physical PCIe traffic/utilization, GPU occupancy, or a union of busy time. The current profile remains whole-process, nonexclusive timing; it does not establish physical traffic, occupancy, or a device-busy union.

The payload/source join recipe is useful when a concrete attribution question arises: capture per-instance append, pointers, contexts, requested size and source callsite; tag library wrappers; join to command instance/timeline and dependency evidence; then sum only the selected logical operation. A PCIe bottleneck claim additionally needs same-interval link evidence or a controlled payload-rate baseline, route/topology, and demonstrated request critical-path impact. This is a source-only recipe, not a claim that those measurements exist.
