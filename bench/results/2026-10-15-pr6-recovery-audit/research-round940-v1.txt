# R940 — BF16 probability-boundary gate for QSA prefill

**Class:** decision support. **Question:** compare the actual model QSA prefill arithmetic in the pinned SGLang and versioned vLLM sources, then define a prospective gate for the Strata BF16 candidate after a measured BF16 probability-rounding crossing. No implementation, build, test, framework execution, or performance run was performed.

## Findings from the current receipt

The closed synthetic baseline receipt preserves the original failure: the instrumented output reproduces the original FNV fingerprint, while the recorded numerical status remains `FAIL` with 10/24,576 output coordinates beyond its old FP64-derived budget. It uses 8,192 synthetic query rows, 2,051 selected cells per row, and a 262,144-cell synthetic pool; this is not a model prefill or physical-context qualification. The supplied baseline/pack fingerprints match for this fixture.

For the inspected head, 1,233/2,051 scores differ between host reference and GPU capture, with maximum absolute difference `1.19209289551e-7`. Two probabilities cast to different BF16 values. At both cells (204 and 581), the scores are equal (`0.263088017702`) but the online maxima differ (`0.383504837751` host, `0.383504807949` GPU). The host probability is `0.919921815395`; the GPU probability is `0.919921875`. The latter is the BF16 rounding midpoint between `0.91796875` and `0.921875`; ties-to-even selects the upper value, while the slightly smaller host value selects the lower value. Applying host `std::exp2` to the captured GPU score-minus-maximum gives `0.919921875` and produces no BF16 cast differences across the recorded cells. This receipt therefore supports a small FP32 score/maximum-path difference crossing a BF16 boundary; it does not show a same-argument host/SYCL exp2 disagreement.

Replaying captured GPU P, alpha and normalizer with independently decoded V reproduces all 256 output dimensions exactly and accounts for all 10 former oracle mismatches. That is an exact component replay, not a new pass: the original failure status remains unchanged. The receipt has no model PP, RESTORE, or 262,144-context model qualification and no speed samples.

## Production arithmetic compared

The pinned SGLang `forward_extend` path selects the direct sparse GQA kernel when there is no cached prefix; with a prefix it packs KV to the query dtype and calls the chunk-prefill kernel. Both routes reach the QSA Triton arithmetic described below. The vLLM v0.30.0 Qwen4Exp QSA Triton kernel is tuned for Qwen3.8-Flash-Next shapes and selects a prefill configuration at the owner call site. These source paths are relevant references, not Strata runtime measurements. [SGLang backend at 877be2974aa151a984e52822c028276c2b1e9303](https://github.com/sgl-project/sglang/blob/877be2974aa151a984e52822c028276c2b1e9303/python/sglang/srt/layers/attention/qwen_sparse_attn_backend.py), [SGLang QSA operators at that revision](https://github.com/sgl-project/sglang/blob/877be2974aa151a984e52822c028276c2b1e9303/python/sglang/srt/layers/attention/qsa/sparse_attn.py), [vLLM QSA owner API v0.30.0](https://docs.vllm.ai/en/v0.30.0/api/vllm/models/qwen4_exp/nvidia/qsa/), [vLLM QSA kernel v0.30.0](https://github.com/vllm-project/vllm/blob/v0.30.0/vllm/models/qwen4_exp/nvidia/ops/qsa.py).

The QK source in both frameworks passes BF16 operands to `tl.dot` without annotating an accumulator dtype. Triton’s API describes the matrix product and optional accumulator, but does not promise a fixed summation tree or bitwise order. FP32 QK accumulation is the expected lowering for these BF16 GPU dots; confirm the actual JIT output/runtime before treating it as evidence. Strata explicitly declares an FP32 joint-matrix accumulator, though the hardware’s internal reduction order still is not a cross-device bitwise contract. The online max/normalizer recurrence is the standard blockwise method described by Milakov and Gimelshein. [Triton `tl.dot`](https://triton-lang.org/main/python-api/generated/triton.language.dot.html), [Milakov and Gimelshein, *Online normalizer calculation for softmax*](https://arxiv.org/abs/1805.02867).

## Prospective numerical gate

Keep the historical receipt byte-identical and marked failed. Add a prospective gate for a declared arithmetic contract, with three layers. Do not replace it with a looser final-output epsilon.

1. **Exact structural invariants.** For each case, compare Q/K/V operand bytes after the declared dequantize-and-cast boundary, selected logical IDs, causal/tail visibility, page mapping, valid masks, output shape and guard regions. IDs and masks must match exactly. Invalid cells must contribute zero; empty rows, missing/out-of-range pages, partial tails, non-finite inputs/scales and physical-boundary cases retain their explicit handling. A wrong cell, scale, transpose, mask or out-of-bounds access is a hard failure regardless of output distance. Add negative controls that deliberately change scale and one selected ID and verify that the stage/output checks detect both.

2. **Tensor-stage numerical bounds.** Freeze the chosen SGLang-style scale placement, BF16 rounding points, BF16 operand bytes, exp2 inputs, tile width/order, normalizer rule and split count. For every valid QK dot, record the pre-cast operands and compare FP32 scores against a same-contract reference with an operand-specific forward-error bound. For BF16 products accumulated in FP32, a first bound is `gamma_(D-1) * sum(abs(q[d] * k[d]))` per dot; when comparing two reduction orders, use the sum of each path’s bounds. This is an error model, not an observed tolerance: confirm it against the actual JIT lowering and widen only if the measured arithmetic contract requires it. Higham’s summation analysis explains why the addition order changes the computed sum. [Higham, “The Accuracy of Floating Point Summation”](https://epubs.siam.org/doi/10.1137/0914050).

   Propagate the measured score bounds through the row maximum and `2^(score - max)` to a per-cell probability interval, including measured same-argument exp2 error. Require matching BF16 P casts when that interval stays within one rounding cell. Permit a differing cast only when the interval crosses a single BF16 midpoint, the two results are adjacent BF16 values on opposite sides of that midpoint, and the pre-cast difference is within the propagated bound. Record each such cell, signed distance to the midpoint, cast direction and its contribution to output error. This accepts a real discontinuity while rejecting arbitrary probability or output drift. The current two cells fit this pattern; the same-argument host-exp2 receipt is evidence for those inputs only, so add a directed sweep immediately below, at and above BF16 midpoints over the production exponent range.

   Compare FP32 alpha, unrounded probability sums, normalizer and PV accumulator before final BF16 storage. Bound final component error from the permitted P ULP changes, FP32 accumulation-order error and normalizer error; use the actual K/V operands and report per-row and per-dimension maxima plus aggregate bias. Do not require identical FP32 reductions across compilers/devices. Do reject repeated one-sided score shifts, scale errors, non-adjacent P changes, row-normalizer drift, error growing outside the derived envelope, or a boundary mismatch not predicted by its pre-cast interval. The FMA difference and any vLLM split/merge path must be represented in the selected reference contract.

3. **Same-contract backend and task evidence.** First compare a same-contract reference on identical captured operands and selected IDs; compare Strata to SGLang’s Q-scaling contract on the same pre-gate output. Run vLLM as an alternate contract comparison, not as a bitwise gate against the SGLang-style candidate. Where native framework KV is BF16 and Strata starts from int8 plus group scales, hold the decoded BF16 matrix operands equal for the arithmetic test, then measure cache quantization as a separate stage. Record framework revision, CUDA/Triton/compiler/GPU, resolved prefill branch, BF16/FP32 lowering, tile/split configuration and actual call arguments; source flags alone do not prove the runtime contract. Repeat on random and adversarial rows (flat/peaked logits, tied maxima, midpoint P, invalid/tail cells, large selected sets) and preserve finite, guard, fault and lifetime checks.

   Finally run the model with the candidate isolated from selector and other precision changes. Measure teacher-forced per-token loss/logprob deltas and a predeclared task suite against the selected production reference; use paired prompt-level summaries and confidence intervals, and require no systematic task regression under non-inferiority margins chosen from baseline repeatability and fixed before seeing candidate results. Different sampled or greedy token strings alone are not a numerical failure. Separately retain the project’s long-prefill performance gate and repeated >600 tok/s milestone, then continue toward 1000 tok/s. Numerical correctness, model quality and throughput are independent decisions.

## Decision and remaining evidence

The source design is defensible for SGLang-style BF16 Q scaling, BF16 P storage and FP32 attention accumulation. Current receipt evidence establishes reproducible baseline behavior, exact captured-coefficient replay, two boundary crossings and no same-argument BF16 exp2 cast changes in that case. It does not establish the candidate’s complete stage bounds, the vLLM-style alternative, model quality, long-prefill performance, physical 262,144-context correctness, RESTORE safety or production adoption. Minimum next evidence is the instrumented candidate under the frozen SGLang-style gate, JIT/lowering proof for its BF16 operands and FP32 accumulators, stage-complete structural/fault/lifetime checks, same-input framework comparison, followed by full-model task, context/RESTORE and repeated long-prefill performance qualification. Keep the current production selection unchanged until those decisions are recorded.
