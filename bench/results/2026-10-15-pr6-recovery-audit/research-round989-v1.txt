# INT8 sparse attention contracts and applicability

Classification: knowledge collection  
Retrieved: 2026-10-17  
Target: Strata sparse selected attention on Arc B570 (Xe2/BMG), with 2 KV heads, 12 query heads per KV head, head dimension 256, up to 2051 selected cells, 32-cell online tiles, BF16 query/probability/global I/O, FP32 persistent online state and accumulation, and K8/V8 source storage. This report is research only: no Strata implementation or B570 performance result is claimed.

## Findings for Main

The most direct INT8 experiment would retain the existing K8 codes and their four per-cell 64-channel scale groups, quantize each BF16 query head in matching 64-channel groups, and compute signed INT8×INT8 dot products into INT32. Scale each group’s partial score by its query and stored-key scales, sum in FP32, then continue the existing BF16 probability/value path and FP32 online softmax/state. This avoids re-encoding K and could halve the bytes of an expanded K tile in local staging. It does not reduce K8 source bytes read from global memory, and it adds query quantization, scale handling, and a different rounding path.

Intel’s published BMG matrix shapes temper the throughput hypothesis: the listed signed-INT8 form is M≤8,N=16,K=32 with INT32 output, while BF16 is M=16,N=16,K=16. For a 16-row padded query tile, 32 key cells, and D=256, a simple descriptor-level count is 32 matrix operations for either type (BF16: 1×2×16; INT8: 2×2×8). This is arithmetic from the published shapes, not a measurement; it means there is no basis here to promise fewer matrix instructions. The concrete potential is lower local operand footprint/traffic and perhaps different hardware scheduling. The spec is experimental; only the installed compiler/runtime’s queried combination can establish availability on the target.

The SageAttention alternative is less direct for this cache: it dynamically quantizes Q/K by blocks, smooths K, and uses FP16 P/V in its Sage-1 path. Strata already has K8 with finer feature-group scales, so reconstructing/requantizing K adds work and another rounding step. Correct smoothing for this sparse selection must use the same mean vector for every valid selected key; a per-32-cell mean changes relative logits. FP16 and BF16 both use two bytes, so Sage’s FP16 P/V result does not itself predict a storage or speed win over Strata BF16.

## Four coherent designs and their countercases

| Design | Data/math contract | Plausible benefit | Main countercase |
|---|---|---|---|
| A. Current BF16 XMX baseline | Expand or stage source K8 as BF16 for BF16 QK; BF16 P/V; preserve FP32 online max/sum/output state. | Keeps the existing score path and avoids new Q quantization error. | A 32×256 BF16 K tile occupies 16 KiB if materialized in that form. Decode, transpose, or padding may add local traffic; verify actual source path before attributing a cost. |
| B. Cache-native INT8 QK, BF16 P/V | Quantize Q per head and 64-channel group; multiply against stored signed K8 codes per matching group into INT32; dequantize each group’s dot with FP32 scales; retain BF16 P/V and FP32 online state. | K operand staging is 8 KiB for a 32×256 tile, versus 16 KiB for BF16. It avoids dequantize-then-requantize of K and preserves the source K codes/scales. | No reduction in source K8 global bytes. Q quantization, group scaling, score conversion, and INT8 matrix support may erase local savings. Published BMG matrix shape arithmetic gives 32 versus 32 operations for this tile under the stated row padding; actual time is unknown. |
| C. Sage-style block INT8 QK with K smoothing and FP16 P/V | Reconstruct source K, subtract a common valid-selected-set mean per KV head/channel, dynamically quantize Q/K blocks, use online softmax, and use FP16 P/V. | Independent algorithmic precedent for low-precision QK and an accuracy-oriented K transform; could help if current K/Q ranges are poorly conditioned. | Existing K8 is already quantized; reconstruction and re-quantization add error and work. A selected-set mean needs a valid-ID-aware prepass or equivalent; per-tile means are not softmax-invariant. FP16 and BF16 storage are both 2 bytes and have different range/rounding. This is a poor first fit absent range/error evidence. |
| D. BF16 XMX with decode/layout fusion | Keep BF16 score arithmetic, but generate only the consumed 32×256 BF16 tile in the exact layout the matrix load needs, avoiding an additional padded/transposed scratch representation where the API permits. | May reduce copies/transposes without changing QK precision or source K encoding. | A BF16 matrix operand still needs BF16 data. `joint_matrix_load` does not by itself establish an INT8-to-BF16 converting load; if a full local BF16 tile remains necessary, the expected saving may disappear. Treat this as a layout hypothesis, not an established capability. |

For design B, symmetric quantization can be written as `sQ[h,g]=max(abs(Q[h,g]))/127`, `q=clip(round_to_nearest_even(Q/sQ),-127,127)`, with a defined zero-group rule. Use source `sK[cell,g]` unchanged. Each group’s 64-channel signed dot has maximum absolute magnitude at most `64×127×127 = 1,032,256`, safely within signed INT32. Restore the exact model attention normalization (commonly `1/sqrt(256)`, but verify the executed path) and sum the four scaled partials in FP32. Scale application must match the actual stored scale type and rounding point. This is a candidate contract, not a claim that the repository currently uses those exact scale semantics.

At the 2051-cell cap there are 65 logical 32-cell tiles per KV head (last tile partial). A materialized full tile has 8192 values: 16,384 bytes as BF16 and 8,192 bytes as INT8. The 8 KiB difference is per local tile if the current kernel really stages expanded K that way. Source K8 payload remains `2051×256` bytes per KV head in both designs; V8 and scale metadata also remain. These byte counts do not include padding, alignment, scale traffic, registers, barriers, or hidden compiler spills, and are not timings.

## Numerical contract and sparse-selection implications

- Preserve query/key ordering and the selected ID multiset exactly, including duplicate IDs if the selector can emit them. Apply invalid/negative/padded-ID masks before any statistics or reduction; do not let padding rows enter a smoothing mean or receive a score. Preserve the 2051 width boundary and the physical 262144-context bounds.
- The exact softmax is invariant to subtracting the same `q·mu` from every valid key logit for one query. It is not invariant to a different mean per cell tile. For sparse attention, compute any K mean over the valid selected population actually scored (with defined duplicate semantics); different selection sets can have different means. Quantization after smoothing can still change logits because the quantizer is nonlinear.
- INT8 QK changes Q rounding and the score reduction order/rounding. Keep INT32 partials and scale products separate until FP32 score accumulation; compare score errors, selected-score order near selection/tie boundaries, online max/sum, output vectors, and task results. The selected set itself should remain fixed when isolating this kernel change, then selector interaction should be tested separately.
- FP32 persistent online max/sum and recurrent state are not interchangeable with low-precision tensor storage. A Sage-like FP16 P/V route introduces its own probability rounding, value conversion, product accumulation, and FP32 update boundaries. BF16-to-FP16 conversion can overflow or underflow differently; numerical range and actual timings decide, not the equal two-byte size.
- Compare against the actual SGLang/vLLM path for this model when available, including storage, accumulation, reductions, normalization, routing, and state boundaries. A generic backend feature list does not prove that it executes this sparse 256-dimension path. A mismatch with a stricter FP32/llama.cpp oracle alone is not an adoption failure under the supplied policy.

## Evidence and transfer limits

SageAttention’s paper reports a near-baseline WikiText perplexity example (Llama-2: 5.823 baseline and 5.824 for SageAttention) and an RTX 4090 speed example for QKV shape `(4,32,1536,128)` at roughly 1.77×. These results support low-precision attention as a real design point, not this workload: the cited head dimension is 128, the execution is CUDA/NVIDIA, the context is not this sparse 2051-cell selected set, and the paper does not establish Arc B570 performance. Sage’s reported Q/K block scheme and K smoothing also differ from consuming Strata’s existing K8 group codes.

The pinned SageAttention repository implementation documents a CUDA path and its core uses dynamic block quantization/smoothing; its relevant path does not establish support for head dimension 256 on Strata’s SYCL route. Use it as an algorithm reference only. Do not port its source. SageAttention repository license is Apache-2.0; repository metadata and exact source notices should be checked before any future source reuse.

The vLLM attention-backend matrix documents backend/cache combinations, including `int8_per_token_head` for its Triton attention cache path. A cache dtype declaration is not evidence that QK uses integer XMX dot products. vLLM’s quantized-KV-cache documentation describes an FP8 FlashAttention-3 path that also quantizes Q and supports tensor/head scaling, which is relevant precedent for joint Q/K quantization but remains a different dtype/backend/device path. The pinned source path below is NVIDIA FlashAttention integration, not proof of an Intel SYCL contract.

The inspected SGLang LLM attention-backend documentation lists FlashInfer/FlashAttention/Triton options and FP8 cache support. SageAttention appears in the separate SGLang diffusion backend documentation, where the Sage route is CUDA-oriented and the XPU choices are XPU Flash Attention or SDPA. This is scoped to those inspected first-party docs, not a claim that no other SGLang code exists. Neither framework page proves the numerical route for this exact Strata model and sparse selector.

The current main-provided model evidence (six actual 39K model processes) shows no stable model-level win between the compared QSA variants, around 490 tokens/s in both groups. That does not identify attention’s fraction of runtime or establish an INT8 QK opportunity. The provided 25-event service calibration validates timer/event behavior only; it is not device busy-time, bandwidth, or attention performance evidence.

## Bounded follow-up question for Main

If Main selects design B, first query/compile the installed LLVM 22.1, libsycl 9, UR Level Zero runtime for the exact BMG signed-INT8×signed-INT8→INT32 matrix combination; source-spec support alone is insufficient. Then run an isolated, same-input prefill comparison at fixed 2051 selected cells and at representative shorter/tail widths, with the selected IDs held constant. Record actual operand layout and bytes, local-memory use, matrix instructions, full dependency-path time, QK scores/order, FP32 online state/output, logits and model task metrics, plus fault and 262144-context bounds results. Compare to the actual SGLang/vLLM model path if one can be made to execute this same sparse component; otherwise label the reference gap. Do not treat the 39K model comparison or source matrix dimensions as an INT8 speed result.
