## Findings

### 1. Selection, prefix admission, allocation, and lifetime wiring are internally consistent

`Prefill::carve` parses `native16::requested`, `qsa::requested`, and `qsa::attention_math` at initialization (`src/prefill/prefill.cpp:970-979`), so an unknown math string throws before the first model request. The route is long-prefill-only: `Prefill::run` enters `run_layer_major` only with `STRATA_PREFILL_LAYER_MAJOR=1` and `n > m.T` (`src/prefill/layer_major.inc:3-29`). A short request remains on `run_impl`; `native16_active` is false there, so the new typed subgroup branch is not reachable on short input.

For long requests, the subgroup value is included in `qsa_prefix_on` (`layer_major.inc:57-67`), and prefix storage is reserved cumulatively with the expert cache before model work (`231-249`). The request/session bounds are checked first (`105-115`); the scratch layout allocates both BF16 tensors plus per-head row flags, and assigns the three pointers at `429-437`. QSA16's mode, mappings, resident INT8 pools, tables, and per-session typed-QSA input/output spans are validated before the layer loop (`174-208`). The required pairing is guarded before model work: non-`existing` math requires `STRATA_SYCL_PREFILL_NATIVE16_QSA=1` (`57-60`), and QSA16 requires native16 BF16 (`66-67`).

The production call is selected before the existing tilepack/optimized/serial branches (`src/prefill/prefill.cpp:2398`, `2644-2671`); a false return is an error with **no fallback submitted** (`2670-2671`). Thus an unsupported subgroup route cannot silently run another arithmetic path. Startup logging now identifies active logical-prefix storage, pitch 33, row-major operands, and `softmax=subgroup` (`layer_major.inc:439-448`). That line records configured selection; it is not itself evidence that a kernel dispatched, though later dispatch failure is surfaced.

The integration reuses the qualified arithmetic in the same template as existing variants: the new export instantiates `prefix_batch_impl<Cells + 1, false, true>` (`qsa_bf16_prefix.cpp:348-353`), selecting score pitch 33, row-major operands, and subgroup softmax. The inserted `if constexpr (SubgroupSoftmax)` body at `234-264` matches the private candidate's subgroup body; the serial body remains the `else` branch. Its row assembly, invalid/missing-row handling and padded-head work are shared with the original kernel body, not separately rewritten here. The prior R980 review and component receipt remain the applicable evidence for those math and fixture gates.

The source has a distinct template specialization from the `SubgroupSoftmax=false` serial exports, so the source-level kernel closure is specialization-specific. Khronos SYCL 2020 revision 12 requires template parameters used by a kernel to be represented in its kernel name; see §5.2, [Naming of kernels](https://registry.khronos.org/SYCL/specs/sycl-2020/html/sycl-2020.html). This is a source-level inference only: the integration manifest says it has not been compiled, and there is no linked-binary/kernel-ID evidence yet.

The queue/lifetime handoff is consistent: `queue_for` requires an in-order queue (`include/strata/sycl/launch.hpp:47-57`); pack and attention are submitted to that same explicit queue; `finish` is intentionally nonblocking for a non-null stream (`60-63`). The outer layer-major lease's checked drain waits that stream before owners are released (`layer_major.inc:399-413, 702-714`); the SYCL compatibility implementation maps `cudaStreamSynchronize` to `wait_and_throw` (`src/sycl/compat.cpp:332-338`). `PrefixBorrow` restores the prior scratch view after the lease drain and before storage destruction (`layer_major.inc:364-370`). No integration-specific lifetime or barrier defect was found by static inspection.

The new CMake target is wired correctly: `sycl_qsa_bf16_prefix_subgroup_test` links `strata_kernels`, uses the existing `tests/sycl/qsa_bf16_prefix.cpp` fixture, and maps its `qsa_bf16_prefix_batch` call to `qsa_bf16_prefix_subgroup_batch` (`cmake/sycl_backend.cmake:458-463`; fixture call at `tests/sycl/qsa_bf16_prefix.cpp:108-112`). Like its neighboring QSA targets, it is `EXCLUDE_FROM_ALL`, so it needs an explicit target build. It tests the component export; it does not exercise the environment parser, production route selection, or prefix allocation through `run_layer_major`.

### 2. Follow-through: preflight checks the wrong matrix element type for the new route

There is one concrete admission gap on devices other than the already component-qualified B570. Before model work, `run_layer_major` calls `qsa_prompt_attn_bf16_validate` (`layer_major.inc:203-206`). That shared validator's `prompt_bf16_matrix_available` check (`src/kernels/sycl/prompt_attention.cpp:551-575, 793-829`) requires SG16 and Intel matrix support, but enumerates **FP16** A/B matrix combinations at `564-570`. It does not establish the BF16 A/B combination required by this integrated QSA prefix kernel.

The route-specific check exists, but only inside the subgroup entry after model execution has started: `prefix_batch_impl` checks `matrix_available(..., LocalPayload<ScoreStride>)` at `qsa_bf16_prefix.cpp:83-85`, and that helper checks the BF16 matrix tuple at `48-65`. A device with FP16 matrix support but without the required BF16 tuple can therefore pass the pre-model typed-QSA validator, execute earlier layer/chunk work, and then return false at the subgroup attention call; the caller stops the request without fallback. This is a code-derived reachable-device case, not an observed B570 failure. The private candidate's successful B570 component run is counterevidence for the current specified machine only, not a general preflight proof.

Before broader use, make the pre-model route gate check the same BF16 tuple and local-memory requirement as the selected prefix kernel (or provide an equivalent route-specific capability query). Preserve the current fail-without-fallback behavior. Main should verify that gate with the candidate build and confirm it rejects an unsupported capability before any layer work.
