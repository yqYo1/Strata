## Correction to V1 and source finding

V1's `kv_resident==0` admission and terminal `state.kv_mode==0` guard exclude the actual long-model configuration `--kv-resident32768`. V2 removes that artificial limitation. It permits a valid requested target residency before preset transformations, then inspects the actual SessionState layout after prefill. Actual target modes0 and1 are supported; target ring mode2 is rejected. The current --native mapping and explicit --suffix-draft0 are retained, so the default suffix policy cannot silently expand spec4 into6. Ordinary output/API semantics and the physical262144 limit are unchanged.

No missing ordinary Prefill→Verifier streamed-KV seam was found. An initial search for `kv_mode` inside verify.cpp alone would miss it: the actual verifier calls the shared `qsa_kv_resolve` helper. The following existing dependency path already implements the required lifecycle; this proposal reuses it without adding a second full KV allocation or a new diagnostic-only attention algorithm.

1. `src/core/layer.cpp::kv_plan` uses requested resident cells and the ordinary minimum20480; when the rounded slot count is below logical pages it creates mode1, authoritative mapped host pools, a partial GPU pool and fixed residency map. At512 context, requesting32768 resident cells legitimately yields actual mode0, not a tiny streamed test. At262144 context/request32768 the intended mode1 has8192 physical pages (32768 cells) versus65536 logical pages. These are planning/layout values, not measured payload correctness.
2. `src/prefill/prefill.cpp::take_stage` and the QSA chunk branch use the existing one-layer staging pool. `kv_stage_from_host` brings all already conditioned pages[0,p0) into the staging identity layout. Each ordinary chunk `kv_append`/`kv_append_q4` writes new K/V into `st.host`, into staging, and into GPU slots only where the residency map already names them. Prefix prefill remains[0,N−1). Completion/callback and existing checked drain boundaries retire those host writes before the staging workspace is reset. V2 adds no staging/full-KV owner.
3. `src/core/verify.cpp::record_window` computes terminal K/V and calls `kv_append_step`/q8/q4 with `&st.host`. Therefore the terminal row is written to authoritative host backing even if its page is currently nonresident. Indexer append, scores and topk then select the actual needed prior cells. The graph invokes `qsa_kv_resolve(st,...)` after selection and before `qsa_decode_attn_batch`.
4. `src/core/layer.cpp::qsa_kv_resolve` dispatches mode1 to `kv_stream_resolve`. `src/kernels/sycl/kv_stream.cpp` claims selected missing logical blocks, assigns physical slots, publishes forward/reverse maps, then copies their K/V planes from authoritative host into those slots in the same ordered queue. The later attention reads through that page table. Thus prior-state availability comes from the completed Prefill host writes and the actual selection-driven resolver, not from requiring all262144 cells to be simultaneously resident.
5. Ordinary verifier run completes its compute/copy streams. `commit(1)` commits GDN recurrence/conv, indexer tail/pool and PLE history/predecessors; `wait_commit` drains asynchronous commit. No separate target KV spill is missing: ordinary append always writes authoritative host backing, and resident slots are also updated when present. The comment in kv_stream.hpp explicitly establishes why no invalidation/spill is needed after rejected drafts. Here T1 is fully committed and no later draft/position is attempted.

The diagnostic still guards the exact final prompt ID/position/T1 before ver.run, snapshots first_window before its ordinary mutation, blocks adaptation thread/resource startup, and exits before produced.push/draft/p advancement. It reaches existing manual cleanup rather than an early return0. Prediction computation remains the real verifier path.

## Bounded actual observations

The new observer changes neither graphs nor maps/pools. It allocates no GPU memory and no extra full KV pool. After checked prefill main-queue completion it reads actual per-QSA mode, context, pages, slots, format and host-backing presence. For mode1 it validates map/table ownership and records the existing device control counters with bounded64B reads. Fresh standalone Prefill uses staging rather than decode resolves, so calls/misses/lookups must initially be0 and overflow0; unexpected reused state is rejected, never reset to make the diagnostic pass.

After the real terminal run/commit/wait and checked main/MTP completion, each mode1 layer must show exactly one real resolver call and no overflow, with actual placed misses. It reads the finite miss-block list (bounded by physical slots<65536, at most256KiB metadata), selects an actual missed block strictly before the terminal page, reads its miss slot and forward/reverse map entries, and verifies their agreement. It then copies the exact packed K/V planes of that one prior block from authoritative backing and the normal resolver's GPU slot and compares bytes. For current geometry that is8192B F16,4224B INT8 (including scales), or2304B Q4 per layer, using two reusable8192B host buffers. No full-context tensor capture is retained. A sample hash, block/slot and byte count are reported only after actual comparison succeeds.

This is evidence of one selected prior block's availability and host/slot coherence per QSA layer, not all selected payloads, every layer's logical position or all-context numerical correctness. No invented success counter is substituted for the real map ctl words. The baseline/terminal device resolver call counts, misses/lookups/overflow are separate from host geometry. The existing twelve observed indexer block-origin words and host PLE token predecessors remain separate observations. GDN is still geometry plus run/commit completion with no per-layer position counter. Attention status is not falsely claimed as observed.

Mode0 records actual slots/format/context without pretending to have a streamed resolve or host/slot payload comparison. A small context or STRATA_KV_MAIN_OFF can leave a nonzero requested residency in mode0; the receipt explicitly exposes that. The independent checker requires expected actual mode/resident cells, so resident fallback cannot qualify the requested physical streamed gate. The actual long gate requires input262144/context262144/requested32768, twelve actual mode1 layers with resident_cells32768, and real resolver/probe observations. No context262145 or hidden full-KV replacement is introduced.

Receipt schema2 adds requested residency, actual per-layer mode/resident/context/format, real map counters and the bounded selected-prior-block observation to V1's exact input fingerprint/chunk coverage/terminal/no-output fields. MTP callback coverage and attached head/native publication observations remain separate from target KV state. Ordinary MTP draft KV can be mode2; it is not confused with target mode1. New explicit competing-diagnostic rejects also cover STRATA_SYCL_VERIFY_LOGITS and STRATA_DBG_NAN.
