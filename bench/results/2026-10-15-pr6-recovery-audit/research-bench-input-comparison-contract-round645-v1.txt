# R645 — benchmark request identity and agent feedback audit

Date: 2026-10-15 JST
Scope: read-only static review of `bench-fixed-workload-v1`, `bench-request-identity-v1`, `recover_bench_nonce_v1.py`, `qualify_bench_input_tools_v1.py`, `run_matched_iq_on_v2.py`, and current `tools/strata_bench.py`, reconciled with the research index through R644, Main review R641–644, R642 workload calibration and R614 fail-stop review. Report only; no test/build/GPU/process/cleanup/Git operation, no candidate/product edit, no active job 16956 or raw output inspection. No external benchmark docs were needed for the source-contract question.

## Finding

The fixed-ID change itself preserves the original request-generation code. The proposal's host AST gate admits only `Suite.__init__` and the reviewed provenance/CLI/comparison changes; existing request and timed methods remain byte-for-byte AST-equal. Recovering the old timestamp nonce by matching both actual calibration request hashes is sound provenance for the seconds-based nonce. But the later whole-journal comparator is too strict for the natural agent workload: it requires every exact request body to match, including turns that contain assistant answers produced by the model. Consequently a valid model-output difference can become `REQUEST_INPUTS_MISMATCH`, which blocks the entire ON suite before performance qualification. This operationally makes exact generated-answer/history equality a prerequisite even though the benchmark does not claim answer-quality qualification.

**Decision:** Keep strict actual-body equality for fixed-input, independent requests and keep the full agent conversation as a natural-feedback observation. Separate the latter's status from exact-input pairing. A small comparator/runner adjustment is necessary if the plan is to keep agent turns in the same suite and allow model outputs to differ without invalidating unrelated matched workloads. Do not call the overall pair input-identical when agent histories diverge; record an explicit mixed status and exclude agent speed from the exact-input paired comparison. The agent measurements can remain in both result sets as exploratory workload behavior, together with each turn's prompt/completion counts, output hashes and timing.

## Evidence by question

### 1. Old nonce and timed request semantics

Current `Suite.__init__` chooses `str(int(time.time()))` once (`tools/strata_bench.py:375-386`). `tag()` appends that nonce (`:487-488`); calibration and fresh prompts use it in the prompt body (`:494-508`), as do chat, client and agent session prefixes. The fixed-ID diff replaces only that nonce choice when `--workload-id` is supplied and records it; it does not change those request builders or `Suite.request` (`bench-fixed-workload-v1/source.diff`, `:382-393,487-488,494-543`). The proposal adds the ID after legacy positional parameters and validates it during CLI parse, before server work. Therefore passing the recovered original digits reconstructs the old tag value rather than redefining the workload.

`recover_bench_nonce_v1.py` requires the closed historical receipt, child/session retirement, pinned benchmark sources, valid complete request journal, and exactly two calibration start hashes with runs 200/800, max_tokens 1 and thinking false. It searches only integer seconds within the recorded command's start/finish interval (with one-second margins) and accepts exactly one nonce matching both reconstructed request bodies. This proves the nonce used in those two calibration bodies, not by itself every subsequent body. The later comparator supplies that missing whole-journal gate. The new fixed ID is passed to the same constructor and request methods; fixed ID alone is not used as proof of body equality.

`run_matched_iq_on_v2.py` further requires that the only changed benchmark source is `tools/strata_bench.py`, that its reviewed fixed ID equals the recovered nonce, and that the closed OFF journal hash still matches the historical proof. The timed endpoint/body parameters, ordering and source remain paired; exact request hashes are then compared separately. This structure is sound for all deterministic request phases that do not include prior generated text.

### 2. Agent history makes full wire equality answer-dependent

`agent_session()` constructs a new system/user/file sequence for each turn, then appends the just-produced model text to the history (`tools/strata_bench.py:586-597`). The next call passes that complete `msgs` list to `Suite.request`; the journal hashes the serialized full `chat_body` (`:389-412`). Thus the turn-1 request depends on the previous assistant reply (and subsequent turns on the accumulated replies). With thinking enabled, reasoning content is also sent back as `reasoning_content`; with the default thinking-off setting, normal assistant content still enters history. Identical system prompt, tool schema, files, run/turn keys, and generation settings do not imply identical request hashes after any output differs.

The comparator has no phase exception. It matches each ordered `start` row on `(phase, run, turn, max_tokens, thinking, request_sha256)` (`bench-request-identity-v1/compare_requests.py:21,67-82,100-107`) and claims every journaled input, including every agent turn (README). `run_matched_iq_on_v2.py` runs it over the entire OFF and ON journals and requires `inputs_match` before setting `input_match_qualified` or `passed` (`:157-163`). The comparator's documented complete sequence includes warm-up, calibration, chat, prompts, all agent turns and long-generation phases.

Therefore, if an ON result changes an assistant answer, the following agent request hash differs even if the new code is correct and the fixed file/tool/task input is identical. The comparison then fails the whole paired suite. That is a valid strict statement that *the full wire bodies were not identical*; it is not evidence of a correctness/quality failure. The current record keeps `quality_qualified=false`, and the suite describes itself as a speed suite (current `tools/strata_bench.py:1116-1119`); no answer-quality evaluator exists here. Still, because exact body match gates whole-run `passed`, input comparability and exact output equality are operationally conflated for the agent phase.

### 3. Minimal separation that retains comparability and natural agent behavior

Do not remove the agent session or feed prerecorded replies into it. Preserve the natural conversation and report its normal completion, cache-reuse, token, output-hash and timing observations for each arm. Keep current whole-body equality for deterministic phases that are intended to have identical input bodies.

For a future minimal change, make the comparator/runner distinguish:

- **Exact-input pair:** ordered non-agent request keys, generation parameters and actual body hashes must match. A mismatch here remains a blocking input-pair FAIL.
- **Agent feedback cohort:** run/turn order, model settings, tool schema, fixed system text and current file/task payload should match, but assistant-history segments are allowed to differ. Record the per-turn full body hashes and per-turn assistant history/output hashes as observed divergence. This cohort is *not* exact-input paired and must not be included in a strict paired speed statistic.

The current journals contain only full body digests, not a decomposition into static user/tool input and generated assistant history. Therefore that distinction cannot be reliably reconstructed from existing journals. Minimal prospective instrumentation is to journal a second structured identity/digest for agent turns: exact invariant fields plus the newly introduced fixed user/file payload, alongside the existing full request hash. Do not retain full message bodies. Then `run_matched_iq_on_v2` can require exact pair equality for fixed phases, require the same agent task/file/protocol envelope, preserve each arm's natural history and outputs, and report agent results as exploratory/feedback-sensitive. Continue to leave `quality_qualified=false` until an independently specified quality gate is run.

A still smaller operational alternative is to exclude agent phases from the blocking exact-body comparator and label them explicitly nonpaired; this preserves natural behavior but gives weaker proof that per-turn fixed user content matched. The structured decomposition is preferable if reviewer confidence in the agent cohort matters. In either case, no actual OFF/ON result may be reclassified retrospectively; only future journals get the extra identity fields.

## Blocking / nonblocking / unresolved

| Status | Finding |
|---|---|
| **Blocking for the proposed whole-suite input-match gate** | Exact `request_sha256` comparison for every agent turn rejects output-dependent feedback bodies when model answers differ, blocking all matched-suite qualification. This does not mean the outputs failed quality. Split strict deterministic-input pairing from agent feedback results before interpreting such a failure. |
| **Nonblocking for current recipe if `--clients` is absent** | The ordinary concurrent `clients` worker writes journal `start` rows without the request-body hash/max_tokens/thinking fields required by the comparator (`strata_bench.py:656-676` vs comparator `:67-76`). A run containing `--clients` will fail validation independently of agent output. The matched-v2 recipe must keep this phase absent or add equivalent body identity. No reviewed receipt was inspected to claim whether it was present in historical OFF. |
| **Nonblocking** | Two exact calibration hashes identify the old timestamp nonce, while the final full journal comparison validates all remaining request bodies. Search time range and uniqueness requirements are bounded and sensible. |
| **Not a quality gate** | Benchmark result schema and long-generation workload explicitly set `quality_qualified=false`; output hashes are recorded but not scored. Input hash mismatch must not be relabeled as model quality failure or numerical correctness failure. |
| **Unresolved / not measured** | No test or run here establishes that a future IQ ON answer changes. The report identifies a possible blocking condition from source semantics, not an observed output mismatch. No paired result, speed, answer quality, full-context or RESTORE conclusion is made. |
