# IQ timing v3: source-only diagnostic proposal

Status: NOT_BUILT / NOT_TESTED / NOT_RUN. Main owns build, controller, tests, GPU and Git. The v2 source and dependencies are unchanged. timing.cpp is a full standalone sibling replacement; its existing relative fixture include still resolves. No product adoption or performance qualification.

Set STRATA_IQ_TIMING_PROGRESS=1 in the exact native child environment before exec. Missing or any other value is OFF. This variable is read once at main entry, before runtime/queue initialization; no setenv/unsetenv exists. Default OFF emits no progress, reads no diagnostic clocks and introduces no waits. Runtime-disabled marker branches remain; binary-level zero overhead is not claimed. Diagnostic ON timing samples are ineligible for speed comparison: trial submitted logging lies between host-submit and completion timestamps. Original stdout schema/results and failure/exit handling are retained.

Progress lines start iq-progress-v3 and carry contiguous sequence, steady_clock nanoseconds, phase, edge and index. Each line is flushed to stderr. At most 16384 bytes are attempted; cap or I/O failure disables tracing without replacing the original native outcome. Existing owner stderr budget remains necessary for exception/shim/library output. A normal maximum-30-trial run has fewer than 180 fixed-size lines (actual formatted lines are well below 192 bytes). Main must flag a missing expected terminal marker or sequence gap as incomplete. No per-element or per-repeat logs.

Coverage: main entry; Runtime constructor; queue construction (which owns implicit context/provider initialization); every Guard device allocation plus host staging construction; host initialization/oracle; every blocking upload; reference GEMM submit and existing drain; cold candidate dequant and GEMM submissions; verification drain/download/check scope; aggregate warmup; each trial pre-drain/submit/completion; retirement. submitted marks host API return, not device completion. Candidate completion is the existing verify drain, not a new wait. No extra drain is inserted to distinguish device dequant versus GEMM; the owned stack and API-boundary markers provide that distinction as far as host evidence permits. A hang before main has no progress marker; the optional preloaded constructor can supply its grant marker.

Optional attachment: reuse the already CPU-qualified native-only LD_PRELOAD shim pinned in pins.json / the host receipt, not a new ptracer implementation. The shim grants PR_SET_PTRACER to getppid only and verifies parent stability; never PR_SET_PTRACER_ANY. Main must verify the actually qualified binary hash against its host qualification receipt and keep the debugger environment free of native LD_PRELOAD. Do not add a preload to clean timing.

Original evidence remains FAIL: wide-v2 case031, OFF/type23/GU/ne16/GEMM cold, PID3767352, 180-second hang, empty stdout/stderr, owner SIGTERM exit -15 and reaped. First 31 processes completed normally; xe CCS reset near watchdog; no devcoredump was reported. These supplied observations do not establish a causal driver diagnosis and are not repaired by this proposal.
