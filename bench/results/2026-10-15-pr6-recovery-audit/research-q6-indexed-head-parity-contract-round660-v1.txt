# Q6_K indexed-head bitwise parity contract (R660)

Read-only audit of the current root SYCL `native_mmvq` implementation and `gather_rows`. Prior context checked: public research index, R657 and corrected R658 v2. The in-progress proposal was not read. Private B, live-ON state, and environment were not inspected. No build, test, GPU run, Python compilation, process control, Git operation, cleanup, source edit, or existing report/index edit was performed.

## Scope and parity target

The existing path in `MtpDrafter::bind` uploads `draft_vocab.bin` indices into `dvocab_`, gathers exactly those packed head rows from the full native head into `dhead_`, then full decode calls `native_mmvq(head_type, dhead_, xq, head_logits_, n_embd, n_dvocab, T=1, queue)`. For Q6_K only, the proposed direct path may instead give the existing full packed weight pointer plus `dvocab_` and compute compact output rows directly. To be bitwise comparable, it must emit output row `j` from full packed weight row `dvocab[j]` into compact logit row `j`, for the same Q8_1 activation, with the same selected output width and unchanged Q6_K arithmetic/reduction. Do not compute all full-vocabulary logits and then gather: the comparison target is the old gathered matrix's `n_dvocab`-row launch, including its launch geometry.

This is a Q6_K-only dispatch option. Existing Q6_K byte interpretation, Q8_1 quantization, Q6 dot product, float operation order, reduction, sampler, and every other format remain unchanged. Q6_K type ID 14 already dispatches through `Q6KTraits`; it has no ESIMD-specialized branch. The initial qualification should be default-off and limited to the Q6_K draft head; do not infer support for Q4_K, IQ, or other native formats from the shared template.

## Layout and actual launch geometry

The on-disk Q6_K row remains ordinary row-major GGUF blocks: one `Q6KBlock` is 210 bytes for 256 weights, with `ql` at byte 0, `qh` at 128, 16 signed scales at 192, and FP16 `d` at 208. `native_mmvq_weight_bytes(14, n_in, n_rows)` is `(n_rows * (n_in/256) * 210)` after checked dimension arithmetic. `n_in` must be a positive multiple of 256; the real MTP head activation width is `N = n_embd` and the actual full forward is `T = 1` (`record_forward` rejects full `T != 1`). For `n_in=2560`, a row is 10 blocks = 2,100 bytes. Weight addressing must use byte offset `source_id * row_bytes`; row starts are guaranteed 2-byte Q6 block aligned, while the base pointer must retain the public API's 4-byte alignment requirement. Do not round row starts to four bytes or add padding that is absent from the existing gathered `dhead_`.

The native kernel writes columns contiguously as `y + col*n_out + output_row`; activation column `c` starts at `x + c*n_in`, represented as Q8_1 blocks at `c*(n_in/32)`. The index applies to output rows and is shared by all columns. For the actual MTP call, `ncols=T=1`, so output is a compact `n_dvocab`-float row. `head_logits_` is allocated for `max_t*n_vocab`, but the sampler is passed `nv=n_dvocab` and reads only the compact prefix. The indexed path must preserve that exact compact output layout and must not change sampler indices: `sample_tokens` returns a compact position and `map_ids` converts it through `dvocab_` afterward (except coupled mode, which receives the mapping directly).

For the actual `n_in=2560`, Q6_K has `DIV=256`, `T=32`, `KBY=8`, `BPI=4`; `n_in/DIV=10`, so normal exact dispatch selects `launch<Q6KTraits, ROWS=1, NW=4>`. Its work-group is 128 work-items with required subgroup size 32. Each of four warps accumulates its assigned Q6 blocks in the same `kbx` loop; warp 0 adds warp partials in ascending warp order, then performs XOR reductions at offsets 16, 8, 4, 2, 1. The indexed change should alter only the row used to form the Q6 block pointer and the compact destination row. Keep `F::load`, `F::apply`, each FP32 `+=`, the partial-store layout, ascending partial merge, subgroup XOR order, and output store condition identical. A subgroup size of 16 is not the current contract. The code's `[[sycl::reqd_sub_group_size(32)]]` and 32-lane XOR sequence are explicit.

`multi_exact` defaults true. With true, every multi-column lane/row uses the same single-column layout and arithmetic; for the actual `ncols=1`, the flag does not alter dispatch. If false and `ncols>1`, generic dispatch changes to `ROWS=2,NW=4` when `ncols<=4`, and `ROWS=2,NW=2` otherwise. Do not describe those as 16-lane subgroups: `launch` still requires 32, and NW is the number of 32-lane warps in the work-group. Preserve the same flag value and current Q6 dispatch for both old and indexed arms in any multi-column parity check; never change global `multi_exact` mid-graph or mid-process as an experiment arm.

## Index semantics and safety contract

The old `gather_rows` copies bytes in `ids[j]` order, so nonmonotonic ordering and duplicate IDs are meaningful and preserved. For a negative ID it writes an all-zero packed row; this is the defined behavior of that helper. A direct kernel must either preserve that exact zero-row behavior or the public API must reject negative IDs before launch and the parity domain must explicitly be valid nonnegative vocabulary IDs. A positive ID `>= n_vocab` currently has no defined safe behavior: `gather_rows` performs an out-of-range read. The new path must not silently reproduce that unsafe behavior. Since `dvocab_` is device memory and the launch is asynchronous/graph-compatible, a host wrapper cannot validate its contents by dereferencing the device pointer. Validate the decoded subset on the host before upload/publication (including length, signedness, every ID `< n_vocab`, and exact order/duplicates), or add a checked device-status protocol that is completed before use; do not add an implicit host wait to the head kernel.

The new wrapper must validate the entire original full-weight span for `(n_vocab, n_in, Q6_K)` rather than sizing it as if only `n_dvocab` rows existed. Also validate `n_selected>0`, `n_vocab>0`, `n_in%256==0`, checked `row_bytes*n_vocab`, checked `4*n_selected` index span, Q8_1 activation span for `n_in*ncols`, and compact output span for `n_selected*ncols`. Retain 4-byte alignment for base pointers/indices/output and at least Q6 block alignment for byte-offset rows. Reject integer overflow before pointer arithmetic. Preserve the kernel API's disjoint-span rule: writable compact output cannot overlap the full weights, index map, or activations; the ID array must not alias a writable destination. No unchecked reinterpretation of an `int32_t` ID as an unsigned row offset.

The kernel entry should retain the existing native MMVQ contract: caller-owned device spans, explicit non-null in-order queue, enqueue work on that queue, no allocation, host copy, synchronize, event wait, or device-to-host metadata inspection in the compute routine. The existing generic `native_mmvq` requires a non-null stream and submits asynchronously. `gather_rows` permits null and therefore completes through the runtime's `finish` behavior; the current MTP bind also explicitly synchronizes after materializing the subset. The optimized path may remove that materialization/synchronization only if the caller's allocation and graph lifetime contract is reviewed independently. If captured, the full weights and `dvocab_` pointers and their contents must remain valid and immutable for replay; do not record a transient host pointer or late-reallocated map. Queue ordering must make activation quantization precede the indexed MMVQ and sampling follow it, without adding a wait inside the kernel.

## Required GPU parity fixture

Use a deterministic small packed Q6_K weight matrix and the same Q8_1 activation bytes for both arms. Arm A is the exact current sequence: `gather_rows(full_weights, row_bytes, ids, n_selected, dhead)` followed by current generic `native_mmvq(14, dhead, xq, compact_logits, n_in, n_selected, ncols, q)`. Arm B is the Q6_K-only full-weight indexed launch with those same inputs and output shape. Compare every output bitwise, not only argmax or tolerance. Do not regenerate or requantize activations independently between arms.

Minimum cases should include the actual `n_in=2560`, plus a one-block `n_in=256` boundary; selected counts 1, 3, and 5 to exercise different output tails; full row counts that are not divisible by four; an index list with first/last valid rows, a nonmonotonic order, and duplicates (for example `[last, 0, middle, middle, 1]`); and a distinct activation. For a multi-column API contract check, test 2 and 8 columns with distinct activations under the same `multi_exact` setting for both arms, but keep actual MTP qualification anchored to T=1. Include negative IDs to assert either old zero-row parity or documented prelaunch rejection, and positive out-of-range IDs to assert safe rejection before any row read. Check output column offsets and compact dimensions, not only values.

Capture/replay parity is a separate required case if the production MTP full-forward graph captures this head call. Capture the new dispatch with stable full-weight and ID allocations, replay more than once, and compare to the gathered baseline. Assert no host wait is introduced in the launch wrapper. Also run the existing full MTP/reference/token quality gates after bitwise head parity; exact head logits alone do not establish end-to-end equivalence if call ordering, mapping, or graph capture differs.
