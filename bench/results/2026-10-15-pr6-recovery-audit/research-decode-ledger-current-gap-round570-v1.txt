`NT` is overloaded unless named precisely: ledger `T` is verifier window rows; each `ExpertJobMulti::nt` is rows coalesced for one distinct CPU expert; each `pool task` is a flattened output-row range. The proposal's `rows[l][T][owner][job_nt]` counts owner groups and route entries by actual job nt, not CPU tasks. For the minimal coverage, need actual T histogram, per-layer callback count and row sum, job-nt histogram, owner-group/entry totals, plus format pair by layer; no per-expert id trace.

## Existing proposal: retain and trim

Keep these pieces when Main integrates:

- the two exact opt-in environment strings (`STRATA_DECODE_ROUTE_LEDGER=1` and `STRATA_DECODE_SERVICE_CPU=1`), default OFF; request scope after prompt processing at existing d0; no clock, scan, dynamic state or output when off;
- MTP loaded, spec capacity 4, suffix 0, split OFF, one stage, native format, no peer/remote, Linux/SYCL and existing pool eligibility. The archived no-MTP/NT1 rejection is superseded. Coupled true/false can be eligible as separate labeled arms;
- W/R/D/A/C/E attempt/verified/commit/emission separation, per-layer actual callback/row checks, route/job/source-counter joins, worker slot one-writer lifecycle, pool completion/park ownership, and one close-only `complete` footer;
- CPU thread time around actual native GU, intermediate quantization and Down calls, separately for issuer and workers; preserve role and call denominators. Keep existing verifier wait/pool/host/commit, dispatcher plan/actq/jobs/run, pool GU/q/Down deltas, and draft wall as labeled overlapping spans. Add no queue marker, event, copy, callback, wait, trace loop or synchronization;
- final `wait_commit` outcome and close/fault/correctness/request identity from Main's separate run receipt. No receipt after abort/kill is incomplete/absent, not success.

Do not carry over the proposal's prompt-ID FNV scan as authority: it is noncryptographic, costs decode-boundary host work, and the retention policy already requires Main's external input SHA256. Do not claim the fixed state/output caps are compiled sizeof/RSS measurements. Do not retain 256KiB route text or all cross-bins solely for a CPU-vs-issue decision; aggregate to the coverage above with fixed bounded state/output. The proposal's `phase_ms` getter is the pool's existing run() counters; its native `run_phase` phases have no corresponding accumulated wait/repark deltas. Preserve this limitation and rely on service scopes/task counts plus phase-completion counts, never interpret zero `phase_ms` delta as zero native wait. Optional asynchronous retention/leak behavior for a pool call that aborts before park is not required for a successful short diagnostic; its exceptional lifetime must be reviewed before adopting the original scope unchanged.

R545's `L` layer waits are required before mapped output is consumed by CPU callbacks. The SYCL verifier uses event-sync at 1295-1300 and copy drains at 1376-1404. The diagnostic must preserve them. R555 separately records that graph/event-level per-node times are not currently exposed; do not treat nonexclusive `ms_wait`, `ms_pool`, `ms_host`, `ms_run`, service wall and CPU ns as mutually exclusive time slices. This receipt can show the CPU service volume and host-side spans present in one >=32K-context/100-300-token run; it cannot alone prove a numeric majority of decode critical path. Any conclusion must say “CPU service counters/wall spans point to …” until a clean uninstrumented paired performance test or non-perturbing device timeline establishes causality.
