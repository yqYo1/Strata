## Correction: head-scratch canary range

R1035 correctly observes that `scratch_guards=PASS` currently checks only the allocation's outer guards, not the head buffer's globally unused columns. Its proposed general check `[padded,panel)` is only correct when `padded <= panel`.

The buffer is `[queries*4, 8192]` with row stride 8192. Each tile writes columns `[0, min(8192, padded-first))`, then the next tile reuses that same buffer. Across all tiles, each row's set of columns ever written is `[0, min(padded,8192))`. Therefore the safe post-run canary check is only `[min(padded,8192),8192)`. If `padded >= 8192`, there are no globally unused columns to check. For a multi-tile case, last-tile columns `[last_columns,8192)` contain earlier-tile outputs and must not be expected to remain canaries. This is a fixture coverage gap, not evidence of a scorer overwrite. Either add the bounded suffix check or name the current result `head_scratch_outer_guards=PASS`.

The sampled score oracle is a reasonable prospective check for FP16-rounded operands with FP32 accumulation: it forms the reference after half conversion, samples 67 positions per query, and keeps the original-FP32 dead-key result separate.
