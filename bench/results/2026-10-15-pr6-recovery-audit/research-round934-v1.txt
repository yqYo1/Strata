## 1. The mergeable state

For a nonempty set of finite scores `x_i` and associated vectors `v_i`, retain a triple

`S = (m, l, a)`, where `m = max_i x_i`, `l = Σ exp(x_i - m)`, and `a = Σ exp(x_i - m) v_i`.

The normalized result is `a/l`; the log-sum-exp is `m + log(l)`. Given disjoint summaries `A=(mA,lA,aA)` and `B=(mB,lB,aB)`, compute

`m = max(mA,mB)`

`α = exp(mA-m)`, `β = exp(mB-m)`

`l = α lA + β lB`, `a = α aA + β aB`.

This follows by expressing both partial sums against the common maximum. In exact real arithmetic, the merge represents the union of the two sets. The operation is associative and commutative in exact arithmetic, so a serial fold, balanced tree, tile tree, or recursively reduced tree yields the same state. The pair `(m,l)` is sufficient for log-sum-exp/softmax normalization. For a weighted value, extend the state with `a`. This is the direct vector-valued extension of the parallel online-normalizer operator proved associative by Milakov and Gimelshein and the tile update used by FlashAttention [1,2].

A common serial recurrence initializes `(m,l,a)=(-∞,0,0)`. For a new tile with local state `(mt,lt,at)`, it applies the same merge and updates the running result. An implementation may store normalized `o=a/l` instead of `a`; then it must reconstruct the weighted numerator during the merge: `o = (α lA oA + β lB oB)/(α lA + β lB)`. FlashAttention uses this normalized output form while carrying the row maximum and normalizer. Keeping `a` unnormalized avoids a division at every merge; keeping `o` can bound the stored vector by the tile's value range. Neither representation removes the max/normalizer rescaling, and they round differently.

For weights `w_i ≥ 0` that do not need exponential stabilization, the simpler state is `(W,S)=(Σw_i,Σw_i v_i)`, merged by componentwise addition, with output `S/W`. A centered equivalent stores `(W,μ)` and merges with `W=WA+WB`, `μ=μA+(WB/W)(μB-μA)`. The latter can avoid forming a large raw `w*v` numerator, but still needs a defined zero-weight identity and safe weight totals. For weights spanning extreme magnitudes, use the log-scaled `(m,l,a)` form instead. Negative weights break the convex-average bound and can make `W` nearly cancel to zero; the log-sum-exp form assumes positive exponential weights and does not solve signed cancellation.

The log-scaled state is larger than the ordinary weighted-mean pair because it preserves enough information to rebase partials after the global maximum is known. It also performs exponentials during merges. That is the numerical price for handling a score range where direct `exp(x)` would overflow or underflow. For moderate, already bounded mask weights, adding local numerators and denominators is simpler and often better conditioned than routing through max/exponential machinery; do not pay for log-stability that the input contract does not need.

## 2. Dataflow alternatives

**Local one-pass / serial online state.** One work group owns a query or row, walks its key/value tiles, updates `(m,l,a)` in registers or local storage, and writes one output. It does not materialize the score matrix or per-tile vector summaries. The independent input tiles are streamed, but each row's recurrence has a dependency from one tile to the next. FlashAttention's original algorithm fuses score calculation, stable normalization, weighted value accumulation, and output in a CUDA kernel; it keeps only the current output plus row statistics rather than a copy per tile [2]. This is attractive when each work group already has enough local parallelism and query rows provide enough independent groups.

**Independent tile summaries plus merge.** Give each of `P` partitions of the key/cell dimension a work group. Each computes its own local stable summary and writes `(m,l,a)` (or `(m,l,o)`) to scratch. A later stage reads the `P` states and reduces them, then writes the normalized result. With `D` value components and FP32 scratch, the partial payload is roughly `4P(D+2)` bytes per row, before alignment or metadata; it adds a write and read of that payload. For `Q` rows the payload scales as `Q·P·(D+2)`. Splits must cover disjoint cells or the output double-counts them. This produces more grid-level parallelism when one row has too little work to occupy the device, but the number of CTAs increases with `P` and the merge has its own work.

The usual robust implementation has at least two launches: partition kernels and a final merge kernel. A hierarchical tree can merge small groups in one stage and then merge their states at the next, limiting a final work group's state fan-in; it adds launch boundaries and intermediate scratch. A single final group can consume all partials for small `P`, but large `P·D` raises register/local-memory pressure and serial work there. Cross-CTA atomics are not a drop-in replacement: when a late partition raises `m`, every accumulated normalizer and vector numerator must be rescaled consistently. An order-independent atomic max plus sum cannot repair earlier sums without additional protocol. A global barrier/grid synchronization or a multi-kernel boundary provides the needed phase ordering; the latter is more portable but costs launch latency.

**Two-pass stable reduction.** First determine the global row maximum; then recompute or reload scores and accumulate `exp(x-m)` and `exp(x-m)v`. It avoids per-partition vector outputs but requires a global maximum before the weighted pass. If score tiles are retained, scratch is proportional to score count; if not, the query-key score calculation is repeated. A separate max stage plus weighted-sum stage ordinarily needs a synchronization boundary. It can make sense when scores already exist, are cheap to reload, or scratch for vector partials dominates. The one-pass recurrence instead rescales old state whenever a new max arrives, which is what makes it possible to stream without knowing the final max.

There is a second crossover inside this option: if one work group can own the entire weighted pass, it needs only a row result after the max stage, but it serializes that pass. If the weighted pass is itself split across groups, each group can use ordinary `(l,a)` partial sums because `m` is fixed; those partials still need a final reduction, so the full design has an additional merge stage. The apparent “two pass” algorithm then has three global phases unless the implementation uses a valid global synchronization mechanism.

**Ordinary weighted-average tree.** For a video centroid, a tile can reduce `(Σw·x,Σw)` independently and the next level adds both fields; divide only once at the end. The NVIDIA GPU Gems 3 object-tracking chapter computes a masked image centroid from weighted pixel coordinates, records numerator and denominator components, and repeatedly downsamples on a GPU. It also documents the boundary correction required for non-power-of-two dimensions [4]. This is a concrete non-LLM graphics workload using associative weighted-average summaries; it is not a modern GPU performance comparison. Averaging partial means without weighting each by its actual denominator is incorrect when tile populations or mask mass differ.

## 3. Precision, rounding, and boundary behavior

Real-number associativity does not survive finite-precision arithmetic. A serial recurrence, left fold, balanced tree, and different partition counts round additions and exponential rescalings in different places. `max` over finite same-format scores is exact selection, but a tied maximum still makes both tied contributions count; choose neither arbitrarily. Each merge can introduce rounding in `exp`, `α·lA`, `β·lB`, and every component of `a`; the final division adds another rounding. Fused multiply-add choices, approximate exponent instructions, compiler reassociation, and flush-to-zero behavior can change results again. A fixed reduction tree can make results repeatable under fixed inputs/configuration; repeatability is not bitwise equivalence to the serial recurrence or a different backend.

For a mixed-precision implementation, keep score accumulation, maximum, exponentials, normalizer, and weighted accumulator in the precision required by the reached reference contract. Input Q/K or values may be stored in BF16/FP16 while dot products and reductions accumulate in FP32, but that is a candidate contract to verify, not something implied by the paper or a source flag. FP16 partial-state storage narrows dynamic range; BF16 has a wider exponent range but fewer significand bits. Rounding local `l`/`a` before global merge can lose low-mass partitions or perturb their relative weight. Casting only the final output to a 16-bit activation is a different boundary from writing every partition state in 16-bit. For a bounded ordinary mean, wide accumulation plus final division is often adequate; for signed weighted sums, cancellation requires more care. No universal BF16-versus-FP16 choice follows from byte size.

Use `(−∞,0,0)` as the real-arithmetic identity, but guard it explicitly: naïvely evaluating `−∞−(−∞)` for two empty partitions produces NaN. Empty partitions should pass through the nonempty state; if all partitions are empty/all scores are masked, define the behavior before division according to the calling contract. Treat masked or padded score lanes as invalid/`−∞` and ensure padded weights are zero; a padded zero score can incorrectly become the maximum. Tail partitions must use actual element counts or zero weights, not average partial means equally. Positive infinity also makes `∞−∞` undefined and needs a specified path or a finite-score precondition. NaN propagation/ignore rules must be consistent across local and final reductions. Ordinary weighted averages require `W=0` handling; for masked-centroid style inputs an empty mask has no mathematical centroid and needs an explicit fallback.

## 4. Costs and crossover evidence

The merge buys concurrency by turning one long dependency chain per row into `P` independent chains, but it also emits `P` vector summaries and introduces a global phase boundary. As a rough state-traffic estimate, FP32 scratch for one row is `4P(D+2)` bytes written and the same amount read for the merge; normalized-output partials have similar size. If the reduction is small or has many rows/queries already, added scratch and launch cost can exceed the saved serial dependency. If `D` is large, vector-state traffic may outweigh the additional parallel work. If `P` is large, a single final group may spill or become the new serial bottleneck, motivating another tree level. If `P=1`, the split machinery is pure overhead.

Splitting keys can also reduce reuse: each partition reloads query and selector metadata, and a key/value tile previously consumed once by a fused owner may be revisited or lose cache reuse. Conversely, splitting disjoint key ranges need not duplicate key/value bytes in aggregate, but it can change coalescing and scheduling. Total-path accounting must include scratch allocation/lifetime, initialization, writes, reads, merge, launches, and any changed gathers or score recomputation. An in-kernel group reduction avoids a device-wide launch but remains confined to that group; it cannot be assumed to synchronize independent groups. Cooperative reductions and atomics have their own capacity, ordering, and contention constraints.

Crossover evidence should therefore compare: rows and partitions available to schedule; work and value dimension per row; local state footprint/occupancy; partial-state bytes and merge time; input/gather reuse; and full dependency wall time including the added synchronization. A microbenchmark of only the final reduction is not enough. A single favorable run or generic occupancy intuition does not establish the split as useful.

## 5. Positive and negative precedent

Milakov and Gimelshein provide both the serial and parallel online-normalizer formulation. Their `(m,d)` combine is explicitly associative/commutative, and their paper reports a CUDA/CUB implementation on NVIDIA Tesla V100 PCIe 16 GB in FP32. For standalone softmax, they reported up to 1.3× over their safe three-pass implementation at large vector lengths and up to 1.15× in the small-batch case; their own discussion says small batches remain latency-limited and the gains are hardware/workload-specific [1]. It is evidence that a stable pair admits parallel reduction and that avoiding extra passes can matter, not evidence for this model's weighted-vector state, SYCL, or Intel hardware.

FlashAttention establishes the opposing dataflow point: a fused owner can process tiles online and keep only one output vector and row statistics, avoiding an `O(PD)` partial-output array and repeated HBM round trips [2]. FlashAttention-2 increases parallelism across sequence row blocks when long sequences and small batch/head counts leave too few thread blocks, while its paper describes a split-K warp mapping that requires shared-memory writes, synchronization, and an intermediate sum; it switches to splitting query rows across warps to avoid that communication [3]. Those are CUDA/A100/attention results and different dimensions from selected-cell QSA. They support both the possibility of a parallelism gain and the counterexample where splitting the reduction creates costly communication. They do not show that a cross-CTA stable-state split wins for QSA.

## 6. Conditional relevance to selected-cell QSA

A mergeable state is mathematically applicable if each selected-cell subset contributes a score and associated value vector under the same mask, scale, and normalization semantics. The candidate design is to partition the already selected, disjoint cell set; calculate one local `(m,l,a)` per query/partition; merge in a fixed tree; then divide once. For ragged selection, empty and tail partitions need the explicit rules above. If the selection metadata or per-query cell set changes, partition bounds and duplicate suppression must be proven before timing.

Evidence to consider this for Strata would begin with Main-owned evidence, not this survey: (1) identify the actually reached SGLang/vLLM execution branch and numerical contract for this model/configuration/input, including operand storage, score scaling/dtype, dot accumulation, exponent/reduction precision, output conversion, masks and persistent state; (2) establish that the candidate's selected-cell set and reductions match that contract on the same fixtures; (3) show through a phase/dependency measurement that the current QSA row work or scheduling makes a split plausible, without reading host wait as GPU arithmetic attribution; and (4) compare serial, small-P, and perhaps hierarchical candidates over the full path with scratch, gather/reuse, launch and synchronization costs counted. Only then can correctness, numerical agreement to the actually validated SGLang/vLLM path, and repeated whole-model results—including 262144 physical context, RESTORE/lifetime, fault, output-quality and memory gates—support a decision. Existing FP32/ggml results remain diagnostic; disagreement with that extra-precision reference alone does not reject a candidate.

There is no inference here that QSA is currently underoccupied, serial-bound, or reduction-bound. If the active work group already has enough parallel work, if query rows expose ample independent CTAs, if cells/values are cheaply streamed and reused, or if the value vector makes partial traffic large, the online single-pass recurrence may remain faster and simpler. If a source-level precision mismatch remains unresolved or no full-path timing question exists, no split design should advance on theoretical associativity alone. This report makes no B570 speedup/support claim and does not imply a same-model SGLang CUDA run occurred.
