## Contract evidence

The new evidence is about typed producer/consumer boundaries in serving implementations. The two frameworks do not expose a universal “activation dtype”: the hidden activation, residual stream, hyperconnection coefficients, convolution history, recurrent matrix state, gate arithmetic and kernel temporaries can all have different types. A kernel accumulating in FP32 may still round on every persistent-state write or on its output store.

| Producer → consumer | vLLM and SGLang source contract | FP32 or rounding boundary to preserve |
|---|---|---|
| Dense / MoE result → residual boundary | For DeepSeek V4 mHC, the optimized pre kernels take BF16 residual streams and emit BF16 layer input; the mHC post result is stored in the activation/residual dtype. The ordinary serving model's linear and MoE outputs follow its configured activation dtype. This is a BF16 specialization, not evidence of FP16 coverage. | mHC `pre`, `post`, and combination coefficients are FP32. The stream update is accumulated using FP32-valued terms, then narrowed at the declared output boundary. Do not cast the residual backing allocation while consumers still declare `float*`/FP32 inputs. |
| Fused norm / gated activation | vLLM's `layernorm_gated.rms_norm_gated` loads `x`, optional gate `z`, and weights into FP32 registers, keeps mean/RMS statistics FP32, and allocates its result with `empty_like(x)` (activation dtype). SGLang mHC combine/norm has BF16 optimized output and FP32 mix coefficients. | The norm/gate math uses FP32 intermediates, but its output is rounded to the activation dtype. mHC stream storage is a separate contract from this norm output. |
| Attention Q/K/V and output | In GDN/Qwen paths, fused projection produces Q/K/V and gates in the configured activation type; the recurrent kernel promotes Q/K/V and gates to FP32 for the recurrence. Conventional attention similarly uses the model activation type for projected Q/K/V and returns the backend's declared output type. SGLang DeepSeek V4 explicitly allocates one attention output as `x.dtype` even when the query is FP8, because that backend returns BF16. | Attention score/reduction accumulation and GDN recurrence accumulation can be FP32 even when projected inputs and returned outputs are 16-bit. Follow the selected backend's output contract instead of inferring it from query or weight type. |
| GDN convolution and persistent state | SGLang's `mamba2_state_dtype` defaults temporal/SSM state to FP32, then allows model config and `SGLANG_MAMBA_SSM_DTYPE` override; convolution state defaults independently to BF16 and has a separate override. vLLM independently resolves convolution state from `mamba_cache_dtype` and temporal state from `mamba_ssm_cache_dtype`; `auto` means the convolution-state type, which in turn can follow model dtype. Its fused GDN route advertises FP32 and BF16 state types. | A narrow persistent matrix state is rounded on every write, even if the step's accumulator is FP32. Recurrent state, convolution history, and activation output must not inherit one global format switch. SGLang's packed decode kernel also rounds `sigmoid(beta)` through `b.dtype` before promoting it back to FP32; its generic KDA branch keeps beta FP32, while the pinned vLLM branch keeps beta FP32. This is a path-specific rounding point; it does not establish the long-prefill chunk path's behavior. |

This is not just theoretical format bookkeeping. The vLLM generic state calculator can select a 16-bit temporal state under `auto`, whereas SGLang defaults temporal state to FP32 unless configuration or environment overrides it. Conversely, SGLang's default BF16 convolution history is independent of model activation dtype, so a model running FP16 needs the resolved cache contract checked at the assignment site. Do not port a framework-wide default as a Strata invariant.

The mHC examples are specifically DeepSeek V4-style manifold-constrained hyperconnections. SGLang's `HcState` carries BF16 residual streams plus separate FP32 `pre/post/comb` coefficients; its post formula returns `type_as(x)`. The TileLang path asserts BF16 residual input and allocates BF16 sublayer input, while coefficient workspaces are FP32. vLLM's delayed and fused-post/pre TileLang entrypoints follow the same broad split: BF16 stream/input tensors and FP32 coefficient tensors. Some SGLang fast dispatches are additionally gated to HC=4, hidden=5120 and particular NVIDIA architectures. Those assumptions do not match Strata's HC4 with `D=10240` total stream width / `N=2560` embedding and do not prove any path on Intel SYCL.

The recurrent examples are also not interchangeable across framework routes. SGLang's generic recurrent kernel allocates an FP32 final-state output, while its packed-decode Triton path loads and stores the persistent state through its declared state dtype and has a narrower beta round-trip. vLLM's FLA recurrent kernel keeps its matrix accumulator in FP32 and casts outputs and final state to their destination tensor types. Therefore a “FP32 state” label alone does not prove that every gate, intermediate, prefill kernel, or output is FP32, and a BF16 state allocation does not prove low-precision arithmetic throughout.

## Mapping to Strata

Treat framework kernels as contract examples, not code to transplant. Their optimized mHC kernels target CUDA/TileLang or framework-specific GPU paths; the vLLM vendored FLA kernel identifies its FLA source and MIT provenance, while both repositories' project code is Apache-2.0. Preserve those source notices and check the per-file/upstream license before any later reuse. This report proposes no source adoption.

For Strata long prefill, make the dtype part of each kernel interface and plan: the producer's output pointer/type and row stride must match the next consumer's input type and stride. A native-16 GEMM should load FP16 or BF16 activations directly, accumulate into FP32, and store a declared output type. A native-16 residual post should load its stream and sublayer output in their actual types, combine using FP32 coefficients/accumulation, and perform one explicit conversion only at the selected residual-storage boundary. The following pre/norm or projection should consume that 16-bit stream directly and keep its reduction/accumulator FP32. This creates a real typed producer-to-consumer path; converting an FP32 buffer to half behind an unchanged FP32 consumer only adds conversions and leaves the kernel contract unchanged.

Keep FP32 as the reference arm. For the first long-prefill format experiment, run FP16 and BF16 as separate storage choices; do not narrow Q/K/V caches, int8 KV, IQ3 weights, decode buffers, or persistent GDN state as a side effect. For the recurrent branch, keep GDN matrix state and scalar gate/decay arithmetic FP32, and specify convolution-history dtype separately. This isolates the activation/residual question from state-error accumulation. If a later experiment changes recurrent state storage, it needs an independent long-sequence state/output comparison.

At the supplied geometry, one full-context HC4 residual history has `262144 × 4 × 2560 = 2,684,354,560` values: 10 GiB in FP32, 5 GiB in FP16/BF16. One 8192-row chunk is 320 MiB or 160 MiB, respectively. These are logical payload sizes for one such store; they do not predict total prefill speed or GPU fit. Keep chunk placement, layer schedule, int8 KV, shared state, 262144-context semantics, and decode route fixed while evaluating the new type.

## Verification and limitations

A concrete first experiment is a single 8192-row long-prefill producer/consumer pair using the actual HC4 width and Strata kernels: compare the existing FP32 reference against separate native-BF16 and native-FP16 arms. Each candidate must write typed output directly and have the next kernel consume that type; no intervening host cast or backing-storage reinterpretation. Keep weights, IQ3 dequantization, chunk boundaries, int8 KV, GDN FP32 state, and decode code identical. Record source/binary/toolchain/device identity, each arm's physical bytes, conversion count, component timing, and per-row errors at producer output, next-consumer input/output, and final logits. Report finite/overflow/underflow counts, absolute and relative error summaries, top-token/margin changes, and fresh fault status. This is only a component screen; it neither selects a 16-bit format for model quality nor qualifies 256K support, full prefill performance, or decode.

The architecture author's Qwen residual-storage result and the earlier R569 report already provide a reason to evaluate compressed residual storage, but neither is a measurement of repeated FP16/BF16 round-trips in this Strata IQ3 implementation. R569's single saved-final-layer posthoc cast screen is not evidence for accumulated layer-boundary error; R573's teacher-forced logits route and long-context/task gates remain the relevant quality follow-up. FP16's finer significand and BF16's wider exponent range are only hypotheses about which type will fit the target distribution. The B570/oneAPI toolchain, Intel device, Strata's HC equations, IQ3 route, and full physical context all differ from the cited serving kernels; no external source here measured performance or quality on those conditions.
