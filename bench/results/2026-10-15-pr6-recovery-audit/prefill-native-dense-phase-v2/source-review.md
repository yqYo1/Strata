## Implementation and ownership

The patch is against current production, not against v1. NativeDense v1 is carried forward with explicit bank-allocation classification: only cudaErrorMemoryAllocation plus null owner returns false. Non-OOM/null, non-OOM/non-null, OOM/non-null and success/null stop with owners alive. Packed snapshot capture remains startup-only, bounded by 3 GiB payload; native ABI callers must all be rebuilt. Both startup and full restore retain original packed GGUF bytes, FP32 reference and canonical metadata.

`STRATA_PREFILL_NATIVE_DENSE_BANK=1` is the new default-off startup opt-in. Every unset/0 short request takes the old prompt helper directly. Opted-in short requests also use the old layout. Long requests require explicit layer-major=1, configured single-device native path, no split/peer/remote, no token graph handle/capture, an intact full native snapshot owner and unset existing activation hook. Existing full compact FP16/native/MMQ=0 geometry guards remain in layer_major.inc. Long serve-window requests explicitly reject. Native bank plus `STRATA_PREFILL_RELEASE_HEADS=1` explicitly rejects before retirement: no nested head/dense retirement or resume is attempted. Head release alone remains on its existing helper.

The two real generator call sites now pass through a synchronous outer NativeDensePhase wrapper. The generator's request loop is the serial normal-reader owner; its phase atomic_flag additionally rejects overlapping/reentrant bank requests. This is not a general concurrent WeightTable API: any future outside reader must join that request exclusion. The wrapper checks Verifier idle eligibility before mutation, drains main and MTP callback streams, waits Verifier commit and drains compute/copy, checked-destroys Verifier exec/segments/work, then checked-destroys all SessionGraphs exec/posts/routes/shared/preA/preB/preP arrays and resets their pointers/capture flags. Commit state graph is retained after checked completion because it copies session state only. Session/KV/GDN/QSA/PLE/expert cache storage and state remain owned.

PLE's distinct native publication is withdrawn before NativeDense enters Bank. The bank component withdraws normal table rows and frees native owners only after all of those owner APIs have succeeded. A local queue wait alone is not presented as the reader proof. Dedicated Verifier gates block run/capture/record/commit/logit access while dense-retired; resume validates Full native source publication against its own table. Restored graph teardown uses checked retirement mode.

Each real layer-major pass calls the synchronous activation hook after checked local drains. The callback additionally checks main and MTP callback completion, activates exactly that layer, and supplies NativeDense's immutable private overlay. LayerView performs overlay-first lookup and canonical fallback, without copying or rewriting the published WeightTable. In this configured batched long-prefill callchain, prefill.cpp directly computes layer operations and constructs two LayerViews (current layer and lookahead norm); it does not call core block_layer/gdn_layer/qsa_layer/moe_shared helpers. Both real Prefill resolver construction points receive the explicit overlay. Core decode/block helper LayerViews keep their default null overlay and existing table; no thread-local/global substitution is added. Future helpers called from this path must explicitly accept the resolver.

PLE uses a private copied PleRun/weights value. Critically, ready() is evaluated *after* adding the active layer-1 native key: a native-only compact key has no canonical fallback after separate publication withdrawal. Batched and token PLE use that same private weights value. PLE history/state pointers remain the existing session storage. Layer drain precedes clearing the borrowed view; cancellation/exception unwinds through the existing checked local drain guard before outer restoration. No bank pointer is published back into persistent ss.ple.w.

All exits after retirement drain main/MTP, clear the activation hook, transactionally restore the entire NativeDense full owner, rebind PLE from restored table, recapture previously captured SessionGraphs using the original post_inputs recipe, then unblock Verifier for lazy weight-window recapture. Entry confirmed OOM retains Full owners and goes through graph/PLE restoration. Full-restore failure, callback completion uncertainty, graph destroy/recapture failure and retirement exceptions fail-stop before decode; no false restoration success is returned. Cancellation restores weights/reader capability, not a rollback of already advanced recurrent/KV session state; the existing request/session cancellation policy still applies.

MTP record_forward resolves target wt only for token embedding (canonical or NativeEmbed), and resolves projections from its own dense/q8/f32 owners. capture_prefill/capture_prefill_dev record that own K/V route. prefill's E4 path and fallback return after cs_ synchronization; Prefill::draft_kv also uses MTP-owned projections and synchronous callback return. v2 adds a checked MTP queue drain around bank activation and restore, including callback failure. MTP projection graphs/owners and target embedding remain alive. No target native owner is freed while that callback is in flight.

## Capacity boundary

For the previously recorded 300-matrix configuration: full native 2,116,951,040 B, maximum native layer bank 50,918,400 B, theoretical native payload recovery 2,066,032,640 B. Canonical 1,538,035,200 B and shared native scratch 6,912 B remain. Entry/restore temporarily require 2,167,869,440 B native payload. Extra optional PLE native rows/configurations require their own dynamic census. This does not achieve or claim the combined canonical-plus-native one-layer hypothesis. No physical allocator recovery, 262144 admission, task quality or speed is established.
