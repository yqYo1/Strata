# R643 — checked PCIe fetch proposal source contract audit

Date: 2026-10-15 JST
Scope: independent read-only audit of `checked-pcie-fetch-v1` proposal artifacts against current `feature/sycl` source. This report is the only new file. No tests, build, GPU/process operation, Git operation, cleanup, active job 16956 inspection, raw output read, or product edit was performed. Proposal remains unapplied and unqualified.

## Decision

The proposal addresses the main unsafe path: `fetch_dma` currently ignores copy/callback API statuses, while a later successful copy-stream wait cannot recover an omitted transfer. Its helper records the first returned error, drains the submitted prefix at the existing boundary, refuses the consumer, and keeps completion-unknown state from reset. The actual staging geometry and primary caller lifetimes match its assumptions.

Two source-level corrections are needed before treating the proposal's error report as fully accurate:

1. If fetch submission and the concurrent shared/resident work both fail, one early return drops the second status from the error text.
2. The recorded `copy_enqueue` operation means “the copy API call returned non-success,” not necessarily a synchronous copy-enqueue failure: SYCL compat `attempt()` checks sticky runtime async errors before entering the copy body. The consumer is still safely refused, but this attribution is too narrow.

The CPU fixture includes the production helper and tests its isolated state machine. It does not exercise the `Verifier` integration, the real pool callback order, graph retirement, or the two-TU class-layout rebuild. Those remain Main qualification gates.

## Source-to-proposal contract

**Issuer and order.** `expert_pool_dispatch_multi` finishes the GPU plan arrays, calls `P.publish`, then `P.fetch` on the pool-caller thread before CPU jobs are dispatched (`src/core/expert_source.cpp:2128-2133`; CPU pool work begins afterward at `:2177`). The SYCL `publish_plan` can launch `work_` (`src/core/verify.cpp:1542-1548`), while `fetch_dma` is called by that same issuer. The host callback only raises the mapped flag and does not access `fetch_status_`. The proposed state is therefore issuer-owned as documented; no callback-thread sharing is introduced.

**Completion and consumer gate.** After the pool callback returns, the proposed first-error check drains through `finish_fetch` and returns false before fallback plan publication, the host flag raise, and the next segment launch (`source.diff`, hunks around `verify.cpp:1332-1395`). On success the existing copy-stream synchronization point is retained. In overlap-off, PCIe grouped work is in the ordinary next segment; in overlap-on the shared/resident work may already be in flight but the PCIe group remains in the subsequent segment, so the proposal gates the PCIe consumer. The async work error remains separate in `work_status_`.

**State lifecycle.** State resets at run entry and before each layer/group pool callback. `reset()` refuses if the previous copy completion is unknown; after a successful drain it may clear a prior fetch error. Current production call sites treat `Verifier::run` failure as fatal to that generation call (`generate.cpp:5722-5724,6061-6064,7001-7004`), after which the local `Verifier` owner is destroyed. The destructor synchronizes `cs_`, retires graphs/events, then synchronizes/destroys `copy_` before freeing the arena (`verify.cpp:215-236`). Thus the current caller does not continue the failed window as a new token/window. The helper alone does not force that fatal policy for any future direct caller; any new caller that retries the same `Verifier` after false must first establish its existing state/graph retirement and session recovery contract.

On drain failure `finish()` sets `drained=false`, retains `drain_error`, and `reset()` / `can_consume()` reject. That is internally consistent. In today's caller, failure exits the generation function and reaches existing verifier teardown. The destructor's cleanup calls are not a checked recovery API, so the report must not promise that failed stream drain is recoverable or that ordinary teardown proves queue health.

**First error and compat detail.** `CheckedPcieFetch::remember` copies the description into fixed storage immediately and never replaces a prior error. Production calls `cudaGetErrorString(code)` inline after each API returns (`source.diff` fetch hunk); compat's `fail()` stores the current `detail_code/detail`, and `cudaGetErrorString` returns that detail when its code matches (`src/sycl/compat.cpp:47-76,583-605`). Therefore TLS detail is captured before a later drain can overwrite it. The fixture's changing `detail` exercises the helper's copy-now/preserve-first behavior, although its provider is simulated.

The classification caveat is concrete: `attempt()` calls `runtime_for()->check()` before executing the submitted body (`compat.cpp:65-76`), and runtime async exceptions remain sticky (`src/sycl/runtime.cpp:40-55,91`). Therefore `cudaMemcpyAsync` can return a prior queue/runtime error before `queue(st).memcpy` is attempted (`compat.cpp:253-259`). The helper records this as operation `copy_enqueue` and labels it `copy_enqueue` in the user-facing error (`source.diff`, `finish_fetch`). This does not reopen the consumer, but it can misstate the first failure source. Minimal correction: name the record `copy_api`/`copy_call` unless compat adds explicit failure provenance; keep the returned status and immediate TLS detail either way. `cudaStreamSynchronize` separately executes `wait_and_throw()` and runtime error checks (`compat.cpp:328-332`), so drain remains a distinct observation even when the same sticky exception recurs.

## Geometry and ABI/build obligations

Production allocates `kStagingBlobs * expert_layout().max_blob` bytes (16 slots) and initially binds the whole staging arena to the sink (`verify.cpp:364,396-397`). `set_plan_slot` then uses one 16-slot segment for G=1 or an aligned 8-slot half per group for G=2 (`:1504-1519`). The planner caps DMA fetches by `P.staging_cap` and its 64-entry local array (`expert_source.cpp:2068-2069,2084-2091`), then points `ptr2` into `P.staging + q*blob_bytes` for DMA mode (`:2110-2124`). `fetch_dma` computes the full allocation capacity, passes the selected group stage base, per-group slot count, max blob and layer blob bytes to the helper. The helper's static assertion binds its 16-slot constant to the production constant; it checks group capacity, count, blob bound, allocation/group spans, alignment, multiplication/address overflow and every source pointer before its first enqueue. This matches the real 16 total / 8-per-split-group contract. As README states, a raw pointer cannot prove source allocation length or pin identity; those remain upstream `pinned()` / `blob()` source contracts (`expert_source.cpp:2084-2089`).

`verify.hpp` class layout changes only under `STRATA_ENABLE_SYCL`; direct include search in the current tree finds `src/core/verify.cpp` and `src/program/generate.cpp` as the two TUs including it. The former defines methods and the latter owns `Verifier` objects (including serve stage owners at `generate.cpp:4730-4743` and standalone at `:6800`). Both must be recompiled from the same candidate header and linked together; retaining an old `generate.cpp` object would use the old object size/layout. The proposal README's explicit two-object/link-map gate is correct; no build confirmation exists in this audit.

## Error-detail/reporting issue and minimum correction

In the new branch after pool return, `verify.cpp` first checks `fetch_status_.failed()`, calls `finish_fetch(err)`, and immediately returns. `work_status_` may already be non-success from the adjacent `cudaEventQuery(work_done_)` (`:1339-1344`), but this branch does not append it. The later shared/hit error branch appends work status only when reached (`source.diff` hunk around `:1372`); it is bypassed whenever a fetch error is present. Thus simultaneous fetch and shared/hit failure reports only the fetch error, contrary to the README statement that both independent statuses are preserved. Minimal correction: in the first-error branch append the independent `work_status_` code/string when non-success, preserving fetch error as first; do not replace it.

## Fixture boundary

`cpu_fault_fixture.cpp` includes `files/include/strata/core/checked_pcie_fetch.hpp` directly, the same production helper bytes identified by the artifact manifest. Its fake callbacks cover first/middle/last copy status, notification failure, separate drain failure, first-error retention after a changed detail source, refusal before consume, reset refusal while undrained, geometry/source null checks, duplicate fetch, empty n<=0 path, normal callback/copy/drain order, and a no-fetch checked drain. These are useful helper-level fault cases. The fake `finish()` independently controls pending copy/callback state; it cannot establish SYCL queue ordering or real failure side effects. The fixture does not instantiate `Verifier`, call the integrated `fetch_dma`/`finish_fetch`, assert `work_status_` reporting, validate `publish_plan`/pool/next-segment ordering, compile both consumers, or exercise destructor retirement. It is source only and has not been run.
