What it implements
------------------
Only the exact value STRATA_PREFILL_LAYER_MAJOR=1 selects this candidate.
Unset, 0, 10 and all other values take the existing chunk-major body, now named
run_impl. No global environment writes or static selector cache is added.

The candidate requires current 48-layer geometry (36 GDN + 12 QSA), the full
single-device session/range, compact FP16 MoE, explicit STRATA_PREFILL_MMQ=0,
the complete native expert source/layout, and the existing same compute/copy
queue. Peer, portable peer, stage chains, hand_in_, vision rows, reentry,
MMQ/fused MoE, split session, unsupported geometry/positions/chunks, ring KV,
hybrid KV and inconsistent per-layer KV plans are explicitly rejected.
All normal-route defaults remain unchanged.

Each of 48 passes first materializes all 512 experts into ONE owned host slab
on the main thread using copy_blob. Source bookkeeping is never assumed
thread-safe; no source blob pointer is retained after copy_blob returns.
The slab survives every upload reader. Then all 512 slots of a temporary
ExpertCache are uploaded once, on m.copy == m.cs, and checked-drained.
Only after successful completion is the current layer's 512-entry host map
published. All chunks of this layer reuse those slots. The map and slots are
reused for the next layer only after checked pass/boundary completion.

The current chunk math is reused with [stage_lb_,stage_le_)=[layer,layer+1].
New run_impl branches prevent any layer-major Stager job/issuer launch and
reject a missing temporary residency entry before a fallback could use an
absent Stager job. The old unchecked StagerDone finish helper is bypassed in
this route. The wrapper checks no previous host jobs remain claimable/active;
it neither starts jobs nor uses Stager::finish as a retirement proof.

New ExpertCache::open_uninitialized allocates without memset/upload, so an
initialization command cannot fail and trigger the old internal close before
the outer lease sees its completion. This API checks its own allocation/table
products. Existing open/open_sized keep their old zero-initialization behavior
through open_impl(..., initialize=true). Uninitialized storage is only read
after all 512 checked uploads and publication of the temporary host map.
Existing decode cache bytes, MTP weights/workspaces and graph addresses are
retained; this candidate has no release/recapture/reload path for those owners.

Residual admission and storage
------------------------------
The helper checks the full n*10240*sizeof(float) product, addressable pointer
range, each source blob/table span, padded cache stride/product, host map sizes,
and each chunk/store offset. At n=262144 the full residual is 10,737,418,240 B
(10 GiB). That total is NOT required to fit VRAM.

The store is in-place between layers, with a separate device prefix and host
tail. m.R stays the existing chunk scratch; there is no scratch/full-store alias.
The prefix ends at an integer chunk boundary, except that a prefix covering the
entire prompt may include its final partial chunk. Every input/output span is
validated; host-tail offsets subtract gpu_rows rather than indexing a shortened
host allocation by absolute prompt row. Absolute callback positions are checked
before subtracting request pos0, and cursor checks enforce ascending chunks.

STRATA_PREFILL_LAYER_MAJOR_R_GPU:
  unset or exact auto: largest complete prefix within free-VRAM budget
  0: host-only residual store
  decimal integer rows: maximum prefix, rounded down to whole chunks; exactly n
                        includes the partial final chunk
Invalid signs, whitespace, suffixes, overflow, rows>n and an explicit rounded
prefix exceeding the budget fail. This is a row count, not a boolean switch.

Before submitting any GPU command, require known cudaMemGetInfo telemetry and
extra padded 512-expert cache + selected prefix + 512 MiB GPU headroom <= free
VRAM. The existing decode/MTP storage stays live and is already reflected in
that free sample. The 512 MiB reserve is finite policy, not a measured runtime
requirement or proof that later driver allocations always fit. Insufficient
space fails explicitly; there is no cache retirement fallback.

Require known current physical available RAM for host tail + whole-layer upload
slab + ExpertCache blocking-host staging + two residency-map extents + 8 GiB
host headroom, using the existing conversation memory provider. Host allocations
are attempted before new GPU commands. This is sampled physical-memory
admission, NOT an OS memory reservation. The existing provider does not account
for cgroup/job limits or future competing allocations; constrained-container
support remains unqualified. Internal source copy_blob cache growth and driver
staging also consume headroom, not a complete separately reserved budget.

This simple owned slab deliberately adds a host copy and serial source loading.
It removes source-pointer leases and extra per-chunk expert H2D but has no claim
of optimal upload overlap or measured performance. The host-only residual path
adds 47 inter-layer D2H/H2D round trips; the optional/auto prefix reduces that
traffic for its rows. No throughput, fit or correctness inference follows.

State, callbacks and statistics
-------------------------------
run_impl retains each GDN recurrence/conv slice, QSA state/indexer/map/host KV
and the current mode-1 stage-prior/append-current/attend sequence. No sequence
reset occurs at a layer or chunk boundary. Resident 32768 cells and logical
262144-cell host/stage capacity remain distinct; stage allocations are never
replaced by the device resident pool. Uniform native F16, INT8/rotated INT8 or
Q4 mode-0/mode-1 layout paths use existing stage/ingest code; none is qualified
by this source handoff. The configured SYCL kv_stream.cpp remains selected.

The initial ple_prev is restored before every pass. PLE math/history advances
only in the layer-1 pass; final ple_prev is retained. The final whole-model
checkpoint callback also sees the computed final ple_prev, rather than a
scalar token window reset for the current pass. No session tensor rollback is
implemented or claimed on cancellation, callback failure or queue errors.
Partially mutated sessions require the caller's existing restore/discard policy.

Intermediate on_chunk only saves residual rows; the caller/MTP on_chunk runs
once for each final-layer chunk, in ascending position order. The caller's
on_stage_chunk runs ONLY at final layer AND final chunk. Earlier checkpoints
are suppressed even during the final-layer pass: their other layer states
already include later prompt tokens. On the last chunk the original callback
order is preserved (stage checkpoint, then final residual/MTP callback).
Each boundary is checked for duplicate/out-of-order delivery. The last stage
callback occurs before the last MTP callback, as in the existing API; a later
MTP callback failure can therefore follow a valid target-state checkpoint.

tokens/chunks count only the final layer in run_impl; the wrapper sets the
successful totals to old+n and old+logical_chunks. ms_total is added once from
the wrapper's wall interval, including admission/allocation/load/pass waits but
ending before automatic owner destruction. experts_streamed counts the 512
uploads per layer (24576 on successful full traversal), experts_resident counts
actual per-chunk groups served from that temporary cache. experts_dma is not
incremented because upload comes from the owned pageable slab, not directly
from the source's pinned arena. ms_experts_host includes serial source copies,
upload issue and their completion wait; it is not exclusive GPU service time.

The current RoutedFp16Observation, phase timing, layout observer, residual dump,
GDN hash/NAN dump and legacy preload/cache-release/in-place flags are explicitly
rejected when present, including value 0 for presence-based observers. Their
old full-model-call assumptions are not silently emitted as 48 measurements.
STRATA_TRACE remains allowed; its repeated chunk messages describe the actual
per-layer calls, not a normalized whole-model diagnostic counter report.

Ownership and error contract
-----------------------------
Restore saves stage bounds, hand_in_, m.cache/m.host_res, layer-major fields and
caller callbacks. All callback capture targets (cursor, layer, counters, plan,
owners and saved functions) are declared before the checked lease. No capture
owner ends its C++ lifetime before lease retirement, including exceptional exits.

Declaration/destruction order is checked drain -> field/callback restoration ->
temporary device cache/residual/host buffers/maps. The guard reuses the existing
DraftUploadGuard policy. Successful paths explicitly check cudaStreamSynchronize
on all participating compute/copy queues; SYCL compatibility uses wait_and_throw
and sticky runtime checking. If successful completion cannot be established on
an early return/exception, the fatal path aborts the native process while owners
are live. Unchecked destructor waits, Stager::finish or cudaFree are not used as
the completion proof. C++ field restoration is never described as state rollback.

Callbacks are assumed to honor the existing API: any work retaining supplied
rows runs on the prefill streams or is completed by the callback before return.
The wrapper cannot retire arbitrary external queues it does not own. Existing
MTP draft_kv uses the prefill queue and keeps its own immutable upload guards;
it receives only final-layer residuals. No MTP persistent owner is rebound.
