## Finding

The proposed borrow is source-level safe on the stated single in-order queue if it is admitted and retired as described below. I found no live source use of `m.attn_h` in the indexer append, score, or top-k interval. In `prefill.cpp`, that interval begins after `native_qsa_indexer_append_batch` / per-token append completes (2511–2528) and covers each `qsa_block_scores*` then `qsa_block_topk*` pair (2529–2560). Scorer inputs are session `idx_pooled`/`idx_dead`, chunk `q_idx`, `steps_dev`, and output `sel_scores`; top-k writes `sel_ids`. The subsequent optional diagnostics use those selection buffers, not `attn_h` (2581–2651).

Both attention output routes are disjoint from the borrowed arena: typed calls write `m.qsa_attn16`, which is the `m.attn` alias (allocation/aliases at 1013–1024; typed dispatch at 2663–2692), while untyped matrix and fallback calls write `m.attn` (2693–2717). Optional in-place FWHT also touches only `m.attn` (2718). Then the typed or ordinary gate writes `m.attn_h` while reading attention plus the full query/gate projection; output projection consumes `m.attn_h` immediately after (2721–2735). Thus the workspace must be retired before gate submission, and the `m.attn_h` output view must still designate its original allocation at that point.

**Do not borrow `m.Qf` or `m.qsa_Qfull16`.** Typed Q projection stores the full query/gate tensor there (2422–2432); `qsa_Qfull16` is an alias of `Qf` (1022); typed `native16::qsa::gate` reads it as `query_and_gate` (2723–2725), and `gate_attn` reads ordinary `m.Qf` (2728). The gate selects the upper 256 values of each query head (native16 header 35–39 and implementation 123–139). A scratch write to `Qf` would corrupt a live gate input.

## Admission and carving requirements

- Limit this optimization to the dedicated layer-major pass and the actual maximum allocation: require `m.layer_major_active`, `m.T_max == 8192`, same compute/copy queue (`m.copy == m.cs`), and `m.sel_batch <= 256`; keep the new score path explicitly enabled. `sel_batch` is currently initialized to 256 (prefill.cpp:499–502). Layer-major itself admits `T_max < 8192` (layer_major.inc:109–120), so an 8192-byte calculation must not be inferred from the current chunk length; a final partial chunk still borrows within the original `T_max` allocation. Exclude chunk-major/short/decode or any queue/handoff/peer route. The existing layer-major topology guard already excludes split/stage/peer/reentry and enforces `m.copy == m.cs` (101–107); SYCL init makes the copy queue the compute queue (prefill.cpp:874–879).
- The logical `attn_h` capacity at `T_max=8192`, `ZV=6144` is `8192*6144*2 = 100,663,296` bytes (prefill.cpp:491–502, 1013–1015). The stated maximum workspace high-water is 50,610,176 bytes, leaving 50,053,120 bytes within that logical span. Check the actual subspan sizes, offsets, alignment, overflow, and pairwise disjointness against this logical capacity on every admission; keep the 4-byte status outside the borrowed span. `Alloc::take` rounds reservations and adds a 256-byte guard (206–225), so do not treat adjacent arena padding as part of `attn_h` or spill into `sel_ids`/later QSA reservations (1026–1028).
- Pool/query and F32 panel subspans must be pairwise disjoint and disjoint from all score inputs/outputs (`q_idx`, `steps_dev`, `sel_scores`, `sel_ids`, indexer pools/dead) and the external status owner. Preserve each type's alignment. Do not assume that an in-order queue makes overlapping input/output spans valid within a single kernel.
- QSA selection is shared by typed and untyped attention dispatch: its score/top-k loop is common (2531–2560); only the later attention/output route differs. Therefore a score-arena selector may serve both downstream attention variants, but retain the old path if the exact sizing/capability guard fails. Do not condition safety on typed attention alone.

## Ordering, callbacks, failures, and status ownership

`run_layer_major` requires the same queue and drains it at entry (layer_major.inc:101–107, 427–443). The in-order property is checked by `queue_for` (runtime.hpp:45–59), so score/top-k work precedes typed or untyped attention and gate work without a new synchronization. However, there is no QSA-specific checked drain between selection (2531–2560) and attention/gate (2652–2735); QSA profile marks do not establish retirement. Existing checked drains occur later at the window attention-store path (prefill.cpp:3529–3531), regular residual/callback store (layer_major.inc:644–674), and layer-major final drain (layer_major.inc:741–744). After a checked drain covers every score/status writer, copy the separate status word to its separately owned CPU target; if the copy is asynchronous, perform and check a drain for that copy too before inspecting host data. If it must be checked before attention/gate, add an explicit checked synchronization at that boundary—the current source has none. Reset status once on the queue before model work; kernels only atomic-OR thereafter. Never clear/reuse it from the CPU during the pass. Keep the status/readback owners live through the selected drain. The snapshot does not contain the proposed scorer's atomic implementation, so flag width, atomic support, status bit meanings, and copy API behavior still need Main's implementation/runtime qualification.

Declare both the device status owner and host readback owner before `Restore` and `DraftUploadGuard` (the lifetime pattern at layer_major.inc:302–327, 399–440). The guard drains compute and copy queues and aborts with owners alive if retirement cannot be proved (427–440; `DraftUploadGuard` contract in `draft_uploads.hpp`:57–78). Keep the owners alive until after the status readback's checked drain. If borrowing is represented by changing `m.attn_h` or another field, restore that field only after lease retirement on normal return, error return, and exception unwinding; extend the existing `Restore` state or use an earlier-declared borrow guard whose destructor follows the lease. A local borrow declared after the lease would destruct first on unwind and is unsafe. Simplest is to leave `m.attn_h` unchanged and pass bounded scratch subviews explicitly.

No callback/window conflict is visible in the call path: layer-major disables host stager jobs (214–220), the window route remains single-GPU/native16/chunk8192 (layer_major.inc:52–60), and window callbacks / residual stores occur after the attention and gate path (prefill.cpp:3519–3553; layer_major.inc:607–629). A window piece executes the same attention body before storing its residual. The function's outer checked lease also protects early returns/throws before field restoration (layer_major.inc:399–440, 741–761). These source facts do not establish actual runtime queue lowering or that a future callback cannot reenter; preserve the current no-reentry admission and do not move workspace users into callbacks.

## Decision and remaining evidence

Proceed with the bounded borrow only with explicit capacity/topology/alias guards, queue-ordered checked status retirement, and lease-ordered owner/borrow destruction. Keep Qf untouched. There is no source evidence here for runtime atomic lowering, full context-262144 fault/tail behavior, actual scorer read/write bounds, or measured numerical/performance outcomes; these remain Main-owned implementation and validation gates. No source defect is claimed in the frozen snapshot because the new borrow/scorer is not present there.
