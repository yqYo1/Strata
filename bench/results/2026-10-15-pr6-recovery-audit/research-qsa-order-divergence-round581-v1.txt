## Source findings

1. **QSA selection has a context-dependent identity-to-top-k boundary, but not a 12K–16K branch.** `include/strata/kernels/qsa.hpp:127-135` defines `width=min(n_kv, idx_top_k+idx_block-1)` and states identity selection below the bound; `src/kernels/sycl/qsa_index.cpp:103-115` takes the identity path when `width==n`. In the common shapes, obtain the actual `idx_top_k` from model geometry before deriving its boundary. For `n_kv > width`, `qsa_index.cpp:116-150` performs radix threshold selection and emits selected IDs in ascending source index order. The integer reductions/scans are over a 256-item group; there are no floating atomics in this selector. `src/kernels/sycl/qsa_select.cpp:100-139` is the block variant: it uses ordered integer score keys and scans equality candidates in chunk/lane order, then emits ascending cell IDs. Thus a threshold/tie difference remains plausible only if upstream score values differ, the runtime/compiler violates the expected group operation contract, or the actual active route differs; this source does not show an order-dependent atomic race.

2. **The two score paths use different accumulation precision and should be route-pinned.** `src/kernels/sycl/qsa_index.cpp:50-69` accumulates per-head dots and total in `double`, then stores float. `src/kernels/sycl/qsa_select.cpp:48-60` computes four float dot products with fixed XOR shuffles and float total. The native indexer has a third route (`src/kernels/sycl/native_qsa_indexer.cpp:79-155`), which converts the incoming raw row to half at line 93, accumulates pooling/normalization in float, and writes adjacent block/dead rows. These are not interchangeable provenance. The current run's record must be checked for actual selected QSA route and per-layer selection counters before attributing its first-logit change to selection ordering. The native append-batch path is a serial per-cell enqueue (`:173-190`), not a parallel scatter.

3. **Current QSA append/indexer writes are structurally ordered, subject to the caller's queue and state ownership.** The portable indexer appends tail cells at `qsa_index.cpp:213-220`, reads the completed tail only at final block position (`:238-245`), barriers before using local `means` (`:247`), writes pooled vectors and block position (`:257-271`), and calls `finish` (`:275`). Native append writes tail/pooled/dead/block-pos (`native_qsa_indexer.cpp:90-155`) and batch append queues each cell sequentially (`:185-190`). This source inspection found no uninitialized local-accessor element in the valid geometry: the full local arrays consumed by the final-block path are filled by the full 128-lane work-group before their barrier. It does not verify bounds/initialization of caller-provided global tail, pooled or dead storage under the recorded allocation layout.

4. **Prompt attention handles absent pages and partial final tiles explicitly.** In `src/kernels/sycl/prompt_attention.cpp:126-153`, count is clamped to `[0,cap]`, the final 32-cell tile records only actual IDs, negative/unmapped page IDs become row `-1`, and missing rows are loaded as zero. Per-group softmax excludes those rows (`:188-204`). This route has barriers around shared tile production/consumption. It is a matrix selected-cell prompt path and differs from decode attention; record route selection must be established. No atomic accumulation appears in the inspected excerpt. A defect in ID/page mapping or in shared staging lifetime could still cause a position-correlated change, but this review did not find evidence proving one.

5. **Expert routing is deterministic and serial in the inspected helper; routed additions rely on unique destinations.** `src/kernels/sycl/expert_routing.cpp:21-32` and `:54-79` build hit/group lists with a single task in input order. `moe_hit_add` (`:81-99`) uses independent destinations and comments that distinctness follows `hit_select`. No atomic add is used there. The correctness of that precondition is caller-dependent; this code is not enough to attribute the observed logits to MoE ordering.

6. **GDN has explicit ordered recurrence and barriers, with no global atomic reduction in the inspected paths.** Portable `gdn_step` (`src/kernels/sycl/gdn.cpp:97-121`) assigns one output column/state column per work item and loops state rows in fixed order. The fused recurrence (`src/kernels/sycl/fused_gdn.cpp:97-159`) serially loops token `t`, synchronizes shared K/Q and reductions, and writes only from `rg==0`. Long input necessarily changes the number of recurrence iterations and state history, but this is not evidence of a race. Review the full remaining GDN route and actual input-to-kernel batching before claiming coverage; input length alone does not establish which implementation ran.

## Interpretation and limits

The selected first-logit equality through position 8,192, then broad small FP32 drift from 16,383 onward, is consistent with a position-dependent state/numerical difference accumulating in earlier work, not diagnostic of a sparse-selection tie alone. The source does contain score accumulation variants whose route matters, but the inspected top-k implementations have deterministic index-order tie handling and no floating atomic reductions. No concrete UB, race, uninitialized local padding read, or threshold branch specifically at 12K–16K was established. MTP expert release occurs after prefill in the recorded control and is a lifecycle/memory condition, not proof of a kernel arithmetic cause. Main's planned same-binary/release-on GPU control with residual GPU rows fixed at 4,096 is the appropriate first discriminator; its result should be evaluated before any source fix or kernel-specific attribution.

This is observation/review guidance only; no test or replay was run here.
