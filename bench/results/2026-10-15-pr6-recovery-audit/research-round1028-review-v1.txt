## Novelty, evidence, and corrections

R592 and R693 cover GDN work mapping, barriers, state layout, tails, and numerical order. R759 already introduces prefix scans/lookback and warns against carrying NVIDIA claims into SYCL/Xe2. R1027 substantially expands that specific gap with a focused scheduling/publication/lifetime comparison, so retain it as an update to R759 rather than a wholly unrelated topic. R541/R542 concern host/event and graph-callback lifetimes, not device-wide work-group progress.

The central specification claims check out against primary sources. SYCL 2020 revision 12 gives work-items at least weakly parallel forward progress, makes stronger guarantees implementation-defined, requires barrier progress within the same group, and says portable code cannot assume subgroup scheduling or progress details (§§3.8.3.4, 3.9.4). Its atomic orders follow C++ meanings, but it explicitly says the formal SYCL memory model is still ongoing (§3.8.3). Device-scope release/acquire is a valid publication design only when the device supports that atomic order/scope and the participating work-items share the allocation; capability queries and the exact backend contract remain necessary. The spec requires `sycl::atomic_ref` alignment and exposes atomic order/scope capability queries (§§4.6.4.4, 4.15.5). `sycl::free` requires no in-progress or enqueued command to use the memory; event wait covers the event and dependent commands (§§4.8.3.6, 4.6.6). Thus the host-deadline and reader-lifetime cautions are sound for portable SYCL. Reset/cancellation mechanisms remain backend-specific.

CUDA 13.2.2's memory-model message-passing example confirms device-scope release/acquire publication and shows why block scope is insufficient across blocks (§5.7.5). Cooperative grid synchronization is an explicit CUDA facility: `cudaLaunchCooperativeKernel` is required, and the CUDA 13.2.1 Driver API caps the grid at the occupancy-reported active-block count times SM count. This is a NVIDIA/CUDA contract, not SYCL or Xe2 evidence. The CUDA guide also states that ordinary block scheduling order is unspecified. Intel's 2025.2 GPU guide documents occupancy/resource considerations; it supplies no cross-work-group fairness guarantee. The report appropriately avoids claiming an Intel/Xe2 global barrier, but an extension claim should name the exact extension, release, and device; absence of one in the reviewed guide is not proof that no implementation-specific mechanism exists.

Corrections to apply prospectively in the index/retrieval digest:

- **R1028-C1 — local recurrence equation.** The report's illustrative update `S' = λS + βk(v−kᵀS)` is a valid affine recurrence, but it does not match the pinned local kernel as written. `fused_gdn.cpp` computes `proj=kᵀS`, `delta=β(v−λ·proj)`, then `S'=λS+k·delta`; for that source, `A=λ(I−βkkᵀ)` and `B=βkvᵀ`. Keep the equation explicitly schematic, or use the source-matching equation. The local source is not a SGLang/vLLM model contract or evidence that a scan is used.
- **R1028-C2 — affine composition cost.** “General composition is state-dimension-squared” is ambiguous if read as work complexity. For an `K×V` state with dense `A∈R^(K×K)` and `B∈R^(K×V)`, an aggregate map stores `O(K²+KV)` coefficients and dense composition costs `O(K³+K²V)`; applying it costs `O(K²V)`, while one rank-one sequential update costs `O(KV)`. A flattened dense `D=K·V` map is larger (`O(D²)` storage and `O(D³)` composition). State any cheaper structured monoid separately and derive it. Associativity in exact arithmetic does not make reassociation numerically equivalent.
- **R1028-C3 — SYCL atomics and extensions.** Add the §3.8.3 caveat that the formal memory model remains in progress; query the exact device/context order and scope capabilities before treating device-scope publication as available. Distinguish core command dependencies from optional graph support. Do not imply an Intel grid-barrier extension without a named, versioned contract.
- **R1028-C4 — cancellation and reclaim.** State that a host deadline alone does not cancel submitted device work. Preserve storage until event/queue completion or a documented backend abort/reset has completed; a timeout flag only helps work-items that run. The report's reset recommendation is backend-specific, not a portable SYCL guarantee.
- **R1028-C5 — CUDA cooperative sizing citation.** Keep the occupancy/grid limit and oversize failure tied to the CUDA 13.2.1 Driver API entry for `cuLaunchCooperativeKernel`, in addition to Guide §4.4.8; the latter alone does not state the numeric limit in the reviewed HTML.
