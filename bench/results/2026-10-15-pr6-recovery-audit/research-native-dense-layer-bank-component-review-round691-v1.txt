## Source findings

I found no concrete component source defect in the requested ownership and transition paths, subject to the explicit `ReaderRetirement` assertion being truthful and exclusive. Startup snapshots the exact packed bytes while each GGUF mapping is alive, checks shape/type compatibility against the canonical row, and keeps pending owners private until all preparation succeeds. Budget rejection or ordinary allocation failure before publication leaves the table untouched. Captured RAM payload is bounded by the configured limit; metadata is additional as the proposal states.

The Full→Bank transition validates all rows first, allocates the bank while full owners are live, withdraws every affected row (including canonical `data`) before freeing original native owners, and fail-stops on uncertain free status. Layer activation builds a complete private overlay and validates extents before replacing the old view; after the old reader boundary, upload completion is checked before publication. Full restore allocates all owners before uploading or changing the table, keeps the bank/view on ordinary OOM, republishes each saved row only after upload and identity checks, and fail-stops on uncertain copy/free outcomes. Updated `original.native_data` is carried into the next Full validation, so the second enter/restore address change is accounted for. Destruction in Bank state fail-stops before member owners or snapshots can be released.

The component enforces its declared contract through state checks, non-null stream checks, table identity checks, and the required retirement token. It cannot establish that external graphs/callbacks were actually destroyed or prevent a caller from lying with `{true}`; this is explicitly assigned to integration. R689's `SessionGraphs` and PLE pointer findings remain material integration blockers. In particular, `ss.ple.w.key_native_data` needs explicit rebind, and session graph teardown/recapture remains outside this component. The returned active map is only a native projection overlay; the integration must compose it with canonical rows and preserve canonical norms.

## Fixture coverage and remaining gates

The unexecuted fixture is useful because it links the proposed implementation to production GGUF/WeightTable/MMVQ/runtime code and independently reopens each source shard. It checks all 300 target tensors' packed source bytes and metadata, device payloads before/after transitions, provenance fields, computed RAM/bank sizes, missing retirement rejection, invalid-layer nonpublication, all target layers, full restore, and a second enter/restore with changed allocation addresses. It does not use mocks or claim a run occurred.

Its zero-budget test rejects on the first candidate before any owner is allocated, so it does not demonstrate rollback after several pending uploads. It also does not inject allocator failures at later restore indices or exercise subprocess fail-stop paths for copy, drain, or free errors. Those are correctly identified as separate qualification gates in the proposal. The fixture's one `PACK_DIR` invocation does not itself establish both canonical skipped and resident configurations; run both exact configurations as a later gate. It also does not validate actual graph destruction/rebind/recapture, cancellation/exception/callback recovery, decode continuation, RESTORE-and-continue, physical 262144-context buffers, numerical/task quality, or speed. These omissions are not component defects and do not qualify the component for adoption.

Disposition: source review finds no blocker within the stated NativeDense ownership/component boundary. Keep the proposal source-only until Main performs serial compile/link and the listed fault-injection and lifecycle integration gates; make no inference adoption claim from this review.
