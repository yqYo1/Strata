Disposition

The v2 proposal's core q=2/q=4 aggregation is internally consistent with the current serialized layer-major route path. Source pins in `layermajor-wave-census-v2/pins.json` match the current root files (`layermajor_shape_census.hpp`, `layer_major.inc`, `prefill.cpp`, and the v1 validator); `source.diff` is additive to the census header only. I found no arithmetic or hook-order blocker to CPU qualification. The strongest evidence is the direct hook correspondence: `prefill.cpp` calls `counts(l,T,cnt,512)` after extracting all `T*K` route IDs, then invokes `issue(true,...)` and `issue(false,...)` once per active expert in the compact FP16 expert loop; `layer_major.inc` publishes the complete temporary map `residency[layer*512+e]=e` only after all 512 blobs have been uploaded and drained, then calls `begin` with that layer's slice. The census's `cache_slot==expert` and `ring_slot==-1` expectations match this path. The issue callbacks are before the associated GEMMs are enqueued, but `end(layer)` occurs only after `run_impl`, queue drain, and chunk-cursor completion, so the counters describe successfully issued shapes only if the enclosing pass completes; they are not device-completion telemetry.

Exact q2/q4 union accounting

At each `counts` call, the proposal adds each nonzero `cnt[e]` once to both pending windows. This is the chunk-expert incidence count, not token incidence. The window's 512-bit mask tracks whether that expert appeared anywhere in the request-relative group, while `ne[e]` accumulates the actual routed rows for that expert. On flush, mask presence must equal `ne[e]!=0`; `union_sum` adds the unique expert count; `active_incidences` adds the number of active experts in each constituent chunk; and their difference is duplicate expert-chunk incidences beyond the first appearance. `expert_rows` is checked against `10*window_tokens`. q2 resets every two chunks and q4 every four, so both partitions start at chunk ordinal zero independent of nonzero `pos0`. A short last chunk and a partial final wave are represented separately; q4's partial tail may include complete chunks plus a partial chunk, and `partial_tokens` uses the actual request remainder. End-of-layer checks tie wave count/tail, all expert rows, total incidences, histogram mass, and empty pending windows back to the current layer totals.

The independent references are meaningfully separate from the observer's mask/histogram implementation. `cpu_fixture.cpp` builds per-wave `std::set<int>` and `std::map<int,uint64_t>` references from synthetic token routes, then compares union, rows, duplicates, min/max and bins with the C++ observer. The serializer fixture has a separate Python `set`/`Counter` reference over the same declared synthetic routes and checks all 48 serialized layer records, including old histograms and row totals. This is enough to test aggregation/serialization independently of the C++ bitset; the synthetic route distribution is intentionally sparse and regular, not a model-like route distribution or evidence of real overlap.

Expert-ne issuer qualification

For each chunk, expected expert bits and `expected_ne[e]` come from the route histogram. GU and Down have separate seen masks, so they may issue in different expert orders but each must issue exactly once for each expected expert, with exactly that expert's `ne`. Wrong/inactive expert, wrong `ne`, duplicate role call, missing role call, and remaining pending `ne` buckets fail closed. The root path calls hooks only inside the compact non-MMQ FP16 expert compute lambda; layer-major admission pins compact FP16 and disallows threaded issuing, and `begin` additionally records the required serialized/single-GPU conditions. This qualifies the CPU issuer's selected `(role,layer,expert,ne,slot)` calls, not kernel success per individual expert; the enclosing successful `run_impl` and final checked drain provide that boundary.

Geometry, checked arithmetic, and completion checks

The proposed constructor accepts `n>0`, `n<=262144`, nonnegative `pos`, `pos+n<=262144`, and `0<chunk<8193`; this covers source chunks through 8192 and rejects the physical absolute-position overflow case. The fixture cases cover n=1, partial q2/q4 waves, a final short chunk, nonzero positions (including `pos+n==262144`), exact n=262144, and the 16384/32768 `ne` bin boundaries. Multipliers are bounded by constructor-validated geometry or explicit format bounds. `add()` checks 64-bit counters, wave row accumulation checks uint32 before adding, histogram weighted products check before multiplication, and output writes are preflighted against the retained 1 MiB cap. The output contains all 48 layer records, q2/q4 summaries, a schema/grouping marker and `complete:true` only after a full pass. The additive Python wrapper calls the original `validate_census` first, preserving the production gate for actual model metadata, `position==0`, `chunk==4096`, exact model type/row geometry, 512-slot census, and original issue conservation. Generic synthetic `validate_wave_fields()` intentionally supports other geometries but is not a replacement production validator.

Concrete contract/test caveats

1. The v2 header retains the v1 `Writer` behavior: it serializes `"complete":true` in the final text, calls `fwrite` through `Writer`, then calls `fflush`; if `fflush` fails after the writer's puts succeeded, it sets `failure="output_io_incomplete"` but cannot retract bytes already written. The CPU fixture's `/dev/full` test makes the stream unbuffered, so the failure is caught by `fwrite` before a complete record can be emitted. It does not exercise a buffered stream where the error arrives only at `fflush`. This is inherited from the pinned v1 header rather than introduced by wave aggregation, but the README/comment's broad statement that a failed writer cannot emit a valid completion token is only covered for write-time failure. Main's collector still needs the process/census-completion receipt and exactly-one-complete-line gate; if strict I/O fail-closed semantics are required, add a buffered-flush failure test or make the final success marker independently durable/observable before relying on it.
2. `validate_wave_fields()` strictly type-checks new wave scalars, but it compares layer summary integers (for example `layer['gu_calls']`, `layer['chunks']`, and `layer['tokens']`) with ordinary Python equality, which accepts booleans/floats numerically equal to integers. The production wrapper also invokes the old validator first; source-generated JSON is integer-only, so this is a malformed-input hardening gap, not a current C++ arithmetic bug. A small negative test for bool/float summary fields would make the validator contract clearer.
3. The output-IO fixture asserts internal `failure` after `/dev/full`; it does not by itself prove the caller notices that failure, because `complete()` returns void and the enclosing `run_layer_major` returns success after calling it. In the normal runtime `stderr` is ordinarily unbuffered, but the report/collector must continue treating the completion JSON—not inference return status—as the evidence gate. This behavior is also inherited from v1.
4. The five serialization fixture geometries stay small in layer histograms (and compact in JSON); they test the 1 MiB cap through a forced overflow record, not a near-cap successful 262K report. The v2 proposal keeps the old preflight/cap unchanged and does not need raw route IDs, but Main should inspect actual serialized byte length in the eventual model diagnostic, since the new fixed wave arrays add bytes to each of 48 layers.

Remaining limits

- Synthetic n/position=262144 checks arithmetic and absolute geometry only. It is not a full physical-context QSA/KV/model fit, cache residency measurement, RESTORE, or GPU proof.
- The `hardware_cache_residency_measured:false` field is accurate: the route observer confirms the temporary layer-major cache is configured with 512 IDs, not hardware cache hits or reused compute.
- Wave union counts estimate repeated per-expert calls that could be grouped in a hypothetical wave. They do not report dequant reuse, grouped GEMM speed, H2D bytes, successful admission, or saved latency.
- No tests were executed in this audit. The prescribed serial host qualification still needs to compile the pinned fixture with assertions enabled, run normal and sanitizers, compare C++ and Python summaries, exercise malformed validator cases and I/O failure, and verify input hashes before any model census.
