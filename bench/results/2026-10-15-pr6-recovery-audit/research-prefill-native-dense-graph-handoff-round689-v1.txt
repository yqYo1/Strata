# NativeDense graph handoff for long prefill (R689)

2026-10-15 JST. Read-only source-confidence audit of the configured SYCL generator graph/lifetime seam for a future long-prefill NativeDense layer bank. No product source was changed; no build, test, GPU/process query, Git/branch operation, cleanup, or runtime claim was made. Scope assumes the canonical arena remains resident (1,538,035,200 B) and seeks to free/reuse only target `NativeDense` per-layer matrix allocations plus their shared scratch. This report does not recommend changing kernel arithmetic or the prefill schedule.

## Finding: current layer boundary is insufficient

`NativeDense::load` publishes each native matrix as `WeightRef.native_data`, its GGML type, and the same shared `native_q8_1` scratch pointer (`src/core/native_dense.cpp:71-189`). `NativeDense` owns only the allocations in `weights_` and `scratch_`; its destructor frees them but does not clear published table fields (`:66-69`, `include/strata/core/weights.hpp:88-94`). The new component APIs must therefore publish/revoke pointers as an owner transaction and preserve canonical `WeightRef.data`/metadata. The canonical arena is out of the reclaim scope.

`Prefill::run_layer_major` has a valid local pass seam: dispatch only when layer-major is enabled and `n > T` (`src/prefill/layer_major.inc:3-14`); per-layer expert load and `stage_lb_/stage_le_` assignment happen at `:292-333`; the layer pass then completes before the next iteration. It performs checked drains of `m.cs` and `m.copy` at entry, layer boundaries, uploads, and pass completion, with a fail-stop guard if retirement is unknown (`:~210-290,292-319,374+`). That proves only the queues covered by this local boundary and callbacks that have returned. It neither destroys `generate.cpp`'s persistent target-weight graph executables nor blocks later verifier/session graph launches. The optional NativeDense bank must not free a just-used native pointer merely because this local drain succeeded.

## Concrete readers and capture owners

1. **Ordinary `SessionGraphs` are the main blocker.** In configured SYCL serve, startup captures them before cache sizing when `o.expert_cache < 0`, capture is enabled, and `!(native_pack && o.spec >= 2)` (`src/program/generate.cpp:3091-3103`). The SYCL configured path routes normal execution through per-layer `session_capture`; `session_capture` invokes `block_layer_pre/post` (plus optional route/shared and split-prefix forms) for every requested layer and instantiates each graph (`src/core/session.cpp:191-354). Those block calls resolve the same `wt`/`WeightRef` native fields used by direct layer kernels, so graph node arguments can retain native projection pointers and the shared scratch. Include `gr.execs`, `gr.posts`, optional `gr.routes`/`gr.shared`, and split arrays `preA`, `preB`, `preP[0..4]`. The code comment at `generate.cpp:3093-3096` only says these graphs have no **expert cache-slot** pointers; it does not mean no model-weight pointers. They are later replayed in ordinary token service. `session_graphs_free(gr)` destroys this set near normal teardown (`generate.cpp:7421`, `src/core/session.cpp:580+`); that is too late for prefill release. During the release interval, destroy all of them after owning stream drain, prevent replay, then recapture only after the complete native decode set has been restored and republished. A failed recapture must stop decode or take a demonstrably safe no-graph route.

2. **Token graph:** `session_capture_token` captures calls for all layers, but explicitly refuses SYCL (`src/core/session.cpp:1035-1041`). The configured SYCL serve has `no_token_graph = true` (`src/program/generate.cpp:480`) and SYCL's ordinary path uses layer graphs. Thus the token graph is not an active target native reader in this configured mode; retain a capability guard so another backend/mode cannot enter the release path with `tgraph.captured`. Do not destroy unrelated cache residency hit tables/graphs merely because their name contains graph: they hold expert-cache slot pointers, not target NativeDense weights, and existing target layer graph teardown does not imply those buffers should be touched.

3. **Verifier full/window/work/segments:** A `Verifier` stores `wt_` and records full target layer operations in `record_window` (`src/core/verify.cpp:534-540`); lookup then forms native calls from those `WeightRef`s (e.g. native expert and attention projections at `:618-620,712-727,756-757,791,847`). In SYCL, `capture(T)` stores each window as `segments_[T]` graph execs, and optional overlap work in `work_[T]`; `end_segment` instantiates each (`:1099-1117,1121-1153`). The retained full `exec_[T]` is the non-SYCL branch. `commit_exec_`/commit work represents session-state commit, not target projection kernels; it can remain only if its own lifecycle remains valid and it does not point at native weights. Current head-release APIs provide a useful pattern: eligibility checks idle/inactive-or-completed full single-device verifier (`can_release_prefill_head`, `:218-229`); retirement waits commit, drains `cs_` and `copy_`, then destroys `exec_`, all segments and work graphs (`:231-256`); resume lets windows recapture lazily (`:258-264`). But head retirement is not a NativeDense lease and must not be assumed to run for target native weights. In ordinary batched prompt call the verifier is already present and passed to `run_prompt_with_mtp_experts` (`generate.cpp:6005-6009`); window prompt routes (`read_windows`) can use verifier graphs and must be excluded from the layer-major NativeDense-bank capability. Conservative eligibility: no verifier graph can be launched or retained with target native pointers during the whole long-prefill transaction, unless a dedicated checked retire/rebind API drains and destroys every such reader. Restore then recapture lazily or fail before verifier resumes.

4. **MTP prompt callback:** In ordinary serve setup, MTP binds to target `wt` and installs `prefill.on_chunk`; each completed prompt chunk tries `Prefill::draft_kv`, falling back to `mtp.prefill` (`src/program/generate.cpp:6510-6520`). These functions consume the final residual and MTP-owned K/V/model state. `MtpDrafter::record_forward`'s `wt_` lookup in the inspected route is `token_embd.weight` (`src/core/mtp.cpp:790-821`); when `NativeEmbed` is registered it gathers from that separate owner (`:813-814`), otherwise it reads canonical `we->data` (`:815-820`). MTP's `fc_*` and remaining projection helpers resolve the MTP model's own `dense_`/`q8`/`f32` owners, not target layer matrices. Its prefill graphs (`prefill_exec_`, `prefill_dev_exec_`) capture this MTP K/V-only forward (`:1027-1043`); round/step graphs capture MTP full draft work and its own head/experts (`:1045-1125`). Do not retire these just to free target NativeDense. They may stay only under a capability check proving no MTP reader resolves target NativeDense fields. `draft_kv`/`mtp.prefill` callbacks must finish before a bank slot is reused because they borrow the current residual and update MTP K/V, but their current source path appears not to dereference target per-layer native matrices. Keep MTP's own `dense_`, graph state, `NativeHead`, and target embedding source alive. Canonical `token_embd` and `NativeEmbed` are outside the target-native matrix bank.

5. **Direct readers/captured non-session helpers:** The long layer-major pass calls direct `run_impl` kernels with the selected active-layer view; the special layer-1 PLE native key is separately published into `ss.ple.w.key_native_data/type/key_native_q8_1` (`generate.cpp:2429-2438`) and therefore is a captured session-graph reader as well as a direct layer reader. The active view/rebind operation must cover/repoint that PLE native key for layer 1. Direct prefill logits and MTP callbacks are installed at `generate.cpp:6523-6571`; prefill-logit head uses canonical output/head owners, not per-layer NativeDense. Canonical HC lookahead norms and all other `WeightRef.data` fields remain valid because the canonical arena stays resident. Preserve original target PLE canonical fields, `ss.ple` values/norms, `NativeEmbed`, `NativeHead`, output/head, and nextnorm source ownership; do not alias them to a released native bank.

## Minimum guard and order for Main integration

The smallest safe integration is a transaction around the **whole** long layer-major call from the two existing serve callers in `generate.cpp` (batched request around `:6575-6579`, read/continuation around `:6005-6009`) and the view selection inside `layer_major.inc`. Do not try to detach a native layer after each local layer pass while shared decode graphs still exist.

1. At the caller, admit only the exact full-model, single-device, configured native compact FP16, long layer-major route already enforced in `layer_major.inc:~35-70`, with `n > T`, compatible native source and MMQ settings, and no split/peer/remote/diagnostic/window route. Additionally require a full validated NativeDense owner, no active or captured `TokenGraph`, no live verifier graph (or a new verifier retirement lease), no concurrent token/session graph replay, and an intact complete canonical table/NativeEmbed/PLE/session owner set. Short prefill must keep the current shared decode table and resident weights, with no detach.
2. After setup and before freeing any target native payload, close admission to decode/replay for this request; check the capability conditions; drain `main_stream`/any direct owner stream, all relevant session execution streams/queues, verifier compute and copy queues, and any pending MTP callback stream. Use checked status, fail-stop while owners remain live if completion cannot be proven. The existing layer-major `m.cs/m.copy` drain is later and does not replace this acquisition drain.
3. Destroy all target-weight-bearing `SessionGraphs` sets listed above and the verifier window/work segments through owner APIs. Do not rely on `session_graphs_free`'s unchecked general teardown for this transition; make destruction checked and clear captured/readiness state so no replay path can use stale handles. If any unrecognized captured reader exists, refuse the optimization.
4. Through new `NativeDense` component APIs, retain original packed/source identity and metadata and construct a full-restorable native owner contract; revoke only `native_data/native_type/native_q8_1` table publications and PLE native publication under exclusive admission; then release the old target native payload. Keep canonical `WeightRef.data` and session/KV/GDN/QSA state unchanged. For the layer pass, select an immutable per-layer view and native scratch compatible with current operators, including layer-1 PLE key; preserve the persistent fused lookahead canonical norm references. Avoid mutating canonical pointers or arithmetic.
5. For every early return, cancellation, callback error, source/allocation/upload failure, or exception, keep source/destination allocations live until layer-major's checked drain and callback unwind complete. Clear the temporary active view; rebuild/publish the **entire** NativeDense owner and PLE native pointer set from validated original source before returning an ordinary error or allowing decode. If any restore/drain/publication fails, fail-stop with pointers/allocations retained; never expose a partial table. This applies whether callback MTP work is retained or intentionally gated off. `run_layer_major`'s local `Restore` restores borrowed fields/callbacks, not model weights or session tensor state (`layer_major.inc:~235-267`), so weight rollback is separate.
6. On normal completion, drain prefill/callback streams, clear the per-layer prefill view, restore all target NativeDense allocations and table/PLE publications, validate complete owner/pointer coverage, then recapture session graphs against restored pointers and allow verifier to lazily capture. Only after successful recapture may ordinary decode or conversation/session RESTORE proceed. If restoration/recapture cannot complete, stop before decode/RESTORE continuation. Normal teardown must still destroy these restored graph owners before `NativeDense` and arena destruction; source declaration order and error exits need review.

The layer-bank capability guard should be a single explicit predicate/state check at `generate.cpp` request dispatch, with API-enforced exclusive state in `NativeDense`/reader owners; the existing `STRATA_PREFILL_RELEASE_HEADS` boundary is not a suitable substitute. That boundary synchronizes `main_cs`, retires verifier head graphs, and calls `mtp.retire_prefill_head_readers` (`generate.cpp:~198-245`), but it never destroys `gr.execs/posts/routes/shared` and head checks are not a proof that every target NativeDense projection/scratch pointer is gone. It also leaves live handles for future recapture and only models NativeHead/MTP head bytes. Counterexample: start ordinary serve with `o.expert_cache < 0`, capture `SessionGraphs` at startup, run the head-reader pause and free target native layer 0; `main_cs` is idle and verifier/MTP head readers are retired, yet `gr.execs[0]` or split/route graphs remain callable with the old layer-0 `native_data` and shared scratch addresses. A later normal session graph replay dereferences stale pointers.

## State and scope that can remain

Session KV, GDN/QSA/PLE recurrent state, residual/session buffers, doorbell, expert cache residency maps/graphs, and canonical metadata/payload can remain if their graph nodes do not capture NativeDense addresses. The fact that session tensors remain live does not make compute graphs safe; graph destruction must be separated from state destruction. Existing native-hit graph state is expert-cache plumbing; its device residency table and expert slot addresses are not target dense pointers. `NativeHead` output, `NativeEmbed`, target canonical embedding/PLE values, target nextnorm canonical refs, and MTP's distinct draft-native weights/scratch are separate owners and remain live. MTP `draft_kv`/callback needs to finish before residual reuse even where it does not read the target bank.
