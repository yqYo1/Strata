## Finding: the proposed persistent owner has a larger, explicit payload boundary than the existing 16 MiB allowance

`canonical_persistent()` classifies every non-layer row as persistent, both HC norms on every `blk.<layer>`, and every `blk.1.ple_*` row (`proposed/include/strata/core/canonical_bank_policy.hpp:24-26`). `adopt()` puts all such rows into `persistent_offsets_`; each is rounded to 256-byte stride, then `prepare()` allocates one persistent GPU pool and uploads every row before layer retirement (`proposed/include/strata/core/canonical_dense_bank.hpp:98-116, 123-140`). Thus its private pool includes the output HC tensors, all 96 layer HC norms (3,932,160 B raw per R707/R712), and captured canonical PLE payloads such as value/norm/conv. If the three output-HC tensors are retained as canonical rows, their 13,148,160 B plus all norms alone are 17,080,320 B before PLE payload and alignment. That already exceeds the 16 MiB small-owner placeholder; this is a concrete budget incompatibility if the current capacity table is used unchanged, not proof the proposed pool cannot be separately budgeted. The actual pool size is computable at startup from `persistent_bytes()` but has no admission check against that capacity receipt/placeholder. The proposal must carry its actual persistent-pool byte count into the memory plan before using the receipt's 6.8244 GiB as available KV/hidden budget. This extends R712's warning that the proposed persistent PLE/HC pool needs its own budget; the source categorization explains why it is materially above that bucket.

The R712 lookahead case is covered structurally: `LayerView vn(*m.wt, nl, ...)` reads the next layer's `hc_attn_norm.weight` when fused (`prefill/prefill.cpp:3114-3124`). Since every such norm is in the persistent view merged into every active layer overlay, layer `l+1`'s norm can be resolved after its ordinary layer bank bytes have not yet been activated. The concern is its lifetime and budget, not a missing next-layer resolver. No model run confirmed this execution path.

## Resolver and reader flow

* Startup capture is tied to the loaded `WeightTable` and exact arena. `adopt()` rejects native originals that overlap canonical rows, validates captured bytes/metadata, builds per-layer and persistent offsets, and records the canonical owner/table (`canonical_dense_bank.hpp:61-120`). The layer activation callback first activates native rows, then passes that native `layer_view()` to `CanonicalDenseBank::activate()`; the resulting overlay combines persistent canonical rows, current-layer canonical rows, and native rows (`generate.cpp:365-373`; `canonical_dense_bank.hpp:156-165`). `LayerView` is used on each current layer (`prefill.cpp:2093-2097`) and also on the lookahead layer for fused HC norm (`3114-3124`). In source this provides one lookup namespace for canonical/native rows; collisions are rejected. The current implementation's per-layer compact bank omits persistent rows by design, while canonical active view merges them.
* All six PLE fields are accounted for by the transition. The PLE key is looked up from the combined overlay when layer 1 runs; for a native key, the `native_type >= 0` branch requires and binds its native data/scratch; for a canonical key, it requires a resident canonical row and binds BF16 or quantized planes (`prefill.cpp:1710-1736`). Persistent binding separately requires `value`, three norms, and `conv1d`, resets canonical key pointers, and explicitly leaves native-key fields to the NativeDense phase (`canonical_dense_bank.hpp:187-204`). The caller clears native key pointers before releasing the native owner and restores them from `WeightTable` after full restoration (`generate.cpp:320-341, 358-363`). The mixed native-key/canonical-PLE distinction is therefore represented in source rather than relying on the stale startup `PleWeights` pointers. The active layer 1 view is needed for a native key; the persistent canonical PLE projections are available for all chunks.
* The proposal requires `native_embed()` before entering the phase (`generate.cpp:288-291`). Prefill's embedding paths choose `NativeEmbed` and avoid `wt.find("token_embd.weight")` when it is available (`prefill.cpp:1062-1065, 1818-1827`); otherwise they fall back to canonical token embedding. Hence an absent/zero-payload canonical embedding row is compatible only under that enforced independent reader. This check is scoped to the transition entry; the source review did not establish `native_embed()`'s object lifetime or exercise MTP's entire prompt path.
* `NativeHead` is not banked by this proposal. The long-prompt transition runs the existing `run_prompt_with_mtp_experts` callback inside the dense transaction, and then restores canonical and native full owners before returning (`generate.cpp:265-270, 375-377`). The feature's trigger requires a prompt longer than its chunk; short prompts bypass it (`270`). In verifier source, an output-HC consumer reads all three `output_hc_*` rows by base `WeightTable` at the final/head boundary (`verify.cpp:1111-1125`), and MTP's embedding reader uses NativeEmbed when available (`prefill.cpp:1062-1065`). Canonical non-layer rows are kept resident in the persistent pool during the transition; after restore, the base table is republished to the restored arena. This supports the intended reader split by inspection, but no long-prompt MTP/NativeHead lifecycle was executed here.
* Captured MTP/decode commit readers need explicit retirement before canonical rows are withdrawn. The caller requests `retire_prefill_canonical_commit()` when a verifier exists and aborts if it cannot retire, then restores before graph recapture/resume (`generate.cpp:352-356, 329-345`). The new verifier routine drains the stream and destroys the norm-bearing commit graph (`verify.cpp` diff hunk; source.diff lines 353-368). This is an explicit source contract; no MTP, verifier graph replay, restore, or recapture behavior is runtime-qualified by this review.

## Duplicates, nulls, and contract boundaries

The canonical/native overlap rejection in `adopt()` is sensible for rows served by native overrides: native compact skipped rows must remain metadata-only (`WeightRef.data == nullptr`, `resident == false`), while the native owner is injected into the active overlay. A skipped native row may still exist in `WeightTable`; this is not a missing canonical layer row. `bind_ple()` permits `key.data == nullptr` as long as the PLE canonical projections are present, and the caller restores a native key separately. That null is intentional when the model's PLE key is served natively. For an unquantized canonical key, the code keeps/copies it in the persistent canonical owner.

The three `output_hc_*` payload rows are distinct from `output.weight` and `token_embd.weight`; the latter may be metadata-only and have zero arena payload when NativeHead/NativeEmbed serve them. The code should not treat `output_hc_*` as redundant with NativeHead: verifier reads them for `lm_head_mix` even when a NativeHead is loaded (`verify.cpp:1114-1124`). They are therefore retained among non-layer canonical rows by the generic non-layer classification. R707's independent 13,148,160 B correction remains applicable.

The low-level row classifier accepts only numeric layers 0–47 for names beginning `blk.` (`canonical_bank_policy.hpp:14-22`). This is a model-specific contract, not evidence that arbitrary GGUF architectures are supported; startup preconditions elsewhere must continue to constrain this feature to the expected 48-layer model. No new concrete resolver omission was found in the reviewed supported path.
