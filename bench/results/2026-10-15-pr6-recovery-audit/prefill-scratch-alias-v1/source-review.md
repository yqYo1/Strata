## Proposed behavior

Set exact `STRATA_SYCL_PREFILL_SCRATCH_ALIAS=1` in the native child's environment before exec. Absent/exact `0` retain original reference allocation layout and conservative sizing; every other spelling is rejected (including empty, `01`, `true`). Non-SYCL `1` is rejected. The immutable cached mode is shared by init and count-only sizing; invalid sizing throws `std::invalid_argument` before any planner take; invalid init returns false before any allocation/submission. No environment switching occurs.

A single guarded N-wide FP32 allocation backs `emb`, `mixed`, `bo`, `ple_emb`. This topology is independent of prompt length, chunk-major/layer-major dispatch and compact-MoE selection. There is no fallback arena. `R`, all mixed half/BF16/low buffers, residual outputs, attention/MoE region, stage buffers and draft_kv temporary allocations remain distinct. `take_scratch_prefix` is the actual production planner used by owned carve, borrowed carve, relayout and enabled count-only sizing. The tail PLE take is omitted in both enabled layouts and sizing. Guard accounting uses Alloc::take unchanged. Each alias in owned mode has one owner/free, and borrowed mode has one shared offset.

Enabled init rejects peer-portable topology, attached peer, split stage and handoff before allocations. It requires an explicit SYCL queue and validates its in-order property before allocations. SYCL init binds `copy=cs` and Gemm binds the same explicit queue. `set_peer` rejects later valid peer attachment before peer allocations. Relayout rejects topology changes before its stream drain; run_impl rejects changes before its first submission. Layer-major's internal stage range updates are explicitly permitted only while `layer_major_active`; its existing admission rejects external peer/split/handoff/reentry. A rejected topology never switches to a larger successful layout. Threaded weight issue can submit only disjoint stage buffers; it does not consume these four aliases.

## Read/write last-use proof (base source line numbers)

* Chunk start, `1715–1752`: native gather, quantized gather or individual image/token row uploads write emb on cs; `gr_broadcast(emb,R)` is its final read before any layer work. Residual-input paths skip emb entirely. All later writes are after that broadcast in the same in-order queue. Async host upload source ownership remains unchanged.
* Attention half, `2062–2113`, `2307`: gr_mix[_r] writes mixed plus independent mixed_h/BF16/low outputs. Projections consume the half/BF16 buffers, never FP32 mixed as oneMKL input. GDN output projection reads y_h; QSA output projection reads attn_h; both write bo. These inputs are in the separate attention/MoE region. Thus no oneMKL operand overlaps its output. SYCL multiply also retains its production validate_spans checks.
* FFN half, `2327–2373`, `2519–2540`, `2891`: router/shared projections consume distinct mixed_h/BF16/low. Fused activation quantization and MMQ quantization consume FP32 mixed on cs before experts and final combine; FP16 experts gather mixed_h. Their derived activations and expert outputs are in the separate region. `moe_combine(...,bo)` at 2975 is after every same-queue FP32 mixed read. Peer copy at 2554 is intentionally unsupported by admission rather than assuming an independent stream completes soon enough.
* Each half, `3017–3021`: gr_write_norm_rs/gr_write consumes bo into separate live R before next half/layer gr_mix writes the shared slot. SYCL gr_write launches an ordered kernel which reads bo and writes R (postops.cpp 171–187); the fused form then queues norm. There is no outstanding scatter from bo: routed gather/scatter and combine write Dm/bo, then this GR write is its last consumer. Optional audits/debug readback occur before the GR write and before next shared-slot write.
* PLE, `1753–1786`, `1989–2045`: ple_land queues upload only at l=max(LB,1), after layer 0's final GR write when LB=0. The only device reads are the l==1 PLE block, before l==1 attention gr_mix. Batched PLE converts its FP32 input into e16 and performs GEMMs using separate region buffers; token PLE reads FP32 rows before the subsequent GR-mix. All PLE sub-batches/rows are enqueued before that next write. Later layer-major passes may upload unused PLE rows; these too are ordered before mixed, and no later PLE consumer exists. This proof covers short chunk-major, T-sized prompts, multi-chunk, long layer-major, tails, PLE off, batch and token PLE. Host futures/ple_emb_host[2]/ple_copied source events are unchanged and distinct from the device slot; host prefetch never writes it directly.
* Callback/MTP, `975–1148`, `3085–3093`: observers receive R after stream synchronization. draft_kv uses separate temporary region buffers, R and independently allocated MTP state, synchronizes before returning, and never accesses these four fields. Next-chunk embedding is ordered after all prior consumers. No new graph capture, event lifetime assumption, hidden driver reuse or synchronization shortcut is introduced. Cancellation/throw retains existing owner cleanup; its runtime verification is pending.

The source guards reject unsupported peer/multigpu/split/handoff instead of trying to inherit long-route admission for short fallback. Fullalias is justified by the actual PLE-only-at-layer-1 condition, not by the R685 suggestion alone.

## Capacity accounting and limits

For actual carve C8192, three removed takes save `3*(83886080+256)=251659008 B` (240 MiB payload plus 768 B Alloc guards). Owned allocations remove three malloc/free pairs; borrowed carve shortens the occupied span by that exact number. This is source arithmetic, not actual free VRAM or throughput evidence. It is additive to Main's already-present zero SYCL GEMM_WS, not another workspace deletion.

Existing OFF bytes_needed is conservative: its leading prefix counts a full T*D allocation where actual carve counts optional xn plus T*HC grs. OFF preserves those exact old calls as requested. Enabled sizing uses the real shared prefix planner, so its count delta versus OFF also removes that old conservative discrepancy; do not report the full OFF/ON bytes_needed difference as alias payload savings. Existing count-only fused_layout(T,true) versus carve's src-dependent region can still conservatively size the common region; its allocation sequence is unchanged, and the shared aliases never enter it. Enabled scratch prefix/tail take order and guards are identical for all owned/borrowed/relayout/count consumers.
