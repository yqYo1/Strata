# Whole-journal request input identity utility v1

SOURCE ONLY / NOT_TESTED / NOT_RUN. Only this new directory was written. Main runs host checks after its measurement lock is released. Existing client, running benchmark, journals and original statuses are unchanged. Author performed no tests/py_compile/Git/build/GPU/process-control/cleanup actions.

Interface: python3 -B compare_requests.py LEFT RIGHT NEW_REPORT.json. Each input is a suite directory or its requests.jsonl. Output is exclusive-create even for a failed comparison: existing reports are never overwritten. Exit0/REQUEST_INPUTS_MATCH means all journaled request inputs match; exit1/FAIL records validation or ordered-input differences. It does not certify native closure, source/configuration parity, model quality, speed, adoption, or physical context. An uncaught I/O/budget error remains nonzero/incomplete, never PASS.

Each journal is bounded to8MiB and2048 total rows; state is bounded to64KiB. The utility copies the exact bounded journal/state bytes into its own private temporary directory and calls the real tools/strata_bench.py verify_request_journal there. This avoids that verifier's whole-file read bypassing the budget if an original file grows concurrently. Original source bytes are checked again for stability. Snapshot files contain original bytes, not invented completion receipts; only the utility's transient copies are retired. No source journal/state/result is written. Original journal/state hashes, byte counts, verifier result and verifier source hash remain in the report. Report output is bounded to4MiB; overbudget fails incomplete.

Validation requires the full hash chain and terminal complete state, no pending requests, exactly one initial identity row, only identity/start/result rows, valid actual body SHA256 and request parameters. Interrupted/incomplete or missing/extra/duplicate/reordered/mismatched starts cannot pass. Duplicate means repeated phase/run/turn key within one suite, even if the bodies differ. Identical bodies under distinct intentional request keys are allowed but still all compared. Missing body hashes or max_tokens/thinking are rejected rather than inferred. Phase length is bounded256 and run/turn/parameter integers are bounded to signed64-bit magnitudes.

No phase filter exists. Every start is compared in its original order, including warm-up, calibration, short chat,4K/16K/32K prompts, all agent turns, long-generation requests and any client phases present. Each report sample includes both source journal indices, both phase/run/turn keys, both max_tokens/thinking, both actual request_sha256 and every differing field. Missing/extra positions retain the available side and null for the other. Same-count reordering fails too. Identity metadata/source hashes/nonce fields are not compared: old and new clients can differ there while issuing identical inputs. Full journal hash chains still protect those identity rows against tampering.

This utility proves request inputs only.
