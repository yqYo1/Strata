# QSA device-batch v2 seed/boundary source review (R695)

2026-10-15. Read-only review on `feature/sycl`, Arc B570. No source was
applied, compiled, built, tested, run on GPU, or otherwise modified. No process
or environment was changed. Main's serial scratch-alias comparison remains
outside this review.

## Result

No concrete production implementation bug or v2 fixture false positive was
identified in the requested seed-boundary, physical-prefix, invalid-span,
alignment, and alias paths. The v2 additions address the specific R682 holes:

- `qsa_indexer_device_batch.cpp:316-323` creates independent oracle and
  candidate states for each fresh `p0=0,n=2/3/4` run. `candidate()` at
  `:154-157` calls the production `native_qsa_indexer_append_device_batch`
  directly (or the dispatch wrapper) with `n>1`, so these cases cannot pass via
  the original `n==1` fallback. `sequence()` at `:181-204` constructs the
  unchanged single-cell oracle and compares complete tail/dead/pooled/block_pos
  images and guard rows after each append. The relevant no-completed-block
  finalizer branch is therefore reached for n=2 and n=3; n=4 reaches a completed
  block as well.
- The planner's range arithmetic (`qsa_indexer_device_batch_plan.hpp:30-40`)
  bounds `n`, `p0`, and capacity before deriving `end` and block counts. The
  physical suite at `qsa_indexer_device_batch.cpp:329` builds a contiguous
  262140-cell prefix through the real single-cell API, clones it into a
  separately allocated candidate state, and compares the last four cells.
  Its checks at `:205-209` include final `block_pos`, spare row 65536 equal to
  `dead`, and the next-row canary. This is component-level physical allocation
  and boundary coverage only.
- `invalid()` at `qsa_indexer_device_batch.cpp:230-242` snapshots the full
  allocations before and after each expected rejection, drains all fixture
  queues, checks both guard regions, and compares all state bytes. The new
  per-member +2-byte alignment cases (`:264-270`) reach the production
  `validate_spans` check in `include/strata/sycl/launch.hpp:21-27`; the
  representative aligned state-state overlaps (`:272-280`) and input/state
  aliases (`:282-285`) exercise production output/input disjoint checks.
  These assertions do not rely on a copied validator.
- The no-completed-block finalizer retains earlier tail slots when the batch
  starts partway through a block; this matches the original append's prior-tail
  state. For p0=0,n=2,3, the fresh zero state makes untouched tail slots match
  the sequential oracle. For nonzero partial starts, the split histories at
  `:324-325` compare full state after every chunk. I found no discrepancy in
  these paths by source tracing.

## Fixture changes

Required fixture correction: none found from this source review.

Optional broadening only: the physical suite currently tests the final complete
four-cell block `[262140,262144)`. A future separate fixture could test a
partial batch ending at physical capacity from an already populated prefix, if
that transition becomes an explicit production caller contract. The current
review found no evidence that this is needed to interpret the v2 complete-block
case, so it is not a blocker for Main's next compile/GPU step.

The fixture's zero-length call (`:291`) is an intentional no-op path and is
covered by the enclosing suite's final state comparison; it is not counted as
an invalid rejection. The README separately records production dispatch
environment-value behavior as an unexecuted Main gate. Neither point makes the
new seed/alignment cases a false positive.
