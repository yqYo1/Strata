# R836 — native16 GDN source and interface investigation

**Purpose and disposition.** This is a read-only design investigation for a future typed GDN boundary. It does not propose importing another engine, and it establishes no performance, numerical-acceptance, or adoption result. I read the workspace `AGENTS.md`, `docs/ARTIFACT_RETENTION.md`, the current research index, and only relevant review metadata; R820/R822 report bodies were not opened. No build, test, GPU work, profiler, or code change was performed. The report is written for later retrieval if a long-input profile justifies the work.

## What the current native16 path actually does

In `src/prefill/prefill.cpp`, long native16 attention first produces `m.mixed_h` as FP16 (`native16::mix`); the sibling `m.mixed_bf` is BF16 and is used for the two small alpha/beta projections. The GDN branch nevertheless calls `native_proj(..., m.mixed_h, ..., float* Y, ...)` for `attn_qkv.weight` and `attn_gate.weight`, so `m.qkv[T,10240]` and `m.z[T,6144]` are global FP32 outputs. The two BF16 projections write `m.ab[T,96]` in FP32. `gdn_gates` makes FP32 `gate[T,48]` and `beta[T,48]`; gate is `softplus(alpha + dt) * ssm_a`, beta is sigmoid. `gdn_conv` consumes FP32 QKV plus the persistent convolution history and FP32 conv weights, writes FP32 `m.hbuf[T,10240]`, and applies SiLU plus Q/K L2 normalization. `gdn_recurrence` reads that buffer and FP32 gate/beta/z, updates the persistent FP32 recurrence state, then writes both `m.y[T,6144]` FP32 and `m.y_h[T,6144]` 16-bit. In active native16 mode, the next `native_proj16` consumes `y_h`; the `y` FP32 output has no reader on that branch.

There is **no existing full-tensor 16→32→16 round-trip** across these GDN globals: QKV/Z are projected from a 16-bit input to FP32, and stay FP32 through convolution/recurrence; `y_h` is packed from the FP32 recurrence result while `y` is also stored. That dual output is a potentially removable FP32 write on the native16 branch, not an expansion of a prior half tensor. `src/kernels/sycl/gdn.cpp` and `src/kernels/sycl/fused_gdn.cpp` expose float-pointer GDN/conv interfaces; `fused_gdn.cpp` also has multi-token verification helpers. `rg --files` finds no `src/kernels/sycl/gdn_chunk.cpp`; production prefill is `gdn_conv` then `gdn_recurrence`. The standalone kernels in `gdn.cpp` are also FP32 at their public boundary. The current persistent recurrence array is `128*48*128 = 786,432` FP32 cells = 3 MiB per GDN layer. The adjacent convolution history is `10,240*3` FP32 cells = 120 KiB/layer; both occupy the shared per-layer session-state block.

The chunk arena reservation in `gdn_set_bytes(T)` is 32,960 FP32 values plus 6,144 16-bit values per token: **144,128 bytes/token** at source-level sizes. At T=8192 this sums to 1126 MiB across its reservations (not a measured live peak). This exact list includes QKV, Z, AB, gate, beta, hbuf, y, and y_h; the FP32 state above is session-persistent, outside that chunk-arena sum.

## Small typed boundaries and byte accounting

Sizes below are per token, from the local constants `C=10240`, `ZV=6144`, `HV=48`; FP32=4 bytes and the proposed 16-bit format=2 bytes. “Traffic saved” assumes the producer writes a full global and a consumer reads it once. It is a source-level bound, not a cache/DRAM measurement. The conversion count is one FP32-accumulator/result to 16-bit output conversion per element; the consumer widens in FP32 registers only where needed.

| Current global | Current bytes/token and type | Smallest typed seam | Storage saved; conversion cost |
|---|---:|---|---|
| `m.qkv` | 40,960 B FP32 | A direct 16-bit output from the QKV projection; typed conv input | 20,480 B; 10,240 output casts. Up to 40,960 B traffic saved if the projection itself writes 16-bit and conv reads it. |
| `m.z` | 24,576 B FP32 | A direct 16-bit projection output; typed recurrence Z input | 12,288 B; 6,144 casts. Up to 24,576 B traffic saved under the same single-read/write assumption. |
| `m.hbuf` | 40,960 B FP32 | Typed post-conv block output, keeping conv sum and Q/K reductions FP32 | 20,480 B; 10,240 output casts. Up to 40,960 B traffic saved on one producer/consumer pass. |
| `m.ab` | 384 B FP32 | Keep FP32 through softplus/sigmoid transforms | No precision conversion; small compared with block tensors. |
| `m.gate`, `m.beta` | 192 B each FP32 | Keep FP32 recurrent scalars | No conversion. Do not round beta after sigmoid or the log-decay before `exp` without long-recurrence evidence. |
| `m.y` + `m.y_h` | 24,576 B FP32 + 12,288 B 16-bit | On native16, output only `y_h`; keep the current FP32 reference interface for the other path | Remove 24,576 B/token allocation and FP32 store; no new cast (the existing FP32 result already produces `y_h`). |
| Recurrence state + conv history | 3 MiB + 120 KiB per layer, both FP32 | Preserve FP32 state and history; accept typed block inputs | No storage saving. No state re-pack; state advances in place across chunks. |

The three block tensors QKV/Z/hbuf yield a **52 KiB/token** resident-size reduction if their producers write 16-bit directly, with 26,624 element conversions/token and no extra full-buffer conversion pass. Removing `y` on the active path adds 24 KiB/token of scratch reduction, for 76 KiB/token total. A standalone F32→16 conversion kernel after the existing projection is the wrong seam: it adds a full FP32 read, a 16-bit write, and another 16-bit read, so traffic can increase. First prove that the existing native-weight projection can store a 16-bit result from its FP32 accumulator. The current `native_proj16` wrapper does IQ dequant-to-F16 plus `f16_out16`; it is a different projection route, not proof that `Gemm::native` supports output typing with unchanged weight semantics.

## Two source designs, not adoption claims

**1. vLLM's chunk-GDN wrapper boundary.** At vLLM commit `fb3fec970e1efc9b0069c81279bd82c84634c2bb`, `fi_chunk_gated_delta_rule` optionally normalizes Q/K, keeps Q/K/V in their incoming dtype, widens initial state, gate, and beta to FP32, passes `exp(g)` and FP32 state into `flashinfer.gdn_prefill.chunk_gated_delta_rule`, and asks it for final state when requested ([pinned wrapper source](https://github.com/vllm-project/vllm/blob/fb3fec970e1efc9b0069c81279bd82c84634c2bb/vllm/model_executor/layers/mamba/gdn/qwen_gdn_linear_attn.py)). This is a useful boundary shape for block inputs plus FP32 carry; it does not establish FlashInfer's output-state layout or SYCL support from this wrapper alone. vLLM's separate fused-decode admission check requires BF16 activations and convolution cache, K=V=128, supported gating/layout, and allows FP32 or BF16 recurrent state, so that branch is decode-specific and must not be read as long-prefill support. vLLM is Apache-2.0 at the pinned root license; no vLLM code is copied here ([license](https://github.com/vllm-project/vllm/blob/fb3fec970e1efc9b0069c81279bd82c84634c2bb/LICENSE)).

**2. FLA's fused recurrent block-input kernel.** At FLA commit `15396e604df6a4699950d7f20457b391b0cd8e74`, `fused_recurrent_gated_delta_rule_fwd_kernel` loads Q/K/V and gate/beta as inputs, casts each to FP32 inside the kernel, loads the initial state into its FP32 local `b_h`, and applies decay, beta-scaled residual, rank-one update, then readout for every t. Output is cast to its destination dtype; final state is stored in the requested state-output dtype. A low-precision Q/K/V input with FP32 initial/final state therefore avoids a global FP32 block expansion while preserving FP32 recurrence-local math ([pinned kernel source](https://github.com/fla-org/flash-linear-attention/blob/15396e604df6a4699950d7f20457b391b0cd8e74/fla/ops/gated_delta_rule/fused_recurrent.py)). Its separate chunk API supports block boundary initial/final state and has a documented 16/32/64 chunk-size contract ([pinned chunk API source](https://github.com/fla-org/flash-linear-attention/blob/15396e604df6a4699950d7f20457b391b0cd8e74/fla/ops/gated_delta_rule/chunk.py)), but its chunked WY representation is a different algorithmic decomposition and requires its own state/output parity work. FLA's pinned source declares MIT licensing; this is a design reference only, and any future implementation proposal must resolve license/provenance before integration ([license](https://github.com/fla-org/flash-linear-attention/blob/15396e604df6a4699950d7f20457b391b0cd8e74/LICENSE)).

These sources establish patterns, not a claim of semantic equivalence or hardware performance. Strata's contract that a typed SYCL entry must preserve is: packed channel order Q(16 heads), K(16), V(48), 128-wide heads; convolution taps oldest history first then current input, with history committed to the last three raw QKV rows; Q/K normalization `x/sqrt(sum(x*x)+eps)` without moving the recurrent readout scale across the output RMS norm; `gate=softplus(alpha+dt)*ssm_a`, `beta=sigmoid(beta_logits)`, decay `exp(gate)`; delta `(v - decay*(S^T k))*beta`; update `S=decay*S + k*delta`; Q/K head pairing `h % 16`; Strata state layout `(S,h_v,S)`; final `rms_norm(o,eps)*gamma*sigmoid(z)`; and FP32 recurrence state at every prefill chunk boundary. A generic `[head,K,V]` FLA state pointer cannot be assumed to match Strata's `(K,head,V)`-like physical layout. Map indices in the kernel or prove a conversion separately; do not silently pass the pointer through.

## Hard gates before any typed GDN implementation

1. **Projection contract:** verify supported native GGUF weights, row strides, native GEMM output conversion, aliasing, and ordering. Do not substitute IQ→F16 dequant + half GEMM without comparing it to the current native projection on actual tensors.
2. **Numerics:** compare every block's QKV/Z, gate/beta, hbuf, y16, and FP32 final state against current FP32 outputs for T=1,2,3,4, ragged/tail chunks, and production sizes. Include extreme/near-zero Q/K norms, epsilon boundaries, large/small gate, beta near 0/1, SiLU range, z sigmoid, and recurrent cancellation. Test FP16 and BF16 independently; pass through a full 262144-context state chain and record output/logprob/NLL differences against the FP32 reference before setting acceptance.
3. **State and ordering:** test two and multiple chunks with distinct initial recurrence and convolution history; verify final-three-QKV history order and exact next-chunk outputs. Exercise the supported same-queue path and any cross-queue handoff with an explicit event dependency; prove producers complete before typed consumers and before arena/state reuse, without host waits or environment mutation after runtime initialization.
4. **Accounting and performance:** verify actual allocation extents and absence of hidden FP32 pack buffers; measure the complete projection→conv→recurrence→output path, including conversion and synchronization. Compare to the full FP32 reference in clean owned processes. Do not adopt based on this source arithmetic or on isolated kernel throughput.

The narrow candidate is therefore a typed projection output plus typed conv input/output plus typed recurrence block inputs and 16-bit output, while gate transforms, local reductions/accumulation, persistent recurrence state, and initially conv history stay FP32. The largest safe benefit is removing repeated full-width intermediate traffic; whether the current native projection path can supply that interface, and whether the resulting quality and long-prefill time improve, remain unanswered.
