# Decision support: Qwen4-Exp QSA prefill versus Strata

## Scope and evidence

This is a read-only source audit of the exact Qwen4-Exp implementation in SGLang, mapped to the pinned Strata prefill and prompt-attention files. SGLang is pinned to official commit `877be2974aa151a984e52822c028276c2b1e9303`; its repository root license is Apache-2.0. The inspected files are named below. No code was copied or adapted. The assigned Strata source hashes match: `prefill.cpp` d01662ae6c46bfdd2556da1345c5f9edb79f91694391eee2b2b0aebfeab831ce, `layer_major.inc` e2def3bbd248c06c25ff2fce7ebc0ce49aecfcb0e418115196da8bb4b99960b1, `prompt_attention.cpp` 5fa7927e611b8cb746e1d11bd70a8e2aae3c66a48b02a93eb55e86eb9bf0076f, and `hardware-resource-profile-v1.json` ae8140e87bd4ebfa059f9864d6fbc7e8c390093adfd9c0de7dcc0295ec36c410. No source or runtime test was run.

For the measured Strata run, the supplied profile covers an actual 39,262-token input at chunk 8,192 on the B570, using layer-major prefill. Its instrumented host time is 105.006826228 s; the prior clean whole-run median is 403.0 tok/s and is a separate measurement. The profile records 60 QSA attention commands totaling 33.962851021 s and a 94.944752862 s attention envelope. The reported 77.31% compute-command coverage describes that envelope; it is not arithmetic utilization. These numbers make the current attention path the first place to seek finer stage evidence, but do not identify gather, matrix work, reductions, barriers, or memory as the limiting part. The measured path uses FP32 QSA input/output with resident K8V8. The source's separate typed BF16 QSA entrypoint is not the measured route.

## Stage map

| Stage | SGLang CUDA Qwen4-Exp path | Strata counterpart | Assessment |
| --- | --- | --- | --- |
| Call and ordering | `Qwen4ExpAttentionDecoderLayer.self_attention` prepares attention Q/K/V/gate, computes indexer selections, then calls sparse attention. Indexer overlap uses an alternate stream only in capture mode below 1,024 rows; long prefill is above that threshold and stays ordered on the current stream. | `prefill.cpp` runs each QSA layer in the layer-major chunk loop on its existing stream; KV append/query work precedes index scoring, selection, then attention. | Required dependency order. The small-batch overlap branch is not an explanation for this long-input run. Both paths use asynchronous same-stream launches for the main long-prefill sequence; no framework-level sync is needed between each same-stream producer and consumer. |
| Indexer projection and compressed-key cache | `QSAIndexer.project_qk` projects per-token index Q/K. On CUDA BF16/FP16 with supported RoPE shapes/cache, `qsa_index_q_norm_rope_store` fuses query norm/RoPE and stores raw K plus its RoPE position into the pending ring; otherwise Torch tensor operators form Q and K. At a completed group, the fused `qsa_index_k_compress_store` does group mean, K RMSNorm, RoPE, and compressed-cache store; the portable fallback materializes grouped K, mean, normalized K, and rotated K separately. | Strata projects index K/Q via its FP32 index-projection path, applies Q norm/RoPE, and uses `native_qsa_indexer_append_batch` to maintain raw tail and pooled block keys in FP32. Attention K/V are independently appended to the paged K8V8 cache, with FP16 scales per 64 dimensions. | The fused SGLang prep is a useful launch-boundary reference, not a drop-in kernel: its tensors and ring/pool contracts differ. Whether Strata index prep is worth changing is unknown without its own stage duration. Do not infer that a library/JIT path is cheaper from its fused source alone. |
| Block score, top-k, and token IDs | CUDA QSA prefill calls TileLang MQA when `q.is_cuda && HAS_TILELANG`: a query tile and K tile are copied to shared memory, GEMM scores are accumulated in FP32, ReLU is applied per index head, then heads are summed. The FP32 logits table is row-chunked to a 128-MiB budget; Q rows may be padded, K/Q are cast to the common BF16 or FP8 scoring dtype, a scale and row mask are applied, then a separate top-k kernel runs. With 2,048 token budget and compression 4, top-k is 512 compressed IDs; CUDA uses the bundled Triton fast-top-k for 512. Triton expansion writes up to 2,048 selected token IDs plus the query's 0–3 causal tail IDs. The Torch MQA is fallback/reference; CUDA tensors still execute Torch GPU ops, not a CPU-only score path. | Strata's indexer writes FP32 block scores, applying per-head ReLU then summing, and adds a large priority to the live incomplete block. A separate weighted top-k kernel writes cell IDs directly. The 4-head score does not divide by sqrt(128); a common positive divisor would not change ideal ordering. Strata's maximum width is 2,051 and per-query width is `min(n,2051)`. | Selection and IDs are required; score/top-k/expansion are not interchangeable without an ID-set check. There is a source-level boundary to resolve: SGLang selects 512 whole compressed blocks (2,048 cells), then appends only the current partial block's tail; Strata ranks weighted cell slots and can fill the 2,051 width with 1–3 cells of another scored block when the tail has fewer than three cells. For a three-cell tail the counts align. Treat this as a semantic difference to verify against Strata's intended 2,048-plus-tail contract, not a performance opportunity. |
| Main KV write and prefill packing | For ordinary CUDA extend, QSA commits current K/V to its paged pool. With no existing prefix, it calls the sparse Triton kernel directly on current-chunk K/V. With a prefix, it launches `pack_qsa_prefill_kv` to gather every token of each sequence from the page table into contiguous `[total_k, heads, dim]` K and V buffers; the pack casts FP8 pool entries to the query dtype when needed. This is a backend layout conversion for its contiguous-sequence sparse kernel, not part of top-k selection. | Strata prompt attention resolves selected logical cells through the page table and reads the resident quantized pools directly; there is no full-prefix K/V pack per chunk. | SGLang's pack is unnecessary in Strata's current consumer and would add full-prefix writes/reads and temporary lifetimes. Preserve direct paging. It is not evidence that a contiguous K/V scratch is intrinsically necessary for sparse attention. |
| Sparse attention and output | No-prefix prefill reaches `sparse_gqa_fwd_interface_triton`; prefix prefill reaches `sparse_gqa_fwd_interface_triton_ck` after the pack. The latter derives `max_q` with a CUDA `.item()` for grid dimensions, so that path has a host-visible synchronization boundary. The Triton kernel groups 12 query heads per KV head into a 16-row tile (4 padded rows), reuses a selected K/V tile across those heads, and keeps online FP32 max/normalizer/value accumulation. QK uses the attention scale and probabilities are cast to the value dtype for the V dot. The CPU/Torch `qsa_sparse_attention` is not the CUDA long-prefill route; speculative paged and fused decode routes are separate. | The direct prompt kernel launches one work-group per query × KV head, uses the same 12 real + 4 padded head rows, gathers selected cells, and maintains online FP32 softmax/accumulation without a global K/V pack or merge scratch. The current matrix route has one initial work-group barrier plus seven per 32-cell tile. For K8V8 it applies each 64-dimension FP16 scale group in the matrix path. The FP32 Q/P hi+lo FP16 decomposition retains precision while using matrix instructions; the native BF16 API is a separate, not-yet-measured route. | Both designs already reuse K/V across the 12 heads and use online softmax. The four padded rows are common geometry, not a new reason to repeat the rejected heads8 experiment. SGLang's BF16/FP8 arithmetic is not a numerical substitute for Strata's INT8 + per-64 scales and hi/lo path. Removing those scale groups or high/low terms would change the numerical contract. |

## Decision and next evidence

No algorithm-changing SGLang import clears the current evidence gate. The largest measured component is already Strata's direct sparse-attention path; SGLang's additional full-prefix pack does not solve a Strata materialization, and its kernel already has the same query-head reuse and online recurrence. Existing research also records that source load counts do not prove device traffic or a bottleneck, and that the K-only gather candidate needs direct evidence before implementation. No new head mapping, native16 QSA, graph-capture, or CUDA/HIP proposal is recommended.

The ordered actions are:

1. Keep direct page-table K/V reads, per-64 scale handling, and the current online FP32 recurrence while profiling that attention region. Its measured 33.96 s total makes it the first stage to resolve; it does not justify a specific gather or tiling rewrite.
2. Resolve selector semantics before modifying selection. A deterministic SYCL-only component fixture should cover lengths 2,048–2,052, all four live-tail residues, tied scores at the selection boundary, and the physical 262,144-context endpoint. Compare exact ordered IDs and valid widths against the intended “2,048 selected cells plus causal tail” rule, including page-bound checks. This discriminates whole-block expansion from weighted partial-block selection without using a CUDA/HIP test executable.
3. Consider fused indexer prep only if a later Strata profile shows projection/norm/RoPE/compression launch time is material. SGLang demonstrates a possible fusion boundary, not performance evidence for Strata's different FP32 state and physical-context lifetime.

Keep numerical and lifetime gates separate from speed: preserve FP32 reference attention; compare outputs after any selector-compatible change; keep QSA buffers, selection IDs, and paged-cache mappings valid through stream completion; and qualify the full physical 262,144 context independently. The 39,262-token profile is not that boundary test.
