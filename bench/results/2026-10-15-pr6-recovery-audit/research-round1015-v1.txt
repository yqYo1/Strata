## Design families and their invariants

### 1. Keep GQA heads together around the selected K/V tile

The current mapping is the natural high-confidence reuse case: one physical K/V tile feeds 12 distinct Q-head score and softmax rows. Any split by Q heads should be evaluated against the cost of rereading or restaging K/V. R568's source arithmetic shows that its proposed two independent head-tile work-groups double the logical K/V gather requests, even though device cache could reduce external-memory traffic. An alternative is to stage K/V once and process two Q-head subtiles serially inside the owner WG, but that keeps more FP32 outputs/softmax state live or requires spills; it trades read reuse against register/local-memory pressure. It is a counterexample to “more work-groups always improve occupancy.”

This path needs no cross-query index sharing and preserves each head's selector/mask. Each Q head still owns its own score, max, denominator and output accumulator; only K/V operands are common. For two KV heads, they still reference distinct K/V arrays/rows, so a single “both KV heads” tile is not implied by GQA.

### 2. Group query rows whose selected cell sets overlap

For G query rows with list sets `S_i` and mean length M, independent loads request `G*M` K/V rows. If an on-device grouped scheduler loads the union `U = union(S_i)` once, the ideal load-count reduction is `1 - |U|/(G*M)`, before index building, membership checks, staging and cache effects. Define overlap density `rho = 1 - |U|/(G*M)`. Reuse is attractive only if saved K/V traffic and launch/scheduling cost exceed the union construction and per-row mask cost. At `rho=0`, union gathering cannot save operand loads; it adds work. At `rho≈1`, it may save much, but query-specific QK/softmax/PV arithmetic remains G-fold.

A no-host-round-trip design can construct group descriptors, a deduplicated union and per-query membership on device, then load union tiles and apply each row's mask before softmax. To preserve semantics, each query must still see precisely its original selected cells, with disallowed cells assigned `-infinity` before max/exp and no V contribution. A union is a superset worklist, not permission to give every query the union mask. If source-order FP32 reproducibility matters, keep each query's original reduction order; a sorted/deduplicated union and mask can change accumulation order even though the real-number softmax set is unchanged. For causal attention, test the per-query position predicate as well as membership; a shared tile may contain a future token for one row and a legal token for another.

Index cost can erase the gain. With 32-bit IDs, independent storage is `4*G*M` bytes. A shared union costs `4*|U|` plus, for a dense membership bitset, `G*|U|/8` bytes (or `G*|U|` for byte masks), plus row offsets and possible stable-position/order maps. Example G=12, M=2051: independent IDs are 98,448 B. If all lists are equal, U=2,051: union IDs plus bitset are about 11,281 B, before order maps. If lists are disjoint, U=24,612: IDs alone are 98,448 B and bitset adds 36,918 B. The latter case has no K/V reuse and expands metadata. Sparse per-query membership lists can reduce bitset waste but add lookups and irregular branches. These are design arithmetic, not measured local costs.

A useful device-side admission statistic is `rho` plus estimated saved operand bytes: `saved ~= (G*M - |U|) * bytes_per_KV_row`; admission should also include union/membership build cost and number of tiles actually reused. Never use adjacent-row grouping alone as a proxy for overlap. At width 2,051 and dimension 256, one K+V row contains 512 elements before format-specific scales/codes, making overlap potentially valuable, but exact stored bytes depend on the selected QSA mode.

### 3. Split-K / cascade over disjoint selected-cell partitions

FlashInfer documents split-K for block-sparse attention and shared-prefix cascade: compute partial attention states on independent KV regions, then merge. For a query and partition A, maintain stable online state `(m_A, l_A, o_A)`, where `m` is the maximum logit, `l=sum exp(s-m)`, and `o=sum exp(s-m)*v` (unnormalized output). Merge A and B with `m=max(m_A,m_B)`, `a=exp(m_A-m)`, `b=exp(m_B-m)`, `l=a*l_A+b*l_B`, `o=a*o_A+b*o_B`; final output is `o/l`. This is exact in real arithmetic if partitions are disjoint, every selected key is assigned once, and the same score scale and value semantics apply. Empty partitions need an explicit identity state; blindly evaluating `-infinity - -infinity` is unsafe.

A split is most useful when a query has a long list but too few independent rows to occupy the device, or for a genuinely shared prefix that many requests would otherwise reread. It can worsen the 8,192-row case by multiplying already abundant parallelism and adding a second merge pass. Temporary FP32 state scales roughly as `Q * P * (D+2) * 4` bytes for Q query rows, P splits, output dimension D (ignore padding and metadata): at Q=8,192, D=256, P=2 this is about 16.9 MB; P=4 about 33.8 MB. A kernel can reduce state in a second launch without host materialization, but that still costs device traffic, scratch lifetime and launch/synchronization. Splitting should be driven by the per-row length distribution and occupancy evidence, not max cap alone.

For causal/order-sensitive behavior, assign contiguous ranges in each query's existing selector order and apply the original causal test within each partition. The merge is associative mathematically but not bitwise associative in FP32. It changes max/sum/output reduction tree and rounding; it is not a strict preservation of serial accumulation order. If the gate requires exact FP32 operation order, split-K is disallowed. If the selected serving reference accepts the same online-softmax contract within measured tolerances, numerical validation must still compare outputs and downstream logits. Do not claim equivalence merely because the algebraic formula matches.

### 4. Block-sparse representation / persistent scheduling

FlashInfer's BSR/block sparse attention takes query-to-KV block indices and supports a split-K workspace; its public API supports GQA where Q-head count is a multiple of KV-head count, while explicitly documenting backend-specific GQA exclusions. This is a useful scheduling abstraction, not evidence that current cell lists can be rounded to blocks without extra work. Coarsening 2,051 selected cells into blocks can reduce index overhead and improve contiguous/coalesced K/V loading, but may fetch unselected cells and alter sparse semantics unless the kernel retains element-level masks. If each list is highly irregular, padding to a common block count creates tail waste and load imbalance. A persistent worker loop can dispatch variable row/block counts and reduce tail underutilization, but variable row lengths also create stragglers; work stealing or length buckets need GPU-resident queues/compaction and careful output ownership. Host-built grouping would create CPU work and transfer/synchronization, contrary to the requested no-round-trip constraint.

## Irregular GPU analogy and counterevidence

Bell and Garland's original GPU SpMV study treats irregular row lengths as a family of cases, comparing mappings rather than assuming one tile schedule suits all matrices. Its transferable point is to classify degree/list-length distribution and balance work at row/warp/block granularity; it does not establish that attention queries share indirect K/V indices. Sparse matrix-vector input-vector reuse depends on adjacency overlap and cache locality, while attention also has per-query softmax normalization and causal masks. [Paper/source page](https://mgarland.org/papers/2009/spmv/), SC09 (2009). A counterexample to broad reuse claims is a workload with disjoint selected lists but uniform lengths: persistent scheduling may balance it, but union grouping saves no K/V bytes. Another is a common prefix plus different suffixes: a prefix cascade is compelling, whereas arbitrary, high-entropy sparse lists may have no sizable common set and pay extra merge/index costs.

## Primary sources and evidence limits

- FlashInfer authors, *Efficient and Customizable Attention Engine for LLM Inference Serving*, arXiv:2501.01005 (2025), [paper](https://arxiv.org/abs/2501.01005). Paper's block-sparse/page representation and load-balanced scheduling motivate indirection and dynamic balancing. Its benchmark hardware/software results do not transfer to Arc B570 / SYCL.
- FlashInfer 0.7.2, [cascade API](https://docs.flashinfer.ai/api/cascade.html), [sparse API](https://docs.flashinfer.ai/api/sparse.html), and [attention API](https://docs.flashinfer.ai/api/attention.html) (documentation consulted 2026-10-17). Cascade docs describe shared-prefix KV with per-request unique suffix, GQA shape constraints and warn more levels can lose to merge overhead. Sparse docs expose query/KV block-index metadata and split-K workspace; backend exclusions are evidence that feature support is path-specific. APIs are CUDA/PyTorch ecosystem contracts, not an Arc implementation reference.
- FlashInfer authors, [Cascade Inference blog, 2024-02-02](https://flashinfer.ai/2024/02/02/cascade-inference.html). It describes splitting shared prefix attention from request-specific suffix attention and reports H100 results; these quantify only that GPU/software setup.
- vLLM, [Automatic Prefix Caching design (v0.7.0)](https://docs.vllm.ai/en/v0.7.0/design/automatic_prefix_caching.html): equal prefix blocks can map to the same physical block. This reuses storage and enables locality; it does not by itself prove one CTA loads a shared block once for multiple queries.
- SGLang authors, *SGLang: Efficient Execution of Structured Language Model Programs*, [arXiv:2312.07104](https://arxiv.org/abs/2312.07104); current [RadixAttention source](https://github.com/sgl-project/sglang/blob/main/python/sglang/srt/layers/radix_attention.py) is a moving `main` link. RadixAttention shares cached KV for matching prefixes across calls; cross-call storage reuse is distinct from coalesced multi-query tile reuse inside one kernel. Consulted 2026-10-17; no source commit was pinned for this moving link.
- Tri Dao et al., *FlashAttention-2*, [ICLR 2024 paper](https://tridao.me/publications/flash2/flash2.pdf). Tiling and split parallelization motivate work partitioning; its exact online-softmax formulation underlies the merge equations above. CUDA results are not local performance evidence.
- Michael Garland and Nathan Bell, *Implementing Sparse Matrix-Vector Multiplication on Throughput-Oriented Processors*, [SC09 paper/source page](https://mgarland.org/papers/2009/spmv/). Supports irregular-length scheduling analysis only, not attention-mask or softmax conclusions.
