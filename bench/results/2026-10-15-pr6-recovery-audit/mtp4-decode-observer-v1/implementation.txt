Fixed accounting

The 64x4x4x4 Bucket table is removed. Kept state is layer[64] with actual T1..4
attempt/callback/row/job/cpu-row/route-entry/zero-job counts, four actual-T window
aggregates, four request-wide owner Buckets, four CPU job-nt counts and row sums,
one NativeFmt table per layer, masks and scalars. Format rows expose native
GU/Down/activation format IDs and byte layout. Owner/T/nt cross-conditioned
latency claims cannot be made from these marginals.

begin_window counts attempts. verified() follows successful ver.run and dispatch
failure checking. commit_attempt precedes the existing commit; committed() follows
its successful return. emitted() records the delta of original produced_n after
the original output loop. Final wait attempt, returned success/failure and wall
span are separate, around only the existing ver.wait_commit. A missing/throwing
wait keeps its active prefix; a failed returned wait records failure and the
original ERR/return is preserved. A normal joined close occurs only after the
existing successful wait AND DONE/stdout flush.

W = successful verifier + commit-return windows; R = sum actual T; D = R-W;
A = accepted draft positions; C = W+A; E = actually emitted produced_n delta.
The receipt retains attempted/verified run rows, commit attempts/returns,
emission-window count and final-wait status separately. It checks rejected=D-A,
E<=C and terminal committed-but-unemitted=C-E. EOS and max-new may truncate an
accepted prefix, so C-E is explicitly allowed at an observed terminal boundary.
A/D, (D-A)/D, A/E and E/C retain numerator/denominator, with N/A whenever
the relevant denominator is zero; in particular T1-only D0 has N/A acceptance, not 0%.
A terminal length close also requires E==actual max_new. Context limit, cancel,
missing/duplicate callback mask, failed run/commit/wait or any incomplete prefix
cannot become complete=1.

Route grouping validates actual T, layer/k/expert/owner/format bounds, unique
experts per token, actual CPU jobs in first-miss order, blob nonnull and job nt
matching repeated CPU-owned route entries. Zero CPU jobs still count as a real
callback. Per-layer actual-T callbacks and row sums join W/R, never layers*E.
Request owner/job nt and source deltas join multi_misses, multi_entries,
cache_hits, pcie_experts, verifier windows and logical pool multi_bytes.
Logical blob extents are not DRAM/PCIe measured traffic or an independent blob
identity oracle. Input activation quantization remains the existing ms_actq;
issuer service quantization counts the separate Down intermediate, once per
actual CPU job activation row.

CPU service and completion

Each logical worker owns its slot; issuer uses slot -1. Six retained roles are
0 native GU, 1 native Down-activation quant, 2 native Down, 3 Q2 GU+SwiGLU,
4 Q2 Down-activation quant, 5 Q2 Down-any. This keeps native/Q2 entry identity
without recording internal ISA timing. Thread CPU ns, wall ns and calls are
summed into issuer/workers only at close. These are concurrent service volumes,
not decode wall critical-path durations. They can exceed wall time.

Task claims and finished tasks are distinct. Claimed and finished flattened
output-row sums are distinct, including partial prefixes; these rows are the
existing jobs*FF or jobs*H coordinates, not job nt activation rows. Phase plans
are unchanged: 3*(workers+host_works) tasks per nonempty native batch, with the
original kMaxSplitMulti batching. Planned/claimed/completed tasks and flat rows,
issuer intermediate-quant calls==cpu_rows, and expected native batch counts all
join. A done-boundary proof reads exact done==n_tasks after the existing wait.
The park-boundary count records the existing wait_parked return; it adds no wait
or second parked read that could reject a late exhausted wake. Planned, done,
park and completed phase counts must agree. Zero jobs produce zero phases.

Lifetime review and change from original proposal

The original exceptional branch retained just the observer state and left its
dispatch binding in place while returning/unwinding. That alone could not retain
the actual mjobs_ table, nfmt_ table, dispatch/pool and their outer owners; refusing
a future observer allocation did not prove those readers' lifetime.

The new ordinary path binds before native job publication, and clears the pool
pointer only after run_split_multi_native's successful return through its original
done/park ownership boundaries. Successful task readers access service only after
a successful claim and stop before their done release; exhausted late workers
cannot claim/read it. The original publication/acquire and per-slot single writer
contract remain. No instrumentation is added to worker park/probe loops.

The actual decode_native_owner_call helper catches an issuer-side exception
before the caller's job/format/dispatch/observer owners unwind. It prints host-only
failed-prefix counters and complete=0, runs the existing registered release_gpu_waits fatal hook, flushes and aborts
with all those owners still alive. That hook is already used by pool stalls to
release GPU host-flag spin waits before process exit; no new queue/event/wait is
submitted. The model-free fixture installs a CPU-only hook and checks it ran. Binding collision/change or a scope close with unproved pool owner
completion also fail-stop before worker-slot reads, detachment or destruction.
No extra observer wait is inserted to manufacture completion. This intentionally
does not provide exception recovery. Existing pool stalls already abort; an
uncaught worker exception/kill can leave no footer, which Main must reject as
absent/incomplete evidence. CPU fixture coverage of the shared guard is described
below; actual pool happens-before remains Main's source/runtime review obligation.
