## Live path and compatible instrumentation points

`Prefill::run` selects `run_layer_major` only when `STRATA_PREFILL_LAYER_MAJOR=1`, `impl_` exists, and request length exceeds `T` (`src/prefill/layer_major.inc:3-17`). The route requires the SYCL engine and `m.copy == m.cs`, full single-GPU operation, explicit MMQ=0, and rejects timing and several observers (`:20-76`). It checks input geometry and supports up to 262144 tokens (`:49-60`). The actual wrapper processes 48 layers; per layer it drains the queue, copies all 512 expert blobs into one upload slab, submits fills and drains them (`:298-323`), runs `run_impl` for that single layer (`:343-398`), and drains again (`:397-400`). Its outer elapsed wall starts at `:125`; total statistics are committed at `:418`.

The correct QSA and MoE phase seams already exist in `run_impl`: phase names at `src/prefill/prefill.cpp:1388-1399`, `PfTimer` event recording/folding at `:1536-1567`, timer construction at `:1700`, QSA marks around `:2204-2401`, and MoE router/gather/copy-wait/dequant/GEMM/combine marks around `:2422-3070`. These marks do not cover layer-major's outer expert-source/upload loop (`layer_major.inc:307-324`) or residual callbacks and their checked drains (`:357-395`), so add explicit outer spans for those operations. No need to modify kernel bodies to label QSA versus MoE.

`include/strata/sycl/compat/cuda_runtime.h:14-16,91-99` defines streams as `sycl::queue*` and events as this project's compatibility `Event*`; it exposes create/record/query/synchronize/elapsed APIs. `src/sycl/compat.cpp:18-25,364-424` implements recording by submitting an in-order barrier to that queue. `cudaEventElapsedTime` waits for the ending event, reads each event's `command_end` profiling timestamp and subtracts them (`:408-424`); therefore calling elapsed mid-pass would block. `Runtime::compute()` is in-order and profiling-enabled, while transfer queue is in-order without profiling (`src/sycl/runtime.cpp:59-76`); runtime also supports additional optionally profiled queues (`:78-89`). For this route `m.copy == m.cs`, so queue-side markers can cover both residual DMA and expert uploads on one in-order profiled compute queue. Do not assume the profiling property applies to every auxiliary queue, though none is expected here.

## Smallest useful design

Use one explicit, default-off instrumentation mode in the layer-major wrapper, selected before native process start. It should be a separate new setting or source diagnostic selector; it must **not** set or alias `STRATA_PREFILL_TIMING`, loosen that option's general observer guard, or alter dispatch. Keep existing layer-major admission/configuration fixed. Avoid per-kernel changes and avoid printing per chunk/per expert.

Retain current `PfTimer` placements as the MoE/QSA breakdown, but have the instrumented mode collect its existing phase intervals into one bounded aggregate across the 48 single-layer `run_impl` calls. The simplest seam is the existing `PfTimer` in `run_impl` and its final `fold()` after the existing end-of-pass drains (`prefill.cpp:3215-3226`): enable only under an explicit layer-major observer pointer/state and accumulate fixed-size phase totals rather than print 48 records. Preserve the current marks and queue order. This phase view distinguishes QSA attention/index/select, MoE host grouping, gather, copy-wait, dequant and both GEMMs. Its intervals include queue idle caused by late host submissions; it is not kernel-only service time.

Add a small fixed set of outer measurements in `layer_major.inc`:

- Record a host monotonic wall span for each layer's expert source/copy_blob preparation (`:307-316`) and the complete upload operation through its existing drain (`:317-323`). Capture the queue markers around only the upload submissions on `m.cs`; fetch timestamps only after the already-required `drain()` at `:322`. Report aggregate and max/per-layer summaries, not 512 entries. Host source time and queue upload interval distinguish CPU source preparation from H2D service while their sum remains bounded by the measured layer-load wall. If device-to-device/in-device placement is not verified by the SYCL backend's allocation-kind semantics, label this `upload queue interval` and do not claim physical H2D bytes/direction from source intent alone.
- Around each residual-store callback (`:357-395`), collect host elapsed time from callback entry through the existing required `drain()` (`:388`) plus a queue interval bracketed around the existing `to_f16`/`cudaMemcpyAsync` work when present. Report by destination class (device/host) and totals/counts; do not synchronize beyond the callback's existing drain. In current FP32 configuration, this distinguishes D2D from D2H requested path and wall wait; in FP16 it would include pack staging, so keep formats separate.
- Record already-existing explicit drain wait wall spans at the three meaningful boundaries: layer entry/upload/pass/final and residual callback (`:239-250`, `:298-300`, `:322`, `:388`, `:397-399`, `:414`). Do not add polling loops. For each checked `cudaStreamSynchronize`, record host time immediately before/after that same call. This attributes CPU blocked duration without adding another wait. Keep a separate outer wall denominator from `started` (`:125`) to successful `lease.retire()` (`:422`) and emit only after safe retirement. Label it `layer-major wrapper through lease retirement`, not pure prefill: expert-load CPU time, queue work, callbacks and internal checks all lie inside it; the final destructor/field restoration tail occurs after `lease.retire()` and needs a separate small host RAII span if restoration cost is a required metric.
- To measure restoration tail, add a pre-reserved stack/local host clock marker at the point immediately before wrapper-owned teardown, and emit its duration from a final scope guard after `Restore` has copied back borrowed pointers/callbacks (`Restore::~Restore`, `:213-233`) and layer cache/residual owners have been destroyed. This must not release any owner before the existing retirement proof. If exact destructor ordering cannot be instrumented without changing lifetimes, report only the current known interval before `lease.retire` and leave restoration tail explicitly unmeasured.

The denominator is the outer `started` wall (`:125`) through checked lease retirement plus an explicitly distinguished restoration tail. Keep denominator and overlapping sums side-by-side; never compute exclusive fractions by summing phase/event times. The route uses one in-order queue, and all layer boundaries/callback stores currently drain it, so event order on this queue is a useful critical-path timeline; event intervals can still include CPU submission gaps. Host wall measurements around existing waits identify actual blocking time. There is no separate H2D/D2H queue overlap to infer in the admitted current topology. If future route guards change queue topology, re-evaluate instead of treating the current method as multi-queue overlap accounting.

Queue markers are extra barrier commands, so even this design perturbs command count and scheduling slightly. Bound instrumentation to a few aggregate brackets per layer/pass and per residual callback, no marker per expert or kernel. Record marker creation/record errors; an incomplete diagnostic is not a successful profile. To avoid extra blocking, read all timestamps only at existing checked drains. The compatibility `ElapsedTime` API itself waits for the end marker, so do not call it before the natural drain. An alternative direct SYCL-event collector would need changes to expose the queue's `sycl::event` and preserve shared runtime error handling; current compat has no public event-object accessor.

## Interpretation and capability limits

- Current event duration uses `command_end` to `command_end` across ordered markers. It measures elapsed queue timeline, including idle gaps where the next command was not ready/submitted, not isolated kernel duration. The Khronos SYCL reference documents `command_start`/`command_end` as device command timestamps and notes that querying them blocks until the event reaches the relevant state; same-backend timestamps share a timebase. [SYCL event profiling reference](https://github.khronos.org/SYCL_Reference/iface/event.html)
- Source phase categories cannot separate individual QSA attention kernels or MoE kernel variants/occupancy. Use them to rank where to ask a narrower follow-up question.
- Copy intervals characterize the queue operation interval for the requested memory operation, not guaranteed physical link traffic or validated endpoint class. Pair source semantics, queue interval and host wait; do not infer wire bytes.
- `run_impl` performs natural queue drains at chunk callback and pass completion (`prefill.cpp:3181-3192,3215-3223`). Those existing waits already affect baseline order and denominator. The diagnostic must observe them, not create more.
- Host elapsed before a queue marker can reflect source work and submission latency. Explicit source-copy, upload submit, and checked-drain wall spans are needed to separate CPU preparation from queue service.
- Whole-process PTI device aggregate remains a low-intrusion cross-check/fallback if instrumented source is unavailable, but cannot supply this phase attribution; R722's limitations still apply.
