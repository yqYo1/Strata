# R1019 — QSA BF16 prefix の64セル・オンラインタイル判断

分類: decision_support。読み取り専用のソース／一次資料調査。対象は指定 `feature/sycl` f2d0ef42 と、Main測定中のmode8/10 binary339c1ea17e297ee291461e41f6aa6014985a0cdb2a3ef33783a72660a2ebb406。指定QSA kernel/headerは不変ソースとして扱う（window10 capacity extensionは別）。build/test/runtime/GPU/profiler/Git、worker操作はしていない。XeStrata由来のコードや提案は調査・転用していない。R1013/R1016の既存資料と訂正receiptを使い、今回の64-cell geometryに絞る。

## 判断

**最小のopt-in 64-cell比較は実施する価値があるが、採用は保留。** 32-cell反復を64にまとめれば長い列でloop/barrierが減り、QKを8 subgroup全体へ配れる可能性がある。一方、declared SLMは28,224から47,936 B/WGへ増加、serial softmax走査は32から64へ倍増、tile内matrix API MADも倍増する。occupancy低下やsoftmax待ちが利益を上回れば遅くなる。静的カウントから速度は予測できない。

現model diagnosisのQSA 58.1553 s、attention約38 s、GDN 18.0913 s、MoE 20.8916 sは非排他的queue区間で、GPU busyやexclusive kernel latencyではない。効果の根拠にしない。今回は同一query/KV-head、16 padded query rows、WG128/SG16のみを比較し、cross-query reuse、head split、KV duplicationを混ぜない。

## Source geometryと資源計算

現行は`Dim=256, Heads=12, Cells=32, WG=128, SG=16`。1 WGはquery 1件×KV head 1つ、queryあたり2 KV-head workgroup。12実headを16行へpadし、4行はzero Q・非store。QKは8 subgroup中4つが有効で8-head×16-cell領域を覆い、K=256を16ずつ回すため64 joint_matrix MAD/KV-head/tile。PVは8 subgroup全てが動く。各々4個の8×16 accumulatorが32 probability列を16列ずつ処理するので8×4×2=64 MAD/KV-head/tile。PVにQKのK-loopは無い（R1016の見落としをmatrix-accounting-correctionが訂正）。両KV headなら各phase128 MAD。padded MACは各phase262,144で、MAD一回は8×16×16=2,048 MAC。これらはC++ API geometryであり、命令発行数、cycle、occupancy、busy率ではない。

ScoreStride=33での独立accessor合計は28,224 B: Q8192 + KV16384 + BF16 probability1024 + FP32 scores2112 + max/norm/alpha192 + rows256 + bad flags64。Stride32なら28,160 B。計算式は`(16*256 + Cells*256 + 16*Cells)*2 + (16*ScoreStride+3*16)*4 + Cells*8 +16*4`。compiler padding、隠れた割当て、spill、resident WG数は含まない。loop前barrierが1回、各tileに5 WG barrierなのでN tileで`1+5N`。

64セルでScoreStride=65の場合、同式は47,936 B/WG（Q8192 + KV32768 + probability2048 + scores4160 + state192 + rows512 + bad64）。matrix admission閾値はpayload+4096=52,032 Bになる。admission通過は同時resident WG数やcompiler資源を保証しない。

QKは2 head bands×4 cell bandsで8 subgroupが8×16 fragmentを覆うなら128 MAD/tile/KV head。PVは4 cell fragments×4 output-dimension fragments×8 subgroupで128 MAD/tile/KV head。tileあたりAPI MADは倍だが幅も倍なので、全セルに対するshape上のMAC総量は同じ。長列ならtile反復と各tileの5 barrierは概ね半減するが、部分tileや短列は別でloop前barrierは残る。serial softmaxの各`tid<16`所有者はmax/sum走査が倍、exp2も倍近くになる。第一比較はserial順序を保持し、softmax方式を同時に変えない。

Intel SYCL joint_matrix操作はsubgroup collectiveで全lane converged参加が必要。8 subgroupへ広げた時もloop/branchを揃え、各fragmentのpointer/stride/alignmentとscoreの非重複完全書込を確認する。現在の8×16×16 BF16/BF16→FP32 runtime queryが通っても、64-strideのlowering、spill、matrix命令実行、占有率は保証されない。増えたSLMによるresidency低下と減るbarrier待ちの勝敗は実機計測事項。

## 数値と安全性

演算contractはBF16 Q/K/V・BF16 probability、FP32 matrix accumulation、score、online max/normalizer/alpha。各tileは`m=max(old_m,tile_max)`、`alpha=exp2(old_m-m)`、FP32 probability sum、`fma(old_norm,alpha,sum)`でstate更新するが、PV入力の確率はtileごとにBF16 roundされる。64分割でtile-local max、sum association、alphaが変化し、最終FP32が近くてもBF16 probabilityが変わる可能性がある。R940では小さいscore/max差がBF16中点を跨ぎ2セルのround結果を変えた。比較ではpre-round P、中点距離、隣接BF16への方向、PV出力寄与を位置別に記録する。

採用基準は実際に到達する同model configのSGLang/vLLM経路のstorage/accumulation/roundingとteacher-forced logits/logprob/NLLを優先する。framework sourceの存在だけでStrataのK8/V8 decode→BF16 pack契約との一致を主張しない。scalar FP32 oracleは差分診断用。main branchは可変なのでkernel/commitを実験前にpinする。

Bounds/lifetimeは既存gateを保つ。負ID、logical/physical page範囲外、`live_cells`超過、partial final pageはK/V/scaleを読まずmissing/zeroとする。scratch/output/input alias、capacity算術、NaN/Inf・scale異常、12+4 head、256 dims、duplicate-ID仕様を検証。`rows`は64要素、scratchとoutputはcompletionまでcaller-owned、pack→attentionは同一in-order queue。physical 262144 context/page末尾も検査する。empty/partial tileが未初期化scoreや64列外を読むことがないようにする。

## 一度の最小比較とgo/no-go

Mainは現在の測定完了後、CellTile template化で既存32 pathを維持し、別opt-inの64 pathを足す。単一比較要因はtile幅だけ。同一binary内の32/64でselector・query/ID/steps/page residency/queue・入力順を揃え、実route、component event time、tile数、kernel時間を記録する。clean repeated samplesに、local memory/register/spill、可能ならoccupancyとbarrier stallを対応させる。correctness境界はselected count 0/1/31/32/33/63/64/65、invalid/valid page、tail、NaN/Inf/scale failure、12+4 heads、physical end。数値はBF16 P crossingとframework oracleに加えteacher-forced long inputを含める。

**Go**は実route/lowering確認、bounds/lifetime/fault gate合格、QSA component改善が反復差とnoiseを越えること、同一long-input model cohortでtotal prefill改善が再現すること、他phase無回帰、framework/task数値gate内が全て揃う場合だけ。occupancy/softmaxが悪化要因、改善がnoise内、P差がgate超過、memory/fault失敗、または期待形状へlowerされない場合はno-go。非exclusive model区間とbarrier数だけではgoにしない。
