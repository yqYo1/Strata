# R666 — Initial batched-prefill teacher-forced NLL: lifetime and publication audit

Read-only review on 2026-10-15 of the source-only `prefill-teacherforced-nll-v1` proposal, its writer/I/O fixtures, and the pinned current root generate/prefill/MTP path. The source pins for `src/program/generate.cpp`, `src/kernels/sycl/sequence.cpp`, and `include/strata/kernels/verify_kernels.hpp` match the current worktree exactly. No proposal was applied; no build, test, compiler, Python execution, GPU, process, Git, cleanup, private B/environment/live-run inspection, or source/report/index edit was performed. Existing R569/R573 already specify the quality-evaluation distinction; this report is limited to lifecycle, I/O, and integration gaps.

## Conclusion

The proposed opt-in is default-off and adds no queue work or allocation in its disabled path. The prompt callback and scoped owner design are directionally sound: one diagnostic NLL output buffer plus gold IDs are allocated before prompt execution; per-row heads/NLL kernels enqueue on the same in-order queue; one chunk-sized readback/wait occurs; failure paths drain before local owners unwind; MTP expert restore completes before explicit owner retirement and before the final `.meta` completion link is published. The artifact has exact input-token identity and sequential all-prediction coverage by construction, up to 262,144 input IDs.

This is still source-only and unqualified. Two boundaries need explicit handling before integration: (1) static mode/length conflicts are rejected before GPU preflight, but invalid output paths, ID values outside the actual vocabulary, and missing native head are only discovered later, after model/runtime/device initialization and much of setup; (2) the comparator checks identical token bytes and basic metadata but does not bind the pair to source/binary/model/configuration hashes or the actual storage dtype/placement recipe. External recipe pins are documented but not enforced by these files. Also, success metadata does not include an input-token hash (the comparator computes one from raw token bytes), and a raw-file hash must be recorded in the supervising receipt.

## Callback, owner, and MTP ordering

Current root `Prefill::run_impl` calls `on_chunk` after each prompt chunk's normal stream work has completed (`src/prefill/prefill.cpp:3079-3087`). The existing callback installed by `generate.cpp` for MTP calls `draft_kv` and falls back to `mtp.prefill` (`:6438-6443`); `run_prompt_with_mtp_experts` wraps the whole prompt, then restores detached experts before returning (`:119-170`). This makes the residual chunk a valid read-only source during the diagnostic callback.

The proposal wraps the existing callback, performs one row at a time through a local `BlockBuffers` copy, and calls the previous MTP callback only after successful diagnostic readback/write (`source.diff`, NLL callback addition). It redirects only the local `bb.R`; queued GR/head operations use existing scratch and `d_logits`. Each head/NLL/readback sequence stays on `main_cs`/`main_stream` (the same pointer at root `generate.cpp:2254-2259`). `DraftUploadGuard` is armed before the first enqueue and drains that stream on early return/exception; unknown completion invokes `cleanup_fail_stop`, retaining owners rather than unwinding them. After prompt return, the MTP restore helper has already completed. The explicit `PrefillNLLOwner.close()` then performs a checked stream sync and frees both buffers before `Writer.finish()` publishes completion (`generate.cpp` proposal additions around callback/finish). On the ordinary failure return, reverse destruction runs owner close before Writer destruction. This avoids freeing gold/NLL while queued work could still read/write them.

The correctness of this source design still depends on integrating the callback in the exact standalone call site only and retaining its scope through the full `run_prompt_with_mtp_experts` return. The proposal rejects `--serve`, split, peer, remote, stage, graph-only, GPU-only-full, selected-logit overlap, and truncated `prefill-until`; no serve/session/RESTORE semantics are established. There is no independent source proof that a failed partial setup leaves every non-NLL prefill owner safe; existing Prefill initialization/cleanup contracts remain responsible for that route.

## Default-off and reject timing

The new switch is read only inside the SYCL compile guard. Unset means `collect_prefill_nll=false`; the writer, buffers, callback, head calls, clocks, and queue operations are all guarded. The process environment is not mutated. An empty value is rejected. The early preflight rejects incompatible flags and token-count bounds before device preflight (`generate.cpp` proposal around lines 1457 onward), and selected-logit env presence is rejected even if only one selected-logit variable is set.

The preflight does **not** validate the destination's exclusivity/parent/metadata collision, full token IDs against `n_vocab`, or actual `native_head.loaded()`. Those checks happen in `Writer::begin` / the later setup block around the prefill site, after native model/head/cache setup and GPU runtime use. Input-ID validation still precedes NLL gold upload and diagnostic head execution, as claimed; it is not a pre-runtime rejection. Empty output path and unsupported scope are early; filesystem and model-dependent failures are late. The code only requires a nonempty path, so the README's “absolute” path requirement is not enforced. A resolved absolute path or an explicit documented allowance for relative paths should be captured in the eventual receipt.

The full input length cap is 262,144; `Writer` stores all int32 prompt IDs and expects exactly `n_input-1` NLL rows for targets `tokens[p+1]`, matching batched prefill's omitted final prompt row. The implementation can represent that maximum, and the source fixture checks the maximum writer budget. That does not alone prove a physical 262,144-token run: the external recipe must set/check `--max-context`, model/session admission, actual batched count, decode headroom where relevant, and context-boundary behavior. No runtime receipt exists.

## Input/gold identity and result pairing

`Writer::begin` verifies all int64 input IDs are in `[0,vocab)` before narrowing to int32 or creating files; it keeps the exact int32 token sequence in the raw file. The callback supplies gold pointer `tokens+1`; records are sequential with position implied by record order, and `append` checks each record's gold against that same copied token vector. `chunk` and `append` enforce contiguous, nonoverlapping coverage from row zero; `finish` requires both seen and written counts equal `n_input-1`. The comparator verifies raw token bytes match across arms and every record gold equals the next input ID. Thus token/gold identity and full position coverage are strong within each file, conditional on a complete artifact.

The metadata does not include source SHA, binary SHA, model/weight identity, prompt/template/thinking provenance, effective environment, chunk size, KV/context settings, MTP route, FP32/FP16 storage dtype, or GPU-prefix/host-tail choice. It explicitly says `storage_dtype_placement=external-recipe-required`. The comparator compares vocab, `head=native`, head GGML type, scope, and exact token bytes, but will accept same-token NLL files produced with different binaries, model weights, chunk settings, MTP, or residual storage plans. Keep those values and the exact command/env in a paired external receipt and refuse a quality interpretation without them; better, attach/compare an external manifest hash before using the consumer. The printed raw/token hashes are computed by `compare_nll.py`; they are not written by `Writer` into final metadata.

## File creation, bounds, and publication

The raw layout is native-endian `{magic, n_input, vocab, written_rows}`, all int32 input tokens, then sequential `{gold:int32,nll:float32}` records. Maximum raw size is 3,145,736 B for 262,144 input IDs and 262,143 predictions. Metadata is capped at 4,096 B and raw + 4,096 remains below 4 MiB. `compare_nll.py` checks both read bounds, magic/version/scope, dimensions, exact raw length, all metadata row counts, token IDs, all gold records, and finite nonnegative NLL values.

`Writer` checks for an existing completion metadata path, opens raw and `.meta.partial` with exclusive `wbx`, checks each `fwrite`, rewrites row count only at finish, checks raw flush/close, writes completion metadata, checks metadata length/flush/close, then publishes `.meta` with exclusive hard-link creation. A competitor's completed `.meta` is not overwritten. The final metadata link is the only completion marker; an incomplete raw path or `.meta.partial`, even one containing a footer after an interrupted publication attempt, is not accepted by the comparator. Hard-link failure (including unsupported filesystems) fails the run. This protocol is atomic with respect to the final metadata name, not a two-file atomic rename and not crash-durable: no fsync is performed, which the README correctly disclaims. `.meta.partial` intentionally remains as a second hard link after success; failed starts may leave incomplete raw/partial files. Preserve a failed run as failure evidence and record hashes/paths before any later cleanup, per the retention policy.

The writer and I/O fixtures cover exclusive collisions, partial-path failure, whole-chunk validation, ordered/missing/overlap/duplicate coverage errors, invalid NLLs, maximum size, hard-link publication race, and injected `fwrite`/`fflush`/`fclose`/`fprintf` failures. They are source-only and use `assert`; their prescribed builds must keep assertions enabled. The I/O shim does not simulate short positive writes of every byte count or power-loss durability. It checks failures are not marked complete, not that an interrupted filesystem retains durable data.

## Remaining gates

1. Reject or explicitly record relative paths; decide whether filesystem preflight belongs before expensive device setup. Keep actual vocab-dependent token checks before gold upload/head execution.
2. Bind each candidate/control pair to one external manifest with exact model/source/binary/compiler/runtime/driver, input/template identity, context/chunk/KV/MTP, effective environment, and residual-storage dtype/placement. Require the same manifest identity except for the intended arm; store raw and token hashes and all individual outcomes there.
3. Run the CPU writer/I/O failure fixtures with assertions enabled; run the SYCL row-NLL fixture and configured-target build in the owned serial gate. Then verify callback order under normal MTP and expert-detach/restore, all rows across chunk boundaries, failure recovery/fail-stop, and no publication after any failed/cancelled run.
4. Run the same fixed IDs through paired FP32/FP16 (and later separately implemented BF16) for every target row, up to 262,144 actual context only when that physical context is admitted. Repeat FP32 to estimate baseline variance; label task/retrieval/RESTORE and physical-context qualification separately. This artifact supplies a diagnostic path, not a quality threshold or qualification.

R569/R573 already contain the broader numeric and task-quality design. No result from this source proposal is a build, passing fixture, measured NLL, physical 256K, RESTORE, speed, or model-quality claim.
