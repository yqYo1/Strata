# Source-only Level Zero metric enumeration proposal

This package supplies an independently authored host C++ enumerator and a Main-only build/enumeration controller. It does not establish a result for this host: compilation, tests, native execution, process inspection, device queries and profiling were not performed by this worker. All new files stay in this directory; active source, pins, receipts and status were not modified.

## Files and source identity

- `enumerate.cpp`: direct Level Zero host calls, JSONL API entries/results and properties, bounded enumeration, and a 15-second owned stdin hold.
- `result_names.inc`: API enum identifier-to-name mapping mechanically transcribed from the pinned header. No algorithm or helper copied from PTI or another engine.
- `main_controller.py`: separate Main-only build and enumeration modes; pinned `direct_owner.py` import, immutable child environment, exclusive existing measurement lock, ownership/budget and journal/dump closure gates. No automatic build-to-run transition.
- `manifest-candidate.json`: unsealed original inventory and input pins. It intentionally cannot authorize execution.
- `source-provenance.json`: full SHA256/size/path identities for the source and receipt inputs, immutable official revisions, license and limitations.
- `source.patch`: complete additive patch for all deliverable files other than itself and `SHA256SUMS`. No Git operation is needed to read/review it.
- `SHA256SUMS`: complete final package snapshot excluding itself; Main must independently review all files and record its hash outside the package before any execution.

## Exact question and limits

The proposed experiment asks whether this non-root current stack returns real metric groups/properties for the Intel GPU matching the receipt's vendor `0x8086`, device `0xe20c`, and PCI `0000:05:00.0`. It calls `zeInit(0)`, `zeDriverGet`, driver properties/API version/extension properties and `zeDeviceGet` root-device properties, then `zetMetricGroupGet`/`zetMetricGroupGetProperties` and bounded `zetMetricGet`/`zetMetricGetProperties`. It records driver/device UUIDs and reported name as well as PCI identity. `ONEAPI_DEVICE_SELECTOR` is not included or assumed to constrain raw `zeDriverGet`. No subdevice traversal is promised.

Bounds are 8 drivers, 32 roots per driver, 512 extension properties per driver, 256 groups per root, 1024 total groups and 4096 total sampled metrics. Each group gets at most its first 8 metric properties, with requested/available counts and an explicit partial-catalog flag; this is not a complete metric-name catalog. Count/list changes, exceeding a cap or invalid/null returned handles produce `INCOMPLETE`, without retry. Group name/description/domain, raw sampling flags, event/query, time and tracer flags, unknown flag bits, metric name/description/component/units/tier and named/numeric type are printed. All actual API results include name, decimal and hexadecimal code, including failures. Provider text is bounded and JSON escaped.

The helper does not create a SYCL runtime, context, queue, command list, event, allocation, streamer, query pool or metric configuration, and submits no authored GPU commands. Driver initialization and metric enumeration are still native driver activity and must be serialized by Main; source inspection cannot establish absence of driver-internal work. It never changes process environment, privileges or system policy, and does not signal processes. The controller signals only owned pidfds through the existing owner implementation when closure requires it. There is no metric activation, collection or automatic alternative path.

`ENUMERATION_PASS` requires one exact target identity and at least one nonempty group with the requested sampled metric-property calls completed, plus all traversed API calls succeeding within caps. Enumeration stops on an API failure, so a failure before later drivers/roots means the topology walk is partial. `DEPENDENCY_UNAVAILABLE`, unsupported, insufficient permission and not-available/uninitialized results map to `UNAVAILABLE`; zero drivers, missing target/PCI identity or no target nonempty groups also cannot pass. Device-lost/reset/unknown errors remain `ERROR`, with fault closure handled separately. Missing optional PCI identity cannot qualify the target. None of these outcomes is evidence of hardware scarcity. Group flags advertise an API capability; enumeration PASS does not qualify collection, per-kernel attribution, specific counters, bandwidth, SLM wait, occupancy or performance.

R748/R875's `/proc/sys/dev/xe/observation_paranoid=1` observation is historical policy evidence, not an executed metric-enumeration result. No current sysctl/permission/group/device read was performed by this worker. PTI's policy hint in `ze_metrics.h` is on streamer-open failure, distinct from enumeration. The historical source `6354f0b4ff3731466795410e11ca9ef785c9d326`/engine `85643f3926bb9d212945659cb7ddb264e101ca9b2d5fa8f19430e945140ad191` profile is kept distinct from source `63326f98c36656cf3a3e1adcc54c3c25a02aa6ee`, build receipt `3fca64de3664a74ac5a376e4e40cb8a3e2910113f29a4597a564c2f903381327` and current tiny fixture binary `d564fc95854988efb24b990ba64bcd5ac092fdfb597c21b0d4a65c4c54e23bef`. `own-vllm-resource-timeline-tiny-v3.json` is pinned and read as existing timing compatibility evidence, not metric enumeration or collection evidence. No inference kernel/resource number is transferred between these sources.
