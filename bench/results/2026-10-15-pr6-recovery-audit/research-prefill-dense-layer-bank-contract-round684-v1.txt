# Dense layer-bank ownership contract for long prefill (R684)

Read-only audit of the one-active-layer dense-weight assumption in `prefill-capacity-plan.ja.md` against current source owners and readers. No implementation, patch, compile, test, GPU work, environment/process inspection, Git mutation, or cleanup was performed. The proposed bank is not implemented or qualified.

## Capacity interpretation and byte accounting

The metadata receipt records 300 native matrices totaling **2,116,951,040 B** (`prefill-capacity-metadata-v2.json: actual_native_weight_bytes`) and a compact canonical `WeightTable` pool of **1,538,035,200 B** (`actual_canonical_pool_bytes`). These are disjoint GPU payloads in the measured native-pack configuration: `measure_prefill_capacity_v1.py` forms `skip = native_tensors + output.weight + token_embd.weight`, then computes canonical bytes only for rows outside `skip`; `generate.cpp` obtains this skip set before `WeightTable::load` and `NativeDense::load` attaches native projections. Do not count the native projection payload a second time as canonical bytes.

Thus the current target-model dense-weight payload owners total **3,654,986,240 B (about 3.404 GiB)**: one 1,538,035,200-B canonical arena plus 2,116,951,040 B across `NativeDense::weights_`. This is the gross theoretical recovery from those two target dense-weight owners if every other reader and special owner is handled. `NativeDense::weight_bytes()` excludes its shared `scratch_` (`native_q8_1_bytes(max_in)`); the native allocation also has that small scratch owner, not included in the exact sum. Do not add the 77,012,992-B layer-47 canonical+native payload on top of the full-model sum: it is a subset of those two owners. Layer 47 is 32,366,592 B canonical plus 44,646,400 B native; with its 1,363,148,800-B packed expert layer the plan's active combined bank is 1,440,161,792 B.

On a complete 48-layer prefill sweep where each dense layer is uploaded once, the **GPU upload payload** is likewise 3,654,986,240 B in total across canonical and native forms; the maximum layer-47 dense payload is 77,012,992 B. This is not an additional capacity term and does not count packed expert uploads, whose separate per-layer staging is already part of the existing layer-major design. It is not an exact disk/page-cache read total: canonical index rows retain `src_off`, `src_bytes`, `file_id`, conversion kind, and plane sizes, and source bytes can differ from `WeightRef::bytes` when BF16/F16 is narrowed or FP16 scales are widened. A bank loader should report both source bytes actually read and device bytes actually uploaded, summing each source tensor once per layer pass. The native GGUF payloads use the recorded tensor type/shape and are copied from `GgufFile::tensor_data` (`native_dense.cpp:153-169`).

The figures are weight payload capacities, not a live memory admission. Add or independently reserve per-layer expert-cache bytes, shared GEMM scratch/workspace, GDN/QSA/session state, and runtime headroom exactly once as in the capacity report. Special owners have distinct lifetimes: `NativeHead` output weights/scratch, `NativeEmbed` mapped host data, target PLE/session state, and MTP's own full draft `dense_` allocation are not part of the 3,654,986,240-B sum. The capacity plan assumes no decode-only MTP full-draft weights during target prefill; current code can call MTP `draft_kv`/`prefill` from the prompt callback, so that assumption needs an explicit policy before reclaiming MTP memory.

## What source preserves for exact reconstruction

`WeightRef` in `include/strata/core/weights.hpp` keeps canonical tensor shape and form (`ne0/ne1`, `kind`, quantization fields and `codes/scales/offset_bytes`), original pack coordinates (`src_off/src_bytes/file_id`), FP16-scale flag, activation kind, and the current device pointer/residency. `WeightTable::load` resolves file IDs to `dense.bin`, `embd.bin`, `experts.bin`, or `extra.bin` and applies the indexed plane conversions (`src/core/weights.cpp:35-67,145-270+`). The metadata can be retained while canonical bytes are reloaded from the original pack; the loader currently has no per-layer load or release/view API and its table entries currently hold live arena pointers.

For native matrices, `NativeDense::load` validates GGUF architecture/split metadata, tensor bounds/overlap, eligible names, MMVQ support, shapes, and compatibility with each canonical `WeightRef`; it copies original packed GGUF bytes into one `cudaMalloc` per tensor and then publishes `native_data`, `native_type`, and the shared `native_q8_1` scratch (`src/core/native_dense.cpp:39-61,71-188`). `NativeDense` owns the resulting pointer list and scratch, but retains neither each `WeightRef*` nor source shard/offset metadata, and has no detach/reload method. Its destructor frees allocations without clearing the table's published pointers. A reload from original GGUF shards is possible without D2H in principle, but requires retaining/checking shard identity and rebuilding the same layer's metadata-to-source mapping; tensor payloads should not be snapshotted back from GPU.

The exact original formats are recoverable only while the pack and GGUF inputs remain available and unchanged. A loader must bind source identity (header/index hash plus file identity, and verified tensor name/shape/type/offset/length) and reject stale/truncated input rather than uploading another file's plausible bytes. Retain `WeightRef` metadata as CPU data independent of arena lifetime; never leave freed pointers reachable with `resident=true` or non-null `native_data`.

## Smallest prefill-only rebinding boundary

The natural execution boundary is the existing SYCL layer-major loop in `src/prefill/layer_major.inc`: it checks cancellation, drains the compute queue before a layer, loads that layer's experts, sets `stage_lb_/stage_le_`, calls `run_impl` for the whole prompt, drains again, and only then advances (`:292-370`). Add a prefill-owned *immutable active-layer view* selected for that `run_impl` pass, with canonical and native pointers for the layer's required tensors; keep the shared metadata table and decode table distinct. `LayerView`/`WeightTable::find` in `include/strata/core/layout.hpp` are already the narrow lookup interface used by `layer.cpp`; `Prefill::Impl::wt` is currently a pointer to the full const table (`src/prefill/prefill.cpp:424,727`). A view can be a copied `WeightTable` metadata map with only the active layer's device pointers patched, or a small resolver passed through the layer call path. Avoid mutating the table shared with decode/verifier/MTP.

The active view must also cover fused next-layer normalization reads: `run_impl` builds `LayerView(*m.wt, nl)` for `hc_ffn_norm.weight`/`hc_attn_norm.weight` at `nl=l+1` when fusing (`src/prefill/prefill.cpp:3006+`). Either keep these small norm tensors in an always-resident shared owner or include the next layer's norms in the active bank and size that explicit overlap; a strict one-layer-only pointer set is insufficient. The one-layer capacity total in the plan does not itself state this fusion exception. Layer-1 PLE uses `ss.ple.w`, which has its own session owner; embedding lookup can use global `NativeEmbed` (`embed_row`, `native_head.hpp`) in the target configuration, otherwise `token_embd.weight` is another table consumer that must remain available. MTP `record_forward` reads `wt_->find("token_embd.weight")` when no `NativeEmbed` is registered (`src/core/mtp.cpp:804-813`); the table object and that special source must survive even if its dense arena is released.

At a layer boundary, the prior active bank is reusable only after the in-order prefill queue and every callback/reader have retired. Load into a reusable destination bank only after that proof, then publish the view atomically for that layer; do not overwrite a bank still referenced by a queued kernel or captured graph. A direct per-layer extension of `WeightTable::load(skip=...)` is plausible because it already compacts skipped rows and records metadata, but current `load` clears/repopulates the table and uploads all kept rows, then calls `cudaDeviceSynchronize`; using it unchanged per layer risks table identity changes, repeated global syncs, and shared-table invalidation. A purpose-built layer loader/view is the smaller clean boundary.

## Reader lifetime and failure contract

- **Decode/session graphs:** `session_capture` records kernels with current `WeightRef` device addresses, and `session_replay` launches them later (`src/core/session.cpp:192-370`). The whole-token graph also captures model calls (`src/core/session.cpp` token graph API; created in `generate.cpp:4212-4274`). Freeing/reusing dense storage while either graph exists leaves stale graph node arguments. Destroy all affected graph execs after draining every owning stream before releasing the full decode bank; after complete decode weights are restored, recapture graphs against restored/rebound pointers and verify they point to live owners before the next decode. Graph recapture itself may allocate/fail and must have a safe no-graph fallback or fail-stop before inference resumes.
- **Verifier:** `Verifier::init` stores `wt_` and takes layer refs for verify kernels (`src/core/verify.cpp:311+`, per-layer lookup from `:538+`). It is constructed after prompt in the generation path (`generate.cpp:6879+`), but any persistent/preconstructed verifier must be excluded from the release interval. Only initialize/recapture it after full target weights are restored; do not infer safety from object construction timing alone.
- **MTP:** `MtpDrafter` retains `wt_`, `head_`, its separate draft `dense_`, and lazily captured round/step/prefill graphs (`include/strata/core/mtp.hpp`, `src/core/mtp.cpp:125-166,736-795,1007-1055`). The prompt callback may invoke `draft_kv` for each final-layer chunk. If this callback is enabled, retain the MTP draft dense owner and all its graph readers; do not include those bytes in target dense recovery. Its target token embedding must resolve through a surviving `NativeEmbed` or separately retained owner. If MTP prompt work is deferred, defer graph capture/bind until after target decode weights are restored, or otherwise prove the MTP graph does not capture target layer pointers.
- **Normal error/cancel/throw:** current `run_layer_major` uses a `DraftUploadGuard` with checked compute/copy drains and fail-stops if it cannot prove retirement; RAII owners are deliberately declared before the guard so the guard drains before their destruction (`layer_major.inc:~180-290`). Extend that owner ordering to active-bank pointers and restore the prior callbacks/view after the checked drain. On cancellation, allocation/read error, callback false, or exception after a bank swap, keep the current and any destination bank alive through drain, clear the prefill view, and either restore the complete decode owner set or stop before exposing a partial table. Existing `Restore` does not roll back session tensors (`:~245`); weight-owner cleanup must not claim state rollback.
- **262144 and RESTORE:** keep all 48-layer metadata, source identity, session GDN/QSA/KV state, residual state, and physical-context bounds independent of the temporary weight bank. Full-context correctness must exercise actual admitted 262144 buffers and final-layer callback, then restore the complete decode owners and run decode. A conversation/session RESTORE restores state, not missing weights; it must be gated until complete dense owners and valid graph readers exist. Include restore-and-continue after at least one layer-bank release, with exact next output/state against the all-resident oracle.
- **Pointer publication:** add a checked owner/view state machine: no freeing while any in-flight queue, callback, graph exec, `Verifier`, or MTP reader can reach the pointer; no partial publish if any tensor allocation/upload fails; no `WeightRef` with stale `data/native_data/native_q8_1`; no double-free between arena, `NativeDense`, and a reusable bank. On input identity or byte-count mismatch, reject before use.

## Source-only feasibility and gates

This is source-only feasible in principle: every canonical tensor's source format/location is represented by index metadata, and native GGUF tensors can be re-read by validated name/shape/type from the original shards. It is **not** a free/reload switch available in current classes. The main blockers are ref-safe detach/republish APIs, a prefill-only view separate from captured decode consumers, fused next-layer norm pointers, MTP prompt callbacks, and safe graph retirement/recapture. The minimal fallback is to keep the existing full decode owners live and run current layer-major prefill; that preserves correctness but recovers none of the 3.655-GB target dense payload.

Required component oracle before performance/adoption: for each layer, compare a normal full-resident `WeightTable` pass with the single-active-bank pass on identical tokens/chunks/configuration. Check each active tensor's shape/kind/quant metadata/source hash and byte-exact uploaded payload against the reference owner; compare per-layer output/residuals and final GDN/QSA/indexer/KV state, final logits and callback/MTP handoff. Inject allocation failure, short source read, stale source identity, normal cancellation at load/compute/store boundaries, callback error, and thrown exception; prove checked retirement and either full owner restoration or fail-stop. Then prove graph exec destruction and recapture parity, actual RESTORE-and-continue, decode continuation, and physical 262144 context. This is an owner/lifecycle gate; kernel speed and long-prefill throughput require separate clean repeated measurements.

Main priority: first qualify the smaller component-level owner/view API and graph retirement under ordinary context with MTP prompt callback both retained and explicitly deferred; only then run expensive 262144/RESTORE and throughput trials. Do not fold this capacity assumption into admission or claim the theoretical 3.404-GiB gross reclaim until allocator receipts show the owners were released and no stale readers remain.
