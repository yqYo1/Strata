# R662 — Layer-major residual precision: numeric scope and quality gate

Read-only source and public-artifact audit on 2026-10-15. No product edits, build/test, GPU or process work, Git operation, raw model inspection, or private/in-progress artifact access. The reports and receipts below are existing public A artifacts.

## Conclusion

Layer-major residual storage is a real recurrent numeric intervention: each non-final layer stores every chunk's four-branch residual in the selected dtype; the next layer restores it to FP32 before unchanged model operators run. It does not change recurrent state, KV, weights, attention, or layer arithmetic directly. FP16 currently exists in the root path. BF16 does not: the planner and parser enumerate only FP32/FP16, and the input/store/restore path only converts FP16. The existing BF16 bit helpers are not an implemented layer-major mode.

The existing small synthetic receipt is a conversion/path screen, not model quality evidence. Its reported residual relative-L2 of about 9.73% and one-row KL about 0.027 have very narrow scopes described below. Separate natural-history diagnostics are encouraging but selected and correlated. The prior `auto24576` numerical FAIL remains a FAIL; do not reclassify or mask it. The latest fixed-prefix evidence has its own configuration and does not establish the automatic-admission route.

The most useful next quality gate is paired teacher-forced token NLL over a full natural long history, plus selected full-vocabulary distributions at registered positions and task/retrieval checks. The current root already has a default-off `STRATA_PREFILL_LOGITS` + `STRATA_PREFILL_LOGITS_POSITIONS` final-head callback in `generate.cpp`; R573's suggestion to add such a callback is therefore superseded. The existing comparator only reports bit equality/top-1/cosine/RMSE; it does not calculate KL or target NLL. `Verifier::window_logprobs()` and serve `STRATA_LOGPOS` give teacher-forced target log-probabilities for their window path, but are not the same measurement as the initial chunked batched prefill.

## What the reported numbers mean

`layer-major-storage-small-v1.json` is a synthetic 513-token run (512 batched rows in chunks 257 and 255; deterministic synthetic IDs), on a small fixture model. The recurrence did FP16 roundtrip at each inter-layer store, but its residual comparison is only eight selected final-layer rows (positions 0,64,...,448; 81,920 scalars), not all residual transitions/positions. Relative L2 is `sqrt(sum((candidate-reference)^2)/sum(reference^2))`; FP16-auto is about 0.0973. The KL around 0.027 nats is one captured 248,320-logit next-token distribution, not sequence NLL, full-token perplexity, or a 513-token average. This receipt establishes that the conversion path and fault checks ran, not acceptable quality.

`saved-residual-precision-screen-v1.json` is a different operation: CPU post-hoc conversion of 541 selected positions from a saved natural-history *final-layer* tensor (34,602-row history, 5,539,840 scalars). Its FP16 rel-L2 0.000211 and BF16 0.001677 say how that one saved final tensor rounds. They do not include repeated per-layer storage/restore, logits, NLL, or task outcomes. They must not be substituted for the 9.73% small test or described as recurrent model-quality results.

`selected-prefill-long-summary-v1.json` is yet another diagnostic: one natural thinking-template history, 34,603 actual input tokens / 34,602 batched rows, and 19 registered prediction positions. The receipt says positions are correlated, not independent tasks or full-token PPL; KL min/median/max is roughly 0 / 0.000994 / 0.04358 nats, sampled target-NLL delta mean −0.0822 nats with range −1.157..+0.497, and top-1 matched at all 19. It explicitly records `quality_qualified:false`, `physical_262144_qualified:false`, and `restore_qualified:false`. Treat this as selected-logit observation only, not a pass or full perplexity estimate.

The 0.5% relative-PPL and 299-item/1-percentage-point figures carried in R569 are proposed engineering thresholds, not validated target-model guarantees. Do not use them as already-approved acceptance criteria. Calibrate FP32 repeatability and agree the statistical margin before applying any numeric pass/fail bar.

## Numeric boundary and controls

`LayerMajorResidualPlan` calculates bytes as width × 4 for FP32 or ×2 for FP16 and chooses GPU-prefix/host-tail placement from a budget. In the current layer-major callback, each non-final layer packs its callback residual once (`to_f16`, shared RNE helper), stores it in GPU or host storage, and the next layer unpacks once into the live FP32 `m.R`. Host-tail FP16 uses a single chunk staging buffer. Final-layer callbacks remain FP32. The conversion does not clamp finite overflow: FP16 can overflow to infinity, preserve subnormals down to its representable range, and round very small values to signed zero. BF16's eight-bit exponent retains FP32-like range but has fewer fraction bits; it trades range headroom for coarser relative precision. This is a tradeoff to test, not a basis to predict which wins on the quantized model.

For this model's gated-residual stream, D is 4 × 2,560 = 10,240 FP32 scalars per row. A format comparison must hold row count, chunk geometry, token IDs, host/GPU boundary, expert/cache settings, and build fixed. FP32-auto versus FP32-host/fixed is a placement/address control, not a dtype comparison. The old automatic 24,576-row case is a separate known numeric failure; keep its original status and evidence unchanged. Do not compare FP16-auto against a differently admitted FP32-auto run and attribute the difference to storage precision.

A sound staged evaluation is:

1. Repeat identical fixed-prefix FP32 runs to establish baseline variability and retain the existing auto24576 FAIL unchanged.
2. Compare FP32 and FP16 using the same exact natural token IDs, context/chunk settings, explicit GPU prefix, and cache/residency config. Repeat with interleaved clean process order. Capture selected logits at positions spanning beginning, middle, end, chunk boundaries, prefix/tail boundary, and the final valid prediction row; evaluate KL(reference FP32 || candidate), target NLL delta for token[p+1], top-1/top-2 margins and flips. Add full continuation NLL only through an explicitly teacher-forced path; label the initial-batched-prefill and subsequent verifier-window parts separately.
3. Once BF16 storage path is actually implemented, run BF16 as a third independent arm under the same control. Do not infer it from post-hoc CPU tensor casts.
4. Run paired long retrieval and thinking-on task items under identical prompts, output budget, sampler, MTP condition, and scoring. Strong/weak MTP strata are separate; sequence mismatch alone is not a quality failure. Keep task outcomes distinct from logit metrics.
5. Before a 256K claim, repeat at a physically admitted near-262,144-token context with decode headroom and the same checks. The current ~34.6K selected-position receipt cannot qualify that boundary.

## Implemented versus remaining

The relevant current root path is `src/program/generate.cpp` around its `STRATA_PREFILL_LOGITS` setup and `Prefill::on_chunk` callback: it writes full-vocabulary logits for configured positions and target token IDs during native chunked prefill. It is default-off and records selected rows; this is implemented diagnostic plumbing, not evidence that FP16/BF16 passes quality. The current `tools/sycl/compare_logits.py` checks shape, exact equality, top-1 agreement, cosine, and error magnitude. It has no stable log-softmax, KL, or target-NLL summary. `Verifier::window_logprobs()`/`STRATA_LOGPOS` provide target log probabilities in their verification-window path, but do not constitute every-token logits from the first batched prompt pass. A full rolling teacher-forced long-history evaluation and task-quality suite remain unproven by the receipts audited here.

The model-family paper describes Qwen3.8-Flash-Next's four-branch Gated Residual architecture; this supports testing the actual widened residual stream but does not establish reduced-precision safety: [Qwen3.8-Next technical report](https://arxiv.org/abs/2608.30320). Intel's datatype reference summarizes the FP16/BF16 exponent-versus-fraction tradeoff: [oneDNN Developer Guide](https://cdrdv2-public.intel.com/782589/onednn_developer-guide-reference_2023.2-768875-782589.pdf). As an implementation comparison only, vLLM IR explicitly casts its fused residual sum back to the original dtype before normalization; this illustrates that residual rounding is a model/operator contract, not an interchangeable storage detail: [vLLM IR layernorm](https://docs.vllm.ai/en/latest/api/vllm/ir/ops/layernorm/). None of these external sources qualifies Strata's proposed storage mode.
