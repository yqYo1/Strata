Confirmed source contracts
  1. Prompt graph exclusion: src/core/mtp.cpp:661-670 defines `full = step_row0 >= 0`; every `record_forward(T, -1, ...)` is K/V-only, and only full forwards reject missing/detached experts. capture_prefill/capture_prefill_dev at :895-910 record `-1`; E-9 `Prefill::draft_kv` likewise routes to `record_forward(...,-1,...)`. Those graphs consume dense tensors, state/KV and scratch, but the MTP MoE branch is after attention and is only entered on the full-forward route. Thus cached prompt graphs need not be retired with expert storage. This is direct source structure, not captured graph inspection.
  2. Decode readers: capture_round at :913-953 records catch-up K/V plus the full selected row and links `window_R_`; capture_step at :962-992 records one full row. Both ordinary and coupled arrays are separate (`round_exec_`, `step_exec_`, `round_exec_c_`, `step_exec_c_`). `detach_prefill_experts` :438-470 synchronizes `cs_`, destroys all four graph families with checked results, then frees experts; it deliberately leaves `window_R_` untouched. The caller must serialize all public MTP calls as the header documents. Current caller is synchronous in generation; no internal lock protects external concurrent calls.
  3. Restore/re-capture: restored bytes are allocated to a fresh pointer and copied from `expert_host_source_` in <=64 MiB views, with each copy followed by a checked `cudaStreamSynchronize` before publish (`mtp.cpp:338-433`). `capture_round/step` select the correct ordinary/coupled graph family lazily; after release they call `finish_expert_capture`, which checked-ends capture, instantiates, destroys the source graph, graph-uploads, and checked-syncs before retaining exec (`:837-873`). Successful earlier round/step graphs may remain if a later capture returns false; process/request must then treat state as failed and never pretend ordinary decode resumed. The current helper caller returns a draft failure. C++ exceptions in recapture trigger `_Exit` while owners remain live (`:954-958`, :988-992), whereas default-off behavior rethrows unchanged.
  4. Borrowed Verifier final_R: the pointer is bound in `generate.cpp` at :4801 and :6812 and retained as `window_R_` at mtp.cpp bind (:622-626). Release clears only decode graph handles and `experts_`; it does not retarget/free Verifier storage. Prompt execution occurs outside a verifier-window reader; after restore decode uses the same verifier object/allocation. This lifetime premise is valid for the current synchronous generation flow. Any future verifier re-init/rebind while MTP graphs exist still needs a checked MTP graph retirement boundary.
  5. Entrypoint guards and unwind: wrapper `run_prompt_with_mtp_experts` at generate.cpp:119-173 requires exact `STRATA_PREFILL_RELEASE_MTP_EXPERTS=1`, exact layer-major `=1`, long chunked prompt, SYCL and `supported`. It opens release scope, calls synchronous `prompt.run`, then explicitly closes/restores on both true/false return and catch/rethrow. Restore failure or telemetry failure is fail-stop. Scope destructor fail-stops if close was skipped (:496-509). Serve integration is at :5926-5930; the standalone generate path at :6496-6502. The supported predicate excludes multi-GPU/layer split/peer/remote expert routes. Short/window reads do not detach. Serve repeated calls therefore execute a fresh detach/restore around each eligible long segment, with restored experts before returning to decode or starting the next request.
  6. Prefill owners and MTP KV-only use: `Prefill::run` is synchronous and returns from run_impl only after its chunk pipeline and final stage callback; `on_chunk` is invoked at prefill.cpp:3022-3030. In serve wrapper, `prompt.run` has returned before restore begins. E-9 callback draft_kv is K/V-only; legacy mtp.prefill E-4 also passes `-1`. E-4 now holds its `rec` host vector under DraftUploadGuard from before first H2D through checked final stream sync (`mtp.cpp:1055-1111`), so its ordinary return/error/exception destruction ordering is covered by the reused guard. This supplements but is distinct from expert graph lifetime.
  7. 675 MiB host restore source: loader reads exact expected file length, hashes owned bytes, then keeps a private vector; restore does not reread file or allocate a full host slab (`mtp.cpp:351-385,413-420`). Source vector stays owned for repeated serve. Admission checks `bytes + 1 MiB` against available memory with an 8 GiB floor (`:355-356`), but this is an admission snapshot, not a physical-memory reservation; other host allocations can still consume memory. The requested “immutable RAM” property is by private ownership/API convention; the class has no writer exposed, but C++ vector itself is mutable internally.

Concrete open contracts / fixes to consider
  A. Checked recapture false-return can leave a mixture of newly-created and absent ordinary/coupled graphs (`mtp.cpp:913-992`). Current caller must not continue using the same MTP owner after a recoverable graph API error unless it can prove partial graph state and K/V state are coherent. Existing wrapper surfaces false for normal error returns, but it does not mark the MTP object poisoned; serve's outer failure path exits the request/process path, so the present caller does not retry. Make that contract explicit in code/state (poison MTP owner after any release-era recapture failure and reject further draft calls), or demonstrate every false return is safely retryable. Do not silently clear a graph whose destroy status is uncertain; current checked fail-stop is appropriate for uncertain retirement.
  B. `finish_expert_capture` checks end/destroy/upload/sync but `cudaGraphInstantiate` failure may theoretically leave a non-null/partially assigned `exec`; it attempts checked destroy (`:850-860`). A failure of destroy fail-stops. Fine as conservative process behavior, but actual SYCL compat semantics for these status/handle cases have not been verified in this audit.
  C. `MtpPrefillExpertScope` is intentionally fail-stop RAII, not automatic restore RAII. Safety depends on the wrapper catch and all returns passing through `restore`; current source shows that, but a future early return inserted between open and restore will terminate. A dedicated scope guard that restores during unwinding may improve maintainability only if it can preserve checked fatal semantics and not obscure the original prompt error.
  D. `detach_prefill_experts` synchronizes only the MTP stream. Safety depends on no pending external graph launches that reference MTP expert bytes outside `cs_`; current captured graphs are only launched by MtpDrafter draft methods on `cs_`, which are synchronously serialized in this caller. Document/enforce exclusivity if a future caller can invoke MTP concurrently or launch these execs from another stream.
  E. Current checked graph free verifies API success but does not independently query allocation residency/free bytes; telemetry boundaries only record cudaMemGetInfo. They are diagnostic and can distinguish no-return/partial-return, but cannot prove allocation attribution or safe future residual capacity by themselves.
  F. No injected queue/copy/capture/destroy/cancel failure was run (explicitly forbidden here and Main plans no artificial GPU fault). Ordinary source paths establish expected handling but leave driver-specific partial-submission and graph API failure semantics unverified. Do not claim fault-tested recovery; the intended behavior on ambiguous queue retirement is to stop with owners live.
