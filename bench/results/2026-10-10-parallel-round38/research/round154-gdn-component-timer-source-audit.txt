# R154 — GDN component timer source audit

Date: 2026-10-10 (Asia/Tokyo). Read-only review of the immutable timing-fixture snapshot and the named unchanged WFACTOR dependencies/handoff. No source edit, build/compiler/disassembler, test/runtime/device/GPU/model/payload/profiler, Git, lock, cleanup, service, or reset operation was performed. This report establishes only what the fixture source would measure and its admission/closure behavior; it reports no timing sample or runtime pass.

## Finding

For admitted `--bench 32768 --chunk C --repeats R`, the timed quantity is a host wall-clock service interval for one arm's encoded GDN gate producer, convolution, and recurrence/norm submissions, ending only after the in-order queue's `wait_and_throw()` and sticky asynchronous-error check. The interval excludes uploads, state initialization, materialized-exp diagnostic, readbacks, comparisons, hashes, and output rows. Warmup executes both actual arms over a complete carried 32,768-position synthetic prefix before any timed sample, so first-use JIT for the selected kernel path is outside the samples if warmup and measured dispatch configuration are identical. Each timed sample starts both independent arms from identical deterministic state/history and carries them across all chunks; the source verifies exact output/state equality after each paired chunk.

Two concrete source-level qualification gaps remain. First, `--bench` accepts known noisy Level Zero loader variables because its dirty-environment list omits all `ZEL_*` names and `ZE_ENABLE_LOADER_DEBUG_TRACE`; the repository's recovery guide documents these as tracing/diagnostic controls. A clean timing launch must therefore be enforced and recorded by the external owner, not inferred from this executable's admission. Second, the stdout `variant` field does not identify the actual recurrence dispatch selected through `STRATA_GDN_QUAD`, `STRATA_GDN_PIPELINE`, `STRATA_GDN_KEYHEAD`, and `STRATA_GDN_KEYHEAD_TUNED`; route identity requires the externally recorded environment plus prior source qualification. The accepted chunk divisors are powers of two from 1 to 8,192, so each sample has an even number of paired chunks and the alternating arm order is exactly balanced even when `repeats` is odd; the handoff's claim of an extra first position for odd repeats is not true for these admitted values.

## Timer boundaries and transfer effects

`service_stage()` prints and flushes its `STAGE` progress row first, then `stage(..., publish=false)` sets `begin=steady_clock::now()` immediately before invoking the three GDN submissions. `stage` calls `q.wait_and_throw()` and checks `errors.failed` before returning, after which `service_stage` takes the end timestamp (`fixture:48-65`). Thus the measured service time includes host dispatch/kernel-bundle lookup and submission overhead, plus queued producer, convolution, recurrence/norm work and full queue completion/error handling. It is neither device-event kernel time nor wait-free latency. The progress flush is outside the interval; any output generated by a lower-level tool/runtime during calls can still perturb it.

Per chunk, `prepare()` fills deterministic host inputs at the global offset and uploads them, and its `stage` waits before either arm starts (`:131-148`). The service lambda contains only `gdn_gates_encoded`, `gdn_conv`, and `gdn_recurrence_encoded` submissions (`:149-164`). After both arms, materialized `exp(log_gate)` runs separately; then state/history/intermediate/output readbacks and exact checks run outside the service clocks (`:165-182`). Readback transfers and the large immutable-input readback allocate/use host memory and can alter cache, thermal, and queue-idle conditions for the next chunk. Paired arms are timed before these checks, with arm order rotated, so describe the result as matched synthetic component service samples with inter-pair diagnostic work—not clean isolated throughput or full-prefix wall latency.

`BENCH_SAMPLE.seconds` is the arithmetic sum of that arm's per-chunk service intervals. It omits inter-chunk `prepare`, readback, comparisons, printing, initialization, and process startup. It cannot be used as the wall time for an uninterrupted 32K model prompt. Every interval has its own queue drain, so there is no queued cross-chunk overlap hidden in the aggregate.

## State, order, carry, and JIT

Warmup calls `fixture.initialize(false,true)`, runs exactly `Prefix/chunk` chunks in order with global offsets, and executes both arms, diagnostic materialized-exp, readback, full bitwise comparisons, guards, and immutable-input checks for each chunk (`:191-202,149-188`). No warmup interval is accumulated. For each measured sample, `initialize(false,true)` restores both states and convolution histories to the same deterministic nonzero pattern, then each chunk's `prepare` resets all per-chunk input/output/temporary buffers and uploads them; the state and history buffers are deliberately not reset between chunks (`:123-148,203-210`). Therefore each sample is an independent prefix from the same initial state, while its chunks carry state/history forward. Input formulas use `token=offset+t`; each measured prefix reuses the same logical values.

Arm ordering is `factorFirst=((sample+chunks)%2)!=0`, and printed `position` is derived consistently from that choice (`:203-223`). `chunk` must divide 32,768 and be at most 8,192, so `Prefix/chunk` is always an even integer (4 through 32,768). Every sample therefore has exactly half log-first and half factor-first pairs; odd repeats do not create an overall first-arm imbalance. Both orders execute on the same queue and touch the same prepared input buffers, but first-vs-second cache state remains an inherent within-pair condition; balancing order controls its direction, not its existence.

The queue and fixture are constructed before `benchmark()`; the warmup invokes the same three encoded operations, selected `variant`, live sizes, and buffer roles as measurement. This should exclude first-use compilation for the selected dispatch, not every unused kernel or every driver-side lazy action. Root must ensure that the selector environment and binary are identical across warmup and measured samples and retain the actual route/source/binary profile. `selected_identity()` verifies the B570 root/PCI and in-order Level Zero queue but does not report which recurrence implementation the selector chose (`:276-285,305-313`).

## Correctness and asynchronous closure

After the two timed arm intervals, the fixture separately launches a materialized `native::exp` of the log-gate image, downloads full live state/history/conv/gate/beta/output/half buffers and expected factor, and checks bitwise arm equality, factor-vs-materialized-exp equality, finiteness/classification, guards/inactive tails, and immutable inputs (`:165-182,89-109`). These checks are outside timing but must pass for every warmup and timed chunk before hashes/rows are printed. The `BENCH_CHUNK` hashes cover complete host buffers including guards; they are emitted only after `fixture.run` returns with checks complete (`:214-223`). This is synthetic component correctness, not model reachability, model logits, or full KV lifecycle evidence.

Each stage wraps the action and `q.wait_and_throw()` in a fail-stop path. Synchronous submission exceptions, asynchronous errors reported through the handler, or the sticky `Errors.failed` bit print `FAIL_STOP` and call `_Exit(2)` without unwinding potentially live USM buffers (`:33-56`). Host comparison/admission/flush failures throw to `main` and return nonzero; the fixture destructor performs a final drain before its buffer members release USM (`:74-83,113-122,329-332`). On the normal path, benchmark records are followed by `BENCH_COMPLETE`; after fixture destruction the original `TERMINAL` record and final stdout/stderr flush are required before exit 0 (`:229-231,329-331`). A partial `BENCH_*` prefix without `BENCH_COMPLETE`, terminal, clean process closure, and an empty owner session is not a complete run.

The source does not establish that an external loader, profiler, or tracer is absent. In particular, the `--bench` check at `:298-299` rejects `ZE_DEBUG`, some UR/SYCL tracing variables, and dynamic-loader debug settings, but not the known Level Zero loader logger: `ZEL_ENABLE_LOADER_LOGGING`, `ZEL_LOADER_LOGGING_LEVEL`, `ZEL_LOADER_LOGGING_ENABLE_SUCCESS_PRINT`, and `ZEL_LOADER_LOG_CONSOLE`; nor deprecated `ZE_ENABLE_LOADER_DEBUG_TRACE`. `docs/INTEL_GPU_RECOVERY.md:89-111` documents the former variables as API tracing and says timings require a separate process with trace/validation settings removed. It also explicitly states that a clean health environment removes inherited `ZEL_` settings. The in-program cleanliness admission is consequently incomplete. Owner must sanitize/record the entire child environment before launch, and dirty diagnostics must fail admission rather than be mistaken for quiet component timing.

The `variant` is initialized to 0 and changed to 2 whenever `STRATA_GDN_REC_HEADS` is present (`:305`); `BENCH_CHUNK`/`BENCH_SAMPLE` prints only that integer. Other selector variables can steer dispatch without changing this printed field, as the pinned `kernels.dp.cpp` contains separate quad, pipeline, key-head, tuned-key-head and serial selection logic. Record all selector variables and corroborate actual route using the existing exact source/qualification evidence; do not infer dispatch from the field or claim all six selectors were timed by one invocation.

## Quiet-run admission and resource bounds

Argument validation occurs before queue construction: exact argv positions, fixed total 32,768, decimal input, `1<=chunk<=8192`, exact divisibility, and `3<=repeats<=9` are required (`:289-309`). No benchmark runs on the old no-argument/`--prefix`/`--host-only` path. The finite loop bound is `warmup_chunks=32768/chunk` plus `repeats*32768/chunk` measured paired chunks. At chunk 8,192 and repeats 3 this is 4 warmup plus 12 measured pairs, 24 timed arm service intervals, 24 `BENCH_CHUNK` rows, and 24 timed `STAGE` rows. At chunk 1 and repeats 9 it is 32,768 warmup plus 294,912 measured pairs; the measured output alone contains 589,824 `BENCH_CHUNK` records and 589,824 `STAGE` records. The fixture has no internal total wall-time or stdout-byte cap. The handoff's conservative external stdout budget (256 MiB for smallest-chunk mode) and bounded wall/process ownership are necessary; a typical 64-MiB output cap can reject a finite but enormous admitted run. First qualification at chunk 8,192 is far smaller. Resource-cap exhaustion/timeout is a failed/incomplete run, never a partial timing success.

At capacity 8,192, buffer shapes in `Fixture` imply about 1.83 GB decimal of device allocations and comparable host mirrors, with the largest transient immutable-input readback around 336 MB (`:25-29,74-99,113-121,182`). These are source-derived storage sizes, not RSS or usable-device-memory guarantees. The owner needs an external process/host-memory and device-allocation budget that allows the mirrors/readback and the selected runtime, plus a finite wall limit. The smallest chunk multiplies kernel launches, checks, hashes and output volume dramatically; source finiteness alone is not a practical duration guarantee.

## Root admission discriminator

Before any clean timing run, use the owner-controlled process to bind exact executable/source/binary hashes, compiler/JIT and backend/device, full effective environment (explicitly no `ZEL_*`, `ZE_ENABLE_LOADER_DEBUG_TRACE`, UR/SYCL tracing or attached profiler), argv/chunk/repeat bounds, process/session identity, wall/stdout/resource caps, async handler status and normal teardown. Keep correctness diagnostics and selector/path attribution separate from the clean timing process where they enable validation or tracing. For each clean process, require a complete warmup record, exactly `repeats*(32768/chunk)` paired chunk records, exact bitwise checks for every chunk, per-arm sample counts/order balance, finite nonnegative intervals, `BENCH_COMPLETE`, final terminal record, exit 0, final flush and no survivors/fault evidence. Preserve individual intervals and per-sample arm aggregates; report no model speed, full-prefix throughput, or adoption conclusion from their sums.
