Public contract
IqDequantGroup contains bounded gate/up/down address arrays and declared byte capacities, first and n. It is plain metadata captured by value; the kernel does not read a host pointer-array allocation. Active pointer slots are [first,first+n), and destination expert slots use the same indices. Separate GU and Down APIs allow refusal/fallback independently. A call takes a common format type, positive n_ff/n_embd, destination pointer, element stride and byte capacity. Active source addresses must already be device accessible on the Runtime stream's device, valid for the declared required payload, and alive until completion. Destination must be device accessible too. The API cannot establish actual allocation size or device residency from addresses alone; these are caller obligations. There are no allocations, extra queues, concurrent USM accesses or new synchronization.
Destination GU slot e is dst+e*stride with interleaved [2*n_ff,n_embd] FP16; Down slot e is flat [n_embd,n_ff] FP16. Capacity covers all preceding slots as well as the last active payload. Padding and inactive slots are untouched. Stride is in uint16/half elements, capacity in bytes. Stride must cover the payload and be multiple 8; destination base is aligned to alignof(sycl::vec<sycl::half,8>) (normally 16 bytes), matching the existing widest vector store. Active sources conservatively require 4-byte alignment; this can refuse otherwise valid 2-byte-aligned native inputs and safely lets the caller use its old path. Source payload ranges may not overlap the destination span (including gaps/inactive preceding slots); independent source matrices may alias each other for reuse.
Legal bounds: 0<=first<=16, 0<=n<=16-first. n==0 returns true after bounds only; type/dimensions/pointers/capacities/stream are not inspected, no Runtime access or launch occurs. Nonempty zero or negative dimensions return false. n_embd must be multiple 256. n_ff need not be multiple 256; this permits actual n_ff=640,n_embd=2560 Down flattening. All is_iq types are admitted, BF16/unknown types refused. GU and Down formats may differ by calling the respective API with their own type.
False means refusal before submission, permitting individual API fallback. True with nonzero work means submission returned normally, and with null stream the existing wait returned normally too. A nonnull stream true is not completed output or asynchronous failure certification. The exact queue_for(stream) Runtime lookup and sync_if_needed(stream,event,what) convention are reused. Exceptions from Runtime/device-info/submission/wait propagate and are never rewritten as false; do not run fallback after an exception as though nothing submitted. Each API uses 256-work-item local size, checking reported max_work_group_size and last-axis max_work_item_sizes before submission. No vendor/name/ID selection occurs.

Mapping and preserved arithmetic
GU extends the existing 2D parity launch with one expert dimension. Per expert its i=global_last_axis/32, nsb=n_ff*(n_embd/256), row=i/per_row, column=i%per_row, parity is the middle group index. It calls the unchanged dq_dispatch(t, parity?up:gate, i, ToGlobal<half>{slot + ((2*r+parity)*per_row+c)*QK_K}, local_last_axis%32). This is the old address/arithmetic sequence with a checked expert base offset.
Down extends the actual launch_dequant_flat rather than assigning one physical format block per work-item: nsb=(n_embd*n_ff)/QK_K, eight 256-value superblocks per 256-work-item group, i=global_last_axis/32, output slot+i*QK_K, tid=local_last_axis%32. iq_row_bytes(t,256)*nsb supplies payload capacity. Thus IQ4_NL's 32-value blocks and Q2_0's 64-value blocks retain their existing decoder semantics within each 256-value superblock. No decoder expression, FP16 conversion, operation order, ToGlobal/store implementation, or original launcher is edited. This is a source mapping argument, not executed byte parity.

Checked refusal behavior
Before queue lookup/submission the checks refuse illegal bounds, unsupported type, nonpositive dimensions, n_embd misdivisibility, dimension narrowing, matrix/GU payload overflow, short or misaligned stride, rounded global-range and full ND-range product overflow, signed-index/size_t/ptrdiff offset overflow, insufficient declared source/destination capacities, null or misaligned active addresses, address-span uintptr wrap, and overlap of required source payload with destination span. Product checks use a limit no larger than either int64_t or ptrdiff_t max; destination slot-end addition is checked before byte multiplication. The source pointer span is bounded by ptrdiff_t and uintptr. Padding on the last partial group is guarded by i>=nsb, just as existing kernels. The total ND-range product is checked even though no resulting product is used as a flat kernel index. Reported local workgroup/item limits refuse before submission after safe Runtime lookup. Missing actual allocation residency/capacity provenance remains a caller contract, not an unchecked claim of pointer validity.
