Production bounds and off-by-one contract
----------------------------------------
New pure-host context_bounds.hpp is actually used in MTP and generation. It rejects
negative positions/counts, impossible original spans and capacities that cannot
represent exclusive cell+1 in int32. It checks pos<=C before subtracting C-pos;
there is no unchecked pos+rows overflow in the admission/planning helpers.
Resident ring slots, 64-cell margins and allocation slack never grant logical rows.

A verifier with T inputs has T-1 candidate inputs and one bonus output. Its usable
rows are min(requested, C-pos, remaining_outputs); it cannot consume/commit more
rows than the output budget. After accepting a candidates, next_pos is pos+a+1.
An MTP proposal is computed at pos+a+j and serves input row j+1 of that next window.
The MTP plan therefore reserves next window row 0 and the bonus output BEFORE
calculating usable candidates: min(max_candidates,
max(0, min(max_rows, C-(pos+a+1), remaining_outputs)-1)). All additions in this
formula occur only after proving the original span and accepted row are legal.
This is stricter than merely checking each draft KV cell, because a proposal with
no legal verifier input row is not useful and must not drive another window.

Exactly one output remaining means zero MTP candidates and a one-row verifier.
Zero candidates report n_drafts=0 and zeroed unused result slots. When output remains,
the round still performs its bounded KV-only accepted-prefix catch-up via the existing
MTP prefill front, so cached conversation reuse does not lose rows the old round would
have appended. This path performs no attention, experts, prediction head/sampler or
speculative proposal step; the next verifier has only its bonus row. The front may
capture/replay a KV-only graph and copy residual/input records, under v4 checked queue
ownership. Decode catch-up time/rounds stay attributed to draft statistics rather than
prompt prefill. An exhausted output budget is a checked no-op with no new capture,
record staging, residual upload or writer. Completion/previous-writer draining still
occurs before any caller output rewrite.
The returned candidate count also includes an earlier min_p stop, so callers no
longer consume padded zeros as nominal candidates when min_p is zero/disabled.

For prompt+max_new==C, the final output is token position C-1. That token remains
the unconsumed next input; normal decoding needs no verifier input or MTP KV at C.
In the usual native/non-native serial invariant, final committed input is C-2 and
next_pos is C-1. The helper also permits an independently valid verifier row at
C-1 with an exclusive step C, but does not admit an extra normal output beyond
the prompt+max_new budget. The v3 storage-only probe separately writes row C-1
with its explicitly marked terminal successor; its semantics were not changed.

MTP API changes
---------------
draft/draft_first/chain_launch gained a final remaining_outputs argument, defaulting
to int64 max for compatibility. Every production generate.cpp caller now supplies
its actual remaining budget. External callers that omit it still get physical
capacity bounds but must provide a budget to enforce their own output policy.
The optional existing n_drafts output communicates usable candidates, including zero.

MtpDrafter::draft validates ORIGINAL T rows and accepted a before any capture or
record staging, even when CATCHUP_ALL is false. It checks catch-up token IDs against
the bound vocabulary. Default catch-up retains exactly a+1 rows; CATCHUP_ALL retains
the whole validated original span. Draft step depth is capped by the shared plan.
All p+a+j staged positions and exclusive steps remain within the logical extent.

The first-draft bootstrap differs from a real verified span: T originally requests
repeated copies of one real residual/token pair, not T already-verified rows.
Its repeated span now shrinks to C-cell before copies and CATCHUP_ALL recording.
The real row 0 remains at cell. Invalid cell, token and budget reject before copies;
an exhausted budget skips residual copies entirely. Zero candidates with a remaining
bonus retain only bounded repeated-row KV catch-up, not a forced proposal. Away from
the boundary the same repeated rows, source residual and graph math are retained.

Dormant chain_launch checks its original span, accepted row, vocabulary/forcing
inputs and exact n_out against the capacity/output plan BEFORE record staging or
writer enqueue. It rejects a chain whose forced/expected shape cannot fit rather
than silently truncating a chain. -1 remains the existing forcing no-op sentinel.
The v4 capability refusal remains before all chain preparation/staging/enqueue.

Caller changes and before/after behavior
---------------------------------------
1. Standalone native/non-native speculation tracks actual mtp_candidates, applies
   the max-draft knob before the first bootstrap, and chooses at most 1+candidates
   rows. Both the initial draft_first and post-verdict draft pass remaining output
   budgets. A final one-output round uses T=1 without forcing an MTP proposal. KV-only
   catch-up retains accepted drafter state for later cached-request reuse.
2. Serial serve follows the same count/budget rule. Its previous prompt+max_new+8
   admission rejected exact-capacity requests; now subtraction-based admission
   accepts prompt+max_new==C without adding eight hidden cells.
3. Both serial loops clamp the verifier window AFTER suffix/lookup-chain selection.
   T_mtp and chain_n are adjusted to the retained prefix before token/history staging,
   verifier launch, acceptance/commit, output emission and window statistics. A nominal
   four-row tail formerly failed/broke on p+4>C; it now runs its legal shorter prefix.
   Partial rejection computes the next plan from accepted a rather than nominal T.
4. The standalone later admission no longer sums prompt+output; it uses the shared
   subtraction check. The pre-existing early positive/capacity admission still applies.
   The exact no-output probe explicitly bypasses normal positive-output admission.
5. Batch-MTP slots can stage one or two verifier rows according to remaining outputs,
   physical cells and draft readiness. Actual per-slot row_count controls comparisons,
   commit prefixes, residual copies and post-verdict MTP catch-up. No nonexistent second
   row is read/copied. One useful bonus row no longer requires draft_ready. Admission
   and post-verdict slot calls pass output budgets; zero-candidate slots retain the
   accepted KV-only catch-up and then verify one row. Batch row-prefix commit supports
   the existing variable slot groups.
6. Pipelined batch's one-row input records get a host span/output check before launch.
   Its existing unsupported-host-handoff API gate was not removed or weakened.
7. --pipeline-windows selection now turns off on the current unqualified capability
   gate before pipeline allocation/preparation and uses the existing serial loop.
   The debug switch cannot re-enable it because pipe is false. Dormant pipeline chain
   callers pass remaining budgets; impossible chain shapes reject before enqueue.
   A future qualified pipeline's terminal transition/output-completion behavior is
   not claimed by this implementation; it needs separate qualification before enable.
8. Normal speculative/prompt elastic-KV reserve requests are explicitly capped at C
   before kvg_ensure. Existing kvg_ensure also clamps its rounded target at C. No KV,
   resident ring, page-table or RoPE capacity was increased. The unrelated existing
   +256 prompt/cache reserve requests still use that same bounded growth function.
