## Execution gate

Disabling PLE changes the model path. Any future alternate route must say exactly which model components and output-quality claims it covers.

The values below are the candidates to test only after that gate changes. ## What the old 8192/128 receipt means

The retained v0.1.41 pristine records requested `--prefill 8192`, `--expert-cache 128`, `--expert-profile data/expert-profile.bin`, `--expert-cache-per-layer`, `--pool-workers 5`, `--pcie-frac 0`, MTP/speculation 4, and `--no-prefill-borrow`. Their effective progress increments were 6144 and startup INFO reported 144 slots / 281 MiB. The repeated pristine records share a recipe; they do not show a candidate sweep or a selected optimum. The separately labelled tuned 8192/128 runs were control and integrated builds, not pristine.

The current official source explains mechanisms, but only partly explains that particular observation:

- **128 requested → 144 effective slots:** the per-layer path treats N as a budget of `N * max_blob` bytes, computes a uniform per-layer quota from each layer's actual blob size, and sets actual slots to `quota * n_layers`. Actual slots can therefore exceed N while admitted bytes stay under the budget. The retained runs explicitly requested per-layer mode on the native pack. INFO's `expert_slots` / `expert_slots_primary` and cache MiB, together with the `per-layer slots use each layer's blob` line and `PER-LAYER` line, are the relevant evidence. This source behavior can explain 144 without claiming the cache contained more bytes than budgeted.
- **8192 requested → 6144 effective chunk:** serve admission first reduces an explicit borrowed chunk by halving until it fits the participating caches. If the prompt buffers allocate their own VRAM, the later `own_fits` check uses a 512 MiB headroom and a descending supported list containing 6144, 4096, 3072, 2048, 1536, 1024, and 512. Either fit path can resolve a request downward; `generate.cpp` prints a clamp message and uses the resolved chunk in `Prefill::init`. The retained audit has 6144 progress, but not the matching clamp/admission line, free-VRAM value at that point, actual buffer allocation/borrow state, ring setting, or full startup sequence. In its particular `--no-prefill-borrow` recipe the own-buffer path is a plausible source explanation; the source alone cannot prove which constraint chose 6144 on that historical run. Preserve the old requested/effective distinction.
- **v0.1.42 difference that matters:** its `generate.cpp` adds an Intel/Alchemist decision that can force `--no-prefill-borrow` and reduce `auto` to 2048; it also defaults borrowing from context when the operator did not explicitly select it. It documents a >4 GiB oneMKL borrowed-operand issue. This is a source-path change from v0.1.41 and means implicit/default borrowing is not a matched condition across releases. Pin `--prefill-borrow` or `--no-prefill-borrow` explicitly and record whether architecture rules override it. In v0.1.42 the `auto` mode is disabled and converted to fixed 2048 when no borrowing/profile is available; bare `auto` is capped at 8192, with 16384/32768 opt-ins.

For comparisons, report four fields: (a) box defaults with flags omitted, (b) explicit CLI request, (c) parser/admission-resolved setting and clamp message, and (d) actual initialized/used value. `prefill_chunk=0` is source default (token path), not an implicit 8192 batch. `--prefill auto` is a policy request, not an effective chunk. An explicit fixed chunk can also be changed for cache fit/request length or allocation fit.

## Interactions and controls to keep fixed or defer

- **VRAM/cache admission:** expert cache `auto` prices context/session/KV, owned prefill buffers, MTP/head/graph and reserve; allocation is touched and may shrink again. `--vram-reserve-mib` defaults to 700 MiB and changes expert-cache room; only lower/raise it in an explicit separate cache-admission experiment with free-VRAM/cache-resize logs. `--expert-cache-per-layer` changes slot admission and likely hit distribution, not arithmetic; keep its policy constant. The profile controls fill order and caps cache. Preserve the warning/log lines and INFO.
- **Borrow/ring/chunks:** v0.1.42 changes borrowing default by architecture/context; explicit borrowing modes and ring/lend env affect whether buffers consume VRAM or cache slots and which experts stream. Pin these in each arm. Auto must be its own policy axis.
- **KV and contexts:** `--kv int8` / other format affects numerical precision. `--kv-resident 0` means fully resident; nonzero streaming has a 20,480-cell minimum and uses pinned host RAM for the remainder. Keep format and resident cells constant for chunk/worker rows. If 64K admission fails, a separately labelled KV-residency arm may compare 32K vs 64K resident cells, but that changes host-KV traffic and decode latency as well as VRAM headroom.
- **CPU pool:** `--pool-workers` is the actual expert-pool knob; affinity/core placement and host-worker participation are separate controls. `STRATA_FETCH_THREADS` is for file-backed expert prefetch, not pool worker count. The official CLI does not expose `--pool-tasks` or `STRATA_POOL_TASKS`; `STRATA_POOL_SPIN_US` is a test spin/sleep knob, not task grain. Do not invent these as tuning settings.
- **PCIe:** `--pcie-frac` apportions distinct decode verifier cache misses to GPU PCIe service vs CPU expert computation. It is not prompt CPU/GPU share; batched prefill uses its own staging/ring policy. `STRATA_FETCH_THREADS`, `--no-ple-prefetch`, and `--stream-experts` are not interchangeable with this fraction.
- **MTP:** `--spec`, `--mtp`, `--mtp-max-t`, and `--spec-min-p` affect decode work and accepted draft windows. Keep them fixed for worker/cache experiments. Read actual INFO fields and drafted/accepted counters; do not infer effective proposal width from requested `--spec` alone.
- **Diagnostic/control variables:** preserve `STRATA_PREFILL_FIRST`, `STRATA_PREFILL_RING`, `STRATA_PREFILL_COMPACT`, `STRATA_PREFILL_ATTN_LAYOUT`, `STRATA_PREFILL_LAYER_MAJOR`, `STRATA_KV_STAGE_OWN`, `STRATA_KV_PREFETCH`, device selector, Level Zero adapter/copy-offload settings, and loader path exactly for a matched build/run. The compact/attention/layout/KV-stage variables in the old tuned control/integrated arm are local experiment controls and not proof of official tuning. Keep trace/timing/profiler env off in clean samples.

## Correct evidence locations and selection rule

For each run, persist argv, source/binary hash, runtime/driver/device, complete allowlisted environment, exact prompt token count/hash, cache/profile files and hashes, start/end/status/correctness, all raw timing samples, and requested/resolved/effective values.

- `strata serve` start: its `INFO context=...` line records effective KV cells, total and primary cache slots/MiB, `spec`, `mtp_max`, lookup, free VRAM, pool workers, PCIe fraction, and `spec_min_p`. It does **not** record the resolved prefill chunk; retain adjacent clamp/auto/ring logs too.
- Chunk resolution: stderr lines `prompt chunk auto: ...` or `prompt chunk X -> Y ...`; initial cache auto sizing, per-layer quota, touch/shrink, reserve and `Prefill::init` messages explain admission. In prompt-serving, retain every `PP position prompt_tokens cumulative_ms fresh_tok/s` line and actual request completion/status.
- Standalone prompt: final `prefill N tokens in C chunks ...` records batched work; clarify it is normally `n_prompt-1` conditioning positions. The final prompt position plus sample/output are separately performed by token loop. There is no current stock safe full-prefill-only exit as R354 describes.
- Decode: request and end-of-run counters (`--stats`, drafted/accepted windows) record service/acceptance and wall sections, but are diagnostic instrumentation; clean end-to-end request samples are the latency evidence. Keep prefill, decode, and full request in separate fields. Do not derive one by subtracting overlapping timer spans.
- Selection: remove rows only for recorded admission failure, correctness/quality failure, or a predeclared objective threshold. Select by the predeclared primary metric (e.g. median fresh prompt tok/s for A; median decode tok/s for B), retain range and memory/admission status, then independently repeat the selected configuration in at least three new processes. A passing speed row with changed output math/cache/profile must not be called equivalent without the required quality comparison.

## Unsupported knobs and scope boundary

Do not propose `--pool-tasks`, `STRATA_POOL_TASKS`, or treating `STRATA_FETCH_THREADS` as CPU compute workers. Do not treat `--pcie-frac` as a prefill split, `--no-ple-prefetch` as disabling completion synchronization, positive PCIe share on pageable Xe reads as supported, `--no-pool` as a prefill bypass, or a lower chunk as a host-USM synchronization fix. `--graph-only`, `--gpu-only-full`, `--no-capture`, or `--no-token-graph` are not a normal full-path qualification shortcut. Don't carry over XeStrata-specific kernel selectors into official settings.

R344/R365 concern XeStrata hardware/kernel diagnostics and do not establish official upstream settings or a safe official engine run. R349's setup/server work is inference-independent and should be evaluated after engine decisions; fake-engine server tests do not show inference throughput or host-USM safety. R352/R354 remain the controlling source/runtime gate. The R357 prospective chunk values and this low-count matrix are future search proposals, not historical measurements. No optimization winner can be selected until the admitted official route is actually measured.
