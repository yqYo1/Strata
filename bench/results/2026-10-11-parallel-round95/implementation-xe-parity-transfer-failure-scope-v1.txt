Main identified a caller staging lifetime gap in legacy parity plumbing. A copy submission or wait can
throw while queued work may still use a caller-local host vector. process_device is static, so its later
arena destructor cannot keep that local host staging alive during exception unwind. The helper now
catches transfer/sync failures before control can unwind the caller and fail-stops the process.

Implementation and successful-path semantics:
  checked_transfer invokes a small pointer/count-only lambda inside its try block. copy_in and copy_out
  acquire Runtime inside that protected block, submit the same compute barrier, pass it as the same
  dependency to transfer copy_async, and call the same Runtime::wait with parity upload/download labels.
  A normal return still requires the existing event wait and Runtime sticky async-error check to succeed.
  No barriers, waits, data conversions, bytes, tolerances, reference math, queues or streams are added
  or changed on the successful copy path. Byte wrappers continue to route through the typed helpers.
  sync now runs Runtime acquisition and finish(compute) inside the same checked wrapper, with operation
  label parity sync. It obtains Runtime once rather than twice; the compute queue and finish ordering
  remain the same. Device::alloc/upload, arenas, process_device, alloc_bytes and host allocation logic
  are byte-unchanged. stream() is also unchanged.

Failure semantics:
  Runtime::get, compute barrier submission, copy_async or Runtime::wait/finish can throw after prior
  work has been accepted. checked_transfer catches std::exception and prints the operation plus its
  exact what() text. A non-standard exception prints the operation plus unknown exception, because no
  portable message exists. Both paths flush stderr and call std::_Exit(1) without returning or throwing
  through the caller. The operations are explicitly parity upload, parity download and parity sync.
  The caller's local vectors and static Device arenas therefore do not reach their C++ destructors on
  this failure path. No wait failure authorizes release, and no later static arena destructor is relied
  on to protect host storage. This does not depend on whether an uncaught exception would unwind.
  There is no catch-to-success, subsequent unchecked drain, retry, error reset, backend fallback,
  alternate buffer, or attempt to continue validation after unconfirmed completion.
  Runtime/temporary event bookkeeping may unwind inside the protected operation before the catch;
  those locals do not own the caller host vector. The guard prevents escape through the helper boundary.
  The existing Runtime watchdog still fail-stops its monitored wait at its existing deadline; the
  wrapper introduces no new deadline or polling protocol.
