## Decision

The smallest useful production census is caller-side, compile-time diagnostic instrumentation in a disposable diagnostic build, with a fixed-capacity record array allocated before timing and append-only writes during the measured prefill. Count at the existing per-expert decision/call sites, and summarize after the prefill has reached its existing completion boundary. Do not log, allocate, lock, format strings, query clocks, or wait per expert inside the timed path. Keep instrumentation disabled by default and leave the production token route unchanged.

It can establish actual eligibility, wrapper selection, selected arithmetic path, routed-row work, matrix sizes, and staging bytes. It does not establish speed or prove a private helper improvement. A successful census is a prerequisite to the separate real-model A/B; no A/B or eligibility claim follows from the installed metadata alone.

## Minimum fixed diagnostic schema

Use a fixed array sized before the measured call, with an explicit hard maximum and overflow flag. A practical conservative cap is 262,144 fixed-size records (about 8 MiB at 32 bytes/record); if it overflows, the census fails closed. No dynamic growth or per-event heap ownership. A record is appended once for each positive-count expert decision, including bypass decisions, and contains:

- monotonically increasing chunk ordinal and actual chunk `c0,T`; layer and expert `l,e`;
- actual routed rows `m.cnt[e]`, loaded `f.gu_type,f.d_type,f.n_embd,f.n_ff` when native layout exists, and computed `n`;
- selected route: fused, MMQ (and group/batched route where relevant), generic direct native, private direct native, or non-native direct;
- selected Down wrapper; record `not-called` for bypass. For each helper call, set a temporary outcome before the call and mark `returned` immediately after it; failed/throw/early exit leaves incomplete census;
- Down source payload bytes: `n/256 * 18` for type 20, dequant destination bytes `n * 2`, and the selected underlying arithmetic label (native Down IQ4NL-to-FP16 then two FP16 oneMKL GEMMs for the direct path);
- for expert staging, whether the blob was cache-resident or staged, and bytes actually transferred for this expert. On the existing path, a nonresident staged expert uses `lay.blob_bytes(l)` bytes (see `stage_one`, 4630-4670); cache-resident expert is zero staging bytes. Count the established transfer at the staging site or tie it to the matching expert record without reconstructing it from model-wide totals. Do not call compressed source bytes or dequant output bytes “copy bytes.”

No event handles, timestamps, profiler hooks, additional queue submissions, waits, or oneMKL event tracking are required for this census. The record is only host-side factual context. The exact event/service-attribution question belongs to R190 and is deliberately out of scope.

After the existing chunk/prefill drain, emit compact aggregates keyed by `(layer, expert, d_type, route, wrapper)`: call/return counts; summed routed rows; unique chunks; `n`, compressed bytes and FP16 output bytes (counted once per returned call); staged versus resident counts/bytes; and overflow/incomplete/error flags. Also print model/runtime identity and the effective values of build option, frozen private opt-in, `STRATA_PREFILL_MMQ`, prefill mode, native layout and peer/multi-GPU status. Avoid an unbounded per-call text dump; retain the fixed records only if a separate diagnostic consumer needs them.

Reconcile these invariants in the summarizer, not with estimated formulas: every `m.cnt[e]>0` local `order` entry has exactly one route decision record; all direct calls map to exactly one generic or private wrapper-return record; the two direct GEMM calls follow only a completed direct dequant wrapper; every bypass decision is accounted for; per-chunk routed-row totals equal `T*K` across all local/peer/fused decisions; copy bytes equal the staging transfer ledger, with cache hits at zero. Any mismatch, capacity overflow, failed call, incomplete prefill, or missing drain means “census invalid.” For fused execution, which does not create the same host expert order, record per-expert rows from the already available route/sequence metadata where possible; otherwise label that branch aggregate opaque and fail any claim requiring per-expert attribution.

## Workload and gates

The census must observe actual `n_batched >= 32768` passed to `Prefill::run`, with chunk ordinals and `(c0,T)` summing to that count. Prompt length by itself is insufficient; ordinary CLI processing may leave the final prompt token outside the batched prefill, so use at least 32,769 prompt tokens if that path is used and verify the runtime count. Keep route-affecting settings at the intended production values and record them. If a forced direct-path qualification is separately required, label it as such; do not substitute it for the production route census.

Keep three outcomes distinct:

1. **Prefill census gate:** exact count reconciliation and successful prefill completion at >=32,768 actual positions; no counter overflow or async error.
2. **Decode-success gate:** the application continues through its requested decode check successfully. This separately establishes decode viability; the prefill census alone does not.
3. **262,144-position full integration gate:** separately required longer real-model end-to-end run, including its own success/correctness status. Passing the 32K census or decode check does not satisfy this gate.

Only after the relevant production census is valid should the owner run a real-model baseline/private A/B in fresh processes under identical inputs and route settings. First require exact output equivalence and preserved correctness/fault status; collect per-sample prefill and end-to-end timings separately. The per-call ledger may itself perturb host execution slightly, so keep the census diagnostic build separate from clean timing binaries and do not use census-run elapsed time as an A/B result. No speed threshold or performance result is asserted here.
