prefill_iq4nl_service privately defines DEQUANT+EVENT_RECEIPT and links existing
strata_kernels plus ze_loader. Existing library/default flags are unchanged.
Exactly one CLI argument is required:
- --host-only: canonical host packing/oracle checks, plan/metadata adversaries,
  empty-event nested scope rejection, seven private invalid guards; no queue.
- --qualify: full 64-input prephase, fixed warm, one four-cell block, full final
  replay. All rows timed=0; diagnostic use, no clean timing inference.

  only phase=service/timed=1 CALL rows are component service observations.

Exact shape, storage and data

Exactly 64 distinct input allocations and exactly two output allocations on

Exact schedule and successful-run accounting
Cell IDs: 0=generic/same-address, 1=private/same-address,
2=generic/64-address rotation, 3=private/64-address rotation.
Each cell has 64 calls. Same-address uses input0. Rotation uses
input_index=(i+block*9)%64; output_slot=i%2. Eight block orders are:
[0,1,2,3], [1,2,3,0], [2,3,0,1], [3,0,1,2], repeated once.
Predecessor is preserved across cell/block boundaries and printed.
Prephase: for input0..63, generic then private, two-call batch, both slots;
each input/arm output is compared to FULL oracle including full output guards,
and that input is read back including full input guards. Closing replay scan
checks all64 simultaneously. 128 calls, 104857600 active words per arm.
Warm: pass0..1, input0..63, generic then private; alternating slots; no receipt
scope and one completion drain after all256 calls. No per-call warm wait.
Service: 32 cell batches / 2048 calls; qualify: four cell batches / 256 calls.
Final replay: same full 64-input/both-arm prephase and closing all64 scan,
explicitly phase=final_replay, timed=0, 128 calls; never used as timed samples.
Qualify total successful wrappers = 768, completed queue waits = 268.
Service total successful wrappers = 2560, completed queue waits = 324.

Successful BATCH rows: qualify132, service160 (pre/post128 plus cell batches).
Each batch has one DQ wait and a separate untimed readback wait. Additional

Exact events, bounded loop and lifetime/error boundary
Persistent arrays contain exactly64 optional event slots, 64 planned records
and 64 timestamp/host-submit samples. A fresh monotonically assigned scope ID
is used per replay/cell batch; sink serials restart at1 within that scope.
Scope setup, capacity checks and plan admission happen before submitting.
The timed loop contains only planned wrapper calls, counters, steady-clock
sampling and assignment to existing sample storage. No harness allocation,
growth, logging, H2D/readback, profile query or wait occurs in that loop.
The receipt comes only from the existing library's exact-submit hook.
After the one normal DQ drain, validate independent expected count/order and
arm/type20/n/queue/src/dst/scope/serial tuple, presence of optional events,
and pairwise event identity inequality. Query raw uint64 submit/start/end
only after that drain. Require submit<=start<=end and previous end<=next
start; equality and zero service are retained. service=end-start and
queue_delay=start-submit use only one device/backend clock. Host wrapper
latency, full submission window, wait and batch wall use steady_clock only;
host/device clocks are never subtracted. Runtime allocation internal to the
existing SYCL submit/event retention remains part of that instrumented path;
the fixture introduces no dynamic collection storage in the loop.

Each cell's untimed readback checks both FINAL surviving output occupants
against full oracle/guards, and every input allocation against the canonical
bytes/full guards. Logs identify both last occupants and expressly say
oracle_last_occupants_only=1. This cannot prove correctness of overwritten
timed outputs. Pre/post replay is the full input/arm qualification instead.
All arrays/events/USM/queue remain alive until known completion and queries;
optional events are reset after queries/readback, never before completion.
Release is explicit after the last successful full readback and event release.
Terminal GPU PASS is emitted only after all66 USM frees and queue teardown.

The nonthrowing bounded async handler uses one atomic store of a sticky flag,
not an exception counter; no CAS loop, allocation, iteration or logging.
Sticky async or receipt retention loss invalidates a batch only AFTER its
normal completion drain. A receipt loss is not treated as completion loss.
Post-completion metadata/query/async/numerical/log errors reject and safely
unwind known-completed state. Actual raw triples queried before a later
profile failure are kept as QUERY_PARTIAL/timing_valid=0.
Any synchronous exception during wrapper/copy submission, or failure of the
planned completion drain, takes bounded FAIL_STOP and _Exit(2), with no USM,
event, scope or queue unwind. No retry/fallback is attempted. A free error
similarly takes FAIL_CLEANUP/_Exit(2), no ambiguous-free retry. No GPU fault,
host-task fault or real retained-event/query exception is injected here.

Deterministic machine-readable schema
CSV key/value rows, no dynamic strings. SCHEMA version1 then SOURCE, CONFIG,
ORDER (recorded before work), HOST_PASS, INPUT_PATTERN, QUEUE, FP16_CONFIG,
INPUT[64], OUTPUT[2], ALLOCATION_RESULT, flushed PROGRESS boundaries,
REPLAY_BEGIN/END, CALL, BATCH, WARM, FINAL_COUNTS, USM_RELEASED and terminal PASS.
PROGRESS is flushed before each submitted block and its planned drain, outside
the timed loop/window. CALL is emitted after known DQ completion and complete
queries, before untimed readback, to preserve samples if readback rejects.
CALL carries phase/timed/batch/block/position/cell/predecessor, receipt tuple,
input/slot mapping, raw submit/start/end, service, queue delay and host submit.
BATCH carries expected/attempted/successful/receipt/query counts, host submit
window/wait/wall, DQ/readback wait counts, known completion, sticky status,
last occupant mapping and exact scope of all input/oracle/guard checks.
BATCH_REJECT denotes a known-completion failed batch; QUERY_PARTIAL keeps
already read raw triples without claiming validity. FAIL_STOP is uncertain
completion with no unwind. FAIL/FAIL_CLEANUP are stderr failure markers.
No overall pass should be inferred from HOST_PASS, BATCH result=PASS or
FINAL_COUNTS result=PASS; require terminal row whose first field is PASS,
matching mode and expected counts, model=0/adoption=0 and, for GPU modes,
USM_freed=1/queue_teardown=1, plus successful process/controller/fault receipts.
