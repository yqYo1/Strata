Opt-in and scope
STRATA_CACHE_ROUTE_PAIRS is parsed before GPU setup: unset or exactly 0 disables allocation/output; exactly 1 enables; every other string throws. Allocation is host-only and fixed, less than 2 MiB by static_assert, with 24576 cells and an owned copied resident-slot table. Default incurs null diagnostic checks but changes no routing/arithmetic and allocates no collector. No GPU allocation, event, query or readback is added.

Primary supported scope is serving main-model native decode, one stage, MTP/spec4 split, no batch or pipeline windows, no elastic KV/cache or adaptation, no remote/peer and zero PCIe share; dimensions must be exactly 48 layers x 512 experts with an exact host_res table. Existing current runtime conditions are checked at each request's decode start. Other serving combinations emit supported=0 and complete=0 rather than claiming coverage. Non-serving, batch and pipelined entrypoints explicitly emit unsupported_entrypoint and has no per-request DONE diagnostic. Prefill and separate MTP drafter counters are excluded by attaching the pointer only after decode scalar baselines and detaching before DONE/next prefill. An unexpected scalar main callback marks error/incomplete. Non-serving, batch-service paths that never reach this serving decode block are not qualified.

Counting and callback ownership
Hooks sit beside the existing cache_hits/offload_entries/cache_refused increments in expert_pool_dispatch_multi, after each ID's range validation and final kind classification. Each routed token/expert entry counts once: kind0 hit, kind<0 refused CPU route, kind>0 offloaded. CPU blob failure can leave partial refused entries, consistent with original scalar increments, but dispatch_failed forbids complete. callback_pairs counts each distinct expert at most once within one layer callback regardless of duplicate token entries or classification. It is a unique classified callback pair, NOT CPU jobs, pool task fragments, or the native histogram caller-job counter; it includes GPU hits as well as CPU routes. callback count includes callbacks reaching the classification loop. Counters are not weighted by router weights.

Verifier run_boundary invokes callbacks directly on the caller after ready-event waits; the CPU pool dispatch returns after workers complete. Worker kernels have no collector pointer and do not write its cells. begin records the calling thread identity; wrong-thread callbacks only set an atomic error and return before any ordinary counter/seen-table access. Reset and report are caller-owned; existing ver.wait_commit drains the last decode commit before the reporter. Adaptation/async mutation and multistage paths are excluded up front. This is not a claim of arbitrary concurrent-callback support. Wrong-thread error, failed dispatch, invalid IDs/dimensions, overflow, scalar path, empty coverage, resident mutation and reconciliation failure all prevent complete=1. Fatal early exits may omit END/DONE; a consumer must reject missing frames.

Framing schema (ASCII stderr, flushed before existing DONE)
CACHE_ROUTE_PAIRS_V1 BEGIN request=N layers=L experts=E enabled=1 supported=B truncated=0 error=B complete=B
CACHE_ROUTE_PAIRS_V1 RESIDENCY request=N cells=C unchanged=B start_fnv1a64=HEX end_fnv1a64=HEX
CACHE_ROUTE_PAIRS_V1 PAIR layer expert entries hits refused offloaded callback_pairs
CACHE_ROUTE_PAIRS_V1 END request=N cells=C callbacks=C entries=C hits=C refused=C offloaded=C callback_pairs=C done_hits=C done_look=C done_offload=C reconciled=B complete=B

PAIR fields are positional and emitted only for nonzero entries in ascending (layer,expert) order, at most 24576 records. Individual values are bounded uint64 decimal. Each PAIR line is at most 140 bytes at maximal uint64 values, hence all pair lines are <=3440640 bytes; short fixed framing lines keep total below 4 MiB/request. Internal counters check increment and total-sum overflow. There are no raw lookup lines, timestamps or retained source pointers. Request ordinal starts at one for serving decode requests; it is collector-local, distinct from other protocol/session identifiers. The stream has no arbitrary truncation path: sparse capacity is exactly the model cell count, truncated=0, and unsupported dimensions are rejected rather than truncated.

Residency verification
Copies all 24576 int32 host_res slot identities at decode start; END verifies exact byte equality with the live full table. FNV-1a64 is emitted over each int32 as four canonical little-endian bytes, including -1/nonresident and slot IDs, for joinable identity fingerprints. The hash is explicitly noncryptographic; unchanged is based on exact table comparison, not hash equality. The snapshot retains owned integers, never pointers to backing storage. Supported paths exclude mutation machinery; changed table forbids complete. No resident sets or GPU buffers are fetched for this diagnostic.

Scalar reconciliation
END requires pair hits == req_hits, hits+refused == req_look, offloaded == req_offload. req_look is the original DONE delta cache_hits+cache_admitted+cache_refused; supported window paths never admit. An unexpected admission/scalar path therefore cannot silently pass. Also require positive entries, no errors, unchanged residency and supported mode. entries == hits+refused+offloaded follows each classification hook; consumers should independently enforce it and sum PAIR records, callback_pairs<=entries, nonnegative DONE fields, exactly one matched BEGIN/RESIDENCY/END per completed request, unique in-range pairs, identical request IDs and dimensions, no empty/incomplete frame pass. Normal protocol, full-reference and health gates remain independently required.
