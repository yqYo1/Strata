## Result

The specialization is structurally narrow and the reviewed arithmetic/group mapping has no source-level out-of-bounds or alignment defect for the admitted layout. The exact `n=2560*640` call has 6,400 groups, 51,200 IQ4_NL blocks, and 3,276,800 output bytes; each work-group writes its own 256-half range, with eight 18-byte blocks read per group. A 32-lane group maps `tid/4` to one of eight blocks and `tid%4` to a distinct 8-half segment. The run starts are multiples of eight halves; `store_run<half,8>` writes a 16-byte vector at each such offset. Existing expert layout construction uses two-byte block alignment and establishes the `down_off`/row-byte geometry before this call. No overlap or DQ lifetime regression is introduced: the helper submits to `m.cs`, writes the existing `m.dq_d[j%DQ]` slot, and existing ordering marks slot use and feeds the slot to GEMM.

One root gate remains unresolved and is concrete: the helper calls `check("iq_dequant_f16")` after submission, but the shared `check()` implementation is empty (it only creates a dummy `dpct::err0`). Thus this call does not itself surface an asynchronous kernel failure at its documented error boundary. The public generic helper has the same existing weakness, but copying it into the new private arm does not satisfy R156's requirement to surface specialized-command failure without a post-submit generic retry. A future integration gate must establish an explicit supported failure-reporting path at the existing queue/error boundary; do not infer that a later GEMM or queue operation will reliably attribute/surface the error. Preserve no-retry semantics because the DQ destination may be partially written.

## Boundaries reviewed

- CMake adds the same private macro only to `strata_prefill` and `strata_kernels`, and only when the option (default OFF) is enabled. The declaration is private under `src/prefill/iq4nl_dequant.hpp`; it does not alter public `iq_kernels.hpp` or an inline body. `iq_kernels.cu` resolves into `strata_kernels`, while the call is compiled in `strata_prefill`, so the paired private definitions match the two actual consumers. With the option OFF, the declaration/call/helper are preprocessor-excluded and the existing generic call remains.
- Runtime parsing is performed at the start of `Prefill::init`, before the first allocations/submissions in this initializer. Unset and exactly `0` freeze false; exactly `1` freezes true; malformed strings fail initialization. An enabled runtime flag with a build lacking the feature also fails initialization. The frozen member is consulted during run; changing the environment afterward cannot switch behavior. No decode or gate/up call site was found in the changed source snapshot.
- Selection is restricted to the native branch and `f.d_type == 20`; other types and the disabled route use the existing public helper. The target helper rejects wrong type, null pointers, nonpositive/nonmultiple-of-256 length, and an oversized group count before submit. Existing host layout admission sets the format and offsets, and the helper retains the same 32 work items per group, group index formula, direct `dq_iq4_nl` math, and destination element offset as generic dequant.
- The special helper checks fp16 capability before submit and uses the current stream's queue. It adds no buffer or ring slot. Source lifetime/order at this site is inherited from the generic path, not independently proven by this audit.

## Required follow-up gate

Before treating this prototype as safe for implementation adoption, resolve the empty `check()` gap with an explicit asynchronous error propagation contract that does not retry or silently ignore failed work, then validate it in the owning integration path. Existing parity-fixture work can establish exact output bits and address mapping, but it cannot prove that asynchronous failures are delivered. No source change is recommended in this report; no output correctness or performance conclusion is made.
