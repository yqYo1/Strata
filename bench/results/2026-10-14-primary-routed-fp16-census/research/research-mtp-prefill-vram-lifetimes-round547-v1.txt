# R547 — MTP decode allocations across long prompt prefill

Date: 2026-10-15 JST. Read-only lifetime/dependency review of the current root MTP and SYCL prefill path, scoped to the user's earlier question about reclaiming decode VRAM during a long prompt and restoring it from retained model sources. The sole write is this report. No builds, tests, GPU/profiler, process/service, reset/cleanup, Git mutation, current-run reads, model blobs, private environment/session data, or the excluded `prefill-gemm-only-contract-root-v1/record.json` were accessed. The canonical run settings are supplied task context, not new run evidence. Main owns any implementation and runtime validation.

## Finding

`experts_` (the MTP draft layer's full resident expert table) and the draft output work are decode-only in the current prompt paths. A broad `rg` of `record_forward` finds `experts_`, `dhead_` and `head_logits_`, but it does not establish that prompt capture reaches them. Both `capture_prefill` and `capture_prefill_dev` call `record_forward(T, -1, ...)`. That call sets `full=false`; `record_forward` returns immediately after appending K/V at line 531, before the Q projection, full attention, MLP/MoE, final mixer or head. This early return is the decisive dependency proof: neither the canonical `Prefill::draft_kv` route nor its `MtpDrafter::prefill` fallback executes the MTP MoE/head portion during prompt K/V population.

The clearest reclaim candidate is therefore the separately allocated `experts_` table (`g.n_expert * BLOB`, read from `rt_dir/experts.bin` at `mtp.cpp:182-202`). The input source remains on disk and can be re-read in bounded host chunks. Conditional decode-only allocations include the selected draft-head copy `dhead_` and its token map `dvocab_` when `draft_vocab.bin` is present, plus `head_logits_` (currently allocated for `max_t * n_vocab` floats even when a subset head is used). If coupled draft sampling is configured, its `dinv_`, sampler parameters/history, ring, scratch and coupled graph variants are decode-only too. The main target `NativeHead` remains resident and is the immutable source for rebuilding `dhead_`; no-subset mode has no MTP `dhead_` copy.

The large `arena_` is mixed-lifetime, not wholly reclaimable: `record_forward(full=false)` uses parts of it to consume token/residual rows, run the draft layer's embedding/hidden projections and attention hyper-connection, and produce/append K/V. Its bump allocation also contains many decode-only Q/attention/MoE/sampling buffers. Recovering those bytes during prefill would require splitting the arena into stable prefill and decode subarenas (or equivalent separately owned allocations). Freeing `arena_` as currently carved would invalidate live prefill graph addresses and lose scratch needed at every prompt chunk. `state_arena_`/`st_` is persistent MTP K/V state and must remain through the prompt and into draft decode. `dense_` is also mixed: prompt needs `pre_fc_norm_embedding`, `fc_embedding`, `pre_fc_norm_hidden`, `fc_hidden`, attention hyper-connection norm/down/up/inject, K/V projections and K norm. The monolithic dense allocation cannot be retired wholesale. Its unused-by-prefill decode-only tensors could only be split after a precise tensor ownership/rebase design.

This establishes *which allocations have no prompt-path consumers*, not how many bytes the driver will return or how much free VRAM a change will produce. The historical task's MTP VRAM log of 834 MiB is not reused as a measurement. Allocator/graph executable resources may remain after releasing device buffers; only a paired runtime free-memory watermark can establish actual reclaimed VRAM.

## Exact prompt call paths

- CLI generation loads the MTP layer before the large target host arena is registered (`generate.cpp:2717-2732`), then binds the native head before `prefill.run` and installs an `on_chunk` callback (`:6291-6302`). The callback tries `Prefill::draft_kv`; if it returns ineligible with no error, it calls `mtp.prefill`. After the standalone prompt completes, it restores any lent target-cache slots, resets/frees standalone prompt workspaces, and proceeds to decode (`:6304-6348`). This is a useful reclaim/restore boundary, but the code's early MTP load is intentional for WDDM: the comment warns that allocations after large host-page registration can be refused (`:2717-2718`). Restore-time admission on the target platform therefore must be measured; it cannot be assumed safe from this source review.
- Serving binds the MTP drafter before requests (`generate.cpp:4700-4703`) and wires the same `draft_kv`-then-`mtp.prefill` fallback into the prompt chunk callback (`:4861-4866`). Unlike one-shot CLI mode, the `MtpDrafter` and its graph-exec arrays persist across requests. A reclaim operation before a later request must retire prior decode graph executables and drain `cs_` before freeing any captured decode pointer. The prompt callback itself is synchronous with the outer prefill callback contract; R541 records the per-chunk drain and R543 fixes host upload storage lifetime on the batched branch.
- `Prefill::draft_kv` accepts the canonical same-device/non-hybrid route when its preconditions pass; it computes only embedding/hidden/attention-hyperconnection projections and appends draft K/V (`prefill.cpp:927-1100`). It does not call any `MtpDrafter::record_forward(full=true)` entry point. If the batch helper declines due to `STRATA_MTP_BATCH=0`, ineligible KV mode/hybrid/device, bad shape/embedding representation, or fewer than 64 rows per batch, the caller falls back to `MtpDrafter::prefill` (`:930-974`).
- In the fallback, `prefill` groups rows, captures either the host-input or device-input prompt graph, copies R rows, launches the graph and synchronizes (`mtp.cpp:724-824`). `capture_prefill` copies mapped input rows then captures `record_forward(T,-1)`; `capture_prefill_dev` captures the same partial function with prefilled device inputs (`:645-661`). The full-vs-KV-only switch and early return are at `:455-463, 505-531`.

With the supplied native single-device, no-split 4096-chunk configuration, which branch is selected depends on runtime eligibility and geometry; this report does not inspect or claim a current run selection. The allocation dependency result holds for either route. `STRATA_PREFILL_MMQ=0` controls the main prefill path; `draft_kv` separately tests the MMQ build/support to choose its own Q8 implementation (`prefill.cpp:965-974`). It still does not invoke MTP's expert table. R543's corrected upload lease remains necessary for the batch helper and is orthogonal to MTP weight residency.

## Decode-only source and sequencing obligations

1. **Weights and source identity.** The current MTP expert source is `rt_dir/experts.bin`; `load` opens it and copies exact `BLOB`-sized expert records in 64 MiB chunks. Any host copy retained for fast restoration must be bounded/accounted in system RAM and tied to the original pack bytes. Re-reading disk is a reconstruction path but adds synchronous file-read/HtoD work and can fail; that failure must abort before decode rather than continue with partially restored experts. The optional subset is a derived copy of the target's native output head; source identity is the target `NativeHead` plus exact `draft_vocab.bin` ordering/hash. `head_logits_` and split arena scratch are workspace, not weights.
2. **Prompt row/cell semantics.** For every outer chunk, callers pair residual row `R_i` with `next_tokens[i]` (the following token) and cell `cell0+i`; fallback builds `tok`, four step values and per-head position from that cell, then appends K/V (`mtp.cpp:764-772,801-819`). `Prefill::draft_kv` uses matching `cell`, `cell+1`, block position and following-token embedding (`prefill.cpp:764-789,1046-1081`). With an MTP window, `first_needed = prompt_len - window - 64`; only cells before this boundary may be skipped. Preserve the whole retained draft KV window and the final eligible cell through the prompt's last chunk. Retiring only decoder weights must not reset prompt length, token/cell ordering, K/V state, host ring authority, or append timing.
3. **Queue and graph leases.** Both prompt helpers use `MtpDrafter::cs_`; `finish_capture` uploads and synchronizes each new graph (`mtp.cpp:624-642`), the fallback waits per group or once after its device-record batch (`:773-797,814-819`), and the R543-corrected `draft_kv` drains the batched host upload before returning. Before any reuse/free, establish successful completion of the relevant prefill and decode queues. For serving, prior decode `draft()` also synchronizes after each graph launch (`:849-875`), but explicit object-level retirement must still drain and destroy cached round/step graphs before `cudaFree` to close captured-pointer leases.
4. **Restore before first decode and every later prompt.** Standalone `generate` resets its large prefill workspace before token generation (`generate.cpp:6344-6348`), making it the cleanest place to attempt restoration. In serving, the prefill workspace remains owned across requests; restore must fit alongside it, or explicitly coordinate workspace release/reinit. The existing early MTP allocation is documented as protecting WDDM from later allocations after host arena registration (`generate.cpp:2717-2718`), so delay/reallocation behavior is platform-specific and requires an admission test. Preserve `thinkingON`, MTP-enabled decode, target sampling, offered/accepted-draft accounting and `spec=4`; do not route around MTP. The final prompt state and first speculative verifier window must match a no-retirement baseline.

## Minimal safe boundary to evaluate

The source proves a candidate bundle with no prompt consumers: `experts_`, `head_logits_`, optional `dhead_`/`dvocab_`, coupled-only decode sampling allocations, and an explicitly separated decode-only arena segment. The low-risk first concept is to retire only the large `experts_` allocation during prompt processing and restore it after the prompt's final callback has drained. The conditional head/sampler bundle can be tested separately. The current arena should remain intact until an allocation split is designed and audited; do not free the mixed `arena_` based solely on which fields look idle in an individual K/V-only graph.

This is a source-supported candidate boundary, not a source change recommendation. A reviewable experiment must capture before/during/after `cudaMemGetInfo` watermarks and allocation/free failures at unchanged full-262144 context, chunk 4096, no borrowing, compact1/MMQ0, MTP/spec4, split off. Also report wall time for expert restore, graph recapture cost, prompt and decode latency separately, all actual MTP counters and emitted/accepted draft results. Run a no-free control and restore-failure injection before adopting; a failure to rehydrate any piece must stop the request before verifier handoff. Keep the complete model/session resident and compare final logits/draft IDs and next-cell KV behavior against the same no-retirement path. Historical allocation-size/log values are motivation only, not reclaimed-byte predictions.
