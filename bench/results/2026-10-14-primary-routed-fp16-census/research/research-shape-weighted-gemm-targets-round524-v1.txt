## Decision

The next useful experiment is a same-binary, same-oneMKL-runtime, two-orientation probe over a deliberately small, empirical MoE shape set. It must preserve the exact operation and datatype at each cell. The current row-major and old column-major forms remain an unmeasured dispatch hypothesis (R511); the old3processx7 hot/80-row numbers are candidate evidence only and do not settle real-workload speed. Do not infer a gain or adopt either orientation from this design.

Use the following eight `ne` anchors, each for both routed operations:

| `ne` | Why it belongs |
| ---: | --- |
| 1 | Largest exact active-count shape: 14,509 calls in the captured histogram. |
| 12 | Median active-call `ne`; 1,106 occurrences. |
| 428 | Active-call p90. |
| 1,490 | Row-weighted p50; captures the center of routed row work rather than the call count. |
| 1,792 | Actual final-chunk tail shape; four occurrences. |
| 3,245 | Active-call p99. |
| 3,855 | Row-weighted p90. |
| 4,096 | Observed maximum and configured full-chunk ceiling; 15 occurrences. |

The histogram is exact over one real 34,560-batched-token run, and it directly reports occurrence count by `ne`. These anchors intentionally include both launch-heavy small shapes and large shapes carrying most rows. In the receipt, `ne=428` appears 14 times, `1490` twice, `3245` twice, and `3855` three times; those quantile representatives are still useful stress points, but are not themselves frequent exact shapes. The last actual input chunk is 1,792 rows; the route histogram observed four experts at `ne=1792`. Keep that exact tail as its own cell. Do not substitute a uniform 80-row case or call it representative of the real distribution.

For each anchor, compare these exact geometries:

- GU: `X[ne,2560] × W_GU[1280,2560]^T -> Y[ne,1280]`.
- Down: `H[ne,640] × W_D[N,640]^T -> Dm[ne,N]`, `N=2560`.

Both arms use half inputs, float output, the caller's actual `alpha`, `beta`, output stride and leading dimensions, same values, aligned addresses, queue, and synchronization policy. Current is row-major `(m=ne,n=N,k=K, nontrans,trans)`; old-equivalent is column-major `(m=N,n=ne,k=K, trans,nontrans)` with the operands exchanged as in R511. This is the same `Y = X W^T` algebra, not a change of precision or math. Keep GU and Down results separate: their `K/N` and payloads differ. Include output-padding sentinels and matched initial C for nonzero beta. Check finite results and numerical error against the current arm/reference; do not demand bitwise equality across distinct library dispatches without evidence that accumulation order is identical.

## Minimal probe structure

1. Use one probe binary with a runtime arm selector (or two wrappers built together into one binary), and one installed oneMKL 2026.1/SYCL runtime, same compiler, device, in-order queue, queue properties, environment, allocation policy and input pointers. Verify both call descriptors in a separate diagnostic process using oneMKL verbose mode 1; keep verbose disabled during timing. Intel's 2026.0 `gemm` reference documents the row/column storage and leading-dimension contracts, and its C verbose reference says GPU mode 1 logs without timing while mode 2 adds synchronous timing. No internal algorithm or kernel identity should be claimed from verbose output. Links: [oneMKL DPC++ GEMM](https://www.intel.com/content/www/us/en/docs/onemkl/developer-reference-dpcpp/2026-0/gemm.html), [oneMKL verbose mode](https://www.intel.com/content/www/us/en/docs/onemkl/developer-reference-c/2026-0/mkl-verbose.html).
2. Use identical operand/output contents for paired orientation calls. First exercise a hot-resident FP16 operand/output set after first-call/JIT warmup. Then repeat with a fixed rotating set of real dequantized layer weights covering the seven native GU/Down source-format pairs, each member used equally by both arms. Keep source loading and dequant outside the GEMM timer for this dispatch-only probe. Record the time/bytes to prepare those weights separately if observed. A future model-path decision still has to include the actual cold/streamed Stager, blob-copy, dequant and slot-reuse path; a hot pointer reuse win alone cannot justify adoption.
3. For each `ne` × role × orientation cell, run paired A/B blocks in alternating order inside one process for warm samples, and repeat in at least five independently started processes per arm/order to expose run-to-run variation. Record all individual repetitions and randomized/alternating order. Report first-call/JIT separately from steady samples. If process startup dominates feasibility, keep the same process and mark that lifecycle separately; do not mix the two populations. Match cache state (hot repeated operands versus the same seven-layer rotation) between orientations.
4. Separate (a) host time spent submitting GEMM calls, (b) queue drain/wait time and (c) any device command elapsed time that can be measured after completion. Report host submission and end-to-end batch wall as primary probe measures. Queue drain is not device-only: it may include launch, scheduler, and execution. The current wrapper drops the event returned by oneMKL; R513/R521 caution that a returned event may cover an internal/last command rather than every command in the BLAS call. If retaining events is explored, query only after existing completion, verify their scope, and label them command-duration estimates, not full GEMM service or critical path. Do not add per-call waits, synchronous verbose timing, or profiling barriers to the timed path.
5. Keep validation separate from timing. Compare current/old outputs across every cell with finite checks, a declared FP32-output tolerance, and padding checks; verify actual descriptors once with verbose mode 1. Timed runs must use the same prebuilt operands and settings, with no verbose, tracing, validation or extra observation flags. Retain source/binary/runtime/environment identity and every raw sample in the next committed measurement boundary.

Eight `ne` anchors × two roles × seven source-pair representatives × two orientations is a bounded but nontrivial matrix: 224 measured calls per repetition before repetitions/warmup. If the seven-pair rotation is applied to each shape, that is enough to preserve the native layer mix in the probe without crossing to every layer; do not silently select only the common `(22,20)` pair. If runtime cost requires a smaller first probe, keep all eight shapes/roles on at least one common layer pair for dispatch screening, then run the seven-pair rotating matrix for the shortlisted orientation before any adoption discussion. Report which matrix ran; do not weight unseen layer-format interactions as measured.

## Report the real distribution without inventing a representative mean

Publish per-cell samples and robust center/spread for both `ne` and role. Then produce two empirical reweightings from the complete exact histogram `h(ne)`:

- **Call-weighted** estimate: `sum(h(ne) * measured_latency(ne)) / sum(h(ne))`, representing an average active expert GEMM call only if the exact `ne` values were measured. If only the seven anchors ran, label this as an anchor-only comparison, not an estimate of the real mean. Do not interpolate an orientation crossover or synthesize missing shapes without separately validating the model.
- **Row-weighted** comparison: `sum(ne * h(ne) * measured_latency(ne) / ne) / sum(ne*h(ne))` is algebraically the same per-call time weighting adjusted by rows only if the target is cost per routed row; state the chosen statistic precisely. For throughput, use measured GFLOP/s from each real shape and weight useful operations by `ne`/FLOPs, not by call count. Report both call and row/FLOP-weighted views; summarize GU and Down separately. Do not use row-weighted p50 as a substitute for exact histogram weighting.

Because only one actual workload supplies `h(ne)`, it estimates shape exposure for this input/chunk/model/runtime only. Add `T`, chunk index/tail status, layer ID, source format pair and weight residency to future shape records. The prior fixed-bin proposal is superseded for this purpose by R513 correction: fixed bins lose exact common values; here the archived receipt provides exact counts for every observed `ne` from 0 to 4,096. A candidate selection threshold should require an improvement beyond independent-run variation in both per-role empirical weighting and the correct end-to-end prefill comparison, with no unaccepted decode regression. Do not infer whole-model performance from GEMM alone.

## Limits and work after the probe

The long phase measured 207.576 s wall, including 61.535 s for the nonexclusive Down marker interval, 32.529 s dequant, 49.455 s QSA attention and 75.519 s accumulated host staging time. R521 explains that Down marker intervals can contain queue gaps and adjacent queued-copy work; host staging overlaps the GPU timeline. The requested routed-blob payload was 183.863 GB over 89,743 Stager copy attempts, not proven successful DMA or physical-link bytes. H2D's earlier attained 6.447 GB/s gives a conditional payload quotient, not an absolute ceiling. These numbers establish why shape-aware GEMM is worth testing and why its isolated A/B must not claim those intervals as GEMM time.

The measured long phase has not yet established its unprofiled matching reference, oneMKL event coverage, cold-source timing, a causal share for GU/Down, or any model-level effect of orientation. Main currently owns an active unprofiled-reference effort and has the only lane for build/test/GPU work; this report requests no intervention in that work. After that run closes, use the defined probe, then compare a shortlisted candidate in the same fresh long-input configuration and the formal unchanged benchmark with decode reported separately. No current inference component is adopted.
