## Branch and correction boundary

`cmake/sycl_backend.cmake` selects `src/kernels/sycl/qsa_index.cpp`, `native_qsa_indexer.cpp`, `qsa_select.cpp`, `kv_stream.cpp` and the SYCL attention implementation into `strata_kernels`; `src/core/verify.cpp` calls these APIs for the verifier. The CUDA selector in `src/kernels/cuda/qsa_select.cu` and upstream CUDA generators do not establish a root SYCL implementation or a port recommendation.

The applicable prior evidence is registry `bench/results/2026-10-14-primary-routed-fp16-census/research-index.json`, R522, R523 and R531. Main's registry corrections say QSA attention and QSA gate/projection are distinct; the R522 long QSA phase was nonexclusive and did not identify prompt route. R523's old-1eb transposed-query fallback idea is fallback-only, not the prompt path, and was not adopted. R531's proposed host route census remains a proposal, not an observed route. This report does not repeat that transpose or R545's descriptor-dependency proposal. Its focus is verifier-time indexer scoring and exact top-k selection over the context-dependent block list.

## Current root-SYCL path

For each verifier QSA layer and each query row, `Verifier::record_window` appends the row's KV and indexer key, computes the 4-head/128-wide indexer query, calls `qsa_block_scores` and `qsa_block_topk`, then resolves selected KV pages and calls selected-cell decode attention. The root SYCL `qsa_block_scores_tc` is an explicit `return false`; the call therefore uses the subgroup score kernel. It computes a score for every completed four-cell block plus one final `dead`/tail candidate. `qsa_block_topk` then reduces those block scores by four-cell weight (or the partial-tail width), and emits the selected cell IDs in ascending order. It is exact selection, not approximate attention.

At context C, with C divisible by four, `n_bid=C/4`; the score kernel executes useful score math for `N=floor(C/4)+1` candidates, including the dead candidate at `b=n_bid`. That final candidate has selection weight zero when `C%4==0`, but the current score kernel still computes and stores it. Its one 32-lane work-group computes four 128-element dot products, applies ReLU per indexer head, and sums the heads. The mathematical dot work is 512 products and 511 additions (about 1,023 logical FP32 operations), plus ReLU/head-combine work. The subgroup implementation performs its lane-local and shuffle reductions across the group, so this logical arithmetic count is not a hardware instruction count.

The verifier allocates `max_blocks = max_cells/4 + 2`; for a 262,144-cell context this is 65,538. The current verifier calls `qsa_block_scores` without its optional `active_blocks` argument, so the fixed-size captured grid launches 65,538 work-groups per query per QSA layer. The kernel returns before loading data when `b > n_bid`. At the three requested endpoints, 8,193 / 16,385 / 65,537 groups perform score math and 57,345 / 49,153 / 1 groups return early. The header explicitly marks `active_blocks` as not for a captured graph, so passing a changing host active count is not a safe drop-in fix for captured verifier windows. This static-grid excess is a separate unresolved issue; it should not be confused with useful score work.

For every context in this task, selected width is `min(C, idx_top_k + idx_block - 1) = 2,051` cells, not C. That bounds the subsequent attention selection to at most 2,051 selected cells (at most 513 four-cell pages at full-block endpoints), but the indexer still scores all N context blocks. At 32K and 64K this is 6.26% and 3.13% of context cells selected; at 262,144 it is 0.783%. Sparse attention therefore reduces KV attention work but does not make the current indexer scan sparse.

## Source-derived per-window budgets

For a verifier window ending at context C (where the last row has `n_kv=C`), the rows are `n_kv=C-T+1..C`. Since these endpoints are divisible by four, exact score-candidate rows summed over T are `S=T*(C/4+1)-(T-1)`. The three earlier rows in a T=4 window each have one fewer score candidate than the last row. `qsa_block_scores` performs approximately `S * 1,023 * 12` scalar operations over all 12 QSA layers.

The following are source-derived address-reference/payload budgets, not measured physical memory traffic. One score candidate references 512 B of pooled/dead FP32 key, 512 B of FP32 query and writes 4 B of FP32 score. Thus score references are `S * 1,028 * 12`. In a long context, top-k's current 32-bit threshold loop scans the block scores 32 times, then scans them once for greater/equal counts and once to emit selected IDs: 34 score reads per candidate. Its source-level score rereads are `S * 34 * 4 * 12`. These counts omit small step reads, output-ID writes, cache reuse and execution overhead.

For INT8 KV, each cell/layer is 2 KV heads × 256 K/V code bytes plus 16 FP16 scales = 1,056 bytes. Selected K/V payload is `T * 2,051 * 1,056 * 12`; it is not the host-to-device miss traffic of the streamer. At 65,536 and 262,144, a 32,768-cell resident pool has 8,192 four-cell pages; on the ordinary streamed-main path, resolve can copy only missing selected pages from the authoritative host copy. Actual distinct pages, cache misses and copied bytes depend on selected IDs and runtime residency state, so the table does not claim them.

At maximum context, each QSA layer's FP32 pooled-key capacity is roughly 32 MiB and all 12 layers are roughly 384 MiB; `kv_resident=32768` does not shrink the indexer key capacity or its scoring list. At C=32,768 all K/V pages fit the configured 32,768-cell resident extent; larger contexts use the streamed-main plan unless its source-level disable switch applies. These are allocations/planner rules, not proof of physical residency or traffic in a run.

## Prioritized candidate and limits

**Priority 1: compare an exact byte-radix threshold selector for `qsa_block_topk` on the root SYCL path.** The current selector performs 32 full logical passes over the block scores to resolve a 32-bit ordered-float threshold. A four-pass, 8-bit radix threshold keeps the same block scores and cell weights, uses a 256-bin weighted histogram per pass to choose the exact next byte, then performs the existing greater/equal accounting and deterministic ascending-block tie fill. It would reduce the repeated score-list passes from 34 to approximately 6 while leaving the all-block indexer score math, selection width, IDs, KV mapping, attention math, and graph launch geometry unchanged. This is an algorithmic candidate only: a local histogram and its reductions may cost more than the saved reads on this SYCL device, and no runtime speedup is inferred.

The selector must preserve `order(float)` semantics, including signed-zero canonicalization, NaN rank treatment and finite/infinite ordering, the per-block 4/partial-tail weights, the exact `width` count, and the current stable lowest-cell/index tie rule. Do not use approximate shortlist, reused prior-query IDs, cross-layer selection sharing or score quantization without a separate quality/selection-flip contract; those change which cells attention sees. DeepSeek's published TopK work describes threshold filtering plus candidate compaction as an alternate DSA selection architecture, but its published implementation is CUDA/Ascend-specific and its docs recommend disabling sorted indices when not required. Strata does require deterministic ascending IDs, so that code is a design reference, not a drop-in implementation or a measured result.

**Priority 2: defer any captured-grid reduction.** The root API exposes `active_blocks`, but its header excludes it for captured graphs and the verifier's device step can advance while a graph is reused. A future graph-safe grid proposal must preserve dynamic `n_bid` without a stale captured host scalar and show target SYCL parallelism at 32K/64K as well as full context. It is not bundled into the radix candidate.

**Small boundary:** for `C <= 2,051`, current `qsa_block_topk` already writes the identity IDs without reading scores, but verifier still submits the score kernel. The task contexts are all larger than this; skipping those scores is not the long-context candidate and should not distract from the measured-context gate.

After Main closes its current benchmark boundary, the smallest gate is a Main-owned source port and serial tests comparing old/new IDs bit-for-bit at C=32K/64K/262,144, T=1..4 and every tail remainder, with random and adversarial equal-score, signed-zero, infinity/NaN, threshold-boundary, and weighted partial-block fixtures. Then compare the selected attention output and full verifier correctness against the unchanged selector. Benchmark selector and whole decode separately on the target SYCL device, unprofiled first, across the same C/T/mode matrix; keep `kv_stream` misses and transfer bytes separate from logical selected-cell payload. Reject the candidate if exact IDs differ, it regresses any primary shape, increases score-list/temporary storage materially, or fails the existing fault/teardown policy. No code is written here.
