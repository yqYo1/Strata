# R554 — QSA batch indexer numerical-contract audit

Date: 2026-10-15 JST. Independent source/fixture review of `qsa-indexer-batch-proposal-v1`, limited to the shared FP16-input, pooling, RMS normalization, subgroup/local reductions and RoPE math. This review did not execute the fixture or patch, build/test, use a GPU/profiler, inspect a process/service, reset or clean anything, inspect Git/live-run/private/model data, or open the excluded `B/prefill-gemm-only-contract-root-v1/record.json`. Main retains serial validation and adoption authority. No quality, latency or runtime correctness result is claimed.

## Finding

The proposed source copies the existing serial append's numerical body into `normalize_rotate` and calls it for both serial and completed-block paths. The four-input pooling loop, explicit `sycl::fma`, 256-lane reduction tree, two local barriers, RMS expression, gamma multiply, MRoPE coordinate lookup, table/fallback branch and analytic YaRN expression appear unchanged from the baseline. The completed-block caller supplies the serial append's terminal position (`4*block+3`). Its incoming values are explicitly converted through the same `float(sycl::half(...))` path, and the four terms are accumulated left-to-right in the same row order. The shared helper also leaves source-level arithmetic common to baseline and proposal, reducing the risk that the two paths drift.

This is source-level evidence of intended parity, not bitwise validation. The model-free fixture includes and executes only `qsa_indexer_batch_plan.hpp`; it does not compile or call the proposed SYCL helper, represent floats, emulate F16 conversion, calculate normalized/rotated keys, or test scores and selected IDs. Its independent literal serial model checks symbolic state/ownership against the candidate's integer plan. The proposal report correctly calls it symbolic; its source arithmetic discussion and deferred F16/numeric parity gates are not fixture assertions.

I found no changed arithmetic expression that alone blocks a serial parity trial. Before any adoption, Main still needs paired device-output parity on the configured compiler/device, plus adversarial fixtures that reach the **actual proposed kernel code**. SYCL collective rules and device math accuracy do not let source inspection establish universal bitwise equality. No kernel time or quality outcome follows from this audit.

## Numerical path compared

1. **Incoming values and four-cell mean.** The old append casts each raw float to `sycl::half` and back to float before it can reside in tail. At token position zero, it repeats that single half-rounded incoming value for all four sum terms to initialize `dead` and a provisional pooled row. Later position 3 (and each subsequent block end) forms the final key from half-rounded tail rows 0, 1, 2 and half-rounded current input, in that order. The proposal's completed-block kernel reads the same three old-tail slots for a prefix block and half-rounds every in-batch row; it starts `sum` from row 0 and executes `sum += row[j]` for j=1,2,3, then the same `sycl::fma(.25f, sum, 0.f)`. For a chunk beginning at zero, its separate initial append establishes the same zero/dead transition; bulk subsequently replaces pooled row zero with the four-row completed key, as the serial sequence does. This is a source-expression and state-transition argument, not measured numerical equality.

2. **RMS normalization reduction.** For each dimension, both bodies begin `ss = mean * mean`. The 32-lane subgroup performs XOR exchanges at offsets 16, 8, 4, 2, 1 with `ss += exchanged`; lane 0 of each of eight subgroups stores its partial into `partials[d/32]`; a local-memory barrier separates write/read; lanes 0..7 of each subgroup load the eight partials and other lanes load zero; the same XOR tree reduces those values; then dimensions 0..127 compute `(sycl::rsqrt(ss / 128.f + eps) * mean) * gamma[d]`, followed by a second local barrier before any lane exits or reads `values`. This retains the explicit multiplication order and gamma placement. The proposal changes the helper's high-lane `return` to `return 0.f`, after the second barrier; the caller then suppresses stores from lanes `d>=128`. In the bulk kernel those lanes still participate in both subgroup reductions and barriers. The 256-work-item group and required subgroup size 32 are unchanged.

   SYCL group functions must be encountered by all work-items in converged control flow, and the XOR permutation mask must be uniform; the fixed offsets are within the required 32-lane subgroup. These rules support the structural argument, but they do not certify device output. The proposed calls use a uniform per-group block position and no lane-dependent branch around a collective. Khronos documents these constraints in [group functions](https://github.khronos.org/SYCL_Reference/iface/group-functions.html) and [`permute_group_by_xor`](https://github.khronos.org/SYCL_Reference/iface/group-algorithms-library.html). Local accessors are group-private and shared within each group, as described by the [SYCL local accessor reference](https://github.khronos.org/SYCL_Reference/iface/local_accessor.html).

3. **RMS epsilon and explicit fused operation.** Both paths use the same validated positive finite `eps` and expression `ss / 128.f + eps`; validate requires the same 128-dimensional QSA shape. Pooling explicitly invokes `sycl::fma` with multiplier 0.25 and addend zero in both paths. The [SYCL math reference](https://github.khronos.org/SYCL_Reference/iface/math-functions.html) defines `fma` as a correctly rounded operation with no intermediate product rounding. In the configured root build, `strata_kernels` has `-ffp-contract=off` and this source has `-fno-fast-math` (`cmake/sycl_backend.cmake`); Intel documents that `-ffp-contract=off` prevents contraction of separate expressions ([Intel compiler reference](https://www.intel.com/content/www/us/en/docs/dpcpp-cpp-compiler/developer-guide-reference/2023-1/ffp-contract.html)). This preserves the stated source order and prevents implicit contraction, but does not make `rsqrt`, `sin`, or `cos` bit-identical across different devices, compiler versions, or math-library implementations. Intel's compiler guide says offload-device default math accuracy is device-dependent ([Intel floating-point accuracy reference](https://cdrdv2-public.intel.com/848584/dpcpp-cpp-compiler_developer-guide-reference_2025.1-767253-848584.pdf)). Compare old/new outputs on the same configured target and toolchain, and record exact flags and compiler/runtime identity.

4. **Gamma and rotary transform.** For each `d<128`, both paths multiply normalized `mean` by `gamma[d]`; for `d<64`, both then rotate the 32 pairs using `x=values[pair]`, `z=values[pair+32]`, with outputs `x*c-z*s` and `x*s+z*c`. Dimensions 64..127 bypass RoPE and keep normalized values. For position zero, rotary coordinate is forced to zero. Otherwise the block-end position maps to `rp=base+4*(pos/4)`, which is the completed block's first cell and is equal to `base+4*block` in both paths.

   If MRoPE is registered, coordinate `p` is selected by `mrope[rp*3 + pair%3]`; otherwise `p=rp`. If a cos/sin table exists and `0<=p<max_pos`, both load `[p, pair]`; negative or out-of-range MRoPE/table coordinates take the same analytic fallback. That fallback uses the same precomputed frequency array, `extrap=float(p)*frequency[pair]`, initial `angle=freq_scale*extrap`, `magnitude=attn_factor`, and, when `ext_factor != 0`, the same YaRN ramp, blended angle and log-based magnitude adjustment before `sycl::cos/sin`. None/linear/YaRN parameters are validated identically by the shared `Angles` preparation. This source audit cannot verify table contents, registered-table context/lifetime, MRoPE values, or the platform results of transcendental functions.

## Fixture boundary and concrete missing cases

The fixture's include is exactly `strata/kernels/qsa_indexer_batch_plan.hpp`. Its `serial_cell` and `serial_batch` are a symbolic re-expression of serial state transitions; `planned_batch` uses the real integer planner, but builds each key from integer position symbols. It checks row ownership, old-tail read range, tail retention, spare-row write and whole symbolic-state agreement. It has no floating-point representation: the comment says F16 conversion is deferred to GPU parity. It does not cover `normalize_rotate` or either device kernel. Do not call it a numerical fixture or a math oracle.

Main's paired device fixture should use two builds or two code paths from the exact original and proposed native indexer and compare **all output words** (pooled row(s), dead, tail, block position) after each tested chunk, with canaries and identical input/state/scaling/table. It should also compare a subsequent one-token append to test state continuity. Add vectors and parameters that specifically exercise:

- **F16 ingress:** FP32 values exactly on and immediately to either side of half-way rounding boundaries; positive/negative zero; normal/subnormal boundaries; underflow, overflow, infinities and NaNs if supported inputs can reach the helper. Include rows whose half-rounded values differ from their original FP32 values so the test detects a missed or reordered conversion.
- **Pooling order and token-zero special case:** a fresh one-token chunk that initializes `dead` from four repeated copies of token zero; fresh chunks with lengths 2 and 3; a chunk that completes block zero; aligned and unaligned continuation chunks with a completed first block; cancellation-sensitive four-row vectors such as `[65504, 2^-24, -65504, 2^-24]` per chosen dimension, plus sparse impulses and alternating signs. Compare the *mean input* as well as the final key where possible so errors are localized.
- **Reduction/RMS/gamma:** basis impulses in each of 128 dimensions and impulses across subgroup boundaries (31/32, 63/64, 95/96); equal values, alternating magnitudes, signed zeros and finite cancellation cases; multiple positive finite epsilons including the model value and values near the accepted extremes; gamma vectors with zeros, signs and nonuniform magnitudes. Compare normalized pre-RoPE values and pooled results, recording exact mismatch count and max absolute/relative/ULP delta. Confirm no lane skips a shuffle or either barrier.
- **RoPE variants:** no scaling, linear and YaRN; base-zero and nonzero aligned base; position zero and ordinary block positions; rotations covering all 32 pair indices; YaRN with `ext_factor=0`, partial and full extension, plus pair indices below/inside/above the ramp window and low/high close enough to exercise the 0.001 denominator floor. Compare normalized-before-RoPE, cos/sin choice and post-RoPE result separately.
- **Table, fallback and MRoPE:** no registered table; registered table at first/last valid coordinates and immediately across the `max_pos` boundary; analytic fallback with no table; MRoPE disabled and enabled with distinct temporal/height/width coordinates so `pair%3` routing is visible; negative MRoPE coordinate (analytic fallback) if valid. Exercise matching registration context and reject cross-context cases exactly as baseline does. Compare output while holding exact table bytes and lifetime fixed.
- **End-to-end numeric consequence:** after state parity, compare selector scores and selected IDs using identical query and score/top-k kernels, then attention output or first logits. Include low-margin score cutoffs to expose any downstream sensitivity if a discrepancy occurs. This is a correctness diagnostic, not a quality or latency verdict.

The fixture should ensure the proposed SYCL helper itself is under test, rather than copying its equations into another host oracle. If the standalone math cannot be called from a device test without duplicating the implementation, add a narrow diagnostic output path around the actual serial and bulk kernels; keep a separately derived expected-value check for the simple pooling stage. Main's existing `qsa_parity.cpp` aligned n=8 scaling cases do not cover this batch source change or these continuation/math branches.

## Decision and limits

The proposal has a reasonable source-level numerical-parity design: it keeps the same FP16-rounded inputs, ordered sum, explicit FMA, reduction tree, epsilon placement, gamma application and rotary branch logic. The structural collective conditions appear satisfied. The missing evidence is actual device tensor parity, particularly because the added host fixture is integer/symbolic and because SYCL transcendental accuracy is device-dependent. Source review therefore supports proceeding to Main's serial correctness gate after its priority boundaries; it does not establish that the proposal is bitwise equivalent, quality-neutral or faster. Keep performance work separate until numeric and state parity pass.
