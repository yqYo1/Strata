## Current dispatch and admission

`src/prefill/prefill.cpp` builds the pools for each QSA layer and attempts `qsa_prompt_attn_batch` once for the whole current prefill chunk `T`. The actual expression is `old_attn || !qsa_prompt_attn_batch(...)`: when `STRATA_PROMPT_ATTN_OLD` is present, the call is skipped; otherwise a `true` return means the prompt kernel admitted/launched and the decode fallback is not called. A `false` return invokes `qsa_decode_attn_batch` in `m.attn_batch` slices. Thus the current source already has a precise host-side selected-versus-fallback decision, but the long-run record has no count for it. The environment omission only establishes that the explicit force-fallback switch was not set; it does not establish matrix admission or launch.

The current SYCL prompt implementation (`src/kernels/sycl/prompt_attention.cpp`) selects KV mode by populated pool pointers: mode 0 is FP16, mode 1 is int8 K/V, mode 2 is Q4 K/V, and mode 3 is int8 K with Q4 V (hybrid). The observed run's int8 KV corresponds to mode 1, assuming the recorded runtime setting maps to the ordinary int8 pools as `qsa_attn_pools` does. For nonzero `nq`, pre-matrix admission rejects invalid query count (`nq < 0` or `nq > 65,535`), nonpositive or over-`INT_MAX` capacity, head dimension other than 256, KV heads other than 2, query heads other than 24, and nonpositive or over-`INT_MAX` page size. `nq == 0` returns true without launching and is not evidence of a selected kernel; real prefill chunks here are nonzero.

Mode 2 alone may be declined by `STRATA_PROMPT_ATTN_Q4=0`. Matrix admission then requires subgroup size 16, local memory at least `51,648 + 2,180 * groups + 128 * mode_factor` bytes (mode 1: 60,880 bytes), max work-group size at least 128, and a reported Intel joint-matrix combination compatible with FP16 x FP16 -> FP32 and m8/n16/k16 (exact size or a maximum at least each requested size). An exception while querying combinations is a decline. After admission, spans for outputs, query/IDs/steps, page table, and mode-specific pool pointers are validated; a malformed span throws rather than returning false into the fallback. `validate_spans` is a safety contract, not a performance dispatch choice.

For the 34,560-token run, each regular chunk (4,096 queries) is below the count guard, as is the 1,792 tail. The current per-kernel selection capacity is separately set by `m.cap` and is not total context; physical context and page-table coverage must be validated independently. The source uses `size_t` checked counts for launch/output spans and page-table arithmetic derived from the selected cell and `page_size`. Nothing in source admission alone proves the runtime device reported compatible matrix combinations or enough local memory.
