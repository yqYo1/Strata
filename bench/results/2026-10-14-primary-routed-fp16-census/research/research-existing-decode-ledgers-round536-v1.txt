The two old proposals can provide a joined decode-only view with small adaptation, but the join is not yet a durable, single receipt: the route proposal emits a separate block and has only route/owner/format/NT counts; the service proposal emits a separate block and has host phase/service times and CPU-job totals. Their common eligibility and normal-close coverage make them compatible for the exact target mode, but a shared request identity and common completeness footer are the minimum additions for unambiguous joining. Prefer one request-local scope/state and one bounded close block, or add an identical request sequence key and cross-check both close statuses if preserving the two helpers.

## Actual current source path and target-mode compatibility

At this revision, `cmake/sycl_backend.cmake` builds `strata` from root `src/program/generate.cpp`. Its `strata_engine` sources include root `src/core/session.cpp`, `src/core/expert_source.cpp`, `src/core/verify.cpp`, `src/core/mtp.cpp`, and other root engine files; it links `strata_kernels_cpu`, which includes root `src/kernels/cpu/pool.cpp` and, for native experts, root `src/kernels/cpu/native_expert.cpp` and the pinned GGML CPU implementation. The prefill library is separately rooted at `src/prefill/prefill.cpp` and its SYCL/oneMKL units. No historical side tree is selected by this configured SYCL resolver. This is the source-path evidence for the supplied current `root native68da` identity; no binary was inspected here.

The actual requested route is ordinary single-GPU `--serve --spec 4 --no-spec-split --suffix-draft 0`, with no `--mtp`, batch, suffix lookup, or lookup chain. `--spec 4` is verifier capacity; without MTP it does not mean the actual routed group has four rows. The verifier's first window is `T=1`; the last prompt token is consumed there, after the preceding prompt tokens have been prefetched. In `expert_pool_dispatch_multi`, `n_tok` is the actual dispatch width, `ids`/`kind` describe each routed entry, and the CPU job builder deduplicates CPU misses into one `ExpertJobMulti` per distinct missed expert. For this request each dispatch should remain actual `NT=1`; that is a checked runtime condition, not inferred from the capacity flag. `--no-spec-split` keeps the single-stage path required by the proposals.

The old proposal's common gate is already close to this mode: ordinary serving, batch 0, one stage, no MTP, suffix 0, lookup 0, capacity >=2; dispatch then checks native pack, actual NT=1, and zero remote entries. For this task, retain that conservative gate and additionally ensure split is off. Capacity 4 is admitted. Unsupported/changed modes must emit an incomplete/eligible=0 result, never silently label the counts as this route. The no-remote/single-device and native-format conditions are important because the route owner's fixed four-way accounting does not include peer or remote ownership.

The route source compares repeated expert IDs within each dispatch to count each distinct GPU owner once, and sums the actual `nt` for its routed entries. It counts CPU job `nt` from the completed job array. The format pair is copied from the layer layout and checked on each callback. Logical `gu`, `down`, and `blob` extents are charged once per group. The route table has a fixed envelope of 64 layers × 4 owners × 8 `nt` bins, 128 KiB state ceiling, and 512 KiB output ceiling. It does not retain route IDs, timestamps, tensors, or one line per expert.

The host source's fixed service slots distinguish inline issuer from worker threads. It times native GU, activation quantization, native Down and the existing Q2 fallback buckets, plus dispatch and pool lifecycle phases. Linux `CLOCK_THREAD_CPUTIME_ID` is thread CPU time, while its steady clock is elapsed wall time; wall minus CPU includes blocking and preemption and is not pure wait. The [Linux `clock_gettime(3)` reference](https://man7.org/linux/man-pages/man3/clock_gettime.3.html) defines `CLOCK_THREAD_CPUTIME_ID` as CPU time consumed by the calling thread. The design correctly treats these host clocks as attribution counters rather than exclusive critical-path time.

## Minimal adaptation, not another proposal

1. Reuse the two archived designs and their fixtures as reference inputs; do not create a third route or host-service proposal. Current implementation is absent, so inspect/adapt to the current root `ExpertDispatch`, `ExpertPool`, and serve loop rather than applying the old branch diff blindly. The archived branches have different commits/source sizes and are reference history, not current compiled implementation.
2. Add one opt-in request-local ledger, default off, bound at the existing decode boundary. A single exact environment gate is enough; with it off, take no new clocks and allocate no per-job/per-layer observation state. At dispatch, aggregate the route table and service counts into that request's fixed-size state. Snapshot current `Verifier` and `ExpertDispatch` cumulative counters at decode entry. Do not add a new queue, event, wait, copy, device branch, per-layer log line, or GPU synchronization.
3. Keep all output after the existing successful `wait_commit`/request close. Preserve the real close status and emitted count. Cancellation, early return, invalid pointer/count/format, clock failure, overflow, incomplete layer coverage, or output-budget failure must produce an incomplete result. Coverage is an observed-count check: for ordinary `T=1`, expect `layers × emitted` completed layer dispatches and verify every layer separately; never fill an omitted callback from the expected count.
4. Add a common request sequence/receipt key and one close footer. Cross-check (a) route CPU unique groups == `cpu_jobs`, (b) route CPU job-row sum == `cpu_activation_rows`, (c) routed entries against dispatch entries, (d) per-layer dispatch completion and service counters against emitted tokens, and (e) pool task totals against planned tasks. Preserve per-layer format and actual owner/`nt` bins even when a layer has zero CPU misses. Report all units and overlapping intervals explicitly.
5. Keep the output within a fixed bound and emit once at close. Reuse the old host-only fixtures, with `-UNDEBUG`; add only cases required by the combined state (identity/close agreement and cross-counter mismatch). These are not run in this research task. The observer's timings are not measurement-arm performance evidence; clean uninstrumented decode samples remain the rate source.

## Contracts and unresolved risks

- **Failure/teardown:** Both proposals use request scopes and shared ownership. The route scope unbinds and marks the state inactive at finish; the service dispatch scope serializes a full dispatcher callback and clears the pool's observer pointer before releasing the request lock. Pool task slots are read after the existing completion/park boundary. Keep that lifecycle: closing the request while workers can still write would invalidate the receipt and race the state. Scope destruction on an early return reports incomplete; it must not synthesize `length` or `stop`.
- **No event/queue change:** The observations are host-only and add no SYCL event, queue marker, host wait, copy, or queue synchronization. This matters because the measurements should not insert a new completion dependency into the routed decode handoff. Existing doorbell, pool-drain, output staging and `wait_commit` behavior remains the synchronization contract.
- **Capture/serving mode:** The proposal is not universal. MTP, multi-token actual dispatch, suffix/lookup drafts, batching, split stages, remote/peer experts, non-native packs, or more than 64 layers are ineligible for this specific ledger. Failure to match a gate is an incomplete receipt, not an inferred zero count. The task target explicitly uses ordinary native single-device `T=1` mode.
- **Observer failure:** Allocation/formatting failures, clock errors, invalid counts, overflow and early close are represented as incomplete. A process abort or forced kill before close produces no receipt. Preserve actual state/status and do not retry or repair counters after the run.
- **Timing interpretation:** Request, dispatch, service, pool phase and worker wall intervals overlap. Do not add them or treat wall-minus-CPU as blocking time. Existing `STRATA_DECODE_TIMING` averages can guide comparison but the joined receipt should keep exact nanosecond totals and explicit denominators. `STRATA_VERIFY_PROFILE` changes the eligible branch and must remain off for this route-preserving diagnostic.
- **No runtime claim:** Neither archived proposal was adopted, built against the reviewed current source, or qualified on the target request by this review. The existing long prefill Stager is a separate path; its worker-copy timings are not decode host CPU service and should not be included in this ledger.
