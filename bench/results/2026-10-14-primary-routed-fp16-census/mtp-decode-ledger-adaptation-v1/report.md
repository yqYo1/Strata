## Window, route and task accounting

Binding occurs after the prompt at the existing d0 decode entry, after the existing DecSnap/window counter declarations and before the first verifier window. Source prefix work and earlier requests are outside the before/after delta. The first actual T1 verifier call consumes the last real prompt token and produces the first output; it belongs to this decode ledger. Later actual T is passed from each caller invocation and must be 1..4. Capacity 4 does not supply observed width.

`begin_window` records an attempted call and resets a fixed layer-mask pair. Dispatch entry records an attempt; the hook after successful native pool completion and existing dispatch finish records that actual layer/T callback. Route input pointers, layer, k, entries <=128, job count/capacity, expert range, owner, format fields and job nt are checked before observer indexing. Each token row must have distinct experts. CPU groups are associated with actual jobs in first-miss order and each job nt must equal its observed repeated-expert route count in 1..T. Kind -1 is CPU, 0 VRAM, 1 PCIe; unsupported owner kinds are incomplete rather than silently omitted. Zero-CPU-job dispatches still advance real layer/T coverage.

The caller marks a verified window only after successful `ver.run` and the dispatch failure latch check. It counts committed window totals only after `commit(a+1)` returns success. Actual emitted count is the change in existing `produced_n` across the original output loop, and terminal EOS/cap truncation is recorded independently. The original source's successful-return arithmetic is retained:

- W: successful verifier-plus-commit-return windows; R: sum of their actual T.
- D=R-W; A: accepted proposal positions; C=W+A; rejected draft rows D-A.
- E: the original emitted-output counter; E<=C. Terminal C-E can be positive.

Attempted windows, verified-only windows/run rows, attempted/completed layer callbacks, active unfinished window T and task prefixes remain separate. A failed commit does not increment W/C. Successful asynchronous commit return is **not** physical completion proof: W/C remain a successful-return prefix if final `wait_commit` fails or is absent. Such a close is incomplete and cannot qualify committed GPU state. Normal completion requires the final existing `wait_commit` to succeed, every observed layer/T count and row sum to match W/R, exact source-counter joins and a normal DONE close with an observed EOS/cap boundary; length additionally requires E to reach actual max_new. Cancellation, errors, a context-capacity break, missing callback, bad owner/format/shape, clock failure, overflow or output-budget failure are incomplete. No missing count is filled from an expected value; layers times E is never used.

The close joins route CPU groups/jobs and entries/nt, VRAM routed entries, PCIe group count and CPU logical blob extents to existing `multi_misses`, `multi_entries`, `cache_hits`, `pcie_experts` and pool `multi_bytes` deltas. Per-T/window histograms join back to request W/R/D/A/C/E; per-layer histograms join W and R separately. Expected counts are checks only. Logical GU/Down/blob extents are counted once per distinct owner group, not physical weight/DRAM reads, successful DMA or PCIe bytes.

The service adaptation retains six per-thread roles and the inline issuer/worker slot ownership. Slot -1 is the issuer/host participant, slots 0..N-1 are logical persistent pool worker indices, not OS TIDs. Current worker count and actual T are immutable across each synchronous native call and published with the existing job generation. Role scopes validate worker index, role and job nt before touching their slot. Clocks sample only the original kernel/quantizer entry intervals; they do not identify the internal ISA/reduction dispatch or exclusive per-format service time.

Native tasks are counted after a successful claim, with the original flattened row span, and completed only after their work before the existing done release. Pool phase completion is counted after the original final worker-park wait. Planned/completed task and row sums are cross-checked with observed job counts and actual batch phases, including zero-job dispatches. This preserves the source's `3*(workers+host)` split over `jobs*640` GU and `jobs*2560` Down rows. Fewer unique experts than workers does not imply empty tasks. The fixture explicitly uses one job and six positive row ranges. Q2 Down(type42) still calls `q2_rows_any`, which selects `q2_0_gguf_rows_multi_avx2` on this Zen3 path when AVX512 is absent; no scalar-only assumption, new kernel or grouping is adopted.

## Timing and close identity

No new dispatch/verifier/pool phase timer duplicates existing timings. The collector snapshots existing verifier wait/pool/host/commit, dispatcher plan/actq/jobs/run, pool multi GU/quant/Down, existing per-request run/commit/draft intervals and `phase_ms`. `receipt-schema.json` gives all 17 real and six integer indices. Those intervals overlap. `phase_ms` wait_park/repark accumulation is currently in `run()`, not a separate native `run_phase` timing, so zero native-request deltas must not be read as no native wait cost. The native drain delta includes the existing whole call interval. CPU-role clocks are the distinct additional per-thread service measurement reused from the archive; wall minus thread CPU is not pure wait.

Identity is one request ordinal and one little-endian FNV64 fingerprint over actual prompt IDs plus prompt length/max_new/context, shared by all rows and the authoritative footer in a single block. It contains no IDs, expert-by-expert trace or model data. FNV64 is not cryptographic and the ordinal is native-instance-local. Main must bind the receipt to its externally owned boot/PID/start/source/binary/compiler/runtime/environment and full request SHA256; the proposal does not invent those identities or inspect the live run. The header's decode_ms is the original interval computed before final wait_commit. Hashing/setup and on-clock overhead can affect that diagnostic interval; the close output itself follows DONE.

The explicit normal finish is after the existing successful final wait **and** the existing DONE/stdout flush. A state-hash/read error occurring between final wait and DONE therefore gets the incomplete destructor close. Other ERR/early exits emit their observed prefix via RAII when normal C++ unwinding occurs. Kill/abort/terminate can leave no ledger; absence is not success. The logger does not change protocol, original status, token output, commit/rollback, rounding, sampling, queues, events, copies, waits, graph capture, affinity, thresholds or scheduling.

## Lifetime and bounds

The narrow ordinary unsplit source calls its pool callback synchronously on the issuer. Route state has one host writer; each service worker slot has one writer, and the issuer owns slot zero. Native binding is established before publishing jobs and cleared only after `run_split_multi_native` returns through its original completion and worker-park boundaries. Close reads worker counters only after those same boundaries; no observer wait is added. If an exceptional native CPU call never returns through that boundary, the scope does not read slots, clear the worker pointer or free state. It emits `complete=0 reason=pool_completion_unobserved`, deactivates route collection and retains that one bounded state until the owned native exits. The still-bound dispatch pointer refuses a second observer allocation. This conservative exception path is not cancellation/recovery and requires Main review; no runtime execution proves it here.

Route storage is `[64 layers][4 actual-T bins][4 owners][4 job-nt bins]`: 4096 fixed buckets, 160 KiB for five uint64 fields per bucket. The strict job-nt<=T<=4 contract removes the archived unnecessary nt5..8 bins for this scope. Fixed layer/window/format metadata and the adapted 129 service slots share a request-state cap of 256 KiB. Static assertions require native service storage <=64 KiB, total request state <=256 KiB, and combined state + 256 KiB close buffer + 129 clock objects + 4096-byte formatting allowance <=512 KiB. **These are uncompiled enforcement guards, not measured sizeof/RSS evidence.** Existing engine/worker stacks and allocator bookkeeping are not claimed to fit that observer-object envelope.

The close buffer is fixed at 256 KiB, below the requested 512 KiB ceiling, and allocated only at close. It emits nonzero fixed aggregate rows, fixed format/identity metadata and a reserved 1024-byte footer; no vector scales with generated length and no per-window/per-expert or per-job heap allocation/log exists. Dense histograms can exceed the text budget: omitted rows are counted, the collected prefix and reserved footer remain, and authoritative `complete=0 output_bounded=0` prevents qualification. State arithmetic and service counters saturate with overflow flags. Formatting/allocation failures remain incomplete. `coverage_complete=1` or `service_complete=1` alone must never override a false joined close `complete`.
