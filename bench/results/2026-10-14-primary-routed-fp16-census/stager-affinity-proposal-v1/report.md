The existing `pin_current_thread` Linux helper saves only CPU IDs below 64 and does not propagate the underlying pin syscall result. Its `restore_thread_affinity` accepts only positive signed masks. Consequently blindly reusing that saved value would not establish a complete original allowed set or a successful issuer pin. The proposal performs an additional, opt-in-only capture before the existing pin, validates its bounded representation, compares the existing saved value, and reads back the issuing thread's actual singleton mask. It never asks `physical_cores` after pinning to reconstruct an original allowed set.

## Proposed behavior

Unset `STRATA_SYCL_STAGER_AFFINITY` or `=0` retains the original Stager startup loop, worker count, inherited masks, lack of worker naming, and lack of policy output. Existing allocation failure handling on the default path is retained. The new API argument defaults to zero, so existing callers compile against the unchanged call forms. Source and binary layout change; no old binary ABI compatibility is claimed.

`STRATA_SYCL_STAGER_AFFINITY=1` is a Linux/SYCL experiment. Session scratch owns a validated `uint64_t stager_affinity_mask` captured from the current issuing thread before pinning. The primary serve and standalone Prefill callers pass that scalar explicitly as a trailing `Prefill::init` argument; workers copy its value. No borrowed pointer or global affinity mask is introduced. Scratch clears the saved value at teardown. Other callers without that owned mask fail initialization when the option is requested; this intentionally excludes unrelated library and multi-GPU-stage paths from this proposal.

Each newly created Stager worker applies exactly the captured mask to itself before entering `work()`, then reads back its effective mask. Linux still intersects the request with current cpuset restrictions; a narrowed result is an explicit initialization failure, not a successful policy claim. The caller's thread remains pinned throughout worker creation, and `ExpertPool` workers and policies are untouched. The allowed set includes the issuer core and its SMT sibling if they were originally allowed; no exclusive worker placement or speed benefit is promised.

The option names workers `strata-stager`, making future `/proc` role observations possible. A single startup line per successfully created Stager instance includes requested mask, worker count, each worker's effective mask, affinity return code, naming return code, and `status=verified|failed`. Naming failure is recorded separately and does not change the affinity result. No per-job logging is added. If a worker fails affinity setup it never enters the staging loop; successfully configured peers are notified to quit and joined, and Prefill initialization fails before jobs are published. Partial thread-creation failure also wakes and joins created workers and reports the exception. Missing saved mask, invalid option values, and unsupported platforms are explicit errors rather than silent fallback.

The helper rejects any allowed CPU ID above 63 instead of truncating the set. Session integration additionally declines CPU63 before pinning because the unchanged existing signed-mask teardown cannot restore a mask with its sign bit set. This is therefore **a bounded CPU0..62 session integration**, suitable for the recorded CPU0..11 host; it is not generic >64-CPU or Windows support. Linux masks larger than fixed `cpu_set_t` also fail capture. No CUDA/HIP implementation or validation is claimed.

## Lifetime review

No changes touch generation/head claims, `ready` publication, `issued` acknowledgment, active-job accounting, ring buffer selection, CUDA/SYCL event creation/order, memcpy/copy_blob math, `start`, `wait`, `issued_one`, `finish`, or `work`. Existing jobs and DMA events keep their original consumer/reader-before-reuse edges. No queue, copy stream, task schedule, async issue mechanism, or event lifetime is added.

The only new worker boundary is before the original `work()` call. Startup slots belong to the Stager and are allocated before thread creation. Each worker publishes its slot with an acq_rel increment; the issuer waits with an acquire load for all increments before consuming the slots and returning from successful init. Successful workers may already be parked in the original generation wait. A generation published after init still follows the same original mutex/CV contract. On startup failure no generation has been published, so signaling `quit` and joining does not skip in-flight staging work. Normal destruction still calls `finish`, publishes `quit`, notifies, joins, and then destroys events and buffers. The failure path joins and clears only its already-joined thread vector, avoiding a second join during destruction.
