## Existing patch overlap and interface boundary

The local server is already customized: `serve/server.py` has a batch `Service`/`StrataEngine`, `_pump` scheduling, slot grouping/affinity, and restart waiters. Thus upstream parallel-state/READY/restart changes touch the same scheduler and lifecycle paths. Port the state/race fixes into these existing abstractions and extend `serve.test_parallel`/`serve.test_restart_waiters`; do not replace the local pump or bypass slot affinity. Context-overflow handling overlaps request/error mapping in `serve/test_request_hardening.py`; preserve OpenAI/Anthropic error shape and test both recognized overflow and unrelated engine errors. Keepawake must count queued plus active work and balance acquire/release across success, error, cancellation, timeout, and shutdown. Replica tests must exercise readiness failure, dispatch/affinity, and cleanup of sibling children after one child fails.

Request-schema overlaps already include `repetition_penalty` compatibility aliasing, reasoning configuration, and `effort_end_args` in local server code/tests. Keep the compatibility alias and established parameter mapping. Add launcher tests that prove version/feature detection resolves the actual configured `STRATA_SYCL_BIN` executable rather than inferring support from a wrapper or default CUDA/HIP path. Upstream unsupported content parts should retain the documented filter/log behavior instead of being converted into blanket request rejection; cover this in frontend/parser tests.

Minimum seams to keep stable while bringing in all functionality:

1. Preserve the API/request-to-generation contract and `runconfig` loader. Server-only features should not silently rewrite generation parameters or token accounting.
2. Keep an engine-process adapter boundary (binary path + argv/env, readiness, request/stream, stop/park, exit/error, close). Replicas should compose multiple adapters and reuse the same protocol; they should not fork a second API/request implementation. Readiness timeout and replica failures must propagate through this boundary.
3. Tie keepawake to explicit service activity lifecycle hooks (`queued`, `started`, `finished`), not to backend-specific decode timing. Use an injectable OS adapter for deterministic tests.
4. Keep performance instrumentation/backend selection outside HTTP semantics. SYCL-vs-CPU phase measurements belong in engine/backend config and phase metrics; do not add request-visible knobs or alter API output to represent performance state. Any SYCL cancellation implementation still requires a separate protocol/real-engine correctness check; fake server tests establish only the server side.
5. Route engine flags and feature detection through the resolved executable/config interface. Avoid using a server option as an implicit engine tuning change; freeze and assert argv for representative CPU/SYCL launcher configurations.

## Recommended verification sequence

First run existing suites above to record local baseline. After adapting code/tests, run server lifecycle/scheduler/error/API suites together, then replica and keepawake tests, parser/effort-end tests, and local archive recovery tests. Keep cancel/park real-engine verification separate and use the configured SYCL executable with the same protocol and deterministic fixture as the current integration harness. Do not call a CPU-only fake test evidence of SYCL correctness, and do not combine server API work with performance measurements.

## Conclusion

There is a usable CPU-only baseline, but the v0.1.42 server delta is not fully regression-covered in this worktree: READY timeout, context overflow, queue keepalive, replicas, keepawake, parser tracking, launcher-specific effort-end detection, and archive recovery test files are missing. The safest integration keeps the existing scheduler/API interfaces, adds replica/keepawake composition at the process/activity boundaries, and verifies request semantics with fake engines before the separate SYCL engine cancellation and performance gates. R331 contains the upstream feature/commit catalog; R333 contains the inference/SYCL implementation delta.
