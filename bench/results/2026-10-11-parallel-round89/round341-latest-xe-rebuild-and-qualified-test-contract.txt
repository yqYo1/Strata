B570 release-like configure recipe
After the runs close and a clean fixed-SHA integration tree exists, configure a fresh, empty build directory (do not reuse `eval-b570-icpx-v1`) with the established B570 compiler and target mode. The intended CMake values are:

```sh
cmake -S . -B build/eval-b570-icpx-e32-v1 -G Ninja \
  -DCMAKE_C_COMPILER=/usr/bin/cc \
  -DCMAKE_CXX_COMPILER=/opt/intel/oneapi/compiler/2026.1/bin/icpx \
  -DCMAKE_BUILD_TYPE=Release \
  -DCMAKE_EXPORT_COMPILE_COMMANDS=ON \
  -DSTRATA_ENABLE_XE=ON \
  -DSTRATA_LICENSE=contrib-icpx \
  -DSTRATA_ONEMKL=ON \
  -DSTRATA_CUDA_ARCHS= -DSTRATA_HIP_ARCHS= \
  -DSTRATA_NATIVE_EXPERTS=ON \
  -DSTRATA_BUILD_TESTS=ON \
  -DSTRATA_WERROR=ON
cmake --build build/eval-b570-icpx-e32-v1 --parallel <recorded-job-count>
```

Use the B570/SPIR-V target configuration from the existing B570 build record; do not add CUDA/ROCm targets, change the BMG AOT backend options, or infer a new target from the generic Xe release table. Keep the complete configure argv, compiler SHA/version output, CMakeCache, `compile_commands.json`, `ninja -t commands strata`, the oneMath xestrata-3 archive hash, produced archive member manifests, link argv, and final executable hash in the build receipt. `STRATA_WERROR=ON` is a useful stricter project-code build if clean; the repository requires no new `-Wall -Wextra` findings, and this setting turns those warnings into failures. Meaningful CPU and sanitizer qualification
The current source tree contains `tests/core/*`, `tests/platform/*` and source-level CTest targets, but lacks `tests/CMakeLists.txt` and `bench/micro/`. `CMakeLists.txt` therefore defaults `STRATA_BUILD_TESTS` to OFF despite available CPU test sources; set it ON explicitly. Top-level CTest targets include CPU-only `pool_tasks_test`, `pool_test`, `pool_stress`, `expert_multi_test` (return code 77 means expected ISA skip), `expert_parity`, `iq_avx2_parity`, `q8k_quant_parity`, and `q2_bitplane_parity`. These use synthetic data or checked-in expert fixtures and need no model/GPU. The test runner should select that set explicitly, not run unrelated GPU parity/device tests on a no-GPU host:

```sh
ctest --test-dir build/eval-b570-icpx-e32-v1 --output-on-failure \
  -R '^(pool_tasks_test|pool_test|pool_stress|expert_multi_test|expert_parity|iq_avx2_parity|q8k_quant_parity|q2_bitplane_parity)$'
```

`pool_tasks_test` is directly relevant: the latest patch adds its Q2_0 ActQ batch and missing-activation rejection case. It does not exercise `CpuCalJobs`' startup factory through the complete engine, so retain a source/callsite assertion that its Q2_0 branch fills `act` before `run_split_multi_native`; then add a small actual B570/model calibration smoke only after the active runs close. Keep `expert_multi_test`'s expected no-AVX-512 skip explicit; no latest source change alters the AVX-512 implementation or selection.

Build a separate clean sanitizer tree; never reuse the optimized build directory:

```sh
cmake -S . -B build/eval-b570-icpx-e32-asan-v1 -G Ninja \
  -DCMAKE_C_COMPILER=/usr/bin/cc \
  -DCMAKE_CXX_COMPILER=/opt/intel/oneapi/compiler/2026.1/bin/icpx \

cmake --build build/eval-b570-icpx-e32-asan-v1 --parallel <recorded-job-count>
ctest --test-dir build/eval-b570-icpx-e32-asan-v1 --output-on-failure \

```

The CMake sanitizer flags instrument project-owned host code; ggml and SYCL device code are not instrumented. This can catch CPU pool/job/pointer and host publication helper errors; it cannot establish GPU event completion or device memory safety. Do not run sanitizer binaries under Intel SDE. Additionally compile/run `tools/test_prefill_publication.cpp` as a CPU-only harness with the exact preserved `publication.hpp` and `-fsanitize=address,undefined`; this file is not currently a CTest target. Record compiler, full command, source/header hashes, stdout and exit status. It validates helper state/order/failure cutpoints, not actual GPU queue completion.
